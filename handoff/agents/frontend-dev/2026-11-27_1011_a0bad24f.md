## 2. 먼저 확인할 것 4건 (근거: 파일:줄, `_gg_route` 기준)
**ⓐ 메뉴를 옮길 때 편집 상태와 경고**
- 메뉴 이동 경로 `openNavItem`(app.js:726-734)에는 이탈 경고가 없습니다. `confirm`이 없고, `openTab`이 가득 찼을 때만 막습니다.
- 이사회 자료: `board.unmount`는 빈 함수이고(board.js:2454) 편집 상태를 지우지 않습니다. 다른 메뉴로 갔다 와도 편집 상태가 남습니다.
- 현황판: 다른 화면으로 갈 때 언마운트하지 않아 숨은 채 남습니다. 다시 들어오면 `kbb.mount`가 `gs.draft = {}`로 초기화합니다(kbboard.js:3824). **저장하지 않은 구분 변경이 경고 없이 사라집니다.** 메뉴 클릭도 똑같이 사라집니다.
- `beforeunload`는 새로고침·창 닫기에만 걸립니다(kbboard.js:3826, board-write.js:2831). hash 이동은 이 경고를 일으키지 않습니다.
- 주석상 `kbb.draftCount`는 "app.js 메뉴 이동 경고가 나중에 부를 입구"입니다(kbboard.js:3808). 아직 쓰는 곳이 없습니다.
- **결론**: 이번 패치는 주소 이동을 전부 `app.openNavItem`으로 보냅니다. 뒤로 가기·주소 입력은 메뉴 클릭과 똑같이 동작하고, 경고는 새로 만들지 않습니다(planner §5 규칙대로).
- 나중에 이탈 경고를 `openNavItem`에 붙이면 `false`를 돌려주게 됩니다. 이 패치의 `routeOpen`은 이를 'full' 경로로 받아 `routeSettleHash`로 주소를 지금 화면에 되돌립니다. 다만 뒤로 가기로 이미 이동한 기록 칸은 교체됩니다. 이 한계는 감수합니다.
- 현황판 초안 소실은 기존 문제입니다. 이관 메모에 적었습니다.

**ⓑ 접근 이력(`/auth/screen`)**
- 남기는 시점은 `syncNavActive` 끝의 `recordScreen`입니다(app.js:691). 모든 화면 전환의 공통 경유점입니다.
- 주소 진입도 `openNavItem` → `activateItem` → `onTabChange` → `syncNavActive`를 지나므로 **메뉴 클릭과 똑같이 남습니다.**
- 같은 화면 연속 호출은 `lastRecorded`로 중복이 제외됩니다. 준비중 화면(`soon:`)과 guest는 원래 기록하지 않습니다(`nav.screenName`, app.js:703).
- 내 정보(`myinfo`)는 메뉴 항목이 아니라 `screenName`이 그대로 `myinfo`를 보냅니다. 서버가 받는지는 못 확인했습니다. 지금 ⚙로 열어도 같은 호출이 나가므로 동작은 같습니다.

**ⓒ 둘러보기(guest)**
- 세션은 `{mode:'guest'}`이고 `enterApp`을 그대로 지납니다(app.js:1181-1184). `navContext`의 역할이 빈 값이라 `homeIdFor`가 null이고, 시작 화면은 지도입니다.
- 주소 규칙은 로그인 사용자와 같습니다. 화면을 여는지는 `findNavItem`(메뉴에 보이는가)이 정합니다.
- guest의 `#/home`·`#/my-info`는 권한 없음입니다. `#/my-info`는 `routeCanOpen`이 account 세션만 허용합니다. ⚙가 guest에게 숨겨지는 것과 같습니다(index.html CSS 129).
- guest가 [로그인] 칩으로 연 로그인 화면은 **주소를 쓰지 않는 덮개**로 취급합니다. 이유는 아래 §5 위험 3번에 있습니다.
- guest가 `#/login`을 직접 치면 "로그인한 채 `#/login`은 시작 화면" 규칙을 받습니다. 로그인 칩으로 가야 합니다.

      pendingRoute = false;
      const h = root.location.hash;
      const p = routeNext ? { name: routeNext } : r.parse(h);
      routeNext = null;
      if (!p) { if (r.isRoute(h)) msg = '없는 화면 주소입니다'; }
      else if (p.name === 'intro') { routeShowIntro(); }
      else if (p.name && p.name !== 'login') {
        const res = routeOpen(p.name, false);
        if (res === 'ok') held = true;
        else if (res === 'denied') msg = '이 화면을 볼 권한이 없습니다';
      }
    }
    if (held) { pendingHome = false; flushOverdue(); } else applyHome(settled);   // 주소가 연 화면이 있으면 시작화면이 덮지 않는다(지도 주소도 그대로)
    if (!routeReady && settled !== false && root.store.loadSession()) { routeReady = true; routeSettleHash(); }
    if (msg) showTabNotice(msg);
  }

  function routeHideIntro() { const L = root.landing; if (L && routeTop() === 'intro') L.hide(); }
  // 소개·로그인 덮개가 바뀔 때(MutationObserver): 주소·제목을 맞춘다.
  function routeTopChanged() {
    const now = routeTop();
    const prev = routeTopPrev;
    routeTopPrev = now;
    routeTitle();
    if (now === prev) return;
    if (!root.store.loadSession()) { if (now) routeWrite(now, prev !== null); return; }   // 로그인 전 소개↔로그인은 기록 1칸, 첫 화면·로그아웃은 교체
    if (now === 'intro') { app.setBehindInert(true); return; }                              // 로그인한 채 연 소개 — 뒤 앱은 Tab·낭독에서 막는다
    if (prev === 'intro' && !now) {                                                         // 소개의 [로그인] = 시작 화면으로 돌아가기
      app.setBehindInert(false);
      if (!pendingRoute && root.location.hash === '#/intro') {
        routeReplace = true;
        try { app.goHome(); } finally { routeReplace = false; }
        routeSettleHash();
      }
    }
  }
  // 주소 → 화면(뒤로·앞으로·직접 입력·즐겨찾기). 처음에 세션부터 다시 확인한다(다른 탭 로그아웃·bfcache).
  function onRouteHash() {
    const r = root.router;
    if (routeQuiet || !r) return;
    const h = root.location.hash;
    if (!root.store.loadSession()) {
      if (!routeTop()) { app.logout(); return; }   // 세션이 없는데 앱이 보인다 — 정리하고 로그인 화면으로(logout이 주소를 #/login으로 교체)
      const p = r.isRoute(h) ? r.parse(h) : { name: '' };   // 화면 주소가 아닌 값은 기본 주소로 본다
      if (p && (p.name === '' || p.name === 'intro')) {
        if (root.landing) { routeShowIntro(); routeWrite('intro', false); } else routeWrite('login', false);
      } else {
        if (p && p.name !== 'login') routeNext = p.name;   // 로그인 뒤 열 화면 — 메모리에만
        routeHideIntro();
        routeWrite('login', false);
      }
      routeTopPrev = routeTop();
      routeTitle();
      return;
    }
    if (!r.isRoute(h)) { if (h === '' || h === '#') routeSettleHash(); return; }
    if (!routeReady) return;   // 권한 응답 전 — applyRoute가 그때의 주소를 읽는다
    const p = r.parse(h);
    if (!p) { routeHideIntro(); routeFallback('없는 화면 주소입니다'); return; }
    if (p.name === 'intro') { routeShowIntro(); return; }
    routeHideIntro();
    if (p.name === '' || p.name === 'login') { routeFallback(null); return; }   // 기본 주소·로그인한 채 #/login = 시작 화면
    const res = routeOpen(p.name, true);
    if (res === 'denied') routeFallback('이 화면을 볼 권한이 없습니다');
    else routeSettleHash();   // 열렸으면 주소를 맞추고, 탭이 가득 차 못 열었으면 지금 화면 주소로 되돌린다
  }
  app.wireRoute = function () {
    const r = root.router;
    if (!r) return;
    if (root.store.loadSession()) pendingRoute = true;
    else {
      const p = r.parse(root.location.hash);
      if (p && p.name && p.name !== 'intro' && p.name !== 'login') routeNext = p.name;   // 로그인 전에 연 내부 주소 — 로그인 뒤 그 화면을 연다
    }
    routeTopPrev = routeTop();
    if (!root.store.loadSession() && routeTopPrev) routeWrite(routeTopPrev, false);   // 소개·로그인 주소로 교체(기록 없이)
    root.addEventListener('hashchange', onRouteHash);
    root.addEventListener('pageshow', function (e) { if (e.persisted) onRouteHash(); });
    if (typeof MutationObserver === 'function') {
      const mo = new MutationObserver(routeTopChanged);
      [['landing-view', ['hidden']], ['login-view', ['class']]].forEach(function (a) {
        const el = byId(a[0]);
        if (el) mo.observe(el, { attributes: true, attributeFilter: a[1] });
      });
    }
    routeTitle();
  };

## 5. 수용 기준 14개 — 어느 코드가 채우나
1. **표 전체를 주소창에 넣으면 열림**: `applyRoute`(새로고침·로그인 뒤)와 `onRouteHash`(실행 중 입력)가 `routeOpen` → `app.openNavItem`으로 엽니다. 준비중 화면도 같은 경로입니다. 시험은 `router.test.js`의 대응표 대조입니다.
2. **열면 주소가 표와 같아짐**: `syncNavActive` → `routeSync` → `routeWrite`입니다.
3. **새로고침 시 같은 화면**: `wireRoute`가 `pendingRoute`를 걸고, `applyRoute`가 `/menus` 응답(settled) 뒤 `location.hash`를 읽어 엽니다.
4. **A→B→C, 뒤로 2번이면 A**: 전환마다 `location.hash =`(1칸)입니다. 상세 팝업·모달은 `syncNavActive`를 안 거쳐 기록이 늘지 않습니다. `onRouteHash`는 `routeQuiet`·`skipSame`으로 되쓰기를 막습니다.
5. **로그인 뒤 뒤로 가도 로그인이 안 나옴 / 랜딩→로그인→뒤로면 랜딩**: 로그인 직후 `routeReady`가 false라 첫 쓰기가 `routeSettleHash`(교체)입니다. 랜딩↔로그인은 `routeTopChanged`의 `prev !== null`일 때 push입니다.
6. **세션 없이 `#/proposal-prep`**:
   - `landing.wantsIntro`가 false라 랜딩이 안 뜨고 로그인이 뜹니다.
   - `wireRoute`가 `routeNext`를 기억하고 주소를 `#/login`으로 교체합니다.
   - 로그인 뒤 `applyRoute`가 그 화면을 엽니다.
   - 재무라서 `findNavItem`이 null이면 'denied' 안내입니다. 이때 재무의 시작 화면은 `applyHome`이 이사회 자료 작성으로 열어 줍니다. 그래서 이 항목은 **패치로 충족하지만 브라우저 확인이 필요**합니다.
7. **권한 없음·없는 주소는 시작 화면 + 안내**: 'denied'와 `parse` null이 각각 「이 화면을 볼 권한이 없습니다」「없는 화면 주소입니다」입니다. `showTabNotice`(기존 `#tab-notice`)를 재사용하고, 서버 데이터는 열지 않습니다.
8. **로그아웃하면 `#/login`, 뒤로 가도 내부 화면 없음**: `routeLoggedOut`이 `location.replace`로 교체합니다. 뒤로 가면 `onRouteHash`의 세션 없음 분기가 화면을 열지 않고 `routeNext`만 두고 로그인에 머뭅니다.
9. **로그인한 채 `#/login`이면 시작 화면**: `routeFallback(null)`입니다(안내 없음).
10. **편집 중 뒤로 가기는 메뉴 클릭과 같음**:
    - §2 ⓐ대로 메뉴 클릭에 경고가 없으니 뒤로 가기도 경고가 없습니다.
    - **"경고가 뜨면 [취소] 뒤에도 그대로"는 해당 경고가 없어 지금은 시험할 대상이 없습니다.**
    - 경고를 붙이는 날을 위한 자리(`openNavItem` false → 주소 복원)만 마련했습니다.
11. **탭 10개·닫기·닫힌 화면으로 뒤로**:
    - 탭 클릭은 `openNavItem` → `routeSync`로 push입니다.
    - 활성 탭 닫기는 `closeNavTab` 래퍼가 교체로 처리합니다.
    - 닫힌 화면으로 뒤로 가면 `openNavItem`이 탭을 다시 엽니다.
    - 탭이 가득 차면 'full'이라 `routeSettleHash`가 주소를 지금 화면으로 되돌립니다.
12. **탭 제목**: `routeTitle`이 화면 이름을 읽고(소개·로그인은 router의 이름), `syncNavActive`와 덮개 변화마다 갱신합니다.

## 6. 보안 필수 규칙 이행 표
| 규칙 | 이행 위치 |
|---|---|
| ⓐ 대응표 `has` 통과 값만, 진입은 `openNavItem` 하나 | `router.parse`가 표를 통과한 이름만 돌려줍니다. `routeOpen`이 `openNavItem(id)` 하나로 엽니다. 직접 click은 내 정보 한 곳이며, 근거는 `wireLogin`의 ⚙ 단추와 같은 기존 경로이고 account 세션만 허용하는 것입니다(시험이 click 1곳임을 고정). |
| ⓑ 세션 확인 + `/menus` settled 뒤 해석 | `applyRoute`가 `settled !== false`와 `loadSession()`을 확인하고, `applyHome`과 같은 호출 지점(`paintTabs`)에서 합니다. `pendingRoute`는 `pendingHome` 패턴입니다. |
| ⓒ 되돌아갈 화면은 메모리, 이름 형식 | `routeNext`는 `let` 변수만 씁니다(시험: storage 금지). 형식은 `HASH_RE`이고 `^[a-z][a-z0-9-]{0,31}(/…)?$`와 같습니다. 디코드는 하지 않습니다. |
| ⓓ hashchange·pageshow 재확인, 로그아웃 replace | `onRouteHash` 첫머리 `loadSession()`입니다. `pageshow`는 `persisted`일 때 호출합니다. 로그아웃은 `location.replace`입니다. |
| ⓔ 주소 값을 innerHTML·선택자에 안 넣음 | glue 안에 innerHTML·querySelector가 없고(시험으로 금지) 선택자는 상수 id만 씁니다. |
| ⓕ 해석 실패는 예외 없이 시작 화면 | `parse`/`format`/`resolve`는 예외를 내지 않습니다(시험). 실패 분기는 `routeFallback`입니다. |
- 다른 탭 로그아웃 전파(`storage` 이벤트 수신)는 security가 "권장"으로 둔 기존 문제라 이번에 넣지 않았습니다.

## 7. 위험·되돌리는 법
1. **현황판 초안 소실**: 기존 문제입니다. 뒤로 가기·즐겨찾기로 오가면 더 자주 만날 수 있어 체감이 커질 수 있습니다. 근본 대책은 `kbb.draftCount`를 쓰는 메뉴 이동 경고입니다(별도 항목).
2. **`pendingHome`과 주소의 충돌**: 주소가 연 화면이 있으면 `pendingHome = false; flushOverdue()`로 시작 화면 자동 열림을 건너뜁니다. 경과 요약 팝업은 그대로 뜹니다. 지도 주소(`#/notice-forecast`)도 시작 화면이 덮지 않습니다(의도).
3. **guest의 로그인 덮개는 주소를 안 씁니다**: guest가 [로그인] 칩으로 연 로그인 화면은 세션이 있어 `#/login`을 쓰지 않습니다. 뒤로 가기로 덮개를 닫는 길을 만들려면 `app.hideLogin` 같은 공용 함수가 필요한데 범위를 넘습니다.
4. **권한 응답이 영영 실패**(`settled === false` 유지): `routeReady`가 false로 남아 주소가 갱신되지 않습니다. 화면 동작에는 영향이 없습니다.
5. **`#/intro` 위에서 로그인 유무**: 로그인한 채 `#/intro`는 랜딩이 앱 위를 덮고, 뒤 앱은 `setBehindInert`로 막습니다. landing.js가 login-view만 inert하던 기존 동작에 더한 것입니다.
6. **탭 이동의 기록 칸**: 탭 클릭은 기록 1칸(planner 권장안)이라 탭을 많이 오가면 뒤로 가기 수가 늘어납니다. 팀 판단으로 바꾸기 쉽습니다(`routeSync`의 push 조건).
7. **추측**: ① `recordScreen`이 `myinfo`를 서버가 받는지(위 ⓑ). ② Chrome/Edge 105에서 `location.replace('#/…')`가 같은 문서 교체로 동작한다는 것. 표준 동작이지만 실제 확인은 못 했습니다.
- **되돌리기**: index.html의 script 한 줄 삭제 → app.js A1~A6 되돌림 → landing.js 두 곳 되돌림 → 새 파일 2개 삭제. `root.router`가 없으면 `applyRoute`가 곧바로 `applyHome(settled)`를 부르므로, router.js만 빼도 기존 동작으로 돌아갑니다(안전판).
