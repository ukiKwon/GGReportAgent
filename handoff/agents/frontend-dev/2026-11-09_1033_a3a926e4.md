**1. 바꾼 부분**
- `frontend/js/board-write.js`
  - 1050줄 근처에 순수 함수 `bw.srcScrollTop(barBottom, anchorTop)`을 추가했습니다. `max(작성 바 bottom, 기준 top)`을 정수로 돌려주고, NaN이면 0으로 처리합니다.
  - 같은 위치에 `bw.needsOcclusionFix(inTables, inFixed)`도 추가했습니다. 표 영역 안이고 고정 영역(작성 바·원본 패널·상태 줄) 밖일 때만 true입니다.
  - `measureSrc`(약 1412줄)의 `--bd-scroll-top` 계산을 바꿨습니다. 기존에는 `max(bar.offsetHeight, src.top)`이었습니다. 이제는 `bw.srcScrollTop(bar.getBoundingClientRect().bottom, (grid||src).getBoundingClientRect().top)`입니다.
  - `onFocusIn`(약 1856줄)에 `else if` 분기를 추가했습니다. 칸이 아닌 요소(예: '이 표 복사')에 포커스가 가면, 표 영역 안이고 고정 영역 밖일 때만 `keepVisible(t)`을 부릅니다. 선택은 바꾸지 않습니다.
- `frontend/index.html` 384줄 앞에 CSS 규칙을 추가했습니다. `.bd-w-tables`의 button·input·select·textarea·a[href]에 칸과 같은 `scroll-margin-top`·`scroll-margin-bottom`을 줍니다. Tab 이동 때 브라우저 자체 스크롤도 같은 여백을 쓰게 하려는 것입니다.
- `frontend/test/board-write-focus.test.js`에 테스트 2건을 추가했습니다(`표 A 칸 이름` 테스트 앞).
  - `srcScrollTop`: 값 케이스 6개, 같은 입력을 반복해도 값이 같은지, 소스가 `grid||src`와 `bw.srcScrollTop(...)`을 쓰는지, `offsetHeight` 혼용이 없는지를 확인합니다.
  - `needsOcclusionFix`: true/false 케이스, `onFocusIn` 소스 확인, 버튼 분기가 선택을 바꾸지 않는지, CSS `scroll-margin`이 있는지를 확인합니다.

**원인 판단과 고정점**
- 패널 자신의 top을 기준으로 재면, 패널이 sticky 컨테이너 끝에 밀려 올라갈 때 높이와 top이 서로를 바꿔 위로 기어오릅니다.
- 이제 기준을 같은 줄에서 시작하는 격자(grid)의 top으로 바꿨습니다. 격자 top은 패널 높이와 무관하므로, 같은 스크롤 상태라면 계산 결과가 같습니다.
- 하한은 작성 바 bottom(뷰포트 좌표)이라 단위 불일치도 사라집니다.
- 929 stacked는 `max-height:30vh` 규칙이라 `--bd-scroll-top`을 쓰지 않아 영향이 없습니다.
