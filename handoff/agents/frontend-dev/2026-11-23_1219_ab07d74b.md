## 2. 원인 요약
- **P2-1**: `fresh()`가 `seq:0`으로 시작합니다(395-396). `load()`는 `token = ++B.seq`로 번호를 받고(536), `token !== B.seq`로 응답을 거릅니다(539·553). `pb.reset()`이 B를 통째로 바꾸면(754) 카운터가 0으로 돌아갑니다. 이전 계정의 늦은 응답(token 1)이 새 계정 첫 요청(token 1)과 같은 번호가 되어 통과합니다.
- **P3-1**: `pb.reset()`이 `B = fresh()`를 먼저 하고 `closeMenu(false)`를 부릅니다(754→756). 그 시점에 `B.menu`가 null이라 `closeMenu`가 첫 줄에서 반환하고(613), `menuEl`이 그대로 남습니다.
- **P3-2**: `load()` 성공 시 `B.data`가 새 객체로 바뀝니다(540). 그런데 진행 중이던 `save()`의 then/catch는 클로저로 잡은 옛 `row`에 씁니다(658·667). 그래서 화면은 새 데이터인데 저장 결과가 반영되지 않습니다.
- **prep.js 확인(수정하지 않음)**: 같은 문제입니다.
  - `freshState()`가 `seq: 0`입니다(924-927).
  - 요청은 `token = ++S.seq`(1143)로 번호를 받고 `token !== S.seq`(1158·1163)로 거릅니다.
  - 계정이 바뀌면 `S = freshState()`로 카운터가 0이 됩니다(1745·1761·1776).
  - `S.seq += 1`로 무효화하는 곳(1006)은 같은 S 안이라 괜찮습니다.
  - 같은 방식으로 모듈 변수 카운터로 고치면 됩니다. NEXT에 올릴 항목으로 이관 메모에 적었습니다.

## 3. 구현안
적용 순서는 시험 먼저, 구현은 그 다음입니다. 시험을 먼저 돌리면 T8·T9가 현재 코드에서 실패해야 정상입니다.

### 패치 A — 요청 번호를 모듈 변수로 (P2-1)
`frontend/js/prepboard.js`
```
old:
  let B = fresh();
  let wired = false;
new:
  let B = fresh();
  let reqSeq = 0;   // 요청 번호는 B 밖에서 단조 증가 — reset으로 B가 바뀌어도 옛 응답 번호와 겹치지 않는다
  let wired = false;
```
```

new:
    const token = B.seq = ++reqSeq;
```
`fresh()`의 `seq: 0`은 그대로 둡니다. reset 직후 B.seq는 0이고 어떤 token도 0이 아니므로 옛 응답은 모두 버려집니다.

### 패치 B — reset에서 메뉴를 먼저 닫기 (P3-1)
`frontend/js/prepboard.js`

### 시험 — `frontend/test/prepboard.test.js` 파일 맨 끝에 추가
기존 시험은 모두 순수 함수와 소스 정적 검사입니다. DOM 모의 시험은 이번이 처음이라 작은 모의 환경을 같이 둡니다.
- `wired`와 `menuEl`이 모듈 안에 한 번만 만들어져 캐시됩니다. 그래서 환경 객체는 파일 안에서 하나만 만들어 시험 사이에 재사용합니다.
