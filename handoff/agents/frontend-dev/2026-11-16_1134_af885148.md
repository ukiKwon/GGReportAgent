### 2. 현재 동작과 요구 요약
- `serve.js`가 405를 돌려주는 곳은 `/api/questions`(50줄) 한 곳뿐입니다.
- `/api/state`는 `req.method === 'POST' && url === '/api/state'`일 때만 처리합니다(28줄). 다른 메서드는 정적 서빙으로 떨어집니다.
  - `PUT /app.js`, `POST /app.js`, `OPTIONS /`는 200으로 파일을 돌려줍니다.
  - `DELETE /api/state`는 404입니다.
  - `/api/version`에도 메서드 검사가 없습니다.
- 규칙(`/api/questions` 405와 일관되게):
  1. Host 검사(403)가 먼저입니다. 기존 순서를 유지합니다.
  2. 알려진 표준 메서드(GET HEAD POST PUT DELETE PATCH OPTIONS TRACE CONNECT) 밖이면 501입니다.
  3. `/api/state`는 POST만 허용하고, 그 밖은 405에 `Allow: POST`를 붙입니다.
  4. `/api/questions`는 현행 그대로(405, `Allow: GET, HEAD`)입니다.
  5. 그 외 모든 경로(`/api/version`, 정적 파일, 없는 경로)는 GET·HEAD만 허용하고, 그 밖은 405에 `Allow: GET, HEAD`를 붙입니다. 405가 404보다 먼저입니다.
- `app.js`가 `/api/state`를 호출하는 곳은 POST 하나뿐입니다(1121줄). GET `/api/state`를 405로 바꿔도 화면은 영향이 없습니다. 이전에는 404였습니다.
- 501 시험에는 `FOO` 같은 이름을 쓸 수 없습니다. Node의 http 파서(llhttp)가 모르는 메서드 이름은 400으로 먼저 끊기 때문입니다. 파서가 받아 주는 `PROPFIND`로 시험합니다. 실제로 501이 나는 것은 이런 "파서는 알지만 우리가 안 쓰는" 메서드입니다.

### 5. 위험·되돌리는 법
- `GET /api/state`가 404에서 405로 바뀝니다. 화면은 이 경로를 GET으로 부르지 않아서 영향이 없습니다.
- 정적 경로의 PUT·POST·OPTIONS가 200·404에서 405로 바뀝니다. 대시보드 화면에는 영향이 없습니다.
- `hook.js`가 상태를 파일로 직접 쓰고 서버를 부르지 않는지는 이번에 확인하지 않았습니다. 서버를 부르는 곳이 있으면 POST `/api/state`만 쓰는지 확인이 필요합니다.
- 되돌리는 법은 `git checkout agent-dashboard/serve.js agent-dashboard/test/server.test.js`입니다.
- 서버 프로세스가 구버전 코드로 떠 있으면 재기동해야 반영됩니다. 시험은 사본을 새로 띄우므로 영향이 없습니다.
