## 2. 원인/요구 요약과 설계 결정
- **현재 구조**
  - 순위표 카드·마커 클릭은 `render.showPopover`(작은 요약 카드)를 연다. 카드는 render.js 828줄, 키보드 Enter는 837줄, 마커는 `render.onMarkerClick` 976줄에 있다.
  - 현황판 상세는 `dash.paneHtml(it, ctx)`(순수 함수)가 만든다. 하지만 `renderPane`·`doConfirm`·`onClick`이 현황판 상태 `st`·`host`·`M`에 묶여 있어 그대로 재사용할 수 없다.
  - 상세 칸에 쓰는 기관 한 건(`it`)은 `dash.model` 안에서만 만들어진다. 날짜 미상 기관은 `it` 자체가 없다.
- **결정 1. 분리 방식**
  - `paneHtml`·`actHtml`은 그대로 재사용하되 옵션 칸만 더한다. 기본값은 기존과 같아서 현황판 출력은 바뀌지 않는다.
  - 새 진입점은 `dash.itemForRec(rec, today)`, `dash.openDetail(rec, {opener})`, `dash.closeDetail(refocus)`다.
  - `renderPane`·`headSection`·`headEnv`는 건드리지 않는다. `head-card.test.js:597·600`이 소스 문자열을 단언하고, 현황판 회귀 위험도 0으로 두려는 뜻이다. 모달은 자기 상태 `dm`과 자기 맥락 함수(`dmRender`·`dmHeadEnv`)를 쓴다. 중복은 약 8줄이고, 현업 검토가 끝난 뒤 합칠 수 있다.
  - `doConfirm`의 오류 문구 계산만 `dash.confirmFail(x)`로 뽑아 모달과 같이 쓴다.
- **결정 2. 지도 쪽 진입**
  - 클릭하면 바로 모달을 연다. 이를 위해 `render.openRecord(rec, opener, x, y, opts)`를 새로 두고, 대시보드 모듈이 없으면 예전 팝오버로 되돌아간다(안전장치).
  - 팝오버 코드(`showPopover`·`popoverHtml`·`prep.decoratePopover`·`headcard.decoratePopover`)는 **지우지 않는다.** 클릭 배선만 바꾼다.
    - 이유: 테스트가 많이 걸려 있다(`head-card.test.js:1007~1090`, `prep.test.js:354·630~682`). 되돌리기도 3곳만 원복하면 된다.
    - 정리(삭제)는 현업이 모달 모양을 확정한 뒤 `cleaner`가 한다.
    - 오늘 넣은 [기관장 보기]는 모달에 기관장 카드가 있어 쓸 곳이 없어진다. 코드는 두되 호출만 끊긴다.
  - 팝오버에만 있던 기능은 모달에서 이렇게 살린다.

| 팝오버 기능 | 모달에서 |
|---|---|
| [제안 확정]·[사전준비 열기] | 현황판 `actHtml`과 같은 하단 줄. 제안 진행 중인지는 모달이 열릴 때 `/preps`를 받아 정하고, 받는 동안은 '진행 상태를 확인하는 중입니다' 안내를 둔다. |
| [편집] | 하단 줄 [편집]. 누르면 상세 팝업을 닫고 `app.openEdit(rec)`를 연다. 편집 창(`#edit-modal`)이 상세 팝업보다 DOM에서 앞이라 z-index 30이 같으면 가려지기 때문이다. 저장하면 지도가 다시 그려져 상세 내용도 낡는다. |
| 원본 정보(`<details>`·누락 칸 알림) | 상세 맨 아래에 같은 접이식으로 둔다. 이를 위해 `render.popRawHtml(rec)`를 `popoverHtml`에서 뽑는다(출력은 같다). |
| [전국 지도에서 보기] | 뺀다. 그 자리에 [닫기]를 둔다. |

- **결정 3. 기관장 자동 조회(열람 감사)**
  - 모달을 열면 현황판과 같은 규칙(`headcard.ensure`, 0.4초 debounce 뒤 한 번)으로 자동 조회한다. 모달은 사용자가 그 기관을 카드나 마커로 **명시적으로 누른 결과**다. 모달이 떠 있는 동안 지도를 훑을 수 없고, 0.4초 안에 닫으면 읽지 않는다. 그래서 오늘 정한 "팝오버는 자동 조회 금지"(지도를 훑을 때 기록이 쌓이지 않게)와 충돌하지 않는다고 판단한다. 다만 지도 카드를 연달아 눌러 보면 현황판보다 기록이 빨리 쌓일 수 있으니 열린 질문 1번에 올린다.
  - 화면 ID는 서버 변경 없이 기존 허용값 **`map_popover`**(`HeadUiIds.SCREENS`에 있음)로 보내고, 버튼은 기존 `open_card`·`refresh`다. 기관장 **편집·추가 요청**(모달 안 편집 팝업)은 지금처럼 `head_card`로 남는다.
  - 감사 기록의 화면 이름이 "팝오버"로 남는 불일치는 `map_detail` 같은 새 이름을 서버에 추가하면 풀린다(이관 메모 참조).
  - 비영업 역할·정적 모드·서버에 없는 기관은 `headcard.gate`가 서버 호출 없이 기존 안내 문구를 보여 준다.
- **headcard가 한 번에 한 기관만 쥔다는 점(싱글톤 V)**
  - 모달이 열리면 `ensure`가 상태를 새로 잡는다(현황판의 기관장 상태·repaint는 버려짐).
  - 닫을 때 `headcard.reset()`을 부른다. 현황판은 다시 열릴 때 `mount`→`ensure`로 다시 읽으므로 문제없다.
  - 로그아웃·계정 전환 때는 `app.onProfileChanged`에서 모달도 닫는다(8번 패치).
- **숨은 현황판과의 id 중복**
  - 현황판이 한 번이라도 열렸으면 `#dash-root`(display:none)가 DOM에 남아 `#db-name`·`#hc-sec`·`#db-cf` 같은 id가 중복된다.
  - 모달 제목 id는 `dm-name`으로 바꾸고(`ctx.nameId`), 모달 안 조작은 전부 모달 요소 기준으로 찾는다.
  - 기관장 편집 창이 닫힐 때의 포커스 복귀 대체 경로(`closeModal`)는 `#dm-box` 안을 먼저 찾도록 고친다(5번 패치).
- **겹침(z-index)**
  - 기관장 편집 창(`hc-ov`, `.modal-overlay` z 30)은 `document.body`에 나중에 붙으므로 같은 z-index에서 상세 팝업 위에 뜬다. 두 오버레이는 형제라서 편집 창의 Esc·Tab이 상세 팝업의 핸들러로 올라가지 않는다. 편집 창이 닫히면 눌렀던 버튼으로, 그 버튼이 다시 그려져 사라졌으면 `#dm-box` 안의 같은 뜻 버튼으로 돌아간다.
  - 지도의 문서 클릭 핸들러(render.js 1041줄)는 팝업·편집 창 안의 클릭을 '빈 곳 클릭'으로 보고 지도 선택 강조를 풀어 버린다. `.dm-ov, .hc-ov`를 제외해서 닫은 뒤에도 보던 카드·마커 강조가 남게 한다.
- **참고: 현황판 기존 버그 하나**
  - `doConfirm`의 `(known && (known.message || known))`에서 `prep.ERR_BY_CODE`의 값은 `{text: …}` 모양이라, 이 경로로 가면 `String(object)`가 되어 "[object Object]"가 화면에 나올 수 있다(`PREP_ALREADY_ACTIVE`는 앞에서 걸러진다).
  - `confirmFail`에서 `known.message || known.text`로 고친다. 현황판에도 적용되는 **유일한 동작 변화(버그 수정)** 이고, 원치 않으면 `known.text`를 빼면 된다.

그리고 `function doConfirm() {` **바로 앞**에 추가:
```js
  // [제안 확정] 실패 응답 → { again: 이미 진행 중이라 목록을 다시 받아야 함, msg: 화면 문구 }. 현황판·지도 상세 팝업 공용.
  dash.confirmFail = function (x) {
    const e = root.errtext ? root.errtext.parse(x.body && x.body.detail) : { code: '', message: '' };
    if (e.code === 'PREP_ALREADY_ACTIVE') return { again: true, msg: '' };
    const known = root.prep && root.prep.ERR_BY_CODE && root.prep.ERR_BY_CODE[e.code];
    const msg = (known && (known.message || known.text)) || e.message ||
      ((x.r.status === 401 || x.r.status === 403) ? '제안 확정 권한이 없습니다(' + x.r.status + '). 로그인 사번과 권한을 확인하세요.'
        : '제안 확정하지 못했습니다(' + x.r.status + '). 잠시 뒤 다시 시도하세요.');
```

## 5. 위험·되돌리는 법
- **감사 기록량**: 팝업을 열 때마다 기관장 열람 기록이 남는다(디바운스 0.4초). 지도 카드를 연달아 눌러 보는 사용에서 현황판보다 기록이 빨리 쌓일 수 있다. 완화책은 열린 질문 1번에 있다.
- **headcard 싱글톤**: 현황판과 팝업이 상태를 공유한다. 팝업을 닫으면 `reset`으로 비워지고, 현황판이 보일 때는 팝업이 열릴 수 없다(오버레이가 막는다). 현황판이 `display:none`으로 남아 있어도 팝업을 닫은 뒤 현황판으로 돌아가면 `mount`가 다시 읽는다.
- **id 중복**(`#hc-sec`, `#db-cf-t` 등): 숨은 현황판이 있으면 중복이다. 팝업 안 조작은 전부 팝업 요소 기준이고 제목·포커스 복귀는 `dm-*`로 분리했다. 남는 틈은 현황판이 확정 확인 줄을 연 상태에서 지도 팝업이 열리는 극히 드문 경우의 `aria-labelledby="db-cf-t"` 하나뿐이다(음성 안내 이름이 틀릴 수 있음).
- **`confirmFail` 버그 수정**이 현황판에도 적용된다(위 2항). 원치 않으면 `known.text`만 뺀다.
- **날짜 미상 기관**: `it.unknown` 항목은 이번에 새로 생겼다. 현황판은 이 항목을 만들지 않아 영향이 없다.
- **되돌리기**
  - 가장 빠른 방법: render.js C-3의 세 호출을 `render.showPopover(...)`로 원복하면 예전 요약 카드로 복귀한다. 나머지 패치는 사용되지 않는 채로 남는다.
  - 완전 원복: 패치 A~E를 역순으로 되돌리고 `map-detail.test.js`를 지운다.
- **팝오버 잔존 코드**는 호출만 끊긴다. 모달 확정 뒤 `cleaner`가 `showPopover`·`decoratePopover` 계열 정리를 검토한다.
