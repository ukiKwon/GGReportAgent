## 입찰 현황판 1단계 구현 보고

테스트는 실행하지 못했습니다(Bash 없음). 구현은 지시대로 했지만, 요청하신 `frontend/data/kb-verified.js`는 만들지 않았습니다. 아래 "벗어난 판단" 1번을 봐 주세요.

### 1. 고친 파일
- **새 파일 `frontend/js/dashboard.js`**: `root.dashboard = {mount(el), unmount(), ...순수 함수}`. node에서는 `module.exports`로 내보냅니다.
  - 순수 함수:
    - `model`, `regionOptions`, `typeOptions`, `showTypeFilter`, `filterItems`
    - `kbCount`, `kbKeys`, `kbEntry`, `progressCount`, `activePreps`
    - `actionKind`, `josaEul`
    - `rowHtml`, `rulerHtml`, `stripHtml`, `statsHtml`, `footHtml`, `blankHtml`, `paneHtml`, `actHtml`
  - 쓰는 `logic` 함수: `dedupeByInstitution`, `effectiveBid`, `overdueSummary`, `isDateUnderReview`, `daysUntil`, `instKey`, `confidenceLabel`. 새 판정 로직은 만들지 않았습니다.
  - DOM 동작:
    - listbox 키보드: ↑↓ Home End가 선택을 따라가고, Enter는 `#db-name`으로 포커스를 옮깁니다.
    - 첫 진입에 자동 선택하지 않습니다.
    - 경과 행도 선택하면 상세가 열립니다.
    - **'공고 예정일 경과' 묶음은 기본으로 펼침**입니다(`st.pastOpen = true`). 1년 안 목록 아래에 놓았습니다.
  - 제안 확정 흐름:
    - [제안 확정]은 확인 줄을 거칩니다(Esc와 [취소]로 되돌아가며 포커스가 돌아옵니다).
    - [확정하기]는 `POST /preps {institution_id}`를 보냅니다.
    - 성공하면 `prep.SOON_ID`로 이동하고 `prep.openCase`를 부릅니다.
    - `PREP_ALREADY_ACTIVE`이면 새로 불러와 [사전준비 열기]로 바뀝니다.
    - 그 밖의 오류는 `errtext.parse` 결과와 `prep.ERR_BY_CODE`로 안내하고, 없으면 401/403용 기본 문구를 씁니다.
  - 불러오기와 오류 문구:
    - `/preps`와 `/workflow/overview`를 따로 받습니다. 둘 중 하나가 401/403이어도 나머지로 띠 3을 그립니다. 둘 다 401/403이면 권한 안내를, 실패면 [다시 시도]를 보입니다.
    - file:// 모드에서는 "서버에 연결하면 보입니다."와 파일 모드 안내를 보입니다.
    - 서버 병합이 실패해 내장 자료만 보일 때는 role=alert 배너와 [다시 불러오기]를 보입니다.
- **`frontend/index.html`**
  - CSS 블록에 `/* 입찰 현황판 시작 … 끝 */` 주석을 둘렀습니다. `</style>` 바로 앞이고 `.db-*` 클래스를 담았습니다.
    - 새 hex는 없고, 입력창은 건드리지 않았습니다.
    - hover는 `color-mix(var(--accent-color) 6%)`를 씁니다.
    - `#dash-root`에 flex 규칙을 CSS로만 더했습니다. 마크업은 건드리지 않았고, 인라인 `display:none` 토글은 그대로 동작합니다.
  - 스크립트 태그를 `js/prep.js` 바로 아래에 추가했습니다.
    - `<script src="data/kb-verified.js"></script>`
    - `<script src="js/dashboard.js"></script>`
    - `js/app.js`보다 앞이고, `prep.js` 태그는 다른 세션이 이미 둔 것을 그대로 썼습니다.
- **새 파일 `frontend/test/dashboard.test.js`**: 테스트 21개입니다.
  - 구간 경계 0·30·31·90·91·180·181·182·183·365·366, 182일 빨강과 183일 주황
  - 경과·미상 집계와 수원 4구 중복 제거
  - 확정·확인 중·자료 수정 집계
  - 1년 안 0곳 때의 띠와 꼬리 문구
  - 종류 필터 숨김, `regionOptions`, `filterItems`
  - `kbCount` 3건(목록 없음 / 키 매칭 / 실제 데이터)
  - `progressCount` 2건(중복 제거 / 권한 밖 null)
  - 버튼 행렬(역할 × 활성 건 × 서버 모드 × prep 유무)
  - `actHtml` 문구, 조사 `josaEul`
  - 상세의 금고 순번(slot) 표시, `<script>` 이스케이프, 경과 행
  - 11px 미만 글자·새 hex 없음, 스크립트 태그 순서

### 3. 지시에서 벗어난 판단
1. **`frontend/data/kb-verified.js`를 만들지 않았습니다.** 제 규칙이 `frontend/data/` 수정을 금지해서, 메인이 직접 만들어 주세요.
   - **내용**: 호출자가 지정한 6개 항목입니다.
     - 맨 위 주석: "출처 문장으로 확인한 곳만(data-auditor 2026-11-11). 현 약정 기준. 72 약정 기록이 생기면 대체"
     - 형식: `(function(root){ root.KB_VERIFIED = [...]; if (typeof module!=='undefined' && module.exports) module.exports = root.KB_VERIFIED; })(typeof window!=='undefined'?window:globalThis);`
     - 항목: `{key:'26|부산광역시', name:'부산광역시', slot:2, quote:'현 약정 2025-01-01~2028-12-31 · 1금고 BNK부산은행 · 2금고 KB국민은행', src_date:'2024-09-24'}` 등 6개를 그대로 넣으면 됩니다.
   - **키 확인**: `logic.instKey = region + '|' + name`이고, `dedupeByInstitution`도 같은 키를 씁니다. 번들에서 `region:"26"`, `name:"부산광역시"`가 실제로 있음을 확인했습니다. 서울 5구는 코드 `11`입니다.
   - **index.html**: 이 파일이 아직 없어서 브라우저 콘솔에 404가 한 번 납니다. 파일을 만들면 사라지고, 화면은 "확인 0곳"으로 정상 동작합니다.
2. **띠 1의 "확인 n"은 1·2금고를 합쳐 셉니다.** `kbCount(list, root.KB_VERIFIED)`가 세고, 키는 문자열 또는 `{key}` 객체를 모두 받습니다. 상세의 "현재 금고 은행"은 검증된 기관이면 "KB국민은행 · {slot}금고(slot이 있을 때만)", 근거 문장, 출처 기준일을 보입니다. slot이 null이면 순번을 표시하지 않습니다. 약정 기간은 계속 [미확인]입니다.
3. **`prep.js`는 디스크에 아직 없습니다.** `root.prep`이 없으면 `actionKind`가 `'unavailable'`을 돌려주고, 상세 바닥에 "서버에 연결되면 [제안 확정]을 쓸 수 있습니다."만 보입니다(버튼 없음).
   - `popoverAction`의 반환 모양을 몰라서 문자열이나 `{kind|action|type}`(`open`·`열기` / `confirm`·`확정` 포함)을 모두 받는 어댑터를 썼습니다.
   - `actives`에는 `/preps` 중 `state_cd≠CANCELLED`만 넘깁니다. `/preps` 조회가 실패하면 빈 배열입니다.
   - ctx는 `{serverMode, role: 프로필 team, session}`입니다.
4. **띠 3 계산**: 같은 기관은 한 번만 셉니다.
   - 사전준비는 활성 건입니다.
   - 제안서 작성은 overview 항목 중 `!done`이고 `state≠NONE`이며, 사전준비에 이미 셌던 기관은 뺀 것입니다.
   - 합계는 둘의 합입니다. 이 "진행 중"의 정의는 기획 확인이 필요합니다.
5. **조사 을/를은 이 파일 안의 지역 함수 `dash.josaEul`입니다.** 공용 모듈에는 없고 `board-write.js`의 `bw.josaEul`만 있어서, 그 파일을 끌어오지 않았습니다. 공용화(NEXT P2-5)되면 이 지역 함수를 지우면 됩니다.
6. **영업부장에게는 "제안 확정은 영업팀·영업팀장이 합니다." 한 줄을 보입니다.** 시안과 같습니다. 버튼은 없습니다.
7. **목록 행·상세의 지역 표시는 시·도 이름만입니다(`render.REGION_NAME`).** `subRegion`은 코드라 이름이 아니어서 시군구를 따로 붙이지 않았습니다. 기관명에 이미 시·군·구가 들어 있습니다.
8. **목록 꼬리 문구에 한 문장을 더했습니다.** "입찰이 1년 뒤인 n곳도 목록에 없습니다."입니다. 1년 밖 기관이 조용히 사라지지 않게 하려는 것입니다.
9. **`ov-stamp`에 시계 글리프는 붙이지 않았습니다.** "D+n" 글자와 채운 잉크 칩만 씁니다.
10. **상세의 "임직원 수" 줄은 뺐습니다.** 레코드에 그 값이 없습니다.
11. **컨테이너 처리**:
    - `#dash-root` 안에 `mount`가 `<section id="db-root">`를 직접 만듭니다.
    - `mount`는 호출될 때마다 DOM을 다시 짓고 데이터를 새로 불러옵니다(`openNavItem`마다 새로고침됩니다).
    - 필터와 선택 상태는 모듈 변수에 남습니다.

### 4. 다른 세션(app.js 등)이 연결해야 할 것
- **`mount` 호출은 이미 연결돼 있습니다.** `app.showSoon`이 `root.dashboard.mount(dashEl)`을 부릅니다. `dashboard.js`가 로드되면 `dashReady`가 켜집니다.
- **`unmount()`는 아직 아무도 부르지 않습니다.** 필요하면 다른 화면으로 갈 때 부르면 됩니다. 안 불러도 문제는 없습니다.
- **`root.prep` 계약**(prep.js가 맞춰야 함):
  - `prep.popoverAction(rec, ctx, actives)`
  - `prep.SOON_ID`
  - `prep.openCase(bid_case_id)`
  - 선택으로 `prep.ERR_BY_CODE[code]`(문자열 또는 `{message}`)
  - `/preps` 응답 필드는 snake_case(`institution_id`, `state_cd`, `bid_case_id`)와 camelCase를 둘 다 받습니다.
- **`app.bootstrapServer()`는 Promise를 돌려줘야 합니다.** [다시 불러오기]가 이 값에 의존합니다. 지금 코드는 이미 그렇습니다.
- **마지막 탭을 닫았을 때 현황판으로 돌아가기, 로그인 첫 화면, 경과 팝업 생략은 건드리지 않았습니다.** 다른 세션 담당입니다.
- **`design_history` ⑰ 장**: 시안의 6-F 초안이 있으니 메인이 숫자를 채워 추가해 주세요. 푸시 전 관문 항목입니다.

### 6. 위험·되돌리는 법
- 되돌리려면 `index.html`에서 CSS 블록(시작/끝 주석 사이)과 스크립트 태그 2줄을 지우고 `dashboard.js`와 `dashboard.test.js`를 삭제하면 됩니다. 그러면 `app.showSoon`은 "입찰 현황판은 준비 중입니다." 안내로 돌아갑니다.
- `index.html`은 다른 세션도 편집하고 있어서 줄 번호가 움직입니다. 저는 문자열 기준으로만 고쳤습니다.
- 브라우저에서 실제로 열어 본 적은 없습니다. 배치·키보드는 시안으로만 확인된 상태이므로, 로그인한 화면에서 한 번 확인해 주세요.
