## 대상·방법·못 본 것
읽은 곳: `frontend/js/board-write.js`(검수·초안·원본 패널·상태 줄), `frontend/index.html` CSS(163~415행), 서버 `BoardWrite*.java`(grep만), 테스트는 건수만 셈. 못 본 것: 서버 `BoardWriteService`가 응답에 sources·값을 만드는 세부, 테스트 본문 전체, 실제 화면(Playwright 안 씀). 아래 줄 번호는 지금 파일 기준.

## 1. '검수'·'확인했음'의 모양과 조건
- **'검수 n/m' + '확인했음' 체크박스**: 요약·필터 줄 아래, 표 격자 위의 한 줄(`bw.reviewHtml`, board-write.js:842~854, 조립은 `writeHtml` :1190). DOM id는 `#bd-w-count`, `#bd-w-done`(체크박스), `#bd-w-donewhy`(안내). CSS는 `.bd-w-rev`·`.bd-w-count`·`.bd-w-donelab`·`.bd-w-chip.is-done`(index.html:297~306).
- **'검수 n/m'의 n·m**(`bw.tally`, :440~461): m은 작성본의 모든 값 칸 수(`eachCell`)이고, n은 `c.checked`인 칸 수다. **칸 하나하나에 '확인'을 눌러야 n이 오른다.**
- **'확인했음' 활성화**: `ok = y.m>0 && y.n===y.m`일 때만 켜진다. 아니면 `disabled`이고 안내문은 "모든 칸을 확인하면 선택할 수 있습니다(남은 칸 N)"(:843, :850, :852). 사용자가 느낀 "각 칸을 확인해야 '확인했음'이 뜬다"는 이 코드가 맞다.
- **칸 단위 '확인' 버튼**은 하단 고정 상태 줄(`#bd-w-status`)에 있다. 칸을 선택해야 나타나는 `data-w="check"` 버튼이고(`bw.statusHtml` :1176), 누르면 `toggle`(:1686) → `bw.toggleCheck`(:500)가 `checked`를 뒤집는다.
  - 읽지 못한 빈 칸은 값을 넣기 전에는 확인할 수 없다(:503).
  - 칸 값을 고치면 그 칸의 확인이 풀리고, '확인했음'도 풀린다(`editCell` :737~740, `normalize` :495~499, 알림 문구 :1744).
  - '원본 값으로'(revert)도 같은 경로를 탄다(:1827).
- **'확인했음' 클릭**: `onChange`(:1862~1867) → `bw.setDone`(:506~510). 조건이 맞으면 `ws.done = {who, at}`이 되고, 옆에 "검수 완료 · 이름 시각" 칩이 뜬다(:851). 체크를 끄면 `done`을 null로 만든다.
- **셀의 체크 표시**: 확인한 칸에는 `.is-checked` 클래스와 `CHECK_SVG`가 붙는다(:902, :923).

## 2. 저장 여부와 다른 기능에 미치는 영향 — 화면 표시뿐이다
- **저장 안 함**: 파일 머리 주석에 "확인·수정 표시는 이 화면의 메모리에만 둔다. 브라우저 저장소·초안 요청 본문에 넣지 않는다"(:5)고 적혀 있다. 화면 하단에도 "저장되지 않습니다"가 뜬다(:778).
- **워드 초안에 영향 없음**: `bw.draftBody`(:206~215)는 매핑된 표의 `{ref, cells:{key:value}}`만 보낸다. `checked`와 `done`은 안 들어간다.
- **초안 버튼은 검수와 무관하게 항상 눌린다**: 조건은 `ws && !draftBusy`뿐이다(:775). 미확인 칸이 있으면 완료 문구 뒤에 "확인하지 않은 칸 N개가 포함된 초안입니다"를 덧붙일 뿐이다(`draftDoneText` :235~238).
- **서버는 모른다**: `BoardWrite*.java`에서 checked·done·confirm·검수를 grep했을 때 걸리는 게 없다.
- **'확인했음'(`ws.done`)이 쓰이는 곳**: 체크박스 표시, 완료 칩, 칸을 고쳤을 때 알림 문구 분기(`released`)뿐이다. 막는 기능은 없다. '작성 끝내기'·엑셀 교체 때 `hasWork`(`y.n>0 || y.edited>0`, :462)가 "확인 N칸이 사라집니다" 확인 줄을 띄운다(`leaveText` :515~522).
- **복사 쪽**: 복사 알림에 "확인하지 않은 칸 N개가 그대로 들어 있습니다"를 덧붙인다(`copyExtras` :1255~1265). 막지는 않는다.
- **'확인했음'을 켠 사람·시각도 서버에 안 간다**: `env.who()`로 이름을 받아 `ws.done`에 넣지만 화면에만 쓴다.
- **동작 여부**: 코드상으로는 의도대로 동작한다. 칸 확인 → n 증가 → 전부 확인하면 체크박스 활성화 → 값을 고치면 해제된다. 다만 결과는 화면 표시뿐이다. 테스트 `board-write.test.js`와 `board-write-edit.test.js`에서 done·checked·normalize·toggleCheck·setDone·reviewHtml 관련 단언이 합쳐 33건 잡힌다(count 결과, 이번에 실행은 안 함).

## 3. 화면 두 곳과 '재산상 이익 제공' 패널
- **'원본 수익성 분석표'라는 이름은 코드에 없다.** 화면 상단 막대에 "원본 <엑셀 파일명>(저장 안 됨)"이 찍힌다(:771, 예: 테스트에 `v3 · 원본 수익성.xlsx(저장 안 됨)`). 파일명이 '수익성…'이면 그 글자일 가능성이 크다(추측).
- **오른쪽 패널 = 엑셀 원본 패널**: `bw.sourceHtml`(:1110~1158), `<aside id="bd-w-src">`, 본문 `#bd-w-srcbody`(시트별 `table.bd-w-srctbl`). 머리글자는 "엑셀 원본 · 파일명"이다. 데이터는 서버가 준 `resp.sources[]`(시트·범위·원본 격자, :288)를 `bw.mergeSources`(:956 이후)로 시트별 격자로 합친 것이다. 접기·넓게 보기 버튼이 있다.
- **왼쪽 = 작성본 표 카드들**: `#bd-w-tables` 안에서 `bw.cardHtml`(:925)이 `section.bd-card.bd-w-card`로 그린다. 값 칸은 `valueCellHtml`(:896)이다.
- **'하단 반복 표시'는 `#bd-w-status`(상태 줄)로 추정한다.** `bw.statusHtml`(:1159)이 선택 칸의 비교줄(`bw.compareLine`, `.bd-w-cmp`)·출처·원래 값을 하단 고정 줄에 다시 보여 준다. 그 안에 '확인' 버튼도 있다. 두 곳(우측 패널과 하단 줄)의 값은 같은 `ws`(작성본 값, `c.value`/`c.orig`)와 `c.src`(원본 주소·표시값·raw)에서 나온다. 우측 격자는 서버 원본 격자 셀이다. 하단 줄은 칸 하나의 요약이다. 즉 데이터 출처는 같고 표현만 다르다. 사용자가 말한 '하단 반복'이 이게 맞는지는 화면으로 확인하지 못했다.
- **'재산상 이익 제공' 패널**: 이름은 서버 양식의 표 제목 `title`("재산상 이익제공", 테스트 샘플의 mapping 'A')이다. 코드에 고정된 패널이 아니고 `bw.cardHtml`이 양식 표마다 만드는 `section.bd-w-card`다(제목 `<strong class="bd-w-title">`).
- **현재 글자 크기**: 제목 `.bd-w-title` 13px(index.html:308), 표 본문 `.bd-table` 12px(:168), 주석 `.bd-notes` 12px(:176), 원본 격자 `.bd-w-srctbl` 12px(:341), 상태 줄 `.bd-w-status` 12px(:408), 원본 값 줄 `.bd-w-orig` 11px(:405). 변수 이름은 건드리지 않고 값만 바꿀 수 있다.

## 4. 원본 표를 모달로 옮기고 수정 값을 반영할 때의 제약
- **원본은 읽기 전용이다.** `resp.sources`는 서버가 엑셀을 읽어 준 표시값(`display`)·`raw`·셀 주소다. 원본 격자 셀(`td`)은 문자열을 그대로 찍을 뿐이고 편집 로직이 없다(:1139~1149). 작성본 칸은 `c.value`(현재), `c.orig`(처음 채운 값)로 분리돼 있다(:321).
- **작성본 칸과 원본 칸은 다대일·일대다다.** 여러 원본 칸을 합산하는 `parts`, 억원 환산 `convert`(eok·eok_paren), 표시값 합계 `display_sum`, 직접 입력 칸(`manual`)이 있다(:565~580). 그래서 원본 칸을 고치면 작성본 값이 어떻게 변해야 하는지(재환산·재합산)가 코드에 없다. 서버가 계산한 환산을 클라이언트가 재현해야 한다. 그러지 않으면 "원본 값을 고쳤는데 작성본은 그대로"가 생긴다.
- **이미 있는 수정 경로는 작성본 칸 직접 수정뿐이다.** `bw.editCell`(:731)이 `value`를 바꾸고 `checked`를 풀며, 수정 사유(`why`, :666)를 받는다. 모달에서 원본을 고쳐 반영하려면 저장 위치를 정해야 한다. 가장 가까운 후보는 `c.value`이고(`orig`는 "원본으로 되돌리기 기준"이라 바꾸면 안 됨, 추측), 원본 격자 값(`ws.sources`)을 같이 바꿀지는 별개 결정이다.
- **메모리에만 둔다는 원칙**(:5)과 **초안은 `c.value`만 보낸다**(:211)는 점은 그대로 지켜진다. 서버 변경 없이 가능하다. 원본 격자 자체를 수정하게 하면 초안·서버 재계산과 어긋날 수 있다(서버 쪽 확인은 못 함).
- **바뀔 함수**(구현 방식 추정):
  - `bw.sourceHtml`(:1110) 렌더를 모달로 분리 → `bw.writeHtml`(:1182)의 그리드 구성.
  - `bw.gridClass`·`measureSrc`(:1406)·`scrollSrcTo`·`jumpSrc`·`srcwide`·`panel` 액션(:1802~1812)처럼 우측 패널 레이아웃에 묶인 코드는 모달화하면 대부분 불필요해진다.
  - `bw.statusHtml`·`select`(:1552 근처)는 패널 강조(`is-src`, `selCols`)에 의존한다.
  - 값 수정 입력은 `commitEdit`(:1736)·`bw.editCell`을 재사용하거나 원본용 별도 함수를 추가한다.
  - CSS `.bd-w-src*`, `.bd-w-grid*`(index.html:315~381)를 정리한다.
- **규모(추정)**: 단순히 '패널 → 모달'만이면 JS 약 150~250줄, CSS 약 70줄 변경. 값 수정을 작성본에 연동(환산·합산 재계산 포함)하면 2~3배다. 영향 받는 테스트는 `board-write-src.test.js`, `board-write-parts.test.js`, `board-write-focus.test.js`와, `board-write.test.js`의 원본 패널·상태 줄 단언이다. 정확한 건수는 안 셌다.

## 5. '확인'을 칸 단위에서 표(섹션) 단위로 바꿀 때
- **바뀌는 코드**(board-write.js):
  - 데이터 모델: `c.checked`(:330, 356)를 표 단위 `t.checked`로 이동.
  - `bw.tally`의 n·m·`unchecked` 계산(:440~461).
  - `bw.matches`의 'unchecked' 필터(:436)와 `FILTERS`·`filterHtml` 문구(:490, 836~841).
  - `bw.normalize`·`toggleCheck`·`setDone`(:495~510).
  - `bw.editCell`의 해제 로직(:737~738)과 알림 문구(:1744~1745). 표 단위가 되면 "이 표의 확인 해제"가 된다.
  - `bw.reviewHtml`의 문구(:842~854).
  - `bw.chipsHtml`의 남은 칸 수(:856~869).
  - `statusHtml`의 '확인' 버튼(:1176)은 표 헤더(`cardHtml` :927 head)로 옮긴다.
  - `valueCellHtml`의 `is-checked`·`CHECK_SVG`(:902, 923).
  - `bw.copyExtras`(:1255), `bw.draftDoneText`(:235), `bw.leaveText`/`hasWork`(:462, 515), `bw.cellInfo`/`infoLines`/`cellAria`의 '확인됨/미확인'(:627~630, :709), `act 'check'`/`toggle`(:1686, :1816).
  - CSS는 `.bd-w-ck`, `.bd-w-cell.is-checked`와 표 헤더용 확인 버튼 스타일이 추가·정리된다.
- **서버 영향 없음**(checked가 서버에 안 간다).
- **테스트**: `board-write.test.js`(done·checked 관련 24건 안팎)와 `board-write-edit.test.js`(9건)가 직접 깨진다. 예: `미확인` aria-label 단언(`board-write.test.js:305`), `tally`·`toggleCheck`·`setDone`·`reviewHtml`·`leaveText` 단언. `board-write-copy.test.js`는 `copyExtras`/`copyNote` 문구가 걸린다.
- **규모(추정)**: 로직 ~15개 함수 수정 + 테스트 약 35~45건 수정·갱신. 서버 변경 없음.
- **의미상 결정 필요**: 표 단위로 바꾸면 "칸 값은 안 보고 표만 체크해도 되는" 허술한 검수가 된다. 칸마다 원본 대조를 강제하려던 기존 의도와 달라진다. 이건 기획이 정할 일이다.

## 이관 메모
- [이관: 기획] '검수'를 칸 단위로 둘지 표 단위로 바꿀지, '확인했음'이 문서 생성·제출을 막는지 또는 기록으로 남는지(지금은 화면 표시뿐) — 기다리는 것: 사용자 판단 — 근거: board-write.js:206~215, :775, :842.
