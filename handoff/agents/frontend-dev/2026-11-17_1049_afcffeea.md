## 1. 요약 절 숨김: `frontend/js/plans.js`

`sectionInner`는 `paneSection`뿐 아니라 `refreshSlots`(현황 수신 후, 계정 변경 후)도 부릅니다. 그래서 숨김 판정을 `sectionInner` 맨 앞에 두면 슬롯 갱신 경로까지 한 번에 막힙니다. 판정을 `paneSection`에만 두면 계정이 바뀐 뒤 `refreshSlots`가 예산팀 화면에 절을 다시 그립니다.

`paneSection`은 `ensureStatus` 요청 전에도 `menuVisible()`을 확인합니다. 그래서 숨김 사용자는 `/institution-plans/status` 요청도 나가지 않습니다. 이 요청은 `map` 키 AND 영업·전산팀이 아니면 어차피 403이 나는 경로입니다.

버튼 분기는 단순화합니다. 절이 보이는 사용자는 항상 메뉴를 열 수 있으므로 `open`은 무조건 버튼입니다.

NEW:
  plans.sectionInner = function (id, nameId) {
    // 메뉴에 '기관 사업계획'이 안 보이는 사용자(예산팀 등)는 요약 절도 보지 않는다(11-17). paneSection·refreshSlots 가 모두 여기를 거치므로 한 곳에서 막는다.
    if (!plans.menuVisible()) return '';

## 2. 선택 행 스크롤: `frontend/js/plans.js`

`renderList`는 필터를 바꿀 때마다 불리므로 거기에 스크롤을 넣지 않습니다. 대신 `mount`에서 `pendingId`가 있었던 경우, 즉 `openInstitution`으로 들어온 경우에만 맞춥니다. `select()`의 스크롤 코드는 `revealRow(key)`로 빼서 두 곳이 같이 씁니다. 스크롤 영역은 `#pl-scroll`이고, `scrollIntoView({block:'nearest'})`가 가장 가까운 스크롤 조상(`#pl-scroll`)을 움직입니다.

패치 2-a, `select` 안의 스크롤 코드를 헬퍼로 교체:
```
OLD:
    Array.prototype.forEach.call(host.querySelectorAll('[role=option]'), function (o) {
      if (o.getAttribute('data-key') === key && o.scrollIntoView) o.scrollIntoView({ block: 'nearest' });
    });
  }
NEW:
    revealRow(key);
  }
  // 키가 같은 행이 목록 스크롤 영역(#pl-scroll) 안에 보이게 한다. select 와 mount(다른 화면에서 기관을 골라 들어왔을 때)가 함께 쓴다.
  function revealRow(key) {
    if (!host || !key) return;
    Array.prototype.forEach.call(host.querySelectorAll('[role=option]'), function (o) {
      if (o.getAttribute('data-key') === key && o.scrollIntoView) o.scrollIntoView({ block: 'nearest' });
    });
  }
```

패치 2-b, `mount`에서 `pendingId` 유무를 기억:
```
OLD:
    fillControls();
    applyPending();
NEW:
    fillControls();
    const hadPending = !!S.pendingId;   // 현황판·지도에서 기관을 골라 들어왔는가
    applyPending();
```

패치 2-c, 목록을 그린 뒤 선택 행으로 스크롤:
```
OLD:
    renderBanner(); renderList(); renderFoot(); renderPane();
    ensureStatus(true);
  };
NEW:
    renderBanner(); renderList(); renderFoot(); renderPane();
    if (hadPending && S.selRow) revealRow(S.selRow.key);   // '전체' 창처럼 목록이 길 때 선택 행이 스크롤 밖에 남지 않게
    ensureStatus(true);
  };
```

호출자가 확인할 것은 두 가지입니다. 하나는 `app.showSoon`이 `mount` 전에 호스트를 `display`로 보이게 해 두는지입니다. 숨겨진 상태면 `scrollIntoView`가 아무 일도 하지 않으니, 그 경우 `requestAnimationFrame`으로 한 번 미룹니다. 중구(추정일 2030-10-13, '전체' 창)로 브라우저에서 한 번 확인하면 됩니다. 다른 하나는 `mount` 직후 `ensureStatus(true)`가 끝나면 목록이 다시 그려지는데, `#pl-scroll`은 그대로라 스크롤 위치가 유지된다는 점입니다.

## 영향 범위와 실행 명령

- `plans.menuVisible()`은 실제 브라우저에서 `#side-nav [data-nav]`로 판정합니다. 사이드바가 아직 없으면 true이므로, 로그인 직후 사이드바가 그려지기 전에 절이 한 번 그려졌다가 `onProfileChange`의 `refreshSlots`에서 사라질 수 있습니다. 이 경로는 위 패치 1-a가 막습니다.
- 숨김 사용자의 슬롯에는 빈 `.db-sec.pl-slot` div가 남을 수 있습니다. `.db-sec`의 테두리·여백이 있는지 `index.html`에서 확인해 주세요. 권한 거부(`denied`) 때와 같은 동작이고, 이 세션에서는 `index.html`을 건드리지 않았습니다.
- 다른 시험은 `menuCheck`를 쓰지 않아(grep으로 `plans.test.js` 394~403행뿐인 것을 확인) 영향이 없습니다. `plans.test.js` 367행의 시험은 node에서 `menuVisible()===true`라 그대로 통과합니다.
