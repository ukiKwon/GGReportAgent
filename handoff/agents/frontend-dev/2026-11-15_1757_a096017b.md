### 4. 구현안 — 합치기 키 우선순위와 근거
- 정한 순서:
  1. **서버 id**는 번들이 id를 갖지 않아(번들 레코드에 `institutionId`가 없음) 합치기 키로 못 쓴다. 합친 뒤 `applyBidCases`의 키로만 쓴다.
  2. **orgCode**는 번들엔 있어도 DB에는 칸이 없다(029:11). 키로 못 쓴다. DB에 칸이 생기면 1순위로 올린다(이관 메모).
  3. **지역 + 정규화한 이름**을 키로 쓴다. 서버 region이 비어 있으면(기존 시험 `serverdata.test.js:56`) 이름만으로 맞춘다. 서버 region이 있고 번들과 다르면 합치지 않는다.
  4. **type 종류 호환**: 지자체와 비지자체는 서로 합치지 않는다.
- 지자체 외는 `mergeUnion`에 넣지 않는다. `baseInstitutions`가 기관 추가 때 저장되는 목록이라 172곳을 넣으면 복제되기 때문이다(`render.js:137`의 의도 유지). 대신 `allInstitutions` 단계에서 `지역|이름`(`instKey`)이 같으면 nonMuni 풍부행 위에 base 행을 덮는다(base가 이기는 기존 정책 유지). 그 뒤에 개원 예정 법원을 전체 목록에서 거른다.

최종 적용형:
```js
    function pick(b) {
      const ok = (byName[mergeKey(b.name)] || []).filter(function (c) { return sameKind(c.rec.type, b.type); });
      return ok.filter(function (c) { return c.rec.region && c.rec.region === b.region; })[0] ||
             ok.filter(function (c) { return !c.rec.region; })[0] ||
             (!b.region ? ok[0] : null) || null;

    const out = bundle.map(function (b) {
      const c = pick(b);
      if (!c) return b;
      used.add(c);
      return Object.assign({}, b, c.rec, { name: b.name });

    Object.keys(byName).forEach(function (k) {
      byName[k].forEach(function (c) { if (!used.has(c)) out.push(c.rec); });
    });
    return out;
```
- 위 `Object.keys` 순회는 서버 행 순서가 바뀌므로 `serverRows.forEach`로 후보를 찾아 쓰는 것이 낫다. 적용 시 `const cand = new Map(); serverRows.forEach(r => cand.set(r, entryOf(r)))` 형태로 원래 순서를 보존한다. 기존 시험 `serverdata.test.js:155-162`는 서버 전용 행의 추가 순서를 본다.
