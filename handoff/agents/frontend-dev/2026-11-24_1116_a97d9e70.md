### 1. 고친 곳
**`frontend/index.html`**
- CSS 1459~1464줄: `.pb-scope`, `.pb-sc`, 눌림 상태, `:focus-visible`을 6-4 그대로 넣었습니다.
- CSS 1516줄: 880px 미디어쿼리 줄에 `.pb-scope{width:100%}`, `.pb-sc{flex:1 1 0}`를 이어 붙였습니다.
- 마크업 3268~3272줄: `<select id="pb-who">` 담당자 라벨을 빼고 세그먼트를 넣었습니다.
  - 세그먼트는 `div.pb-scope#pb-scope`(`role=group`, `aria-label="조회 범위"`, `aria-describedby="pb-scope-note"`)이고 단추는 `.pb-sc`·`data-scope`·`aria-pressed` 3개입니다.
  - `#pb-q`는 세그먼트 뒤로 옮겼습니다.
- 3278줄: `#pb-scope-note`(hidden)를 `#pb-legend` 앞에 넣었습니다.
- `id="pb-scope"`는 규격 마크업에 없던 것을 제가 더했습니다(JS가 단추를 찾는 용도).

**`frontend/js/prepboard.js`**
- 문구 T: `scopeMine/Team/Dept`, `scopeNote`, `teamUnresolved`, `emptyMine/Team/Dept`, `seeMine`, `seeTeam`, `clearQ`를 추가했습니다.
  - `T.empty`, `T.clear`, `T.mine`은 제거했습니다.
  - `T.all`은 `headModel`이 쓰므로 남겼습니다.
- 지운 것: `WHO_MINE`, `whoOptions`, `filterRows`의 담당자 분기, `paintWho`, `pb-who` change 처리.
- 새 순수 함수:
  - `pb.SCOPES`, `scopeValid`, `scopeLabel`.
  - `boardUrl(scope, ended)`: scope를 모르면 붙이지 않고, 끝난 건은 `&include_ended=true`로 붙입니다.
  - `scopeNoteText(scope, teamResolved)`: 팀·부서일 때만 값이 나오고, 팀이면서 `team_resolved:false`면 결재선 안내를 앞에 붙입니다.
  - `liveText`: "팀 작업, 기관 12곳" 형식입니다.
- `filterRows`는 이름 검색만 합니다. `is_mine`으로 다시 거르지 않고, `.is_mine`은 '내 담당' 칩에서만 읽습니다.
- `emptyModel(total, shown, {q, scope})`는 `action`이 `actions:[{act,label}]` 배열로 바뀌었습니다. 빈 결과 6-4 표와 같습니다.
  - 내 작업 0건: [지역별 공고현황 열기] [팀 작업 보기]
  - 팀·부서 0건: [내 작업 보기]
  - 범위 안 검색 0건: "{범위}에서 '{q}'과/와 맞는 기관이 없습니다." + [검색 지우기]. 조사는 `prep.josa(q,'과','와')`입니다.
- 화면 상태와 동작:
  - 상태: `B.who`를 `B.scope`·`B.teamResolved`·`B.announce`로 바꿨습니다. `normalize`가 응답의 `scope`·`team_resolved`를 받습니다.
  - `load()`는 `pb.boardUrl(B.scope, B.ended)`로 요청합니다. 첫 요청은 scope 없이 가고, 응답의 `scope`가 `B.scope`가 됩니다.
  - `paintScope()`는 `aria-pressed`와 `#pb-scope-note`를 그립니다. 범위를 아직 모르면 내 작업으로 보입니다.
  - 새 함수 `setScope()`는 칩이나 빈 표 단추를 누르면 범위를 바꾸고 다시 불러옵니다. 눌린 모양이 바로 바뀌고, 표 자리에는 '불러오는 중…'이 뜹니다. 이미 눌린 범위나 모르는 값은 무시합니다.
  - 새로 고침과 '취소·중단한 건도 보기'도 `B.scope`를 유지합니다.
  - 불러오기가 끝나면 `#pb-live`에 알림을 보냅니다. 범위를 바꿨을 때만 보내고, 실패하면 보내지 않습니다.
  - 실패하면 칩 상태는 그대로 두고 [다시 시도]가 같은 범위로 다시 부릅니다.
  - `reset()`은 `B`를 새로 만들어 `scope`를 비웁니다. 다음 계정의 첫 요청은 scope 없이 갑니다.
  - 버튼 id는 기존 `refresh`를 씁니다.

### 3. 지시에서 벗어난 판단
- `emptyModel`의 반환 모양을 `action` 문자열에서 `actions` 배열로 바꿨습니다. 내 작업 0건에 단추가 2개 필요해서입니다.
- 팀 범위에서 `team_resolved:false`면 안내 줄에 결재선 문구와 `scopeNote`를 함께 보입니다. 지시는 "한 줄 정도"였습니다. 부서 범위에는 결재선 안내를 붙이지 않습니다.
- 범위를 바꿀 때 `B.data=null`로 비워서 표를 '불러오는 중…'으로 돌립니다. 실패하면 칩은 그대로이고 오류 박스와 [다시 시도]가 나옵니다(규격 6-4 '상태별 모양'대로).
- 계정 전환 때 칩은 `reset()`에서 `paintScope()`로 내 작업 모양으로 돌아갑니다. 새 응답의 scope로 다시 정해집니다.
- 지시받지 않은 `design_history` 전/후 장은 건드리지 않았습니다. 규격 6-6 문안이 이미 있습니다.
