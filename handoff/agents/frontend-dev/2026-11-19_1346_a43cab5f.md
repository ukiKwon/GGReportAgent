## 2. 원인·요구 요약 (근거)
- 규칙은 `dash.proposeGate`(dashboard.js 345~361행) 한 곳이다. 마지막 `return 'later'`가 "공고 전"이고, 여기만 바꾼다.
- `[제안 확정]` 입구는 3곳이며 모두 `dash.actionKind(…, gateOpts())`를 거친다. 그래서 gate 한 곳과 gateOpts 한 곳만 고치면 세 입구가 함께 바뀐다.
  1. 입찰 공고 현황 상세: `paneAct`(dashboard.js 1107행), `renderPane`.
  2. 지도 상세 팝업·현황판 줄에서 여는 팝업: `dmRender`(dashboard.js 1645행).
  3. 현황판 목표 줄: `kbboard.actOf`(kbboard.js 1364~1369행). 단계 배지가 있으면 먼저 'open'으로 나가므로 "진행 중이면 안 보임"이 이미 지켜진다.
- `portal.js`는 `P.SCREEN`만 쓰고 게이트를 따로 만들지 않는다.
- 목표 기관 여부는 지금 dashboard.js가 모른다. kbboard의 `gs.data`(`/bid-targets?year=` 응답, `items`=목표, `watch_items`=관심, `year`)에만 있고 `dash.util`로 공유되지 않는다. 상세 팝업도 갖고 있지 않다.
- 가장 덜 위험한 경로(둘을 함께 쓴다):
  - dashboard.js 안에 올해 목표 id 집합을 두는 저장소(`dash.setGoals`)를 둔다.
  - kbboard가 이미 받은 응답을 `dash.setGoals(gs.data)`로 넘긴다. 이미 있는 값을 공유할 뿐이라 추가 요청은 없다.
  - kbboard를 거치지 않는 입구(공고 현황·지도 팝업)를 위해 `dash.loadGoals()`가 `GET /bid-targets?year=올해`를 한 번 받아 같은 저장소를 채운다.
- 그래서 kbboard를 아직 안 연 세션에서도 세 입구가 같은 답을 낸다. 지도 렌더 코드는 건드리지 않는다.
- 저장소 규칙:
  - `data.year`가 오늘 연도일 때만 저장한다. 다른 연도를 보는 중이면 기존 값을 유지하고 덮지 않는다.
  - 관심(`watch_items`)은 읽지 않는다.
  - 못 받거나 403이면 집합이 없으므로 지금 규칙 그대로(공고 뒤에만)다.

### 판정 결과 (기본 유지, 이관 아님)
- 올해 목표에 공고 전(`later`)이면 `confirm`.
- `nobid`(입찰 없음 기록)·`closed`·`delayed`·`past`는 목표 기관이어도 그대로 막는다.
  - `NO_BID`는 사용자 기본안대로, 98-1 팝업과 일관되게 막는다.
  - `past`(접수 마감이 지났거나 공고 후 30일 초과)와 `delayed`(공고 지연·재공고 대기)는 "공고 전"이 아니라 공고 상태가 정해진 경우라 건드리지 않았다.
  - 이 둘도 목표 기관이면 열어야 하는지는 기획 확인 사항이다(이관 메모).
- 이미 제안 진행 중이면 'open'이라 그대로다.

### 패치 A-1. dashboard.js — 목표 저장소와 게이트 (한 가지 일: 규칙)
`actCtx` 함수 끝(`master: …` / `}` / `}`) 바로 뒤, `// [제안 확정] 노출 규칙` 주석 앞에 추가:
```js
  // ── 올해 목표 기관 집합(사용자 11-19 Q2: 올해 목표 기관은 공고 전에도 [제안 확정]) ──
  // kbboard가 받은 GET /bid-targets 응답을 setGoals로 넘기거나, 없으면 loadGoals가 직접 받는다. 올해(오늘 연도) 응답만 담는다.
  const goalSt = { year: 0, ids: null, st: 'idle', seq: 0 };
  dash.setGoals = function (data, today) {   // data = { year, items:[{institution_id}] }. 담았으면 true
    const y = (today || todayDate()).getFullYear();
    if (!data || Number(data.year) !== y || !Array.isArray(data.items)) return false;
    const ids = {};
    data.items.forEach(function (t) { const id = String(instId(t)); if (id) ids[id] = true; });   // watch_items는 읽지 않는다 — 관심 기관은 규칙 밖
    goalSt.year = y; goalSt.ids = ids; goalSt.st = 'ok';
    return true;
  };
  dash.clearGoals = function () { goalSt.seq += 1; goalSt.year = 0; goalSt.ids = null; goalSt.st = 'idle'; };
  dash.loadGoals = function () {
    if (!serverMode() || !hasEmp()) { dash.clearGoals(); return Promise.resolve(); }
    const y = todayDate().getFullYear(), my = ++goalSt.seq;
    if (!goalSt.ids) goalSt.st = 'loading';
    return fetchJson('/bid-targets?year=' + encodeURIComponent(y)).then(function (r) {
      if (my !== goalSt.seq) return;
      if (r.status === 'ok' && dash.setGoals(r.data)) return;
      goalSt.ids = null; goalSt.year = 0; goalSt.st = r.status === 'ok' ? 'error' : r.status;   // 못 받으면 지금 규칙 그대로(공고 뒤에만)
    });
  };
  // 순수: 올해 목표 기관인가. goals = { year, ids }.
  dash.isGoalRec = function (rec, goals, today) {
    const t = today || todayDate();
    return !!(goals && goals.ids && Number(goals.year) === t.getFullYear() && goals.ids[String(instId(rec))]);
  };
```

```
```

    return 'later';
  };
new:    if (ns && ns.check) return 'past';

  const Y = TODAY.getFullYear();
  const r = function (days, extra) { return rec('가', '11', days, Object.assign({ institutionId: 'I1' }, extra || {})); };
  const goals = function (year, ids) { const m = {}; (ids || ['I1']).forEach(function (i) { m[i] = true; }); return { year: year, ids: m }; };
  const gate = function (x, g, snap) { return dash.proposeGate(x, { today: TODAY, snap: snap || null, goals: g }); };
  assert.strictEqual(gate(r(40), goals(Y)), 'confirm');                     // 올해 목표 + 공고 전
  assert.strictEqual(gate(r(null), goals(Y)), 'confirm');                   // 날짜 없음도 공고 전
  assert.strictEqual(gate(r(40), null), 'later');                           // 관심(목표 집합에 없음)·목표 못 받음
  assert.strictEqual(gate(r(40), goals(Y, ['I9'])), 'later');               // 다른 기관만 목표

## 5. 위험·되돌리는 법
- **403 가능성**: `GET /bid-targets`를 영업팀·영업팀장이 받을 수 없으면 `loadGoals`가 `denied`로 끝난다. 이때 규칙은 지금 그대로(공고 뒤에만)로 조용히 되돌아간다. 화면 오류는 없고 `fetchJson`이 콘솔 403만 남긴다.
- **새 요청 1건**: 공고 현황·팝업을 열 때마다 `/bid-targets?year=올해`를 받는다(연타하면 `seq`로 이전 응답은 버린다). 부담이 크면 `dash.loadGoals`에 `goalSt.ids`가 이미 있으면 건너뛰는 캐시를 한 줄 더한다. 다만 목표를 빼도 낡게 남으므로 지금 안은 매번 받는 쪽이다.
- **버튼 깜빡임**: 목표를 받는 중에는 `wait`("확인하는 중")으로 시작해 깜빡임을 줄였다. 응답이 느리면 이 문구가 보이는 시간이 길어질 수 있다.
- **kbboard 연도 전환**: 다른 연도를 보는 중에는 `setGoals`가 무시하고 기존 집합을 유지한다. 올해 목표를 다른 화면에서 바꾼 직후에는 그 화면이 다시 받을 때까지 낡을 수 있다. 서버는 어차피 공고 조건 없이 허용하므로 데이터 위험은 없고 화면 노출만 달라진다.
- **되돌리기**: `proposeGate` 마지막 `return` 한 줄을 `return 'later';`로 되돌리면 규칙이 즉시 원복된다. 나머지(A-1 저장소·B)는 남아도 무해하다.

## 6. 이관 메모
- `[이관: 개발(백엔드)]` `GET /bid-targets?year=`를 영업팀·영업팀장 역할이 읽을 수 있는지 확인 — 기다리는 것: 역할별 허용 여부 — 근거: 지금 kbboard는 `can_edit`로 편집만 가르고 목록 읽기 권한은 코드로 확인하지 못했다. 막혀 있으면 공고 현황·지도 팝업에서 예외가 동작하지 않는다.
- `[이관: 기획]` 목표 기관이어도 `past`(접수 기간 지남·공고 후 30일 초과)와 `delayed`(공고 지연·재공고 대기)를 계속 막을지 — 기다리는 것: 결정 — 근거: 이번 구현은 "공고 전(`later`)"만 열었고 이 둘은 막는다. `NO_BID`는 98-1 팝업과 일관되게 막는다. 다르게 하려면 `proposeGate` 해당 줄에 목표 판정만 더하면 된다.
- `[이관: 디자인]` 안내 문구 '올해 목표 기관이라 공고 전에도 영업부서가 제안 확정할 수 있습니다.'와 위치(버튼 줄 안 `db-why`, 기존 틀) 확인 — 기다리는 것: 문구·위치 승인 — 근거: 새 CSS 없이 기존 `.db-why`를 재사용했다. 현황판 줄에는 안내가 없고 팝업과 공고 현황 상세에만 붙는다.
- 상세 팝업의 확인 상자 문구(938행 '…확정하면 …준비 건이 생깁니다')와 기존 `noperm` 문구('영업팀·영업팀장이 합니다')는 부서 이름 변경(팀→부서) 범위 밖이라 그대로 뒀다.
