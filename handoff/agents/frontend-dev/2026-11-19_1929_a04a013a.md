## 3. 공통 모듈 설계안 — `frontend/js/popup.js`

### 3-1. 판단: 껍데기와 본문은 분리할 수 있습니다
- 모든 팝업의 본문 렌더러(`dmRender`, `hc.modalListsHtml`, `instedit`의 fill*, `renderOurs` 등)는 `innerHTML`을 꽂는 방식입니다. 그래서 **껍데기만 바꾸는 이행**이 됩니다.
- 이행을 두 모드로 나누길 권합니다. 이렇게 하면 한 단계에 로직과 마크업을 동시에 바꾸지 않아 회귀가 적습니다.
  - **(A) `popup.adopt(overlayEl, opts)`** — 기존 오버레이 요소에 동작(가둠·Esc·배경·inert·포커스 복원·층·dirty)만 붙입니다. 마크업은 안 바꿉니다. 마크업 단언 테스트가 안 깨집니다.
  - **(B) `popup.shell(opts)`** — 표준 껍데기(`.pop`/`.pop-bar`/`.pop-note`/`.pop-body`/`.pop-foot`/`.pop-x`)의 HTML 문자열을 만들고 `{bar, note, body, foot}` 자리를 돌려줍니다. 본문 렌더러는 `body` 자리에만 꽂습니다. (A) 위에서 한 팝업씩 켭니다.
- `.modal-overlay`·`.modal-box` 클래스는 별칭으로 남깁니다. 새 클래스를 덧붙이면 공용 규칙과 기존 CSS 단언이 그대로 유지됩니다. 예: `class="modal-overlay pop-ov"`.

### 3-2. API 초안 (UMD, `module.exports`로 node 테스트 가능)
```js
popup.adopt(ov, {
  id, size,                        // size: 'sm'|'md'|'lg'|'xl' (디자이너 단계에 맞춤)
  kind: 'view'|'edit'|'confirm',   // confirm이면 role="alertdialog", 처음 포커스는 상자
  initialFocus: el|selector|fn,
  opener: el,                      // 기본 document.activeElement
  fallbackFocus: selector,         // opener가 사라졌을 때(dm의 fallback)
  inertBehind: true,               // 기본 true. 정적 껍데기는 false 가능
  closeOnBackdrop: true,           // mousedown과 click이 둘 다 오버레이일 때만
  onEscape(e): 'close'|'handled'|'ignore',   // 인라인 확인 줄·busy 처리를 팝업이 정함
  canClose(): bool|'confirm',      // busy면 false, dirty면 'confirm'
  dirty(): string[],               // 저장 안 한 변경 목록. 비면 즉시 닫음
  onClose(why)                     // teardown 끝에 한 번(instedit onClose와 같은 의미)
})
popup.close(ov, {restore:true})
popup.top()                        // 맨 위 팝업. Esc·Tab은 맨 위 것만 받는다
popup.shell({ id, titleId, descId, role, size, title, note, foot })
popup.inertBehind / popup.inertRelease   // kbboard 것을 이사. kbb.* 별칭은 유지
popup.nextFocus(list, active, shift)     // 순수 함수(가둠 계산)
```
- **키 처리는 한 곳**: document 캡처 `keydown` 하나. 스택 맨 위만 처리합니다.
  - Tab: `nextFocus`로 순환. 팝업 밖이면 끌어들입니다.
  - Esc: `onEscape` → `canClose`/`dirty` → 닫기 순으로 묻습니다.
  - 지금은 element·document·window 레벨이 섞여 있어서 캡처 순서로 서로 가로채고 있습니다. 한 곳이 되면 이 문제가 사라집니다.
- **층**: 스택 깊이 n의 z-index는 `30 + 2n`입니다. 열면 아래 팝업에 `inert`를 겁니다. 이미 inert인 요소는 건너뛰는 현재 `inertBehind` 규칙을 유지합니다.
- **배경 클릭**: mousedown과 click의 대상이 둘 다 오버레이일 때만 닫습니다(지금 다수파). `#hb-ours`의 mousedown 닫기가 사라집니다. 동작이 바뀌는 곳이라 디자이너·메인이 승인해야 합니다.
- **dirty**: instedit의 `#ie-cbox`를 공통화합니다. 확인 줄은 `.pop-note` 자리에 둡니다. `#add-modal`은 지금 확인이 없어 데이터가 사라집니다. 입력이 있으면 `dirty`가 이름 목록을 돌려주면 됩니다. 동작 변경이라 7장에 올렸습니다.
- 공용 `app.wireModalDismiss`는 마지막 단계에서 지웁니다. 정적 5개가 `adopt`로 옮겨지면 대상이 없습니다.

### 3-3. 팝업별 필수 예외 (adopt가 흡수해야 함)
- dm: `refocus` 함수와 `fallback`. busy와 `m.confirm` 중의 Esc.
- hc: busy와 pending 중의 Esc. 위에 얹히는 층.
- instedit: `requestClose`/`teardown`/`onClose`. `S.teardown` 안에서 정리하는 일(`bankCtl`, `wrap.innerHTML=''`)은 `onClose`가 맡습니다.
- hb-dlg: 결과 목록(combobox)이 열려 있으면 Esc는 목록만 닫음(`onEscape`가 `handled`). busy면 닫지 않음.
- prep `#pp-nb`: 처음 포커스는 상자이고, 첫 Tab은 첫 버튼입니다. 화면 숨김을 감시하는 MutationObserver는 `onClose` 쪽에 남깁니다.
- board-write `#bd-src-pop`: 입력 안 Esc는 입력 취소입니다(`bw.popEscAction`). `onEscape`로 위임하면 됩니다. 순수 함수는 그대로 둡니다.
- overdue: 닫을 때 `restore` 여부가 경로별로 다릅니다(`closePopup(true/false)`). `popup.close(ov,{restore})`로 맞습니다.

## 4. 테스트 전략
- **순수 함수 단위**(node): `nextFocus`(첫·끝·밖·빈 목록·shift), 스택 push/pop과 z-index 계산, Esc 라우팅(`onEscape`·`canClose`·`dirty` 조합), 배경 클릭 판정(mousedown 대상 ≠ click 대상).
- **가짜 DOM**: `kbboard-1119.test.js:114~116`에 `inertBehind` 가짜 노드 하네스가 있습니다. 이것을 `popup.test.js`로 옮기거나 재사용해 inert 걸기·풀기·남이 건 것 보존·다른 모달 건너뛰기를 검증합니다.
- **소스 정규식 래칫**: 새 테스트 `popup-lint.test.js`가 `frontend/js`에서 다음을 센 값이 허용 목록에서 줄어들게만 합니다.
  - `key !== 'Tab'` 직접 구현
  - `role="dialog"` 직접 생성
  - 허용 목록은 지금 10곳과 아직 안 옮긴 마크업이고, 단계마다 줄입니다.
  - `popup.js`에서만 document 캡처 keydown을 거는지도 확인합니다.
- **index.html CSS 단언**(기존 방식): `.pop`·`.pop-bar`·`.pop-foot`이 `var(--…)`만 쓰는지, 크기 단계 값, 층 규칙, `prefers-reduced-motion`.
- **팝업별 이행 회귀 테스트**: 각 팝업을 옮길 때 기존 단언을 새 형태로 갱신하고, "Esc → 닫힘 + 포커스가 opener로", "dirty면 확인 줄", "busy면 Esc 무시"를 한 건씩 추가합니다.

### 5-2. 순서에 대한 근거
- **1단계는 `#doc-modal`을 권합니다.**
  - 이유: 소유 파일이 `knowledge.js` 하나입니다. 읽기 전용 팝업이라 저장 데이터 위험이 없습니다. 테스트 단언이 0건입니다.
  - 지금 가둠이 없어 개선 효과가 눈에 보입니다. `popup.js`가 실제 DOM에서 동작하는지 가장 싸게 검증합니다.
- **마지막 단계는 dm·headcard·kbboard·prep 묶음**입니다.
  - 이유: 예외(busy·인라인 확인·refocus)가 가장 많고 서로의 층 쌓기에 얽혀 있습니다.
  - 담당이 fa·e4라서 `popup.js`가 안정된 뒤에 합류시키는 것이 충돌이 적습니다.
- 파일 충돌:
  - `index.html`은 세 세션이 같이 건드립니다. `.pop-*` CSS는 구분 주석이 있는 한 블록에만 둡니다.
  - 기존 `.modal-box.*` 규칙은 이행이 끝날 때까지 지우지 않습니다.
- 단계 0~3까지는 기존 마크업 단언이 거의 깨지지 않습니다(위 표에서 "없음"). 마크업을 바꾸는 (B) 단계는 5단계부터이고, 이 때 깨지는 건수가 큽니다.

### 5-3. 깨질 기존 테스트 추정
- 팝업 id·클래스·ARIA를 단언하는 줄은 15개 파일 약 73건입니다.
- 이 중 (B) 마크업 교체 때 실제로 고쳐야 하는 것은 약 25~30건입니다. `role="dialog" aria-modal="true" aria-labelledby="…"` 문자열 통째 단언이 12건이고, 나머지는 CSS 선택자 단언입니다.
  - 해결: `aria-labelledby`의 id는 그대로 유지하도록 `shell`이 `titleId`를 받습니다. 그러면 통째 단언 12건은 속성 순서(`role`·`aria-modal`·`aria-labelledby`)만 지키면 통과합니다.
- (A) adopt는 단언을 거의 깨지 않습니다. 소스 정규식이 `closePop(true)`나 `ov.id !== 'tm-modal'`처럼 핸들러 소스를 잡는 곳(`kbboard-c54:303`, `team.test:402~406`, `prep.test:105~106`, `inst_edit:423`)만 이행 때 수정합니다. 약 10건입니다.
- `kbb.inertBehind`는 `popup.inertBehind`로 옮기되 `kbb.*` 별칭을 둡니다. 그러면 `kbboard-1119.test.js:114~116` 등 9건이 안 깨집니다.
- 전체 313건 중 최종적으로 손볼 것은 약 35~40건으로 추정합니다. 정확한 수는 단계마다 재집계해야 합니다.

## 6. 위험·되돌리는 법
- 단계마다 한 팝업씩, 한 커밋입니다. 되돌릴 땐 그 커밋의 `git revert`입니다. 호출 쪽만 바꾸고 `popup.js`는 남깁니다.
- 위험 1. 키 처리를 한 곳으로 모으면 기존 element 레벨 핸들러와 이중 처리됩니다. 한 팝업을 옮길 때 그 팝업의 옛 핸들러를 같은 커밋에서 지웁니다.
- 위험 2. `inert`를 새로 걸면(정적 5개, dm, hc 등) 뒤 화면의 버튼이 막힙니다. 팝업을 닫지 못한 채 에러가 나면 화면이 영구히 잠깁니다. `onClose`에서 반드시 풀고, 풀기는 "이 팝업이 건 것만"(`inertRelease`)으로 유지합니다.
- 위험 3. 배경 클릭을 mousedown+click 둘 다 확인으로 통일하면 `#hb-ours`의 동작이 바뀝니다.
- 위험 4. 쪽지함·원문·색상·기관 추가·전체 입찰건에는 `role="dialog"`가 없어, 새로 넣을 때 `aria-labelledby`용 id를 만들어야 합니다. `index.html`에 id를 더하는 일입니다. 기존 id와 안 겹치는지 grep 필요합니다.
- 위험 5. 한글이 든 소스는 편집 도구로만 `old → new` 적용합니다(PowerShell 재작성 금지).
