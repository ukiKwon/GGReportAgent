## 1. 고친 곳
수정한 파일은 `frontend/js/plans.js`, `frontend/test/plans.test.js`, `frontend/index.html`의 plans CSS 블록(`#pl-foot .db-link` 규칙과 바로 아래 새 규칙)입니다. 줄 번호는 편집 중에 바뀌어 함수 이름 기준으로 적었습니다.

| 항목 | 처리 |
|---|---|
| B2 | `syncActive()`를 새로 만들었습니다. 선택된 option의 id를 listbox의 `aria-activedescendant`에 넣고, 선택이 없으면 속성을 뺍니다. `renderList` 끝과 `markSelected` 끝에서 부릅니다. |
| B3 | `ORIGIN`을 `IMPORT: '수집 파일 반입'`, `SEED_TXT: '서울 25구 원문에서 옮김'`으로 바꿨습니다. |
| M3 | `STATS`의 `all` 라벨을 '모두'로, 빈 목록 안내를 "위에서 [모두]를 고르세요."로 바꿨습니다. 값 `all`은 그대로입니다. |
| M4 | 순수 함수 `plans.footHtml(n, m, busy)`를 새로 만들었고 `renderFoot`가 씁니다. n은 `missingIds`의 개수, m은 머리의 '자료 없음' 수입니다. m이 n보다 클 때만 "서버에 등록되지 않은 M−N곳은 목록에 넣을 수 없습니다." 줄을 붙이고, 숫자는 mono(`.v`)입니다. n이 0이어도 m이 있으면 이 줄만 보입니다. |
| M5 | `#pl-foot .db-link`에 `min-height:24px`를 더했습니다. |
| M6 | `badgeHtml(cls, html)`을 새로 만들었고 `badge()`는 이것을 거쳐 `esc`를 합니다. '사업계획 N건' 배지와 '사업계획 N건 보기' 버튼의 숫자를 `mono()`로 감쌌습니다. 목록 머리의 `<b>`는 `.db-grp b`가 이미 mono라 그대로 뒀습니다. |
| M7 | 오프라인 안내를 `#pl-flash`(role=status)로 보냅니다. `#pl-err`에는 denied와 error만 남습니다. 오프라인에서 벗어나면 그 문구만 지웁니다. |
| M8 | SKELETON에 `#pl-g`(`aria-live`)와 `#pl-body`를 고정했습니다. `renderList`는 `#pl-g`의 안쪽과 `#pl-body`만 바꿉니다. `aria-busy`는 `#pl-scroll`에 그대로 둡니다. |
| M9, M10 | 헤더 문구와 noid 안내 문구를 지시한 대로 바꿨습니다. |
| 이관① | `srcUrlOf(d)`를 새로 만들었습니다. `url_missing`이 참이면 null을 돌려줘 링크가 없고, `docHtml`의 `noUrl`도 같은 함수를 씁니다. |
| 이관② | 렌더 부작용은 의도한 것으로 주석에 적고 멱등하게 만들었습니다. 낡은 ok 상태에서는 다시 그릴 때마다 새 요청이 나가던 문제가 있었습니다. `statusInflight` 플래그로 요청이 나가 있는 동안엔 `ensureStatus(false)`가 같은 promise를 돌려줍니다. `applyStatus`, `setStatusState`, `resetStatus`가 플래그를 내립니다. |
| 가시성 | `plans.menuVisible()`을 새로 만들었고 `sectionInner`가 씁니다. 메뉴에서 열 수 없으면 '사업계획 N건 보기' 버튼과 `.pl-msg` 줄을 빼고 요약(배지·확인일)만 보입니다. `.pl-open .v` mono 규칙도 CSS에 더했습니다. 이 버튼은 `#plans-root` 밖에 있어서 필요합니다. |

판단한 것이 있습니다. `app.js`의 `findNavItem`이 밖으로 나와 있지 않고 `app.js`는 고칠 수 없어서, 사이드바 DOM의 `#side-nav [data-nav]`에서 `plans.SOON_ID`를 찾는 방식을 썼습니다.
- `nav.build`가 역할·서버 메뉴 키로 이미 걸러 그린 결과라 판정이 nav 규칙과 같습니다. 메인이 `nav.js`에서 노출 규칙을 바꿔도 따라갑니다.
- 사이드바가 아직 없거나 항목이 하나도 없으면(node, 로그인 전) 열 수 있다고 봅니다.
- 시험에서는 `plans.menuCheck`에 함수를 넣어 덮어씁니다.
- 로그아웃·계정 전환 때는 `onProfileChange`가 `refreshSlots`를 부르지만, 그 시점에 사이드바가 다시 그려져 있는지는 확인하지 못했습니다.

숨김 문자는 쓰지 않았고, 한글 파일은 모두 Edit으로만 고쳤습니다.

## 3. 사람이 확인할 것
브라우저에서 확인해야 합니다.
- **스크린리더**: 목록에서 ↑↓를 누를 때 낭독기가 현재 항목을 읽는지.
- **필터·건수**: 필터를 바꿀 때 '○곳' 건수 변화가 낭독되는지, 레이아웃이 그대로인지(`.db-grp`가 `#pl-scroll` 안 첫 자식이라 전과 같아야 함).
- **오프라인**: 연결이 안 될 때 안내가 빨간 띠가 아니라 `#pl-flash`로 나오는지.
- **푸터**: '자료 없음 수'와 '담을 수 있는 수'가 다르면 2줄째가 나오는지.
- **지도·현황판 상세**: 영업 계열이 아닌 계정에서 '사업계획' 절에 버튼이 없는지, 영업 계열에서는 있는지. 지도 팝오버가 열려 있을 때는 슬롯이 늦게 갱신될 수 있습니다.
