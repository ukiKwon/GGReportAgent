# [워드 내려받기] 포커스·저장 실패 패치안 (P3-2·P3-3)

## 1. 대상·방법·못 본 것
- 대상은 `frontend/js/headcard.js`의 `docxGo`, `saveBlob`, `refHtml`, `cardHtml`, `TEXT`와 `frontend/test/head-card.test.js`, 그리고 `frontend/index.html`의 기관장 카드 CSS 블록입니다.
- 방법은 코드를 읽고 qa 보고서의 P3-2·P3-3 대목을 대조하는 것이었습니다.
- 못 본 것이 있습니다. 브라우저에서 실제 포커스와 스크린 리더 낭독은 확인하지 못했습니다. 테스트도 실행하지 않았습니다. `app.js`에서 data-hc 클릭이 `onPaneClick`으로 가는 위임 부분은 읽지 않았고, 이름과 테스트 줄(1075 등)만 보고 가정했습니다. 적용할 때 확인해 주세요.

## 2. 원인
- **포커스 소실**
  - `cardHtml`이 busy일 때 `disabled`를 붙이고, `paintDl`이 카드를 다시 그려서 포커스가 body로 빠집니다(`headcard.js:365`, `:1187`).
  - 끝난 뒤에는 `focusPane`이 무조건 버튼으로 포커스를 끌어옵니다(`:1193`, `:1198`). 받는 동안 사용자가 다른 곳으로 옮겼어도 끌려옵니다.
  - 409일 때는 `hc.refresh(true)`가 다시 그리면서 포커스가 또 빠집니다(`:1199`). 이때 카드에 기관장이 없으면 버튼 자체가 사라집니다.
  - '만드는 중…'은 live 영역이 아니라서 스크린 리더가 읽지 않습니다.
- **저장 실패 문구**
  - `saveBlob` 예외가 `.then` 안에서 나면 `.catch`로 갑니다. 그 예외에는 `status`가 없어서 `docxErrText`가 '서버에 연결하지 못했습니다'를 냅니다(`:391`).
  - 서버에는 이미 내보낸 기록이 남았는데 화면은 서버 연결 실패라고 말합니다.
  - 또 `saveBlob`이 예외로 끝나면 임시 `<a>`가 DOM에 남고 URL이 해제되지 않습니다(`:1174-1175`).

### 패치 A. 포커스 유지와 진행 안내 (`headcard.js`, `index.html`)

`headcard.js` TEXT에 한 줄을 추가합니다.

`refHtml`은 busy일 때 화면에 보이지 않는 낭독 전용 줄을 반환합니다. 레이아웃은 밀리지 않고, `.hc-ref` 줄도 만들지 않으므로 기존 test 1045는 그대로 통과합니다. `.sr-only` 클래스가 `index.html`에 있는지 적용 때 한 번 확인해 주세요. 카드에서 이미 쓰고 있어서 있을 것으로 봅니다.
```
old:

    let out = '';
new:
    if (!dl) return '';
    if (dl.busy) return '<p class="sr-only" role="status" id="hc-ref">' + esc(hc.TEXT.docxBusy) + '</p>';

```

`docxGo` 앞에 포커스 도우미를 둡니다. 다시 그리기 전에 "그 단추가 포커스를 갖고 있었는가"를 재서, 그럴 때만 되돌립니다. 이 코드는 `paneQ`와 `focusPane` 정의(`:1166`) 바로 아래에 들어갑니다.
```
old:
  function focusPane(sel) { const el = paneQ(sel); if (el && el.focus) el.focus(); }
new:
  function focusPane(sel) { const el = paneQ(sel); if (el && el.focus) el.focus(); return !!el; }
  // 다시 그리면 단추가 새 요소로 바뀌어 포커스가 body로 빠진다 — 그리기 전에 포커스가 그 단추에 있었는지 재 두었다가 있었을 때만 되돌린다.
  function paneHasFocus(sel) {
    if (typeof document === 'undefined') return false;
    const el = paneQ(sel);
    return !!el && document.activeElement === el;
  }
```

`docxGo`는 아래처럼 바꿉니다. 이 패치에는 패치 B의 저장 실패 처리도 함께 들어 있습니다. 그래서 `docxGo`는 한 번에 적용하고, 패치 B에서는 그중 `saveErr` 처리를 설명합니다.

### 패치 B. 저장 실패 문구와 정리 (`headcard.js`)

TEXT에 한 줄을 추가합니다.
```
old:
    docxBusy: '워드 파일을 만드는 중입니다.',
new:
    docxBusy: '워드 파일을 만드는 중입니다.',
    docxSaveFailed: '파일은 만들어졌지만 이 컴퓨터에 저장하지 못했습니다. 다운로드가 막혀 있지 않은지 확인하고 다시 받으세요.',
```
- 예외 분기는 패치 A의 `docxGo`에 이미 들어 있습니다(`saveFailed`).
- `saveBlob`이 예외여도 임시 요소와 URL을 정리하도록 바꿉니다. 예외는 그대로 위로 던지고, 브라우저가 아니면 false를 돌려주는 기존 동작도 유지합니다.
```
old:
    const url = URL.createObjectURL(blob), a = document.createElement('a');
    a.href = url; a.download = fileName; a.style.display = 'none';
    document.body.appendChild(a); a.click(); document.body.removeChild(a);
    const t = setTimeout(function () { revokeUrl(url); }, 1000);
    if (t && t.unref) t.unref();
    return true;
new:
    const url = URL.createObjectURL(blob), a = document.createElement('a');
    a.href = url; a.download = fileName; a.style.display = 'none';
    try {
      document.body.appendChild(a); a.click();
    } finally {
      try { document.body.removeChild(a); } catch (x) { /* 이미 빠졌으면 무시 */ }
      const t = setTimeout(function () { revokeUrl(url); }, 1000);
      if (t && t.unref) t.unref();
    }
    return true;
```

**깨질 기존 테스트 (`head-card.test.js`)**

  const body = { tag: 'body' };

## 5. 위험·되돌리는 법
- **되돌리기**: `headcard.js`와 `index.html`의 패치를 거꾸로 적용하고, 테스트의 `:1044`·`:1151`을 `disabled`로 되돌립니다.
- **aria-disabled 위험**: 누를 수 있는 모양으로 남기 때문에 마우스 클릭이 `docxGo`까지 도달합니다. `dl.busy` 가드가 막으므로 동작은 같습니다. `app.js` 쪽 위임이 `disabled`를 먼저 걸러 주는 구조였다면, 막는 곳이 `docxGo` 한 곳으로 줄어드는 셈입니다.
- **포커스 되돌림 조건**: 포커스가 단추에 있었던 경우에만 되돌립니다. 마우스로 눌러 Safari처럼 포커스가 안 가는 브라우저에서는 되돌리지 않습니다. 이전에는 무조건 끌어왔으므로 동작이 달라집니다. 키보드·스크린 리더 사용자 쪽이 우선이라는 판단입니다.
- **저장 실패 시 서버 기록**: 서버에는 내려받기가 이미 OK로 남아 있습니다. 같은 사람이 다시 받으면 열람 기록이 한 줄 더 생깁니다.
- 지도 상세 팝업(`#dm-box`)에서도 `paneQ`가 같은 순서로 찾으므로 두 화면 모두 적용됩니다.

|---|---|---|---|
| 받는 중 단추 글자 | 만드는 중… | 만드는 중… | 변화 없음. `disabled`가 `aria-disabled`로 바뀌고, 포커스 링과 반투명 모양은 유지 |
| 받는 중 화면 낭독(보이지 않음) | (없음) | 워드 파일을 만드는 중입니다. | 새로 추가. 눈에는 보이지 않고 스크린 리더만 읽음 |
| 저장 실패 | 서버에 연결하지 못했습니다. 서버가 켜져 있는지 확인하세요. | 파일은 만들어졌지만 이 컴퓨터에 저장하지 못했습니다. 다운로드가 막혀 있지 않은지 확인하고 다시 받으세요. | 서버 문제가 아님을 분명히 함 |
| 완료·서버 오류 문구 | (기존) | (기존) | 변화 없음 |

보이는 변화는 저장 실패 문구 하나뿐입니다. 포커스 변화는 시연 화면에서 눈에 띄지 않습니다.
