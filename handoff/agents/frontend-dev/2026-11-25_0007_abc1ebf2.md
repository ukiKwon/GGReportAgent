- 읽은 것: `frontend/js/render.js`(buildCard, rankedList, drawRegion), `store.js`, `logic.js`(sortByInterest), `kbboard.js`의 post 패턴, `index.html`의 .rank-card·.heart CSS, 관련 테스트.
- 못 본 것: 서버 컨트롤러 코드, 실제 화면, 서버 오류 본문의 `code` 필드 모양.
- 서버 오류 문구는 상태 코드(403·404·409·그 밖)로만 가른다. 본문의 `code`는 쓰지 않는다. 그래서 409 중 CHANGE_PENDING이 아닌 것도 "결재 중" 문구로 나간다. 이 점은 이관 메모에 적었다.
- 서버 모드를 쓰는 화면은 열지 않았다.

## 설계 요약
1. 서버 모드는 `store.isServerMode()`로 판별한다. 서버 모드에서는 ♥ 상태와 '관심도순' 기준이 서버 값이다(`render.watch.mine`, institutionId 집합). 로컬 모드는 지금처럼 `store.isInterested(name)`을 쓴다.
2. 서버 모드에서 GET이 실패하면 ♥를 빈 상태로 둔다. 로컬 ♥로 바꿔 보이지 않는다. 기존 localStorage ♥는 서버로 올리지도 않고, 서버 모드에서 보이지도 않는다. 값은 지우지 않고 그대로 남는다(요구 3).
3. `render.syncWatch(code)`는 `drawRegion`이 목록을 그린 직후 부른다. `GET /my-watch`와 `GET /watchers`를 동시에 받고, 성공하면 지금 그 지역이 열려 있을 때만 목록을 다시 그린다. `/watchers`가 실패하면 ♥는 서버 값, 관심 n명은 빈 값으로 둔다.
4. ♥ 클릭은 낙관적 갱신 없이 `PUT` 또는 `DELETE`를 보낸다. 켜져 있으면 DELETE, 꺼져 있으면 PUT이다. 성공하면 `syncWatch`로 다시 받아 다시 그린다.
5. 실패하면 목록은 다시 그리지 않는다. 그 카드 바로 아래에 `<p class="rk-note" role="status">` 한 줄을 넣는다(권한 없음, 결재 중, 기관 없음, 실패). 이 줄은 다음에 목록을 다시 그릴 때 사라진다.
6. 같은 기관에 요청이 진행 중이면 두 번째 클릭을 무시한다(`_watchBusy`).
7. 머리글은 쓰기 요청에만 `X-Screen-Id: map_popover`, `X-Button-Id: toggle_watch_heart`를 싣는다. 공용 지원 함수는 없어서 render.js에 상수와 fetch 함수를 따로 뒀다(kbb 패턴). GET에는 머리글을 싣지 않는다. 읽기용 버튼 id가 서버 허용 목록에 있는지 몰라서 뺐다.
8. `render.env.fetch`를 시험이 가짜로 꽂을 수 있게 했다. `X-Emp-No`는 app.js의 fetch 덮개가 붙인다.
9. `r.institutionId`가 없는 레코드는 요청을 보내지 않고 "서버에 등록되지 않은 기관" 알림을 낸다.
10. 관심 n명은 `<small class="rk-wn" title="관심 있는 사람: 이름…">관심 3명</small>`이다. 0명이면 표시하지 않는다. 이름과 문구는 `esc()`를 거친다.
11. 순수 로직 3개를 logic.js에 추가했다: `watchIndex`, `watchOutcome`, `watchCount`.
12. app.js는 고치지 않는다. 지도 경로가 모두 `drawRegion`을 지나므로 render.js 한 곳으로 충분하다. 로그인 사용자가 바뀌어도 다음 `drawRegion`에서 다시 받는다.
13. 시각 규격은 디자인 확인 대기다(`--red` 알림 글자색, 관심 n명 위치).

## 위험·되돌리는 법
- 처음 그릴 때는 서버 응답이 오기 전까지 ♥가 모두 빈 상태로 보이다가 응답이 오면 목록이 다시 그려진다. 깜빡임이 있을 수 있다. 목록의 스크롤 위치와 펼친 묶음은 `rankOpen`과 `_selectedGroup`으로 유지된다.
- 서버 모드에서 기존 로컬 ♥는 사라진 것처럼 보인다. 이 부분은 사용자 결정이 맞는지 확인이 필요하다(열린 질문).
- 되돌리는 법은 패치 6개를 역순으로 되돌리거나 `map-watch.test.js`와 함께 `git checkout`하는 것이다. 서버 데이터는 건드리지 않는다.

## 이관 메모
- [이관: 디자인] 관심 n명(`small.rk-wn`)의 위치와 크기, 알림 줄(`.rk-note`)의 글자색 `--red`와 배경 `--panel2`, 대비와 모양 확인 — 규격 대기 — 위 CSS는 임시값이다.
- [이관: 개발: 백엔드] 오류 본문 모양 확인. 409가 CHANGE_PENDING 말고 다른 것도 있는지, 403 WATCH_USER_DENIED를 본문 `code`로 가를지 결정한다 — 지금은 상태 코드만 본다. `PUT`을 본문 없이 보내도 되는지, GET에 `X-Screen-Id`가 필요한지, 읽기용 `X-Button-Id` 허용 id가 있는지도 확인한다. 이 안은 PUT에 `{}`를 보내고 GET은 머리글 없이 보낸다.
- [이관: 기획] 서버 모드에서 기존 localStorage ♥(기관 이름 기준)를 이관하지 않고 보이지 않게 두는 것이 맞는지 확인한다 — 이관하려면 이름→institutionId 매핑과 일괄 PUT이 필요하다.
