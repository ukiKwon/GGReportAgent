- 못 본 것: 브라우저 실측, 시험 실행, 서버 화면.

## 2. 요구 요약과 판단한 것
- 줄 단추·동작 칸 제거: 목표 표 열은 7개 + 고르기 열. 관심 표는 그대로 둡니다.
- 하단 띠 단추 셋: `[수정하기] [관심 기관으로] [목표 기관에서 제외]`. 새 단추 id는 `hb-seltow`. `hb-seledit`·`hb-seldel` id는 유지하고, `hb-seldel`이 [목표 기관에서 제외] 자리입니다.
- [관심 기관으로]: `tc.bulkDialogHtml` 새 kind `'towatchn'`의 간단 확인 창을 띄웁니다. 확인하면 `submitChanges`로 TO_WATCH를 여러 곳 한 번에 보냅니다(기관 상세 팝업의 단건 TO_WATCH와 같은 경로). 관심 줄·지난해 목표·결재 중 줄은 제외하고, 지금 [삭제하기]의 skip 방식과 같습니다.
- [목표 기관에서 제외]: 같은 확인 창(kind `'delete'`) 본문을 라디오 둘로 바꿉니다. 첫째는 CANCEL, 둘째는 TO_WATCH입니다.
- 다음 회차 목표로(tonext): 화면 입구와 처리부만 지웠습니다. 서버 호출·이월 관련은 건드리지 않았고 6번에 목록으로 적었습니다.
- 사유 select 유지 판단: 첫째 라디오(CANCEL)일 때 '빼는 사유(필수)' select를 그대로 둡니다. `tc.validate`가 CANCEL에 사유 코드를 요구하고(`tchange.js:219`), 결재 사유 문장도 이 코드로 만들기 때문입니다. 없애려면 서버 변경이 필요합니다. 둘째 라디오(TO_WATCH)는 사유 select를 숨기고, 결재 사유는 고정 문구 `tc.TOWATCH_REASON`으로 보냅니다(`tc.deleteReason`과 같은 방식이라 개인정보 검사에 걸리지 않음).
- 단추 색: 시안의 [목표 기관에서 제외] 빨간 테두리는 따르지 않고 보통 단추로 뒀습니다. 현재 CSS 주석의 '빨강은 바로 빼는 모드의 확인 상자에만' 규칙과 충돌해서입니다. 디자인이 정할 일입니다.
- DIRECT 모드 문구: 사용자 지정 문장은 APPROVAL 기준이라 DIRECT는 제가 분기했습니다('…바로 옮기시겠습니까?', '결재 없이 바로 옮겨집니다.', '어느 쪽이든 결재 없이 바로 반영됩니다.'). 승인 주체는 `tc.approverShort(role)`로 구합니다(영업팀 → '팀장 결재', 영업팀장 → '부장 결재').
- 표 정렬: `.hb-tt` th와 칸은 가운데·세로 가운데입니다. 묶음 제목 줄(`tr.grp th`)과 빈 상태 칸(`tr.emp td`)은 왼쪽이고, 관심 표 메모 칸도 DESIGN '여러 줄 본문 칸' 예외로 왼쪽입니다. 이 표에는 금액 칸이 없어 오른쪽 정렬 대상이 없습니다.
- 최소 폭: 목표 표가 856으로 줄면 관심 표 메모 칸이 46px로 쪼그라드므로 `.hb-tt.wt { min-width:996px; }`를 새로 추가했습니다.
