# NEXT 104 협약 성과 관리 실사용 피드백 반영 패치안

## 1. 대상·방법·못 본 것
- 대상은 `frontend/js/results.js`, `frontend/test/results.test.js`, `frontend/index.html`의 '협약 성과 관리' CSS 블록(`/* 협약 성과 관리 시작` ~ `끝 */`, 약 2626~2707줄)이다.
- 방법은 정적 읽기뿐이다. Playwright가 `file:` 프로토콜을 막아 실제 화면은 못 열었고, 서버 화면도 열지 않았다.
- 못 본 것은 사용자의 실제 브라우저와 테마에서 거르기 줄이 어떻게 보이는지다. 2)의 원인은 코드로 확정한 것이 아니라 가장 유력한 후보다. 아래에 근거와 함께 밝혔다.

## 2. 원인·요구 요약

### 2) 거르기 줄이 안 보이는 원인
렌더 조건과 숨김은 원인이 아니라고 코드로 확인했다.

- `results.filtersHtml`(results.js 275줄 이후)은 `items`가 0건일 때만 `''`를 돌려준다. 목표 1곳 이상이면 이미 항상 그린다. 건수가 0인 분류도 `재유치 0`처럼 라디오로 나오고, 분류가 하나뿐이어도 나온다.
- `renderTop`(411줄 이후)은 `isEmpty(d)`가 아니면 항상 `rs-fil`을 채운다.
- `#results-root #rs-body > div:empty {display:none}`은 내용이 있는 `rs-fil`에는 걸리지 않는다.
- `hidden` 속성은 거르기 줄에 없다.

유력한 원인은 CSS에서 '버튼'으로 보이지 않는 것이다.
- `.db-per`(index.html 1747줄)는 원래 `.db-list` 같은 `--panel` 바탕 위에서 쓰도록 만든 모양이다. 배경이 `var(--bg)`, 테두리가 `var(--line)`(가장 옅은 선), 안쪽 글자가 `var(--muted)` 13px이다.
- 협약 성과 화면에서는 이 줄이 페이지 바탕 위에 그대로 놓인다. 배경이 페이지 바탕과 같은 색이라 알약 모양이 사라지고, 옅은 테두리와 흐린 글자만 남는다. 선택 칸의 16% 틴트만 겨우 보인다.
- `input`은 `opacity:0`이므로 라디오 원도 없다. 그래서 눈에 '단추'로 안 잡힌다.
- 현황판 규격은 이 줄을 패널 위에 두는 것이었고, results 블록은 `.rs-frow .db-per`에서 margin만 바꿨다.

고칠 곳은 두 가지다.
- (a) `.rs-frow .db-per`를 `--panel` 배경에 `--line-strong` 테두리로 올리고, 선택 안 된 글자를 `--fg`로 올린다.
- (b) 목표 0곳이지만 '연중에 뺀 곳'만 있는 경우는 거르기 줄이 없는 것이 맞다. 거를 대상이 없고 빈 상태 문구가 나온다. 그대로 둔다.
- 거르기 줄은 목표 1곳 이상이면 항상 보이는 현재 동작을 유지하고, 이를 고정하는 회귀 시험만 추가한다.
- 사용자 화면에서 실제로 아예 안 나온다면 CSS가 아니라 `items`가 비어 온 경우다. 그때는 서버 응답을 확인해야 한다.

### 3) 막대 규칙(권장안)
- 막대는 **목표 n ≥ 5이고 분류가 2가지 이상**일 때만 그린다. 그 밖에는 막대와 꺾쇠를 그리지 않는다.
- 근거는 이렇다. 칸이 하나뿐이면 폭이 전부 차서 '2'라는 숫자 하나가 늘어진 띠 위에 얹히는 모양이 된다. n<5이면 비율 그림이 정보를 주지 못한다.
- 숫자는 요약 띠가 이미 모두 보여 준다. 목표 기관 칸에 '재유치·신규 a 타은행 유치 b', 협약 내역 칸에 재유치·신규, 결과 미확정 칸에 대기·확인 필요가 있다.
- 숫자를 범례로만 보이게 하는 대안은 같은 숫자가 세 번째로 나오는 것이라 채택하지 않았다.
- 충분한 데이터일 때 모양은 그대로다. `results.BAR_MIN_N = 5`로 노출한다.

### 1) 문구 매핑
| 구 | 신 |
|---|---|
| 성공률 | 달성률 |
| 성공 내역 | 협약 내역 |
| 재유치 성공 | 재유치 |
| 신규 성공 | 신규 |
| 실패 | 타은행 유치 |
| 결과 없음 | 확인 필요 |
| 결과 대기 | (유지) |
| 공식 | `재유치·신규 a ÷ (재유치·신규 a + 타은행 유치 b)` |

- '성공·실패가 난 곳이 아직 없습니다'는 '결과가 난 곳이 아직 없습니다'로 바꾼다.
- 거르기 라벨은 `LABEL`을 그대로 쓰므로 자동으로 맞춰진다.
- 표 caption과 legend에는 해당 말이 없다. 막대 aria-label과 꺾쇠, legend는 `LABEL`과 문장을 고쳐서 맞춘다.

## 5. 위험·되돌리는 법
- '재유치'와 '신규'는 이제 두 곳에서 같은 말이다. 결과 칩·거르기 '결과' 줄과 '목표 구분'(tag_name) 열·거르기 '목표 구분' 줄이다. 줄 머리말('결과'·'목표 구분')과 열 머리글로 구분되지만, 표에서 두 열이 모두 '재유치'일 수 있다. 같은 값으로 이어 읽으면 오해 소지가 있다. 디자인 판단 대상이다.
- '확인 필요'(NONE)와 서버가 모르는 코드를 보낼 때의 '확인 불가'가 한 글자 차이다. 이관 메모 참고.
- 막대 숨김 규칙은 '목표 5곳 미만'이면 분류가 여러 개여도 막대가 없다. 숫자는 요약 띠에 있다.
- 되돌리는 법은 results.js, results.test.js, index.html 세 파일의 해당 변경만 되돌리면 된다. 서버·데이터 계약은 건드리지 않았다.
- 2)의 CSS 원인은 정적 판단이다. 적용 뒤 사용자 화면에서 거르기 줄이 보이는지 확인이 필요하다. 그래도 안 보이면 `items` 빈 응답(서버)을 의심한다.

## 6. 이관 메모
- [이관: 디자인] 거르기 알약(`.rs-frow .db-per`)이 페이지 바탕 위에서 패널 바탕·진한 선·`--fg` 글자로 올라가는 시각 결정 확인 — 디자인 규격 확정 대기 — 현황판 `.db-per`는 패널 위 전제.
- [이관: 디자인] 결과 칩 '재유치'·'신규'와 목표 구분 열의 같은 말 충돌 여부, 칩 '확인 필요'(점선)와 '확인 불가'(칩 없는 글자) 근접 문구 정리. 후자는 '분류 불가'로 바꾸는 안을 권장한다 — 문구 결정 대기 — results.js `chipHtml`.
- [이관: 기획] '타은행 유치'가 "다른 은행이 금고를 가져감"이라는 정의와 맞는지, '달성률' 공식 문구 확정 — 용어 정의는 기획 소관 — 사용자 11-23 피드백.
- [이관: 기획·디자인] 문구가 바뀌면 `docs/design_history/index.html` 전/후 장 추가가 필요하다(PUSH-GATE).
- 이 문구 변경은 서버 DTO 값(`success_n`, `fail_n`, `result_cd`)을 바꾸지 않는다. 백엔드 이관은 없다.

## 7. 열린 질문
- 목표 n이 4 이하이면 막대를 아예 숨기는 규칙을 5로 둬도 되나? 4나 3으로 낮추는 값 조정은 `results.BAR_MIN_N` 한 줄이다. 답이 없으면 5로 진행한다.
- 사용자 화면에서 거르기 줄이 정말 아예 없었는지, 아니면 옅게만 보였는지 알려 주면 2)를 확정할 수 있다. 아예 없었다면 서버 응답의 `items`가 비었던 경우다.
