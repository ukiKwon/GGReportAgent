## 1. 고친 파일과 바꾼 부분 (파일은 이름으로만 적는다. 줄 번호는 적용 뒤 grep으로 다시 찾는다.)

모든 항목을 반영했다. 테스트는 실행하지 못했다.

**frontend/js/approvals.js**
- **P2-1**: 결재를 마친 뒤 목록을 다시 그리면 포커스가 body로 떨어진다. 그래서 `loadRequests()`가 끝난 뒤에 포커스를 되찾는 `refocusAfterLoad(box)`를 추가했다.
  - 승인·반려(`reviewDecide`)와 카드 안의 승인·반려·취소(`act`)가 이 함수를 부른다.
  - 포커스가 이미 다른 곳에 있거나 검토 화면이 열려 있으면 건드리지 않는다.
  - 받은 결재는 다음 `.ap-review-btn,.ap-req-ok`로 보내고, 없으면 `#ap-tab-inbox`로 보낸다. 내가 올린 요청은 `.ap-req-cancel`, 없으면 `#ap-tab-mine`으로 보낸다.
  - 순수 함수 `approvals.focusAfterDecide(rows)`가 'card' 또는 'tab'을 고른다. 버튼이 없는 이사회 카드(`materialId` 없음)는 건너뛴다.
- **기본 탭**: 순수 함수 `approvals.defaultTab(inboxRows)`를 추가했다. `canDecide`인 건이 있으면 'inbox', 없으면 'mine'을 돌려준다.
  - `mount`가 `autoTab`을 켠다. `openTab`으로 탭을 지정한 경우(`wantTab`)는 켜지 않는다.
  - 첫 `loadRequests` 성공 때 한 번만 적용한다. 사용자가 탭을 직접 누르면(클릭·화살표) 해제된다.
- **#ap-flash 비우기**: `clearFlash()`를 추가했다(`apFlash`를 비우고 DOM도 비운다). `mount`와 `onProfileChange`에서 부른다. 로그아웃에 걸린 별도 훅은 없어서, 프로필 변경 훅과 마운트에 달았다.

**frontend/js/board-material.js**
- **P3-1**: 순수 함수 `mat.headMainOn(open, dirty)`를 추가했다. 수정이 남았거나 `open==='submit'`이면 false다. `headActsHtml`이 이 함수를 쓴다.
  - 제출 확인 줄이 열리면 머리 [안건 제출]은 틸이 아니고, 줄의 [버전 n 안건 제출]이 틸이다.
  - 칸을 고치는 동안에는 `syncSubmitTeal()`이 `#bd-m-submit`의 클래스만 바꾼다. 상태가 DRAFT일 때만 동작한다.
  - 호출 방식: `build()`에서 `#bd-body`에 MutationObserver를 붙인다. 작성 줄의 `#bd-m-state`가 다시 그려질 때마다 호출된다. 이 방식은 board-write.js를 고치지 않으려고 골랐다.
- **P3-2**:
  - 의결 결과 폼: `onMatChange`가 select·날짜를 바꿀 때 `#bd-m-ferr`와 날짜 칸의 aria-invalid·aria-describedby를 지우고 `res.error`도 비운다. `#bd-mat`에 `input` 리스너를 하나 더 달아 날짜를 입력하는 중에도 지워진다.
  - 재작성 모달: `onModalInput`이 사유를 고칠 때 `#bd-m-rw-err`와 textarea의 aria-invalid·aria-describedby를 지우고 `rw.error`도 비운다.
- **P3-3**: 경고문을 "의결 결과 '가결'과 개최일(2026-12-03)이 지워집니다."로 바꿨다.

## 2. 메인이 실행할 명령
PATH에 `/c/dev/node/node-v22.23.4-win-x64`를 더하고 `node --test "frontend/test/*.test.js"`를 실행한다. 기대: 전부 통과(기존 + 신규 3 test() 블록).
그다음 실화면에서 다음을 확인한다.
- 반려·승인 직후 `document.activeElement`가 다음 카드 버튼이나 '받은 결재' 탭인지.
- 칸을 고쳤을 때 머리 [안건 제출]의 틸이 빠지는지.
- 날짜 오류 뒤 날짜나 결과를 바꾸면 오류가 사라지는지.

## 3. 지시에서 벗어난 판단
- 확정 경고문에서 개최일이 없는 경우(`'가결'가`처럼 조사가 틀렸다)를 "…'가결'이(가) 지워집니다"로 바꿨다. 지시는 날짜가 있는 경우만 말했다. 이 문구를 고정한 테스트는 없다.
- `act()`(카드 안 승인·반려·취소)에도 같은 포커스 복귀를 넣었다. 지시는 승인·반려만 말했지만, 카드 버튼이 교체되는 것은 같은 원인이다.
- 로그아웃에 걸린 별도 훅이 없어서 `onProfileChange`와 `mount`에서 `#ap-flash`를 비웠다. 그래서 로그아웃 직후 DOM의 문구는 다음 마운트나 프로필 변경 때 지워진다.

## 4. 확실하지 않은 것
- MutationObserver는 브라우저에서만 동작한다. node 테스트에는 없어서 `typeof` 가드로 건너뛴다. 이 경로는 단위 테스트가 없어서 실화면 확인이 필요하다. 작성 줄이 다시 그려질 때 `liveDirty()`가 새 값을 이미 돌려주는지가 전제다(`matBarHtml`이 같은 상태로 그리므로 맞을 것으로 본다).
- 새 테스트의 `submitRowHtml` 단언은 `id="bd-m-subok" class="bd-wb-main"` 문자열이 붙어 있다고 가정한다. 현재 마크업은 그렇다.
- 기본 탭 전환은 `requestRows`의 `canDecide`를 쓴다. 이사회 카드 중 `materialId`가 없어 버튼이 안 나오는 건도 탭 전환 판단에는 포함된다(드문 경우).
