## 2. 설계 결정
- fmt.js 신규 qGroups(list)->{pending(open·hold, 물은 날 내림·같은 날 id 큰 것 먼저·날짜 없음 맨 뒤), answered(answeredAt||askedAt 내림, 같은 날 id 큰 것 먼저), done(qSplit과 동일 규칙), counts:{pending,answered,done}}, qClock(Date)->'HH:MM:SS'(잘못된 값 '').
- qSplit·export 불변 → 기존 시험 기대값 변경 없음(qSplit은 앱에서 안 쓰게 되므로 cleaner가 삭제 판단).
- 응답 탭 숫자 = answered+done 합계(기본안; qRender의 responded 변수 한 줄로 변경 가능). done 0건이면 '해소된 질문' details 숨김(이전엔 항상 표시).
- 오류 안내는 #qnote로 분리, 빈 상태 문구는 탭 안 정적 p. 서버 읽기 실패+목록 비었을 때만 두 빈 상태 숨김.
- 새로고침: disabled 대신 qUi.busy 가드+aria-busy. 자동 폴링과 수동 모두 pollQuestions를 지나며 진행 중이면 무시. 확인 시각은 마지막 성공 시각(실패 시 유지, 한 번도 없으면 '확인 전'). 수동 결과만 #qlive로 알림.
- 탭: role=tablist/tab/tabpanel, aria-selected, roving tabindex, ←/→/Home/End, localStorage 'dash.qtab' try/catch+화이트리스트. 선택 탭은 굵기+3px 밑줄(--accent)로 색 외 구분. 탭 전환은 hidden만 바꿈(카드 재생성 없음, sig 조기반환과 무충돌).

## 3. 패치 (적용 순서: 시험 → fmt.js → index.html → style.css → app.js)
(전문 diff는 직전 응답 본문의 3-1~3-5절. 요점)
- test/questions.test.js: require에 qGroups,qClock 추가 + 시험 4건 추가(혼합 9건 → pending [f,b,c,g], answered [h,i,a], done [e,d], counts{4,3,2}; 같은 날 q-10,q-9,q-2 순; 불변·이상값·빈 입력; qClock '09:05:07'·'23:59:00'·''·'').
- fmt.js: qGroups·qClock 추가, module.exports에 두 함수 추가.
- index.html: aside#qpanel 안을 .qtop(qhead[h2·#qbadge·#qrefresh(aria-label '질문 목록 새로고침', ↻ 새로고침)·#qclose], #qchecked, #qtabs[#qtab-pending '미응답 0', #qtab-answered '응답 0'])) + #qnote + #qpane-pending(#qempty '답을 기다리는 질문이 없습니다', #qlist) + #qpane-answered(#qempty-answered '아직 답한 질문이 없습니다', #qanswered, details#qdone>#qdonesum+#qdonelist)로 교체.

- app.js: qUi 확장(busy·okAt·tab·새 요소 참조), qRender를 qGroups 기반으로 교체(탭 라벨·배지·헤더 버튼은 counts.pending), qSetTab+키보드+localStorage 복원 추가, pollQuestions(manual) 교체(busy 가드·okAt·확인 줄·수동 알림), qUi.refresh.onclick=()=>pollQuestions(true). poll() 안 await pollQuestions()는 그대로.
