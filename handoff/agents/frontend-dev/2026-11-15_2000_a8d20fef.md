### 1. 바뀐 파일과 요약
`frontend/js/instedit.js`

### 2. 메인이 돌릴 명령과 기대 결과
```
export PATH="$PATH:/c/dev/node/node-v22.23.4-win-x64"
node --test "frontend/test/*.test.js"
```
기대는 0 fail이다(기존 1141건 + 이번에 추가한 12건 안팎).
확인용: `git diff -U0 frontend/js/dashboard.js | grep -nE "doConfirm|dmDoConfirm|confirmFail"` → 출력 없음.

실패할 수 있는 지점(코드만 읽고 짠 부분)이 두 군데 있다.
- 새 테스트 '개원 확인 필요 기관의 상세…'의 대조 부분은 일반 기관 paneHtml에 `db-term`이 나온다고 가정한다. `dash.termBar`가 가짜 rec에서 빈 값을 주면 이 단언만 실패한다. 구현이 아니라 테스트 입력의 문제다.
- 링크 검사는 Java `URI`를 정규식으로 흉내 낸 것이다. 극단적인 모양(예: IPv6와 포트, 마지막 조각이 숫자인 호스트)은 서버와 다를 수 있다. 서버가 400을 내면 서버 문구가 그대로 묶음 안에 보인다.

### 3. 지시에서 벗어난 판단
- `reason`은 `scheduleCheck` 반환값에 추가했다. 기존 테스트는 필드별 단언이라 영향이 없다.
- 입찰주기는 정수만 허용했다(`^\d+$`). 서버 Integer로 보고 정했고, "4.5"는 막힌다. 소수 주기가 필요하면 알려 달라.
- lng·lat 형식은 `^-?\d+(\.\d+)?$`다. `1e3`·`0x10`은 숫자로 보지 않는다.
- qa 테스트 4(`basicPatch`)는 '본문에 term 없음 + `basicErrors` 오류' 두 단언으로 나눴다. qa 테스트 8(`statusCheck`의 형식 오류 openDate 의도 고정)은 지시 목록(1~7)에 없어 추가하지 않았다.
- `applyBidCases`는 공고가 있으나 날짜가 없는 경우에도 `_bid`를 지운다. 이전 적용분의 표시가 남지 않게 하려는 것이다. `contractEnd`가 낡은 채 남는 기존 동작은 그대로 뒀다(범위 밖).
