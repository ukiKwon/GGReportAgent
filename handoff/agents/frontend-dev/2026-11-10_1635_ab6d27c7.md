- diff 줄 번호는 현재 파일 기준이다. hunk 헤더의 새 쪽 시작 번호는 누적 오프셋으로 계산한 값이다. 0줄 문맥 hunk가 있어 `git apply --unidiff-zero`가 필요하다. 편집 도구로 적용하면 old/new 텍스트 기준으로 하면 된다.

## 2. 확인한 맞물림
- soon(sub, label, tag, note, withTasks, id, onlyRoles) 인자 순서 확인. soon('준비 과제','제안서 사전준비 프로세스', undefined, '', false, PREP_ID)는 tag가 기본 '준비중', id가 'soon:사전준비'가 된다.
- subs 없는 relate는 subOrder가 [''], showSubs가 !!cat.subs로 false. soon('', ...)의 sub는 ''.
- showSubs 예상: 영업팀(전체 권한)은 scan·plan·manage·tools true, relate false. 디자이너 manage는 true(작성에 작업함·공동 작성 2개). 영업팀 approvals=false의 manage는 false(진행·결재 1개, 기존 테스트 L158-166 기대값 유지). 예산·전산팀 manage는 false(진행 2·작성 1). 예산·전산팀 plan은 이사회 자료 작성 1개뿐이라 소제목 없음.
- 준비중 라벨(키 없는 항목) 합계 17 = scan 3·plan 5·manage 4·relate 2·tools 3.
- .nav-label은 대분류 버튼(app.js:673)에도 쓰이므로 CSS는 .nav-item .nav-label로 범위를 좁혔다.
