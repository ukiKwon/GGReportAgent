PR-4(행·열 삽입/삭제, 되돌리기, '잠김' 제거) 구현을 마쳤다. 다만 Bash 도구가 없어서 테스트를 실행하지 못했다. 브라우저에서도 열어 보지 못했고, 테스트 기대값은 손으로 계산해 맞췄다.

## 1. 고친 파일 (서버·data·handoff는 건드리지 않음)
**`frontend/js/board.js`** (한글이라 모두 Edit로 수정)
- **저장·카탈로그**
  - `loadCatalog`는 서버가 `limits`를 주면 결과에 담고, 없으면 키를 만들지 않는다.
  - `saveForm(fetch, st, opts)`는 400 `UNMAP_CONFIRM_REQUIRED`를 `{ok:false, unmap:{count,dropped,message}}`로 돌려준다.
  - 성공 응답의 `dropped_mapped`는 `droppedMapped`로 담는다.
- **편집 상태(`editFromForm`·`editAdd`)**
  - 표마다 `structOk`, `rowIds`, `colIds`, `seq`, `origStruct`가 생겼다.
  - 서버 `row_ids`/`col_ids`가 둘 다 있고 길이가 격자와 맞을 때만 행·열 편집이 켜진다(`structOk`).
  - 양식 단위로 `limits`를 받는다.
- **순수 함수** (`board.rc*`, `board.limitsOf`, `board.gridWidth`)
  - 행·열 삽입/삭제는 `rcInsertRow`, `rcDeleteRow`, `rcInsertCol`, `rcDeleteCol`. 병합 갱신, 보호 규칙, 상한은 `rcRules`가 처리한다.
  - 되돌리기는 `rcPush`/`rcUndo`다. 조작 직전의 표 구성 사본을 쌓는다. 되돌릴 때 지금 입력된 글자는 유지하고, 이미 빠진 표의 항목은 건너뛴다. 최대 50단계.
  - 이름·문구 도우미와 `rcEmptyName`(빈 이름 검출)도 이 묶음에 있다.
- **변경 감지·본문 변환**
  - `changeCount`는 표마다 1건이다. 행·열을 넣었다 지우면 0건으로 돌아온다.
  - 행·열만 바뀐 표의 배지는 '행·열 바뀜' 하나다. 글자도 바뀌었으면 '변경됨'이 함께 붙는다.
  - `putBody(st, opts)`는 구조가 바뀐 표만 `cols`+`rows`를 보낸다(`cells`는 안 보냄).
    - 새 열 id는 임시 `n1`, `n2`…이고 서버 열 id와 겹치지 않게 발급한다.
    - 새 행 id는 `null`이다. 병합으로 가려진 칸은 보내지 않는다. 연결 칸(mapped) 글자는 `""`로 보낸다.
    - `confirm_unmapped`는 `opts.confirmUnmapped`가 있을 때만 붙는다.
  - `validateEditAt`에 빈 행/열 이름 오류가 추가됐다. 문구는 "N번째 표에 이름이 빈 행/열이 있습니다."이고, 고치러 가기 대상은 그 칸이다.
- **화면 HTML**
  - 안내 문구 `editGuideHtml`(화면에 한 번, 편집 막대 아래·양식 이름 위).
  - 손잡이·메뉴 패널: `rcMenuHtml`은 `role="group"`에 버튼 3개이고, 꺼진 항목은 `aria-disabled`와 이유 한 줄로 그린다.
  - 행 왼쪽 `td.bd-gut`, 열 위 `tr.bd-colbar`, 삭제 대기 칸 표시, `data-pos`.
  - 편집 막대에 [되돌리기]와 `#bd-rowcol-msg`가 생겼다.
  - 값 칸(`input:true`)은 입력이 아닌 글자로, 연결 칸은 틸 배경과 title만 남겼다. 이름 칸이 비어 있어도 새로 넣은 칸(`fresh`)이면 입력으로 그리고 placeholder '행 이름'/'열 이름'을 단다.
  - 새 칸의 aria-label은 "표 제목 · N번째 열/행 이름"이다.
- **배선**
  - 손잡이로 메뉴를 열고 닫는다. 한 번에 하나만 열리고, 메뉴 밖 클릭·Esc·표 가로 스크롤·창 크기 변경에서 닫힌다. Esc는 닫고 손잡이로 포커스를 돌려준다.
  - 키보드(Enter/Space)로 열면 첫 켜진 항목으로 포커스가 간다.
  - 삽입 뒤에는 새 머리 칸으로 포커스가 간다.
  - 삭제는 연결 칸이 없으면 즉시 실행하고 [되돌리기] 링크를 띄운다. 연결 칸이 있으면 카드 안 확인 줄을 띄우는데, 첫 포커스는 [그대로 두기]다. 삭제 뒤에는 올라온 행(열)의 손잡이로 포커스가 간다.
  - UNMAP 오류를 받으면 인라인 확인 줄(`[저장][돌아가기]`, 첫 포커스 [돌아가기])로 건수를 알린다. 사용자가 확인하면 `confirm_unmapped:true`로 다시 보낸다. 첫 요청에는 이 값을 보내지 않는다.

**`frontend/index.html`**: `.bd-lock` 규칙을 지우고 새 CSS를 추가했다(`.bd-edit-guide`, `.bd-swatch`, `.bd-sr`, `.bd-gut`, `.bd-colbar`, `.bd-handle`, `.bd-rcmenu`, `.bd-rc-item`, `.bd-rc-why`, `.bd-undo`, 대상·삭제 대기 표시, 560px 이하). 기존 변수만 썼다.

## 3. 지시와 달리 판단한 것
- **행·열 편집 켜는 조건**: `row_ids`/`col_ids`가 없거나 길이가 안 맞는 표는 손잡이를 아예 그리지 않는다. 서버가 아직 id를 안 주면 구조를 보내면 모든 행이 새 행으로 취급되기 때문이다. 그래서 서버(PR-2)가 붙기 전에는 이 기능이 조용히 꺼져 있다.
- **값 칸이 입력이 아니게 됨**: 서버가 `input:true`로 표시한 비연결 값 칸은 예시 글자로만 보이고 편집할 수 없다. 이전에는 글자가 있는 비연결 칸이 전부 입력이었다. 안내 문구의 "숫자는 예시"에 맞춘 것이다. 지시가 다른 뜻이면 한 줄로 되돌릴 수 있다.
- **`max_table_cells`(표당 300칸)**: 계약의 limits에는 없는 키다. 서버가 주면 쓰고, 없으면 기본 300을 쓴다.
- **limits의 출처**: 카탈로그 응답의 `limits`, 또는 양식 응답의 `limits`를 받는다. 편집을 시작할 때 카탈로그를 한 번 받아 둔다. 못 받으면 기본 한도(40행·12열·칸 300·양식 800)를 쓴다.
- **빈 이름 판정**
  - 새 행은 그 행이 직접 가진 이름 칸 중 가장 안쪽 칸이 비면 오류다.
  - 새 열은 머리 행에서 그 열을 덮는 칸이 비면 오류다. 구분 병합 안쪽에 넣은 열은 머리가 이미 이름을 가지므로 오류가 아니다.
  - 기존 행·열은 이름이 비어 있어도 오류가 아니다.
- **스펙에 없던 문구**
  - 머리 행 위 삽입 이유: "머리 행 위에는 행을 넣을 수 없습니다."
  - 머리 행 손잡이 이름: "머리 행 편집"
  - 상한 문구: 표당 칸 "표 하나에 칸은 최대 N개까지 넣을 수 있습니다." 양식 "양식 전체에 칸은 최대 N개까지 넣을 수 있습니다."
  - 연결 칸 저장 확인 문구: "…칸 N개가 양식에서 빠집니다. 저장하면 작성할 때 이 값들이 문서에 들어가지 않습니다. 그래도 저장할까요?"
  - 저장 성공 문구는 `dropped_mapped`가 있으면 " 엑셀 값이 들어가는 칸 N개가 빠졌습니다."를 덧붙인다.
- **알림 낭독**: 편집 막대를 다시 그린 뒤 50ms 있다가 `#bd-rowcol-msg`를 채운다. `aria-live`가 낭독되게 하려는 것이다.
- **`aria-controls`**: 메뉴가 닫혀 있어도 손잡이에 항상 붙어 있다.
- **새 칸 표시(`fresh`)**: 구분용 플래그이고 서버로는 보내지 않는다.
- **칸 aria-label 규칙**: 빈 새 이름 칸에만 "N번째 행/열 이름"을 쓴다. 기존 칸 이름 규칙은 그대로다.

## 4. 남은 위험
- 브라우저·키보드 동작(포커스 이동, 메뉴 위치, sticky 열)은 코드로만 검증했다. `qa-verifier`나 playwright로 확인이 필요하다. 서버 연결 없이는 실제 저장 흐름도 못 본다.
- 머리 행 보호는 0번 행만 대상이다. C-5처럼 머리가 여러 줄인 표의 둘째 줄은 삭제할 수 있다.
- `columns`가 문자열 배열이고 머리 행이 없는 표의 열 이름은 `columns[idx]`에서 읽는다. 이 경우 `<thead>`는 편집하지 않는다.
- 서버의 `row_ids`/`col_ids`가 이 가정(길이 = 행 수, 격자 폭)과 다르게 오면 편집이 꺼진다. 서버 응답 모양은 PR-2와 대조가 필요하다.
