## 결론 먼저

코드를 따라가 봤지만, **목표 결재(TARGET_CHANGE)의 승인 경로가 배지 갱신을 건너뛰는 곳은 없고, 서버가 승인된 건을 계속 '대기'로 세는 곳도 없습니다.** 승인한 사람 본인의 화면에서는 배지가 곧바로 줄도록 짜여 있습니다. 사용자가 본 '1'은 **다른 화면(다른 탭, 다른 사람 세션)의 배지가 갱신 신호를 못 받아서** 남은 것으로 보입니다. 이 판단은 코드 추적으로만 한 것입니다.

## 1. 대상·방법·못 본 것

- **본 것**: `approvals.js`, `notify.js`, `portal.js`, `team.js`, `kbboard.js`, `nav.js`, `app.js`를 읽었습니다. 서버는 `ApprovalRequestService.java`를 읽었습니다.
- **못 본 것**: localhost:8080 화면은 열지 않았습니다. 로그인과 두 역할이 필요하고, 승인은 쓰기 동작이라 금지돼 있어서 실측은 못 했습니다. 배지가 실제로 얼마나 늦게 줄어드는지는 확인하지 못했습니다.

## 3. 원인 구분

**승인 경로: 이상 없음**
- 카드의 승인 단추(`approvals.js:526`)는 `act()`(`:683`)를 거쳐 `loadRequests()`를 부르고, 그 안에서 `notify.refreshAppr()`가 호출됩니다(`:726`).
- 이사회 자료 승인(`reviewDecide`)도 `loadRequests()`를 부르므로 같은 경로입니다.
- 종류별 분기는 없습니다. 목표 결재만 갱신을 건너뛰지 않습니다.

**서버 집계: 이상 없음**
- `ApprovalRequestService.java:659`에서 inbox는 `selectPending()`만 대상으로 합니다.
- 목표 결재는 결재선이 1단계(`:265`)이고, 승인하면 `:482-485`에서 바로 APPROVED가 됩니다. 이후 inbox에서 빠집니다.
- 영업부장의 `headOverride` 항목도 PENDING일 때만 나옵니다.
- 따라서 승인된 건이 inbox 건수에 남지 않습니다.

**남는 원인 후보 (프런트, 모두 '다른 화면' 문제)**
- **A. 승인하지 않은 쪽 화면의 갱신 지연.** 상신자 화면, 다른 브라우저 탭, 다른 결재자 화면의 머리 띠 배지는 최대 30초 뒤에 줄어듭니다. 결재함 탭 배지는 그 화면을 다시 열기 전까지 안 줄어듭니다. 사용자가 말한 '바로 줄지 않는다'와 가장 잘 맞습니다.
- **B. 두 배지의 기준이 다릅니다.** 탭 배지는 inbox 전 건을 세고(영업부장이 반려만 가능한 `can_head_reject` 건 포함), 머리 띠 배지는 `can_decide`만 셉니다. 승인 뒤에는 둘 다 줄어듭니다. 다만 승인 전에 두 숫자가 어긋나 보일 수 있습니다.

실측으로 확인하려면 팀장 화면과 상신자 화면을 두 창으로 띄워 놓고, 승인 뒤 어느 쪽 어느 배지가 얼마 만에 줄어드는지 보면 됩니다.

## 4. 최소 패치안 (원인 A 완화, 지도 렌더 무관)

한 가지 일만 합니다. 탭으로 돌아오거나 창에 포커스가 올 때 결재 배지를 다시 계산합니다.

`frontend/js/notify.js`, `notify.start` 안의 폴링 설정 바로 아래:
```js
// old
    pollTimer = setInterval(function () { fetchList(); fetchAppr(); }, POLL_MS);
  };
// new
    pollTimer = setInterval(function () { fetchList(); fetchAppr(); }, POLL_MS);
    if (!notify._wired && typeof document !== 'undefined') {   // 다른 탭·창에서 승인한 뒤 돌아오면 30초를 기다리지 않고 바로 센다
      notify._wired = true;
      document.addEventListener('visibilitychange', function () { if (!document.hidden) { fetchAppr(); fetchList(); } });
      if (typeof window !== 'undefined') window.addEventListener('focus', function () { fetchAppr(); });
    }
  };
```

결재함 탭 배지(원인 A의 두 번째 부분)는 결재함이 열려 있는 동안만 다시 받으면 됩니다. `notify.refreshAppr`를 부를 때 결재함도 `loadRequests`를 하도록 연결합니다.

`frontend/js/approvals.js`, `approvals.mount` 근처에 추가:
```js
// old
  approvals.openTab = function (key) { wantTab = approvals.normTab(key); };
// new
  approvals.openTab = function (key) { wantTab = approvals.normTab(key); };
  // 결재함이 보이는 채로 창에 돌아오면 목록·탭 배지도 다시 받는다(다른 탭에서 처리됐을 수 있다)
  if (typeof document !== 'undefined') document.addEventListener('visibilitychange', function () {
    const p = el('ap-pane-inbox');
    if (!document.hidden && p && p.offsetParent !== null && !review) loadRequests();
  });
```

주의: `loadRequests`는 `paintRequests`를 부르므로 결재 카드의 입력 중인 의견 칸이 지워질 수 있습니다. 그래서 `!review`와 가시성 조건을 걸었습니다. 입력 중 손실이 걱정되면 이 두 번째 패치는 빼고 첫 번째만 적용해도 됩니다. 머리 띠 배지는 그것으로 충분히 줄어듭니다.
