3. **시험 공백, `frontend/test/noticerec.test.js`**
   - 상단에 `const store = require('../js/store.js')`를 추가했습니다.
   - `nr.save` 시험을 추가했습니다. confirmed true는 `save_confirmed`, false와 생략은 `save`이고, `X-Screen-Id`는 `bid_notice`입니다. 경로(`a%2Fb`), POST, Content-Type, 본문, 응답도 확인합니다.
   - `ov.waiting`과 `ov.count` 시험을 추가했습니다. offline은 대기가 아니고, idle과 loading은 대기입니다. 값은 `parts.pending` 길이(5가 아니라 3)입니다. 가짜 `document`로 `paintNavBadge`를 불러, loading 중에는 배지가 없고 받은 뒤에는 "미처리 3건" 배지가 붙는지 봅니다. `parts`가 null이면 경과 전체를 세고, `summary`도 null이면 0입니다.
   - `onLogin` 시험을 둘 추가했습니다. 첫째는 fetch 1회, 대기 중 팝업 보류, 미처리 0이면 팝업 없음, 2건이면 팝업 1회입니다. 둘째는 대기 중 로그아웃하거나 다른 사번이 로그인하면 팝업이 없고, 같은 사번이면 팝업이 뜨는지 봅니다. `ov.refresh`·`ov.count`·`ov.showPopup`과 `store.loadSession`은 시험 안에서 가짜로 바꿨다가 finally에서 되돌립니다.
   - 152줄 부근 `a && b || c`를 `a && (b || c)`로 괄호 정리했습니다.
   - `notice_text.test.js:62`의 `assert.ok(it.phase === 'unknown')`을 `assert.strictEqual`로 바꿨습니다.
4. **`frontend/js/kbboard.js` footHtml(60~80줄 부근)**

## 메인이 실행할 명령과 기대 결과
PATH에 `/c/dev/node/node-v22.23.4-win-x64`를 더한 뒤 실행합니다.
- `node --test frontend/test/noticerec.test.js frontend/test/notice_text.test.js frontend/test/kbboard.test.js frontend/test/overdue.test.js`
- 이어서 전체 `node --test "frontend/test/*.test.js"`

기대 결과는 모두 통과입니다. 새로 추가한 시험은 noticerec 4건(save, waiting·count, onLogin 2건)입니다. kbboard 시험 1건은 기존 시험에 단언을 추가한 것이고, 건수는 그대로입니다. 새 시험 3건은 `setTimeout` 10ms로 비동기 완료를 기다립니다. 느린 PC에서 간헐 실패하면 이 값부터 늘려 보세요.

## 지시에서 벗어났거나 판단한 것
- **sr-only 확인**: `index.html:1391`에 `.sr-only`가 이미 있고, `.db-why`는 1606줄에 있습니다. `.hb-src` CSS는 없으니 메인이 규격 6-1의 CSS 두 줄을 넣어야 합니다.
- **muni:false 문장**: 규격이 "기획 확인 필요"라고 한 부분입니다. 법원·공공기관 문장만 남기고("법원은 …, 공공기관은 … 칸으로 셉니다."), 둘 다 꺼져 있으면 빈 문장 뒤에 이어지는 문장만 남깁니다. 지금 화면에서는 `OURS_SCOPE.muni`가 true 상수라 생기지 않습니다.
- **주소가 비었을 때**: plans.js 114행 방식대로 링크와 안내를 빼고 "지자체 출처: 행안부 금고지정 현황(2026.1.1. 기준)" 글자만 남깁니다.
- **overdue.test.js는 건드리지 않았습니다.** onLogin·count·waiting 시험은 지시한 대로 `noticerec.test.js`에 넣었습니다. overdue.test.js에는 기존 onLogin 시험이 없습니다.
