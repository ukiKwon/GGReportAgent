### 4-2. 공통 검증 함수 설계안 (`popup.js`의 `dlg` 네임스페이스, 순수/DOM 분리)
```js
// 순수 함수(node 테스트 가능)
dlg.mergeDescribedBy(existing, id)   // "a b" + "c" → "a b c", 이미 있으면 그대로
dlg.removeDescribedBy(existing, id)  // 그 토큰만 제거, 비면 null
// DOM
dlg.invalid(field, msg, opts)        // opts: { focus:true, id:null, group:null }
dlg.clearInvalid(field)
dlg.clearAll(root)
dlg.firstInvalid(root)               // DOM 순서 첫 칸
```
- `invalid(field, msg)` 동작:
  1. `aria-invalid="true"`.
  2. 칸 바로 아래에 `<p class="dlg-ferr" id="<field.id>-ferr">`를 만들거나 갱신(같은 id가 있으면 재사용).
  3. `aria-describedby`에 그 id를 **합쳐서** 넣음(`mergeDescribedBy`).
  4. `opts.focus`이면 `field.focus({preventScroll:false})` 후 `.dlg-body` 안에서 `scrollIntoView({block:'nearest'})`. 머리·안내 줄이 고정이라 가려질 일은 없습니다.
- `role="alert"`는 칸 문구에 붙이지 않고 **창 상단 `.dlg-err` 하나**에만 요약을 둡니다("2곳을 확인하세요"). 이유는 칸마다 `role=alert`이면 스크린리더가 연달아 읽기 때문입니다. 포커스 이동이 곧 알림 역할을 합니다.
- `clearInvalid`는 해당 칸의 `input`/`change` 이벤트에서 자동 호출합니다(app.js:1013 `clearInvalid`와 같은 의미). 칸이 radio/checkbox 묶음이면 `fieldset`(또는 `role=group`)을 대상으로 하고 `aria-invalid`는 그룹에 줍니다.
- 마이그레이션 위치(한 번에 하지 말고 창마다 한 커밋): instedit.js:458~467·:611, bankcontract.js:439~443, headcard.js:333~340·:909, board-material.js:351·:613·:632, prep.js:1169~1170·:1419, team.js:827~828·:847~852, app.js 기관 추가(새로 붙임).
- 동작 변경이 따르는 곳:
  - hb·pp·tm은 "입력이 모자라면 [저장] 비활성 + `.tm-why`" 방식입니다. 이 의견대로 하려면 단추를 활성으로 두고 클릭 때 `dlg.invalid`로 알려야 합니다. 두 방식을 섞으면 이유 문구와 칸 문구가 중복됩니다. 선택이 필요합니다(아래 열린 질문).
  - 서버 오류(500·연결 실패·권한)는 칸이 없으므로 `.dlg-err` 창 상단 줄이 남아야 합니다. 이름 중복 409는 이름 칸 `dlg.invalid`로 보낼 수 있습니다(app.js:424).
- 테스트: `mergeDescribedBy`/`removeDescribedBy` 순수 단위(중복·빈 문자열·토큰 순서), 가짜 DOM에서 `invalid`→`aria-invalid`·`describedby`·포커스, `clearInvalid`→모두 되돌림. 소스 래칫: `setAttribute('aria-invalid'`가 `popup.js` 밖에서 줄어들게만.
