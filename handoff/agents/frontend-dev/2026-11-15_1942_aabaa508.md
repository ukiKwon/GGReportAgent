### 4. 항목 2 — serve.py 405·RecursionError (하)
NEXT·START·`handoff/agents/`에서 실제 로그나 재현 기록은 찾지 못했다(START.md 8행에 이름만). 아래는 코드 읽기 추정이다.

**405 — 추정 원인**: serve.py는 `do_POST`에서만 `/api/questions`에 405를 준다(`serve.py:87~91`). 그런데 serve.js는 이 경로의 GET·HEAD 외 모든 메서드에 405+`Allow: GET, HEAD`를 준다(`serve.js:50`)고 `server.test.js:366~373`이 POST·PUT·DELETE 모두 405로 시험한다. Python `BaseHTTPRequestHandler`는 `do_PUT`·`do_DELETE`가 없으면 **501**을 돌려준다. 또 POST는 `/api/questions` 분기가 Host 검사(`serve.py:99~102`)보다 먼저라 위조 Host에도 403이 아닌 405가 간다. 즉 "serve.py가 serve.js와 같은 405를 안 낸다"는 계약 불일치다. (실제 장애는 아니다. 어디서 405를 봤는지는 모르니, 다른 경로에서 본 것이라면 알려 달라.)

**RecursionError — 추정 원인**: POST 본문 상한은 16KB(`MAX_BODY`, 109행)인데 `json.loads`(`serve.py:108`)는 `[[[[…`처럼 깊게 중첩된 본문(약 1000단 이상, 16KB면 8000단 가능)에서 `RecursionError`를 낸다. 이는 `RuntimeError` 계열이라 `except (ValueError, OSError)`(130행)에 안 잡혀 핸들러 스레드가 트레이스백을 찍고 응답 없이 연결이 끊긴다. 파싱을 통과한 깊은 객체도 `json.dumps`(129행)에서 같은 오류를 낼 수 있다(쓰기 전에 직렬화되므로 state.json이 잘리지는 않는다). serve.js는 `JSON.parse` 예외를 `catch(e)`→400으로 처리(`serve.js:45`)해서 같은 입력에도 응답한다.

            return True
        self.send_response(405)

        self.send_header("Content-Length", "0")
        self.end_headers()

    def do_PUT(self):
