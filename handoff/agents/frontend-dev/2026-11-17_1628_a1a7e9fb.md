## 2. 요구 요약과 결정 (근거: 파일:줄, 적용 전에 다시 grep할 것)
- **처리 화면 위치**: 새 파일 `frontend/js/plancollect.js`로 만들고, `admin.js`에는 view `collect` 연결만 둔다.
  - 이유: `admin.js`는 868줄이고 view마다 `ad-body`를 직접 그린다. 여기에 화면 하나를 더하면 한 파일이 너무 커진다.
  - 순수 함수를 따로 두어 node 시험이 쉬워진다.
  - `admin.js`에는 이미 `function collect()`(격자 수집)가 있어 이름이 겹치지 않게 모듈명은 `root.plancollect`로 했다.
- **상세 요청 줄 / 목록 칩 / 요약 절 / 상태 조회**: `plans.js`에 넣는다. 공용 함수 `plans.reqBadgeHtml`, `plans.reqLineHtml`을 노출한다.
- **메뉴 배지**: overdue.js와 app.js 두 곳에 걸려 있어 작은 패치가 둘 필요하다(5절).
  - `overdue.js` `paintNavBadge`는 모든 항목의 `.nav-count`를 지운다. 그대로 두면 수집 요청 배지가 지워진다.
  - `app.js` `paintCatBadges`는 문구가 '공고 예정일 경과 미처리'로 고정돼 있다. 시스템 관리 분류가 접혀 있으면 틀린 문장이 낭독된다.
- **서버 값 사용**
  - 디자이너 버튼 숨김은 서버 `can_request`로 한다.
  - 실행 버튼은 `agent_enabled`가 true일 때만 DOM에 그린다.
  - 메뉴 배지는 `GET /plan-collect/admin/status`의 `requested_count`다.
- **서버 원문은 화면에 내지 않는다**: 오류는 HTTP 상태와 `detail.code`(있을 때)로, 결과는 `result_cd`로 문구 표에서만 고른다.

## 6. 규격에서 달라진 점과 이관 메모
**규격에서 달라진 점(디자인 확인 필요)**
- 사유 입력 최대 길이는 서버 상한 100자로 했다(규격 200자). 문구도 '100자 이내'다.
- 수집 서버 호출이 실패하면 서버가 요청을 '실패'가 아니라 '요청됨'으로 되돌린다. 그래서 결과 문구를 "보내지 못했습니다 — …"로 했다. 규격의 "'실패'로 바뀌었습니다"는 쓰지 않았다.
- 실패는 종료 상태(팀 결정)이고 서버도 실패 행은 다시 실행하지 못한다. 그래서 규격 표의 실패 행 [다시 실행] 버튼은 만들지 않았다.
- "이미 요청한 기관입니다(나 포함 n명)" 문구를 새로 만들었다(서버 outcome DUPLICATE용, 규격에 없음).
- 수집 중 행의 상태 칸 보조 줄에 "실행자 이름 · 수동 표시/수집 서버로 보냄"을 넣었다(서버 응답에 있는 값).
- 기관 종류·지역 줄은 서버 응답에 없어 화면의 기관 목록(`render.allInstitutions`)에서 찾는다. 못 찾으면 줄을 뺀다.

**이관 메모**
- [이관: 백엔드] `Menus.SCREENS`(`Menus.java:57`)에 `"admin:collect"`를 넣어야 한다.
  - 기다리는 것: 허용 목록에 없으면 이 화면의 열람 기록이 조용히 버려진다.
  - 근거: `AuthController.java:58`, nav 항목 id가 `admin:collect`.
  - 연관 시험이 있으면 같이 고쳐야 한다.
- [이관: 백엔드] 상세 요청 줄의 마지막 행("마지막 요청이 실패·제외로 끝남 → 칩 + 사유 + 다시 요청")을 구현하지 못했다.
  - 이유: `GET /plan-collect/status`가 열린 요청만 준다.
  - 필요한 것: 기관별 마지막 닫힌 요청 `{status_cd, closed_at, close_reason}` 필드.
  - 화면은 `plans.reqLineHtml`에 그 분기를 더하기만 하면 된다.
- [이관: 백엔드] 400·409·404 오류가 문자열 `detail`이라 화면이 HTTP 상태만으로 문구를 고른다(제외 사유가 개인정보로 거부된 400도 같은 문구).
  - 필요한 것: 503·409(BUSY)처럼 `detail.code`를 주는 방식(예: `REASON_REQUIRED`, `REASON_PII`, `STATE_CHANGED`).
  - 화면은 `pc.errorText`에 분기만 추가하면 된다.
- [이관: 디자인] 위 "규격에서 달라진 점" 확인, 그리고 시스템 관리 접힌 분류의 합계 배지(5절). 적용 뒤 1280폭 렌더 확인(표 너비·대비는 계산값이었다).
