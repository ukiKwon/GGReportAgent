## 2. 요약
- footHtml(n, m, busy)에는 can이 없다. 호출처는 renderFoot(plans.js 657) 하나뿐이고(시험 제외), 같은 파일 안에 CS.can이 있다(447·467: `!!data.can_request`, 상태가 ok가 아니면 freshCollect의 false). 따라서 4번째 인자 `can`만 추가하고 renderFoot에서 `CS.can`을 넘긴다. 요청 줄(806)과 같은 값이라 판정이 어긋나지 않는다. CS가 ok가 아닐 때(offline·forbidden·로딩)는 false이므로 "확인용입니다."만 나온다.
- 배지: onNavDrawn은 메뉴를 그릴 때마다 불리므로, 거기서 한 번만 window focus 리스너를 단다(모듈 플래그로 중복 방지). 핸들러는 pc.refreshBadge(false)만 부른다. refreshBadge가 이미 DOM 메뉴 없음·서버 미연결·사용자 바뀜·403 중단·60초 제한을 처리하므로 규칙은 그대로 유지된다. 로그아웃 후에는 메뉴가 없어져 navBtn()이 null이라 호출이 즉시 끝난다. 리스너를 지우지 않는 것은 의도(한 번만 달고 refreshBadge 가드에 맡김).
- window focus를 고른 이유: 탭 전환 때 대체로 같이 발생하고, 다른 창 갔다 올 때(탭은 계속 보임)는 visibilitychange가 안 뜨므로 focus가 더 넓다. visibilitychange와 함께 달면 중복 호출이 생기므로 하나만 쓴다.

### 패치 E(시험, 먼저). frontend/test/plancollect.test.js (CRLF) 272줄 `});` 뒤에 추가
```js
test('배지: 창으로 돌아오면(focus) refreshBadge(false) 1회, 리스너는 한 번만 단다', function () {
  const calls = [], handlers = [];
  const win = { addEventListener: function (t, f) { handlers.push([t, f]); } };
  assert.strictEqual(pc.bindBadgeFocus(win), true);
  assert.strictEqual(pc.bindBadgeFocus(win), false);   // 중복 등록 방지
  assert.strictEqual(handlers.length, 1);
  assert.strictEqual(handlers[0][0], 'focus');
  const orig = pc.refreshBadge;
  pc.refreshBadge = function (force) { calls.push(force); return Promise.resolve(); };
  try { handlers[0][1](); } finally { pc.refreshBadge = orig; }
  assert.deepStrictEqual(calls, [false]);   // 60초 제한이 걸리는 force=false 로만
});
test('배지: addEventListener 없는 환경(node)에서는 아무 일 없음, 배지에 aria-live 없음', function () {
  assert.strictEqual(pc.bindBadgeFocus(null), false);
  assert.ok(PC_SRC.indexOf('aria-live') < 0 || !/pc-nav[^\n]*aria-live/.test(PC_SRC));
});
```
주의: 첫 시험이 모듈 플래그를 true로 만들므로 두 번째 시험의 bindBadgeFocus(null)은 플래그 때문에 false(의도와 별개로 통과). 순서 의존이 싫으면 두 번째 시험에서 null 단언을 빼도 된다. PC_SRC는 파일 상단에 이미 있는 변수(276행에서 사용).

### 패치 F. frontend/js/plancollect.js (CRLF) onNavDrawn 551–556 교체

```js
  pc.onNavDrawn = function () {   // app.drawNav 끝에서

new:

  // onNavDrawn 이 메뉴를 그릴 때마다 불리므로 플래그로 한 번만 단다. 배지에는 aria-live 를 넣지 않는다(바뀔 때마다 읽히는 소음 방지).
  let focusBound = false;
  pc.bindBadgeFocus = function (target) {
    const w = target || (typeof window !== 'undefined' ? window : null);
    if (focusBound || !w || typeof w.addEventListener !== 'function') return false;
    w.addEventListener('focus', function () { pc.refreshBadge(false); });
    focusBound = true;
    return true;
  };
  pc.onNavDrawn = function () {   // app.drawNav 끝에서
    if (!navBtn()) return;
    resetBadgeIfWhoChanged();
    pc.paintNavBadge();
    pc.refreshBadge(false);
    pc.bindBadgeFocus();
  };
```

## 5. 위험·되돌리는 법
- focus 시 refreshBadge는 60초 안이면 호출하지 않으므로 서버 부하 증가 없음. 리스너를 뺄 필요 없음(플래그·가드). 되돌리기: 패치 F의 bindBadgeFocus 블록과 호출 한 줄 삭제.
- footHtml 4번째 인자 생략 시 "요청 불가" 문구가 나온다(안전한 기본값). 요청 가능 사용자의 CS 응답이 늦으면 처음엔 '확인용입니다.'만 보였다가 응답 뒤 바뀔 수 있음(패치 C 주의 참조).
- 문구는 design-reviewer 규격 그대로. DOM id(pl-dl)·구조 불변이라 다른 시험 영향 없음.
