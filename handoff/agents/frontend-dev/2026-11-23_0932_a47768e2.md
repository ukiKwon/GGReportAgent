### 1. 바꾼 점
줄 번호는 편집 중 계속 밀려서 함수 이름으로 적습니다.

**board-minutes.js**
- **P2-1 파일을 바꿔 다시 미리보기**
  - `mn.fileSig(u)`를 새로 만들고, `mn.signature`는 같은 `slotSigs(u)`를 쓰도록 나눴습니다.
  - `mn.dropEdited(fix)`와 `mn.fixDroppedText(n)`를 새로 만들었습니다.
  - `doPreview`에서 요청을 만들기 전에 `u.pvFileSig`와 `fileSig`를 비교합니다. 다르면 고친 발언을 모두 버리고 이름표는 둡니다.
  - 버렸으면 `say("원문이 바뀌어 고친 발언 n건을 지웠습니다.")`를 하고, `u.fixNote`에 담아 `drawFix`가 `#mn-fix`에 보여 줍니다.
  - 요청에 고친 발언을 아예 싣지 않으므로 서버가 새 파일의 같은 번호 줄에 붙일 일이 없습니다.
  - 이름표는 `mergeFix`가 새 응답에 그 번호가 있을 때만 유지합니다.
  - `newUp`에 `fixNote`와 `pvFileSig`를 더했습니다.
- **P2-2 요청 시점 표식**
  - `doPreview`는 요청 직전에 `sig = mn.signature(u)`와 보낸 발언 모음 `sent`를 잡아 둡니다.
  - 응답이 오면 `u.pvSig = sig`를 넣고 다시 계산하지 않습니다.
  - `mn.mergeFix(fix, pv, {sent})`는 보낸 글과 다른 줄(요청 뒤에 바꾼 줄)의 `shown`을 덮지 않습니다.
- **P2-3**
  - `isEditFail`은 slot이 edit인 `CONTROL_CHAR`·`LIMIT_LINE`·`LIMIT_EDIT_LEN`을 포함합니다. 슬롯 없는 `LIMIT_EDIT_LEN`은 기존 시험 때문에 그대로 true입니다.
  - `errorText`는 slot=edit인 `CONTROL_CHAR`에 "고친 발언 {seq}에 쓸 수 없는 보이지 않는 문자가 있습니다. 그 글자를 지우고 다시 반영하세요."를 주고 field는 `'edit'`입니다.
  - 파일 쪽 `CONTROL_CHAR` 문구는 그대로입니다.
- **P2-4 `saveLabels`**
  - 시그니처를 `saveLabels(cur)`로 바꿨습니다.
  - 중간에 실패하면 "참석자 a·b는 저장했습니다. 참석자 c부터는 저장하지 못했습니다: {오류}"로 알립니다. 성공분이 없으면 오류만 보입니다.
  - 성공분은 `cur.data.speakers`와 원문 목록에 반영하고, `drawTr`와 `drawLbl`로 다시 그립니다.
  - 새 함수 `setLblBusy`가 저장 중에 표의 select·버튼, `#mn-edit-toggle`, `#mn-lbl-open`을 disabled로 둡니다.
  - 저장 중에는 `[고치기 끄기]`의 click 처리와 `toggleLbl`도 막습니다. 끝나거나 실패하면 `setLblBusy(cur,false)`로 풉니다.
  - `drawLbl`을 다시 그려도 저장 중이면 잠긴 채로 그립니다.
  - REV_CHANGED 뒤 `[새로 불러오기]`가 초안을 버린다는 안내는 그대로 뒀습니다.
- **P2-5 `toggleLbl`**
  - 원문을 받아 `drawLbl`을 다시 그리기 전에 포커스가 `mn-lb-`로 시작하는 칸에 있었는지 기억합니다.
  - 다시 그린 뒤 그 칸으로 되돌립니다. 포커스가 이미 body였다면 첫 소속 select로 보냅니다.
  - 사용자가 다른 곳으로 옮겼다면 포커스를 가져오지 않습니다.
- **P3-1 `revertAll`**
  - 되돌린 뒤 stale을 직접 계산합니다.
  - stale이면 기존 `FIX_REVERTED`와 `#mn-restale`로 보냅니다.
  - 아니면 새 문구 `FIX_REVERTED_SAME`("고친 내용을 모두 되돌렸습니다.")과 `#mn-fix`로 보냅니다.
  - `#mn-fix`에 `tabIndex=-1`을 줬습니다.
- **P3-2**
  - `mn.fixed(e)`를 새로 만들어 trim 뒤 비교합니다.
  - `editsPayload`, `mergeFix`, `utterLi`의 고침 배지가 이것을 씁니다.
  - `pvApply`도 공백만 다른 글은 "바뀌지 않음"으로 봅니다.
- **P3-3**
  - 소속만 고르고 역할이 비면 `cfg.set`을 하지 않습니다. 이전 값이 유지됩니다.

  - 소속·역할·번호를 모두 비우면 기존처럼 이름표를 지웁니다.

  - 지시문의 콜론을 그대로 따라서, 이 줄만 다른 줄("고친 뒤 …", 콜론 없음)과 모양이 다릅니다.

### 3. 지시와 다르게 판단한 것, 못 한 것
- **고친 발언 버리는 시점**: 응답을 받은 뒤가 아니라 요청 전에 비교해서 버립니다. 요청에 옛 edits를 실으면 서버가 새 파일의 같은 번호 줄에 붙이기 때문입니다. 실패했는데 발언을 이미 버렸다면 옛 미리보기를 남기지 않고 지웁니다(`u.pv=null`).
- **버린 건수 표시**: 상태 줄(`say`) 말고도 `#mn-fix`에 계속 보이도록 `u.fixNote`를 두었습니다.
- **P2-1 시험**: QA가 제안한 "새 응답 줄의 원래 글과 비교해 버린다"는 서버가 새 원래 글을 주지 않아 할 수 없습니다. 파일 표식 비교로 대신했습니다.
- **제목 편집기**: 상세 화면에 제목 수정 UI가 없습니다(`BTN.META`는 이름만 있고 편집 코드는 없음). 그래서 문구와 field만 `errorText`에 넣었고 시험 1건도 더했습니다. "제목 편집기에 오류를 단다"는 못 했습니다. 제목 수정 UI를 새로 만들 때 `errorText`의 `field:'title'`을 쓰면 됩니다.
- 실화면(포커스 복구, 저장 중 잠금)은 못 봤고, 위 시험은 DOM 없이 상태만 확인합니다. `toggleLbl` 포커스와 select disabled는 실제 브라우저로 확인해야 합니다.
- 컨트롤러 시험은 제가 돌려보지 못해 첫 실행에서 어긋날 수 있습니다. 실패하면 메시지와 함께 알려 주세요.

### 4. CSS
추가는 필요 없습니다. `#mn-fix`에 `tabIndex=-1`을 줬지만 프로그램으로만 포커스를 받아 기본 윤곽선으로 충분합니다. 윤곽선을 직접 정하고 싶으면 index.html에 아래를 넣으면 됩니다.
```css
.mn-fix:focus-visible { outline: 2px solid var(--focus, currentColor); outline-offset: 2px; }
```
`--focus`는 예시 변수이며 이 저장소 `:root`에 없을 수 있습니다. 쓰려면 기존 포커스 변수 이름에 맞춰 바꾸세요.
