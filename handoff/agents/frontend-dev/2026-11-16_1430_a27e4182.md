## 바꾼 곳

frontend/js/plans.js
- CHECK 상수를 지웠습니다.
- plans.srcBudgetText와 unverifiedCell을 새로 넣었습니다(budgetCell 바로 위, 약 61~77줄).
  - srcBudgetText는 note에서 "예산 원문: " 뒤 글자를 줄바꿈 앞까지 뽑고, 첫 " / " 앞까지만 남깁니다.
  - unverifiedCell은 조각이 있으면 db-why 글자로 "…(원문 표기)"를 냅니다. 40자를 넘으면 40자 + "…"로 자르고 전체를 title에 둡니다(esc 처리). 낭독용 글자는 "원문 표기 " + 전체 글자입니다.
  - 조각이 없으면 "예산 미기재"(db-why 글자)입니다.
- budgetCell 끝의 확인안됨 반환 두 곳을 unverifiedCell(it)로 바꿨습니다. 끝자리와, AMOUNT인데 금액·단위가 깨진 경우입니다.
- 계산값 규칙은 그대로입니다. 계산값이 UNVERIFIED면 상위사업 자신의 상태로 가서, note가 없으면 "예산 미기재"가 나옵니다.
- itemRowHtml에서 부분확인·확인안됨 칩 줄을 지웠습니다.
- checkCountsHtml 함수, docHtml의 '확인 상태' 줄, "'확인안됨'은 원문에서 아직 대조하지 못한…" 안내를 지웠습니다. check_counts와 check_cd는 읽지 않습니다.

frontend/test/plans.test.js
- budgetCell 확인안됨 테스트를 새로 썼습니다(기존 "나머지 상태" 테스트는 칩 검사를 빼고 유지).
  - note "예산 원문: 268+32 / 기타"는 "268+32 (원문 표기)"가 되고, 낭독은 "원문 표기 268+32"입니다.
  - 줄바꿈 앞에서 끊기는지, 실제 시드 예시("별도 합계 649,112백만원…")가 40자 + "…"와 title 전체로 나오는지 봅니다.
  - 정확히 40자는 자르지 않습니다.
  - note가 null, 빈 값, 다른 비고, 조각만 있고 내용이 없는 경우는 "예산 미기재"입니다.
  - 이스케이프와, 계산값 UNVERIFIED에 note가 없을 때 "예산 미기재"인지도 봅니다.
- itemRowHtml 테스트는 check_cd가 어떤 값이어도 확인안됨·부분확인·미조사·확인됨 글자와 칩이 없는지로 바꿨습니다.
- docHtml 테스트는 '확인 상태' 줄과 안내가 check_counts가 와도 없는지, plans.checkCountsHtml === undefined인지로 바꿨습니다.

## 지시와 달리 판단한 것
- AMOUNT인데 금액이나 단위가 깨져서 예전에 확인안됨 칩이 나오던 경우, 알 수 없는 예산 상태도 같은 unverifiedCell로 보냈습니다. 확인안됨 칩이 화면에 남지 않게 하려는 것입니다. 이 경우도 원문 조각이 없으면 "예산 미기재"로 보입니다.
- pop-unk 칩은 '자료 없음'에 아직 쓰여서 unk()와 CSS는 그대로 뒀습니다.
