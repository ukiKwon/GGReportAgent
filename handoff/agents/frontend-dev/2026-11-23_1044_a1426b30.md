## 1. 대상·방법·못 본 것

## 2. 원인·요구 요약
- 상세를 여는 곳은 results.js:498 `d.openDetail(rec, { opener: t })`이다. 막는 옵션은 넘기지 않는다.
- dashboard.js openDetail(1946)은 opener·screen·fallback·refocus·back·focus만 받는다. [제안 확정]을 막는 옵션은 없다.
- 기존 `readOnly`(dash.isViewOnly())는 역할로 정해지고 약정 편집·[기관 정보 수정]까지 함께 잠근다(1751·1756·1886). 이 요청은 [제안 확정]만 막아야 하므로 재사용하지 않는다.
- 선례는 `dash.CONFIRM_WHY`(404·1027)다. later·closed·past 등은 버튼을 없애고 같은 자리에 이유 글(.db-why)을 보여 준다.
- 권장은 숨김 + 이유 글이다. aria-disabled 버튼은 선례가 없고, 이유 글은 이미 같은 위치에 그려진다.
- 새 옵션 이름은 `noConfirm`이다.

## 3. 구현안 (적용 순서: 시험 → results.js → dashboard.js)

### A. 적용 패치 frontend/js/results.js
old:

B3. 판정 뒤에서 confirm만 바꾼다(dmRender, 1751 다음 줄)
old:
    if (m.readOnly) act = 'none';   // 보기 전용: [제안 확정]·[사전준비 열기] 없음(전산팀은 prep.canView 밖이라 이미 none이지만 규칙으로 한 번 더 막는다)
new:
    if (m.readOnly) act = 'none';   // (기존 줄 그대로)
    else if (m.noConfirm && act === 'confirm') act = 'noconfirm';   // 협약 성과 화면에서 연 상세: [제안 확정] 버튼 대신 이유 글(CONFIRM_WHY.noconfirm)
- early와 confirm 계산은 act === 'confirm' 조건이라 자동으로 false가 된다.
- actParts와 1002행의 CONFIRM_WHY[c.act] 분기가 noconfirm을 이유 글로 그린다. 다른 변경은 필요 없다.
- 'open'(사전준비 열기)은 이미 확정된 건으로 가는 길이라 그대로 둔다.

B4. 클릭 이중 방어(dmClick, 1886 다음 줄)
old:
