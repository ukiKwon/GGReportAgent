## 2. 원인/요구 요약
- 승인·반려 버튼은 `pending_gate`만 보고 활성화된다(`syncButtons`, workflow.js:714~720). 역할을 보지 않아서 영업부장이 아니어도 눌리고, 눌러야 403이 온다.
- `act()`(workflow.js:722~732)는 실패하면 본문을 버리고 `요청 실패 (403)`만 띄운다. 서버 문구는 사용자에게 안 보인다.
- `wf-by` 입력(745~746)과 `by` 전송(766)은 서버가 무시한다. 이 입력이 있으면 "다른 사람 이름으로 결재할 수 있다"는 오해를 준다. 참조는 workflow.js 3곳(745·766·`app.js:241~242`)뿐이고 **테스트에는 없다**.
- 신원은 `root.store.loadSession()`({mode, emp})과 `loadProfile().team`이다. 로그인 시 `app.js:846`이 `team = a.role`로 저장한다. 사번 헤더 `X-Emp-No`는 `installIdentityHeader`(app.js:796)가 전역 fetch에 자동으로 붙이므로 `act()`는 따로 할 일이 없다.
- 둘러보기는 `mode:'guest'`이고 `emp:''`다. 그래서 "계정 로그인 + 사번 7자리 + team===영업부장" 세 조건을 모두 만족할 때만 활성화한다.
- 역할 상수는 `roles.FINAL_APPROVER`('영업부장', roles.js:20)를 재사용한다. 이 값에는 '영업'과 '부장'이 모두 들어 있어 `team === '영업부장'`으로 비교하면 된다.

```js
  // 비활성+이유로 보여준다. 둘러보기(사번 없음)도 비활성. 신원은 로그인 세션·프로필에서 읽는다.
  const FINAL_APPROVER = (root.roles && root.roles.FINAL_APPROVER) || '영업부장';
  workflow.gateAccess = function (profile, session) {
    const p = profile || {}, s = session || {};
    if (s.mode !== 'account' || !/^[0-9]{7}$/.test(s.emp || '')) {
      return { allowed: false, reason: '로그인한 영업부장만 승인할 수 있어요' };
    }
    if ((p.team || '').trim() !== FINAL_APPROVER) {
      return { allowed: false, reason: '영업부장만 승인할 수 있어요' };
    }
    return { allowed: true, reason: '' };
  };

  // 실패 문구 — 서버가 한글 사유를 주면 그대로, 아니면 상태 코드별 업무 말투.
  workflow.failText = function (status, body) {
    const b = body || {};
    const msg = String(b.detail || b.message || b.error || '');
    if (/[가-힣]/.test(msg)) return msg;
    if (status === 403) return '이 작업은 권한이 없어 처리하지 못했어요. 영업부장 계정으로 로그인했는지 확인해 주세요';
    if (status === 409) return '지금은 처리할 수 없는 상태예요. 화면을 새로 고쳐 다시 확인해 주세요';
    return '처리하지 못했어요 (' + status + '). 잠시 뒤 다시 시도해 주세요';
  };
```

## 5. 위험·되돌리는 법
- 이유 문구는 `pending_gate`가 있을 때만 보인다. 대기 게이트가 없을 때 버튼은 이전처럼 비활성이고 문구가 없다.
- `profile.team`이 localStorage 값이라 사용자가 DevTools로 바꿀 수 있다. 이 화면 제어는 편의일 뿐이고 실제 차단은 서버 403이다(서버 응답 문구 표시 경로가 그 대비책이다).
- `act()`의 alert를 인라인으로 바꾼 것은 이 화면의 모든 액션(실행 포함)에 영향이 있다. 롤백은 git으로 workflow.js·app.js·index.html·approvals.js 되돌리기 한 번이다.
- 한글이 든 파일이므로 PowerShell로 재작성하지 말고 편집 도구로 `old → new`를 적용한다.

## 6. 이관 메모
- [이관: 개발(백엔드)] Spring `/checkpoint` 403의 응답 본문 키(`detail`/`message`)와 한글 문구 여부 확인. 기다리는 것: 서버 응답 형식 알림. 근거: `failText`가 키를 모르므로 `detail`·`message`·`error`를 모두 보고, 한글이 없으면 프런트 문구로 대체한다.
- [이관: 개발(백엔드)] `server/routers/workflow.py:68`(옛 Python 서버)은 아직 `body.by or x_user_id`를 쓴다. `by`를 제거하면 이 서버에서는 결재자가 `web-user`로 기록된다. 현재 운영 서버가 Spring뿐이면 무시해도 되고, Python 서버를 쓰는 경로가 남아 있으면 확인이 필요하다.
- [이관: 디자인] 이유 문구의 위치(버튼 옆 한 줄, 12px muted)와 문안 두 가지가 규격에 맞는지 확인. 기다리는 것: design-reviewer 확인(PUSH-GATE 전). 근거: 화면 마크업이 바뀐다.
- [이관: 기획] 게이트 7·8단계(이관결재·최종결재)도 같은 `/checkpoint`라 같은 규칙을 적용했다. 단계별로 결재자가 다르면 알려주세요.

## 7. 화면 전/후 (docs/design_history용 설명)
- **전**: 기관 상세 위쪽 줄에 `[결재자 이름 입력칸] [의견(선택)] [승인] [반려]`가 있었다. 결재 대기 중이면 누구에게나 버튼이 켜지고, 영업부장이 아닌 사람이 누르면 `요청 실패 (403)` 팝업만 뜬다. 결재자 이름 칸은 아무 이름이나 적을 수 있어 실제 기록과 달라 보였다.
- **후**: 이름 입력칸이 사라지고 `[의견(선택)] [승인] [반려]`만 남는다. 영업부장이 아니면 결재 차례에도 두 버튼이 흐리게(비활성) 보이고 옆에 "영업부장만 승인할 수 있어요"가 한 줄로 나온다. 둘러보기에서는 "로그인한 영업부장만 승인할 수 있어요"가 나온다. 영업부장 계정에서만 버튼이 켜진다. 서버가 거절하면 팝업 대신 버튼 줄 아래에 서버가 준 한국어 사유(없으면 "이 작업은 권한이 없어 처리하지 못했어요…")가 붉은 글씨로 남는다.
- 스크린샷 대상은 영업팀장(비활성+이유), 영업부장(활성), 둘러보기(비활성+로그인 안내) 세 장이 좋다.
