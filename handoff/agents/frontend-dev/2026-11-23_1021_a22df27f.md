## 2. 요구 요약과 서버가 실제로 주는 키

**GET /bid-targets 최상위**
- `goal_change_mode`: `DIRECT`|`APPROVAL`|`null`. `null`이면 쓰기 자격이 없다.
- `carry_due`: 정수. `carryEnabled=false`면 서버가 늘 0으로 준다.
- `carry_default_start`: `"MM-DD"`
- `codes.cancel_reasons`: `[{code,name}]`. 기타의 코드는 `ETC`.

**items(목표 줄)**
- `change_pending`: 모두에게 온다.
- `change_pending_info`: 쓰기 자격자에게만 온다. 모양은 `{req_id, op_cd, requested_by_name, created_at}`이다.
- `carried`, `carry_basis_cd`(UNREGISTERED|FAIL|PENDING|null)
- `judge_from`, `judge_from_assumed`, `term_start`, `term_rev_no`
- `change_mode`, `owner_name`

**watch_items(관심 줄)**
- `change_mode`(쓰기 자격자는 항상 DIRECT), `change_pending(_info)`, `carried`, `carry_basis_cd`
- `judge_from` 계열은 오지 않는다.

**POST /bid-targets/changes**
- 요청: `{reason, items:[{institution_id, op_cd, target_no, base_rev_no, target_year, tag_cd, memo, owner_emp_no, cancel_reason_cd, cancel_reason_etc}]}`
- 응답 200
  - DIRECT: `{mode:'DIRECT', applied, items}`
  - APPROVAL: `{mode:'APPROVAL', request:{req_id…}}`
- 오류: `detail:{code, message, item_no, institution_name?}`. `item_no`는 요청 배열 순서다.

**POST /bid-targets/carry**
- 요청 본문 없음. 응답 200 `{carried, revoked, skipped, more, carry_default_start}`
- 꺼져 있으면 409 `CARRY_DISABLED`

**POST /institutions/{id}/bid-terms**
- 요청 `{target_year, term_start, base_rev_no}`. `term_start`가 빈 글자면 기록을 지운다.
- 응답: 201 `{saved:true, …}` / 200 `{saved:false, code:'NO_CHANGE'}` / 409 `STALE`
- 개시일은 목표 연도나 그다음 해 날짜만 받는다(`BidTargetRules.termStart`).

**결재 카드**
- `req_type='TARGET_CHANGE'`일 때 `target_items:[{item_no, institution_name, op_cd, before:{kind_cd, target_year, tag_name, memo, owner_name}|null, to_year, tag_name, memo, owner_name, cancel_reason_name, warn_cd}]`
- `can_head_reject`, `can_cancel`
- 결재선 밖 영업부장은 받은 결재함에도 이 카드가 온다. 반려는 `/decide`에 `REJECT`를 보내면 된다(`decide()`가 `headOverride`로 통과시킨다).

**서버가 이미 정한 규칙**
- 옮기기(TO_WATCH·TO_GOAL)는 방향과 상관없이 결재 대상이다(`BidTargetService.move()`의 `requireDirect`).
- 구분 고치기·넣기·빼기도 결재 대상이다. 단 **관심 줄의 구분 고치기·관심에서 빼기·관심 넣기는 결재 없이 바로**다(`requireDirect`가 `!watch` 가드 안에 있다).
- 그래서 APPROVAL 모드의 한 줄 동작 중 결재로 보내야 하는 것은 아래 다섯 가지다.
  - 목표 줄 구분 고치기
  - 목표에서 빼기
  - 관심으로
  - 다음 회차 목표로
  - 관심 줄 목표로 옮기기

  tc.validate = function (items, o) {
    o = o || {};
    const out = { ok: true, top: '', reason: '', items: [] };
    const bad = function (it, f, msg) { out.items.push({ uid: it.uid, f: f, msg: msg }); out.ok = false; };
    if (!items || !items.length) { out.ok = false; out.top = '바꿀 기관을 하나 이상 골라 주세요.'; return out; }
    if (o.mode === 'APPROVAL') {
      const t = str(o.reason).trim();
      if (!t) { out.reason = '사유를 적으세요.'; out.ok = false; }
      else if (t.length > tc.REASON_MAX) { out.reason = '사유는 ' + tc.REASON_MAX + '자 이내로 적으세요.'; out.ok = false; }
    }
    items.forEach(function (it) {
      if (it.op === 'ADD') return;
      if (!it.op) { bad(it, 'op', '동작을 고르세요.'); return; }
      if (it.op === 'EDIT') {
        const s = it.snap;
        if (!Number(it.year)) { bad(it, 'year', '목표 연도를 고르세요.'); return; }
        if (str(it.memo).trim().length > tc.MEMO_MAX) { bad(it, 'memo', '메모는 ' + tc.MEMO_MAX + '자 이내로 적으세요.'); return; }
        if (Number(it.year) === Number(s.year) && it.tag === s.tagCd && str(it.memo).trim() === str(s.memo).trim()) bad(it, 'edit', '고친 내용이 없습니다. 칸을 바꾸거나 이 기관을 목록에서 제외하세요.');
      } else if (it.op === 'CANCEL') {
        if (!it.cancelCd) { bad(it, 'cancelCd', '빼는 사유를 고르세요.'); return; }
        if (it.cancelCd === tc.ETC_CD) {
          const e = str(it.cancelEtc).trim();
          if (!e) bad(it, 'cancelEtc', '기타 사유를 적으세요.');
          else if (e.length > tc.ETC_MAX) bad(it, 'cancelEtc', '기타 사유는 ' + tc.ETC_MAX + '자 이내로 적으세요.');
        }
      } else if (it.op === 'TO_GOAL') {
        if (!Number(it.year)) bad(it, 'year', '목표 연도를 고르세요.');
      }
    });
    return out;
  };

      else if (s === 409 && code === 'STALE') { m = ITEM_MSG.stale; e.refresh = true; }

      else if (s === 404) m = msg || '기관을 찾지 못했습니다.';
      else if (s === 400) m = msg || '입력한 내용을 확인하세요.';
      else m = msg || fallback(s);
      e.kind = 'item'; e.top = no + '번째 ' + name + tc.eul(name) + ' 확인하세요.'; e.item = { uid: it.uid, f: f, msg: m };

## 5. 위험·되돌리는 법

**위험**
1. **첫 가동 일괄 이월**
   - 서버를 true로 켜고 영업 계정이 현황판을 처음 열면 `carry_due`만큼 한 번에 처리한다. 한 번에 최대 300곳이고, `more`면 화면이 한 번 더 부른다.
   - 알림은 합쳐서 한 번만 뜬다. `carry_due`는 `carryEnabled=false`면 0이라, 켜기 전에는 건수를 볼 수 없다.
   - 켠 뒤 **아무도 현황판을 열기 전에** `GET /bid-targets`(영업 계정 헤더, curl)로 `carry_due`를 읽으면 사전 집계가 된다. 그 숫자로 판단한다.
   - 원치 않으면 `ggreport.bid-target.carry.enabled=false`를 로컬 설정에 둔다. 이 경우 화면의 이월 호출은 없다(`carry_due`가 0이므로).
2. **서버만 먼저 켜면** 옛 화면의 단건 버튼이 403이다. 화면 적용이 먼저다.
3. **결재함 열기**: `#tab-btn-approvals` 단추를 눌러 이동한다. `notify.js`와 같은 방식이지만 현황판에서 쓰는 건 처음이다. 못 열면 안내 문장이 뜬다. qa가 눌러 봐야 한다.
4. **`classList.toggle(name, force)`·`element.inert`**는 Chromium에서 쓰는 걸로 가정했다. `dlg.js`가 이미 `inert`를 쓴다.
5. **줄바꿈 혼재**: CRLF 파일에 LF 줄이 섞일 수 있다.
6. **새 창 포커스**: 열면 제목, 닫으면 연 단추(없으면 머리 체크박스 → 표). Playwright로 확인하지 못했다.

**되돌리는 법**
- 화면: K·A·H를 되돌리고 `tchange.js`·`tchange.test.js`를 지운다. 새 필드는 모두 옵션이라 서버는 영향 없다.
- 서버: S1~S3을 되돌리거나 `approval.enabled=false`·`carry.enabled=false` 설정 한 줄로 끈다. 화면은 `goal_change_mode`를 DIRECT로 받아 예전처럼 바로 저장한다(고르기 열과 바닥 띠만 보인다).

## 7. 열린 질문

사용자가 답하면 진행되는 것만 적는다.
- 일괄 요청 창을 닫을 때 '미리 채운 항목만 버리고 이미 고른 줄은 그대로'(규격 6-3) 규칙으로 구현했다. 그런데 사용자가 창 안에서 [목록에서 제외]를 누르면 그 줄은 **고른 상태에서도 풀린다**(다음에 창을 열면 다시 나오지 않게). 규격에 명시가 없어 내가 정했다. 다르게 하려면 `chRemove`의 `tc.unpick` 한 줄을 지우면 된다.
- 알림의 [결재함에서 보기]는 '내가 올린 요청' 탭으로 열고, 결재 진행 중 창의 [결재함에서 보기]는 탭을 지정하지 않아 결재함이 정한 기본 탭(받은 결재에 처리할 건이 있으면 그쪽)으로 열린다. 요청자가 아닌 사람이 볼 수도 있어서다. 이 구분으로 충분한지 확인이 필요하다.
