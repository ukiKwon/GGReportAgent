# 예산팀 상세 '사업계획' 요약 칸 숨김: 패치가 이미 작업 트리에 있음

## 1. 대상·방법·못 본 것
- `frontend/js/plans.js`, `frontend/js/nav.js`, `frontend/test/plans.test.js`, `frontend/test/nav.test.js`를 Grep과 Read로 읽었습니다.
- 테스트는 돌리지 못했습니다(Bash가 없습니다). 브라우저 화면도 열지 않았습니다.
- 서버를 쓰는 화면은 열지 않았습니다.

## 2. 요약
- 요청하신 내용은 `plans.js`와 두 테스트 파일에 이미 들어 있습니다(git status에 미커밋으로 `M`). 새로 짤 패치는 없습니다.
- `plans.sectionInner`(`plans.js:395-397`)와 `plans.paneSection`(`plans.js:432-437`)이 둘 다 `plans.menuVisible()`이 false면 `''`를 돌려줍니다.
- `refreshSlots`(`plans.js:447`)는 `sectionInner`를 거치므로, 늦게 도착한 현황 응답으로 칸이 다시 그려지는 경로도 막힙니다.
- `paneSection`은 `ensureStatus` 요청보다 앞에서 막습니다. 예산팀이 서버에서 403을 받을 요청 자체가 나가지 않습니다.
- `menuVisible`(`plans.js:415-421`)은 사이드바에 `data-nav="soon:기관 사업계획"` 버튼이 있는지 봅니다. 그 사이드바는 `nav.build`가 그리고, `nav.build`는 `withKey`와 `onlyTeams`에 `nav.teamIn`을 씁니다(`nav.js:166`). 그래서 메뉴와 같은 규칙입니다.
- 사이드바가 아직 없는 상태(로그인 전, node 시험)에서는 보인다고 봅니다.
- 시험은 `plans.test.js:389-408`(menuCheck로 숨김·표시 전환, 슬롯 갱신 경로 포함), `:433-436`(소스 순서 검사), `nav.test.js:428`, `:468`에 있습니다.

## 3. 구현안
- 새 패치는 없습니다. 추가를 권하는 시험도 없습니다. 서버 응답은 바꾸지 않았습니다.
- 알려진 한계: 로그인 사용자가 바뀌어 사이드바를 다시 그려도 열려 있는 상세의 칸은 다음에 다시 그릴 때에야 바뀝니다. 예산팀과 영업팀이 번갈아 쓰는 경우뿐이라 위험은 낮습니다.

## 7. 디자인 이력 ㊻ 전/후 문안
- 제목: ㊻ 입찰 현황판·전국 지도 기관 상세 — 예산팀(재무팀)에게 '사업계획' 요약 칸을 숨김
- 왜: 왼쪽 메뉴 '기관 사업계획'은 영업팀·전산팀(디자이너·마스터 포함)에게만 보이는데, 재무팀은 기관 상세 아래 '사업계획' 칸(자료 있음·N건·확인일)은 그대로 보았습니다. 메뉴로는 열 수 없는 화면의 요약만 보이고, 눌러도 갈 곳이 없었습니다.
