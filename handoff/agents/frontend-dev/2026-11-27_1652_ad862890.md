## 2. 추가 버그(관심 추가 창의 '2026 목표로 고르기'): 미완료

**원인**
- 추천 패널 줄의 단추 문구는 `kbb.recBtnText(it)`(`kbboard.js:1439`)가 `it.kind`로 정합니다.
- `it.kind`는 `kbb.recommend`(1355의 `pickYear`, `nearYear`)가 만듭니다. 이 두 함수는 창의 갈래(`m.kind`)를 모르고, 고를 수 있는 연도에 들면 GOAL로 정합니다.
- 그래서 관심 추가 창에서도 단추가 '2026 목표로 고르기'로 나옵니다. `pickRec`(2558)은 그 `it.kind`로 `m.kind`를 덮어쓰기까지 합니다. 즉 누르면 관심 창이 목표 창으로 바뀝니다.

**적용된 것 (3건 중 1건)**
- `kbboard.js:2456` `recInput` 반환 객체에 `watchOnly: !!m && m.kind === 'WATCH'`를 더했습니다.
- 지금은 `recommend`가 이 값을 안 읽으니 동작 변화는 없습니다.

**거부되어 안 한 것 (2건)**
- 1355줄 바로 위에 `const wOnly = !!o.watchOnly && !o.noWatch;`를 더하고, `pickYear` 맨 앞에서 `wOnly`이면 `{ kind: 'WATCH', year: 0 }`을 돌려줍니다. 이 줄이 없으면 위 `watchOnly`는 쓸모가 없습니다.
- `nearYear`의 첫 조건을 `if (wOnly || !pref || !years.length || years.indexOf(pref) >= 0) return pickYear(pref);`로 바꿉니다. 현재는 `if (!pref || !years.length || years.indexOf(pref) >= 0) return pickYear(pref);`입니다.
- 이렇게 하면 관심 창의 추천이 모두 '관심으로 고르기'가 되고 `pickRec`도 관심을 유지합니다. 목표 창은 그대로입니다. `noWatch`이면 `wOnly`가 꺼져서 기존 동작(목표 연도 또는 제외)을 유지합니다.

**테스트: 아직 못 썼습니다.**
- 추가할 곳은 `frontend/test/kbboard-rec.test.js`입니다. 그 파일 안의 `kbb.recommend(m, base({...}))` 호출(예: 151줄 부근)을 따라 `base({ ..., watchOnly: true })`로 부릅니다.
- 단정은 두 가지입니다. 각 줄의 `kind`가 `'WATCH'`이고 `recBtnText`가 '관심으로 고르기'일 것, 그리고 `kbb.recHtml(...)`에 '목표로 고르기'가 없을 것입니다.
- `watchOnly`를 주지 않은 호출은 기존 단정(87, 115, 299, 331줄)이 그대로 통과해야 합니다.

**막혔다고 판단한 이유와 필요한 것**
- 같은 파일에 대한 Edit 세 건 중 `recInput`만 통과하고 나머지 두 건은 "Destructive or Unwanted Actions"로 거부되었습니다.
- 우회하지 않고 멈췄습니다. 거부 사유가 불분명하니, 호출자가 확인해 재지시하거나 허용해 주시기 바랍니다. 재지시를 받으면 위 두 건과 테스트를 바로 적용하겠습니다.
