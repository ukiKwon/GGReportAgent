## 2. 조사 결과 (줄 번호는 grep 시점)
**지도 ♥**
- `render.js:973` buildCard와 `:976`·`:984`가 `store.toggleInterest(r.name)`을 부른다. `'관심도순'`은 `:937`의 `logic.sortByInterest`다.
- 저장은 `store.js:6`의 localStorage `tbd.interest`다. 기관 이름 배열이고, 서버 호출도 권한도 없다. 브라우저·PC마다 따로이고, 뷰어를 포함해 누구나 누를 수 있다.
- 쓰는 곳은 render.js 안의 정렬·표시뿐이다. 입찰 현황판은 이 값을 읽지 않는다.

**현황판 관심기관**
- 서버 저장이다. `POST /institutions/{id}/bid-targets`에 body `{kind_cd:'WATCH', tag_cd, memo}`를 보낸다(`kbboard.js:2295`, `kbb.saveTarget` `:1439`). 연도는 보내면 400이다.
- 읽기는 `GET /bid-targets?year=`의 `watch_items`다. 해제는 `/{no}/cancel`이고 `base_rev_no`가 필요하다. 목표로 옮기는 것은 `/move`다.
- 개인별이 아니다. 서비스 `list()`의 `mapper.selectActiveWatch()`에는 사번이 없어 팀 공용으로 읽힌다. 화면 칩 문구만 '나의 관심'(`plans.js:538`)이다.
- 쓰기 권한은 `can_edit`이다. `permissions.canEditInstitution`이고 영업 계열 역할(`HeadRules.isSales`)이다. 관심은 결재 없이 바로 저장된다(`BidTargetService:308`). 목표는 결재 대상이다.
- '목표 기관'은 다른 개념이다. 목표는 연도가 있고 결재 대상이며, 관심은 연도가 없고 '다음 입찰 때 가져올 기관'이다. 한 기관이 둘 다일 수는 없다. 관심인 기관을 올해 이후 목표로 넣으면 409 ALREADY_WATCH다.
- 공개된 함수는 `window.kbboard`(`kbboard.js:3104`)의 `kbb.saveTarget`·`cancelTarget`·`moveTarget`·`BTN`·`headers`·`outcome`이다. 지도의 `dash.itemForRec`도 공개돼 있다. 지도 ♥에서 곧바로 부를 수 있는 서버 API는 이미 있다.
- 서버가 허용하는 화면 이름에 `map_popover`가 이미 들어 있다(`TargetUiIds.SCREENS`). 그런데 `kbb.headers`는 `bid_board`로 고정이라, 지도에서 부르면 감사 기록에 지도 출처가 남지 않는다.
- 지도 기관 레코드는 `r.institutionId`를 가진다. `kbboard.js:1843`이 같은 필드로 `BYID`를 만든다.

## 3. 합치는 안
- **ⓐ 완전 일치** (♥ = 팀 공용 관심기관, 서로 반영). 문제가 세 가지다. ① 한 번 누름이 팀 전체 목록을 바꾼다(지금 ♥는 개인 표시). ② 뷰어·비영업 계정은 쓸 수 없다. ③ 서버가 구분(tag_cd: 재유치·되찾기·신규유치)을 요구하는데 ♥에는 입력 자리가 없다.
- **ⓑ 둘 다 두고 별도 동작** (♥는 개인 표시 그대로, 관심기관에는 따로 [관심 기관에 넣기]). 안전하지만 사용자가 원한 '하트 누르면 등록'이 아니다.
- **권장: ⓒ 하이브리드.** ♥ 켬은 항상 지금처럼 localStorage에 저장한다. 서버 모드에서 `can_edit` 계정이면 같은 클릭에 관심기관 등록도 시도한다.
  - ♥ 끔은 관심기관을 건드리지 않는다. 팀 공용 목록의 해제는 현황판 [관심에서 빼기…](인라인 확인)에서만 한다.
  - 등록할 때 구분은 `kbb.defaultTag(rec, sum)`의 기본값을 쓴다. 현황판 추가창도 같은 기본값을 미리 채운다.
  - 등록 결과(넣음/이미 관심/이미 목표/권한 없음/실패)는 카드 아래 한 줄 알림으로 말한다.
  - 이유는 되돌리기 쉽고 기존 ♥ 사용자의 표시가 보존되며, 되돌리기 어려운 팀 공용 변경은 명시 동작(해제)으로 남기기 때문이다.
- **사용자에게 물어야 할 것**
  - ⓐ '관심기관'이 팀 공용 목록인 것을 아는가. 내 ♥ 한 번이 팀 모두의 관심 목록에 들어가도 되는가. 아니라면 서버에서 개인별로 바꾸는 별도 안이 필요하다. 이건 백엔드 이관이다.
  - ⓑ 구분은 ♥ 클릭 때 자동(기본값)으로 넣고 현황판에서 고치게 할지, 클릭 때 3택 선택을 띄울지.
  - ⓒ 기존 ♥(브라우저 기록)를 한꺼번에 관심기관으로 올릴지. 권장은 올리지 않는 것이다. 기관 이름으로만 저장돼 있어 id 매칭이 틀릴 수 있고 팀 목록이 한꺼번에 불어난다.
  - ⓓ 해제를 지도에서도 할지. 권장은 지도에서는 하지 않는 것이다.
  - 권한이 없는 계정은 ♥가 개인 표시로만 동작한다. 이건 질문이 아니라 권장 규칙이다.

## 4. 패치 (지도 세션 몫: render.js 한 군데. buildCard 마크업 구조 변경 없음)
**적용 순서: ① '다른 세션 요청' kbboard 어댑터를 먼저 → ② render.js.** 어댑터가 없으면 ②는 아무 일도 하지 않는다(기존 동작 그대로).

render.js buildCard (old → new, `:984~986`):
```js
// old
card.querySelector('.heart').addEventListener('click', function (e) {
  e.stopPropagation(); store.toggleInterest(r.name); render.drawRankingPanel(code);
});
// new — ♥ 켬이면 서버 관심기관 등록도 시도(어댑터가 있을 때만). 끔은 로컬만. 결과 문장은 어댑터가 textContent로 돌려준다.
card.querySelector('.heart').addEventListener('click', function (e) {
  e.stopPropagation();
  const turningOn = !store.isInterested(r.name);
  store.toggleInterest(r.name);
  const mw = (typeof window !== 'undefined' && window.kbboard) ? window.kbboard.mapWatch : null;
  if (turningOn && mw && mw.canAdd(r)) {
    mw.add(r).then(function (msg) { render.state.heartNote = msg ? { name: r.name, msg: msg } : null; render.drawRankingPanel(code); });
  } else render.drawRankingPanel(code);
});
```
같은 함수 안 `card.innerHTML` 만드는 줄 바로 뒤에 한 줄 알림을 붙인다(마크업 구조 유지, `small` 뒤 한 줄).
```js
// new (card.querySelector('.heart')... 보다 앞)
if (render.state.heartNote && render.state.heartNote.name === r.name) {
  const n = document.createElement('div'); n.className = 'heart-note'; n.setAttribute('role', 'status');
  n.textContent = render.state.heartNote.msg; card.appendChild(n);
}
```
index.html 지도 CSS(`:root` 변수만 사용, 새 hex 없음). 위치는 `.rank-card` 규칙 옆이다.
```css
.rank-card .heart-note{margin-top:2px;font-size:11px;color:var(--muted)}
```
`render.state`(`render.js:22`)에 `heartNote: null`을 한 줄 추가한다. 디자인 세션이 묶음 머리 규격을 만드는 중이므로 `.heart-note` 시각 값은 디자인 확인이 필요하다(이관).

**다른 세션 요청 (kbboard.js, 입찰 현황판 세션 담당)** — `kbb`에 다음을 추가한다.
```js
kbb.mapWatch = {
  // 서버 모드 + 로그인 + (이미 받은) can_edit. 목록을 아직 안 받았으면 false라서 지도는 로컬만 쓴다.
  canAdd: function (rec) { return !!(rec && rec.institutionId && U.serverMode() && U.hasEmp() && gs.data && gs.data.can_edit && !noWatchNow()); },
  // 결과 문장 resolve. 헤더 화면 이름은 'map_popover'(서버 허용 목록에 있음). 버튼은 kbb.BTN.addWatch.
  add: function (rec) {
    const sum = gs.sum, d = kbb.defaultTag(rec, sum, {});
    return post('/institutions/' + encodeURIComponent(rec.institutionId) + '/bid-targets', kbb.BTN.addWatch,
        { kind_cd: 'WATCH', tag_cd: d.tag, memo: null }, 'map_popover').then(function (x) {
      const o = kbb.outcome(x, 'add', {});
      if (o.kind === 'saved') { loadGoals(); return kbb.flashWatchAdded(rec.name); }
      if (o.kind === 'nochange') return rec.name + '은(는) 이미 관심 기관입니다.';
      if (o.kind === 'already') return kbb.alreadyText ? kbb.alreadyText(o) : o.msg;
      return o.msg || '관심 기관에 넣지 못했습니다.';
    });
  }
};
```
`post`와 `kbb.headers`는 선택 인자 `screen`(기본 `kbb.SCREEN`)을 받게 고쳐야 한다. 현황판 화면이 닫혀 있어 `gs.data`가 없는 상태에서는 `canAdd`가 false가 되는데, 이 경우 지도가 단독으로 `GET /bid-targets`를 한 번 받는 방식이 필요하다(`dash.loadGoals`가 `watch`를 이미 담으므로 `dash.watchIds()` 공개 한 줄 추가를 권장). `kbb.outcome`의 반환 모양(`kind` 값 이름)은 `kbboard.js:1450~1470`에서 확인해 맞춘다.

## 6. 위험·되돌리는 법
- 위험: ♥ 한 번이 팀 공용 목록을 바꾼다(질문 ⓐ). 구분을 자동으로 넣어 틀릴 수 있다. 해제가 한쪽만 되어 ♥는 꺼졌는데 관심기관에는 남는다.
