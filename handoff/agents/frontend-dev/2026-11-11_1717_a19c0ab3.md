## 바꾼 곳
- **① 사이드바 기억 규칙**
  - `nav.js`에 `newOpenState`·`settleOpen`·`navigatedOpen`·`toggledOpen`을 추가했다. 규칙은 이렇다.
    - 저장은 사용자가 분류를 직접 펼치거나 접을 때만 한다. 호출은 `app.js` 클릭 한 곳뿐이다.
    - 화면 이동과 홈 자동 열림에서는 저장하지 않는다. 홈 자동 열림은 `applyHome`의 `navHoming` 표시로 구분한다.
    - 저장값이 있으면 로그인·새로고침 때 그것이 우선이고, 홈 자동 열림이 덮어쓰지 않는다. 저장값이 없으면 현재 화면 분류를 연다.
    - 아직 안 보이는 저장값은 권한이 와서 보일 때까지 미룬다.
    - '모두 접음'은 `'none'`으로 저장한다(`store.saveNavOpen(null)`). `none` 복원 때는 현재 분류로 다시 열리지 않는다.
    - 사용자가 바뀌면 새 상태로 시작해서 앞 사용자의 열림을 쓰지 않는다.
    - 저장 키는 복원을 마친 `navOpenWho`를 쓴다. 로그아웃 중에 `guest` 키로 새지 않는다.
  - 홈이 아닌 화면을 사용자가 직접 열었을 때는 그 분류를 연다(저장은 안 함).
  - 지시에 없던 판단: 위 규칙 때문에 사용자가 한 번이라도 펼치거나 접으면 홈 자동 열림이 그 선택을 덮지 못한다.
- **② 포커스와 aria**
  - `db-widen`은 선택된 기간 라디오로, `db-tile-later`는 다시 그린 칸으로, `db-retry`는 `#db-rail`(`tabindex=-1`)로, `db-clear`는 검색창으로 포커스를 돌린다.
  - '1년 뒤' 칸에 `aria-pressed`를 달았다.
- **③ basis 표기**
  - 모델 `label`이 약정 만료 기준 추정이면 `(추정·약정 만료 기준)`이다. 목록 행, 메타, 상세 dd가 모두 이 값을 쓴다.
  - `render.js:814` 지도 팝오버도 `basis==='expiry'`면 `추정·약정 만료 기준`을 쓴다. `formatBidDateLabel`을 그대로 쓰면 `2027-03-02(추정)`처럼 공백이 없어져 `prep.test.js:632`의 `2027-03-02 (추정)`이 깨져서, 공백 형식은 그대로 두고 태그만 바꿨다.
- **④ 설명 분기:** `basis='notice'`이고 확정이 아니면 상세에 "공고된 날짜이나 의미 확인 중입니다"를 보인다. 범례에도 "공고 날짜 의미 확인 중"을 넣었다.
- **⑤ CSS:** `@media (max-width:1599px)`에서 `.db-work{flex:1 0 auto;min-height:0}`로 바꿨다.
- **⑥ P3**
  - 범례 문구를 "추정(최근 절차일+약정 주기 / 약정 만료 6개월 전 / 공고 날짜 의미 확인 중) · 1년 안 약정 만료 기준 n곳"으로 바꿨다.
  - 상세 막대의 `.term-stamp`(마크업·CSS)를 지웠다.
  - 미선택 상세 영역에 `aria-label="기관 상세"`를 달았고, 선택하면 `aria-labelledby`로 되돌린다.
  - 기간·경과 묶음 접힘에 따른 선택 해제 판정을 `dash.visibleKeys`로 모았다. `setWindow`, `db-past` 토글, mount의 `refreshData`가 이것을 쓴다. mount 때 저장 기간 밖이거나 사라진 기관이면 선택을 푼다.
