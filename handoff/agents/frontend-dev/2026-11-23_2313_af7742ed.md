## NEXT 102 P3-7 패치안: enterCase가 대시보드 경로에서 /preps를 부르지 않게 하기

**1. 대상·방법·못 본 것**
- 읽은 것: `frontend/js/prep.js`(940–1200, 1355–1390, 1505–1535, 1735–1795), `prepboard.js`의 openCase 호출부, `frontend/test/prepboard.test.js`와 `prep-nobid.test.js`의 해당 줄, qa 보고서 P3-7.
- 못 본 것: 브라우저 실행은 하지 않았다(서버 화면을 열지 않음). 테스트 실행도 하지 않았다(읽기 전용).

**2. ① 의존 지점 목록 (`S.rows`·`rowOf`·`cache.rows`)**

enterCase는 `boardHooks().openCase`로만 불린다. 표가 있을 때만 호출되므로 이 경로에서는 `boardOn()`이 항상 참이다.

| 1107 paintCase 로딩 중 | `rowOf(S.selected).name`을 제목으로 | 로딩 동안 제목이 빈 글자. 상세가 오면 `d.view`로 그려져 정상 |
| 1115 paintCase 오류(404·기타) | 같은 이름 제목 | 오류 화면의 제목만 빈 글자. 메시지·[다시 시도]는 정상. 유일한 눈에 보이는 회귀 |

- `S.tab`을 선택 건의 탭으로 맞추는 줄(1082)은 숨은 목록용이라 불필요하다.
- **backToBoard(1026)**: 이미 `invalidateCache()` 뒤 `prepboard.show(..., {reload:true})`로 표를 다시 받는다. `S.rows`에 기대지 않아 영향이 없다.
- **옛 화면**: 표가 없으면 enterCase 자체가 불리지 않고, `refresh()`(1193)와 `selectCase`가 그대로 `loadList()`를 쓴다. enterCase에서 `boardOn()` 검사를 해도 옛 화면 동작은 그대로다.

**알려 둘 것 — 같은 불필요 요청이 더 있다**
- (a) 지도·현황판이 `openCase`(1774)로 열 때는 `mount→refresh()`의 `loadList()`(1193)가 나간다. `view='case'`라서 board 분기(1190)를 못 탄다.
- (b) `doAct`(1246)와 `handleError`(1223)도 쓰기 뒤에 `loadList()`를 부른다.
- 이번 패치는 지시대로 enterCase만 고친다. (b)의 doAct 줄은 `prep-nobid.test.js:159`가 정규식으로 고정하고 있어, 고치려면 그 테스트도 함께 바꿔야 한다. 후속으로 분리하길 권한다.

**3. ② 구현안 (unified diff, 적용 순서: 테스트 먼저 → 구현)**

```diff
--- a/frontend/js/prep.js
+++ b/frontend/js/prep.js
@@
     showView();
-    loadList();
+    // 표에서 연 상세는 숨은 왼쪽 목록이 필요 없다 — GET /preps(prep_list/refresh)를 보내지 않는다(qa P3-7).
```

- 적용은 편집 도구로 한다. old는 `    showView();\n    loadList();\n    loadDetail(S.selected, { popup: true });`이고 enterCase 안에서 유일하다.
- 선택 사항(제목 빈칸 보완): 1107·1115줄의 `row ? row.name : ''`은 그대로 둔다. 이름을 넘기려면 prepboard의 `openCase(bid)` 시그니처를 바꿔야 하며 지금 범위가 아니다.

**4. ③ 테스트**
- **기존 테스트**: 깨지는 것은 없다. `prepboard.test.js:362–373`은 enterCase 줄을 보지 않는다. `prep-nobid.test.js:159`는 doAct만 본다.
- **추가(`frontend/test/prepboard.test.js` 끝, 같은 파일의 `PREP_SRC` 정적 검사 방식)**: 이 저장소는 prep.js 내부(enterCase·boardHooks)를 export하지 않고, 같은 파일의 기존 시험도 소스 문자열로 연결을 검증한다. 동작 시험을 하려면 fetch·DOM 가짜 환경에 prep 내부를 노출해야 해 범위를 넘는다. 그래서 같은 방식으로 쓴다.

```js
test('enterCase(P3-7): 표에서 상세를 열 때 /preps 목록을 부르지 않는다, 옛 화면(refresh·selectCase)은 loadList 유지', function () {
  const a = PREP_SRC.indexOf('function enterCase(bid) {');
  const b = PREP_SRC.indexOf('function backToBoard()');
  assert.ok(a > 0 && b > a, 'enterCase 범위');
  const body = PREP_SRC.slice(a, b);
  assert.ok(!/(^|[^!\w.])loadList\(\)/m.test(body.replace(/if \(!boardOn\(\)\) loadList\(\);/, '')), 'enterCase가 loadList를 무조건 부르지 않는다');
  assert.ok(/if \(!boardOn\(\)\) loadList\(\);/.test(body), '표가 없을 때만 목록을 부른다');
  assert.ok(body.indexOf("loadDetail(S.selected, { popup: true })") > 0, '상세는 그대로 연다');
  // 옛 화면 경로는 그대로
  const r = PREP_SRC.slice(PREP_SRC.indexOf('function refresh() {'), PREP_SRC.indexOf('// ── 쓰기 공통'));
  assert.ok(/paintList\(\);\s*loadList\(\);/.test(r), 'refresh의 목록 호출 유지');
  assert.ok(/case 'pp-retry-list'|pp-retry-list': S\.listState = 'loading'; paintList\(\); loadList\(\)/.test(PREP_SRC));
});

test('enterCase(P3-7): 상세 요청 화면 이름과 시작 상태는 그대로(prep_dashboard, view case, fromBoard)', function () {
  const a = PREP_SRC.indexOf('function enterCase(bid) {');
  const body = PREP_SRC.slice(a, PREP_SRC.indexOf('function backToBoard()'));
  assert.ok(body.indexOf("S.view = 'case'; S.fromBoard = true;") > 0);
  assert.ok(body.indexOf('showView();') < body.indexOf('loadDetail('));
});
```

- 실행: `node --test "frontend/test/prepboard.test.js" "frontend/test/prep-nobid.test.js" "frontend/test/prep.test.js"`, 그다음 전체 `node --test "frontend/test/*.test.js"`.
- 수동 확인(사용자 허용 시 열람만): 네트워크 탭에서 표의 기관 이름을 눌렀을 때 `GET /bidcases/{id}/prep`(prep_dashboard)만 나가고 `GET /preps`는 없어야 한다. [← 대시보드로]를 누르면 `/prep-board`가 한 번 나간다.
