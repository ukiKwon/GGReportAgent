## 1. 고친 파일과 주요 부분
고친 파일은 `frontend/js/instsummary.js`, `frontend/test/instsummary.test.js` 두 개뿐입니다. `index.html`·`prep.js`·`preptask.js`는 건드리지 않았습니다. 줄 번호는 편집 중에 밀리므로 함수 이름으로 적습니다.

**순수 함수(node 시험 대상)**
- `scNorm`·`scBody`·`scKey`·`scBlank`·`scReadResult`·`scUrl`·`scHeadRows`·`scGrid`·`scCanDel`·`scDelRow`·`scAddRow`·`scSum`·`scWarn`을 새로 만들었습니다.
- `footNo`·`footCount`·`footMark`(각주 번호)도 새로 만들었습니다.
- `modelFromView`는 모델에 `notes.mmda_basis`(줄마다 각주)와 `biz[].bold`(줄마다 굵게)를 나란한 배열로 둡니다. 서버의 객체 줄 `{text,note}`·`{text,bold}`와 옛 문자열 줄을 둘 다 읽습니다. `scoring`은 `scNorm`으로 읽습니다.
- `buildBody`는 `mmda_basis`를 `{text,note}`로, 사업 줄을 `{text,bold}`로 씁니다. `tables.scoring`은 항상 포함하고, 없거나 칸 글자가 하나도 없으면 null입니다. `head_title`은 칸 지도(tpl)의 TEXT 칸이라 기존 반복문으로 나갑니다.
- `precheck`에 각주 300자, 평가표 칸 500자, 행 200줄 검사를 더했습니다.
- `errInfo`는 `400 BAD_SCORING`과 `key=scoring`의 `TOO_MANY`를 평가표 문구로 처리합니다. `422 PII_DETECTED`의 `scoring`은 "평가 기준표에 …"로 나옵니다.
- `isn.call`에 `opt.screen`을 더했습니다.
- 문구(`T`)는 `afterEnd`·`page1`을 고치고 `bidHelp`·`titleHelp`·`footHelp`·`bankRef`·`boldHelp`와 `sc*` 문구들을 더했습니다.

**화면**
- `renderDoc`: 입찰 종류 칸 안내, 직함 칸, 산정 기준 목록의 각주 입력, 현 거래 은행 안내, 맨 아래 '평가 기준표(2쪽)' 구역을 더했습니다.
- `listEditor`·`onListKey`·`onListPaste`에 `o.aux`(나란한 배열)를 더했습니다. 줄을 넣고 빼고 옮기고 붙여넣을 때 각주·굵게가 같이 움직입니다.
- `refreshFoot`: 각주를 고칠 때 '주n)' 번호와 표 뒤 주석 번호를 그 자리에서 다시 매깁니다.
- `bizRow`: 줄마다 '굵게' 체크가 있고, 보기 모드에서는 굵은 줄이 `<strong>`으로 나옵니다.
- `scoringBlock`·`onScRead`·`scFetch`·`onScBlank`·`onScClear`: 2쪽 구역의 읽기·표 그리기·빈 표·비우기를 맡습니다.
- `applyView`는 2쪽 상태(`S.sc`)를 새로 만듭니다.

## 2. 사용자가 화면에서 보게 되는 것
1. 맨 위 제목 아래, 입찰 종류 칸 안내: "1·2쪽 제목에 같이 쓰입니다(예: 주거래은행 선정, 금고 지정)."
2. 현황 표 위에 '기관장 직함' 입력(20자, 비우면 '기관장')과 안내문이 있습니다.
3. 사업 표에서 내용 줄마다 '굵게' 체크가 있고, 표 아래에 안내가 나옵니다.
4. MMDA 산정 기준은 `·` 줄 아래에 '각주(선택)' 칸이 붙습니다. 글과 각주가 둘 다 있는 줄만 '주1)'부터 번호가 붙고, 연도 표 뒤 주석이 번호를 이어받습니다. 안내는 "각주는 그 줄 아래 주1)부터 나오고, 표 아래 주석이 번호를 이어받습니다."
5. 연도 표: 협약 종료 뒤 연도 칸은 원래 입력 가능했고, 안내만 바꿨습니다. "협약이 끝난 뒤 연도는 빗금으로 표시되고 숫자는 그대로 나옵니다."
6. 현 거래 은행 아래에 "화면에서 참고만 하는 칸입니다. 워드 문서에는 나가지 않습니다."가 나옵니다.
7. 맨 아래 '평가 기준표(2쪽)' 구역:
   - 제목 미리보기: '참고자료 2. 「기관명」 {입찰 종류} 평가 기준표'. 입찰 종류를 고치면 바로 바뀝니다.
   - [공고 원본에서 읽기]를 누르면 HWPX 표가 병합(rowspan/colspan) 그대로 칸마다 `textarea`로 나옵니다. 표가 있으면 버튼이 [다시 읽기]와 [표 비우기]로 바뀝니다.
   - 후보 표가 2개 이상이면 후보 고르기 `select`와 "이 공고에서 평가 표 후보 n개를 찾았습니다" 문구가 나옵니다. 고르면 `?table=n`으로 다시 읽습니다.
   - 읽지 못했거나(찾지 못함, PDF 줄 단위, `cells` 없음) 하면 "공고 원본(HWPX)에서 표를 읽지 못했습니다. 아래 빈 표에 직접 적으세요."가 나옵니다. [빈 표로 시작]은 5칸 머리(평가 부문·평가 항목·세부 평가 항목·배점·평가 방법)와 빈 한 줄을 만듭니다. PDF 줄이 있으면 접힌 '공고 원문 줄(참고용)'로 보여 줍니다.
   - [줄 추가]는 어느 표에서나 됩니다. 줄별 [줄 삭제]는 머리가 아니고 병합에 걸리지 않는 줄에만 나옵니다.
   - 합계는 "합계 N점"으로 보이고, 배점 열 합과 다르면 경고만 나옵니다. 저장은 막지 않습니다. 배점 열을 확신할 수 없으면 경고를 생략합니다.
   - 덮어쓰기 확인은 `dlg.confirm`으로 합니다.
8. [저장]하면 `tables.scoring`이 항상 함께 나갑니다.

## 4. 지시와 다르게 판단한 것
1. **서버 message는 화면에 쓰지 않았습니다.** 기존 시험이 `.message` 사용을 막고 있어서, `BAD_SCORING`·`TOO_MANY`·`PII`는 서버 message를 보여 주지 않고 고정 문구로 보여 줍니다. 서버 message를 그대로 보여 주려면 그 시험을 바꾸는 결정이 필요합니다.
2. **공고 원본 읽기 요청의 화면 머리글은 `prep_detail`/`refresh`입니다.** `PrepFormUiIds`는 `prep_form`용 10종뿐이라 `form_*` 단추 ID를 새로 만들 수 없습니다. 같은 요청을 쓰는 `prep.js`와 같은 머리글을 썼습니다. 서버가 `SCORING_READ`를 이 화면·단추 조합으로 받아 주는지 확인이 필요합니다.
3. **덮어쓰기 확인은 상황에 따라 생략합니다.** 표가 있고 직접 고친 경우에만 `dlg.confirm`으로 묻습니다. 방금 읽어 온 표 그대로면 묻지 않습니다(후보를 바꿔 볼 때 매번 묻지 않으려고). 저장 뒤 다시 열면 `S.sc`가 새로 만들어져서 그때는 항상 묻습니다.
4. **칸 글자가 하나도 없는 표는 `scoring: null`로 보냅니다.** 머리 글자가 있는 [빈 표로 시작] 표는 그대로 나갑니다. 비우기만 한 표를 빈 2쪽으로 내지 않으려는 판단입니다.
5. **스타일을 줄 안(inline)으로 넣었습니다.** `index.html`을 고치지 말라고 해서 평가표 칸 `textarea`와 '굵게' 체크·라벨에 inline style을 썼습니다(hex 색 없음, 12px).
6. **산정 기준 목록에는 기존 `isf-notes` 클래스를 재사용했습니다.** '주n)' 글자가 들어갈 36px 열을 쓰기 위해서입니다.
7. **경고 줄에는 기존 `.isf-warn`을 썼습니다.** 그 규칙이 창 위 경고 띠(`padding 8px 24px`, 아래 줄)용이라 평가표 경고도 그 모양으로 나옵니다.

## 5. 필요하다면 index.html에 더할 CSS(메인이 따로 처리)
필수는 없습니다. 모양을 다듬으려면 아래를 고려하세요.
- 평가표 칸 `textarea`: `.isf-tbl textarea { width:100%; box-sizing:border-box; min-width:7em; }`
- 사업 줄 '굵게' 라벨: `.isf-bold { display:inline-flex; gap:4px; font-size:12px; white-space:nowrap; }`. 안의 체크박스는 `.isf-lines > div input` 규칙(폭 늘림)에서 빼야 합니다.
- 평가표 경고용 별도 클래스(지금은 `.isf-warn` 재사용)
