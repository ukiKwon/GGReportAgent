## 2. 설계 결정
1. **서브에이전트 구별**: `p.agent_id`가 있거나, `p.agent_type`이 MAP 키이거나 `:`를 포함하면 서브에이전트로 보고 그냥 끝낸다(exit 0, state 안 씀). `--agent`로 띄운 메인처럼 `agent_type`만 있고 `agent_id`가 없으면 메인으로 센다.
2. **훅 등록**: `PreToolUse`에 matcher 없는 항목을 하나 더 둔다(모든 도구). 기존 `Edit|Write` 가드와 `Agent|Task` dispatch는 그대로다. **PostToolUse는 등록하지 않는다.** 도구 1회당 node 프로세스가 2번 뜨는 것을 피한다. 완료 시각은 "다음 호출 또는 Stop"으로 대신한다. 서브에이전트 안의 호출도 node는 뜬 뒤 바로 끝난다. 호출당 약 50~80ms(Windows node 기동)가 든다.
3. **센 단위: 메인 도구 호출 1회 = 1건. 권장.**
   - 대시보드를 보는 목적이 "작업이 되는지"다. 도구 호출은 몇 초마다 숫자가 올라 살아 있다는 신호가 된다. 사용자 지시 1회 = 1건은 하루 몇십 번뿐이라 이 목적에 안 맞는다.
   - 지시 1건은 도구 호출 1~200회로 크기가 제각각이라 지시 수는 '처리량'이 못 된다.
   - 도구 호출은 Pre 훅 하나로 센다. 완료까지 세려면 PostToolUse가 필요해 비용이 2배다.
   - 한계: Read·Grep도 센다. 숫자는 "활동량"이다. 이름은 사용자 말대로 "메인 처리 N건"으로 둔다. 작업성 도구만 세고 싶으면 `hook.js`의 `tool` 분기에서 `s.stats.mainOps` 증가 줄을 조건부로 바꾸면 된다(한 줄).
   - 세는 곳은 `state.stats.mainOps`(하루). 세션별 `mains[*].n`은 날짜가 바뀌면 그 세션의 첫 호출에서 0부터 다시 센다(`m.day`).
4. **세션 줄**: `state.mains = { m_<session_id 영숫자 앞12자>: { sid(앞6자), dir(cwd 끝 폴더), st:'work'|'idle', task, at, n, day, hold? } }`.
   - `prompt`는 `st='work'`, task `지시 받음: …`으로 올린다. `tool`은 도구별 task를 올린다. `idle`(Stop)과 SessionStart는 `st='idle'`, task `''`로 만든다. SessionEnd는 줄을 지운다(선택).
   - 마지막 신호가 60분 지난 줄은 `statefile.normalize`가 지운다(`MAIN_TTL`).
   - **멈춤?**: `st==='work'`이고 `now-at > max(5분, hold+30초)`이고 일하는 에이전트가 없을 때. Bash는 `tool_input.timeout`(최대 10분)을 `hold`로 저장해 긴 `mvn` 시험을 멈춤으로 오판하지 않게 한다. 판정은 화면(`fmt.js mainState`)이 1초마다 다시 한다. 훅이 안 불려도 시간이 가면 멈춤?으로 바뀐다.
5. **화면**: ① 상단 `#now` 아래 새 줄 `#mains`에 세션별 한 줄(세션·하는 일·마지막 시각·건수). ② 전광판 마지막 줄(메인:)은 일하는 세션의 task를 보여 준다. ③ 전광판 바로 아래 새 판(y276~304)에 "● 메인 처리 N건". 점 색은 일함=초록, 멈춤?=빨강, 대기=회색. 숫자가 늘면 0.8초 흰색으로 반짝인다.
6. **쓰기 표시**: 인스턴스 `w:1`(dispatch·start가 `WRITE` 집합으로 기록)을 화면이 `r.write`로 받는다. 이름표는 `프론트·쓰기`, 현황판 task는 `[쓰기] …`, 상단 `#now`는 `쓰기` 배지, 칩은 `쓰기 작업 중`으로 보인다. `WRITE`는 MAP 블록 밖에 둔다. `server.test.js`가 MAP 블록을 정규식으로 읽기 때문이다.

function agoLabel(ms) { // 마지막 신호로부터 지난 시간

function mainState(m, now, busy) { // 'work' | 'idle' | 'stall'. busy = 일하는 에이전트가 있는가

}

## 7. 위험·되돌리는 법
- **훅 지연**: `tool` 훅은 도구 호출마다 node를 한 번 띄운다(약 50~80ms, 모든 도구 호출에 더해진다). 서브에이전트 안의 호출도 프로세스는 뜨고 바로 끝난다. state 쓰기는 `update()`의 잠금과 원자적 쓰기를 따르고, 잠금은 최대 3초까지 기다린다. `"timeout": 5`로 상한을 둔다. 체감이 크면 §2의 PostToolUse 안 하는 선택은 유지하고, matcher로 `Bash|Edit|Write|NotebookEdit|Agent|Task`만 세게 줄이면 Read·Grep 호출의 비용이 사라진다. 그 경우 `Read` 줄은 안 보인다.
- **state.json 동시 쓰기**: 여러 세션이 동시에 쓰는 경우를 시험 4-1의 "동시 10건"이 확인한다. 쓰기는 모두 `statefile.update` 하나를 통하고, 훅 갱신은 키 단위(`mains[k]`·`stats.mainOps`)라 서로 덮어쓰지 않는다.
- **서브에이전트 구별 불확실**: PreToolUse 입력의 `agent_id` 유무는 문서와 write-guard 사용 방식에 근거했다. 틀리면 서브에이전트 호출까지 메인으로 센다. §8의 확인 절차로 적용 직후 확인한다. 틀렸으면 `isSub`의 판정 조건만 고친다.
- **멈춤? 오판**: `mvn`이 Bash timeout(최대 10분) 안에 끝나면 안전하다. `run_in_background`로 띄운 뒤 아무 도구도 안 쓰고 기다리는 경우는 5분 뒤 멈춤?으로 보일 수 있다. 정상이며 다음 호출에서 풀린다.
- **누출**: 화면에는 `description`·파일 이름·cwd 끝 폴더·session_id 앞 6자만 오른다. 명령 본문과 전체 경로는 싣지 않는다. state.json은 gitignore 대상이고 서버는 127.0.0.1에서 Host 검사를 한다. `description`을 모델이 쓰므로 비밀이 들어갈 가능성은 낮지만 0은 아니다.
- **레이아웃**: `#mains` 줄이 하나 늘어 캔버스가 약 25px 작아진다. 전광판 아래 판의 위치와 색은 디자이너 확인이 필요하다.
- **되돌리기**: `.claude/settings.json`에서 `tool`·`end` 항목을 지우면 신호가 즉시 끊긴다(코드는 그대로 둬도 안전하다). 전체는 변경 파일 원복(`git checkout -- <파일>`). `state.json`의 `mains`·`stats.mainOps`는 남아도 무해하고, 구버전 화면은 이 키를 무시한다.
