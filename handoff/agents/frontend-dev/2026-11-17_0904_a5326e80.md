## 1. 대상·방법·못 본 것

- 대상은 `frontend/js/board-write.js`, `frontend/index.html`(CSS 한 줄), `frontend/test/`(새 시험 파일 1개)입니다. `board.js`와 `errtext.js`는 건드릴 일이 없었습니다. reason 코드 표(`REASON`, `reasonText`)가 `board-write.js`에만 있기 때문입니다.
- 방법은 코드와 서버 보고서(`handoff/agents/backend-dev/2026-11-16_1813_af5f0d77.md`)를 읽는 것뿐이었습니다. 시험은 실행하지 못했습니다.
- 못 본 것은 서버 패치 적용 후의 실제 응답 모양입니다. 그래서 실패 셀의 `source`는 `{sheet:null}`이거나 없는 경우를 둘 다 견디게 가정했습니다(`buildState`가 이미 둘 다 처리합니다).

## 2. 요구 요약과 근거

서버가 `C-4/r3_c2`를 `input=true`, `mapped=false`인 칸으로 주고, 엑셀 채우기 응답의 `tables[].cells`에 문장을 싣습니다. 화면에서 이미 되는 것과 모자란 것은 다음과 같습니다.

| 지시 | 현재 코드 | 판정 |
|---|---|---|
| (a) 응답 셀을 칸에 반영 | `buildState`가 `rt.cells`로 셀을 만들고(`board-write.js:344`), 입력 칸 보충 루프는 `has(t.cells,key)`면 건너뜁니다(`:403`). `cardHtml`은 `input===true && has(cells,key)`면 값 칸으로 그립니다(`:1075`). | 이미 됨 |
| (b) 숫자 검증·서식 제외 | `numericKeys`는 `mapped===true`만 봅니다(`:1641`). `fmtOf`는 `input && !mapped`면 null입니다(`board-material.js:713`). | 이미 됨. 시험으로 고정만 합니다 |
| (c) reason 문구 | `reasonText`가 모르는 코드를 일반 문구로 보냅니다(`:463`). | 추가 필요 |
| (d) 값이 없을 때 기본 문구 | 서버가 셀을 안 보내면 `fc.text`가 비어 있지 않아 정적 문구로 그려집니다(`:401`). 이 경우는 됩니다. 저장본으로 여는 화면(`stateFromSaved`, `:1654`)은 저장값이 없으면 빈 칸 "직접 입력"이 됩니다. 서버 Word 출력은 값이 없으면 기본 문구를 쓰므로 화면과 어긋납니다. | 추가 필요 |
| 덮어쓰기 규칙 | `adoptManual`(`:1665`)은 manual 칸만 저장값을 이어받습니다. 엑셀로 채운 연결 칸은 엑셀 값이 이깁니다. | 아래 결정 참조 |

**덮어쓰기 규칙 제안**
- 서버가 `filled`로 문장을 주면 저장본에 사용자 문구가 있어도 엑셀 문장이 이깁니다(연결 칸과 같은 규칙). 화면 값이 저장본과 달라져 `matDirty`에 잡히므로 사용자가 저장 전에 알 수 있습니다.
- 서버가 `failed`(못 읽음)를 주고 저장본에 사용자가 쓴 문구가 있으면 저장본 문구를 살립니다. 못 읽은 때 손으로 쓴 문장이 사라지면 안 되기 때문입니다.
- 사용자가 고쳐 둔 문구를 엑셀이 덮는 것이 싫으면 열린 질문 1을 보세요.

**코드에 서버 계약을 하나 박습니다.** 저장본 화면(상태 B)에서는 모든 칸이 manual이라 "서버가 채우는 입력 칸"을 응답에서 알아낼 수 없습니다. 그래서 서버 `BoardDocSpec.isTextFillKey`와 같은 칸(`C-4/r3_c2`)을 상수로 둡니다. 칸이 더 생기면 서버와 함께 고쳐야 합니다(이관 메모 참조).

### 패치 B — `board-write.js`: 칸에 기본 문구를 달기 (d)

`buildState`의 셀 생성(`t.cells[key] = {` … `asked: false, why: '', memo: '', whyAsked: false`) 첫 번째 것에서, 마지막 줄만 바꿉니다. `label:` 줄 다음의 줄입니다.

```js

            asked: false, why: '', memo: '', whyAsked: false

// new

          };
          if (fmt) Object.assign
```

`dflt`는 저장값이 아니라 표시용이라 `putValue`, `matDirty`, `nextBase`에 영향이 없습니다. 입력 칸 보충 루프(`:404`)의 객체는 건드리지 않습니다. 거기는 `fc.text`가 빈 칸만 들어와서 `dflt`가 필요 없고, 없으면 falsy로 처리됩니다.

### 패치 C — `board-write.js`: 기본 문구 표시·복사 (d)

`valueCellHtml`, `cellAria`, `cellTextOf`를 고칩니다. 글자는 모두 `esc()`를 거칩니다.

```js

// new

```
```js

// new
      i.unreadable ? missText(c) : (pr ? pr.main + ', 괄호 안 ' + pr.sub : (c.value === '' ? (c.manual ? (c.dflt ? '기본 문구 ' + c.dflt : '직접 입력') : '비어 있음') : bw.cellText(c)))];
```
```js

못 읽은 칸(failed, 값 '')은 "읽지 못함"이 우선합니다. 사용자가 직접 입력하라는 안내가 먼저 보이게 하는 것입니다. 입력하지 않고 저장하면 서버가 Word에 기본 문구를 씁니다.

### 패치 D — `board-write.js`: 못 읽었을 때 저장본 문구 살리기 (a)

`adoptManual`을 고칩니다.

        if (!c || !c.manual) return;
        const sk = c.fmt && c.fmt.paren ? c.fmt.subKey : null;

test('IRR 판단기준 + 엑셀 올리기: 읽으면 엑셀 문장이 이기고, 못 읽으면 저장본 문구를 살린다', function () {
  const base = { 'C-4': { r3_c2: '손으로 쓴 문구' } };
  const ok = bw.adoptManual(bw.buildState(form(), respOk(SENT), {}), base);
  assert.strictEqual(C(ok).value, SENT);
  assert.deepStrictEqual(bw.matDirty(ok, base).map(function (x) { return x.key; }).sort(), ['r3_c1', 'r3_c2']);
  const fail = bw.adoptManual(bw.buildState(form(), respFail(), {}), base);
  assert.strictEqual(C(fail).value, '손으로 쓴 문구'); assert.strictEqual(C(fail).manual, true); assert.strictEqual(C(fail).status, 'manual');
  assert.strictEqual(bw.cellInfo(T(fail), C(fail)).unreadable, false);
  assert.strictEqual(bw.tally(fail).failed, 0);
  // 저장본에 문구가 없으면 못 읽음 그대로
  const none = bw.adoptManual(bw.buildState(form(), respFail(), {}), { 'C-4': { r3_c2: '' } });
  assert.strictEqual(C(none).status, 'failed'); assert.strictEqual(C(none).value, '');
  // 숫자 칸이 못 읽힌 경우는 저장본을 이어받지 않는다(기존 규칙)
  assert.strictEqual(bw.isTextFill('C-4', 'r3_c1'), false);
});
```

## 5. 위험·되돌리는 법

- **배포 순서**는 서버 보고서의 위험 1대로 서버와 프런트를 함께 올립니다. 이 패치만 먼저 올려도 안전합니다. 서버가 셀을 안 보내면 기존 동작(정적 기본 문구)이 그대로입니다.
- **서버 계약 의존**은 `TEXT_FILL`과 reason 코드 이름 `IRR_RULE_UNREADABLE` 두 곳입니다. 서버 구현이 바뀌면 같이 고칩니다.
- **엑셀로 채울 때 사용자 문구 소실**은 위 결정대로 읽은 경우에만 덮입니다. 덮인 값은 저장 전에는 `matDirty`로 보이고, 저장해야 확정됩니다.
- **되돌리기**는 패치 A~E를 되돌리고 새 시험 파일을 지우면 됩니다. 저장 데이터 형식은 안 바뀝니다. `dflt`는 화면 상태에만 있습니다.
- 서버를 쓰는 화면은 열지 않았습니다. 브라우저 육안 확인이 필요하면 서버 적용 뒤 호출자가 열람만 하세요. 확인할 곳은 C-4 판단기준 칸의 흐린 기본 문구, 문장이 채워진 모습, "읽지 못함" 툴팁입니다.
