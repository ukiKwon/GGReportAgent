## 보고: installIdentityHeader 사번 머리글 시험 1건 (frontend/test/map-detail.test.js)

### 1. 대상·방법·못 본 것
- 읽은 파일은 `js/app.js`(1~12, 915~1062줄), `js/login.js`(80~129줄), `js/prep.js`(825~880줄), `test/map-detail.test.js`(170~291줄)입니다.
- **테스트는 실행하지 못했습니다.** 읽기 전용이라 코드 읽기만으로 판단했습니다. 호출자가 적용한 뒤 아래 명령으로 확인해 주세요.
- `app.js` 전체를 훑지는 않았습니다. 최상위에서 실행되는 코드가 `document.addEventListener` 말고 더 있는지는 확인하지 못했습니다(가정 4).

### 2. app.js를 노드에서 불러올 수 있는가
**가능합니다. 다만 `module.exports`가 없어서 `loadFresh`의 반환값은 쓸 수 없고, 가짜 self에 붙은 `selfObj.app`을 읽어야 합니다.**
- `app.js`는 `(function(root){…})(typeof self !== 'undefined' ? self : this)`로 감싸져 있습니다(1줄, 1062줄). `root.app = app`으로 노출합니다(1061줄). `module.exports`는 없습니다.
- 불러올 때 최상위에서 도는 외부 의존은 `document.addEventListener('DOMContentLoaded', app.init)` 한 줄뿐입니다(1059줄). 그래서 `global.document = { addEventListener(){} }` 스텁이 필요하고, `init`은 실행되지 않습니다. 157줄의 `document.addEventListener('keydown'…)`는 함수 안쪽이라 호출되지 않습니다.
- `installIdentityHeader`는 `root.fetch`(전역 `fetch`가 아님), `root.store.loadSession()`, `root.login.withIdentity`를 씁니다(931~946줄). 따라서 가짜 self에 `fetch`·`store`·`login`을 넣어야 합니다.
- `login.js`는 노드에서 `require`할 수 있습니다(`module.exports = login`, 127줄). `roles.js`는 스스로 `require`합니다(10줄).
- **함정이 하나 있습니다.** `prep.js`의 `req`는 전역 `fetch`를 직접 부르고 `root.fetch`를 쓰지 않습니다(842줄). 브라우저에서는 `self === window`라 같은 객체이지만, 노드의 가짜 self에서는 다릅니다. 그래서 설치 뒤 `global.fetch = selfObj.fetch`로 감싼 함수를 연결해야 `prep.postConfirm`이 래퍼를 지나갑니다.
- `withIdentity` 순수 함수는 `login.withIdentity`로 이미 노출돼 있습니다. 다만 이 함수만 검증하면 "래퍼가 실제 요청에 적용되는지"를 보장하지 못합니다. 그래서 `installIdentityHeader`를 통째로 설치하는 방식을 택했습니다.

### 3. 구현안 — 시험 코드
**붙일 위치:** `frontend/test/map-detail.test.js` 맨 끝(291줄 `});` 다음). `loadFresh`(207줄)를 재사용하므로 그 뒤여야 합니다. 기존 파일 맨 위에 `assert`·`dash`·`read`가 선언돼 있을 것으로 가정합니다. 새로 필요한 `require`는 아래 시험 안에서 지역으로 처리했습니다.

```js
// ── security 11-15 하: 사번(X-Emp-No)이 화면 머리글과 함께 실제 요청에 실린다 ──
// app.js는 module.exports가 없어 loadFresh 반환값이 아니라 가짜 self의 app을 쓴다. 최상위 외부 의존은 document.addEventListener 한 줄뿐.
test('installIdentityHeader 설치 후 prep.postConfirm 요청: X-Emp-No가 X-Screen-Id·X-Button-Id와 함께 실린다', async function () {
  const sent = [];
  const rawFetch = function (url, init) {
    sent.push({ url: url, init: init });
    return Promise.resolve({ ok: true, status: 201, json: function () { return Promise.resolve({ bid_case_id: 'B1' }); } });
  };
  let session = { mode: 'account', id: 'x', emp: '3918264' };
  const fakeSelf = {
    fetch: rawFetch,
    store: { loadSession: function () { return session; } },
    login: require('../js/login.js')
  };
  const prevDoc = global.document, prevFetch = global.fetch;
  global.document = { addEventListener: function () {} };
  try {
    loadFresh('../js/app.js', fakeSelf);
    assert.strictEqual(typeof fakeSelf.app.installIdentityHeader, 'function');
    fakeSelf.app.installIdentityHeader();
    assert.strictEqual(fakeSelf.fetch.__identity, true, '전역 fetch가 신원 래퍼로 바뀌었다');
    global.fetch = fakeSelf.fetch;            // 브라우저에서는 self === window라 같은 객체 — prep.js는 전역 fetch를 직접 부른다

    const prep = require('../js/prep.js');
    await prep.postConfirm('I1', 'bid_board');
    const h = sent[0].init.headers;
    assert.strictEqual(sent[0].url, '/preps');
    assert.strictEqual(h['X-Emp-No'], '3918264');
    assert.strictEqual(h['X-Screen-Id'], 'bid_board');
    assert.strictEqual(h['X-Button-Id'], 'confirm');

    await prep.postConfirm('I2', 'map_popover');
    assert.strictEqual(sent[1].init.headers['X-Emp-No'], '3918264');
    assert.strictEqual(sent[1].init.headers['X-Screen-Id'], 'map_popover');

    session = null;                            // 로그아웃 상태면 사번을 붙이지 않되 화면 머리글은 그대로
    await prep.postConfirm('I3', 'bid_board');
    assert.strictEqual(sent[2].init.headers['X-Emp-No'], undefined);
    assert.strictEqual(sent[2].init.headers['X-Screen-Id'], 'bid_board');
  } finally {
    if (prevDoc === undefined) delete global.document; else global.document = prevDoc;
    global.fetch = prevFetch;
  }
});
```

### 4. 테스트
- 깨질 기존 테스트는 없습니다. 추가만 하고 전역 `document`·`fetch`는 `finally`에서 복원합니다.
- 기대 결과는 시험 파일 313건에서 +1건입니다.
- 실행 명령은 `node --test "frontend/test/map-detail.test.js"`입니다. 전체는 `node --test "frontend/test/*.test.js"`입니다.
- 이 시험이 실제로 사번을 고정하는지 보려면 변이 확인을 권합니다. `app.js:940`의 `withIdentity` 줄을 잠시 주석 처리하면 시험이 실패해야 합니다(소스는 다른 세션이 작업 중이므로, 확인은 메인이 판단해 주세요).

### 5. 위험·되돌리는 법
- 위험은 가정 3·4가 틀릴 때입니다. 그러면 `loadFresh` 단계에서 ReferenceError가 나고, 에러 메시지에 누락된 전역 이름이 나옵니다. 그 이름을 `fakeSelf` 또는 `global`에 추가하면 됩니다.
- 되돌리는 법은 시험 블록 하나를 삭제하는 것뿐입니다. 소스는 건드리지 않습니다.

### 6. 가정
1. `map-detail.test.js` 상단에 `assert`와 `loadFresh`가 선언돼 있습니다(207줄에서 `loadFresh` 확인).
2. `login.isEmpNo('3918264')`가 true입니다. 7자리 사번이고 기존 시험에서도 쓰는 값입니다. `isEmpNo`의 정확한 형식은 직접 읽지 않았습니다.
3. `prep.js`는 `require('../js/prep.js')`로 불러올 때 `root.store` 없이도 `postConfirm`이 동작합니다. 같은 파일 274~290줄의 기존 시험이 이미 그렇게 불러 씁니다.
4. `app.js` 최상위에서 `document.addEventListener` 외에 DOM이나 다른 전역을 건드리는 코드가 없습니다. 이 가정은 확인하지 못했습니다.
5. `loadFresh`는 `require.cache`를 비운 뒤 다시 읽습니다. `app.js`를 처음 불러오는 것이므로 캐시 충돌은 없습니다.
