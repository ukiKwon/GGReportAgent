## 3. 구현안 (적용 순서: 시험 먼저 → 구현. 패치마다 한 가지 일)

### 패치 A1. 전체 입찰건 창 행 높이
판단: 인라인 padding을 CSS 규칙으로 빼는 쪽을 권장한다. 이유는 세 가지다.
- 빈 행과 데이터 행이 같은 규칙을 쓴다.
- `table-center.test.js`가 `.more-table td` 규칙을 이미 단언한다(45·57·105·110행). 이 규칙에 padding만 더하므로 깨지지 않는다.
- `tr.tb-empty > td`(1816)는 padding을 건드리지 않는다.

인라인 `border-top`은 둔다(이 패치는 padding만 다룬다). 인라인 padding을 지우면 CSS 규칙이 이긴다. 인라인이 아닌 CSS끼리의 충돌은 없다. `.more-table td:first-child`는 text-align만, `#more-modal ...td:not(:first-child)`는 white-space만 건드린다.

index.html:1898
```
old:  .more-table td { text-align:center; vertical-align:middle; }   /* 기관·유형·지역·날짜·기간 모두
new:  .more-table td { padding:6px; text-align:center; vertical-align:middle; }   /* 기관·유형·지역·날짜·기간 모두
```
(줄 나머지 주석은 그대로 둔다.)

render.js:1495~1503 `renderMoreTable`의 `td` 6개: `'<td style="padding:6px;">'` → `'<td>'`로 바꾼다.
```
old: '<td style="padding:6px;">' + logic.esc(r.name) + '</td>' +
new: '<td>' + logic.esc(r.name) + '</td>' +
```
나머지 5개 td(type, region, bidDate, term, updatedAt)도 같은 방식이다. `<tr style="border-top:1px solid var(--line);">`는 그대로 둔다.

시험 추가(dlg.test.js:116 아래):
```js
// 빈 행도 데이터 행과 같은 높이: 칸 안쪽 여백은 CSS 한 곳, 데이터 칸에 인라인 padding 없음
assert.match(HTML, /\.more-table td \{ padding:6px;/);
assert.doesNotMatch(tbl, /<td style="padding:6px;">/);
```

### 패치 A2. #more-empty 낭독
index.html:5034
```
old: <p class="tb-empty-note" id="more-empty" hidden></p>
new: <p class="tb-empty-note" id="more-empty" aria-live="polite" hidden></p>
```
주의: `hidden`을 풀 때 텍스트도 같이 바뀐다. 일부 낭독기는 display:none → 표시 전환을 live 변화로 잘 못 잡는다. 확실히 하려면 render.js:1494에서 숨길 때 텍스트도 비우는 방식이 안전하다. 이 방식은 권장 보강이고 선택 사항이다.
```
old: if (none) { none.hidden = rows.length > 0; none.textContent = q ? '조건에 맞는 입찰건이 없습니다. 검색어를 지우세요.' : '등록된 입찰건이 없습니다.'; }
new: if (none) { none.textContent = rows.length ? '' : (q ? '조건에 맞는 입찰건이 없습니다. 검색어를 지우세요.' : '등록된 입찰건이 없습니다.'); none.hidden = rows.length > 0; }
```
시험 수정: dlg.test.js:116 정규식을
`/<p class="tb-empty-note" id="more-empty" aria-live="polite" hidden><\/p>/` 로 바꾼다(깨질 기존 단언이다).
추가 단언(보강을 적용할 때): `assert.ok(tbl.indexOf("none.textContent = rows.length ? ''") >= 0);`

### 패치 A4. 빈 표 → 안내 aria-describedby
id는 `cr-empty`, `ib-empty`(저장소에 사용 0건 확인). 속성은 기존 `id="…" tabindex="-1"` 문자열 바로 뒤에 붙여 기존 부분 문자열 단언을 보존한다(plancollect.test.js:245·602·616 모두 유지).

plancollect.js:253 (tableHtml)
```
old: '<table class="ad-table cr-table" id="cr-table" tabindex="-1"><caption
new: '<table class="ad-table cr-table" id="cr-table" tabindex="-1"' + (items.length ? '' : ' aria-describedby="cr-empty"') + '><caption
```
plancollect.js:265 (screenHtml)
```
old: (arr(st.items).length ? '' : tblEmpty.noteHtml(pc.emptyText(st.view)));
new: (arr(st.items).length ? '' : tblEmpty.noteHtml(pc.emptyText(st.view), '', { id: 'cr-empty' }));
```
plancollect.js:411 (ibTableHtml)
```
old: id="ib-table" tabindex="-1"><caption
new: id="ib-table" tabindex="-1"' + (list.length ? '' : ' aria-describedby="ib-empty"') + '><caption
```
(기존 문자열은 `'<table class="ad-table cr-table ib-table" id="ib-table" tabindex="-1"><caption …'` 형태이므로 따옴표를 닫고 이어 붙인다.)

plancollect.js:424 (ibHtml)
```
old: (items.length ? '' : tblEmpty.noteHtml(pc.IB_EMPTY));
new: (items.length ? '' : tblEmpty.noteHtml(pc.IB_EMPTY, '', { id: 'ib-empty' }));
```
A3를 먼저 적용해야 표와 안내가 같은 기준이다. 한 패치 단위로는 A3 → A4 순이다.

시험 추가:
- `screenHtml(screen({items:[]}))`에 `id="cr-table" tabindex="-1" aria-describedby="cr-empty"`와 `id="cr-empty"`가 모두 있다.
- 항목이 1개 이상이면 `aria-describedby`가 없다(`screenHtml(screen())`).
- `ibHtml` 빈 경우에는 `aria-describedby="ib-empty"`와 `id="ib-empty"`가 있다. 채워진 경우에는 둘 다 없다.

대안 검토: 표 아래 안내를 `role="status"`나 `tabindex`로 만드는 방안은 포커스·낭독이 중복돼 채택하지 않았다. describedby가 가장 변경이 작다.

## 5. 위험·되돌리는 법
- A1: `.more-table td`가 다른 곳에서 재사용되는지는 index.html에서 이 규칙 한 곳만 확인했다(`index_*.html` 시안 파일은 별개). 되돌리기는 CSS 한 줄과 td 6개 인라인 복원이다.
- A2: 보강안은 hidden과 텍스트를 함께 바꾼다. 검색 입력마다 텍스트가 같으면 낭독이 반복되지 않는다. 같은 문구가 계속이면 정상이다.
- A4: aria-describedby는 빈 표일 때만 붙는다. 항목이 생겨 다시 그릴 때 속성이 사라진다. 전체 HTML 재생성 방식이라 안전하다.
- B: 낭독 문장 앞이 `, ` → ` (`로 바뀌어 배지 숫자 뒤 낭독이 "… 2 (공고 예정일 경과 미처리 2건)"이 된다. 같은 항목이 접힌 분류 덧말에 합쳐질 때는 app.js가 괄호를 벗겨 다시 감싸므로 이중 괄호는 안 생긴다.
