## 2. 현재 상태와 요구 (근거)
서버가 칸마다 새로 내려 주는 것(`BoardExcelNamedFill.toCell`):
- `parts[]`: `{role main|sub, sheet, cell, display, raw, rounded}`
- `part_count`
- `convert`: `{kind eok | eok_paren | display_sum, unit_from, unit_to, divisor, sum, sub_sum, of, rounding, result}`
- `main_value` / `sub_value`: 괄호 병기를 두 값으로 따로 내려 줍니다. 문자열은 `"5.00 (1.00)"`입니다.
- `status` 에 `manual`이 추가됐습니다. 이때 `reason`은 `MANUAL_INPUT`이고 `source.sheet`는 null입니다. 합계를 구하는 `derive_sum` 칸도 `source.sheet`가 null입니다.
- `reason` 신규 값: `PART_EMPTY`, `PART_FAILED`, `NOT_NUMERIC`, `ROW_*`, `AREA_*`, `HEADER_NOT_FOUND`, `COL_*`
- `warnings` 신규 값: `TEXT_NUMBER`, `EXTERNAL_REF`, `UNIT_MISMATCH`, `UNIT_UNKNOWN`
- 응답 최상위의 `assumptions[]` (`UNIT_ASSUMED`)

프런트의 현재 문제:
- `buildState`(board-write.js:282-303)는 `source` 하나만 읽습니다. `parts`, `convert`, `main_value`, `sub_value`는 버립니다.
- `REASON` 표에 새 코드가 없습니다. `PART_EMPTY`도 478행의 대체 문구 때문에 "수식의 계산 결과가 파일에 저장돼 있지 않습니다"로 나옵니다. 입력 안 된 칸이라는 뜻과 다릅니다.
- `manual`/`derive_sum` 칸은 `source.sheet`가 null이라 툴팁에 "` 시트 `"처럼 깨진 줄이 나옵니다.
- 괄호 병기 `"5.00 (1.00)"`는 `shownNum`이 null을 돌려줘서(725행) 왼쪽 정렬이 됩니다.
- `manual` 칸은 status가 filled로 처리되어 "채웠다"로 세어집니다.

## 5. 위험·되돌리는 법
- **서버 문자열 의존**: `isParen`이 `main + ' (' + sub + ')'`와 정확히 같을 때만 두 값으로 그립니다. 서버가 `BoardNumber.paren`을 바꾸면 평문으로 내려와서 화면은 안 깨지고 muted만 사라집니다.
- **부품별 이유 코드 없음**: 서버 `parts[]`는 실패 칸의 `display`를 `""`로만 보냅니다. 여러 칸 중 어느 칸이 비었는지는 "읽지 못함"으로 중립 표시합니다. 서버가 `part.reason`을 보내면 코드가 이미 그 값을 우선 씁니다(`partOf`/`partText`). 개발: 백엔드에 요청할 사항입니다.
- 되돌리기: 패치는 `board-write.js`와 `index.html` CSS 한 덩어리입니다. 새 테스트 파일은 삭제하면 됩니다. 칸 스키마 변경(`parts`, `conv`, `manual` 필드)은 추가뿐이라 기존 흐름을 막지 않습니다.
- `reasonText`의 대체 문구가 바뀝니다. 서버가 알 수 없는 `reason`을 주면 "저장돼 있지 않다"는 거짓 안내 대신 일반 문구가 나옵니다.

## 6. 이관 메모
- [이관: 디자인] 비어 있음/직접 입력(muted), 계산 줄 위치(툴팁은 전부, 상태 줄은 `.bd-w-calc` 분리), 부품 줄 6개 상한, 괄호 안 muted 색 — design-reviewer C-5 규격과 대조해 확인 — 커밋 전 대조(PUSH-GATE) — 위 CSS 4줄과 P2 `barHtml` 분리.

## 7. 열린 질문
- 직접 입력 칸(기관명)이 비어 있어도 "확인"을 누를 수 있습니다. 비어 있으면 확인을 막을지(읽지 못함처럼) 정해야 합니다. 이 패치는 기존처럼 허용합니다.
