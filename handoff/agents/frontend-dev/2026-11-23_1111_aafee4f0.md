## 1. 바꾼 점

### 새 파일 `frontend/js/prepboard.js` (약 600줄)
- **앞 절반 순수 함수 (node 테스트 대상)**
  - 머리 구성: `headModel`·`colInfos`. `columns[]` 순서 그대로 쓰고, 같은 `group`이 이어지면 묶음 머리(colspan)로 묶습니다. 묶음이 없는 열은 rowspan 2입니다.
  - 칸 모양: `cellModel`·`cellHtml`·`cellAria`. kind(NOTICE·AUTO·MANUAL)와 mark별로 글리프, 틴트, 누를 수 있는지를 정합니다.
  - 날짜: `dateText`. 올해면 MM-DD, 다른 해면 YYYY입니다.
  - 정보 줄·메뉴: `infoParts`·`infoHtml`·`menuHtml`.
  - 거르기: `filterRows`·`whoOptions`·`emptyModel`·`countHtml`·`readOnlyAll`. 서버 순서는 다시 정렬하지 않습니다.
  - 문구: `saveError`(409 STALE_CHECK·STATE_CHANGED·NOT_MANUAL을 코드로 고르고, 403·400·401·404·연결 실패도 처리), `saveOk`, 조사 `ro`.
  - 키보드: `nextPos`(화살표·Home·End·Ctrl+Home/End), `markByKey`(1~4).
  - 마크업: `tableHtml`·`rowHtml`·`headHtml`·`legendHtml`.
- **뒤 절반 DOM 배선**
  - 진입점은 `show(hooks, {reload, focusBid})`, `leave()`, `reset()` 세 개입니다.
  - 표 키보드는 roving tabindex입니다. Tab 정지는 표 안에서 1개이고 화살표로 이동합니다.
  - 칸 메뉴는 `.hb-menu`를 body에 붙이고 `role=menuitemradio`를 씁니다. 키 1~4, ↑↓·Home·End, Esc·Tab으로 닫으면 칸으로 포커스가 돌아갑니다.
  - 저장은 낙관적으로 그립니다. 고른 값을 바로 그리고, 성공하면 응답 `cell`로 그 칸만 바꾸고, 실패하면 이전 값으로 되돌린 뒤 칸에 `is-failed`를 붙입니다.
  - `saved:false`는 메시지를 내지 않습니다. 같은 값이면 요청도 보내지 않습니다.
  - 성공 알림은 `#pb-live`, 실패는 `#pb-err`입니다.
  - 자동 새로고침, 저장소, `confirm()`은 없습니다.
- **서버 값 처리**: 모든 마크업은 `esc()`를 거칩니다. `.innerHTML`·`.outerHTML` 대입 줄은 허용된 조립 함수만 쓰도록 시험이 줄 단위로 검사합니다. 템플릿 문자열 보간은 없습니다.
- 글리프는 SVG 획입니다(규격 6-3). `marks[].symbol`(V·△)은 화면에 쓰지 않습니다.

### 고친 파일 `frontend/js/prep.js` (최소 연결, 표가 없으면 옛 화면 그대로)
- **전환 상태**: `freshState`에 `view('board'|'case')`, `fromBoard`, `pendingCase`를 추가했습니다.
- **`paintGate`**: 게이트가 걸리면 `#pp-board`도 숨깁니다.
- **새 함수 5개**: `boardOn`, `showView`, `toBoardState`, `boardHooks`, `enterCase`, `backToBoard`.
  - `boardOn()`은 `root.prepboard`와 `#pp-board`가 둘 다 있을 때만 참입니다. 하나라도 없으면 옛 목록+상세 화면이 그대로 돕니다. 그래서 index.html을 고치기 전에도 기존 시험이 깨지지 않습니다.
  - 상세 모드에서는 `#pp-list`를 숨기고 `#pp-back`을 보입니다.
- **`refresh()`**: `view==='board'`이면 `prepboard.show()`를 부르고 끝냅니다.
- **`enterCase(bid)`**: 이 함수는 `prepboard.leave()`(스크롤 저장)를 부른 뒤 같은 자리에서 상세로 바꿉니다.
- **`backToBoard()`**: 표를 다시 불러옵니다. 거르기, 스크롤, 포커스(그 행 이름 칸)는 prepboard가 유지합니다.
- **`loadDetail` 상세 열기 GET**: 표에서 연 상세만 `X-Screen-Id: prep_dashboard`, `X-Button-Id: open`입니다. 지도·현황판이 `openCase`로 연 상세는 그대로 `prep_detail`입니다.
- **`onClick`**: `case 'back'`을 추가했습니다.
- **`wire()`**: `#pp-pane` 맨 위에 `#pp-back`([← 대시보드로])을 JS로 만들어 넣습니다. 그래서 index.html에 이 단추를 넣을 필요가 없습니다.
- **`mount()`**: 메뉴로 들어오면 표부터 보입니다(`toBoardState`). `openCase` 경로만 `pendingCase`로 상세를 한 번 지킵니다.
- **계정 변경 처리**: `mount`와 `onProfileChange` 두 곳에서 `prepboard.reset()`을 부릅니다.

## 2. 규격·지시와 다른 점 (숨기지 않고 적음)
1. **담당자 선택지 순서**는 `전체 → 내 담당 → 이름 가나다순`입니다. main 결정은 "맨 위에 내 담당"이었는데, 기본값인 '전체'를 맨 위에 두고 바로 아래에 '내 담당'을 두었습니다. 바꾸려면 `whoOptions`의 배열 순서만 바꾸면 됩니다.
2. **'내 담당' 칩**은 규격의 `can_check`가 아니라 `is_mine`(main 결정 2)으로 그립니다.
3. **끝난 행 칩 글자**는 `state_name`을 쓰고, 비면 '확정 취소'입니다. 규격은 '확정 취소' 고정이었습니다. `state_name`이 '중단'과 '확정 취소'를 구분해 주기 때문입니다.
4. **404 문구**는 규격에 없어서 하나 새로 썼습니다: "이 칸이나 기관을 찾을 수 없습니다. [새로 고침]으로 확인하세요." 문구가 맞는지 확인이 필요합니다.
5. **상세의 다른 요청**(체크·업로드 등)은 이전과 같이 `prep_detail`입니다. 지시대로 '상세를 여는 GET'만 `prep_dashboard`로 보냈습니다. 서버 `PrepUiIds`가 `prep_dashboard/open`을 받는지 확인이 필요합니다. 다른 버튼 이름은 보내지 않았습니다.
6. **범례와 열 머리**는 JS가 `#pb-legend`에 채웁니다. 마크업에는 빈 `<p>`만 두면 됩니다. 규격 6-5처럼 머리 행을 index.html에 직접 쓰지 않습니다.
7. **칸 정보 줄에 쓴 말**은 `기록한 날`(AUTO 칸 날짜 이름표 임시안)입니다. 공고 칸의 `marked_on`이 무슨 날짜인지는 기획 확인이 아직 필요합니다(규격 이관 메모 그대로).
8. **클라이언트 게이트**: 디자이너 등은 메뉴에서 이미 숨겨져 있고, `prep.gateOf`가 막으면 옛 `T.forbidden` 문구가 나옵니다. 서버가 403을 주는 경우에만 새 문구("이 화면은 영업부서만 볼 수 있습니다…")가 나옵니다.

## 3. index.html에 메인이 넣을 것

주의할 점은 두 가지입니다.
- `id="pb-scroll"`은 규격 6-5에는 없었고 JS가 씁니다(필수).
- `#pb-count`·`#pb-at`은 비워 두면 JS가 채웁니다.

### (B) script
`<script src="js/prep.js"></script>` 바로 다음 줄에 넣습니다. app.js·render.js 앞이어야 합니다.
```html
<script src="js/prepboard.js"></script>
```
순서는 prep.js → prepboard.js → app.js입니다. prepboard.js는 prep.js를 로드 뒤에 참조합니다. `root.prepboard`는 prep.js가 호출 시점에 읽어 쓰므로 위 순서면 충분합니다.

### (C) CSS
규격 6-6 블록(design-reviewer `2026-11-23_1049_ae4db5c1.md` 266~318줄)을 그대로 쓰고, `/* 제안서 사전준비 끝 */`(1436줄) 바로 뒤에 붙입니다. 그 마커 안에 넣으면 기존 prep 시험의 hex·11px 검사 범위가 됩니다. 이 블록은 12px 이상이라 통과하지만, 마커 밖이 안전합니다. 블록 시작이 `#pp-board {`, 끝이 `.pb-back {` 줄이 되게 하세요(시험이 이 둘로 범위를 잡습니다). 규격에서 더할 것은 아래 두 줄뿐입니다.
```css

```
`#pb-ro`가 `.pb-legend`(display:flex)와 `hidden`을 같이 쓰기 때문에 필요합니다. 규격 CSS의 `#pp-board[hidden], #pp-wrap[hidden] { display:none; }`는 그대로 필요합니다.

## 6. 확인 절차 (브라우저, 서버가 적용된 뒤)
1. 영업팀 계정으로 [영업 추진 준비 › 대시보드]를 엽니다. 머리 2단, 기관 이름 열 고정, 가로 스크롤을 확인합니다.
2. 완료 칸은 파랑 10%, 진행 칸은 주황 10% 틴트와 체크·세모·가로줄 글리프가 보여야 합니다.
3. 칸 안 날짜는 올해면 `MM-DD`, 다른 해면 `YYYY`입니다. 칸을 고르면 아래 정보 줄에 체크한 날과 사람이 나옵니다.
4. 담당 기관의 손 칸을 눌러 메뉴를 열고 1~4, Esc, Tab을 써 봅니다. 저장되면 그 칸만 바뀌고 `#pb-live`에 알림이 갑니다.
5. 같은 칸을 두 탭에서 고르면 STALE_CHECK 문구가 나오고 칸에 빨간 테두리가 보이는지 확인합니다.
6. '내 담당' 거르기, 이름 검색, [취소·중단한 건도 보기](재요청)를 확인합니다.
7. 기관 이름을 누르면 같은 자리에서 상세가 열리고, 서버 접근 이력에 `prep_dashboard/open`이 남습니다. [← 대시보드로]를 누르면 표가 다시 불러와지고 거르기·스크롤·그 행 포커스가 유지돼야 합니다.
8. 담당이 없는 계정(영업팀장·영업부장)은 `#pb-ro` 안내가 보이고 버튼이 없어야 합니다. 디자이너는 메뉴에 없어야 하고, 서버가 403이면 권한 없음 문구가 나와야 합니다.
9. 지도·현황판의 [사전준비 열기]는 이전처럼 상세로 바로 열려야 합니다(`openCase`가 `pendingCase`로 상세를 지킵니다).

## 7. 이관 메모
- [이관: 개발] 서버 `PrepUiIds`가 `prep_dashboard`의 `open`(목록 GET과 상세 GET 둘 다)·`refresh`·`dash_check`를 받는지 확인합니다. 상세 안의 쓰기 버튼은 `prep_detail`을 그대로 씁니다.
