### 2. 항목별 결과
1. **포커스 복귀: 완료, 지시와 다른 방식입니다.** `pendingFocus` 대신 "다시 그리기 직전의 포커스 위치를 기억했다가 같은 버튼을 다시 찾는" 방식으로 했습니다.
   - `drawRes`와 `drawTop`에 적용했습니다(`board-material.js`).
   - 이렇게 하면 `loadMine`과 `loadList` 응답 순서가 바뀌어도 포커스가 유지됩니다. `toList`와 `leaveForm`의 즉시 포커스는 그대로 두었습니다.
   - `openerId`는 `doCreate` 성공 시 비웁니다. `enterMaterial`에서는 비우지 않았습니다. `openMaterial`이 `enterMaterial` 전에 값을 세팅하고 `reload`도 `enterMaterial`을 거치기 때문입니다.
2. **409 [내 값으로 다시 저장]: 완료.**
   - 누르면 최신 머리를 새로 받아서(`forceSave`) 최신 저장본에 내가 고친 칸만 얹은 값(`bw.rebaseBase`)과 최신 버전 번호로 저장합니다.
   - 내 엑셀에 없던 표와 내가 안 건드린 칸은 최신 값 그대로입니다.
   - 저장 성공 뒤 `adoptSaved`가 남이 고친 칸을 화면에 반영해 "바뀐 칸 0"이 됩니다.
   - 409를 받으면 `env.mat.setHead`로 머리를 갱신하고 버전 이력 캐시도 비웁니다.
   - 안내 문구 "내가 고친 k칸…"은 이제 사실 그대로라 바꾸지 않았습니다. 최신 머리를 못 받으면 "서버에 연결하지 못해 저장하지 않았습니다." 오류를 보입니다.
3. **저장 뒤 요약 줄: 완료.** `onSaved`에서 `savedLabel`을 비우고, 저장 뒤 머리를 받으면 `setSavedLabel`이 `#bd-w-sum`의 글자만 바꿉니다(다시 그리지 않아 포커스 유지).
4. **만들기 오류: 완료.** 문자열 detail(400·404)을 읽어 그대로 보여 주고, 화면 출력 시 esc합니다.

   - '연도는' 앞붙이기는 지웠습니다. 서버 문구가 이미 "연도는 …"로 시작합니다.
5. **느슨한 단언: 완료.** 세 곳을 정확한 단언으로 바꿨습니다.

### 4. 지시에서 벗어난 판단과 불확실한 테스트 기대값
- 포커스 복귀 방식을 바꾼 것은 1번에 적었습니다.
- **`adoptSaved` 부작용(확인 필요)**: 다시 저장한 뒤 남이 고친 칸을 맞출 때 `value`와 `orig`를 같이 바꿉니다(`adoptManual`과 같은 방식). 엑셀 올린 상태에서 그런 칸은 "수정됨" 표시가 풀립니다. 의도한 동작이지만 화면에서 한 번 확인해 주세요.
- **불확실한 테스트 기대값**
  - `matBarHtml` 테스트가 `data-w="swap" disabled>엑셀 올리기`와 `id="bd-w-draft" data-w="draft" disabled>` 문자열 모양에 의존합니다. 마크업을 소스에서 직접 대조했지만 실행은 못 했습니다.
  - `board-material.test.js`의 `<span>저장 전</span>` 단언이 `headHtml`의 `.bd-m-meta` 첫 span 구조에 의존합니다.
- 컨트롤러(`createController`) DOM 동작 테스트(포커스 복귀, 409 흐름, `startMat`의 `max_mb`)는 가짜 DOM이 필요해 추가하지 않았습니다. 순수 함수와 소스 문자열 단언만 추가했습니다.
