## 협약 성과 화면 맨 위 '결과 난 곳 · 남은 곳' 요약 패치 (읽기 전용, 미적용·미실행)

### 1. 대상·방법·못 본 것
- 읽은 것은 `results.js`, `index.html`의 rs-* CSS, `TargetResultRules.java`, `TargetResultService.java`(요약 부분), `results.test.js`입니다. `TargetResultController`는 읽지 않았고, 응답 필드는 서비스의 `sum.put` 줄로 확인했습니다. 화면은 열지 않았고 서버도 쓰지 않았습니다.
- 줄 번호는 `results.js` 242~267(`bandHtml`), `index.html` 2761~2763(`.rs-band`)입니다.

### 2. 요구 요약과 판단
- **서버 숫자는 이미 있어 backend 이관이 필요 없습니다.** 응답 `summary`에 `target_n`, `success_n`, `fail_n`, `pending_n`, `unregistered_n`이 있습니다. 서비스는 `target_n`을 올린 같은 루프에서 나머지 넷 가운데 하나를 올려, 기관 하나가 정확히 한 곳에 셉니다(Service 95~103).
- **요약 띠는 이미 있습니다.** `bandHtml`의 4칸 `.rs-band`(달성률·목표 기관·협약 내역·결과 미확정)이고, 맨 앞 칸이 '달성률'이라 '몇 곳 났고 몇 곳 남았나'가 바로 보이지 않습니다.
  - 칸을 늘리면 5칸이 되어 `results.test.js:61`, `:361`의 `split('class="hb-k"').length === 5`가 깨집니다. 그래서 띠 위에 한 줄 `<p class="rs-lead">`만 추가합니다.
  - 띠 칸과 막대는 건드리지 않습니다. 0건 띠(bd404de2)와 막대 주석(ff768b47)도 그대로입니다.
- **결과 난 곳**은 `success_n + fail_n`입니다. 달성률 분모(`rate_denominator`)와 같은 집합입니다.
- **남은 곳**은 `pending_n + unregistered_n`입니다. 분류 다섯 가지 중 '결과 대기'와 '확인 필요'를 합칩니다.
  - 근거 1: 기존 4번째 칸 '결과 미확정'이 이미 이 합이라, 같은 화면에서 숫자가 갈라지지 않습니다.
  - 근거 2: '확인 필요'(공고는 끝났는데 약정 기록이 없는 곳)도 지금 결과를 못 낸 곳입니다. '결과 대기'만 세면 12곳 중 3곳이 '난 곳'으로도 '남은 곳'으로도 안 잡힙니다.
  - 불변식은 `결과 난 곳 + 남은 곳 = 목표 기관`(`target_n`)입니다. 시험으로 고정합니다.
- 세부 분해(대기 n·확인 필요 n)는 4번째 칸에 이미 있어 줄에는 넣지 않습니다.
- `truncated`(2,000곳 초과)일 때는 서버가 `summary`를 안 보내므로 줄도 그리지 않습니다. 목표 0곳도 줄을 그리지 않습니다(빈 상태 문구가 있음).

### 4. 테스트
- 깨질 기존 시험은 없을 것으로 봅니다. `results.test.js`의 줄 61·361(hb-k 5분할), 66(`결과 대기 <b>10</b> 확인 필요 <b>6</b>`), 76(truncated의 `>—</span>` 5분할), 366(`결과가 나면` 부재), 54(liveText)를 대조했고 줄 문구가 겹치지 않습니다. 줄의 `<b>`는 `<span>` 안이라 `>—</span>` 개수에도 안 걸립니다.
- 위 시험은 입력 `SUM`에서 `{done: 8, left: 16, total: 24}`와 `done + left = target_n`을 확인합니다. 결과 0건 12곳에서는 '0곳 · 12곳', 목표 0·`null`·`truncated`에서는 줄이 없음을 확인합니다.
- 실행 명령은 `node --test "frontend/test/results.test.js"`로 먼저 돌리고, 이어서 `node --test "frontend/test/*.test.js"` 전체를 돌립니다.

### 5. 위험·되돌리는 법
- 위험은 낮습니다. 추가만 있고 기존 마크업은 바꾸지 않습니다. 한 가지 주의할 점은, 서버가 새 `result_cd`를 보내면 `target_n`과 합이 어긋날 수 있다는 것입니다(그 경우 `classify`는 null).
- 되돌리려면 패치 B의 `leadHtml` 호출 한 군데를 빼고 CSS 4줄을 지우면 됩니다.
- 화면이 바뀌므로 PUSH-GATE의 design-reviewer 대조와 `docs/design_history` 전/후 장이 필요합니다.
