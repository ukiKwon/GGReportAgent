## 2. 원인

**① 닫기 확인 줄("적은 내용이 사라집니다. 닫을까요?")은 의도된 동작이고 처음부터 보이지 않습니다.**
- 이 줄은 `prep.closeConfirmHtml()`(prep.js:754)이 만듭니다. 이 함수는 `requestClose()`(prep.js:1291)에서만 호출됩니다. 호출 위치는 prep.js:1297입니다.
- `requestClose()`는 다음 조건을 모두 만족할 때만 줄을 띄웁니다. 의견이 한 글자 이상이거나 지명한 담당자가 한 명 이상이어야 하고(prep.js:1295), 닫는 동작이 일어나야 합니다. 닫는 동작은 [취소]·Esc·바깥 클릭입니다.
- 열 때는 `reason:''`, `sel:[]`, `closing:false`(prep.js:1218)이고, 초기 마크업의 `#pp-m-confirm`은 빈 div입니다(prep.js:739). 그래서 코드상 처음부터 보일 수 없습니다.
- 내용이 없으면 줄 없이 바로 닫힙니다(prep.js:1301).
- 사용자가 본 장면은 의견을 적거나 담당자를 고른 뒤 [취소]·Esc·바깥 클릭을 한 경우로 보입니다. 이 경우는 사용자 말대로 "취소를 눌렀을 때 나와야 하는 멘트"가 맞습니다.
- 다만 의견 입력란 바로 밑에 나타나는 위치와, 확인 줄 안의 버튼 이름이 [계속 작성]과 [닫기]인 점은 오해를 부를 수 있습니다. 그래서 버그는 아니고 안내 문제로 분류했습니다.
- 처음부터 보이는 것이 재현되면 코드와 어긋난 별개 문제입니다. 그때는 재현 순서를 알려 주세요.
- 이 줄을 없애지 않기를 권합니다. 없애면 적은 의견과 지명을 실수로 잃습니다.
- 기존 시험은 prep.test.js:333이 `closeConfirmHtml()` 마크업(`aria-label="닫기 확인"`)만 확인합니다. 그래서 줄이 언제 나타나는지는 시험으로 고정돼 있지 않습니다. 아래 4번에서 보강합니다.

**② 의견 textarea 가로가 좁은 것은 CSS 누락입니다.**
- 제안팀 구성 창은 `#tm-reason { display:block; width:100%; … }`(index.html:1173)를 갖고 있습니다.
- 개설 신청·확정 취소·중단·무효 창의 `#pp-reason`(prep.js:690)에는 규칙이 하나도 없습니다. 브라우저 기본 폭(cols 기본값)으로 나옵니다.

## 3. 구현안

패치는 한 가지만 합니다. index.html의 `.pp-confirm span` 줄(약 1208행) 바로 뒤에 한 줄을 더합니다. 새 hex는 쓰지 않고 기존 변수만 씁니다.

```
old:
  .pp-confirm span { flex:1 1 320px; word-break:keep-all; }
new:
  .pp-confirm span { flex:1 1 320px; word-break:keep-all; }
  #pp-reason { display:block; width:100%; box-sizing:border-box; margin-top:4px; resize:vertical; }
  #pp-reason[aria-invalid="true"] { border-color:var(--red); }
  #pp-m-confirm:not(:empty) { margin-top:10px; }
```

- 두 번째 줄은 prep.js:1309가 `aria-invalid`를 제거하므로 설정하는 쪽이 있다는 전제입니다. grep으로 설정 위치를 먼저 확인하고 없으면 이 줄은 뺍니다.
- 세 번째 줄은 확인 줄이 뜰 때 본문과 붙지 않게 하는 여백입니다. `#tm-m-confirm`(index.html:1176)과 같은 방식입니다.
- 모바일 창은 `.modal-box.tm-modal-box`(index.html:1183)가 이미 폭을 줄이므로 100%가 따라갑니다.
- 문구는 건드리지 않습니다. 확인 줄 버튼 이름을 바꾸는 것은 디자인·기획 결정이라 7번 질문으로 올립니다.

적용 순서는 시험을 먼저 추가하고 구현을 나중에 합니다.

## 4. 테스트

**깨질 기존 시험은 없습니다.**

**추가할 시험(frontend/test/prep.test.js, `HTML`이 line 8에 이미 있으므로 그대로 쓴다):**
```js
test('개설 신청 의견란은 창 폭에 맞춘다 (#pp-reason width:100%)', () => {
  assert.match(HTML, /#pp-reason\s*\{[^}]*width:\s*100%[^}]*box-sizing:\s*border-box/);
});
test('닫기 확인 줄은 처음엔 비어 있고, 내용이 있을 때만 closeAsk 문구를 쓴다', () => {
  const body = prep.modalHtml({ kind: 'open', reason: '', sel: [], q: '', candState: 'ok', cands: [], closing: false }, { name: 'x' });
  assert.ok(body.indexOf('pp-m-keep') < 0 && body.indexOf('닫기 확인') < 0);   // 처음부터 보이지 않음
  assert.ok(body.indexOf('<div id="pp-m-confirm"></div>') > 0);                // 빈 자리만
  assert.ok(prep.closeConfirmHtml().indexOf('적은 내용이 사라집니다. 닫을까요?') > 0);
});
```
- 두 번째 시험은 마크업만 확인합니다. 언제 띄우는지(`requestClose` 조건)는 DOM 배선 안이라 노드 시험 대상이 아닙니다. 그 부분은 Playwright 수동 확인으로 대신합니다.

## 6. docs/design_history 전/후 장 문안 (section.ch로 호출자가 추가)
- 제목: 개설 신청 창 의견란 가로 맞춤
- 전: 의견 입력란이 브라우저 기본 폭(좁은 칸)으로 나와 창 오른쪽이 비어 보였습니다. 제안팀 구성 창의 의견란은 이미 창 폭을 채우고 있어 두 창이 서로 달랐습니다.
- 후: 개설 신청·확정 취소·중단·무효 창의 의견란이 창 폭을 꽉 채웁니다. 세로로만 늘릴 수 있고, 닫기 확인 줄은 입력란과 10px 떨어져 나옵니다.
- 닫기 확인 줄 설명: "적은 내용이 사라집니다. 닫을까요?"는 의견이나 담당자를 적은 뒤 [취소]·Esc·바깥 클릭으로 닫으려 할 때만 나옵니다. 처음 열었을 때와 아무것도 적지 않았을 때는 나오지 않고 바로 닫힙니다.
- 스크린샷 경로 제안은 handoff/agents/frontend-dev/shots/2026-11-16_pp-open-before.png와 2026-11-16_pp-open-after.png입니다. 찍을 순서는 다음과 같습니다.
  1. 개설 신청 창을 엽니다.
  2. 의견란 폭을 캡처합니다.
  3. 의견에 글자를 넣고 [취소]를 눌러 확인 줄이 나온 모습을 캡처합니다.
  4. 제출은 누르지 않습니다.
