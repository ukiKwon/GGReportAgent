제안 준비 현황 상세 2단계 '입찰공고확인'에서 금고 은행·약정 기간·기관장이 미확인이면 붉은 줄을 더하도록 고쳤습니다. 테스트는 실행하지 못했고, 아래 명령은 메인이 돌려야 합니다.

## 고친 곳
- **`frontend/js/preptask.js`**
  - T에 문구 4개를 더했습니다: `chkBank`·`chkTerm`·`chkChief`·`instUnknown`('미확인').
  - `pt.noticeChecks`가 5번째 인자 `inst = { bank, term, chief }`를 받습니다. `false`(미확인)인 값마다 `{ label, text:'미확인', bad:true }` 줄을 하나씩 더합니다.
  - `true`(값 있음)나 `undefined`(아직 모름)이면 줄을 더하지 않습니다. `inst`를 안 넘기면 예전과 같습니다.
  - `noticeChecksHtml`이 bad 줄 끝에 sr-only '(확인하세요)'를 붙이므로 그 부분은 손대지 않았습니다.
  - `noticeGaps`와 `noticeConfirmDue`는 그대로라서 [다음] 확인은 막히지 않습니다.
- **`frontend/js/prep.js`**
  - `instFacts(rec, D, today, instId)`를 새로 만들었고, `noticeInfo`가 `out.inst`로 돌려줍니다. 2단계 확인 항목을 만드는 곳이 `ni.inst`를 `noticeChecks`의 5번째 인자로 넘깁니다.
  - 은행은 KB 수집, KB_NEXT의 현재 은행, 행안부 현황(`lofinLines`), 레코드의 `rec.bank` 중 하나라도 있으면 값 있음으로 봅니다.
  - 약정 기간은 `dash.termLine` 결과에 `pop-unk`(미확인 칩)가 있으면 미확인으로 봅니다. 이 기준은 `dashboard.js:925~1015`를 읽고 맞췄습니다.
  - 기관장은 `headcard.view()`가 이 기관을 불러온 뒤 status가 `none`일 때만 미확인으로 봅니다. `ok`는 값 있음, 로딩이나 실패는 모름입니다.
  - 2단계 분기에서 `headcard.gate`를 통과하면 `ensure`를 한 번 부릅니다. 이게 없으면 2단계에서는 기관장 조회 결과가 없어 기관장 줄이 영원히 안 뜹니다.
- **`frontend/test/preptask.test.js`**: 시험 `2단계 확인 항목: 금고 은행·약정 기간·기관장 미확인은 붉은 줄(막지 않음), 값이 있거나 못 불러왔으면 줄 없음`을 더했습니다.
  - 세 값이 모두 `false`면 줄이 3건 늘고, 붉은 줄 수 B와 중립 줄 숫자가 그만큼 늘어납니다.
  - 값이 있거나 `undefined`거나 `inst`가 없으면 줄이 없습니다.
  - 하나만 `false`면 그 줄만 생깁니다.
  - `noticeConfirmDue`는 그대로 true입니다.
  - `PREP_SRC`에 `instFacts`와 `ni.inst`가 있는지 소스 단언도 넣었습니다.

## 규격과 다르게 판단한 것
1. **기관장 조회를 2단계에서 시작합니다.** 3단계와 같은 `hc.ensure`를 부릅니다. 서버 읽기와 열람 기록이 2단계 진입 때 생기고, 같은 기관이면 다시 읽지 않습니다. 원치 않으면 `prep.js`의 `try { const hcm = root.headcard` 블록만 빼면 기관장 줄은 항상 '모름'이 됩니다.
2. **'미확인'이 뜨는 조건이 팝업과 완전히 같지는 않습니다.** 팝업은 서버의 직접 입력 금고 약정(`c.bank`)도 보지만, 2단계 prep.js에는 `/bank-contracts/summary`가 없습니다. 직접 입력만 있는 기관은 은행·약정 기간이 오탐(값이 있는데 미확인으로 뜸)될 수 있습니다. 개선하려면 `kbboard.gs.sum`(다른 세션 담당)이나 prep.js가 받는 별도 조회가 필요합니다.
3. 문구는 label + text '미확인' 형태로 썼습니다. 예시의 '금고 은행 미확인'과 같은 읽힘입니다.
