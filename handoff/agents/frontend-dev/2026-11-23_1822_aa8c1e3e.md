## 1. 반영 내용

11개 항목을 모두 반영했습니다. 테스트는 실행하지 못했습니다.

- 항목 7, `kindQueueModel`(약 172줄): `noticeN`을 `ids`가 있으면 `instId(it.rec)`로 걸러 셉니다.
- 항목 7, `kindQueueHtml` meta(약 182줄): '곳(위 띠)'에서 '(위 띠)'를 뺐습니다.
- 항목 6, `kindQueueHtml`: aria를 '6개월 내 공고 예정 없음', 막대 빈 줄을 '6개월 내 예정 없음'으로 바꿨습니다.
- 항목 8, `dash.scopeIds`(383줄): 합집합이 빈 객체면 `null`을 돌려줍니다.
- 항목 9, `noticeBandHtml`(523줄 부근): `open`이 0이어도 `w>0`이면 띠를 그립니다. 전부 0이면 `''`입니다. 이때 aside는 `one` 조건을 `open.length <= 1 && w > 0`으로 넓혀 나옵니다(카드 없음). `renderNotice` 주석도 고쳤습니다.
- 항목 3, `paneParts`: `bcm.sectionHtml` 옵션에 `editing: !!c.editing`을 더했습니다. `popupHtml`이 `c`를 그대로 넘기므로 `dmRender`의 `editing: !!m.bankEdit`가 닿습니다.
- 항목 5, `paneParts` 폴백 경로(987줄): 절에 `id="db-bank"`를 붙였고, 순서를 dl → muniSrc → note → 출처 details로 바꿨습니다.

**`frontend/js/bankcontract.js`**
- 항목 4(a), 263줄: `dl.replace(/<\/dl>$/, function () { return rows + tail + '</dl>'; })`로 바꿨습니다. 같은 패턴은 `bankcontract.js`와 `dashboard.js`에서 더 찾지 못했습니다.

**`frontend/js/render.js`**

## 3. 판단과 주의
- **foot 교체 문제**: `dmRender`가 약정 편집 중에 `.bk-foot`을 입력 묶음으로 갈아 끼웁니다. 출처 details를 foot 안에 두라는 지시대로 했더니, 편집 단계에서는 출처 details도 같이 가려집니다. 편집을 마치면 다시 나옵니다. 편집 중에도 출처를 보여야 한다면 `dashboard.js` 1806~1810줄을 따로 손봐야 합니다. 지시 범위 밖이라 건드리지 않았습니다.
- **`dm-popup-c65.test.js` 88줄**: `bk-edit` 배선을 소스 정규식으로 확인하는 단언입니다. 이번 변경과 직접 관련은 없다고 봤지만 실행 결과를 확인해 주세요.
- **`$&` 시험 미추가**: 항목 4(a)의 치환 문법 방어용 시험은 추가하지 않았습니다. 지시 목록에 없었습니다.
- `index.html`의 다른 세션 영역(머리 띠·`.stab-*`·aria·기관장 카드·`tab-btn-map`)과 `kbboard.js`·`headcard.js`·`tchange.js`·`nav.js`는 건드리지 않았습니다.
