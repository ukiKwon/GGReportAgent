- 11-20 커밋 00796b0은 직접 열어 보지 않았습니다. 현재 파일 기준으로 짰고, 07649ad1이 건드린 워드 내려받기 부분(1184줄 부근)은 이 패치가 건드리지 않아 충돌이 없습니다.

## 2. 원인/요구 요약
- `headcard.js` 212~218줄 `hc.startMonthOk`의 정규식 `^\d{4}-\d{2}$`가 연-월만 통과시킵니다.
- 1080~1081줄이 이 검사를 호출하고, 1081줄에 오류 문구 '시작은 YYYY-MM(예: 2018-07) 형식으로 입력하세요.'가 있습니다.
- 713·714줄에 입력 칸 라벨과 placeholder가 있습니다.
- 카드 표시(`period()` 180줄, `valueText` 231줄)는 저장값을 문자열 그대로 이어 붙입니다. 그래서 'YYYY'는 'YYYY', 'YYYY-MM'은 'YYYY-MM'으로 이미 그대로 나오고, 표시 쪽은 바꿀 것이 없습니다.
- 정렬 `sortPeriod`(240줄)는 문자열을 그대로 비교해서 섞인 값에서 깨집니다. 예를 들어 `to='2022'`와 `to='2022-06'`이 있으면, 접두어가 짧은 '2022'가 '2022-06'보다 작게 취급되어 2022년 말까지인 항목이 아래로 갑니다. 이 부분은 고쳐야 합니다.
- 끝값(to)은 화면에서 형식 검사를 하지 않습니다. 이번 범위에서는 그대로 두고, 서버 검사에 맡깁니다.

## 3. 구현안 (적용 순서: 테스트 먼저, 그다음 구현)

패치 A — `startMonthOk`가 연도 4자리 또는 연-월을 받습니다. 함수 이름은 테스트 호환을 위해 유지합니다.
```
old:
  // 학력·경력 시작 년-월(YYYY-MM, 1900~2100, 월 01~12) — 서버 HeadText.requireStartMonth 와 같은 규칙
  hc.startMonthOk = function (v) {
    const m = /^(\d{4})-(\d{2})$/.exec(trim(v));
    if (!m) return false;
    const y = Number(m[1]), mo = Number(m[2]);
    return y >= 1900 && y <= 2100 && mo >= 1 && mo <= 12;
  };
new:
  // 학력·경력 시작: 연도(YYYY) 또는 연-월(YYYY-MM), 1900~2100, 월 01~12 (사용자 11-24 — 웹은 둘 다 받고 Word 는 연도만). 서버 HeadText 와 같은 규칙. 시작은 필수라 빈 값은 false.
  hc.startMonthOk = function (v) {
    const m = /^(\d{4})(?:-(\d{2}))?$/.exec(trim(v));
    if (!m) return false;
    const y = Number(m[1]);
    if (y < 1900 || y > 2100) return false;
    if (m[2] === undefined) return true;
    const mo = Number(m[2]);
    return mo >= 1 && mo <= 12;
  };
```

패치 B — 오류 문구(1081줄)

```
new:   setMsg('시작은 연도(예: 2018) 또는 연-월(예: 2018-07)로 입력하세요.', true);
```

패치 C — 입력 칸 라벨과 placeholder(713·714줄)
```
old: '<label class="hc-lab">시작(YYYY-MM, 필수)<input type="text" name="from" maxlength="7" required inputmode="numeric" autocomplete="off" placeholder="2018-07"></label>' +
new: '<label class="hc-lab">시작(연도 또는 연-월, 필수)<input type="text" name="from" maxlength="7" required inputmode="numeric" autocomplete="off" placeholder="2018 또는 2018-07"></label>' +

new: '<label class="hc-lab">끝(연도 또는 연-월, 비우면 현재)<input type="text" name="to" maxlength="7" inputmode="numeric" autocomplete="off" placeholder="2022 또는 2022-06"></label>';
```

placeholder가 길어서 칸 폭에 잘리면 `2018` / `2022`로 줄이세요. 모바일 폭에서 잘리는지는 못 봤습니다. 라벨은 CSS로 한 줄이어야 한다는 제약이 없는 것으로 보고 썼습니다.

패치 D — 섞인 값에서도 정렬이 유지되게(240~243줄). 연도만 있는 값은 끝은 12월, 시작은 1월로 보고 비교합니다. 연도만 있는 끝값은 그 해 말까지로 보는 것이 업무상 자연스럽습니다.
```
old:
  function sortPeriod(list) {   // 최근 것이 위로(끝 연월이 없으면 현재 진행으로 보아 맨 위)
    const key = function (it) { return (trim(it.to) || (trim(it.from) ? '9999-99' : '0000-00')) + '|' + trim(it.from); };
new:
  // 'YYYY' 와 'YYYY-MM' 이 섞여도 비교되게 연-월로 맞춘다(연도만이면 끝은 12월·시작은 01월로 본다).
  function ym(v, endSide) { const s = trim(v); return /^\d{4}$/.test(s) ? s + (endSide ? '-12' : '-01') : s; }
  function sortPeriod(list) {   // 최근 것이 위로(끝 연월이 없으면 현재 진행으로 보아 맨 위)
    const key = function (it) { return (ym(it.to, true) || (trim(it.from) ? '9999-99' : '0000-00')) + '|' + ym(it.from, false); };
```
나머지 줄(`return (list || []).slice().sort(...)`)은 그대로입니다.

## 4. 테스트

깨질 기존 테스트는 `frontend/test/head-card.test.js` 1566~1572줄 한 건입니다. 1568·1569줄은 라벨 문구가, 1571줄은 `'2018'` 기대값이 바뀌어서 깨집니다. 아래로 통째로 교체합니다.
```
test('학력·경력 시작 연도 또는 연-월(사용자 11-24): 입력 칸 안내와 화면 검사', function () {
  const career = hc.valueRowHtml('CAREER', TODAY);
  assert.ok(career.indexOf('시작(연도 또는 연-월, 필수)') >= 0 && /name="from"[^>]*required/.test(career) && career.indexOf('placeholder="2018 또는 2018-07"') >= 0);
  assert.ok(career.indexOf('끝(연도 또는 연-월, 비우면 현재)') >= 0);
  assert.ok(career.indexOf('YYYY-MM') < 0);
  ['2018', ' 2018 ', '2018-07', ' 2018-07 ', '1900', '2100', '1900-01', '2100-12'].forEach(function (v) { assert.strictEqual(hc.startMonthOk(v), true, v); });
  ['', null, '2018-7', '2018-13', '2018-00', '1899', '2101', '1899-12', '18', '18-07', '2018-07-01', '2018.07'].forEach(function (v) { assert.strictEqual(hc.startMonthOk(v), false, String(v)); });
});

test('학력·경력 표시와 정렬(사용자 11-24): YYYY 와 YYYY-MM 이 섞여도 순서가 맞고 저장값 표기 그대로', function () {
  const mk = function (id, value, from, to) { return { item_id: id, head_id: 7, field_cd: 'CAREER', value: value, from: from, to: to, source: SRC, created_by: '1' }; };
  const html = hc.cardHtml(view({ head: { career: [
    mk(1, '가경력', '2010', '2017'),
    mk(2, '나경력', '2018', '2022-06'),
    mk(3, '다경력', '2018-03', '2022'),
    mk(4, '라경력', '2023-01', '')
  ] } }), { today: TODAY });
  const at = function (s) { return html.indexOf(s); };
  // 현재 진행(라경력) > 2022 말(다) > 2022-06(나) > 2017(가)
  assert.ok(at('라경력') >= 0 && at('라경력') < at('다경력') && at('다경력') < at('나경력') && at('나경력') < at('가경력'));
  assert.ok(html.indexOf('2010~2017') >= 0 && html.indexOf('2018~2022-06') >= 0 && html.indexOf('2018-03~2022') >= 0 && html.indexOf('2023-01~현재') >= 0);
});
```
- 카드에서 `view()` 헬퍼의 `head` 병합 방식이 이 형태로 받는지 못 봤습니다. 48줄 부근의 fixture 형태에 맞춰 조정이 필요할 수 있습니다. 이 경우 `career` 키만 바뀌도록 `view({ head: { career: [...] } })`를 기존 사용례(169·178줄)대로 고치세요.
- 기존 시험(46·48·49줄 fixture)은 이미 'YYYY'와 'YYYY-MM'이 섞여 있고, 패치 D가 어긋나게 만들지 않는지 함께 확인하세요.
- 실행: `export PATH="$PATH:/c/dev/node/node-v22.23.4-win-x64"` 다음 `node --test "frontend/test/head-card.test.js"`, 그다음 전체 `node --test "frontend/test/*.test.js"`(313건 기준 + 추가 1건).

## 5. 위험·되돌리는 법
- 서버가 연도만 받는 규칙으로 안 바뀐 상태에서 이 패치를 먼저 적용하면, 화면 검사는 통과하고 서버가 400으로 거절합니다. 서버 변경과 같은 배포로 묶는 것이 안전합니다.
- 오류 문구를 서버가 별도로 내려주면 (예: 'YYYY-MM 형식') 같은 용어로 맞춰야 합니다. 서버 문구는 못 봤습니다.
- 되돌리기는 패치 A~D를 역으로 적용하면 됩니다. 저장 형식이 바뀌지 않고 정렬 키만 바뀌므로 데이터 영향은 없습니다.
