## 2. 요약과 판단 (근거)
- **화면 ID는 새로 안 넣는다. `map_popover`가 이미 `HeadUiIds.SCREENS`에 있다**(HeadUiIds.java:16-17, PrepUiIds에도 있음). 사전준비 [제안 확정]이 이미 쓰는 이름이다(prep.js `ui('map_popover','confirm')`).
- **버튼 ID는 `head_view`를 새로 넣는 것을 권장한다.** `open_card`(head_card 화면)를 쓰면 지도 팝오버 열람과 현황판 카드 열람이 감사 기록에서 구별되지 않는다. 사용자 결정의 목적이 "지도를 훑을 때 쌓이지 않게"이므로, 버튼을 눌러 본 열람을 따로 셀 수 있어야 한다. 서버 변경은 한 단어다. DB 컬럼은 VARCHAR(30)이라 문제없다.
- **결합 방식**: render.js는 headcard.js를 `require`하지 않는다. prep과 같이 **showPopover가 런타임에 `root.headcard.decoratePopover(pop, rec)`를 부르는 방식**이다. index.html은 headcard.js(2235줄)가 render.js(2262줄)보다 먼저 로드되고, 호출 시점에 `root.headcard`를 조회하므로 순서 문제가 없다. node에서 render.js 테스트는 영향이 없고, 버튼 동작은 headcard.js에 가짜 팝오버 객체를 넘겨 테스트한다.
- 서버 모드·로그인·영업 계열·서버 기관 ID 판단은 **`hc.gate(rec, env)`를 그대로 재사용**한다(headcard.js `hc.gate`). `gate`가 빈 문자열이 아니면 버튼을 만들지 않고 기존 "현황판에서 확인" 칩을 그대로 둔다. 정적 모드·비영업·서버에 없는 기관은 모두 이 경로다.
- **캐시 없음.** 결과는 팝오버 DOM에만 있다. 닫거나 다른 기관을 고르면 `showPopover`가 innerHTML을 다시 쓰므로 자동으로 버려진다. 같은 기관에서 다시 누르면 재조회한다.
- 늦게 도착한 응답은 `pop.__hcTok`(decorate마다 증가), 팝오버가 열려 있는지(`display==='block'`), `pop.__hcRec`로 버린다(prep.decoratePopover와 같은 방식).
- 버튼은 로딩 중에 `disabled`를 쓰지 않고 `aria-disabled`와 busy 플래그를 쓴다. disabled를 쓰면 포커스를 잃는다. 결과 영역은 `aria-live="polite"`다. 클릭 핸들러는 `stopPropagation`을 한다. 안 하면 document의 바깥 클릭 핸들러(render.js:1037)가 DOM에서 빠진 대상을 보고 팝오버를 닫는다.

## 5. 위험·되돌리는 법
- `hc.request` 시그니처에 인자 하나(`screen`)를 뒤에 덧붙이는 변경이라 기존 호출은 그대로다.
- 줄끝: 세 파일의 줄끝(CRLF/LF)을 편집 도구가 유지하는지 적용 뒤 `git diff --stat`로 확인한다. 삽입 블록은 기존 파일 줄끝에 맞춰야 한다.
- 서버 한 줄을 안 넣으면 열람은 되지만 감사 기록의 버튼이 `UNKNOWN`/`ui_valid=false`로 남고, 위의 head-card 허용 목록 테스트도 실패한다. 배포 시 서버 JAR이 프런트보다 먼저 올라가야 한다(프런트가 먼저 올라가면 UNKNOWN 기록).
- 결과가 붙어 팝오버가 길어지면 `popFit`이 위로 올린다. `#popover` CSS의 max-height 스크롤과의 상호작용은 눈으로 확인해야 한다.
- 되돌리기: 3-C의 두 줄을 되돌리면 버튼이 사라진다. headcard.js 블록은 남겨도 무해하다. 서버 `head_view`는 남겨도 무해하다.
