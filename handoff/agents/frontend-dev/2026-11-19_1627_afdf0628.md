## 2. 요구 요약과 근거
- 줄 버튼은 아래 칸만 채운다. 저장은 기존 `#hb-a-go` 하나다.
  - 줄에서 바로 저장하지 않는다.
  - 근거: `kbboard.js`의 `submitAdd`, `pickInst`.
- 서버 요청은 0건이다. `ALL`(dash.model 결과)·`gs.sum`·`LOFIN_2026`·`LIST`로 화면에서 계산한다.
- 재사용하는 것은 `defaultTag`·`bankInfo`·`closedBasis`·`takenFor`·`dText`·`yearList`다.
- 새 색·새 `:root` 변수는 없다.
  - CSS는 `var(--line)`·`--panel`·`--fg`·`--muted`·`--line-strong`·`--mono`·`--r`만 쓴다.
  - 현황판 CSS 블록의 '새 변수' 시험(`--rowbg` 3개만 허용, `kbboard-goals.test.js` 645줄·`kbboard-c54.test.js` 327줄)과 hex 없음·글자 11px 이상 시험을 지킨다.

**내가 정한 해석(되돌리기 쉬움, 기획 확인 요청은 6절)**
1. **추천 풀**
   - 공고 중(`m.notice`, phase가 awaiting 아님)과 확정 공고 예정(`m.upcoming`, confidence '확정')만 쓴다. 추정은 뺀다.
   - 예외: phase가 awaiting인 공고 중 기관은 입찰 종료 근거(`closed`)가 있을 때만 풀에 든다. 청주시 같은 '결과 정해진 기관'이 보통 이 상태일 것이라 넣었다.
2. **분류(한 기관은 처음 맞는 단계에 한 번만)**
   - ①-재유치: `defaultTag().tag === 'RETAIN'`
   - ①-되찾기: `kb_now !== 'KB'`이고 `last_kb_year > 0`
   - ②: 기관유형(`dash.kindOfRec`)과 금고 성격(단수/1·2금고)이 모두 알려져 있고 '국민은행이 금고인 기관'에도 있는 조합
   - ③: ①②에 안 든 기관 중 접수 마감 D-n이 있는 것
   - 위에 해당하지 않으면 추천하지 않고 세지도 않는다.
3. **금고 성격 판정**
   - 현재 줄(`lines_now`에서 `term_from`이 오늘 이전이거나 없는 줄)이 없으면 만료되지 않은 행안부 줄을 본다.
   - `FIRST`·`SECOND`가 있으면 '1·2금고', 없고 `SINGLE`이 있으면 '단수 금고', 그 밖은 비교 불가다.
4. **다음 회차 준비 조건**
   - 입찰 종료 근거가 있고, 되찾기 대상이며, `lines_now`에 미래 시작 줄이 있고 그 은행이 국민은행이 아닐 때만이다.
   - 미래 줄이 없으면 '결과를 모른다'로 보고 '올해 입찰이 끝난 곳'에 센다. 결과가 국민은행인 곳도 센다.
5. **연도 규칙**
   - 다음 회차는 `y0+1`이 고를 수 있는 연도(`yearList()`)에 있으면 목표, 없으면 [관심으로 고르기]다.
   - 공고 중은 올해, 확정 예정은 공고 예정일의 연도다. 고를 수 있는 연도 밖이면 관심이다.
   - 관심 기능이 꺼진 서버(`noWatch`)에서 관심이 필요한 줄은 뺀다. 제외 줄에 '관심으로만 고를 수 있는 n곳은 …뺐습니다'로 따로 센다. 디자인 규격은 이를 '올해 입찰 종료'와 합치라고 했지만 뜻이 달라 나눴다.
6. **제외 판정**
   - 이미 목표·관심은 `takenFor(0,'WATCH')`로 구한다. 이 함수는 불러온 연도의 목표 전부와 관심 전부를 돌려준다.
   - 보고 있는 연도가 아닌 해의 목표는 못 걸러진다. 저장할 때 서버의 '이미 있음' 응답이 막는다.

function dueMany(n, extra) {
  const recs = [], notice = [];
  for (let i = 1; i <= n; i += 1) { const r = rec('D' + i, '기관' + i); recs.push(r); notice.push(nIt(r, i)); }
  return { recs: recs, r: kbb.recommend({ notice: notice, upcoming: [] }, base(Object.assign({ list: recs, years: [2026] }, extra || {}))) };
}

- **되돌리기**: 패치 A~G를 되돌리고 새 시험 파일을 지우면 된다. 서버·DB·데이터는 건드리지 않는다. 쓰기 호출이 없다.
- **성능**: 추천은 [추천받기]를 처음 누를 때 한 번 계산한다(`LIST` 전체에 `defaultTag`+`lofinLines`). 창 안에서 캐시된다. 수천 건이어도 한 번이다. 느리면 `refs` 계산만 `gs.sum` 로드 시점으로 옮긴다.
- **'다음 회차 준비'가 비어 보일 위험**: 기준이 '미래 시작 약정 줄이 있고 국민은행이 아님'으로 엄격하다. 입찰 공고 현황만 '종료'이고 새 약정이 039에 아직 안 들어온 기관은 '올해 입찰이 끝난 n곳'으로만 센다. 실제 청주시 자료가 어느 쪽인지는 데이터를 못 봤다.
- **과다 제외**: 올해 종료로 센 기관을 풀에서 빼는 게 spec의 '올해 입찰 종료 제외'와 일치하는지 사용자에게 한 번 보여 줘야 한다.
- **중첩 연도 목표**: 보고 있는 연도의 목표만 제외된다. 다른 해에 이미 목표인 기관은 줄에 나오고 저장할 때 서버가 막는다.
- **접근성**: 패널 안 `role="status"` 문장은 내용을 통째로 갈아 끼우므로 낭독이 안 될 수 있다. 규격과 같다. 실브라우저 낭독 확인은 못 했다.
- **디자인 이력**: 푸시 관문의 `docs/design_history/index.html` 장 60은 이 패치 범위 밖이다. 문안은 design-reviewer 보고서 6절 끝에 있다. 화면(펼친 창 높이·880px 줄 접힘)은 8080 재빌드 뒤 실측해야 한다.
- 다른 세션 구간(`.pt-*`·머리 띠·로그인)은 건드리지 않았다.

## 6. 이관 메모
- [이관: 기획] '다음 회차 준비'에서 입찰 공고 현황 근거만 있고 새 금고 약정이 아직 없는 되찾기 기관을 어떻게 볼지. 지금 구현은 '결과를 모른다 → 제외'이고, 후보는 '종료만 확인되면 모두 포함' — 근거: `recommend`의 종료 분기(미래 시작 줄이 있어야 포함), 지시문 '결과가 국민은행이 아닌 곳'.
- [이관: 기획] ② 이유 문장의 기관 종류가 '구청'이 아니라 '지자체'로 나온다. 종류 값이 6종(지자체·교육청·공공기관·대학·법원·병원)뿐이라서다. '구청·시·군'으로 가르려면 종류 판정 규칙이 필요하다 — 근거: `dash.kindOfRec`, 디자인 규격 5절 ② 이유 예시.
- [이관: 디자인] 관심 기능이 꺼진 서버에서 관심이 필요한 줄을 '이미 목표·관심·종료'와 따로 한 줄('관심으로만 고를 수 있는 n곳은 …뺐습니다')로 세게 했다. 규격의 합산과 다르다 — 근거: 규격 5절 마지막 줄.
- [이관: 데이터] 추천 ①·②·되찾기 판정은 039 요약의 `last_kb_year`·`lines_now`(미래 시작 줄 포함)와 `noticerec.snap`이 실제로 채워져 있어야 쓸모 있다. 예전 국민은행 금고 기록이 비어 있으면 '반입되지 않아 …건너뜁니다' 문장이 뜬다 — 근거: `recommend`의 `noFormer`·`kbN`.
