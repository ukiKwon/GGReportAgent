## 1. 고친 곳
**`frontend/js/kbboard.js`** (줄 번호는 편집 뒤 기준, 다시 grep 하세요)
- **파일 머리 주석(7줄 위)**: 사람별 관심 계약을 한 줄 추가했습니다.
- **탭 이름(약 1063줄)**: 탭 이름을 '내 관심 기관'으로 바꿨습니다. 표 캡션(약 994줄)은 '내 관심 기관 …곳 중 …곳 보임'입니다. 빈 화면 제목(약 1002줄)은 '내 관심 기관이 없습니다'이고, 내 관심은 나만 넣고 뺄 수 있다는 안내를 덧붙였습니다.
- **안내 문구**: `dupText('WATCH')`는 '이미 내 관심 기관으로…', `dupHint('WATCH')`는 '…내 관심 탭에서…'가 됩니다. 검색 결과 표시는 '· 이미 내 관심 기관'입니다.
- **알림 문구**: `flashWatchAdded`·`flashWatchCancelled`·`flashMoved(WATCH)`에 '내'를 붙였습니다.
- **옮기기 확인 창**: 목표→관심은 "내 관심 기관에 들어갑니다 … 팀 이력에 남습니다"로 바꿨습니다. 관심→목표는 "팀의 목표 기관이 되고 내 관심에서는 빠집니다"를 더했습니다.
- **`kbb.outcome` 정리**
  - ALREADY_GOAL 분기를 지웠습니다. 서버가 더 보내지 않습니다. 오더라도 일반 409(stale, 목록 다시 읽기)로 처리됩니다.
  - ALREADY_WATCH는 '내 관심에 이미 있음'으로 바꿨습니다. `op==='move'`이면 "이미 내 관심 기관에 들어 있어 옮길 수 없습니다. 목표는 그대로 두거나, 내 관심에서 먼저 빼 주세요."라고 말합니다.
  - 403 NOT_WATCH_OWNER는 고정 문구 "다른 사람의 관심 기관은 바꿀 수 없습니다. 내 관심 기관만 바꿀 수 있어 목록을 다시 불러왔습니다."와 함께 stale로 처리합니다(목록을 다시 읽습니다).
  - 409 CHANGE_PENDING에는 고정 문구를 넣었습니다. 서버 문구와 같은 뜻입니다.
- **내 관심 빼기 (약 1472줄 근처)**: `kbb.unwatch(id)`를 새로 만들었습니다. `DELETE /institutions/{id}/my-watch`를 부르고, 본문은 없으며 `X-Screen-Id: bid_board`, `X-Button-Id: cancel_bid_target`를 보냅니다. 서버 `WATCH_OFF` 허용값에 이 버튼 이름이 있어 `kbb.BTN`은 그대로 8개입니다.
- **`kbb.unwatchOutcome(x)`**: 200이고 `changed:false`면 nochange로 보고 "이미 내 관심에서 빠져 있는 기관입니다. 목록을 다시 불러왔습니다."라고 알립니다. 200이고 changed가 true면 saved입니다. 그 밖의 응답은 `kbb.outcome`으로 넘깁니다.
- **관심 빼기 흐름(`cancelDialogHtml`·`cancelState`·`openCancel`·`submitCancel`)**: 관심 줄이면 사유 칸 없이 확인만 합니다. 창 제목은 '내 관심에서 빼기'이고, 단추는 처음부터 눌립니다. 저장은 `unwatch`로 합니다. 목표 빼기는 그대로 POST …/cancel에 사유 필수입니다.
- **메뉴 글자(약 2018줄)**: '내 관심에서 빼기…'로 바꿨습니다. `paintCancel`의 단추 글자도 맞췄습니다.
- **`takenFor`**: 넣을 곳이 관심이면 내 관심만, 목표면 그 연도 목표만 '이미'로 칩니다. 서버가 팀 목표와 내 관심이 겹쳐도 막지 않기 때문입니다. 추천 입력은 `'ANY'`(둘 다)로 바꿔 기존 동작을 유지했습니다.

**`frontend/js/tchange.js`**
- `ITEM_MSG.notOwner`와 `alreadyWatch`를 추가했습니다. 일괄 변경의 항목 오류에서 NOT_WATCH_OWNER와 ALREADY_WATCH를 처리하고, NOT_WATCH_OWNER는 목록을 다시 읽게 했습니다.

## 3. 지시에서 벗어난 판단
- 관심 빼기 사유 칸은 없앴지만, 같은 창을 쓰되 관심 줄만 확인 전용으로 분기했습니다. 새 창을 만들지 않았습니다.
- 관심 빼기 응답 200이고 `changed:false`는 오류가 아니라 닫고 목록만 다시 읽도록 했습니다(서버가 멱등이기 때문).
- `kbb.outcome`의 CHANGE_PENDING에 고정 문구를 넣었습니다. 서버 문구가 한글이 아니면 사라지는 일을 막기 위해서이고, 기존 시험 `tchange.test.js:514`는 그대로 통과합니다.
- 알림 띠의 '관심 탭에서 보기' 단추(`seeWatchHtml`)는 시험이 글자 하나까지 고정하고 있어 이번엔 바꾸지 않았습니다. 탭 이름과 불일치하니 나중에 디자이너가 판단하면 됩니다.
- 803ca82c(구분·메모 바로 저장 `valueBody`, 관심 줄은 연도 제외)는 건드리지 않았습니다.
- 목표 기관 쪽과 [목표 기관 +] 신규 규격은 범위 밖이라 손대지 않았습니다.

## 4. 이관 메모와 남은 것
- **[이관: 기획/디자인]** 협약 팝업(`renderOurs`, 약 1621줄)에서 내 관심이 걸린 기관은 mark 때문에 [목표에 넣기]가 숨습니다(`popCanAdd`가 mark가 있으면 숨김). 서버는 이제 목표와 내 관심이 겹쳐도 막지 않으니, 이 숨김을 풀지는 기획 결정이 필요합니다. 이번엔 그대로 뒀습니다. 팝업 칩 글자 '관심'도 '내 관심'으로 바꿀지 같이 정해 주세요.
- **[이관: 개발]**
  - `GET /watchers`의 기관별 관심 있는 사람 이름 표시는 이번에 붙이지 않았습니다. 화면 위치·규격이 정해진 뒤에 하면 됩니다.
  - 지도 ♥(`PUT/DELETE my-watch`, `X-Screen-Id map_popover`)와 `dashboard.js`의 `watch_items` 사용은 다른 작업의 범위라 보지 않았습니다.
  - 현황판의 관심 넣기는 아직 `canEdit`(영업부서)일 때만 보입니다. 서버 ♥는 등록된 활성 사용자면 누구나 되므로, 권한 정책이 바뀌면 화면 조건도 바꿔야 합니다. 서버 권한 결정이라 이관합니다.
- 서버 시험에서 응답 형식을 못 봤습니다. `GET /bid-targets`가 관심 줄에 `can_cancel`을 여전히 주는지는 서버 `list()`를 끝까지 읽지 않았습니다. 실제 화면에서 관심 줄의 [내 관심에서 빼기…] 메뉴가 보이는지 메인이 확인해 주세요.
