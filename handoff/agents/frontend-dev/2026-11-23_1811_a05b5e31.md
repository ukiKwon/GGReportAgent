## 2. 원인·요구 요약과 판단 근거
- 현재 정의는 nav.js:92-96. scan 소제목은 기관·입찰 공고 둘뿐이다.
- 함정 1, 소제목이 통째로 사라진다. nav.js:251의 showSubs는 "보이는 중분류 2개 이상, 각각 2항목 이상"이어야 켜진다. '대시보드' 소제목에는 입찰 현황판 하나뿐이라 영업팀 화면에서도 소제목이 전부 꺼진다. 해결은 scan 분류에만 soloSubs:true를 줘서 한 항목짜리 소제목을 허용하는 것이다.
- 함정 2, 순서가 뒤집힌다. build는 중분류 안에서 live 항목을 soon 항목보다 앞에 둔다. '기관 사업계획'(soon)을 '전국 지역별'(live)보다 앞에 두려면 front:true가 필요하다.
- '공고 자동 수집'은 soon() 7번째 인자 onlyRoles로 ['전산팀','전산팀장']을 준다.
  - 제안팀 구성·배정의 onlyRoles 관례와 같고, nav.roleIn은 마스터면 false라 마스터는 제외된다.
  - 서버 키 AND(withKey)는 걸지 않는다. 지금도 키가 없고 화면은 준비중 안내뿐이다.
  - 결과적으로 영업팀·영업팀장·영업부장·디자이너에게는 숨겨진다. 지금은 영업 계열 일반 규칙으로 보인다. 의도한 변경이다.
- 문구 판단:
  - 메뉴 이름을 가리키는 것은 바꾼다: portal.js:51의 [전국 지도], prep.js:41·44, prepboard.js:32·33, dashboard.js:703·1020·1552, index.html:3020(숨은 탭 버튼 글자), overdue.js·app.js의 사이드바 항목 설명 주석.
  - 지도 자체를 설명하는 문장은 그대로 둔다. 화면은 여전히 지도이기 때문이다. render.js:332·972·994·1140 주석, app.js:745(마스터가 여는 화면 설명), overdue.js:4·145·278(지도 다시 그리기 설명)이 해당한다.
  - 동작 코드(overdue.paintNavBadge)는 id 'map'과 NOTICE_ID로 찾으므로 영향이 없다.
- 요구사항 파악 문서(docs/요구사항 파악/*)는 지난 날짜 파일이라 고치지 않는다. tools/req-review/template.html·stories.json은 이관 메모로 넘긴다.
