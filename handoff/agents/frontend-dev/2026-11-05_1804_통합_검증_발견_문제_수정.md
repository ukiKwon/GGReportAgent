## 3. 지시에서 벗어났거나 내가 판단한 것
- 1번: 글자(예시 값)가 이미 있는 `input:true && mapped:false` 칸은 직접 입력 칸으로 바꾸지 않았다. 기존 양식의 예시 값 칸이 작성 모드에서 갑자기 공란 입력란이 되어 초안에서 지워지는 것을 막으려는 것이다. 새로 넣은 칸은 `text:''`라서 모두 대상이다.
- 1번: 공란 구성 칸이 하나라도 있으면 그 합계 검산 전체를 건너뛴다(공란만 빼고 더하지 않는다). 서버 PART_EMPTY 규칙("빈 칸은 0으로 계산하지 않음")과 맞추기 위해서다.
- 1번: 새 직접 입력 칸도 기존 기관명 칸처럼 '확인' 표시를 해야 전체 검수가 끝난다. 별도 면제는 두지 않았다.
- 2번: "합계 범위에 직접 입력 칸이 있는 합계" 줄은 review 칸만이 아니라 경고를 가진 모든 칸 수를 센다.
- 4번: 이름을 아직 쓰지 않은 새 행(fresh, 글자 없음)은 바깥 병합 이름('은행')을 행 이름으로 빌리지 않고 '' 로 둔다. 그렇지 않으면 손잡이 라벨이 새 행을 '은행' 행이라고 부르게 된다.
- 5번: 열 삭제에도 같은 규칙(colspan 1이고 그 열에서 시작)을 적용했다.
- 6번: 머리 행이 없는 표의 열 삽입도 입력란이 본문 이름 칸이라 "새 열의 행 이름" 문구를 쓴다.

## 4. 남은 위험
1. 새 직접 입력 칸 키를 서버가 받는 전제로 만들었다(지시 근거). 서버가 모르는 키를 400으로 거절하면 초안 요청이 실패한다. 실제 서버로 확인이 필요하다.
2. `labelIn`의 새 분기(`t.rowIds`/`t.colIds` 사용)는 편집 모드 표에만 해당한다. 작성 모드 labeler는 ids를 넘기지 않아 영향이 없다.
3. 브라우저에서 929px 폭의 `#tab-soon` 가로 스크롤 해소는 직접 확인하지 못했다. 소스 검사 테스트만 있다. qa-verifier나 playwright로 확인이 필요하다.
4. `.bd-cell-in`의 min-width 10em으로 행 이름 열이 넓어졌다. 좁은 화면에서 표 가로 스크롤이 늘 수 있고, 시각 확인은 못 했다.
