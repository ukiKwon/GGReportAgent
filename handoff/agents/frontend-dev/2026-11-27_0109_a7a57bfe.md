## 1. 바꾼 곳

`frontend/js/prep.js`만 고쳤다. preptask.js와 preptask.test.js는 건드리지 않았다. 1단계 안내는 endHtml에서 그려서 preptask.js를 고칠 필요가 없었다. 대본 창 코드(SCRIPT_FIELDS·scriptDialogHtml·onScript*)도 건드리지 않았다.

- **안내 문구 (T.startBlocked)**: 문구 사전 `T`의 `closeAsk` 바로 아래(약 86행)에 `startBlocked` 객체를 추가했다. `NOT_GOAL_TARGET`과 `GOAL_CHANGE_PENDING` 두 문구는 지시한 글 그대로다.
- **`prep.startBlockedText(viewer)`**: `isNewStartFlow` 위에 새로 만들었다. `viewer.start_blocked_reason`에 맞는 문구를 돌려주고, 키가 없거나 null이거나 모르는 값이면 ''을 돌려준다. 문구는 사전에서 고정으로 가져오고 서버 값을 화면에 쓰지 않는다.
- **`endHtml`의 CONFIRMED 분기**: `can_start_prep`이 false인 경우 안내 문구를 `(newFlow && prep.startBlockedText(vw)) || 기존 문구`로 정했다.
  - 기존 `.pp-why` span을 그대로 쓰므로 새 CSS는 없고, [담당자 지정] 단추는 나오지 않는다.
  - 사유 코드가 있을 때 사유 문구가 기존 '권한 없음' 문구(`T.startOnlyOwner`)를 대신한다.
  - 사유가 없으면 기존 동작이다.
  - 1단계 '완료 조건' 줄과 `nextLine`은 그대로 뒀다.
- **`prep.modalTouched(m)`**: 새 순수 함수다. 의견을 적었거나 고른 담당자가 열 때의 기본값(`m.selInit`)과 다르면 true를 돌려준다. 담당자 변경 창(`m.change`)은 기존처럼 `assigneeDiff`로 판정한다.
- **`openModal`의 후보 목록 도착 처리**: 기본값(누른 사람) 선택을 정한 직후에 `m.selInit = m.sel.slice()`를 기록한다.
- **`requestClose`**: 기존 판정 두 줄을 `if (prep.modalTouched(m))`로 바꿨다.

## 2. 테스트: `frontend/test/prep.test.js`

`담당자 지정 모달…` 테스트 바로 앞에 2건을 추가했다.
- **`시작 막힘 사유`**: 두 사유 문구와 단추 없음, null·undefined·모르는 코드일 때 기존 문구, `startBlockedText`의 모르는 값 처리를 확인한다.
- **`모달 닫기 확인`**: `modalTouched`가 기본값 그대로·빈 의견·다른 종류 창은 false, 담당자를 더하거나 빼거나 의견을 적으면 true, 개설 신청 창(기본값 없음)에서 고르면 true로 나오는지 확인한다.

## 3. 메인이 확인할 것

- 실행 명령은 `PATH`에 `/c/dev/node/node-v22.23.4-win-x64`를 더한 뒤 `node --test "frontend/test/prep.test.js" "frontend/test/preptask.test.js"`이고, 전체는 `node --test "frontend/test/*.test.js"`다. 새 2건을 포함해 모두 통과해야 한다. 실행은 못 했다.
- 화면에서는 두 가지를 보면 된다.
  - 목표 기관이 아닌 확정 건: 상세 1단계에 안내 한 줄만 나온다.
  - 담당자 지정 창을 열고 기본 선택 그대로 [취소]: 닫기 확인이 뜨지 않는다. 서버 오류만 난 뒤 [취소]해도 같다.
- 후보 목록이 도착하기 전에 닫으면 `selInit`이 아직 없다. 이때는 빈 선택 기준으로 판정하고, 아무것도 안 골랐으므로 묻지 않고 닫힌다.
