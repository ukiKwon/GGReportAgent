## 2. 원인/요구 요약과 서버 키 vs 규격 어긋난 곳
요구는 상세 '현재 금고 은행' 절의 4번째 갈래(직접 입력), 기관 정보 변경 창의 '금고 약정' 묶음, 모든 문자열 escape, 저장·취소 머리글, 409 DUP_RANK·STALE 처리, 현황판 숫자 미섞임입니다. 규격과 서버가 어긋난 곳은 서버를 따랐습니다.

| # | 규격 | 서버(근거) | 이 패치의 선택 |
|---|---|---|---|
| 1 | 지우기 사유 '선택' 자유 입력 | 사유 코드 필수(`BankContractRules.parseCancel` 199줄, BANK_CANCEL_REASON, ETC면 50자 글) | `codes.cancel_reasons` 셀렉트를 필수로 하고, 고르기 전엔 [지우기]를 막습니다. |

| 7 | (규격 없음) 겹침 | `DUP_RANK`와 `confirm_overlap`, `current.lines[].overlap_with`·`overlap_confirmed` | 저장 409면 겹친 줄(`detail.overlaps`)을 보여 주고, [겹침을 알고 저장]이면 `confirm_overlap:true`로 다시 보냅니다. 상세 줄에는 `overlap_with`가 있을 때 주황 글자 `같은 순위 약정과 기간이 겹칩니다`를 붙입니다. |
| 8 | '확인일' 미래 막기 | 서버가 막음, 응답 `today` | 화면은 응답 `today`로 미리 알립니다(서버가 정본). |
| 9 | 서버 오류 때 해당 칸 `aria-invalid` | 오류 문구에 칸 이름이 없음(고정 문구) | 화면 사전 검사 오류만 칸을 표시하고, 서버 오류는 `#ie-bank-err role=alert`에만 냅니다. |
| 10 | 닫기 확인 버튼 | 기존 창 | 기존 [버리고 닫기]·[계속 편집]을 유지하고 변경 목록에 `금고 약정`만 더합니다(디자이너 P2-1 권장안). |

    if (!/^\d{4}(-\d{2}(-\d{2})?)?$/.test(s)) return bc.MSG.term;
    const y = +s.slice(0, 4);
    if (y < 1990 || y > 2100) return bc.MSG.termRange;
    if (s.length >= 7 && (+s.slice(5, 7) < 1 || +s.slice(5, 7) > 12)) return bc.MSG.termNone;
    if (s.length === 10 && !exists(y, +s.slice(5, 7), +s.slice(8, 10))) return bc.MSG.termNone;
    return '';

## 5. 위험·되돌리는 법
- **되돌리기**: `bankcontract.js`와 시험 파일을 지우고, `index.html`의 script 한 줄·CSS 블록, `instedit.js`·`dashboard.js`의 연결 코드를 되돌립니다. 연결 코드는 전부 `c.bank`·`S.bankCtl` 분기 안이라, `bankcontract.js`를 로드하지 않으면 화면은 기존 그대로입니다(`root.bankcontract` 없으면 `BC()`는 null, `instedit`는 묶음을 넣지 않음).
- **위험 1**: ②의 `paneHtml` 문자열 분할을 한 글자라도 틀리면 기존 시험이 깨집니다. 적용 직후 `dashboard.test.js`·`map-detail.test.js`를 먼저 돌리세요.
- **위험 2**: `bankRepaint`가 현황판 상세 전체를 `renderPane()`으로 다시 그립니다. 기록 칸 입력 중에 약정 응답이 도착하면 `renderPane`의 기존 `keep` 로직(`db-rec-` 칸 커서 복원)이 지켜 줍니다. 입력 중 순간 깜박임은 qa가 봐야 합니다.
- **위험 3**: `emp_verified`는 자기신고 사번일 수 있어 표지가 보안 경계가 아닙니다(서버 주석과 같음).
- **위험 4**: `bankKey` 정규화는 최소 규칙입니다(`KB국민은행`↔`국민은행`, `NH농협`). 자유 문자열인 `c.next.now`와는 '다름' 오탐이 날 수 있어 개발 이관 항목입니다.
- **위험 5**: 팝업 [금고 약정 입력]은 팝업을 닫고 변경 창을 엽니다. 변경 창을 닫으면 `opener`가 사라져 포커스가 body로 갈 수 있습니다. 규격 6-1 '닫으면 opener 버튼으로 돌아갑니다'와 어긋나므로 qa가 확인하세요.
- **위험 6**: 같은 기관을 현황판 상세와 지도 팝업이 동시에 열 수 없다는 가정입니다. `bc` 상태는 기관 하나만 쥡니다.

## 7. qa가 볼 확인 절차 (8080, 039 로컬 적용 전제, 열람 위주)
1. 8080을 한 세션만 쓰고, 039 적용 여부는 `GET /institutions/{id}/bank-contracts`가 200인지로 봅니다.
2. 입찰 공고 현황에서 지자체 기관을 고릅니다.
   - 약정이 없으면 기존 '미확인' 갈래와 [금고 약정 입력]이 보이는지 봅니다.
   - 영업팀이 아니면 `금고 약정은 영업팀이 입력합니다.`만 보이는지 봅니다.
3. 쓰기 확인은 사용자 허락 뒤에만 합니다.
   - 변경 창 '금고 약정' 묶음이 운영 상태와 기본 정보 사이에 있는지 확인합니다.
   - 출처 종류를 바꿀 때 링크·번호·부서 칸이 바뀌는지, 필수가 비면 `저장하려면: …`과 비활성 버튼이 나오는지 확인합니다.
   - 1280폭에서 라디오가 줄바꿈되는지, 상세 dd 폭 약 400px 안에서 줄 넘침이 없는지 확인합니다.
4. 지자체와 법원 종류 기관 둘을 비교해 순위 목록(1·2금고 유무)과 회계 칸 노출을 확인합니다.
5. 같은 순위·겹치는 기간을 저장하면 겹침 상자(줄 목록)가 뜨고, 확인하면 저장되며 상세 줄에 주황 `같은 순위 약정과 기간이 겹칩니다`가 뜨는지 봅니다.
6. 두 창에서 같은 줄을 고치고 먼저 저장한 뒤 다른 쪽을 저장하면 STALE 문구가 나오는지 봅니다.
7. 영업팀 일반 사용자로 남이 만든 줄을 [지우기]하면 서버 403 문구가 그대로 보이는지 봅니다.
8. 지우기는 사유를 고르기 전 비활성인지, 지운 뒤 줄이 사라지고 이력에 `지움`이 보이는지 봅니다.
9. 변경 창에서 `<img onerror>` 같은 값을 비고·부서·기타 은행에 넣어도 상세·이력에서 글자로만 나오는지 봅니다(서버가 막으면 문구만 확인).
10. 로그인 확인 전(`emp_verified=false`)으로 저장한 줄에 `(로그인 확인 전)`이 보이는지 봅니다.
11. 현황판 `국민은행이 맡은 기관` 숫자가 직접 입력 전후에 같은지 확인합니다.
12. 지도 팝업의 [금고 약정 입력]이 변경 창을 `focus:'bank'`로 열고, 닫을 때 포커스가 어디로 가는지 확인합니다.
