# req-review 도구를 새 화면에 맞추는 패치안

## 1. 대상·방법·못 본 것

- **대상**: `tools/req-review/` 아래 `capture.mjs`, `stories.mjs`, `stories.json`, `README.md`. `build.mjs`는 선택 패치 1줄입니다.
- **방법**: 코드만 읽고 작성했습니다. `nav.js`, `app.js`, `portal.js`, `kbboard.js`, `dashboard.js`, `overdue.js`, `render.js`, `board*.js`와 `template.html`의 `STEPS`/`SCREEN_INFO`/`ORDER`를 확인했습니다.
- **못 본 것**:
  - Playwright 브라우저가 다른 세션에서 사용 중이라 화면을 직접 열지 못했습니다. 서버도 건드리지 않았습니다.
  - 브라우저는 제가 열지 않았고 다른 세션 것이라 닫지 않았습니다.
  - 아래는 코드에서 추정한 값이라 재실행 때 확인이 필요합니다. 실패하면 `stories.mjs`가 "찾지 못한 요소" 목록으로 알려 주고, 종료 코드는 2입니다.
    - `#hb-goals`의 `aria-busy`가 로딩 뒤 해제되는지
    - 기관 상세 팝업 겉 덮개가 `.dm-ov`/`.modal-overlay`인지
    - `sales.lead`에게 `#hb-add`가 보이는지
    - `#hb-ours .hb-row`가 한 줄 이상 있는지
    - 영업팀장이 어디에서 막히는지는 라이브로 보지 못해 가설입니다(2번 첫 항목).

## 2. 원인 요약 (근거 파일:행, grep 시점 기준)

**첫 화면이 바뀌었습니다.**
- 영업 계열·디자이너·개발부서는 로그인하면 현황판이 아니라 시작화면(포털)으로 들어갑니다.
  - `frontend/js/nav.js` 68행 `HOME_ID='soon:시작화면'`, 73행 `HOME_ROLES`, 142~146행 `homeIdFor`
  - `frontend/js/app.js` 593~604행 `applyHome`
- 마스터는 지도로, 재무(예산팀)는 `이사회 자료 작성`으로 들어갑니다. 시작화면은 메뉴가 아닙니다.
  - `app.js` 736행: `headOnly`는 사이드바에 그리지 않습니다.
  - `app.js` 722행: 상단 고정 탭 `.stab.pin`으로만 엽니다.
- 그래서 `stories.mjs`가 "로그인 직후 #db-chart"를 찾으면 실패합니다. 현황판은 `gotoNav('soon:현황판')`으로 열어야 합니다.

**`#db-chart`, `#db-notice`, `#db-per`, `#db-pane`은 사라진 것이 아닙니다.**
- `soon:입찰 공고 현황`(`NOTICE_ID`, `dashboard.js` 1516~1529행 SKELETON)의 요소입니다.
- 새 `입찰 현황판`은 `kbboard.js`(2539~2548행 SKELETON)로 구성이 완전히 다릅니다.
  - 제목 줄: `#hb-year`, `#hb-ours-btn`, `#hb-add`
  - 요약 띠: `#hb-band`
  - 목표 표: `#hb-goals`, `#hb-tb`, `#hb-ts`

**`map5`의 `#popover`는 없습니다.**
- 지도에서 기관을 누르면 `dash.openDetail`이 상세 팝업(`#dm-box`, `#dm-bar`, `#dm-pane`)을 엽니다(`render.js` 917~920행, `dashboard.js` 1943~1955행).

**이사회 7단계가 전부 실패한 것은 타이밍 문제로 보입니다.**
- 이사회 선택자는 모두 살아 있습니다(`board-material.js` 464행 `#bd-l-newbtn`, 420행 `.bd-l-open`, `board-write.js` 895행 `#bd-writebar`, 897행 `srcopen`, 2425행 `srcclose`).
- 이 계정은 로그인 직후 1.8초 안에 `/menus` 응답이 오지 않으면 `#side-nav`에 `soon:이사회 자료`가 아직 없습니다. 그래서 `gotoNav`가 "못 찾음"으로 판단했습니다.
- 패치: 항목이 나타날 때까지 최대 8초 기다립니다.

**`capture.mjs`의 `login-id` null과 `sales.lead` 메뉴 0개도 같은 계열로 보입니다.**
- `c.nav`는 1.5초만 기다립니다. `#login-id`는 정적 HTML이라 일찍 존재하지만 `app.init`의 클릭 핸들러(`app.js` 1053행)는 스크립트가 다 돈 뒤에야 붙습니다.
- 그 사이에 값을 넣고 클릭하면 아무 일도 일어나지 않아, 사이드바가 아직 빈 채로 목록을 읽게 됩니다.
- 팝업이 가렸다면 DOM 항목 수는 0이 되지 않습니다(`inert`는 DOM을 지우지 않음).
- 이 가설이 틀렸을 때를 대비해 로그인 실패 시 `#login-msg`를 출력하고 한 번 더 시도합니다.
- 로그인 직후 팝업은 `overdue.js`의 `#ov-pop`뿐입니다. 닫기 버튼 id는 `ov-pop-close`(`index.html` 2884행)입니다. 상세 팝업은 `#dm-close`입니다. 그래서 문구가 '닫기'인지가 아니라 id가 `-close`로 끝나는지로 닫도록 바꿨습니다.

**`build.mjs`에는 `designer`가 없습니다.**
- `labels`는 5개 계정뿐입니다(`build.mjs` 20행). 캡처에 더해도 화면에 안 나옵니다. 아래 3-E가 그 한 줄입니다.
- `template.html`의 `ORDER`(395행), `STEPS`(342행), `SCREEN_INFO`(349행)는 이미 `시작화면`을 알고 있습니다.
  - 캡처 index에 `label:'시작화면'`, `cat:'기관·입찰 현황'` 항목이 들어가면 템플릿 쪽 수정 없이 보입니다.
  - 그래서 시작화면 항목에 이 두 값을 넣었습니다.
