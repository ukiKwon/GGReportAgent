# frontend-dev 보고 추가분 (정정 지시서): 머리글 불일치 `label_state`·`review` 칸 반영

> 메인이 frontend-dev 응답을 저장했다(2026-11-02). 본 지시서 `2026-11-02_이사회자료_작성모드_지시서.md`의 ① 구현(`frontend/js/board-write.js`) 위에 얹는다. 미실행.

## 1. 화면 규칙
- **review 칸**: 값은 보이고, 확인 전에는 검수 n/m의 n에 넣지 않음. 요약 줄 "머리글이 달라 확인이 필요한 칸 R". 확인 필요 필터 포함(`needsReview`). 고쳐도 review 유지 — 확인해야만 셈.
- **failed+LABEL_MISMATCH 칸**: 칸 글자 "채우지 않음". 상태 줄·툴팁: "읽지 못함: 표 머리글이 양식과 많이 달라 값을 채우지 않았습니다. 원본 시트를 보고 직접 입력하거나 올바른 엑셀을 다시 올려 주세요." 값을 직접 넣어야 확인 가능.
- **배너**: failed "이 표는 머리글이 양식과 많이 달라 값을 채우지 않았습니다." / "엑셀의 시트와 표가 맞는지 확인하고, 값을 직접 넣거나 올바른 파일을 다시 올려 주세요." partial은 기존 문구.
- **칩**: failed "주의 · 채우지 못함", 남은 칸 수는 partial만. 배너는 확인 뒤에도 유지.
- **요약 줄**: "값 N칸을 채웠습니다. 머리글이 달라 확인이 필요한 칸 R칸, 읽지 못한 칸 F칸."(0 생략). failed 표 칸은 읽지 못함 쪽.
- 칸마다 아이콘은 달지 않음.

## 2. 패치 (`frontend/js/board-write.js`, old → new)
1. `buildState` 표 객체 — old `mapped: !!rt, needsReview: !!(rt && rt.needs_review === true),` → new `mapped: !!rt, needsReview: !!(rt && rt.needs_review === true), labelState: rt ? (rt.label_state === 'failed' ? 'failed' : (rt.needs_review === true ? 'partial' : 'ok')) : 'ok',`
2. `buildState` 칸 status — old `status: rc.status === 'failed' ? 'failed' : 'filled', reason: str(rc.reason),` → new `status: rc.status === 'failed' ? 'failed' : (rc.status === 'review' ? 'review' : 'filled'), reason: str(rc.reason),`
3. `REASON`에 추가: `LABEL_MISMATCH: '표 머리글이 양식과 많이 달라 값을 채우지 않았습니다. 원본 시트를 보고 직접 입력하거나 올바른 엑셀을 다시 올려 주세요.',`
4. `cellInfo` — old `unreadable: unreadable, edited: edited,` → new `unreadable: unreadable, review: c.status === 'review', edited: edited,`
5. `tally` — 초기 객체에 `review: 0`; 루프 `if (c.status === 'failed') y.failed++; else y.filled++;` → `if (c.status === 'failed') y.failed++; else if (c.status === 'review') y.review++; else y.filled++;`
6. `summaryHtml` — old `else if (y.failed > 0) text = '값 ' + y.filled + '칸을 채웠고 ' + y.failed + '칸은 읽지 못했습니다.';` → new
```js
    else if (y.failed > 0 || y.review > 0) {
      text = '값 ' + (y.filled + y.review) + '칸을 채웠습니다.' + (y.review > 0 ? ' 머리글이 달라 확인이 필요한 칸 ' + y.review + '칸' : '') +
        (y.failed > 0 ? (y.review > 0 ? ',' : '') + ' 읽지 못한 칸 ' + y.failed + '칸' : '') + '.';
    }
```
   ('읽지 못한 칸 보기' 버튼 조건 `y.failed > 0` 유지.)
7. `valueCellHtml` — old `let inner = i.unreadable ? '<span class="bd-w-miss">읽지 못함</span>' : esc(c.value);` → new `let inner = i.unreadable ? '<span class="bd-w-miss">' + (c.reason === 'LABEL_MISMATCH' ? '채우지 않음' : '읽지 못함') + '</span>' : esc(c.value);`
8. `cellAria` — old `i.unreadable ? '읽지 못함' : (c.value === '' ? '비어 있음' : c.value)` → new `i.unreadable ? (c.reason === 'LABEL_MISMATCH' ? '채우지 않음' : '읽지 못함') : (c.value === '' ? '비어 있음' : c.value)`
9. `bannerHtml` — 제목·본문을 `t.labelState === 'failed'`로 갈라 1절 문구 사용.
10. `chipsHtml` — old `if (t.needsReview) h += left ? ...` → new `if (t.needsReview) h += t.labelState === 'failed' ? '<span class="bd-w-chip is-warn">' + icon('warn') + '주의 · 채우지 못함</span>' : (left ? ...기존 식... )`
11. `warnItems` — failed 표가 있으면 앞에 `'머리글이 많이 달라 값을 채우지 않은 표가 N개 있습니다(…).'` 항목 추가, 기존 문장은 partial 표만 셈.
12. `infoLines` 중복 제거 — old `c.warns.forEach(function (w) { if (WARN[w]) out.push({ k: 'note', text: WARN[w] }); });` → new `c.warns.forEach(function (w) { if (WARN[w] && !(w === 'LABEL_MISMATCH' && c.reason === 'LABEL_MISMATCH')) out.push({ k: 'note', text: WARN[w] }); });`

## 3. 테스트 (`frontend/test/board-write.test.js`에 이어서)
```js
function respLabel(state) {
  const r = resp(); const t = r.tables[0];
  t.needs_review = true; t.label_state = state;
  t.label_mismatches = [{ code: 'LABEL_MISMATCH', cell: 'B1', expected: '구분', actual: '항목' }];
  t.cells.forEach(function (c) { c.warnings = [{ code: 'LABEL_MISMATCH' }];
    if (state === 'failed') { c.status = 'failed'; c.reason = 'LABEL_MISMATCH'; c.value = ''; c.source.display = ''; c.source.raw = null; }
    else c.status = 'review'; });
  return r;
}
test('partial: review 칸은 값이 보이고 확인 전에는 확인됨으로 세지 않으며 요약에 따로 센다', function () {
  const ws = ws0(respLabel('partial')), y = bw.tally(ws);
  assert.deepStrictEqual([y.m, y.n, y.review, y.filled, y.failed, y.need], [2, 0, 2, 0, 0, 2]);
  assert.ok(bw.summaryHtml(ws).includes('머리글이 달라 확인이 필요한 칸 2칸'));
  assert.strictEqual(bw.findT(ws, 'A').labelState, 'partial');
  assert.strictEqual(bw.tally(bw.toggleCheck(ws, 'A', 'r1c1')).n, 1);
});
test('failed: 모든 칸 비어 채우지 않음, 직접 입력 전에는 확인 불가, 합계 검산 없음, 배너·칩 문구', function () {
  const ws = ws0(respLabel('failed')), t = ws.tables[0];
  assert.strictEqual(bw.toggleCheck(ws, 'A', 'r1c1'), ws);
  assert.ok(bw.valueCellHtml(t, t.cells.r1c1, { fc: {} }).includes('채우지 않음'));
  assert.strictEqual(bw.cellInfo(t, t.cells.r2c1).sumBad, false);
  assert.ok(bw.cardHtml(ws, t, bw.freshUi(), null).includes('이 표는 머리글이 양식과 많이 달라 값을 채우지 않았습니다.'));
  assert.ok(bw.cardHtml(ws, t, bw.freshUi(), null).includes('주의 · 채우지 못함'));
  const lines = bw.infoLines(t, t.cells.r1c1).map(function (x) { return x.text; });
  assert.strictEqual(lines.filter(function (s) { return s.indexOf('머리글') >= 0; }).length, 1);
  assert.ok(bw.summaryHtml(ws).includes('읽지 못한 칸 2칸'));
});
```

## 4. 이관·질문
- 프런트는 응답 `summary` 대신 칸에서 직접 센다. `label_state` 없는 구버전 응답은 `needs_review`만으로 partial.
- failed 표에서 서버가 `source.display`를 비운다는 가정(계약대로면 방어 불필요).
- 열린 질문: failed 안내의 "올바른 엑셀" 표현(권장: 그대로).
