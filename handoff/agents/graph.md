# 에이전트 그래프 (방식 A — 메인이 라우터)

사용자는 **판단 지점(게이트)**에서만 개입한다. 그 사이의 전달·되돌림·재검토는 메인이 이 명세대로 자동으로 돌린다.
에이전트는 서로 직접 부를 수 없다(서브에이전트는 Agent 도구가 없다) — **메인이 보고서의 "이관 메모"를 읽어 다음 노드를 고른다.**
에이전트는 모두 읽기 전용이므로 파일 적용·테스트·커밋은 메인(`apply` 노드)이 한다. 소통 규칙·저장 위치는 `README.md`.

## 노드

| 노드 | 역할 | 하는 일 | 쓰기 |
|---|---|---|---|
| `planner` | 기획 | 범위·용어·선택지·결정 질문 | 없음 |
| `design-reviewer` | 디자인 | 화면 진단·규격·문구 | 없음 |
| `frontend-dev` / `backend-dev` | 구현 설계 | 적용 가능한 패치안 | 없음 |
| `apply` (메인) | 적용 | 패치 적용 + 테스트 실행 | 허용 경로만 |
| `qa-verifier` | 검증 | 독립 검토·회귀·재현 | 없음 |
| `security` | 보안 | 권한·입력·비밀값 | 없음 |
| `data-auditor` | 데이터 | 레코드 값을 원문과 대조 | 없음 |
| `pm` | 진행 | 여러 항목의 순서·배분 | 없음 |
| `cleaner` | 정리 | 정리 후보 목록. 매일 18:00 "마무리"(커밋·푸시)도 이 캐릭터가 한다 | 마무리 때만 |
| `GATE` | 사용자 | 아래 판단 지점에서 질문 | — |

## 대표 흐름

```
F1 화면 변경 : planner → design-reviewer → frontend-dev → apply → qa-verifier ─┬→ (통과) cleaner → 끝
                                                    ▲                           └→ (수정 필요) frontend-dev  ※최대 2바퀴
F2 서버·DB   : planner → backend-dev → security → apply → qa-verifier → cleaner
F3 데이터    : data-auditor → planner(불일치 정리) → GATE(어느 값이 맞나) → apply
F4 여러 항목 : pm(순서·배분) → GATE(우선순위) → 항목별 F1/F2/F3
```

생략 규칙: 한두 줄 수정·오타는 `apply`만. 화면이 안 바뀌면 `design-reviewer` 생략, 입력·권한·비밀값·서버를 건드리지 않으면 `security` 생략(생략 사유를 실행 기록에 한 줄 남긴다).

## 이동 규칙 (메인이 보고서를 읽고 정한다)

- 보고서 끝의 `[이관: 기획|디자인|프런트|백엔드|데이터]` → 해당 노드로. 같은 일을 맡을 에이전트가 이미 있으면 그쪽에 **원문 인용**으로 넘긴다(요약해서 의미가 바뀌지 않게).
- `qa-verifier`·`security`의 발견: **P1/상 이상** → 구현 노드로 되돌림. P2 이하 → 메모만 남기고 진행(사용자에게는 끝에 한 줄).
- 병렬 가능: 서로 독립인 검토(`qa-verifier` ∥ `security`, `design-reviewer` ∥ `data-auditor`).
- 노드가 사용자에게 물을 질문을 남기면 모아서 **한 번에 한 묶음**으로 GATE에 올린다(질문 하나당 한 번씩 끊지 않는다).

## 멈춤 규칙

| 규칙 | 값 | 넘으면 |
|---|---|---|
| 구현↔검증 되돌림 | 같은 작업에서 최대 2바퀴 | GATE: 계속 / 접근 변경 / 중단 |
| 한 작업의 에이전트 호출 총합 | 12회 | GATE |
| 같은 지적이 두 번 반복 | — | GATE (의견 충돌로 취급) |
| 보고서가 근거(파일·줄·출처) 없이 단정 | — | 그 지적은 "추정"으로 낮추고, 결정이 달린 것이면 GATE |

## 판단 지점 (사용자가 하는 일)

- **G1 범위·우선순위** — 무엇을 할지, 무엇을 먼저 할지
- **G2 의견 충돌** — 에이전트끼리 결론이 다를 때, 또는 같은 지적이 반복될 때
- **G3 되돌리기 어려운 행동** — 푸시(자동 마무리 제외), 삭제, DB 변경, 외부 전송, `main` 병합
- **G4 한도 초과** — 되돌림 2바퀴, 호출 12회
- **G5 근거 부족** — 결정에 필요한데 원문·재현이 없는 경우
- **G6 보안 이상** — 상 등급 발견이 남았거나 비밀값이 의심될 때

사용자 승인 없이 자동으로 진행해도 되는 것: 읽기 전용 에이전트 호출, **허용 경로 안**의 패치 적용 + 테스트 통과, 로컬 커밋, 18:00 자동 마무리(아래).

## apply 노드 규칙

1. 패치 대상이 지시한 범위(파일·폴더) 안인지 확인한다. 밖이면 GATE.
2. 적용 뒤 해당 영역의 테스트·구문 검사를 실행한다. 실패하면 출력 전체를 구현 노드에 넘기고 되돌림 1회로 센다.
3. 사용자의 미커밋 변경(`git status`에 내가 만들지 않은 것)은 건드리지 않는다.

## 실행 기록

작업 하나당 `handoff/agents/runs/YYYY-MM-DD_<주제>.md` 한 개: 거친 노드(순서)·되돌림 횟수·GATE에 올린 질문과 답·생략한 노드와 이유. 개별 보고서는 각 에이전트 폴더에 저장하고 이 파일에서 링크한다. 작업이 끝나면 **NEXT.md의 해당 항목에 포인터 한 줄**을 남기고, 남은 일은 `[담당: …]` 태그로 NEXT.md에 올린다(소유자는 NEXT.md 하나, `README.md`의 "NEXT.md와의 관계").

## 정기 노드: 18:00 마무리

`cleaner`(청소부) 캐릭터가 매일 오후 6시에 `CLAUDE.md`의 "마무리" 절차(날짜별 summary·NEXT.md 갱신 → 커밋 → 푸시)를 수행한다. 안전 규칙은 `agent-dashboard/closing.js`에 있다 — 작업 중인 에이전트가 있으면 미룬다, `main`/`master`에서는 푸시하지 않는다, 경로를 지정해 커밋한다, 사용자와 무관한 미추적 폴더(`GGReportAgent/`)는 담지 않는다.
