## 보안 검토: 로컬 Ollama 어댑터와 발표 대본 AI 초안

**판정: 적용해도 됨.** 상·중급 발견은 없습니다. 아래 하급 4건은 이관만 하면 됩니다.

### 1. 대상·방법·못 본 것
- **전제가 다릅니다.** 지시는 "적용 전 설계 단계"였지만 코드는 이미 저장소에 들어와 있습니다. `llm/Ollama*`, `service/ScriptDraft*`, `web/PrepScriptDraftController`, 시험 8개, out-local 견본 키가 모두 있습니다.
- 지금 코드는 설계 보고서 두 개보다 더 나아갔습니다. 칸이 4개에서 2개(intro·effect)로 줄었고, 담당자만 쓸 수 있게 막는 검사(403)·상태 검사(409)·사번별 쿨다운·감시 스레드·보내기 전 감사(`SCRIPT_AI_SEND`)가 더해졌습니다. 이전 security 지적(중-1, 중-2, 하-2~5)도 반영돼 있습니다.
- 그래서 설계안이 아니라 **현재 코드**를 기준으로 봤습니다.
- **못 본 것**:
  - 화면 연결: `frontend/`에 `board-script-draft` 호출이 아직 없습니다.
  - `NoticeBasisSource`(공고 자료) 구현: 구현 빈이 아직 없습니다.
  - Ollama가 실제로 어느 주소에 열려 있는지(OLLAMA_HOST).
  - 실제 `config/` 설정 파일(읽지 않았습니다).

### 2. 점검 항목별 확인 결과
1. **켜짐 조건과 SSRF**: `OllamaGuard.java:56-58`이 JNDI 값이 있거나 MySQL·H2가 아니면 막습니다. prod는 `jndi-name=java:comp/env/...`(`config-envs/prod/application.properties:6`), stg·dev·local은 Oracle이라 모두 INTERNAL_ENV로 막힙니다. 시험도 있습니다(`OllamaGuardTest.java:38-41`).
   - 주소는 `:76-83`이 검사하고, 실제로 부르는 주소는 상수 `127.0.0.1:<port>/api/chat`으로 새로 만듭니다(`:86-87`). 그래서 `127.1`, `0x7f..`, `[::1]`, `nip.io`, userinfo, 경로 같은 변형은 통과하지 못하고, 이름 해석도 타지 않습니다.
   - 리다이렉트·재시도·시스템 프록시는 꺼져 있습니다(`OllamaLlmClient.build`). **우회 경로는 확인되지 않았습니다.**
2. **권한**: 기존 대본 Word 만들기(`PrepController.java:267-286`)는 열람 규칙(404)만 봅니다. 초안 API는 404 → `canViewCase`(403) → `TASK_STATES`(409) → 503 순서로 **더 엄격합니다**(`ScriptDraftService.java:156-167`).
   - 다른 건 자료가 섞이지 않습니다. 모든 읽기가 `p.getBidCaseId()`를 키로 씁니다(`ScriptDraftBasisReader.java:102,110,120,150`).
3. **프롬프트에 들어가는 값과 로그**:
   - 기관장 이름·직함, 주소, org_note, mmda_basis는 읽지 않습니다(`:136`).
   - 값마다 `Pii.scan`·`scanExternal`·7자리 사번 모양 검사를 걸어 걸리면 버립니다(`:224`). 출력에도 같은 검사를 다시 겁니다(`ScriptDraftService.java:232`).
   - 서버 로그에는 모델명·HTTP 상태·ms만, 접근 이력에는 코드와 숫자만 남습니다. `org.apache.http.wire`·`headers`는 모든 환경에서 WARN입니다(out-local `:72-73`).
4. **응답 처리**:
   - 응답 크기 상한 64KB(Guard가 최대 1MB로 제한), 잘린 출력(`done_reason=length`)은 버림, 파싱 실패는 `BAD_OUTPUT`으로 처리합니다.
   - 응답 글은 NFKC 정규화 → 제어·방향 문자 제거 → 12줄·1,000자 상한 → 칸별 허용 숫자 대조를 거칩니다.
   - Word 쪽은 POI `XWPFRun`이 글자를 이스케이프하고(`DocxKit`), AI 글은 사람이 칸에 넣은 뒤 기존 경로로 들어갑니다.
5. **자원**:
   - 서비스 안에서 동시 1건만 받고(나머지는 바로 BUSY) 사번별 60초 쿨다운이 있습니다.
   - 감시 스레드가 connect+read(약 482초)를 넘기면 끊습니다.
   - 서블릿 스레드를 오래 잡는 것은 최대 1개입니다. 쿨다운 키는 자기신고 사번이지만 전역 1건 제한이 있어 스레드 고갈로 이어지지 않습니다.
6. **감사**: BID_PREP_ACT에 DENIED·HIDDEN·BLOCKED·ERROR·OK가 모두 남고, 화면·버튼과 UI_VALID도 함께 남습니다. 확정 이사회 숫자를 보낼 때는 **보내기 전에** BOARD_MATERIAL_ACT를 쓰고, 이 기록이 실패하면 LLM을 부르지 않습니다(`PrepScriptDraftController.java:129-142`). "누가·어느 화면·어느 버튼" 원칙에 맞습니다. 단, 사번·화면·버튼은 자기신고라는 알려진 한계가 그대로 있습니다.
7. **견본 설정**: `config-envs/out-local/application.properties:88-101`에는 enabled=false, 루프백 주소, 모델명, 숫자 설정만 있습니다. **비밀값은 없습니다.**

### 4. 권장 조치 순서
1. 화면을 붙일 때 `textarea.value` 또는 `textContent`만 씁니다.
2. 공고 자료를 구현하기 전에 security 설계 검토를 받습니다. 같은 건만 거르는 조건과, 출력의 URL·다른 기관명 검사를 함께 봅니다.
3. 이 PC의 `OLLAMA_HOST`가 127.0.0.1인지 확인합니다.
4. 사내 AI로 옮길 때 켜짐 판정을 데이터소스 대신 명시적인 환경 키로 바꿀지 다시 봅니다.
