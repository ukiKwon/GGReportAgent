### 판단 요청에 대한 답
1. **교차 서명 R46을 ca_extra에 넣은 위험은 하(수용 가능)이다.**
   - 적용 범위: 컨텍스트는 `HttpClient._contexts[TlsPolicy]`로 정책마다 하나씩 만든다. `load_verify_locations`는 그 컨텍스트에만 추가되므로 R46은 Sectigo 정책 호스트(인제·성동은 같은 정책 객체를 함께 쓰고, 속초는 ciphers가 붙어 별도 컨텍스트)에만 적용된다. 기본 호스트(`tls=None`)의 컨텍스트에는 들어가지 않는다.
   - `VERIFY_X509_PARTIAL_CHAIN`을 끄므로 R46(자체 서명 아님, USERTrust RSA가 발급, 유효기간 2021-03-22~2038-01-18, EKU serverAuth/clientAuth)은 신뢰 앵커가 되지 못한다. 체인은 자체 서명인 USERTrust RSA 루트(시스템 저장소)까지 이어져야 통과한다. 결국 신뢰 범위는 공개 WebPKI(USERTrust)와 같고 새로 늘어나는 신뢰는 없다.
   - 주의 1: 다른 PC(폐쇄망 반입 PC 등)에 USERTrust RSA 루트가 없으면 실패한다(실패하는 쪽이므로 안전하다).
   - 주의 2: Python 3.10 미만에는 `ssl.VERIFY_X509_PARTIAL_CHAIN` 속성이 없어 `build_context`가 AttributeError를 낸다. 실행 Python이 3.10 이상인지는 확인 필요다(동작 오류일 뿐 보안 구멍은 아니다).
2. **SECLEVEL=1의 허용 범위**는 위 표 1행과 같다. 더 좁은 값을 제안한다(`ALLOWED_CIPHERS`의 단일 값을 교체).
   - 서버 DH가 2048비트 이상이면: `ECDHE+AESGCM:ECDHE+CHACHA20:DHE+AESGCM:DHE-RSA-AES256-SHA:DHE-RSA-AES128-SHA` (SECLEVEL 기본값 2 유지)
   - DH가 1024비트일 때만: 같은 목록 뒤에 `:@SECLEVEL=1`
   - 확인 명령(메인 실행):
     - `openssl s_client -connect eminwon.cheongju.go.kr:443 -cipher DHE-RSA-AES256-SHA </dev/null | grep "Server Temp Key"`
     - `python -c "import ssl;c=ssl.create_default_context();c.set_ciphers('DEFAULT:@SECLEVEL=1');print([x['name'] for x in c.get_ciphers()])"`
3. **검증 끄기 경로**: 실질적으로 없다.
   - `get(verify=False)`는 예외를 낸다(`httpclient.py:137`). `tls_verify`가 true가 아니면 로더가 거부한다(`eminwon.py:147`). `ciphers`는 허용 목록과 정확히 일치하는 값만 받고(로더와 build_context 양쪽), `min_tls`는 거부된다.
   - 예외는 `pins`뿐이며 그 경로는 직접 검증으로 대체되어 있다.
   - TLS 예외 호스트는 schemes가 https 하나여야 하고, TlsError·HttpError가 나면 http로 강등하지 않는다(`eminwon.py:248`).
   - collector 전체에서 `_create_unverified_context`나 다른 CERT_NONE 사용은 찾지 못했다.
4. **vaccine 강제**: 의도대로 동작한다.
   - 완화 호스트(ca_extra·ciphers·pins 중 하나라도 있으면)는 도메인과 상관없이 "사용자 확인"이 된다(`privacy.py:62`, `eminwon.py:385`).
   - 그 값이 meta에 기록되고 build.py가 그대로 보존하며, pipeline.py:70이 `!= "생략"`인 첨부를 `vaccine_confirm`에 올린다. E2E 시험은 `test_end_to_end_relaxed_host_forces_vaccine`이다.
   - 기록만 해 둔 서울 3곳(도봉·중구·강남)은 정책이 없어 relaxed가 아니지만, 검증에 실패하므로 수집 자체가 되지 않는다. http 전용 2곳은 scheme 때문에 "사용자 확인"이다.

## 3. 권장 조치 순서
1. **커밋 가능.** 상(차단) 항목이 없다. 이번 변경은 이전 권고(검증 끄기 금지, 호스트 한정 예외, 기록 필드, 강등 금지, 백신 강제)를 충족한다.
2. 가능하면 커밋 전에, 늦어도 다음 작업에서: 위 명령으로 5곳의 DH 크기를 확인하고 ciphers 허용 값을 좁은 목록으로 바꾼다(`ALLOWED_CIPHERS`, json 5곳, test_tls 파라미터).
3. 실행 PC의 Python 3.10 이상 여부를 확인한다(PARTIAL_CHAIN 속성).
4. 선택: ca_extra 검사를 바이트 비교 대신 "issuer 이름이 subject와 같지 않음 + AKI≠SKI"로 보강하고, `tls_verify` 필드를 정리한다.
