**확인 결과 문제 없는 항목**:
- **innerHTML 이스케이프**: innerHTML에 들어가는 서버 문자열을 모두 `logic.esc`(`& < > " '` 다섯 글자 이스케이프)로 감쌌습니다.
  - 해당 값: 기관명, 확정자·담당자·지명자·직위, 의견, 반려·중단 사유(`cancelBanner`), 파일명(표·aria-label·모달 제목), 올린 사람·무효 처리자, `pii_note`, `disabled_reason`·`done_rule`, 선행 과제 이름, 검색어 echo.
  - 속성 값(`data-id`·`data-attach`·`data-req`·`data-task`)도 같은 함수로 이스케이프합니다.
  - 클래스명은 `BADGE_CLS` 등 고정 표에 있는 값만 들어가고, 숫자 값은 `Number()`로 바꿉니다.
- **경로 조각**: 경로 변수(id·cd·attachId·reqId)는 모두 `encodeURIComponent`로 처리합니다. 서버도 `parseId`로 숫자만 받고 `bidCaseId`를 64자로 제한합니다.
- **X-Screen-Id·X-Button-Id**: 모든 호출의 값이 코드에 박힌 상수입니다. 사용된 값은 화면 4종(prep_list·prep_detail·prep_history·map_popover)과 버튼 17종이고, 전부 `PrepUiIds.java:16-21` 허용 목록 안에 있습니다. 목록 밖 값은 서버가 UNKNOWN으로 바꿉니다.
- **내려받기**:
  - fetch로 받아 blob으로 저장하는데, 사번 머리글(`X-Emp-No`)은 같은 출처 요청에 `app.installIdentityHeader` 래퍼가 붙입니다. 상대 경로 `/bidcases/...`는 같은 출처로 판정됩니다.
  - 파일명은 `a.download` 속성으로 넣으므로 HTML로 해석되지 않습니다.
  - 서버 응답은 octet-stream 형식에 `filename*`(UTF-8), `nosniff`, `no-store`를 붙여 보냅니다.
  - 임시 blob URL은 4초 뒤 해제합니다.
- **권한을 서버가 다시 막는지**: 화면에서 버튼을 숨기는 조건마다 서버 검사가 있습니다.
  - 목록 보기(VIEW_ROLES): `PrepService.java:113-115`가 403을 냅니다.
  - 무효 처리(영업팀장이거나, 올린 본인이면서 담당자): `PrepAttachService.java:234-253`
  - 확정본 지정·해제: `PrepService.java:494, 524`
  - 올리기: `PrepAttachService.java:102`
  - 첨부 목록·내려받기: `requireViewer`가 담당자가 아니면 404를 냅니다.
  - 과제 체크, 기획승인 요청, 작성 시작, 중단: `PrepService.java:448, 583, 654, 294`
  - 목록의 `can_view=false` 행을 화면에서 막아도, 서버 상세 조회가 그와 상관없이 404를 냅니다.
- **localStorage·console**: `prep.js`에는 `console.*`과 localStorage 직접 접근이 0건입니다. 세션은 `store.loadSession()`으로 읽기만 합니다. 팝오버 캐시는 사번과 역할 기준이라 계정이 바뀌면 비워집니다(`fetchActives`·`onProfileChange`).
- **지도 팝오버 '원본 정보' 링크**: `render.js:607-608`에서 `^https?://`로 시작하는 값만 `<a>`로 만들고, 그 밖의 값은 글자로만 표시합니다. 그래서 `javascript:`나 `data:` 주소는 링크가 되지 않습니다. 링크에는 `target=_blank`와 `rel="noopener noreferrer"`가 붙고 값은 `esc`로 감쌉니다.
- **알려진 한계**: 사번 머리글(`X-Emp-No`)을 자기신고로 받는 인증 구조는 그대로입니다. 이번 diff가 새로 만든 위험은 아니고, 이미 확정된 전제로 두었습니다.
