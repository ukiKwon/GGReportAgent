## 4. 권장 조치 순서와 패치 후보
1. **1번 직무 분리**. `eligibility`의 ADMIN 분기에서 같은 요청의 앞 단계 `acted_by`가 me면 null을 돌려준다. `decide`에서 `steps`를 넘기면 된다. 예: `if ("ADMIN".equals(step.getKind())) return permissions.canAdmin(me) && !actedEarlier(steps, step, me) ? "SELF" : null;`. 이렇게 하면 다른 관리자(전산팀원)가 ADMIN 단계를 맡는다. 관리자가 전산팀장 한 명뿐이면 막히므로, 이 경우 처리 방식은 기획이 정한다.
2. **2번 격자 변경 이력**. `MenuService.save`에서 바뀐 칸마다 이전값과 새값을 PERM_CHANGE_LOG(또는 별도 ROLE_MENU_LOG)에 같은 트랜잭션으로 남긴다. 최소안은 `MenuController`가 `AccessLogInterceptor.DETAIL`에 "menus changed=N"을 넣는 것이다.
3. **4번 로그**. `ApiExceptionHandler.handleUnexpected`의 `log.error(..., e)`를 클래스명과 가공된 메시지로 줄이거나, 운영 프로파일에서 메시지를 마스킹하는 것을 검토한다. 기존 정책과 함께 결정할 일이다.
4. **5번·6번**. 잠김 판정 규칙을 공통 정적 함수 하나로 모으고, 400 문구에서 원문 대신 "모르는 메뉴/역할"로 고정한다.
