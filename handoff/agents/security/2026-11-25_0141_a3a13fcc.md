**항목별 확인 결과:**
- **이스케이프:** 앞글자 idp는 상수다. 팝업은 `'dm-'`(dashboard.js:1813), 현황판은 `''`(1280)라서 서버 값이 id에 들어가지 않는다. 의견·처리자·날짜·라벨은 모두 `esc()`를 거치고(noticerec.js:216-219, 240-250, 277-281), 팝업 알림 줄은 `textContent`로 쓴다(dashboard.js:1795-1796).
- **저장 권한:** 입력 칸은 `n.canEdit() && !rc.viewOnly()`일 때만 그린다(1329, noticerec.js:286). 버튼 함수도 한 번 더 막는다(1410). 서버도 `requireInstitutionEdit`와 `canJudge`로 403을 낸다(Controller:58-60). 화면에서만 숨기는 구조가 아니다.
- **401/403 문구 위치:** 팝업은 `authErr`로 위쪽 `#dm-err`에 띄우고, 현황판은 기록 절 안 `r.err`에 띄운다(1444-1449). 의도대로다.
- **X-Screen-Id:** `REC_POPUP_SCREEN=false`라 `screenId()`가 undefined를 돌려주고, `nr.save`는 `nr.SCREEN`='bid_notice'를 보낸다(1821, noticerec.js:73). 서버 허용 목록은 bid_notice 하나뿐이다(NoticeUiIds:20). 따라서 감사 기록이 UNKNOWN으로 남지 않는다.
- **초안 공유:** 현황판과 팝업은 `st.drafts`를 같이 쓴다. 사번이 바뀌면 `recGuard`가 초안을 비운다(1298-1305). 팝업이 그려질 때마다 부르는 `dmRecSync`(1833)와 목록 변경 처리 `onRecChange`(1348)에서도 부른다. 화면을 떠나거나 초기화할 때도 비운다(2213, 2252). 다른 사용자에게 남는 경로는 찾지 못했다.
- **오류 본문 노출:** 화면에 내는 것은 서버의 `detail.message`(400·409)와 먼저 기록한 사람 이름(STALE)뿐이다. 둘 다 이스케이프되고, 원래 보여 주려던 업무 문구다. 그 밖의 상태코드는 고정 문구로 바뀐다(noticerec.js:198). 스택이나 원문 본문은 나가지 않는다.
