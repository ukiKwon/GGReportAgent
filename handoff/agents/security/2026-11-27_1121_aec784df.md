## 2. 판정
**① next 규칙 — 이행.**
- 형식 검사는 `router.js:10`. 디코드하지 않으므로 `%`가 든 값은 떨어진다.
- 대응표는 모듈 안의 `Map`에 있다(`router.js:46-49`). `has`가 `typeof string`과 `Map.has`로 검사하므로 `__proto__`가 통과하지 못한다(`:60-62`).
- routeNext는 메모리에만 있고 parse를 통과한 이름만 담는다(`app.js:1217,1349,1374`). location.href나 window.open으로 쓰지 않는다. 주소에 쓰는 곳은 `router.format`(표에 있는 이름만, `:81`)을 거치는 `location.hash`/`replace` 하나뿐이다(`app.js:1231-1235`).
- 권한 없는 화면은 조용히 시작화면으로 보내라는 규칙이 있었는데, 지금은 안내를 띄운다. 3번에서 다룬다.

**② 진입점 — 이행, 예외는 1건(myinfo).**
- 메뉴 화면은 `routeCanOpen`을 거친다. 이 함수는 `findNavItem`(보이는 항목만)을 쓴다(`app.js:1261-1266`). 그다음 `app.openNavItem(id)`로 연다(`:1277`). `admin.showView`나 `tab-btn-*`를 주소에서 직접 부르는 곳은 없다.
- 주소 해석은 세션 확인과 `/menus` 확정 뒤에만 한다: `routeReady`(`:1215,1314,1358`), `applyRoute`의 `settled !== false && loadSession()`(`:1299`), 그리고 `:146`의 menus=null이면 미루는 처리.

**④ 주소 값으로 화면 그리기 — 이행.**
- 주소 조각은 선택자·innerHTML·API 경로 어디에도 가지 않는다.
- 안내는 고정 문자열을 `textContent`로 넣는다(`:720`). 탭 제목은 `document.title`이다.
- 해석에 실패하면 예외 없이 null을 돌려주고 시작화면으로 간다(`router.js:72-79`, `app.js:1360`).
- 이번 범위에는 ID 조각이 없으므로 숫자·ID 형식 검사는 해당 없음.

**⑥ 로그아웃·뒤로 가기 — 대부분 이행.**
- hashchange 처리 첫 줄에서 세션을 다시 확인한다(`:1342`).
- 로그아웃은 `location.replace('#/login')`로 현재 항목을 덮는다(`:1290`, showLogin 뒤에 하므로 되풀이 없음, `:1100-1101`).
- `pageshow`에서 persisted면 onRouteHash를 부른다(`:1379`).
- **미이행: `storage` 이벤트(다른 탭 로그아웃 전파).** 설계 때도 '권장, 기존 문제'로 분류했다. 다른 탭에서 로그아웃해도 이 탭은 주소가 바뀌거나 bfcache로 복원되기 전까지 화면을 계속 보여 준다. 중~하, 기존 문제라 막을 사유는 아니다.

**남은 상·중 위험**: 이번 변경으로 새로 생긴 상 위험은 없다. 기존 위험 R5·R6(자기신고 사번, InstitutionController GET 문지기 없음)은 그대로이고 라우팅과 무관하다(NEXT 35, 백엔드).

**2. F4 myinfo `click()` 예외 — 승인한다. 조건 3가지.**
- (a) `routeCanOpen`의 `s.mode === 'account'` 검사(`app.js:1264`)가 ⚙ 단추가 보이는 조건과 같아야 한다. 둘이 갈라지지 않게 같은 판정 함수를 쓰거나 시험으로 고정할 것.
- (b) `click()` 대상은 상수 `'tab-btn-myinfo'` 하나로 둔다. 주소 값으로 버튼 id를 만들지 않는다. 지금 그렇다.
- (c) 내 정보 화면의 데이터는 서버가 `X-Emp-No`로 본인 것만 주는 전제를 유지한다. 둘러보기 세션이 이 탭을 열어도 노출은 '본인 정보'뿐이라 화면 틀만 열리는 수준이다.
- 이 예외는 ②의 취지(메뉴 숨김 우회 금지)를 해치지 않는다. myinfo는 메뉴 권한 대상이 아니기 때문이다.

**3. 「이 화면을 볼 권한이 없습니다」 안내 — 수용 가능.**
- 화면 이름 목록은 이미 공개 JS(`router.js:14-45`, `nav.js`)에 다 있으므로, 안내로 더 드러나는 정보가 없다.
- 데이터 경계는 서버 문지기다.
- 조건: 안내는 고정 문자열을 `textContent`로만 쓰고, 주소 값을 문구에 넣지 않는다. 지금 그렇다. 내 ①의 '조용히'는 이 조건이면 철회한다.

**4. F1~F3 수정의 새 구멍 — 없음.**
- **F1**: `routeEnter`가 `routeFromHash=false`로 만든다(`:1287`). 그래서 로그인으로 들어올 때는 주소창 값을 읽지 않는다. 둘러보기에서 쓰던 주소가 다음 계정의 목적지로 넘어가지 않는다.
- **F2**: `routeLeft`는 한번 true가 되면 되돌리지 않는다(`:1289,1349`). 이 문서에서 로그아웃한 뒤 들어온 hashchange 주소는 모두 무시한다. 보수적인 방향이라 기능 제약일 뿐 구멍은 아니다.
- **F3**: 세션이 없는데 앱이 보이면 소개를 닫고 `app.logout()`을 부른다(`:1344`). 세션이 없으므로 `/auth/logout` 호출은 건너뛴다(`:1089`). showLogin이 먼저 돌므로 replace로 다시 들어온 hashchange는 로그인이 보이는 분기를 탄다. 되풀이 없음.
- 덧붙여 routeNext에는 표에 있는 이름만 들어간다. 그 값도 로그인 뒤 `routeCanOpen`을 다시 거친다. 바깥 링크가 `#/admin/users`를 심어도 권한 있는 사람에게만 열린다.

**5. 결론: 커밋해도 된다. 막을 것은 없다.** 커밋 뒤 후속으로 둘 것은 아래 4절에 적었다.
