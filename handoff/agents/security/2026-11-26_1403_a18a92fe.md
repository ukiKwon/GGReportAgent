## 3. 앞선 설계 검토의 '적용 전 필수' 반영 여부
- **(1) 뒤 화면 막기와 포커스**: 반영됨.
  - 세션이 없는 분기에서 `app.init`이 `setBehindInert(true)`로 header와 #shell을 막는다(app.js:1199).
  - landing.js의 `setBehind`(296-300)와 `afterDom`(387)이 `#login-view`를 inert로 막는다. landing.js가 먼저 읽혀 DOMContentLoaded 리스너가 app.init보다 앞서 등록되기 때문이다.
  - init 분기에서는 login-id로 포커스를 옮기지 않는다. goLogin(318-326)은 랜딩을 닫고 inert를 푼 다음에 login-id로 포커스를 준다.
  - 랜딩(z-index 110)이 로그인 화면(100) 위에 덮인다.
  - 남은 것은 위 표의 히어로 타이머 하나다.
- **(2) 세션이 없을 때만 띄우기, 닫을 때 정리**: 반영됨.
  - `hasSession`(34-39)이 store와 같은 키·판정을 쓰고, 테스트가 이를 대조한다.
  - `stopMotion`(279-293)이 관찰자, visibilitychange·scroll·resize 리스너, 타이머, rAF를 모두 정리한다.
  - 로그인 화면이 다른 경로로 숨겨져도 MutationObserver가 랜딩을 닫는다(396).
- **(3) 캡처 기준**: 실제 화면 캡처는 아직 넣지 않았다. 자리 표시에 "개인정보를 가린 캡처로 넣을 자리"라고만 적혀 있다. 그래서 이번 범위에서 할 일은 없고, 캡처를 넣을 때 기준을 적용한다.
- **입력 처리(F)**: landing.js에 innerHTML·eval이 없고 사용자 입력도 없다. 저장소는 세션을 읽기만 한다. 선택자에 들어가는 값은 고정 TIMELINES 토큰뿐이다. 문제없다.
