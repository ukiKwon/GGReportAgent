**3. 설계에 반드시 넣을 조건(권장 순서)**
1. 업로드는 `AdminGuard.require`로만 받는다. 조회 GET 전부에 `guard.require(req, <사업계획 메뉴키>)`를 건다(화면 숨김만으로 막지 않는다).
2. 상한을 둔다. 파일 ≤5MB(HeadPhotoService.java:63,92,105와 같은 이중 검사), 행 ≤5,000, 칸 길이 상한(내용 4,000자 등), 따옴표가 닫히지 않으면 400. 확장자는 .csv, 파일명은 정규식 `^[A-Za-z0-9_-]+_\d{8}_plan\.csv$`로 검사한다. 원래 파일명은 저장하지 않는다(HeadPhotoService.java:95 선례).
3. 인코딩은 엄격 UTF-8만 받고, 실패하면 400으로 거부한다(cp949 폴백 금지). NUL·제어문자·U+202E 같은 서식문자가 든 칸도 거부한다.
4. URL은 서버에서 InstitutionEditRules.url()(268행)을 재사용하거나 공용으로 끌어올려 검증한다. 화면은 logic.safeHttpUrl(logic.js:238)이 통과한 값만 href로 쓰고, `rel="noopener noreferrer" target="_blank"`를 붙인다.
5. 내용·사업명은 서버가 원문 그대로 저장한다. 화면은 항상 esc()로 이스케이프하고 innerHTML 직삽입을 금지한다. 줄바꿈은 CSS(pre-line)로 처리한다.
6. 수식 주입 방어는 두 겹이다. ⓐ반입 때 `= + - @ \t \r`로 시작하는 텍스트 칸은 거부하거나 경고한다(예산은 숫자+단위 칸이라 따로 검증). ⓑ모든 CSV 내려받기는 admin.csvCell(admin.js:232) 규칙을 쓴다. 공용화가 필요하다.
7. 판 보관: 새 판은 INSERT만 하고 UPDATE·DELETE는 하지 않는다. 판 행에 반입자 사번·시각·원본 SHA-256·행 수·manifest 배치 id를 남긴다. 감사 기록은 화면/버튼을 서버 고정값으로 남긴다(InstUiIds.java:13-20처럼 헤더로 받지 않는 `plan_import`/`plan_upload`). 실패한 반입(400)도 DENIED/FAIL로 접근 이력에 남긴다.
8. "출처 URL 없음" 예외는 CSV 값으로 열지 않는다. 25구 시드 경로(서버 고정 원천종류 `seed_txt` 또는 별도 플래그)에만 허용하고, 바깥 반입에서는 URL 필수를 유지한다.
9. 전체를 한 트랜잭션으로 처리한다(선례 InstitutionCommandService.java:132). 기관ID는 DB 존재 확인, 사업번호·상위번호는 정규식(InstitutionEditRules.java:24 NO 패턴)으로 검증한다. 오류 메시지에는 행 번호만 넣고 칸 원문은 넣지 않는다(로그 주입 방지).
