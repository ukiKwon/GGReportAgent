## 3. 권장 조치 순서

**구현 전에 반드시 바꿀 것(차단)**
1. **B1**: 생성기 `validUrl`을 서버 `url()`과 같은 글자 기준으로 맞춘다. 패치 후보: `/^[\x21-\x7e]+$/`를 먼저 걸고 `" < > \ { } | ^ \``를 거부한다. 시험 ⑥에 `"`·`<` 거부 사례를 추가한다.
2. **B2**: 출처 없는 `confirmed:true`는 경고 대신 `ceConfirmed=0`(추정)으로 내린다. 또는 `--check`가 실패하게 해서 data-auditor가 출처를 채운 뒤에만 생성되게 한다.
3. **B3**: 반입 경로(CSV·inbox)가 값을 바꾸면 INST_EDIT_LOG에 칸별 1행을 남긴다. SCREEN_ID는 `csv_import`·`inbox_apply` 같은 고정값으로 하고, 최소한 CONTRACT_END와 확정 강등은 남긴다. 그게 안 되면 설계·주석의 "이력 없는 변경 없음" 문구를 고치고 NEXT 항목으로 결정을 남긴다.

**구현 뒤 확인할 것**
4. **L1**: 상태를 바꾸지 않는 저장에서 출처 둘 다를 비우는 것을 거부한다(400). 그리고 시험에 한 줄 추가한다.
5. **L5**: `contract_end_confirmed:"yes"` / `contract_end:123` PUT의 응답 본문에 클래스명·파서 메시지가 없는지 MockMvc로 단언한다.
6. **L2**: 패치 후보로 `url()`에서 `Character.getType(c)==Character.FORMAT`를 거부한다.
7. **L3**: 패치 후보로 update용 `selectByIdForUpdate`(`FOR UPDATE`)를 둔다. 선택 사항이다.
8. **배포 순서**: 운영에서는 030 → 031을 사용자에게 화면을 열기 전 같은 배포 창에서 적용한다(DBA 메모). INST_EDIT_LOG 앱 계정 권한은 SELECT·INSERT만 준다.
