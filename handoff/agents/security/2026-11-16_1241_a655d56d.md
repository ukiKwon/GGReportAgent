- 망 안의 아무 단말이나, 외부 agent가 인증 없이 이 주소에 닿을 수 있다.

### 3. 권장 조치 순서
1. **상태 검사(①, ③)는 인증 결정을 기다리지 말고 지금 고친다.**
   - 패치 후보: 매퍼에 `findActiveById`를 새로 둔다. 내용은 `SELECT * FROM TSKGIAF01 WHERE 업로드파일일련번호=#{id} AND <include refid="처리중"/>`이다. 상세 두 곳과 다운로드가 이것을 쓴다. 목록과 같은 SQL 조각을 쓰므로 기준이 하나로 모인다.
   - 대안: 컨트롤러에서 `REJECTED`·`DELETED`면 404를 반환한다.
2. **404 문구를 하나로 고정한다(④).**
   - 패치 후보: 원인과 상관없이 `{"error":"찾을 수 없습니다."}` 하나만 쓴다. id와 파일명은 응답에 싣지 않고, 원인은 서버 로그에만 id와 함께 남긴다.
3. **예외를 숨긴다(⑤).**
   - 패치 후보: 읽기·파싱을 try/catch로 감싼다. 실패하면 `log.warn("산출물 읽기 실패: id={}", id, e)`를 남기고 500 `{"error":"산출물 읽기 실패"}`를 돌려준다(이미 반영된 download N2와 같은 방식). `parsed`가 객체가 아니면 같은 500으로 처리한다.
4. **테스트를 붙인다.** 03·04 상태 행에 대해 상세 두 곳과 다운로드가 404를 내는지 MockMvc로 확인한다.
5. **인증(②)은 문의 03-4ⓒ 대기 항목으로 둔다.** 다만 대기하는 동안의 위험을 NEXT 87에 함께 적는다: 무인증이고 id를 차례로 넣어 볼 수 있다는 점. 임시 완화책도 결정 후보로 올린다: 호출 agent의 IP 허용 목록, 또는 공유 토큰 헤더. 저장형 본문 제공(NEXT 87, security 11-16 요구 3·4)을 열기 전에 이 결정이 먼저 있어야 한다. 저장형이 생기면 같은 무인증 경로로 노출되는 본문이 더 늘어난다.

### 4. 이관 메모
- [이관: 백엔드] 상세 두 곳과 다운로드에 03·04 상태 검사를 넣는다(`findActiveById` 권장). 404 문구를 하나로 고정하고, IO와 형변환 예외는 로그만 남기고 고정 500을 돌려준다. MockMvc 테스트도 붙인다. 기다리는 것은 없다(바로 착수 가능). 근거는 RfpApiController.java:85–104, ProposalApiController.java:75–95, FileSearchApiController.java:59, UploadedFileMapper.xml:165–167·293.
