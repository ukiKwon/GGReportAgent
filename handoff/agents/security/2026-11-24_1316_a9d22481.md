## 3. 'security에 넘길 것' 5개에 대한 답
1. **ReDoS·우회**
   - ReDoS 위험은 낮다. 입력이 칸당 300·200자이고 설계 패턴에 중첩 반복이 없다.
   - 우회는 실제로 된다(중3). 대응은 셋이다.
     - 전화·이메일·주민번호·카드는 새로 만들지 말고 `Pii.scanExternal(text, 파일 공용 마감)`을 쓴다. 시간 초과는 거부로 처리한다(`PlanCollectService.reason()` 853행 선례).
     - 나이·생년만 새로 만들되, NFKC와 비ASCII 숫자를 ASCII로 접은 사본에 검사한다. 저장은 원문으로 한다.
     - 대상 칸은 제목·요약·언론사.
2. **폴더 읽기 방어**
   - `readSafe`(251-287행)는 이름과 무관하게 같은 방어를 한다: 링크·폴더 거부, 실제 경로의 부모가 root인지, 대소문자 무시 이름 비교, 크기 재검사. 그래서 `_news`에도 그대로 적용된다.
   - `_plan.csv`와 `_news.csv`는 길이가 같아 `dateOf`·`idOf`(305-306행)가 맞는다.
   - 두 정규식은 끝부분이 달라 서로 겹치지 않는다. 대소문자를 무시해도 `plan`≠`news`라 종류가 바뀌지 않는다.
   - **조건 하나**: 종류는 서버에서 "어느 정규식이 맞았나"로만 정한다. 요청 칸이나 응답의 `kind`를 되받아 쓰지 않는다.
3. **감사 원칙**
   - `PlanAudit.record`(26-32행)는 SHA 형식 검사만 하고 본문·URL·파일 이름 칸이 아예 없다. 원칙은 지켜진다.
   - 남는 문제는 행위 코드가 정확한가다(하1, 하3, 중2-ⓑ).
4. **403 경로와 자기신고 한계**
   - 관리자가 아니면 403, 사번이 없으면 401이 난다. 접근 이력 DENIED는 `AdminGuard`가 남기고, 감사 DENIED는 컨트롤러의 `requireAdmin` 패턴이 남긴다.
   - 뉴스 반입도 같은 패턴을 쓰되 `action`은 `NEWS_IMPORT`로 넘긴다.
   - `IMPORTED_VERIFIED`는 `actor.isVerified()`를 그대로 저장한다. 화면에 "확인된 사용자"로 표시하지 않는다.
5. **XSS**
   - 서버는 문자열을 그대로 준다. 제어·서식 문자는 이미 거부되지만 `<`·`"`는 허용된다.
   - 프런트는 `plans.js` 선례대로 한다: `esc()` 뒤에만 줄바꿈 처리(또는 `textContent`+`white-space:pre-line`), 링크는 `logic.safeHttpUrl`, `target="_blank" rel="noopener noreferrer"`.

**uploader 정규식 확장 `(plan|news)`**: 문제없다.
- Java `matches()`는 전체 일치를 보고, `\d`는 ASCII만 받아 서버와 같다.
- 임시 파일 `.plan-upload-*.tmp`는 두 정규식 어디에도 맞지 않는다.
- `existsIgnoreCase`는 끝부분까지 포함한 전체 이름으로 비교하므로 종류가 섞이지 않는다.
- 조건: 머리행 집합(HEADERS·REQUIRED)은 같은 matcher의 `group(3)`으로만 고른다.
- 확인 필요: 한 번에 100파일이면 요청 하나가 최대 500MB가 될 수 있다. uploader의 multipart 요청 상한 설정이 이를 막는지 봐야 한다. 설정 값은 읽지 않았다.

## 4. 꼭 고칠 것의 패치 후보 (한 줄씩)
- **중1**: `BoardWriteLimitFilter` 63행 정규식을 `(?:^|/)institutions/+[^/]+/+(?:plans|news)/+import/*$`로 넓히거나 `NEWS_IMPORT`를 따로 두고, 124행 `plan` 판정에 더한다(테스트: news/import 6MB Content-Length → 413).
- **중2**: `onImported`를 다시 쓰지 말고 `onNewsImported(instId, newsImportId, actor, ui)`를 새로 만든다.
  - 동작: `APPLIED`로 닫되 `APPLIED_IMPORT_ID`는 NULL로 둔다.
  - 구분: 060에 `APPLIED_NEWS_ID` 칸을 더하거나, DDL 없이 하려면 `CLOSE_REASON='NEWS'` 고정 코드를 쓴다.
  - 감사는 `COLLECT_APPLY` / OUTCOME `NEWS`, 쪽지는 "관련 뉴스로 대체" 문구로 한다.
- **중3**: `NewsCsv`의 연락처 검사는 `Pii.scanExternal(t, deadline)`(빈 결과가 아니거나 시간 초과면 거부)로 바꾼다. 나이·생년은 NFKC로 접은 사본에 아래 패턴을 쓴다. 오탐은 `NewsCsvTest`(설계 테스트 5번)에 `21세기`·`2026년 생활임금`·`3세대`·`세입`을 넣어 고정한다(패턴 효과는 추정).
  - 나이: `(?<![0-9])[0-9]{1,3}\s?(?:세|살)(?![기대입출금수계부무외목율액법정])`
  - 생년: `(?<![0-9])(?:[0-9]{2}|[0-9]{4})년(?:생(?!활)|\s?출생)`
  - 괄호 나이: `[가-힣]\s?\(\s?[1-9][0-9]\s?\)`
- **하1·하2·하3**: `PlanInboxService.failed()`가 종류별 action(`IMPORT`/`NEWS_IMPORT`)을 받게 하고, 뉴스 서비스는 `InstitutionPlanService.MSG_SAME`·`MSG_OLDER` 상수를 그대로 쓴다. 060 머리글에 "`INST_PLAN_ACT.IMPORT_ID`는 `ACTION_CD`가 `NEWS_*`이면 `INST_NEWS_IMPORT`를 가리킨다"를 적는다.
- **하5**: 뉴스는 `PlanCsv.header()`처럼 이름 매핑(순서 자유)으로 하고, SCHEMA 표의 "순서 고정"을 "열 이름 고정"으로 고친다. 또는 예시를 표 순서로 맞춘다. uploader 사본도 같은 규칙으로 맞춘다.
- **하6**: `NewsCsv.parse`에서 머리행 검사 직후 `recs.size() > 11`이면 바로 400을 낸다. 행 검사 전이다.
- **하4**(기존): `PLAN_COLLECT` 패턴(69행)에 `inbox/+import`를 더해 `COPY_MAX`로 묶는다.
