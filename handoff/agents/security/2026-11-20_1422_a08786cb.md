## 3. 구현 전에 반드시 바꿀 것

**B1. EDIT_MASK_REMOVED를 서버 설계에 넣는다(F1·F2·F8). 저장 전과 저장 후 모두.**
- **저장 전(MinutesParse)**
  - 대체·가림 루프에서, 고친 seq마다 기준값을 만든다. 기준값은 `maskCount(별도세션.mask(원문 u.body))`이다.
  - 별도 세션은 `masker.newSession(terms, release, 같은 budget)`으로 만들고 **버린다**. 본 세션을 쓰면 카운터와 해제 검증이 틀어진다.
  - 가림은 줄 단위로 결정적이므로, 이 기준값은 미리보기에 보인 '가린 원래 글'과 같다.
  - 지금은 `prepareEdits`가 세션 생성 전에 불리므로 순서를 옮겨야 한다.
- **비교 대상**: 고친 글을 **정규화한 뒤, 가리기 전에** 센다. 다시 가린 뒤에 세면 "`[이름]`을 지우고 다른 자리에 직원 이름을 적는" 경우가 통과한다. 화면의 `mn.lostMasks`와도 기준이 같아진다.
- **비교 방식**: 종류별(`[이름]`, `[가림]`, `[가림: 개인정보 의심 줄]`)로 고친 글의 개수가 기준보다 적으면 422로 거부한다.
- **저장 후(editText)**: 잠금 뒤 읽은 `old`(`Service:931-935`, 저장된 본문 = 가린 글)를 기준으로 `clean`과 비교한다. `editText`는 UTTER와 ITEM이 함께 쓰므로 **요약 항목(PUT items)에도 같이 건다.** 저장 후 경로는 추가로 가릴 단어가 없어 이 검사가 유일한 방어선이다.
- **응답**: `422 EDIT_MASK_REMOVED`, `slot=edit`, `target_no=seq`, `kinds{name|pii|line: 빠진 수}`, 고정 문구만 싣는다. 원래 가렸던 문자열이나 고친 글은 싣지 않는다(R6).
- **시험**: 아래 세 경우가 422인지 확인한다. 별도 세션 사용으로 `masked` 건수와 `name_candidates`가 바뀌지 않는지도 확인한다.
  - `[이름] 위원장` → `박외부 위원장`
  - `[가림: 개인정보 의심 줄]` → 고쳐 쓴 줄
  - `[이름]` 2개 → 1개
- **한계(F3)**: 토큰을 옮기는 우회는 막지 못한다. 이것은 문서로 남긴다.
- **저장 전 '가림'과 저장 후 '거부'가 다른 것(설계 5-2)은 타당하다.** 저장 전에는 추가 가림 단어까지 포함한 같은 세션으로 다시 가리고, c)에 따라 다시 미리보기에서 결과를 확인한 뒤 저장한다. 저장 후에는 그 단어 목록이 없으니 거부하는 것이 맞다.

**B2. R14 예외를 쓰는 조건을 설계·규격에 '유지 조건'으로 명시한다(F5).** 현 설계는 이미 대부분 지킨다. 새로 만들 것은 없고, 앞으로 이 조건이 깨지지 않도록 문구로 고정하는 것이다.
- 라벨은 상세·원문·미리보기 응답에만 싣는다. 목록 API, 020 탭 머리·건수, ACT·ACCESS_LOG detail, 오류 응답에는 싣지 않는다. 접근 이력에는 건수만 남긴다(설계 그대로).
- 라벨로 여러 회의록을 가로질러 검색·필터·모아 보기 하는 기능을 두지 않는다. 그런 기능을 더하려면 security 검토를 다시 거친다.
- 화면에는 늘 '참석자 N'을 함께 보이고, 라벨은 올린 사람이 붙인 이름표라는 점을 드러낸다(디자인 6-2·문구 원칙 그대로). 자유 입력과 datalist는 없다(main 결정 a).
- 감사: 저장 후 라벨을 바꾸면 REV(이전→이후), LOG EDIT, ACT EDIT_LABEL이 남는다(설계 그대로). 업로드 때 붙인 라벨은 LOG UPLOAD에 남은 행위자로 추적한다.
- 공개범위는 따로 보완하지 않아도 된다. 라벨이 열람 대상을 넓히지 않기 때문이다.

## 4. 뒤로 미뤄도 될 것
- **D1(F4, 운영 켜기 전 결정 필요)**: 은행 직책 라벨. security 권장은 은행 쪽을 '은행 측 N'(필요하면 '은행 담당자')으로만 두고 영업부장·영업팀장·지점장·본부장·행장을 빼는 것이다. 바꿀 것은 서버 목록 한 줄이다. 이미 붙은 라벨은 PUT speakers로 고칠 수 있으므로 되돌리기 쉽다. 사용자 결정이 필요하다(아래 이관).
- **D2(F6)**: `readUpload`에서는 edits·options를 문자열로만 들고 있고, Jackson 파싱은 `requireUploader` 뒤로 옮긴다. 그러면 자격 없는 사람의 요청이 감사에 DENIED로 남는다.
- **D3(F7)**: Jackson 실제 버전을 확인하고, 반입할 때 2.15 이상으로 올릴지는 NEXT 48 ④(Spring Boot CVE)와 묶어서 판단한다.
- **D4(F9, 선택)**: 업로드 응답과 LOG에 고친 발언 번호를 남기고 싶으면, 텍스트 없이 대상 번호만 담은 LOG 줄을 쓴다. 예: `UPLOAD_EDIT` + target seq. 원래 글을 REV로 남기는 것은 REV PK 구조를 바꿔야 하고 이득이 작아 권장하지 않는다.
- **D5**: R23 표지 문구에 "발화자 이름표는 올린 사람이 붙인 것이며 틀릴 수 있음"을 덧붙인다. 라벨을 잘못 붙였을 때 생기는 문제를 줄이려는 것이다.
- **D6(F10)**: 058 번호와 test properties 34행은 다른 세션과 겹치지 않는지 적용 직전에 확인한다.
