## 3. 권장 조치 순서
1. **S1 (적용 전 필수)**: `classify`와 INVALID message에서 `e.getMessage()`를 쓴다. 시험 3·5·6이 회귀 근거가 된다.
2. S7: LEAD_ONLY일 때 접근 이력에 고정 사유 문자열이 남게 한다. 한 줄 수정이라 S1과 함께 고친다.
3. **설정 키를 켜기 전 조건 (S2·S3·S4)**:
   - 반입 전용 폴더 ACL: uploader 서비스 계정만 쓰기, 웹 서비스 계정은 읽기만.
   - uploader는 같은 이름을 거부한다(시각을 붙이지 않는다).
   - 업로드할 때 SHA-256과 올린 사람 사번을 uploader DB에 남긴다. 그러면 웹 감사의 `FILE_SHA256`과 이어 볼 수 있다.
   - 열거 상한과 읽기 상한을 나눈다. 이름 열거는 싸므로 상한을 크게 하고 읽기만 예산으로 막는다.
   - GET에 시간 상한(남은 파일은 NOT_CHECKED)과 동시 실행 1건(tryAcquire하고 안 되면 409)을 둔다.
   - `codes()`는 확인 한 번에 한 번만 부른다.
4. S11: 운영·스테이징 DB에 033이 적용됐는지 확인한다.
5. **C로 넘어가기 전 (S5)**:
   - 예약 사번은 `Actor.of`(헤더와 principal 모두)에서 거부한다.
   - 시스템 주체는 서버 안에서만 만드는 전용 생성자로 만든다.
   - 권한관리 API가 예약 사번을 수정하지 못하게 막는다.
6. S8·S9·S10·S12: SCHEMA ⑪-5 문서화, 감사 화면 이름표, 노드 하나에서만 켜는 설정을 문서로 정리한다.
