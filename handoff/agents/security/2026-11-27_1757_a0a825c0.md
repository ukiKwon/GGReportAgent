## 3. 권장 조치 순서 (패치 조정안, 각 한 줄)
1. **C1**: `setBoardNa`/`clearBoardNa`는 관문 다음에 `IN_PROGRESS`만 허용합니다(그 밖은 409 `STATE_CHANGED` 또는 새 코드 `PLAN_IN_FLIGHT`). view의 `can_set`/`can_clear`도 같은 조건으로 맞춥니다. claimPlan의 전이 UPDATE가 같은 BID_PREP 행을 잠가 경합도 막힙니다.
2. **C2**: `PrepWriteGate.lockForAssigneeWrite` 맨 앞(잠금 전, DB 접근 없음)에 `PrepBoardService.canList(me)` 403을 더합니다.
3. **C3**: `PrepStageController`에서 `ui.isValid()`가 아니면 관문 전에 400 `UI_ID_REQUIRED`(감사 INVALID)를 냅니다. 시험 #1~16에 '헤더 없음 → 400' 한 줄을 더합니다.
4. **C4**: 기획 결정을 받고 둘 중 하나로 갑니다.
   - (가, 권장) PREP·DRAFT 자료가 있으면 409 `BOARD_DOC_DRAFT`로 막습니다. 아울러 `BoardMaterialService.create`/`planSubmit`이 `BID_PREP_TASK.NA_YN=1`이면 409 `BOARD_NA`를 냅니다.
   - (나) 그대로 두고, 확정 시점에 NA를 자동 해제합니다(이력 BOARD_NA_CLEAR, 행위자=시스템).
   - L1(잠금 행이 다름)은 (가)에서 board 쪽 검사를 BID_PREP 잠금 안에서 하면 함께 풀립니다.
5. **M5**: 사전준비 승인 결재 payload·카드에 `board_na`(누가·언제)를 싣습니다. 팀장 쪽지 여부는 기획에 넘깁니다(설계 7절 질문 그대로).
6. **L2**: 되돌린 칸의 `MARK_DATE`는 묶음 직전 개정의 값을 씁니다(행위자는 해제자로 두되 이력으로 구분). 묶음이 쓴 칸은 `SAVED_AT==NA_AT`에 `BUTTON_ID='board_na'`를 더해 판정합니다.
7. **L3**: `board_na.by`는 이름만 싣습니다(`{name}`). 사번이 꼭 필요하면 담당·팀장·부장에게만 싣습니다.
8. **L4**: `BoardWriteLimitFilter`에 `bidcases/+[^/]+/+prep/+(?:committees/+[^/]+|board-na)` 16KB를 더합니다(PUT·POST).
9. **L5**: Oracle 머리에 '도중 실패 시 되돌리기 후 재실행' 안내를 더하고, DDL 쌍 시험에 NA_BY·NA_AT 단언을 더합니다. SORT_NO는 069~072 담당과 맞춥니다.
