**하-2** 검사 전 정규화를 한 곳에 모은다. `Pii`에 메서드를 추가하고 `:709,805`의 `Pii.scan(Normalizer.normalize(...))`를 `Pii.scanLoose(...)`로 바꾼다.
```java
// 후 (Pii.java 추가)
public static List<Finding> scanLoose(String text) {
    if (text == null) return new ArrayList<Finding>();
    String s = java.text.Normalizer.normalize(text, java.text.Normalizer.Form.NFKC);
    StringBuilder b = new StringBuilder(s.length());
    for (int i = 0; i < s.length(); ) {
        int cp = s.codePointAt(i); i += Character.charCount(cp);
        if (Character.getType(cp) == Character.DECIMAL_DIGIT_NUMBER) b.append((char) ('0' + Character.digit(cp, 10)));
        else if (Character.getType(cp) == Character.DASH_PUNCTUATION || cp == '.' || cp == 0x00B7) b.append('-');
        else b.appendCodePoint(cp);
    }
    return scan(b.toString());
}
```
이렇게 바꾸면 `9.001` 같은 소수 금액이 오탐될 수 있다. 다만 RRN은 6+7자리 구조라 오탐 가능성은 낮다. 테스트에 금액 표본을 넣어 확인한다.
