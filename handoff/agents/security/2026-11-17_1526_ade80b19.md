**문제없음으로 확인한 항목**
- **권한 우회**: 쓰기는 컨트롤러에서 두 겹으로 막는다 — `requireInstitutionEdit`(ACTIVE 포함, `PermissionService.java:134`), 그다음 `canEdit`(isSales). 둘 다 잠금 전에 막고 DENIED를 남긴다. `insert()`에도 방어 검사가 있다(910줄). 039와 같은 구조라 화면에서 숨기기만 하는 문제는 없다.
- **조회 권한**: 조회는 `map`으로, 039 기관별 조회(`BankContractController.java:26,39`)와 같은 범위다. 요약 API가 더 넓게 열리지는 않는다(한 번 호출로 전 기관을 모아 보게 되는 차이만 있다 — DETAIL에 n이 남는다).
- **SQL 주입**: Mapper XML 전체가 `#{}`만 쓴다. `${}`는 Java `@Value` 한 곳(741줄)뿐이다. 코드표 그룹은 리터럴이다.
- **입력 검증**
  - 기관 ID: `validInstId`(64자·제어·슬래시 거부) 뒤 잠금 행이 없으면 404.
  - 코드: `[A-Z0-9_]{1,20}`이고 ENABLED=1만 받는다.
  - 연도: 넣거나 바꿀 때는 올해~+2, 조회는 1990~2100, 연표는 최대 40년.
  - 주 담당: 7자리 숫자이고 ACTIVE 영업 계열만. 오류 문구는 하나라 사번 존재 여부를 캐낼 수 없다.
  - 자유 글: `text()` 상한과 제어·서식 문자 거부, PII·정당·전화 422. 응답에는 종류와 개수만 싣는다.
- **응답 노출**
  - 수정자 사번·화면·버튼·UI_VALID는 응답에 싣지 않는다.
  - `owner_emp_no`는 can_edit일 때만 싣고, history와 409 detail에는 없다.
  - `edited_by_other`는 서버가 사번을 비교해 계산하고 사번 자체는 내보내지 않는다.
- **접근 이력**: DETAIL에는 건수·번호·REV·오류 코드만 남는다(코드는 `[A-Z_]` 패턴만). 경로에는 기관 ID만 들어가고 쿼리는 기록되지 않는다(`AccessLogInterceptor.java:44`).
- **자기신고 표기**: DDL 헤더, Service, Controller 주석에 모두 있다. `EMP_VERIFIED`를 저장하고 응답 `emp_verified`로 내보낸다.
- **동시성·중복**: 첫 DB 문장이 INSTITUTIONS FOR UPDATE라 MySQL RR 스냅샷 문제가 없다. 그 뒤에 DUP·STALE·ALREADY_CANCELLED를 검사하고, 복합 PK가 마지막 방어선이다. 컨트롤러의 `canEdit`는 별도 읽기 트랜잭션이라 잠금 순서에 끼어들지 않는다.
- **DDL 쌍**: 1단계는 칸, 순서, PK, 인덱스가 같고 타입 대응도 039 관례와 같다. INSERT 블록은 DdlPair 시험으로 대조한다.
