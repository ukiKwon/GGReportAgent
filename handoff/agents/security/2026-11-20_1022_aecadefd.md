## 4. 남은 위험 ①~④ 판단

**① 수집 반입 직접 INSERT**
- 판단: 계약 문구와 서버 재검사를 둘 다 둔다. 계약만으로는 망 밖 도구의 실수를 막지 못하므로, 서버가 확정 순간에 다시 본다(발견 1).
- `collector/SCHEMA.md` §⑧ 비범위 끝에 넣을 문안:

> - **기관장 생년월일(BIRTH_DATE) 반입 금지** — 기관장 정보를 반입하는 경로가 생기더라도 수집기는 `FIELD_CD='BIRTH_DATE'` 행·칸을 만들지 않는다(나이·생년월일·'YYYY년생' 표기를 다른 칸이나 출처 제목에 옮겨 적는 것도 금지). 생년월일은 영업 담당이 상세 화면의 칸 입력(`POST /institutions/{id}/head/items`)으로만 넣는다 — 그 경로만 범위(1920-01-01 ~ 서울 오늘-18년)·권한·열람 기록을 거친다(사용자 결정 2026-11-19, NEXT 77). 망 안 반입 처리기는 이 칸이 든 배치를 `FIELD_NOT_ALLOWED`로 거부하고 사람에게 알린다.

- 서버 패치 후보(한 줄): `confirmHead`의 `:1028` 반복과 `confirmItem`의 `:880` 앞에서, 칸이 `BIRTH_DATE`이면 `HeadText.requireBirthDate(i.getValDate())`를 불러 범위 밖이면 400을 낸다. 시험은 "DB에 직접 넣은 1919년 후보를 머리 확정하면 400, 상태 그대로" 1건.

**② SRC_TITLE에 날짜를 적는 우회**
- 판단: **잔여 위험으로 수용(하).** 날짜 전체를 막지 않는다.
- 출처 제목에는 "2026-07-01 취임식 보도자료"처럼 정당한 날짜가 흔하다. 날짜를 막으면 오탐이 크고 막는 이익은 작다.
- 대신 ③의 '년생'·'생년월일' 낱말 검사를 출처 제목에도 걸어 의도적으로 적은 것만 막는다.
- 남는 위험은 화면 안내("출처 제목에 생년월일·나이를 적지 마세요")와 열람 기록으로 다룬다.

**③ 직위 'YYYY년생' 차단**
- 판단: **넣는다. 다만 backend 5절 정규식을 좁혀서 넣는다.**
- 근거: 직위는 '상세만' 규칙 밖인 목록 A1·Word·매칭 대기 목록에 나가는 유일한 짧은 글 칸이다(발견 2). 사용자 결정(목록·Word 제외)을 우회하는 구체적인 길이다.
- 5절 안의 일반 날짜 패턴 `\d{4}[-./]\d{1,2}[-./]\d{1,2}`는 뺀다. "구청장(2022.07.01 취임)" 같은 정당한 입력을 막기 때문이다. "출생"도 넣지 않는다. "저출생대응과장"이라는 실제 직위가 있다.
- 패치 후보(한 줄): `HeadText`에 다음 패턴을 둔다.

  ```
  Pattern AGE_HINT = Pattern.compile("(?:19|20)\\d{2}\\s*년\\s*생(?!산)|생년월일|만\\s*\\d{2}\\s*세")
  ```

  - NFKC 정규화한 값에 `find()`를 건다.
  - 적용 대상은 `addHead` position(`:701`), `fillValue` POSITION·EDU·CAREER(`:351·353·358`), `source()` title(`:316`)이다.
  - 걸리면 기존 `INVALID_TEXT` 400을 내고, 입력값은 응답에 싣지 않는다.
  - 오탐 시험: '구청장'·'제8대 구청장'·'저출생대응과장'·'2022.07.01 취임'은 통과. '1965년생 구청장'·'만 61세'는 400.

**④ 생년월일 전체 저장의 처리 근거 — 현업 보고서 안건 문안**

> **[안건] 기관장 생년월일 저장의 처리 근거 확인**
> - 현황: 사용자 결정(2026-11-19)으로 기관장 '생년월일 전체(YYYY-MM-DD)'를 저장한다. 상세 화면에서만 보이고 목록·엑셀·Word에는 나가지 않으며, 열람은 누가·언제 기록된다. 입력은 영업 담당이 공개 자료 출처와 함께 넣는다.
> - 쟁점 1 (근거 범위): 기관장 정보 처리 근거(NEXT 76, 정보보호 답)는 '기관영업 추진·보존 계속·DB 저장 가능(민감 칸 마스킹)·연락처 비수집'이고 **나이·생년월일은 명시돼 있지 않다.** 이 근거에 생년월일이 포함되는지 정보보호 확인이 필요하다.
> - 쟁점 2 (최소 수집): 업무 목적이 '나이대 파악'이면 **출생 연도만**으로 충분하다. 생년월일 전체는 주민등록번호 앞 6자리와 같아 다른 정보와 합쳐지면 식별력이 커진다. 선택지: ⓐ 전체 유지(현행) ⓑ 출생 연도만 저장(기존 값은 연도만 남기고 정리) ⓒ 저장하지 않고 화면에서 출처 링크로만 확인.
> - 쟁점 3 (보존·파기): 무효·대체·이전 기관장 행에도 값이 계속 남는다. 기관장이 바뀐 뒤 몇 년 보존할지, 파기할 때 값을 지울지(현재는 상태만 바꾸고 값은 남음) 정해야 한다(NEXT 35 감사 로그 보존 기간과 함께).
> - 요청: 정보보호팀 회신(쟁점 1)과 현업 결정(쟁점 2·3). 회신 전까지는 현행 유지, 열람 기록으로 사후 확인.
