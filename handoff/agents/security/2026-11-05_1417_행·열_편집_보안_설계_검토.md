## 3. 권장 조치 순서 (패치 후보 한 줄씩)
1. **(#1, PR-1에 앞당김)** 필터에 `PUT` + `(?:^|/)board-forms/[^/]+/*$`를 추가해 512KB로 막는다. `POST /board-forms/copy`도 작은 한도(예: 16KB)로 막는다. 헤더 검사에 더해 **읽은 바이트를 세어 넘으면 끊는 InputStream 래퍼**를 둔다(#2 방어 심층화). 앱 전체 `@RequestBody`에 기본 한도를 둘지는 따로 결정한다.
2. **(#3)** 사용자 구조 검증은 `Table` 생성 **전에** 한다. cs·rs를 1..cols/1..rows로 먼저 제한(곱셈·덧셈 전)하고, 실패는 고정 문구 `EditException` → 400으로 낸다. `layout()`의 ISE는 카탈로그 상수 전용으로 남긴다.
3. **(#4)** 옛 포맷 번역표는 **catalog_ver별로 얼려 둔 상수**(v1 위치→id)로 두고, 저장된 `catalog_ver`로 고른다. 모르는 버전이면 닫힌 실패(fail closed)로 처리한다. "카탈로그 v1 표에서 위치→id 번역이 고정됨"을 고정하는 테스트를 넣는다.
4. **(#6)** id 검증 규칙 ⓐ~ⓔ를 서버 단위 테스트로 고정한다. ⓕ 카탈로그 행·열의 순서 이동 허용 여부를 정하고, 허용하면 연결 행·열의 머리 문구가 카탈로그와 다를 때 작성 모드에서 경고한다(LABEL 계열).
5. **(#7)** 사라짐 판정은 **base 버전 대비**로 하고, 가려진 연결 칸도 센다. 화면은 첫 요청에 true를 보내지 않는다. 접근 이력 detail에 `unmapped=N confirm=1` 같은 건수만 남긴다.
6. **(#8)** 구조 변경 저장의 접근 이력 detail에 `rows+N/-M cols+N/-M unmapped=K`(숫자만)를 남긴다. 작성 모드에 "양식 v{n}·마지막 수정자·수정 시각"을 표시한다. 관리자용 이전 버전 복구 경로를 검토한다.
7. **(#5)** 결재 상신 때 **렌더된 문서·연결 칸 목록 스냅샷**을 보관하는 쪽으로 결재 연계를 설계한다(NEXT 37 열린 결정 ⓐ와 통합).
8. **(#14)** PR-1부터 `Save`에 `fmt` 필드를 받고, 지원하지 않는 fmt면 400을 낸다. 이렇게 하면 PR-2를 롤백해도 조용한 초기화가 나지 않는다.
9. **(#9·#10)** 양식당 버전 수 상한 또는 행위자별 저장 빈도 제한을 둔다. 카운터 상한은 99999로 올리거나, 표를 다시 추가해도 카운터를 유지한다.
10. **(#11·#12·#13·#15)** `clean()`에서 Cf 문자를 거부한다(필요하면 ZWJ만 예외). 양식 저장에도 `Pii.scan`을 적용한다(거부 또는 경고). `MAX_JSON`은 칸 수·글자 상한으로 대체하거나 바이트 기준으로 여유 있게 잡는다. 요청 DTO에 `JsonNode`·`Object`를 쓰지 않는다. 저장 직전 `toJson → parse → build`를 한 번 왕복해서 "읽을 수 없는 버전"(읽기 시 500으로 양식 영구 고장)이 저장되지 않게 한다.
