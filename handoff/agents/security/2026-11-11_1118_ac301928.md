**문제없음으로 확인한 것**
- **행위별 권한**은 정책과 맞는다.
  - 제출·결과 입력: 현재 담당자만. 비담당은 404, 부장은 403.
  - 회수: 담당자 누구나, SUBMITTED일 때만.
  - 재작성 요구: 활성 부장만, SUBMITTED·CONFIRMED일 때만. 부장이 아니면 존재 확인 전에 403이라 번호로 존재를 떠볼 수 없다.
  - 검토 열람: 결재선 또는 부장, 그 밖은 404.
  - 결재: 결재자 본인만. 설계 반영 시 대결 불가(NO_PROXY에 BOARD_SUBMIT 추가).
  - 자기 결재 금지: 본인 요청 결재 금지(`eligibility`), 담당자인 승인자 403, 팀장이 관련되면 부장만(409).
  - 관리자: 취소 불가, 전체 목록에서 제외.
- **회수·반려·재작성·승인의 경합**: `updateStep`과 `updateRequest`가 모두 `STATUS='PENDING'` 조건(`ApprovalRequestMapper.xml:46,53`)이고 자료 쪽도 조건부 UPDATE라 이중 처리 시 409로 롤백된다.
- **오류 문구**에 내부 정보(SQL·스택·사번)가 없다.
- **접근 이력**(ACCESS_LOG detail)에는 자료 번호·코드·req·결과 코드만 들어간다. **감사 기록**(ACT)에는 사유·값이 없다.
- **결재 제목** 길이는 기관명 100자 + 약 20자로, 제목 칸 200자 안에 들어간다.

## 3. 권장 조치 순서

**커밋 전 필수**
1. **S3**: write-agent 결과에 설계 §3-1 ①②③과 §3-3 `can_cancel`이 모두 들어갔는지 diff로 확인한다.
2. **S2**: decide에서 BOARD_SUBMIT(또는 모든 유형)의 의견을 검증한다.
   ```java
   String comment = BoardMaterialService.checkedText(in.getComment(), 500, "의견", !approve); // null→""
   ```
   현재 `comment` 계산을 바꾸는 방식이다. 정적 메서드가 패키지 공개(package-private)인데 같은 패키지라 호출할 수 있다. 개인정보는 422, 제어문자는 400이 된다. 하는 김에 `lastReturn`에서도 `Pii.scanLoose(reason)`가 걸리면 사유를 비우는 방어를 하나 더 두는 것을 권한다.
3. **S1**: 둘 중 하나로 고친다.
   - (가, 권장) CONFIRM 감사 기록을 `applyConfirm` 안, 즉 **같은 트랜잭션**에서 넣는다. 화면·버튼은 `RequestContextHolder`로 현재 요청을 얻어 `BoardUiIds.of(...)`로 만든다. 기록이 실패하면 승인도 되돌아가고, 상태 경합이 없다. 상태는 S9 기준 `SUBMITTED`로 적는다.
   - (나, 최소) 컨트롤러 호출을 `try { audit.recordApproved(...) } catch (RuntimeException e) { log.warn("board approve audit failed req={}", id); }`로 감싼다. 기록 누락 위험은 남는다.

**다음 묶음**
4. **S5 ②**: cancel에서 BOARD_SUBMIT이면 `materials.planWithdraw(readPayloadMaterialId(r), me)`를 먼저 불러 현재 담당자만 회수하게 한다. 비담당은 404/403.
5. **S4**: 기획이 확정하면 열람 자격을 좁힌다. SUBMITTED면 "현재 요청(`SUBMIT_REQ_ID`)의 결재자", CONFIRMED면 "`CONFIRMED_BY`가 나"로 한다. 확정 뒤 열람을 아예 막을지도 함께 정한다.
6. **S8**: 프런트가 결재함 헤더를 붙이는 시점에, BOARD_SUBMIT의 decide·cancel에서 헤더를 필수로 만든다(400 `UI_ID_REQUIRED`).
7. **S6, S5 ①**: 021에서 cancelPendingSubmit을 설계할 때 락 순서를 명시한다. 예: 자료 행만 조건부로 DRAFT로 되돌리고, 요청·단계는 건드리지 않거나 별도 트랜잭션으로 정리한다.
8. **S7, S9, S10, S11**: 정리성 항목이다. 가장 작은 S7 대응은 out-local 문서에 "동시성 보장은 Oracle 기준"이라고 적는 것이다.
