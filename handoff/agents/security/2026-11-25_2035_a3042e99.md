### 문제없음으로 확인한 것

- **valueOnlyEdit 통합**: 일괄 EDIT의 기존 판정(`TargetChangeService.java:180-181`)은 "올해 이후 + 연도 같음 + 주 담당 같음"입니다. `Rules.valueOnlyEdit`의 추가 조건 `cur != null`, `!p.watch`, `GOAL`은 일괄 경로에서 이미 참입니다(171–174줄에서 목표만 EDIT 허용, `parse`는 watch=false). 그래서 지난해 목표 결재(지난번 F1)와 주 담당 변경 결재의 판정은 바뀌지 않습니다. 갱신 기준(aim 조건 없음)에서는 aim이 결재를 낮추지도 올리지도 않습니다.
- **지난해 목표**: 금고 방식만 고쳐도 결재로 갑니다(구분 태그와 같은 규칙).
- **결재 우회 경로**:
  - 지우기→다시 채우기, 일괄 ADD에 싣기: ②에서 바꾸기 자체가 바로 반영이므로 우회할 대상이 없습니다. ADD에 싣는 것은 위 '중' 항목으로 막을 것을 권합니다.
  - 관심→목표: 옮기기는 여전히 `requireDirect`/결재입니다.
  - 일괄 묶음: `plan.valueOnly`는 전부 참일 때만 바로 반영되고, 하나라도 결재 대상이면 전체가 결재로 갑니다.
- **감사 기록**: 바로 반영과 승인 반영 모두 `BidTargetService.write()` 488–496줄을 지나며 다음을 남깁니다: 수정자 사번·이름, `EMP_VERIFIED`, 화면, 버튼, `UI_VALID`, 시각, `APPROVAL_REQ_ID`. 새 버튼 `set_target_aim_rank`를 EDIT·CHANGE 허용 목록에 넣는 것도 문제없습니다. 화면이 보낸 머리글을 믿는 구조라 `UI_VALID` 표시로만 쓰이며, 이 점은 기존과 같습니다.
- **접근 이력**: `aimTag`는 서버 상수 세 개만 통과시키고, 일괄은 건수(Integer)만 남깁니다. 값·메모·사번은 들어가지 않습니다. 실패 이력(`failDetail`)은 코드 정규식으로 거릅니다.
- **SQL**: `BidTargetMapper.xml`에 `${`가 0건입니다. 새 칸은 `#{aimRankCd,jdbcType=VARCHAR}`이고 코드 그룹은 리터럴입니다. 입력은 `[A-Z0-9_]{1,20}`과 코드표 활성 검사를 거치며, 칸 길이 VARCHAR 20과 맞습니다.
- **♥ 다시 켜기**: `watchOn`이 재사용하는 행(`m[1]`)에서 aim을 null로 비우는 패치가 들어 있어, 옛 값이 새지 않습니다.
- **알려진 한계**: 모든 판정은 `X-Emp-No` 자기신고 사번 위에 있습니다(백엔드 보고서와 같은 전제).

## 3. 권장 조치 순서

1. **설정 키와 오버로드를 없앱니다.**
   - 다음을 패치에서 뺍니다: `BidTargetSettings.aimChangeApproval`, 4인자 `valueOnlyEdit`, `aimChangeNeedsApproval`, `aim_change_mode`의 APPROVAL 분기.
   - `valueOnlyEdit`는 지금의 3인자 그대로 둡니다. aim은 구분 태그처럼 다루며, 지난해 목표 규칙은 그대로 적용됩니다.
   - 일괄도 이 함수를 부르게 합치는 부분만 유지합니다.
2. **③을 서버에서 강제합니다.** 패치 후보 한 줄: ADD에서 `aim_rank_cd`가 비어 있지 않으면 400을 냅니다. 적용할 곳은 두 군데입니다.
   - `BidTargetService.save`의 `cur == null && !watch` 경로
   - `TargetChangeService.planItem`의 ADD 분기
3. **`REQ_ITEM.AIM_RANK_CD`와 claim·replan·write의 aim 전달은 유지합니다.** EDIT 승인 때 값이 지워지지 않게 하기 위해서입니다. 다른 방법은 `write()`가 EDIT에서 aim을 `cur` 값으로 고정하는 것인데, 그러면 연도와 금고 방식을 한 결재에 담을 수 없습니다.
4. **(선택) 결재 카드의 '이후' 금고 방식을 바로잡습니다.** TO_GOAL·TO_WATCH·CANCEL은 '이후'를 `before` 값으로 채우거나, 화면에서 그 칸을 숨깁니다.
5. **시험을 더합니다.**
   - ADD에 aim을 실으면 400 (단건·일괄)
   - 결재 EDIT(주 담당 변경)를 승인한 뒤에도 기존 aim이 유지됨
   - 지난해 목표에서 aim만 고치면 403
