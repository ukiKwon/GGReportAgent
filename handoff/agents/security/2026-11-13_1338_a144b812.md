## security 검토: 63ed4e1(구형 HWP 글을 근거로 사용)과 522ac0a(preview 이전 회차 판정)

**결론: 두 커밋 모두 그대로 둬도 된다.** 상급·중급 위험은 없다. 11-12 보고에서 붙인 조건(글 전체 상한, 문단 덩어리 단위 decode, olefile 내부 예외 감싸기, olefile==0.47 고정)은 모두 들어가 있다. 하급 3건은 다음 바퀴에 고치면 된다.

### 1. 대상·방법·못 본 것
- **본 파일**:
  - `collector/extract/build.py:76-129`
  - `collector/extract/hwp5.py` 전체
  - `collector/tests/test_build_hwp.py`
  - `collector/preview.py:375-505`

- **못 본 것**:
  - olefile 0.47 내부 동작. 순환하는 FAT 체인을 막는지, 스트림을 처음에 통째로 읽는지는 확인하지 못했다.
  - `mask_contacts`가 HWP에서 뽑은 글에 대해 실제로 얼마나 잘 가리는지(가림률).

### 2. 요청하신 관점별 확인
- **11-12 조건 반영**: 반영됨.
  - 상한: 파일 30MB(`hwp5.py:15`), 구간 50개(`:16`), 압축 푼 크기는 구간당 30MB(`:17`, `_inflate`에서 `unconsumed_tail`로 판정), 글 200만 자(`:18`, `:101-103`).
  - 문단 덩어리 decode: `:32-50`.
  - 예외 감싸기: `:110-112`.
  - 암호·배포용 HWP는 거부(`:88-89`), OLE 서명 먼저 확인(`:78`).
- **mask_contacts 통과**: 확인됨.
  - HWP 글은 `texts`에 들어간 뒤 `build.py:109`에서 일괄로 가려지고, 그다음에야 `build_candidate`(basis·evidence)로 넘어간다. 가리지 않고 나가는 길은 없다.
  - HWP 파일 자체는 배치에 싣지 않는다(`:94-95`).
  - 테스트 `test_build_hwp.py:36`이 전화번호가 남지 않는지 검사한다.
- **실패 메모(notes)**: 원문 조각이나 경로는 새지 않는다.
  - hwp5가 내는 오류 문구는 고정 문자열이거나 예외 종류 이름(`type(exc).__name__`)뿐이다. 예외 메시지 본문은 넣지 않는다.
  - notes에 들어가는 외부 값은 첨부 파일명(`a['name']`)뿐이다. 이건 이번 커밋 전부터 그랬다(아래 L3).
- **olefile이 없는 PC**: 문제없다.
  - `ImportError`가 `ExtractError`로 바뀌어 notes에 남고(`hwp5.py:72-75`), 공고 처리는 계속된다.
  - 안내 문구에 경로가 없고, 테스트 `:48-51`이 이 경우를 검사한다.
  - 영향은 HWP 근거 글이 빠지는 것뿐이다. 파일이 원래 실리지 않으므로 유출 위험은 없다.
