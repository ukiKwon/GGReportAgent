요청하신 네 가지 확인 결과는 다음과 같습니다.

**① 응답 모양과 기관 분리 — 문제없음**
- 행마다 붙는 키는 `rank_cd`·`bank_name`·`term_to` 세 개뿐입니다(`PrepBoardService.java:332-334`).
- `CONTRACT_NO`는 조회만 하고 응답에 싣지 않습니다. 사번·편집자·SRC_URL·NOTE는 조회조차 하지 않습니다.
- 기관별 맵은 `institutionId`로 묶고(`:335-337`), 행에는 `p.getInstitutionId()` 몫만 붙입니다(`:225-226`). 목록에 없는 기관의 약정은 메모리에만 있고 응답에는 나가지 않습니다.

**② 질의 안전성과 Oracle 11g 호환 — 문제없음**
- 바인딩 변수가 없고 상수 `'BANK'`·`'SAVE'`만 씁니다. 따라서 SQL 주입 경로가 없습니다.
- ANSI LEFT JOIN, 상관 NOT EXISTS, COALESCE, `&gt;` 이스케이프, ORDER BY는 11g에서 동작합니다.
- 최신 개정 조건은 `BankContractMapper.xml:72-73`의 `latest`와 같습니다.

**③ `/preps`를 안 보내 생기는 감사 누락 — 의도대로이고 누락 없음**
- `GET /preps`(`PrepController.java:78-81`)는 사전준비 감사에 실패(거부)만 남깁니다. 표에서 상세를 열 때 이 요청은 숨은 왼쪽 목록을 채우는 부수 요청이라, 사용자가 실제로 본 화면이 아니었습니다.
- 사용자가 실제로 본 것은 그대로 기록됩니다.
  - 표: `DASH_LIST`·`DASH_LIST_ROW`
  - 상세: `VIEW`(화면 이름 `prep_dashboard`, `prep.js:1148`)
- 오히려 접근 이력에 `prep_list` 화면이 잘못 찍히던 문제가 없어집니다. 옛 화면(`refresh`)은 `loadList`를 그대로 부르고, 시험 `prepboard.test.js:461-472`가 이를 고정합니다.

**④ 권한 경로 — 변화 없음**
- `canList`의 403(`:159`)과 `prep.boardCanSee`(`:210`) 위임은 그대로이고, 복제하지 않았습니다.
- 끝난 건의 이름 가리기(`hideNames`)는 은행 칸과 관계가 없습니다. 은행 정보는 기관 단위라 가리기 전에도 같은 범위였습니다.
- 저장 경로(`save`)는 바뀌지 않았습니다.
