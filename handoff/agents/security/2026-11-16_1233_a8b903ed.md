**3. ③ 저장형 본문 제공을 설계할 때의 보안 요구사항**
- 본문은 업로드 분석 때 ZipGuard·ENCRYPTED 검사를 통과한 결과로 한 번만 만든다. 조회할 때 다시 추출하지 않는다.
- 문서 하나의 본문 길이와 응답 하나의 총 크기에 상한을 둔다. 검색 결과는 페이징한다(NEXT 17·21과 연결).
- 본문 조회는 서버에서 권한을 검사한다. 지금 인증은 자기신고 방식이라 본문 노출 범위가 넓어지므로, 문의 6-2·4ⓒ 회신 전에는 열지 않는다.
- 상태가 DELETED인 파일은 본문도 지우거나 감춘다. 원본을 삭제하면 본문도 따라 지워진다.
- 실패 사유·서버 경로·예외 메시지는 본문 칸과 응답에 넣지 않는다(FileContentService 51행 계약 유지).
- 화면에 본문을 그릴 때는 textContent로 넣는다(XSS). 검색어는 MyBatis 바인딩(#{})으로만 넘긴다.
- 본문 저장 테이블·열에 개인정보가 들어갈 수 있다. 보존 기간과 로그에 남기지 않는다는 원칙을 기획이 정한다.
