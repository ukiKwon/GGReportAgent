## 3. 권장 조치 순서 (패치 후보 한 줄씩)
1. **중-1**: 취소 버튼 판정은 새 서비스에서 따로 계산하지 말고, `PrepService`에 `viewer`의 `can_unconfirm`·`can_cancel`(1013~1019행)과 같은 식을 package 메서드로 꺼내 그대로 호출합니다. 판정 함수를 하나로 둡니다. 테스트 14에 "영업부장 → NONE"과 "디자이너 → NONE"을 넣습니다.
2. **중-2·중-3**: 047을 다음처럼 바꿉니다. 그러면 11g 호환과 멱등을 한 번에 해결합니다.
   - `ACK_ID`를 없앱니다.
   - 037 방식대로 `PRIMARY KEY (EMP_NO, INSTITUTION_ID, ROUND_SEQ, NOTICE_HANDLED_AT)`를 둡니다.
   - 서비스는 INSERT를 시도하고, `DuplicateKeyException`이 나면 200 `saved=false`를 냅니다.
   - 추가로 `NobidAckDdlPairTest`(두 파일의 열 목록이 같은지)와 테스트용 `spring.sql.init.schema-locations`에 oracle 047을 더합니다.
3. **중-4**: GET 응답의 `notice.handler_name`(필요하면 `handled_at`도)은 `permissions.canView(emp,"map")`일 때만 채우고, 아니면 null로 둡니다. `can_view_notice`도 같은 값으로 계산합니다. 이것으로 기획 이관 하나가 해소됩니다.
4. **하-1**: POST 본문을 이렇게 검증합니다. 모두 역할 403 **뒤**에 둡니다.
   - `round_seq`: Integer, null이면 400, 1~999999
   - `handled_at`: null·빈 값·40자 초과이면 400
   - INSERT에는 클라이언트 값이 아니라 **서버가 다시 읽은** `round_seq`·`handled_at`·`bid_case_id`·`state_cd`를 넣습니다.
5. **하-4**: 컨트롤러 실패 경로에서 접근 이력 DETAIL을 `nobid-notice ack <상태> <CODE>`(대문자 코드만, `failDetail` 틀)로 남깁니다.
   - 성공 DETAIL은 `nobid-notice ack inst=<id>`입니다.
   - `handled_at`·이름·round 외의 값은 넣지 않습니다.
   - GET DETAIL `nobid-notice view applicable=Y/N`은 그대로 둡니다.
6. **하-2**: GET에서 형식이 맞지만 없는 기관은 `none`이 아니라 404로 통일합니다(테스트 15 기준). 역할 403을 먼저 판정합니다.
7. **하-3**: 테스트 11을 "기관 자료가 넘어가면 `applicable=false`, 옛 값으로 POST하면 409 `NOT_APPLICABLE`"로 바꿉니다. NO_CHANGE 기획 이관은 철회합니다.
8. **하-6**: 프런트는 이름·기관명을 `textContent`로만 그립니다.
