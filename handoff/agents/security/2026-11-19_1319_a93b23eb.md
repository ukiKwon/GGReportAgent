# S1·S2 재판단 — 사용자 11-19 흐름 기준 (security, 보충)

**결론**: 녹음·받아쓰기가 네이버에서 일어나는 것은 이 흐름에서도 그대로입니다. 바뀐 것은 "그 뒤는 내부에서 가공한다"는 부분뿐입니다. 시스템 쪽 위험은 크지 않아 **S1을 상에서 중으로 낮춥니다**. 다만 바깥에 남는 사본 세 곳은 시스템이 지울 수 없어서, 운용 수칙으로만 다룰 수 있습니다. **사용자에게는 짧은 확인 질문 1개를 다시 묻고, 나머지는 운용 수칙 안내로 대신하기를 권장합니다.** 규정 위반 여부는 사내 규정을 보지 못해 판단하지 않았습니다(추정).

## 바깥에 남는 사본과 위험
| 위치 | 남는 것 | 위험 | 시스템이 할 수 있나 |
|---|---|---|---|
| 네이버 클로바 노트 | 녹음 음성 + 받아쓴 원문 전체(실명 포함) + 클로바 요약 | 은행이 지울 수도, 누가 봤는지 확인할 수도 없음. 개인 계정이면 퇴직·계정 탈취 때도 남음. 공유 링크를 만들면 링크를 가진 사람은 열람 가능(추정). 데이터 활용 설정이 있으면 서비스 개선에 쓰일 수 있음(확인 필요) | 없음. 안내만 가능 |
| 메일함 | 가리지 않은 원문 텍스트(본문 붙여넣기 또는 첨부) | **사내 메일**이면 사내 보존·전달 범위 문제로 그침(낮음). **개인·외부 메일**(네이버 메일 등)이면 바깥 사본이 하나 더 생김(중) | 없음. 안내만 가능 |
| 담당자 PC·망연계 | 가리지 않은 txt 파일, 망연계 전송 기록 | PC에 오래 남거나 공유 폴더로 퍼질 수 있음. 망연계는 공식 경로라 낮음 | 일부 가능. 업로드 완료 화면에서 "원본 파일을 지우세요"라고 안내 |

S2(참석자 동의)는 이번 답으로 해소되지 않았습니다. 녹음 시점의 문제라 텍스트를 내부에서 가공해도 달라지지 않습니다.

## 시스템에서 할 수 있는 것
- 업로드 화면에 운용 수칙을 고정해 둡니다(4줄).
  - 공유 링크를 만들지 않습니다.
  - 텍스트는 사내 메일로만 보냅니다.
  - 업로드 뒤 클로바 노트 기록, 메일, PC 파일을 지웁니다.
  - 외부 참석자의 이름은 직접 지정해 가립니다.
- 업로드할 때 "수칙을 확인함" 체크를 받고, 그 사실을 감사 기록에 남깁니다(값 없이 사번·시각만).
- 기능 플래그로 운영 공개 시점을 조절합니다(R20과 같은 장치).
- 원본 미보관, 가림, 열람 제한, 감사(R1~R25)는 그대로 둡니다. 시스템 안쪽은 이 장치들로 충분합니다.

## 시스템에서 할 수 없는 것
- 네이버 쪽 사본과 메일 사본을 지우거나 감사하는 일
- 녹음 동의를 받는 일
- 어느 계정을 쓰는지 강제하는 일
