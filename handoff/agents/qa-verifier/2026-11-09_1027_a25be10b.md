- 대상: NEXT 45②·51① — 929px와 창 크기 변경 때 선택 칸이 가려지는지 확인. 8080(새 코드)에서 이사회 자료 → 기본 양식 → 이 양식으로 작성 → `docs/samples/수익성분석표_샘플_머리글다름.xlsx`를 올렸다(결과: 236칸 채움, 13칸 읽지 못함, 머리글 다름 경고 표시). 저장·제출은 하지 않았다.
- 방법: 페이지 안에 측정 함수를 넣어 잰 값으로 판정했다.
  - 잰 것: 선택 칸 사각형이 작성 바(`#bd-writebar`), 원본 패널(`#bd-w-src`), 상태 줄(`#bd-w-status`)과 겹치는 픽셀 수, 그리고 칸의 네 모서리와 가운데가 실제로 맨 위에 보이는지(elementFromPoint).
  - 실제 마우스 클릭: 작성 바 경계에 걸친 칸과 원본 패널 경계에 걸친 칸.
  - 화살표 키로 전 칸 순회: 지시의 "Tab으로 선택"을 화살표 키로 대신했다. 표 전체가 tabindex=0 칸 하나만 갖는 구조라 Tab을 누르면 표 밖으로 나간다.
- 못 본 것:
  - 화살표 순회는 실제 키 입력이 아니라 합성 keydown으로 했다. 실제 키 입력(ArrowDown 1회·Tab 3회)은 표본으로만 확인했다.
  - 높이 800 이외의 창 높이는 보지 않았다.
  - 자동 테스트(`node --test`)는 실행하지 않았다. 호출자의 테스트 출력도 받지 못했다.

  - 1440에서 C-5 r20_c4를 y=640에 선택한 뒤 929로 줄이면 383~408로 옮겨진다(패널 위쪽 416보다 위).

**P2-1. 1440 화면에서 페이지 맨 아래로 스크롤하면 원본 패널이 스크롤할 때마다 위로 기어 올라가 작성 바 밑에 숨는다(창 크기 변경과 무관)**
- 측정값:
  - 스크롤 600일 때 패널 top 174 = 작성 바 bottom 174로 정상이다.
  - 맨 아래(1796)에서 2px 위·아래로 흔들 때마다 패널 top이 158→144→130→116→102→88→74로 오르고, 높이는 528→598로 늘어난다.
  - 그 결과 패널 제목, "넓게 보기"·"원본 접기", 표 칩(A~C-5)·"선택 칸으로", 원본 열 머리가 작성 바에 가려진다. 929→1440 직후에는 top이 142로 버튼 가운데가 이미 가려진 상태였다.
- 929(아래 배치)에서는 같은 조작에도 382로 고정되어 재현되지 않았다.
- 원인으로 보이는 곳:
  - `frontend/js/board-write.js:1402`가 `--bd-scroll-top`을 `max(bar.offsetHeight, src.top)`으로 잰다. 그런데 `frontend/index.html:322`의 max-height가 이 값을 쓴다.
  - 패널이 그리드 끝에 밀려 top이 줄면 → 패널이 커지고 → 더 밀려 올라가는 되먹임이 생긴다.
  - 하한 `bar.offsetHeight`(69)는 높이 값인데 비교 대상은 뷰포트 좌표(작성 바 bottom 174)라 단위가 맞지 않는다.
- 재현 절차:
  1. 1440×800에서 위 절차대로 업로드한다.
  2. 페이지를 맨 아래까지 스크롤한다.
  3. 휠을 위·아래로 조금씩 여러 번 움직인다.
  - 기대: 패널 머리가 작성 바 아래에 머문다.
  - 실제: 머리가 작성 바 밑으로 사라진다. 위로 크게 스크롤하면 복구된다.

## 4. 테스트 공백과 추가 제안
- measureSrc 되먹임:
  - 입력: 패널 top이 작성 바 bottom보다 작은 상태(그리드 끝에 밀린 상태).
  - 기대: `--bd-scroll-top`이 작성 바 bottom(뷰포트 좌표) 아래로 내려가지 않는다. 같은 입력을 반복해도 값이 변하지 않는다(고정점).
- 칸이 아닌 포커스 대상(표 복사 버튼):
  - 입력: 929·stacked 상태에서 버튼에 포커스.
  - 기대: 버튼 사각형이 원본 패널·상태 줄과 겹치지 않는다(겹침 0).
