**확인한 것 (문제없음)**
- **S1**: `bankSummary()`(diff 498-502)는 5000줄 상한에 닿으면 마지막 기관 묶음을 빼고 `truncated:true`를 유지한다. 정렬은 `ORDER BY k.INSTITUTION_ID, k.CONTRACT_NO`이고 LinkedHashMap이 그 순서를 그대로 따른다.
- **S2**: cancel 성공 시 DETAIL이 `other=1|0`이다(diff 960-961). `edited_by_other`는 처음 입력자와 이번 수정자의 사번 비교로 만들고, 사번 자체는 응답에 싣지 않는다. 시험 diff 1577·1587이 1과 0을 둘 다 고정한다.
- **S3**: 042 다음에 043을 붙였고(diff 44) mapper 수 27이다(diff 31).
- **S4**: save·cancel 모두 insert 전에 999999를 넘으면 409 `LIMIT`이다(diff 556·582).
- **권한 두 겹**:
  - `requireEditor`가 `requireInstitutionEdit`(401/403 DENIED)를 먼저 하고, 이어서 `canEdit`(ACTIVE 확인 + `isSales`)를 본다(diff 976-980).
  - 서비스 `insert()`가 `isSales`로 한 번 더 막는다.
  - 디자이너: 조회 200, `can_edit=false`, `owner_emp_no` 키 없음(시험 diff 1605·1621).
- **추가 전용 무결성**:
  - 매퍼에 UPDATE·DELETE 문장이 없다.
  - save·cancel 모두 첫 DB 문장이 `lockInstitution FOR UPDATE`다. `canEdit`는 컨트롤러에서 별도 readOnly 트랜잭션으로 돌므로 잠금 순서를 깨지 않는다.
  - 순서: `selectLatestTarget` → CANCEL이면 409 `ALREADY_CANCELLED` → `base_rev_no` 다르면 409 `STALE` → 같은 해 다른 살아 있는 기록이면 409 `DUP_TARGET`.
  - PK 중복은 409 `STALE`(마지막 방어선).
  - 빼기는 직전 행을 복사하고 REV+1을 넣는다. 다시 넣으면 새 TARGET_NO다(시험 diff 1579-1581).
- **연도**:
  - 넣기·연도 바꾸기는 올해~+2만 허용한다. 고치기에서 그대로 둔 지난해는 허용한다(`BidTargetRules.parse`, diff 316-318).
  - 조회 연도는 4자리, 1990~2100.
  - 연표는 from≤to, 최대 40년.
  - 기준일은 `Times.todayKst`다.
- **자유 글**:
  - 메모: `text()`(제어·서식 문자 400, 100자) 뒤에 PII와 정당·전화번호 검사(422).
  - 기타 사유: 같은 검사에 이름+직함 검사를 더한다.
  - 422 본문은 종류·개수만 담는다(시험 diff 1593).
  - 메모에 이름 검사가 없는 것은 S6 결정을 이어받은 것이다.
- **사번 미노출**:
  - `view()`는 수정자·처음 입력자 사번, 화면·버튼, UI_VALID를 내보내지 않는다.
  - 409 `latest`에는 `editor_name`만 있다.
  - history는 `owner_emp_no`를 싣지 않는다.
  - insert 응답의 `owner_emp_no`는 쓰기 자격자에게만 돌아간다.
- **접근 이력 DETAIL**: 건수, no/rev, 상태 코드, 오류 코드(`[A-Z_]` 형식만 통과), other 플래그만 남는다. 메모와 연도는 없다(시험 diff 1652-1656).
- **Oracle 11g 호환**:
  - IDENTITY·FETCH FIRST·LIMIT를 쓰지 않고, 페이징은 RowBounds다.
  - COALESCE, ANSI LEFT JOIN, NOT EXISTS, FOR UPDATE, `DEFAULT 0 NOT NULL` 순서 모두 11g에서 된다.
  - 인덱스 이름 `IDX_IBT_*`는 다른 DDL과 겹치지 않는다(grep 확인).
  - 빈 문자열은 `text()`가 null로 바꾸므로 Oracle의 ''=NULL 차이가 생기지 않는다.
- **DDL 쌍**: 두 파일 모두 18칸이 같은 순서·같은 NULL 여부이고, PK와 인덱스 2개가 같고, INSERT 6행이 글자 그대로 같다. 타입 차이(MySQL INT ↔ Oracle NUMBER(6))는 S4가 막는다.
