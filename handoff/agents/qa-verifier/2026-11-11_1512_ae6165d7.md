## 3. 발견 목록

**[P2-1] 반려·회수된 개설 신청 정보가 정작 볼 권한이 있는 사람에게 안 보임**
- 근거:
  - `prep.js:403` `pastOpenLine`은 `v.open_request`가 있기만 하면 빈 줄을 돌려줍니다.
  - 서버 `PrepService.java:945`는 영업팀장·영업부장·그 신청자에게 끝난 신청(status REJECTED/CANCELLED)도 `open_request`로 내려줍니다.
  - 그런데 `endHtml`의 CONFIRMED 분기(`prep.js:566`)는 `nomineeLines`를 그리지 않습니다.
- 결과: 권한자에게는 "지난 개설 신청 n건" 요약도, 지명자·의견도 안 보입니다. 권한이 없는 영업팀원에게는 요약이 보여서 권한과 반대로 동작합니다. 개설 승인 뒤(IN_PROGRESS, open_request.status=APPROVED)에도 지난 반려 건수가 숨겨집니다.
- 테스트 `prep.test.js:293`이 status 없는 `{req_id:1}`로 이 동작을 굳혀 두었습니다.
- 재현:
  1. 영업팀원 A가 개설 신청 → 영업팀장이 반려 → 건이 CONFIRMED로 돌아갑니다.
  2. 영업팀장으로 사전준비 화면에서 그 건을 엽니다.
  - 기대: "지난 개설 신청 1건 · 마지막 반려됨"(필요하면 지명자·의견도)
  - 실제: 두 줄 모두 없음
  3. 영업팀원 B(권한 없음)로 열면 요약 줄이 보입니다.

**[P2-2] 중단된 건에서 영업팀장에게 [무효 처리]가 보이지만 누르면 엉뚱한 오류**
- 근거:
  - `PrepService.abort`(:292~318)는 과제 행을 지우지 않습니다. 그래서 CANCELLED 건에도 T3가 TODO/DONE으로 남습니다.
  - `loadDetail`(`prep.js:986~987`)은 영업팀장이면 첨부를 불러옵니다.
  - `attachActions`(:457)는 건의 상태를 보지 않고 `lead`이면 voidIt=true로 둡니다.
  - 서버 `voidAttach`(:243)는 TASK_STATES 밖이면 409 STATE_CHANGED입니다. 화면 문구는 "그사이 다른 사람이 이 건의 상태를 바꿨습니다…"로 사실과 다르고, 다시 불러와도 버튼이 그대로 남습니다.
- 재현:
  1. 확정본이 아닌 T3 파일이 있는 IN_PROGRESS 건을 영업팀장이 [중단…]합니다.
  2. '취소·중단' 탭에서 그 건을 엽니다 → 파일 행에 [무효 처리]가 보입니다.
  3. 사유를 적고 [무효 처리하기]를 누릅니다.
  - 실제: 409 STATE_CHANGED 문구가 나오고 버튼은 다시 보입니다.

**[P3] 짧게**
1. **T4 파일 섞임**: `filesHtml`이 `task_cd==='T3'`로 거르지 않습니다(규격 §6-A "task_cd=T3만"). 서버 목록은 T4 첨부도 돌려줍니다(`PrepAttachService.list`). 서버는 T4 업로드를 받으므로 T4 파일이 생기면 T3 표에 섞이고, 확정본 지정 시 ATTACH_NOT_ELIGIBLE이 납니다.
2. **열람 범위 문구가 낡음**: `T.noView`·`noViewShort`(:46~47)가 지금 서버 규칙과 다릅니다. 서버는 영업팀장이 모든 상태를 보고, 중단 건은 옛 담당자도 봅니다. 또 `errorInfo`가 status 404면 모두 이 문구라서, 쓰기 동작의 404(첨부 없음 등)에도 "상세는 담당자·영업부장만…"이 나옵니다.
3. **경과 팝업 억제 조건이 넓음**: `app.js:818`의 `homeIsDash`는 역할과 본체가 있는지만 봅니다. 현황판이 실제로 열렸는지는 보지 않습니다. 다음 경우 현황판도 안 열리고 경과 팝업도 뜨지 않습니다.
   - `/menus`가 실패해 map 키가 꺼진 경우
   - 같은 페이지에서 다시 로그인했는데 지도 말고 다른 탭이 이미 열려 있는 경우(`homeItemId` null)
4. **마지막 탭 닫힘 폴백**: 현황판 규격 §6-D 5는 마지막 탭을 닫으면 현황판으로 가라고 합니다. 그러나 `closeNavTab`(`app.js:651`)은 아직 지도로 갑니다. 다른 세션 범위라 공존 확인만 했습니다.
5. **팝오버 Esc 포커스**: 마우스로 연 뒤 [제안 확정]을 누르면 포커스가 [확정하기]로 들어갑니다. 이때 Esc를 누르면 `_popOpener`가 null이라 포커스가 body로 빠집니다(`render.js:634, 745~753`). 또 [편집] 모달이 열린 채 Esc를 누르면 문서 핸들러 둘이 모달과 팝오버를 함께 닫습니다.
6. **되돌릴 수 있는 동작인데 확인 없음**:
   - [신청 회수]가 한 번 클릭으로 바로 회수됩니다.
   - 기획승인 뒤 [완료 취소]는 확인 줄을 거치는데, 같은 효과(T3 완료가 풀림)를 내는 [확정본 해제]·다른 파일 지정은 확인 없이 진행됩니다.

8. **필드 형식 제각각**: `emp_verified`가 상세 view에서는 int(0/1), 첨부·이력에서는 boolean입니다. 화면은 `===0`과 `===false`로 각각 맞춰 두었지만 계약이 들쭉날쭉합니다.
9. **탭 접근성**: `#pp-tabs`가 role=tab인데 `aria-controls`나 tabpanel이 없습니다.

**문제 없음으로 확인한 것**

  - 팝오버 출처 링크는 http(s)만 걸고 esc합니다.
  - `logic.esc`가 따옴표까지 바꾸므로 aria-label 속성도 안전합니다.

- **로드 순서**: script가 team → prep → kb-verified → dashboard → … → render → app 순입니다. 현황판 CSS 블록과 겹치는 선택자는 보지 못했습니다.
- **nav 기대값 9곳**: nav.js의 `withKey:'map'`·`front` 정의와 맞습니다. 다만 둘러보기·타 팀·파일 모드에서도 입찰 현황판이 보이는 것을 테스트가 굳히고 있습니다(열린 질문 1).

## 4. 테스트 공백과 추가 제안
- `pastOpenLine`:
  - `{open_request:{status:'REJECTED'}, past_open_requests:{count:1,last_status:'REJECTED'}}` → 요약 줄이 나와야 합니다.
  - `open_request.status:'APPROVED'` + past count 2 → 요약 줄이 나와야 합니다.
  - `prep.test.js:293`의 기대값도 고쳐야 합니다.
- `attachActions`(또는 `filesHtml`)에 건 상태를 넘겨 CANCELLED + 영업팀장 → `voidIt:false`.
- `filesHtml`에 T4 행을 섞어 넣으면 → 표에 나오지 않아야 합니다.
- `errorInfo(404, {}, [], 'attach')`가 열람 문구가 아닌 문구를 내야 합니다.
- 첫 화면: 영업 역할이고 본체가 있지만 `homeItemId`가 null인 경우 → `overdue.onLogin`이 불려야 합니다. 지금 app.js 검사(`prep.test.js:82`)는 소스 문자열 대조라 구현 세부에 묶여 있어서, `homeIsDash` 판정을 순수 함수로 빼서 검증하길 권합니다.
