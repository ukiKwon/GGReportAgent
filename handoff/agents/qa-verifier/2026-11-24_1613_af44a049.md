## 3. 발견 목록

**문제 없음으로 확인한 것**
- 범례·ResizeObserver 루프 없음: `_legendFor`가 innerHTML을 바꾼 직후 offsetHeight를 읽어 lastH를 맞춘다(render.js:125, 162~165). 그래서 다음 프레임 RO 콜백은 `h === lastH`에서 바로 끝난다(127행). RO가 다시 그려도 범례 내용이 같아 높이가 그대로이므로 수렴한다. drawRegion·drawNational 모두 랭킹 패널 표시와 overdue.syncLayout을 먼저 확정한 뒤 범례를 바꾸고(585~588, 251~255) 그다음 폭을 잰다. 순서가 맞다.
- 전국 복귀 시 줌 복구: drawRegion이 `svg.on('.zoom', null)`로 wheel·mousedown·dblclick·touch 리스너를 뗀다(592). drawNational은 `render._zoom`을 새로 만들어 `svg.call`로 다시 걸고 identity로 맞춘다(347~351). flyZoomTo는 전국에서만 불린다.
- 마커 투영: `render._regionProjection = proj`(fitExtent 결과)를 drawMarkers보다 먼저 대입한다(650~651). drawMarkers(788)·_drawRipple(1150)·sub-glyph(path)·카드 앵커(path.centroid)가 모두 같은 proj를 쓴다. 따로 계산하는 곳은 없다(grep: fitSize·fitExtent는 261·603·604행뿐).
- 카드 클릭 = 면 클릭: 둘 다 `render.onSubregionClick(d, ev)`이고 d도 같은 feature다(byCode). 카드가 붙는 면은 기관이 있어 rec이 null이 아니다. stopPropagation이 걸려 document의 '빈 곳 클릭' 해제와 부딪히지 않는다.
- 선택 연동: `_blinkSubRegion`·`_blinkMunicipality`가 `_cardSelect()`를 부른다. 수원처럼 한 기관이 여러 구에 걸리면 그 카드 4장이 모두 선택된다. `clearSelection`은 `g.sub-card.selected`를 푼다(1035). 필터 변경과 RO로 다시 그릴 때는 DOM이 새로 만들어지고 호출부가 다시 선택하므로 남는 강조가 없다.
- 이스케이프: 카드 이름·안내는 모두 `.text()`(textContent)다. 범례 innerHTML은 상수와 `logic.esc`만 쓴다. `#map-svg:focus`의 outline 제거는 svg에 tabindex가 없어 키보드 손실이 없다. 면 포커스는 `.ring-focus`가 그린다.

**P2**
1. **드릴인 중 창 크기를 바꾸면 카드가 옛 폭 그대로 남는다.**
   - 근거: overdue.js:462~469의 resize 처리는 `shouldRedraw(…, isDrilled())`가 드릴인이면 false라(147~148) 다시 그리지 않는다. svg에는 viewBox가 없다(index.html:3182). 범례 줄바꿈이 바뀌어 높이가 달라질 때만 RO가 우연히 drawRegion을 부른다(render.js:126~133). 그래서 결과가 들쭉날쭉하다.
   - 영향: 예전 fitSize 지도는 가운데 쪽에 있어 덜 티가 났다. 이제 오른쪽 열 카드는 x = w−128에 고정되므로, 창을 줄이면 그대로 잘려 사라지고 넓히면 가운데로 떠 보인다. 규격 ③-9 "크기가 바뀌면 지금처럼 drawRegion을 다시 그린다"와도 다르다.
   - 재현: ① 1440px에서 서울로 드릴인한다. ② 창 폭을 1100px로 줄인다. 범례 높이가 그대로이면 다시 그려지지 않는다. ③ 오른쪽 카드 열이 판 밖으로 잘린다. 기대 결과는 카드가 새 폭에 맞춰 다시 배치되는 것이다.

**P3**
2. **카드가 그려지지 않아도 범례는 카드 설명을 보인다.** 판 폭이 `w < 2*148+240 = 536`이면 카드가 없다(601). 이때 범례는 이미 드릴인용 '카드: …' 줄로 바뀌어 있고(588), ▲n 라벨도 지워져 있다. 좁은 화면에서는 시군구별 숫자가 아예 없는데 범례만 카드를 설명하는 셈이다.
3. **회색 면에서 카드 앵커 점이 ⚠ 글리프를 덮는다.** 공고 중(결과 대기)이나 경과 기관만 있는 면은 dated=0이라 band가 gray가 되면서(logic.js:575·581·594) 동시에 카드 대상도 된다. 그러면 앵커 점(r 2.5, 686행)이 같은 centroid의 ⚠ 글리프 위에 그려져 느낌표를 가린다.
4. **지자체를 끄면 카드 층 전체가 opacity 0.25로 흐려진다**(578·676행). 그런데 카드 숫자에는 켜 둔 다른 종류 기관도 들어 있고, 끈 지자체도 여전히 포함된다(municipalityForFeature가 켬·끔을 보지 않음). 범례의 '켠 종류 모두'와 어긋나고 12px 글자의 대비도 떨어진다. 디자인 이관 2번이 아직 열려 있다.
5. **넘침 안내 문구가 규격과 다르다.** 구현은 '카드 밖 면 n개 / 마우스를 올리면 / 보입니다'(711행)이고, 규격은 '카드 밖 n곳 — 면에 마우스를 올리면 보입니다'다. 면 수를 세니 '개'가 맞을 수 있지만, 팀이 정한 단위 '곳'과 다르므로 확인이 필요하다.
6. **카드 열 높이를 확인하지 않는다.** `withCards`는 폭만 본다. h가 아주 작으면(약 100px 이하) `limitOf − top`이 음수가 되어 카드가 모두 빠진다. 안내 y도 `h−12−45`로 왼쪽 top 48보다 위가 되어 breadcrumb와 겹친다(logic.js:671~673, 703). 실제로 그런 높이가 나올 가능성은 낮다.
7. **'6개월 안(추정)' 줄과 두 자리 수가 맞닿을 가능성이 있다.** 추정으로 라벨은 x=9에서 약 78px로 87 근처에서 끝나고, '12곳'(mono, 끝 정렬 114)은 88 근처에서 시작한다. 측정하지 못했으니 화면에서 확인해야 한다.
8. **키보드로 포커스한 면에서 마우스가 나가면 카드 강조(hl)가 포커스가 남아 있어도 풀린다**(mouseleave.card, 719행). 작은 일관성 문제다.
9. **테스트가 구현 모양에 묶여 있다.** map-subcard 190행은 drawMarkers 다음 줄에 `if (withCards) render._drawSubCards(`가 오는 줄바꿈 형태를 정규식으로 요구한다. 189·191행도 변수 이름(S.G, S.TOP_R)에 묶여 있다. 동작이 같은 리팩터링에도 깨진다.

## 4. 테스트 공백과 추가 제안
지금 테스트는 순수 함수와 소스 정규식뿐이고 DOM 동작 검증이 없다. 추가 제안(입력 → 기대값):
- `_cardSelect` + `clearSelection`: 가짜 d3·DOM에서 path.subregion[data-code=X].selected를 만든 뒤 `_cardSelect()` → g.sub-card[X]만 .selected. 이어 `clearSelection()` → .selected 0개.
- 카드 클릭 동등성: `_drawSubCards`의 카드 click → onSubregionClick 스파이가 면 click과 같은 feature로 불림. selectInstitution 결과 `_selectedName`도 같아야 한다.
- 범례 동기화: 가짜 ResizeObserver에서 `_legendFor('drill')` 뒤 같은 높이로 콜백 → drawRegion·drawNational 호출 0회. 다른 높이 → 80ms 뒤 1회.
- 줌 복구: drawRegion 뒤 svg의 `.zoom` 리스너 없음 → drawNational 뒤 wheel.zoom 다시 있음.
- withCards 경계: w=535 → 카드 층 없음·fitSize, w=536 → 카드 층 있음·fitExtent.
- 위 2번 결정이 나면: w<536 드릴인에서 범례 카드 줄의 표시 여부.
- layoutSubCards h 하한: h=120에 카드 3장 → 안내 y가 top 이상(또는 안내 생략).
- 드릴인 resize: 창 폭 변경 → 카드 x가 새 w−128.
