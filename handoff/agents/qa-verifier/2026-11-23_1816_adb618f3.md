## 3. 발견 목록
**P2-1 `showWait`가 페이지 전체를 스크롤한다** (`dashboard.js:1609`)
- 코드: `g.scrollIntoView({ block: 'start' })`. scrollIntoView는 조상 스크롤 영역을 모두 움직인다.
- `#db-root`는 띠 + 막대 + 목록(높이 100vh-140)이라 화면보다 길다. 그래서 바깥 탭 영역까지 스크롤돼 `#db-g0w`가 화면 맨 위에 붙는다. 그러면 누른 띠, 목록 머리(탭·검색), 막대가 화면 밖으로 밀린다.
- 비교: `db-nb-more`(1707)와 `db-kq-find`(1729)는 `block:'nearest'`를 쓴다.
- 재현: 화면 높이 800 정도에서 선정 결과 대기가 있는 데이터로 엽니다 → 띠 [선정 결과 대기 n곳 보기]를 누릅니다.
  - 기대: 목록(`#db-scroll`) 안만 스크롤된다.
  - 실제(추정): 페이지 전체가 내려간다.
- 수정안 후보: `#db-scroll.scrollTop = g.offsetTop - 목록 첫 위치`로 목록 안만 움직이고, 페이지는 `nearest`로 둔다. 실측이 필요하다.
- 테스트가 `block: 'start'`를 정규식으로 못박고 있다(`kind-queue.test.js:107`). 고칠 때 그 테스트도 같이 바꿔야 한다.

**P2-2 지도 지역 툴팁 안에서 '선정 결과 대기' 숫자가 위아래로 다르다** (`render.js:468` vs `:495-496`)
- 머리 줄: `선정 결과 대기 rest.length` = 마감 지남(awaiting) + 마감일 미확인 30일 초과(late).
- 꼬리 줄: awaiting은 '마감 지난 공고 n곳', late만 '선정 결과 대기 n곳'.
- 예: awaiting 1 + late 1인 지역 → 머리 "선정 결과 대기 2", 꼬리 "마감 지난 공고 1곳·선정 결과 대기 1곳".
- 수정안 후보: 꼬리를 `info.awaiting + info.late`로 합쳐 같은 이름으로 쓴다. 아니면 꼬리의 late 이름을 다른 말로 바꾼다(문구는 기획이 정할 일).

**P2-3 지도 팝업의 금고 약정 편집 단계(merged 절)**
- 원인: [금고 약정 고치기]는 이제 절 머리(`bankcontract.js:285`)에 있고, 편집 묶음은 여전히 `.bk-foot` 자리에 꽂힌다(`dashboard.js:1806-1807`).
- (a) 편집하는 동안 머리의 [금고 약정 고치기]가 그대로 보인다. 눌러도 아무 일이 없다(`dmBankEnter` 첫 줄 guard에서 끝남).
- (b) 입력 묶음이 은행 줄 바로 아래가 아니라 약정 기간 → 지난 금고 선정일 → 운영 상태 → 출처 details 뒤, 절 맨 끝에 나온다.
- (c) `.is-editing` 왼쪽 막대가 기관 정보 절 전체에 걸린다.
- 재현: 팝업 → [금고 약정 고치기] → 입력 묶음 위치와 머리 버튼을 확인한다.
- 수정안 후보: 편집 중(`c.editing`)에는 머리의 `#bk-edit`를 숨긴다. 꽂을 자리는 은행 dl 바로 뒤에 별도 표지로 둔다. 문서 쪽 거의 공용 구간이라 디자인 확인이 필요하다.

**P3**
- `bankcontract.js:263`: `dl.replace(/<\/dl>$/, rows + tail + '</dl>')`. 치환 문자열에 `$&`·`` $` ``가 들어 있으면 치환 패턴으로 해석된다. 이번에 tail(운영 상태·날짜)이 추가돼 범위가 넓어졌다. 데이터는 이미 이스케이프돼 있어 XSS는 아니고 글자가 깨지는 정도다. 수정안: `function(){return rows+tail+'</dl>'}`.
- 막대 넘침: `.kq-s`는 `flex:none; min-width:28px`이고 `.db-kq-bar`에는 overflow 제어가 없다. 좁은 폭(@media 1969)에서 4구간 줄이 숫자 칸(48px)을 덮을 수 있다. 실측이 필요하다.
