**판정: 조건부 통과.** 코드 자체는 안전한 편이다. 장부가 깨져 있거나 형식이 다르면 쓰지 않고, 임시 파일에 쓴 뒤 바꿔치기(rename)하며, 쓰기 전에 잠금을 잡는다. 정렬 변경도 회귀가 보이지 않는다. 다만 아래 P1 두 건이 실제 운영에서 장부를 어지럽힐 수 있다.

**대상·방법·못 본 것**: `.claude/hooks/capture-questions.js`, `agent-dashboard/test/capture-questions.test.js`, `.claude/settings.json:65-78`, `.gitignore:104-105`, `agent-dashboard/fmt.js:32-40`, 현재 `handoff/questions.json`을 읽었다. 패널은 열지 않았고 실행·시간 측정도 하지 못했다. 96 pass는 메인 보고를 그대로 옮긴 것이다.

**발견**
- **P1 이중 기록**: `CLAUDE.md:53`에 아직 "메인이 기록(물으면 open 추가)"이 남아 있다. 중복 판정은 요약 글자가 똑같을 때만 걸린다(`capture-questions.js:116,128`). 메인이 쉬운 말로 다시 쓴 손 기록과 훅이 원문으로 뽑은 기록은 글자가 달라서 질문마다 2건씩 쌓인다.
  - 재현: 🙋 블록으로 묻고, 같은 턴에 장부에 손으로 추가한 뒤 턴을 끝낸다 → 같은 질문이 2건 생긴다.
- **P1 마지막 답변 누락 가능성**: Stop 훅이 돌 때 이번 턴 마지막 답변이 아직 대화 기록 파일에 안 써졌을 수 있다(미확인). 메인의 dry-run은 '이전 턴'을 읽었으므로 이 점을 증명하지 못한다. 놓치면 다음 사용자 입력에서 수집 범위가 초기화돼(`:90`) 그 질문은 영구히 빠진다. Stop 입력에 마지막 답변 필드가 있는지 Claude Code 버전에서 확인해야 한다.
- **P2 AskUserQuestion 상태**: 사용자가 같은 턴 안에 이미 답한 질문도 `status:"open"`, `answer:""`로 들어간다(`:97`, `:131`). 사용자의 답은 같은 턴의 tool_result 안에 이미 있는데, 그걸 쓰지 않는다.
- **P3 오탐·누락**
  - 줄이 `**🙋 물어볼게:**`처럼 굵게로 시작하면 빠진다.
  - 이모지 뒤에 변형 문자(U+FE0F)가 붙은 `🙋️`도 빠진다(`HEAD :7`).
  - 본문 줄이 "🙋 물어볼게 블록을…"으로 시작하면 질문으로 잘못 잡힌다.
  - 머리줄과 같은 줄에 글을 붙이면 아래 목록은 버려진다(`:44`).
  - `1.`이나 `*`로 쓴 목록은 첫 줄만 잡힌다(`:51,54`).
  - 중복 판정이 done 상태 질문까지 포함해서, 똑같은 질문을 다시 물으면 추가되지 않는다.
- **P3 장부 쓰기**
  - 메인의 손 Edit은 잠금을 거치지 않는다. 다른 세션의 훅과 겹치면 한쪽 변경이 사라질 수 있다.
  - 오래된 잠금 파일을 두 훅이 동시에 지우면 둘 다 잠금을 잡은 것으로 될 수 있다(`:165`). 드문 경쟁이다.
  - rename이 실패하면 `.tmp` 파일이 남는다(gitignore 대상이라 git에는 안 올라감).
- **확인됨**
  - 줄바꿈 혼재: LF·CRLF 모두 원래 줄바꿈을 유지한다(`:134`).
  - 장부를 다시 파싱해 건수를 맞춰 본 뒤에만 쓴다(`:140`).
  - 정렬은 날짜가 최근인 것이 위, 같은 날이면 번호 큰 것이 위다. 현재 장부에 있는 `-08`이 `-06`보다 앞에 적힌 경우도 표시 순서상 문제없다. `qSplit`을 쓰는 곳은 `app.js:1148` 하나다.

**테스트 공백**
- 시험이 CRLF 장부만 쓴다. 지금 실제 장부는 LF인데, LF 장부에 추가하면 LF만 유지되는 경우를 시험해야 한다.
- 굵게·이모지 변형 입력, AskUserQuestion에 답(tool_result)이 붙은 경우, 잠금 파일이 이미 있을 때 3초 뒤 0 반환하는 경우가 없다.
- 실제 대화 기록 모양(같은 답변이 블록 하나씩 여러 줄로 나뉘어 저장됨)을 쓴 시험이 없다.
