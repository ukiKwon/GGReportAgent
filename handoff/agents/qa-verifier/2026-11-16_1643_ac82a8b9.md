## 3. 발견 목록

**P2-1. 409 때 회차 닫힘이 롤백되는지를 시험이 입증하지 못한다**

- **근거**
  - `NoticeRoundApiTest` 는 클래스 단위 `@Transactional` 이다(:39). 그래서 서비스의 `@Transactional(REQUIRED)` 가 시험 트랜잭션에 합류한다.
  - `NoticeRoundService.java:163-172` 는 `closeRound` 를 실행한 뒤 ROUND_CHANGED 409 를 던진다. 운영에서는 이 닫힘이 롤백된다. 시험에서는 롤백 전용 표시만 붙고 UPDATE 는 남는다.
- **결과**
  - 시험 14(`:397-413`)는 롤백이 되든 안 되든 통과한다.
  - 응답의 `closed_round_seq` 가 운영에서는 1, 시험에서는 null 로 달라진다. 시험은 이 값을 보지 않는다.
- **현재 코드의 롤백 동작 자체는 맞다**: ApiException 이 RuntimeException 이다.
- **재현 절차**
  1. 시험 14 에서 409 직후 `SELECT CLOSED_AT FROM NOTICE_ROUND WHERE ROUND_SEQ=1` 을 단언해 본다.
  2. 기대: NULL(운영 의미). 실제: 시험 환경에서는 값이 있다.

**P2-2. 의견 개인정보 검사가 `Pii.scan`(엄격형)이라 구분자만 바꾸면 통과한다**

- **근거**
  - `NoticeRoundRules.java:178` 은 `Pii.scan` 을 쓴다.
  - 보안이 선례로 든 기관장 사유 칸(`HeadForbidden.java:212`)과 BoardMaterialService·PrepAttachInspector 는 `Pii.scanLoose` 를 쓴다. scanLoose 는 NFKC 정규화, 전각 숫자, `.`·`·`·연속 구분자 접기를 처리한다(`Pii.java:113-166`).
- **위험**: 이 표는 추가 전용이라 앱으로 지울 수 없다. 그래서 새어 들어가면 되돌리기 어렵다.
- **재현 절차**
  1. 영업팀으로 DELAYED 를 저장하되 의견을 `담당 010.1234.5678` 또는 `０１０-1234-5678`(전각)로 넣는다.
  2. 기대: 400 opinion. 실제(코드상 추정): 201 로 저장된다.

**P2-3. 회차 넘어감을 문자열 사전순으로 판정해서, LAST_BID 형식이 다르면 회차가 잘못 닫힌다**

- **근거**
  - `NoticeRoundRules.advanced`(파일 :68 근처)는 `c.compareTo(a) > 0` 로 판정한다.
  - LAST_BID 는 서버 어디서도 형식을 검사하지 않는다. CSV 반입(`InstitutionCsv.java:97-98`)과 편집(`InstitutionUpdateIn.java:63-65`) 모두 그대로 저장한다.
  - 예: 기준값이 `2024-07-24` 일 때 같은 날을 `2024-7-24` 나 `2024.07.24` 로 고치면 "뒤"로 판정된다.
- **결과**: 닫힌 회차는 되돌릴 경로가 없다. 판정이 목록에서 사라지고 그 기관이 '기록 없음'으로 다시 센다. 이력은 남는다.
- **재현 절차**
  1. 첫 저장 뒤 `UPDATE INSTITUTIONS SET LAST_BID='2022.10.18'` 을 실행한다.
  2. GET current 를 부른다.
  3. 기대: 같은 날이니 목록에 남는다. 실제: 목록에서 빠지고, 다음 저장 때 SOURCE_ADVANCED 로 닫힌다.

**P3**

1. **이력 잘림 표시**: `history` 의 `truncated = logs.size() >= 200`(:143)이라 정확히 200건일 때도 true 다. 또 회차 20개·이력 200건 상한이 서로 따로 걸려, 오래된 회차가 이력이 있는데도 `logs: []` 로 보일 수 있다.
2. **ROUND_CHANGED 문구**: 하나의 코드에 두 원인이 섞여 있다. 남이 먼저 첫 저장을 한 경우(시험 6)와 기관 자료가 바뀐 경우인데, 문구는 "기관 자료가 바뀌어 회차가 달라졌습니다"뿐이다(:172). 첫 경우에는 사실과 다르다.
3. **037 INSERT 블록 표식**: 표식이 `[INSERT 블록 — MySQL 037 과…` 다(MySQL 037:57, Oracle 037:67). 기존 쌍 시험이 찾는 `[INSERT 블록 시작` 관례와 달라, 쌍 시험을 붙이면 못 찾는다. 037 용 DdlPairTest 자체도 없다.
4. **서비스 안의 방어용 403**(:194-197): 진행 중 제안 409 보다 뒤에 있고, DENIED 행을 남기지 않는다. 정상 경로에서는 컨트롤러가 먼저 막으므로 영향은 거의 없다.
5. **관리자 403 시험 없음**: 관리자(8203417)가 저장하면 403 이라는 시험이 없다. 시험 머리 주석(:34)에 사번만 적혀 있고 쓰이지 않는다.

## 4. 테스트 공백과 추가 제안

| 제안 | 입력 | 기대값 |
|---|---|---|
| 롤백 시험(P2-1) | 트랜잭션이 없는 별도 시험 클래스 또는 `@Transactional(propagation=NOT_SUPPORTED)` + 정리 코드로: 첫 저장 → LAST_BID 를 넘김 → `{1,1}` | 409 ROUND_CHANGED, 회차 1의 CLOSED_AT 은 NULL 그대로 |

| 개인정보 우회(P2-2) | 의견 `010.1234.5678` · `０１０-1234-5678` · `010 - 1234 - 5678` | 각각 400 opinion |

| 관리자 저장 | POST, 관리자 8203417 | 403, DENIED 1행 |
| DDL 쌍(037) | InstPlanDdlPairTest 방식으로 두 파일 블록 비교 | 글자 그대로 같음, 13행 |
| 이력 경계 | 이력 정확히 200건 | `truncated` 가 기대대로 나옴 |
