## 4. 발견 목록
- **P2-1 결재(승인·반려) 직후 포커스가 body로 사라진다.**
  - 규격 §6-5는 다음 카드의 첫 버튼, 없으면 '받은 결재' 탭으로 보내라고 한다.
  - 실측: 승인과 반려 두 번 모두 `document.activeElement = BODY`였다.
  - 원인 추정:
    - `frontend/js/approvals.js:581-582`가 `closeReview(msg)`에서 포커스를 옮긴 직후 `loadRequests()`를 부른다.
    - 응답 뒤 `paintRequests()`가 `approvals.js:420`에서 `#ap-tabs` innerHTML을 다시 써서, 포커스를 받았던 탭과 카드 버튼 노드를 갈아 끼운다.
  - 볼 곳: 포커스를 `loadRequests()` 완료 뒤로 옮기는 방식, 또는 탭을 다시 그리지 않는 방식.
  - 재현: 이영업 → 결재함 → 받은 결재 → [자료 보고 결재] → 의견 입력 → [반려] → `document.activeElement` 확인.
- **P3-1 틸 테두리 한 개 규칙 위반.**
  - 칸을 고쳐 "저장하지 않은 수정 1칸"이 생겨도 머리의 #bd-m-submit이 `bd-wb-main`으로 남는다. 작성 줄 [버전 저장]도 `bd-wb-main`이라 틸이 두 개가 된다.
  - 로직은 `board-material.js:489`(`dirty>0`이면 main 해제)에 있다. 원인은 셀 편집 때 머리가 다시 그려지지 않는 것으로 보인다(headActsHtml을 dirty 변경 시 호출하지 않음).
  - 덧붙여 확인 줄이 열리면 머리 [안건 제출]과 [버전 n 안건 제출]이 둘 다 틸이다.
- **P3-2 칸 오류가 고친 뒤에도 남는다.**
  - 의결 결과 폼에서 날짜 오류가 난 뒤 '가결'로 바꾸고 날짜를 넣어도 `#bd-m-ferr`와 `aria-invalid="true"`가 남는다(레이블 꼬리는 "(선택)"으로 바뀜).
  - 재작성 모달도 422 뒤 사유를 고쳐도 `#bd-m-rw-err`·aria-invalid가 남는다. 다음 저장이나 전송 때 사라지는지는 성공 경로에서만 봤다.
  - 볼 곳: input/change 핸들러에서 오류를 지우는지.
- **P3-3 조사 오류.** "개최일 2026-12-03**가** 지워집니다"는 날짜를 '삼일'로 읽으면 '이'가 맞다. 규격 §6-3 원문이 "{YYYY-MM-DD}가"라서 규격과는 일치한다. "개최일(2026-12-03)이"처럼 받침과 무관한 형태를 검토할 만하다.
- **P3-4 확정 해제 뒤 반환 배너가 확정 해제·결과 삭제 사실을 말하지 않는다.** 이미 디자인 규격 §7에 이관된 항목(`last_return.from_status` 미제공)이다. 이번 실측으로 다시 확인만 했다.
- **관찰(결함 아님)**:
  - 결재함을 처음 열면 받은 결재 1건이 있어도 기본 탭이 '내가 올린 요청'이다.
  - `#ap-flash`가 로그아웃 뒤에도 DOM에 앞 사용자 문구를 남긴다(보이지 않음). 다음 사용자가 결재함을 열면 비워진다.

## 5. 테스트 공백과 추가 제안
- **approvals 결재 뒤 포커스**: decide 성공 → `loadRequests` 완료 → 기대 activeElement가 `#ap-tab-inbox` 또는 다음 `.ap-review-btn`. P2-1 회귀 방지용이다.
- **headActsHtml dirty**: 셀 편집으로 dirty=1이 되면 → 머리 DOM의 #bd-m-submit에 `bd-wb-main`이 없어야 한다. 단위 테스트는 `headActsHtml(d,{dirty:1})`만 보므로, 다시 그리는 경로도 검증해야 한다.
- **결과 폼 오류 해제**: 오류 상태에서 select를 가결로 바꾸고 날짜를 입력하면 → `#bd-m-ferr`가 없고 aria-invalid도 없어야 한다.
- **재작성 모달 오류 해제**: 422 뒤 사유를 입력하면 → 오류가 지워져야 한다.
- 위 4건이 `frontend/test/board-material.test.js`·`approvals.test.js`에 있는지는 파일:줄로 확인하지 못했다. 호출자의 테스트 출력이 필요하다.
