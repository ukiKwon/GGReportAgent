### 2. web 계약 대조 (모두 일치)

**재현 (P2)**
1. 하드링크를 쓸 수 있는 NTFS 폴더를 plan-csv-dir로 설정한다.
2. 백신이나 색인기가 `.plan-upload-*.tmp`를 잡고 있게 한다. 테스트라면 `publish` 안의 tmp 삭제가 AccessDeniedException을 던지게 만든다.
3. `sample-gu_20261118_plan.csv`를 올린다.
- 기대: 저장 후 영수증 1행이 생기거나, 파일을 되돌린다.
- 실제: 화면은 "저장하지 못했습니다"인데 폴더에는 파일이 있고 영수증 행은 없다. 다시 올리면 "같은 이름의 파일이 이미 있습니다".

**대소문자 중복, 경로, 정리 순서는 문제없다**
- 대소문자 중복 검사는 락 안에서 목록을 훑은 뒤 공개한다. 같은 묶음 안에 대소문자만 다른 이름이 둘 오면 두 번째가 거부된다.
- 임시 파일은 finally에서 지운다. 남더라도 `.tmp`라 web이 무시한다.
- 하드링크 폴백(UnsupportedOperation, FileSystemException → move)은 JVM 락 아래에서 동작한다. 노드가 하나일 때만 보장된다는 점은 주석에 명시돼 있다.

### 4. 테스트 공백과 추가 제안
1. **tmp 삭제 실패**: 공개 성공 뒤 tmp 삭제가 IOException을 던지면, 저장 성공으로 처리해 영수증 1행을 남기거나 되돌려서 파일 0개가 돼야 한다. 지금은 시험할 수 있는 지점이 없다.
2. **폴백 경로**: createLink가 UnsupportedOperationException을 던지면 move로 공개돼야 하고, 대상이 이미 있으면 EXISTS로 거부돼야 한다. 지금 테스트(:100, :113)는 하드링크 경로만 본다.
3. **컨트롤러 테스트가 하나도 없다.** 추가할 케이스:
   - 빈 파일 파트 1개만 보냄 → `errorMessage`가 "파일을 선택해 주세요."
   - planCsvEnabled=false → 꺼짐 안내 문구가 보이고 입력칸 3개가 disabled
   - 켜짐일 때 저장 → planResults 표에 SHA 앞 16자가 보임
   - 기존 `/upload/proposal` 결과 화면에도 planCsvEnabled가 들어감(advice의 assignableTypes 회귀 방지)
4. **날짜 경계**: 지금은 20990101만 쓴다. `LocalDate.now(Asia/Seoul)` 날짜는 저장, 내일 날짜는 DATE로 거부, 20000101은 저장되는지 본다.
5. **기타**:
   - BOM이 붙은 UTF-8 → 저장
   - 같은 요청에 같은 이름 두 파트 → 첫째 저장, 둘째 EXISTS
   - 두 번째 업로드 → 영수증 머리줄이 반복되지 않음(행 3개 = 머리 1 + 데이터 2)
   - (선택) 기관ID 칸에 켈빈 기호 → 지금은 저장되는데, 의도인지 문서로 고정
