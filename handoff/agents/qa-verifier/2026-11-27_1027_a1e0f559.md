## 3. 발견 목록
**P2-1. 서버가 PREP_ACTIVE로 막으면 어느 기관이 막혔는지 이름이 빠지고, 제안 준비 자료도 다시 읽지 않는다**
- 근거: tchange.js:613이 `e.item.msg`(서버 공통 문장)만 돌려준다. errorOf(:279)가 만든 'n번째 ○○을 확인하세요'와 detail.bid_case_ids는 버린다. refresh:false라 kbboard.js:3452의 다시 읽기도 없다. 다시 읽더라도 loadGoals라 /preps는 갱신되지 않는다.
- 재현: 제안 준비 자료(/preps)를 받기 전이거나 받은 뒤에 다른 사람이 준비를 시작한 상태에서 3곳을 고르고 [목표 기관에서 제외] → 빼기.
  - 기대: 막힌 기관 이름, 또는 막힌 줄이 회색으로 바뀜.
  - 실제: '제안을 준비 중인 기관은 …' 공통 문장만 뜨고, 다시 눌러도 같은 409가 반복된다.
- 시험 bulk-confirm.test.js:89-91은 이 '이름 없음'을 정답으로 고정하고 있다.

**P2-2. 결재 승인 때 PREP_ACTIVE가 나면 결재자에게 '중단한 뒤 다시 하세요'라고 안내한다**
- 근거: replan(TargetChangeService:340·344)이 BidTargetService:92의 문장을 그대로 쓴다. approvals.js:271-275는 이를 'n번째 기관(이름): …중단한 뒤 다시 하세요'로 보여 주고, :699는 의견 칸으로 포커스를 옮긴다(반려를 권하는 흐름).
- 결과: 결재자가 진행 중인 제안 준비를 중단하라는 뜻으로 읽을 수 있다. 다른 409 문장(ITEM_CHANGED)은 '반려하고 다시 요청해 주세요'로 끝나는데 이것만 다르다. 요청 상태는 PENDING으로 남는다(시험 :351로 확인).
- 재현: 팀원이 제외 결재 요청 → 그 기관 제안 확정 → 팀장이 승인 → 카드 오류 문장 확인.

**P2-3. 기관 상세 팝업의 단건 [관심 기관으로…]는 미리 막지 않고 [제안 준비 화면으로 →]도 없다**
- 근거: openToWatch·toWatchState(kbboard.js:3492-3517, tchange.js:620-627)에는 prepBlockOf 판정이 없다. 결재 모드에서는 사유를 다 쓴 뒤에야 서버 409 공통 문장을 받는다(toWatchError → bulkErr).
- 사용자 결정 '막고 중단 안내 + 이동 단추'가 띠 경로에만 적용됐다. 범위에서 뺀 것이면 그 사실을 기록해야 한다.

**P3**
- P3-1. 이유 문장이 사실과 다를 수 있다.
  - 막힘 1곳 + 관심 줄 1곳: DEL_PREP는 '고른 기관이 모두 제안 준비 중'이라 하고 제목은 '— 2곳'이 된다(tchange.js:405·455·551).
  - 제외 창의 관심 갈래: 보낼 수 있는 줄이 모두 지난해 목표·결재 중이고 나머지가 막힘이면 wwhy가 TOWATCH_PREP '모두 제안 준비 중'으로 나온다(:470-478).
- P3-2. openPrepFromBulk(kbboard.js:3386)가 `restore:false`로 창을 먼저 닫는다. goPrep이 실패하면(can_view 거짓) 상태 줄 문장만 남고 포커스가 돌아갈 곳이 없다.
- P3-3. 꼬리표를 없애면서 목표 표의 '이월'·'되찾기 후보'가 눈에 보이지 않게 됐다. title은 td에만 붙어 키보드 사용자에게 보이지 않고, 화면낭독기 문장(sr)만 남는다(kbboard.js:970-982). 사용자 결정대로이지만 잃는 정보로 적어 둔다. '바뀜'은 점선(.draft)으로 여전히 보인다.
- P3-4. 주석이 낡았다.
  - index.html:2534 '등장 200ms 예외'인데 실제 값은 .36s.
  - :2256 'td.aim 92px 안에', :2285 '구분 열 166px', tchange.js:323 '146px'. 목표 표는 이제 128px.
- P3-5. 바로 반영 모드에서 창 제목은 '목표 기관에서 제외'인데 보내기 단추는 '빼기'다(tchange.js:568). 낱말 통일 범위에서 빠졌다.
- P3-6. PREP_ACTIVE 응답이 bid_case_ids를 돌려준다. 열람 권한이 없는 사용자(can_view 거짓)에게 건 번호가 노출되는지 security 확인이 필요하다.
- 확인한 것: 상태 집합 일치, 서버 차단 순서(잠금 → STALE → CHANGE_PENDING → PREP_ACTIVE), min-width 814 = 150+32+128+128+120+124+132, 선택자 우선순위(:not(.wt)가 166·92를 덮음), esc 적용(pnote·pq·rows), 꺼진 단추(aria-disabled + title + sr + 누르면 창이나 상태 줄), 전부 막힘 창(go disabled, 이유는 aria-describedby #tc-bd-q, 첫 포커스 [취소]).

## 4. 테스트 공백과 추가 제안
- 서버
  - 승인 시점 TO_WATCH: 요청 → BID_PREP OPEN_PENDING 삽입 → 승인. 기대: 409 PREP_ACTIVE, REQ PENDING 유지.
  - OPEN_PENDING·APPROVAL_PENDING 두 상태의 차단: 지금은 IN_PROGRESS·WRITING·CONFIRMED·WRITABLE만 덮는다.
  - 관심 줄 빼기는 막지 않음: WATCH 기록 + 활성 준비 → DELETE my-watch(또는 cancel). 기대: 성공.
- 화면
  - bulkError PREP_ACTIVE + item_no: 기대 문장에 기관 이름이 들어가야 한다(P2-1 수정 시 :89-91 기대값을 바꿀 것).
  - prepBlockOf가 st.prepSt 'loading'·'error'일 때 null을 돌려주는지 동작으로 시험. 지금 :87은 소스 문자열 indexOf다.
  - 지나친 결합: bulk-confirm.test.js:86-88, kbboard-rec.test.js:137(애니메이션 CSS 전체 문자열), kbboard-stages-1126.test.js:155가 소스·CSS 문자열에 묶여 있다.
