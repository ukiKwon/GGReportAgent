## 3. 발견 목록

**P2-1. ST·CS 도착 순서에 따라 '자료 없음'이 잠깐 보였다가 '사업계획 요청됨'으로 바뀝니다**
- **근거**
  - ensureStatus 518이 두 요청을 동시에 냅니다.
  - ST가 먼저 오면 onStatus → renderList 657에서 `collectOf`가 null(CS loading)이라 `자료 없음`을 그립니다.
  - CS가 도착하면 onCollect 845에서 `사업계획 요청됨`으로 바뀝니다.
- **영향**: 요청한 사람이 화면을 다시 열 때 잠깐 "요청이 사라졌나" 싶을 수 있습니다. 데이터 손상은 없습니다.
- **재현**
  1. 영업부서 계정으로 기관 하나를 [수집 요청]합니다.
  2. 다른 메뉴로 갔다가 기관 사업계획으로 돌아옵니다.
  3. 느린 네트워크(DevTools Slow 3G)에서 해당 행의 3행을 봅니다.
- **기대/실제**: 기대는 처음부터 '사업계획 요청됨'입니다. 실제로는 ST가 먼저 오면 '자료 없음'이 잠깐 보입니다.
- **어디를 볼지**: renderList의 `pending` 판정(657)이 `ST.state === 'loading'`만 봅니다. CS가 loading인 경우는 고려하지 않습니다.

**P2-2. 'new'와 '수집 실패/수집 제외'가 함께 보이는 조합이 실제로 생깁니다**
- **근거**
  - 서버 시험 425–438 '반입_뒤_다시_열린_요청이…EXCLUDED'가 이 상태를 일부러 만듭니다: 반입 후 재요청이 제외됨.
  - 이때 stateChipsHtml 238·241은 `사업계획 N건 · new · 수집 제외`를 그립니다(요청 가능한 사람의 목록과 상세).
- **영향**: "새 자료가 들어왔는데 수집은 제외됐다"는 칩이 나란히 붙어 해석이 갈릴 수 있습니다. 규격 6-1 표에 없는 조합입니다(frontend-dev가 다르게 정한 1번의 연장선).
- **재현(서버 허용 시)**
  1. 기관 A 요청 → 반입(APPLIED)
  2. 다시 요청 → 개발부서 처리 화면에서 '제외'
  3. 영업부서 계정으로 목록 A행을 봅니다.
- **기대/실제**: 기대는 정책에 따라 다릅니다. 실제는 칩 3개(`N건`, `new`, `수집 제외`)입니다.

**P3-1. 목록 3행은 '수집 실패/제외'를 서버 가드에만 의존합니다(상세와 비대칭)**
- 상세는 `closedReq = rq.can ? rq.closed : null`(326)로 프런트에서도 거릅니다.
- 목록 renderList 658은 `cc.closed`를 그대로 넘깁니다.
- 지금은 서버 264(`if (!canRequest) break`)가 디자이너에게 last_closed를 비우므로 실제 노출은 없습니다. 다만 서버가 바뀌면 목록에만 디자이너용 '수집 실패'가 새어 나옵니다.

**P3-2. `closed_at` 7일 판정을 프런트가 다시 확인하지 않습니다**
- CS는 STATUS_FRESH_MS 동안 재사용되므로, 탭을 오래 열어 두면 7일이 지난 'new'가 다음 재조회 전까지 남습니다.
- 다시 열거나 재조회하면 사라지므로 영향은 작습니다.

**P3-3. 시험의 'constructor' 단언이 진짜 위험을 가립니다**

## 4. 테스트 공백과 추가 제안
1. **renderList 결선이 시험되지 않습니다.** collectOf → rowHtml `{req, closed, isNew, pending}` 연결은 순수 함수 시험만 있습니다.
   - 제안: `applyStatus({items:[]})` + `applyCollect({can_request:true, items:[REQUESTED jongno], last_closed:[], recent_applied:[]})` 뒤 mount한 DOM(또는 소스 정규식)
   - 기대: jongno 행 `.pl-st`에 `사업계획 요청됨` 하나
2. **상세에서 can=false + closed FAILED.**
   - 입력: `detailHtml(view([]), {req:{item:null, can:false, closed:{status_cd:'FAILED'}}})`
   - 기대: `data-st="FAILED"` 없음(326 가드 고정)
3. **new + 닫힘 조합(P2-2).**
   - 입력: `stateChipsHtml({item_count:2}, null, {status_cd:'EXCLUDED'}, AP)`
   - 기대: 정책 결정에 따라 단언(지금은 칩 3개)
4. **서버: 디자이너 7일 경계 '아직 있음'.**
   - 지금은 `SALES2`만 7일 − 1분을 보고, 디자이너는 8일 '빠짐'만 봅니다.
   - 입력: CLOSED_AT = now − 7일 + 1분, DESIGNER로 조회
   - 기대: recent_applied에 기관이 있음(디자이너는 SQL since 자체가 7일이라 경계가 다른 경로)
5. **서버: 열린 요청 없이 반입(SEED·요청 없음)하면 recent_applied에 없음.**
   - 입력: ask 없이 importPlan
   - 기대: recent_applied에 기관 없음(onImported 588의 'open==null → return')
6. **P2-1 순서 시험.**
   - 입력: applyStatus 뒤, CS loading 상태에서 rowHtml 결선
   - 기대: 현재 동작('자료 없음')을 명시적으로 고정하거나, 고친 뒤 '빈 자리' 또는 '요청됨'
