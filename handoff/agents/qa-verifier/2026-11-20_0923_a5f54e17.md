### 3. 발견 목록

**P3-1. ① 포커스 복원: 다른 곳 포커스를 뺏는 경우는 사실상 없음**
- 복원 조건(plans.js:699)은 두 가지입니다.
  - 지금 포커스가 `pl-dl`이다.
  - `S.dlFocus`가 켜져 있고 포커스가 body이거나 없다.
- 사용자가 내려받는 중에 검색칸·목록·상세로 옮겼다면 activeElement가 body가 아니므로 복원하지 않습니다. 이어서 846에서 `S.dlFocus=false`가 되어 상태가 남지 않습니다. 시나리오로 확인했습니다.
- 남는 경우는 하나입니다. 내려받는 중에 사용자가 포커스 없는 영역(본문 글자)을 클릭해 body가 된 상태에서 완료되면 `pl-dl`로 돌아갑니다. `preventScroll`이라 화면은 튀지 않고 의도된 복원 범위라 결함으로 보지 않습니다.
- 메뉴 이동이나 재마운트 중 완료되는 경우도 봤습니다.
  - unmount 상태: `M=null`이라 renderFoot이 일찍 끝납니다(688).
  - 재마운트 뒤: 메뉴 버튼이 포커스를 가져 body가 아니므로 복원하지 않습니다.
- 계정 전환: `onProfileChange`가 `S=null` 뒤 새 S를 만들면, 옛 fetch의 `.then`(846)이 새 S의 dlBusy/dlFocus를 끕니다. 이건 이번 변경 전부터 있던 동작이고 해는 없습니다.
- 주석 하나가 동작과 다릅니다. 826 주석은 "키보드 포커스였으면"이라고 하지만, Windows Chrome은 마우스 클릭에도 버튼에 포커스를 줍니다. 그래서 마우스로 눌러도 복원됩니다. 동작상 문제는 없습니다.
- onCollect 860의 복원 줄은 renderFoot이 먼저 복원하므로 이제 중복입니다. 다시 focus해도 해는 없습니다(정리 후보).

**P3-2. S가 null일 때**
- `renderFoot`은 `!M`이면 return합니다(688).
- M이 non-null이면 S도 non-null입니다. mount가 S를 먼저 만들고(986) M을 넣고(995), onProfileChange는 S=null 직후 바로 unmount로 M=null을 만듭니다.
- 다운로드 완료 콜백은 `if (!S) return`이 있습니다(846). 691의 `S.q`도 같은 근거로 안전합니다.

**P3-3. ② 401 재시도가 쌓는 접근 이력의 무게: 가벼움**
- `refreshBadge`를 부르는 곳은 세 군데이고 타이머는 없습니다(전 frontend에 refreshBadge용 setInterval 없음).
  - onNavDrawn(566)
  - window focus(558)
  - 처리 동작 뒤 force(382·385·404·449, plans.js:911)
- 그래서 401은 "창으로 돌아올 때 60초에 최대 1회" 정도입니다. 분당 1회가 계속 쌓이는 구조가 아닙니다.
- 세션이 만료되면 사용자는 다시 로그인하게 되므로 지속 시간도 짧습니다.
- `/plan-collect/admin/status`는 `admin.require`만 거칩니다(PlanCollectController.java:88-91). 별도 감사 클래스에서 401을 따로 남기지 않으니 AccessLogInterceptor 일반 기록 1행입니다.
- 403 중단은 유지됩니다(548). 사번이 바뀌면 풀립니다(521).

### 4. 시험 공백과 추가 제안
- **①은 동작 시험이 없습니다.** plans.test.js:714-722는 소스 정규식이라 구현 문장 그대로에 결합돼 있고, 문장만 바꿔도 깨지고 동작이 틀려도 통과할 수 있습니다. 가짜 DOM(activeElement, `$` 대체)으로 동작 시험 3건을 권합니다.
  - activeElement=`pl-dl`에서 renderFoot → 새 `pl-dl`이 focus됨.
  - dlFocus=true, activeElement=`pl-q`, 완료 renderFoot → `pl-q` 유지(뺏지 않음), 이후 dlFocus=false.
  - dlBusy=true(disabled) 중 renderFoot → focus 호출 없음, dlFocus 유지 → 완료 후 focus.
- 결과가 0곳이 되어 버튼이 사라진 경우: renderFoot → `b` 없음 → dlFocus=false, 예외 없음.
- plancollect.test.js:491-494(소스 정규식)는 458의 동작 시험과 중복되고 구현에 결합돼 있습니다. 지워도 되는 후보입니다.
- ③은 plans.test.js:680-707이 동작으로 덮습니다. `applyCollectResult`로 `'__proto__'` 키를 넣고 지우는 경로는 ID_RE 때문에 닿지 않으므로 추가가 필요 없습니다.
