# QA 보고: 결재함 전원 노출 실화면 검증 (NEXT 62, 커밋 317e0b0·53564b2)

## 1. 대상, 방법, 못 본 것
- **대상**: http://localhost:8080 (이미 떠 있던 서버). 로그인한 계정은 sales.member(김영업), sales.lead(이영업), budget.member(정예산, 화면 표시 '재무팀', 저장값 '예산팀'), 둘러보기.
- **방법**: Playwright로 화면만 열어 봤다. 폭은 1440, 929, 880px. `getComputedStyle` 값을 직접 쟀고, `/menus`·`/approvals`·`/approval-requests/my-perms`는 GET으로만 불렀다. 저장·제출·승인은 하지 않았다.
  - 부수 기록이 남았다. 로그인·로그아웃 때 `/auth/login`·`/auth/logout`이, 화면을 열 때 `/auth/screen` POST가 나가서 접근 이력이 쌓였다.
  - 처음 열었을 때 브라우저에 마스터 세션이 남아 있어서 로그아웃하고 시작했다.
  - 끝난 뒤 브라우저는 둘러보기 상태, 1440px로 두었다.
- **못 본 것**
  - SQL은 실행하지 못했다. `SELECT ... FROM ROLE_MENUS WHERE MENU='approvals' AND ENABLED=0`은 돌리지 않았다. 대신 `/menus` 응답(저장값이 기본값 위에 합쳐진 결과)으로 확인했다.
  - 개인 권한 view=false가 반영되는지는 데이터를 바꿔야 해서 보지 않았다.
  - 서버·화면 테스트 출력은 받지 못했다. 테스트 실행 결과가 필요하다(5절).

## 2. 판정: 조건부 통과
로그인한 세 계정은 결재함이 사이드바에 보이고, 눌렀을 때 정상 화면이 나온다. 다만 둘러보기는 결재함이 보이지 않는다. 이는 코드·테스트가 의도한 동작(역할 없음이면 꺼짐)이지만, 이번 요청의 "4계정 모두 보임"과 다르다. 둘러보기를 '전원'에 넣을지는 기획이 정해야 한다.

## 3. 발견 목록
- **P2: 둘러보기는 결재함이 보이지 않아 "전원 노출" 요청과 다르다.**
  - 근거: `Menus.java:107`. 등록되지 않은 역할은 `FALLBACK_MENUS`(지도·지역별만)를 쓴다. `frontend/test/nav.test.js:72-76`도 둘러보기를 지도·지역별만으로 고정해 두었다. backend-dev 보고서(2026-11-09_1751)도 같은 내용을 기획 쪽으로 넘겨 두었다.
  - 재현: 로그인 화면 → '둘러보기' → 사이드바에 '제안서 관리' 대분류 자체가 없다.
  - 결함이라기보다 정책이 아직 정해지지 않은 상태다. 둘러보기에는 사번이 없어 결재함이 열려도 빈 화면만 나온다.
- **P2 (이미 알려진 위험을 화면에서 재현): 둘러보기 상태에서도 다른 역할의 결재 대기 목록을 볼 수 있다.**
  - 근거: 둘러보기 세션에서 `fetch('/approvals?role=영업부장')`가 200을 돌려줬다(지금은 항목 0건). security 1831 보고서의 '중' 위험과 같은 내용이다.
  - 재현: 둘러보기 → 콘솔에서 `fetch('/approvals?role='+encodeURIComponent('영업부장')).then(r=>r.status)` → 200.
- **P3: 880px에서 '준비중' 표시가 10×10 빗금 칩으로 줄어 테두리 대비가 낮다.**
  - 근거: `index.html:143-146`, 의도된 축소다. 칩 테두리 #424e62와 패널 #181e29의 대비가 약 2.0:1로, 그래픽 기준 3:1보다 낮다.
  - 그래도 항목 글자색 구분(#98a1af, 6.4:1)과 `.sr-only` '준비중' 읽기는 남아 있어 진행을 막지는 않는다.
- **P3: 둘러보기로 들어갈 때 `/menus?role=`가 두 번 나간다** (요청 #55·56, #107·108). 기능 영향은 없다.
- **P3: 콘솔 오류 2건, 둘 다 이미 알려진 것이다.** `img/login-bg.jpg` 404는 svg로 폴백하도록 의도된 것이고, 나머지는 `favicon.ico` 404다. 그 밖에 실패한 네트워크 요청은 0건이다.
- **참고 (범위 밖): 둘러보기 지도 화면에 '기관 추가', 'CSV 업로드' 버튼이 보인다** (`qa-1110-guest.png`). 서버가 막는지는 확인하지 않았다.

**사이드바 3단 구분 (항목 2) 측정값: 통과**
- 대분류: 14px·700, 색은 강조색 또는 fg.
- 소제목: 11px·700, #98a1af. 하위 항목이 활성화돼 있으면 fg로 바뀐다.
- 구현된 항목: 14px(880px에서는 13px)·400, fg 70% 혼합색 ≈ rgb(204,210,219).
- 준비중 항목: #98a1af. 패널 대비 약 6.4:1로 기준 4.5:1을 넘는다. 배지는 11px에 테두리가 있다.
- 소제목과 준비중 항목은 같은 색이지만 크기(11 대 14)와 굵기로 구분된다. 스크린샷 `qa-1110-sales-member-nav.png`, `qa-1110-sales-lead-approvals.png`에서 확인했다.
- 화면 전체에서 12px 미만인 글자는 11px인 nav-sub와 nav-soon-tag뿐이다(최소 11px 규칙 안). 결재함 안내 문장은 12px다.
- 929px과 880px에서 문서 scrollWidth가 화면 폭과 같아 가로 넘침이 없다. 가장 긴 라벨 '사내 업무 키워드 조회'도 오른쪽 끝 164px로 칩 시작 173px 전에 끝나 겹치지 않는다.

## 4. 테스트 공백과 추가 제안
- 서버: 역할 `''` 또는 모르는 역할 → `/menus` approvals=false. 둘러보기 정책이 정해지면 그 결과를 고정하는 테스트가 필요하다.
- 서버: ROLE_MENUS에 `approvals ENABLED=0` 저장값이 있음 → 그 역할의 `menusFor`가 false. 지금 덮어쓰기 경로를 확인하는 테스트가 있는지 확인이 필요하다.
- 화면: 880px 미만에서 `.nav-soon-tag`가 있는 항목마다 `.sr-only` '준비중'이 함께 있는지 검사하는 테스트를 제안한다.
