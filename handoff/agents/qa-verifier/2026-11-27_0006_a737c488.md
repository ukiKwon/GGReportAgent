### 코드 검토 결과(문제 없음)
- **굵기 범위**: 본문체 300–400 / 500–600 / 700–900은 겹침이 없다. 100·200은 Light, 800은 Bold로 간다.
- **경로**: 인라인 `<style>`의 상대 경로 `fonts/…`는 문서 URL 기준이다. `js/…`·`vendor/…` 스크립트 참조와 같은 방식이므로 `/ggreport/` 배포에서도 같이 맞고, 틀릴 때도 같이 틀린다.
- **배포 묶음**: `pom.xml:139-148`이 frontend/를 static으로 복사하고 fonts는 제외 대상이 아니다. WAR가 약 7.3MB 커진다.
- **정적 폴더 판정**: `fonts`는 이미 `StaticCacheFilter.STATIC_DIRS`에 있고, `LegacyFlowGuardApiTest:92-103`이 폴더 목록과 대조한다.
- **nosniff**: Content-Type이 비표준(`application/font-woff2`)이지만 Chrome은 글꼴에 MIME을 강제하지 않아 로드에 성공했다.
- **인쇄**: `@media print`는 390행 하나이고 글꼴 지정이 없다. 화면 글꼴을 그대로 쓴다.
- **13px 이하 되돌림**: 크기 13px 이하인 h3/h4 규칙 6곳은 모두 55–57행 목록에 들어 있다. 제목 안 400 요소(`.tm-n`·`.hc-m-sec .v`·`.hb-rec h4 .no`·`.rk-gh`)는 각자 `var(--mono)` 또는 `font:inherit`로 family를 덮어 안전하다. 본 화면 전수 스캔에서 "제목체인데 13.5px 이하 또는 굵기 500 미만"인 요소는 0건이다(숨은 DOM 포함). 기관 상세 `#hc-name`은 16px로 정상이다.

## 4. 테스트 공백과 추가 제안
- `kb-fonts.test.js`는 문자열을 정확히 일치시키는 방식이다(51행 `'h1, h2, h3, h4 { font-family:var(--font-display); }'`, 53행 정규식 순서). 공백이나 선택자 순서만 바뀌어도 실패하므로 구현 세부에 과하게 묶여 있다. 선택자 집합을 비교하는 방식을 권한다.
- 추가할 케이스(입력 → 기대값):
  1. CSS에서 `h1–h4` 또는 제목체 클래스 규칙 중 `font-size ≤13px`이거나 `font-weight:400|300|normal`인 선택자를 모은다 → 전부 57행 되돌림 묶음에 있거나 자체 font-family 또는 `font:`를 가져야 한다(발견 1을 막는 회귀 테스트).
  2. `frontend/fonts/` 파일 4개 → 존재하고, 앞 4바이트가 `wOF2`이고, 크기가 0보다 크다(@font-face url과 이름이 일치하는지 포함).
  3. `input, select, textarea { font-family:inherit; }`가 70행 `input[type=text]…{font:inherit}`보다 **앞**에 있고, 클래스로 `var(--mono)`를 주는 입력 규칙(353·3290·3299행)의 특이도가 0,1,1 이상이다.
