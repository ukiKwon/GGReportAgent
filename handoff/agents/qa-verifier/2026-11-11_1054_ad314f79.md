## 3. 발견 목록

**P2-1 C-4 NPV 칸: 업로드 직후 "-1.10", 저장 후 다시 열면 "-1.1"**
- **근거**
  - 이 칸은 dec·unit·paren이 모두 없다(`BoardDocSpec.java:1157` `f.vc("2,345")`, form 응답 `dec:null, unit:''`).
  - 그래서 `board-material.js:374` `mat.fmtOf`가 null을 돌려준다. 결과로 업로드 직후에는 엑셀 표시 글자("-1.10")를, 저장 후 다시 열면 서버 정규형("-1.1")을 그대로 보여 준다.
  - 같은 값이 B r2_c8에서는 dec=2라 "-1.10"으로 나온다. 같은 문서 안에서 표기가 엇갈린다.
- **재현**
  1. 김영업으로 노원구 2026을 열고 샘플 엑셀을 올린다. C-4 순현재가치가 "-1.10"으로 보인다.
  2. [버전 저장]을 누른다. 같은 세션에서는 여전히 "-1.10"이다.
  3. 새로고침해 다시 연다. "-1.1"로 바뀐다.
- **기대**: 저장 전후와 B/C-4가 같은 표기여야 한다.
- **확인할 곳**: C-4 r2_c1에 dec=2를 줄지, 정수로 둘지(샘플 문구 "2,345"). 업무 결정이 필요하다(이관 메모 참고).

**P3-1 개인정보 경고 상자가 칸을 고친 뒤에도 남는다**
- A r1_c0을 "노원구"로 되돌리고 다른 칸을 고친 뒤에도, 다음 저장 전까지 "개인정보로 보이는 값이 있어 저장하지 않았습니다…"가 계속 보인다.
- 재현: 4단계 422 → 칸 수정 → 경고가 그대로 남는다.

**P3-2 '확인 필요' 필터가 빈 상태로 남는다**
- 숫자 형식 오류로 막히면 '확인 필요' 필터가 자동으로 켜진다. 문제 칸을 고쳐도 필터가 유지돼 "확인 필요 0"과 표 6개 모두 "해당 칸 없음"이 보인다. 사용자가 [전체]를 직접 눌러야 돌아온다.

**P3-3 화면·서버 안내 문구가 실제 규칙과 어긋난다**
- 숫자 오류 안내 "괄호·△·단위·% 기호는 뺍니다"와 달리, 단위 칸은 "3.5년"처럼 자기 단위가 붙어도 받아 준다.
- 서버의 `_p`만 있는 경우 메시지는 일반 문구 "숫자 칸에는 숫자…만"이라 원인(앞 값 없음)을 알려 주지 않는다(`BoardMaterialService.java:759-767`). 일반 화면 경로에서는 생기기 어려운 경우다.

**참고(결함 아님)**
- 직접 입력 칸의 개인정보는 화면에서 미리 막지 않고 서버 422에 맡긴다. 결과적으로 막히므로 문제는 없다.
- 이전 P3-1("엑셀을 올리면 볼 수 있습니다" 안내가 남는 문제)은 이번에 따로 확인하지 못했다.

## 4. 테스트 공백과 추가 제안
- **표시 일관성**: dec=null·단위 없음 칸에 엑셀 표시 "-1.10"이 들어오면, 업로드 직후 `bw.cellText`와 저장본 재로딩 후 표시가 같아야 한다. 지금은 다르고, P2-1을 고치면 통과해야 한다.
- **천 단위 쉼표**: dec=2 칸 값 "1234.5"는 화면 "1,234.50"이고 저장값은 "1234.5"여야 한다. 괄호 칸 앞 값 "1234"·`_p` "56"은 "1,234.00 (56.00)"이어야 한다. 샘플 엑셀로는 확인할 수 없어 단위 테스트가 필요하다.
- **단위 칸에서 다른 단위**: `parseCell({unit:'년'}, "3.4개월")`은 ok=false, `"3.4 년"`은 main "3.4"여야 한다(공백 처리 확인).
- **서버 `_p` 경계**(통합 테스트 존재 여부 확인 필요): `_p`만 있는 경우 400과 cells r2_c5_p. 괄호 칸이 아닌 칸의 `_p`는 400이고 cells가 없어야 한다.
