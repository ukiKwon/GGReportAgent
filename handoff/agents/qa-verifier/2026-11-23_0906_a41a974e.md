## 3. 발견 목록
**P2-1 전산팀원이 [CSV 내려받기]를 누르면 "권한 없음(개발부서만)"이라는 틀린 문구가 뜬다**
- 근거: 서버는 `PlanCollectController.java:202-214`에서 팀장이 아니면 403과 `detail.code=LEAD_ONLY`를 돌려준다. 그런데 화면 `frontend/js/plancollect.js:424-433`의 `doCsv`는 응답 코드를 읽지 않고 `pc.errorText(403,'')`만 부른다. 그 결과 69행 문구 "이 화면은 시스템 관리 권한이 있는 개발부서만 씁니다(403)…"가 나온다. 누른 사람은 이미 개발부서다. 버튼도 `can_export`(컨트롤러 100행)를 쓰지 않아 늘 켜져 있다. 마스터 계정도 반출할 수 없게 됐다(`PlanCollectService.java:130-131`, A2 결정과는 맞음).
- 재현: 8080 서버에서 전산팀원 사번(예: 시험 ADMIN 8203417)으로 로그인 → 처리 화면에서 요청 선택 → [CSV 내려받기]. 기대: "목록 반출은 개발부서 팀장만 할 수 있습니다." 실제: "개발부서만 씁니다(403). 로그인 사번과 권한을 확인하세요."
- NEXT 56의 다음 걸음인 '반입 대기 파일' 절에 화면 보완이 잡혀 있다. 그 전에 war를 배포하면 이 혼란이 그대로 노출된다.

**P3-1 업로드 반입(/plans/import)도 '예전 판과 같은 파일'이면 409가 된다**
- 근거: `InstitutionPlanService.java:246-248`의 SHA 가드는 `ORIGIN_IMPORT` 전체에 걸린다. 그래서 `importUpload`(115행)도 영향을 받는다. SCHEMA ⑪-5(414행)에 이 동작이 계약으로 적혀 있으니 의도된 변경으로 본다. 영향: 예전 판 내용을 다시 올려 되돌리는 방법이 사라졌고(새 날짜로만 가능), 문구 "이미 반입된 파일과 같습니다"는 현재 판이 아닌 예전 판과 같을 때도 그대로 나온다.
- 이 경로의 시험이 없다. `InstitutionPlanApiTest:236`은 최신 판과 같은 파일만 본다.

**P3-2 같은 파일인데 폴더 확인과 반입의 상태 표시가 다르다**
- 근거: `inspect`는 날짜를 먼저 봐서 OLDER를 돌려준다(173행). `apply`는 SHA를 먼저 봐서 ALREADY를 돌려준다(242-248행). 예전에 반입했고 날짜가 이른 파일을 확인하면 OLDER, 반입하면 ALREADY로 나온다. 데이터 손상은 없다.

**P3-3 폴더 반입에서 기관을 찾지 못하면 감사 기관ID가 NONE이 아니라 원래 값으로 남는다(S9 일부 미적용)**
- 근거: `importFile` 133행에서 `canonicalId`가 실패하면 `instId`가 파일 이름에서 뽑은 원래 값 그대로다. 141행 `failed(instId,…)`가 그 값을 감사에 쓴다. 정규식이 걸러 주므로 주입 위험은 없다. 시험(`PlanInboxServiceTest:186-198`)은 TOO_LARGE 경로만 NONE을 확인한다.
- 재현: 폴더에 작은 정상 CSV `nosuch-x_YYYYMMDD_plan.csv`를 두고 반입 → `INST_PLAN_ACT`에 `OUTCOME='NOT_FOUND'`, `INSTITUTION_ID='nosuch-x'`가 남는다.

**P3-4 개시일 기록이 다음 해 3월처럼 늦을 때 104와 105의 판정 시점이 어긋난다**
- 근거: `TargetResultRules.java:42`는 `year < thisYear`이면 무조건 ended(미등록)로 본다. 105 `CarryRules.decide`는 개시일 전이면 보류다. 예: 목표 2026, 기록 개시일 2027-03-01, 오늘 2027-01-15이면 104는 '미등록', 105는 '보류'. 성공률 분모(성공+실패)에는 영향이 없고 분류 칩만 다르다. 설정 기본일(`carry_default_start`)이 01-01이 아닐 때도 같은 어긋남이 생긴다.

**P3-5 약정 시작이 연도만 있으면 개시일 기록과 연도만으로 귀속된다**
- 근거: `ResultYearRules.java:22`의 `d.startsWith(termFrom)`. termFrom "2027"이 기록 "2027-03-01"(목표 2026)과 맞으면 2026으로 센다. 기록이 없을 때는 `YEAR_ONLY_IS_JANUARY=false`라 세지 않는다. 그래서 "월을 모르면 추정하지 않는다"는 원칙과 조금 어긋난다. 이 부분은 cb8daa99에서 들어온 코드일 수 있다.

**P3-6 문서 표기 오류**: SCHEMA ⑪-1(337행)에 `GET /plan-collect/export.csv`라고 적혀 있지만 실제는 POST다.

**확인하고 문제없던 항목**
- 경로 안전: `readSafe`는 NOFOLLOW_LINKS로 속성을 읽고, 일반 파일인지·실제 경로의 부모가 root인지·이름이 같은지(대소문자 무시)를 본다. 읽기 중에 5MB를 넘으면 끊는다. 이름 정규식 때문에 구분자·`.`·`:`·`~`를 쓸 수 없다.
- 시간·동시성 상한: 시간 상한이 있고, 확인·반입이 같은 busy 플래그를 쓰며, finally에서 해제한다. 판을 쓸 때는 기관 잠금을 건 뒤 SHA를 다시 확인한다.
- 감사·접근 이력: 거부·꺼짐·BUSY·INVALID가 감사에 남고, 접근 이력에는 경로·이름이 실리지 않는다.
- 104 귀속: 약정 줄과 개시일 기록을 연도 제한 없이 모두 읽는다(`TargetResultMapper.xml:69-98`). 기록의 최신 행이 CANCEL이면 기록 없음으로 처리한다. 개시일 당일은 지난 것으로 본다(`!isBefore`). 기록이 없으면 기존 동작과 같다(`ResultYearRulesTest:16`).
- 105 이월 행의 영향:
  - 미달성 이월은 새 TARGET_NO, `KIND=GOAL`, `TARGET_YEAR=Y+1`, `ACTION=CARRY`로 생기고(`BidTargetService:558-563`), `isActive`가 Y+1 목표로 센다.
  - FAIL에서 만든 관심 행은 `KIND=WATCH`이고 연도가 NULL이라 Y+1 목표에 들어가지 않는다.
  - 작년(Y) 원천 행은 고치지 않으므로 Y년 결과가 그대로 남는다.
  - 자동 취소된 이월(CARRY_REVOKED)은 정정으로 보고 '뺀 곳'에서 뺀다(`TargetResultService:148-149`).

## 4. 시험 공백과 추가 제안
- 다음 1~3번은 이 PC(Windows)에서도 돌아가는 시험이다.
  1. 폴더에 `jongno_YYYYMMDD_plan.csv`라는 이름의 **하위 폴더**를 만들고 확인·반입 → 둘 다 `UNSAFE`. 링크 시험이 skip돼도 UNSAFE 경로가 실행된다.
  2. 확인 뒤 파일을 지우고 반입 → `GONE`, 감사 1행.
  3. `SCAN_BUDGET`보다 큰 누적(예산을 줄이는 시험용 생성자 필요) → 남은 파일 `NOT_CHECKED`.
  4. 업로드 /plans/import: 판 A → 판 B(같은 날짜) → 판 A 다시 업로드 → 409, 문구 MSG_SAME, 판 수는 2. (P3-1)
  5. 예전에 반입했고 날짜가 이른 파일 → 확인 결과와 반입 결과가 같은 코드인지. 현재는 OLDER/ALREADY로 갈린다. (P3-2)
  6. 폴더 반입에서 기관이 없는 경우 → 감사 `INSTITUTION_ID='NONE'`. (P3-3)
- 104·105:
  7. `TargetResultApiTest`에 INST_BID_TERM 통합 시험이 없다. 목표 2026, 개시일 기록 SAVE "2027-03-01", 국민은행 약정 2027-03-01 시작 → 2026 보고 SUCCESS, 2027 보고에서 빠짐. 같은 연도에 최신 행이 CANCEL이면 기존 규칙(2027 귀속).
  8. CARRY 행 통합 시험: Y 목표 UNREGISTERED와 새 번호 CARRY GOAL Y+1 → Y 보고는 원천 1건이 그대로 UNREGISTERED, Y+1 보고는 target_n에 1 포함. FAIL과 CARRY WATCH → Y+1 보고 target_n 0, removed 0.
  9. `ResultYearRulesTest`: 두 해의 기록 날짜가 **완전히 같을 때**("2027-03-01" 두 개) → 추정으로 간다. 지금 시험은 접두 겹침만 본다.
  10. 연도만 있는 termFrom "2027"과 기록 → 기대값을 정한 뒤 고정한다. (P3-5)
- 시험이 구현에 묶인 부분: `PlanInboxServiceTest:229-237`이 리플렉션으로 `busy` 필드를 바꾼다. 필드 이름을 바꾸면 깨진다. 지금은 큰 문제는 아니다.
