**회귀 질문에 대한 답**
- **합치기 409 때 반쯤 남는지**: 남지 않습니다. ITEM_LIMIT은 기각보다 앞에서 던집니다(:1217-1219). assignHead≠1이면 기각 뒤에 던지지만 `@Transactional`이 있고 ApiException이 RuntimeException이라 되돌려집니다. retireEmptyHead도 voidEmptyHead 실패가 기각보다 앞입니다.
- **상한 50**: 생년월일 제외 계산이 맞습니다(:1211-1216).
- **'BIRTH_DATE' 글자 노출**: 화면에 글자로 나오는 곳은 없습니다. data-f 속성과 option value에만 있고, 라벨은 fieldLabel을 거칩니다. 로그 사유 BIRTH_NOT_MOVED를 보여 주는 화면은 없습니다(frontend에서 grep 0건).
- **카드**: factsHtml이 날짜 3칸만 그리고 각주도 띠·날짜·학력·경력·사진뿐이라 생년월일은 나오지 않습니다(6-9 시험도 있음).
- **aria**: 생년월일 칸 aria 합치기(오류→안내 순)와 clearFieldErr 원복은 맞습니다. 이월 안내는 `hc-s4-hint hc-s4-carry`로 두 id가 다 있습니다.
- **2/29 상한**: 서버와 화면이 같습니다. 화면 birthMax(:204-209)와 서버 minusYears(18) 모두 2/28입니다.

## 4. 테스트 공백과 추가 제안
- 화면, P2-1: 생년월일 제출에 서버 400 `{code:'INVALID_DATE', message:'확인일은…'}` → 상단 상태줄에 나와야 하고 #hc-birth에 aria-invalid가 없어야 합니다. 지금 6-5·6-6(head-card.test.js:1382)은 생년월일 문구만 봅니다.
- 서버, P2-2: HeadTextTest 정상 목록에 "2020년 생활체육회장", "2019년 생명과학" 추가 → 통과해야 합니다.
- 서버: 합치기 상한 경계. 현 머리 열린 칸 49 + 매칭 후보(NAME 1, BIRTH 1) → 200 MERGED에 생년월일 REJECTED. 50 + NAME 1 → 409이고 생년월일은 CANDIDATE 그대로(기각 안 됨).
- 서버: confirmHead 경로의 retireEmptyHead(VOID_BY_CONFIRM). 빈 현 머리에 생년월일 후보가 있는 상태에서 후보 기관장 확정 → 생년월일 후보 REJECTED와 BIRTH_NOT_MOVED 로그 1건. 지금은 addHead 경로만 시험합니다.
- 서버: 경계값. requireBirthDate("1920-01-01", today) 통과, "1919-12-31" 400. 평일 today 기준 오늘-18년 당일 통과, 다음 날 400.
- 서버, P3-1: 사진 업로드 출처 이름에 '년생' → 정책을 정한 뒤 400 또는 201로 고정.
