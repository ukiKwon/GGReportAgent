### 4. 새로 찾은 문제

**N-1 (P3) 사번이 바뀐 뒤 기록 칸이 "불러오는 중입니다…"에서 멈춤** — P2-2 수정이 만든 결함입니다.
- **원인**:
  - `onRecChange`가 `recGuard`를 부르면 `st.rec`가 `recFresh('')`로 초기화됩니다(histSt 'idle').
  - 이어서 `repaintRec`만 부르고 `recSync`는 부르지 않습니다(1037–1042). 그래서 이력 요청이 나가지 않습니다.
  - `recViewHtml`은 histSt가 'idle'이면 'loading'으로 그립니다(1021).
- **재현(코드 추적, 화면 미확인)**:
  1. A(영업)로 입찰 공고 현황 탭에서 기관을 고릅니다.
  2. 로그아웃하고 B로 로그인합니다. dashboard가 다시 마운트되지 않는 경로에서 일어납니다.
  3. `ov.onLogin`이 `nrm.load()`를 부르고, 응답이 오면 `notify`로 `onRecChange`가 불립니다.
  4. 기대: B 기준으로 이력과 빈 폼이 보인다. 실제: "불러오는 중입니다…"가 그대로 남습니다.
  5. 목록에서 아무 기관이나 누르면 풀립니다(`recSync`의 id가 ''이라 다시 받음).
- **볼 곳**: `onRecChange`에서 `recGuard()`가 true를 돌려줄 때 선택된 기관의 이력을 다시 받는 경로가 있는지.

**N-2 (P3) NO_BID 필수 문구의 앞부분이 다름**
- 화면(noticerec.js 147): "입찰 없음으로 적을 때는 의견이 필요합니다. 왜 입찰이 없는지 적으세요."
- 서버(NoticeRoundRules.java 137): "입찰 없음(연장·지정)으로 적을 때는 의견이 필요합니다. 왜 입찰이 없는지 적으세요."
- 화면 검사가 먼저 걸리므로 사용자는 보통 화면 문구를 봅니다. 화면 검사를 지나 서버가 거부하면 서버 문구가 보입니다. 상태 라벨은 '입찰 없음(연장·지정)'입니다(test 151).

**N-3 (P3) current 요청이 실패하거나 10초 제한을 넘기면 영업팀에게도 "공고 상태는 영업팀이 기록합니다"가 뜸**

**N-4 (P3) `onLogin` 대기 중 사용자가 바뀌면 앞사람 기준으로 팝업 판정이 날 수 있음**

### 5. 남은 시험 공백
**순수 함수·모듈 시험(지금 넣을 수 있음)**
1. `nr.save` 헤더: confirmed가 true면 `X-Button-Id: save_confirmed`, false면 `save`, 그리고 `X-Screen-Id: bid_notice`. 가짜 fetch로 확인하는데, 여전히 0건입니다.
2. `ov.onLogin` 보류:
   - canLoad가 true면 false를 돌려주고 fetch는 1회만 불려야 합니다.
   - 응답 뒤 미처리가 0이면 팝업이 없어야 합니다.
   - 대기 중 세션이 사라지면 팝업이 없어야 합니다.
3. `ov.count`·`ov.waiting`: state가 loading이면 배지가 없고, 값이 `parts.pending.length`와 같아야 합니다. 직접 단언하는 시험이 없습니다.

5. noticerec.test.js 152줄 단언은 `a && b || c` 우선순위 때문에 사실상 c 하나만 검증합니다. 괄호를 넣어 정리할 후보입니다.
