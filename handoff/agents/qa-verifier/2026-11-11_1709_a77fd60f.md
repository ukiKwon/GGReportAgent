## 2. 판정
**조건부 통과**입니다. 순수 로직(기간 경계·later·moreHint·막대 칸)과 이스케이프, localStorage 허용 목록은 맞습니다. 다만 아래 P2 셋은 확인이 필요합니다: 사이드바 '기억'이 홈 자동 열림에 늘 덮어써지는 문제, 기간 넓히기 버튼의 포커스 유실, 약정 만료 기준 표기 불일치.

## 3. 발견 목록

**P2-1. 영업 계열은 사이드바 '마지막 상태 기억'이 로그인 때 전혀 보이지 않습니다**
- 근거 (app.js)
  - 135행 `paintNav`가 저장값을 복원합니다(801-805행, 예: 'manage').
  - 곧바로 141행 `applyHome` → `openNavItem(현황판)` → `showSoon` → `onTabChange('soon')` → `syncNavActive`(616행)가 돌고, `openOnNavigate`가 'scan'으로 덮어쓴 뒤 `rememberOpenCat()`으로 저장까지 합니다.
- 같은 부류의 덮어쓰기
  - 화면 이동은 무엇이든 저장합니다. 그래서 '기억'은 결국 "마지막으로 본 화면의 분류"와 같아집니다.
  - 로그아웃 때 797행에서 지도를 누르면 syncNavActive가 새 who('guest') 키에 'scan'을 저장합니다. 이 저장이 800행의 복원보다 먼저 일어납니다.
- 재현
  1. 영업팀으로 로그인합니다.
  2. '제안서 작성·관리'만 열어 둡니다(화면 이동 없이).
  3. 새로고침합니다.
  - 기대: 현황판이 열리면서 '제안서 작성·관리'가 열린 상태로 복원.
  - 실제: '기관·입찰 현황'이 열리고 저장값도 'scan'으로 바뀝니다.
- 사용자 결정과 이 결과가 맞는지 기획 판단이 필요합니다(이관 참고).

**P2-2. 기간을 넓히는 버튼과 '1년 뒤' 칸을 누르면 포커스가 사라집니다**
- 근거: dashboard.js 771행 `setWindow` → 693행 `renderStrip()`·`renderList()`가 `#db-tl`·`#db-scroll` innerHTML을 통째로 다시 씁니다. 그래서 방금 누른 `#db-widen`·`#db-tile-later`가 DOM에서 사라지고 포커스는 body로 떨어집니다.
- `db-clear`(766행)도 같습니다. 반면 `db-past`(765행)는 다시 포커스를 주는데, 패턴이 서로 다릅니다.
- 재현: 키보드로 [1년으로 넓히기]를 Enter합니다. 다음 Tab이 문서 처음부터 시작합니다.
- 함께 볼 것: `.db-tile.later.on`은 시각 표시만 있고 aria-pressed 같은 상태 전달이 없습니다(P3).

**P2-3. '약정 만료 기준' 추정 표기가 화면마다 다릅니다**
- 지도·팝오버는 `logic.formatBidDateLabel`(logic.js:195)로 "(추정·약정 만료 기준)"을 씁니다.
- 현황판은 다음 세 곳 모두 `it.label` = `confidenceLabel` = "추정"만 씁니다.
  - 목록 행: dashboard.js 285행
  - 상세 dd: 440행
  - 행 메타
- 상세는 '왜' 문구(436행)와 약정 주기 막대(402행)에서만 구분됩니다. 같은 기관이 지도와 현황판 목록에서 다르게 읽힙니다.

**P2-4. 공고는 있으나 확정되지 않은 기관에 '왜' 설명이 잘못 나옵니다**
- 근거: dashboard.js 435-437행. `basis==='notice'`이고 `confirmed=false`인 기관(contractEnd만 있음, '날짜 의미 확인 중' 기관 등)이 마지막 분기로 빠집니다. 그래서 "최근 절차일에 약정 주기를 더한 날입니다"가 나오는데, 사실과 다릅니다.
- 범례(324행)도 이 경우를 빼고 있습니다(P3).

**P3**
- 모두 닫기는 기억되지 않습니다. 닫으면 키를 지우고(store.js:166), 다음 `paintNav` 때 806행이 지금 화면의 분류를 다시 엽니다. 메뉴 권한이나 프로필이 갱신될 때마다 다시 열립니다.
- 사번 없는 계정은 navOpen 키를 공유합니다. 7자리 사번이 아니면 모두 `tbd.navOpen.guest`를 씁니다(store.js:155).
- 사용자를 바꿀 때 새 사용자에게 저장값이 없으면 앞 사용자의 openCat이 그대로 남습니다(801-806행).
- setWindow의 선택 해제 판정은 경과 묶음이 접혀 있어도(`pastOpen=false`) 경과 기관을 "보이는 것"으로 칩니다(690행). 검색·지역을 바꿀 때는 선택을 풀지 않아 목록에 없는 기관이 상세에 남습니다(791-794행, 기존 동작일 수 있음).
- mount 때 저장소가 막혀 기간이 '6'으로 돌아가면, 세션에 남은 st.sel이 기간 밖이어도 상세가 그대로 보입니다(798-801행에서 선택을 검사하지 않음).
- `expiryN`은 1년 안만 셉니다(64행). 범례의 "그중 약정 만료 기준 n곳"이 1년 안 기준이라는 점이 문구에 드러나지 않습니다.

**문제없음으로 확인한 것**
- MutationObserver
  - wireNav는 init에서 한 번만 불려(998행) 감시자 누수가 없습니다.
  - paintCatBadges는 값이 다를 때만 textContent를 씁니다. hidden 속성 변경은 감시 대상(childList)이 아닙니다.
  - paintNavBadge의 제거·재삽입이 감시자를 한 번 깨우지만 그 이상 이어지지 않아 무한 루프가 아닙니다.
- XSS
  - 새 innerHTML 조각은 모두 이스케이프되거나 숫자·고정 문자열입니다: 시간표, moreHint, termBar, periodHtml, groupLabel, 사이드바 chev·카운트.
  - srcItem href는 정규식으로 검사한 뒤 esc를 거칩니다.
  - toolIcon은 내부 상수 SVG입니다.
- localStorage 허용 목록: dashWindow는 4값만 받고 그 밖은 '6'입니다. navOpen은 `^[a-z]{2,20}$`를 거친 뒤 validOpen으로 다시 거릅니다. 테스트도 있습니다.
- later[]·'전체' 정확성
  - 1년 안과 1년 뒤의 경계는 365일이 1년 안, 366일이 1년 뒤입니다. windowItems('12')는 upcoming과 같습니다.
  - moreHint 구간이 맞고, 막대 13칸은 upcoming만 셉니다.
- 경과 칸: showPast가 목록을 펼친 뒤 listbox로 포커스·스크롤합니다(697-702행). 경과 목록이 비어 있으면 #db-past로 갑니다.
- 기간 변경 때 listbox 동기화: markSelected가 aria-activedescendant를 다시 정합니다.
- 다른 역할 회귀
  - homeItemId는 TEAM_ROLES만 대상이고, 마스터는 roleIn이 false입니다. 둘러보기(guest)는 그대로 지도입니다.
  - 관리자 메뉴 sys id 'sys'는 정규식을 통과합니다.
- render.js와의 간섭: dashboard는 render.REGION_NAME·ICONS·allInstitutions를 읽기만 합니다.

  - setWindow('12'→'6')에서 선택 기관 D-200 → 기대: st.sel='' 그리고 db-blank.
- nav-accordion.test.js:140은 app.js 소스를 정규식으로 읽는 테스트라 구현 세부에 결합돼 있습니다. 리팩터링 때 거짓 실패가 날 수 있습니다.
