### 4. 테스트 공백과 추가 제안
- `importDateChanged`를 직접 겨냥한 단위 시험이 없다(main 코드에서만 참조). 추가할 경우(입력 → 기대값):
  - 기존 null, 보낸 값 `"2026-10-29"` → true
  - 기존 `"2026-10-29"`, 보낸 값 `"2026-10-29"` → false
  - 기존 `"2026-10-29"`, 보낸 값 null → false
  - 기존 `"2026-10-29"`, 보낸 값 `""` → false
  - cur가 null → 보낸 값이 있으면 true
- inbox 반입 경로의 이력 시험이 없다(테스트에 `inbox_apply` 0건). 추가할 경우: 확정된 기관의 날짜를 inbox 배치로 바꾸면 확정 0, 출처 NULL, 이력 2행(`SCREEN_ID=inbox_apply`, `ACTOR_EMP_NO` NULL, `UI_VALID=1`).
- 공백 시험: PUT `{"contract_end":" 2026-10-29 "}`(기존과 같은 날짜) → DB에는 `2026-10-29`(P3-1). 지금 코드로는 실패할 것이다.
- 화면 시험: `frontend/test`에 편집 모달의 PUT 본문을 확인하는 시험이 없다. 날짜를 바꾸면 `contract_end_confirmed`가 함께 실려야 한다. 화면 대응 때 추가할 것.
- 반입 시험: CSV 반입에서 기존 `CONTRACT_END`가 NULL이고 날짜를 처음 채우는 경우 → 확정 0 유지, 이력은 `CONTRACT_END` 1행.
- 형식이 다른 옛 값(P2-2): DB에 `2026.10.29`가 있는 기관에 `{"term":3}`만 보내면 200, 지금 화면처럼 날짜도 같이 보내면 400. 이 동작을 고정하는 시험이 필요하다.
