## 1. 대상·방법·못 본 것
- 대상: 미커밋 '예상 공고현황' 변경. 코드는 frontend/js/logic.js(505–765)·render.js(20–470, 549–1110, 1239–1362)·overdue.js 전체, 화면은 index.html의 머리 줄·테마 창·#ov-pop, 시험은 map_expected.test.js 전체를 읽었다. 지운 이름이 남았는지는 frontend 전체에서 grep으로 찾았다.
- 못 본 것:
  - `git diff`는 돌리지 못했다(Bash 없음). 그래서 현재 파일 상태만 봤고, 변경 전부터 있던 문제와 이번에 생긴 문제를 일부 구분하지 못한다(P2-2).
  - Playwright는 쓰지 못했다. "Browser is already in use"가 나서 8080 지도 탭과 전국 지역별 탭의 콘솔 오류는 확인하지 못했다.
  - 시험은 직접 돌리지 못했다. 통과 판단은 메인이 준 결과(2045/2045)를 근거로 했다.

## 2. 판정
조건부 통과. 지운 필드나 함수를 다른 파일이 부르는 곳은 없다(런타임 오류 위험 없음). 다만 머리 줄의 이동 링크가 로그인이나 권한 변경 뒤에 따라 바뀌지 않는다(P2-1). 그리고 마커 색이 범례 구간과 맞지 않는다(P2-2).

## 3. 발견 목록

**P2-1. 머리 줄 '입찰 공고 현황' 링크(#map-out)가 메뉴 권한이 바뀐 뒤 다시 판정되지 않는다**
- 근거:
  - render.js:839–849 `paintMapHead`가 `noticeMenuOn()`(= `app.findNavItem(NOTICE_ID)`)으로 `out.hidden`을 정한다. 이 함수를 부르는 곳은 drawNational(260)과 drawTicker(851)뿐이다.
  - 메뉴는 app.js:243 onProfileChanged → applyMenuPermissions(비동기 fetch) → paintTabs:140 → paintNav에서 그려지는데, 이 경로에 paintMapHead가 없다.
  - enterApp(1057–1080)과 resetScreens → onTabChange('map')(76)도 applyWatchStyles만 부른다.
  - app.openNavItem(736–739)은 항목이 없으면 조용히 false를 돌려준다.
- 재현:
  - ① 로그아웃 상태에서 페이지를 연다 → ② 영업 계정으로 로그인한다 → ③ 지도 탭으로 간다. 기대는 '공고가 났거나 예정일이 지난 곳은 [입찰 공고 현황]'이 보이는 것이다. 실제로는 init 때 판정한 hidden이 남는다고 추정한다(드릴인 뒤 '← 전국'을 누르거나 종류 필터를 바꾸면 나타남).
  - 반대 경우: 영업 계정에서 로그아웃하고 디자이너·재무 계정으로 로그인하면 링크가 남는다. 누르면 아무 반응이 없다(죽은 단추).
- 화면에서 확인하지 못했다. 코드 경로로 추정한 것이라 사용자 확인이 필요하다.

**P2-2. 드릴인 마커 색이 새 범례 구간과 어긋난다**
- 근거:
  - render.js:790은 `markerColor(logic.urgencyOf(r))`이다.
  - urgencyOf는 computeUrgency(logic.js:89–96)를 쓰고 경계가 RED ≤182 / ORANGE ≤365 / YELLOW ≤730 / BLUE이다.
  - BAND_TO_MIX(render.js:58)는 red→r3, orange→r2, yellow→b2, blue→b3이다.
  - 그런데 범례(114–117)는 이제 r3='3개월 안', r2='3~6개월', p='6개월~1년'이라고 적는다.
- 결과:
  - 200일 남은 공공기관 마커는 r2 색('3~6개월')으로 칠해지지만 범례 기준으로는 p('6개월~1년')여야 한다.
  - 120일 남은 마커는 r3 색('3개월 안')이 된다.
  - p(보라)는 마커에 한 번도 나오지 않는다.
- 재현: 드릴인(예: 경기)에서 약정 만료가 6~12개월 남은 비지자체 기관의 마커 색을 범례와 비교한다.
- 원래부터 있던 매핑일 수 있다. 그래도 이번에 범례를 일수 구간 이름으로 바꾸면서 거짓 표기가 됐다.

**P3-1. 드릴인에서 공고 전 기관이 0곳인 면(공고 중·경과 기관만 있는 면)**
- 툴팁을 아예 달지 않는다(render.js:598의 `total > 0` 필터). 그래서 tipHtml:473의 '아직 공고 전인 기관이 없습니다' 갈래는 드릴인에서 쓰이지 않는다.
- tabindex와 role이 없어 키보드로는 닿지 않는다.
- 그런데 cursor는 `municipalityForFeature(d).length`(594–596) 기준이라 pointer로 보인다. 클릭하면 recordForFeature가 null이라 아무 일도 없다(1354).
- 전국에서는 같은 상태의 면도 툴팁을 띄우고 Tab으로도 닿는다. 그래서 두 화면의 동작이 다르다.
- 재현: 지자체가 공고 중인 시군구 면에 마우스를 올린다. 기대는 '아직 공고 전인 기관이 없습니다'이고, 실제로는 손가락 커서만 뜨고 아무것도 안 나온다.

**P3-2. overdue.js에 쓰이지 않는 코드가 남아 있고, 없는 DOM을 가리킨다**
- 운영 코드에서 부르는 곳이 없는데 남아 있는 것: `ov.listHtml`·`groupHtml`·`openItem`·`pickRefocus`·`openBtn`·`groupHead`·`HINT_WATCH`·`STATUS_TEXT`(63–141), `state.view/mode/open/opened`(19–22).
- `openBtn`·`groupHead`는 없어진 `#ov-list`를 찾고, `openItem`은 없어진 `#ov-toggle`을 fallback으로 넘긴다.
- 이 코드를 overdue.test.js:266–350·429–432와 noticerec.test.js:323–327이 계속 시험해서 살려 두고 있다. 누가 다시 연결하면 깨진 포커스 복귀가 그대로 살아난다.
- 낡은 주석: overdue.js:296("패널 제목으로"), app.js:883("'전국 지도' 옆"), app.js:1217("경과 패널").

**P3-3. 다른 파일의 문구가 바뀐 지도와 맞지 않는다(범위 밖, 이관)**
- prep.js:43·prepboard.js:44: "지역별 공고현황에서 공고가 난 기관을 고르고 [제안 확정]". 이제 지도에는 공고가 난 기관이 없다.
- dashboard.js:1607: "지역별 공고현황과 같은 기관". 이제 같은 기관 집합이 아니다.
- dashboard.js:1041·1786: 공고 중이거나 경과한 기관 상세의 [지역별 공고현황에서 보기]가 지도 탭만 연다. 그 기관은 지도에 없다.
- render.js:1413: 전국 지역별 카드의 '기관 n곳'은 공고 중·경과 기관도 센다. 지도의 '공고 전 기관 n건'과 숫자가 다르다.

**P3-4. 목록 정렬과 '가장 이른 예상'의 동점 처리가 다르다**
- rankedList(render.js:935)는 sortByUrgency(일수만 봄)를 쓴다.
- earliestExpected(logic.js:548)는 같은 날이면 확정을 먼저 둔다.
- 그래서 같은 날 추정·확정 기관이 있으면 툴팁 1순위와 목록 1순위가 다를 수 있다.

2. drawTicker(render.js:850–854)는 `root.overdue.refresh()`를 계속 부른다. 사이드바 배지는 refresh → paintNavBadge로 유지된다. startTickerSync는 빈 함수로 남겨 app.js:1216과 호환된다.
3. `#main:has(> #tab-map.active)`: index.html:3337–3370에서 `section#tab-map`이 `main#main`의 직계 자식이라 조건이 맞는다. index.html에는 이미 `:has(`가 15곳 있어 브라우저 지원도 앞선 사례가 있다. 다만 기본값이 `display:none`이라 :has를 지원하지 않는 브라우저에서는 머리 줄이 통째로 사라진다.
4. 0곳인 면: 전국은 문제없다(툴팁 '아직 공고 전인 기관이 없습니다', Tab·Enter로 드릴인 가능). 드릴인은 P3-1과 같다.

## 4. 테스트 공백과 추가 제안
- 머리 줄 재판정: 메뉴를 다시 그린 뒤(paintNav나 paintTabs 호출 뒤) `#map-out.hidden`이 `noticeMenuOn()`과 같아야 한다. 입력은 navBuilt에 NOTICE_ID가 없다가 생기는 경우, 기대는 hidden이 false로 바뀌는 것.
- 마커 색과 범례: `drawMarkers`에서 120일·200일·400일 남은 비지자체 기관의 fill이 각각 `MAP_COLORS.r2`·`MAP_COLORS.p`·`MAP_COLORS.b2`인지 확인한다. 지금 코드로는 실패할 것으로 예상한다.
- 드릴인 0곳 면: 공고 중 기관만 있는 면이 tabindex 없음, 툴팁 없음 또는 안내 툴팁, cursor가 pointer가 아님을 확인한다.
- DOM 구조: index.html을 파싱해 `#tab-map`의 부모가 `#main`인지 확인한다. 지금 시험(map_expected:258)은 CSS 문자열이 있는지만 본다.
- 날짜 경계: 확정 날짜가 오늘인 기관은 notice(map_expected:45)다. 확정 날짜가 120일 전이면 notice, 121일 전이면 overdue이고 지도에서 빠져야 한다. 이 경계 케이스를 추가한다.
- 구현 세부에 너무 묶인 시험:
  - map_expected:235–236·286은 소스 문자열을 slice하거나 정규식으로 검사한다. 함수 이름이나 공백만 바뀌어도 깨진다.
  - overdue.test가 죽은 listHtml·pickRefocus를 계속 시험한다(P3-2).
