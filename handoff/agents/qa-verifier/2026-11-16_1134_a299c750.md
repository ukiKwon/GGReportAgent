### 4. 테스트 공백과 추가 제안 (입력 → 기대값)
1. **진짜 롤백 검증.** `InstitutionPlanApiTest`는 클래스 전체가 `@Transactional`이다. 그래서 반입 트랜잭션과 실패 감사가 모두 테스트 트랜잭션에 합류한다. "중간 실패 시 전부 롤백 + 실패 감사는 커밋됨"이 실제로는 검증되지 않는다(선례: InboxTxRollbackTest).
   - 트랜잭션 없는 클래스를 만든다.
   - 입력: 금액 16자리 행이 마지막에 있는 3행 파일.
   - 기대(수정 후): 400, INST_PLAN_IMPORT·ITEM 0행, INST_PLAN_ACT에 INVALID 1행이 커밋된 채 남는다.
2. **오래됨 경계** (`isStale` 단위 시험):
   - today=2026-11-16, checked=2025-11-16 → false
   - checked=2025-11-15 → true
   - today=2028-02-29, checked=2027-02-28 → false
3. **기간 지남** (`periodEnded`): PERIOD_TO = 올해 → false, 작년 → true.
4. **계산값** (`calculated` 단위 시험):
   - 하위 하나가 NOT_IN_SOURCE → UNVERIFIED
   - 상위 자신이 AMOUNT → null

5. **status 다기관·다판**: 기관 A에 판 2개, 기관 B에 판 1개 → items 2개, A의 doc_count·item_count가 최신 판 값이다.
