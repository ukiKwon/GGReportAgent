### P2-1. relevant()가 진짜 공고를 놓친다 (`g2b.py:34`)
아래 제목은 모두 놓친다(실제 공고라면 원문을 받지 않음).

| 제목 예 | 놓치는 이유 |
|---|---|
| `○○공사 금고(은행) 선정` | `금고\s*\(`가 없다 |
| `금고 운영 기관 선정` | `운영기관`이 붙여쓰기만 허용 |
| `금고 운영 은행 선정` | 해당 패턴 없음 |
| `금고 약정기관 선정` | 해당 패턴 없음 |
| `○○공단 금고 입찰 공고` | 해당 패턴 없음 |
| `금고 관리은행 선정` | 해당 패턴 없음 |

- 더 큰 문제는 걸러진 공고가 `pipeline.py:26-28`에서 `skipped=True`로 '본 것' 처리된다는 점이다. 나중에 정규식을 고쳐도 그 공고들은 다시 받지 않는다.
- **수정안**:
  - 공백을 지운 제목에 대해 `금고(?:\(?은행\)?|지정|선정|업무|취급|사업자|운영|약정|입찰|관리)`처럼 넓힌다.
  - 건너뛴 항목에 규칙 판(rule version)을 기록하거나, skipped만 다시 판정하는 옵션을 둔다.

### P2-2. relevant()가 잡음을 통과시키고, 그 잡음이 '계획' 후보가 된다

- **수정안**: NOISE에 `시스템|구축|유지\s*보수|용역(?!.*선정)|연계|전산`을 추가하는 안을 검토한다. 아니면 `build.py:57` 분기를 '기타'에는 적용하지 않고 '지정'·'결과'에만 적용한다.
- 반대로 NOISE의 `고등학교`·`새마을금고`는 `○○고등학교 주거래은행 선정`, `새마을금고중앙회 주거래은행 선정`처럼 진짜 공고도 지운다(P3 수준).

### P2-4. list_new 안의 예상 못 한 예외가 실행 전체를 멈춘다
- **근거**:
  - `g2b.py:129`의 `body["response"]["body"]`는 try 밖에 있다. 응답에 body가 없으면 KeyError가 난다.

  - 이 셋은 SourceError가 아니다. 그래서 `:167`의 except를 지나쳐 cli까지 올라간다(`cli.py:108`이 잡지 않아 트레이스백이 난다).

- **수정안**: `:122-129`를 하나의 try로 묶어 `(ValueError, KeyError, TypeError, AttributeError)`를 SourceError로 바꾼다. `totalCount` 변환도 같은 try 안에 넣는다.

### P2-5. with_config가 env 주입 여부로 http를 유지할지 정한다 (`g2b.py:93-98`)
- **동작**:
  - cli(`cli.py:85-86`)는 http가 없으면 인자 없이 `with_config()`를 부른다. 운영 인스턴스는 `_env`가 None이라 새 HttpClient를 만든다. 이건 정상이다.
  - 테스트는 env를 넣었으니 가짜 API를 유지한다.
- **결함 1**: `G2bSource().with_config(env=ENV)`처럼 http 없이 env만 주면 실제 HttpClient가 생긴다. 시험에서 실제 네트워크가 호출될 수 있다.
- **결함 2**: http를 유지하는 경우에는 timeout·delay를 바꿔도 반영되지 않는다.
- **결함 3**: `hosts_file`을 받기만 하고 조용히 버린다. `--hosts`도 무시된다(`list_new`의 hosts 인자를 쓰지 않음).
- **결함 4**: 새 인스턴스는 `_items`·`calls`를 넘겨받지 않는다. list_new 뒤에 with_config를 부르면 fetch_raw가 `item={}`로 진행해 기관이 '미상'인 빈 원문을 저장한다(`:174`, 확인 없음).
- **수정안**:
  - http 유지 여부를 명시 플래그(예: `self._injected_http`)로 판단한다.
  - fetch_raw에서 item이 없으면 SourceError를 낸다.
  - g2b에 hosts가 주어지면 무시한다는 사실을 report에 남긴다.

## 4. 테스트 공백과 추가 제안
1. **eminwon 회귀**: `classify("OO군 금고 선정 공고")` → '기타'(P1-1 수정 후 기대값). `test_eminwon.py:68` parametrize에 추가한다.
2. **키 노출(실패 경로)**:
   - FakeApi가 `FetchError("연결 실패")`를 내거나 `resultCode "30"`·XML 본문을 돌려줄 때, `report.hosts_failed`·state.json·stdout·stderr 어디에도 SECRET이 없어야 한다.
   - 실제 HttpClient로 `https://127.0.0.1:1/x?serviceKey=SECRET`을 요청했을 때, FetchError 문구에 SECRET이 없어야 한다(httpclient 문구 규칙을 고정하는 테스트).
3. **응답 이상**: `{"response":{"header":{"resultCode":"00"}}}`(body 없음) → SourceError로 기록되고 실행이 끝까지 가야 한다(P2-4).
4. **relevant 경계**: `금고(은행) 선정`·`금고 운영 기관 선정` → True, `주거래은행 펌뱅킹 연계 시스템 구축` → False.
5. **개인정보 칸**: 목록에 없는 칸 `dminsttOfclNm:"김철수"` → 보관본에 없어야 한다(P1-2).
6. **store 재시도**: `Path.rename`을 monkeypatch해 2회 PermissionError 후 성공 → 반환이 final이고 `.tmp-*`가 없어야 한다. 6회 모두 실패 → PermissionError가 나야 한다.
7. **pipeline OSError**: fetch_raw가 OSError를 낼 때 → summary.failed에 1건이 남고 state에 '본 것'으로 기록되지 않아(`is_seen` False) 다음 실행에서 다시 시도해야 한다.
8. **with_config**: `with_config(env=ENV)`만 줬을 때 실제 HttpClient가 생기지 않아야 한다(P2-5 수정 후). 지금은 테스트가 없다.
9. **기존 테스트의 맹점**: `test_g2b.py:70-72`의 노출 검사는 `.json/.html/.csv`만 본다. 첨부 `.hwpx` 안(마스킹 후)도 검사하도록 확장을 권한다.
