**P3 (사소한 것)**
- **P3-1 결재 중인 기관에서 오류 순서가 일관되지 않습니다.** `move()`는 `requireNoPending`이 `checkOverlap`·`closedCheck` 뒤에 있습니다(`:349-351`). 그래서 결재 중인 기관에서도 CHANGE_PENDING 대신 ALREADY_GOAL이나 INST_BID_CLOSED가 먼저 나올 수 있습니다. `cancel()`도 사유 검사(400)가 먼저입니다(`:424-425`). `save()`는 순서가 맞습니다.
- **P3-2 요청 뒤 직책이 바뀌면 승인할 수 없게 됩니다.** `TargetChangeService.apply:250-254`는 결재 시점의 요청자 역할로 결재자 자격을 다시 판정합니다. 팀원이 요청한 뒤 팀장으로 바뀌면 원래 결재자인 팀장의 승인이 403이 됩니다. 반려·취소로는 빠져나갈 수 있습니다.
- **P3-3 약정 시작일이 개시일과 하루만 달라도 추정으로 돌아갑니다.** `ResultYearRules.yearOf:22`는 날짜가 정확히 같아야 맞다고 봅니다. RFP 개시일과 실제 약정 시작이 하루 다르면 1월 개시만 전년도로 보는 추정 규칙을 씁니다.
- **P3-4 이월·자동 취소 행의 수정자가 화면을 연 사람으로 남습니다.** 근거는 `insert(row, actor, …)`(`:552`, `:563`)입니다. `carried`·CARRY_REVOKED로 자동임을 구분할 수는 있지만, 이력 화면의 editor_name만 보면 그 사람이 바꾼 것으로 읽힙니다.
- **P3-5 목록을 열 때마다 이월 판정을 다시 돕니다.** `list()`가 GET마다 쓰기 자격자에게 `carryPlan`을 돌립니다(`:170`). 질의 3개와 대기 목록 조회가 추가되어 규모가 커지면 비용이 늡니다.
- **P3-6 MySQL 056은 시험에서 한 번도 실행되지 않습니다.** 시험 스키마는 Oracle 056만 읽습니다. 쌍 시험은 칸 이름·순서와 INSERT 블록만 비교하고, 형식 차이(SMALLINT↔NUMBER(4) 등)는 보지 않습니다.

**문제없음으로 확인한 것**
- DDL 쌍: 표 3개의 칸 순서와 개수(19·10·12), INSERT 블록이 일치합니다.
- `lockAll`이 `submitTargetChange` 트랜잭션에 합류해 잠금이 상신 끝까지 유지됩니다.
- 영업부장 반려(HEAD)는 승인이 막혀 있습니다(`:449`). 관리자는 취소할 수 없습니다(`:508`).
- 감사 행(SUBMIT·APPROVE·REJECT·CANCEL)은 결재와 같은 트랜잭션에 들어갑니다.
- 본문 상한 경로 6개(`BoardWriteLimitFilter:82`).
- 이월에서 사람이 고치거나 뺀 행은 거두지 않고 다시 넘기지도 않습니다(CarryRules:75-80).

### 4. 테스트 공백과 추가 제안
- **P1-1 회귀를 드러내는 시험이 없습니다.** 스위치 기본값(켬)에서 영업팀장이 단건으로 목표를 넣으면 403 APPROVAL_REQUIRED가 나는지 확인하는 시험이 필요합니다. 현재는 팀원 케이스만 있습니다(:133).
- **같은 원천의 이월 구분이 바뀌는 API 시험** (CarryRulesTest:116은 순수 시험만 있음)
  - 입력: GOAL로 이월된 뒤 다른 은행 약정을 등록하고 다시 carry를 부릅니다.
  - 기대: revoked=1, carried=1이고 WATCH 행이 생깁니다.
- **올해 원천의 조기 개시일 API 시험**
  - 입력: 올해 목표에 오늘보다 앞선 개시일을 기록하고 약정은 없습니다.
  - 기대: carry 1건, TARGET_YEAR=Y+1. 설계서의 13b가 실제로 빠져 있습니다. 1월 1일에는 Assume으로 건너뜁니다.
- **TO_GOAL 승인 시 연도 경과**
  - 입력: TO_GOAL(to_year=Y)을 올린 뒤 승인 시점에 thisYear를 Y+1로 바꿉니다.
  - 기대: 409 YEAR_PASSED. 시계를 주입할 수 없다면 `replan`을 순수 함수로 떼어 시험하는 방안도 있습니다.
- **영업부장 반려 뒤 잠금 해제**
  - 입력: HEAD2가 반려합니다.
  - 기대: 그 기관의 관심 기록 저장이 201(잠금 해제). 현재 :274 시험은 반려 감사 행만 확인합니다.
- **결재 카드 노출 범위**
  - 입력: 관리자(비영업)로 box=all을 조회합니다.
  - 기대: TARGET_CHANGE가 목록에 없음(S7). 시험이 있는지 확인되지 않았습니다.
- **'관심 기관에 목표 넣기' 경로가 시험에서 빠졌습니다.** 409 ALREADY_WATCH가 기존 규칙이라 이것 자체는 정상입니다. 다만 그 대신 쓰는 TO_GOAL이 승인까지 반영되는지(MOVE 행, KIND=GOAL, APPROVAL_REQ_ID)를 단언하는 시험이 있는지 확인이 필요합니다.
