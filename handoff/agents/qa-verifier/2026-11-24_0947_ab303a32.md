### 3. 발견 목록
P0·P1·P2는 없다.

**Oracle과 H2 차이 (P3 이하, 문제 없음)**
- 매퍼 46~47행을 Oracle 기준으로 따져 봤다.
  - Oracle은 `''`를 NULL로 본다. 그래서 `NULLIF(TRIM(x), '')`는 `NULLIF(값, NULL)`이 되고, 이것은 그 값을 그대로 돌려준다.
  - 공백만 있는 값은 `TRIM`이 NULL로 만든다. 따라서 "비었거나 공백뿐이면 NULL"이라는 의미가 MySQL·H2와 같다.
  - Oracle의 NULLIF 제약은 첫 인자에 리터럴 NULL을 쓸 수 없다는 것뿐이다. 여기서는 해당하지 않는다.
- CASE와 COALESCE의 결과 형식도 문제없다. `CODE_NAME VARCHAR2(100 CHAR)`(016:18), `BANK_NAME_ETC VARCHAR2(30 CHAR)`(039:34), `BANK_CD`가 모두 VARCHAR2라 ORA-00932가 날 위험이 없다.
- 행 수 제한 구문 같은 방언 구문은 없다. `CASE WHEN`은 다른 매퍼(InstitutionMapper 44, TaskMapper 254)에서도 이미 쓴다.

**`LocalDate.parse(today)` (문제 없음)**
- `Times.todayKst()`는 `LocalDate.now(Asia/Seoul).toString()`이다. 항상 ISO `yyyy-MM-dd`이므로 parse가 실패할 경로가 없다. 다른 서비스 8곳에서도 같은 방식으로 쓴다.
- 응답의 `today`와 만기 판정이 같은 변수 하나를 쓰므로 자정 경계에서도 서로 어긋나지 않는다.

**can_check 동일성 (확인됨)**
- `checkBlock`은 `CHECK_STATES`에 들지 않으면 non-null을 돌려준다. 들면 `mine`일 때만 null이다.
- 따라서 `block == null`은 `CHECK_STATES.contains(state) && mine`과 정확히 같다. 이것은 PUT 판정(374·392행)의 조합과도 같다.
- D42가 모든 행에서 이 짝을 단언한다(741행).

**P3-a: 깨진 TERM_TO의 동작 변화 (의도된 변경)**
- 예전 문자열 비교에서는 `"abc"`나 `"2026.12.31"` 같은 값이 `"2026-11-24"`보다 크게 판정돼 현재 은행으로 **보였다**. 이제는 **빠진다**.
- 저장 경로(`BankContractRules.term`)가 형식을 검사하므로, 이런 값은 DB를 손으로 고쳤거나 옛 가져오기 데이터일 때만 생긴다.
- 반대로 `InstSummaryPrefill.endOf`(260행)는 지금도 깨진 값을 문자열로 비교하므로 "현재"로 판정할 수 있다. 두 화면의 결과가 갈릴 수 있다는 기록만 남긴다.

**P3-b: 바깥 공백이 붙은 ETC 이름 (기존과 같음)**
- ETC 이름에 앞뒤 공백이 있으면 매퍼가 TRIM하지 않은 원문을 내보낸다(46행 `THEN b.BANK_NAME_ETC`). `bankText`도 같다.
- 저장 경로가 trim하므로 실제로 생길 가능성은 낮다. 프런트도 `.trim()`을 한다(prepboard.js 207행).

**P3-c: MySQL에서 이름이 빈 문자열로 나오는 경우 (기존 문제)**
- 조건: ETC가 아닌 은행, 코드표에 없는 코드, `BANK_NAME_ETC=''`.
- 이때 `COALESCE(NULL, '', BANK_CD)`가 `''`를 돌려준다. Oracle에서는 코드값이 나온다.
- 프런트는 빈 이름을 걸러 내므로(207행 `filter(Boolean)`) 화면에는 빈칸만 생긴다. 이번 변경 범위 밖이다.

**프런트 영향 (없음)**

### 4. 시험 공백과 추가 제안
Oracle과 관련 있는 TRIM 경로 하나가 비어 있다. 나머지는 선택 사항이다.
1. **(권장)** ETC + `BANK_NAME_ETC='   '`(공백만) → bank_name `기타(직접 입력)`. 이 경우만 TRIM을 실제로 거친다. D41에는 NULL만 있다(718행).
2. ETC + `BANK_NAME_ETC=''` → `기타(직접 입력)`. MySQL에서의 빈 문자열 경로다.
3. `expired(" 2026 ", today)` → false. 서비스의 trim이 동작하는지 확인한다(U10에 없음).
4. `expired("2026-02-30", today)` → true, `expired("2026-13", today)` → true. 형식은 맞지만 존재하지 않는 날짜다.
5. `checkBlock("CANCELLED", false)` → `ENDED`. 상태 판정이 담당 판정보다 먼저인지 확인한다(U11 226행은 mine=true만).
- 구현 세부에 과하게 묶인 시험은 없다. U10·U11이 패키지 공개 static을 직접 부르는 것은 기존 관례와 같다.

### 5. 호출자에게 요청할 실행

- (가능하면) 사내 Oracle 개발 DB에서 아래 질의 하나를 실행한다. 기대값은 ORA 오류 없이 행이 나오고, ETC 줄은 직접 입력 이름이 나오는 것이다.
  ```
  SELECT CASE WHEN b.BANK_CD='ETC' AND NULLIF(TRIM(b.BANK_NAME_ETC),'') IS NOT NULL THEN b.BANK_NAME_ETC ELSE COALESCE(c.CODE_NAME,b.BANK_NAME_ETC,b.BANK_CD) END
  FROM INST_BANK_CONTRACT b LEFT JOIN COMMON_CODE c ON c.CODE_GROUP='BANK' AND c.CODE=b.BANK_CD
  ```
