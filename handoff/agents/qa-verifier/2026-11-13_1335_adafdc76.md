## 3. ① 월요일 로그 점검표 (`data/collector/_logs/2026-11-16_09xx_weekly.log`)
로그 구조는 `[TS] eminwon` → JSON 한 줄 → `eminwon exit=N` → `[TS] g2b` → JSON → `g2b exit=N` → `final exit=N` 순서입니다.

**종료 코드별 의미**
- 0: 정상.
- 3: 결과는 만들어졌고 새 실패가 있습니다. `hosts_failed_new`와 `failed`를 확인합니다.
- 4: 다른 실행이 진행 중입니다. 같은 시각에 손으로 돌렸는지, 6시간이 안 된 잠금이 남았는지 봅니다.

- 2: 사용법 오류입니다. `--since`가 비었으면 powershell 날짜 계산이 실패한 것입니다.
- 그 밖(9009 등): python 경로 문제입니다.

## 4. ② 첫 실행 위험 목록
1. **실행 시간**:
   - 11-12 실행은 14분이 걸렸습니다(그때는 시간 초과가 더 짧았음).
   - 지금은 시간 초과 45초, 요청 전체 마감 135초(`httpclient.py:173`), 재시도 간격 30초·90초입니다.
   - 시간 초과 호스트 1곳에 첫 시도 약 4~9분, 2nd pass 최대 135초가 걸립니다. 12곳이면 약 1~2시간 더 걸립니다.
   - `max_run_sec`(3시간)은 지나면 재시도와 2nd pass만 끊는 "부드러운" 상한입니다(`eminwon.py:245,371`). 남은 요청은 계속 갑니다.
   - 잠금 회수 기준은 6시간이라 정상 범위에서는 충돌하지 않습니다.
   - g2b는 eminwon이 끝난 뒤 시작합니다. 시작 시각이 10~11시대로 밀릴 수 있습니다.
2. **잠금**: 월요일 오전에 누가 손으로 실행하면 뒤에 실행된 쪽이 4로 끝납니다. 비정상 종료 뒤에는 6시간 안에 다시 돌려도 4가 나옵니다.
3. **시간 초과 12곳**:
   - 알려진 실패로 등록돼 있지 않아 계속 실패하면 매주 3이 나옵니다.
   - 그러면 진짜 새 실패가 묻힙니다(신호 약화).
4. **TLS 예외 10곳**:
   - 수를 다시 세면 정책을 가진 호스트는 10곳입니다. 속초가 CA와 cipher를 둘 다 써서 항목으로 세면 11입니다.
   - 실제 Python 핸드셰이크가 openssl 실측과 다를 수 있습니다(특히 SECLEVEL 2에서 DHE 키가 1024비트이면 거절).
   - 이 경우 해당 호스트가 kind `tls_handshake`로 3을 일으킵니다.
5. **g2b 키와 한도**:
   - 실행당 최소 호출 수는 9회입니다(14일 → 7·7·1일 구간 3개 × 검색어 3개).
   - 200회 상한과 하루 1000회 한도에는 여유가 큽니다.
   - g2b는 재시도가 없습니다(`g2b.py:125-130`). 한 번만 시간 초과가 나도 그 검색어는 실패하고 3이 됩니다.
   - 키가 만료되면 세 검색어가 모두 실패해 1이 됩니다. `.env.local`은 파일로 읽으므로 실행 계정과는 무관합니다.
6. **환경**:
   - PC가 켜져 있고 로그인돼 있어야 합니다. 작업 설정에서 "로그온 여부와 관계없이 실행"과 "놓친 실행을 나중에 실행" 여부를 확인해야 합니다.
   - 실행 계정의 프록시 설정을 urllib이 레지스트리에서 읽습니다. 계정이 SYSTEM이면 다를 수 있습니다.
7. **디스크**: 첨부는 20MB×5개 상한입니다. 새 공고가 수십 건이면 최악 수 GB, 실제로는 수십 MB 수준으로 봅니다. 로그와 상태(실행 기록 50개 상한)는 작습니다.
