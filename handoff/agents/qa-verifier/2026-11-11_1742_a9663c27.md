## 3. 발견 목록
**P2-1 응답 대기 중 Enter로 로그인 요청이 거듭 나갈 수 있음**: app.js:976이 `login-go.disabled = true`로 버튼만 막습니다. 그런데 app.js:990-991의 keydown Enter는 이 상태를 보지 않고 `submit()`을 다시 부릅니다. `<form>`이 있었다면 기본 버튼이 비활성일 때 Enter 제출도 막혔겠지만, 지금은 그렇지 않습니다.
- 재현: 서버 모드에서 사번 7자리를 입력하고 서버 응답을 느리게 만든 뒤 Enter를 연타하거나 길게 누릅니다.
- 기대: POST `/auth/login` 1회.
- 실제(코드상): 누른 횟수만큼 요청이 나가고 `enterApp`도 여러 번 불립니다. 접근 이력이 중복으로 남고 overdue 팝업 판정도 반복됩니다.
- 이 keydown 처리가 이번에 새로 생겼는지는 diff로 확인해야 합니다. 기존 동작이면 P3로 내립니다. 요청 대기 중 '둘러보기'를 누르면 guest 진입 뒤 account 진입이 이어지는 문제도 같은 뿌리입니다.

**P3 항목**
- **P3-1 멈춤 뒤 재생하면 진행 막대와 실제 넘김이 어긋남**: 멈추면 `data-play="off"`라서 index.html:657의 animation 규칙이 빠집니다. 다시 재생하면 막대는 0부터 6초로 새로 시작합니다. 그런데 타이머는 login-hero.js:335/360에서 남은 `left`만큼만 기다립니다. 3초째에 멈췄다가 재생하면, 막대가 절반쯤일 때 장이 넘어갑니다.
- **P3-2 자정을 넘기면 D-day가 갱신되지 않음**: mount 때 `today`를 한 번만 정합니다(login-hero.js:304). showLogin의 mount는 `active`가 있으면 아무것도 하지 않습니다(301행). 로그인 화면을 밤새 켜 두면 D-day와 "11월 11일 기준"이 그대로 남습니다. 접수 마감이 지난 notice도 새로고침 전까지 계속 보입니다. app.js:870 주석 "보일 때마다 다시 그린다"는 실제 동작과 맞지 않습니다.
- **P3-3 마우스로 히어로 버튼을 누르면 자동 재생이 계속 멈춰 있음**: 클릭한 버튼이 포커스를 가져가 `st.focus=true`가 됩니다. 이 값은 focusout으로만 풀리므로(376행) 마우스를 치워도 다시 재생되지 않습니다. 규격 시안과 같은 동작이므로 결함인지 의도인지는 디자인 확인이 필요합니다.
- **P3-4 데이터 검증의 빈틈**(화면이 깨지지는 않고 겹침이나 숫자 오류 수준):
  - id가 `__proto__`, `constructor`, `toString`이면 `seen = {}`(129행) 때문에 그 장이 조용히 빠집니다.
  - `hot`에 같은 code가 두 번 있으면 범례 수가 2곳으로 셉니다. far 수(278행)도 틀립니다.
  - `noticeFrom ≤ noticeTo`를 검사하지 않습니다.
  - items나 steps의 개수, say나topic 길이에 상한이 없습니다. 슬라이드가 `position:absolute; inset:0`이라 넘치면 출처 줄과 겹칠 수 있습니다(화면에서 확인하지 못함).
  - `noticeFrom` 이전에도 notice 장이 "공고 제…호"로 보입니다. 하한이 없고, 이때 '오늘' 점이 '공고' 점과 같은 0% 위치에 겹칩니다.
- **P3-5 전역 버튼 스타일이 일부 남음**: `button:active { transform: scale(.98) }`(index.html:47)이 `.lg-cbtn`, `.lg-dot`, `.lg-ghost`에 그대로 걸립니다. hover만 #login-view 규칙으로 무력화했습니다. 무해하지만 의도인지 확인이 필요합니다. border, cursor, disabled는 #login-view 쪽 특이도가 이겨서 충돌이 없습니다.
- **P3-6 비밀번호 관리자**: `<form>`이 없고 화면 전환 없이 display:none으로 숨기므로, 브라우저의 저장 제안이 뜨지 않을 수 있습니다. autocomplete는 username/current-password로 맞게 들어가 있습니다. 비밀번호를 확인하지 않는 시험 운영이라 영향은 작습니다.

**확인했고 문제없음**
- id 7개 유지(test 140-150).
- 숨기는 경로 2곳(enterApp, 세션 복원)에서 destroy를 부르고, 보이는 경로 2곳(showLogin, 첫 화면)에서 mount를 부릅니다. showLogin을 부르는 곳은 logout과 profile-chip뿐입니다.
- `wire(false)`가 등록한 리스너와 타이머를 모두 거둡니다. 등록 대상은 click 3개, 점, ctl keydown, hover, focus, visibilitychange, matchMedia 2개입니다.
- 슬라이드가 0장이면 no-op 인스턴스가 들어가 다음 mount가 정상 동작합니다. 데이터 파일에 문법 오류가 나거나 배열이 아니면 빈 목록이 되고, 히어로를 숨긴 채 로그인 카드만 보입니다.
- 모든 글자는 `textContent`나 `createTextNode`로 들어가고, `innerHTML`은 쓰지 않습니다. 데이터 값은 setAttribute로 aria-label에만 들어갑니다. app.js:945-948의 select는 `esc()`를 거칩니다.
- reduced-motion이면 처음부터 멈춘 상태로 열리고 CSS 전환도 끕니다. 키보드 ←→ Home End는 순환하고, 점에 있던 포커스는 따라갑니다. aria-live는 재생 중 off, 멈추면 polite입니다.
- 날짜: Date는 로컬 달력으로, 문자열은 UTC로 정수 일 번호를 만들어 시각이 섞이지 않습니다. 접수 첫날은 '접수 중', 마감 당일은 D-DAY, 다음 날은 빠집니다.
- `:root`에는 `--lg-*` 이름을 새로 더하기만 했고, 동결 대상 이름은 바꾸지 않았습니다.

## 4. 테스트 공백과 추가 제안
- DOM 경로 테스트가 없습니다. 가짜 document나 타이머로 다음을 확인할 것을 제안합니다.
  - mount → destroy 뒤 6초가 지나도 `go`가 불리지 않는다.
  - destroy 뒤 다시 mount하면 점이 N개(중복 없음)이고 리스너 수가 처음과 같다.
  - mount를 두 번 부르면 아무 일도 없다.
  - `list = []`이면 `heroEl.hidden === true`이고 stage에 `lg-solo`가 붙는다.
- XSS: `say: '<img src=x onerror=alert(1)>'`를 넣으면 그 글자가 그대로 보이고 img 요소가 0개여야 합니다.
- `problems({...FLOW, id:'__proto__'})`와 activeSlides 결과(현재는 빠짐) → 기대 동작을 정하고 테스트로 고정합니다.
- `noticeView(NOTICE, 2026-10-20)`(공고 전) → state와 showToday 기대값.
- `hot`에 중복 code → problems에 잡혀야 함.
- `noticeFrom > noticeTo` → problems에 '날짜 순서'.
- 구현에 과하게 결합된 테스트: login-hero.test.js:176의 개행과 공백까지 맞추는 정규식, 174행 `slice(i, i+260)`은 줄을 정리만 해도 깨집니다.
