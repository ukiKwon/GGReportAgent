## 3. 발견 목록

**[P1] `header` 타입 선택자가 수익성 분석표 팝업 머리에도 걸린다 — 제목과 [고친 칸만 표시]·[닫기] 단추가 흰 글자로 사라진다**
- **원인**: M3이 남색 띠를 `header { … background:#052561; color:#fff; }`, `header button {…}`, `header :focus-visible {…}` 같은 **타입 선택자**로 넣었다(`frontend/index.html:53-63`).
- **영향받는 곳**: `frontend/js/board-write.js:1381`이 팝업 안에 `<header class="bd-src-head">`를 따로 만든다.
- **결과**
  - 바탕: `.bd-src-head`(index.html:452-453)가 `var(--panel2)`로 덮어써서 남색은 막힌다.
  - 제목 `color`: 덮어쓰는 규칙이 없다. 그래서 `#fff`를 물려받는다. 제목 h3(`.bd-src-box .bd-src-head h3`:454, `.modal-box h3`:1364)에도 색이 없어 **흰 글자가 #f6f7f9 위에 놓인다. 약 1.07:1**이다.
  - 단추: `header button`(특이도 0,0,2)이 기본 `button`(0,0,1)을 이긴다. 그래서 `data-w="srcedited"`·`data-w="srcclose"` 두 단추가 **투명 바탕 + 흰 글자 + 반투명 흰 테두리**가 된다. 이 단추에만 걸리는 규칙은 없다(grep으로 확인).
  - 포커스 링: `header :focus-visible { outline-color:#fff }` 때문에 팝업 머리 안의 포커스 링이 흰색이라 보이지 않는다. 원본 이동 칩 `.bd-w-srcjump`도 hover 때 테두리가 흰색이 된다(`header button:hover`, 0,1,2).
- **재현**
  1. 로그인한다.
  2. 이사회 자료 작성 화면에서 수익성 분석표 팝업을 연다.
  3. 기대: 제목 '수익성 분석표 · 파일명'과 [고친 칸만 표시 n]·[닫기]가 보인다.
  4. 실제(코드 판단): 셋 다 흰색이라 보이지 않는다. Esc 말고는 닫는 법이 눈에 띄지 않는다.
- **볼 곳**: index.html:53-63의 선택자 범위(앱 머리 띠 하나로 한정할 것), board-write.js:1381. 1484줄 `@media … header { flex-wrap:wrap; }`도 같은 문제다(지금은 무해).
- **테스트 공백**: 이 연결은 지금 어떤 테스트도 잡지 못한다(4절).

**[P3] 같은 면에 포커스가 있는 채로 선택하면 포커스 표시가 선택 링 밑에 깔린다**
- render.js:944-948 `_ringPaths`는 덮개 층에 그냥 `append`만 한다. 그래서 위아래가 그린 순서로 정해진다.
- 키보드 흐름: Tab으로 면에 포커스(잉크 6 + 흰 2.5)를 둔 뒤 Enter를 누른다. 그러면 `onSubregionClick` → `selectInstitution` → `_ringSelect`가 선택 링(흰 5 + 잉크 2.5)을 **나중에** 그려 위에 덮는다. 포커스는 그 면에 그대로 있지만, 바깥 잉크 0.5px만 남고 '흰 선에 검은 테두리' 모양이 사라진다. 순서를 반대로 하면 포커스가 위에 온다(일관성이 없다).

## 4. 테스트 공백과 추가 제안
- **(필수, P1 대응)** 앱 머리 띠 규칙이 JS가 만드는 `<header>`에 새지 않는지 확인하는 테스트.
  - 입력: index.html의 `<style>` 규칙 목록과 `board-write.js`의 `popHtml` 출력(`<header class="bd-src-head">` 포함).
  - 기대: 남색 바탕·흰 글자·흰 포커스 링을 주는 규칙의 선택자가 `.bd-src-head`에 매치되지 않는다. 최소한 선택자가 `header`로 시작하는 맨 타입 선택자가 없어야 한다.
- **덮개 층 동작 테스트(지금은 소스 정규식뿐)**: render.js는 node에서 `require`할 수 있다(map-detail.test.js:347). 가짜 layer 객체(`append`가 class·d 기록을 쌓음)로 아래를 확인한다.
  - `_ringPaths(fake, 'sel', ['M0','M1'])` → class 순서가 `under, under, over, over`(여러 구에서 under가 이웃 over를 덮지 않음).
  - `_ringFocus({matches:()=>false, getAttribute:()=> 'M0'})` → 아무것도 그리지 않음.
  - `_ringFocus`를 두 번 부름 → `ring-focus` 경로는 한 쌍만 남음(가짜 d3로 `_ringBlur` 호출 확인).
  - `clearSelection` → `g.sel-ring-layer path.ring-sel` 제거 호출, `ring-focus`는 유지.
- **결합 과다**: `screen-97s2.test.js:81-88`과 `:68`은 CSS 한 줄의 공백·순서까지 그대로 맞춘다(예: `.region.watched { stroke:var(--fg); stroke-width:1.5; stroke-dasharray:4 2; }`). 값이 같아도 서식만 바뀌면 깨진다. 속성별 단언이 낫다(P3).
- **테스트 범위 한계**
  - 글자 테스트(`:32-38`)는 `<style>` 안만 본다. 마크업 인라인 style과 JS가 만드는 인라인 style은 보지 않는다. 지금은 grep으로 0곳임을 확인했다.
  - `.label` 예외 정규식은 지도 밖 `.x .label`도 면제할 수 있다.
