### 뒤로 미룰 것
- **P3-1** 미리보기·저장을 누르면 `draw('mn-preview')`/`draw('mn-save')`가 그 버튼에 포커스를 보낸다. 그런데 버튼이 disabled라 `focusById`(258)가 건너뛰고, 포커스가 body로 빠진다. 실화면 확인 대상이다.
- **P3-2** 목록을 다시 받을 때 404가 오면 상태가 `hidden`이 된다. `buildList`는 이 상태를 따로 다루지 않아 "아직 올린 회의록이 없습니다…"(380)를 띄운다. 기능이 꺼졌는데 빈 목록처럼 보인다.
- **P3-3** 삭제할 때 409 REV_CHANGED가 오면 "[새로 불러오기] 뒤 다시 고치세요"라고 쓴다. 하지만 삭제 경로(762 `handleErr`)에는 그 버튼이 없다. 버튼은 편집 경로(728)에만 있다.
- **P3-4** 공개 대상이 30명이면 추가 줄 전체가 disabled다(854). 서버는 이미 있는 사람의 기한 연장은 30명이어도 허용한다(`Service:1143-1153`). 그래서 30명 상태에서는 기한 변경을 할 수 없다.
- **P3-5** [저장]이 진행 중일 때도 [취소](999)가 켜져 있다. 취소하면 응답을 버리지만(1161), 서버에는 회의록이 생겼을 수 있다. 이때 목록과 탭 건수가 맞지 않는다.
- **P3-6** `gone()`이 `#mn-err`로 포커스를 보낸 직후, 목록 재조회가 끝나면 `draw('')`(338)가 DOM을 다시 그려 포커스를 잃는다.
- **P3-7** 공개범위 후보 조회 `/assignment-candidates`에 회의록 헤더(`board_minutes`/`minutes_scope_open`, 776)를 실어 보낸다. 다른 컨트롤러의 접근 이력에 회의록 화면 id가 남는다. 기능에는 영향이 없다.
- **P3-8** 공개범위 추가 줄의 `.mn-slot`은 CSS가 `.mn-up .mn-slot`에만 grid를 준다(319). 그래서 841행 인라인 `gridTemplateColumns`는 효과가 없다. 배치는 실화면으로 확인해야 한다.
- **P3-9** `index.html:323`은 `:has()` 선택자와 `.on`을 한 규칙 목록으로 묶었다. `:has`를 모르는 브라우저는 규칙 전체를 버리므로 `.on` 대체가 동작하지 않는다. 기존 494행도 같은 패턴이니 참고만 한다. 325행 포커스 링도 같은 이유로 빠지고, 라디오가 `opacity:0`이라 포커스가 보이지 않는다.

### 확인 결과 문제없음(요청 항목별)
1. **회귀**
   - `tabsHtml`·`tabKey`는 선택 인자가 없으면 기존 결과와 같다(679·691).
   - `onHistClick`은 `[data-act]`만 잡는다. 회의록 요소에는 data-act가 없어 충돌하지 않는다.
   - `toList`·`openMaterial`·`reset`에서 `stop()`을 부른다.
   - probe 뒤 `drawMat(true)`를 `focusKeyIn`/`refocus`로 감싸 포커스를 지킨다.
   - `me().role`은 board-material의 `isHead`와 같은 출처(`profile.team`)다.
2. **보안**
   - innerHTML·outerHTML·insertAdjacentHTML·document.write·localStorage·sessionStorage 모두 0건이다(정적 시험 174–177).
   - a/href/src 생성이 없다.
   - id는 숫자로 검증하거나 서버 정수를 property로 넣는다.
   - 헤더 화면·버튼 13쌍 모두 `MinutesUiIds` 허용 목록 안에 있다.
   - File과 미리보기 응답은 컨트롤러 변수에만 두고, `stop()`·저장 성공 때 비운다.
3. **서버 계약**
   - 목록 `{items, can_upload}`, 상세 viewer 8개 플래그, 원문 `items[]`, 공개범위 배열, 이력 `{logs, revs}`, 할 일 `changed`, scopeAdd의 `reason/changed/event`, 업로드 201 `minutes_id`, ALREADY_UPLOADED의 `detail.minutes_id`가 모두 맞는다.
   - 필터 411/413 코드도 맞는다.
   - `rules_ack`는 `@JsonIgnoreProperties`로 무시되어 오류가 나지 않는다.
4. **6-2**
   - 404는 숨긴다. 200은 `items` 또는 `can_upload` 조건을 따른다.
   - 5xx·네트워크는 팀장·부장·`is_assignee`일 때만 보인다. 401은 숨긴다.
5. **digest**
   - 서명에는 회의일·제목·파일(이름/크기/수정시각)·붙여넣기 전문·가릴 단어 원문·해제 목록이 들어간다.
   - 서명이 다르면 stale 안내를 띄우고 [저장]을 끈다. `doSave`도 다시 확인한다.
   - PREVIEW_CHANGED가 오면 `pvSig=''`로 둔다.
6. **30명·365일**
   - 클라이언트 `rows.length>=30`은 서버 `rows.size()>=SCOPE_MAX`와 같은 집합(만료 포함)을 센다.
   - max `today+365`는 서버 `plusDays(365)`와 같고, 기본값은 +30일이다.

## 4. 테스트 공백과 추가 제안
- 시험은 순수 함수와 probe만 다룬다. **DOM 컨트롤러 흐름 시험은 0건**이다(`board-minutes.test.js` 전체). 아래를 제안한다.
  - 미리보기 응답 400 `{code:'RELEASE_INVALID'}` → 오류 문구를 담은 요소가 DOM에 있고, '가리지 않기' 체크를 풀 수 있다(P1-2 회귀 방지).
  - 미리보기 성공 뒤 제목을 바꿈 → `#mn-stale`이 보이고 `#mn-save.disabled===true`. 체크해도 저장이 켜지지 않는다.
  - 저장 응답 409 PREVIEW_CHANGED → `#mn-err-save`에 문구가 있고 저장이 꺼져 있다.
  - 저장 진행 중 패널을 다른 노드로 교체한 뒤 응답 201 → 교체한 노드의 내용이 바뀌지 않는다(P2-1).
  - 공개범위 행 30개 → 추가 칸이 모두 disabled이고 "30명까지" 문구가 있다. 기한 input의 `max === addDays(today,365)`.
  - 상세 404 → 목록으로 돌아가 `S.notice === TEXT.GONE`.
  - `errorText(409,{code:'REV_CHANGED'},{action:'delete'})` → 버튼을 언급하지 않는 문구(P3-3을 고친다면).
- CSS 시험 공백: 회의록 880 블록(`.mn-sum` 1열)을 검사하는 시험이 없다. "첫 매치"에 기대지 않고 선택자로 찾는 형태를 권한다. 기존 overdue·board-write-focus 시험이 첫 매치에 묶여 있는 것 자체가 구현 결합이다.
