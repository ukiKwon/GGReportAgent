### 3. 발견 목록

**P2-1. 1장 맞춤 추정의 여유가 작다(실제 Word에서 2쪽이 될 수 있음)**
- 근거(`HeadDocBuilder.java:67,74,75,76`): 맑은 고딕 12pt 한 줄은 약 5.63mm, 뒤 간격 3pt(1.06mm)를 더하면 실제 약 6.69mm다. ROW_MM 7.0이니 줄당 여유는 0.3mm, 전체 여유는 BUDGET 247 / 본문 257로 10mm다.
- 추정 방식(`wrapLines` 351–368)은 글자 단위로 줄을 바꾼다. Word는 한글을 어절 단위로 줄바꿈하므로, 36–38자 근처 줄은 추정 1줄이 실제 2줄(+5.6mm)이 될 수 있다. 이런 줄이 2개쯤이면 여유 10mm를 넘는다.
- 날짜 포함은 괄호 때문에 줄 길이가 바로 이 경계를 많이 지난다.
- 재현:
  1. 사진이 있는 기관장에 학력 3줄, 경력 12–13줄을 넣는다. 각 줄은 한글 30자 안팎의 긴 어절에 날짜를 붙인다.
  2. `?mode=dated`로 받아 Word로 연다.
  3. 기대: 1쪽, `X-Head-Trimmed-*`는 0. 실제: 미확인. 2쪽이면 결함이다.

**P3-1. 둘째 줄 내어쓰기 위치가 첫 줄 글자 시작과 어긋남**
- 근거(`DocxKit.java:247–250`): hanging = 12pt(240twip)인데 접두어 '■ '의 폭은 약 15.6pt(■ 1em + 공백 약 0.3em)다. 그래서 줄이 바뀐 둘째 줄이 첫 줄 본문보다 약 1.3mm 왼쪽에서 시작한다.
- 이 렌더러는 사진 옆 정보 줄(14pt)도 같이 쓰고 그쪽은 원래 그랬다. 이번에 학력·경력 줄에 새로 퍼졌다. 바르게 보일지는 디자인이 판단할 일이다.

**P3-2. A15 Javadoc이 떨어져 나감**
- 근거(`InstitutionHeadController.java:141–148`): A15 설명 블록 바로 뒤에 `datedMode`의 `/** */`가 끼어서, A15 블록은 어느 선언에도 붙지 않는 주석이 됐고 `docx()`에는 문서 주석이 없다. 동작에는 영향이 없다.

**P3-3. 테스트 이름이 바뀐 규칙과 반대로 읽힘**
- 근거(`InstitutionHeadDocxSourcePhotoApiTest.java:220`): 이름이 `…기간이_앞에_붙는다`인데, 실제로 확인하는 것은 내용 뒤 괄호다.

**P3-4. 선택값(dlOpt)이 화면 전체에서 하나**
- 근거(`headcard.js:84`): dlOpt는 모듈 전역이고, 기관장 상태 V도 하나다(`paneSection` 608–617). 대시보드 상세 칸과 지도 팝업(#dm-box)·현황판이 값을 같이 쓴다.
- 팝업에서 '날짜정보 포함'을 고른 뒤 다시 그려지지 않은 다른 칸의 선택 상자는 '요약본'으로 보이는데, 그 칸에서 누르면 dated로 받을 수 있다.
- 완료 문구에 종류가 나오므로(`docxOkLead`) 큰 피해는 없다. 화면을 옮길 때 상세 칸을 다시 그리는지는 화면에서 확인하지 못했다.

**확인된 것(문제 아님)**
- **권한 → mode 순서**: `run()` 485–499에서 사용자·영업 역할·기관 id를 먼저 검사한 뒤 `fn.apply`로 넘어가고, 그 안에서 UI id 검사 → `datedMode`(169) → `heads.detail`(170) 순서다.
  - 영업이 아닌 사용자가 `mode=bad`를 보내면 403(DENIED)이 먼저다.
  - 잘못된 mode는 DB를 읽기 전에 400을 내고, 감사에는 `outcomeOf(400)`이 남는다.
  - 입력값은 메시지에 싣지 않는다(156).
- **지도 팝업 키보드**: `dmKey`(1968–1988)는 Escape와 Tab만 처리하고 방향키·Enter·Space는 건드리지 않는다.
  - `dashboard.onKey`의 방향키는 role=tab/listbox일 때만 동작한다(1666–1688).
  - `app.js:164`도 Escape만 본다.
  - 다만 닫힌 select에 포커스를 두고 Esc를 누르면 팝업이 한 단계 뒤로 간다(`dmBack`). 다른 컨트롤과 같은 동작이다.
- **click 위임**: select를 클릭하면 `onPaneClick('docx-opt')`이 null을 돌려줄 뿐 부작용이 없다(1931, 1704).
- **사진 옆 정보 줄**: `square()`·INFO_* 상수는 그대로이고, 사진이 있을 때 표가 1개뿐인 것은 DatesTest 130–146이 확인한다.
- **oldestIndex**: 입력이 이미 sortPeriod 내림차순이라 `<=`는 항상 마지막 줄을 고른다. 날짜 없는 줄 → 가장 오래된 줄 → … → 현직 순서는 카드와 같다.
- **이스케이프**: option 값은 상수 `cd`이고, 라벨과 aria-label은 `esc()`를 거친다(381–382). `:root` 변경은 보이지 않는다.

### 4. 테스트 공백과 추가 제안
1. **API 감사 기록**: `?mode=full` → 400이고 감사 표 HEAD_DOCX 행의 결과가 INVALID여야 한다. 현재 SourcePhotoApiTest 249–256은 상태 코드와 코드값만 본다.
2. **권한 우선순위**: 영업이 아닌 사용자 + `?mode=full` → 403·DENIED(400이 아니어야 함).
3. **경계 값**:
   - `?mode=` 빈 값 → 200 요약본
   - `?mode=summary` 명시 → 200 요약본
   - `?mode=summary&mode=dated` → 400 (Spring이 'summary,dated'로 합침)
4. **dated 응답 헤더**: 경계 길이 줄이 많을 때 `X-Head-Trimmed-Career`가 숫자이고 dated ≥ summary인지. 지금은 빌더 단위(DatesTest 157)만 있다.
5. **빈 내용 항목**: 저장 검증이 막지 않는다면 value 빈 값 + 날짜 → dated는 '■ (2018)', summary는 '■ '만 나오는지 확인하거나 막는 테스트가 필요하다.
6. **화면 이벤트 연결**: test 1431은 리스너 개수만 센다. document에 `change` 이벤트(target `data-hc="docx-opt"`, value 'dated')를 보내면 `getDlMode()`가 'dated'가 되는지 연결을 확인하는 케이스가 필요하다.
7. **결합도**: DatesTest 165 `">■ 가상경력0("`는 DocxKit의 run 분할에 묶여 있다. 접두어를 따로 run으로 내보내도록 바뀌면 거짓 통과가 된다. `!x.contains("가상경력0(")`처럼 접두어 없이 확인하는 쪽을 권한다.
