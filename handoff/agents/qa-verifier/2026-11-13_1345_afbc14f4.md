## 3. 발견 목록
**P1-1. 빈 머리에서 [기관장 추가]를 누르면 바로 등록되지 않고 '팀장 전용 충돌 후보'가 된다**
- 근거:
  - 빈 머리도 서버에는 현 기관장(CURRENT)으로 남아 있다(`cur != null`). 그래서 `addHead`가 `direct=false`로 CANDIDATE 머리를 만든다(InstitutionHeadService.java:638–646).
  - A3 응답에서 후보 기관장의 `conflict = cur != null`이 참이 되고(578), 확정할 때 LEAD_ONLY·SELF_RESOLVE가 걸린다(HeadRules.java:50–54).
  - 변경 전에는 빈 머리가 ok 모드였다. 그때는 '항목 후보 추가'로 NAME을 넣으면 `confirm = old==null && open.isEmpty()`가 참이 되어 바로 확정됐다(addItem 740). 이번 변경으로 none 모드에서는 add-item 양식이 숨겨져(headcard.js:654–661) 이 길이 사라졌다.
- 영향:
  - 카드는 "새로 추가할 수 있습니다"라고 안내한다. 하지만 영업팀원이 추가하면 후보만 남고, 본인은 확정할 수 없으며 팀장만 처리할 수 있다.
  - 팀장이 확정하면 빈 머리가 이전 기관장(PREVIOUS)으로 바뀌어, 이력에 이름 없는 기관장이 쌓인다.
  - 모달 안내문은 일부러 '바로 확정'을 뺐지만(655 주석), 결과 차이는 사용자에게 설명되지 않는다.
- 재현:
  1. 영업팀 계정으로 기관장이 있는 기관을 연다.
  2. 모달에서 확정 항목(이름 등)을 모두 무효 처리한다. 등록 양식으로 바뀌는 것을 확인한다.
  3. 이름·직위·출처를 넣고 등록한다.
  - 기대: 기관장이 등록된다.
  - 실제: "후보 기관장으로 넣었습니다"가 뜨고, 후보 행의 [기관장으로 확정]이 비활성화되며 이유로 '충돌하는 값은 영업팀장…'이 표시된다.

**P2-1. 후보 기관장 행의 배지와 막힘 사유가 서로 맞지 않는다**
- 빈 머리에서는 `cur = d.head.name`이 ''라서 배지가 '후보'로 나온다(headcard.js:580,593).
- 그런데 서버 block_code는 LEAD_ONLY라 사유 문구는 '충돌하는 값은…'으로 나온다. P1-1과 같은 뿌리다.

**P2-2. '기관장 없음'으로 바뀌는 조건이 의도("이름까지 무효")보다 좁다**
- `isEmptyHead`는 확정 항목·학력·경력·사진이 하나도 없을 때만 참이다(94–101).
- `addHead`에서 권한대행을 '아니오'로 고르면 ACTING=false 항목이 확정으로 생긴다(660–661). 이 값은 카드에 보이지 않는다(배지는 true일 때만, 256행).
- 그래서 이름·직위를 무효해도 카드는 ok로 남고 '이름 미확인'만 보이며, [기관장 추가]는 나오지 않는다. 사용자에게는 보이는 값이 없는데 '보이는 값이 남으면 ok'라는 주석의 전제가 깨진다.
- 재현: 권한대행 '아니오'로 등록한 뒤 이름·직위를 무효 처리한다 → 카드에 '이름 미확인'만 남는다.

**P3-1. none 카드에서 잃는 정보와 버튼**
- 빈 머리가 none으로 바뀌면서 입찰 D-day·공고 진행 중 띠와 [새로 고침] 버튼이 사라진다(281–286). 변경 전에는 ok 카드라 보였다.
- 의도된 것인지 확인이 필요하다.

**P3-2. 모달을 닫으면 포커스가 엉뚱한 곳으로 간다**
- ok에서 none으로 바뀐 뒤 모달을 닫으면, 처음 누른 [편집] 버튼은 다시 그려져 사라졌으므로 포커스가 `#db-name`으로 간다(918).
- [기관장 추가]로 돌아가는 편이 자연스럽다.

**P3-3. 상태가 바뀌면 입력하던 값이 지워진다**
- `switched`면 409 실패 경로에서도 양식을 새로 그린다(714–718). 예: none에서 등록 양식을 입력하는 중에 다른 사람이 기관장을 확정한 경우.
- 상태가 바뀌었으니 불가피하다고 볼 수 있다. 기록만 남긴다.

**P3-4. 각주 연결이 화면 낭독기에 안 읽힐 수 있다**
- `dd`에 aria-describedby를 단다(216). 포커스를 받지 않는 요소라 낭독기에 따라 읽히지 않을 수 있다.
- 각주 id `hc-fn-N`은 문서 전체에서 쓰는 고정 id다. 지금은 카드가 하나라 충돌이 없다.

**회귀 점검 결과 (문제 없음)**
- M.pending: 성공·409·404 경로에서 모두 비운다(737,749). none↔ok 전환 때 남는 확인 상자가 없다.
- 사진 절: 빈 머리일 때만 숨긴다. 그때는 정의상 사진이 없으므로 무효 버튼을 잃지 않는다.
- 사진 업로드 경로: 빈 머리에서는 사라진다. 이름 없이 사진만 올리는 길이 막힐 뿐이다. 사진을 올리면 ok가 되는 우회가 막히므로 오히려 일관된다.
- 포커스 가두기: Tab을 누를 때마다 `querySelectorAll`로 다시 계산한다(888). `#hf-name`은 none 모드에서 details 밖, 모달 안에 있다. `.hc-busy`는 opacity만 바꾸므로(index.html:1763) 바쁜 중에 focus()를 불러도 막히지 않는다.
- `#hf-name` 중복: ok 모드에서는 교체용 details 안 양식만, none 모드에서는 등록 양식만 그리므로 id가 하나뿐이다.
- 이스케이프: factsHtml 값은 `mono→esc`, 출처는 `srcHtml`을 탄다. 후보 수는 숫자, descId는 esc를 거친다. 누락은 찾지 못했다.

## 4. 테스트 공백과 추가 제안
- 모달 안에서 ok→none 전환 흐름 테스트가 없다. `fakeDom` map(724)에 `#hf-name`이 없어 focusAfter 경로를 검증하지 못한다. 제안: ok 상태에서 모달을 열고 → ask-void-item → do → 재조회가 EMPTY_HEAD를 준다. 기대: `isModalOpen()` 참, forms innerHTML에 `data-form="add-head"`, `hf-name.focused === 1`, status는 포커스 안 받음, `view().status === 'none'`.
- none→ok 전환 테스트가 없다. 제안: EMPTY_HEAD에 NAME 후보가 있는 상태 → confirm-item → 재조회가 이름 있는 머리를 준다. 기대: withForms가 false여도 forms가 add-item 양식으로 바뀌고, status에 포커스.
- 상태 변화 없이 다시 그릴 때(none→none, 예: 등록 결과가 CANDIDATE) 포커스는 status, forms는 다시 그려진 상태여야 한다.
- 409 경로에서 상태가 바뀌는 경우도 없다. 제안: void → 409 → 재조회가 빈 머리. 기대: 오류 문구가 유지되고 포커스는 hf-name.
- `isEmptyHead`에 `fields:{ACTING:{value:false}}`인 경우 기대값을 명시해야 한다. P2-2의 정책이 정해진 뒤에 쓴다.
- `openModal(..., {focus:'add-head'})`가 none에서 `#hf-name`에 포커스하는지 확인하는 테스트도 없다.

## 6. 이관 메모
- [이관: 기획] 빈 머리 상태에서 다시 등록할 때 바로 확정할지, 팀장 승인 후보로 받을지 정책을 정해야 한다(P1-1). '기관장 없음'으로 볼 기준을 '이름 무효'로 할지 '모든 값 무효'로 할지도 정해야 한다(P2-2).
- [이관: 백엔드] 빈 CURRENT 머리를 `addHead`의 direct 판정과 후보 머리 `conflict` 판정에서 '현 기관장 없음'으로 볼지, 아니면 프런트가 빈 머리에 add-item으로 넣게 할지 정해야 한다. 이력에 이름 없는 PREVIOUS 머리가 쌓이는 문제도 함께 본다.
- [이관: 디자인] none 카드에서 입찰 D-day 띠와 [새로 고침]이 빠지는 것이 괜찮은지 판단이 필요하다(P3-1).
