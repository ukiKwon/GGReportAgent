### 질문하신 항목별 확인

1. **성공 응답 body 매핑: 회귀 없음.**
   - 이전 코드는 JSON 해석에 실패하면 null이었습니다. 지금은 `req`가 빈 본문을 `{}`로 돌려주고, 어댑터(dashboard.js:873)가 빈 객체를 다시 null로 바꿉니다.
   - 응답이 JSON `null` 그대로여도 null이 됩니다.
   - `goPrep`(dashboard.js:859–865)은 `prep`가 null이면 `openCase`를 건너뛰고 메뉴만 엽니다. 이전과 같습니다.

   - `x.r.status=200`은 고정값이지만, 성공일 때 `confirmFail`이 status를 읽지 않으므로 무해합니다.
2. **실패 매핑: 동등.**
   - HTTP 실패는 `{r:{ok:false,status}, body:{detail}}`로 바뀝니다. 그래서 `PREP_ALREADY_ACTIVE` 다시 읽기, 401/403 문구, 그 밖의 문구가 그대로 유지됩니다.
   - 본문이 JSON이 아닌 500은 이전에 body가 null이었고 지금은 `{detail:undefined}`입니다. `confirmFail`의 `x.body && x.body.detail` 결과가 어느 쪽이든 undefined라 같습니다.
   - 네트워크 실패(TypeError, status 없음)는 다시 던져져 기존 `.catch`의 "서버에 연결하지 못했습니다" 문구로 갑니다.
3. **X-Emp-No 헤더: 붙습니다.**
   - prep.js:842는 맨 이름 `fetch`를 호출합니다. prep.js 안에 이 이름을 가리는 지역 변수가 없습니다.

### 발견

**[권고 P2] 실제 경로가 시험되지 않습니다.**
- 노드에서 dashboard.js의 `root`는 `this`(최초 module.exports)이고 `self`가 없습니다. 그래서 `root.prep`이 늘 undefined입니다.
- 결과적으로 map-detail.test.js:181의 시험은 대비 경로(직접 fetch)만 지납니다. 이 경로는 브라우저에서 사실상 실행되지 않습니다.
- 어댑터 분기(dashboard.js:871–877)의 세 가지(`{}`를 null로, Error를 `{r,body}`로, 네트워크 오류 다시 던지기)를 보는 시험이 없습니다. 이 셋은 회귀 위험이 가장 큰 부분입니다.
- 197행 시험은 소스 문자열 검사입니다. 정규식 `\n  };`가 들여쓰기 두 칸에 묶여 있어 깨지기 쉽고, 동작은 보증하지 못합니다.

**[권고 P3] 캐시 무효화가 시험되지 않습니다.** prep.js:877–878이 지워져도 206행 시험은 통과합니다.

### 추가 시험 제안 (입력 → 기대)

어댑터 시험은 require 캐시를 지운 뒤 `global.self = { prep: 가짜 }`를 두고 dashboard.js를 다시 불러오는 방식으로 가짜 prep을 주입하면 됩니다.

| 입력 | 기대 |
|---|---|
| 가짜 `postConfirm`이 `{}`로 성공 | `{r.ok:true, body:null}` |
| 가짜가 `{bid_case_id:'B1'}`로 성공 | body가 그 객체 그대로 |
| 가짜가 `Error{status:409, detail:{code:'PREP_ALREADY_ACTIVE'}}`로 실패 | `confirmFail(x).again === true` |
| 가짜가 `Error{status:403}`로 실패 | 문구에 '권한이 없습니다(403)' 포함 |
| 가짜가 status 없는 `TypeError`로 실패 | Promise가 거부됨(reject) |
| `prep.fetchActives()`로 캐시 채움 → `postConfirm`(성공/실패) → `fetchActives()` | GET /preps를 다시 호출 |
