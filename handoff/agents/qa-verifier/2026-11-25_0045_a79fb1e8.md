## 3. 발견 목록

**P2-1. 협약 팝업에서 넣기 단추가 서버 규칙보다 많이 숨습니다(양방향)**
- **근거**

  - `popCanAdd`(`:230`)와 `popCanWatch`(`:225`)는 칩이 있으면 단추를 숨깁니다.
  - 그래서 ⓐ 내 관심 기관은 [목표에 넣기]가 숨고, ⓑ 팀 목표 기관은 [관심에 넣기]가 숨습니다. 서버는 두 경우 모두 허용합니다(`BidTargetService.java:391-405`).
  - 구현자 이관 메모는 ⓐ만 적었습니다. ⓑ가 빠져 있습니다.
- **재현**
  1. 영업부서 계정으로 국민은행 확정 줄 기관 A를 팀 목표로 넣습니다.
  2. [협약 중인 기관] 팝업에서 A 줄을 봅니다.
  - 기대: [관심에 넣기]가 보입니다(사람별 관심은 목표와 겹쳐도 됩니다).

- 숨길지 말지는 정책 판단이라 이관합니다(6절).

**P2-2. 넣을 곳마다 '이미 걸림' 판정이 서로 다릅니다**
- **근거**
  - 추가 창 검색: `takenFor(m.year, m.kind)`(`:2301`)는 고른 쪽만 '이미'로 칩니다.
  - 추천받기: `takenFor(0,'ANY')`(`:2224`)는 목표·관심을 둘 다 '이미'로 칩니다.
  - 빈 후보: `takenIds()`(`:1725-1729`)는 목표와 내 관심을 합칩니다.
  - 그래서 같은 기관이 검색에서는 '목표로 넣기 가능'인데 추천 목록에서는 빠집니다.
- **새로 생긴 경계 상황**
  - 기관을 고른 뒤 넣을 곳 라디오를 바꾸면, `m.inst`가 있을 때는 다시 검사하지 않습니다(`:2354`). 이때 서버가 409(ALREADY_WATCH 또는 DUP_TARGET)로 막습니다. 문구는 나오지만, 전에는 검색 단계에서 미리 막히던 경우입니다.
  - 재현: [목표 기관 추가] → 넣을 곳 '목표' → 내 관심에 있는 기관 A 검색·선택(이제 선택됨) → 넣을 곳을 '관심 기관'으로 변경 → [관심 기관에 넣기].
    - 기대: 미리 '이미 내 관심 기관' 안내가 나옵니다.
    - 실제: 서버 409를 받은 뒤에야 안내가 나옵니다.
- **빈 후보의 뜻이 바뀌었습니다**: 남의 관심 기관이 이제 내 빈 후보에 다시 나타납니다. 의도한 것인지 기획 확인이 필요합니다.

## 4. 테스트 공백과 추가 제안
- **`takenFor` 시험이 없습니다.** 클로저라 밖으로 꺼내지 않았고, 이번 동작 변경을 검증하는 시험이 없습니다. 꺼내거나 화면 시험으로 추가하기를 제안합니다.
  - 내 관심에 A, 2027 목표에 B가 있을 때:
    - kind='GOAL', year=2027 → B만 '이미'
    - kind='WATCH' → A만 '이미'
    - kind='ANY' → A와 B 둘 다
    - kind='GOAL', year=2028(불러온 해와 다름) → 빈 집합
- **`submitCancel` 분기 시험이 없습니다.** 관심 줄이면 `cancelTarget`이 아니라 `unwatch`를 부르고 body를 보내지 않는지, nochange면 창을 닫고 목록을 다시 읽는지 확인하는 시험이 필요합니다. 지금은 부품(`unwatch`·`unwatchOutcome`·`cancelState`)만 시험합니다(`kbboard-c54.test.js:229-254`).
- **`openCancel` 시험이 없습니다.** 사유 목록(`cancel_reasons`)이 비어도 관심 줄은 창이 열리고 목표 줄은 막히는지(`:2526`) 확인하는 시험이 필요합니다.
- **WATCH_USER_DENIED 403 시험이 없습니다.** 지금은 서버 한글 문구로 넘어가고, 문구가 비면 '영업부서만' 문장이 나옵니다(`:1517`). 의도를 고정하는 시험을 제안합니다.
- **구현 세부에 묶인 시험**: `kbboard-goals.test.js:614`는 소스 문자열을 그대로 비교합니다. 동작이 같아도 코드 모양만 바뀌면 깨집니다.
