## 4. 테스트 공백과 추가 제안
- **폴더 반입·같은 날짜**: 같은 날짜 plan+news, 열린 요청이 있는 상태에서 반입 → APPLIED_IMPORT_ID가 사업계획 판이고 CLOSE_REASON이 NULL(발견 1)
- **뉴스 OLDER 폴더 경로**: 뉴스 판 D1을 반입한 뒤 다른 내용·D0 파일 → scan `OLDER`, import `OLDER`. 지금은 서비스 문구 비교만 있고 폴더 경로는 사업계획만 시험한다(`PlanInboxServiceTest:279`).
- **detail `plan_state`**: 사업계획 판과 뉴스 판이 둘 다 있으면 `PLAN_FOUND`. 지금 시험은 NOT_FOUND·NEWS_ONLY만 본다(`InstitutionNewsServiceTest:152`).
- **onNewsImported RUNNING**: 요청이 RUNNING일 때도 APPLIED/NEWS로 닫힌다.
- **프런트**: `pc.rowHtml({status_cd:'APPLIED', close_reason:'NEWS', …})` 결과에 'NEWS'·'사유'가 없다(`frontend/test`). 지금은 우연히 안전한 상태를 시험으로 고정하자는 것이다.
- **NewsCsv 오탐 기대값**: 발견 2의 문구 4개와 발견 3의 공백 2칸을 통과로 둘지 거부로 둘지 정해 시험으로 고정한다.
