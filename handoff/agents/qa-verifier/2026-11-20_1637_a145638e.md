## 3. 발견 목록

**P2-1 저장·보내기 응답이 오면, 확인 상자가 떠 있어도 잠갔던 단추가 다시 눌린다**
- 근거: dlg.js:135는 확인 상자를 띄울 때 이미 `disabled`인 단추를 잠금 목록에서 뺀다.
  - 저장 중 [저장]은 app.js:454에서 이미 disabled다. 응답이 오면 app.js:473의 `.then(function () { save.disabled = false; })`가 확인 상자와 상관없이 단추를 푼다.
  - [보내기]도 같다(notify.js:287, 302).
- 재현(서버 모드, 응답을 느리게 해서):
  1. 기관 추가에 이름·구분·지역을 넣고 [저장]을 누른다.
  2. 응답 전에 Esc를 누른다. "닫으면 입력한 기관 정보가 사라집니다" 확인 상자가 뜬다.
  3. 409(이미 등록된 기관명)가 도착한다.
- 기대: 확인 상자가 떠 있는 동안 머리·발 단추는 막혀 있어야 한다(규격 7-7).
- 실제: [저장]이 다시 눌린다. 409 경로에서는 dlg.invalid(app.js:459)가 이름 칸으로 커서를 옮겨 [계속 작성]에서 포커스를 뺏는다. 쪽지 [보내기]도 같은 순서로 재현된다.
- 볼 곳: dlg.js:135(이미 disabled인 단추도 잠금 대상으로 기록할지), 또는 app.js:473·notify.js:302에서 확인 상자가 열려 있는지 확인하는 조건.

**P3-1 [열기 →]에서 읽음 처리가 실패해도 사용자는 알 수 없다**
- 근거:
  - notify.js:233–234의 `done.then(function () { go(row.dest); ... })`는 markRead 결과(ok)를 보지 않고 이동한다.
  - markRead 실패 시 setErr(181)가 문구를 쓰지만, 곧바로 go(200)의 close()가 onClose=resetDraft(144 `setErr('')`)를 불러 문구를 지운다.
  - 예전 alert는 이동 전에 보였을 것이다(바뀌기 전 코드 미확인).
- 재현: /notifications/{id}/read가 500을 돌려주게 한 뒤, 안 읽은 개인 결재 쪽지의 [열기 →]를 누른다.
- 기대: 실패를 알린다(창을 유지하거나 이동 후 알림).
- 실제: 결재함으로 조용히 이동하고 배지도 그대로다.

**P3-2 blocker 검사와 go() 사이에 쓴 글이 확인 없이 사라진다**
- 근거: blocker(notify.js:228)의 isDraft 검사와 go()(234) 사이에 markRead를 기다리는 시간이 있다. 그동안 창이 열려 있어 nt-text에 글을 쓸 수 있다. go()의 close()는 확인 없이 닫는 함수(263)라, 쓴 글이 resetDraft로 지워진다.
- 창이 좁아 발생 가능성은 낮다. go() 직전에 isDraft를 한 번 더 보면 막힌다.

**P3-3 이동 후 포커스가 쪽지함 단추에 남는다**
- 근거: dlg.close(dlg.js:92)가 opener(#btn-notify)로 포커스를 돌린 뒤 go()가 btn.click()(notify.js:202)으로 화면을 바꾼다. 결재함이 열려도 키보드 위치는 위쪽 쪽지 단추다.
- 접근성 문제로 경미하다.

**P3-4 쪽지함이 열린 동안 30초마다 포커스가 사라진다** (기존 동작, 이번 변경으로 드러남)
- 근거: fetchList(notify.js:166)가 paintList로 nt-tabs·nt-list의 innerHTML을 다시 그린다. 탭이나 [열기 →]에 있던 포커스가 body로 빠진다.
- dlg의 Tab 가두기(dlg.js:173–174)가 다음 Tab에 첫 칸으로 돌려놓으므로 막히지는 않는다.

**P3-5 기관명이 공백뿐이어도 저장된다**
- 근거:
  - app.js:438의 `else if (inp.value)`는 trim하지 않는다. 그래서 validateRecord(logic.js:455)가 "   "을 값이 있는 것으로 본다.
  - 반면 isDirty(app.js:423)는 trim한다. 공백만 넣은 창은 "바뀐 것 없음"으로 판정되는데, 저장하면 공백 이름 기관이 만들어진다.
- 기존 동작이지만 칸 경고(dlg.invalid)를 도입한 지금 함께 보는 게 맞다.

**P3-6 서버 모드가 아니면 쪽지함 [닫기]·[보내기]가 연결되지 않는다**
- 근거: notify.start는 서버 모드에서만 불린다(app.js:1144). 이 경우 nt-close·nt-send onclick이 비어 있다.
- notify.openCompose(designer.js:363)는 start 여부와 무관하게 창을 연다. 디자이너 [문의]가 비서버 모드에서 나올 수 있다면 [닫기]가 눌러도 반응이 없다(Esc·바깥 클릭은 dlg가 처리).
- 디자이너 화면이 서버 전용이면 문제 없다. 확인이 필요하다.

**질문별 확인 결과**
- ① openCompose 재호출: 문제 없음.
  - 쪽지함이 열려 있으면 뒤 화면이 inert라 [문의]를 누를 수 없다.
  - 혹시 이미 열린 상태로 호출되어도 dlg.open(69)은 옵션만 바꾸고, composeLink는 덮어쓰고, 쓰던 글은 보존된다. 흐름이 맞다.
  - 프로필이 없으면 nt-text.focus()는 숨은 칸이라 아무 일도 하지 않는다. composeLink는 닫을 때 비워진다. 문제 없다.
- ② go() 순서: dlg.close가 inert 해제 → onClose(resetDraft) → 포커스 복귀 순으로 진행한 뒤 btn.click()이 일어난다. 비활성 뒤 화면을 클릭하는 문제는 없다. blocker가 이미 draft 없음을 보장해서 nt-to만 지워진다. 남는 문제는 P3-1·P3-2뿐이다.
- ③ getComputedStyle: 권한 숨김이 인라인 `style.display='none'`(app.js:136)이므로 계산값에도 그대로 반영된다. 예전 비교 방식의 상위집합이다. 상위 `.tabs`가 숨겨져 있어도 단추 자신의 계산값으로 판정하므로 오판이 없다. 대상 탭은 approvals만 있어 상시 숨김인 myinfo와 충돌하지 않는다.
- ④ save.disabled: 409·!ok는 return으로 끝나 마지막 `.then`(473)에 도달하므로 풀린다. 다시 열 때도 419에서 풀린다. 잠금 문제는 P2-1 참고.
  - 성공 후 bootstrapServer가 실패하면 catch가 "기관은 추가되지 않았습니다"를 쓴다. 이미 닫힌 창이라 보이지는 않지만 문구 자체는 틀렸다(P3).
- ⑤ 다시 열기: 문제 없음. 경고 줄(.dlg-ferr)은 input 바로 뒤 형제로 #add-fields 안에 있어 wrap.innerHTML(403)이 칸과 함께 지운다. add-err는 419에서 비운다.
- ⑥ range 비교: 문제 없음. base를 fill 직후 같은 collect()로 만들어, 단계(step) 맞춤과 색 소문자 정규화가 양쪽에 같게 적용된다. 초기화 후에도 base를 다시 잡는다(372).
- ⑦ 선택자: 문제 없음. `#tab-map` 하위로 more-table·modal을 꾸미던 규칙이 없다(index.html 867–872·1605는 #map-stage 관련만). .more-table 규칙(1498–1500)은 범위 없는 전역 규칙이다. JS 쪽도 id로만 찾는다.
  - more-find가 `.dlg-note`라서 확인 상자가 여기 들어갈 자리인데, isDirty가 없어 실제로 확인 상자가 뜨지는 않는다.

## 4. 테스트 공백과 추가 제안
- dlg.test.js 85–149는 소스 문자열 단언뿐이다. 코드 서식에 과하게 묶여 있어, 공백이나 함수 형태만 바꿔도 깨진다(예: 93의 isDirty 본문 정규식). 동작은 검증하지 않는다.
- _fakedom_dlg.js로 추가할 케이스(입력 → 기대값):
  1. 지도 색상: 열기 → 값 그대로 Esc → 확인 상자 없이 닫힘. 색 하나 바꿈 → Esc → .dlg-cf 생김. 초기화 → Esc → 확인 상자 없음.
  2. 기관 추가: 이름만 넣고 저장 → type·region 칸에 aria-invalid, .dlg-ferr 2개, 포커스는 type. 닫고 다시 열기 → aria-invalid·.dlg-ferr 0개.
  3. 기관 추가 서버 409(fetch 가짜) → 이름 칸 경고, save.disabled === false.
  4. P2-1 회귀: 저장 중 requestClose → 응답 도착 → 확인 상자가 열린 동안 save.disabled === true.
  5. 쪽지: send 빈 값 → 두 칸 경고, 포커스는 nt-to. 내용만 비었을 때 → 포커스는 nt-text.
  6. 쪽지: openCompose({recipient, institutionId:5}) → 닫기 → 다시 open → send body에 institution_id 없음.
  7. blocker: 탭 단추 style.display='none' → 권한 문구. 글이 있으면 → draft 문구.
  8. P3-1: markRead 500 → 이동하지 않거나 오류 문구가 남음(어느 쪽이든 정책 결정 후).
