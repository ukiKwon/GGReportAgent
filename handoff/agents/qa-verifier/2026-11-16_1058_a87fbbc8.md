**P3-1. `onDash()` 조건이 "현황판이 보이는 중"보다 넓음** (`overdue.js:277-280`)
- 조건은 `#tab-soon` 활성 + `dashboard.isMounted()`입니다.
- 그런데 `isMounted`는 `!!host`이고, 화면을 옮겨도 `host`는 지워지지 않습니다. `showSoon`(`app.js:538-539`)은 `#dash-root`를 숨기기만 하고 unmount하지 않습니다. unmount는 다시 mount할 때만 일어납니다(`dashboard.js:1282`).
- 그래서 현황판을 한 번 연 뒤 같은 `#tab-soon` 자리의 사전준비·이사회·제안팀 화면에 있으면 `onDash()`가 true입니다.
  - 문구가 '현황판에서 경과 건 보기'로 바뀝니다.
  - 클릭하면 숨은 `#db-root` 안에서 `showPast()`가 돌아, 화면에는 아무 변화가 없고 포커스는 숨은 요소로 갑니다.
- **지금 경로로는 드묾**: 로그인 팝업은 `enterApp`에서만 뜹니다. 로그아웃 뒤 둘러보기에 보이는 준비중 화면은 현황판뿐이고, 나머지는 `paintNav`(`app.js:753`)가 지도로 돌려보냅니다. 앞으로 다른 진입점이 생기면 그대로 드러납니다.
- **볼 곳**: 판정 기준을 `navActiveId === nav.DASH_ID` 또는 `#dash-root` 표시 여부로 할지.

**P3-2. 현황판 여부를 팝업을 열 때 고정해 두어, 그 뒤 화면이 바뀌면 낡은 값이 됨** (`overdue.js:321,324,397`)
- 순서: `enterApp` → `onLogin`(동기) → 메뉴 권한 응답 → `paintTabs` → `paintNav`(비동기).
- 디자이너·마스터처럼 홈 역할이 아닌 사람은 팝업이 바로 뜹니다. 그 뒤 권한 응답에서 현황판 항목이 사라지면(map 키 꺼짐) `app.js:753`이 지도로 옮깁니다. 그래도 `st.dash`는 true로 남습니다.
- 결과: 클릭 → `showPast()`가 숨은 현황판에서 실행되고, 지도 패널도 열리지 않습니다. 사용자에게는 버튼이 먹지 않은 것처럼 보입니다.
- 반대 방향(지도에서 연 팝업 아래로 현황판이 열리는 경우)은 생기지 않습니다. 홈 역할은 `expectsDashHome`(`app.js:861`)로 팝업을 미루고, `applyHome`(`:564`)이 현황판을 열면 팝업을 버리기 때문입니다. **질문하신 "지도 이동 회귀"는 없습니다.**
- 같은 이유로 버튼 문구도 열 때 정해진 채 남습니다.
- **볼 곳**: 클릭 순간에 `onDash()`를 다시 확인할지.

**P3-3. 팝업이 센 경과 건수와 현황판 경과 묶음 건수가 다를 수 있음**
- 팝업은 `ov.state.summary.items`를 셉니다(`overdue.js:157`, 처리 상태 기준). 현황판 경과 묶음은 `M.overdue` 전체입니다.
- 현황판의 검색·지역·종류 필터(`st.q/region/type`)는 `showPast`(`dashboard.js:988-993`)에서 풀리지 않습니다. 필터가 걸려 있으면 '조건에 맞는 경과 기관이 없습니다'가 나올 수 있습니다.
- 숫자가 다른 것이 문제인지는 기획 판단입니다(이관 참조).

**확인 결과 문제없음**
- **id 고정의 영향 범위**:
  - 실제로 저장되는 것은 분류 id(`scan`)뿐입니다(`store.js:155,161` `NavOpen`).
  - 탭 목록은 메모리에만 있습니다(`app.js:478`).
  - 화면 기록 `screenName`은 `soon:`으로 시작하면 null입니다(`nav.js:267`). `menu_rules.js`와 서버(`kgi-ggreport-web/src/main`)에는 이 이름·id 참조가 없습니다.
  - 따라서 `NOTICE_ID` 고정은 무해하고 방어적입니다. 다만 주석의 "저장된 탭·순서·사번별 기억"은 실제보다 과장돼 있습니다(`nav.js:57`).
- **데이터 로드 전 `showPast`**: `mount`가 `refreshData()`를 동기로 불러 `M`을 바로 채웁니다(`dashboard.js:1016-1018, 1299`). `host`가 있으면 `M`도 null이 아니어서 `renderList`가 터지지 않습니다.

- **마크업 기본 문구**: `index.html:2244`의 문구가 `POP_ALL_MAP`과 같습니다.
- **옛 이름 노출**: 사용자 화면에 보이는 런타임 문구(index.html, js)에는 옛 이름이 없습니다. 남은 것은 주석·CSS 주석·문서·도구뿐입니다.

### 4. 테스트 공백과 추가 제안
- **`overdue.test.js:415-422`가 구현 문장에 묶여 있음**: 정규식으로 소스 문장을 대조합니다. 동작은 검증하지 않고 리팩터에 깨집니다. DOM 없이 갈아끼운 가짜 함수로 동작을 보는 케이스를 제안합니다.
  - `state.pop={dash:true}` + `dashboard.showPast` 가짜 → 클릭 → showPast 1회, openPanel 0회.
  - `dash:false` → openPanel 1회.
  - `dash:true`인데 `root.dashboard` 없음 → openPanel.
- **`onDash()` 판정**: `#tab-soon` 활성 + `isMounted` true지만 `#dash-root`가 숨김(사전준비 화면) → 기대 false. 지금 코드로는 이 테스트가 실패합니다(P3-1).
- **실제 id 유일성**: `nav.test.js:287`은 라벨 유일성만 봅니다. 모든 역할을 켠 `nav.build` 결과의 항목 id가 서로 겹치지 않는지 보는 케이스를 제안합니다. 나중에 누가 `'입찰 공고 현황'` 라벨로 새 항목을 만들면 `NOTICE_ID`와 충돌하기 때문입니다.
- **dashboard 쪽**: 마운트 전 `dash.showPast()` → 예외 없음. `dash.isMounted()`는 mount 전 false → 후 true → unmount 후 false.
