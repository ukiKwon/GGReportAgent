## 4. 테스트 공백과 추가 제안
- 생년 지우기: 나이 출처 제목 "1970년 인사 프로필"(noAge 통과)과 생년월일 1970-05-17 → Word 출처에 그 제목이 없고 "1970"도 없음. 지금은 생년 지우기를 확인하는 시험이 하나도 없다.
- P2-2 재현용: NAME 출처 제목 "프로필 1970-05-17"에 생년월일 1970-05-17 → (원하는 동작) Word 본문 XML에 "1970-05-17"이 없음. 지금은 실패할 것이다.
- INST_PERMIT 사진 → 그림 1개, 캡션 "기관 직접 허락". 지금은 KOGL1만 있다.
- 이름·직위 없이 TERM_END와 BIRTH_DATE만 → Word에 나이가 있는가(카드는 숨김). 기대 동작을 정한 뒤 고정한다(P3-1).
- 직위 없이 권한대행만 '예' → Word에 "출처 정보 없음" 줄이 없음(P3-2).
- 시작 "2022-03"과 끝 "2022" → 기대 동작(201 또는 끝도 YYYY-MM 필수 400)을 정한 뒤 고정한다(P3-5).
- 화면: refHtml 안내 문구 시험(1046줄)을 고친 문구로 바꾼다.
- 시험이 구현에 묶인 정도: `occurrences(xml, "「시험 출처 문서」")==1`은 XML run 분할에 기대고 있어 서식이 바뀌면 깨질 수 있다. 큰 문제는 아니다.

## 6. 이관 메모
- [이관: 기획] INST_PERMIT(기관 직접 허락) 사진을 은행 밖으로 나갈 수 있는 Word에 넣어도 되는지 확인이 필요하다. 허락 범위가 '화면 게시'에 한정될 수 있다. 공공누리 1유형은 출처 표시가 의무라 지금 구현(캡션 + 출처 목록)으로 충족한다.
- [이관: 기획] 생년월일을 다른 칸의 출처 제목·값에서도 막을지, Word 출력 단계에서 모든 출처의 생년 표기를 지울지 정해야 한다(P2-2).
- [이관: 기획] 끝이 비면 '~현재'로 보이는데, 기존 학력 데이터에도 그렇게 보여도 되는지(P3-6). 끝이 연도만일 때를 허용할지(P3-5).
- [이관: 디자인] Word 본문에서 위첨자 번호가 읽는 순서대로가 아니다(사진 캡션이 큰 번호로 먼저 나온다). 팀 결정이라 판단은 넘긴다. 시작 년-월 오류 위치(P3-11)도 함께 넘긴다.
- [이관: 데이터] collector/DB 반입으로 들어오는 학력·경력의 VAL_FROM 형식(연도만·없음)이 확정 경로에서 다시 검사되지 않는다(P3-7). SCHEMA에 반영할지 정해야 한다.
