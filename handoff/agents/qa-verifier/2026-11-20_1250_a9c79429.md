- **대조한 것**: 규격 `handoff/agents/design-reviewer/2026-11-20_1212_a501b274.md`, 서버 `TargetResultController.java`·`TargetResultService.java`·`TargetResultRules.java`·`TargetResultMapper.xml`·`BidTargetRules.java`(bidClosedBasis), 그리고 `nav.js`·`logic.js`(esc)·`dashboard.js`(regionName·openDetail)와의 연결.
- **못 본 것**: Playwright 연결 실패로 화면을 열지 못했습니다. 대비·넘침·포커스 링 실측이 없습니다. 테스트는 직접 돌리지 못해 호출자 출력(results 21 통과·1 skip, 프런트 전체 1634/1635)만 근거로 씁니다. 지시대로 design 대조 P2 세 건(표 머리 sticky, 은행 칸 폭·두 줄, '개발부서' 통일)은 반영 예정으로 보고 제외했습니다.

## 2. 판정: 조건부 통과
화면 논리·서버 계약·이스케이프·상태 처리는 규격·서버와 맞습니다. 조건은 둘입니다. 로그인할 때 열지 않은 화면에서 서버 요청이 나가는 문제(P2-1)를 막을 것, 그리고 nav.js가 이미 바뀌어 skip이던 시험이 이제 실제로 돌므로 다시 실행해 결과를 확인할 것(P2-2).

## 3. 발견 목록

### P2-1. `app.resetScreens`의 unmount 목록에 results가 없음 — 로그인 직후 숨은 화면에서 요청이 나감
- **근거**: `app.js:619` 목록은 `['portal','kbboard','dashboard','plans']`로 results가 빠져 있습니다. `results.onProfileChange`(`results.js:539–545`)는 `host`가 남아 있고 `#results-root`의 `style.display !== 'none'`이면 다시 mount해 `load()`를 부릅니다. showSoon만 `#results-root`의 display를 바꾸므로, 지도 탭으로 돌아가도 display는 `''`로 남습니다.
- **재현**:
  1. 영업 계정으로 협약 성과 관리를 엽니다.
  2. 로그아웃합니다. 세션이 지워진 뒤라 이때는 `serverOk()`가 false여서 요청이 나가지 않습니다.
  3. 다른 계정(예: map 키는 있으나 canView에 걸리는 역할, 또는 map 키가 없는 역할)으로 로그인합니다.
  - **기대**: 협약 성과 화면을 열기 전까지 `/bid-targets/results` 요청이 없습니다.
  - **실제**: `enterApp → onProfileChanged → results.onProfileChange → mount → load` 순서로 GET이 나갑니다. 화면은 숨은 채입니다. 서버 쪽에서는 새 계정 이름으로 접근 이력 `target-result n=…`이 남거나, 403이면 `guard.denied`가 '거부된 접근'을 기록할 수 있습니다. 열람·거부 기록이 실제 행동과 어긋납니다.
- **비교**: plans는 같은 문제를 resetScreens 목록에 넣어 막았습니다(같은 줄).
- **같은 뿌리(P3)**: 세션 안에서 계정을 바꿀 때(`app.js:223·283`)도 지도 탭에 있으면 같은 숨은 요청이 나갑니다. 이 부분은 plans와 같은 패턴입니다.

### P2-2. nav.js 작업 트리에 이미 RESULTS_ID가 있음 — skip이던 시험이 지금은 실행됨
- **근거**: `nav.js:66·82·110·134`(미커밋 M)에 `RESULTS_ID`가 있습니다. 시험 `results.test.js:291`의 조건 `{ skip: !nav.RESULTS_ID }`가 이제 거짓이라 실행됩니다. 호출자의 "1 skip" 출력은 그 전 시점의 것으로 보입니다.
- nav.js 변경이 다른 nav·권한 시험에 미치는 영향도 다시 확인해야 합니다.
- 커밋을 나눌 때 0d 소유인 nav.js를 이번 커밋에 섞지 않도록 주의가 필요합니다. 경로를 지정해 커밋하면 작업 트리 전체가 담기는 함정이 있습니다(메모리 규칙).

### P3-1. 서버 null이 화면에 'null' 글자로 찍힘
- **근거**: `logic.esc`는 `String(s)`라서(`logic.js:7`) `esc(null)`이 `"null"`이 됩니다. 서버에서 null이 올 수 있는 값은 셋입니다.
  - `institution_name`: `INSTITUTIONS` LEFT JOIN(`TargetResultMapper.xml:51`). `results.js:208`의 `nameHtml`이 그대로 씁니다.
  - `bank_name`: BANK 코드 LEFT JOIN이거나 ETC인데 `BANK_NAME_ETC`가 null인 경우.
  - `rank_name`: `selectCodes`가 `ENABLED = 1`만 읽음. 둘 다 `results.js:194`의 `banksCell`이 씁니다.
- **재현**: 기관 행이 지워진 목표, 또는 비활성 순위 코드를 가진 약정 줄이 있는 연도를 엽니다. 기관 칸에 "null", 은행 칸에 "null 국민은행"이 보입니다. title·text 쪽은 `str()`을 써서 빈 값으로 나옵니다.

### P3-2. 근거 열 '입찰 없음·공고 마감 YYYY-MM-DD'가 UTC 날짜임
- **근거**: `BidTargetRules.java:138`은 `basis_date = handledAt.substring(0,10)`이고, HANDLED_AT은 UTC ISO입니다. 한국 시각 오전 9시 전에 처리한 공고는 전날로 보입니다.
- 프런트는 `ymd()`로 그대로 씁니다(`results.js:170`). 10자만 와서 화면에서는 고칠 수 없습니다. 현황판(kbboard)과 같이 쓰는 기존 값입니다. 백엔드로 넘깁니다.

### P3-3. 잘림 안내 "목표 기관이 2,000곳을 넘어 앞의 2,000곳만 보입니다"가 실제와 어긋날 수 있음
- **근거**: `TargetResultService.java:52–54`가 자르는 단위는 '목표 행'입니다. 같은 해의 취소·관심 이동·연도 변경 행과 한 기관의 여러 목표 번호가 섞여 있습니다. 그래서 잘렸을 때 items는 2,000보다 적을 수 있습니다. 또 `activeInst`를 잘린 범위 안에서만 계산하므로, 살아 있는 행이 잘림선 뒤에 있으면 그 기관이 빠집니다.
- 화면 caption은 "표시된 N곳"이라 숫자 자체는 정직합니다. 안내 문구의 '2,000곳'만 부정확합니다. 문구는 기획, 집계는 백엔드로 넘깁니다.

### P3-4. resize 리스너가 쌓일 수 있음
- `results.js:526`의 익명 함수는 AbortController가 없는 환경에서 mount할 때마다 하나씩 쌓입니다. click·change는 같은 함수 참조라 중복되지 않습니다. 사내 Chrome이면 실영향은 없습니다.

### P3-5. 규격과 다른 작은 차이
- 뺀 곳이 0건일 때 요약 띠 보조가 "연중에 뺀 곳 0"뿐입니다. 규격 6-2는 "(목표에 안 셈)"을 붙입니다(`results.js:249`).
- 열 폭이 기관 210·결과 190·근거 160으로, 규격 220·150·150과 다릅니다(`index.html:2578–2579`). 은행 칸 폭 조정 때 design이 함께 보면 됩니다.

### 확인 결과 문제없음(근거)
- **응답 키**: 화면이 읽는 키는 모두 서버가 실제로 넣는 키입니다(`TargetResultService.java:110–127·156–223`). `rule`·`owner_name`은 그리지 않고, 시험 `results.test.js:260`이 이를 고정합니다.
- **null 처리**: `summary`·`removed_items`는 잘렸을 때 null이며 `bandHtml`(237행)·`removedHtml`(338행)·`renderBar`(406행)가 막습니다. `success_rate`가 null이면 "—"와 "아직 없음"이 나옵니다.
- **5분류·성공률**: `classify`가 서버 `SUCCESS/FAIL/PENDING/UNREGISTERED`와 `win_kind`에 1:1로 대응합니다. 성공률은 서버 값을 쓰고 공식은 `rate_numerator ÷ (success_n + fail_n)`입니다. 약정 줄이 없는 경우(이월 포함)는 서버가 PENDING/UNREGISTERED로 보내고, 화면은 '결과 미확정, 성공률에 넣지 않습니다'로 표시해 실패로 세지 않습니다. 다른 해로 옮긴 목표(YEAR_CHANGED)는 '연중에 뺀 곳'의 "다른 해로 옮김(이월)"으로 나옵니다. 공동금고는 `otherSuccess`가 받습니다.
- **KST**: `removed_at`(UTC, 마이크로초)을 +9h로 바꿉니다. 경계 시험이 `results.test.js:134–143`에 있습니다.
- **XSS**: 기관명·구분·사유·은행·제안 상태·title 속성·라디오 value 모두 esc를 거칩니다. `data-inst`는 `ID_RE`를 통과한 값만 들어가고, 서버 detail은 200자 이하만 esc해서 씁니다. 숫자는 `num()`을 거칩니다.
- **상태**: 403·401은 alert가 아니며 연도 선택을 숨깁니다. 400·409·연결 실패는 `role=alert`에 [다시 시도]를 붙입니다. 연도 경쟁 요청은 `seq`로 막습니다.
- **연도**: 응답 `today` 기준 −3~+1이며 서버 `yearParam` 범위 1990–2100 안입니다.
- **거르기·정렬**: 두 거르기는 AND로 묶이고, 다른 해에 없는 구분은 풀립니다. 약정 시작이 빈 값이면 방향과 관계없이 끝으로 갑니다.
- **접근성**: `aria-sort`는 th에, 보이는 caption, `role=img`+aria-label, fieldset+sr-only legend, `aria-expanded`/`aria-controls`, h2 `tabindex=-1` 포커스, polite live 영역을 갖췄습니다.
- **app.js 분기**: 분기가 plans·board·dash·notice·home 줄과 독립입니다. 다른 항목을 열면 `#results-root`를 숨기고, isPlans의 soon-plain 줄도 보존됩니다(시험 270행). `rs-` 접두는 다른 화면과 겹치지 않습니다.
- **DESIGN.md**: 71행 예외 목록에 `.rs-chip.kept`·`.rs-seg.kept`가 추가됐습니다. CSS 블록에는 새 hex가 없고 12px 미만도 없습니다.

## 4. 테스트 공백과 추가 제안
- **P2-1**: `APP_SRC`의 resetScreens 목록에 `'results'`가 있는지 확인합니다. 입력은 app.js 소스, 기대값은 `/\['portal', 'kbboard', 'dashboard', 'plans', 'results'\]/` 또는 그에 맞는 포함 검사입니다.
- **P3-1 null 값**:
  - `rowHtml(item({ institution_name: null }), C)` → 'null' 문자열이 없어야 합니다.
  - `banksCell(item({ banks: [{ rank_name: null, bank_name: null, is_kb: false }] })).html` → 'null'이 없어야 합니다.
- **liveText**: `liveText({ year: 2026, truncated: false, summary: null, items: [] })` → 지금은 "일부만 표시"라고 읽습니다. 잘림이 아닌데 그렇게 읽어도 되는지 정해서 고정하는 것이 좋습니다.
- **onProfileChange**: 숨은 상태(display none)에서는 다시 mount하지 않는다는 점을 소스 규칙으로 고정합니다.
- **DOM 흐름**: 연도 변경 중 이전 응답 무시, [다시 시도], '연중에 뺀 곳 n' 단추로 펼침과 포커스는 node 시험 밖입니다. 실사용 확인이 필요합니다.
- **결합도**: `results.test.js:266–271`의 app.js 검사가 문자열 포함이라 구현 세부에 결합돼 있습니다. 지금 규모에서는 수용할 만합니다.

## 7. 열린 질문
- 마스터 역할은 nav `onlyTeams`가 통과시키는데, 서버 `canView`(`Teams.ROLES` 안 + 영업 계열 또는 전산)가 마스터를 허용하는지 코드로 확정하지 못했습니다. 허용하지 않으면 메뉴는 보이는데 403이 납니다. design 7절 이관과 같은 질문입니다.
- 잘림이 아닌데 summary가 null인 경우(서버상 지금은 없음)에 live 문장을 "일부만 표시"로 둘지 정해야 합니다.
