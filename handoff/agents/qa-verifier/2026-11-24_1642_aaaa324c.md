## 3. 발견 목록
**P2-1 현황(ST)이 상세보다 늦게 오면 '계획 아래 뉴스 절'이 다시 고를 때까지 안 나온다**
- 근거: plans.js:1107 `maybeNewsOver`는 `ST.state==='ok'`가 아니면 sn=null이 되어 wantNewsOverPlan이 false를 낸다. 그런데 현황이 도착했을 때 부르는 `onStatus`(1075-1081)에는 maybeNewsOver 호출이 없다. 1087 주석("현황이 늦게 들어왔거나…여기서 다시 판단")은 loadDetail이 다시 불릴 때만 맞는다. loadDetail은 select·mount·retry에서만 불린다.
- 재현: 현황을 처음 받는 상태(새로고침 직후)에서 현황판·지도의 '기관 사업계획에서 보기'로 기관을 연다. 이 기관은 문서가 있고 계획 반입 뒤에 뉴스가 반입된 곳이다. mount(1468 loadDetail → 1471 ensureStatus)에서 /plans가 /status보다 먼저 오면 뉴스 절이 없다. 기대는 현황 도착 뒤 뉴스 절이 보이는 것이고, 실제로는 다른 행을 골랐다 돌아와야 보인다.
- 현황을 다시 받아(STATUS_FRESH_MS 경과) news가 새로 생긴 경우도 같은 경로로 반영되지 않는다.

**P2-2 검색 칸(#pl-kw)에 입력하는 중에 뉴스 응답이 오면 상세 전체를 다시 그린다**
- 근거: loadNews 완료 시(1121-1127) 조건 없이 renderPane을 부르고, 포커스만 같은 id로 되돌린다. 같은 문제를 onCollect는 이미 피하고 있다(1217 `if (S.selRow && !(a && a.id === 'pl-kw')) renderPane()`).
- T10 전에는 문서 0인 기관에서만 뉴스를 받았고, 그 화면에는 검색 칸이 없어 문제가 없었다. 이제 문서 있는 기관에서도 뉴스를 받으므로 새로 생긴 회귀다.
- 재현: 문서 있고 뉴스가 더 새로운 기관을 고른다. 곧바로 검색 칸에 한글을 입력한다(느린 망). 기대는 입력이 이어지는 것이다. 실제로는 input이 새 요소로 바뀌면서 커서 위치가 초기화되고 IME 조합이 끊길 수 있다. 값은 S.kw가 동기 갱신되므로 남는다.
- 측정은 하지 못했다. 사람 확인이 필요하다.

**P2-3 missing.csv 행 수가 화면이 말한 건수보다 적을 수 있다(U6 제외분)**
- 근거: 서버(InstitutionPlanService.java:549)는 뉴스 반입 3개월 안인 기관을 뺀다. 화면은 여전히 아래 두 곳에서 보낸 id 수를 안내한다.
  - 바닥: `목록에 담을 기관 N곳`(plans.js:625, missingIds 길이)
  - 완료 안내: `'자료 없는 기관 ' + ids.length + '곳의 목록을 내려받았습니다'`(1195)
- 뉴스만 있는 기관은 r.st가 없어 ids에 들어간다(613). 모두 제외되면 머리행만 있는 CSV를 받고도 "N곳 내려받았다"고 나온다. 감사 기록(Controller:97)은 out.rows라 맞다.
- 재현: 뉴스를 최근 반입한 기관 하나만 남게 필터한 뒤 [자료 없는 기관 내려받기]를 누른다. 기대는 0곳이라는 안내(또는 제외 수)다. 실제로는 "1곳" 안내에 CSV는 머리행뿐이다.

**P3-1 뉴스 오류는 화면에 표시가 없고 재시도는 '다시 고르기'뿐이다**
- 문서 있음 + 뉴스 error면 아무것도 그리지 않는다(diff 29-31). 다시 시도는 maybeNewsOver(1106) 경로로만 일어나고 사용자 행동 1회당 1회다. 무한 재요청은 아니다: loadNews → renderPane은 loadDetail을 부르지 않는다.
- 401 만료도 고를 때마다 1회 재요청한다. 의도대로라면 문제없다.

**P3-2 3개월 경계 (서버, 정상 동작이지만 기록해 둠)**
- 반입일(서울) + 3개월이 '오늘'과 같은 날부터 목록에 다시 나온다. 즉 '3개월 안'은 그날을 포함하지 않는다(isAfter).
- 월말이 접힌다. 11-29와 11-30 반입은 모두 2-28에 다시 나온다(Java plusMonths가 말일로 맞춤). 시간대 처리(UTC → 서울)는 맞다(RulesTest:104).

**P3-3 Date.parse와 서버 문자열 비교 차이**
- 실제 값은 `2026-11-24T03:00:00.123456+00:00`(마이크로초 6자리, Times.java:29)이다. Date.parse는 ms까지만 보므로, 같은 ms 안에서 차이 나는 두 반입은 화면에서 false, 서버에서 true가 된다. 실무에서는 사실상 일어나지 않는다.
- 반대 방향(화면 true, 서버 false)은 요청 1회만 더 나가고 그리지 않는다. 문제없다.
- 서버 비교는 IMPORTED_AT을 모두 Times.nowIso로 쓰므로(PlanService:273, NewsService:184) 고정 폭이라 안전하다. 단 DB에 손으로 넣은 다른 형식 값이 있으면 깨진다.

**회귀 확인(문제 없음)**
- docs 0 경로는 그대로 `loadNews(id)`(force 없음, 1096)다. newsSecHtml 기본 머리말은 '관련 뉴스'다.
- heading은 esc 처리돼 있고, 반입자 사번·SHA는 응답에 없다.

## 4. 테스트 공백과 추가 제안
- 화면 시험은 소스 정규식 위주라 P2-1·P2-2 동작을 잡지 못한다. 예: plans.test.js 신규 145-149 줄의 문자열 일치.
- 추가할 케이스("입력 → 기대값"):
  1. 현황 늦게 도착: ST loading 상태로 상세 ok(docs 1, import.imported_at=T0) → applyStatus(news imported_at=T1>T0) 후 onStatus → /news 요청 1회.
  2. 검색 칸 포커스: activeElement=#pl-kw 상태에서 뉴스 응답 도착 → #pl-kw 요소가 같은 노드로 유지(renderPane 미호출).
  3. 실제 형식: `wantNewsOverPlan({item_count:1, imported_at:'2026-11-24T03:00:00.123457+00:00'}, '2026-11-24T03:00:00.123456+00:00')` → 결과를 고정해 둔다(현재는 false 예상, 서버와 다름). `Date.parse('2026-11-24T03:00:00.123456+00:00')`가 NaN이 아님도 확인한다.
  4. 서버: 계획·뉴스 IMPORTED_AT이 같은 문자열 → newer_than_plan false.
  5. 서버 newsRecent: 반입 `2026-11-30T03:00:00.000000+00:00`, today 2027-02-27 → true, 2027-02-28 → false. 반입이 서울 자정 직전(UTC 14:59)과 직후(15:00)일 때 경계.
  6. missing.csv: 보낸 id 2개 중 1개 제외 → 응답 행 1. 화면이 그 차이를 안내하는지(P2-3 수정 뒤).
