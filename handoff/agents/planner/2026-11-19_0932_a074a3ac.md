**Q1. '임원급'은 시스템에서 누구를 말하나요?**
- 무엇을 정하는가: 회의록을 볼 수 있는 사람 명단입니다.

- 선택에 따라 달라지는 것: 영업부서가 아닌 임원(예: 다른 본부 임원)도 회의록을 볼 수 있는지가 달라집니다.
- 선택지
  - ① 결재 등급이 '대표급'인 사람이면 소속과 관계없이 열람 (권장 — 새 소속을 만들지 않아도 됨)
  - ② '임원' 소속을 새로 만들어 따로 관리
  - ③ 지금은 영업부장까지만 보면 충분 (임원 = 영업부장으로 간주)

**Q2. 녹음하는 '이사회 회의'는 특정 기관의 금고 입찰 건마다 열리는 회의인가요?**
- 무엇을 정하는가: 회의록을 기존 '이사회 자료 작성'(기관·연도별 자료)과 어떻게 묶을지입니다.
- 선택에 따라 달라지는 것: 기관 없이 열린 회의도 남길 수 있는지, 그리고 이사회 자료 화면에서 회의록으로 바로 갈 수 있는지가 달라집니다.
- 선택지
  - ① 대부분 특정 기관 건이지만 기관과 무관한 회의도 있다 → 회의록은 따로 두고, 기관·연도를 고르면 이사회 자료와 서로 연결 (권장)
  - ② 항상 기관 한 건의 이사회다 → 이사회 자료 안의 한 탭으로 넣음
  - ③ 기관과 무관한 내부 회의다 → 연결하지 않음

  - 외부 클라우드 STT(클로바 노트)로 회의를 녹음하는 것 자체가 사내 정책에 맞는지, 그리고 사용자에게 물을 질문 문안
  - 업로드 파일 재검사 기준(텍스트 전용·크기·인코딩)
  - 실명 가림 규칙(사용자 목록 대조의 오탐·누락)
  - 열람·목록 감사
  - '참고용·대외비' 표지
- **[이관: 백엔드]** Q1·Q2 답을 기다린 뒤 다음을 설계해 달라. 근거: 이 보고 §2·§4.
  - 회의록 저장(회의 머리·발언·시간 구간·요약 항목·다음 할 일 체크·수정 이력)
  - 원문과 요약 파서. 형식은 다음과 같다.
    - 원문: `참석자 N / MM:SS` 머리 + 빈 줄 구분. 60분을 넘을 때 표기는 모름.
    - 시간대별 요약: 시간 줄 / 주제어 줄 / `- ` 항목의 3단 구조, 구간 사이 빈 시간 있음.
    - 맞춤 요약: '주요 주제'·'다음 할 일' 제목 + `- ` 항목.
  - CP949/UTF-8 자동 판별
  - 원본 파일 미보관
  - 열람 권한(영업팀·영업팀장·영업부장 + Q1 정의)
  - 020 건과의 선택 연결(Q2)
  - DB 번호는 세션 분담표대로 받는다.
- **[이관: 디자인]** backend 설계 뒤 다음 규격을 정해 달라. 기다리는 것: Q2, backend 설계.
  - 회의록 목록
  - 상세(맞춤 요약 카드 → 시간대 구간 목록 → 구간을 누르면 원문 해당 시각으로 이동, '구간 밖' 발언, 잡음 발언 접기, '참고용·대외비' 표지)
  - 업로드 화면(파일 3개 중 원문만 필수, 가림 미리보기, 회의 일자·제목·선택 기관/연도)
  - 메뉴 위치('영업 추진 준비' 아래 이사회 자료 근처가 적절한지)
- **[이관: 프런트]** 디자인 규격을 기다린다. 기존 테스트 기준과 바닐라 JS를 유지한다. 020 화면에는 연결 바로가기 1곳만 추가한다.
- **[이관: 데이터]** 실제 회의 1건을 올린 뒤 다음을 표본 검수해 달라. 기다리는 것: 1차 구현.
  - 가림이 누락되거나 잘못 가려진 곳
  - 구간 연결이 맞는지(구간 밖 발언 수 포함)
- **[이관: PM]** Q1·Q2를 질문 장부에 매칭해 달라. NEXT 100(제안서 확정 → 사전준비)과 겹치는 파일은 없을 것으로 보인다(확인 필요).
