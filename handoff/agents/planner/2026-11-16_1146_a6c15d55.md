## 3. 용어·데이터 의미
- **"파일 검색 API"**: 업로드된 공고문·제안서 목록을 기관·연도·파일명으로 찾아 주는 창구다. 사람용 화면이 아니라 다른 시스템이 부르는 통로다.
  - 지금은 **결과 한 건마다 파일을 열어 본문 전체를 뽑아** 함께 돌려준다.
  - 그래서 위험 파일이 하나 저장되면, 누가 검색할 때마다 서버 부하가 반복된다.
- **"암호화 문서"**: 엑셀·파워포인트에서 '암호 설정'으로 저장한 파일이다. 두 경우로 나뉜다.
  - (a) 사람이 정한 암호: 지금도 서버가 못 열어 분석이 실패한다.
  - (b) 기본 암호로 잠긴 파일: 서버가 자동으로 풀어 연다. 이때 압축 폭탄 검사(ZipGuard)를 **건너뛴다**. 공격자가 쓸 수 있는 쪽이 이것이다.
  - 사내 DRM 파일은 이와 다른 형식이며, 해당 여부는 모름이다.
- **"목차 해석 차이"**: 검사기와 실제로 여는 부품(POI)이 zip 목차를 읽는 방식이 미세하게 다를 수 있다는 이론상 틈이다. 실제로 차이가 나는 사례는 확인되지 않았다(security '하·추정').

## 5. 결정이 필요한 질문(사용자에게, 2개)

**Q1. 업로드되는 공고문·제안서 가운데 암호가 걸린 엑셀·파워포인트가 있습니까?**
- 무엇의 이름표인가: 업로드 화면에 올린 파일을 서버가 열어 내용(슬라이드 제목·본문, 표)을 뽑는 '문서 분석' 단계다.
- 무엇이 달라지나:
  - 막으면 암호 문서는 원본만 보관되고 분석 결과가 비어 '분석 실패(암호 문서)'로 남는다.
  - 허용하면 지금처럼 두되, 일부 파일은 안전 검사를 건너뛴다.
- 선택지:
  - ⓐ 거의 없다. 암호 문서는 분석하지 않아도 된다 **(권장, 차단)**
  - ⓑ 자주 온다. 그래도 지금은 분석하지 않고, 암호를 풀어 다시 올리도록 안내한다(차단 + 안내 문구)
  - ⓒ 사내 문서보안(DRM)이 걸린 채로 온다. 모르겠다 → 차단으로 진행하고 DRM 문서 여부는 내부망에서 따로 확인

**Q2. 업로더의 '파일 검색' 통로를 다른 시스템이 쓰고 있습니까?**
- 무엇의 이름표인가: 업로더에 보관된 파일 목록을 다른 프로그램이 조회하는 통로다. 사람이 보는 화면이 아니다.
- 화면·업무 어디에 쓰이나: 저장소 안 화면에는 부르는 곳이 없다. 내부망 기동 점검 때 "목록이 잘 나오는지" 확인하는 데 쓴다.
- 무엇이 달라지나: 결과마다 붙던 '파일 본문 전체'를 빼고 목록만 돌려주려 한다. 본문을 받아 쓰는 시스템이 있으면 그쪽이 빈 값을 받게 된다.
- 선택지:
  - ⓐ 쓰는 곳 없다(08-27 기록대로) → 목록만 반환으로 진행 **(권장)**
  - ⓑ 있지만 목록만 쓴다 → 같은 진행
  - ⓒ 본문까지 쓰는 곳이 있다 → 본문 제공 방식(저장형 D)을 6-2 회신과 함께 다시 정함
