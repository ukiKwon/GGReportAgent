## 3. 용어·데이터 의미 정의
**'결과 확인'의 뜻**: 코드 근거로 보면 '금고 선정(지정) 결과 공고'가 맞습니다.
- `logic.NOTICE_WORDS.resultNote`가 '결과 공고를 확인하세요'입니다.
- 마감 지난 행의 문구는 '마감 지남(MM-DD) · 결과가 났는지 확인하세요'입니다.
- 띠 보조 문구는 '공고가 나서 결과를 기다리는 기관 — 결과 공고가 났는지 확인하세요'입니다.
- 범례에 '공고일 기준(결과 공고 미확인)'이 있습니다.
- planner·NEXT 보고서에 따로 정의된 기록은 없습니다(grep 0건). 코드 주석과 문구만이 근거입니다.

**대상은 두 갈래가 섞여 있습니다.**
- ⓐ awaiting: 접수 마감일을 알고, 그 날짜가 지났습니다.
- ⓑ late: 마감일을 모르고 공고 후 30일이 넘었습니다. 마감이 지났다고 **추정**만 하는 경우입니다.
- 해야 할 일은 같습니다. 어느 은행이 선정됐는지, 또는 유찰·재공고인지 확인해 '공고 상태 기록'(공고 종료 / 입찰 없음 / 지연·재공고 대기)에 적는 것입니다.

**새 이름 후보**
- A '선정 결과 확인 필요'(권장): 무엇을 확인할지가 말에 들어 있습니다.
- B '접수 마감 · 결과 대기': 상태만 말하고 할 일은 말하지 않습니다.
- C '금고 선정 발표 확인': 기관이 결과를 '발표'하지 않고 공고만 하는 경우가 있어 부정확할 수 있습니다.

**'공고 확인 어려움'(2번) 후보**
- ① 날짜 미상(예정일 근거 없음)
- ② 예정일이 지났는데 공고가 안 보임(`m.overdue`)
- ③ 6개월보다 먼 곳
- 셋 중 무엇을 넣을지는 업무 의미이므로 사용자 질문 Q1으로 올립니다.

**막대가 쓰는 날짜**: 기존과 같이 `effectiveBid`(공고로 확정 + 추정: 지난 선정일+약정 주기 / 약정 만료 6개월 전)입니다. 막대 이름을 '공고현황'으로 해도 실제로는 '공고 예정일'입니다. 추정이 섞였다는 표시는 원칙 1(실측이 전부)에 따라 남겨야 합니다.

## 5. 사용자에게 꼭 물을 것(1건)
**Q1. 다가오는 공고 막대의 '공고 확인 어려움' 칸에 어떤 기관을 넣을까요?**

설명: 막대는 기관 종류마다 한 줄이고, 1개월 내 / 3개월 내 / 6개월 내 / 공고 확인 어려움으로 나눠 색칠합니다. 이와 별개로 공고 예정일이 6개월보다 먼 기관이 많습니다. 이 기관들을 어디에 둘지에 따라 '확인 어려움' 칸의 크기와 뜻이 달라집니다.
- ⓐ (권장) '확인 어려움' = 예정일을 모르는 곳 + 예정일이 지났는데 공고가 안 보이는 곳. 6개월보다 먼 곳은 막대 밖에 회색 숫자 '그 뒤 n곳'으로만 보이고, 누르면 목록에 나옵니다. 근거: '확인 어려움'이 '담당자가 직접 알아봐야 할 곳'이라는 한 가지 뜻이 됩니다.
- ⓑ '확인 어려움' = 6개월보다 멀거나 날짜를 모르는 곳 전부. 네 칸으로 끝나 간단하지만, 날짜가 확실한 먼 기관이 '어렵다'로 보입니다.
- ⓒ 칸을 하나 늘려 '6개월 뒤'를 따로 둡니다(5칸).
