## 3. 용어·데이터 의미 정의 후보
**'제출서류'**
- (a) **RFP '제출서류·구비서류' 절에 적힌 은행 제출물 전체.** 예: 금고지정 신청서, 제안서, 서약서, 재무제표, 법인등기부등본, 인감증명.
- (b) (a) 중 RFP에 붙은 양식(붙임 서식)만.
- (c) (a)에 더해 '해당 시 제출' 같은 조건부 서류까지.
- 권장은 (a)입니다. 조건부는 목록에 두되 '- 대상 아님'으로 표시할 수 있게 합니다. 사용자 원문 '서류 전체 확인'과 맞습니다.

**'검수'**
- (a) 이름 대조만 합니다(목록 항목 ↔ 올린 파일 이름 또는 담당자가 이어 준 짝).
- (b) (a)에 더해 파일 안 첫 쪽 제목 글자로도 대조합니다.
- (c) (b)에 더해 부수·원본/사본·인감 날인 같은 요건도 봅니다.
- 1단계 권장은 (a)입니다. 담당자가 '이 파일 = 이 서류'를 직접 이어 줄 수 있게 합니다. (c)는 RFP 문장 해석이 필요해 LLM 단계 후보입니다.

**'서류 전체 확인 V'**
- (a) 담당자가 검수 화면에서 [확인]을 누른 날 V가 됩니다.
- (b) 빠진 서류가 0이 되면 자동으로 V가 됩니다.
- (c) (a) 뒤에 팀장이 확인해야 V가 됩니다.

## 4. 선택지 비교표와 권장안

### A-1. 목록 추출 방식
| 안 | 내용 | 영향 | 위험 | 되돌리기 |
|---|---|---|---|---|
| **A-1a 규칙 기반 + 사람 보정 (권장)** | RFP 텍스트에서 '제출서류·구비서류·제출 서류 목록' 제목을 찾아, 그 아래 번호 목록(1. 가. ① ○ -)과 표의 행을 항목으로 자릅니다. 결과는 '초안'으로 보이고 담당자가 더하기·고치기·지우기·대상 아님 표시를 합니다 | 서버에 추출기와 목록 저장(새 표), T4 상세 화면에 목록 편집과 대조 결과, 시험(골든 RFP 몇 건) | 공고마다 절 이름·표 모양이 달라 놓치거나 더 뽑습니다. 스캔 PDF는 텍스트가 없어 0건이 됩니다 → '자동 추출 실패, 직접 입력' 안내 | 쉬움 |
| A-1b LLM 추출 | 사내 모델이 목록을 뽑습니다 | 오케스트레이터와 모델 의존 | 결과가 매번 다릅니다(README 602 선례). 업무 서비스 뒤로 미뤄진 영역 | 중간 |
| A-1c 수동 입력만 | 추출 없이 담당자가 목록을 칩니다 | 가장 작음 | 사용자 요청('자동 추출')을 못 채움 | 쉬움 |

- **권장은 A-1a입니다.**
  - 정확도는 모름입니다. 실제 공고 몇 건으로 재 봐야 합니다. 그래서 자동 결과를 확정으로 쓰지 않고 '초안 → 담당자 수정 → 확정'으로 둡니다(원칙 1: 근거 없는 판정 금지).
  - 항목마다 근거(RFP 몇 쪽 또는 몇 번째 줄 원문)를 함께 보여 줍니다.
  - LLM은 2단계 후보로 남깁니다.
- **선결 사실**: RFP가 HWP 구형이면 추출하려면 hwplib가 필요합니다. 이것은 `ExtCheckInspector` 경로를 다시 쓸지의 문제로, [이관: 백엔드·보안] 대상입니다.

### A-2. 검수 결과 표현 (무엇만 정합니다. 배치는 디자인 몫)
- 목록 한 줄 = 서류 하나입니다. 상태는 4가지입니다.
  - **있음**: 짝지은 파일이 있습니다.
  - **빠짐**
  - **대상 아님**(-)
  - **확인 필요**: 이름이 비슷한 후보만 있습니다.
- 목록에 없는데 올린 파일은 따로 '목록에 없는 파일 n건'으로 보여 줍니다. 초과 서류가 여기에 해당합니다.
- 요약 한 줄 예시: '서류 12 · 있음 9 · 빠짐 2 · 대상 아님 1 · 목록 밖 파일 1'
- 대시보드 칸 연결은 Q1 기호를 그대로 씁니다.
  - 확인을 누르면 V입니다.
  - 목록이 있고 파일이 1건 이상이면 △입니다.
  - RFP가 없으면 -입니다. 지금 T4의 '해당 없음' 조건과 같습니다.
  - 나머지는 빈칸입니다.
- **T4 완료 판정 '첨부 1건 이상'은 '담당자 확인'으로 바뀝니다.** 024 판정 규칙을 바꾸는 일입니다. [이관: 백엔드]

### B. 맞춤법을 붙일 범위
| 안 | 범위 | 영향 | 위험·비용 | 되돌리기 |
|---|---|---|---|---|
| **B-a 시스템 안 긴 글 입력란 (1단계 권장)** | T1 기관 정보 요약 양식(NEXT 100 S2), 이사회 자료 작성, 기관장 편집 등 문장형 칸에 [맞춤법 검사] 버튼. 의심 낱말 목록 → 고칠 말 제안 → 사람이 반영 | 칸이 있는 화면 몇 곳과 서버 또는 브라우저 엔진 1개 | 번들 사전은 공개 웹 검사기보다 약할 수 있음(정확도 모름). 업무 용어(금고·출연금 등)를 오탐 → 예외 낱말 등록 필요 | 쉬움 |

| B-c 모든 입력란에 실시간 밑줄 | 메모·짧은 칸까지 | 화면 전반 | 짧은 칸에서 소음, 바닐라 JS 범위가 넓어짐 | 중간 |

- **권장**: 1단계는 B-a, 2단계는 B-b입니다.
  - 버튼식(누를 때 검사)을 권장합니다. 실시간 밑줄은 쓰지 않습니다.
  - 이유 1: 사용자가 실제로 고치는 곳은 시스템 안 작성 화면입니다.
  - 이유 2: 파일 검사는 고칠 수 없고 보고만 할 수 있어 효용이 한 단계 낮습니다.
  - 이유 3: 엔진 정확도를 먼저 B-a에서 확인한 뒤 파일로 넓히는 것이 되돌리기 쉽습니다.
- **공통 제약**
  - 검사할 글은 외부로 나가지 않습니다(제안서 내용은 대외비).
  - 엔진과 사전은 저장소에 넣거나 반입합니다(라이선스 확인).
  - '폐쇄망·외부망 같은 결과'를 지키려면 망에 따라 엔진을 바꾸는 분기를 두지 않습니다.

## 5. 결정이 필요한 질문 (최대 2개)

**Q-A. 제출서류 '서류 전체 확인'은 언제 V가 되나요?**
- 무엇: 대시보드의 제출서류 칸입니다. 상세 화면에서는 RFP에서 뽑은 서류 목록과 올린 파일을 대조합니다. 자동으로 뽑은 목록은 틀릴 수 있어 담당자가 고칠 수 있게 합니다.
- 달라지는 것: 누가 '다 갖췄다'를 책임지는지, 빠진 서류가 있어도 V가 될 수 있는지입니다.
- 선택지
  - ⓐ 담당자가 목록을 보고 [확인]을 누르면 V가 됩니다. 빠진 서류가 있으면 경고를 띄우되 막지는 않습니다. **(권장)**
  - ⓑ 빠진 서류가 0이 되면 자동으로 V가 됩니다.
  - ⓒ 담당자 확인 뒤 팀장이 한 번 더 확인해야 V가 됩니다.

**Q-B. 맞춤법 검사를 어디에 먼저 붙일까요?**
- 무엇: 이 시스템 안에서 글을 쓰는 칸과 올린 제안서 파일 중 어디부터 할지입니다.
- 달라지는 것: 칸에서는 바로 고칠 수 있습니다. 파일은 '몇 쪽 무슨 낱말' 목록만 보여 주고 고치기는 한글·워드에서 합니다.
- 선택지
  - ⓐ 1단계는 시스템 안 긴 글 칸(기관 정보 요약 양식·이사회 자료 작성·기관장 편집)에 [맞춤법 검사] 버튼. 파일 검사는 2단계입니다. **(권장)**
  - ⓑ 올린 최종 제안서 파일 검사부터 합니다.
  - ⓒ 둘 다 한 번에 합니다.

(팀이 정하고 결과로 보고할 것: 목록 추출은 규칙 기반 + 사람 보정, 검수는 이름 대조와 담당자 짝짓기, 실시간 밑줄은 쓰지 않음, 업무 용어 예외 낱말 등록.)
