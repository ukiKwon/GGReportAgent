# 이사회 자료 작성 — 사용자 원래 요건 재대조와 MVP 재조정 (planner, 2026-11-02)

> 메인이 planner 응답을 저장했다(에이전트는 읽기 전용). 계기: 사용자가 원래 요건을 직접 재설명(아래 원문).

## 0. 사용자 원문 (2026-11-02)
"수익성분석표로부터 지난번 말해줬던 양식을 뽑아내야하는 요건이고, 그게 docs에 바로 붙여 넣을 수 있는 형태거나 docs로 내려받을 수 있거나 하는 거야. 그리고 화면상에서 엑셀 자료로부터 양식이 잘 뽑혔는지 확인할 수 있는 좌우 확인하는 기능이 있거나 tooltip 방식으로 올리면 어떤 부분을 가져왔는지 보여준다거나 하면 좋겠다는 거였고. 매핑을 했는데 틀렸을 수도 있으니깐 양식의 값을 수정할 수도 있는데, 수정을 실제로 입력하려고 하면 관련된 수익성 분석표가 어디였는지 보여주면 좋을 꺼같아. 그럼에도 진행한다고 하면 이제 진행하는 거고. 이 기능이 왜 필요하냐면 수익성분석표는 round 처리가 되어있다보니깐 실제 값을 맞추려고 하다보면 양식상에 사용자가 수정이 필요한 경우가 생겼었어. 그리고 양식에 대한 폼은 팀별로 조금 형태가 다른 듯했어. 용어도 수익성 분석표상에서 다를수도 있고. 대략 이런 요건이야. 그 외 이사회 자료(내가 최종적으로 보고자 하는 결과물)하는 데 도움 될만한 부가적인 기능도 기획자가 생각해주면 좋겠어"

## 1. 읽은 것·못 본 것
- 읽음: NEXT 26·37·38, planner 10-30 요건 정본, 11-02 착수 기획, design 11-02 MVP 규격, backend 11-02 서버 구현안 요약, frontend 10-30 표 편집·붙여넣기 조사. 사실 확인용 코드: `boarddoc/BoardExcelFill.java`, `docfill/XlsxBook.java`.
- 못 봄: 실제 엑셀 사본(매핑은 가상 엑셀 기준), 팀별 수익성분석표 실례, 실행 화면, 폐쇄망 PC 워드 붙여넣기 실측, 한글(HWP)·구글 문서 사용 여부.
- 메인 지적 ①~⑥ 검증: ①②③⑤⑥ 맞음. ④ 정정 — "반올림 전 원래 값 미표시"는 사용자 확정 결정으로 기록된 곳이 없음(착수기획 용어 후보 1번은 오히려 "표시값(+원래 값)", backend는 열린 질문으로 남김, 구현만 표시값만 싣는 상태).
- **추가 발견(중요)**: 합계 불일치 경고(SUM_MISMATCH)가 반올림 전 원래 값끼리 비교한다(BoardExcelFill.java:82-95, 129-135). 엑셀 합계 칸은 보통 원래 값의 합이라, **"표시된 값을 더하면 표시된 합계와 안 맞는다"는 — 사용자가 수정하게 되는 바로 그 상황을 이 경고는 잡지 못한다**(추정). 부동소수 차이로 엉뚱한 경고 가능성도 확인 필요.

## 2. 확정 전제(다시 열지 않음)
흐름(양식 선택→업로드→자동 입력→좌우 대조→값별 확인→초안 워드), MVP 결재 없음, 원본 엑셀 미저장·무상태, 표시값 그대로·자동 보정 없음, 양식 팀 공유·복제본만 편집·표 모양 편집은 뒤로, 매핑은 개발자 반영, 확인 칸 수정 시 확인 해제·"원본 …" 보조 줄, MS 워드는 사용자 준비. **재확인 필요**: 요건 Q4("머리글이 다르면 전체 중단") — 사용자가 "용어가 다를 수 있다"고 말함.

## 4. 용어 정의 후보(권장 1번)
- "docs": 1 MS 워드 / 2 한글 / 3 구글 문서(폐쇄망 불가 추정).
- "바로 붙여 넣을 수 있는 형태": 1 HTML 표 + 탭 구분 텍스트 동시(워드에서 표·병합·굵기 유지) / 2 탭 텍스트만 / 3 이미지(비권장).
- "반올림 차이": 1 표시된 구성 칸의 합 ≠ 표시된 합계 칸 / 2 칸 하나의 원래 값과 표시값 차이.
- "수정 확인": 1 칸마다 처음 고치기 직전 / 2 작업 전체 첫 수정 1회.
- "출처 툴팁": 1 호버와 키보드 포커스 공통(시트·셀·표시값·원래 값) / 2 호버 전용(비권장).

## 5. 선택지·권장안
- **5-1 원래 값 표시**: A 미표시 / **B 툴팁·상태 줄·수정 확인 줄에 표시(권장)** / C 칸 안 상시. B는 서버 응답 출처에 원래 값 추가 + 화면 3곳, 표시 자릿수 규칙 필요.
- **5-2 표시값 기준 합계 재검산**: A 지금(원래 값 기준) / **B 표시값 기준 + 차이 표시("표시 합 3,579 · 합계 3,580 · 차이 1") + C 수정 때마다 화면 재검산(권장 B+C)**. 자동 보정 없음.
- **5-3 용어(머리글) 차이**: ① 지금(전체 중단) / ② 별칭 사전 / ③ 팀(양식)별 매핑 파일 / **④ 위치 기반 유지 + 머리글이 다르면 그 표만 '주의'(전 칸 확인 필요), 전체 중단은 시트 없음·범위 밖만** / ⑤ 사용자가 화면에서 대응 지정. **권장 ④+② 병행**("개발자 반영" 원칙과 맞고 업무 중단 해소). ③은 팀 사본 2개 이상 오면, ⑤는 4단계. ④는 요건 Q4 변경이라 사용자 결정 필요.
- **5-4 수정 확인 흐름**: 원본 값이 있는 칸을 처음 고치기 직전(아직 "수정됨"이 아닐 때, Enter·F2·더블클릭). 이미 수정된 칸·읽지 못한 칸은 묻지 않고 하이라이트만. 오른쪽 원본에서 해당 셀로 스크롤·강조 + 인라인 확인 줄("이 값은 수익성분석 시트 F8(표시 1,234 · 원래 값 1,233.6)에서 가져왔습니다." + 관련 합계 차이) [그래도 고치기][취소], 포커스는 안전 버튼. 진행 뒤: 수정됨·원본 값·확인 해제·수정 사유(선택). 결재 건 보관은 2단계.
- **5-5 붙여넣기**: 대상 MS 워드(1차) / HTML 표(병합·굵기·정렬·테두리 인라인 스타일)+탭 텍스트, 화면 상태 표시(틴트·체크·삼각형) 제외 / **표 단위 [이 표 복사] + 전체 [모든 표 복사]**(전체는 제목·주석 포함) / 화면 현재 값 / 미확인 칸 있으면 안내 / http 폐쇄망은 최신 클립보드 API 불가 → 10-30 권장 방식(B+A), **폐쇄망 PC 워드 최소 표본 시험 먼저**.

## 7. MVP 재조정
- **1단계 추가**: 출처 툴팁(원래 값 포함), 수정 확인 줄, 표 단위·전체 복사, 응답에 원래 값, 표시값 합계 검산(F1·F2), 머리글 불일치 표 단위 주의 강등 + 별칭(Q4 결정 시), 수정 사유(F3, 화면 작업 중만), 점검 목록은 '확인했음' 조건 안내(F5)로만.
- **미룸**: F4·F6 → 2단계, F7·D표·C-1·page1 → 3단계, 팀별 매핑(③) → 사본 2팀 이상 뒤, ⑤·F9 → 4단계/보류.
- **순서**: 사용자 결정 Q1~Q6 → **서버 변경을 NEXT 38(오류 형식 통일)과 한 지시서로 묶음**(원래 값·표시값 검산·머리글 주의·별칭 — 계약 변경 1회) ∥ design 보강 규격(툴팁·수정 확인 줄·복사 버튼·주의 배너·사유 선택) → frontend 작성 모드(26 N2 먼저) → 복사는 착수 초기에 폐쇄망 PC 워드 표본 시험.
