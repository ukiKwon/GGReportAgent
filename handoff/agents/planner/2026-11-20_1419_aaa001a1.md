**코드에서 확인한 사실(판단의 근거)**
- 사업계획 반입 계약은 이미 있다. 기관 1곳당 CSV 1개, 파일 이름은 `{기관ID}_{YYYYMMDD}_plan.csv`이고 열은 25개다(`PlanCsv.HEADERS`, 주석에 "collector/SCHEMA.md 확장 시 동기화"라고 적혀 있다). 그런데 **SCHEMA.md에는 사업계획 절이 없다.** SCHEMA의 `institutions.csv`는 입찰 일정용이라 이 일과는 다른 계약이다.
- 반입 API `POST /institutions/{id}/plans/import`(관리자)는 있지만 **화면이 없다**(`plans.js:8`).
- 다시 반입해도 안전한 장치가 이미 있다. 최신 판과 같은 해시면 409로 막고, 현재 판보다 이른 날짜의 파일도 409로 막는다. 반입하면 그 기관의 열린 요청이 같은 트랜잭션 안에서 '반영됨'으로 바뀌고 요청자에게 쪽지가 간다.
- `export.csv`(목록 내려받기)에는 **요청 키(req_key) 열이 없다.** 열은 기관ID·기관명·이전 출처 도메인·요청자 수·최초 요청일·상태·올릴 파일 이름이다. 결과와 요청은 지금 **기관ID로 이어지고** 있다(기관당 열린 요청 1건, UQ_PCR_OPEN).
- **uploader는 지금 CSV를 받지 않는다.** `DocumentType`이 허용하는 확장자는 제안서 ppt·pptx와 RFP pdf·hwp·hwpx뿐이다(README의 "pdf·hwp·md"는 옛 기술). 저장 위치도 `classified/{카테고리}/{연도}/{기관명}/`이고 uploader의 기관 마스터 이름과 맞아야 한다. 파일명 규칙은 `{연도}_{기관명}_{설명}`이다. **사업계획 CSV 이름(`기관ID_날짜_plan.csv`)과는 규칙이 맞지 않는다.**
- 고정 폴더를 읽는 선례가 있다. `/inbox/{batch}/validate`·`/import`(설정 `inboxRoot`, 처리한 뒤 `batchesRoot`로 보관, 사람이 누름, 영업팀만)이고, 사업계획 시드도 서버 고정 위치(`ggreport.plan-seed.location`)를 읽는다.

## 2. 요구 요약
**확정된 전제(다시 열지 않음)**

- [수집 실행](agent 직접 호출)은 인터넷 PC 시험용이고, 내부 배포는 키를 비워 둔다(SCHEMA ⑩-6).
- 수집자 칸에는 사람이 아니라 프로그램 식별자를 적는다(Q-11-16-09). 원문 PDF는 저장하지 않고 CSV 행만 저장한다(세션 05 42행).

**새로 정할 것**: ① 결과 파일 계약의 정본 ② 웹이 경로를 읽는 방식(사람이 누름 / 자동) ③ uploader 저장 위치·이름 계약 ④ 요청 키를 쓸지 ⑤ [수집 실행]을 어떻게 둘지 ⑥ 단계 순서 ⑦ 업무 의미 질문(주기·반출 승인·누가 반입·실패 처리).

## 3. 용어·데이터 의미 정의 후보
- **'반입 대기 파일'**: (a) 정해진 폴더에 있고 아직 반입 기록이 없는 파일(권장) (b) uploader DB에서 '사업계획' 종류로 분류 완료된 파일 (c) 폴더의 모든 파일. 예를 들어 같은 파일이 두 번 올라오면 (a)에서는 두 번째가 '이미 반입됨'으로 보인다.
- **'수집 실패'**: (a) 담당자가 사유를 골라 표시(현행) (b) 망 밖 agent가 결과 요약에 '못 찾음'이라고 적어 보냄 (c) N주기 동안 결과가 없으면 자동으로 실패. 예를 들어 홈페이지에 계획서가 없는 군청은 (a)에서는 사람이 판단하고, (b)에서는 사유 코드가 붙어 들어온다.
- **'반출'**: 목록 CSV를 망 밖으로 가져가는 일. 시스템이 남기는 것은 내려받기 감사(COLLECT_EXPORT)까지다. 회사 반출 승인 절차는 시스템 밖의 일이다. 승인을 시스템 안에 둘지는 질문 Q2로 묻는다.

## 4. 선택지 비교 + 권장안

**① 결과 파일 계약의 정본**
| 안 | 내용 | 영향 | 위험 | 되돌리기 |
|---|---|---|---|---|
| A (권장) | 사업계획 CSV(`{기관ID}_{YYYYMMDD}_plan.csv`, 25열)를 정본으로 하고, SCHEMA.md에 '⑪ 사업계획 CSV' 절을 새로 쓴다 | 서버 무변경, 문서와 망 밖 agent만 바뀜 | 파일 단위라 배치 단위 근거(수집 시각·못 찾음)가 남지 않음 | 쉬움 |
| B | SCHEMA 배치 폴더(manifest+files/)에 plan 레코드를 추가 | 새 검증기·서버 코드 | uploader가 파일 단위라 폴더 구조가 깨짐 | 어려움 |
| A+ | A에 '수집 결과 요약' 파일(기관별 찾음/못 찾음/오류, ext-check `checks[]` 방식)을 선택으로 더함 | 2단계에 서버 추가 | 낮음 | 쉬움 |

→ **A로 시작하고 A+는 2단계에.** 이유: 지금 동작하는 반입 경로를 그대로 쓰고, uploader의 파일 단위 처리와도 맞는다.

**② 웹이 경로를 읽는 방식**
| 안 | 내용 | 장점 | 위험 |
|---|---|---|---|
| M (권장, 1단계) | 처리 화면 [폴더 확인] → 파일 목록과 검사 결과(통과·오류·이미 반입) → [반입] | 반입자가 사람(IMPORTED_BY)이라 감사가 기존 그대로, 실패가 눈에 보임, `/inbox` 선례와 같음 | 사람이 잊으면 지연 |
| T | 주기 자동 반입(WebLogic 타이머) | 사람 손이 안 감 | 반입자가 '시스템'이 되어 감사 주체·실패 알림 설계가 새로 필요, 잘못된 파일이 조용히 들어갈 수 있음 |
| M→T | M으로 운영해 보고 안정되면 T를 더함 | 위험을 나눔 | 2번 일함 |

→ **M을 먼저 하고, 사용자 주기 답(Q1)을 보고 T를 판단.**

보안 요구(무엇을 지켜야 하는지만 적는다. 어떻게는 백엔드 몫):
- 경로는 설정 한 곳에만 고정하고 요청에서 받지 않는다(시드 선례).
- 심볼릭 링크와 폴더 밖 경로는 거부한다.
- 파일 이름은 `PlanCsv.FILE_NAME`만 받는다.
- 크기는 기존 5MB 상한, 한 번에 처리하는 파일 수에도 상한을 둔다.
- 같은 파일을 다시 반입하면 409이고, 이를 '이미 반입됨'으로 보여 준다(멱등).
- 감사에는 파일 단위 결과를 남긴다(해시·행 수·결과 코드. 파일 원문 값은 남기지 않는다).
- 오류 문구에는 행 번호만 싣는다(기존 조건 9).
- uploader 폴더는 읽기만 한다. 웹이 uploader 파일을 옮기면 uploader DB의 저장 경로가 깨지므로, 처리했는지는 웹 쪽 기록으로 판정한다(확인 필요).

**③ uploader와의 경로 계약**
| 안 | 내용 | 비고 |
|---|---|---|
| U1 (권장) | uploader에 '사업계획 CSV' 문서 종류(csv)를 추가하고, 분류를 거치지 않고 정해진 전용 폴더 하나(예: `{base-dir}/plan-csv/`)에 원래 이름 그대로 저장 | 기관 마스터·`{연도}_{기관명}` 규칙과 분리, 웹은 그 폴더만 읽음 |
| U2 | 기존 분류 트리(`classified/카테고리/연도/기관명`)에 넣음 | 파일명 규칙이 맞지 않아 미분류로 빠짐 |
| U3 | 공유 폴더가 없으면 웹이 uploader REST(`/api/files/search`·`download`)로 가져옴 | 두 앱이 다른 서버일 때의 대안. 현재 API에 종류 필터가 없음(확인 필요) |

→ **U1. 단, 두 앱이 같은 디스크를 보는지가 전제(질문 Q5).**

**④ 요청 키(req_key)**: 지금은 **쓰지 않는 것을 권장한다.** 기관당 열린 요청이 1건뿐이라 기관ID로 충분히 이어지고, 키를 넣으려면 25열 계약과 망 밖 agent를 함께 바꿔야 한다. 2단계 A+ 요약 파일에 '어느 목록에서 나온 결과인지'를 남기고 싶다면 그때 목록 CSV에 키 열을 더하는 방법이 있다(팀 결정).

**⑤ [수집 실행]**: 이 흐름에서는 필요 없다. 확정 결정(시험용)이므로 지우지 않고 그대로 둔다. 다만 내부 배포에서 버튼이 보이는지는 프런트가 확인한다(키가 비어 있으면 503, 숨김 여부는 확인 필요).

**⑥ 단계 순서(권장)**
1. 계약 고정: SCHEMA.md에 '⑪ 사업계획 CSV' 절을 쓴다(파일 이름·인코딩·25열·추측 금지·BIRTH_DATE 등 금지 칸).
2. **반입 화면**(처리 화면의 '반입 대기 파일' 절, 안 M): 폴더에 손으로 파일을 넣어 끝까지 시험할 수 있다. 같은 화면에 파일 직접 올리기(기존 API)를 대안으로 둘지는 팀이 정한다.
3. uploader U1(문서 종류·전용 폴더).
4. 망 밖 agent 본체: 목록 CSV를 입력받아 기관별 plan CSV를 출력한다(collector, main과 파일 담당을 나눈 뒤).
