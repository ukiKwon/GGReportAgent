## 3. 업무 동작 정의(두 경로)

**단계 이름**(통일 제안):
1. 목표 등록 — 올해 노릴 곳
2. 제안 확정 — 이번 공고에 낸다
3. 개설 — 담당 지명
4. 사전준비 승인
5. 제안서 작성

**경로 ⓐ 목표 기관 경유 — 현재**
```
영업팀원 · 입찰 현황판 · [목표 기관 추가]→[결재 요청 쓰기]→창 [결재 요청]  ── 결재① 영업팀장(팀장이 올리면 부장, 부장은 바로)
   ↓ (공고가 뜨면. 올해 목표는 공고 전에도 가능 — 11-19)
영업팀원 · 입찰 현황판 목표 줄 · [제안 확정]→[확정하기]                  ── 결재 없음
   ↓
영업팀원 · 제안 준비 현황 · [개설 신청](담당 지명)                         ── 결재② 영업팀장
   ↓
담당 · 사전준비 · [사전준비 승인]                                         ── 결재③ (지금 영업부장 → 111에서 팀장)
```
확정까지 1번, 사전준비 시작까지 2번, 제안서 작성까지 3번이다.

**경로 ⓑ 전국 지역별 상태에서 바로 확정 — 현재**
```
영업팀원 · 지역별 공고현황 지도 팝업 / 입찰 공고 현황 / 상세 · [제안 확정]   ── 결재 없음 (목표 밖은 공고가 난 뒤에만)
   ↓  현황판 아래 '그 밖의 제안서 준비 중인 기관'에 보임(목표에 자동 등록 안 됨)
[개설 신청] ── 결재① 영업팀장  →  [사전준비 승인] ── 결재②
```
확정까지 0번, 사전준비 시작까지 1번, 제안서 작성까지 2번이다.

**권장안**: 경로 ⓐ에서 [개설 신청] 결재를 생략한다. 목표 등록 결재가 그 역할을 대신한다.
```
ⓐ 목표 등록(결재①) → 제안 확정(없음) → 개설: 담당 지명만, 팀장 알림·사후 변경 가능(없음) → 사전준비 승인(결재②)
ⓑ 제안 확정(없음) → 개설 신청(결재①) → 사전준비 승인(결재②)
```
→ **어느 길이든 "사전준비 시작 전 팀장 결재 1번 + 제안서 작성 전 1번"으로 같아진다.**

- 근거: 목표 기관은 이미 팀장이 "올해 노린다"고 승인한 곳이다. 같은 팀장에게 다시 승인받는 것은 '일을 두 번 하지 않는다' 원칙에 어긋난다.
- 생략 조건(팀 결정):
  - 공고 연도와 같은 해의 목표여야 한다.
  - 그 기관에 목표 변경 결재가 진행 중이 아니어야 한다.
  - 관심 기관·내년 목표·결재 중인 목표는 지금처럼 결재를 받는다.

## 5. 고른 기관 띠 재정의 초안(design-reviewer 요건)

**지금 문제**
- 동작을 고르기 전부터 띠 버튼이 [결재 요청 n건]이다. 실제로는 결재 요청 1건에 n곳이 들어가므로 '건'도 틀리다.
- 구분만 바꾸려 해도 결재 창(사유 필수)이 열린다.
- [고르기 해제]는 무엇을 푸는지 불분명하다. 결재를 취소하는 것으로 오해할 수 있다.

**요건(팀 결정)**
1. **값 수정은 띠를 거치지 않는다.**
   - 줄의 구분 칩 메뉴·메모에서 고르면 바로 저장한다. 관심 줄과 같은 방식이다.
   - 짧은 알림을 띄운다: "구분을 '신규 유치 도전'으로 바꿨습니다. 결재 없이 반영되고 기록에 남습니다."
   - 여러 곳을 한꺼번에 고칠 때를 위해 일괄 창에도 동작 '구분·메모 수정'을 두고, 이 동작만 있으면 사유 칸 없이 [수정하기]로 끝낸다.
2. **띠는 결재가 필요한 묶음 동작 전용으로 바꾼다.**
   - 문구 후보: `고른 목표 기관 n곳` · (오른쪽) `[빼기·옮기기 결재 요청…]`. 결재자 안내("영업팀장이 결재합니다")는 지금처럼 둔다.
   - 띠가 결재 전용이 되면 `[수정하기 n곳]`은 띠에 두지 않는다. 사용자 원문 "[결재 요청] 대신 [수정하기]"는 1번의 줄 바로 저장과 일괄 창 [수정하기]로 충족한다.
3. **[고르기 해제] 처리**
   - 체크박스로 풀 수 있으므로 띠 왼쪽의 작은 글자 단추 `선택 지우기`로 낮춘다. 사용자는 "없애자"고 했다.
   - 다른 탭·연도에 고른 줄이 남는 구조라 완전히 없애면 모두 푸는 방법이 사라진다. 디자이너가 머리 체크박스로 충분한지 판단한다.
4. 일괄 창에서 수정과 결재 대상이 섞이면 버튼을 `수정 n곳 바로 반영 + 결재 요청 m곳`처럼 둘로 나눠 보여 줄지 디자이너가 정한다. 권장은 섞지 못하게 하는 것이다(창 안 안내 "구분·메모 수정은 줄에서 바로 하세요").
5. 제안 확정 확인 상자(dashboard.js 1034·1060)에 한 줄을 넣는다.
   - 기본: "결재 없이 바로 확정됩니다."
   - 목표 기관이면 덧붙임: "목표 기관이라 다음 [개설]도 팀장 결재 없이 진행됩니다." 이 줄은 Q1 답에 달렸다.
