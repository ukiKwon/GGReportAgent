## 3. 용어·데이터 의미
**'잠김'(코드상 `mapped=true`)**
- 뜻: 작성 모드에서 엑셀 값이 들어갈 자리입니다.
- 양식 편집에서는 문구를 바꿀 수 없습니다. 화면은 입력칸을 만들지 않고, 서버는 그 칸을 보내면 "수정할 수 없는 칸"으로 거부합니다.
- 사용자가 풀 방법은 없습니다. 개발자가 양식 정의를 바꿔야 합니다.
- 칸 목록:

| 표 | 잠긴 칸 | 수 |
|---|---|---|
| A | 기관명, 출연금·예비비·전산 금액, 합계 | 5 |
| B | 명목가치·현재가치 각 7개 값 | 14 |
| C-2 | 8행 × (5개 연차 + 계) | 48 |
| C-3 | 5행 × (4개 연차 + 계) | 25 |
| C-4 | 산출값 3칸 | 3 |

- 매핑과의 관계: 이 칸 목록과 `excel-map.json`의 칸 목록이 정확히 같아야 서버가 매핑을 받습니다(`BoardExcelMap.java:132·443`). 잠긴 칸이 곧 엑셀 연결 대상입니다.
- 엑셀 채우기와의 관계: 작성 모드에서는 이 칸들만 채워지고 확인 체크·수정 대상이 됩니다. 반대로 잠기지 않은 칸(구분 이름, 머리글, 판단기준 문구)은 엑셀이 건드리지 않습니다.

**정의 후보 — '행 삽입'과 '행 추가'**
- 후보 ①: 추가 = 표 맨 아래(합계 행 위)에 붙이기, 삽입 = 지정한 행 바로 아래에 넣기
- 후보 ②: 둘을 하나로 보고 "이 행 아래에 행 넣기" 한 동작만 제공

**정의 후보 — 새 행의 종류**
- 후보 ①: 문구 행. 엑셀 연결 없이 작성 때 사람이 숫자를 직접 입력합니다.
- 후보 ②: 엑셀 연결 행. 개발자가 매핑을 추가해야 채워집니다.

## 4. 표별 현황과 행 편집 시 영향
| 표 | 행 구성 | 행 추가·삽입 | 행 삭제 | 행을 바꾸면 어긋나는 곳 |
|---|---|---|---|---|
| A | 머리글 + 출연금·예비비·전산·합계. 기관명은 세로 4칸 병합, 비고는 3칸 병합 | 미구현 | 미구현 | 병합 범위를 늘리거나 줄여야 함. 합계 계산이 위치 기준으로 출연금·예비비·전산 세 칸을 가리킴. 매핑 1~4행이 밀림 |
| B | 머리글 + 명목·현재가치 2행. 구분 1열이 2행 병합 | 미구현 | 미구현 | 매핑 1~2행이 밀림. 업무상 행을 늘릴 필요는 낮아 보임(확인 필요) |
| C-2 | 머리글 + 8개 지표 행 | 미구현 | 미구현 | 매핑 1~8행이 밀림. 행마다 '계' 열 포함 |
| C-3 | 머리글 + 5개 지표 행 | 미구현 | 미구현 | 매핑 1~5행이 밀림. 사업초기 열 추가 작업과 겹침 |
| C-4 | 머리글 + 회수기간·NPV·IRR | 미구현 | 미구현 | 매핑 1~3행. 판단기준 문구는 편집 가능 |
| D | 카탈로그에 아직 없음 | 3단계 계획(가변 행) | — | — |

**공통 원인**
- 칸 이름표가 "r{행번호}c{그 행에서 몇 번째 칸}"입니다(`BoardDocSpec.cellKey`).
- 이 이름표를 저장된 양식(편집 문구만 저장, `BoardFormJson`), 엑셀 매핑(`lines.row`), 작성 모드 값, 합계 검산이 모두 같이 씁니다.
- 그래서 행 하나를 넣거나 빼면 위 네 곳이 한꺼번에 어긋납니다.

**워드 출력**
- 기본 양식은 양식 정의를 그대로 그리므로, 행 구성만 맞으면 됩니다.
- 3단계에서 실제 워드 사본을 채우는 방식으로 바꾸면 다시 따져야 합니다.

**덤 발견(확인 필요)**
- 빈 칸은 편집되지 않습니다. A의 비고 칸과 B의 구분 병합 칸은 잠기지 않았는데도 양식 편집에서 입력칸이 안 생깁니다. 서버는 받아 줍니다.
  - 원인: `board.js:709`가 입력칸을 만들 때 원래 글자가 비어 있지 않을 것을 조건으로 둡니다(`p.text !== ''`).
  - 의도인지 확인이 필요합니다.
- A의 기관명은 매핑상 '직접 입력'인데도 편집 화면 설명이 "엑셀 값이 들어가는 칸 · 잠김"입니다. 문구가 맞지 않습니다.

- **열 편집**: 대. 모든 행의 칸 수와 병합, 엑셀 연차 열 매핑, 합계 '계' 열, 워드 열 너비가 함께 바뀌어야 합니다. 권장은 사용자 기능으로 만들지 않는 것입니다. 연차 수 변경이 실제로 필요하면 그때 "연차 수 선택(4년/5년)"처럼 제한된 형태를 따로 기획합니다.

  4. 디자인이 행 버튼·경고 문구 규격을 정합니다.

## 6. 사용자에게 물을 질문 (업무 언어)
- **질문 1. 행을 넣거나 빼야 하는 실제 경우는 무엇인가요?**
  - (가) 해당 없는 항목을 빼는 경우(예: 예비비가 없는 사업)
  - (나) 엑셀에 없는 항목을 사람이 적어 넣는 경우
  - (다) 엑셀의 다른 항목을 더 끌어오는 경우(이 경우 개발자 반영이 필요합니다)
- **질문 2. 새로 넣은 행의 숫자는 어디서 오나요?**
  - (가) 작성할 때 직접 입력(권장)
  - (나) 매번 개발자에게 엑셀 연결을 요청
  - (다) 둘 다(처음엔 직접 입력, 자주 쓰면 개발자 연결)
- **질문 3. 표 A '합계'는 행을 빼거나 넣으면 어떻게 계산할까요?**
  - (가) 남은 금액 행을 모두 자동으로 더함(권장)
  - (나) 원래 세 항목만 더하고, 차이가 나면 경고만 표시
- **질문 4. 연차 수(사업초기~4년차)가 다른 사업이 있나요?**
  - (가) 없음 → 열 편집은 만들지 않음(권장)
  - (나) 가끔 있음 → 그때 개발자가 양식을 바꿔 줌
  - (다) 자주 있음 → "연차 수 선택" 기능을 따로 기획
- **팀이 정할 것(묻지 않음)**: 머리글 행은 뺄 수 없게 함, 엑셀 값 행을 뺄 때 경고 문구, 기존 저장 양식을 새 형식으로 옮기는 방식, 기존 결재 건 버전 유지.
