## 3. 새 흐름
```
[지도·공고 현황·포털] [목표 기관 +] ─(팀장 결재 1, 영업부장은 결재 없이 바로)→ 목표 기관
   → 입찰 현황판 [제안 확정] (결재 없음, 목표 기관만)
   → [개설 신청] (팀장 결재 2)
   → … 사전준비 …
   → 작성 전 결재 (결재 3)
관심 기관(개인) ─ 확정 불가, [목표 기관 +]로 올려야 시작
```
목표를 거치는 경로는 결재가 3번이다. 영업부장이 직접 넣으면 2번이다.

## 4. 팀이 정할 것과 권장
| 항목 | 권장 | 이유 |
|---|---|---|
| 목표 넣기 결재가 대기 중일 때 | 비활성 '목표 기관 결재 대기' 배지로 보인다 | 같은 요청이 두 번 올라가는 것을 막는다 |
| 이미 목표 기관일 때(다른 화면) | '목표 기관 ✓' 배지와 [현황판에서 확정] 링크 버튼(현황판을 열고 그 줄로 이동) | 확정 위치를 하나로 두되 길을 끊지 않는다 |
| 확정된 뒤(다른 화면) | 지금의 [사전준비 열기]를 그대로 둔다 | 이미 확정한 뒤의 열람이라 제약과 관계없다 |
| 현황판의 관심 기관 줄 | [제안 확정] 없이 [목표 기관 +](결재 요청)만 둔다 | 사용자가 말한 편법 경로를 막는다 |
| 목표가 아닌데 이미 '준비 중'인 기존 건 | 그대로 진행되게 두고(소급 취소 없음) '목표 밖 준비 중' 표시를 유지한다. 목표 등록은 권유만 한다. 건수는 data-auditor가 센다 | 되돌리기 어려운 일을 피한다. 건수는 모름, 확인 필요 |
| 서버 confirm 조건 | 결재가 끝난 올해 목표 기관만 받고, 그 밖은 409로 막는다. 감사용 화면 값은 bid_board 하나로 줄인다 | security가 지적한 "화면에서만 막는다"는 구멍을 메운다 |
| 포털·공고 현황의 성공 문구 | "다음은 [개설 신청]" 문구를 현황판 쪽으로 옮긴다 | 확정 경로가 하나로 줄었다 |
