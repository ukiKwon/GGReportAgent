# backend-dev 보충 — gemma4:12b 반영과 시간 제한 기본값 (앞 보고서에 이어 붙임)

모델 이름은 설정 키로 넣게 하고 코드 기본값은 빈 값으로 둡니다. 시간 제한 기본값은 300초에서 **480초**로 올립니다.

## 1. 모델 이름 반영: 코드 기본값 대신 설정 파일
**권장안: `OllamaProperties.model`의 코드 기본값은 빈 값(`""`)으로 둡니다.**
- 이유: 기존 `LlmProperties.java:10-13, 77-78`이 같은 원칙을 적어 두었습니다. 모델 이름을 코드에 박았다가, 그 모델이 없는 환경에서 404로 헤맸다는 내용입니다.
- 빈 값이면 `OllamaGuard`가 NO_MODEL로 원인을 그대로 알립니다.

**값은 설정 파일 두 곳에 넣습니다.**
- **`config-envs/out-local/application.properties`**(추적 대상 견본) 끝에 추가합니다. `enabled=false`라 다른 PC에서는 꺼진 채이고, 키 대조(CLAUDE.md 3ⓓ)에는 잡힙니다.
  ```
  # 이 PC 시범 로컬 LLM(NEXT 129 ⑤) — 켜려면 config/application.properties 에서 enabled=true
  ggreport.llm.ollama.enabled=false
  ggreport.llm.ollama.base-url=http://127.0.0.1:11434
  ggreport.llm.ollama.model=gemma4:12b
  ggreport.llm.ollama.fallback-model=
  ggreport.llm.ollama.connect-timeout-ms=2000
  ggreport.llm.ollama.read-timeout-ms=480000
  ggreport.llm.ollama.max-response-bytes=65536
  ggreport.llm.ollama.think-off=false
  ggreport.llm.ollama.num-ctx=0
  ```
- **이 PC의 `config/application.properties`**: 사용자가 직접 넣습니다. 메인은 이 파일을 읽지 않습니다. 넣을 값은 `ggreport.llm.ollama.enabled=true`와 `ggreport.llm.ollama.model=gemma4:12b`이고, 나머지는 견본값 그대로입니다.
- **폴백 모델은 빈 값으로 둡니다.** 이 PC에 받아 둔 모델이 하나뿐이라 넘어갈 곳이 없습니다.

코드 기본값을 `gemma4:12b`로 박기를 원하면 `OllamaProperties`의 한 줄만 바꾸면 됩니다(`private String model = "gemma4:12b";`). 다만 위 이유로 권하지 않습니다.

시험 코드(`OllamaLlmClientTest` 등)는 실제 모델 이름에 기대지 않도록 가상 이름(`test-model`)을 씁니다.

## 2. 시간 제한 기본값

| 키 | 앞 보고서 | 수정 제안 | 근거 |
|---|---|---|---|
| `read-timeout-ms` | 300000 | **480000(8분)** | 아래 추정 |
| `connect-timeout-ms` | 2000 | 2000 그대로 | 루프백이라 연결은 바로 되고, 꺼져 있으면 즉시 거부됩니다 |
| Guard 상한 `MAX_READ_MS` | 600000 | 600000 그대로 | 8분 기본값에 여유를 둡니다 |
| 상태 조회(probe) | 2000 | 그대로 | 모델 목록 조회는 추론하지 않습니다 |

**추정 근거**(실측이 아니라 비례 추정입니다)
- 저장소 실측(`docs/obsidian/task-history/항목/항목 5 …md:75-79, 117-121`): 이 PC(8 vCPU, RAM 15.7GB, 내장 GPU)에서 `qwen3.5:9b`가 프롬프트 약 2.7천 토큰, 출력 약 1천 토큰에 **249초**가 걸렸습니다. 한글은 글자당 약 0.63토큰입니다.
- 이번 일의 크기:
  - 프롬프트: 규칙과 자료를 합쳐 약 1.5천~2.5천 토큰
  - 출력: 4칸 × 최대 400자 ≈ 1,600자 ≈ 약 1천 토큰
  - 작업량은 위 실측과 비슷합니다.
- 12b는 9b보다 매개변수가 약 1.3배 많습니다. CPU 추론은 대략 이에 비례하므로 **약 250~350초**로 봅니다.
- 첫 호출에는 8.0GB 모델을 메모리에 올리는 시간(수십 초, 추측)이 더해집니다.
- 그래서 **480초**로 잡습니다. 정상 호출이 시간 초과로 실패하지 않게 하면서, 멈춘 경우에는 8분 안에 'TIMEOUT 초안 없음'으로 끝납니다.
- 첫 실측에서 `elapsed_ms`가 400초를 넘으면 두 가지 중 하나로 대응합니다. 프롬프트 5번 규칙의 칸당 글자 수를 400자에서 250자로 줄이거나, 칸을 따로 부르는 방식으로 바꿉니다. 둘 다 서버 상수만 바꾸면 됩니다.
- **화면(6e)에 넘길 것**: 기다림 표시는 최대 8분 기준으로 합니다. fetch에 따로 시간 제한을 두려면 서버보다 길게(예: 9분) 잡아야 서버의 TIMEOUT 응답을 받을 수 있습니다.

## 3. '확인 필요' 목록 갱신
**해소된 것**
- 모델 이름: `gemma4:12b`
- 11434 포트가 열려 있는 것

**남은 것**(모두 아래 curl 1회로 확인됩니다)
1. `/api/chat`에 `"stream": false`가 필요한지, 본문이 `message.content`에 오는지
2. gemma4가 `format`(JSON 스키마)을 지키는지. 지키지 않아도 어댑터가 JSON 블록 추출로 받아 주지만, 품질이 떨어집니다.
3. gemma4에 생각 단계가 있는지. 있다면 `think-off=true`가 필요하고, 없는데 `think`를 보내면 거절되는지도 봐야 합니다. 이 모델은 제가 직접 알지 못하므로 **추측하지 않습니다**. 기본값은 보내지 않음(false)입니다.
4. 없는 모델 이름으로 불렀을 때 상태코드가 404인지
5. 첫 호출(모델 올리기 포함)과 두 번째 호출의 소요 시간. 응답의 `total_duration`과 `load_duration`을 봅니다(필드 이름은 추측).

호출자에게 아래 실행을 요청합니다. 읽기 전용이고 루프백만 씁니다.
```
curl -s -w "\nHTTP %{http_code} %{time_total}s\n" http://127.0.0.1:11434/api/chat -d '{"model":"gemma4:12b","messages":[{"role":"user","content":"{\"a\":\"\"} 형식으로 a에 인사말 한 문장"}],"stream":false,"format":{"type":"object","properties":{"a":{"type":"string"}},"required":["a"]},"options":{"temperature":0,"seed":0}}'
curl -s -o NUL -w "HTTP %{http_code}\n" http://127.0.0.1:11434/api/chat -d '{"model":"no-such-model:1b","messages":[{"role":"user","content":"x"}],"stream":false}'
```
결과에 생각 단계 글(예: `thinking` 필드)이 섞여 나오면 `think-off=true`로 바꾸고 같은 명령을 `"think":false`를 넣어 다시 실행합니다.

## 4. 앞 보고서에서 바뀐 곳
- `OllamaProperties.readTimeoutMs`의 기본값 300_000을 **480_000**으로 바꾸고, 주석을 "12b CPU 추정 250~350초 + 모델 올리기"로 고칩니다.
- ② 설정 키 표의 `read-timeout-ms` 기본값도 480000으로 바꿉니다.
- `OllamaLlmClient` 클래스 주석에 "이 PC 기본 모델 gemma4:12b(설정 키로 바꿈)"를 덧붙입니다. 이것 말고는 코드 변경이 없습니다.
- ⑥ 열린 질문 "모델 이름"은 닫힙니다.
