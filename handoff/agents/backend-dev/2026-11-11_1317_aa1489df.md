public static final class ConfirmedDocx {
    private final byte[] bytes;
    private final String fileName;
    private final int snapNo;

    ConfirmedDocx(byte[] bytes, String fileName, int snapNo) { this.bytes = bytes; this.fileName = fileName; this.snapNo = snapNo; }

    public byte[] getBytes() { return bytes; }
    public String getFileName() { return fileName; }

/**
 * 확정본 워드 내려받기 — 열람 자격은 CONFIRMED 열람 규칙 그대로: 담당자·활성 영업부장·확정한 결재선 팀장(canReviewQuiet), 그 외 404(없는 번호와 같음).
 * 확정(CONFIRMED)이 아니면 409 NOT_CONFIRMED. 값은 confirmed_snap 버전(현재 버전이 아니라 확정된 그 버전)을 양식(form_id·form_ver 저장값)에 얹는다.
 */
@Transactional(readOnly = true)
public ConfirmedDocx confirmedDocx(SysUser me, String id) {
    BoardMaterial m = canReviewQuiet(me, id);
    if (m == null) {
        m = loadVisible(me, id);
    }
    if (!CONFIRMED.equals(m.getStatusCd()) || m.getConfirmedSnap() == null) {
        throw coded(409, "NOT_CONFIRMED", "확정된 자료만 확정본을 내려받을 수 있습니다.");
    }
    BoardMaterialSnap s = mapper.selectSnap(m.getMaterialId(), m.getConfirmedSnap());
    if (s == null) {
        throw new IllegalStateException("confirmed board snapshot is missing");   // 서버 결함(500)
    }
    Map<String, Map<String, String>> values = new LinkedHashMap<>();
    for (Map<String, Object> t : tablesOf(s.getValuesJson())) {
        @SuppressWarnings("unchecked")
        Map<String, Object> cells = (Map<String, Object>) t.get("cells");
        Map<String, String> c = new LinkedHashMap<>();
        for (Map.Entry<String, Object> e : cells.entrySet()) {
            c.put(e.getKey(), String.valueOf(e.getValue()));
        }
        values.put((String) t.get("ref"), c);
    }
    byte[] bytes;
    try {
        bytes = BoardDocDocx.build(BoardDocSpec.withValues(forms.docForStoredAny(m.getFormId(), m.getFormVer()), values));
    } catch (BoardDocSpec.EditException e) {
        throw new IllegalStateException("stored board material does not fit its form");   // 저장 때 이미 검증한 값 — 서버 결함(500)
    }
    String inst = m.getInstitutionName() == null ? "기관" : m.getInstitutionName()
            .replaceAll("[\\\\/:*?\"<>|\\p{Cntrl}]", "_").trim();
    if (inst.length() > 60) {
        inst = inst.substring(0, 60);
    }
    String name = inst + "-" + m.getBoardYear() + "-이사회자료-확정본-v" + m.getConfirmedSnap() + ".docx";
    return new ConfirmedDocx(bytes, name, m.getConfirmedSnap());
}

## 5. 보안·위험·되돌리는 법
- 인증은 X-Emp-No 자기신고다. "담당자·부장·확정자만"은 실수 방지용 업무 규칙이며 사칭을 막지 못한다. 문서·로그에 "검증됨"이라 쓰지 않는다. 화면·버튼 식별자도 자기신고다.
- 파일로 나가는 값은 확정본 하나뿐이다. 접근 이력(ACCESS_LOG)에는 자료 번호·코드·버전 번호만, ACT 에는 사번·화면·버튼·outcome 만 남고 값·파일명·기관명은 없다.
- 사번이 있는 호출은 재작성 요구처럼 `run()` 이 `audit.before(id)` 로 ctx 를 잡아, 자격 없음(HIDDEN)·확정 아님이 아닌 거부는 CONFIRMED 자료에서만 ACT 로 남는다. 확정 아닌 자료에 대한 409 는 ACT 에 남지 않는다(기존 규칙과 같음).
- 가장 큰 설계 결정(표시): 다운로드는 `X-Screen-Id`·`X-Button-Id` 가 유효해야 하므로 `<a href>` 직접 링크가 안 되고 프런트가 fetch+blob 으로 받아야 한다. 헤더 강제를 풀고 싶으면 컨트롤러의 `run(..., true, ...)` 를 `false` 로 바꾸면 되고 그러면 UNKNOWN·ui_valid=false 로 기록된다. 기본안은 강제다.
- 쪽지 실패(예: DB 오류)는 같은 트랜잭션이라 반려·재작성도 롤백된다. 기존 notifyResult 와 동일한 성질이다.
- 신청자 제외 규칙으로 "신청자가 현재 담당자인데 쪽지를 2통 받는" 중복을 막았다. 단점: 신청자가 이미 담당에서 빠졌어도 기존 결재결과는 받는다(변화 없음). 담당자 전원에게 같은 본문을 한 번씩 정확히 보내고 싶다면 신청자 제외를 빼면 된다(신청자는 2통).
- ⓑ 이후 SCHEDULED·PASSED·REJECTED 로 이미 저장된 옛 행 중 개최일이 null 인 것은 그대로 남는다(마이그레이션 없음, 화면에서 빈 날짜로 보임). 새 입력부터 필수.
- 되돌리기: 위 패치 4개 파일(BoardUiIds, BoardMaterialService, BoardMaterialController, 테스트)을 되돌리면 끝이다. DB·스크립트 변경이 없고 `/menus` 응답·골든 04·05·`Menus.MENUS`·roles.js·Python server·기존 `/approvals`·`/tasks/{id}/approve` 는 건드리지 않았다.
- NEXT 70 세션과의 충돌: 이 안은 ApprovalRequestService 를 건드리지 않는다. 충돌 가능 지점은 BoardMaterialService 의 생성자(주입 1개 추가)뿐이다. 다른 세션이 같은 생성자를 바꾸면 인자 순서만 맞춰 병합.

## 6. 이관 메모
- [이관: 프런트] 확정본 내려받기 버튼 위치·문구는 디자인 몫이고, 구현 계약은 다음과 같다. 요청 `GET /board-materials/{id}/confirmed-docx`, 헤더 `X-Emp-No`·`X-Screen-Id`(`board_list`·`board_write`·`board_review` 중 현재 화면)·`X-Button-Id: confirmed_docx`. 성공 200 이고 본문은 docx 바이너리, 파일명은 `Content-Disposition` 의 `filename*=UTF-8''…`(RFC5987)에서 읽는다. 오류는 404(없거나 볼 수 없음)·409 `detail.code=NOT_CONFIRMED`·400 `UI_ID_REQUIRED`(JSON). 버튼 노출은 `status_cd==='CONFIRMED'` 일 때만 권장. 상세 응답에 `can_download` 를 따로 주지 않았으니 필요하면 서버에 요청(viewer 에 한 줄 추가). 프런트 상수 목록에 `confirmed_docx` 를 BoardUiIds 와 같이 더한다. — 기다리는 것: 디자인 버튼 배치 — 근거: BoardUiIds.java 주석 "화면을 새로 만들면 여기 목록과 프런트 상수를 같이 더한다".
- [이관: 프런트] 결과 저장 폼은 의결 예정·가결·부결 모두 개최일을 필수로 받아야 한다(서버 400 `MEETING_DATE_REQUIRED`, 메시지 "개최일을 입력하세요."). 반려·재작성 쪽지는 link 가 null 이라 알림창에서 이동 버튼이 없다 — notify.js DESTINATIONS 에 이사회 자료 목적지(예: `board:write`)를 추가하면 서버가 link 만 바꿔 보낼 수 있다. — 기다리는 것: 프런트 결정 — 근거: frontend/js/notify.js:17-20.
- [이관: 기획] 확인 사항 2개. (1) 쪽지 본문에 사유를 넣지 않는 안(권장)으로 구현했다. 사유까지 담당자 전원에게 알리려면 기획 판단 + PII 검사 재확인. (2) 결재 중 반려·재작성 때 신청자는 기존 알림만(사유 포함) 받고 새 쪽지는 받지 않는 중복 방지안. — 기다리는 것: 기획 의견 — 근거: ApprovalRequestService.java:271·403.
- [이관: 데이터] 없음.
