## 2. 요구/원인 요약
- 화면은 GET /prep-board?scope=mine을 부른다(prepboard.js:252-255). 칩을 바꿔야 scope가 붙고, 처음에는 scope 없이 역할 기본값으로 요청한다.
- 영업팀 기본값은 mine이다(PrepBoardService.java:125-131).
- 서버 거르기는 `PrepBoardService.inScope`(152-156)가 한다. mine 조건은 다음 셋 중 하나다.
  1. `meEmp.equals(p.getConfirmedBy())` — 제안 준비를 확정한 본인(개설 전·진행 중 모두).
  2. `active.contains(meEmp)` — BID_ASSIGNMENT에서 ACTIVE_YN=1인 담당(selectActiveAssignees, Mapper.xml:20-26).
  3. 끝난 건(CANCELLED)에 한해 `ever.contains(meEmp)` — 옛 담당 이력 전체(selectEndedEverAssignees, Mapper.xml:29-35). include_ended가 켜진 경우에만 읽는다(PrepBoardService.java:237).
- 팀, 팀장, 결재자, 기본 담당은 mine 조건에 없다. 팀·팀장은 team scope 전용이다(157-163).
- 그러므로 이영업이 활성 담당인데 김영업이 보이는 경우는 아래 둘 중 하나다.
  - (가) 김영업이 CONFIRMED_BY인 경우 — 가장 유력하다. 김영업이 그 건을 확정하고 이영업을 담당으로 지명하는 흐름이면 정상이다.
  - (나) 건이 CANCELLED이고 김영업이 옛 담당인 경우. 이때 include_ended가 켜져 있어야 한다.
- 결함 후보 하나: 표의 `is_mine`(PrepBoardService.java:233, 316)은 활성 담당만 뜻한다. 그런데 '내 작업' 탭의 거르기는 확정자도 포함한다. 두 기준이 달라 화면에서는 "내 작업 탭인데 담당은 이영업"으로 보인다.

## 의도인지 결함인지
- 의도로 판단한다. 근거는 세 가지다.
  - 주석(PrepBoardService.java:149): "mine = 확정자 본인 또는 활성 담당(개설 전 포함) + 끝난 건은 옛 담당도".
  - 시험 U12(PrepBoardServiceTest.java:277): "확정자 본인(개설 전 포함)"을 assertTrue로 고정했다.
  - 개설 전에는 담당이 없을 수 있어, 확정자를 넣어야 자기 건이 '내 작업'에 보인다.
- 다만 개설 뒤에도 확정자가 계속 mine에 남는지는 사용자 의도를 확인해야 한다. NEXT 131·113에서 근거를 찾지 못해 기획에 넘긴다.

## 3. 확인용 읽기 전용 SQL (MySQL, 메인이나 사용자가 실행)
```sql
-- 그 건의 사전준비 행: 확정자, 상태, 개설 시각
SELECT p.BID_CASE_ID, p.INSTITUTION_ID, p.STATE_CD, p.CONFIRMED_BY, u.NAME AS CONFIRMER_NAME, p.CONFIRMED_AT, p.OPENED_AT
  FROM BID_PREP p
  LEFT JOIN USERS u ON u.EMP_NO = p.CONFIRMED_BY
 WHERE p.INSTITUTION_ID IN (SELECT INSTITUTION_ID FROM INSTITUTION WHERE NAME LIKE '%사립학교교직원연금공단%');
-- 위 INSTITUTION 테이블·컬럼 이름이 다르면 BID_PREP.INSTITUTION_NAME으로 바꿔 검색한다.

-- 그 건의 담당 행(활성·비활성 전부)
SELECT a.BID_CASE_ID, a.EMP_NO, u.NAME, a.ACTIVE_YN, a.ASSIGNED_AT
  FROM BID_ASSIGNMENT a LEFT JOIN USERS u ON u.EMP_NO = a.EMP_NO
 WHERE a.BID_CASE_ID IN (SELECT BID_CASE_ID FROM BID_PREP WHERE INSTITUTION_NAME LIKE '%사립학교교직원연금공단%')
 ORDER BY a.BID_CASE_ID, a.ASSIGNED_AT;
```
읽는 법: CONFIRMED_BY=3918264이면 (가), STATE_CD='CANCELLED'이고 김영업이 담당 행에 있으면 (나)다. 둘 다 아닌데 보인다면 결함이니 이 보고서를 다시 불러 달라.

## 4. 구현안·시험
- 결함이 아니므로 패치는 없다.
- 사용자가 "확정자만으로는 mine에 넣지 말라"고 정하면 최소 패치는 `inScope` 155행에서 `meEmp.equals(p.getConfirmedBy())`를 `(!opened && meEmp.equals(p.getConfirmedBy()))`로 바꾸는 것이다(개설 전 건만 확정자를 남김). 그 경우 U12 277행의 CONFIRMED 케이스는 유지되고, 개설 뒤 확정자 케이스를 assertFalse로 추가한다. 이 방향은 정책이라 기획 확정 전에는 적용하지 않는다.
- 실행 명령(변경 시): `cd kgi-ggreport-web && mvn -q -o test -Dtest=PrepBoardServiceTest`.

## 5. 보안·위험
- scope는 편의 거르기이지 열람 경계가 아니다(PrepBoardService.java:44). mine에서 빠져도 `canSee` 상세 열람은 그대로다.
