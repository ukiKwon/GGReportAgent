### 5. 보안·위험·되돌리는 법
- 403: 기존 requireInstitutionEdit 그대로. 401·403은 접근 이력에 DENIED로 남고 본문·쿼리값은 안 남음. 400은 접근 이력 상태코드로만. 새 이력 표에는 성공한 변경만(같은 트랜잭션이라 이력 없이 값이 바뀌지 않음).
- 자기신고 한계: 사번·화면·버튼은 X-Emp-No·X-Screen-Id·X-Button-Id로 위조 가능. EMP_VERIFIED=0이면 "검증됨" 표시 금지. 앞단 인증 전에는 사후 추적용일 뿐 보안 경계가 아님.
- 이력 표는 날짜·코드·http(s) 링크·공고 번호만 담음(개인정보 아님). 접근 이력과 달리 값 일부가 들어가는 점은 security가 확인할 것.
- 위험: 골든 00·01이 Python 스냅샷과 갈라짐(Python server/는 불변) / MySQL SET 평가 순서(반입 CASE는 CONTRACT_END 대입보다 앞, 031 CONFIRMED는 마지막) / 031은 한 번만 / PUT은 마지막 쓰기 우선(낙관적 잠금은 범위 밖) / contract_end 형식은 값이 바뀔 때만 검사 / 출처 없는 옛 확정 행은 값이 안 바뀌면 거부하지 않음.
- 되돌리기: 코드는 되돌려도 새 칸이 NULL·기본값이라 기존 동작에 영향 없음. DB 되돌리기 SQL은 030 헤더(데이터 소멸, 운영 금지). 적용한 파일은 고치지 않고 새 번호로. 거부 규칙을 푸는 것은 contract_end 분기 한 곳.
