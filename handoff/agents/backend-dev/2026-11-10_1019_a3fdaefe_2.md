## 2. 원인 (근거)
- **서빙 경로가 두 갈래다.** 둘 다 Spring Boot 기본 `ResourceHttpRequestHandler`가 서빙한다.
  - 로컬: `config-envs/out-local/application.properties:33`의 `spring.web.resources.static-locations=file:../frontend/,classpath:/static/`. `config/application.properties:33`도 같다. 파일시스템에서 직접 읽는다.
  - 배포: `pom.xml:131-140`이 빌드 때 `../frontend`를 `static/`으로 복사한다. WAR 안 classpath에서 서빙한다.
- **캐시 설정이 어디에도 없다.** `spring.web.resources.cache` 계열은 `src/main/resources`에도 없다. `WebConfig`는 인터셉터만 건다. Boot 기본은 Cache-Control·ETag를 안 보내고 `Last-Modified`만 준다. 그래서 브라우저가 휴리스틱 캐시를 쓴다.
- **properties 방식은 쓰지 않는다.**
  - `spring.web.resources.cache.cachecontrol.no-cache=true`는 한 줄이다. 다만 환경 파일이 dev·local·out-local·prod·stg 5개에 `config/`와 테스트용까지 있다. 하나라도 빠지면 그 환경만 옛 화면이 뜬다.
  - 확장자별로 나눌 수도 없다.
  - 그래서 `SecurityHeadersFilter`와 같은 방식의 Filter 하나로 처리한다. 환경에 상관없고, 이식 방식도 이미 검증돼 있다.

## 3. 구현안

새 파일 `src/main/java/com/kbstar/kgi/ggreport/web/config/StaticCacheFilter.java`:
```java
package com.kbstar.kgi.ggreport.web.config;

import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;

import javax.servlet.*;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.util.Locale;

/**
 * 화면 정적 파일의 캐시 정책. 배포 뒤 옛 JS 가 실행되는 것(NEXT 53)을 막는다.
 * HTML·JS·CSS 는 no-cache(매번 재검증 — Last-Modified 로 304), 이미지·폰트는 5분.
 * 확장자 허용 목록만 대상이라 API 응답에는 붙지 않는다. GET/HEAD 만.
 * 상태(200/304/404)와 무관하게 요청 경로로 붙인다(404 가 캐시되는 것도 막는다).
 * WebLogic(Servlet 3.1) 이식: SecurityHeadersFilter 와 같이 init/destroy 를 직접 구현한다.
 */
@Component
@Order(Ordered.HIGHEST_PRECEDENCE + 1)
public class StaticCacheFilter implements Filter {

    static final String REVALIDATE = "no-cache";
    static final String SHORT = "private, max-age=300";

    @Override public void init(FilterConfig c) { }

    @Override
    public void doFilter(ServletRequest req, ServletResponse res, FilterChain chain)
            throws IOException, ServletException {
        if (req instanceof HttpServletRequest && res instanceof HttpServletResponse) {
            HttpServletRequest rq = (HttpServletRequest) req;
            String m = rq.getMethod();
            if ("GET".equals(m) || "HEAD".equals(m)) {
                String policy = policyFor(rq.getRequestURI(), rq.getContextPath());
                if (policy != null) ((HttpServletResponse) res).setHeader("Cache-Control", policy);
            }
        }
        chain.doFilter(req, res);
    }

    @Override public void destroy() { }

    /** 정책 문자열, 대상 아니면 null. 쿼리는 getRequestURI 에 없고 ;jsessionid 는 잘라낸다. */
    static String policyFor(String uri, String ctx) {
        if (uri == null) return null;
        String p = uri;
        if (ctx != null && !ctx.isEmpty() && p.startsWith(ctx)) p = p.substring(ctx.length());
        int semi = p.indexOf(';');
        if (semi >= 0) p = p.substring(0, semi);
        if (p.isEmpty() || "/".equals(p)) return REVALIDATE;          // 진입점
        int dot = p.lastIndexOf('.');
        if (dot < 0 || dot < p.lastIndexOf('/')) return null;
        switch (p.substring(dot + 1).toLowerCase(Locale.ROOT)) {
            case "html": case "htm": case "js": case "css": case "map": return REVALIDATE;
            case "png": case "jpg": case "jpeg": case "gif": case "svg": case "ico":
            case "woff": case "woff2": case "ttf": return SHORT;
            default: return null;
        }
    }
}
```
- 이미지·폰트에 `private`을 붙인 이유가 있다. 업로드 파일 다운로드 API 경로가 `.png`로 끝나더라도 공유 캐시에 남기지 않기 위해서다.
- `/`를 포함한 이유가 있다. `index.html`은 `/`로도 열린다.
- 새 파일을 안 쓰고 `SecurityHeadersFilter`에 합치는 방법도 있다. 다만 책임이 갈리므로 분리를 권장한다.

properties와 DB 스크립트는 바꾸지 않는다. `/menus`, 골든, `Menus.MENUS`는 건드리지 않는다.

## 5. 위험·WebLogic·롤백
- **재검증 비용**: no-cache라도 `Last-Modified` 기반 304가 오므로 본문 재전송은 없다. 요청 수만 늘고, 폐쇄망 내부 트래픽에서는 무시할 수준이다.
- **ETag는 없다.** Last-Modified만으로 충분하다고 본다.
  - 배포 방식이 복사로 mtime을 바꾸는 경우를 점검해야 한다.
  - 복사가 원본 mtime을 보존하면서 더 옛 파일로 교체하면 304로 옛 화면이 남는다. 이때는 ETag(`ShallowEtagHeaderFilter` 또는 resource chain)를 검토한다.
- **WebLogic WAR**: `@Component` Filter는 `SpringBootServletInitializer`가 기존 `SecurityHeadersFilter`처럼 서블릿 컨텍스트에 등록한다. `javax.servlet` 3.1 API만 쓰고 default 메서드는 안 쓴다. 추가 `web.xml` 설정은 필요 없다.
  - WebLogic 자체가 정적 파일을 앞단에서 서빙하는 구성이면 이 필터가 닿지 않는다. 그 경우 WebLogic 쪽에서 헤더를 설정해야 하고, 이 부분은 이식 담당과 확인할 사항이다.
- **인증·접근 이력**: 권한 경로(403)는 건드리지 않는다. 헤더에는 개인정보나 본문이 없다.
- **롤백**: `StaticCacheFilter.java`와 `StaticCacheApiTest.java` 두 파일을 삭제한다. DB·설정 변경이 없다.
