## 2. 설계 결정과 근거
- **D1. 뉴스 CSV는 사업계획 CSV와 별개 계약이다.** 열이 다르므로 한 파일에 섞지 않는다(⑪-4 '한 파일에 한 종류'와 같은 취지).
  - 같은 목록 CSV, 같은 반입 경로, 같은 inbox 폴더를 쓴다.
  - 파일 이름은 `{기관ID}_{YYYYMMDD}_news.csv`이다.
  - 정규식은 `([A-Za-z0-9-]{1,64})_(\d{8})_news\.csv`로 둔다.
  - `_plan.csv`와 `_news.csv`는 글자 수가 같다(`_` 포함 9자). 그래서 PlanInboxService의 `dateOf`·`idOf`(끝에서 17·18자 자르기)가 그대로 맞는다.
- **D2. 판(version) 방식이 사업계획과 같다.**
  - 뉴스 반입 1건은 판 1개이고, 현재 판은 가장 최근에 반입한 판이다. 이전 판은 보존한다.
  - 같은 SHA-256 파일은 409 `MSG_SAME`로 거부한다.
  - 현재 판보다 이른 날짜의 파일은 409 `MSG_OLDER`로 거부한다.
  - 같은 날짜·다른 내용은 새 판으로 받는다.
  - 근거는 이미 검증된 `apply`의 잠금·멱등 가드를 그대로 재사용하는 것이다. 누적 병합 방식은 중복 제거 규칙이 새로 생겨서 쓰지 않는다.
  - 한 판은 최대 10건이므로 기관당 10건 상한은 판 단위로 자연히 지켜진다.
- **D3. 감사는 새 표를 만들지 않는다.** `INST_PLAN_ACT`(034)에 `ACTION_CD='NEWS_IMPORT'`를 더해 재사용한다.
  - `ACTION_CD`가 VARCHAR2(30)이라 DDL 변경이 없다.
  - 기관ID·SHA·행 수·사번·화면·버튼이 이미 들어 있어 그대로 맞는다.
  - 034의 주석에 `PLAN_ACTION` 코드 그룹이 있다. 그 그룹을 서버가 값 검증에 쓰면 060(가)에 `PLAN_ACTION/NEWS_IMPORT` INSERT를 더해야 한다. 쓰지 않으면 상수만 추가하면 된다. 이 부분은 확인이 필요하다.
  - 접근 이력에는 본문·요약·URL·제목을 넣지 않는다(기존과 같음).
- **D4. 사업계획이 있는 기관에 뉴스가 와도 거부하지 않는다.** 서버는 두 자료를 독립으로 저장한다. "사업계획 없는 기관만 뉴스를 보여 준다"는 화면 쪽 규칙으로 두면, 파일 도착 순서가 어긋나도 막히지 않는다.
- **D5. 요약 파일(⑪-6)은 이번에 서버가 읽지 않는다.** 서버는 DB에서 결과 상태를 계산해 API로 준다(§5).
  - `PLAN_FOUND`: 수집 판(`origin=IMPORT`)이 있다.
  - `NEWS_ONLY`: 수집 판은 없고 뉴스 판이 있다.
  - `NOT_FOUND`: 둘 다 없다.
  - agent가 만드는 요약 파일은 계약 초안만 두고, 읽기는 다음 단계로 미룬다.
  - 이유는 파일 종류가 하나 더 늘면 이름 정규식·uploader·감사·검사가 모두 늘기 때문이다. 요약 파일의 가치는 `ERROR`·오류 코드를 사람이 보는 정도이고, 지금은 개발부서 담당자가 사람이 판정하는 것이 현행이다.
- **D6. 열린 수집 요청은 뉴스 반입으로 닫을지 정책 결정이 필요하다.** 사용자가 "한 번 못 찾으면 바로 뉴스로 넘긴다"고 했으므로 권장안은 닫는 것이다.
  - 방식은 `collect.onImported`를 재사용하되 `result` 구분(`NEWS`)을 주는 것이다.
  - 닫지 않으면 목록에 계속 다시 나와서 agent가 같은 기관을 반복 수집한다.
  - `PlanCollectService`의 요청 상태 어휘를 못 읽었다. 닫는 방식은 PlanCollectService를 읽은 뒤 정하고, 정책은 기획에 확인한다(§7 이관).
- **D7. 요약 직접 쓰기는 서버가 증명할 수 없다.** 결정적으로 막을 수 있는 것만 막고, 나머지는 data-auditor 표본 검수로 넘긴다.
  - 서버가 막는 것: 3줄 이내, 300자 이내, 제목과 같은 문장, 개인정보 패턴.
  - 원문 복사 여부와 일반인 이름은 서버가 판정할 수 없다.

## 4. 반입·저장 설계

### 4-1. 060(가) DB 스크립트(번호는 main과 조율)
**Oracle 정본 `db/oracle/060_inst_news.sql`:**
```sql
-- kgi-ggreport-web — Oracle 정본 (060 가칭) : 기관 관련 뉴스 반입 INST_NEWS_IMPORT / INST_NEWS_ITEM
-- 034 적용 뒤 한 번만(멱등 아님). 외래키·CHECK 없음. 참조는 서비스가 확인: INST_NEWS_ITEM.IMPORT_ID -> INST_NEWS_IMPORT
-- 본문 저장 금지: SUMMARY(직접 쓴 300자 이내)만. 요약에 개인정보·실명(일반인) 없음은 서버 검사+표본 점검.
-- DBA 권한 메모: SELECT·INSERT(UPDATE·DELETE 불필요 — 판은 추가 전용).
-- 되돌리기: DROP TABLE INST_NEWS_ITEM; DROP TABLE INST_NEWS_IMPORT;
CREATE TABLE INST_NEWS_IMPORT (
    IMPORT_ID         NUMBER GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    INSTITUTION_ID    VARCHAR2(64 CHAR)  NOT NULL,
    FILE_DATE         VARCHAR2(10 CHAR)  NOT NULL,   -- 파일 이름 날짜 = 확인일 중 가장 늦은 날
    FILE_SHA256       VARCHAR2(64 CHAR)  NOT NULL,
    FILE_BYTES        NUMBER(12)         NOT NULL,
    ITEM_COUNT        NUMBER(3)          NOT NULL,   -- 1~10
    BATCH_ID          VARCHAR2(64 CHAR),
    IMPORTED_BY       VARCHAR2(7 CHAR)   NOT NULL,
    IMPORTED_AT       VARCHAR2(40 CHAR)  NOT NULL,
    IMPORTED_VERIFIED NUMBER(1)          DEFAULT 0 NOT NULL,   -- 자기신고 사번이면 0
    CONSTRAINT PK_INST_NEWS_IMPORT PRIMARY KEY (IMPORT_ID)
);
CREATE INDEX IDX_INI_INST ON INST_NEWS_IMPORT (INSTITUTION_ID, IMPORT_ID);
CREATE INDEX IDX_INI_SHA  ON INST_NEWS_IMPORT (INSTITUTION_ID, FILE_SHA256);

CREATE TABLE INST_NEWS_ITEM (
    NEWS_ID         NUMBER GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    IMPORT_ID       NUMBER             NOT NULL,
    INSTITUTION_ID  VARCHAR2(64 CHAR)  NOT NULL,
    ROW_NO          NUMBER(3)          NOT NULL,
    FIELD_CD        VARCHAR2(20 CHAR)  NOT NULL,     -- NEWS_FIELD
    TITLE           VARCHAR2(200 CHAR) NOT NULL,
    PRESS           VARCHAR2(60 CHAR)  NOT NULL,
    PUBLISHED_ON    VARCHAR2(10 CHAR)  NOT NULL,     -- yyyy-MM-dd
    SRC_URL         VARCHAR2(1000 CHAR) NOT NULL,
    SUMMARY         VARCHAR2(900 CHAR) NOT NULL,     -- 직접 쓴 요약, 300자+줄바꿈 여유
    CHECKED_ON      VARCHAR2(10 CHAR)  NOT NULL,
    COLLECTOR_AGENT VARCHAR2(60 CHAR)  NOT NULL,     -- 프로그램 식별자(사람 아님)
    CONSTRAINT PK_INST_NEWS_ITEM PRIMARY KEY (NEWS_ID)
);
CREATE INDEX IDX_INW_IMPORT ON INST_NEWS_ITEM (IMPORT_ID, ROW_NO);

-- [INSERT 블록 시작 — MySQL 060 과 글자 그대로 같아야 한다(DDL 쌍 시험)]
INSERT INTO COMMON_CODE (CODE_GROUP, CODE, CODE_NAME, SORT_NO, ENABLED, UPDATED_AT) VALUES ('NEWS_FIELD', 'TREASURY', '금고', 1, 1, '2026-11-24T00:00:00+09:00');
INSERT INTO COMMON_CODE (CODE_GROUP, CODE, CODE_NAME, SORT_NO, ENABLED, UPDATED_AT) VALUES ('NEWS_FIELD', 'FINANCE', '재정', 2, 1, '2026-11-24T00:00:00+09:00');
INSERT INTO COMMON_CODE (CODE_GROUP, CODE, CODE_NAME, SORT_NO, ENABLED, UPDATED_AT) VALUES ('NEWS_FIELD', 'BUDGET', '예산', 3, 1, '2026-11-24T00:00:00+09:00');
INSERT INTO COMMON_CODE (CODE_GROUP, CODE, CODE_NAME, SORT_NO, ENABLED, UPDATED_AT) VALUES ('NEWS_FIELD', 'MAJOR_PROJECT', '주요사업', 4, 1, '2026-11-24T00:00:00+09:00');
INSERT INTO COMMON_CODE (CODE_GROUP, CODE, CODE_NAME, SORT_NO, ENABLED, UPDATED_AT) VALUES ('NEWS_FIELD', 'HEAD_NEWS', '기관장동정', 5, 1, '2026-11-24T00:00:00+09:00');
-- [INSERT 블록 끝 — 5행]
COMMIT;
```
- SUMMARY는 '300자 이내'를 서버가 검사한다. 칸을 900으로 둔 것은 문자 수가 아니라 바이트·줄바꿈 여유 때문이다.
- **MySQL `db/mysql/060_inst_news.sql`**은 같은 칼럼·인덱스 이름을 쓴다.
  - 타입은 `BIGINT AUTO_INCREMENT`, `VARCHAR(n)`, `INT`로 바꾼다.
  - 엔진·문자셋 줄은 `db/mysql/034_inst_plan.sql`의 것을 그대로 따른다.
  - INSERT 블록은 Oracle과 글자 그대로 같게 두고, `COMMIT;`으로 끝낸다.
  - 머리글에 "058·059까지 적용한 DB는 이 파일 하나만 돌린다. 적용 후 고치지 않는다(체크섬). 멱등 아님"을 쓴다.
  - 되돌리기는 `DROP TABLE INST_NEWS_ITEM; DROP TABLE INST_NEWS_IMPORT; DELETE FROM COMMON_CODE WHERE CODE_GROUP='NEWS_FIELD';`이다.

### 4-2. 서버 코드 개요 (전체 코드 불필요)
- **`support/NewsCsv.java`(신규)**
  - `HEADERS`(9열), `FILE_NAME`(Pattern), `parse(byte[] raw, Options(instId, fileDate, today), Codes)` → `Result{ List<Row>, int rows }`.
  - `PlanCsv`가 쓰는 `CsvLimits.parse`와 공용 칸 검사(제어 문자·수식 시작·1,000자·URL 규칙·수집자 규칙)를 재사용한다. 그 함수 이름은 PlanCsv 본문을 열어 맞춘다.
  - 오류는 `InstitutionCsv.CsvFormatException`과 `row n: 고정 문구` 형식을 쓰고, 칸 원문은 싣지 않는다.
- **`InstitutionNewsService`(신규)**
  - `Map importFile(String fileName, byte[] raw, String batch, Actor actor, Ui ui)`와 `importUpload(instId, MultipartFile, ...)`.
  - 내부 `apply`는 InstitutionPlanService.apply와 같은 구조다. `lockInstitution` → `selectLatestNewsImport` → SHA 같음이면 409 `MSG_SAME` → 파일 날짜가 이르면 409 `MSG_OLDER` → insert 판·항목·`insertAct(ACTION_NEWS_IMPORT)`를 한 트랜잭션으로 처리한다.
  - `Map detail(String instId)`(조회, §5).
  - 상수 `ACTION_NEWS_IMPORT = "NEWS_IMPORT"`.
- **`NewsMapper`(+XML)**: `lockInstitution`(PlanMapper 것 재사용), `selectLatestImport`, `countImportBySha`, `insertImport`, `insertItem`, `selectItems(importId)`.
- **`PlanInboxService` 확장**
  - 두 이름 정규식을 모두 받는다(`PlanCsv.FILE_NAME`, `NewsCsv.FILE_NAME`). `scan()`은 둘 다 `names`에 넣고, 항목에 `kind`(`PLAN`/`NEWS`)를 붙인다. 지금은 `_news.csv`가 `ignored_count`에 들어가므로, 이 확장 전에는 뉴스 파일이 "형식 밖"으로 세어진다.
  - `inspect`·`importFile` 호출은 종류별로 분기한다.
  - `names()`는 두 정규식 중 하나에 맞으면 통과한다.
  - 한 기관에 두 종류가 같은 배치에 오면 순서는 날짜순이고, 종류가 다르면 서로 막지 않는다.
  - `MAX_IMPORT`는 50 → **100**으로 올린다(50기관 × 2종류). 반입 상한 테스트는 같이 고친다. `MAX_LIST`(내용 확인 100개)는 그대로 둘지 스캔 부담을 보고 qa가 판단한다.
- **`PlanUiIds`**: 뉴스 반입의 화면·버튼 id는 서버 고정값으로 정한다. 기존 사업계획 반입 id 재사용 여부는 PlanUiIds를 읽고 정한다. 헤더로 받지 않는다.
- **uploader(ac0b626f 설계에 더하는 변경)**
  - 정규식은 `([A-Za-z0-9-]{1,64})_(\d{8})_(plan|news)\.csv`로 확장하고, 그룹 3이 종류다.
  - 같은 이름 거부와 대소문자 중복 검사는 종류까지 이름에 포함한 전체 이름 기준이다.
  - 열 머리행 검사는 종류별로 한다(plan은 25열, news는 9열). 머리행 검사는 사본이므로 서버를 정본으로 하고 "두 곳을 함께 고친다"를 주석에 적는다.
  - 한 번에 올리는 파일 수 상한은 100으로 맞춘다.
  - 같은 폴더에 쓰고, 안내 문구는 `{기관ID}_{YYYYMMDD}_(plan|news).csv`로 바꾼다.

## 5. 조회·반입 API 모양 (snake_case)
- `POST /institutions/{id}/news/import`(multipart) — 사업계획 `plans/import`와 같은 권한을 쓴다.
  - 성공 200: `{import_id, institution_id, item_count, file_sha256}`.
  - 상태 코드: 400(검증 실패, 문구는 `row n: 고정 문구`), 404(기관 없음), 409(MSG_SAME·MSG_OLDER), 413(5MB 초과).
- `GET /plan-collect/inbox`(응답의 `items[].kind` 추가)와 `POST /plan-collect/inbox/import`(파일 이름 목록이 두 종류 모두 가능)는 기존 계약에 `kind`만 더한다. 기존 응답 키는 바꾸지 않는다.
- `GET /institutions/{id}/news`
  ```json
  {
    "institution_id": "sample-gu",
    "has_news": true,
    "import_id": 12,
    "file_date": "2026-11-18",
    "checked_on": "2026-11-18",
    "window_from": "2025-11-18",
    "window_to": "2026-11-18",
    "item_count": 2,
    "items": [
      {"news_id": 101, "field_cd": "TREASURY", "field_name": "금고",
       "title": "...", "press": "가상일보", "published_on": "2026-10-30",
       "url": "https://example.org/n1", "summary": "...", "checked_on": "2026-11-18",
       "collector_agent": "news-collector/1.0", "stale": false}
    ],
    "plan_state": "NEWS_ONLY"
  }
  ```
  - 판이 없으면 200으로 `has_news:false, items:[]`를 준다(404 아님).
  - `stale`은 `checked_on`이 오늘(서울) 기준 12개월을 넘었을 때 `true`이다(조회 시 계산, 저장하지 않음).
  - `plan_state`는 `PLAN_FOUND`/`NEWS_ONLY`/`NOT_FOUND`이다. 사업계획 판이 있으면 `PLAN_FOUND`이다.
  - 사번·반입자는 내보내지 않는다.
  - 조회 권한은 사업계획 `GET /institutions/{id}/plans`와 같게 맞춘다(그 검사를 읽고 맞춘다).
- 기존 `GET /institutions/plans/status`(목록)에는 항목마다 `news_item_count`·`plan_state`를 더하는 것을 다음 단계 화면 요구에 맞춰 정한다. 이번에는 개요만 제안한다.

## 7. 보안·위험·되돌리는 법
- **권한**
  - 반입은 사업계획 반입과 같은 권한을 쓴다(그 검사를 읽고 맞춘다). 권한이 없으면 403이고, 시도는 `INST_PLAN_ACT`에 `DENIED`로 남는다.
  - 접근 이력에는 SHA·행 수·결과 코드만 남기고 URL·제목·요약은 남기지 않는다.
  - `X-Emp-No`는 자기신고다. 사번이 `IMPORTED_BY`에 들어가지만 `IMPORTED_VERIFIED=0`이므로 "검증된 사용자"로 표시하지 않는다.
- **저작권·본문**
  - 본문은 저장하지 않는다. 요약이 원문 복사인지 서버가 증명할 수 없다.
  - 서버 방어는 300자·3줄·제목 동일 금지 정도이고, 나머지는 data-auditor 표본 검수다.
- **개인정보**
  - 정규식 방어는 전화·이메일·주민번호 형태·'N년생'·'N세'뿐이다. 일반인 이름은 못 막는다. 기관장·공직자 이름은 허용한다.
  - '65세'를 기관장이 아닌 일반 문맥(예: 65세 이상 지원 사업)에서 쓰면 거부된다. 이 오탐은 감수하고, 요약에서 '65세 이상'을 '고령층'으로 쓰게 안내한다. 기획 확인이 필요하다.
- **링크**: 내부망에서는 URL이 열리지 않는다. 프런트가 링크를 만들더라도 `http/https` 검증값만 쓰고(javascript: 등은 서버가 거부), 새 창은 `rel="noopener noreferrer"`로 연다. 이 부분은 프런트·디자인 이관이다.
- **DoS·폴더**: 5MB·10행이므로 부담이 작다. scan 예산(64MB·20초·최신 100개)은 두 종류가 합쳐져 줄어들므로, 100개 상한에 도달하는 날을 qa가 본다.
- **되돌리는 법**: 060 DDL의 DROP 문 두 개와 NEWS_FIELD 코드 삭제. 서버 쪽은 `InstitutionNewsService`·NewsCsv·컨트롤러 엔드포인트를 지우고, `PlanInboxService`의 분기를 원복한다. 기존 `/approvals`·`/tasks/{id}/approve`·`/menus` 계약은 그대로다.

## 8. 이관 메모
- `[이관: 기획]` 뉴스를 반입하면 그 기관의 열린 수집 요청을 `반영됨`으로 닫을지, `뉴스로 대체` 같은 별도 상태를 둘지 — 기다리는 것: 정책 답 — 근거: D6, 지금은 사람이 닫는 현행.
- `[이관: 기획]` 요약에 "65세 이상" 같은 정책 문구가 나올 때의 오탐을 허용할지(거부 vs 경고) — 근거: §7 개인정보.
- `[이관: 기획]` 뉴스 조회 권한을 사업계획 조회와 같게 둘지(디자이너 '보기' 포함) — 근거: 메모리의 '디자이너 기본값=보기'. 같게 두는 것이 권장안이다.
- `[이관: 디자인·프런트]` 뉴스 카드·"뉴스로 대체됨" 표시, 링크가 열리지 않을 때의 안내, `stale`(12개월 초과) 표시 — 근거: §5의 응답 모양. 화면은 다음 단계이다.
- `[이관: 데이터]` 요약 직접 쓰기 표본 검수(원문 복사·일반인 이름·기관장 나이 여부), 분야 5종 분류 일관성 — 근거: D7.
- `[이관: uploader 쪽 설계 담당]` §4-2의 정규식 확장·상한 100·종류별 머리행 검사 — 근거: ac0b626f 설계가 진행 중이다.

### security에 넘길 것
1. `NewsCsv` 개인정보 패턴과 정규식이 ReDoS·우회(전각 숫자, 공백 변형)에 안전한지.
2. 이름 정규식 두 종류와 폴더 읽기 경로 방어(`readSafe`의 부모 비교·대소문자 비교)가 `_news`에도 같은지.
3. `INST_PLAN_ACT` 재사용 시 OUTCOME·ACTION_CD가 접근 이력 원칙(본문·URL 없음)을 지키는지.
4. 반입 권한 403 경로와 자기신고 사번의 한계 표시.
5. 제목·요약이 화면에서 HTML로 렌더링될 때의 XSS는 프런트가 텍스트로만 쓰는지(응답은 그대로 문자열).

### data-auditor에 넘길 것
1. 뉴스 CSV 가상 예시와 실제 수집분 표본의 요약이 원문 복사가 아닌지, 3줄·300자 기준에 맞는지.
2. 일반인 이름·연락처·기관장 생년·나이가 요약·제목에 섞이지 않았는지.
3. 분야 5종 분류가 맞는지, 보도일이 기관과 무관한 기사가 아닌지.
4. SCHEMA 표본(⑪-9 예시)이 서버 테스트로 통과하는지(⑪-8처럼 실제 통과는 아직 안 해 봄).
