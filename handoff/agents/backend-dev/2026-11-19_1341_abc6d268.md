### ① 출력 엔진: 새 패키지 `com.kbstar.kgi.ggreport.web.docout`

**`DocModel`(불변 값 객체)**
- 문서 = 블록 목록
  - `Heading(text, size)`
  - `Para(runs, bullet: NONE|CIRCLE_O('ㅇ ')|DASH('- '), level 0~2)`. 글머리는 번호 목록(numbering.xml)을 쓰지 않고 글자 + 내어쓰기로 만든다.

  - `Table(columns, colWidthsPct, rows, headerRows)`
  - `PageBreak`

- 행을 복제한 뒤 병합을 고치는 방식이 아니다. 데이터에서 매번 새로 계산한다.

**`DocxKit.render(DocModel, Footer)`**
- A4, 맑은 고딕(eastAsia 포함)
- 표 속 표
  - `XWPFTableCell.insertNewTbl(cursor)`·`insertNewParagraph(cursor)`로 칸 끝에 순서대로 넣는다. `addNewTbl`은 같은 종류 요소 뒤에 붙어 순서가 꼬일 수 있어 쓰지 않는다.

### ② T1 '기관 정보 요약' 과제 재정의

**양식 정의는 코드 상수 `InstSummaryTpl`**

**사실 값 수정 방식**
- 양식의 FACT_PREFILL 칸은 읽기 전용이다. 서버는 이 칸에 들어온 값을 400 FIELD_READONLY로 거부한다.
- 값을 고치려면 원래 화면(기관장 정보, 약정, 기관 편집)에서 고친 뒤 [미리 채움 다시 불러오기]를 누른다.
- planner 권장 ⓐ('원 데이터에도 반영')와 결과는 같다. 쓰기 경로가 원 화면 하나로 남아 권한·감사가 갈라지지 않는다. 다만 planner 권장과 다른 쪽이라 기획 확인이 필요하다(이관).

**저장 형식(CONTENT_JSON)**
- 형식 v1: `{"v":1,"tpl":"INST_SUMMARY","tpl_ver":1,"fields":{key:{"val":..,"src":{"kind","ref","title","url","checked_on","at"}|null,"note":..}},"lists":{..},"tables":{..}}`
- `src.ref`가 출처 판이다. 예: `HEAD_ITEM:123`, `BANK_CONTRACT:inst/3/rev2`, `PLAN_IMPORT:7`.
- 해시 = 정렬된 표준 JSON(UTF-8)의 SHA-256. 출처까지 해시에 들어가므로, 확정 뒤 출처가 바뀌었는지 증명할 수 있다.
- 칸별 출처를 별도 표로 빼지 않은 이유: 출처가 해시 범위에 들어가고, 020의 VALUES_JSON과 같은 방식이다.

**낡음 표시**
- 상세를 열 때 src.ref를 현재 원본과 비교해 `stale_keys`를 낸다. 대상: 칸이 대체·무효가 됨, 약정 rev가 올라감, 새 반입이 있음.
- 확정은 막지 않고, 확정 판의 `STALE_KEYS`에 기록한다. 막을지 말지는 기획이 정한다(이관).

**과제 판정(S3, fa 커밋 뒤 PrepService)**
- `judgeFact`에 `"T1_FORM"`을 더한다. 완료 조건은 모두 만족해야 한다.
  - BID_PREP_FORM.CONFIRMED_VER가 있다.
  - 그 판 행이 KIND=CONFIRM이다.
  - 다시 계산한 SHA가 CONTENT_SHA256 및 CONFIRMED_SHA256과 같다. 그래서 DB를 직접 고치면 자동으로 미완료가 된다.

- 파일을 실제로 첨부(BID_PREP_ATTACH)하지 않는다. 정본은 시스템 확정 내용이라는 결정에 맞춘다.

### ③ 기관장 정보 docx 내려받기 (S1, fa 파일과 겹치지 않음)

**경로**: `GET /institutions/{institutionId}/head/docx`. `InstitutionHeadController`에 `run(req, id, null, null, "HEAD_DOCX", true, …)`로 추가한다.

**처리 순서**는 기존 공통 틀 그대로다.
1. 스위치(꺼져 있으면 404)
2. 사번 없으면 401
3. 미등록·비활성 403
4. 영업 역할이 아니면 403 DENIED
5. 기관 id 형식 밖이면 404 HIDDEN
6. 그다음 단계를 더한다: 화면·버튼 식별자가 허용 목록 밖이면 400 UI_ID_REQUIRED(INVALID)
7. 현 기관장이 없거나 빈 기관장이면 409 HEAD_EMPTY(BLOCKED)
8. 200

**응답**
- `Content-Disposition: attachment; filename="head_info.docx"; filename*=UTF-8''기관장정보_{기관명}_{yyyyMMdd}.docx`
- `Cache-Control: no-store`, `nosniff`

**감사**
- INST_HEAD_ACT에 `HEAD_DOCX`와 화면·버튼을 남긴다. 응답 전에 기록하고, 기록이 실패하면 500이며 파일은 나가지 않는다.
- `HeadAudit.isView`에 HEAD_DOCX를 더해 하루 열람 경고 수에 포함한다.
- 접근 이력은 기존 `inst-head inst=… code=HEAD_DOCX`다. 이름은 남기지 않는다.

**HeadUiIds**: 버튼 `head_docx`를 더한다. 화면은 기존 `head_card`, `prep_detail`, `bid_board`, `map_popover`다.

**내용(`HeadDocBuilder`가 detail() 결과로 DocModel을 만든다)**
- 제목: `참고자료 {n}. 「{기관명}」 기관장 정보`. n은 선택 질의값 `ref_no`(정수 1~20, 기본 1)이고, 형식 밖이면 400이다.
- 2열 겉 표의 절 순서:
  - 인적 사항: 'ㅇ 성명/직위(권한대행)/첫 취임일/현 임기'
  - 학력('- ' 목록)
  - 경력('- ' 목록)
  - 출처: 칸마다 한 줄 '- {칸}: {출처 종류} 「제목」, 확인일 yyyy-MM-dd'. URL은 일반 글자로 쓰고 링크로 만들지 않는다.
- 맨 아래: "확정된 값만 담았습니다. 기준일 yyyy-MM-dd"
- **사진은 넣지 않는다**(NEXT 77 저작권). 후보 값과 사번(created_by)도 넣지 않는다.

## 5. 보안·위험·되돌리는 법

**403 경로**
- 양식 쓰기는 활성 담당자만이고, 담당 검사가 건 조회보다 먼저 온다(setTask와 같은 순서).
- 읽기는 visible에 더해 담당자나 팀장·부장이어야 하고, 그 밖은 404다.
- 기관장 docx는 영업 역할만이다.
- 모든 거부는 감사 표와 접근 이력 DENIED에 남는다.

**감사**
- 누가·어느 화면·어느 버튼을 BID_PREP_ACT(+FORM_VER)와 INST_HEAD_ACT에 남긴다.
- 성공한 읽기와 파일은 응답 전에 기록한다. 기록이 실패하면 500이고 데이터는 나가지 않는다.
- 접근 이력에는 건 번호·코드·판 번호만 남긴다. 값·이름·파일명·사유는 남기지 않는다.

**자기신고의 한계**
- 사번·화면·버튼은 모두 X-Emp-No·X-Screen-Id·X-Button-Id 자기신고다.
- 감사는 '정직한 화면'을 전제로 하고, 사칭 방지가 아니다. EMP_VERIFIED에는 사실만 적는다.

**민감 정보**
- 연도별 MMDA 추정은 내부 추정치다. 읽기를 담당자·팀장·부장으로 좁혔다.
- 디자이너가 그 건의 담당자로 지정되면 볼 수 있다(기존 canSee 규칙). 막을지는 기획 몫이다.

**미리 채움의 감사 공백**
- 기관장 이름이 미리 채움으로 양식에 들어갈 때 INST_HEAD_ACT에는 남지 않고 BID_PREP_ACT FORM_PREFILL로만 남는다. security 판단이 필요하다.

**출력물 정본**
- docx는 확정 판 JSON에서 매번 다시 만든다. 렌더러를 고치면 옛 확정본의 모양이 바뀔 수 있다.
- 판에 RENDER_VER를 남기고, 렌더러를 고칠 때 옛 판 분기를 남기는 것을 규칙으로 한다.

**위험**
- POI lite에 쪽 번호 클래스가 없을 수 있다. S0에서 확인한다.
- 표 속 표의 쪽 넘김이 Word에서 어떻게 보이는지는 실물로 확인해야 한다.

**되돌리기**
- S0·S1은 새 파일과 추가 메서드뿐이라 되돌린 커밋으로 끝난다.
- S2는 049 DROP으로 되돌린다(데이터 소멸).
- S3는 050 반대 UPDATE와 코드 되돌리기다.

- 사용자 실사용 확인 요청(S0·S1 뒤): 내려받은 기관장 docx와 기관 정보 요약 시안 docx를 현업 Word 버전에서 열어 표 속 표·병합·빗금·쪽 번호가 샘플과 같아 보이는지 확인을 부탁한다. 서버 시험은 XML 구조만 확인한다.
