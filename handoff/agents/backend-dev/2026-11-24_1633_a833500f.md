## 2. 요구/원인 요약

### T10 (계획 판보다 새 뉴스 판정값)
- `GET /institutions/{id}/plans`의 `import.imported_at`, `import.file_date`는 이미 있다(`InstitutionPlanService.java:392-393`).
- 뉴스 쪽은 `detail`에 `file_date`·`checked_on`만 있고 `imported_at`이 없다(`InstitutionNewsService.java:243-244`). 목록용 `GET /institution-plans/status`의 `news[]`도 `institution_id`·`item_count`·`checked_on`·`stale` 4개뿐이다.
- 그래서 화면이 두 판의 반입 시각을 비교할 수 없다.
- 판정 기준은 권장대로 **뉴스 IMPORTED_AT > 현재 계획 판 IMPORTED_AT**으로 한다.
  - 근거 1: `file_date`는 파일 이름에서 오는 값이라 사람이 정한다. 옛 날짜로 재반입하면 순서가 뒤집힌다. IMPORTED_AT은 서버 시각(`Times.nowIso()`)이라 그렇지 않다.
  - 근거 2: 두 시각 모두 UTC `+00:00` 고정 마이크로초 형식이라 문자열 비교가 시간 순서와 같다(`Times.java:28-29`). 새 SQL이 필요 없다.
  - 근거 3: T8(같은 날 반입은 사업계획 먼저)과 맞는다. 계획 시각이 앞서므로 같은 날 반입한 뉴스는 "새 뉴스"로 보인다. 이것이 의도라면 문제없다. 같은 날 뉴스를 보이고 싶지 않다면 기획이 정할 일이다.
- 서버가 `newer_than_plan`을 계산해 내린다. 화면에서 문자열 비교를 하지 않게 하기 위해서다.
- 계획 판이 없으면 `newer_than_plan=false`이고 동작은 그대로다. 화면은 계속 `plan_state=NEWS_ONLY`로 판단한다.

### U6 (뉴스 반입 3개월 안 기관을 정기 수집에서 제외)
- 코드에 정기 수집 스케줄러는 없다. 목록은 두 개다.
  - `POST /institution-plans/missing.csv`: 화면이 보낸 기관ID에서 계획 판이 있는 기관만 뺀다. 화면의 '사업계획 없는 기관' 목록 내려받기이고, 정기 수집(영업·개발부서가 일괄로 돌리는 것)의 후보 목록이다.

- 결정: **제외 규칙은 missingCsv에만 넣는다.**
  - 근거 1: export.csv는 사람이 요청한 건이라 U6의 "수시 요청은 막지 않음"과 충돌한다.
  - 근거 2: missingCsv는 이미 "자료가 있는 기관을 뺀다"는 필터 자리다.
  - 근거 3: 뉴스 반입은 열린 요청을 닫으므로(`onNewsImported`), 닫힌 요청은 export에 나가지 않는다.
- 3개월 기준 시각은 뉴스 **IMPORTED_AT(서버 반입일, 서울 날짜)**로 한다. 파일 확인일(`FILE_DATE`)은 수집 시점이라 반입이 늦은 경우를 가릴 수 있고, 사람이 조작할 수도 있다.
- 경계: 반입일 + 3개월이 오늘보다 **뒤**면 제외하고, 같은 날부터는 다시 나온다.

- missing.csv는 SCHEMA ⑪에 없는 화면용 내려받기라 외부 agent·RPA 계약을 깨지 않는다. SCHEMA에는 ⑪-6에 규칙 한 줄만 더하자(맨 아래 패치).

        try {

## 5. 보안·위험·되돌리는 법
- 권한 변경은 없다. missing.csv와 뉴스 조회는 기존 map 권한(401·403 경로 그대로), export.csv는 전산팀장 전용 그대로다. 새로 내리는 값은 서버 반입 시각과 건수·확인일뿐이다. 사번·SHA·제목·요약·URL은 싣지 않는다. 접근 이력(MISSING_CSV 감사)에는 본문·쿼리를 넣지 않는 기존 방식 그대로이고, 감사의 건수(n)는 제외된 기관을 뺀 행 수가 된다.
- 반입 시각은 `X-Emp-No` 자기신고 사번으로 반입한 기록의 시각이다. 서버 시각이라 파일명 조작에는 강하지만, 반입자가 사칭이 아니라는 뜻은 아니다. "검증됨" 표현은 쓰지 않는다.
- 위험 1: `plan_state` 판정은 계획 판 존재 여부, `newer_than_plan`은 시각 비교로 서로 독립이다. 화면이 두 값을 혼용하지 않게 해야 한다(프런트 이관).
- 위험 2: 3개월 제외는 화면이 보낸 기관 목록에 대한 서버 필터라, 화면이 "목록엔 남기고 CSV에서만 빠지는 것"을 알려 주지 않으면 사용자가 내려받은 행 수가 화면보다 적어 의아할 수 있다. 응답 헤더에 제외 건수를 넣을 수도 있지만 이번엔 넣지 않았다(필요하면 `CsvOut` 확장).
- 위험 3: 시각 형식이 UTC 고정 문자열이라는 전제를 쓴다. 다른 형식으로 저장된 옛 행이 있으면 비교가 틀리지만, 반입 경로가 `Times.nowIso()` 하나뿐이라 현재는 해당하지 않는다.
- 되돌리는 법: DB 변경이 없으므로 위 3개 파일 패치를 되돌리면 된다. 응답 키가 늘기만 하므로 프런트와 호환된다. 단 status의 `news[]`가 5개 키가 되므로 기존 시험 한 줄을 같이 되돌린다.

## 6. 이관 메모
- `[이관: 프런트]` 계획 아래 뉴스 절 노출 조건을 `plan_state === 'NEWS_ONLY' || newer_than_plan`으로, 목록 칩 비교에는 `status.news[].imported_at`과 `items[].imported_at`을 쓴다. 기다리는 것은 위 서버 패치 적용이다. 근거는 3-1~3-3이다.
