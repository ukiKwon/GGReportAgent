### 3. 실측 결과 (코드 추론, 실행 아님)
- 사전에 "차장"·"위원"·"감사"(성+한 글자 형태의 가상 이름)가 들어 있으면, 어휘 라벨 "차장"·"위원"·"감사"는 `normalize`는 통과하지만 `requireClean`에서 LABEL_INVALID{name}으로 막힌다.
- 이유는 `MinutesMasker.boundaryOk`다. 두 글자 이름은 앞이 한글이 아니고 뒤가 끝·공백·조사·직함일 때 가려진다. 라벨 전체가 그 이름이면 앞은 문자열 시작이고 뒤는 끝이라 가려진다.
- "은행 차장 2"처럼 소속·번호가 붙어도 앞은 공백, 뒤는 끝·공백이라 똑같이 막힌다.
- 어휘는 바꾸지 않았다. 현재 동작을 단언하는 시험과 설명 주석만 남겼다.
- 부수 관찰: "위원장"처럼 뒤에 글자가 이어지는 어휘는 사전에 "위원"이 있어도 `boundaryOk` 때문에 막히지 않는다. "위원" 뒤의 "장"이 조사도 직함도 아니기 때문이다. 이것도 코드 추론이다.

### 4. 메인이 실행할 것
- `cd kgi-ggreport-web && mvn -q -o test -Dtest=BoardMinutesApiTest,MinutesParseEditsTest,SpeakerLabelsTest`로 3개 클래스를 먼저 돌린 뒤 전체 `mvn -q -o test`를 돌린다. 전부 통과가 기대 결과이고 DB 변경은 없다.
- 새 시험이 실패하면 아래를 먼저 의심한다.
  1. 항목 시험에서 `BODY LIKE '%[이름]%'` 조회가 null이면 요약의 SEED_NAME 가림 결과 항목이 없다는 뜻이다. 그러면 `assertNotNull`에서 실패한다.
  2. SpeakerLabels 시험에서 `toDetail().toString()`에 직책 글자가 포함돼 있으면 단언이 깨질 수 있다. 값은 안 싣는 구조지만 직접 확인하지는 못했다.

### 5. 판단·이관 메모
- 지시 범위를 벗어난 것은 없다. 허용된 파일만 고쳤다.
- 제목 시험은 편의상 `preview` + `upload` 헬퍼를 직접 조합했다(uploadOk는 제목을 가릴 이름 없이 만들기 때문).
- [이관: 데이터] 실제 직원 명단에 "차장"·"위원"·"감사"와 같은 두 글자 이름이 있는지 대조(data-auditor). 있으면 그 이름의 직원이 있는 환경에서는 해당 어휘 라벨을 쓸 수 없다. 기획이 어휘를 바꿀지 결정해야 한다.
- [이관: 프런트] `EDIT_MASK_REMOVED`에 `slot=title`이 새로 실린다. 화면이 slot별로 안내 문구를 가르는지 확인이 필요하다.
