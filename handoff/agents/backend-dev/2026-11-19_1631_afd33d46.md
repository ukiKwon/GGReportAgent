(b) 260~261줄 조회 since.
```java

                Times.iso(Instant.now().minus(canRequest ? LAST_CLOSED_WINDOW : RECENT_APPLIED_WINDOW)));
// new
```

- `now`·`appliedCutoff`라는 지역 변수 이름이 status() 안에서 이미 쓰이는지는 못 봤다. 겹치면 이름을 바꾼다.
- 메서드 이름과 지역 변수 이름이 같아도 자바에서는 컴파일된다. 읽기 불편하면 `cutoff`로 바꿔도 된다.

(c) 279줄 필터.
```java

// new
            if (!APPLIED.equals(r.getStatusCd()) || !notBefore(r.getClosedAt(), appliedCutoff)) continue;
```

(d) 640줄 `within` 메서드 바로 뒤(641줄 앞)에 추가.
```java
    /** recent_applied 기준 시각 — 오늘(KST) 날짜 − 6일의 KST 00:00. 반입한 날을 포함해 7일(NEXT 56, 사용자 11-19). */
    static Instant appliedCutoff(Instant now) {
        return now.atZone(SEOUL).toLocalDate().minusDays(RECENT_APPLIED_DAYS - 1).atStartOfDay(SEOUL).toInstant();
    }

    /** iso 시각이 cutoff 이후(같으면 포함)면 true. 비었거나 읽지 못하면 false. */
    static boolean notBefore(String iso, Instant cutoff) {
        if (iso == null) return false;
        try {
            return !OffsetDateTime.parse(iso).toInstant().isBefore(cutoff);
        } catch (DateTimeParseException e) {
            return false;
        }
    }
```
- `within`은 RUN_GAP·RENOTIFY_GAP에서 계속 쓰니 그대로 둔다.
- SQL(selectRecentClosed)은 `closedAt >= since` 비교를 문자열로 하는 것으로 보인다. 못 봤다. UTC ISO 문자열 비교로 시간순과 같다는 전제다. 이 전제는 기존 동작과 같다.

### 5. 보안·위험·되돌리는 법
- 권한 경로 변경 없음. `/plan-collect/status`의 403(재무부서 등)과 응답 키는 그대로다. 디자이너에게 `last_closed`가 빈 배열인 것도 그대로다.
