## 확인 결과
- 카드: `headcard.js:231-234` `sortPeriod` — 키는 `(끝연월 || (시작 있으면 '9999-99' : '0000-00')) + '|' + 시작`을 **문자열로 비교해 내림차순**한다. JS `sort`는 안정 정렬이다.

- 기간이 값 앞에 온다. 기존 "값 (시작 ~ 끝)" 형식은 바뀐다. 기존 시험은 학력·경력 값 글자만 단언하므로 깨지지 않을 것으로 보인다. main은 `(`·`~`로 단언하는 시험이 없는지 한 번 grep해 달라.

```java
    /** 최근 것이 위로 — 끝 연월이 없으면 현재 진행으로 보아 맨 위(시작도 없으면 맨 아래). 키·문자열 비교·안정 정렬 모두 headcard.js sortPeriod 와 같다. */
    private static List<Map<String, Object>> sortPeriod(List<Map<String, Object>> in) {
        List<Map<String, Object>> out = new ArrayList<Map<String, Object>>(in);
        Collections.sort(out, new java.util.Comparator<Map<String, Object>>() {   // Collections.sort 는 안정 정렬
            @Override
            public int compare(Map<String, Object> a, Map<String, Object> b) {
                return sortKey(b).compareTo(sortKey(a));   // 내림차순
            }
        });
        return out;
    }

    private static String sortKey(Map<String, Object> it) {
        String from = str(it.get("from")).trim();
        String to = str(it.get("to")).trim();
        return (!to.isEmpty() ? to : (!from.isEmpty() ? "9999-99" : "0000-00")) + "|" + from;
    }
```

### 3. 기간을 값 앞에 'YYYY-MM~YYYY-MM' / 'YYYY-MM~현재'
old(앞 패치의 `itemText`):
```java
    private static String itemText(Map<String, Object> i) {
        String v = str(i.get("value"));
        String from = str(i.get("from"));
        String to = str(i.get("to"));
        if (!from.isEmpty() || !to.isEmpty()) {
            return v + " (" + from + " ~ " + to + ")";
        }
        return v;
    }
```
new:
```java
    /** 기간을 앞에: 'YYYY-MM~YYYY-MM' · 시작만 있으면 'YYYY-MM~현재' · 끝만 있으면 '~YYYY-MM'(카드와 같음). 연도만 저장된 값은 그대로. 기간이 없으면 값만. */
    private static String itemText(Map<String, Object> i) {
        String v = str(i.get("value"));
        String from = str(i.get("from")).trim();
        String to = str(i.get("to")).trim();
        String period = !from.isEmpty() && !to.isEmpty() ? from + "~" + to
                : !from.isEmpty() ? from + "~현재"
                : !to.isEmpty() ? "~" + to : "";
        return period.isEmpty() ? v : period + " " + v;
    }
```

## 앞 보고서 시험 중 영향받는 것
- 앞 보고서의 시험 `같은_출처는_출처_절에_한_번만…`은 학력·경력을 서버 순서로 쓰지 않으므로 그대로 유효하다. 번호 단언(`1. `·`2. `)이 있으나 출처가 둘뿐이라 순서와 무관하다.
- 학력·경력 입력의 `from`을 필수로 만드는 main의 서버 검사가 들어오면, 앞 보고서의 시험 중 `itemText(head,"EDU",..)`·`itemText(head,"CAREER",..)`로 학력·경력을 넣는 곳은 400이 될 수 있다. 대상은 `InstitutionHeadDocxApiTest`의 `확정_학력_경력과_후보_학력_경력이…`(`:254-269`)와 앞 보고서 시험 중 `같은_출처는…`(EDU·CAREER 3건)이다. `itemText`를 위 `periodItem`(시작 포함)으로 바꾸고, 후보 쪽 `insertCandidateItem`은 직접 INSERT라 영향이 없다. 정확한 영향 범위는 main이 검사를 넣을 때 확정한다.
