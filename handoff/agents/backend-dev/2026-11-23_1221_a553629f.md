## C. 실행·가정·위험

- **실행**: `cd kgi-ggreport-web && mvn -q -o test -Dtest=PrepBoardApiTest` 다음에 전체 `mvn -q -o test`를 돌립니다(기존 380건 + 신규 7건). 8080 서버가 같은 `target/`을 쓰면 테스트 뒤 재기동합니다.
- **깨질 기존 테스트**: 없을 것으로 봅니다. 기존 체크 시험은 전부 영업 역할 담당자이고, D12도 영업 역할의 비담당이라 같은 403과 DENIED 3줄이 나옵니다.
- **가정**: 아래가 어긋나면 해당 시험만 고칩니다.
  - D25: `BoardUiIds.UNKNOWN`의 값이 "UNKNOWN"이라고 가정합니다. 직접 열어 보지 않았습니다.
  - D27: 중단 뒤 `confirm`이 새 건을 만든다고 가정합니다(PrepApiTest 833줄에 같은 호출이 있습니다). `dobong`이 시드에 있다는 가정은 PrepApiTest가 `dobong`을 쓰는 데 기댔습니다.
  - D22·D23: `stateOf`에 캐시가 없다고 가정합니다. 감사의 `STATE_CD`가 낡은 값이면 `prep.stateOf` 구현을 확인합니다.
- **D28**: 서비스의 `canList` 검사를 빼면 200이 나와 실패하므로 회귀 방지용으로 쓸 수 있습니다.
- **보안**: 403 경로가 하나 늘 뿐 응답 문구와 상태 코드는 기존 비담당 403과 같고, DENIED 감사는 컨트롤러가 따로 커밋합니다. 사번은 `X-Emp-No` 자기신고라 이 검사는 업무 규칙(실수 방지)이지 사칭 방지가 아닙니다.
- **되돌리기**: 서비스에 추가한 `if` 블록과 Javadoc 한 줄을 지우면 됩니다. DB 변경과 마이그레이션은 없습니다.
