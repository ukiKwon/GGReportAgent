# 이사회 자료 양식 커스텀 1단계 — 서버 설계 (backend-dev, 2026-10-30)

> 읽기 전용 설계. 서버·DB는 실행하지 않았다. 대화에서 받은 보고서의 핵심 요약이며 원문 전체는 아니다.

## 요건(사용자 확정)
표 추가·삭제·순서 변경 + 표 제목·머리글·고정 문구·양식 이름 수정. 표 모양(행·열·병합) 편집은 이번에 안 함. 양식은 팀 공유. 편집은 따로 부여받은 지정 담당자·관리자만. 변경 이력은 결재 건에 쓴 양식 버전만. 엑셀 연결은 개발자가 반영. 영업부장은 화면 열람 불필요(결재로 받아봄).

## 권한 표현 (새 메뉴 키 금지 전제)
| 안 | 평가 |
|---|---|
| **A. `tasks` 메뉴의 CAN_EDIT 재사용(권장)** | `PermissionService.canEdit(empNo,"tasks")` 신설. 골든 04·05·MENUS 8키 영향 없음. 기존 권한관리 화면·권한 신청(`edit`)이 그대로 동작. 단점: `tasks.edit` 의미가 '양식 편집'으로 굳음 → 화면 라벨 보완, 키는 상수 한 줄 |
| B. 별도 기능 권한 테이블 | 가장 깨끗하나 신청·결재·권한관리 화면 확장 필요 — 1단계엔 과함 |
| C. 사용자 예외에 새 메뉴 키 | `Menus.MENUS`에 없는 키는 저장 400 — 비권장 |
| D. 역할 고정 | '지정 담당자 부여' 요건 미충족 |
- 배포 전 점검: `SELECT EMP_NO FROM USER_MENU_PERMS WHERE MENU_KEY='tasks' AND CAN_EDIT=1` — 이미 켜진 행이 있으면 배포 즉시 편집 권한을 얻는다.
- 편집 권한 신청에 시스템 관리자 확인까지 넣으려면 `submitPerm`의 `needsAdmin`에 `"tasks".equals(menu) && edit` 한 줄(기획 결정).

## 저장 모델
헤더 `BOARD_FORM` + 불변 버전 `BOARD_FORM_VER`(SPEC_JSON 한 덩어리, 정규화 안 함) + 결재 사용 기록 `BOARD_FORM_USE`(상신은 후속이라 지금은 빈 표). `default_doc`은 코드의 수정 불가 원본, 복제하면 팀 소유 v1. 편집 = 새 버전 INSERT(예전 버전은 지우지 않음). 삭제는 ARCHIVED로 숨김만. 공유 범위 `TEAM_KEY = Teams.teamOf(role)`(부장·디자이너 role의 teamOf 값 **불확실**). 표 추가는 `BoardDocSpec.catalog()` 목록에서 고르기, 같은 표 중복 금지.

## API (`/board-forms`, 기존 `/board-docs` 불변, snake_case)
GET 목록·카탈로그·상세(`?version=`)·docx·versions, POST copy·archive·restore, PUT 저장(`{base_version,name,tables:[{ref,title,notes,cells}]}`). PUT은 구조·매핑을 받지 않고 **재정의 값만** 받아 서버가 카탈로그에서 구조를 다시 만든다(변조 입력점 없음). 오류: 401/403(`양식을 편집할 권한이 없습니다.`)/404(남의 팀 양식은 존재 숨김)/400/409(`다른 사람이 먼저 저장했습니다…`, 낙관적 락 `CURRENT_VER`).

## 결재 연계(후속)
상신 payload에 `{form_id, form_version, …}`만 박고 스냅샷은 넣지 않음(4000자 제한). 버전 행이 불변이라 결재 중 편집해도 상신 버전 유지. `default_doc` 직접 상신 금지 권장. 결재자 보기 API `GET /approvals/{id}/board-doc` 윤곽. 지금 매핑 칸의 값은 비어 있어, 실제 수치 대조는 docfill 항목(엑셀→워드)의 몫.

## 검증·DDL·테스트
길이(이름 60, 표 제목 100, 칸 100, 주석 300×5, JSON 60KB), 제어문자 거부, 매핑 칸 키 전송 시 400. DDL 번호 014(mysql/oracle 쌍, Oracle은 CLOB·IDENTITY, `IS JSON`은 불확실해 제외), 되돌리기는 DROP 3개. 테스트 약 25건(권한·복제·저장·409·팀 공유·버전 고정).

## 열린 질문
편집 권한을 걸 메뉴 키(`tasks` vs `workflow`), 운영 DB의 `tasks.edit=1` 기존 행, 팀 내 활성 이름 중복 금지의 엄격함(동시성 경합 시 중복 가능), 버전 보존 기간.
