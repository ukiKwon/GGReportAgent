## 설계와 다른 점
- 모두 시험 구성이나 사소한 처리입니다. 설계 로직은 바꾸지 않았습니다.
- 접근성을 확인했습니다. `NoticeRoundRules.advanced/CLOSED/NO_BID`, `NoticeRoundService.CLOSE_NO_BID`, `BankContractRules.termState/endOrNull`은 같은 package 멤버라 직접 호출했습니다. 복제하지 않았고 `BankContract*`·`NoticeRound*`는 건드리지 않았습니다.
- 시험 19번은 설계 문구("Y+1을 Y로 고치기 409")를 그대로 쓰면 DUP_TARGET이 먼저 걸립니다. 그래서 1번을 뺀 뒤 Y+1(번호 2)을 Y로 고쳐 `INST_BID_CLOSED`를 검증하게 구성했습니다.
- 시험 10번(옮기기 입력 검사)은 관심 기록이 있으면 목표를 새로 못 넣습니다. 그래서 먼저 관심 기록을 빼고 목표를 넣은 뒤 "목표→관심에 연도 400"을 확인합니다.
- `BidTargetApiTest`는 `round()`·`activePrep()` 같은 보조 메서드와 `code(MvcResult)`를 새로 두었습니다. 기존 메서드 이름과 겹치지 않습니다.

## 메인이 실행할 것
1. 순서는 코드 적용 → `cd kgi-ggreport-web && mvn -q -o test` → 로컬 MySQL에 `db/mysql/044_bid_target_kind.sql` 한 번 실행(045를 이미 돌렸어도 가능) → 8080 재기동입니다.
2. 기대는 기존 시험과 추가분 전부 통과, 골든 04·05 변화 없음입니다.
3. 컴파일에서 확인할 곳은 `BidTargetService`의 `in.getBaseRevNo() != cur.getRevNo()`(Integer/int)와 `BidTargetRulesTest`의 `setTargetYear(null)`입니다.
4. 시험 컨텍스트가 안 뜨면 H2가 `MODIFY (TARGET_YEAR NULL)`을 못 받는 경우입니다. 이때는 Oracle 044의 두 번째 문장을 `ALTER TABLE INST_BID_TARGET MODIFY TARGET_YEAR NULL;`로 바꿉니다. 이 경우 `BidTargetKindDdlPairTest`의 `contains("MODIFY (TARGET_YEAR NULL)")` 단언도 같이 고쳐야 합니다.
