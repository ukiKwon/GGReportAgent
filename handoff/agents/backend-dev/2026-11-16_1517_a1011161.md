### 2. 설계와 달라진 점·보안 반영
- **중-1·중-4**: `NoticeRoundService.canJudge(empNo)`를 만들었다. 조건은 `permissions.canEditInstitution` 그리고 `HeadRules.isSales(role)`이다.
  - 컨트롤러는 `requireInstitutionEdit` 다음에 `canJudge`를 쓴다. 실패하면 `throw guard.denied(req, new ApiException(403,…))`로 DENIED 한 줄을 남긴다. `canJudge`는 서비스 트랜잭션(기관 행 잠금) 전에 부른다.
  - `current()`의 `can_edit`도 같은 함수를 쓴다.
  - `save()` 안에도 `isSales` 방어 검사를 하나 더 뒀다.
  - 시험 19는 DESIGNER 403과 DENIED +1행으로 바꿨다. IT에 map·regions 수정 예외를 준 경우의 403 시험도 더했다. 그 밖에 영업팀 수정 권한을 끈 경우와 팀장·부장 201 시험이 있다.
- **중-2**: `opinion()`을 코드 포인트 단위로 바꿨다. CONTROL·FORMAT·LINE/PARAGRAPH_SEPARATOR·SURROGATE를 거부하고 `\n`·`\t`만 허용한다. 시험은 U+202E, U+0085, U+2028, 짝 없는 `\uD800`을 규칙 시험(DB 없음)과 API 시험에서 각각 400으로 확인한다. 소스에는 보이지 않는 문자를 날것으로 두지 않고 코드 포인트 숫자로 만들었다.
- **중-3**: `opinion()` 끝에서 `Pii.scan`이 하나라도 걸리면 400이다. 문구는 `의견에 주민등록번호·전화번호 같은 개인정보를 적을 수 없습니다.`로 고정했고 검출값은 싣지 않는다. 휴대폰·주민번호·이메일·카드 시험이 있고, API 시험은 응답에 번호가 없는지 확인한다.
- **하-3**: 컨트롤러가 `ApiException`을 잡아 DETAIL에 `notice-round save <상태> <CODE>`를 넣고 다시 던진다. CODE는 `[A-Z_]`만 받는다. 코드가 없으면 상태만 남긴다.
- 설계 코드에서 Java 8 안전을 위해 `new HashMap<>()` 등을 명시 타입으로 풀었다. 의미는 같다.
- ACCESS_LOG 칸 이름은 기존 시험의 `EVENT_TYPE`·`STATUS_CODE`·`REQ_PATH`·`DETAIL`·`EMP_NO`·`HTTP_METHOD`·`LOG_ID`를 따랐다.
