## 3. 구현안

### 3-0. 설계 결정 요약
1. **오류 통일 범위 한정**: 새 `@RestControllerAdvice(assignableTypes = BoardWriteController.class)` + `@Order(HIGHEST_PRECEDENCE)`. 이 advice 는 그 컨트롤러가 handler 인 예외에만 적용되고, 기존 `ApiExceptionHandler`(order 없음=최하위)는 다른 컨트롤러에 그대로 문자열 detail 을 낸다. 컨트롤러 메서드 안(가드 401·403, 서비스 400·404, `@RequestBody` Jackson 400/415)은 모두 이 advice 로 온다.
2. **advice 가 닿지 않는 곳**(handler 가 없는 시점에 터지는 것) → 각자 고친다: 서블릿 필터 411/413(본문 직접 작성, message 추가), 전역 multipart 한도 `MaxUploadSizeExceededException`(전역 핸들러가 이미 객체 — message 만 추가, 다른 화면 영향 없음), 경로·메서드 매칭 실패(404/405, 작성 화면이 만들 일 없음 — 비범위로 명시).
3. 상태별 code: 400 `BAD_REQUEST`, 401 `UNAUTHENTICATED`, 403 `FORBIDDEN`, 404 `NOT_FOUND`, 409 `CONFLICT`, 415 `UNSUPPORTED_MEDIA_TYPE`, 5xx `SERVER_ERROR`. 서비스가 이미 정한 객체 detail(`EMPTY_FILE`, `PII_DETECTED` 등)은 그대로 통과. 5xx 문자열은 일반 문구(`GENERIC_500`)로 바꾸며 개발축(verbose) 원문은 이 advice 에서 싣지 않는다.
4. **머리글 주의 표현**: 표마다 `needs_review`(boolean)·`label_mismatches`(목록, 최대 10) + 그 표의 모든 칸 `warnings` 에 `{"code":"LABEL_MISMATCH"}` + 최상위 `warnings` 에 `LABEL_MISMATCH`(`tables` 목록, 배너용). `summary.label_mismatch_tables` 추가. 422 `STRUCTURE_MISMATCH` 는 시트 없음(`SHEET_MISSING`)만 남는다.
5. **raw**: `source.raw`(숫자 셀만, 아니면 null) + `source.rounded`(true/false/null). 수식은 캐시값 기준, 숫자만(`Value.numeric` 플래그 신설), 소수 6자리 HALF_UP·후행 0 제거·지수 표기 없음·`-0`→`0`·40자 초과면 null. `rounded` = 표시값을 숫자로 읽을 수 있을 때 표시값 ≠ raw면 true, 같으면 false, 읽을 수 없으면 null.
6. **합계 검산 = 표시값 기준**. 쉼표·공백 제거, `(1,234)`·`△`·`▲` 음수, 단위·%가 붙으면 검산 생략(경고 없음). 경고 `{"code":"SUM_MISMATCH","basis":"display","expected","actual","diff"}`. 원래 값 기준 비교는 삭제.
7. **별칭**: labels 값을 문자열 또는 문자열 배열로. 비문자열·빈 배열·빈 문자열·10개 초과·100자 초과 → 기동 실패. 공백 정규화 후 완전 일치, 어느 하나와 같으면 통과. 응답 `expected` 는 첫 번째(대표) 별칭.

## 5. 보안·위험·되돌리는 법
- **권한 검사 불변**: 401·403 판정과 `DENIED` 이력은 `MenuGuard` 그대로. 인증은 여전히 `X-Emp-No` 자기신고 — 앞단 인증 전에는 보안 경계 아님.
- **접근 이력**: 코드·pii_kinds·size 만. 값·머리글·파일명·raw 를 이력·로그에 쓰지 않는다. 머리글 주의(200)는 `code=OK`.
- **raw 노출**: (1) `scanPii` 가 표시값·원값 둘 다 검사 후 지도 범위 적발 시 422 — 새 PII 경로 아님. (2) **표시 서식으로 줄이거나 가린 값**(`#,##0,`·리터럴 서식·반올림 등)의 정밀값이 raw 로 응답에 나간다(재정정 2026-11-02 테스트 결과: POI는 `;;;` 서식에서도 숫자를 표시값으로 돌려준다 → 값·raw 모두 응답에 나감. 적용분은 칸 warnings에 `HIDDEN_FORMAT` 경고를 붙인다. security F5·C4의 "EMPTY·raw null" 추정은 틀림) — 업로드한 본인에게만, 서버 미저장. 프런트 안내 문구 필요, NEXT 35·Q6 정보보호 문의에 포함 권장. (3) 지도 칸(95칸)·숫자 셀·최대 40자만. (4) 프런트가 raw 를 localStorage·초안 docx 요청에 넣지 않도록 못 박을 것.
- **머리글 강등 위험**: 시트 이름만 같은 엉뚱한 엑셀도 값이 채워진다 → 칸마다 LABEL_MISMATCH+최상위 경고+전 칸 확인(프런트 규격에서 강제 필수). 시트 없음은 여전히 422.
- **검산 생략**: 단위·% 표시값이면 경고 없음(침묵). 필요 시 `SUM_UNVERIFIABLE` 후속.
- **되돌리기**: 새 핸들러 삭제 → 이전 오류 형식. 응답 키는 전부 추가, 제거는 STRUCTURE_MISMATCH 의 LABEL_MISMATCH reason 뿐 + SUM_MISMATCH `expected` 의미 변경(원래 값 합 → 표시값 합).
- **내부 정보**: HttpMessageNotReadable 메시지를 응답에 싣지 않음(테스트 포함).

## 6. 프런트 계약 변경 요약
