# 이사회 자료 '작성' MVP(1단계) 서버 구현안 — 요약 (backend-dev, 2026-11-02)

> 메인이 backend-dev 응답의 계약·결정·보안·테스트 부분을 저장했다(전체 패치 코드는 적용 때 다시 받는다). 서버·테스트 미실행, POI 5.2.3 API(`getPartsByName`·`isMacroEnabled`·`getCTCell().isSetV()`) 컴파일 미확인.

## 결정
- **무상태**: 업로드 즉시 파싱 결과 응답, 원본 바이트는 요청 끝에 버림. 초안 워드는 화면이 보낸 현재 값으로 생성. 서버 세션·DB 변경 없음(디자인 §6.5 '세션 만료' 상태 없음).
- 작성 권한 = tasks **write**: `PermissionService.canWrite`·`MenuGuard.requireWrite` 신설(관리자 통과, 역할 기본값엔 write 없음). `GET /board-forms`에 `can_write` 추가.
- 기존 `ExcelSource`는 재계산(FormulaEvaluator)하므로 새 리더 `docfill/XlsxBook`은 캐시값만 읽음(캐시 없으면 `NO_CACHED_VALUE`). 수식 셀은 캐시 결과 타입으로 `formatRawCellContents` 표시값(엑셀 반올림 그대로).
- 매핑 칸 95개(A 5 + B 14 + C-2 48 + C-3 25 + C-4 3). 매핑은 `src/main/resources/boarddoc/excel-map.json`(mapping_ver·catalog_ver, 표별 sheet·range·labels(구조 검사)·cells/rows·sums). 가상 엑셀 기준 — 실제 사본 오면 이 파일만 바꾸고 mapping_ver 증가. 로더가 기동 시 검증(카탈로그 매핑 칸 집합과 정확히 일치, 범위 안, 2,000칸 이하) 실패면 기동 실패.

## API
| 메서드·경로 | 권한 | 요청 | 성공 |
|---|---|---|---|
| `GET /board-forms/excel-map` | tasks view | — | `{mapping_ver, max_mb, tables:[{ref,sheet,range}]}` |
| `POST /board-forms/{id}/excel` | tasks write | multipart `file`, 선택 `version` | 200: `form{id,version,name}`, `mapping_ver`, `summary{total,filled,failed,warnings}`, `tables[{ref,cells[{key,value,status,reason,source{sheet,cell,display},warnings[]}]}]`, `sources[{ref,sheet,range,first_row,cols,rows,merges}]`, `unmapped_tables` |
| `POST /board-forms/{id}/draft-docx` | tasks write | JSON `{version, tables:[{ref, cells:{key:value}}]}`(매핑 칸만) | docx, `{양식이름}_초안.docx`, `Cache-Control: no-store` |
- `{id}` = `default_doc` 또는 양식 번호. 남의 팀 404, 보관 양식 400, default_doc+version 400. 원본 파일명은 응답에 없음.
- 칸 실패 reason: `NO_CACHED_VALUE|EMPTY|EXCEL_ERROR|TOO_LONG`. 주의 code: `EXTERNAL_LINK|HIDDEN_SHEET|HIDDEN_ROW|HIDDEN_COLUMN|SUM_MISMATCH(expected)`.
- 오류는 `{"detail":{code,message,…}}`(객체): 400 `EMPTY_FILE` · 413 `FILE_TOO_LARGE`(max_mb) · 415 `NOT_XLSX`(확장자·PK 시그니처·.xls·암호) · 422 `MACRO`(.xlsm·vbaProject·macrosheets·activeX·macroEnabled) · 422 `BROKEN`·`TOO_MANY_CELLS`(20만) · 422 `PII_DETECTED`(`kinds:[{kind,count}]`, 값·시트·셀 없음) · 422 `STRUCTURE_MISMATCH`(`reasons` 최대 20, actual 40자 자름) · 503 `BUSY`(동시 2건 초과).
- 처리 순서: 형식 → 열기(매크로) → **개인정보(통합문서 전체)** → 구조 → 값. 개인정보가 구조 오류의 actual에 섞여 나가지 않음.

## 보안(백엔드 자체 평가)
- 업로드·초안은 requireWrite, 401/403 DENIED 기록(경로만). multipart는 컨트롤러 전 수신 완료라 권한 없는 사용자도 50MB까지 올라옴(파싱은 안 함). 인증은 X-Emp-No 자기신고(SSO 전엔 경계 아님).
- 5MB 앱 한도, PK 시그니처, OOXML만(WorkbookFactory 미사용 → HSSF 경로 없음), 매크로 3중 검사, ZipSecureFile 전역(기존), 셀 20만, 동시 2, 재계산 없음(외부 함수 실행 경로 없음).
- 위험: XSSF DOM은 5MB xlsx도 수백 MB 힙 가능 — 운영 힙에 맞춰 조정. `0` 서식 13자리 숫자(사업자·계좌번호)는 주민번호로 오탐 → 업로드 거부 가능. 50MB 초과 `MaxUploadSizeExceededException` 핸들러 없음(500 가능, 별도 항목).
