### 3. 설계와 다르게 한 곳
1. **`@MockBean` 시험을 만들지 않고 Mockito 시험으로 대체했다.**
   - 설계의 `PrepScriptDraftOnApiTest`는 `@MockBean OllamaLlmClient`를 썼다. 그런데 `AppTest.java`는 컨텍스트가 둘 뜨면 H2의 001 DDL이 두 번 돌아 전체 시험이 죽는다고 적어 두었고, `@MockBean`도 쓰지 말라고 한다.
   - 그래서 스프링 컨텍스트 없이 `PrepScriptDraftFlowTest`를 만들었다(`InstitutionHeadDocxAuditFailureTest`와 같은 standalone MockMvc + Mockito 방식).
   - `Basis` 필드와 `BoardMaterialAudit.Ctx` 생성자가 package-private이라 이 시험은 `service` 패키지에 두었다.
   - 이 시험이 보는 것은 아래다.
     - 판정 순서 404, 403, 409, 503
     - SEND 감사, 호출, 결과 감사 순서
     - COOLDOWN
     - 보내기 전 감사가 실패하면 500이고 호출하지 않으며 자리를 돌려주는지
     - 결과 감사 실패 시 500
     - NO_BASIS
     - 확정 전 자료의 `basis.draft`
     - 허용 숫자 위반 시 그 칸만 비움
     - status의 probe 무시
2. **status의 probe 성공 경로(reachable, model_ready 키가 실제로 실리는지)는 시험하지 못했다.** `OllamaLlmClient.Probe`가 final이고 생성자도 package-private이라 Mockito로 만들 수 없다.
3. `ScriptDraftOut`, `ScriptDraftService`, `ScriptDraftPrompt`, `ScriptDraftBasisReader`는 바탕 문서에 전체 코드가 있어 그대로 채웠다. 3-3의 `OllamaLlmClient` 차이도 반영했다. 시험은 바탕 문서에 설명만 있고 코드가 없어서 설명을 바탕으로 새로 썼다.
4. **프롬프트 규칙 5**("400자 이내" → "400자 안팎")와 아래 4번은 지시나 설계에서 벗어난 판단이다.
5. **`OllamaLlmClientTest`**: 서버가 몇 바이트씩 끌며 보내는 감시 타이머 시험은 약 6초 걸린다. 응답이 늦은 시험은 약 1초다.

### 4. 컴파일·실행이 의심되는 지점
실제 코드를 열어 확인한 것은 모두 설계와 맞았다. 확인한 것은 `BoardAccess`(canViewCase, isSalesWriter, isViewAll), `PrepService`(`TASK_STATES`가 같은 service 패키지, `requireVisible`·`stateOf`), `PrepAudit.record`(7인자), `BoardMaterialAudit.before`·`record`·`Ctx`, `ApiException.withDetail`, `MenuGuard`(requireActiveUser, denied), `BoardUiIds.Ui` 생성자(package-private이라 `support` 패키지에 둠), `BoardScriptFigures` 필드, `WorkflowOverviewService.regionName`, `BoardMaterialService.CONFIRMED`, `Pii.scan`, `LlmException` 계열 생성자 등이다. 남은 위험은 다음과 같다.
- `ScriptDraftPrompt.put/putList`는 가변인자 대신 두 집합을 받는 시그니처로 바꿨다(null이면 건너뜀). 경고 대신 단순화한 것이다.
- Pii 판정 관련 시험은 이 정규식이 실제로 어떻게 판정하는지 확인하지 못한 채 쓴 것이다. 실패하면 시험 기대값 쪽을 의심한다.
  - `ScriptDraftBasisReaderTest`의 "예산 1,234,567천원"과 "12345678"이 유지되는지
  - `ScriptDraftServiceTest`의 `test@example.com`이 PII로 걸리는지
- `PrepScriptDraftApiTest`는 사번 `9999999`가 미등록 → 403이 되는지를 가정했다.
- `PrepScriptDraftFlowTest`의 `mock(ScriptDraftBasisReader.class)`와 `mock(PrepService.class)`는 기본 Mockito로 만든다. 이 저장소의 Mockito가 클래스 모킹을 못 하면 여기서 실패한다.
- `ollama` 키는 `LlmProperties`(prefix `ggreport.llm`)와 겹쳐 보이지만 Boot 기본 설정이 모르는 키를 무시한다.

### 5. 메인이 돌릴 명령
8080 서버가 같은 `target/`을 쓰고 있으면 먼저 확인한다. 다른 세션이 쓰는 중이면 기다린다.
```
cd kgi-ggreport-web
mvn -q -o test -Dtest='OllamaGuardTest,OllamaLlmClientTest,ScriptDraft*Test,ScriptAiFieldsTest,PrepScriptDraftFlowTest,PrepScriptDraftApiTest'
mvn -q -o test
```
기대: 모두 통과하고, 기존 시험에는 영향이 없다. 새 빈은 `enabled` 키가 없으면 생기지 않는다. `OllamaProperties`와 `ScriptDraftService`, `ScriptDraftBasisReader`, `PrepScriptDraftController`는 컴포넌트 스캔으로 올라오는데 의존 빈은 모두 이미 있다.
