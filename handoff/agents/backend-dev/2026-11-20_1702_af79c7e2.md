## 3. 팀·사용자 결정의 반영 (InstNameMatcher)
- **정식 이름만**: 약칭 사전은 없습니다.
- **시도 접두 표**
  - 46은 `전남광주통합특별시·전남광주·광주광역시·광주시·광주·전라남도·전남`으로 바꿨습니다.
  - 전남광주통합특별시 행은 시도급으로 인식됩니다. 이름이 접두와 같으면 자동으로 그렇게 됩니다.
  - 29·51·52는 옛 표기용으로 남겼습니다.
- **낱말 경계**
  - 일치 바로 뒤가 `청년·청소년·청사·청렴·시민·도민·군민·구민`으로 이어지면 그 일치를 버립니다.
  - 일치의 마지막 글자를 낱말 첫 글자로 겹쳐 쓰는 경우도 봅니다. `서울청`+`년`, `부산시`+`민`이 그 예입니다.
  - 정확한 위치는 `glued()` 한 곳입니다.
- **법인 접두**: `재단법인·사단법인·의료법인·(재)·(사)`는 사전 등록 때 뗍니다(`stripCorp`). 전각 괄호도 처리합니다.
- **영문 소문자 통일**: `normalizeWithMap`에서 처리합니다.
- **기획 기본값**: 잠긴 작업 ack는 디자이너 작업만 409로 막고, ack는 담당 본인만, `rejectUnsafe` 기본 off, 같은 시도 교육청 언급은 보고합니다.

## 4. 설계와 달라진 점
1. MySQL 057 머리말을 고쳤습니다. 설계는 "056은 비어 있다"고 썼지만 이제 056·058이 있어서 "056까지 적용한 DB에서 057만 한 번"으로 썼습니다. Oracle 머리말도 055→056으로 고쳤습니다.
2. 영벡 문자(제로폭 공백 등) 제거는 `'​'` 리터럴 대신 `(char) 0x200B` 형태로 썼습니다. 소스에 보이지 않는 문자가 들어가는 것을 막기 위해서입니다.
3. `DocCheckService`의 `extract`·`record`·`onFileRemoved`는 설계대로 public으로 뒀습니다. 반환·인자 타입이 package-private인데, Mockito가 mock할 때 NPE가 나지 않게 하려는 것입니다.
4. 낱말 경계를 버릴 때는 같은 시작 위치의 더 짧은 일치로 되돌아가지 않고 한 글자 건너뜁니다.
5. 알려진 빈틈: 공백을 지운 뒤 비교하므로 "도봉구 민원"이 "도봉구민원"이 되어 `구민` 규칙에 걸려 버려집니다. 화면 문구의 "한계"에 넣어 주세요(→ 디자인).
6. 설계 4절의 시험 중 다음은 넣지 않았습니다.
   - DTD(외부 엔티티) pptx가 BROKEN이 되는 시험: JDK StAX는 SUPPORT_DTD=false이면 DOCTYPE 이벤트가 안 올 수 있어 결과가 불확실합니다. 보안상 안전하지만 기대값을 장담할 수 없습니다.
   - 첨부(EmbeddedFile) PDF의 ATTACHMENT 시험: `hasName` 단위 시험으로 대체했습니다.
   - 서로 다른 세 팀(영업) 작업의 ack 시험.

## 5. 메인이 실행할 명령
1. 로컬 MySQL: 056·058과 무관하게 057만 한 번 적용합니다. 비밀번호는 프롬프트로 받습니다. 실행 전에 8080 서버·DB를 한 세션만 쓰는지 확인하세요.
   `mysql -u <계정> -p <DB> < kgi-ggreport-web/src/main/resources/db/mysql/057_doc_check.sql`
2. `cd kgi-ggreport-web && mvn -q -o test`. 시험은 H2가 oracle/057을 돌리므로 위 1번과 무관합니다.
3. 8080 서버가 같은 `target/`을 쓰면 시험 뒤 재기동합니다.

기대 결과는 전체 통과입니다. 새로 늘어난 시험은 DdlPair 4, InstNameMatcher 약 11, Runner 4, Extractor 약 14, UnsafeTest 3, ApiTest 9, 필터 1건입니다. 기존 `GoldenWriteScenarioTest`, `DesignReviewApiTest`는 응답 계약이 그대로라 영향 없다고 봤습니다.
