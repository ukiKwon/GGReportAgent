## 3. 구현안

### 확정한 설계

**(1) 양식 정의.** 칸 속성 3개를 추가한다. 모두 `BoardDocSpec.Cell`에 있고 카탈로그에서만 정해진다. 사용자 입력으로는 바뀌지 않는다.

| 속성 | 의미 | 값 |
|---|---|---|
| `unit` | 표시 단위. 저장은 숫자만, 화면·워드가 뒤에 붙인다 | `""`(없음) / `"년"` / `"%"` |
| `paren` | 값이 두 개인 칸. 둘째 값의 key는 `key + "_p"`(`sub_key`) | boolean |
| `dec` | 표시 소수 자릿수 고정. null이면 저장값 그대로 | 2 / null |

- 적용 칸:
  - B r1_c5·r2_c5: `paren`
  - C-4 r1_c1: `unit="년"`. r3_c1: `unit="%"`. 이 칸들의 `dec`는 null
  - A·B·C-2·C-3·C-5의 연결 칸 전부: `dec=2`
- A r1_c0은 `input:true, mapped:false`, 가운데 정렬, 문구 ""로 바꾼다.
- 합쳐서 한 칸에 문자열로 담는 방식(예: 객체 값)은 쓰지 않는다. 스냅샷이 평면 문자열 맵이라서, 평면 키 방식이 기존 스냅샷과 가장 호환이 쉽다. 옛 스냅샷은 `_p`가 없을 뿐이다.

**(2) 옛 저장 양식 호환.**
- `catalog_ver` 2로 저장된 양식(r1_c0이 `i:false`인 연결 칸이었음): `assembleChecked`가 카탈로그에서 입력 칸으로 바뀐 자리의 비머리·비입력 칸을 입력 칸으로 올린다.
  - 이 칸은 연결 칸이었으므로 사용자가 쓴 문구가 없다 (`t=""`).
  - 단점: 이 자리를 다시 일반 칸으로 되돌리는 편집은 안 된다. 기관명 자리라 문제 없다고 본다.
- `catalog_ver` 1로 저장된 양식: `readV1Structure`가 `i`를 카탈로그와 대조하는 곳에서 A r1_c0만 얼린 모양(`i:false`)으로 비교한다. 안 그러면 닫힌 실패(500)가 난다.
- `CATALOG_VER`와 `mapping_ver`는 올리지 않는다.
  - 올리면 기존 테스트가 늘어난다.
  - 이행은 위 두 지점만으로 충분하다.

**(3) 서버 검증.**
- 연결 칸: 숫자만 허용한다 (13자리·소수 2자리, 쉼표 허용, `canonNumber` 그대로). `unit` 칸에 "3.4년"을 보내면 400이다. 단위는 서버가 받지 않는다.
- `paren` 칸: 앞 값과 `_p` 값을 각각 같은 규칙으로 검사해 각각 `canonNumber`로 저장한다.
  - 앞 값 없이 `_p`만 있으면 `_p` 칸을 문제 칸으로 표시한다 (400).
  - `paren`이 아닌 칸에 `_p`가 오면 400 `BAD_VALUE`("값을 넣을 수 없는 칸이 포함되어 있습니다.") 단일 메시지다. 이 경우 `cells` 목록은 없다.
- 텍스트 입력 칸: 이미 `scanPii`(scanLoose)가 모든 원본 칸을 훑는다. 저장 전 trim·제어문자·100자는 `clean`이 맡는다. 저장 후 재스캔도 유지한다.
- 400 detail은 그대로다: `{code:"BAD_VALUE", message, count, cells:[{ref,key}]}`. `key`가 `r1_c5_p`일 수 있다. `Marks.safe`(SAFE_ID `[A-Za-z0-9_]{1,40}`)를 통과한다.

**(4) 표시 정책 (QA P3-1).**
- 저장은 정규형이다 (후행 0 제거. 예: "5.10"→"5.1", "1.00"→"1"). 서버 `canonNumber`는 건드리지 않는다.
- 표시는 화면·워드 모두 같은 규칙이다.
  - `dec=2` 칸: 소수 둘째 자리 고정 + 천 단위 쉼표. 5→"5.00", 5.1→"5.10".
  - `dec=null` 칸: 저장값 그대로. 여기에 `unit`을 붙인다 ("3.4년", "0.74%").
  - `paren` 칸: "5.00 (1.00)".
- 이렇게 하면 업로드 직후 화면(2자리 고정), 저장본, 읽기 전용, 워드가 모두 같은 글자가 된다.
- 숫자 모양이 아닌 값(예: 구형 초안이 보낸 "5.00 (1.00)")은 가공 없이 그대로 쓰고 단위도 붙이지 않는다. 그래서 초안 API의 하위 호환이 유지된다.
- 영향: 초안 docx에서 예전에는 "500"으로 보이던 `dec=2` 칸이 "500.00"으로 나온다 (§4의 깨질 테스트 참고).

**(5) 업로드 정규화는 서버가 한다** (`BoardExcelNamedFill`). 이유:
- 서버가 이미 `main_value`·`sub_value`를 준다.
- 단위는 양식 칸이 정의하므로 칸을 아는 서버가 떼는 편이 일관된다.
- 클라이언트 파싱을 줄여 회귀를 줄인다.

규칙:
- 칸에 `unit`이 있으면 `value`를 trim한다. 끝이 그 단위면 단위를 떼고 trim한다.
- 남은 글자를 `shownNum`으로 숫자 해석한다. 이 함수는 쉼표·공백 제거, `(1,234)`·`△`·`▲`는 음수로 처리한다.
- 성공하면 `value`는 `plain(BigDecimal)`(예: "3.4", "0.74", "-1.2")이다.
- 실패하면 (예: "3.4개월") `value`는 그대로 두고, 경고 `CELL_UNIT_TEXT`를 달고, `status`를 `review`로 한다. 단위 없는 숫자("3.4")는 그냥 통과한다.
- 숫자 해석 뒤에도 소수가 3자리 이상이면 값을 반올림하지 않는다. 저장 때 서버가 막고 칸이 표시된다 (조용한 반올림 금지).
- `paren` 칸은 서버가 이미 `main_value`·`sub_value`를 준다 (값 "1,234.50" 모양 포함). 서버 `canonNumber`가 쉼표를 받으므로 그대로 보내도 된다.

     * 화면이 보낸 값 검증·정리: 표 ref·칸 key 가 문서에 있어야 하고(값 칸 + 괄호 칸 둘째 값만), 값은 clean(제어·서식 문자 거부·trim·100자).
     * 빈 값은 빼고 문서 순서로 돌려준다(빈 표는 생략). 저장용이다 — 표시 가공(단위·소수 자릿수·괄호)은 {@link #withValues}.
     * 오류는 EditException(고정 문구, 입력값 미포함).
     */
    public static Map<String, Map<String, String>> cleanValues(Doc doc, Map<String, Map<String, String>> values) {
        Map<String, Map<String, String>> in = values == null
                ? new java.util.HashMap<String, Map<String, String>>() : values;
        Set<String> refs = new HashSet<>();
        for (Table t : doc.getTables()) {
            refs.add(t.getId());
        }
        if (!refs.containsAll(in.keySet())) {
            throw new EditException("알 수 없는 표입니다.");
        }
        Map<String, Map<String, String>> out = new java.util.LinkedHashMap<>();
        for (Table t : doc.getTables()) {
            Map<String, String> cells = in.get(t.getId()) == null
                    ? new java.util.HashMap<String, String>() : in.get(t.getId());
            Set<String> allowed = valueKeys(t);
            if (!allowed.containsAll(cells.keySet())) {
                throw new EditException("값을 넣을 수 없는 칸이 포함되어 있습니다.");
            }
            Map<String, String> cl = new java.util.LinkedHashMap<>();
            for (String key : allowed) {
                String v = cells.get(key);
                if (v != null) {
                    String s = clean(v, MAX_CELL, true, null,
                            "칸 값은 " + MAX_CELL + "자 이하로 입력해 주세요.", "칸 값에 쓸 수 없는 문자가 있습니다.");
                    if (!s.isEmpty()) {
                        cl.put(key, s);
                    }
                }
            }
            if (!cl.isEmpty()) {
                out.put(t.getId(), cl);
            }
        }
        return out;
    }

    /**
     * 화면이 보낸 값을 값 칸에만(연결 칸 + 직접 입력 칸) 얹은 새 Doc — 워드 초안용 <b>표시 문구</b>.
     * 보내지 않은 값 칸은 빈칸. 표시 규칙(화면과 같다): dec 가 있는 칸은 소수 dec 자리 고정 + 천 단위 쉼표, unit 이 있는 칸은 숫자 뒤에 단위,
     * 괄호 칸은 "앞 (괄호 안)". 숫자 모양이 아닌 값(옛 초안이 보낸 "5.00 (1.00)" 등)은 가공하지 않고 그대로 쓴다.
     * <p>⚠️ 보안 메모(기존 유지): 워드에는 w:t 일반 텍스트로만 쓴다(BoardDocDocx.run → XWPFRun.setText). 필드 코드·하이퍼링크에 넣지 말 것.
     * CSV/xlsx 내보내기가 생기면 =,+,-,@ 로 시작하는 값 앞에 ' 를 붙일 것.
     */
    public static Doc withValues(Doc doc, Map<String, Map<String, String>> values) {
        Map<String, Map<String, String>> cleaned = cleanValues(doc, values);
        List<Table> out = new ArrayList<>();
        for (Table t : doc.getTables()) {
            Map<String, String> cells = cleaned.get(t.getId()) == null
                    ? new java.util.HashMap<String, String>() : cleaned.get(t.getId());
            List<List<Cell>> rows = new ArrayList<>();
            for (int r = 0; r < t.getRows().size(); r++) {
                List<Cell> dst = new ArrayList<>();
                for (int i = 0; i < t.getRows().get(r).size(); i++) {
                    Cell c = t.getRows().get(r).get(i);
                    String text = c.getText();
                    if (c.isMapped() || c.isInput()) {
                        text = display(c, cells.get(c.getKey()), c.isParen() ? cells.get(c.getSubKey()) : null);
                    }
                    dst.add(c.withText(text));
                }
                rows.add(dst);
            }
            out.add(new Table(t.getId(), t.getMapping(), t.getTitle(), t.getColumns(),
                    t.getRowIds(), t.getColIds(), t.getNextR(), t.getNextC(), rows,
                    t.getNotes().toArray(new String[0])));
        }
        return new Doc(doc.getId(), doc.getName(), out.toArray(new Table[0]));
    }

    private static final Pattern DISP_NUM = Pattern.compile(
            "-?(?:\\d{1,13}|\\d{1,3}(?:,\\d{3}){1,4})(?:\\.\\d{1,2})?");

    /** 칸 표시 문구. main/sub 는 clean 을 거친 값(없으면 null). */
    static String display(Cell c, String main, String sub) {
        String m = main == null ? "" : main;
        String s = sub == null ? "" : sub;
        if (c.isParen()) {
            if (m.isEmpty() && s.isEmpty()) {
                return "";
            }
            String ms = shown(c, m, false);
            return s.isEmpty() ? ms : (m.isEmpty() ? "" : ms + " ") + "(" + shown(c, s, false) + ")";
        }
        return shown(c, m, true);
    }

    private static String shown(Cell c, String v, boolean withUnit) {
        if (v.isEmpty() || !DISP_NUM.matcher(v).matches() || (c.getDec() < 0 && c.getUnit().isEmpty())) {
            return v;                                   // 숫자가 아니거나 가공 규칙이 없는 칸은 보낸 그대로
        }
        java.math.BigDecimal d = new java.math.BigDecimal(v.replace(",", ""));
        String body = c.getDec() >= 0 ? BoardNumber.fixed(d, c.getDec()) : v;
        return withUnit ? body + c.getUnit() : body;
    }

    /** 임의 소수 자릿수 고정 표시: HALF_UP, 천 단위 쉼표, 음수는 ASCII '-', 반올림 뒤 0 이면 부호 없는 0.00…(저장값은 이미 소수 2자리 이내라 반올림이 일어나지 않는다). */
    public static String fixed(BigDecimal v, int scale) {
        BigDecimal s = v.setScale(scale, RoundingMode.HALF_UP);
        if (s.signum() == 0) {
            return BigDecimal.ZERO.setScale(scale).toPlainString();
        }
        StringBuilder p = new StringBuilder("#,##0");
        if (scale > 0) {
            p.append('.');
            for (int i = 0; i < scale; i++) {
                p.append('0');
            }
        }
        DecimalFormat df = new DecimalFormat(p.toString(), DecimalFormatSymbols.getInstance(Locale.ROOT));
        df.setRoundingMode(RoundingMode.HALF_UP);
        String body = df.format(s.abs());
        return s.signum() < 0 ? "-" + body : body;
    }

            (com.fasterxml.jackson.databind.node.ObjectNode) om.readTree(BoardFormJson.toJson(d));
    com.fasterxml.jackson.databind.node.ObjectNode cell0 =       // A 표 r1 행의 첫 칸을 옛 모양(i:false)으로

## 5. 보안·위험·되돌리는 법
- 권한: 이 변경은 저장·초안 API의 권한 검사(403 경로)와 접근 이력 기록을 건드리지 않는다. 검증 순서는 그대로다 (한도→길이 400→PII 422→숫자 400→구조→재스캔 422).
- 인증은 여전히 `X-Emp-No` 자기신고다. 이 변경이 "검증된" 인증을 만들지 않는다.
- 입력: `_p` 키는 `cleanValues`의 허용 집합(괄호 칸의 둘째 key만)으로 거른다. 오류 메시지·`cells`에는 입력값이 없고, 키는 SAFE_ID와 PII 비검출을 통과한 것만 실린다.
- 위험:
  - ① 초안 docx의 `dec=2` 칸이 "500" → "500.00"이 된다. 사용자에게 보이는 표기 변경이다. 이관 메모의 디자인 확인이 필요하다.
  - ② 이미 저장된 A r1_c0 값(숫자)이 있으면 텍스트 칸으로 읽힌다. 개발 DB 정도라 무해하다.
  - ③ 지도가 바뀌어(A row 1) 기존 업로드 응답에서 r1_c0이 사라진다. 프런트가 입력 칸을 양식 구조에서 그리는지 확인해야 한다 (`adoptManual`이 `manual` 상태 칸을 기대하는 코드다).
  - ④ `applyUnit`의 `shownNum`은 `△`·괄호 음수를 받아 `-`로 바꾼다. % 칸에서 괄호만 있는 값은 음수 처리된다.
- 되돌리는 법: 패치 A~G를 되돌리면 된다 (DB 변경 없음). 이미 저장된 스냅샷에 `_p` 키가 생겼다면, 되돌린 서버는 그 키를 `withValues`에서 "값을 넣을 수 없는 칸"으로 거부해 재저장이 막힌다. 롤백이 필요하면 `_p`가 든 스냅샷이 없는지 먼저 확인한다 (개발 단계라 사실상 없음).

## 6. 프런트 계약 (frontend-dev용)

**양식 구조** — `GET /board-materials/{id}`의 `form.tables[].rows[][]` 칸에 필드가 추가된다 (기존 필드는 그대로, snake_case).

| 필드 | 형 | 의미 |
|---|---|---|
| `unit` | string | `""`/`"년"`/`"%"`. 값 뒤에 붙이는 표시 단위(저장에는 없음). |
| `paren` | boolean | 값 두 개 칸. |
| `sub_key` | string\|null | `paren`이면 `key + "_p"`, 아니면 null. |
| `dec` | int\|null | 2면 소수 둘째 자리 고정 + 천 단위 쉼표 표시. null이면 저장값 그대로. |

- B r1_c5·r2_c5: `paren:true, sub_key:"r1_c5_p"/"r2_c5_p", dec:2`.
- C-4 r1_c1: `unit:"년", dec:null`. C-4 r3_c1: `unit:"%", dec:null`.
- C-4 r2_c1: `unit:""`, `dec:null` (NPV).
- A·B·C-2·C-3·C-5의 나머지 연결 칸: `dec:2`.
- A r1_c0: `header:false, mapped:false, input:true, align:"center", text:""`. 직접 입력 칸으로 그린다.
- 양식 편집 화면의 `tablesView`도 같은 필드를 받는다.

**스냅샷·저장 본문** — 칸 값 형태는 이전과 같은 `{ref, cells:{key:"문자열"}}`이다.
- 연결 칸 값은 숫자 문자열만 담는다: `-?정수부 13자리 이내(쉼표 묶음 허용)`, 소수 ≤2자리. 단위·괄호·`△`·`%`는 불가. 서버 `NUM`과 같은 규칙이다 (`NUM_SERVER` 그대로).
- 괄호 칸은 같은 `cells`에 `sub_key`로 둘째 값을 보낸다. 예: `{"r1_c5":"5","r1_c5_p":"1"}`.
  - 앞 값 없이 `_p`만 보내면 400. `paren`이 아닌 칸에 `_p`를 보내도 400.
  - 값이 없으면 키를 빼거나 `""`로 보낸다 (서버가 빈 값은 버린다).
- 직접 입력 칸(A r1_c0 포함)은 텍스트다. 100자 이내이고 제어·서식 문자는 불가하다. 개인정보 모양이면 422 `PII_DETECTED` + `cells:[{ref,key}]`다.
- 옛 스냅샷은 `_p`가 없을 뿐이다. 그대로 열린다.
- 저장 응답/GET 후 값은 정규형이다 ("4.70"→"4.7"). **표시는 항상 `dec`·`unit`·`paren` 규칙으로 다시 그린다.** 저장 전후 글자가 같아진다.

**표시 규칙** (워드와 동일하게 구현. 화면에서 같은 함수를 써야 한다):
- 값이 `-?\d{1,13}(\.\d{1,2})?`(쉼표 허용)이면:
  - `dec=2`이면 소수 둘째 자리로 맞추고 천 단위 쉼표를 넣는다.
  - `unit`이 있으면 `dec`가 null인 칸에서 값 뒤에 붙인다.
- `paren`이면 `앞 (괄호안)`이고, 괄호 안이 비면 앞 값만 보인다.
- 숫자 모양이 아닌 값은 그대로 보인다 (단위도 붙이지 않는다).

**엑셀 업로드 응답** (`POST …/excel` 계열, 칸 `cells[]`):
- `paren` 칸: `value`는 표시 글자 `"5.00 (1.00)"` 그대로다. 저장값은 `main_value`("5.00")와 `sub_value`("1.00")다. 클라이언트는 칸 상태에 앞 값·둘째 값을 따로 두고 `main_value`→`key`, `sub_value`→`sub_key`로 보낸다. 쉼표가 들어와도 서버가 받는다.
- 단위 칸: `value`가 이미 숫자만이다 ("3.4", "0.74"). 원본 표시는 `source.display`·`parts`에 남는다 ("3.4년"). 단위 때문에 클라이언트가 문자열을 자를 필요는 없다.
- 새 경고 `warnings[].code == "CELL_UNIT_TEXT"`: 단위가 다르거나 숫자가 아님. `status`는 `review`이고 `value`는 원본 글자 그대로라서 저장 전 고쳐야 한다. `WARN` 문구표에 안내 문구를 더해야 한다.
- A r1_c0은 이제 응답 `cells`에 없다 (연결 칸이 아님). `adoptManual`류가 `status:'manual'`을 기대한다면 양식 구조의 입력 칸(`input && !mapped`)에서 만들어야 한다.

**`bw.numberProblems`** (:1626) 변경:
- 연결 칸 중 `paren`이면 앞 값과 둘째 값을 각각 `NUM_SERVER`로 검사한다.
- 문제 칸 위치는 `{t, key}`에 `sub_key`를 쓴다.
- 앞 값 없이 둘째 값만 있으면 둘째 값 칸이 문제다.
- `unit` 칸은 단위 없는 숫자만 통과한다. 사용자가 "3.4년"을 직접 쳤다면 접미사가 `unit`과 같을 때만 떼고, 아니면 문제로 둔다.
- 서버 400의 `cells[].key`가 `r1_c5_p`로 오면 같은 TD(`r1_c5`)로 포커스한다.

**사용자가 칸 글자를 직접 고칠 때의 해석 규칙** (엑셀 표시 글자를 붙여 넣는 경우도 같다):
1. 공백·NBSP·쉼표를 제거한다.
2. 끝이 그 칸의 `unit`이면 뗀다 (다른 단위는 그대로 둔다 → 문제 칸).
3. 음수: `-숫자`, `△숫자`/`▲숫자`, 또는 `(숫자)`.
4. `paren` 칸은 `^\s*(수)\s*\(\s*(수)\s*\)\s*$`이면 앞 값·둘째 값으로 나눈다. 둘째 값에도 3번이 적용된다. 수만 있으면 앞 값이고 둘째 값은 비운다.
5. 어느 규칙에도 안 맞으면 값은 그대로 두고 문제 칸이다 (서버가 400으로 막는다).
