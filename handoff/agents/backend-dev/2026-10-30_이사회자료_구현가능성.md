# 이사회 자료 엑셀→워드 매핑 — 구현 가능성 (backend-dev, 2026-10-30)

> 읽기 전용 검토. 코드를 짜지 않았고 서버·테스트는 실행하지 않았다. 실제 양식(.xlsx·.docx)이 없어 코드 읽기 기반 추정. POI 5.2.3(pom.xml). `docs/samples/`는 비어 있음.

## 1. docfill 현재 능력과 부족한 것
현재: 키워드 하나에 값 하나(라벨 옆 칸/문단 뒤 삽입, 병합·머리말·중첩 표 순회). 엑셀은 셀 주소 또는 머리글 조회로 값 하나. 컨트롤러·화면 없음.

| # | 부족 | 방향 |
|---|---|---|
| 1 | 범위 읽기 | `ExcelSource`에 시트·범위 → `String[][]`(+병합 정보) `rangeAt` |
| 2 | 표 통째 이식 | 새 `TableRule`(양식 표 시작 칸에 2차원 값). 표 찾기는 "제목 문단 다음 첫 표"가 단순 |
| 3 | 표 행 수 가변 | (a) 견본 행 1줄을 `CTTr.copy()`로 복제·남는 행 삭제(권장) (b) 고정 행 약속+불일치 오류. D 표는 가변 가능 → (a) |
| 4 | 값 구조화 | 문자열 → `(시트, 범위, 표시값, 원값)`. `FillReport.Entry`에 출처 추가 |
| 5 | 서식 변환 | 엑셀 표시값을 그대로 쓰면 불필요(`%`·`억`·`△`는 표시값 오독 위험만 테스트) |
| 6 | 문단 속 값(A·B) | 기존 `insertAfter`로 가능. SDT·텍스트 상자·필드 코드가 양식에 있으면 순회 못 함 → 양식 실측 선행 |

## 2. 계산값 읽기
- 수식은 **캐시된 결과 우선**(Excel이 저장한 값 = 사용자가 본 값). `DataFormatter`에 evaluator null이 가장 작은 변경. 캐시 없는 수식 셀은 재계산 폴백+경고. 업로드 화면에 "엑셀에서 저장한 파일" 안내.
- 워드에는 `DataFormatter` **표시값**(반올림 포함, `Locale.KOREA` 유지). 한글 날짜는 `ExcelDateFormat` 유지(되돌리지 말 것). 오류값(`#REF!`)은 문제로 처리.

## 3. 원본 미보관 상태의 출처 대조
서버가 만들어 둘 것: 매핑 결과(워드 위치→시트·범위·표시값·원값), 사용 범위 스냅샷(문자열·병합·정렬·굵게·배경색), 채워진 docx.

| 안 | 장점 | 단점 |
|---|---|---|
| 세션 메모리 | 단순, 저장소 정책 무관 | 재시작·다중 노드 불가, 결재 단계까지 못 감 |
| DB 스냅샷(JSON+docx BLOB, 원본 xlsx 미저장) | 결재 중 검토자가 출처 확인 | 테이블 신설(mysql/oracle 쌍), 보존·파기 정책 |
| **조합(권장)** | 미리보기는 메모리(TTL), 상신 때 DB 확정 | 구현량 증가 |

사용자별 구분·본인/결재선만 조회. 접근 이력에는 값 미기록.

## 4. 매핑 정의 위치
**A. 클래스패스 JSON(권장)** — `resources/docfill/board-form-v1.json`, 양식 버전 필드. B DB 테이블·C 양식 내 책갈피(SDT 미순회)·D 코드 상수는 비권장. JSON 항목: 매핑 ID(A/B/C-1~4/D), 엑셀 시트·범위, 워드 대상(제목 문단 키워드·표 선택), 행 수 처리, 표시 옵션.

## 5. 업로드 검증
`.xlsx`만(ZIP 시그니처+`[Content_Types].xml`), 크기 상한(5~10MB 제안), 매크로(`vbaProject.bin`) 거부, 외부 링크 거부/경고(정책 결정), `ZipSecureFile` 명시, 숨은 시트·행/열 경고. 양식 불일치는 400으로 어느 시트·라벨이 없는지만 알림(내부 경로·스택 금지). 워드 양식은 서버 고정본(업로드 안 받음). 메뉴 키 신설 시 `Menus.java`·`server/menus.py`·`menu_rules.js`·`nav.js` 동시 수정, 단 `Menus.MENUS` 8개 키·골든 04·05 되돌리지 말 것 항목과 충돌 → 키 추가 여부 합의 필요.

## 6. 테스트 전략
단위(`rangeAt`·`TableRule` 멱등·표시값 서식), 가상 데이터 골든 샘플(캐시 있는 수식은 Excel 저장 샘플 필요), MockMvc API(업로드 정상/거부 케이스/403/401), 회귀 전체 `mvn -o test`. 테스트 뒤 IntelliJ 서버 재시작.

## 7. 서버에서 .docx 생성·양식 확보 (후속 질의)
- 새 문서 생성·표·병합(gridSpan/vMerge)·서식 모두 XWPF로 가능하나 외관 재현이 어렵다 → 이번에는 **양식 채우기** 방식.
- 양식 확보: (a) 웹 편집기 → 템플릿 생성: 과함 (b) 업로드 등록: "나중에" (c) **`docs/samples/` 고정본: 권장**. 양식 로더를 인터페이스로 분리.
- D표 견본 행 복제는 가능. 자리표시 `{{D.rows}}`는 run이 쪼개질 수 있음 → 이어 붙여 검색·첫 run에 치환, 자리표시는 한 곳으로 한정, 메모장에서 붙여넣기. 대안은 첫 칸 키워드로 견본 행 찾기.
- 워드패드 산출물 읽힘은 실물 검증 전까지 불확실. 양식 사본은 POI 코드 생성으로 결정됨.
