# backend-dev 보고서 (자동 보존)

> SubagentStop 훅이 에이전트의 최종 메시지를 그대로 저장했다(2026-11-15 1930 KST, agentId a579c8a7cad78984e). 에이전트 출력이므로 사용자 결정이 아니다. 지시 내용·주제는 이 파일에 없다 — 필요하면 handoff/NEXT.md 항목이나 커밋 메시지로 찾는다.

---

## 1. 대상·방법·못 본 것
- 읽은 파일: `.claude/hooks/capture-questions.js` 전체, `agent-dashboard/test/capture-questions.test.js` 전체, `.claude/settings.json`의 UserPromptSubmit·Stop 부분.
- 못 본 것: 실제 transcript 파일 구조와 AskUserQuestion `tool_result`의 실제 문구. 기존 `isRealPrompt`와 기존 시험 구조를 근거로 짰다. 코드는 실행하지 못했다.

## 2. 설계 근거
- **대상 턴 판정**: `extractQuestions`는 실제 사용자 프롬프트를 만날 때마다 `prev = blocks; blocks = []`로 갈라 둔다(94~105줄).
  - UserPromptSubmit 시점에 새 prompt가 transcript에 아직 없으면 `blocks`가 방금 답하는 대상 턴이다.
  - 이미 들어와 있으면 `blocks`가 비어 있고 `prev`가 대상 턴이다.
  - 그래서 "`blocks`가 비었으면 `prev`, 아니면 `blocks`"로 정한다.
  - prompt 텍스트를 비교하지 않는다. 사용자가 "네"를 두 번 치면 텍스트 비교는 오판하지만, 이 방식은 안전하다.
- **라인 교체**: 장부는 항목 1줄 형식이다(`addToLedger`의 `]}` 앞 삽입 방식과 같은 전제). 한 줄이 `^\s*{...},?\s*$` 모양이고 status가 open인 줄만 `JSON.stringify`로 바꾼다. 줄 끝의 `\r`·콤마는 그대로 둔다.
  - 여러 줄로 펼쳐 쓴 항목은 매치되지 않아 갱신하지 않는다(안전 쪽 실패).
- **AskUserQuestion**: 같은 턴의 `tool_result`를 `tool_use_id`로 연결한다. 결과 문자열에서 `"질문"="답"` 짝을 먼저 찾고, 없으면 결과 전체를 쓴다. `is_error`이거나 "rejected"류 문구면 답으로 치지 않는다(거절은 open 유지).
  - 실제 결과 문구는 확인하지 못했다. 짝 정규식이 안 맞으면 전체 문자열로 떨어질 뿐 깨지지는 않는다.

```js
function fromAskDetailed(input, res) {
  const out = [];
  const qs = input && Array.isArray(input.questions) ? input.questions : [];
  for (const q of qs) {
    if (!q || typeof q.question !== 'string') continue;
    const opts = (Array.isArray(q.options) ? q.options : []).slice(0, 26).filter(o => o && typeof o.label === 'string');
    const joined = opts.map((o, k) => String.fromCharCode(0x24D0 + k) + o.label.trim()).join(' ');
    let answer = '';
    if (res && !res.err && res.text && !/rejected|doesn't want to proceed/i.test(res.text)) {
```

**(c) `extractQuestions`(94~112줄)를 아래로 교체** (`isRealPrompt`는 그대로)
```js
function resText(c) {
  if (typeof c === 'string') return c;
  return Array.isArray(c) ? c.map(x => (x && typeof x.text === 'string' ? x.text : '')).join(' ') : '';
}

// JSONL 줄들 → {prev, blocks, results}. results: tool_use_id → {text, err}
function scan(lines) {
  let blocks = [], prev = []; const results = {};
  for (const line of lines) {
    if (!line || !line.trim()) continue;
    let o; try { o = JSON.parse(line); } catch (_) { continue; }
    if (!o || o.isSidechain) continue;
    if (isRealPrompt(o)) { prev = blocks; blocks = []; continue; }
    if (o.type === 'user' && o.message && Array.isArray(o.message.content)) {
      for (const b of o.message.content)
        if (b && b.type === 'tool_result' && typeof b.tool_use_id === 'string') results[b.tool_use_id] = { text: resText(b.content), err: !!b.is_error };
      continue;
    }
    if (o.type !== 'assistant' || !o.message || !Array.isArray(o.message.content)) continue;
    for (const b of o.message.content) if (b) blocks.push(b);
  }
  return { prev, blocks, results };
}

function detail(blocks, results) {
  const out = [];
  for (const b of blocks) {
    if (b.type === 'text' && typeof b.text === 'string') for (const q of fromText(b.text)) out.push({ q, answer: '' });
    else if (b.type === 'tool_use' && b.name === 'AskUserQuestion') out.push(...fromAskDetailed(b.input, results[b.id]));
  }
  return out;
}

// Stop 수집용: 직전 턴 + 이번 턴(직전 턴도 보는 이유: Stop 시점에 마지막 답변이 아직 기록 파일에 없으면 다음 Stop에서 잡기 위해서다 — qa 11-15 P1)
function extractDetailed(lines) { const s = scan(lines); return detail(s.prev.concat(s.blocks), s.results); }
function extractQuestions(lines) { return extractDetailed(lines).map(x => x.q); }

// 답 기록용: 사용자가 방금 답하는 대상 턴만. 새 prompt가 이미 기록돼 있으면 blocks가 비어 prev가 대상 턴이다.
function extractTarget(lines) { const s = scan(lines); return detail(s.blocks.length ? s.blocks : s.prev, s.results).map(x => x.q); }
```

**(e) `addToLedger` 뒤에 `answerLedger` 추가**
```js
// 장부 원문 + 대상 질문 키 집합 + 사용자 답 → {text, changed} 또는 null.
// open이고 summary 키가 같은 한 줄 항목만 그 줄을 JSON.stringify로 교체한다. 다른 줄은 바이트 그대로.
function answerLedger(raw, keys, prompt, now) {
  if (typeof raw !== 'string' || raw.length > MAX_LEDGER) return null;
  let data; try { data = JSON.parse(raw.replace(/^﻿/, '')); } catch (_) { return null; }
  if (!data || !Array.isArray(data.questions)) return null;
  const ans = mask(String(prompt || '').replace(/\s+/g, ' ').trim()).slice(0, 300);
  if (!ans) return null;
  const today = ymd(now || new Date()), changed = [];
  const lines = raw.split('\n').map(line => {
    const m = /^(\s*)(\{.*\})(,?)(\s*)$/.exec(line);
    if (!m) return line;
    let q; try { q = JSON.parse(m[2]); } catch (_) { return line; }
    if (!q || q.status !== 'open' || !keys.has(normKey(q.summary))) return line;
    changed.push(q.id);
    return m[1] + JSON.stringify(Object.assign({}, q, { status: 'answered', answer: ans, answeredAt: today, answerSource: 'auto' })) + m[3] + m[4];
  });
  if (!changed.length) return null;
  const text = lines.join('\n');
  try {
    const chk = JSON.parse(text.replace(/^﻿/, ''));
    if (chk.questions.length !== data.questions.length) return null;
    if (chk.questions.filter(q => changed.includes(q.id) && q.status === 'answered').length !== changed.length) return null;
  } catch (_) { return null; }
  return { text, changed };
}
```

**(f) `writeLedger`(172~191줄)를 잠금 공통 함수로 교체**
```js
// fn(raw) → {text, count} | null. 잠금 → 읽기 → 변환 → 임시파일 rename. 못 쓰면 0.
function withLedger(ledger, fn) {
  const LOCK = ledger + '.lock', t0 = Date.now(); let locked = false;
  while (!locked) {
    try { fs.closeSync(fs.openSync(LOCK, 'wx')); locked = true; }
    catch (_) {
      try { if (Date.now() - fs.statSync(LOCK).mtimeMs > 3000) fs.unlinkSync(LOCK); } catch (__) {}
      if (Date.now() - t0 > 3000) return 0; // 못 잡으면 포기(장부를 덮어쓰지 않는다)
      sleep(15 + Math.random() * 25);
    }
  }
  try {
    let raw; try { raw = fs.readFileSync(ledger, 'utf8'); } catch (_) { return 0; }
    const r = fn(raw);
    if (!r) return 0;
    const tmp = ledger + '.' + process.pid + '.tmp';
    try { fs.writeFileSync(tmp, r.text); fs.renameSync(tmp, ledger); }
    catch (e) { try { fs.unlinkSync(tmp); } catch (_) {} return 0; } // 백신 등이 파일을 쥐면 임시 파일만 치우고 포기
    return r.count;
  } finally { try { fs.unlinkSync(LOCK); } catch (_) {} }
}

function writeLedger(ledger, qstrs, now) {
  return withLedger(ledger, raw => { const r = addToLedger(raw, qstrs, now); return r && { text: r.text, count: r.added.length }; });
}
```

## 5. 보안·위험·되돌리는 법
- **오기록**: 답이 질문과 무관해도(예: "계속해") 직전 턴의 open 질문이 모두 answered가 된다. 설계 확정 사항이다. 이후 정정은 메인이 손으로 한다. 질문에 ⓐ/ⓑ가 있으면 "ⓐ로"처럼 답이 남아 알아보기 쉽다.
- **개인정보·비밀값**: 사용자가 친 글이 git 추적 장부에 남는다. `mask()`를 적용하고 300자로 자른다. `mask()` 패턴 밖의 민감값(한글 서술형 비번 등)은 못 거른다. 비밀값을 채팅에 치지 않는 운영 규칙은 그대로다.
- **동시성**: Stop 훅과 같은 `.lock`·임시파일 rename을 쓴다. 단, 장부를 손으로 편집하는 중이면 마지막 저장이 이긴다(기존과 동일한 한계).
- **한 줄 항목 가정**: 여러 줄로 펼친 항목은 조용히 갱신되지 않는다. 오류는 전부 exit 0이다.
- **되돌리기**: settings.json에서 추가한 한 줄을 지우면 기능이 꺼진다. 자동 기록분은 `answerSource:"auto"`로 걸러 낼 수 있다.

## 6. 이관 메모
- [이관: 기획] 자동 answered와 메인의 "반영 후 done" 구분을 대시보드 패널에 표시할지 — 기다리는 것: 표시 규칙 — 근거: 신규 필드 `answerSource`.
- [이관: 프런트] `agent-dashboard` 쪽이 `answerSource`를 모르고 무시해도 문제없는지 확인 — 기다리는 것: 대시보드 표시 코드 확인 — 근거: 장부에 필드가 하나 늘어난다.
