## 요구/원인 요약
- 고정 경로는 `path.join(ROOT,'..','handoff','questions.json')`입니다. 요청 값으로 경로를 만들지 않습니다.
- 현재 `serve.js`는 `/api/state` POST와 `/api/version`, 허용 목록 정적 서빙만 있습니다(`serve.js:17,38,42-44`). `serve.py`도 같은 구조입니다(`send_head` 44행, `do_POST` 60행).
- `serve.js`는 메서드와 상관없이 정적 서빙으로 넘어가므로, `/api/questions`를 명시적으로 405로 거절하는 코드가 필요합니다.
- `/api/version`은 건드리지 않습니다. 화면 파일 4개의 mtime만 보기 때문에 요구 3번은 이미 충족됩니다.
- 응답은 200 + `{"questions":[...]}` 하나입니다. 파일이 없거나 JSON이 깨졌거나 256KB를 넘으면 200 + `{"questions":[],"error":"짧은 일반 문구"}`입니다. 오류 문구에 경로나 예외 메시지는 싣지 않습니다.
- 헤더는 `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`입니다. Host 검사는 기존 순서 그대로 가장 먼저 합니다.
- GET과 HEAD 외 메서드는 405 + `Allow: GET, HEAD`입니다.
- 형식 검증은 최소로 합니다. 최상위가 객체이고 `questions`가 배열인지만 보고, 항목 중 객체가 아닌 것은 걸러냅니다. 필드 해석은 화면(app.js) 몫입니다.

## 테스트
기존 시험은 임시 폴더에 파일을 복사해 서버를 띄웁니다. 이 폴더의 부모는 `os.tmpdir()`라서 `ROOT/../handoff/questions.json`이 공용 임시 폴더로 잡힙니다. 그래서 `tmp`에 쓰지 않고, 별도의 `base/agent-dashboard` + `base/handoff` 구조에 두 번째 서버를 띄웁니다. 기존 `before`와 `FILES`는 그대로 둡니다. 깨지는 기존 시험은 없습니다.

  const qreq = (method, p, headers = {}) => new Promise((resolve, reject) => {

      let b = ''; res.setEncoding('utf8'); res.on('data', d => b += d); res.on('end', () => resolve({ status: res.statusCode, headers: res.headers, body: b }));
    });

### README.md(agent-dashboard) 문안
> **사용자에게 물은 질문 패널.** 정본은 저장소 루트 `handoff/questions.json`(git 추적, 메인이 손으로 기록)이고, 서버는 `GET /api/questions`로 그 파일 하나만 읽어 `{"questions":[...]}`로 돌려줍니다(읽기 전용 — POST 등은 405, 256KB 초과·파일 없음·깨진 JSON은 200 + 빈 목록 + `error`).
> 화면은 이 주소를 폴링해 갱신하므로 파일을 고치면 새로고침 없이 반영됩니다(`/api/version`은 화면 코드 변경만 감지).
> 항목 형식: `id, summary, askedAt, next[], options, recommend, status(open|answered|done|hold), answer, answeredAt, appliedRef`.

## 보안·위험·되돌리는 법
- 경로는 상수로 고정되어 사용자 입력이 경로에 들어가지 않습니다. 정적 서빙 허용 목록(`ALLOW`)은 그대로라 `handoff/` 파일이 직접 노출되지 않습니다(위 마지막 시험으로 확인).
- 이 API는 `questions.json` 내용을 그대로 노출합니다. 서버가 127.0.0.1에만 바인딩되고 Host 검사로 DNS 리바인딩을 막지만, 질문·답변에 비밀값이나 개인정보를 적으면 안 됩니다. 기록하는 쪽(메인·pm)이 지킬 사항입니다.
- 자기신고 인증 같은 권한 모델은 없는 로컬 도구이며, 읽기 전용이라 쓰기 경로가 늘지 않습니다.
- `/api/version`과 기존 `/api/state`·정적 서빙은 건드리지 않습니다.
- 되돌리기는 위 삽입 블록을 지우면 되고, DB·데이터 변경은 없습니다.
- 위험은 `questions.json`이 편집 중에 깨진 상태로 읽히는 경우입니다. 이때는 그 폴링 한 번만 `error` + 빈 목록이 오므로, 화면은 이전 목록을 유지하고 오류만 표시하는 편이 좋습니다.

## 이관 메모
- [이관: 프런트] 패널은 `error`가 있으면 목록을 비우지 말고 직전 성공본을 유지하며 작은 오류 표시만 합니다. 폴링 주기는 `/state.json` 폴링과 맞춥니다. 대기 중: 패널 구현(app.js·style.css, `FILES`와 `/api/version` 대상에는 이미 포함). 근거: 편집 중 깨진 JSON 응답.
- [이관: 기획] `status` 4값(open|answered|done|hold)의 표시 용어와 정렬 우선순위는 기획이 정할 일입니다. 서버는 `status` 값을 검증하지 않고 그대로 통과시킵니다.
