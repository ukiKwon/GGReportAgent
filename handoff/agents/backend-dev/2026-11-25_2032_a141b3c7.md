## 2. 요구/원인 요약 (근거)
- **MEMO가 덮이는 위험**: `BidTargetIn.java:6`은 "고치기는 전체 값을 다시 보낸다"는 계약입니다. `BidTargetRules.common` 89줄은 `p.memo = text(in.getMemo())`이고, `BidTargetService.save` 360줄은 `row.setMemo(p.memo)`, `TargetChangeService.write` 358줄은 `row.setMemo(p.memo)`입니다. 따라서 화면이 memo를 빼고 보내면 **새 REV에서 MEMO가 NULL로 덮입니다.** 패치에서 "보내지 않은 칸(null)은 지금 값 유지, 빈 문자열은 지움"으로 바꿉니다.
- **결재 판정 위치**: 단건은 `BidTargetRules.valueOnlyEdit` 118~123줄을 쓰고 `BidTargetService.save` 346~348줄에서 판정합니다. 일괄은 `TargetChangeService.planItem` 180~181줄에서 같은 판정을 따로 하고, `ApprovalRequestService` 252줄은 `direct || plan.isValueOnly()`면 바로 반영합니다. 순위 판정을 `valueOnlyEdit` 하나에 넣고 일괄도 이 함수를 부르게 합쳤습니다.
- **결재 중 잠금**: 단건은 `requireNoPending` 341줄, 일괄은 `planItem` 157줄 `countPendingByInst`입니다. 순위 쓰기도 그대로 409 CHANGE_PENDING으로 막힙니다.
- **감사 기록**: 행마다 수정자·이름·자기신고 여부·화면·버튼·UI_VALID·시각을 남깁니다(`write()` 488~496줄). 버튼 허용 목록은 `TargetUiIds` 17·21줄입니다.
- **코드 값**: `BANK_RANK`(039 76~79줄, 041 12줄)는 FIRST·SECOND·SINGLE을 쓰고, 여기에 NONE·JOINT가 더 있습니다. NONE·JOINT는 노리는 순위가 아니므로 **새 코드 그룹을 만들되 같은 코드 글자를 씁니다.** 나중에 실제 약정 순위와 견주기 위해서입니다.

## 3. 구현안

### 3-0. 결정 요약
**① '최초 등록'의 정의 — 둘 다 결재 없이**
- **(가) 목표 넣기와 함께**: ADD 항목에 `aim_rank_cd`를 싣습니다.
  - 영업부장은 바로 반영됩니다.
  - 팀원·팀장은 이미 결재 대상인 **목표 넣기 결재에 같이 실려** 승인 때 반영됩니다. 순위 때문에 결재가 따로 생기지 않습니다.
  - 값은 결재 항목 행 `INST_BID_TARGET_REQ_ITEM.AIM_RANK_CD`에 저장됩니다.
- **(나) 목표가 된 뒤 처음 채우기**: 비어 있던 순위에 값을 넣는 경우, 올해 이후 목표이면 영업 계열 누구나 바로 반영됩니다(direct_basis VALUE_EDIT).
- 지난해 목표는 구분 고치기와 같이 결재입니다(기존 security F1과 같은 규칙).

**② 이후 변경 — ⓐ/ⓑ가 갈리는 곳은 한 곳뿐**
- 갈리는 곳은 `BidTargetRules.valueOnlyEdit(..., aimApproval)`의 마지막 조건입니다.
  - **ⓑ (true, 기본값)**: 값→다른 값, 값→지움 모두 결재입니다. 단건은 403 APPROVAL_REQUIRED가 되어 일괄(changes)로 결재를 올립니다.
  - **ⓐ (false)**: 바로 반영되고, 이력은 행의 REV로 남습니다.
- 영업부장이거나 결재 스위치가 꺼져 있으면 어느 쪽이든 바로 반영됩니다(지금 규칙과 같음).

**③ 저장 구조와 API**
- **칸**: `INST_BID_TARGET.AIM_RANK_CD`, `INST_BID_TARGET_REQ_ITEM.AIM_RANK_CD`(둘 다 VARCHAR 20, NULL = 아직 안 정함).
- **코드 그룹** `TARGET_AIM_RANK`:

  | 코드 | 이름 |
  |---|---|
  | FIRST | 1금고 |
  | SECOND | 2금고 |
  | SINGLE | 단수금고 |
  | MAIN_BANK | 주거래은행 |

- **API는 새로 만들지 않고 기존 두 엔드포인트를 확장합니다**: `POST /institutions/{id}/bid-targets`(본문 `aim_rank_cd`)와 `POST /bid-targets/changes`(items[].`aim_rank_cd`). 같은 잠금·STALE·결재 중 잠금·REV 이력을 그대로 탑니다.
- **새 버튼 id** `set_target_aim_rank`: 단건(EDIT)과 일괄(CHANGE) 허용 목록에 둘 다 넣습니다.
- **조회 응답에 더하는 것**:
  - 줄마다 `aim_rank_cd`·`aim_rank_name`, 목표 줄에는 `aim_mode`(DIRECT|APPROVAL|null)
  - 전체에 `aim_change_mode`, `codes.aim_ranks`
  - 결재 카드에 before/after의 `aim_rank_cd`·`aim_rank_name`
- **권한**: 지금의 쓰기 자격(기관 수정 권한 AND 영업 계열) 그대로입니다. 관심 기록은 주인만 고칩니다. 관심 기록에 순위를 보내면 400입니다(목표에서 옮겨 온 값은 그대로 둠).
- **접근 이력**: 값은 넣지 않고 종류만 남깁니다. 단건은 ` aim=first|change|clear`, 일괄 바로 반영은 ` aim=n`(건수).

**④ MEMO 처리**
- 칸은 지우지 않습니다.
- `memo`·`aim_rank_cd`가 null(키 없음)이면 지금 값을 이어 씁니다(`keepUnsent`). `""`이면 지웁니다.
- 넣기(ADD)는 memo를 계속 받지만, 화면이 보내지 않으면 NULL입니다.

**⑤ 그 밖**
- 자동 이월은 순위를 이어받고, ♥ 다시 켜기는 순위를 비웁니다.

## 5. 보안·위험·되돌리는 법
- **403 경로**: 순위 바꾸기(ⓑ) 거절은 기존 `requireDirect` → 403 `APPROVAL_REQUIRED` → 컨트롤러 `deniedIfRole`이 ACCESS_LOG DENIED로 남깁니다(고정 문구, 본문 없음). 쓰기 자격(`requireEditor`)과 관심 주인 검사는 순서까지 그대로입니다.
- **접근 이력**: 순위 값, 메모, 사번은 넣지 않습니다. 종류(`aim=first|change|clear`)와 건수(`aim=n`)만 남기고, `aimTag`가 서버 상수 셋만 통과시킵니다.
- **감사 기록**: 결재 끝난 목표의 순위 변경도 행 REV로 수정자·이름·자기신고 여부·화면·버튼(`set_target_aim_rank` 허용 목록)·시각이 남습니다. 결재로 반영되면 APPROVAL_REQ_ID와 REQ_ACT(상신·승인 행위)도 남습니다.
- **자기신고의 한계**: 이 모든 판정은 `X-Emp-No` 자기신고 사번 위의 업무 규칙입니다. 앞단 인증이 붙기 전에는 사칭을 막지 못합니다.
- **위험 1 — 화면 계약 변경**: memo 의미가 "빼면 지움"에서 "빼면 그대로"로 바뀝니다. 옛 화면이 메모를 지우려고 memo 키를 빼고 보냈다면 이제 안 지워집니다. `""`를 보내야 지워집니다. 프런트 확인이 필요합니다.
- **위험 2 — ⓑ에서 결재 중 잠금이 넓다**: 순위 변경 결재가 올라가 있는 동안 그 기관의 구분 고치기까지 409로 막힙니다(기관 단위 잠금, 기존 설계).
- **위험 3 — tag_cd가 여전히 필수**: 순위만 저장하려 해도 tag_cd를 함께 보내야 합니다(없으면 400).
- **되돌리기**: 설정 `ggreport.bid-target.aim-change.approval=false`로 ⓐ 전환은 재기동만으로 됩니다. 기능 전체를 되돌리려면 코드를 먼저 되돌린 뒤 063 헤더의 DROP/DELETE를 실행합니다. 값이 든 행이 있으면 먼저 개수를 확인하고, 코드만 끄려면 ENABLED=0을 씁니다.
- **새 설정 키**: 기본값이 코드에 있어 키가 없어도 기동합니다. `config-envs/out-local`에 넣을지는 선택입니다.
