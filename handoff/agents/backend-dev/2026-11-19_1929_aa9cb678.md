## 2. 요구·원인 요약 (근거)
- **번호:** `db/*/05*`에 `051_design_review.sql`만 있고 `055`는 없습니다. 052는 NEXT.md에서 "main 052 박디자이너"로 아직 파일이 없습니다. 053·054는 저장소에서 못 찾았습니다.
- **코드표:** `HEAD_FIELD`는 `026_inst_head.sql`의 mysql 141~148행, oracle 155~162행(NAME…CAREER, SORT 1~8)입니다.
  - 서버는 `HEAD_FIELD`를 읽지 않습니다. 읽는 코드표는 `countEnabledCode("HEAD_SRC", …)` 하나뿐입니다. 그래서 055 행은 표시·문서용이고, 055를 안 돌려도 서버는 동작합니다.
  - 새 표와 컬럼은 필요 없습니다. `INST_HEAD_ITEM.VAL_DATE`(VARCHAR(10))에 그대로 저장됩니다.
- **허용 칸:** `InstitutionHeadService.java` 44~47행의 `SINGLE`·`DATES`입니다. 날짜 칸 검증은 `fillValue`의 else 분기(368~370행, `HeadText.requireDate`)입니다.
  - `keyOf`(198행)와 `valueOf`(209행)도 `DATES`를 보므로 `DATES`에 넣으면 충돌 비교와 값 변환이 자동으로 따라옵니다.
  - 등록 A4는 `HeadIn.Head`에 날짜 3종만 있어 BIRTH_DATE는 칸 입력 API로만 들어갑니다. 이 구조는 건드리지 않습니다.
- **목록 A1:** `list()`(384~426행)는 `selectCurrentConfirmedSingleItems`의 IN절(xml 264행, 6칸 고정)만 읽고 응답 키도 고정입니다. IN절을 안 바꾸면 BIRTH_DATE는 자동으로 빠집니다.
- **발견한 구멍 1(대기열 A2):** `queue()`(447행)도 같은 쿼리로 "확정값"을 모아 충돌을 셉니다.
  - IN절에 BIRTH_DATE가 없으면 대기열은 충돌 0으로 보고, 상세는 충돌로 봅니다. 두 화면이 어긋납니다.
  - 해결: 대기열 전용 쿼리를 추가합니다(아래 패치). A1용 쿼리는 그대로 둡니다. 대기열 응답은 칸 코드만 싣고 값은 싣지 않으므로 `field_cds`에 "BIRTH_DATE"가 나올 수 있습니다.
- **발견한 구멍 2(빈 머리·문서 판정):**
  - `countShownItems`(xml 156행), `selectEmptyCurrentHeadIds`(xml 293행), 상세 `shownCount`(service 567행), `HeadDocBuilder.hasContent`(45~53행)가 모두 `<> 'ACTING'`만 제외합니다.
  - 이대로면 생년월일만 남은 머리가 "빈 머리가 아님"이 되고, Word는 빈 본문으로 내려갑니다.
  - `HeadPhotoService.java:269`도 `countShownItems`를 씁니다. 같은 SQL이라 같이 바뀌며 의미는 일관됩니다(생년월일만 남았으면 사진 무효 때 옛 사진을 되살리지 않음).
- **Word:** `FIELD_ORDER`·`FIELD_LABEL`은 6칸 고정이고, `personal()`과 `sources()`는 이 칸들만 꺼냅니다. `detail.head.fields`에 BIRTH_DATE가 있어도 본문에 안 나옵니다. 코드를 안 고치면 되고, 시험으로 고정합니다.
- **PII 충돌:**
  - 날짜 값은 `rejectAny(text=null, 출처 제목)`에 들어갑니다(null 처리는 기존 날짜 칸이 이미 하고 있어 문제 없음). 값 자체는 `Pii` 검사를 거치지 않지만 `YYYY-MM-DD` 정규식을 통과해야만 저장됩니다.
  - 충돌 지점은 출처 제목입니다. 입력 중 제목에 "900101-1234567" 같은 주민번호 모양이 있으면 기존 코드로 400이 됩니다. 새 충돌은 없습니다.
  - 접근 이력(`ACCESS_LOG.DETAIL`)은 `inst-head inst=… code=…` 형식이라 값이 없습니다. `INST_HEAD_LOG`도 id·코드만 쓰니 값은 안 남습니다. 시험으로 확인합니다.

## 5. 보안·위험·되돌리는 법
- **권한(403 경로):** BIRTH_DATE는 기존 칸 입력·확정·무효·상세 열람과 같은 권한 경로를 지나므로 새 권한 규칙이 없습니다. 상세는 `run(...,"VIEW", true)`로 응답 전에 감사 기록과 접근 이력(기관·코드만)이 남습니다.
- **자기신고 한계:** 사번·화면·버튼은 `X-Emp-No` 자기신고입니다. 감사 `*_VERIFIED=0`이면 "검증됨"으로 표시하지 않는 규칙은 그대로입니다. 생년월일은 개인정보이므로, 열람 기록이 사칭을 막아 주는 것은 아니라는 점을 화면·문서에 가리지 마세요.
- **구멍 1(대기열 충돌 불일치):** 위 쿼리 추가로 막았습니다. 이 쿼리가 없으면 대기열이 충돌을 놓칩니다. 시험 "후보 경로"가 잡습니다.
- **구멍 2(빈 머리·docx 빈 문서):** mapper 2곳, service 1곳, `hasContent` 1곳으로 막았습니다. 화면 `headcard.js:100`은 서버와 기준이 달라지면 "빈 머리"가 서로 다르게 보이므로 프런트가 같이 고쳐야 합니다.
- **수집 반입 경로(위험):** Python/수집기가 `INST_HEAD_ITEM`에 후보를 직접 넣을 때 FIELD_CD를 서버가 걸러 주지 않습니다(`insertCandidateItem`이 시험에서 쓰는 방식). 수집기가 BIRTH_DATE 후보를 내려보내면 범위 검증을 건너뜁니다. 데이터·수집 쪽 계약에서 이 칸을 금지해야 합니다(이관 메모).
- **잔여 PII 위험:**
  - 출처 제목(`SRC_TITLE`)·URL에 사용자가 생년월일을 써 넣을 수 있습니다. 기존 `rejectAny`가 주민번호 모양만 잡고 `1970-05-17` 같은 날짜는 안 잡습니다.
  - 출처 제목과 Word 출처 절에는 다른 칸처럼 그대로 나갈 수 있으므로, 보안 쪽에서 이 구멍을 허용할지 판단해 주세요.
- **되돌리는 법:**
  1. 위 diff 되돌리기. 서버는 코드 행이 없어도 동작합니다.
  2. `DELETE FROM COMMON_CODE WHERE CODE_GROUP='HEAD_FIELD' AND CODE='BIRTH_DATE';`
  3. 이미 쌓인 BIRTH_DATE 값은 "행을 지우지 않는다" 규칙상 상세에서 무효 처리하거나 DBA가 `STATE_CD='VOIDED'`로 정리하세요. 코드를 되돌려 `SINGLE`에서 빠지면 그 행은 화면에서는 안 보이지만 DB에 남습니다.
- **적용 순서:** DB 055는 선택이고 서버 코드와 순서 의존이 없습니다. 이미 051·052까지 적용한 DB는 055 한 파일만 이어서 돌리면 됩니다. Oracle은 정본 작성까지만이고 적용은 DBA 몫입니다.

### 선택 ⑥ (본 패치 밖): POSITION 칸에 연령·날짜 우회 입력 금지
- **패턴과 위치:**
  - `HeadText`에 `Pattern.compile("(?:19|20)\\d{2}\\s*년\\s*생|\\d{4}\\s*[-./]\\s*\\d{1,2}\\s*[-./]\\s*\\d{1,2}")`를 둡니다.
  - 직위를 받는 두 곳(`addHead`의 `position`, `addItem`의 POSITION)에서만 `matcher.find()`가 참이면 기존 `coded(400,"INVALID_TEXT",…)`로 막습니다.
  - 새 오류 종류는 만들지 않습니다.
- **오탐 시험:** `구청장`, `제1대 구청장`, `2기 구청장`은 통과, `1970년생 구청장`, `구청장 1970-05-17`은 400.
- **권고:** 직위 문구에 숫자가 정상적으로 섞이는 경우가 있어 효과가 작고 오탐 가능성이 있습니다. 필요하면 security가 결정해 주세요.

## 6. 이관 메모
- **[이관: 프런트]** `frontend/js/headcard.js`가 쓸 응답 키는 `detail.head.birth_date`(문자열 `YYYY-MM-DD` 또는 null)이고, 출처는 `detail.head.fields.BIRTH_DATE.source`입니다. 후보는 기존 `candidates[].field_cd=="BIRTH_DATE"`로 오며 `value`는 문자열입니다.
  - 저장은 기존 칸 입력과 같은 `POST /institutions/{id}/head/items`에 `{head_id, field_cd:"BIRTH_DATE", date, source}`로 보냅니다. 오류 코드는 `INVALID_DATE`(400)이고 서버가 범위 밖 400을 돌려줍니다.
  - 만 나이(`만 N세`)와 입력 범위 안내문은 화면에서 계산합니다. 서버는 나이를 내려 주지 않습니다.
  - 빈 머리 판정(`headcard.js:100` `hc.isEmptyHead`)에서 `BIRTH_DATE`도 `ACTING`처럼 제외해야 서버의 `head_empty`와 같아집니다.
  - 대기열 `field_cds`에 `"BIRTH_DATE"`가 나올 수 있으니 칸 이름 표에 항목이 필요합니다. 라벨은 "생년월일"이고 생략하면 코드명이 그대로 보입니다.
- **[이관: 데이터]** 수집 반입이 `INST_HEAD_ITEM`에 FIELD_CD=`BIRTH_DATE` 후보를 만들지 않도록 계약(`collector/SCHEMA.md` 등)을 정리하세요. 서버는 반입 행의 칸 코드나 범위를 검증하지 않습니다.
- **[이관: 기획]** 생년월일만 남은 머리를 "현 기관장 없음"으로 보는 규칙(구멍 2)은 security가 요청한 것을 구현한 것입니다. 정책 용어로 확정해 주세요. 생년월일을 가진 확정 값이 지워진 뒤 무효 처리한 머리에서 값이 계속 DB에 남는 점의 보존 규칙(NEXT 35 미정)도 함께 정해야 합니다.
