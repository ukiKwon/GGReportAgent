## (C) '제출' 동작 — 현재 상태
- 이미 있는 것: `POST /institutions/{id}/complete`(`InstitutionController.java:230`, `InstitutionCommandService.complete:160-175`). 9단계(`STAGE_READY_TO_SUBMIT`)에서만(아니면 409), 아카이브 후 **최신 공고(BID_CASE) 참여 상태를 `제출완료`로** 바꿈(`BidCaseMapper.updateParticipationStatus`). 응답 `CompleteResponse(dest, userId)`. `WorkflowOverviewService.java:26,36` 이 `최신 공고 = 제출완료`를 done으로 읽어 진행 현황에 반영 — 즉 사용자 결정 ③의 "제출 → 제안서 진행 현황 반영"은 **이 경로가 사실상 이미 구현**돼 있다. STAGE는 올리지 않는다(주석 `:26`).
- 주의: 이 엔드포인트는 `X-User-Id` 헤더만 받고 **역할 검사가 없다**(`InstitutionController:231-232`)·가결 검사도 없다. FinishHandler(`FinishHandler.java:21-23`)는 "제출 대기(9단계)" 알림만 남김. TaskController submit(`TaskController.java:175`, `TaskCommandService:62`)은 팀 작업 결재 상신(1차완료)이며 사내 '제출'과 다른 말 — 용어 혼동 주의(화면 라벨 정리는 기획/디자인 몫).
- 새 칸이 필요한가: 상태 값은 기존 `제출완료`로 충분(추측). 다만 **누가·언제 제출했는지** 기록과 "이미 제출함" 멱등 처리를 위해 별도 칸(예: BID_CASES.SUBMITTED_AT/SUBMITTED_BY)을 019+에서 추가하는 방안이 있음. INSTITUTIONS.STAGE는 쓰지 않는 게 맞다(주석상 complete는 STAGE 불변; 9→완료로 올리면 오케스트레이터와 충돌).
- 가결 전 서버 거절 설계
  1. 이사회 자료 건 테이블(NEXT 57·59, 설계 전)에 `기관+회차(BID_CASE)별 최근 상태`에 `가결/부결/…` 값을 둔다.
  2. `InstitutionCommandService.complete()`에서 최신 BID_CASE의 최근 이사회 상태가 `가결`이 아니면 **409(또는 403) + "이사회 가결 전에는 제출할 수 없습니다"** (내부 정보 없는 메시지). 예외 해제(우회 파라미터·관리자 해제) 없음 — 요청에 override 필드를 두지 않는다.
  3. 이사회 건이 없는 기존 공고는? 정책 질문(아래 이관)이다. 기본은 "건이 없으면 불가"(사용자 결정에 맞춤)지만 기존 테스트(complete 시나리오 `GoldenWriteScenarioTest` 등)가 깨지므로 테스트 픽스처에 가결 건을 심어야 함.
- 의존 순서: ① 이사회 자료 건 테이블·상태 DDL·API(NEXT 57·59) → ② complete 가결 검사 + 역할 검사 → ③ (선택) 제출자·시각 칸 → ④ 화면 제출 버튼 활성/비활성 안내. ①이 없으면 ②는 불가하므로 **②를 먼저 넣으려면 임시로 "항상 거절"이 되어 현행 제출이 막힘** — 순서를 지킬 것.
- DDL 번호: 018까지 적용, 019는 MENU_ORDER 후보. 이사회 건 테이블은 019가 이미 후보로 잡혀 있으면 **020**, 제출자·시각 칸은 별도 번호(예: 021) 또는 이사회 건 테이블과 같은 번호로 묶기 — mysql·oracle 쌍, 이미 적용된 DB는 ALTER/CREATE만 이어 붙임(번호는 NEXT 확정 후). 재무팀 역할 식별자 변경은 DDL 없이 표시만 바꾸면 불필요.

- 제출: 영업 계열(`영업팀`·`영업팀장`·`영업부장`·`디자이너`는 영업 소속) 중 **누가** 제출 가능한지 확정 필요(담당자? 팀장? 부장?). 서버는 `X-Emp-No` 자기신고(`Actor`) 기반 role로 `Teams.teamOf(role)=="영업"` 검사 → 아니면 403, 접근 이력에는 본문·개인정보 없이 role만. 자기신고라서 "검증됨" 표현은 쓰지 않는다.
