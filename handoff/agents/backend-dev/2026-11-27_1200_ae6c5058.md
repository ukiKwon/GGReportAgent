## 2. 원인 요약
- `StaticCacheFilter.java:109-111`에서 `png`·`jpg`·`jpeg`·`gif`·`svg`·`ico`와 `woff`·`woff2`·`ttf`가 같은 `SHORT`(`private, max-age=300`)를 받는다(`:30`).
- `fonts`는 이미 `STATIC_DIRS`(`:119`)에 들어 있어 경로 판정은 문제없다. 정책 분기만 나누면 된다.
- `index.html:17-25`의 글꼴 URL은 `fonts/KBFGText-Light.woff2`처럼 버전 쿼리가 없다. 파일 이름은 같고 내용만 바뀔 수 있다는 뜻이다.
- 파일은 `frontend/fonts/`에 `KBFGText-Light`, `KBFGText-Medium`, `KBFGText-Bold`, `KBFGDisplay-Bold` 4개(woff2)다.

## 3. 구현안

### `StaticCacheFilter.java`
**old (30행)**
```java
    static final String SHORT = "private, max-age=300";
```
**new**
```java
    static final String SHORT = "private, max-age=300";
    /** 글꼴: 30일. immutable 은 쓰지 않는다 — 글꼴 URL 에 버전이 없어 파일을 바꿔도 이미 받은 브라우저가 못 알아챈다. */
    static final String FONT = "private, max-age=2592000";
```

**old (109-111행)**
```java
            case "png": case "jpg": case "jpeg": case "gif": case "svg": case "ico":
            case "woff": case "woff2": case "ttf":
                return SHORT;
```
**new**
```java
            case "png": case "jpg": case "jpeg": case "gif": case "svg": case "ico":
                return SHORT;
            case "woff": case "woff2": case "ttf":
                return FONT;
```

**old (클래스 주석 20행)**: `이미지·폰트는 5분.`
**new**: `이미지는 5분, 폰트(woff·woff2·ttf)는 30일.`

- 디렉터리가 아니라 확장자로 나눴다. 정적 폴더 밖에서 `isStaticPath`가 이미 걸러내므로 API 응답에는 붙지 않는다.
- `private`는 유지했다. 공유 프록시에는 올리지 않는다는 기존 방침과 같다.

### immutable 판단: 쓰지 않는다
- immutable은 URL이 바뀌어야만 새 내용이 나가는 파일에 맞는다. 지금 URL에는 버전이 없다.
- immutable을 쓰면 새로고침(F5)에서도 재검증하지 않는다. 글꼴을 잘못 올렸을 때 사용자가 직접 비우지 않는 한 되돌릴 수 없다.
- 30일 max-age만 둬도 재방문 때 woff2 4개(7.3MB)를 다시 받는 문제는 해결된다.

### 운영 배포 영향·캐시 무효화
- 글꼴 파일을 교체해도 이미 받은 브라우저는 최대 30일간 옛 파일을 쓴다.
- **권장 절차: 교체할 때 `index.html` @font-face의 URL에 `?v=YYYYMMDD`를 붙이거나 파일 이름을 바꾼다.** 예: `url("fonts/KBFGText-Light.woff2?v=20261201")`.
  - `index.html`은 `no-cache`(재검증)라 다음 접속에 바로 새 URL을 읽는다.
  - 쿼리는 `getRequestURI`에 없으므로 정책 판정에는 영향이 없다.
  - 접근 이력에도 쿼리값은 들어가지 않는다.
- 이 절차를 `kgi-ggreport-web/README.md`나 배포 안내에 한 줄 적어야 한다. 프런트 소관이므로 이관한다.
- 이번 변경으로 글꼴이 바뀌는 것은 아니다. 현재 파일에는 `?v=`를 붙일 필요가 없다.

## 4. 테스트
**깨질 기존 테스트**: 없다. `StaticCacheApiTest`는 `/img/a.png`만 `max-age=300`으로 검사한다. `LegacyFlowGuardApiTest:86-101`은 `policyFor` null과 `isStaticPath`만 본다.

**추가할 테스트**: `StaticCacheApiTest`의 `이미지_폰트는_짧은_캐시`를 아래처럼 나누고, 단위 검사를 더한다. 파일이 없어도 404에 헤더가 붙는 기존 방식이다.
```java
    @Test
    public void 이미지는_짧은_캐시() throws Exception {
        mockMvc.perform(get("/img/a.png")).andExpect(header().string("Cache-Control", "private, max-age=300"));
    }

    @Test
    public void 글꼴은_30일_캐시_immutable_없음() throws Exception {
        for (String p : new String[]{"/fonts/KBFGText-Light.woff2", "/fonts/a.woff", "/fonts/a.ttf"}) {
            mockMvc.perform(get(p)).andExpect(header().string("Cache-Control", "private, max-age=2592000"));
        }
        mockMvc.perform(get("/fonts/KBFGText-Light.woff2"))
                .andExpect(header().string("Cache-Control", not(containsString("immutable"))));
    }

    @Test
    public void 글꼴_판정_단위() {
        assertEquals("private, max-age=2592000", StaticCacheFilter.policyFor("/app/fonts/X.WOFF2;jsessionid=1", "/app"));
        assertEquals("private, max-age=2592000", StaticCacheFilter.policyFor("/fonts/x.woff2", ""));
        assertEquals("no-cache", StaticCacheFilter.policyFor("/js/a.js", ""));          // 그대로
        assertEquals("no-cache", StaticCacheFilter.policyFor("/css/x.css", ""));
        assertNull(StaticCacheFilter.policyFor("/tasks/1/files/a.woff2", ""));          // API 경로 제외
    }
```

**실행(호출자)**: `cd kgi-ggreport-web && mvn -q -o test -Dtest=StaticCacheApiTest,LegacyFlowGuardApiTest`. 통과하면 `mvn -q -o test` 전체를 돌린다(380건 이상). 8080 서버가 같은 `target/`을 쓰면 테스트 뒤 재기동한다.

적용 뒤 확인용:
```
curl -I http://localhost:8080/fonts/KBFGText-Light.woff2
```
`Cache-Control: private, max-age=2592000`이 보여야 한다. 읽기 전용 호출이다.

## 5. 보안·위험·되돌리는 법
- 권한·인증 경로는 건드리지 않는다. 글꼴은 공개 정적 자원이고 접근 이력 대상도 아니다.
- 위험은 하나다. 글꼴을 같은 이름으로 교체하면 최대 30일간 옛 글꼴이 보인다. 위의 `?v=` 절차로 막는다.
- 앞단 프록시나 WebLogic이 `Cache-Control`을 덮어쓰면 효과가 없다. 운영에서 `curl -I`로 확인해야 한다.
- 되돌리기: `FONT` 상수와 `case` 분기를 원래대로 합치면 된다. 이미 받은 브라우저의 캐시는 만료까지 남는다. 그래서 30일이 부담스러우면 7일(`604800`)로 시작하는 선택도 있다.
