## 2. 요구·원인 요약 (근거)
- **번호:** `db/*/05*`에는 `051_design_review.sql`만 있습니다. 055는 비어 있습니다. 052는 NEXT.md에서 "main 052 박디자이너"로 아직 파일이 없습니다. 053·054는 저장소에서 못 찾았습니다.
- **코드표:** `HEAD_FIELD`는 026의 mysql 141~148행, oracle 155~162행(SORT 1~8)입니다.
  - 서버는 `HEAD_FIELD`를 읽지 않고 `HEAD_SRC`만 읽습니다. 055는 표시·문서용이고, 안 돌려도 서버는 동작합니다.
  - 새 표와 컬럼은 필요 없습니다. 값은 `INST_HEAD_ITEM.VAL_DATE`(VARCHAR(10))에 저장합니다.
- **허용 칸:** `InstitutionHeadService.java` 44~47행의 `SINGLE`·`DATES`입니다.
  - 날짜 검증은 `fillValue`의 else 분기(368~370행)입니다. `keyOf`(198행)와 `valueOf`(209행)가 `DATES`를 보므로, `DATES`에 넣으면 충돌 비교와 값 변환이 자동으로 따라옵니다.
  - 등록 A4는 `HeadIn.Head`에 날짜 3종만 있어 BIRTH_DATE는 칸 입력 API로만 들어갑니다.
- **목록 A1:** `list()`(384~426행)는 xml 264행의 IN절(6칸 고정)과 고정 응답 키만 씁니다. IN절을 그대로 두면 BIRTH_DATE가 자동으로 빠집니다.
- **구멍 1(대기열 A2):** `queue()`(447행)도 같은 쿼리로 확정값을 모아 충돌을 셉니다. IN절에 BIRTH_DATE가 없으면 대기열은 충돌 0으로 보고 상세는 충돌로 봅니다. 대기열 전용 쿼리를 추가해 해결합니다.
- **구멍 2(빈 머리·문서 판정):** 아래 네 곳이 모두 `<> 'ACTING'`만 제외합니다.
  - xml 156행 `countShownItems`
  - xml 293행 `selectEmptyCurrentHeadIds`
  - service 567행 `shownCount`
  - `HeadDocBuilder.hasContent`(45~53행)

  이대로면 생년월일만 남은 머리가 "빈 머리 아님"이 되고 Word가 빈 본문으로 내려갑니다. `HeadPhotoService.java:269`도 `countShownItems`를 쓰므로 같이 바뀌는데, 의미는 일관됩니다.
- **Word:** `FIELD_ORDER`·`FIELD_LABEL`은 6칸 고정이고 `personal()`·`sources()`가 그 칸만 꺼냅니다. `fields`에 BIRTH_DATE가 있어도 본문에는 안 나오며, 시험으로 고정합니다.
- **PII 충돌:**
  - 날짜 값은 `rejectAny(text=null, 출처 제목)`을 지납니다(null은 기존 날짜 칸이 이미 그렇게 처리). 값은 `YYYY-MM-DD` 정규식을 통과해야만 저장됩니다.
  - 출처 제목에 주민번호 모양이 있으면 기존대로 400입니다. 새 충돌은 없습니다.
  - 접근 이력(`ACCESS_LOG.DETAIL`)은 `inst-head inst=… code=…` 형식이고 `INST_HEAD_LOG`는 id·코드만 써서 값이 안 남습니다. 시험으로 확인합니다.

## 5. 보안·위험·되돌리는 법
- **권한(403 경로):**
  - BIRTH_DATE는 기존 칸 입력·확정·무효·열람과 같은 권한 경로를 지나므로 새 권한 규칙이 없습니다.
  - 상세는 `run(...,"VIEW", true)`로 응답 전에 감사 기록이 남고, 접근 이력은 기관·코드만 남습니다.
  - 값은 감사·이력에 안 들어갑니다.
- **자기신고 한계:** 사번·화면·버튼은 `X-Emp-No` 자기신고라 열람 기록이 사칭을 막지는 못합니다. `*_VERIFIED=0`이면 "검증됨"으로 표시하지 않는 기존 규칙을 유지하세요.
- **수집 반입 경로(위험):** 수집기가 `INST_HEAD_ITEM`에 직접 넣는 후보는 서버 검증을 건너뜁니다. BIRTH_DATE 후보가 반입되면 범위 검증을 못 거칩니다. 수집 계약에서 금지해야 합니다.
- **출처 제목 우회(잔여 위험):** `SRC_TITLE`에 생년월일을 `1970-05-17`처럼 써 넣는 것을 기존 `rejectAny`는 주민번호 모양만 잡아 막지 못합니다. Word 출처 절에는 BIRTH_DATE 줄이 없으나 허용 여부는 security가 판단해 주세요.
- **되돌리는 법:**
  1. 위 diff를 되돌립니다. 서버는 코드 행이 없어도 동작합니다.
  2. `DELETE FROM COMMON_CODE WHERE CODE_GROUP='HEAD_FIELD' AND CODE='BIRTH_DATE';`
  3. 이미 쌓인 값은 "행을 지우지 않는다" 규칙상 무효 처리하거나 DBA가 VOIDED로 정리합니다.
- **적용 순서:** DB 055는 서버와 순서 의존이 없습니다. 이미 051·052까지 적용한 DB는 055만 이어서 돌립니다. Oracle은 정본 작성까지만이고 적용은 DBA 몫입니다.
- **선택 ⑥ (본 패치 밖): POSITION 칸에 연령·날짜 우회 입력 금지.**
  - `HeadText`에 `Pattern.compile("(?:19|20)\\d{2}\\s*년\\s*생|\\d{4}\\s*[-./]\\s*\\d{1,2}\\s*[-./]\\s*\\d{1,2}")`를 두고, `addHead`의 `position`과 `addItem`의 POSITION에서만 `find()`가 참이면 기존 `INVALID_TEXT` 400을 냅니다.
  - 오탐 시험: `구청장`, `제1대 구청장`, `2기 구청장`은 통과, `1970년생 구청장`, `구청장 1970-05-17`은 400.
  - 효과가 작고 오탐 가능성이 있으니 넣을지는 security가 결정해 주세요.

## 6. 이관 메모
- **[이관: 프런트]** `frontend/js/headcard.js`가 쓸 응답 키.
  - 값: `detail.head.birth_date`(`YYYY-MM-DD` 또는 null).
  - 출처: `detail.head.fields.BIRTH_DATE.source`.
  - 후보: `candidates[].field_cd=="BIRTH_DATE"`, `value`는 문자열.
  - 저장: 기존 `POST /institutions/{id}/head/items`에 `{head_id, field_cd:"BIRTH_DATE", date, source}`. 오류는 400 `INVALID_DATE`.
  - 만 나이와 입력 범위 안내문은 화면에서 계산합니다. 서버는 나이를 내려 주지 않습니다.
  - `headcard.js:100`의 `hc.isEmptyHead`에서 BIRTH_DATE도 ACTING처럼 제외해야 서버의 `head_empty`와 같아집니다.
  - 대기열 `field_cds`에 `"BIRTH_DATE"`가 나올 수 있어 칸 이름 표에 "생년월일"이 필요합니다.
- **[이관: 데이터]** 수집 반입이 FIELD_CD=`BIRTH_DATE` 후보를 만들지 않도록 계약(`collector/SCHEMA.md` 등)에 못박아 주세요. 서버는 반입 행의 칸 코드·범위를 검증하지 않습니다.
- **[이관: 기획]**
  - 생년월일만 남은 머리를 "현 기관장 없음"으로 보는 규칙은 security 요청을 구현한 것이니 용어를 확정해 주세요.
  - 무효 처리한 머리에 남는 값의 보존 규칙은 NEXT 35(미정)와 함께 정해야 합니다.
