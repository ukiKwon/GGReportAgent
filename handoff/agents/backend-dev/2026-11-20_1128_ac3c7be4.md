### 3-2. 기관명 사전과 매칭 규칙
`NAME_KO`와 `REGION_CODE`에서 변형을 만듭니다. 시도 코드 표는 11 서울, 26 부산, 27 대구, 28 인천, 29 광주, 30 대전, 31 울산, 36 세종, 41 경기, 42/51 강원, 43 충북, 44 충남, 45/52 전북, 46 전남, 47 경북, 48 경남, 50 제주입니다 (짧은 이름과 정식 이름 쌍). **이 코드 값은 데이터가 확인해야 합니다 (7번 이관).**

1. `body` = NAME_KO에서 앞의 시도 접두(짧은·정식)를 뗀 값. `core` = body에서 `구청|시청|군청`이면 끝의 `청`을 뗀 값.
2. 변형 (공백 제거 후 비교)
   - 시도 접두형은 항상 넣습니다: `{짧은,정식}+core`, `{짧은,정식}+core+청`
   - 맨몸형 `core`, `core+청`은 **`len≥3`이고 표 전체에서 core가 유일할 때만** 넣습니다.
   - 그래서 `서구`·`중구`·`동구`·`남구`·`북구`·`강서구` 같은 맨몸 두 글자와 동명 구 맨몸은 다른 기관으로 잡지 않습니다. `서구 문화`, `중구난방`, `성동구` 안의 `동구`, `강남구` 안의 `남구`가 걸리지 않게 합니다.
   - 두 글자 지역명(`서울`·`경기`)은 사전에 넣지 않습니다.
3. 현재 기관 행(`TaskContext.institutionId`)의 모든 변형은 **맨몸 두 글자 포함** `current=true`로 넣습니다. 매칭되면 소비만 하고 보고하지 않습니다.

7. 알려진 빈틈 (보고서·화면 문구에 밝힐 것)
   - 시도 없이 `서구청`처럼 쓴 동명 구 맨몸은 잡지 못합니다.

        //         END_ELEMENT 'p','br' 에 '|' 삽입. 누적이 TEXT_CAP 넘으면 PARTIAL/TEXT_CAP. 빈 결과면 NOT_CHECKED/NO_TEXT.
        //         이름에 'ppt/media/' 있으면 hasImages. 순서 파싱 실패하면 파일번호 + orderApprox=true.
    }
    private static Extracted pdf(byte[] d) {
        if (!startsWith(d, PDF)) return none("FORMAT_MISMATCH");
        // PrepAttachInspector.pdfTask 와 같은 모양 — PDDocument.load(.., setupTempFileOnly()), Future.get(20s) 시간 초과는 취소 후 TIMEOUT.
        // isEncrypted → ENCRYPTED, pages>500 → 앞 500쪽만 PARTIAL/TOO_MANY_PAGES,
        // PrepAttachInspector.rejectPdfActive 가 ApiException 을 던지면 ACTIVE_CONTENT (텍스트 추출하지 않음).

## 5. 보안·위험·되돌리는 법
- 인증은 `X-Emp-No` 자기신고입니다. ack의 `acked_by`는 **사칭 방지가 아닙니다.** 이 업무 규칙 위의 기록이며 `EMP_VERIFIED=0`이 정상값입니다. 화면·보고서에 '검증됨'이라고 쓰지 않습니다.
- 접근 이력과 감사에는 파일 이름·글·문맥을 넣지 않습니다. 403은 `MenuGuard.denied`가 DENIED로 남깁니다. 읽기 API는 현재 파일 목록과 같은 권한(로그 없음)입니다.
- 새 업로드 파싱(zip bomb·PDF 능동 요소·시간): ZipGuard·엔트리 수·크기·원소 수 상한, PDF는 임시파일 모드·20초·500쪽·능동 요소 시 파싱 생략, XML DTD·외부 엔티티 끔. 풀 2개 데몬 스레드이므로 **동시 업로드가 많으면 PDF 검사가 줄을 섭니다** (사용자 요청이 20초까지 걸릴 수 있음).
- 동기 검사 때문에 업로드 응답이 느려질 수 있습니다. 파일은 이미 메모리(`getBytes`)에 있어서 메모리는 늘지 않지만 ZipGuard가 XML 부분을 메모리에 보관합니다 (최대 200MB 상한, 사전준비 쪽과 같은 상한).
- 같은 파일을 동시에 같은 이름으로 올리면 파일(마지막이 이김)과 DOC_CHECK 행이 어긋날 수 있습니다. 요약이 size·mtime 대조로 `STALE`로 보여 줘서 깨끗하다고 오해하지 않습니다.
- 검사 실패를 삼키는 설계라, 표가 없을 때 운영에서 조용히 ERROR가 쌓입니다. WARN 로그(예외 종류만)로 찾습니다. 배포는 DB 먼저입니다.
- ack는 재표시 시 이전 표시자를 덮어씁니다 (이력 한 줄 유지). 모든 이력이 필요하면 `ACK_SEQ`를 더하는 추가 설계가 필요합니다.
- 알려진 오탐·미탐은 3-2의 7번을 화면 문구에 밝혀야 합니다. 특히 시도 없는 동명 구 맨몸은 못 잡고, 이미지 속 글자는 못 봅니다.
- 되돌리기: 코드는 `TaskFileService`의 두 호출과 컨트롤러 엔드포인트 4개를 지우면 이전 동작입니다. DB는 `DROP TABLE DOC_CHECK_ACK; DROP TABLE DOC_CHECK_HIT; DROP TABLE DOC_CHECK;` (데이터 소멸). Python `server/`는 건드리지 않습니다.

### security가 볼 점
