## 2. 응답 필드 계약(프런트용)
- 목록 `GET /preps` 행에 다음이 추가됩니다.
  - `can_view`(boolean): false 면 상세가 404 입니다.
  - `bid_expected_date`(string|null): 기관의 입찰예상일(`INSTITUTIONS.CONTRACT_END` 원문)이고, 없으면 null 입니다.
- 상세 `GET /bidcases/{id}/prep`
  - `open_request`: `{req_id, status, requester:{emp_no,name}, requested_at, nominees:[{emp_no,name,position}], comment|null}`. 건이 없으면 null 입니다.
  - `plan_request`: `{req_id, status, requester, requested_at}`. 없으면 null 입니다.
  - `tasks[].done_rule`(string|null): 사용자 문구 그대로입니다.
  - `state_name`: IN_PROGRESS 는 "사전준비 중"입니다. 목록도 같습니다.
  - `viewer.can_withdraw_open`: 대기 중 신청의 신청자일 때만 true 입니다. 부장·지명자는 false 입니다.
  - OPEN_PENDING 신청자는 읽기 전용이라 `can_upload`, `can_check` 등은 false 입니다.
- 결재함 `GET /approval-requests` 의 BID_OPEN 항목에 `nominees:[{emp_no,name,position}]` 이 추가됩니다. 의견은 기존 `payload.comment` 에 있습니다. 결재함에 PREP_APPROVAL 지명 줄은 필요 없어서(지명자 없음) 추가하지 않았습니다.
- 바뀐 문구
  - 꺼진 이유(`disabled_reason`): "이 과제는 아직 직접 체크할 수 없습니다. 선행 확인이 끝난 뒤 다시 시도하세요."
  - `institution_id` 400: "기관을 선택하세요."
  - `BAD_VALUE`: "첨부할 과제를 고르세요(수익성 분석표 또는 RFP 붙임서류)."
  - 무효 처리 403: "첨부를 올린 담당자 또는 영업팀장만 무효 처리할 수 있습니다."

## 4. 지시에서 벗어난 판단
- 필드 이름은 제가 정했습니다. 입찰 예정일은 `bid_expected_date`, 지명자 직위는 `position`(기존 `people[]` 은 `position_title`) 입니다. 프런트가 다른 이름을 원하면 알려 주세요.
- 문구 두 개를 바꿨습니다. 지시에 없던 "기관을 선택하세요." 와 무효 처리 403 문구입니다. 둘 다 기존 테스트에는 문구 단언이 없습니다.
- `setTask` 의 409 `TASK_NOT_AVAILABLE` 문구("…전제 미충족")는 이번에 건드리지 않았습니다.

## 5. 위험
- **영업팀장이 첨부를 볼 수 없는 문제**: 비담당 영업팀장은 무효 처리 API 를 부를 수 있지만, 첨부 목록·내려받기는 담당자와 부장에게만 열려 있어(404) 화면에서 버튼에 닿을 길이 없습니다. 팀장이 담당자로 지명된 건에서만 쓸 수 있습니다. 목록 열람을 팀장까지 넓힐지는 기획 결정이라 그대로 뒀습니다.
- 영업팀 전원이 확정됨 건의 상세와 이력(확정자, 사유, 사번 자기신고 표시)을 봅니다. 사용자 결정이라 적용했고, security 가 확인할 항목입니다.
- OPEN_PENDING 건에서 영업팀장은 신청자가 아니면 여전히 404 입니다. 결재자인 팀장이 건 상세를 못 보고 결재함 카드만 봅니다. 의도된 동작인지 기획 확인이 필요합니다.
- `list` 가 행마다 `canSee` 를 호출해 `isActiveAssignee`·`countEverAssigned` 쿼리가 행 수만큼 늘어납니다. 건수가 많지 않으면 문제없습니다.

## 6. 이관 메모
- [이관: 프런트] 위 응답 필드 계약대로 `can_view`, `done_rule`, `nominees` 를 쓰면 됩니다. `done_rule` 이 오므로 T3·T5 하드코딩은 제거할 수 있습니다.
- [이관: 기획] 영업팀장(비담당)에게 첨부 목록 열람을 열지, 결재자 팀장에게 OPEN_PENDING 상세를 열지 정해야 합니다.
- [이관: 기획] 디자인이 올린 기획승인 요청 뒤 '완료 취소' 허용 여부는 이번 범위가 아니라 미적용입니다.
- 무효 처리한 파일은 50개·300MB 한도에 포함됩니다(`PrepAttachService.requireRoom`, 기존 동작). `ATTACH_LIMIT` 안내 문구에 반영하면 됩니다.
