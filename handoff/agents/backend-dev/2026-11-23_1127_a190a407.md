**맨 앞 요약**
- 결재 요청 때 결재자에게 가는 쪽지를 만드는 곳은 두 계열이다. 신규 결재 요청 계열은 `ApprovalRequestService.notifyStep`(호출 줄 :152·:181·:214·:238·:269·:405·:479 — 한 함수로 모임)이고, 옛 작업 결재 계열은 종류 `결재요청` 쪽지를 5곳에서 만든다.
- 권장안은 설정 키 `ggreport.notify.approval-request.enabled`를 두고 기본값 `false`로 하는 것이다. 결재자 알림만 꺼지고, 요청자에게 가는 `결재결과`와 감사 기록은 그대로다. 키를 `true`로 바꾸면 이전 동작으로 돌아간다.
- 못 본 것: 옛 작업 결재 계열을 프런트가 어떻게 쓰는지, 머리 띠 숫자가 옛 계열 제출 건도 세는지는 모른다(frontend-dev 확인). `:152·:181·:214·:238·:269` 각각이 어떤 상황의 호출인지는 줄 번호만 보고 읽지 않았다. 조사만 했고 파일은 고치지 않았다. mvn은 main 세션이 실행한다.

**2. 사용자 결정의 범위 (권장)**
- 결재자에게 가는 `결재알림`(신규)과 `결재요청`(옛)만 끄고, 요청자에게 가는 `결재결과`는 유지한다. 요청자는 결재함 숫자에 안 잡히고 반려 사유가 `결재결과` 본문으로만 전해지며, 사용자가 든 이유(같은 일을 두 번 알림)는 결재자 쪽에만 해당한다.
- 감사 기록은 쪽지와 별개다. `ApprovalRequestService.auditPrep`(:834)과 `DesignReviewService`의 `audit.record`는 쪽지 생성과 따로 호출된다. 결재함 목록은 결재 요청·단계 테이블에서 만들어지므로 쪽지가 없어도 숫자는 정확하다.
- 옛 계열 `결재요청`을 같이 끌지는 사용자 확인이 필요하다. 옛 계열 제출 건이 머리 띠 숫자에 잡히면 끄는 것이 결정에 맞다. 안 잡히면 끌 경우 영업팀장·부장이 제출 사실을 알 길이 없다.

**4. 서버 시험 영향**
- 신규 계열을 끄면 `ApprovalLineApiTest`에서 `결재알림` 1건 이상을 단언하는 곳이 깨진다: :272, :504~522, :557~559. 0건 단언(:265, :509~510, :522, :529, :557, :630)과 `결재결과` 단언(:535~572), `BoardMaterialApiTest:1472~1479`는 통과한다.
- 옛 계열까지 끄면 `DesignReviewApiTest:231·:529`(`KIND='결재요청'` 1건)와 `GoldenWriteScenarioTest:108~142`(제출 뒤 첫 쪽지 종류가 `결재요청`)가 깨진다. 골든 쪽 시험이라 처리 방침을 먼저 정해야 한다.
- 영향 없음: `OrchestratorCoreTest:104`(`recorder.notify` 직접 호출), `NotificationWriteApiTest:47`(사람이 `결재요청`을 위조하는 시도를 막는지 보는 시험이라 `kind` 검증 불변).
- 테스트 `application.properties`에 키를 `true`로 두면 기존 단언이 그대로 통과한다. 새 동작은 별도 시험으로 보증하는 것이 낫다.
- 추가할 시험: 키 `false`에서 상신하면 결재자 `결재알림`이 0건이고 같은 요청이 `inbox`에는 나타난다. 승인·반려하면 요청자 `결재결과`가 1건 간다.
- 실행 명령: `cd kgi-ggreport-web && mvn -q -o test`. 좁게 돌리려면 `-Dtest=ApprovalLineApiTest+DesignReviewApiTest+GoldenWriteScenarioTest`. 8080 서버가 같은 `target/`을 쓰면 테스트 뒤 재기동한다.

**5. 보안·위험·되돌리는 법**
- 권한 검사(403)는 건드리지 않는다. 결재 가능 여부는 `eligibility`와 `Ranks`가 정하고, 이 변경은 쪽지를 안 만들 뿐이다. 접근 이력에 새로 쓰는 값은 없다. 인증은 `X-Emp-No` 자기신고라는 한계가 그대로다.
- 위험은 머리 띠 숫자가 `inbox` 건수와 다르면 결재 요청을 놓친다는 점이다. 이미 만든 `결재알림` 쪽지는 쪽지함에 남는다(정리는 이번 제안에 없음).
- 되돌리기는 설정 키를 `true`로 바꾸는 것이다.
