**4번의 칸 규칙**
- 칸 키가 `[A-Za-z0-9_]{1,40}`이 아니거나 `scanLoose`에 걸리면 `cells` 목록에는 넣지 않고 `count`에만 센다. 클라이언트가 보낸 임의 문자열이 응답에 그대로 되돌아가지 않게 하려는 것이다.
- 숫자 오류의 칸은 양식에 있는 칸 키만 나온다.
- `withValues`가 내는 BAD_VALUE("모르는 표·값 칸이 아닌 키")는 위치 정보가 없다. `cells`가 없고 메시지도 그대로다.

⚠️ **security 하-2 코드에서 고친 점**: 제안은 `'.'`을 전부 `'-'`로 바꾼 뒤 `scan`을 부른다. 그러면 `user@example.com`이 `user@example-com`이 되어 **이메일 검출이 사라진다**. 그래서 두 번 훑는다.
- 숫자류(주민·휴대폰·외국인·카드)는 `.`·`·`도 `-`로 바꾼 변형으로 찾는다.
- 이메일은 `.`을 그대로 둔 변형으로 찾는다.
- 이렇게 하면 한 값이 두 번 세어지지 않는다.

보고서에 없던 것 두 가지를 더했다.
- 서식 문자(ZWSP·소프트 하이픈 등 FORMAT)를 제거한다. 칸 값에는 메모와 달리 서식 문자 거부가 없어서, 숫자 사이에 끼우면 우회된다.
- U+2212(−)와 U+30FB를 구분자 취급한다.

알려진 오탐은 `900101.1234567`처럼 6자리.7자리 모양의 소수다. 숫자 칸은 소수 2자리까지이므로 정상 금액에서는 나오지 않는다.

    public static List<Finding> scanLoose(String text) {
        List<Finding> out = new ArrayList<Finding>();
        if (text == null || text.isEmpty()) {
            return out;
        }
        for (Finding f : scan(fold(text, true))) {
            if (!EMAIL_KIND.equals(f.getKind())) {
                out.add(f);
            }
        }
        for (Finding f : scan(fold(text, false))) {
            if (EMAIL_KIND.equals(f.getKind())) {
                out.add(f);
            }
        }
        return out;
    }

    private static String fold(String text, boolean dotAsDash) {
        String s = java.text.Normalizer.normalize(text, java.text.Normalizer.Form.NFKC);
        StringBuilder b = new StringBuilder(s.length());
        for (int i = 0; i < s.length(); ) {
            int cp = s.codePointAt(i);
            i += Character.charCount(cp);
            int ty = Character.getType(cp);
            if (ty == Character.FORMAT) {
                continue;
            }
            if (ty == Character.DECIMAL_DIGIT_NUMBER) {
                b.append((char) ('0' + Character.digit(cp, 10)));
            } else if (ty == Character.DASH_PUNCTUATION || cp == 0x2212
                    || (dotAsDash && (cp == '.' || cp == 0x00B7 || cp == 0x30FB || cp == 0x2027))) {
                b.append('-');
            } else {
                b.appendCodePoint(cp);
            }
        }
        return b.toString();
    }

     * NFKC·비ASCII 숫자·대시류·서식 문자 우회까지) → 숫자 칸 검증(연결 칸: {@link #canonNumber}, 400) → 양식 구조 대조(BoardDocSpec.withValues:
     * 값 칸이 아닌 키·모르는 표는 거부, 제어문자·trim·100자) → 값이 있는 칸만 추출 → <b>저장할 최종값으로 개인정보 한 번 더</b>(쉼표 제거로 생기는
     * 주민번호 모양, security 하-1). 400/422 는 문제 칸 위치(ref·key, 값 없음, 최대 {@value #MAX_MARKS}개)와 총수를 detail 에 싣는다.
     * 칸 값은 다른 담당자·결재자 화면에 그려지므로 화면은 esc 만 써야 한다.
     */
    private Map<String, Map<String, String>> checkedValues(String empNo, BoardMaterial m, List<BoardWriteIn.TableIn> tables) {
        if (tables == null || tables.size() > MAX_TABLES) {
            throw coded(400, "BAD_REQUEST", "표 목록(tables)이 올바르지 않습니다.");
        }
        Map<String, Map<String, String>> raw = new LinkedHashMap<>();
        Marks tooLong = new Marks();
        for (BoardWriteIn.TableIn t : tables) {
            if (t == null || t.getRef() == null || raw.containsKey(t.getRef())
                    || (t.getCells() != null && t.getCells().size() > MAX_CELLS)) {
                throw coded(400, "BAD_REQUEST", "표 목록(tables)이 올바르지 않습니다.");
            }
            Map<String, String> cells = t.getCells() == null ? new LinkedHashMap<String, String>() : t.getCells();
            for (Map.Entry<String, String> e : cells.entrySet()) {
                if (e.getValue() != null && e.getValue().length() > BoardDocSpec.MAX_CELL) {
                    tooLong.add(t.getRef(), e.getKey());
                }
            }
            raw.put(t.getRef(), new LinkedHashMap<>(cells));
        }
        if (tooLong.total > 0) {
            throw badCells("칸 값은 " + BoardDocSpec.MAX_CELL + "자 이하로 입력해 주세요.", tooLong);
        }
        Map<String, Integer> kinds = new LinkedHashMap<>();
        Marks pii = new Marks();
        scanPii(raw, kinds, pii);
        if (!kinds.isEmpty()) {
            throw piiDetected(kinds, pii);
        }
        BoardDocSpec.Doc base = forms.docForStored(empNo, m.getFormId(), m.getFormVer());
        Marks badNum = new Marks();
        for (BoardDocSpec.Table t : base.getTables()) {    // 연결(숫자) 칸은 숫자 검증·정규화 — 틀린 칸을 전부 모아 알린다
            Map<String, String> cells = raw.get(t.getId());
            if (cells == null) {
                continue;
            }
            for (List<BoardDocSpec.Cell> row : t.getRows()) {
                for (BoardDocSpec.Cell c : row) {
                    String v = c.isMapped() ? cells.get(c.getKey()) : null;
                    if (v != null && !v.trim().isEmpty()) {
                        if (isNumber(v)) {
                            cells.put(c.getKey(), canonNumber(v));
                        } else {
                            badNum.add(t.getId(), c.getKey());
                        }
                    }
                }
            }
        }
        if (badNum.total > 0) {
            throw badCells(NUM_MSG, badNum);
        }
        BoardDocSpec.Doc filled;
        try {
            filled = BoardDocSpec.withValues(base, raw);
        } catch (BoardDocSpec.EditException e) {
            throw coded(400, "BAD_VALUE", e.getMessage());
        }
        Map<String, Map<String, String>> out = new LinkedHashMap<>();
        for (BoardDocSpec.Table t : filled.getTables()) {
            for (List<BoardDocSpec.Cell> row : t.getRows()) {
                for (BoardDocSpec.Cell c : row) {
                    if ((c.isMapped() || c.isInput()) && c.getText() != null && !c.getText().isEmpty()) {
                        Map<String, String> cells = out.get(t.getId());
                        if (cells == null) {
                            cells = new LinkedHashMap<>();
                            out.put(t.getId(), cells);
                        }
                        cells.put(c.getKey(), c.getText());
                    }
                }
            }
        }
        Map<String, Integer> kinds2 = new LinkedHashMap<>();   // 숫자 정규화(쉼표 제거)·trim 뒤 저장값으로 재검사 — security 하-1
        Marks pii2 = new Marks();
        scanPii(out, kinds2, pii2);
        if (!kinds2.isEmpty()) {
            throw piiDetected(kinds2, pii2);
        }
        return out;
    }

    /** 칸 값 전체를 {@link Pii#scanLoose} 로 훑어 종류별 건수와 검출된 칸 위치를 모은다(값은 모으지 않는다). */
    private static void scanPii(Map<String, Map<String, String>> byRef, Map<String, Integer> kinds, Marks marks) {
        for (Map.Entry<String, Map<String, String>> t : byRef.entrySet()) {
            for (Map.Entry<String, String> c : t.getValue().entrySet()) {
                List<Pii.Finding> found = Pii.scanLoose(c.getValue());
                if (found.isEmpty()) {
                    continue;
                }
                marks.add(t.getKey(), c.getKey());
                for (Pii.Finding f : found) {
                    Integer n = kinds.get(f.getKind());
                    kinds.put(f.getKind(), n == null ? 1 : n + 1);
                }
            }
        }
    }

    private static ApiException piiDetected(Map<String, Integer> kinds, Marks marks) {
        Map<String, Object> d = new LinkedHashMap<>();
        d.put("code", "PII_DETECTED");
        d.put("message", "개인정보로 보이는 값이 있어 저장하지 않았습니다. 해당 칸을 지우고 다시 저장해 주세요.");
        List<Map<String, Object>> ks = new ArrayList<>();
        for (Map.Entry<String, Integer> e : kinds.entrySet()) {
            Map<String, Object> k = new LinkedHashMap<>();
            k.put("kind", e.getKey());
            k.put("count", e.getValue());
            ks.add(k);
        }
        d.put("kinds", ks);          // 종류·건수만 — 검출된 값은 싣지 않는다
        d.put("count", marks.total); // 검출된 칸 수(cells 는 알려진 칸만, 최대 MAX_MARKS)
        d.put("cells", marks.cells);
        return ApiException.withDetail(422, d);
    }

    private static ApiException badCells(String message, Marks marks) {
        Map<String, Object> d = new LinkedHashMap<>();
        d.put("code", "BAD_VALUE");
        d.put("message", message);
        d.put("count", marks.total);
        d.put("cells", marks.cells);
        return ApiException.withDetail(400, d);
    }

    /** 문제 칸 위치 모음 — 총수는 세고, 목록은 안전한 식별자(SAFE_ID, 개인정보 모양 아님)만 최대 MAX_MARKS 개. */
    private static final class Marks {
        final List<Map<String, Object>> cells = new ArrayList<>();
        int total;

        void add(String ref, String key) {
            total++;
            if (cells.size() < MAX_MARKS && safe(ref) && safe(key)) {
                Map<String, Object> c = new LinkedHashMap<>();
                c.put("ref", ref);
                c.put("key", key);
                cells.add(c);
            }
        }

        private static boolean safe(String s) {
            return s != null && SAFE_ID.matcher(s).matches() && Pii.scanLoose(s).isEmpty();
        }
    }

    private static boolean isNumber(String raw) {
        return NUM.matcher(raw.trim()).matches();
    }

    /** 숫자 칸 정규화: 앞뒤 공백 제거 → 천 단위 쉼표 허용(올바른 묶음만) → 정수부 13자리·소수 2자리 → 쉼표 없는 표준형. 아니면 400(입력값 비노출). */
    static String canonNumber(String raw) {
        String v = raw.trim();
        if (!NUM.matcher(v).matches()) {
            throw coded(400, "BAD_VALUE", NUM_MSG);
        }
        BigDecimal d = new BigDecimal(v.replace(",", ""));
        if (d.signum() == 0) {
            return "0";
        }
        return d.stripTrailingZeros().toPlainString();
    }

## 5. 응답 계약 변경 (프런트에 넘길 것)
1. **`form` 키 신설**: `GET /board-materials/{id}`(담당자·영업부장), `POST /board-materials` 201 응답, `GET /board-materials/{id}/snapshots/{n}`에 들어간다. `GET /board-materials/{id}/snapshots` 목록과 `/history` 응답에는 없다. 모양은 `{form_id, name, version(기본 양식은 null), catalog_ver, tables:[{id, ref, mapping, title, columns, row_ids, col_ids, rows:[[{key,row_id,col_id,text,colspan,rowspan,header,mapped,input,align,editable}]], notes, unit}]}`이다.
   - 값은 없다(mapped 칸의 `text`는 빈 문자열). 값은 `snapshot.tables[].cells`에서 `ref`+`key`로 찾는다.
   - **`editable`은 항상 false다. 입력 가능 여부는 `viewer.can_write`와 칸의 `mapped`·`input`으로 판단한다.**
   - `/board-forms`·`/board-docs`의 권한은 그대로다. 부장에게 양식 편집·복제 화면은 열리지 않는다. 디자인 §6-2의 "[양식 보기·편집] 부장에게 숨김"이 유지된다.
2. **`POST /board-materials` 409 `ALREADY_EXISTS`**: `detail:{code, message, material_id}`. 화면은 이것을 [자료 열기]로 바꿀 수 있다.
3. **400 `BAD_VALUE`(숫자 형식·100자)와 422 `PII_DETECTED`(칸)**: `detail.count`(문제 칸 총수)와 `detail.cells:[{ref,key}]`(최대 50, 값 없음)가 추가된다.
   - `cells`는 알려진 칸 키만 담으므로 `cells.length`가 `count`보다 작을 수 있다.
   - 422 `kinds`는 그대로다.
   - 양식 구조 대조 실패(모르는 표·값 칸이 아닌 키)의 400과 메모·사유의 400/422에는 `cells`가 없다. 메모 422는 `kinds`·`cells` 둘 다 없다.
   - 판정 순서는 길이(400) → 개인정보(422) → 숫자(400) → 구조(400) → 최종값 재검사(422)다.
4. **숫자 칸 문법**: 부호는 선택, 정수부 최대 13자리, 소수는 최대 2자리다. 쉼표는 올바른 3자리 묶음만 되고 13자리는 `d,ddd,ddd,ddd,ddd` 모양뿐이다. 이전에는 15자리까지 통과했다. 디자인 문구의 "정수 13자리·소수 2자리까지, 천 단위 쉼표 가능"과 이제 일치한다.
5. **개인정보 검출 확대**: 칸 값과 메모에서 en dash·가운뎃점·점 구분자, 비ASCII 숫자, 폭 없는 공백을 끼운 주민·휴대폰·외국인번호도 422다. 전각 숫자는 이미 막혀 있었다.
6. **`GET /board-materials/{id}/acts`**: `action_cd`에 `LIST`가 새로 나온다(`outcome` OK). 작업·감사 화면이 있다면 라벨을 추가한다. 그 밖의 응답 키는 바뀌지 않는다.
7. **401·403**: 응답은 그대로다. ACT 기록만 바뀐다(401 제외).

## 6. 보안·위험·되돌리는 법
- **인증 한계**: `X-Emp-No`·`X-Screen-Id`·`X-Button-Id`는 모두 자기신고다. `form` 노출과 중복 409는 업무 규칙이지 사칭 방지가 아니다. 접근 이력과 ACT에는 값·메모·본문을 넣지 않았다. LIST 행도 자료 번호·입찰 건·결과코드·버전 번호뿐이다.
- **403·404 경로**: 변하지 않는다. 비담당은 `loadVisible`에서 먼저 404이므로 `form`을 받을 수 없다. 만들기는 자격 검사(403)가 중복 검사보다 앞이라 건 존재 여부와 중복 여부를 모른다. 쓰기 거부 403은 기존대로 `guard.denied`가 ACCESS_LOG에 DENIED로 남긴다.
- **ACT 기록량 증가(LIST)**: 부장이 목록을 열 때마다 확정 건 수만큼(최대 300행) INSERT가 생긴다. 팀 결정(포함)대로 구현했고, 한 트랜잭션이며 응답 전에 실행한다. 확정 건이 늘면 ACT 보존·정리 기준이 필요하고, 그것은 운영·기획 판단이다.
- **401 제외**: 사번 없는 요청은 ACT에서 빠지고 ACCESS_LOG(DENIED)에만 남는다. 비활성·미등록 계정의 403은 ACT에 DENIED로 계속 남긴다(사번이 확인된 호출만).
- **알려진 한계(남김)**
  - `checkedValues`의 `docForStored(empNo,…)`는 아직 팀 범위를 본다. 복제 양식을 쓰는 자료를 다른 팀 담당자가 저장하면 404가 날 수 있는데, 이제 같은 사람이 `form` 구조는 읽는다. 해결하려면 저장 쪽도 `structureForStored`와 같은 비팀 조회로 맞추면 되는 한 줄 변경이다. 이번 범위 밖이라 적용하지 않았다. 필요하면 지시해 달라.
  - 메서드 진입 전 실패(깨진 JSON 400, 필터 413)는 ACT에 안 남는다. security 하-4②에서 "ACCESS_LOG로 충분"으로 권장한 대로다.
  - 중복 방지에는 DB UNIQUE가 없다. 코드 검사와 잠금뿐이다. 운영 DB에 중복 행이 이미 있는지 먼저 확인한 뒤에야 021 UNIQUE를 제안할 수 있다. 중복이 있어도 이 변경은 안전하다(가장 작은 번호를 알려 준다).
  - `form`이 매 상세 응답에 들어가 응답이 커진다(기본 양식 표 전체). 문제가 되면 `?form=0` 같은 옵트아웃을 따로 더할 수 있다.
- **되돌리는 법**: 파일별로 독립이다. 컨트롤러 `run`·`list`를 원복하면 감사 변경이 사라지고, `Pii.scanLoose`를 부르는 세 곳을 `Pii.scan(Normalizer…)`로 되돌리면 검출이 원래로 돌아간다. `form` 키는 `body`·`snapshot`의 `put` 두 줄을 지우면 된다. DB 변경이 없으므로 롤백 SQL도 없다. 이미 저장된 데이터와도 호환된다(저장 형식 변경 없음).

## 7. 이관 메모

- `[이관: 데이터]` 엑셀 연결 칸의 실제 값 모양(괄호 병기 `48.51 (36.85)`·`(1,234)`·`△`·U+2212)이 숫자 문법 때문에 400이 되는지 확인한다. 서버는 이번에도 그런 모양을 거부한다(거부 칸 위치는 이제 알려 준다). 괄호 병기 칸을 숫자로 줄여 저장할지, 서버가 받아 줄지는 data·기획 결정이다. — 기다리는 것: 데이터 샘플 — 근거: design-reviewer P0-3
- `[이관: 기획]` ① 확정 건 ACT 보존·정리 기준: 부장 목록 조회마다 LIST가 쌓인다. ② security 하-3: 배정 이력의 '작성본 인계' 행을 비담당 영업팀원에게 숨길지. — 기다리는 것: 사용자 답 — 근거: security 이관 메모
- `[이관: cleaner]` `BoardFormService.list`의 `can_write`(`permissions.canWrite`)는 컨트롤러가 덮어써서 효력이 없다. 정리 후보다. 여기서는 건드리지 않았다.

## 8. 열린 질문
1. 저장 쪽(`docForStored`)도 팀 범위 없는 조회로 맞출까요? 다른 팀 담당자가 복제 양식 자료를 저장할 때의 404를 없애려는 것입니다. 한 줄 변경이고, 안 하면 현행 유지입니다.
2. 확정 건이 많아질 때 LIST 기록을 호출당 1행(건수만 기록)으로 줄일 필요가 있나요? 지금은 팀 결정대로 행마다 기록합니다. 줄이면 "어느 건을 봤는지"를 잃습니다.
3. 중복 운영 DB 점검 후 UNIQUE(`BID_CASE_ID`,`BOARD_YEAR`)를 021로 제안할까요? 점검 쿼리는 `SELECT BID_CASE_ID, BOARD_YEAR, COUNT(*) FROM BOARD_MATERIAL GROUP BY BID_CASE_ID, BOARD_YEAR HAVING COUNT(*) > 1`입니다.
