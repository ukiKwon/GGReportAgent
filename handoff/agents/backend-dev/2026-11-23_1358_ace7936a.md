## 3. 구현안

### 3-0. 팀 결정 (되돌리기 쉬운 쪽)

**(1) 결재 팀장 한 명을 정하는 순서.** 회차를 열 때 한 번 정하고 DESIGN_ROUND_RECIP에 박제합니다. REASON_CD는 `APPROVER`, NOTIFICATION_ID는 자리표 `NONE`입니다.
1. 그 건의 활성 담당(BID_ASSIGNMENT) 중 **영업팀원**이 있으면, 각자 결재 체인(`ApproverRules.chain`)에서 처음 만나는 활성 영업팀장을 모읍니다.
2. 영업팀원 담당이 없고 **영업팀장 본인이 담당**이면 그 팀장을 후보로 봅니다. 그 건의 영업팀장이고, 디자이너 작업 담당이 아니라서 본인 결재 금지에 걸리지 않습니다.
3. 후보가 1명이면 그 사람입니다.
4. 후보가 2명 이상이면, 디자이너 자신의 결재 팀장이 후보 안에 있을 때 그 사람을 고릅니다. 없으면 배정순(ASSIGNED_AT, EMP_NO) 첫 사람입니다.
   - 막지 않는 이유: 결재 권한은 역할 기준으로 남겨 두므로 잘못 골라도 되돌릴 수 있습니다. 디자이너 제출을 막는 쪽이 업무를 더 멈춥니다.
5. 담당이 없으면 디자이너의 결재 팀장으로 갑니다. 그것도 없으면 활성 영업팀장이 정확히 1명일 때만 그 사람입니다. 그래도 없으면 409 `NO_REVIEWERS`(코드는 그대로, 문구만 바꿈).

**(2) 결재함에 올리는 방식: 기존 `/approvals` 작업 카드를 그대로 씁니다.**
- 영업팀장 결재함에서는 디자이너 1차 카드 가운데 **회차 결재 팀장 본인이거나 그의 대결자**인 경우만 남깁니다.
- 영업팀장이 아닌 대결자에게는 같은 카드를 덧붙이고 `acting_as_deputy=true`를 싣습니다.
- 새 유형(APPROVAL_REQUEST의 DESIGN_REVIEW)을 쓰지 않는 이유: 상태 정본이 TASKS.STATUS와 결재 요청 두 벌이 되어 다시 수정·반려·승인 때마다 맞춰 줘야 하고, 기존 카드와 숫자가 이중으로 잡힙니다.

**(3) 결재 권한.**
- 역할 기준(영업팀장 누구나)은 그대로 둡니다. 사용자 11-10 확정 규칙이고, `/tasks/{id}/approve` 동작을 지키기 위해서입니다.
- **디자이너 1차 단계에 한해** 회차 결재 팀장의 그날 대결자를 추가로 허용합니다. 조건은 활성 사용자이고 `mayDecide`를 통과하는 것입니다.
- 대결로 처리하면 감사에 `DSN_FORWARD_DEP` / `DSN_LEAD_RETURN_DEP`가 남습니다. 회차 결재 팀장이 아닌 다른 영업팀장이 처리한 경우는 DESIGN_ROUND_RECIP와 ACTOR_EMP_NO를 비교하면 알 수 있습니다.

    static final class Reviewer {
        final SysUser user;
        final String basis;   // ASSIGNEE_LINE · ASSIGNEE_LEAD · MULTI_DESIGNER_LINE · MULTI_FIRST_ASSIGNED · DESIGNER_LINE · ONLY_LEAD
        Reviewer(SysUser user, String basis) { this.user = user; this.basis = basis; }
    }

    /**
     * 그 건 담당 영업의 결재 팀장 한 명. ① 활성 담당 중 영업팀원의 결재 체인에서 처음 만나는 활성 영업팀장
     * ② 팀원 담당이 없으면 담당인 영업팀장 본인 → 1명이면 그 사람, 여럿이면 디자이너의 결재 팀장(후보 안에 있을 때) 아니면 배정순 첫 사람
     * ③ 담당이 없으면 디자이너의 결재 팀장 ④ 활성 영업팀장이 정확히 1명이면 그 사람. 못 정하면 null.
     */
    Reviewer resolveReviewer(String bidCaseId, SysUser designer) {
        List<SysUser> all = users.selectAll();
        Map<String, SysUser> byEmp = new HashMap<String, SysUser>();
        for (SysUser u : all) {
            byEmp.put(u.getEmpNo(), u);
        }
        Set<String> viaMember = new LinkedHashSet<String>();
        Set<String> viaLead = new LinkedHashSet<String>();
        for (BidAssigneeView v : assignments.selectActiveAssignees(bidCaseId)) {   // ASSIGNED_AT, EMP_NO 순
            SysUser u = byEmp.get(v.getEmpNo());
            if (u == null || !"ACTIVE".equals(u.getStatus())) {
                continue;
            }
            if (LEAD_SALES_ROLE.equals(roleOf(u))) {
                viaLead.add(u.getEmpNo());
            } else if (MEMBER_SALES_ROLE.equals(roleOf(u))) {
                SysUser l = firstActiveLead(u, byEmp);
                if (l != null) {
                    viaMember.add(l.getEmpNo());
                }
            }
        }
        Set<String> cands = viaMember.isEmpty() ? viaLead : viaMember;
        SysUser designerLead = firstActiveLead(designer, byEmp);
        if (cands.size() == 1) {
            return new Reviewer(byEmp.get(cands.iterator().next()), viaMember.isEmpty() ? "ASSIGNEE_LEAD" : "ASSIGNEE_LINE");
        }
        if (cands.size() > 1) {
            if (designerLead != null && cands.contains(designerLead.getEmpNo())) {
                return new Reviewer(designerLead, "MULTI_DESIGNER_LINE");
            }
            return new Reviewer(byEmp.get(cands.iterator().next()), "MULTI_FIRST_ASSIGNED");
        }

    public String currentReviewer(String taskId) {

        if (n <= 0) {

        return rs.isEmpty() ? null : rs.get(0);

        return reviewer != null && isDeputyOf(reviewer, me, taskId);

    private boolean isDeputyOf(String reviewer, SysUser me, String taskId) {
        if (me == null || reviewer.equals(me.getEmpNo()) || !"ACTIVE".equals(me.getStatus())
                || !deputies.deputiesOf(reviewer, Times.todayKst()).contains(me.getEmpNo())) {
            return false;
        }
        DesignRound r = mapper.selectRound(taskId, mapper.selectMaxRound(taskId));
        SysUser designer = r == null ? null : users.selectByEmpNo(r.getOpenedBy());
        return designer != null && Ranks.mayDecide(designer, me);
    }

    /**
     * 결재함(/approvals)의 디자이너 1차 카드를 me 에게 보일지. 새 규칙 회차는 결재 팀장 본인·그의 대결자만.

     * ⚠️ 보이기만 정한다 — 결재 권한은 TaskCommandService.approve 가 정한다.
     */
    public boolean firstStageVisibleTo(String taskId, SysUser me) {
        String reviewer = currentReviewer(taskId);
        if (reviewer == null) {
            return true;
        }
        SysUser rv = users.selectByEmpNo(reviewer);
        if (rv == null || !"ACTIVE".equals(rv.getStatus())) {
            return true;
        }
        return reviewer.equals(me.getEmpNo()) || isDeputyOf(reviewer, me, taskId);
    }

    private boolean isActiveAssignee(String bidCaseId, String empNo) {
        for (BidAssigneeView v : assignments.selectActiveAssignees(bidCaseId)) {
            if (empNo.equals(v.getEmpNo())) {
                return true;
            }
        }
        return false;
    }

    /** 옛 '결재요청' 신호 — 결재 팀장과 그날 대결자의 사번으로(역할 쪽지함 아님). 설정 키가 꺼져 있으면(out-local 기본) 아무것도 보내지 않는다. */
    private void notifyReviewer(SysUser reviewer, SysUser designer, TaskContext ctx, String taskId) {
        if (!notifications.approvalRequestEnabled()) {
            return;
        }
        List<String> to = new ArrayList<String>();
        to.add(reviewer.getEmpNo());
        for (String d : deputies.deputiesOf(reviewer.getEmpNo(), Times.todayKst())) {
            SysUser u = users.selectByEmpNo(d);
            if (u != null && "ACTIVE".equals(u.getStatus()) && !d.equals(designer.getEmpNo())
                    && Ranks.mayDecide(designer, u) && !to.contains(d)) {
                to.add(d);
            }
        }
        String text = ctx.getInstitutionName() + " " + Teams.DESIGNER_TEAM + " 작업물 제출 — 결재를 부탁드립니다.";
        for (String emp : to) {
            notifications.create(emp, "결재요청", text, ctx.getInstitutionId(), taskId, null, ctx.getStage(),
                    NotificationCommandService.SYSTEM_SENDER);
        }
    }

    public ApprovalsResponse forUser(SysUser me) {
        String role = me.getRole() == null ? "" : me.getRole().trim();
        List<ApprovalItem> items = new ArrayList<>();

            }

        }
        if (!deputies.principalsOf(me.getEmpNo(), Times.todayKst()).isEmpty()) {   // 대결 지정이 있을 때만 더 돈다

## 5. 보안·위험·되돌리는 법
- **권한(403 경로)**
  - 결재 권한은 넓어지기만 합니다(디자이너 1차 단계, 회차 결재 팀장의 그날 대결자). 좁아지지 않습니다.
  - 대결 판정은 서버가 합니다: APPROVAL_DEPUTY의 유효 기간·취소 여부, 활성 사용자, `Ranks.mayDecide`(디자이너 기준), 본인 작업 결재 금지(155-159행 유지).
  - 403은 기존처럼 `guard.denied`로 ACCESS_LOG DENIED에 남고, `DesignGate.auditApproveFailure`로 DSN_* DENIED도 남습니다.
- **보이기 필터는 보안 경계가 아닙니다.** 다른 영업팀장도 API로는 여전히 결재할 수 있습니다(11-10 규칙). 막을지는 7절 질문입니다.
- **대결 허용은 기존 원칙과 다릅니다.** 영업팀 내부 결재 유형은 모두 대결 불가입니다(ApprovalTypes.java:32-34). 사용자 답에 따른 예외이므로 security 검토가 필요합니다.
- **감사**: 결재 행위는 DSN_FORWARD(_DEP)·DSN_LEAD_RETURN(_DEP)에 ACTOR_EMP_NO·SCREEN_ID·BUTTON_ID·EMP_VERIFIED와 함께 남습니다. 열람은 DSN_VIEW 그대로입니다. 본문·사유·이름은 넣지 않습니다(기존과 같음).
- **자기신고의 한계**: 사번·화면·버튼은 모두 `X-Emp-No` 자기신고입니다. 대결자 판정도 자기신고 사번 위에서 하므로 사칭을 막지 못합니다. 운영 노출 전 SSO가 필요합니다(NEXT 35).
- **위험**
  - ① 대결자에게 `approvals` 메뉴 권한이 없으면 `guard.requireUser(req,"approvals")`에서 403이 납니다(TaskController.java:244, ApprovalController.java:48). 권한 부여는 기획과 관리자 몫입니다.
  - ② portal.js:27 때문에 영업팀장·영업부장이 아닌 대결자는 `/approvals`를 부르지 않아 결재함 숫자에 이 건이 안 잡힙니다(프런트 이관).
  - ③ `/approvals` 호출마다 디자이너 1차 카드 한 장당 조회가 2~4번 늘어납니다. 카드가 적어서 무시할 만합니다.
