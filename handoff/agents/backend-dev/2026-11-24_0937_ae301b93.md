## 고친 파일(모두 kgi-ggreport-web 아래)
1. `src/main/java/com/kbstar/kgi/ggreport/web/service/PrepBoardService.java`
   - ③d: `banks` 필드, 생성자 인자 `BankContractMapper`, import를 제거했습니다. 생성자는 이제 `(preps, mapper, prep, assignments, notices, audit, extChecks)`입니다.
   - ③a: `static boolean expired(String termTo, LocalDate today)`를 추가했습니다.
     - `BankContractRules.endOrNull(trim)`이 날짜를 풉니다. YYYY는 12-31, YYYY-MM은 그 달 말일입니다.
     - 끝날이 null(null이거나 파싱 불가)이면 `expired`는 true라서 현재 약정에서 빠집니다.
     - 오늘 만료는 유효합니다.
     - `currentBanksByInst(LocalDate today)`가 이 메서드를 쓰고, 호출부는 `LocalDate.parse(today)`를 넘깁니다.
     - 기존 문자열 `compareTo`는 없앴습니다.
   - ③f: `static String checkBlock(String stateCd, boolean mine)`을 추가했습니다.
     - 상태를 먼저 봅니다. `CHECK_STATES` 밖에서 CONFIRMED·OPEN_PENDING은 `PRE_OPEN`, CANCELLED는 `ENDED`, 그 밖은 `STATE`입니다.
     - 허용 상태 안에서는 담당이 아니면 `NOT_MINE`, 담당이면 null입니다.
     - 행에 `check_block`을 넣고 `can_check = (check_block == null)`로 맞췄습니다. 기존 `can_check`와 같은 근거(`CHECK_STATES`·`mine`)라 결과가 같습니다.
2. `BankContractRules.java`는 고치지 않았습니다. 같은 패키지이고 `endOrNull`이 이미 패키지 공개라서 접근 제한자를 바꿀 필요가 없었습니다.
3. `src/main/resources/mapper/PrepBoardMapper.xml`
   - ①: 은행 이름을 아래 CASE로 바꿨습니다. 양쪽 DB에서 도는 표준 SQL입니다.
   - `BANK_CD='ETC'`이고 `NULLIF(TRIM(BANK_NAME_ETC),'')`가 null이 아니면 `BANK_NAME_ETC`를 씁니다.
   - 아니면 `COALESCE(코드표 이름, BANK_NAME_ETC, BANK_CD)`입니다.
   - 주석도 새 순서로 고쳤습니다.
4. `src/test/java/.../service/PrepBoardServiceTest.java`
   - 생성자 호출과 import를 정리했습니다.
   - U10을 추가했습니다. 날짜를 2026-11-24로 고정하고 `expired` 경계를 봅니다.
   - U11을 추가했습니다. `checkBlock`의 모든 값을 봅니다.
5. `src/test/java/.../web/PrepBoardApiTest.java`
   - D24 루프에 `check_block == PRE_OPEN` 단언을 한 줄 넣었습니다.
   - D40: TERM_TO가 올해('YYYY')와 이번 달('YYYY-MM')이면 보이고, 지난해·지난달·"abc"는 빠집니다.
   - D41: ETC 줄은 직접 입력 이름, 이름이 없으면 코드표 이름('기타(직접 입력)'), 코드표에 없으면 코드값(Z99)으로 나옵니다.
   - D42: `check_block`은 PRE_OPEN·null·NOT_MINE·ENDED이고, 모든 줄에서 `can_check`와 짝을 이룹니다. 비담당 건이 PRE_OPEN 줄이어도 PRE_OPEN이 나옵니다(상태 먼저).
   - D43: 비담당이 승인 전 줄이나 남의 줄을 PUT하면 403이고 체크 행은 0입니다.
   - 날짜는 기존 시험처럼 `Times.todayKst()`에서 계산해 오늘 값에 기대지 않습니다.
   - 기존 D31~D39는 바꾸지 않았습니다.

## 판단과 확인할 것
- 지시와 다르게 한 곳이나 임의로 정한 것은 없습니다.
- 시험 이름은 보고서의 U7·U8이 아니라 U10·U11입니다. U7·U8이 기존 시험과 겹쳤습니다.
- D40~D43은 H2 위에서 도는 것으로 가정했습니다. H2에서 `NULLIF`·`TRIM`이 문제를 일으키면 XML의 CASE만 보면 됩니다.
- D42는 `dobong`에 승인 전 건(CONFIRMED)을 만들고 `nowon`에 승인된 건을 둡니다. MEMBER와 MEMBER2 모두 영업팀 역할이라는 기존 시험 전제를 따랐습니다.
- IDE 진단에 `currentBanksByInst(String)` 오류가 한 번 떴지만, 병렬 편집 도중의 낡은 값으로 보입니다. 시그니처와 호출부를 둘 다 LocalDate로 바꿨습니다. 컴파일 결과로 확인해 주세요.
