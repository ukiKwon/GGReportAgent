## 1) close_reason 삼항식: 정리 가능, 동작 변화 없음
- 근거: PlanCollectService.java:273 `m.put("close_reason", canRequest ? r.getCloseReason() : null);` 에서 canRequest는 항상 true입니다.
  - 같은 루프 266행에 `if (!canRequest) break;`가 있어, canRequest가 false면 273행에 도달하지 않습니다.
  - 그래서 null 가지는 죽은 코드이고, 결과는 r.getCloseReason()과 같습니다.
- 디자이너 차단은 266행의 break와 last_closed 자체를 비우는 동작이 맡습니다. PlanCollectApiTest:387-388, 406이 이를 확인합니다.
- 파일은 CRLF입니다(768줄 CRLF 확인). 줄 끝을 \r\n으로 유지해야 합니다.

패치 A (필수·최소):
```
old (273행):
            m.put("close_reason", canRequest ? r.getCloseReason() : null);
new:
            m.put("close_reason", r.getCloseReason());   // canRequest 는 위 break 로 이미 보장됨
```

패치 B (선택, 가독성): 266행의 break를 루프 앞으로 옮깁니다.
```
old (264~266행):
        for (PlanCollectReq r : recent) {
            String inst = r.getInstitutionId();
            if (!canRequest) break;   // 디자이너에게는 last_closed 를 비운다(security 11-17)
new:
        for (PlanCollectReq r : canRequest ? recent : Collections.<PlanCollectReq>emptyList()) {   // 디자이너에게는 last_closed 를 비운다(security 11-17)
            String inst = r.getInstitutionId();
```
Collections는 이미 import되어 있습니다(229행에서 사용). 동작은 같고, A만으로 요청 범위는 충족합니다.

## 2) CLOSED_AT 인덱스: 지금은 불필요 (판정: 보류)
- 쿼리: selectRecentClosed는 `WHERE OPEN_INST_ID IS NULL AND CLOSED_AT >= #{since} ORDER BY INSTITUTION_ID, REQ_SEQ DESC`입니다(PlanCollectMapper.xml:48-50).
- 기존 인덱스: PK(INSTITUTION_ID, REQ_SEQ), UQ_PCR_KEY, UQ_PCR_OPEN, IDX_PCR_STATUS(STATUS_CD, REQUESTED_AT)가 있습니다(045 mysql 33~36행, oracle 47~51행). CLOSED_AT으로 탈 인덱스는 없습니다.
- 규모(추정, 실측 아님): 기관당 열린 요청은 1건이고, 닫힌 건은 누적되지만 가끔 생기는 수준이라 수천 행 정도로 봅니다.
- ORDER BY가 PK 순서와 맞아 filesort가 필요 없을 수 있습니다.
- 호출은 기관 사업계획 화면의 status 조회 때뿐이고, 수천 행 풀스캔은 밀리초 단위입니다.
- 판정: 인덱스는 필요하지 않습니다. 더하면 닫을 때의 쓰기 비용, 마이그레이션 번호, Oracle DBA 적용 부담만 늘어납니다.
- 재검토 기준: 닫힌 행이 대략 10만 건을 넘거나 status 응답이 느려질 때 다시 봅니다. 아래는 그때를 위한 초안입니다. 번호는 NNN으로 비웠고 외래키는 없습니다.

```sql
-- db/mysql/NNN_plan_collect_closed_idx.sql (한 번만 실행)
CREATE INDEX IDX_PCR_CLOSED ON PLAN_COLLECT_REQ (CLOSED_AT);
-- 되돌리기: DROP INDEX IDX_PCR_CLOSED ON PLAN_COLLECT_REQ;

-- db/oracle/NNN_plan_collect_closed_idx.sql (정본, 적용은 DBA)
CREATE INDEX IDX_PCR_CLOSED ON PLAN_COLLECT_REQ (CLOSED_AT);
-- 되돌리기: DROP INDEX IDX_PCR_CLOSED;
```
- 단일 칸 CLOSED_AT 인덱스는 열린 건(CLOSED_AT NULL)을 담지 않아 닫힌 건만 가려내 줍니다.
- 045는 적용 후 수정 금지(체크섬)이므로, 필요해지면 새 번호 파일로 추가합니다.
- 이미 적용한 DB는 새 파일만 한 번 더 돌리면 이어집니다.
