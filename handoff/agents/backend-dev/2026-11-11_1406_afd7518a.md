## 5. 보안·위험·되돌리는 법
- **권한 경로**: 바뀌지 않습니다. 제출은 404→403→(새로)400→409 순서이고, 403은 기존처럼 컨트롤러 `guard.denied`로 ACCESS_LOG DENIED에 남습니다.
  - SNAPSHOT_CHANGED는 담당자 검사를 지난 뒤에만 나옵니다. detail에는 버전 번호만 싣고 값·저장자는 싣지 않습니다.
  - 접근 이력 DETAIL은 그대로 `id·code·req`이고, 클라이언트 snap_no는 넣지 않습니다.
  - 제출 건은 CONFIRMED가 아니므로 ACT 대상이 아닙니다(기존과 같음).
- **이름 노출 범위**: 제출자·결재자·확정자 **이름**이 detail(현재 담당자·영업부장)과 review(현재 결재자·확정자·부장)에 새로 보입니다. 사번은 넣지 않았습니다. 결재자 이름은 신청자가 결재함에서 이미 보는 정보이지만, 같은 건의 다른 담당자에게도 보이게 됩니다. security 확인 대상입니다.
- **PII**: 작업 이력의 REJECT 의견과 REWORK 사유에 `Pii.scanLoose` 가림이 새로 적용됩니다(옛 행 방어, null 반환).
- **동시성**:
  - 자료 행 FOR UPDATE를 submit 트랜잭션 끝까지 잡습니다. 잠금 순서는 배정 머리 → 자료 행이고, applyConfirm(단계→머리→자료)·인계(머리→자료)와 같은 방향입니다.
  - 저장·회수·재작성 요구는 배정 머리를 잡지 않아 순환이 없습니다.
  - 잠금 시간이 결재자 계산과 요청 INSERT 동안으로 조금 늘어납니다.
  - 남는 위험: 실제 경합은 단위 테스트로 재현하지 못했습니다. 실DB 두 세션 시나리오는 qa가 보는 것을 권장합니다.
- **N+1 조회**: 이력의 REJECT 행마다 `selectSteps`를 한 번 부릅니다. 같은 요청은 1차 캐시가 막고, 반려 횟수만큼만 늘어납니다. 커지면 selectLog에 상관 서브쿼리로 바꿉니다.
- **자기신고 인증의 한계**: X-Emp-No는 자기신고입니다. snap_no 비교는 실수 방지용이고 위조를 막는 장치가 아닙니다.
- **되돌리는 법**: 위 파일들을 되돌리면 끝납니다. DDL·데이터 변경이 없습니다. BOARD_FINAL은 DB 행이 없어 복원도 한 줄입니다.

## 6. 이관 메모
- [이관: 프런트] 제출 정보 표시와 snap_no 전송 — 이 패치 적용을 기다림 — 근거 `board-material.js:553-571, 626-643, 292-298, 1044, 1267-1270`
  - **제출 시 전송**: `doAct('submit')` 본문을 `{snap_no: savedCount(M.data)}`로 보냅니다. 제출 줄에 보인 n과 같은 값이어야 합니다.
  - **409 문구**: `kind==='submit'`에서 `code==='SNAPSHOT_CHANGED'`를 일반 409보다 먼저 처리합니다. 문구 후보: 제목 "다른 담당자가 새 버전을 저장해 제출하지 않았습니다.", 안내 "지금 최신은 버전 {detail.current_snap}입니다. [새로 고치기]로 바뀐 내용을 확인한 뒤 다시 제출해 주세요." 버튼은 R(새로 고치기).
  - **머리 메타**: SUBMITTED이면 `제출 버전 {submit_snap} · {submitted_by_name} {kst(submitted_at)} 제출 · 결재 {approver_name}`. CONFIRMED이면 기존 confirmMeta에 `{confirmed_by_name} 확정`을 더합니다. null인 조각은 생략합니다.
  - **잠금 줄**: SUBMITTED이면 `savedCount(d)` 대신 `d.submit_snap`을 씁니다. 예: "버전 N을 {submitted_by_name}이(가) 제출해 {approver_name}이(가) 결재 중입니다…" (이름이 null이면 기존 문장).
  - **되돌림 배너**: `last_return.from_status==='CONFIRMED'`이면 "확정이 풀렸습니다"를 보이고, `from_result_name`이 있으면 "(지워진 의결 결과 '{from_result_name}')"를 붙입니다.
  - **작업 이력 탭**: REJECT 행에도 사유를 그립니다. REJECT·REWORK인데 reason이 null이면 기존 배너와 같은 "사유는 개인정보로 보이는 내용이 있어 표시하지 않습니다."를 씁니다.
