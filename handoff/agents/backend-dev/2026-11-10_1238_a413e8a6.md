## 1. 대상·방법·못 본 것
- 읽은 파일: `ApprovalRequestService`, `ApprovalRequestMapper`(.java/.xml), `BidAssignmentService`, `BidAssignmentMapper`(.java/.xml), `AssigneeChangeApiTest`.
- 보안 보고서 원문(`handoff/agents/security/2026-11-10_*`)은 읽지 않았고, 지시문의 요약만 근거로 했습니다.
- DDL 변경이 없어 `db/mysql`·`db/oracle` 스크립트는 추가하지 않습니다.
- `PENDING_REQ_ID`에는 외래키가 없습니다(`019_bid_assignment.sql:12`). 그래서 `releasePending`이 남의 선점을 건드리지 않는 것은 SQL 조건(`AND PENDING_REQ_ID = reqId`)이 맡습니다.

## 2. 원인 요약
- **중-1**: `decide`와 `cancel`은 `selectById`로 읽은 상태(`ApprovalRequestService.java:221`, `:272`)만 믿습니다. 쓰는 UPDATE에는 상태 조건이 없고(`ApprovalRequestMapper.xml:42-52`) 반환 행 수도 확인하지 않습니다(`:244-259`, `:277`). 취소 때 `PENDING_REQ_ID`를 풀지도 않습니다. 낡은 선점은 `planChange`가 교체하므로(`BidAssignmentService.java:261-266`) 기능은 막히지 않지만, 선점 상태가 요청 상태와 어긋납니다.

### 테스트를 쓸 때 유의한 점
- **1차 캐시**: 경합 재현은 1차 캐시를 일부러 이용합니다. `selectById`로 PENDING을 읽어 두고 JdbcTemplate으로 상태를 바꾼 뒤, 서비스 호출 전에 MyBatis 쓰기가 없도록 했습니다. 결재선을 JdbcTemplate으로 바꾼 케이스는 `flushCache()`를 호출합니다. `submitOk`가 `selectSteps`를 캐시해 두기 때문입니다.
- **외부 트랜잭션**: 서비스 예외 뒤에도 같은 테스트 안에서 이미 쓴 값(`skipRest` 등)은 되돌려지지 않습니다. 그래서 요청 상태와 선점만 단언하고 단계 상태는 단언하지 않았습니다. 운영에서는 409가 트랜잭션 전체를 되돌립니다.

## 5. 보안·위험·되돌리는 법
- **중-1**: 승인·반려·취소가 서로 덮어쓰지 못합니다. 동시에 들어오면 먼저 커밋한 쪽만 성공합니다. 나중 쪽은 행 잠금을 기다린 뒤 조건이 맞지 않아 0행이 되고 409로 롤백되며, 마지막 단계의 `applyChange`·`permissions.save` 후처리도 함께 되돌아갑니다. MySQL REPEATABLE READ에서도 UPDATE는 현재 읽기라 유효합니다. Oracle은 READ COMMITTED에서 대기 후 재평가한다고 가정했습니다(미검증).
- **반려에는 `releasePending`을 걸지 않았습니다.** 낡은 선점은 종전처럼 `planChange`가 교체합니다. 반려에도 풀려면 `decide`의 반려 분기에 `if (ASSIGNEE_CHANGE) assignments.releasePending(r)` 한 줄을 더하면 됩니다. "기존 동작 불변"을 우선해 이번에는 뺐습니다.
- **하-1의 409**: 운영에서 이 409가 나면 결재선이 어긋난 신청입니다. 반려하거나 취소한 뒤 다시 신청하면 부장으로 결재선이 다시 계산됩니다. 영업부장 역할자(박영업·백수아)는 어느 경우에도 통과합니다. 문구에 사번·이름을 싣지 않았습니다.
- **하-4·5**: 영업 계열이 아닌 역할은 입찰 건 존재와 무관하게 403입니다. 영업팀 전원은 이미 `view`로 존재를 조회할 수 있어 정보 누출이 늘지 않습니다. 영업부장 상신은 종전에도 담당자가 될 수 없어 사실상 403이었고, 지금은 더 일찍 403이 됩니다.
- **한계**: 모든 검사는 `X-Emp-No` 자기신고를 전제로 한 업무 규칙입니다. 사칭 방지가 아닙니다.
- **되돌리는 법**: 소스 4개, 매퍼 XML 2개, 테스트 1개를 바꿉니다. 커밋을 되돌리면 끝나고 DDL과 데이터 변경은 없습니다.
