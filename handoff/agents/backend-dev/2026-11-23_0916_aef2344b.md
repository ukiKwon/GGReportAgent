**소스** (`kgi-ggreport-web/src/main/java/.../service/ResultYearRules.java` 17~23행)
- 기록 대조 블록의 조건을 `starts != null && termFrom.length() >= 10`으로 바꿨다.
- 10자 미만 termFrom(연도만·연월)은 이 블록을 건너뛰고 바로 `TargetResultRules.targetYearOf(termFrom)`로 간다.
- 10자 이상이면 `d.equals(termFrom.substring(0,10))` 정확 일치만 본다. `startsWith` 분기는 없앴다.
- 두 해가 모호하게 겹치면 추정으로 가는 기존 줄과 마지막 return은 그대로다.

**시험** (`ResultYearRulesTest.java`)
- 기존 `개시일과_같으면_그_목표_연도`에서 `yearOf("2027-03", st)` → 2026 기대 줄을 뺐다. 새 원칙과 맞지 않아서다. "2027-03-01" → 2026 기대는 유지했다.
- 기존 `두_해가_같은_접두에_겹치면_추정으로_간다`("2027-03" 접두 겹침)는 새 원칙에서 의미가 달라져 아래 ①로 바꿨다.
- ① `두_해의_기록_날짜가_완전히_같으면_추정으로_간다`: 기록 {2026:"2027-01-01", 2027:"2027-01-01"}, "2027-01-01" → `targetYearOf` 결과와 같다.
- ② `연도만_시작이면_기록과_맞추지_않고_추정`: 기록 {2026:"2027-03-01"}, "2027" → `targetYearOf("2027")`와 같다. 2026으로 귀속하지 않는다.
- ③ `연월만_시작이면_기록과_맞추지_않고_추정`: 같은 기록, "2027-03" → `targetYearOf("2027-03")`와 같다.
