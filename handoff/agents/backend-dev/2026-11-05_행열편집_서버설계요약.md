# 이사회 양식 편집 — 행·열 삽입/삭제 서버 설계 요약 (backend-dev, 2026-11-05)

원 보고서의 요약본. 코드 패치 전문은 생략(구현 시 backend-dev-write가 다시 설계서대로 작성).

## 사용자 결정 (2026-11-05)
- 부서/팀마다 이사회 자료 템플릿이 달라 행 추가/삭제/삽입 + 열 추가/삭제/삽입 모두 필요. 열 편집 이유는 연차가 아니라 '구분' 같은 머리 열이 2열로 쪼개진 템플릿.
- 새 행/열의 값 칸은 공란(또는 0)이면 충분. 핵심은 행·열 머리 문구. 새 행/열은 엑셀 연결 없음.
- '잠김' 개념은 화면에서 폐지 → "표 안의 숫자는 예시입니다" 안내로 대체.

## 핵심 설계
1. 칸 key를 위치 순번 `r{행}c{순번}` → 안정 id 쌍 `r{행id}_c{열id}` (예 `r2_c2`). 옛 key와 모양이 달라 낡은 화면이 조용히 엉뚱한 칸에 적용되지 않고 400.
2. 행 id `r{N}`, 열 id `c{N}`. 카탈로그 N<100, 사용자가 만든 것 N≥100(서버가 `next_r/next_c` 카운터로 발급, 재사용 금지 — 지운 행의 엑셀 연결이 새 행에 붙는 것을 막음).
3. 양식 저장 JSON `fmt:2`: 표마다 cols[], rows[{id, cells[{c,t,cs,rs,h,i,a}]}]를 저장. 엑셀 연결 여부는 저장하지 않고 (표, 행id, 열id)를 카탈로그와 대조해 매번 계산. 옛 포맷(fmt 없음)은 읽을 때 번역(DB 변경 없음, 불변 버전 안전).
4. CATALOG_VER는 올리지 않음(새 상수 FORM_FMT=2). NEXT 37 S5(C-3 사업초기 열)가 나중에 한 번만 1→2. 새 카탈로그 열은 명시 id 사용.
5. PUT은 표 구조 전체를 보냄(서버는 검증만). 병합 갱신 규칙(행/열 삽입·삭제 시 rowspan/colspan 조정)은 화면이 수행, 서버는 layout 검증(겹침/범위/열 순서 일치)으로 차단.
6. 연결(mapped) 칸이 사라지는 저장은 `confirm_unmapped:true` 없이는 400 `UNMAP_CONFIRM_REQUIRED`(건수·최대 50개 목록). 엑셀 채우기는 양식에 남은 연결 칸만 평가, 나머지는 건너뛰고 `unlinked_count`.
7. 표 A 합계: 서버가 값을 자동 보정하지 않음(10-30 확정 규칙). 합계 범위(남은 of 중 최상단 행~합계 바로 위)의 같은 열에 사용자가 추가한 입력 칸이 있으면 `sums.of`에 포함, 경고 `SUM_HAS_MANUAL_PARTS`, status filled→review.
8. 상한: 표당 행40/열12/칸300, 양식 전체 칸800, 문구 100자, 저장 JSON 120,000자, PUT 본문 512KB(필터), id 카운터 ≤9999. 기존 id는 현재 버전에 있는 것만 인정(위조 방지), 새 id는 서버 발급. 오류 메시지는 고정 문구(입력 되돌려 싣지 않음).
9. 권한: 기존 requireEdit 그대로(자기신고 X-Emp-No 한계 불변). 버전 불변이라 복구 가능.
10. docx 열 너비: 안 건드린 표는 현재와 동일, 고친 표는 합계 100%로 정규화(최소 5%).
11. 작성 모드: 연결 칸=엑셀, 직접 입력 칸(input && !mapped)=사용자 입력. withValues는 두 종류 허용.
