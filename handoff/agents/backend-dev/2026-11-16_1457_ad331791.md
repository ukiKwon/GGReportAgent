## 3. 구현안

### 3-0. 설계 요지

**표 2개**
- `NOTICE_ROUND`: 회차. 키는 (기관, 회차 순번).
- `NOTICE_ROUND_LOG`: 판정 이력. 추가만 한다. 키는 (기관, 회차, REV_NO).
- 회차 행은 **첫 판정을 저장할 때** 생긴다. 미처리는 저장하지 않는다.

**열린 회차 1개**
- 저장은 늘 INSTITUTIONS 행을 FOR UPDATE로 먼저 잠근다. 그 뒤 열린 회차를 확인한다.
- UNIQUE 제약 대신 integrity Q10으로 감시한다.
- `PrepService.confirm`도 같은 행을 같은 순서로 잠그므로 교착이 없다. 진행 중 제안 확인과도 직렬화된다.

**회차가 닫히는 때 (지시 ③)**
- 서버가 판단한다. 화면이 보낸 값은 쓰지 않는다.
- 회차를 열 때 서버 DB의 `INSTITUTIONS.LAST_BID`를 `ANCHOR_LAST_BID`로 기록한다.
- 저장 시점의 LAST_BID가 기준값보다 **뒤**(문자열 비교 `>`)이면 그 회차를 `SOURCE_ADVANCED`로 닫고 새 회차를 연다.
- 기준값이 NULL인데 지금 값이 생겼으면 **닫지 않고 기준값만 채운다**. 자료가 뒤늦게 채워진 것으로 본다.
- 값이 앞으로 당겨지거나 NULL이 되면 아무것도 하지 않는다.
- 조회(current)는 같은 함수로 "기관 자료가 넘어간 회차"를 목록에서 뺀다. 그래서 화면은 그 기관을 '기록 없음'으로 계산한다. 실제 닫기는 다음 저장 때 일어난다(조회가 DB를 쓰지 않게).
- 근거: `app.js:13-17`. 서버 모드에서는 /institutions가 기준 자료라서 화면이 보는 lastBid와 DB 값이 같은 출처다.
- 결과 등록(NEXT 73)의 RESULT 닫힘은 코드 자리만 만들어 둔다(ENABLED=0).

**낙관적 잠금**
- 화면은 자기가 본 `(round_seq, base_rev_no)`를 보낸다. 기록이 없으면 `(null, 0)`이다.
- 서버 값과 다르면 409를 돌려준다.
  - 회차가 다름 → `ROUND_CHANGED`
  - REV가 다름 → `STALE`. 최신 기록 요약(`latest`)을 함께 보낸다. 화면이 "김영업이 먼저 기록했습니다(…)" 문구를 만들 수 있게 하려는 것이다.
- PK가 마지막 방어선이다.

**'공고 종료' 확인 창**
- 상태가 CLOSED이고 진행 중 제안이 있는데 버튼이 `save_confirmed`가 아니면 409 `ACTIVE_PREP_CONFIRM_REQUIRED`(+`prep_state_cd`)를 돌려준다.
- 화면은 확인 창을 띄운 뒤 `X-Button-Id: save_confirmed`로 다시 보낸다.
- 이력에는 `BUTTON_ID=save_confirmed`, `ACTIVE_PREP=1`이 남는다.

**감사**
- 이력 행 자체가 감사 기록이다. 처리자 사번·이름 스냅샷, EMP_VERIFIED, 화면, 버튼, UI_VALID, 이전 상태, 이전 다음 확인일, 시각이 들어간다.
- 거부(401/403)는 MenuGuard가 ACCESS_LOG DENIED로 남긴다.
- 의견 본문은 접근 이력에 넣지 않는다.

**바뀐 것 없음**
- 상태·의견·다음 확인일이 지금 값과 모두 같으면 200 `{saved:false, code:"NO_CHANGE"}`를 돌려주고 행을 만들지 않는다.

**API (응답 snake_case)**

| 메서드·경로 | 권한 | 응답 |
|---|---|---|
| `GET /notice-rounds/current` | map 조회 | `{items:[{institution_id, round_seq, rev_no, status_cd, next_check_date, handler_name, emp_verified, handled_at}], can_edit, today}` — 열린 회차 중 기관 자료가 넘어가지 않은 것만, 기관당 1개 |
| `GET /institutions/{id}/notice-rounds` | map 조회 | `{institution_id, rounds:[{round_seq, open, stale, opened_at, closed_at, close_reason_cd, logs:[…]}], truncated}` — 최신이 먼저, 회차 20개·이력 200건 상한 |
| `POST /institutions/{id}/notice-rounds/judgments` | 기관 레코드 수정(map·regions edit) | 201 저장 / 200 NO_CHANGE / 400 INVALID(field) / 401 / 403 / 404 / 409 STALE·ROUND_CHANGED·ACTIVE_PREP_CONFIRM_REQUIRED |

POST 본문:
```json
{"round_seq": 1, "base_rev_no": 1, "status_cd": "DELAYED", "opinion": "…", "next_check_date": "2026-11-30",
 "snapshot": {"due_date": "2026-10-31", "due_basis": "cycle", "due_confirmed": false, "auto_kind": "overdue", "auto_days": 16}}
```
- 머리글은 `X-Emp-No`, `X-Screen-Id: bid_notice`, `X-Button-Id: save|save_confirmed`.
- 본문에 처리자 칸이 와도 무시한다. Jackson이 모르는 키를 무시하므로 DTO에 칸이 없다.
- **미처리 판정(화면)** = 경과 회차인데 `items`에 그 기관이 없거나, `status_cd=DELAYED`이고 `next_check_date <= today`인 경우.

import com.kbstar.kgi.ggreport.web.domain.NoticeRoundLog;
import com.kbstar.kgi.ggreport.web.dto.NoticeRoundIn;
import com.kbstar.kgi.ggreport.web.web.ApiException;

import java.time.format.DateTimeParseException;
import java.util.*;

/** 공고 상태 기록(037)의 입력 검사·회차 넘어감 판정. DB 없이 시험한다. 오류 문구는 design-reviewer 11-16 규격, 내부 정보 없음. */
final class NoticeRoundRules {

    static final String IN_PROGRESS = "IN_PROGRESS";
    static final String CLOSED = "CLOSED";
    static final String DELAYED = "DELAYED";
    static final Set<String> STATUSES = Collections.unmodifiableSet(new HashSet<String>(Arrays.asList(IN_PROGRESS, CLOSED, DELAYED)));
    static final int OPINION_MAX = 500;
    static final int NEXT_CHECK_MAX_DAYS = 366;   // 팀 결정(열린 질문 3) — 끝없는 대기로 미처리에서 영영 빠지는 것을 막는다
    static final int AUTO_DAYS_MAX = 36600;
    static final String FORMAT = "요청 형식이 올바르지 않습니다. 화면을 새로 불러온 뒤 다시 저장하세요.";
    static final Map<String, String> BASIS;
    static final Map<String, String> AUTO;
    private static final Pattern YMD = Pattern.compile("^\\d{4}-\\d{2}-\\d{2}$");

    static {
        Map<String, String> b = new HashMap<>();
        b.put("notice", "NOTICE"); b.put("cycle", "CYCLE"); b.put("expiry", "EXPIRY");
        BASIS = Collections.unmodifiableMap(b);
        Map<String, String> a = new HashMap<>();
        a.put("before", "BEFORE"); a.put("receiving", "RECEIVING"); a.put("deadline_unknown", "DEADLINE_UNKNOWN");
        a.put("deadline_passed", "DEADLINE_PASSED"); a.put("overdue", "OVERDUE");
        AUTO = Collections.unmodifiableMap(a);
    }

    private NoticeRoundRules() {
    }

    static final class Parsed {
        Integer roundSeq;
        int baseRev;
        String status;
        String opinion;
        String nextCheck;
        String dueDate;
        String dueBasis;
        int dueConfirmed;
        String autoKind;
        Integer autoDays;
    }

    /** 기관 자료가 다음 회차로 넘어갔나 — 둘 다 있고 지금 값이 기준보다 뒤일 때만. NULL·같음·앞당김은 false(닫지 않음). */
    static boolean advanced(String anchor, String current) {
        String a = trim(anchor);
        String c = trim(current);
        return a != null && c != null && c.compareTo(a) > 0;
    }

    static boolean sameJudgment(NoticeRoundLog cur, Parsed p) {
        return p.status.equals(cur.getStatusCd())
                && Objects.equals(p.opinion, trim(cur.getOpinion()))
                && Objects.equals(p.nextCheck, trim(cur.getNextCheckDate()));
    }

    static Parsed parse(NoticeRoundIn in, LocalDate today) {
        if (in == null) {
            throw bad("body", FORMAT);
        }
        Parsed p = new Parsed();
        Integer base = in.getBaseRevNo();
        Integer seq = in.getRoundSeq();
        if (base == null || base < 0 || (seq != null && seq < 1) || ((seq == null) != (base == 0))) {
            throw bad("base_rev_no", FORMAT);
        }
        p.roundSeq = seq;
        p.baseRev = base;

        String st = trim(in.getStatusCd());
        if (st == null || !STATUSES.contains(st)) {
            throw bad("status_cd", "판정을 하나 고르세요.");
        }
        p.status = st;

        p.opinion = opinion(in.getOpinion());
        if (p.opinion == null && CLOSED.equals(st)) {
            throw bad("opinion", "공고 종료로 적을 때는 의견이 필요합니다. 무엇을 보고 끝났다고 판단했는지 적으세요.");
        }
        if (p.opinion == null && DELAYED.equals(st)) {
            throw bad("opinion", "지연·재공고 대기로 적을 때는 의견이 필요합니다. 왜 늦어지는지 적으세요.");
        }

        String nc = CLOSED.equals(st) ? null : trim(in.getNextCheckDate());   // 공고 종료는 다음 확인일을 두지 않는다(화면도 숨김)
        if (nc != null) {
            LocalDate d = date(nc);
            if (d == null || !d.isAfter(today)) {
                throw bad("next_check_date", "다음 확인일은 내일 이후 날짜로 고르세요.");
            }
            if (d.isAfter(today.plusDays(NEXT_CHECK_MAX_DAYS))) {
                throw bad("next_check_date", "다음 확인일은 1년 안의 날짜로 고르세요.");
            }
        } else if (DELAYED.equals(st)) {
            throw bad("next_check_date", "지연·재공고 대기는 다음 확인일이 필요합니다. 다시 확인할 날을 고르세요.");
        }
        p.nextCheck = nc;

        NoticeRoundIn.Snapshot s = in.getSnapshot();
        if (s != null) {
            String dd = trim(s.getDueDate());
            if (dd != null && date(dd) == null) {
                throw bad("snapshot.due_date", FORMAT);
            }
            p.dueDate = dd;
            String b = trim(s.getDueBasis());
            if (b != null && !BASIS.containsKey(b)) {
                throw bad("snapshot.due_basis", FORMAT);
            }
            p.dueBasis = b == null ? null : BASIS.get(b);
            p.dueConfirmed = Boolean.TRUE.equals(s.getDueConfirmed()) ? 1 : 0;
            String k = trim(s.getAutoKind());
            if (k != null && !AUTO.containsKey(k)) {
                throw bad("snapshot.auto_kind", FORMAT);
            }
            p.autoKind = k == null ? null : AUTO.get(k);
            Integer days = s.getAutoDays();
            if (days != null && Math.abs(days) > AUTO_DAYS_MAX) {
                throw bad("snapshot.auto_days", FORMAT);
            }
            p.autoDays = days;
        }
        return p;
    }

    /** 앞뒤 공백 제거, 줄바꿈 \n 통일, 제어 문자 거부(\n·\t 허용), 500자(코드 포인트 — Oracle CHAR·utf8mb4 와 같은 셈). 비면 null. */
    static String opinion(String raw) {
        if (raw == null) {
            return null;
        }
        String s = raw.replace("\r\n", "\n").replace('\r', '\n').trim();
        if (s.isEmpty()) {
            return null;
        }
        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if ((ch < 0x20 && ch != '\n' && ch != '\t') || ch == 0x7f) {
                throw bad("opinion", "의견에 쓸 수 없는 문자가 있습니다.");
            }
        }
        int n = s.codePointCount(0, s.length());
        if (n > OPINION_MAX) {
            throw bad("opinion", "의견은 500자까지 적을 수 있습니다(지금 " + n + "자).");
        }
        return s;
    }

    static LocalDate date(String s) {
        if (s == null || !YMD.matcher(s).matches()) {
            return null;
        }
        try {
            return LocalDate.parse(s);   // ISO_LOCAL_DATE 는 STRICT — 2026-02-30 거부
        } catch (DateTimeParseException e) {
            return null;
        }
    }

    static String trim(String s) {
        if (s == null) {
            return null;
        }
        String t = s.trim();
        return t.isEmpty() ? null : t;
    }

    static ApiException bad(String field, String message) {
        Map<String, Object> d = new LinkedHashMap<>();
        d.put("code", "INVALID");
        d.put("field", field);
        d.put("message", message);
        return ApiException.withDetail(400, d);
    }
}

 * 공고 상태 기록(037). 조회는 map 조회 권한(전 팀), 저장은 기관 레코드 수정 권한(map·regions edit — 영업 계열 역할 기본, 사용자 예외로 조정).
 * 401/403 은 MenuGuard 가 DENIED 로 접근 이력에 남긴다(본문·쿼리값 없음). 접근 이력 DETAIL 에는 건수·REV 만 싣는다(의견 본문 금지).
 * ⚠️ 사번은 X-Emp-No 자기신고일 수 있다 — 앞단 인증 전에는 권한 검사도 보안 경계가 아니다.
 */
@RestController
public class NoticeRoundController {

    static final String VIEW_MENU = "map";   // 입찰 공고 현황 화면의 서버 메뉴 키(nav.js:66). 메뉴 키 8개 동결

    private final NoticeRoundService rounds;
    private final MenuGuard guard;

    public NoticeRoundController(NoticeRoundService rounds, MenuGuard guard) {
        this.rounds = rounds;
        this.guard = guard;
    }

    @GetMapping("/notice-rounds/current")
    public Map<String, Object> current(HttpServletRequest req) {
        Actor actor = guard.require(req, VIEW_MENU);
        Map<String, Object> out = rounds.current(actor.getEmpNo());
        req.setAttribute(AccessLogInterceptor.DETAIL, "notice-round current n=" + ((List<?>) out.get("items")).size());
        return out;
    }

    @GetMapping("/institutions/{institutionId}/notice-rounds")
    public Map<String, Object> history(@PathVariable String institutionId, HttpServletRequest req) {
        guard.require(req, VIEW_MENU);
        return rounds.history(institutionId);
    }

    @PostMapping("/institutions/{institutionId}/notice-rounds/judgments")
    public ResponseEntity<Map<String, Object>> save(@PathVariable String institutionId,
                                                    @RequestBody(required = false) NoticeRoundIn body,
                                                    HttpServletRequest req) {
        Actor actor = guard.requireInstitutionEdit(req);
        Map<String, Object> out = rounds.save(institutionId, body, actor, NoticeUiIds.of(req));
        boolean saved = Boolean.TRUE.equals(out.get("saved"));
        req.setAttribute(AccessLogInterceptor.DETAIL, saved ? "notice-round save rev=" + out.get("rev_no") : "notice-round save no-change");
        return ResponseEntity.status(saved ? HttpStatus.CREATED : HttpStatus.OK).body(out);
    }
}

## 5. 보안·위험·되돌리는 법 (security가 볼 점)

1. **자기신고 인증**
   - 처리자·권한 판정 모두 `X-Emp-No`(Actor) 위에 서 있다. 누구나 영업팀 사번을 대면 저장할 수 있다.
   - `EMP_VERIFIED=0`으로 남기고, 화면은 "검증됨"이라고 쓰지 않는다. 앞단 인증 전에는 보안 경계가 아니다.
2. **수정 권한 범위**
   - `requireInstitutionEdit`는 `Teams.isSalesFamily` 역할 기본값을 따른다. 그래서 **디자이너(영업 소속)도 통과**하고, 관리자가 사용자 예외로 다른 사람에게 켤 수도 있다.
   - planner의 "영업팀"과 맞는지 판단이 필요하다. 좁히려면 `HeadRules.isSales`(영업팀·팀장·부장)를 추가로 검사한다.
3. **열람 범위**
   - map 조회 = 전 역할이다. 의견 본문과 처리자 이름이 전 팀에 보인다.
   - 사번·화면·버튼은 응답에서 뺐다. 의견의 개인정보는 화면 안내에만 기대고, 서버는 거르지 않는다.
4. **본문 위조**
   - 처리자 칸은 DTO에 없어서 무시된다(시험 5).
   - 스냅샷은 화면 값이라 형식·코드만 검사한다. **판단에는 쓰지 않는다.**
   - 회차 닫힘은 서버 DB의 LAST_BID로만 정한다. 클라이언트가 회차를 닫을 수 없다.
5. **확인 창 우회**
   - `save_confirmed`는 자기신고 머리글이다. 실수를 막는 장치이지 통제가 아니다.
   - 다만 우회해도 `ACTIVE_PREP=1`, `BUTTON_ID`가 남아 사후에 볼 수 있다.
6. **감사**
   - 성공 저장은 이력 행에 누가·화면·버튼·이전 값·시각이 남는다. 거부는 ACCESS_LOG DENIED에 남는다.
   - 400·409 시도는 별도 감사 표가 없다. ACCESS_LOG에 상태 코드로만 남는다.
   - Head·Plan처럼 `_ACT` 표가 필요하면 표를 하나 더 만든다(판단 요청).
   - DETAIL에는 `rev=`·`n=`만 싣고 의견·날짜는 싣지 않는다.
7. **잠금 순서**
   - INSTITUTIONS 행 잠금을 먼저 잡는다. `PrepService.confirm`·Head·Plan과 순서가 같아 교착 위험이 없다.
   - 진행 중 제안 확인과 제안 확정 사이의 경합도 이 잠금으로 직렬화된다.
   - 잠금 전에 DB 읽기는 없다(검증은 DB 없이 한다).
8. **입력 검사**
   - 의견: 제어 문자를 거부하고 500 코드 포인트까지 받는다.
   - 다음 확인일: 엄격한 날짜, 내일부터 1년 안.
   - 기관 id: `validInstId` 검사, 틀리면 404.
   - 오류 문구에 내부 정보가 없다.
   - 유니코드 방향 제어 문자(U+202E 등)는 거르지 않는다(판단 요청).
9. **DB 권한**: LOG는 INSERT만, ROUND는 UPDATE를 허용하되 닫힘·기준 칸만 고친다. DBA 요청서에 반영해야 한다.
10. **데이터 위험**
    - LAST_BID가 갱신되지 않으면 예전 회차의 '공고 종료'가 계속 '처리됨'으로 남는다. 기획 ⓑ 규칙이 가진 한계다.
    - 수집·이관 주기(데이터)에 달려 있다.

**되돌리기**
- 컨트롤러를 빼면 API가 404가 되고, 화면은 "서버 미연결" 문구를 보인다.
- DB는 037 헤더의 DROP·DELETE를 쓴다(데이터가 사라짐, 운영 금지).
- 018 헤더 주석, README, integrity 변경은 git revert로 되돌린다.
