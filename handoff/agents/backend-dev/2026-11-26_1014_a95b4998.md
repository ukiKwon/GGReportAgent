## 1. 고친 파일 (이 둘만, DocxKit·DocModel은 손대지 않음)
- `kgi-ggreport-web/src/main/java/com/kbstar/kgi/ggreport/web/docout/InstSummaryDocBuilder.java`
- `kgi-ggreport-web/src/test/java/com/kbstar/kgi/ggreport/web/docout/InstSummaryDocBuilderTest.java`

RENDER_VER는 3 그대로입니다. 바뀐 코드는 모두 `v3` 분기(`renderVer >= 3`) 안이라 옛 판 1·2의 출력은 한 글자도 바뀌지 않습니다.

### Builder에서 바뀐 곳 (메서드 단위)
- **`build()`**
  - ■ 소제목은 v3일 때만 11pt 굵게입니다(`squareHead`). 판 1·2는 10pt 그대로입니다.
  - 겉 표 이름표는 `midText("추진\n배경"…, 1, 3)`과 `midText("기타\n사항"…)`입니다. 보통 굵기, 음영 없음, 가운데 정렬, 세로 가운데입니다.
  - 겉 표 열 폭은 v3에서 8/92입니다(판 1·2는 14/86).
  - 클래스 javadoc에 v3 서식 두 줄을 추가했습니다.
- **`background()`**
  - '- {기관} 현황' 소제목이 굵습니다(`dashHead`).
  - 현황 표 머리가 '임직원수'·'기관형태'로 바뀝니다(v3만).
  - 현황 표 열 폭은 13/20/16/17/20/14입니다(v3만).
- **`bizBlocks()`**
  - 소제목이 굵고, 열 폭은 8/20/72입니다.
  - 묶음 칸과 세부 칸은 `midText`(가운데, 세로 가운데, 보통 굵기)입니다.
  - sub가 없는 행은 내용 줄이 모두 bold이고 줄이 1개 이상일 때만 이름표가 굵습니다(`allBold` 유도).
- **`fundBlocks()`**
  - 소제목이 굵고, 열 폭은 13/87이며, '구분' 칸은 `midText` 가운데입니다.
  - MMDA '·' 줄에 note가 있으면 줄 끝에 `Run.sup("주n)")`를 붙입니다.
  - 각주 줄은 전각 공백 2개 + 9pt입니다. 표 뒤 주석(years.notes)은 들여쓰지 않습니다.
- **`footnote(no, t, indent)`**: `indent` 인자를 추가했습니다.
- **`yearsTable()`** (v3만)
  - 첫 칸은 굵은 '구분' + 위첨자 '(단위 : 억원)'이고, 단위가 비어 있으면 '구분'만 냅니다.
  - 연도 머리는 'YYYY년'이고, 종료 해는 굵은 'YYYY년' + 위첨자 '협약 종료'입니다.
  - 'MMDA 연평잔'과 '자금수익'은 가운데 정렬이고 자금수익은 굵게입니다.
  - 열 폭은 20/(80÷n)이고, 값 칸은 오른쪽 정렬을 유지합니다.
- **`etcBlocks()`**: '경쟁은행 동향' 소제목과 '우리 회사 기대효과' 소제목이 v3에서 굵습니다.
- **`scoringBlocks()`**
  - 열 폭은 글자 길이 비례입니다. 한글·전각은 2, 그 밖은 1이고 `clamp(max(H+2,B),7,40)`으로 계산해 `Table` 열 폭에 넘깁니다(`null`이 아님).
  - 가로 정렬: 폭 가중치가 30 이상인 열은 왼쪽, 나머지와 `cs>1` 칸은 가운데입니다.
  - 본문 칸은 전부 세로 가운데입니다.
  - 0열에 `rs>1` 칸이 있으면 0열 본문이 굵고, 합계 줄(TOTAL_LABELS가 든 행)은 전부 보통 굵기입니다.
  - 머리 칸은 `headCell`(굵게, 음영, 가운데)이고 글자 크기와 간격을 본문 단계에 맞춥니다.
  - ■ 소제목은 11pt입니다.
- **새 helper**
  - `dashHead`, `squareHead`
  - `midText` (두 가지 인자 형태)
  - `midCell` — header=true + Shade.NONE 우회를 여기 하나로 모았고, 이유 주석 한 줄이 있습니다.
  - `headCell`, `glyphLen`, `isWide`
  - `scoringStage` — A(10pt, 3/3) → B(10pt, 0/0) → C(9pt, 0/0). 줄 수 L을 추정해 `L×13.3 + 행×10` 또는 `+행×4`가 660pt 이하인 첫 단계를 고릅니다.

## 3. 지시에서 벗어났거나 판단한 곳 (숨기지 않음)
- **열 폭 허용 오차**: 22×5 평가표는 지시대로 ±1tw입니다. 열이 많은 안쪽 표는 마지막 열에 반올림 오차가 쌓여서 허용 오차를 2~3tw로 뒀습니다. 사업 표(3열)는 2.0, 현황 표(6열)와 연도 표(5열)는 3.0입니다. 규격 위반이 아닙니다.
- **빈 자리 칸**: 평가표 격자에서 비는 자리는 본문이면 가운데 빈 칸, 머리 줄이면 음영이 있는 빈 머리 칸으로 채웁니다. 이전에는 머리 줄의 빈 자리도 음영 없는 일반 칸이었습니다. 규격에는 이 경우가 없어서 제가 판단했습니다.
- **단계 선택에서 C 단계 줄 수**: 규격은 "C는 9pt로 줄 수를 다시 셈"이라고 했습니다. 하지만 C는 마지막 단계(하한)라서 어차피 C로 가므로, 재계산은 구현하지 않고 B까지만 10pt 기준으로 추정했습니다. 선택 결과는 같습니다.
- **쪽 높이 예산 660pt**는 규격 숫자를 그대로 상수로 썼고 실측하지 않았습니다. 규격 자체가 추정이므로 Word 실물로 확인해야 합니다. 샘플은 L=24(마지막 '장비구성…' 칸이 2줄로 계산됨)여서 추정 약 539pt입니다. A 단계이고 여유가 있습니다.
- **각주 번호**: MMDA 줄 끝 위첨자와 아래 각주 줄이 같은 번호를 씁니다. 번호 부여 순서(MMDA 줄 → 표 뒤 주석)는 기존과 같습니다.

## 4. DocModel API 한계로 못 한 것
- 제목 아래 가로줄(R2), '·' 줄 둘째 줄 내어쓰기(R3), 줄 간격(R4), run 글자 크기(R5, 그래서 '(단위 : 억원)'은 위첨자 근사)는 지시대로 하지 않았습니다.
- 세로 가운데는 정식 API(R1)가 없어 `midCell`의 header=true + Shade.NONE 우회입니다. R1이 오면 `midCell`만 교체하면 됩니다. 시험이 vAlign center, 음영 없음, 굵기를 고정합니다.
- P3-C(1쪽이 넘칠 때 자동 줄이기)는 하지 않았습니다.
- 각주 들여쓰기는 전각 공백 2개의 근사입니다. 정확한 위치는 R3가 필요합니다.
