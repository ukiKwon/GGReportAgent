- **판정**
  - 약정 줄이 있고 KB(B02)가 없으면 FAIL이다(`TargetResultRules.java:49`).
  - KB 줄이 있으면 SUCCESS다. 직전 줄이 없으면 `priorWasKb`가 null이라 TARGET_TAG로 재유치/신규를 가른다(`:52-54`, `:86-97`).
  - 귀속 연도는 시작이 2027-01이므로 2026 목표에 속한다(`:13-14`, `:65`).
- **기대 숫자(2026)**: 목표 12, 협약 11(재유치 5·신규 6, 근거 TARGET_TAG), 타은행 유치 1(서울특별시), 달성률 11/12 = 91.7%.
- **알아둘 점**

  - 기관 종류별 순위 허용(`rankAllowed`)을 서울특별시(광역)의 FIRST에 대해 확인하지 못했다. 지금은 약정 화면에서 그 줄을 열었을 때만 영향이 있을 수 있다.

## 4. 적용·테스트
- 적용 명령(저장소 루트, 승인 뒤 호출자가 실행):
  `mysql -h localhost -P 3306 -u root -p --default-character-set=utf8mb4 ggreportdb < kgi-ggreport-web/tools/db/samples/104_target_result_user_1123_mysql.sql`
- 이 파일이 맨 앞에서 기존 `sample_104` 행을 지우므로 따로 되돌릴 필요가 없다. 도중에 실패해도 DELETE만 반영된 상태일 수 있으니, 다시 같은 파일을 실행하면 된다.
- 확인: 확인 쿼리 2개(기관별 들어감/건너뜀, 건수 12/12/0)를 본다. 그다음 화면 숫자가 목표 12·재유치 5·신규 6·타은행 유치 1·달성률 91.7%인지 본다.
- 서버 코드 변경이 없어 서버 테스트(`mvn -q -o test`)는 영향이 없다.

## 5. 보안·위험·되돌리는 법
- 로컬 MySQL 전용이고 번호 마이그레이션이 아니다. Oracle 쌍은 만들지 않았다(운영·Oracle에는 넣지 않는 파일).
- 서울특별시의 "타은행" 은행 이름은 미확인이라 `BANK_NAME_ETC`에 그대로 적었다. 사용자가 은행을 알려 주면 그때 바꾼다.
- 약정 시작·끝·순위는 가정값이다. 이 약정 줄은 금고 약정 화면에도 보이므로 확인이 끝나면 위 되돌리기 3문을 실행한다.
- 사용자가 준 12곳 외의 어떤 기관에도 행을 만들지 않는다. 실제 행이 있는 기관은 건너뛴다.
- 표본의 `EMP_VERIFIED=0`, 편집자명 '표본'으로 접근 이력·인증과 무관하다.
