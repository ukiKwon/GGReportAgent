영업팀장(비담당) 열람을 열었다. 쓰기 권한은 그대로다. 테스트는 실행하지 못했다(Bash 없음).

**바꾼 파일**
- `service/PrepService.java`
  - `canSee`(약 700줄): 영업부장에 더해 영업팀장도 모든 상태에서 `true`를 돌려준다. 그래서 OPEN_PENDING 상세·이력과 개설 뒤(IN_PROGRESS 이후) 상세·이력도 읽기 전용으로 열린다.
  - 개설 뒤 상세도 연 것은 지시대로 판단한 부분이다. 첨부만 열고 상세를 닫으면 화면에서 첨부에 닿을 길이 없다.
  - 이미 팀장을 따로 통과시키던 `isLead(me) ||` 두 곳(개설 전 확정 취소 건, 개설 뒤 중단 건)은 위에서 먼저 통과하므로 지웠다.
  - 목록의 `can_view`도 `canSee`를 쓰므로 팀장에게 `true`로 바뀐다.
  - viewer 플래그는 건드리지 않았다. 담당자 기준 `can_upload`·`can_check`·`can_uncheck`·`can_request_plan_approval`·`can_start_writing`은 팀장이 비담당이면 `false`다. 팀장 전용인 `can_cancel`(중단)과 `can_unconfirm`은 이전 그대로 팀장에게 유지된다.
- `service/PrepAttachService.java`
  - `requireViewer`: 영업팀장을 허용 역할에 추가했다. 목록과 내려받기가 이 판정을 같이 쓴다. javadoc도 고쳤다.
  - 무효 처리는 이미 팀장 허용이고 확정본은 409(`ATTACH_IN_USE`)여서 코드를 바꾸지 않았다. 업로드는 담당자만이라 그대로 403이다.
- `PrepApiTest`(개설 대기 신청자 읽기 전용 테스트, 783~)
  - 팀장 상세 404 단언을 200으로 바꿨다.
  - 추가한 단언: `state_cd`가 OPEN_PENDING, `can_withdraw_open`·`can_upload`·`is_assignee`가 `false`, 이력 200, 목록 `can_view`가 `true`, 체크 403.
- `PrepAttachApiTest`(비담당 테스트, 460~)
  - 팀장 내려받기 404 단언을 200으로 바꿨다.
  - 추가한 단언: 목록 200, 업로드 403, 체크 403.
  - 팀장의 무효 처리 200과 확정본 409는 기존 테스트(604~628줄)가 이미 확인한다.

**메인이 실행할 명령**
`cd kgi-ggreport-web && mvn -q -o test -Dtest=PrepApiTest,PrepAttachApiTest`
통과하면 전체 `mvn -q -o test`도 돌린다. 8080 서버가 같은 `target/`을 쓰면 테스트 뒤 재기동한다.
기대 결과는 전부 통과이고, 기존 건수 단언(HIDDEN 감사 건수 등)은 영향이 없다.

**벗어난 판단·이관**
- 개설 뒤 상세를 팀장에게 연 것은 위에 적은 대로다(지시에 따른 판단).
- 팀장 쓰기가 403인 것은 체크 서비스가 담당자 확인을 하는 것으로 보고 단언했고, 서비스 코드는 읽지 않았다. 실패하면 알려 달라.
- `[이관: 프런트]` 팀장이 보는 OPEN_PENDING 상세와 첨부 영역이 읽기 전용(`can_*`가 모두 `false`)으로 깨끗이 그려지는지 확인해야 한다. 이번 범위 밖이라 건드리지 않았다.
