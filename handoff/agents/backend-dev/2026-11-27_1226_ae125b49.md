## 보고: 발표 대본 금액 처리 보완

**상태:** 4가지를 고쳤습니다. 빌드와 시험은 돌리지 못했습니다. 에디터가 잠깐 낸 "cannot be resolved" 표시 두 건은 편집 순서 때문으로 보이며, mvn으로 확인이 필요합니다.

### 1. 고친 곳 (kgi-ggreport-web/src 아래)
- **BoardScriptFigures.java**
  - `labeledRaw` 도우미를 새로 만들었습니다. 칸의 글자를 그대로 돌려주고, `labeled`는 이를 `num`으로 감쌉니다.
  - 합계 칸은 `labeledRaw`로 읽습니다. 칸이 null이거나 공백일 때만 출연금+예비비+전산비로 대체 계산합니다.
  - 칸에 값이 있는데 숫자 모양이 아니면(`9.000`, `9.00 (1.00)`, `-`) null로 둡니다. 대본에는 〔확인 필요〕가 나옵니다.
- **ScriptDraftPrompt.java**
  - 새로 `facts(b, ask, amountMode)`를 만들었습니다. 기존 2인자 `facts`는 모드 null(TOTAL)로 넘깁니다.
  - `EXCL_IT`를 명시하면 `amountExclIt`을 싣고, 줄 이름은 "이사회 자료 승인 금액(출연금+예비비, 전산시스템 구축/운영비용 제외, 억원)"입니다.
  - 그 밖에는 `amountTotal`을 싣고, 줄 이름은 기존 "이사회 자료 승인 총 금액(표 합계, 억원)"입니다.
  - `boardSent`는 이제 실제로 실리는 금액이나 순이익이 있을 때만 true입니다.
- **ScriptDraftBasisReader.java:** `Basis.hasBoardFigures()`를 지웠습니다. 쓰는 곳이 프롬프트 한 곳뿐이었습니다.
- **PrepScriptService.java:** `amountMode(String)`을 private에서 패키지 공개로 바꿨습니다. 비움은 TOTAL, 모르는 값은 400 `amount_mode`인 규칙을 대본 본문과 같이 쓰려는 것입니다.
- **ScriptDraftService.java:** `prepare(me, bid, amountMode)` 오버로드를 추가했습니다. 기존 2인자 `prepare`는 null을 넘깁니다. 검증은 403 다음, 409 앞에서 합니다. 판정 순서는 404, 403, 400(amount_mode), 409, 503입니다.
- **PrepScriptDraftController.java:** `draft()`가 선택 쿼리 파라미터 `?amount_mode=`를 받아 `prepare`에 넘깁니다.

### 2. 시험 (추가한 것)
- **BoardScriptFiguresTest:**
  - 합계 `9.000`, `9.00 (1.00)`, `-`에 세 항목이 있으면 total은 null입니다.
  - 합계가 `""`나 공백이면 total은 9.00입니다.
- **ScriptDraftPromptTest:**
  - TOTAL이거나 모드가 없으면 `"9"`가 실리고 `"6"`은 없습니다.
  - EXCL_IT이면 `"6"`이 실리고 줄 이름에 "전산시스템 구축/운영비용 제외"가 들어갑니다.
  - `boardSent`는 선택한 기준의 금액이나 순이익이 있을 때만 true입니다.
- **ScriptDraftBasisReaderTest:** `boardSent` 경계를 확인합니다. 숫자가 없거나 선택 기준에 안 맞는 값만 있으면 false이고, 선택 기준의 금액이 있으면 true입니다. effect를 묻지 않으면 false입니다.
- **PrepScriptApiTest:**
  - 새 시험은 스냅샷 값을 출연금 5·예비비 1·전산비 3·합계 9로 바꿉니다.
  - amount_mode가 없으면 문서에 "9억원", `EXCL_IT`이면 "6억원", `X`이면 400 `amount_mode`입니다.
  - 합계 9인 건을 위해 기존 도우미로 `UPDATE BOARD_MATERIAL_SNAP`을 하고 `flushCache`를 부릅니다.

### 3. 메인이 돌릴 시험
```
cd kgi-ggreport-web
mvn -q -o test -Dtest=BoardScriptFiguresTest,ScriptDraftPromptTest,ScriptDraftBasisReaderTest,ScriptDraftServiceTest,ScriptDraftBasisReaderDbTest,PrepScriptApiTest,BoardScriptDocBuilderTest
```
- 기대 결과는 전부 통과입니다.
- `ScriptDraftPromptTest`는 Jackson pretty-print 모양(`"키" : "값"`)에 기대는 문자열 비교를 씁니다. 여기서 실패하면 시험 문구만 고치면 됩니다.
- 8080 서버가 같은 `target/`을 쓰면 시험 뒤 재기동이 필요합니다.
- 컨트롤러 시그니처를 바꿨으니 AI 초안 컨트롤러 시험이 있으면 함께 돌리십시오. 파일은 못 찾아 확인하지 못했습니다.

### 4. 지시와 다르게 판단한 것
- 지시한 파일 목록에 `PrepScriptDraftController.java`는 없었습니다. 초안 엔드포인트가 본문 없는 POST라 amount_mode를 받을 곳이 없어서 쿼리 파라미터를 하나 추가했습니다. 입력 DTO(`PrepScriptIn`)는 건드리지 않았습니다.
- `canViewCase` 판정은 건드리지 않았습니다.
- `Basis.hasBoardFigures()`를 지웠습니다. 이를 쓰는 다른 코드나 시험이 없는 것은 grep으로 확인했습니다.
- `amount_mode`가 잘못된 값이면 초안 API가 400을 돌려줍니다. 이 경우 컨트롤러가 `auditFailure`에 `PrepAudit.outcomeOf(400)` 결과를 남깁니다. 이 줄이 INVALID로 기록되는지는 확인하지 못했습니다.

### 5. 이관 메모
- **[이관: 프런트]** 화면이 AI 초안 호출 때 `POST /bidcases/{id}/prep/board-script-draft?amount_mode=EXCL_IT|TOTAL`로 사용자가 고른 기준을 보내야 합니다. 안 보내면 TOTAL로 동작하니 지금도 깨지지는 않지만, 사용자가 EXCL_IT를 골라도 초안에는 합계가 실립니다. 파일은 `frontend/js/…`이고 제가 만지지 않았습니다.
- **[이관: 데이터]** 이사회 자료 양식의 합계 칸 값이 `9.000` 같은 형식이면 이제 대본에 〔확인 필요〕가 나옵니다. 이는 사용자 결정(11-27 낮)에 따른 동작입니다.
