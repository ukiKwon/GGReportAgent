# 워드 출력 규격 적용(백엔드) — backend-dev-write (sonnet)

> 자동 보존본: 서브에이전트가 메인에 돌려준 최종 보고서를 대화 기록에서 그대로 옮겼다(2026-11-05 13:09 KST, agentId a8632e9244d7ec48c). 에이전트 출력이므로 사용자 결정이 아니다.

---

이사회 자료 워드(docx)와 표 모델을 규격대로 고쳤습니다. 빌드·테스트는 실행하지 못했습니다(Bash 없음). 메인이 `mvn -q -o test -Dtest='Board*'`로 확인해 주세요.

**고친 파일 (kgi-ggreport-web/src 아래, frontend/는 건드리지 않음)**
- `main/.../boarddoc/BoardDocSpec.java`
  - `Table`에 읽기 전용 `unit`을 추가했습니다. `getUnit()`과 `unitOf(id)`가 있고, 표 A·B·C-2·C-3은 "(단위: 억원)", C-4는 빈 문자열입니다.
  - 표 id로만 정해지므로 `build`와 `withValues`로 표를 다시 만들어도 값이 유지되고, 사용자 입력으로는 바뀌지 않습니다. 생성자 시그니처는 그대로입니다.
  - 상수 `UNIT_EOK`도 추가했습니다.
- `main/.../boarddoc/BoardDocDocx.java`
  - A4 세로(`pgSz` 11906×16838, 여백 상하좌우 1134)를 넣었습니다. 본문폭은 9638입니다.
  - 표는 `tblLayout fixed`, `tblW` DXA 9638, `tblCellMar` 좌우 60으로 했습니다.
  - `gridCol`은 표별 비율대로 만들고, 각 칸의 `tcW`는 걸친 열 너비의 합으로 넣었습니다. 열 수가 다른 표와 모르는 id는 균등 분배입니다. 마지막 열이 나머지를 받아 합이 항상 9638입니다. 로직은 `gridWidths(id, cols)`입니다.
  - 모든 행에 `cantSplit`, 0번 행에 `tblHeader`를 넣었습니다. 머리칸 음영은 F2F2F2입니다.
  - 표 제목 문단은 `keepNext`입니다. unit이 비어 있지 않으면 제목 아래·표 위에 9pt 오른쪽 정렬 `keepNext` 문단을 출력합니다.
  - `build(doc, boolean sampleNotice)`를 추가했습니다. true면 문서 제목 바로 아래에 "샘플 — 표의 수치는 가상 예시입니다."를 9pt, 색 595959, 아래 간격 6pt(120)로 넣습니다.
  - 기존 `build(doc)`은 안내문 없이 그대로 동작합니다. `BoardWriteController`의 draft-docx가 이걸 쓰므로 작성 모드에는 안내문이 안 들어갑니다. 문서 제목 "(기본 양식)"은 그대로 뒀습니다.
- `main/.../service/BoardFormService.java`: `catalog()`의 items와 `detail()`의 tables JSON에 `unit`을 추가했습니다.
- `main/.../web/BoardDocController.java`
  - 안내문은 `values`가 blank가 아닐 때만 넣습니다.
  - 파일명은 이미 `이사회자료_기본양식_샘플.docx` 형태여서 바꾸지 않았습니다.
  - `/board-docs/{id}` 응답은 `Table`을 Jackson으로 직렬화하므로 `getUnit()`만으로 `unit`이 나갑니다.
- `main/.../web/BoardFormController.java`: 파일명 접미사를 샘플이면 `_샘플`, 빈 양식이면 `_빈양식`으로 바꿨습니다. 예전에는 샘플에 접미사가 없었습니다. 안내문은 `build(doc, sample)`로 넣습니다.
- 테스트
  - `BoardDocDocxTest`
    - 새로 5건: sectPr 값(11906/16838/1134), 5개 표의 `gridCol` 비율·합 9638·fixed·셀 여백 60·`cantSplit`·`tblHeader`(0행만)·F2F2F2, 단위 문단(4개, 오른쪽·9pt·`keepNext`, 앞 제목도 `keepNext`), 안내문 on/off(595959·9pt·spacingAfter 120), 균등 폴백.
    - 시각 확인용 샘플 쓰기 테스트는 `build(doc, sample)`로 바꿨습니다.
  - `BoardDocSpecTest`: 새로 1건. 표별 unit, 제목에 "단위"가 없는지, `build`/`withValues` 뒤에도 유지되는지 봅니다.
  - `BoardDocApiTest`: `/board-docs` 응답에서 표 A·B·C-2·C-3의 `unit`이 "(단위: 억원)", C-4는 ""인지 확인합니다. docx 파일명이 `_샘플.docx`로 끝나는지도 확인합니다.
  - `BoardFormApiTest`: 샘플 docx는 문단 1이 안내문, 2가 표 제목, 3이 단위로 바뀌었습니다. 이 기존 단언(문단 1→2)을 고쳤습니다. 파일명이 `_샘플.docx`로 끝나는지, `values=blank`에는 안내문이 없는지도 확인합니다.

**메인이 실행할 명령**
- `cd kgi-ggreport-web && mvn -q -o test -Dtest='Board*'`
- 기대: 전부 통과합니다. DB 변경은 없습니다.
- 눈으로 보려면 `target/boarddoc-samples/default_doc_샘플.docx`를 Word로 열어 보세요. 안내문, 단위 줄, 열 비율, 머리행 음영이 보여야 합니다.

**확인이 필요한 점 (컴파일 전)**
- 컴파일해 보지 못했습니다. 중간에 IDE 진단이 `STTblLayoutType`·`CTTblCellMar`·`XWPFTableRow`·`CTTrPr`를 못 찾는다고 떴는데, 그 시점에 import를 추가하기 전이라 낡은 진단으로 보입니다. import는 추가했습니다.
- POI 5.2.3의 `setW`는 `Object`를 받아서 `BigInteger`로 넘겼습니다. 컴파일 오류가 나면 이 부분부터 보세요.
- 테스트의 `gridCol` 값은 `String.valueOf(...getW())`로 읽습니다.

**지시와 다르게 판단한 것**
- `BoardDocController`의 docx 파일명은 이미 `_샘플`로 끝나서 그대로 두었습니다.
- 안내문 여부는 `build`에 boolean 오버로드를 추가해 전달했습니다. `Doc` 모델에는 sample 필드를 넣지 않았습니다.
- `unit`은 생성자 인자가 아니라 id로 계산합니다. 그래서 `BoardFormJson`·`BoardFormService`의 표 재구성 경로를 고칠 필요가 없었습니다.

**이관 메모**
- [이관: 프런트] `/board-docs`, `/board-forms` 응답의 표에 `unit`이 생겼습니다. 화면 표 제목 옆이나 아래에 표시하는 건 프런트 몫입니다. 제목에 "(단위...)"를 붙여 쓰고 있었다면 중복 표시를 확인해야 합니다.
- [이관: 기획] docx 제목 "(기본 양식)"은 미정이라 그대로 뒀습니다.
- [이관: 기획] 표 B 머리행의 가로 병합 칸 등 병합 셀이 걸친 열 너비는 합산해서 `tcW`로 넣었습니다. Word에서 보고 비율이 어색하면 비율표(`pct`)만 조정하면 됩니다.
