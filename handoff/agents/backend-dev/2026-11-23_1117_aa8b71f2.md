S1~S3 적용을 마쳤다. mvn은 돌리지 않았다.

**S1. BidTargetSettings.java**
- 19~20행: 주석을 "코드 기본값은 둘 다 true … 끄려면 approval.enabled=false · carry.enabled=false(되돌리기 스위치)"와 "(화면 적용 커밋에서 true 로 바꿨다 …)"로 바꿨다.
- 21~22행: `approval.enabled:false`를 `true`로, `carry.enabled:false`를 `true`로 바꿨다.
- 9~10행의 클래스 설명은 이미 올바른 내용이라 그대로 뒀다.

**S2. BidTargetApiTest.java**
- 43행: `@After 결재_스위치_복구`가 `setApprovalRequired(true)`로 복구하도록 바꿨다. 주석도 "(true)"로 고쳤다.
- 42행 `@Before`의 `setApprovalRequired(false)`는 일부러 끄는 줄이라 그대로 뒀다.

**S3. TargetChangeApiTest.java**
- 48행: `@Before` 주석을 "코드 기본값은 둘 다 true — 이 시험은 켠 상태가 바탕(명시)"으로 바꿨다.
- 53~54행: `@After 설정_복구`가 `setApprovalRequired(true)`, `setCarryEnabled(true)`로 복구하도록 바꿨다.
- 396행(`setCarryEnabled(false)`)과 403행(`setApprovalRequired(false)`)은 시험 안에서 일부러 끄는 줄이라 건드리지 않았다.

**메인이 실행할 것**
- `cd kgi-ggreport-web && mvn -q -o test`를 돌린다. 범위를 줄이면 `-Dtest=BidTargetApiTest,TargetChangeApiTest`.
- 기대 결과는 전체 통과다.
- `BidTargetApiTest`는 `@Before`에서 결재를 끄므로 단건 쓰기 시험이 그대로 통과해야 한다.
- 다른 클래스는 `settings`나 `/bid-targets` 단건 쓰기를 쓰지 않는다. 그래서 공유 컨텍스트가 기본값 true로 복구되는 것이 안전하다.

**참고**
- 편집 도구의 진단에 `BidTargetApiTest` 417행의 `queryForObject` null 가능성 경고가 떴다. 기존 코드 경고이고 이번 변경과는 무관하다.
- 로컬 `config/application.properties`에 `approval.enabled=false` 같은 값이 있으면 그 값이 코드 기본값을 덮는다. 켜 둔 상태를 확인하려면 이 키를 점검한다.
