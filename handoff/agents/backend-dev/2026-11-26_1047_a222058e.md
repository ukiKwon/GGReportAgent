## 2. 보안 검토 ① 네 건 반영 위치

- **(상) 확정 자료 감사**
  - 컨트롤러가 `run()`에 넘기는 람다 안에서, 서비스(읽기 전용 트랜잭션)가 끝난 뒤 `boardAudit.record(boardAudit.before(자료번호), "SCRIPT_DOCX", "OK", actor, BoardUiIds.of(req, ACT_SCRIPT_DOCX))`를 씁니다. 기존 `confirmedDocx`와 같은 `BoardMaterialAudit.record` 방식입니다.
  - 감사 쓰기가 실패하면 BID_PREP_ACT에 ERROR가 남고 500입니다. 파일은 나가지 않습니다(fail-closed).
  - 근거는 접근 이력(ACCESS_LOG.DETAIL) 끝에 `board=<자료번호|-> snap=<판|-> form_ver=<요약양식 판|-> draft=Y|N`으로 붙습니다. 숫자와 Y/N뿐입니다. BID_PREP_ACT 칸에는 새 값이 없습니다.
  - BOARD_MATERIAL_ACT는 확정(CONFIRMED) 자료를 실제로 골랐을 때만 씁니다. 확정 전 자료나 볼 수 없는 사람에게는 줄이 없습니다.
- **(중) 요약 양식 열람**
  - `PrepFormService.canReadForm`을 통과한 사람에게만 staff·budget·current_bank·effect를 채웁니다. 아니면 〔확인 필요〕 괄호이고 `form_ver=-`, 초안(Y)입니다.
  - 기관명은 `p.getInstitutionName`이 먼저고, 양식은 보조 출처일 뿐입니다.
- **(하) forScript**
  - 일반 `PrepUiIds.BUTTONS`에는 넣지 않았습니다. `forScript(req)`만 `prep_detail/script_docx`를 유효로 칩니다.
- **(하) 약정 시작일**

  - 자료가 있으면 그 `BOARD_YEAR`와 같은 목표 연도의 SAVE 행만 씁니다.

## 5. 화면(frontend-dev)이 알아야 할 API 계약

`POST /bidcases/{bid_case_id}/prep/board-script-docx`
- **요청 머리글**: `X-Emp-No`, `X-Screen-Id: prep_detail`, `X-Button-Id: script_docx`.
  - 이 짝이 아니면 파일은 받지만 감사 줄이 UNKNOWN·ui_valid=0이 됩니다. 400으로 거절하지는 않습니다.
- **본문**: JSON이며 생략 가능합니다. 키는 모두 선택이고 모르는 키는 무시합니다.
  - `meeting`: `BOARD`(기본) 또는 `COMMITTEE`. 한글 "이사회"·"출연금심의위원회"도 받습니다.
  - `round`: 숫자 1~3자리.
  - `agenda_no`: 30자 이내. 쓴 그대로 "의안번호 …"에 들어갑니다.
  - `speaker_dept`: 40자 이내. 시스템에 소속이 없어 손 입력만 받습니다.
  - `speaker_name`, `speaker_title`: 각 30자 이내. 비우면 내려받는 사람의 이름·직위가 기본입니다.
  - `term_years`: 정수 1~30.
  - `review_when`: 40자 이내. 쓴 그대로 문장에 들어가므로 예시를 "10월 중"처럼 '중'까지 쓰게 안내합니다.
  - `accounting`: 40자 이내. 기본은 무형자산입니다.
  - `amount_mode`: `EXCL_IT`(출연금+예비비, 기본) 또는 `TOTAL`(표 A 합계).
  - 여러 줄 칸 `intro`, `status_note`, `effect`, `profit_note`: 줄바꿈으로 나눕니다. 12줄, 줄당 300자, 합계 1,000자 이하입니다.
  - 본문은 32KB를 넘으면 413 BODY_TOO_LARGE입니다.
- **성공 200**: 본문은 docx 바이트입니다.
  - `Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document`
  - `Content-Disposition: attachment; filename="board_script.docx"; filename*=UTF-8''…` (한글 파일명은 `발표대본_기관명[_초안]_YYYYMMDD.docx`)
  - `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`
  - **`X-Script-Draft: Y|N`**: Y면 제목에 "[확정 전 초안]"이 붙습니다. 이사회 자료나 요약 양식 중 하나라도 확정이 아니면 Y입니다. 화면에서 안내 한 줄에 쓰면 됩니다.
- **오류**
  - 400 `{"detail":{"code":"BAD_VALUE","key":"<칸 이름>","message":…}}`: 입력값은 싣지 않습니다. `key`는 위 snake_case 칸 이름입니다.
  - 401: 사번 없음.
  - 403: 비활성·미등록 사번.
  - 404: 사전준비를 볼 수 없는 사람이나 없는 건. 구별하지 않습니다.
  - 413 BODY_TOO_LARGE.
- **빈 자리 표시**: 시스템이 모르는 값은 `〔… 확인 필요〕`, 사람이 안 쓴 칸은 `〔… 입력 필요〕`로 나옵니다. 숫자는 지어내지 않습니다.
- **정보 노출 범위**
  - 이사회 숫자(승인 금액·순이익·연도·약정 시작일)는 담당자와 영업부장에게만 채워집니다. 영업팀장 등은 〔이사회 자료 없음 — 확인 필요〕가 나옵니다.
  - 요약 양식 값은 양식을 볼 수 있는 사람(담당·영업팀장·영업부장·배정된 디자이너)에게만 채워집니다.
  - 화면에서 "왜 비었는지"를 안내하려면 이 두 규칙을 문구에 반영해야 합니다.
- 별도의 "현재 값 조회" GET은 만들지 않았습니다. 필요하면 요청해 주세요.
