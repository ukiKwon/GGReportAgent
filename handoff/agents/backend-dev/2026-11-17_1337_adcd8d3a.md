NEXT 90 2단계 Java 쪽을 지시서대로 적용했습니다. 빌드와 테스트는 못 돌렸으니 메인이 mvn으로 확인해야 합니다. 경로 기준은 kgi-ggreport-web/src/{main,test}/java/com/kbstar/kgi/ggreport/web/ 입니다.

1. 고친 파일
- support/BatchSchema.java: 상수 EXTCHECK_PREFIX(약 237줄)를 추가했습니다. hasChecks를 한 번만 계산하고, batch_id에 extcheck 포함 검사와 slug가 extcheck로 시작하는지 검사를 넣었습니다. manifest 읽기 실패 문구는 고정했습니다.
- support/Pii.java: SEP_RUN_EXT를 [...]++로 바꿔 구분자 한 글자도 접습니다(39~42줄). 주민·카드 검사(약 212줄)도 fold(text, true, SEP_RUN_EXT)를 씁니다.
- service/ExtCheckInspector.java:
  - 이미지 수를 countImages와 countInline으로 셉니다. Form XObject 안과 인라인(BI) 이미지까지 보고, 링크 주석의 URI도 검사합니다.
  - HWPX에서 허용 목록 밖 항목은 UNSUPPORTED_ENTRY로 거부합니다. Preview 그림은 허용합니다.
  - sha256Hex와 한컴 빈 틀 상수 4개(HWPX_*, 주석에 "한컴 기본 빈 틀(UTF-16LE, 실물 공고 6건 확인 2026-11-17)")를 추가했습니다.
- service/InboxService.java: log와 withOriginalsDeleted를 추가하고 importExternalChecks를 교체했습니다. 모든 실패 응답의 detail에 originals_deleted가 들어갑니다. 원본이 남으면 배치를 batches로 옮기지 않고 inbox에 두며 log.error만 남깁니다.
- 시험 5개에 지시서 케이스를 더했습니다.
  - BatchSchemaChecksTest: run을 runAs로 일반화했습니다.
  - PiiExternalTest
  - ExtCheckFixtures: pdfFormImage, pdfInlineImage, pdfLinkUri를 추가했습니다.
  - ExtCheckInspectorTest
  - InboxExtCheckApiTest: Windows 전용 "원본 못 지움" 시험을 포함합니다.

2. 메인이 실행할 명령
cd kgi-ggreport-web
mvn -q -o test -Dtest=PiiExternalTest,PiiTest,BatchSchemaChecksTest,ExtCheckInspectorTest,InboxExtCheckApiTest
mvn -q -o test
기대 결과는 전부 통과입니다. Windows 전용 시험은 Windows가 아닌 환경에서 건너뜁니다.
pdfbox API 불일치는 컴파일에서 날 수 있습니다. 후보는 PDFStreamParser(PDContentStream), PDAppearanceStream용 PDPageContentStream, PDStream.createOutputStream(COSName), PDAnnotationLink.setAction입니다. 컴파일되지 않으면 해당 메서드만 고치면 됩니다.

3. 지시와 달리 판단한 것
- Scripts 예외:
  - 이름이 정확히 Scripts/headerScripts.js 또는 Scripts/sourceScripts.js이고 원본 sha256이 같을 때만 허용합니다. 허용하면 검사하지 않고 그대로 보관합니다.
  - 이름 비교는 대소문자를 구분합니다. scripts/...처럼 소문자면 SCRIPT로 거부합니다.
  - sha256 계산을 위해 이 두 항목은 drain에서 바이트를 보관합니다.
- Scripts 허용 쪽 양성 시험은 없습니다. 실물 fixture sunchang_32708.hwpx를 검색했더니 Scripts 항목이 없었습니다(mimetype 검색은 잡혀서 바이너리 검색 자체는 동작함). 빈 틀의 실제 바이트를 몰라 코드로 만들 수도 없었습니다. 시험은 거부 쪽만 있습니다. 내용이 다른 headerScripts.js/sourceScripts.js, 다른 이름 other.js, 소문자 scripts/가 SCRIPT로 거부되는지 봅니다. Scripts가 든 실물 HWPX 한 건이나 그 바이트를 주시면 양성 시험을 더할 수 있습니다.
- 실물 fixture 시험을 추가했습니다. ../collector/tests/fixtures/eminwon/sunchang_32708.hwpx를 읽고, 파일이 없으면 건너뜁니다. 통과 조건은 hit이 모두 PII_* 또는 IMAGE_ONLY뿐인 것입니다.
- bmp는 IMAGE_EXT에 이미 있어 추가하지 않았습니다. BinData/image1.bmp가 통과하는 시험을 넣었습니다.
- 4xx 실패 시험은 asBoolean(true) 기본값을 써서 originals_deleted 키가 없으면 실패하게 했습니다.

4. 이관 메모
- [이관: 메인] contract/batch_schema.py와 collector/에도 같은 규칙(slug·batch_id·고정 문구)을 같은 커밋에 넣어야 합니다. 한쪽만 먼저 들어가면 collector가 만든 배치를 망 안이 거부합니다.
- [이관: 데이터] SCHEMA.md 문구와 UNSUPPORTED_ENTRY 사유 코드 문서화가 남아 있습니다.
- [이관: 백엔드] 아직 반영하지 않은 것: records 쪽 오류 문구의 값 에코, security 하-8·하-9.
- checks 반입 경로의 500 응답 detail이 문자열에서 {code, message, originals_deleted} 객체로 바뀝니다. 이 경로를 호출하는 화면은 찾지 못했습니다.
