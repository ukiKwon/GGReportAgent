## 2. 요구·원인 요약
- 지금 무효 권한은 입력자(CREATED_BY)만 봅니다 — `HeadRules.java:64-67`. 호출하는 곳은 `InstitutionHeadService.java:942`(칸)과 `HeadPhotoService.java:257`(사진)입니다.
- **확정자(DECIDED_BY)를 채우는 곳** — 지시 ①을 실제 흐름으로 확인했습니다.
  - 등록이 곧 확정인 경우(현 기관장이 없거나 빈 머리): `newItem`이 CONFIRMED면 `decidedBy = me`(`:322-325`). 머리도 `:706-709`에서 같습니다.
  - 칸 입력이 곧 확정인 경우(빈 칸, 학력·경력, 같은 값 재확인): `:806-810`에서 `decidedBy = me`.
  - 정리하면 **본인이 입력해 곧바로 확정된 값은 입력자와 확정자가 같습니다. 새 규칙에서도 본인이 무효할 수 있습니다.**
  - 후보 칸 확정: `mapper.confirmItem(itemId, me, now)`(`:865`, SQL `xml:174-177`)로 확정자 = 누른 사람.
  - 후보 머리 확정: `confirmItemsOfHead(headId, me, now)`(`:1017`, `xml:194-197`)로 그 머리의 칸 전부 확정자 = 누른 사람.
- **새로 찾은 우회(이번 패치에 넣음)**: 같은 값을 다시 입력하면 남이 확정한 값이 "내 값"이 됩니다.
  - 경로 1: L1이 확정한 직위 "구청장"을 T2가 같은 값으로 다시 입력합니다. `:798-799`에서 바로 확정되고 앞 행은 대체(SUPERSEDED)되며, 새 행은 입력자 = 확정자 = T2입니다. T2가 그 행을 무효하면 팀장 없이 값이 지워집니다.
  - 경로 2: 같은 값의 반입 후보를 반입자가 직접 확정하는 경우도 같습니다(`:853` 충돌 없음 → `:859-865` 대체).
  - 확정자 조건만 넣으면 이 길이 남습니다. 그래서 **같은 값 재확인은 앞 값의 확정자를 이어받게** 했습니다. 확정자를 그대로 두는 단순한 방식이고, 실제로 누른 사람은 INST_HEAD_LOG·INST_HEAD_ACT에 남습니다. 지시서에 없던 제 판단이니 빼려면 (3)과 (4)를 덜어 내면 됩니다.
- **화면 판정**: 서버에는 무효 버튼용 판정이 없고, 상세 응답에 `decided_by`도 없습니다(`itemMap` `:209-222`, 단일 칸 `:562-568`). 화면은 `headcard.js:509-511`의 `hc.canVoid(created_by, viewer_role, emp)`로 직접 판단합니다. 그래서 **서버가 `can_void`를 내려 주는 방식**으로 설계했습니다.
- **거절과 감사**:
  - 서비스가 403을 던지면 `run()`이 INST_HEAD_ACT에 **DENIED**를 남기고(`Controller:398-406`, `HeadAudit.outcomeOf` 403→DENIED), ACCESS_LOG에도 `head NOT_OWNER` 고정 코드만 남깁니다.
  - **BLOCKED는 409 전용**이라 이 경로와는 상관없습니다. 새 코드는 만들지 않고 `NOT_OWNER`를 그대로 씁니다(화면의 사유 문구 표도 그대로 씀).

## 5. 보안·위험·되돌리는 법
- **권한 검사 순서**: 기관 잠금 → 칸·머리 404/409 → `canVoid` 403 NOT_OWNER → OWN_VALUE_GUARD 403.
  - 403이면 INST_HEAD_ACT에 DENIED, ACCESS_LOG에 `head NOT_OWNER` 고정 코드만 남습니다. 이유·값은 넣지 않습니다.
  - INST_HEAD_LOG는 성공한 처리만 기록하므로 403이면 남지 않습니다(테스트로 확인).
- **자기신고 인증의 한계**: 사번·역할이 `X-Emp-No` 자기신고라서 누구든 "영업팀장"을 자칭하면 이 규칙을 넘을 수 있습니다. 이 패치는 업무 규칙을 맞추는 것이지 사칭을 막는 것이 아닙니다(기존과 같은 전제).
- **남는 경로(사용자 결정 범위 안)**:
  - A가 직접 입력해 바로 확정한 값만으로 된 머리는 A가 혼자 비울 수 있습니다. 비우고 나면, 팀장 결정을 기다리던 B의 후보 기관장이 충돌이 아니게 되어 B 본인이 확정할 수 있습니다(security ⓑ의 남은 절반).
  - "본인이 입력하고 본인이 확정한 값은 본인이 무효"라는 결정 안의 일이라 막지 않았습니다.
- **알려진 대가**: 충돌이 없는데 다른 영업팀원이 확정해 준 본인 값도 팀장에게 무효를 부탁해야 합니다(security가 말한 대가 그대로).
- **DECIDED_BY 뜻이 조금 바뀜**: 같은 값을 다시 확인한 행에서는 DECIDED_BY가 "값을 처음 확정한 사람"입니다. 실제로 누른 사람은 INST_HEAD_LOG(ITEM_ADD·ITEM_CONFIRM·ITEM_SUPERSEDE의 ACTOR)와 INST_HEAD_ACT에 남습니다. 감사 원칙(누가·어느 화면·어느 버튼)은 그대로 지켜집니다.
- **되돌리는 법**: 코드 커밋 하나만 되돌리면 됩니다(DB 변경 없음). 이미 쌓인 데이터 중 되돌린 뒤에도 남는 것은 두 가지뿐입니다.
  - 같은 값 재확인 행의 DECIDED_BY에 이어받은 확정자가 남습니다.
  - HEAD_VOID·HEAD_MERGE 행의 REASON 코드가 남습니다.
  - 둘 다 이전 코드가 읽어도 문제가 없습니다.
