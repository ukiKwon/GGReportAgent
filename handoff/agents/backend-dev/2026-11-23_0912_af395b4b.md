```java
        assertEquals("FAIL", report(Y - 1).path("items").get(0).path("result_cd").asText());
        JsonNode now = report(Y);
        assertEquals(0, now.path("summary").path("target_n").asInt());
        assertEquals(0, now.path("summary").path("removed_n").asInt());
        assertEquals(0, now.path("items").size());
    }
```
- `target_no`가 items에 없으면 단언 두 줄만 `items.size()`나 `result_cd`로 바꾸면 된다.
- CANCEL 뒤 `report(Y)`는 NOT SUCCESS만 단언했다. PENDING/UNREGISTERED는 공고 근거에 따라 갈려 고정하지 않았다.

### 시험 9 (제안만 — ResultYearRulesTest는 fa 소유)
- 두 해의 기록 날짜가 완전히 같으면 추정으로 간다.
  - 입력: starts {2026:"2027-03-01", 2027:"2027-03-01"}, termFrom "2027-03-01".
  - 기대: `yearOf` = `targetYearOf` = 2027.
- P3-5 기대값은 기획 결정 뒤에 고정한다.
  - 입력: termFrom "2027"(연도만), starts {2026:"2027-03-01"}.
  - 현재 코드(ResultYearRules:22 `startsWith`)는 2026을 돌려준다.
  - "월을 모르면 추정 없음" 원칙이면 null이어야 한다.

## 5. 보안·위험·되돌리는 법
- DB 스크립트·API 응답 계약·권한 검사는 바뀌지 않는다. 마이그레이션은 없다.
- P3-2 비용: 이른 날짜 파일도 이제 읽는다.
  - 상한은 그대로 유효하다: 최신 100개, 64MB, 20초, 파일당 5MB.
  - 확인 한 번의 최악 비용은 이전과 같다. 이전에는 OLDER 파일이 예산을 쓰지 않았지만 이제는 쓴다. 그래서 오래된 파일이 많은 폴더에서 NOT_CHECKED가 더 일찍 나올 수 있다.
- P3-3: 폴더 반입의 감사 기관ID는 정식 표기이거나 NONE이다. 파일 이름에서 온 값이 감사에 남지 않는다.
- **같은 취약점이 `importUpload`에도 남아 있다(범위 밖, 제안)**.
  - 106행 `instId = canonicalId(instId)`가 던지면 URL 경로 변수의 원래 값이 117행 `failed()`로 감사에 들어간다. `validId`만 통과하면 그대로 기록된다.
  - 같은 방식(`String inst = null` 후 성공 시 대입)으로 고치면 된다. 이 패치에서는 건드리지 않았다.
- P3-4: 성공률 분모(성공+실패)에는 영향이 없다. 분류 칩만 미등록에서 대기로 바뀔 수 있다. 올해 + 공고 종료 근거(bidClosed)는 개시일 전이어도 ended를 유지한다. 이 부분은 시험으로 고정했다.
- 접근 이력: 변경 없음. 경로·이름·쿼리값은 여전히 안 싣는다.
- 인증은 X-Emp-No 자기신고다. 이 패치는 권한 규칙을 바꾸지 않는다.
- 되돌리기: 파일별 revert로 된다. 3-1은 inspect 한 블록과 importFile 몇 줄, 3-2는 생성자 오버로드, 3-3은 `ended` 한 줄과 헬퍼다.
