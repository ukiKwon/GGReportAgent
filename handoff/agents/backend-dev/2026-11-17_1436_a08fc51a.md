    static boolean cancelRule(String actionCd, String firstEmpNo, String empNo, boolean lead) {

    }
}

## 5. 보안, 위험, 되돌리는 법
- 사번은 계속 응답에 싣지 않는다. 비교는 서버 안에서만 하고 boolean만 내보낸다. 이를 시험에서 raw 문자열에 사번이 없는지로 확인한다.
- 권한 경계는 여전히 서버 403이다(`cancel()`에서 canChangeLine). can_cancel은 화면 표시용일 뿐이다. 옛 화면이나 조작된 요청이 와도 403 경로와 DENIED 이력은 그대로다.
- 응답값과 실제 403이 같은 판단을 내리는 근거:
  - 두 경로가 같은 `cancelRule`을 쓴다.
  - canEdit 조건도 컨트롤러 `requireEditor`와 맞췄다.
  - 처음 입력자 사번의 출처가 조인값과 `selectFirstEditor`로 다르지만, 둘 다 같은 REV_NO=1 행이다.
- 자기신고의 한계: 요청자는 `X-Emp-No` 자기신고 Actor라서 can_cancel은 신고된 사번 기준이다. 사칭을 막는 장치가 아니다.
- 접근 이력: 컨트롤러 DETAIL(`n=` 건수)을 바꾸지 않았으므로 새 정보가 기록에 들어가지 않는다.
- 성능: 조회 1회당 USERS 조회가 lead 판정용으로 최대 1회 늘어난다(줄 수와 무관).
- 되돌리는 법: 서버는 3-1 되돌리기만 하면 되고 DB 변경이 없다. 화면은 3-2를 되돌리면 이름 비교로 돌아간다. 서버와 화면은 서로 폴백하므로 따로 되돌려도 된다.
