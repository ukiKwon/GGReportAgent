**빼는 순서 키 `dropKey`**
- 시작(from)이 있으면 from, 없고 끝(to)만 있으면 to, 둘 다 없으면 "" 로 한다. 문자열 사전순 비교라 '2010' < '2010-03' 이 되어 연도만 값도 안전하다.
- 가장 작은 키가 가장 오래된 것이다. 키가 같으면 표에서 더 아래 줄을 먼저 뺀다.
- 날짜 없는 줄은 키가 ""이므로 맨 먼저 빠진다. 이것은 내 가정이고 기획 확인 대상이다(이관 메모).

```java
// (D) 새 헬퍼 — sortKey(472행) 아래에 추가
private static List<String> contentsOf(List<Map<String, Object>> items) {
    List<String> out = new ArrayList<String>();
    for (Map<String, Object> it : items) { out.add(str(it.get("value"))); }
    return out;
}

/** 시작 년-월 기준 가장 오래된 줄의 위치. 시작이 없으면 끝, 둘 다 없으면 "" (가장 먼저 뺀다). 같으면 표에서 더 아래 줄. */
static int oldestIndex(List<Map<String, Object>> items) {
    int best = 0;
    String bestKey = dropKey(items.get(0));
    for (int i = 1; i < items.size(); i++) {
        String k = dropKey(items.get(i));
        if (k.compareTo(bestKey) <= 0) { best = i; bestKey = k; }
    }
    return best;
}

private static String dropKey(Map<String, Object> it) {
    String from = str(it.get("from")).trim();
    return !from.isEmpty() ? from : str(it.get("to")).trim();
}
```

추가 테스트(HeadDocBuilderFitTest에 단위, InstitutionHeadDocxApiTest에 API):
1. 경력 30줄(from 2000-01…2029-12 등 서로 다른 값)에 학력 2줄, 사진 없음: `buildDoc` 후 `careerDropped() > 0`이고 `estimateMm(0,…)` ≤ 247이다. 남은 줄 중 가장 오래된 시작이 빠진 줄들의 시작보다 늦거나 같다. 렌더 텍스트에 가장 오래된 값은 없고 가장 최근 값은 있다.

## 5. 보안·위험·되돌리는 법
- 새 머리는 고정된 숫자만 담는다. 사용자 입력은 새로 받지 않는다.
- 추정식이 실제 Word 쪽 수와 어긋나면 불필요하게 많이 빼거나 여전히 2쪽이 될 수 있다. 이 위험이 더 커진 것은 아니다. 불필요하게 많이 빼는 쪽은 예산 247mm를 낮추는 식으로 보수적으로 조정한다.
- 되돌리기: (B)의 while 블록만 지우면 이전 동작이다. 머리 두 줄을 지워도 화면은 정상이다(머리가 없으면 안내만 빠진다).
