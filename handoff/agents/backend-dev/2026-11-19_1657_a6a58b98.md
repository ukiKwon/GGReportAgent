## 3. 설계와 다르게 판단한 것 (숨기지 않음)
1. **Ctx에 머리를 싣고 지연 생성한다.**
   - `BoardMinutesAudit.Ctx`에 `head`를 넣었고, 컨트롤러는 `Supplier<Ctx>`로 받는다.
   - 기능이 꺼져 있으면 DB를 읽기 전에 404를 낸다.
   - `Call`(me, head, decision, ctx, actor)을 서비스에 넘긴다.
2. **매퍼 문장을 하나 더했다.** `selectUtterIndex`는 CLOB 본문 없이 번호·화자·시각만 읽는다. 상세의 구간 연결 계산에 쓴다.
3. **미리보기 응답에 `transcript`(가린 발언 목록)를 더했다.**
   - 설계는 "상세와 같은 모양 + stats·masked·warnings·name_candidates·preview_digest"였다.
   - 가림 결과를 눈으로 확인하려는 미리보기 목적에 맞춰 넣었다.
   - 업로더에게만 나가고 이름 후보는 설계대로 포함된다. 보안 판단은 `security`에 넘긴다.
4. **응답 모양 보강.**
   - 구간·항목의 `items`는 `{item_no,text,edited}` 객체다(번호로 수정하려면 필요).
   - `viewer`에 `can_view_history`와 `can_scope_edit`를 더했다.
   - 목록 응답에 `truncated`를 더했다.
5. **새 오류 코드**(설계 목록 밖): `MEETING_DATE_INVALID`(422), `REV_NO_REQUIRED`(400), `FIELD_INVALID`(400), `BAD_REQUEST`(400). 제목이 100자를 넘어도 `TITLE_REQUIRED`(422)다.
6. **오류 검사 순서.**
   - multipart 구조 오류(`TOO_MANY_PARTS`, `OPTIONS_INVALID`)는 호출자 확인과 UI 식별자 확인 뒤, 서비스 호출 직전에 낸다.
   - 서비스 안에서는 파일 크기·확장자를 옵션 검사보다 먼저 본다. 그래야 `NOT_TXT`, `EMPTY_FILE`을 확인하는 시험이 옵션 값에 걸리지 않는다. 바이트는 자격 확인 뒤에 읽는다.
7. **필터는 `enabled=false`이면 `no-store`만 붙이고 크기 검사를 건너뛴다.** 404는 컨트롤러가 낸다.
8. **VIA 기록.** 미리보기·업로드의 성공 한 줄은 `WRITER`, 실패는 `NONE`이다.
9. **감사 열람 응답 코드.** 볼 수는 있으나 감사 열람 권한이 없는 사람(DEFAULT·UPLOADER·GRANTEE)은 403이다. 아예 못 보는 사람은 404이고, ADMIN과 삭제된 건의 HEAD는 200이다.
10. **공개범위 목록 열람.** `GET /scope`는 부장급과 영업팀장(DEFAULT)만 열린다. 등록자와 개인 공개받은 사람이 부르면 403이다.
11. **`ALREADY_DEFAULT` 판정 위치.** 영업팀장·영업부장에게 공개를 추가하면 잠금 없이 트랜잭션 밖에서 판정한다(변경 없음이라 문제 없다).
12. **시험은 캐시를 못 비운다.** 시험 메서드를 27개로 묶었고, 설정 스위치는 `ReflectionTestUtils`로 바꿨다가 finally에서 되돌린다.
