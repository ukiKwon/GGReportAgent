    private static int crop(String xml, String attr) {
        Matcher e = Pattern.compile("<[A-Za-z]*:?srcRect\\b[^>]*>").matcher(xml);
        if (!e.find()) {
            return -1;
        }
        Matcher a = Pattern.compile("\\s" + attr + "=\"(\\d+)\"").matcher(e.group());
        return a.find() ? Integer.parseInt(a.group(1)) : 0;

### 5. 보안·위험·되돌리는 법
- 권한·감사·입력 경로는 무변경이다. `srcRect` 값은 `withCrop`이 0~1 범위로 검증하고, 오류 문구는 기존 "docx build failed" 또는 "picture crop"만 쓴다.
- 접근 이력과 감사에 새로 넣는 값은 없다. 인증은 기존 `X-Emp-No` 자기신고 그대로다.
- 위험:
  - 얼굴이 잘릴 수 있다. 3:4는 약 21%만 잘리고 위쪽 6.4%·아래 14.9%라 위험이 낮다. 정사각 사진은 좌우 각 2.3%만 잘린다.
  - 구버전 뷰어가 `srcRect`를 무시하면 사진이 상자에 맞게 늘어난다. Word 실물 확인 전에는 단정하지 않는다. 문제가 되면 ImageIO 픽셀 자르기로 대체한다. 그 경우 원본 되돌리기는 포기해야 한다.
  - 웹 카드는 사진 전체를 보여 주고 Word는 잘린 사진을 보여 준다. 두 모양이 달라진다.
- 되돌리기: `MAX_CROP`을 0으로 두면 `cropFor`가 항상 null을 돌려줘 이전 contain과 같아진다. 시험 `…꽉_채운다`와 `…위30_아래70…`은 함께 되돌려야 한다.

### 7. 열린 질문 및 확신 못 하는 점
- POI 5.2.3 poi-ooxml-lite에 `CTBlipFillProperties`와 `CTRelativeRect`가 모두 있는지는 컴파일해 봐야 안다. 80% 확신이다. 없으면 3-3의 대안(`XmlCursor`로 직접 삽입)으로 간다.
- `XmlCursor.setAttributeText`는 요소 시작 위치 커서에서 동작할 것으로 본다. 시험 `crop()` 단언이 속성 값을 검증하므로 잘못 쓰이면 바로 실패한다.
- `srcRect` 직렬화 접두어와 속성 순서는 가정하지 않고 정규식(`<[A-Za-z]*:?srcRect`, 속성 개별 검색)으로 받았다. 그래도 시험 `crop()`이 첫 번째 `srcRect`만 본다. 문서에 그림이 하나뿐이라 문제없다.
- 4절 5(빈 값 줄)와 4절 4(API 트림 헤더)는 이번 패치에서 뺐다. 필요하면 별도로 낸다.
- 대상 파일 범위는 지켰다. `PrepService.java`·`PrepAttachApiTest.java`는 건드리는 패치가 없다. `DocModel.java`와 `DocxKit.java`는 `docout` 패키지의 HeadDocBuilder 의존 파일이라 포함했다. 다른 세션이 이 두 파일을 쓰는지는 호출자가 확인해 달라.
