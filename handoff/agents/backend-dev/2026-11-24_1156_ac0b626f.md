## 2. 현재 구조 요약
1. **확장자는 사용자 이해와 다르다.** 코드 `DocumentType.java:34-35`는 입찰제안서 `ppt·pptx`, RFP `pdf·hwp·hwpx`다. `md`는 업로드 확장자가 아니라 산출물이다(`isOutputPath`, :89). 업로드 창구는 `KGI11100$UploadAction`의 `/upload/proposal`, `/upload/rfp` 둘이다.
2. **저장 흐름.** `FileUploadService.upload`가 `FileStorageService.saveOriginal`(`userdata`)로 저장하고, DB `UPLOADED_FILE` 행을 넣은 뒤 파싱한다. 같은 이름이면 `_yyyyMMddHHmmss`를 붙여 덮어쓰지 않지만 다른 이름으로 저장한다(`FileStorageService.java:124-131`). 사업계획 CSV에는 맞지 않는다(이름이 바뀌면 web이 못 읽음).
3. **"올린 사람" 개념이 없다.** `SystemUser.java:6` 주석에 "로그인도 사용자 개념도 없다"고 적혀 있다. 감사 컬럼에는 화면번호(`GI11100`)만 들어간다. 요청 로그(`RequestLoggingConfig`)는 클라이언트 IP만 남기고 본문은 안 남긴다(`includePayload=false`).
4. **설정은 파일 교체 방식**(`config-envs` 5개). `ConfigEnvsTest`가 `REQUIRED` 키의 5곳 누락을 막는다. 테스트는 JUnit4다.
5. **web 쪽 읽기.** `PlanInboxService`는 폴더를 읽기만 한다. 이름이 `PlanCsv.FILE_NAME`과 정확히 맞는 파일만 대상이고, 나머지는 `ignored_count`로 센다(:128). 링크·하위 폴더는 `UNSAFE`다. SHA-256은 파일 바이트에서 소문자 hex로 계산해 `INST_PLAN_IMPORT`에 저장한다(`InstitutionPlanService.java:691-697`). **web은 사이드카·영수증 파일을 읽지 않는다.**
   - web 설정 키 `ggreport.plan-inbox.location`은 이미 5개 환경 파일에 빈 값으로 있다(`config-envs/*/application.properties` 54·78 등). **web 설정 변경은 필요 없다.**

## 3. 설계 결정과 근거

### 요건별 결정
- **D1 ① 별도 종류**: `DocumentType`·`UploadedFile` DB·파싱은 쓰지 않는다. 사업계획 CSV는 DB 행도 없고 파싱도 안 한다.
  - 근거: `DocumentType`은 DB 코드(01·02)와 SQL LIKE 규칙에 묶여 있다(:75-77). 거기에 넣으면 스키마·DBA 변경이 생긴다.
  - 새 창구 `POST /upload/plan-csv`(`KGI11200$PlanCsvUploadAction`, 화면번호 `GI11200`)와 새 서비스 `PlanCsvUploadService`를 둔다.
  - 확장자는 `.csv`만이다.
- **D2 ② 전용 폴더**: 설정 키 `upload.plan-csv-dir`(빈 값=꺼짐). 영수증 폴더 키 `upload.plan-csv-receipt-dir`가 비어 있어도 꺼진다(④를 못 지키므로 닫힌 상태가 기본).
  - 이름 규칙 통과 이름은 구분자가 없다(`[A-Za-z0-9-]`+`_`+숫자 8자리+`_plan.csv`). 그래서 `root.resolve(name)`은 폴더 밖으로 나갈 수 없다. `../`는 구조적으로 불가능하다.
  - IE가 보내는 전체 경로는 기존 `FileStorageService.safeFileName`으로 폴더 부분을 떼어 낸 뒤 정규식을 건다(`../x_20261118_plan.csv`는 `x_...`로 저장될 뿐 폴더 안이다).
  - 폴더를 자동 생성하지 않는다(경로 오타로 엉뚱한 곳이 생기고 web은 `BAD_CONFIG`가 되는 일을 막음). 없으면 "설정 확인" 안내.
- **D3 ③ 덮어쓰기 금지**
  - (a) JVM 락 안에서 폴더를 훑어 **대소문자 무시 동일 이름**이 있으면 거부한다. web은 기관ID 대소문자를 무시하므로 `Sample-gu_…`와 `sample-gu_…`가 둘 다 살아남으면 모호하다.
  - (b) 임시 파일 `.plan-upload-<uuid>.tmp`(FILE_NAME에 안 맞아 web이 무시)에 쓴 뒤 `Files.move(tmp, target)`를 **옵션 없이** 호출한다. 이미 있으면 `FileAlreadyExistsException`이라 거부된다.
  - 임시 파일을 같은 폴더에 두는 이유는 같은 파일시스템이라 rename이 되고, web이 쓰다 만 파일을 읽지 않게 하려는 것이다. `createTempFile`은 0600이라 web 프로세스가 못 읽을 수 있어 쓰지 않는다(`newOutputStream CREATE_NEW`, 기본 umask).
  - 노드가 둘이면 JVM 락이 안 통한다. 그때는 (b)의 `move` 예외가 마지막 방어선이다(점검-쓰기 사이 아주 작은 경쟁 구간은 남음, 한계로 밝힘).
- **D4 ④ 올린 사람·SHA-256**: 영수증 파일(추가 전용 TSV) `<영수증 폴더>/plan-csv-receipts.tsv`에 한 줄씩 남긴다.
  - 열: `uploaded_at(서울, +09:00)`, `file_name`, `sha256`, `size`, `institution_id`, `file_date`, `uploader_self`, `remote_user`, `client_ip`.
  - **올린 사람은 자기신고다.** 화면 입력칸 `uploaderName`(필수, 글자·숫자·공백·`._-` 1~30자)과 컨테이너가 주면 `getRemoteUser()`(값 정제)를 함께 남긴다. 이 앱에는 로그인이 없으므로 "검증됨"이라고 쓰지 않는다.
  - **영수증을 별도 폴더에 두는 이유**: web은 inbox 폴더의 이름 밖 파일을 `ignored_count`로 센다. 사이드카를 거기 두면 매번 센다.
  - **SHA 형식**: 소문자 hex, web `InstitutionPlanService.sha256`과 동일해서 대조가 문자열 비교로 끝난다.
  - 영수증 쓰기가 실패하면 방금 만든 파일을 지우고 실패로 처리한다(우리가 방금 만든 파일이므로 덮어쓰기 금지에 어긋나지 않음). 영수증 없는 파일이 폴더에 남아 web이 읽는 일을 막는다.
  - DB 테이블은 만들지 않는다(DBA 부담·FK 금지 규칙 회피). 필요해지면 후속.
- **D5 ⑤ 이름 규칙**: SCHEMA ⑪-2 정규식 `([A-Za-z0-9-]{1,64})_(\d{8})_plan\.csv`, "기관당 1파일", 날짜는 실제 달력 날짜.
  - 추가로 2000-01-01 이후, 서울 오늘 이하만 허용한다(⑪-3 7열 "확인일 … 오늘 이전"과 같은 범위 — 파일 이름 날짜는 확인일 중 가장 늦은 날이라서).
  - SCHEMA ⑪-5 마지막 줄 "같은 이름의 파일을 새로 내려면 날짜(확인일)를 바꾼다 — uploader는 같은 이름을 거부한다(예정)"를 이 구현이 이행한다. 거부 안내 문구도 그렇게 쓴다.
- **D6 ⑥ 크기·최소 검사**
  - **크기**: 5MB(`CsvLimits.MAX_FILE_BYTES`와 같음)를 스트림으로 읽으며 5MB+1에서 끊는다(`getSize()`를 믿지 않음). 한 번에 50파일(⑪-5).
  - **본문 최소 검사**(web이 최종 판정, uploader는 빠른 거름망):
    - 엄격 UTF-8(BOM 허용, cp949 거부, ⑪-2).
    - NUL 없음.
    - 머리줄(첫 줄 2,000자 이내)의 열 이름이 모두 25개 정의 안에 있고 겹침 없고, 필수 11열이 다 있다(`PlanCsv.REQUIRED`와 같음: 기관ID·문서명·원천종류·대상기간시작·대상기간끝·출처URL·확인일·수집자·사업번호·사업명·예산상태).
    - 사업 행이 1줄 이상.
    - 기관ID가 첫 열이면 첫 사업 행의 값이 파일 이름의 기관ID와 같다(대소문자 무시).
  - **드리프트 위험**: 25열 목록과 정규식은 web 코드의 **사본**이다(`PlanCsv.java:31, :60-64`). 두 곳을 함께 고친다고 서비스 주석에 적고 qa에 확인을 넘긴다.
- **D7 ⑦ 로그**: 기록하는 것은 이름(정규식 통과분만)·크기·SHA·정제된 올린 사람·결과 코드뿐이다. 본문·경로·`e.getMessage()`는 로그에도 화면에도 싣지 않는다. 기존 `FileUploadService.java:78`의 `"오류: " + e.getMessage()`와 달리 고정 문구만 쓴다. 예외는 클래스 이름만 로그에 남긴다.
- **D8 화면**
  - `upload.html`에 세 번째 카드(올린 사람 입력 + CSV 파일 선택)와 별도 결과표를 더한다.
  - 꺼짐이면 "설정되지 않아 사용할 수 없습니다" 안내를 보이고 입력을 막는다. `@ControllerAdvice`로 세 컨트롤러에 `planCsvEnabled`를 넣는다(기존 컨트롤러 생성자 무변경).
  - 이 화면은 기존 방식대로 HTML 200으로 응답한다. 인증·CSRF 없는 내부 앱이다(기존 현황 유지, 아래 보안 절).

        Path root = realDir(dir);
        Path receipts = realDir(receiptDir);
        List<PlanCsvResultItem> out = new ArrayList<PlanCsvResultItem>();
        for (MultipartFile f : files) {
            String orig = f.getOriginalFilename();
            if (orig == null || orig.trim().isEmpty()) continue;   // 파일을 고르지 않은 빈 파트
            out.add(one(root, receipts, f, FileStorageService.safeFileName(orig), uploader, remoteUser, clientIp));
        }
        if (out.isEmpty()) throw new PlanCsvException("파일을 선택해 주세요.");
        return out;
    }

    private PlanCsvResultItem one(Path root, Path receipts, MultipartFile f, String name,
                                  String uploader, String remoteUser, String clientIp) {
        String shown = shown(name);
        Matcher m = FILE_NAME.matcher(name);
        if (!m.matches()) {
            return reject(shown, "NAME", "파일 이름은 {기관ID}_{YYYYMMDD}_plan.csv 형식이어야 합니다.");
        }
        String inst = m.group(1);
        LocalDate day;
        try {
            day = LocalDate.parse(m.group(2), DAY);
        } catch (DateTimeParseException e) {
            return reject(shown, "DATE", "파일 이름의 날짜가 실제 날짜가 아닙니다.");
        }
        if (day.isBefore(MIN_DAY) || day.isAfter(LocalDate.now(SEOUL))) {
            return reject(shown, "DATE", "파일 이름의 날짜는 2000-01-01부터 오늘까지여야 합니다.");
        }
        byte[] raw;
        try {
            raw = readCapped(f);
        } catch (IOException e) {
            return fail(shown, "READ", e, "파일을 읽지 못했습니다.");
        }
        if (raw == null) {
            return reject(shown, "SIZE", "파일은 5MB 이하여야 합니다.");
        }
        String why = checkContent(raw, inst);
        if (why != null) return reject(shown, "CONTENT", why);

        String sha = sha256(raw);
        Path target = root.resolve(name);
        Path tmp = root.resolve(".plan-upload-" + UUID.randomUUID() + ".tmp");
        try {
            try (OutputStream o = Files.newOutputStream(tmp, StandardOpenOption.CREATE_NEW, StandardOpenOption.WRITE)) {
                o.write(raw);
            }
            synchronized (lock) {
                if (existsIgnoreCase(root, name)) {
                    return reject(shown, "EXISTS",
                            "같은 이름의 파일이 이미 있습니다. 덮어쓰지 않습니다. 새로 내려면 확인일(파일 이름 날짜)을 바꿔 다시 만드세요.");
                }
                try {
                    Files.move(tmp, target);   // 옵션 없음 — 이미 있으면 FileAlreadyExistsException
                } catch (FileAlreadyExistsException e) {
                    return reject(shown, "EXISTS",
                            "같은 이름의 파일이 이미 있습니다. 덮어쓰지 않습니다. 새로 내려면 확인일(파일 이름 날짜)을 바꿔 다시 만드세요.");
                }
                try {
                    appendReceipt(receipts, name, sha, raw.length, inst, day, uploader, remoteUser, clientIp);
                } catch (IOException e) {
                    // 방금 우리가 만든 파일이다. 기록 없는 파일이 폴더에 남아 web 이 읽지 않게 되돌린다.
                    Files.deleteIfExists(target);
                    return fail(shown, "RECEIPT", e, "올린 기록을 남기지 못해 저장하지 않았습니다. 개발부서에 문의해 주세요.");
                }
            }
            log.info("plan-csv saved name={} size={} sha256={} by={}", name, raw.length, sha, uploader);
            return new PlanCsvResultItem(shown, true, sha, "저장했습니다. 웹에서 폴더 확인 후 반입하세요.");
        } catch (IOException e) {
            return fail(shown, "WRITE", e, "저장하지 못했습니다. 개발부서에 문의해 주세요.");
        } finally {
            try {
                Files.deleteIfExists(tmp);
            } catch (IOException ignore) {
                log.warn("plan-csv tmp cleanup failed");
            }
        }
    }

    // ── 검사 ─────────────────────────────────────────────

    /** 5MB 이하면 바이트, 넘으면 null. */
    static byte[] readCapped(MultipartFile f) throws IOException {
        try (InputStream in = f.getInputStream()) {
            java.io.ByteArrayOutputStream out = new java.io.ByteArrayOutputStream();
            byte[] buf = new byte[8192];
            long total = 0;
            int r;
            while ((r = in.read(buf)) > 0) {
                total += r;
                if (total > MAX_BYTES) return null;
                out.write(buf, 0, r);
            }
            return out.toByteArray();
        }
    }

    /** 통과면 null, 아니면 고정 문구. 칸 원문은 문구에 싣지 않는다. */
    static String checkContent(byte[] raw, String instId) {
        if (raw.length == 0) return "빈 파일입니다.";
        String text;
        try {
            text = StandardCharsets.UTF_8.newDecoder()
                    .onMalformedInput(CodingErrorAction.REPORT)
                    .onUnmappableCharacter(CodingErrorAction.REPORT)
                    .decode(ByteBuffer.wrap(raw)).toString();
        } catch (CharacterCodingException e) {
            return "UTF-8 파일이 아닙니다. 엑셀이면 'CSV UTF-8'로 저장해 주세요.";
        }
        if (text.indexOf('\0') >= 0) return "CSV 파일이 아닙니다.";
        if (text.startsWith("\uFEFF")) text = text.substring(1);
        int eol = firstEol(text, 0);
        String head = eol < 0 ? text : text.substring(0, eol);
        if (head.length() > MAX_HEADER_CHARS) return "머리줄이 너무 깁니다.";
        List<String> cols = splitSimple(head);
        Set<String> seen = new HashSet<String>();
        for (String c : cols) {
            if (!HEADERS.contains(c)) return "머리줄에 모르는 열 이름이 있습니다.";
            if (!seen.add(c)) return "머리줄에 같은 열 이름이 겹칩니다.";
        }
        if (!seen.containsAll(REQUIRED)) return "머리줄에 필수 열이 빠져 있습니다.";
        int pos = eol;
        while (pos >= 0 && pos < text.length()) {
            int s = pos;
            while (s < text.length() && (text.charAt(s) == '\r' || text.charAt(s) == '\n')) s++;
            if (s >= text.length()) break;
            int e = firstEol(text, s);
            String line = e < 0 ? text.substring(s) : text.substring(s, e);
            if (!line.trim().isEmpty()) {
                if (cols.indexOf("기관ID") == 0) {
                    List<String> cells = splitSimple(line);
                    if (cells.isEmpty() || !cells.get(0).equalsIgnoreCase(instId)) {
                        return "1열 기관ID가 파일 이름의 기관ID와 다릅니다.";
                    }
                }
                return null;
            }
            pos = e;
            if (e < 0) break;
        }
        return "사업 행이 없습니다.";
    }

    private static int firstEol(String s, int from) {
        for (int i = from; i < s.length(); i++) {
            char c = s.charAt(i);
            if (c == '\n' || c == '\r') return i;
        }
        return -1;
    }

    /** 머리줄·기관ID 열 용도의 단순 분리(쉼표, 양끝 따옴표 제거). 본문 칸 해석이 아니다. */
    static List<String> splitSimple(String line) {
        List<String> out = new ArrayList<String>();
        for (String p : line.split(",", -1)) {
            String t = p.trim();
            if (t.length() >= 2 && t.startsWith("\"") && t.endsWith("\"")) t = t.substring(1, t.length() - 1);
            out.add(t);
        }
        return out;
    }

    // ── 파일·기록 ─────────────────────────────────────────

    private static Path realDir(String configured) {
        try {
            Path real = Paths.get(configured).toRealPath();
            if (!Files.isDirectory(real)) throw new IOException("not a directory");
            return real;
        } catch (IOException | InvalidPathException e) {
            log.error("plan-csv folder unavailable");   // 경로는 싣지 않는다
            throw new PlanCsvException("사업계획 CSV 폴더를 사용할 수 없습니다. 개발부서 설정을 확인해 주세요.");
        }
    }

    /** 대소문자만 다른 이름도 같은 이름으로 본다(web 은 기관ID 대소문자를 무시한다). 너무 많으면 닫힌 채 거부. */
    private static boolean existsIgnoreCase(Path root, String name) throws IOException {
        try (DirectoryStream<Path> ds = Files.newDirectoryStream(root)) {
            int n = 0;
            for (Path p : ds) {
                if (++n > MAX_ENTRIES) throw new IOException("too many entries");
                if (p.getFileName().toString().equalsIgnoreCase(name)) return true;
            }
        } catch (DirectoryIteratorException e) {
            throw new IOException("list failed");
        }
        return false;
    }

    private static void appendReceipt(Path receipts, String name, String sha, int size, String inst, LocalDate day,
                                      String uploader, String remoteUser, String clientIp) throws IOException {
        Path file = receipts.resolve(RECEIPT_FILE);
        StringBuilder sb = new StringBuilder();
        if (!Files.exists(file)) {
            sb.append("#uploaded_at\tfile_name\tsha256\tsize\tinstitution_id\tfile_date\tuploader_self\tremote_user\tclient_ip\n");
        }
        sb.append(ZonedDateTime.now(SEOUL).format(DateTimeFormatter.ISO_OFFSET_DATE_TIME)).append('\t')
          .append(name).append('\t').append(sha).append('\t').append(size).append('\t')
          .append(inst).append('\t').append(day).append('\t')
          .append(uploader).append('\t').append(clean(remoteUser)).append('\t').append(clean(clientIp)).append('\n');
        Files.write(file, sb.toString().getBytes(StandardCharsets.UTF_8),
                StandardOpenOption.CREATE, StandardOpenOption.APPEND);
    }

    /** 탭·줄바꿈·제어 문자 주입을 막는다. 없으면 '-'. */
    static String clean(String s) {
        if (s == null) return "-";
        String v = s.replaceAll("[^\\p{L}\\p{N}._:@-]", "_");
        if (v.length() > 45) v = v.substring(0, 45);
        return v.isEmpty() ? "-" : v;
    }

    /** 화면에 되돌려 줄 이름 — 제어 문자를 지우고 길이를 줄인다. */
    static String shown(String name) {
        String v = name.replaceAll("\\p{Cntrl}", "?");
        return v.length() > 80 ? v.substring(0, 80) + "…" : v;
    }

    static String sha256(byte[] data) {
        try {
            byte[] h = MessageDigest.getInstance("SHA-256").digest(data);
            StringBuilder sb = new StringBuilder(64);
            for (byte b : h) sb.append(String.format("%02x", b & 0xff));   // web 과 같은 소문자 hex
            return sb.toString();
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException(e);
        }
    }

    private static PlanCsvResultItem reject(String shown, String code, String message) {
        log.info("plan-csv rejected code={}", code);
        return new PlanCsvResultItem(shown, false, null, message);
    }

    private static PlanCsvResultItem fail(String shown, String code, Exception e, String message) {
        log.error("plan-csv failed code={} err={}", code, e.getClass().getSimpleName());   // 메시지·경로 없음
        return new PlanCsvResultItem(shown, false, null, message);
    }
}

## 9. security에 넘길 확인 항목
1. `FILE_NAME` 정규식과 `safeFileName` 조합으로 폴더 밖 쓰기·`../`·ADS(`:`)·예약 이름이 불가능한가. 대소문자 중복 검사가 파일시스템별(NTFS·ext4)로 충분한가.
2. 임시 파일 → `Files.move` 옵션 없음의 no-overwrite 보장. 다중 노드·NFS에서의 경쟁 구간을 허용 가능한 한계로 볼지.
3. 임시 파일 권한(기본 umask)이 web 프로세스가 읽을 수 있는 수준이면서 과하게 열리지 않는가.
4. 올린 사람(자기신고 이름)·`getRemoteUser()`·`getRemoteAddr()`를 영수증에 남기는 것이 개인정보 방침에 맞는가. `X-Forwarded-For`는 신뢰하지 않았다. 영수증·로그에 탭·줄바꿈 주입이 막히는가.
5. 인증 없는 업로드 창구가 폴더에 쓸 수 있는 것 자체의 위험. 요청 빈도 제한이 필요한가. 50파일 × 5MB 메모리 사용(요청당 최대 250MB는 `max-request-size=200MB`로 막힘).
6. 에러 문구에 경로·예외 메시지가 없는지.
7. CSV 최소 검사(엄격 UTF-8·NUL·머리줄)로 충분한가. 수식 시작 문자 검사를 uploader에도 둘지, web 판정에 맡길지.
8. 영수증 TSV 폴더를 inbox와 분리한 결정(`ignored_count` 오염 회피)과 두 폴더의 권한 분리.
