'승인 총 금액'의 기본 기준을 이사회 자료 표 A의 합계 칸으로 바꿨습니다. 컴파일과 `mvn` 시험은 돌리지 못했습니다(Bash 없음). 시험 기대값 수정과 새 시험 추가까지 끝냈습니다.

**새 기준의 정의**
- 이사회 자료 양식 표 A('재산상 이익제공 및 기부금(안)')에서 라벨이 "합계"인 행의 제공금액 칸 저장 값을 씁니다. 기본 양식에서는 출연금 + 예비비 + 전산시스템 구축/운영비용입니다(`BoardDocSpec.java:1110-1116`).
- 합계 칸이 비었거나 숫자가 아니면, 출연금·예비비·"전산시스템 구축/운영비용"이 모두 숫자일 때만 세 값을 더합니다. 하나라도 없으면 null이고, 대본에는 〔이사회 자료 표 A 확인 필요〕 또는 〔이사회 자료 없음 — 확인 필요〕가 그대로 남습니다.
- 합계 칸이 있으면 그 값을 그대로 씁니다(더하지 않음).
- 기존 입력 `amount_mode`는 같은 개념이었습니다. `EXCL_IT`는 출연금+예비비(전산비 제외), `TOTAL`은 표 합계입니다. 따로 계산을 만들지 않고 기본값만 `EXCL_IT`에서 `TOTAL`로 뒤집었습니다. 입력을 비우거나 보내지 않으면 표 합계가 되고, `EXCL_IT`는 명시했을 때만 씁니다. 유효하지 않은 값은 지금처럼 400입니다.

**판단이 필요했던 점**
1. 새로 만든 대체 계산(합계 칸 비었을 때 더하기)은 "전산시스템 구축/운영비용"이라는 라벨 글자로 칸을 찾습니다. 양식 구조가 바뀌어 이 라벨이 없어지면 대체 계산은 null이 되고 〔확인 필요〕로 남습니다.
2. 합계 칸에 숫자가 아닌 값이 있어도 세 항목이 모두 숫자이면 더한 값으로 대신합니다. 이 경우를 막으려면 알려 주세요.
3. 새 시험의 전산비 칸 key를 `r3_c2`로 가정했습니다. 표 A는 r1=출연금, r2=예비비, r4=합계이고 기존 시험도 `_c2`가 값 칸이므로 맞을 가능성이 높습니다. 다르면 `BoardScriptFiguresTest`의 이 한 건만 먼저 깨집니다.
4. `ScriptDraftBasisReader`의 `amountExclIt` 필드는 남겼습니다(`hasBoardFigures` 판정에 쓰입니다). 필드를 지우려면 별도 작업입니다.
5. 사용자 화면 쪽에 `amount_mode` 선택 칸이 있으면 기본 표시가 `EXCL_IT`로 되어 있는지 프런트 확인이 필요합니다. 화면 파일은 건드리지 않았습니다.
