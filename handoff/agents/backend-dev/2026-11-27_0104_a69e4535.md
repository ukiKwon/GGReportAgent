연결 단계 시간 초과를 UNREACHABLE로 분류하도록 고쳤습니다. 빌드와 테스트는 실행하지 못했습니다(Bash 없음).

**바꾼 곳**
- `OllamaLlmClient.java`
  - import 추가: `org.apache.http.conn.ConnectTimeoutException`(import 블록, 10행 부근).
  - `call()`의 catch에서 `InterruptedIOException` 분기 앞(153행 부근)에 `catch (ConnectTimeoutException ex) { post.abort(); throw new LlmCallException(UNREACHABLE, 0); }`를 추가했습니다. 지시한 한 줄 주석(Windows 닫힌 포트는 거절 대신 연결 제한에 걸릴 수 있다)도 달았습니다.
  - `ConnectionPoolTimeoutException`과 `SocketTimeoutException`은 기존 `InterruptedIOException` 분기라서 TIMEOUT 그대로입니다. 감시 타이머(`fired`) 분기도 그대로입니다.
- `OllamaLlmClientTest.java`: 303행(`닫힌_포트는_UNREACHABLE…`)의 기대값은 UNREACHABLE 그대로 두고, 이유 주석 한 줄만 달았습니다.

**probe()**
`probe()`는 `IOException`/`RuntimeException`이 나면 모두 `Probe(false,false)`(닿지 않음)로 처리합니다. 연결 시간 초과도 이미 "연결 안 됨"이라서 같은 뜻이고, 고칠 곳이 없었습니다.

**다른 시험에 미치는 영향**
- 영향받는 시험은 없을 것으로 봅니다. 시험 전체를 읽어 확인했습니다.
- 응답 지연 시험(`응답이_너무_늦으면_TIMEOUT`, 249행)과 느리게 보내는 시험(`서버가_몇_바이트씩…`, 273행)은 연결 제한 500ms를 쓰지만, 서버가 열려 있어 연결은 즉시 됩니다. 그래서 기대값 TIMEOUT은 소켓 시간 초과나 마감에서 나오고, 새 분기를 거치지 않습니다.
- BUSY 시험(307행 이후)은 `ConnectTimeoutException`과 무관합니다.
