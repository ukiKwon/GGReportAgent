# 붙임 5·C-3 사업초기 열 서버 구현 — backend-dev-write (sonnet)

---

붙임 5(C-5)와 C-3 사업초기 열(NEXT 37 S5·S7)을 구현했지만, 빌드·테스트는 한 번도 돌리지 못했다(Bash 없음). `mvn -q -o test` 결과는 아직 모른다. 아래 변경은 모두 `kgi-ggreport-web/` 안이고 프런트·`config/`·`handoff/`·`.claude/`는 건드리지 않았다.

## 판단 사항

1. **C-3 새 열 id는 `c6`.** 화면 순서는 구분, 사업초기(c6), 1년차(c1) … 4년차(c4), 계(c5)다. 기존 id와 칸 key(`r{n}_c1`~`c5`)는 그대로고, 카탈로그 id 영역(100 미만)이라 `nextC`는 100을 유지한다. C-3은 명시 id 생성자를 쓴다. C-5는 기본 id(`r0`~`r25`, `c0`~`c8`)다.
2. **`BoardLegacyKeys`(v1 번역표)는 그대로 뒀다.** `BoardExcelMap.newKey`만 바꿨다. 옛 모양 key(`r1c2`)는 지도의 `catalog_ver`와 상관없이 항상 v1 위치로 옮긴다. 안 바꾸면 `catalog_ver` 2 지도에서 옛 key가 전부 기동 실패한다. 새 칸은 새 모양(`r1_c6`)으로 적는다.
3. **옛 버전 양식은 내용이 같아도 저장하면 새 버전이 생긴다.** `BoardFormService.save`가 `cur.getCatalogVer()==CATALOG_VER`를 요구하는 기존 로직 때문이고, 의도한 동작이다. `catalog_outdated` 필드는 이미 있어서 서비스 코드는 고치지 않았다. 옛 버전은 true, 저장 후엔 false다.
4. **C-3 샘플 숫자를 새로 정했다.** 카탈로그 샘플의 사업초기 값은 revenue/cost 배열의 t=0, 미회수투자액 사업초기는 1600, 계는 5칸 합이다. 가상 값이다.
5. **C-5 샘플 문구는 `행번호*1.25 + 열*0.5`로 만든 가상 숫자다.**
6. **C-5 라벨 표기를 정했다.** 정의안에 글자가 없는 칸이라 "총 수익", "총 비용", "예상영업이익", "협력사업비(출연금)", "예비비", "법인세 차감전 순이익", "법인세(26.4%)", "법인세 차감후 이익"으로 썼다.
7. **docx 열 너비.** C-3은 `{28,12,12,12,12,12,12}`, C-5는 `{10,12,22,9,9,9,9,9,11}`이다. 마지막 열이 나머지를 받아 합은 본문폭(9638)이다.
8. **`excel-map.json`의 `derive_sum`.** 표 A의 `of`를 `r1_c2`, `r2_c2`, `r3_c2`로 바꿨다. 옛 key 번역에 기대지 않는다.

## 남은 위험

- **샘플 xlsx 라벨 대조를 못 했다.** `수익성분석표_샘플_가짜값.xlsx`와 `src/test/resources/boarddoc/profit_sample.xlsx`가 바이너리라 Read 도구로 열 수 없었다. 지도의 새 행 경로와 오라클 문자열은 `GenProfitSample.java.txt` 기준이고, xlsx가 다르면 그 xlsx가 기준이어야 한다. `BoardProfitSampleTest`가 실패하면 먼저 `ROW_NOT_FOUND`/`ROW_COUNT_MISMATCH` 등 `lookup_errors`를 보라.
  - 확인할 곳: 정기예금 4행 `정기예금(1개월)|(3개월)|(6개월)|(12개월)`, `영업점 인건비|물건비`, `ATM 구축비|ATM 운영비`, `본부부서 인건비`(같은 경로 2행), `전산구축비(사후관리비용 포함)`, `이익(소계)`.
  - 정의안에 적힌 "실제 사본 재확인 필요"는 여전히 유효하다.
- **누락 행이 있으면 실패한다.** 실제 사본에서 정기예금 일부가 빠져 있으면 `count` 불일치로 해당 칸이 실패한다(추측하지 않는 설계). 이 경우 칸 단위 실패이고 다른 칸은 영향이 없다.
- **옛 형식 지도 검증이 느슨해졌다.** `newKey`가 옛 모양 key를 항상 v1로 옮기므로, `catalog_ver` 2 지도에 C-3 옛 key를 적으면 v1 위치(c1~c5)로 해석된다. 사업초기(c6)는 반드시 새 모양으로 적어야 한다.
- **저장 JSON 크기 한도(240000B).** 편집 가능한 칸이 약 95개로 늘어 100자 최대 입력 시 약 57KB로 어림했다. 여유는 있지만 실행으로 확인하지 못했다.
- **전체 응답 용량.** `BoardExcelNamedFill` 격자 상한(표당 1000, 요청당 5000칸)을 C-5가 더 쓴다. 넘으면 격자만 `omitted`로 알리고 값 채우기에는 영향이 없다. 샘플 기준으로 약 2,600칸 안팎으로 어림했다.

## 이관 메모

- [이관: 프런트] `GET /board-forms/catalog`와 양식 응답에 C-5(9열, 26행)와 C-3 7열이 생겼다. 열 id가 `c0,c6,c1,…`처럼 순서와 달라 `col_ids` 순서대로 그려야 한다.
- [이관: 프런트] 옛 양식은 `catalog_outdated:true`로 오고, 읽을 때 이미 이행된 표(C-5 포함)가 내려온다. 저장하면 새 버전이 생긴다.
- [이관: 데이터] 실제 수익성분석표 사본으로 C-5 원본 경로(위 라벨 목록)와 '기부금(E)'·'영업점(출장소) 이익'·'점포개설비용' 같은 소계에만 들어가는 행의 처리(정의안 Q2)를 확인해야 한다.
- [이관: 기획] 정의안 Q1(행 수 가변의 의미)은 기본 ⓐ로 가정하고 구현했다. 가변 행 기능은 이번 범위에 없다.
