## 2. 설계안과 달라진 점
- **후보 규칙**: 사용자 결정(영업부서 + 임원급)에 맞췄다. 팀 비교는 설계 지시의 `"영업팀".equals(team)`이 아니라 `Teams.DESIGNER_HOME_TEAM`("영업")이다. `ApproverRules.team()`이 접미사 없는 "영업"을 돌려주기 때문이다.
- **관리자 판정**: `perms.canAdmin(empNo)`(권한관리 메뉴를 볼 수 있는지)를 썼다. 후보 판정에서만 부르고, 영업·임원 조건을 먼저 본 뒤 마지막에 부른다.
- **scopeAdd와 기본 열람자**: 기본 열람자(영업팀장·영업부장)는 후보가 아니지만, 대상이 기본 열람자면 기존처럼 200 `ALREADY_DEFAULT`를 돌려준다. 기존 시험(`LEAD2` 대상)이 이것을 기대하기 때문이다. 그 밖의 후보 밖 대상은 400 `SCOPE_TARGET_INVALID`다.
- **S6**: 설계안의 `notFound()`와 `forbidden()` 대신 같은 문구의 `RecheckException`을 던진다. 컨트롤러의 `guard.denied` 경로(403이면 ACCESS_LOG DENIED)는 그대로 탄다.
- **시험 1번**: 설계안 1번의 DESIGNER/MEMBER 기대는 새 규칙에 맞춰 조정했다. 둘 다 영업부서라 후보에 남는다. IT_LEAD와 ADMIN은 후보에서 빠진다.
- **ADMIN 제외 시험**: ADMIN의 `APPROVAL_GRADE`를 EXECUTIVE로 바꿔도 후보에서 빠지고 scopeAdd가 거부되는지 본다. 이 시험은 ADMIN이 `canAdmin=true`라는 전제에 기대고 있다.
- **LOG 추가**: 업로드 한 건마다 `BOARD_MINUTES_LOG`에 행이 하나 더 생긴다(`RULES_ACK`). 이력 화면은 모르는 event 문구가 비어 보일 수 있어 프런트 이관 사항이다.

## 4. main이 돌릴 명령과 예상 실패 지점
`cd kgi-ggreport-web && mvn -q -o test` (8080이 같은 `target/`을 쓰면 테스트 뒤 재기동)

예상 실패 지점, 확신이 낮은 순서로 적는다.
1. **컴파일 오류**: Java 8 람다와 import(`Predicate`, `Comparator`, `HashMap`, `OffsetDateTime`, `ZoneId`, `ChronoUnit`), `Ranks`/`Teams`/`MenuPerms` import를 확인해야 한다.
2. **새 시험의 시드 가정**:
   - ADMIN이 `canAdmin=true`인지.
   - `first_seq`가 1, 2인지(발언 번호가 1부터 이어진다는 가정).
   - `INSERT USERS` 컬럼.
   - `UPDATE BID_ASSIGNMENT SET ACTIVE_YN=0`(제약은 없는 것으로 확인했다).
   - 가림 단어 "ABC"·"abc"·"회의"가 마스커 검증을 통과하는지.
3. **`lockHead`의 `CREATED_AT` 매핑**: 컬럼이 camelCase로 자동 매핑된다는 전제다. 같은 매퍼의 다른 select가 같은 방식으로 `BoardMinutes`에 매핑하므로 문제없을 것으로 본다.
4. **기존 시험 중 LOG 행 수를 세는 것**: grep으로는 `SCOPE_ADD`, `SCOPE_EXTEND`, `DELETE`만 세고 있어 영향이 없을 것이다.
