공고 hwpx 올리기 400(FILE_REJECTED) 수정을 적용했다. 실행은 하지 않았다. mvn 실행 금지에 따라 컴파일과 테스트도 못 돌렸다.

**1. 바꾼 곳**
- `kgi-ggreport-web/src/main/java/com/kbstar/kgi/ggreport/web/docfill/ZipGuard.java`
  - 7인자 `check(..., maxXmlElements)`는 시그니처를 그대로 두고, 새 8인자 오버로드 `check(..., maxXmlElements, boolean lenientNonXml)`를 호출하게 했다(lenient=false). XlsxBook 등 다른 호출처는 동작이 같다.
  - 새 상수 `STRICT_SUFFIX = .xml/.hpf/.rels/.xsd/.rdf`와 `strictXmlName(name)`을 추가했다.
  - 완화 지점은 `countXml` 호출부 바로 위로, 요청하신 주석 "지킬 조건 — 서버가 XML로 해석하는 항목 이름 ⊂ 엄격 검사 이름. ..."을 달았다. lenient는 `lenientNonXml && !strictXmlName(name)`이다.
  - `countXml`에 lenient 인자를 추가했다. catch는 `XMLStreamException | RuntimeException`이고, lenient이면 건너뛰고 아니면 BROKEN이다.
  - `Rejected`는 checked 예외라서 위 catch에 잡히지 않고 그대로 전파된다. DTD 이벤트, 요소 수 상한, 칸·행 상한 모두 그렇다.
- `.../service/PrepAttachInspector.java` `inspectZip`: 마지막 인자로 `"hwpx".equals(ext)`를 넘겼다. xlsx·docx는 완화되지 않는다.
- 새 시험 `.../service/PrepAttachInspectorHwpxTest.java`: ZipGuard 단위 시험은 이미 있지만 이번 시험은 `PrepAttachInspector.inspect`를 직접 부른다. 기존 `ExtCheckFixtures.hwpx`와 `Zip`을 썼고, API 시험은 추가하지 않았다. 검증 항목 7건은 다음과 같다.
  - ⓐ `<><><><>\r\n<  <>` 로 시작하는 PrvText.txt(UTF-8) → 통과
  - ⓑ 같은 내용의 UTF-16LE+BOM 판 → 통과
  - ⓒ 이름이 .txt이고 맨 앞이 DOCTYPE/ENTITY → FILE_REJECTED
  - ⓓ 깨진 section0.xml → FILE_REJECTED, 깨진 container.rdf → FILE_REJECTED
  - ⓔ 대소문자만 다른 중복 이름 → FILE_REJECTED
  - ⓕ 같은 PrvText.txt를 넣은 xlsx → FILE_REJECTED(완화 꺼짐)
  - ⓖ 이름에 activex가 든 hwpx → ACTIVE_CONTENT

**2. 설계·security 조정과 달라진 점**
- 추가한 방어가 하나 있다. lenient로 건너뛰기 전에 원문(0 바이트 제외, 소문자)에 `<!doctype`이나 `<!entity`가 있는지 보고, 있으면 BROKEN으로 거절한다(`hasDtdMarker`). 파서가 DTD 이벤트에 이르기 전에 예외를 내는 경우에도 DOCTYPE이 우회로가 되지 않게 하려는 것이다. JDK와 Woodstox의 동작을 실행으로 확인할 수 없어서 넣었고, 필요 없다고 보면 빼도 된다.
- lenient로 건너뛴 항목도 파싱 도중까지의 요소 수는 `counts`에 누적된다. 요소 수 상한은 그대로 적용된다.
- `PrepAttachService.java`와 오류 문구, 개인정보 검사, 감사 기록은 건드리지 않았다.
- ZipGuard에 lenient 전용 단위 시험은 따로 추가하지 않았다. 새 Inspector 시험이 같은 경로를 덮는다.

**3. 메인이 실행할 시험**
- `cd kgi-ggreport-web && mvn -q -o test -Dtest=PrepAttachInspectorHwpxTest+ZipGuardTest`
  - 기대: 둘 다 통과한다. ZipGuardTest는 완화가 꺼진 기존 동작이 그대로인지 보는 용도다.
- 이어서 관련 회귀로 `-Dtest=PrepAttach*Test+ExtCheck*Test+InboxExtCheckApiTest`를 돌리고, 마지막에 전체 `mvn -q -o test`를 돌린다.
  - PrepAttachApiTest는 클래스명을 확인하지 못했다. `PrepAttach*Test` 패턴에 걸린다.
- 실제 사용자 hwpx로 한 번 올려 보면 확인된다.
- 8080 서버가 같은 `target/`을 쓰면 시험 뒤 재기동한다.
