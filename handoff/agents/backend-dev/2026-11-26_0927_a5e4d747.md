  - `BankYears`·`mapper.selectContractsOf`·`countEnabledCode`는 다른 곳에서 쓰므로 그대로 둔다.
  - `BankContractCode` import가 다른 곳에서 안 쓰이면 지운다. 안 지워도 컴파일은 된다.
- 프런트의 `kbb.defaultTag`는 현황판용 JS 함수라 이번 일과 무관하며 건드리지 않는다.
- 지도 '내 관심' 화면은 **고칠 곳이 없다**.
  - `render.syncWatch`는 `logic.watchIndex`로 `institution_id`만 Set에 담는다(`logic.js:792–797`).
  - 구분(`tag_cd`·`tag_name`)은 그리지도 읽지도 않는다. 그래서 `'null'`이 찍힐 길이 없다.
  - 화면 덩어리 없음. frontend-dev-write 작업은 필요 없다.
- 응답 키 `tag_source`의 값: 서버 호출자(프런트)는 이 키를 쓰지 않는다. 접근 이력의 `tag=` 꼬리표에만 쓴다.
  - 값 `DEFAULT`는 없어지므로 `NONE`으로 바꾸고, 이력 꼬리표는 `tag=none`으로 한다.
  - 이력에는 값이 아니라 출처 종류만 남긴다. 기존 규칙과 같다.
- 기존 ♥ 기록은 소급하지 않는다. 이 패치는 새로 담는 행에만 영향이 있고, 기존 행을 UPDATE하는 SQL은 없다.
- 같은 번호를 ♥ 끄고 다시 켤 때(`m[1]` 재사용)는 구분도 새 규칙대로 NULL이 된다. 그 경우는 이미 '값은 비우고 시작'이라는 기존 주석과 같은 방향이다.
- DB 변경 없음. 063이 이미 적용되어 있어야 한다. 아직 적용 전인 DB에서는 NULL 저장이 DB 오류가 난다(qa 0741 5절과 같은 전제).

### 5. 보안·위험·되돌리는 법
- 권한: `guard.require(req, VIEW_MENU)`와 `watchUser`(ACTIVE 사용자)는 그대로다. 403 경로 변경 없음.
- 입력: 구분을 주면 기존대로 코드표 검사(400). 안 주면 NULL이라 입력 위험이 줄었다.
- 자기신고 인증: `X-Emp-No`를 믿는 한계는 그대로다. 이번 변경이 그것을 바꾸지도 가리지도 않는다.
- 접근 이력: 값이 아니라 출처 종류(`given`/`none`)만 남는다. 본문·쿼리값·개인정보는 없다. 이력 어휘가 `default`에서 `none`으로 바뀌므로, 이 문자열을 집계하는 곳이 있으면 확인이 필요하다. 저장소 안에서는 시험 1곳뿐이다.
- 위험: 낮다. 영업 화면 쪽에서 ♥로 담은 기관은 구분이 비어 보이게 된다(사용자 결정). 구분으로 거르는 화면은 `NONE`(구분 정하지 않음) 필터가 이미 있다(qa 0741: kbboard 581·1196).
- 되돌리기: 패치 A~E와 컨트롤러 한 줄을 되돌리고 `defaultTag`를 복구한다. NULL로 담긴 행은 지울 필요가 없다. NULL을 허용하는 063 때문에 정상이다. DB 롤백 없음.
