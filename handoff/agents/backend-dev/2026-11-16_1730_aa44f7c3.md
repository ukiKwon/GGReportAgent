## 5. 보안·위험·되돌리는 법
- 경로 변수 검증 유지: validId(길이 1~64·[A-Za-z0-9-])가 DB 조회보다 먼저, 밖의 값은 DB에 닿지 않고 404. 바인드 변수만 사용해 UPPER(#{...})에도 SQL 주입 여지 없음.
- 404 메시지는 "institution not found"로 동일, 내부 정보 없음. 관리자 검사가 먼저라 ID 존재 여부 탐색 불가(403). 성공 감사는 같은 트랜잭션 유지, canonicalId는 읽기 전용이라 트랜잭션 구조 불변. 감사 INSTITUTION_ID: 못 찾으면 요청 원문(validId 통과 ≤64자), 찾으면 정식 표기. validId 탈락 값이 감사에 남는 것은 기존 동작 — 컬럼 길이가 64 미만이면 기존 위험(이번에 안 바꿈).
- 자기신고 인증(X-Emp-No) 한계는 그대로. 권한을 넓히거나 줄이지 않으며 관리자 검사는 "검증됨"이 아니라 업무 규칙.
- 성능: UPPER(...)는 PK 인덱스를 못 씀. INSTITUTIONS가 수천 행 이하면 문제없음. 커지면 Oracle 함수 기반 인덱스/MySQL 생성 컬럼 검토. missing IN은 최대 1,000개.
- MySQL·Oracle 일치: 비교는 양쪽 UPPER=UPPER, 저장·잠금·INSERT는 항상 정식 표기. Oracle에서 대소문자만 다른 ID 두 개가 있으면 정확 일치 우선, 일치 없으면 모호 → 404. MySQL ci는 UNIQUE가 중복을 막음. 위 확인 쿼리로 0행 확인.
- 되돌리기: 서비스·PlanCsv·매퍼 변경을 되돌리면 끝. DB 변경 없음, 저장분은 이미 정식 표기라 호환.
