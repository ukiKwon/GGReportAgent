**지금 기관 단위로 묶인 곳**
1. 목표는 같은 해 기관당 1건입니다: `BidTargetService.java:420-426` checkGoalOverlap → 409 DUP_TARGET.

package com.kbstar.kgi.ggreport.web.service;

import com.kbstar.kgi.ggreport.web.domain.BankContract;
import com.kbstar.kgi.ggreport.web.domain.BidTarget;
import com.kbstar.kgi.ggreport.web.domain.TargetCaseRef;
import com.kbstar.kgi.ggreport.web.web.ApiException;
import java.util.*;

/**
 * NEXT 125(사용자 11-26) — 목표 = 입찰 건. 업무 키 = 기관 + 입찰 대상(ETC 는 이름까지) + 금고 순위(AIM_RANK_CD) + 목표 연도.
 * 금고 순위는 MAIN_BANK 건에만(NULL = 미정), 그 밖 대상은 늘 NULL(해당 없음). 같은 (기관·연도·대상)에 살아 있는 목표 건 1개,
 * MAIN_BANK 만 1금고+2금고 두 건을 함께 둘 수 있다. 판정은 '바뀐 뒤 모습' 전체(일괄 요청의 미정→1금고 + 2금고 넣기가 함께 통과).
 * 순수 로직(DB 없음). 오류 문구는 고정 문구(입력값 없음). ⚠️ X-Emp-No 자기신고 위의 업무 규칙.
 */
final class BidTargetKeys {
    static final String DUP_MSG = "이 기관은 같은 연도·같은 입찰 대상의 목표 건이 이미 있습니다. 금고는 1금고와 2금고만 함께 둘 수 있습니다.";
    static final String RANK_NA_MSG = "금고 순위는 입찰 대상이 '주거래은행·금고'인 목표 건에만 정합니다.";
    static final String SUBJECT_MSG = "입찰 대상을 목록에서 골라 주세요.";
    static final String ETC_MSG = "기타 입찰 대상 이름은 1~50자로 적어 주세요.";
    static final String ETC_ONLY_MSG = "입찰 대상 이름 직접 입력은 '기타'를 고를 때만 씁니다.";
    static final String SUBJECT_FIXED_MSG = "입찰 대상은 바꿀 수 없습니다. 목표에서 빼고 새로 넣어 주세요.";
    static final String SUBJECT_OFF_MSG = "주거래은행·금고 밖의 입찰 대상은 아직 목표로 넣을 수 없습니다.";
    static final String WATCH_SUBJECT_MSG = "관심 기관에는 입찰 대상을 두지 않습니다.";
    static final String RANK_LOCKED_MSG = "제안 준비가 진행 중인 공고와 이어진 목표 건은 금고 순위를 바꿀 수 없습니다(미정이면 한 번 정할 수 있습니다).";
    static final String NA = "NA", UNDECIDED = "UNDECIDED", SET = "SET";
    /** PrepMapper.countActiveByInstitution 과 같은 목록 — 바꾸면 둘 다. */
    static final Set<String> ACTIVE_PREP = Collections.unmodifiableSet(new HashSet<String>(Arrays.asList(
            "CONFIRMED", "OPEN_PENDING", "IN_PROGRESS", "APPROVAL_PENDING", "WRITABLE", "WRITING")));

    static final class Slot {
        final int no;            // 기존 건 번호(>0) 또는 새 건(<=0)
        final Integer year;
        final String subject, etcKey, aim;
        Slot(int no, Integer year, String subject, String etc, String aim) {
            this.no = no; this.year = year;
            this.subject = subject == null ? BidSubjects.MAIN_BANK : subject;
            this.etcKey = BidSubjects.ETC.equals(this.subject) ? etcKey(etc) : "";
            this.aim = aim;
        }
        static Slot of(BidTarget t) { return new Slot(t.getTargetNo(), t.getTargetYear(), t.getBidSubjectCd(), t.getBidSubjectEtc(), t.getAimRankCd()); }
        String bucket() { return year + "|" + subject + "|" + etcKey; }
    }

    private BidTargetKeys() { }

    static String etcKey(String etc) { return etc == null ? "" : etc.trim().replaceAll("\\s+", " ").toLowerCase(Locale.ROOT); }

    static String rankState(String subject, String aim) {
        if (subject != null && !BidSubjects.MAIN_BANK.equals(subject)) return NA;
        return aim == null ? UNDECIDED : SET;
    }

    /** [코드, 기타 이름]. 비우면 MAIN_BANK. 켜진 코드만. ETC 는 이름 1~50자(BankContractRules.text 글자 규칙 + 금칙), 그 밖에 이름이 오면 400. */
    static String[] subject(String cdRaw, String etcRaw, BankContractRules.CodeCheck codes, boolean multi) {
        String cd = cdRaw == null ? "" : cdRaw.trim();
        if (cd.isEmpty()) cd = BidSubjects.MAIN_BANK;
        if (!cd.matches("[A-Z0-9_]{1,20}") || !codes.enabled(BidSubjects.GROUP, cd)) throw ApiException.badRequest(SUBJECT_MSG);
        if (!multi && !BidSubjects.MAIN_BANK.equals(cd)) throw ApiException.badRequest(SUBJECT_OFF_MSG);
        String etc = BankContractRules.text(etcRaw, 50, ETC_MSG);
        if (BidSubjects.ETC.equals(cd)) {
            if (etc == null) throw ApiException.badRequest(ETC_MSG);
            new MemoScreen("TARGET_FORBIDDEN", BidTargetRules.FORBIDDEN_MSG).free(etc).throwIfAny();
        } else if (etc != null) {
            throw ApiException.badRequest(ETC_ONLY_MSG);
        }
        return new String[]{cd, etc};
    }

    static boolean subjectGiven(String cd, String etc) { return cd != null || etc != null; }

    static void requireRankFits(String subject, String aim) {
        if (aim != null && subject != null && !BidSubjects.MAIN_BANK.equals(subject)) throw ApiException.badRequest(RANK_NA_MSG);
    }

    /** 바뀐 뒤 모습에서 규칙을 어기는 건 하나(이미 있던 건 먼저). 맞으면 null. year == null 은 목표가 아니라 뺀다. */
    static Slot conflictOf(Collection<Slot> after) {
        Map<String, List<Slot>> by = new LinkedHashMap<String, List<Slot>>();
        for (Slot s : after) {
            if (s.year == null) continue;
            List<Slot> l = by.get(s.bucket());
            if (l == null) { l = new ArrayList<Slot>(); by.put(s.bucket(), l); }
            l.add(s);
        }
        for (List<Slot> l : by.values()) {
            if (l.size() < 2 || pairOk(l)) continue;
            for (Slot s : l) if (s.no > 0) return s;
            return l.get(0);
        }
        return null;
    }

    private static boolean pairOk(List<Slot> l) {
        if (l.size() != 2 || !BidSubjects.MAIN_BANK.equals(l.get(0).subject)) return false;
        Set<String> r = new HashSet<String>();
        for (Slot s : l) r.add(s.aim);
        return r.size() == 2 && r.contains("FIRST") && r.contains("SECOND");
    }

    /** 금고 약정 줄을 그 건의 순위로 거른다 — 1·2금고 건은 그 순위 줄만, 그 밖(미정·단수·주거래)은 모두. */
    static List<BankContract> linesFor(List<BankContract> lines, String aim) {
        if (lines == null || !("FIRST".equals(aim) || "SECOND".equals(aim))) return lines;
        List<BankContract> out = new ArrayList<BankContract>();
        for (BankContract c : lines) if (aim.equals(c.getRankCd())) out.add(c);
        return out;
    }

    /**
     * 명시 연결이 없는 목표 건 → 추정 제안 건(열쇠 "기관#번호"). 같은 (기관·대상·연도)에 연결 없는 목표 건이 1개이고,
     * 어느 목표에도 명시 연결 안 된 진행 중 제안이 1개(확정 KST 연도 = 목표 연도, 순위 어긋나지 않음)일 때만. 쓰기 없음.
     */
    static Map<String, String> infer(List<BidTarget> goals, List<TargetCaseRef> cases) {
        Set<String> linked = new HashSet<String>();
        for (BidTarget t : goals) if (t.getBidCaseId() != null) linked.add(t.getBidCaseId());
        Map<String, List<BidTarget>> open = new LinkedHashMap<String, List<BidTarget>>();
        for (BidTarget t : goals) {
            if (t.getBidCaseId() != null || t.getTargetYear() == null) continue;
            String k = t.getInstitutionId() + "|" + Slot.of(t).bucket();
            List<BidTarget> l = open.get(k);
            if (l == null) { l = new ArrayList<BidTarget>(); open.put(k, l); }
            l.add(t);
        }
        Map<String, String> out = new HashMap<String, String>();
        for (List<BidTarget> l : open.values()) {
            if (l.size() != 1) continue;
            BidTarget t = l.get(0);
            Slot s = Slot.of(t);
            String hit = null;
            int n = 0;
            for (TargetCaseRef c : cases) {
                if (!t.getInstitutionId().equals(c.getInstitutionId()) || linked.contains(c.getBidCaseId()) || !ACTIVE_PREP.contains(c.getStateCd())) continue;
                String cs = c.getBidSubjectCd() == null ? BidSubjects.MAIN_BANK : c.getBidSubjectCd();
                if (!s.subject.equals(cs)) continue;
                if (BidSubjects.ETC.equals(cs) && c.getBidSubjectEtc() != null && !s.etcKey.equals(etcKey(c.getBidSubjectEtc()))) continue;
                String d = PrepBoardService.kstDate(c.getConfirmedAt());
                if (d == null || !d.startsWith(String.valueOf(t.getTargetYear()))) continue;
                if (t.getAimRankCd() != null && c.getBidRankCd() != null && !t.getAimRankCd().equals(c.getBidRankCd())) continue;
                hit = c.getBidCaseId();
                n++;
            }
            if (n == 1) out.put(t.getInstitutionId() + "#" + t.getTargetNo(), hit);
        }
        return out;
    }
}

## 5. 보안·위험·되돌리는 법

**권한(403 경로)**
- 목표 쓰기는 지금과 같습니다: `requireEditor` → `guard.denied` 감사.
- 확정은 PrepController의 기존 403 경로(`guard.denied` + BID_PREP_ACT DENIED)를 그대로 씁니다.
- 연결 쓰기는 확정 안에서만 일어납니다. `insert()`가 영업 계열이 아니면 403으로 막습니다(방어선).
- 새 엔드포인트는 없습니다.

**감사(누가·어느 화면·어느 버튼)**
- 연결은 목표 건 새 REV에 수정자·EMP_VERIFIED·화면·버튼·UI_VALID가 남습니다(bid_board/confirm).
- 미정→순위는 기존 고치기 REV(set_target_aim_rank)로 남습니다.
- 결재는 REQ_ACT에 그대로 남습니다.
- 결과·제출 체크는 BID_PREP_CHECK + BID_PREP_ACT(CK_RESULT·CK_PROPOSAL_SUBMIT)에 남습니다.
- BID_CASES.BID_RANK_CD UPDATE는 칸 자체에 감사가 없습니다. 같은 트랜잭션의 목표 REV가 근거입니다.

**접근 이력**: 확정에 `link=explicit|auto|none`만 더합니다. 기관·건 id, ETC 이름, 순위 값은 넣지 않습니다.

**자기신고 한계**: 모든 판정은 `X-Emp-No` 자기신고 위의 업무 규칙입니다. 비금고 건 성과는 담당 손 체크(자기신고)가 근거입니다. 화면에 근거를 표기해야 합니다(judged_by).

**동시성**
- 목표·확정·연결은 같은 기관 행 FOR UPDATE를 첫 문장으로 잡습니다.
- 키 규칙은 DB 유일 제약이 없고 잠금이 지킵니다. 점검 쿼리 ①로 확인합니다.

**점검 쿼리(되돌리기 전, 운영 점검 — 모두 0줄이어야 함)**
```sql
-- ① 같은 기관·연도에 살아 있는 목표 건 2개 이상
SELECT b.INSTITUTION_ID, b.TARGET_YEAR, COUNT(*) FROM INST_BID_TARGET b
 WHERE b.KIND_CD='GOAL' AND b.ACTION_CD<>'CANCEL'
   AND NOT EXISTS (SELECT 1 FROM INST_BID_TARGET n WHERE n.INSTITUTION_ID=b.INSTITUTION_ID AND n.TARGET_NO=b.TARGET_NO AND n.REV_NO>b.REV_NO)
 GROUP BY b.INSTITUTION_ID, b.TARGET_YEAR HAVING COUNT(*)>1;
-- ② 한 요청에 같은 기관 항목 2개 이상
SELECT REQ_ID, INSTITUTION_ID, COUNT(*) FROM INST_BID_TARGET_REQ_ITEM GROUP BY REQ_ID, INSTITUTION_ID HAVING COUNT(*)>1;
-- ③ 같은 기관 진행 중 제안 2개 이상
SELECT INSTITUTION_ID, COUNT(*) FROM BID_PREP WHERE STATE_CD IN ('CONFIRMED','OPEN_PENDING','IN_PROGRESS','APPROVAL_PENDING','WRITABLE','WRITING') GROUP BY INSTITUTION_ID HAVING COUNT(*)>1;
```

**되돌리기**
- S2·S3·S4는 서버만 되돌리면 됩니다.
  - 단 ①②③이 0이 아니면 옛 서버에서 문제가 생깁니다: 목록 줄 중복, 그 기관 쓰기가 DUP_TARGET, 확정이 영구 409.
  - 먼저 둘째 건을 빼고(목표 CANCEL), 진행 중 둘째 제안을 확정 취소해서 0으로 만든 뒤 되돌립니다.
- 스위치만 끄면(`multi-subject=false`) 새 비금고 건만 막히고 이미 있는 건은 남습니다.
- DB는 각 헤더의 DROP 순서를 따릅니다. **운영에서는 칸을 남기고 서버만 되돌리는 것을 권장합니다.**

**위험**
- 추정 연결은 화면 표시용입니다. 잠금(RANK_LOCKED)은 명시 연결에만 걸립니다.
- 1·2금고 둘 다 미연결이고 옛 제안이 1건이면 추정하지 않습니다 → 미분류로 보입니다(의도).

- S3b는 S2가 필요합니다.
- S4는 S2·S3a가 필요합니다.

## 부록 B. security 확인 목록(⑪)
1. ADD에 금고 순위 허용 — security 11-25가 '처음 넣을 때 비움'을 정한 이유가 결재 카드 단순화 말고도 있었는지.
2. 결재 항목 PK (REQ_ID, ITEM_NO): 한 요청에 같은 기관 여러 항목이 생깁니다. 다음을 확인해 주십시오.
   - 반영 원자성
   - 잠금 순서(기관 TreeSet)
   - 승인 때 묶음 키 재검사(`apply` → `checkSlots`)
   - DUP_ITEM
3. 요청자 조인 `ITEM_NO = 1` — 요청자 이름이 다른 요청에서 새지 않는지(요청 단위로 1명).
4. 제안 확정이 목표 표를 쓰는 새 경로(연결 REV) — 결재 우회가 아닌지(연도·대상·담당 불변, BID_CASE_ID와 미정→순위만), 화면·버튼 감사 값.
5. `/bid-targets`에 더한 `prep_state_cd·bid_case_id·link_basis` 노출 범위 — 영업 계열·디자이너(Teams.isSalesFamily)로 좁혔습니다. map 열람 전체 역할과 비교해 이 범위가 맞는지.
6. ETC 대상 이름 입력 검증(1~50자, 제어문자, 금칙), 오류 문구에 원문 없음, 접근 이력 미기재, 결재 카드·목록 이스케이프(프런트).
7. BID_CASES.BID_RANK_CD UPDATE — 조건부(NULL일 때만)이고 칸 자체 감사는 없습니다. 목표 REV를 근거로 보는 것으로 충분한지. 명시 연결·해제 API를 2차에 열 경우 다시 검토.
8. RESULT WON/LOST 허용 목록이 칸별인지(PT 등에서 거부), `/preps`에 이름 없음.
9. 비금고 성과를 자기신고 체크로 판정 — 성과표 표기(judged_by)로 충분한지.
10. 스위치 `multi-subject` 기본 false, 켜는 시점.
11. 466 이후 자기신고 인증 한계 문구 유지(새 클래스 머리 주석에 넣음).

## 부록 C. 사전 조회(⑦, 읽기만 — main이 로컬 MySQL에서 실행)
```sql
SELECT COUNT(*) FROM INST_BID_TARGET_REQ_ITEM x JOIN APPROVAL_REQUEST r ON r.REQ_ID=x.REQ_ID WHERE r.STATUS='PENDING';
SELECT REQ_ID, ITEM_NO, COUNT(*) FROM INST_BID_TARGET_REQ_ITEM GROUP BY REQ_ID, ITEM_NO HAVING COUNT(*)>1;   -- 0 줄이어야 066 가능
SELECT b.TARGET_YEAR, CASE WHEN b.AIM_RANK_CD IS NULL THEN 'UNDECIDED' ELSE b.AIM_RANK_CD END AS RANK, COUNT(*) FROM INST_BID_TARGET b
 WHERE b.KIND_CD='GOAL' AND b.ACTION_CD<>'CANCEL'
   AND NOT EXISTS (SELECT 1 FROM INST_BID_TARGET n WHERE n.INSTITUTION_ID=b.INSTITUTION_ID AND n.TARGET_NO=b.TARGET_NO AND n.REV_NO>b.REV_NO)
 GROUP BY b.TARGET_YEAR, CASE WHEN b.AIM_RANK_CD IS NULL THEN 'UNDECIDED' ELSE b.AIM_RANK_CD END;
```
5절 점검 쿼리 ③(같은 기관 진행 제안 2건 이상)도 함께 돌립니다.
