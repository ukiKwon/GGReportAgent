**1. 금고 방식 이어받기 3건 (:740·:754·:769).** 금고 순위를 비우던 부분을 되돌렸다.
- `BidTargetService.clearForWatch`는 이제 연결(`BID_CASE_ID`)·입찰 대상·기타 이름만 비우고, 금고 순위(`AIM_RANK_CD`)와 `AIM_RANK_ETC`는 그대로 둔다. `move()`와 `TargetChangeService.write()`의 TO_WATCH가 같은 함수를 쓴다.
- :769(이월)는 순위를 비워서 깨진 게 아니었다. 이월 판정에서 약정 줄을 `linesFor(…, aim)`으로 거른 것이 원인이었다. 시험의 약정은 1순위인데 건은 SECOND라 줄이 걸러져 이월이 안 됐다. `carryPlan`과 `carryInst`에서 이 필터를 뺐다.
  - 비금고 건을 이월에서 제외하는 것은 그대로다.
  - 순위별 약정 거르기는 설계서의 S4(성과·이월 건 단위화)로 넘긴다.

**2. 입력 오류 시험 (:275).** 원인은 `checkSlots`의 순서가 아니었다. 설계서가 DUP_INST를 없애서 같은 기관 ADD 두 개가 409 DUP_TARGET이 된 것이다.
- `lockAll`: 스위치(`multi-subject`)가 꺼져 있으면 같은 기관을 두 번 넣을 때 다시 400 DUP_INST(item_no 포함)를 던진다. 켜지면 같은 기관의 여러 건을 허용한다. 기본값이 false라 옛 동작이 그대로다.
- `plan()`에서 `checkSlots`를 사유 검사 뒤로 옮겨, 입력 400 → 409 순서를 지켰다.

**3. 영업부장 반려 뒤 관심 저장 (:227). 설계가 통과시키라고 하는 쪽이라 시험을 고쳤다.**
- 근거:
  - 1737 2절 표 '결재 중 잠금': "ⓐ 결재 중인 목표 건(TARGET_NO)만 모든 쓰기·확정·시작을 막는다. ⓑ 키 보호는 결재 중 항목이 건드리는 칸(연도·대상)에서 키를 바꾸는 변경만 막는다. 같은 기관의 다른 대상·다른 연도 건은 허용."
  - 1737 ④ save 패치: `requireNoPending(inst, cur)`는 `cur`가 있을 때만 막고, 새로 넣기(`cur==null`)는 칸 검사가 막는다.
  - 새 관심 행은 목표 칸 판정에서 빠지므로 키를 깨뜨리지 않는다. 중복 관심은 기존 `ALREADY_WATCH`와 `watchOn`의 내 TO_WATCH 충돌 검사가 계속 막는다.
- 시험 수정(`TargetChangeApiTest`): 결재 중 관심 저장은 201로 바꾸고, 반려 뒤에는 한 번 더 저장하면 409 `ALREADY_WATCH`를 확인한다. 메서드 이름과 javadoc은 이 근거를 적어 바꿨다.
- 이 결정이 틀리다고 보면(WATCH도 기관 단위로 막아야 한다면) `save()`에서 `watch && cur==null`일 때 `countPendingByInst`를 쓰는 한 줄로 되돌릴 수 있다. 메인이 판단해 달라.

**4. 연도 바꾸기 DUP_TARGET (:284).** 판정은 새 연도로 이미 잡혔고, 응답의 `latest`가 바뀌는 건 자기 자신(1번)이어서 시험의 기대값 2번과 달랐다.
