## 2. 키 계약
- 요청
  - API: POST /board-materials/{id}/result.
  - 본문: {result, meeting_date, agenda_no?}.
  - agenda_no는 result가 PASSED나 REJECTED일 때만 받는다.
  - 키를 생략하면 기존 값을 유지하고, ""이면 지운다. 앞뒤 공백은 잘린다.
  - 오류: 31자 이상, 줄바꿈이나 제어문자는 400 BAD_VALUE, 개인정보는 422 PII_DETECTED.
  - SCHEDULED로 보내거나 POST /board-materials/{id}/meeting-date에 agenda_no가 오면 400 AGENDA_NO_NOT_ALLOWED.
- 응답
  - agenda_no(null 가능)는 header()가 만드는 곳 어디에나 실린다. 결과 등록 응답, 자료 상세 GET /board-materials/{id}, 목록 items[]가 해당한다.
  - 기관 상세 8단계가 읽는 board 블록이 어디서 만들어지는지는 이 서버 코드에서 찾지 못했다. 다른 서비스가 result_cd나 meeting_date를 직접 내보내는 곳은 없었다.
  - 그래서 board 블록이 header() 결과를 그대로 쓰는지, 프런트가 목록 API를 읽는지는 메인이 확인해 주기 바란다.
- 이력: GET /board-materials/{id}/history의 RESULT 행 reason 칸에 `안건 번호: 제2026-12호 → 제2026-13호`가 남는다. 값이 없을 때는 (없음)으로 쓴다. 안건 번호가 바뀌지 않았으면 reason은 null이다.

## 3. 판단한 것
- 의결 예정으로 되돌릴 때: PASSED나 REJECTED에서 SCHEDULED로 바꾸면 안건 번호를 NULL로 비우고 이력에 남긴다. 원치 않으면 changeResult의 `else if (!decided && oldAgenda != null)` 가지를 빼면 된다.
- 오류 코드: 결과가 아닌 경로의 400에는 새 코드 AGENDA_NO_NOT_ALLOWED를 썼다.
- 줄바꿈 검사: 기존 checkedText는 \n을 허용한다. 줄바꿈 거부는 호출 쪽에서 \n과 \r을 따로 막았다.
- reason 칸 길이: 이력 문자열은 reason 칸(200자)에 들어간다. 안건 번호가 최대 30자씩 둘이어도 넉넉하다. 새 LOG 열은 만들지 않았다.

## 5. 메인이 실행할 것
1. 로컬 MySQL에 db/mysql/068_board_agenda_no.sql을 한 번만 적용한다(064까지 적용된 DB 기준, 멱등하지 않음). 8080 서버는 DB 적용 뒤에 재기동한다.
2. 먼저 `cd kgi-ggreport-web && mvn -q -o test -Dtest=BoardMaterialApiTest`를 돌리고, 통과하면 `mvn -q -o test` 전체를 돌린다. 기대 결과는 모두 통과다.
3. 새 시험은 rework(id, HEAD, ...)·send(...)·setResult 헬퍼를 쓴다. 같은 파일 앞쪽 시험이 쓰는 방식 그대로지만, 시그니처가 다르면 컴파일 오류가 날 수 있다.
