되찾기(REGAIN) 태그 서버 패치를 적용했다. mvn은 돌리지 않았다.

**만든 파일 (kgi-ggreport-web/ 아래)**
- `src/main/resources/db/oracle/059_target_tag_regain.sql`: 설계 원문 그대로다.
- `src/main/resources/db/mysql/059_target_tag_regain.sql`: 설계 원문 그대로다.
- `src/test/java/.../db/TargetTagRegainDdlPairTest.java`: 두 파일의 INSERT 블록이 같은지, 1행인지, NEW를 SORT_NO=3으로 올리는 UPDATE가 있는지 본다.

**고친 파일**
- `src/test/resources/application.properties:34`: schema-locations에서 058 뒤, 054 앞에 `db/oracle/059_target_tag_regain.sql`을 끼웠다.
- `BidTargetApiTest.java:168`: 태그 개수 단언을 2에서 3으로 바꿨다. 순서(RETAIN, REGAIN, NEW)도 확인한다. 요소 키는 `BidTargetService.codeList`(671줄)에서 `code`/`name`임을 확인해 `code`로 맞췄다.
- `BidTargetRulesTest.java:20`: 가짜 CodeCheck에 REGAIN을 추가했다. 새 테스트 `태그_REGAIN_통과`도 넣었다.
- `TargetChangeApiTest.java`: 새 테스트 `태그_REGAIN_ADD_EDIT_승인은_반영_모르는_태그는_400`을 추가했다. `tag_cd:"ZZ"`는 400이다. ADD(jongno)와 EDIT(jung)를 REGAIN으로 상신하고 영업팀장이 승인하면 TAG_CD='REGAIN' 행이 생긴다.

**하지 않은 것·확인한 것**
- `TargetResultRulesTest`(4절 4번)는 05 세션 파일이라 건드리지 않았다.
- `CommonCodeSchemaTest:58`은 TARGET_TAG 그룹을 이미 제외하고 있어 수정하지 않았다.
- Java 본 코드는 바꾸지 않았다.
- `BidTargetRules.parse` 결과의 필드명 `.tag`는 설계 보고서 말만 믿고 썼다. 컴파일 오류가 나면 이 필드명이 원인이다.
