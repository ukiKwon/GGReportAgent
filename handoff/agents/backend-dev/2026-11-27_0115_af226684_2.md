- **번호 현황:** `db/mysql`·`db/oracle`의 마지막 번호는 **064**(`064_bid_subject.sql`). 065·066·067은 아직 파일이 없으므로 **068은 비어 있다.** 단 065~067을 다른 세션이 만드는 중이니 적용 순서를 맞춰야 한다. MySQL은 번호 순서대로 한 번씩 돌리므로 065~067이 비어 있어도 068만 먼저 돌리는 건 문제없다.
- **개최일 흐름:** 화면은 `GET /board-materials/{id}`의 `header()` 응답을 쓴다. `meeting_date`는 `BoardMaterialService.java:899`, 화면은 `prep.js:1576`에서 읽는다.

- **대본 기본값 현황:** `PrepScriptIn.agendaNo`는 손 입력(`PrepScriptService.java:153`)이다. 비었을 때 `BoardScriptDocBuilder:74`가 '의안번호 입력 필요'를 찍는다. `loadAuto`(271행)는 이미 `chosen`(이사회 자료)을 읽고 있다.

## 4. 화면 계약 (프런트 이관)

- **필드 계약:** `GET /board-materials/{id}`와 목록 항목에 `agenda_no`(문자열 또는 `null`)가 추가된다. 키는 snake_case다.
- **쓰기 계약:** `POST /board-materials/{id}/result` 본문에 `agenda_no`를 선택으로 더한다. 빈 문자열이나 생략은 '기존 값 유지'다.
- **오류:**
  - 400 `BAD_VALUE` — 30자 초과나 제어문자.
  - 422 `PII_DETECTED` — 개인정보 같은 값.
  - 메시지에 입력값은 싣지 않는다.
- **프런트가 할 일:**
  1. `prep.js:1576` stepBoard 결과에 `agenda: str(d.agenda_no)`를 더한다.
  2. `resDateHtml`에 `<dt>안건 번호</dt><dd class="m">…</dd>`를 같은 `dl`에 더한다. 값이 없으면 '미입력'으로 표시한다.
  3. 결과 등록 폼에 안건 번호 입력 칸을 더한다. 30자 제한, 자유 형식, placeholder는 예 '제2026-12호'.
  4. 대본 창의 의안번호 칸을 `agenda`로 미리 채운다.
- **알려 둘 점:** 수정은 결과 등록 창을 같은 결과값으로 다시 저장하는 흐름이다. 비워 저장하면 지워지지 않는다는 문구가 필요하다.

## 6. 보안·위험·되돌리기

- **security가 볼 점:**
  - 안건 번호는 자유 글이므로 `checkedText`(개인정보 422·제어문자)를 거친다.
  - 이력·접근 로그에 값을 싣지 않는다.
  - 대본 폴백은 `canViewCase` 안쪽에서만 읽는다.
  - 쓰기는 기존 `/result`의 담당자 검사(`requireWriter`, 403)를 그대로 쓴다.
  - 인증은 `X-Emp-No` 자기신고이므로 '검증된 사용자' 표현은 쓰지 않는다. 변경 기록의 `emp_verified=false` 가능성이 있다.
- **위험:**
  - DB를 서버보다 먼저 적용해야 한다. 열이 없으면 이사회 자료 SELECT가 전부 500이다.
  - 값이 덮어써질 때 이전 번호는 남지 않는다.
  - `updateResult`의 `@Param` 누락은 시험이 바로 잡는다.
- **되돌리기:** 서버를 이전 빌드로 되돌린 뒤 `ALTER TABLE BOARD_MATERIAL DROP COLUMN AGENDA_NO`(Oracle은 `DROP (AGENDA_NO)`). 열이 남아 있어도 이전 서버는 읽지 않아 무해하다. 이미 적용한 DB는 068만 한 번 더 실행하면 된다(멱등하지 않으므로 중복 실행 금지).
