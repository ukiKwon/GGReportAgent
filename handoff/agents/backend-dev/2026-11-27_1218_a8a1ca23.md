hwpx 업로드 400의 가장 유력한 원인은 ZipGuard가 hwpx 안의 .xml이 아닌 파일까지 XML로 파싱하다가 실패해서 FILE_REJECTED(400)를 내는 것입니다. 코드만 읽고 낸 추정입니다. Bash가 없어 재현·git log 확인은 못 했고, config/application.properties는 읽지 않았습니다.

## ⓐ 원인 (가능성 순)
1. **Preview/PrvText.txt가 '<'로 시작하는 경우 (가장 유력).**
   - ZipGuard.check는 항목 이름이 아니라 내용으로 XML 여부를 정합니다 (docfill/ZipGuard.java:96-108,124-126,144-160). 앞 64바이트에서 BOM·공백·0바이트를 건너뛴 첫 글자가 '<'이면 XML로 보고 StAX로 끝까지 읽습니다.
   - 파싱이 실패하면 catch(XMLStreamException|RuntimeException)에서 Rejected("BROKEN")을 던지고 (ZipGuard.java:213-214), PrepAttachInspector.inspectZip이 이를 400 FILE_REJECTED "파일 구조가 안전하지 않거나 열 수 없어 올릴 수 없습니다."로 바꿉니다 (PrepAttachInspector.java:162-165).
   - 한컴이 저장하는 PrvText.txt는 문서 앞부분의 일반 텍스트(보통 UTF-16LE+BOM)입니다. 공고문은 '<입찰공고>', '< 붙임 >'처럼 '<'로 시작하는 경우가 흔하고, 이런 줄은 올바른 XML이 아니라서 예외가 납니다.
   - 시험 도우미 ExtCheckFixtures.hwpx에는 PrvText.txt가 없어서 이 경우는 한 번도 검증되지 않았습니다 (ExtCheckFixtures.java:206-209).
2. 한컴이 아닌 도구가 저장한 hwpx에서, STORED 항목에 데이터 디스크립터 플래그가 있는 경우. ZipInputStream이 ZipException을 내고 BROKEN → FILE_REJECTED가 됩니다. 한컴 원본에서는 드뭅니다.
3. section0.xml 등 XML에 DOCTYPE이 있거나 문법이 깨진 경우. 이때도 BROKEN입니다. 정상 파일에서는 드뭅니다.
4. 파일 이름 문제 (PrepAttachService.cleanName :499-519, requireAllowedExt):
   - 이름의 마지막 점 뒤가 hwpx가 아님 → UNSUPPORTED_FORMAT.
   - 서식 문자(U+200B·U+00AD·U+200E·U+200F 등) 포함 → BAD_VALUE.
   - 200자(UTF-16 단위) 초과 → BAD_VALUE.
   나라장터 이름이 길긴 하지만 200자를 넘는 경우는 드뭅니다.
5. mimetype도 contents/content.hpf도 없으면 FORMAT_MISMATCH (PrepAttachInspector.java:181). 한컴 hwpx에는 mimetype이 있어 정상 파일은 해당 없습니다.

**원인이 아닌 것**
- PrepUiIds는 허용 목록 밖의 값을 400으로 거절하지 않고 UNKNOWN으로 기록만 합니다 (PrepUiIds.java:9-11,82-88). attach_upload도 BUTTONS에 있습니다 (:25).
- BoardWriteLimitFilter는 Content-Length 초과 시 411/413만 냅니다 (:148-156). 400은 내지 않습니다.
- multipart 파라미터 이름은 task_cd·file로 화면과 일치합니다 (PrepController.java:356-358). NOTICE도 UPLOAD_KINDS에 있습니다 (PrepAttachService.java:81-82).
- 다른 400은 ApiExceptionHandler.java:81-91의 multipart 해석 실패(MSG_BAD_MULTIPART)뿐입니다.
- Scripts/ 빈 폴더, BinData의 이미지·OLE 확장자, META-INF, settings.xml, 압축 안 된 mimetype 첫 항목은 막지 않습니다. ACTIVE_CONTENT는 항목 이름에 vbaproject·activex·vbadata가 포함될 때만 걸립니다. 암호화 표시는 검사하지 않습니다.
- 개인정보(주민·외국인등록·카드번호) 차단은 422입니다. 400이 아닙니다.

## ⓑ 화면에 서버 문구가 안 보인 이유
- 서버 문구는 표시되도록 되어 있습니다. FILE_REJECTED는 p.message를 그대로 보여 주고 (prep.js:1018-1019), FORMAT_MISMATCH·ACTIVE_CONTENT·UNSUPPORTED_FORMAT은 ERR_BY_CODE 고정 문구입니다 (prep.js:172-174).
- BAD_VALUE는 문구에 "파일"이 들어 있고 영문_영문 패턴이 없을 때만 그대로 보이고, 아니면 일반 문구(prep.js:114, "처리하지 못했습니다. 화면을 새로 고친 뒤 다시 하세요.")가 나옵니다 (prep.js:1021-1026).
- 사용자가 본 "400"은 개발자 도구나 내부 로그일 가능성이 큽니다.
- setPerr가 단계 화면의 보이는 자리에 그려지는지는 확인하지 못했습니다 (프런트 확인 사항).

## ⓒ 최소 패치안
hwpx 검사에서만 "이름이 .xml/.hpf/.rels/.xsd가 아닌 항목이 '<'로 시작해도 파싱에 실패하면 건너뜀"을 허용합니다. 기존 xlsx·docx 동작은 바꾸지 않도록 ZipGuard에 오버로드를 추가합니다.

                           int maxXmlElements) throws Rejected {

public static Result check(..., int maxXmlElements, boolean lenientNonXml) throws Rejected {
    ...
    boolean xmlName = name.endsWith(".xml") || name.endsWith(".hpf") || name.endsWith(".rels") || name.endsWith(".xsd");
    countXml(kept.toByteArray(), counts, maxCells, maxRows, maxCellChars, maxXmlElements, lenientNonXml && !xmlName);

// countXml 에 boolean lenient 인자 추가
} catch (XMLStreamException | RuntimeException ex) {
    if (lenient) { return; }   // DOCTYPE·요소 수 한도의 Rejected 는 이 catch 에 오지 않고 그대로 전파

## ⓓ 사용자에게 확인할 것
- 화면에 나온 정확한 문구. 고정 문구마다 원인이 다릅니다.
  - "구조가 안전하지 않거나 열 수 없어" → FILE_REJECTED (원인 1~3).
  - "파일 내용이 확장자와 맞지 않습니다" → FORMAT_MISMATCH.
  - "파일 이름…" 계열 → 이름 규칙.
  - "처리하지 못했습니다…" → 일반 문구.
- 파일 이름 전체(길이·특수문자), 크기(MB), 가능하면 unzip -l 결과.
- 같은 파일을 한컴에서 다시 hwpx로 "다른 이름으로 저장"하면 올라가는지, 다른 hwpx는 올라가는지.
- 서버 로그와 응답 JSON의 detail.code (8080 재기동이 가능하면).

## ⓔ security가 볼 점
- 검사를 일부 느슨하게 하는 패치입니다. .xml이 아닌 이름의 항목이 XML처럼 보이는데 파싱이 안 되면 거절하지 않고 넘어갑니다.
- 그대로 유지되는 것: DOCTYPE 거부, 요소 수(3천만)·압축 해제 크기·중복 항목·항목 수 상한, activex·vba 이름 검사, 개인정보 검사.
- 남는 위험: .txt 이름 뒤에 숨긴 XML 안의 주민번호 등은 zipText가 읽지 않아 검사하지 않습니다 (기존에도 동일).
- 권한 검사(403)와 접근 이력은 변경 없습니다. 인증은 X-Emp-No 자기신고라는 한계가 그대로이고, 감사 기록에 파일 이름을 싣지 않는 규칙도 유지합니다.
- 되돌리는 법: ZipGuard 오버로드와 PrepAttachInspector.java:162의 인자를 원래대로 되돌리면 됩니다. DB 변경은 없습니다.
- 더 좁은 대안: Preview/ 항목이나 PrvText.txt만 이름으로 건너뛰는 안. 다만 한컴 외 도구가 만든 파일은 못 거를 수 있습니다.
