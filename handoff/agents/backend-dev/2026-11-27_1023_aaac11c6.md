### 2. 응답 키 계약(화면 담당용)
**GET /preps — 배열의 각 건에 더해진 키.** 사람 이름은 없습니다.

| 키 | 형 | 예시·값 |
|---|---|---|
| `opened_at` | 문자열\|null | `"2026-11-20T01:00:00+00:00"`, 시작 전은 null |
| `case_year` | 정수\|null | `2026`, 확정일의 KST 연도 |
| `bid_rank_cd` | 문자열\|null | `"FIRST"`, 065 건 순위 |
| `bid_rank_name` | 문자열\|null | `"1금고"`, 코드표에 없으면 null |
| `marks` | 객체 | `{submit, result, ceremony, agree_legal}` 각 `{mark_cd, marked_on}`. 기록 없음은 `{"NONE", null}`이고 날짜는 `YYYY-MM-DD`입니다. result에는 옛 DONE·IN_PROGRESS가 그대로 보입니다. |
| `stage5_cd` | 문자열 | `BEFORE`·`PREP`·`SUBMITTED`·`CONTRACT_PLANNED`·`CONTRACT_DONE`·`ENDED` |

| `result_cd` | 문자열\|null | `WON`·`LOST`·`UNDECIDED`(옛 완료·진행)·null |
| `result_recheck` | 불리언 | `result_cd==UNDECIDED`일 때 true, 담당이 선정/탈락을 다시 고릅니다 |

**GET /prep-board**
- 행에 `case_status`·`result_cd`·`result_recheck`가 더해집니다(위와 같은 값). 행의 `cells`는 28칸이 되고 `cells.PROPOSAL_SUBMIT`이 새로 생깁니다. 수동 칸 값은 옛 DONE이 그대로 보입니다.
- 최상위 `columns`는 28개가 되고 각 항목에 `marks`(허용 mark_cd 배열)가 더해집니다.
  - RESULT: `["WON","LOST","NA","NONE"]`
  - 그 밖: `["DONE","IN_PROGRESS","NA","NONE"]`
- 최상위에 `result_marks: [{mark_cd, symbol, name}]`(WON·LOST·NA·NONE)이 더해집니다. WON·LOST의 `symbol`은 null입니다. 기호 정책이 없어 글자 표시는 화면이 정합니다. 이름은 067 코드표(선정·탈락), 없으면 기본값입니다.
- `/prep-board` 행에는 `stage5_cd`·`opened_at`·`case_year`·`marks`·`bid_rank_*`를 싣지 않았습니다. 설계가 `/preps`에만 정한 키입니다.

### 3. 설계와 달라진 점·못 한 것
1. **`target_no`는 싣지 않았습니다.** 건과 목표 건의 연결(`INST_BID_TARGET.BID_CASE_ID`)은 066 표를 읽어야 합니다. 지시 ②에 따라 적용하지 않았고 S3b 몫입니다. 화면이 `target_no`에 기대면 아직 못 씁니다.
2. **`bid_rank_cd`·`bid_rank_name`은 설계 3-3 코드에는 없었는데 넣었습니다.** 지시문에 `bid_rank`가 키 목록에 있었고 065는 읽어도 된다고 해서입니다. 코드표 이름에는 `TARGET_AIM_RANK` 조인을 썼습니다. `OTHER` 이름은 066 INSERT가 적용돼야 나오고, 그 전에는 null입니다.
3. **`PrepUiIds`·`PrepBoardUiIds` 허용 목록은 바꾸지 않았습니다.** 제안서 제출 체크는 기존 `prep_dashboard/dash_check`와 `prep_detail/dash_check`를 그대로 씁니다. 새 버튼 ID가 필요 없습니다.
4. 설계의 `markView(mk, dates)` 대신, 날짜를 `selectStageMarks`가 같이 읽는 `MARK_DATE`로 채웠습니다.
5. `selectStageMarksOf`는 S2(ca)의 `checkRankLock`이 쓸 자리로 만들어 두었습니다. 지금은 호출하는 곳이 없습니다.
6. 중복 제거 열쇠(PrepBoardService 254행), `BidTargetKeys`, 제안 확정=목표 건 연결은 건드리지 않았습니다. `MapperStatementBindingTest`의 매퍼 수는 새 매퍼가 없어 그대로입니다. DB 파일은 건드리지 않았습니다.
