## 2. 확인한 것
- planSubmit 과 submitBoardMaterial 의 호출처는 각각 한 곳뿐이고 새 시그니처로 맞췄다.
- countApprovalStep 과 BOARD_FINAL 은 src 어디에도 남아 있지 않다.
- 타입: currentStep 과 stepNo 는 둘 다 int 라 == 비교가 안전하다. submitSnap 은 Integer, curSnap 은 int 다.
- BoardMaterialService 에 필요한 import 는 모두 이미 있다.
- BoardWriteExceptionHandler 가 BoardMaterialController 에 적용되므로 {"snap_no":"x"} 는 400 이 될 것으로 본다.
- 테스트 도우미: 지시한 이름이 모두 BoardMaterialApiTest 에 같은 이름으로 있다. userName 과 historyRow 만 새로 만들었다.
- 필요한 import 는 이미 있다.
- HEAD 의 /history 읽기는 기존 테스트가 200 을 확인한다.
- ApprovalTypes 에 BID_OPEN, PREP_APPROVAL 키가 있다.

## 5. 이관 메모
- [이관: 프런트] doAct('submit') 이 {snap_no: savedCount(M.data)} 를 보내야 한다. SNAPSHOT_CHANGED 409 문구, 머리 메타와 잠금 줄의 이름 표시, from_status 기반 되돌림 배너, 작업 이력 탭의 REJECT 사유 표시가 필요하다. 상세는 보고서 §6.
- [이관: security] 제출자·결재자·확정자 이름을 같은 건의 다른 담당자에게도 보여도 되는지 판단이 필요하다. 사번은 응답에 넣지 않았다.
- [이관: qa] 실DB 에서 두 세션이 동시에 제출과 저장을 하는 경합은 MockMvc 로 재현할 수 없었다. 그 시나리오는 qa 가 봐야 한다.
