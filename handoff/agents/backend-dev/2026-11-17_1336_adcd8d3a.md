# backend-dev-write 보고서 (자동 보존)

> SubagentStop 훅이 에이전트의 최종 메시지를 그대로 저장했다(2026-11-17 1336 KST, agentId adcd8d3a5bfb88699). 에이전트 출력이므로 사용자 결정이 아니다. 지시 내용·주제는 이 파일에 없다 — 필요하면 handoff/NEXT.md 항목이나 커밋 메시지로 찾는다.

---

NEXT 90 2단계 Java 쪽을 지시서대로 적용했습니다. 빌드와 테스트는 못 돌렸으니 메인이 `mvn`으로 확인해야 합니다.

**1. 고친 파일**
- `support/BatchSchema.java`: 상수 `EXTCHECK_PREFIX`(약 237줄)를 추가했습니다. `hasChecks`를 한 번만 계산하고, batch_id와 slug 검사를 넣었습니다. manifest 읽기 실패 문구는 고정했습니다.
- `support/Pii.java`: `SEP_RUN_EXT`를 `[...]++`로 바꿔 구분자 한 글자도 접습니다(39~42줄). 주민·카드 검사(약 212줄)도 `fold(text, true, SEP_RUN_EXT)`를 씁니다.
- `service/ExtCheckInspector.java`:
  - 이미지 수를 `countImages`와 `countInline`으로 셉니다. Form XObject 안과 인라인 이미지까지 보고, 링크 주석의 URI도 검사합니다.
  - HWPX에서 허용 목록 밖 항목은 `UNSUPPORTED_ENTRY`로 거부합니다.
  - `sha256Hex`와 한컴 빈 틀 상수 4개(`HWPX_*`)를 추가했습니다.
- `service/InboxService.java`: `log`와 `withOriginalsDeleted`를 추가하고 `importExternalChecks`를 교체했습니다. 모든 실패 응답에 `originals_deleted`가 들어가고, 원본이 남으면 배치를 inbox에 두고 `log.error`만 남깁니다.
- 시험 5개에 지시서 케이스를 더했습니다. 대상은 `BatchSchemaChecksTest`(`runAs` 일반화 포함), `PiiExternalTest`, `ExtCheckFixtures`(`pdfFormImage`, `pdfInlineImage`, `pdfLinkUri`), `ExtCheckInspectorTest`, `InboxExtCheckApiTest`입니다.

**2. 메인이 실행할 명령**
```
cd kgi-ggreport-web
mvn -q -o test -Dtest=PiiExternalTest,PiiTest,BatchSchemaChecksTest,ExtCheckInspectorTest,InboxExtCheckApiTest
mvn -q -o test
```
기대 결과는 전부 통과입니다. Windows 전용 "원본을 다 못 지우면" 시험은 Windows가 아닌 환경에서 건너뜁니다.

pdfbox API 불일치는 컴파일에서 날 수 있습니다. 후보는 `PDFStreamParser(PDContentStream)`, `PDAppearanceStream`용 `PDPageContentStream`, `PDStream.createOutputStream(COSName)`입니다. `PDAnnotationLink.setAction` 가능성도 있습니다. 컴파일되지 않으면 해당 메서드만 고치면 됩니다.

**3. 지시와 달리 판단한 것**
- **Scripts 예외**
  - 이름이 정확히 `Scripts/headerScripts.js` 또는 `Scripts/sourceScripts.js`이고 원본 sha256이 같을 때만 허용합니다. 허용하면 검사하지 않고 그대로 보관합니다.
  - 이름 비교는 대소문자를 구분합니다. `scripts/...`처럼 소문자로 쓰면 거부합니다.
  - sha256 계산을 위해 이 두 항목은 `drain`에서 바이트를 보관합니다.
- **Scripts 허용 쪽 양성 시험은 없습니다.** 실물 fixture `sunchang_32708.hwpx`를 검색했더니 Scripts 항목이 없었습니다(mimetype 검색은 잡혀서 바이너리 검색 자체는 동작함). 빈 틀의 실제 바이트를 몰라 코드로 만들 수도 없었습니다. 그래서 시험은 거부 쪽만 있습니다. 내용이 다른 `headerScripts.js`/`sourceScripts.js`, 다른 이름 `other.js`, 소문자 `scripts/`는 모두 `SCRIPT`로 거부되는지 봅니다. 메인이 Scripts가 든 실물 HWPX 한 건을 넘겨 주면 양성 시험을 더할 수 있습니다.
- **실물 fixture 시험:** `../collector/tests/fixtures/eminwon/sunchang_32708.hwpx`를 읽는 시험을 추가했습니다. 파일이 없으면 건너뜁니다. 통과 조건은 hit이 모두 `PII_*` 또는 `IMAGE_ONLY`뿐인 것입니다.
- **bmp:** `IMAGE_EXT`에 이미 있어서 추가하지 않았습니다. `BinData/image1.bmp`가 통과하는 시험을 넣었습니다.
- **실패 응답 검증:** 4xx 시험은 `asBoolean(true)` 기본값을 써서 `originals_deleted` 키가 없으면 실패하게 했습니다.
