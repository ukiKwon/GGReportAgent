## 3. 구현안

### 설계 판단 (근거)
**① 판단기준 칸**
- 연결(mapped) 칸이 아니라 **'직접 입력 + 엑셀 채우기 후보' 칸**으로 만든다.
  - 카탈로그에서 input=true, mapped=false, 기본 문구는 숫자 없는 문장이다. 키는 `r3_c2`로 그대로다.
  - 숫자 검증을 안 받는다(`!isMapped`는 `BoardMaterialService:991`에서 건너뜀).
  - 값은 문장 전체다. 서버가 읽은 `x.xx%`만 정해진 문장 틀에 끼워 만든다. 숫자 외 글자는 서버 상수다.
- 엑셀 지도의 채움 대상은 `mappedKeys`가 아니라 새 `BoardDocSpec.fillKeys`(mapped + 이 칸)이다.
  - 옛 형식(legacy) 지도 검증은 계속 `mappedKeys`를 쓴다. 그래서 `excel-map-legacy.json`과 "99칸" 시험은 그대로다.

**② 각주**
- 각주는 숫자 없는 고정 문장으로 바꾼다("※ 현재가치할인율: 올린 수익성분석표의 투자가부결정기준을 따릅니다"). 숫자는 판단기준 칸에만 나온다.
- 이렇게 하면 읽기 전용 규칙을 건드리지 않는다. 결정 ①(각주 숫자 = 표 숫자)은 각주에 숫자가 없으니 자동으로 충족된다.
- 각주에도 숫자를 보이려면 표에 행을 추가하는 구조 변경이 필요하다. 이관 메모 참조.

**③ CATALOG_VER**
- 올리지 않는다(2 유지). 칸 key·표 구조·열 id가 안 바뀌고, 칸의 mapped/input 속성만 바뀐다. `A r1_c0`을 입력 칸으로 바꿨을 때와 같은 방식이다.
- 올리면 map의 `catalog_ver`, `catalogOutdated` 배너, 시험 2곳이 같이 움직인다. 이점이 없다.

**④ 저장본 호환 (400이 나지 않는다)**
- v2 저장본: 옛 칸은 `i=false`다. `BoardDocSpec.java:864`의 기존 규칙("카탈로그가 입력 칸으로 바꾼 자리 → 저장 문구 유지한 채 입력 칸으로 올림")이 그대로 적용된다. 옛 문구(사용자가 고쳤다면 그 문구)가 남는다.
- v1 저장본(`readV1Structure`): `frozenInput`이 새 입력 칸을 입력으로 보면 `i` 불일치로 닫힌 실패(BAD)가 난다. 아래 패치 2로 예외를 하나 추가한다.
- 저장 JSON은 자동 재작성하지 않는다. 읽을 때 올라온다.
- Word 출력(`withValues`): 값이 없으면 칸의 기본 문구를 그대로 쓴다. 옛 자료도 옛 문구로 나온다.
- 낡은 편집 화면(배포 전에 열어 둔 것)이 옛 각주를 echo해서 저장하면 1회 400("표 주석은 수정할 수 없습니다.")이 난다. 새로 고침하면 풀린다. 프런트는 현재 응답의 notes를 그대로 보낸다(board.js:366·1009).

**⑤ 못 읽음 처리**
- reason 코드 `IRR_RULE_UNREADABLE` 하나로 통일한다(행 없음·빈칸·%가 0개·%가 2개 이상). status는 `failed`, value는 빈 문자열이다.
- `lookup=false`로 둬서 C-4 표 전체가 `needs_review`(머리글 의심)로 번지지 않는다. 다른 C-4 칸은 정상이다.
- 경고 문구 "수익성분석표에서 투자가부결정기준(IRR)을 찾지 못했습니다 — 직접 입력하세요"는 서버에 없다. 이 코드를 보고 화면이 만든다. 기존 reason 코드 처리와 같은 방식이다.
- 칸 기본 문구는 그대로이고 사용자가 직접 입력한다. 채우기 전과 같다.

**⑥ 보안**
- 응답의 `parts[].display`는 업로드 원문이 아니라 추출한 `3.30%` 토큰만 싣는다. 실패 시 parts를 비운다.

## 5. 보안·위험·되돌리는 법
- **권한**: 새 엔드포인트도, 새 403 경로도 없다. 업로드·채우기·저장은 기존 `BoardAccess` 경로를 그대로 쓴다. 인증은 여전히 `X-Emp-No` 자기신고(Actor)다.
- **접근 이력**: 본문·문장·숫자를 넣지 않는다. 기존 `BoardFormService`의 구조 변경 이력(숫자 요약)은 이 변경으로 달라지지 않는다.
- **입력 검증**
  - 문장은 서버 상수 + 정규식으로 뽑은 `[0-9.]%` 토큰으로만 만든다. 업로드 글자를 문장에 섞지 않는다.
  - 정규식은 100자 이하 입력에만 적용된다(`collect`의 TOO_LONG 선검사). 오류 문구에 내부 정보를 싣지 않는다.
  - 사용자가 값을 직접 입력하는 경로는 기존 `cleanValues`·PII 검사를 그대로 탄다.
- **주요 위험 1 (필수 확인)**: 화면(프런트) 쪽 작업 없이 서버만 먼저 배포하면 화면에는 엑셀 채우기 결과가 안 보일 수 있다. 입력 칸은 문구가 있으면 건너뛰기 때문이다(`board-write.js:396~401`). 서버 응답에는 `C-4/r3_c2`가 새로 실리고 summary의 total·filled·failed 숫자가 +1 된다. 배포 순서는 "서버+프런트 같이"로 잡는다.
- **주요 위험 2 (확정본 소급)**
  - 각주는 카탈로그에서 나오므로, 이미 확정된 자료를 Word로 다시 만들면 각주가 새 문장("…올린 수익성분석표의 투자가부결정기준을 따릅니다")으로 바뀐다. 옛 "3.30%" 표기는 사라진다.
  - 확정본의 칸 값 자체(저장된 값 스냅샷)는 안 바뀐다. 판단기준 칸은 옛 저장 문구가 유지된다.
  - 확정본 각주까지 불변이어야 하면 notes를 저장 버전별로 고르는 구조(CATALOG_VER 3)가 필요하다. 이 패치 범위 밖이다.
- **주요 위험 3**: 사용자가 양식 편집에서 이 칸의 문구를 고쳤다면(v2 저장본) 그 문구가 기본 문구로 유지된다. 손실 없음.
- **자기신고 한계**: 이 기능의 내용(투자 판단 숫자)은 인증과 무관한 업무 표시값이다. 검증됨 표현은 쓰지 않는다.
- **되돌리는 법**: 패치 1~6을 되돌리면 된다. DB·저장본 변경이 없어 데이터 롤백은 필요 없다. 이미 저장된 값 중 `r3_c2` 문장이 있으면 되돌린 뒤에는 `cleanValues`가 "값을 넣을 수 없는 칸"으로 거절할 수 있어, 그런 자료는 읽을 때 오류가 날 수 있다. 배포 후 실제 저장이 쌓이기 전에 판단하길 권한다.
