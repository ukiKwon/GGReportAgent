#### 예산 규칙
- **동대문·동작**
  - 사업별 `예산:` 또는 `[예산]` 줄이 있을 때만 읽는다. 지금 원문에는 한 줄도 없다(grep으로 확인).
  - 그래서 전부 `원문에 없음`이다.
  - 줄이 생기면 깨끗한 단일 금액만 `금액`으로 두고, 나머지는 `확인안됨` + `예산 원문` 비고로 둔다.
- **중구** (`jungBudget`, 단위는 장 머리의 `백만원`)
  - `계 N (…)`은 `금액`.
  - 괄호 안에 `YYYY:N, …`가 깨끗하게 파싱되면 연차예산 칸에 넣는다.
  - 재원 분담(`시비50/구비4,250`)·`연차별 배분 일부만…`처럼 남는 문구가 있으면 `예산 원문: …` 비고에 전문을 남긴다(도봉 규칙과 같은 방식).
  - `계 약 540`, `계 약 6,870(추정…)`, `표 미확인`, `표 상세 미확인`, `…추정`은 `확인안됨` + 원문 비고.
  - `표 없음`, `해당없음`, `별도 예산표 없음`은 `원문에 없음` + 원문 비고.
  - `예산:` 줄 자체가 없는 5·경제 14·15번(세입 목표 사업)은 `원문에 없음`.
- **추측 금지 원칙과의 관계**
  - 중구 `계 N`은 원문 계 숫자와 단위를 그대로 옮긴 것이다.
  - 중구의 `계`는 2022~2026 누계다. 노원 총사업비와 달리 "연 단위 칸에 누계를 섞는다"는 우려가 있을 수 있다.
  - 도봉(4개년 누계 `계 718`)이 같은 방식으로 이미 금액 칸에 넣고 있어 그에 맞췄다. 기획 확인 필요 사항으로 이관 메모에 적었다.

**P2. 새 예산 함수.** `export function gwangjinBudget(raw) { … }` 블록 바로 뒤에 추가한다.
```js
/** 동대문·동작: 사업 카드의 '예산:'·'[예산]' 줄(사업별로 적힌 경우에만 존재). 깨끗한 단일 금액만 금액, 그 밖은 확인안됨 + 원문. */
export const BUDGET_LINE_RE = /^(?:\[예산\]\s*:?|예산\s*:)\s*/;
export function labeledBudget(raw) {
  const r = String(raw ?? '').trim();
  if (!r || /^(?:-|미표기)/.test(r)) return blankBudget('NOT_IN_SOURCE');
  const t = tryAmount(r);
  const m = AMT_RE.exec(r);
  if (t.ok && !t.sum && m && m[0] === r) return blankBudget('AMOUNT', { amount: t.amount, unit: t.unit, note: /^연/.test(r) ? '예산 원문: ' + r : '' });
  return blankBudget('UNVERIFIED', { note: '예산 원문: ' + r });
}

/** 중구: '계 830 (2022:…)' = 2022~2026 누계(단위는 장 머리). 연차 괄호가 깨끗하면 연차예산 칸, 남는 문구가 있으면 원문을 비고에. */
export function jungBudget(raw, unit) {
  const r = String(raw).trim();
  const m = /^계\s+(\d[\d,]*(?:\.\d+)?)\s*(.*)$/.exec(r);
  if (m) {
    if (!unit || !(parseFloat(m[1].replace(/,/g, '')) > 0)) return blankBudget('UNVERIFIED', { note: '예산 원문: ' + r });
    let rest = m[2].trim();
    let years = '';
    for (const g of rest.matchAll(/\(([^()]*)\)/g)) {
      if (!/^\d{4}:/.test(g[1])) continue;
      const y = parseYears(g[1]);
      if (y.ok && y.years) { years = y.years; rest = rest.replace(g[0], '').trim(); break; }
    }
    return blankBudget('AMOUNT', { amount: m[1], unit, years, note: rest ? '예산 원문: ' + r : '' });
  }
  if (/^계\s/.test(r) || /미확인|추정/.test(r)) return blankBudget('UNVERIFIED', { note: '예산 원문: ' + r });
  return blankBudget('NOT_IN_SOURCE', { note: '예산 원문: ' + r });
}
```

**P6. 동작 전용 파서.** `parseChapter` 함수 끝(`return { fieldNo, … warns };\n}`) 뒤, `/** 원시 사업 -> 행 후보` 주석 앞에 추가한다.
```js
/** 동작: 파일 하나에 분야 여러 개('[힘이되는 복지] … (20~21쪽)'). 분야마다 '2026년 중점사업(N개):' 아래 '1.'부터 번호를 새로 시작한다. */
export function parseDongjakFile(text, seqStart) {
  const lines = text.replace(/^\uFEFF/, '').replace(/\r\n?/g, '\n').split('\n');
  const chapters = [];
  let ch = null;
  let cur = null;
  let on = false;
  for (let i = 0; i < lines.length; i++) {
    const line = lines[i].replace(/\s+$/, '');
    let mm;
    if ((mm = /^\[([^\]]+)\]\s*(.*?)\s*\((\d+)(?:~(\d+))?쪽\)$/.exec(line))) {
      ch = { fieldNo: String(seqStart + chapters.length), fieldName: mm[1].trim(), pageRange: mm[4] ? `${mm[3]}~${mm[4]}` : mm[3], declared: null, headerTotal: null, unit: '', items: [], warns: [] };
      chapters.push(ch);
      cur = null;
      on = false;
      continue;
    }
    if (!ch) continue;
    if (/^\[요약\]/.test(line)) break;
    if (/^=+$/.test(line)) continue;
    if (!on) {
      const dm = /^2026년\s*중점사업\((\d+)개/.exec(line);
      if (dm) { on = true; ch.declared = Number(dm[1]); }
      continue;
    }
    if (line.trim() === '') continue;
    if ((mm = /^(\d+)\.\s+(\S.*)$/.exec(line))) { cur = newItem(mm[1], mm[2], ''); ch.items.push(cur); continue; }
    const t = line.trim();
    if (!cur) { ch.warns.push(`줄 ${i + 1}: 사업 앞의 줄을 건너뜀`); continue; }
    if ((mm = /^[-*]\s+(.*)$/.exec(t))) { cur.lines.push(mm[1].trim()); continue; }
    if (cur.lines.length === 0) cur.head += ' ' + t;
    else cur.lines[cur.lines.length - 1] += ' ' + t;
  }
  return chapters;
}
```

**호출자가 실행할 명령**
1. 적용 전에 기준선을 잡아 둔다. `git status`가 깨끗한지 먼저 본다.
2. `cd kgi-ggreport-web && node --test tools/db/convert-plan-txt.test.mjs`
3. 건수 검산(쓰기 없음): `node tools/db/convert-plan-txt.mjs --check --strict`
   - 오류 0건이어야 한다.
   - `--strict` 건수 불일치가 없어야 한다.
   - 6개 구 모두 `인덱스 … (일치)`가 나와야 한다.
4. 쓰기: `node tools/db/convert-plan-txt.mjs`. 이어서 `git diff --numstat -- src/main/resources/plan-seed`를 본다.
   - 기대: dobong, gwangjin은 변경 없음, nowon은 정확히 2줄(62·136 레코드) 변경, 새 파일 3개 추가.
   - 새 파일: `dongdaemun_20260716_plan.csv`, `dongjak_20260716_plan.csv`, `jung_20260718_plan.csv`.
   - nowon이 2줄을 넘으면 P3 정규식을 의심한다.
5. 서버: 시드 파일 위치는 `plan-seed/{기관ID}_*_plan.csv` 와일드카드로 읽힌다(`InstitutionPlanService.java:457`). 서버 테스트는 `plan-seed-test`를 쓰므로 380건에는 영향이 없다. 서버 쪽 코드 변경은 없다. 보완 확인용으로 `mvn -q -o test`를 한 번 돌려 본다(8080 서버가 같은 `target/`을 쓰면 테스트 뒤 재기동).

**역슬래시가 든 새 줄(도구 함정 점검용).** 모두 `\d \s \S \p \( \) \[ \] \. \/ \+ \*`와 `\uFEFF`, `\r\n?`, `\n`뿐이고 `\u`+4자리로 문자를 만들거나 `\t`를 쓰는 곳은 없다. 단 `\uFEFF`(BOM 제거)는 기존 줄과 같은 표기라 P6에서 새로 한 줄 들어간다. 목록은 다음과 같다.
- P1: `CHAPTER_RE` 두 줄
- P2: `BUDGET_LINE_RE`, `labeledBudget`의 `/^(?:-|미표기)/`, `jungBudget`의 정규식 4줄
- P3: `multiYearPeriod`의 `matchAll` 줄(`[^~\n/]`의 `\n` 포함)
- P4: `dh`, `fieldName` 정리 2줄, `jd`
- P5: 동대문 2줄, 중구 2줄
- P6: `parseDongjakFile` 안 `\uFEFF`·`\r\n?` 줄과 정규식 5줄
- P7: `split(/\s\/\s/)`, `cm` 줄, `예산\s*:` 2줄
- P8: `inline` 정규식 1줄
- P9: `firstLine`, `pm` 폴백, `idxNamed`, `sums`, `idxFor`의 `f.slice`는 해당 없음, `CHAPTER_RE` 사용 줄
- 시험의 `'\n'` 문자열

적용 뒤 `grep -nE '\\u[0-9A-Fa-f]{4}|\\t' convert-plan-txt.mjs`를 돌리면, `\uFEFF` 줄과 `cleanText` 기존 줄 말고는 나오지 않아야 한다.

### 5. 보안·위험·되돌리는 법
- 서버 코드·DB 스크립트는 건드리지 않는다. 시드 CSV는 기존 경로(서버가 수집자 `seed-txt-convert/1` 고정, URL 빈칸 시드 경로 한정)로 들어간다. 변환기는 입력이 같으면 출력이 같다(시각·난수 없음).
- **권한·접근 이력·자기신고 인증**: 이 패치에는 새 엔드포인트가 없다. 시드 적재 API의 기존 권한은 그대로이고, 자기신고 인증의 한계도 그대로다.
- **되돌리기**: 변환기 파일과 plan-seed 새 CSV 3개를 되돌리고, 노원 CSV는 `git checkout`으로 되돌린다. 적용한 DB는 시드를 재적용하는 기존 절차를 따른다.
- **남는 위험**
  1. 실행해 보지 못했다. 가장 의심스러운 곳은 `내용 1000자 초과` 오류다. 동작 도시 3번(약 700자 추정)과 동대문 긴 사업이 후보이고, 넘으면 "자르지 않음, 사람이 줄여야 함" 오류로 해당 구가 안 써진다. 그 경우 오류 줄을 보고 데이터 이관으로 돌린다.
  2. 동작 `parseDongjakFile`은 이어진 줄이 `- `나 `* `로 시작하면 새 글머리로 오인한다. 현재 원문의 그런 줄(28개)은 모두 글머리라고 확인했다.
  3. 동대문·동작 확인상태는 07의 약식 이름과 완전 일치할 때만 붙는다. 동대문은 거의 전부, 동작·중구는 일부만 `미조사`가 아니게 될 것이다. 오류가 아니다.
  4. 노원 일관성은 콜론 있는 표기만 처리한다(아래 이관 메모).
  5. 동작 07 확인결과의 병합 칸 이름(예: `동작청년센터 개관('26.4월,장승배기로161)`)은 사업명과 달라 미조사가 된다.

### 6. 이관 메모
- `[이관: 기획] 노원의 콜론 없는 여러 해 소요예산(예: "기간 2023.6~2027.1 / 소요예산 4,000백만원", "사업기간 2020.1~2026.10 / 소요예산 16,105백만원")을 62·136행처럼 총사업비 규칙으로 보낼지 결정 — 기다리는 것: 기획 판단. 지금은 호출 지시대로 콜론 표기 2행만 바꿨다. 넓히면 05·06·07장 등 10여 행 이상이 더 바뀌고, 고치는 곳은 `multiYearPeriod` 정규식의 `기간:` → `기간:?` 하나다 — 근거: 노원 `05_4장` 10·12·14행 등, `04_3장` 24행.`
- `[이관: 기획] 중구 4개년 계획의 `계 N`(2022~2026 누계)을 도봉처럼 예산금액 칸에 금액으로 둔 것이 맞는지 확인 — 노원은 총사업비를 금액 칸에서 뺐고(11-16 결정), 도봉·중구는 누계를 금액 칸에 둔다 — 근거: `dobongBudget`, 중구 02 헤더 `계=2022~2026 누계`.`
- `[이관: 기획] 동작 02 세대별 사업(39개)을 분야별 56개와 함께 한 계획으로 넣는 것(권장안)의 확정, 동대문 문서명 `동대문구 2023년 주요업무계획`과 중구 `사업구분:` 내용 줄 방식 확인 — 근거: 동작 07 머리 "95개", 인덱스 54·55행.`
- `[이관: 데이터] 동작 `00_인덱스.txt` 11행 "총 46개 세부사업"을 39로 정정(02 요약·인덱스 54행은 39) — 기다리는 것: 데이터 확인 — 근거: 동작 인덱스 11·54행.`
- `[이관: 데이터] 동대문 07·동작 07·중구 07 확인결과의 사업명을 원문 사업명과 맞출지 — 지금은 완전 일치만 반영하므로 대부분 미조사로 남는다.`
