## 4. 우선순위 이슈

**[P2-1] 로그인 화면이 떠 있는 동안 뒤의 앱이 Tab 순서와 낭독 트리에 그대로 있음**
- 근거
  - `#login-view`는 `position:fixed; z-index:100` 덮개일 뿐입니다.
  - `app.showLogin`(app.js 866–875)과 `wireLogin`에 `inert`나 `aria-hidden` 처리가 없습니다.
  - 그래서 '다음 슬라이드' 버튼 다음에 Tab을 누르면 덮개 뒤에 가려진 헤더 '전국 지도' 탭 버튼으로 포커스가 갑니다.
  - 둘러보기 상태에서 프로필 칩으로 로그인 화면을 다시 연 경우에도 같습니다.
- 왜 문제인가: 키보드 사용자는 포커스 링이 보이지 않는 곳으로 사라집니다. 낭독기 사용자는 로그인 화면을 다 읽은 뒤 보이지 않는 앱 메뉴를 계속 듣습니다.
- 이번 변경 전부터 있던 문제일 가능성이 큽니다. git으로 확인하지 못했으므로 차단 사유로 삼지 않습니다.
- 수정 방향(패치 후보, app.js)
  ```js
  function shellInert(on) {
    [document.querySelector('body > header'), byId('shell')].forEach(function (el) { if (el) el.inert = on; });
  }
  // showLogin: view.classList.remove('hidden') 다음 줄
  shellInert(true);
  // enterApp: byId('login-view').classList.add('hidden') 다음 줄
  shellInert(false);
  // wireLogin 끝: 세션이 있으면 shellInert(false), 없으면 shellInert(true)
  ```

**[P2-2] 전역 `button:hover`의 border-color가 고스트·조작 버튼에 남아 hover 때 테두리가 더 어두워짐 (요청하신 항목)**
- 근거
  - 전역 규칙(index.html 45행)은 `button:hover { … border-color:#4a566b; … }`입니다.
  - `#login-view .lg-ghost:hover`(632행)와 `.lg-cbtn:hover`(643행)는 background·transform·box-shadow만 되돌리고 border-color는 되돌리지 않습니다.
  - 그 결과 기본 테두리 #626d81이 hover 때 #4a566b로 바뀝니다.
- 계산 대비
  | 버튼 | 바탕 | 기본 테두리 | hover 테두리 |
  |---|---|---|---|
  | 고스트 | 카드 바탕 ≈#171c26 | 3.3:1 | **2.3:1** |
  | 조작 버튼 | 화면 바탕 #0f1218 | 3.6:1 | **2.5:1** |
  - hover하는 순간 WCAG 1.4.11의 3:1 아래로 떨어집니다. '반응했다'는 신호가 거꾸로 '흐려짐'으로 보입니다.
  - 또 `.lg-ghost`의 transition에는 background만 있어서 테두리 색이 애니메이션 없이 툭 바뀝니다.
- 같은 뿌리의 잔여: 전역 `button:active { transform:translateY(0) scale(.98) }`가 고스트·조작 버튼·점에 그대로 걸립니다. 고스트와 조작 버튼은 눌림 피드백으로 괜찮습니다. 32px 점에는 불필요합니다.
- 패치 후보(632·643·649행 교체)
  ```css
  #login-view .lg-ghost:hover,
  #login-view .lg-cbtn:hover { background:var(--panel2); border-color:#626d81; transform:none; box-shadow:none; }
  #login-view .lg-dot:hover,
  #login-view .lg-dot:active { background:transparent; transform:none; box-shadow:none; }
  ```

**[P2-3] 꺼진 슬라이드 점의 대비가 2.2:1**
- 근거: `.lg-dot::before { background:var(--line-strong) }`(651행)에서 #424e62를 바탕 #0f1218 위에 쓰면 **2.2:1**입니다. 점은 '몇 장이 있고 지금 어디인가'를 알려 주는 조작 요소라 1.4.11의 3:1 대상입니다. 시안에서 넘어온 값입니다.
- 수정 방향: 꺼진 점만 기존 입력칸 테두리 값으로 바꿉니다. 새 hex가 아닙니다.
  ```css
  .lg-dot::before { left:12px; width:8px; background:#626d81; transition:background-color .2s; }   /* 3.6:1 */
  ```
  - 현재 점의 바탕 막대(653행 `--line-strong`)는 틸 진행 막대가 위에 덮이므로 그대로 둡니다.

**[P3-1] 이름이 "로그인"인 영역이 두 개**
- 근거
  - 바깥: `<div id="login-view" role="region" aria-label="로그인">`
  - 안쪽: `<section class="login-card" aria-labelledby="login-title">`. 이름이 있는 section은 region 영역이 되고, 제목 "로그인"이 이름입니다.
- 수정 방향: 바깥을 `aria-label="로그인 화면"`으로 바꿉니다. 테스트가 이 문자열을 단언하는지 grep으로 확인해야 합니다.

**[P3-2] '오늘' 눈금이 접수 3일 전부터 통째로 사라짐**
- 근거: `noticeView`의 `showToday: startPct - todayPct >= 15`, `buildNotice`의 `if (v.showToday) mark(...)`.
  - 11-13이면 오늘 71.4%, 접수 시작 85.7%라 차이 14.3으로 기준 아래입니다.
  - 접수 중(open)에는 항상 빠집니다.
- 왜 문제인가: D-3·D-2일 때가 가장 "지금 어디쯤인가"가 궁금한 때인데, 바로 그때 줄 위의 현재 위치가 사라집니다.
- 수정 방향: 점(흰 고리)은 항상 두고 글자만 뺍니다.
  ```js
  // buildNotice — 기존 if (v.showToday) … 한 줄 교체
  if (v.todayPct > 0 && v.todayPct < 100) mark('up today' + (v.showToday ? '' : ' lg-quiet'), v.todayPct, v.todayText, '오늘');
  ```
  ```css
  .lg-tl li.lg-quiet span { display:none; }
  ```
  - 순수 함수 테스트에 '접수 중에도 todayPct가 0과 100 사이'라는 단언을 하나 더하면 됩니다.

**[P3-3] "우리은행 → 국민은행"을 화살표로 읽음**
- 근거: `login-slides.js` items[].what의 "→"는 NVDA·센스리더에서 "오른쪽 화살표"로 읽힙니다.
- 수정 방향: 문장으로 바꿉니다. 사실값은 그대로이고 표현만 바뀝니다.
  - "우리은행에서 국민은행으로"
  - "우리은행에서 국민은행으로, 약정 2027–2030" ×2

**[P3-4] 접수 중 문구에 날짜가 없음**
- 근거: `sayOpen: '지금\n마포구 제안 접수 중입니다'`. 접수 전 문구("11월 16일, …")는 날짜로 시작하는데, 접수 중 문구는 '지금'으로 바뀌어 마감일이 큰 글자에서 빠집니다.
- 수정안: `'11월 19일까지\n마포구 제안을 받습니다'`. 날짜는 이미 레코드에 있는 receiveTo입니다.
- 남는 문제: say와 sayOpen의 날짜가 receiveFrom·receiveTo와 따로 적혀 있어 어긋날 수 있습니다. 개발 이관 메모에 적었습니다.

**[P3-5] `aria-roledescription="carousel"` 영문 그대로**
- 지난 보고서의 열린 질문이었는데 결정되지 않았습니다. 되돌리기 쉬운 선택이므로 팀 권장안은 `"슬라이드 묶음"`입니다. 한국어 낭독기에서 영어 발음이 섞이지 않습니다.

**[P3-6] DESIGN.md가 로그인 주버튼을 옛 클래스 이름으로 가리킴**
- 근거: DESIGN.md 411행은 `.login-actions .primary`인데, 구현은 `.login-actions .lg-primary`입니다.
- §6-A 문단과 함께 고치면 됩니다.

**수용 기록(조치 불필요)**
- 앱의 종이결 질감(`body::after`, z-index 99)이 로그인 덮개(z-index 100) 아래에 깔려 로그인 화면에는 질감이 없습니다. 시안과 다르지만 기능상 문제가 없어 그대로 둡니다.

## 6. 규격·문안

### 6-A. DESIGN.md 넣을 문단 (Components의 `### Modals & Popover` 앞에 새 소절로, 그리고 두 줄 수정)

새 소절:
```markdown
### Login Surface (표면 예외, 2026-11-11 — 시안 B-3)
로그인 화면(`#login-view`)은 앱 크롬이 아니라 **문 앞 표면**이다. 앱의 Tight Operate Ramp(11–16px)를
따르지 않는 유일한 곳이며, 예외는 아래 목록에 적힌 것만이다. 로그인 뒤 화면에 이 값들을 가져가지 않는다.
- **큰 글자(이 셋만):** 슬라이드 문구 `.lg-say` 300 / **40px**(폭 ≤1279px 36px, 높이 ≤820px 32px),
  line-height 1.25, -0.03em, `Malgun Gothic Semilight` · D-day `.lg-big` 700 / **64px**(높이 ≤820px 52px) `--mono` ·
  카드 제목 `.login-card h1` 700 / **26px**. 공고 조각 제목 `.lg-notice h3`만 17px `Batang`(공고문 원문의 인쇄체를
  흉내 낸 것, 시스템 글꼴). 나머지 글자는 11–16px 램프 그대로.
- **알약 주버튼:** `.login-actions .lg-primary` — 높이 50px, 반경 25px(=높이의 절반), 틸 채움 + #0d1116/700.
  채운 주버튼 예외 3곳 중 하나. 보조 `.lg-ghost`는 반경 8px 고스트(1px #626d81, 3.3:1). 알약 반경은 이 버튼에만 쓴다.
- **슬라이드 규칙:** 내용은 `frontend/data/login-slides.js`(실측 사실 + 출처 줄 필수, 근거 없는 수치 금지)에만 둔다.
  6초 자동 넘김(`--lg-dur`)과 320ms 페이드+16px 이동(`--lg-swap`) · 조작 줄(재생/멈춤 글자 버튼 → 이전 → 점 → 다음)은
  DOM에서 슬라이드보다 앞 · 자동 재생 중 `aria-live="off"`, 멈추면 `polite` · hover·포커스·탭 숨김·폭 ≤960px에서 정지,
```
