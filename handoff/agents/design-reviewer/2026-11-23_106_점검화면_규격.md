## 5-2. 접근성
- 대비(흰 패널): 확인 필요 `--orange` #8a5c00 5.8:1(10% 틴트 위 약 5.0:1 — 틴트 10% 고정), 점검 못 함 `--gray` #5c6670 5.8:1, `--muted` 8.7:1, `--red` 6.0:1.
- 색만으로 전하지 않음: 배지는 글자가 뜻, SVG 글리프(삼각형·체크·점선 원) `aria-hidden="true"`. '점검 못 함'·'일부만 점검'은 점선 테두리.
- 펼침 단추 [점검 결과]: `aria-expanded` + `aria-controls="dc-p-{n}"`, 높이 28px. 펼침 칸 `role="region"` + `aria-label="{파일명} 점검 결과"`(setAttribute).
- 표: `<caption class="sr-only">{파일명}에서 찾은 다른 기관 이름</caption>`, `<th scope="col">`, 체크칸 `aria-label="{기관 이름} {위치} 의도한 언급"`, label로 28×28px.
- 요청 중 체크칸에 disabled 대신 `aria-disabled="true"`, 다시 그린 뒤 같은 `data-key`(inst_id|loc_kind|loc_no) 체크칸에 포커스 복귀.
- `#dc-live`(sr-only, role=status): 올리기 결과, "서초구 슬라이드 4 — 의도한 언급으로 표시했습니다." / "… 표시를 풀었습니다.", 다시 점검 결과.

- 진행 막대: 기존 `.bd-w-prog`, `role="progressbar"`, `aria-label="파일 올리는 중"`.
- 제출 확인창: `role="alertdialog"`, `aria-describedby` 본문, 첫 포커스 [돌아가서 확인].

- 체크: 바꾸는 즉시 `POST …/doc-check/ack` 본문 `{"acked":true|false,"sha256":상세.sha256,"items":[{inst_id,loc_kind,loc_no}]}`(키 이름은 DocCheckAckIn.java로 확인). 성공 → 응답 상세로 다시 그림 + 요약. 실패 → 체크 원래대로 + 문구. 디자이너 && 상태 ∉ {대기, 작성중} 또는 state ∉ {DONE, PARTIAL}이면 disabled + 잠김 줄. 담당 아님은 403 문구로.
- XSS: name·inst_name·contexts[]·acked_by_name은 createElement + textContent만. URL은 encodeURIComponent(name).
