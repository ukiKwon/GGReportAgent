## 2. 총평
두 변경 모두 규격 안에 있어 막을 것은 없습니다. 새 hex·변수·그림자가 없고, 글자는 12–16px이며 숫자는 `.hb-k .v`와 같은 700 16px mono입니다. 고칠 것은 낭독기 띄어쓰기 1건(P3)이고, 문구 다듬기 1건과 0 표시 1건은 선택입니다.

## 4. 이슈
- **P3-1 낭독기에서 두 구절이 붙어 읽힘**: results.js:246에서 띄어쓰기가 `aria-hidden` 안에 들어 있습니다(`<span class="sep" aria-hidden="true"> · </span>`). 그래서 낭독기에는 '8곳남은 곳'처럼 붙어 읽힐 수 있습니다. 공백을 바깥으로 빼야 합니다.
  old: `'</span><span class="sep" aria-hidden="true"> · </span><span>'`
  new: `'</span> <span class="sep" aria-hidden="true">·</span> <span>'`
  눈에 보이는 모양은 같습니다. 테스트 문자열(`결과 난 곳 <b>8</b>곳` 등)도 그대로 통과합니다.
- **P3-2 0곳 표시(선택)**: 장 81에서는 결과가 0건일 때 띠의 '0곳'을 회색으로 바꿨습니다. 그런데 새 줄의 '결과 난 곳 0곳'은 본문색 굵은 글씨입니다. 사용자가 연초에 가장 먼저 보는 숫자이므로 0도 그대로 내는 것은 맞습니다(테스트도 의도로 고정). 같은 화면 안에서 맞추려면 `c.done === 0`일 때 해당 `<b>`에 `style` 대신 클래스 `mut`를 붙이고 `.rs-lead b.mut{color:var(--muted)}` 한 줄을 더하면 됩니다. 하지 않아도 됩니다.
- **P3-3 같은 숫자를 두 이름으로 부름**: 줄에서는 '남은 곳 16곳', 바로 아래 띠에서는 '결과 미확정 16곳'으로 같은 수를 다르게 부릅니다. '남은 곳'은 사용자 본인의 말이라 그대로 둡니다. 다만 띠 이름을 바꿀지는 이관 메모를 보세요.

## 5. 문구 / 접근성
- **.rs-lead**: 14px 줄이고, 바탕 위치에 따라 대비가 이렇게 나옵니다(토큰 계산).

| 바탕 | 본문 글자 #1e2124 | 가운뎃점·괄호 muted #464c53 |
|---|---|---|
| #e9ecf0 위 | 13.6:1 | 7.3:1 |
| 흰 바탕 | 16.2:1 | 8.7:1 |

  괄호 안 24는 400 13px 본문색으로, 현황판 `#hb-ours-btn b` 문법과 같습니다. 줄과 띠 사이 8px는 #rs-body의 12px 간격보다 좁아 두 덩어리가 한 묶음으로 보입니다. 맞는 선택입니다. truncated이면 줄을 빼서, 일부만 센 숫자를 내지 않는 원칙도 지켰습니다.
- **Word 완료 문구**: 원인(1장에 맞추려고) → 한 일(경력 5줄) → 기준(오래된 것부터) 순서로, 명령형이 아닌 평서형 보고입니다. 길이는 12px에서 한두 줄이고 위치(.hc-ref 안 .hc-ok, role=status, 포커스는 [워드 내려받기]로 복귀)도 적절합니다.
  - 남는 모호함은 '뺐습니다'가 카드 기록에서 지운 것으로 읽힐 수 있다는 점입니다. 권장 old/new(headcard.js:385):
    old: `out += ' 1장에 맞추려고 ' + (c ? ... ) + '을 오래된 것부터 뺐습니다.';`
    new: `out += ' 1장에 맞추려고 파일에서 ' + (c ? ... ) + '을 오래된 것부터 뺐습니다(카드 기록은 그대로).';`
    이렇게 바꾸면 테스트 1064–1066의 기대 문자열 3개도 같이 바꿔야 합니다. 바꾸지 않아도 출하는 가능합니다.
  - 서버는 날짜가 없는 줄을 가장 먼저 뺍니다(HeadDocBuilder:515). 그래서 '오래된 것부터'는 날짜 있는 줄에만 정확합니다. 드문 경우라 문구는 유지해도 됩니다.
