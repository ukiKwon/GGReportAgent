## 2. 한 줄 총평과 가장 큰 기회
**사용자 지적이 맞습니다.** 지금 1280×800과 1280×720에서는 두 카드가 **첫 화면에 전혀 보이지 않습니다**(계산).
- 두 카드는 .hb-grid 맨 아래(grid-column 1/-1)에 있습니다. 두 목록이 clamp(360, 100vh−250, 640)로 화면 아래 끝까지 채우므로, 카드 시작 위치는 약 y 802(800 높이)와 y 722(720 높이)입니다.
- 위에 보이는 것은 1600폭 이상(오른쪽 셋째 칸)뿐입니다.

**가장 큰 기회**: 카드 띠를 아래 두 목록과 **같은 열 비율(1.35fr : 1fr)**로 맨 위에 둡니다.
- 와플은 그 아래 '국민은행이 맡은 기관' 위에, 단계는 '준비 중인 제안' 위에 섭니다.
- 이렇게 하면 요약과 그 요약의 명단이 세로로 짝을 이룹니다. 이 화면에만 있는 짜임입니다.

(이 작업은 배치 규격이라 휴리스틱 점수표는 생략합니다.)

**잘 된 점**
- 두 카드 모두 새 색이 없고, 숫자는 16px mono, 보조 글자는 12px로 이미 규격 안에 있습니다.
- 자료가 비었거나, 권한이 없거나, 오류일 때의 상태 문구가 이미 갈라져 있어 위치를 옮겨도 상태 설계는 그대로 갑니다.

## 3. 우선순위 이슈
- **P1. 요약 카드가 첫 화면 밖에 있습니다.**
  - 근거: `kbboard.js:436`(.hb-cards가 .hb-grid 안 마지막), `index.html:1744`(clamp), `index.html:1760`(grid-column 1/-1), `index.html:1763`(위로 올라오는 것은 ≥1600뿐).
  - 왜 문제인가: '국민은행 금고 약정 243곳 중 n곳'과 '제안 진행 단계'는 화면 이름 옆 설명('국민은행이 맡은 기관과 제안 진행')의 절반입니다. 그런데 스크롤해야 보이고, 목록 안쪽 스크롤과 바깥 스크롤이 겹쳐 있는 줄도 모르기 쉽습니다.
  - 수정 방향: 6절 규격대로 처리합니다.
- **P2. 위로 올리면 목록이 짧아집니다(맞바꿈).**
  - 카드 띠 높이는 약 208px입니다.
  - 1280×800에서 목록 높이는 550 → 320px이 됩니다. 스크롤 칸에 행이 약 2.5개 보입니다.
  - 1280×720에서는 300px이 되고, 페이지가 40px 스크롤됩니다.
  - 그래서 와플 카드를 **가로 배치**(와플 | 범례·안내)로 접어 높이를 290 → 약 202px로 줄였습니다. 지금처럼 세로로 쌓은 채 올리면 290px이 되어 720에서 목록 머리만 보입니다.
- **P3. 헤딩 단계.** 화면 제목 '입찰 현황판'과 카드·목록 제목이 모두 h2입니다(기존과 같음). 이번 범위 밖이니 기록만 해 둡니다.

## 4. 문구 / 접근성
- **문구**: 바꾸지 않습니다. 와플 안내·범례·숫자 줄은 ㊺에서 정한 그대로 둡니다. dashboard.test.js 227·228·231행의 문자열도 모두 유지됩니다.
- **읽는 순서 = 보이는 순서**: 머리 → (오류 배너 role=alert) → 카드 2개 → 공고 알림 줄 → 두 목록.
  - 오류 배너 #hb-err는 카드보다 **위**에 남깁니다. 서버 오류 안내가 카드 숫자보다 먼저 읽혀야 합니다.
- **Tab 순서**: 단계 카드의 [다시 시도](오류일 때만)가 알림 줄 칩보다 앞에 옵니다. 화면 순서와 같으므로 괜찮습니다.
- **대화상자**: 열 때의 opener와 닫을 때의 fallback `#hb-ours`는 그대로입니다. 카드는 대화상자와 상호작용이 없어 영향이 없습니다.
- **대비**: 새 색이 없어 기존 값 그대로입니다(와플 빈 칸 테두리 3.2:1, 보조 글자 6.4:1 — ㊺의 계산값).
- **글자 크기**: 범례·안내 12px, 숫자 줄 13px, 숫자 16px mono입니다. 카드 제목 15px은 기존 값이고 DESIGN.md 램프(10–16) 안입니다.

## 5. 배치 결정

| 항목 | 결정 |
|---|---|
| 순서 | 머리(hb-top) → flash/err → **카드 띠** → 알림 줄 → 두 목록 |
| 알림 줄과의 관계 | 카드 **아래**, 목록 **바로 위**. 알림('공고가 난 국민은행이 맡은 기관 n곳 + 칩')은 바로 아래 목록에 대한 말이라 목록에 붙입니다. 빨강(hot) 알림은 720에서도 y 약 391–443으로 첫 화면 안입니다 |
| 상세와의 관계 | 상세는 대화상자라 위치 영향이 없습니다. 열고 닫는 흐름도 그대로입니다 |
| 열 맞춤 | 카드 띠 = `minmax(0,1.35fr) minmax(0,1fr)`, gap 20(목록 그리드와 같음). 와플 ↔ 맡은 기관, 단계 ↔ 준비 중인 제안 |
| ≥1600 | 오른쪽 셋째 칸 규칙을 **없앱니다**. 모든 폭에서 맨 위 띠입니다(폭마다 자리가 바뀌지 않게) |
| ≤880 | 한 줄로 쌓기(카드 → 카드 → 알림 → 목록), 목록 max-height 50vh(기존 그대로) |

**#hb-root 위끝 기준 세로 위치 (1280폭, 계산)**
- 머리: 0–28
- 카드: 48–256
- 알림: 276–328
- 목록: 348–668(800 높이) / 348–648(720 높이)

**첫 화면에 보이는 것**
- 1280×800: 카드 둘 전부, 알림 줄, 목록 머리(제목·합계·기간 버튼 약 114px), 묶음 제목 + 행 약 2.5개. 페이지 스크롤은 없습니다.
- 1280×720: 카드 둘, 알림, 목록 머리 + 행 약 1.5개. 페이지가 약 40px 스크롤됩니다.

**목록 높이**: `clamp(300px, calc(100vh - 480px), 640px)`
- 720 → 300, 800 → 320, 900 → 420, 1080 → 600
- 480 = 기존 250 + 카드 띠 208 + gap 20(띠와 알림 사이)을 반올림한 값입니다.
- 최소값을 360에서 300으로 낮춘 이유: 360이면 720에서 페이지가 100px 스크롤되어 목록 아래 끝이 잘립니다.

**치수 근거 (1280, 계산)**
- 와플 카드 549px, 안쪽 509 = 와플 294 + 간격 16 + 오른쪽 칸 199.
- 오른쪽 칸 높이 = 범례 18 + 8 + 안내 12px·keep-all 약 16자 × 6줄(108) = 134.
- 와플 카드 높이 = 18 + 머리 22 + 12 + 134 + 18 ≈ 204.
- 단계 카드 406px, 높이 = 18 + 22 + 10 + 114 + 8 + 18 + 18 ≈ 208.
- 띠 높이는 약 208px입니다(stretch로 두 카드가 같은 높이).
- 머리 줄 한 줄 확인: '국민은행 금고 약정'(15px, 약 135) + 12 + 숫자 줄(약 230) = 377 < 509.
