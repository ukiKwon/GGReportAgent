## 2. 한 줄 총평
지금 화면은 "양식 → 엑셀 → 초안 워드"로 끝나는 일회성 도구다. 020a가 정한 "기관+연도 자료 1건을 담당자가 함께 버전으로 쌓는다"와 구조가 맞지 않는다. 자료 단위로 들어가는 입구가 없고, 저장이 없고, 역할 구분도 틀려 있다.

## 4. 우선순위 이슈

**P0-1 담당자의 [이 양식으로 작성]이 아무 반응이 없다.**
- 근거: `board.js` `startWrite()`의 `if (!c || !current || mode !== 'view' || canEdit !== true) return;`. 버튼은 `canWrite`로 보이고 실행은 `canEdit`로 막힌다. 실측: 김영업(can_write true, can_edit false)으로 클릭했을 때 `#bd-w`가 생기지 않았고 `/board-forms/excel-map` 요청도 나가지 않았다.
- 왜: 진행이 불가능한데 이유 안내도 없다.
- 수정 방향: 이번 개편에서 이 버튼 자체를 없애고 목록 → 자료 열기로 진입한다(§6). 개편 전에 임시로 고친다면 조건을 `canWrite`로 바꾼다.

**P0-2 영업부장이 읽기 전용 표를 그릴 수 없다.**
- 근거: 박영업으로 `GET /board-materials/1`은 200(viewer 전부 false)이지만 `GET /board-forms/default_doc`은 403, `/board-docs/default_doc`도 403이다. `BoardFormController`가 `guard.require(req, MENU_KEY)`를 쓴다. 실화면에서도 "이 기능을 쓸 권한이 없습니다."가 떴다.
- 왜: 정책은 "영업부장은 모든 상태 읽기 전용"인데 값을 놓을 양식 구조를 받을 수 없다.
- 수정 방향: 이관(개발). 디자인 규격은 양식 구조를 받는다는 전제로 썼다.

**P0-3 숫자 칸 400이 어느 칸인지 알려 주지 않는다. 괄호 병기 칸은 늘 거부될 수 있다.**
- 근거: `canonNumber` 정규식 `-?(?:\d{1,13}|\d{1,3}(?:,\d{3}){1,4})(?:\.\d{1,2})?`, 메시지에 칸 정보 없음. 반면 화면 값에는 `"48.51 (36.85)"`(`bw.parenOf`, eok_paren), `(1,234)`·`△1,234`(`shownNum`이 받는 음수 표기), `−`(U+2212)가 있다.
- 왜: 엑셀에서 정상으로 채운 자료가 저장되지 않고, 사용자는 어느 칸이 문제인지 찾을 수 없다.
- 수정 방향: 화면에서 저장 전에 같은 규칙으로 미리 검사해 칸을 짚는다(§6 규격). 괄호 병기 칸을 어떻게 저장할지는 이관(개발·데이터).

**P1-1 영업부장 화면이 정책과 반대로 "권한 없음"을 보여 준다.** 근거는 P0-2와 같다. 수정 방향: 목록 화면에서 전체 자료를 읽기 전용으로 보여 준다(§6).

**P1-2 낡은 권한 안내가 함께 뜬다.**
- 근거: `board.actionsHtml`의 `else if (c.hasDoc && c.perm === 'no')` 분기가 canWrite와 상관없이 "자료 작성은 업무 수정 권한이 있어야 할 수 있습니다."를 붙인다. 실측: 김영업 화면에 [이 양식으로 작성]과 이 문장이 같은 줄에 나왔다.
- 왜: 020a부터 작성 자격은 '업무 수정 권한'이 아니라 '담당 배정'이다.
- 수정 방향: 이 문장을 삭제한다. 403 거부의 [권한 신청하러 가기] 버튼(`rejHtml` canPerm)도 삭제한다. 신청해도 담당 배정은 생기지 않는다.

**P1-3 같은 기관+연도 자료가 중복으로 만들어질 수 있다.**
- 근거: `create()`에 중복 검사가 없고 DDL에도 UNIQUE가 없다(grep 0건).
- 왜: 정책은 "1건 = 기관+연도"인데 담당자 2명이 동시에 만들거나 버튼을 두 번 누르면 2건이 생긴다.
- 수정 방향: 화면에서 이미 있으면 [만들기] 대신 [열기]로 바꾸고 누르는 동안 버튼을 잠근다(§6). 서버 강제는 이관(개발).

**P1-4 지금 작성 화면에는 "이어서 쓰기"가 없다.** `buildState`는 업로드 응답만 받는다. 저장본(`snapshot.tables[].cells`)으로 화면을 다시 채우는 상태가 필요하다(§6 상태 B).

**P2-1 시각이 UTC로 온다.** 실측 `created_at "2026-11-10T08:24:29.342000+00:00"`. 화면은 한국 시각 `11-10 17:24`로 바꿔 보여 줘야 한다.

**P2-2 서버 배정 목록에 기관명이 없다.** `/me/assignments`는 `bid_case_id`·`assigned_at`만 준다. 새 자료 만들기의 선택 목록은 team.js처럼 `/bidcases/latest` store와 이어 붙여야 한다(구현 메모).

**P3-1 감사 기록용 화면 이름.** 영업부장이 읽기 전용으로 열 때의 화면 식별자는 `board_review`가 의미에 맞다(§6-3). 서버 의도와 같은지 확인이 필요하다.

### 5-6 접근성(수치)
- **대비(계산값)**: `--muted` #98a1af는 bg 위 7.2:1, panel2 위 5.7:1. `--fg`는 panel 위 13.4:1, panel2 위 11.9:1. `--orange` #d9a05b(저장 안 한 수정)는 bg 위 8.2:1. 틸 테두리(버전 저장)는 panel 대비 7.0:1(비텍스트 3:1 충족). 새 상태 배지 테두리 `--line-strong`은 panel 대비 2.0:1로 장식이다. 뜻은 글자가 전하므로 색 단독 전달이 없다.
- **목록 표**: `<table class="ad-table">`에 `<caption class="bd-sr">이사회 자료 {n}건</caption>`과 `<th scope="col">`를 둔다. 행 클릭 대신 기관명 칸 안에 실제 `<button type="button">`을 두고 `aria-label="{기관명} {연도}년 이사회 자료 열기, {상태명}"`(esc)을 붙인다. 목록으로 돌아오면 열었던 그 버튼으로 포커스를 돌려준다.
- **탭(작성/버전 이력/작업 이력)**: `role="tablist"`, 탭마다 `role="tab"` + `aria-selected` + `aria-controls`를 둔다. ←/→로 이동하고 Home/End를 지원하며 roving tabindex를 쓴다. 기존 `.ap-tabs`의 키 처리 여부는 확인하지 못했다. 없으면 이번에 추가한다.
- **새 자료 패널**: `<fieldset>`+`<legend>`, 입찰 건은 `role="radiogroup"`(네이티브 radio). 열리면 첫 radio로, Esc·[취소] 후에는 [새 이사회 자료] 버튼으로 포커스가 간다. 만드는 중에는 `aria-busy="true"`이고 [만들기]를 `disabled`로 잠근다(중복 생성 방지).
- **저장 결과**: 성공·같음은 `role="status"`이다. 오류 상자는 `role="alert" tabindex="-1"`로 두고 포커스를 옮긴다(기존 `#bd-w-rej` 패턴). [그 칸으로 가기]는 기존 `firstUnreadable`처럼 칸 선택과 스포트라이트를 쓴다.
- **[버전 저장] 비활성**: 바뀐 값이 없을 때 `disabled` + `aria-describedby`로 작성 줄 상태("버전 n과 같음")를 연결한다. 비활성 투명도는 .55 이하를 넘지 않는다(DESIGN).
- **터치 타깃**: 기본 버튼 실측 높이 30px. 행 열기 버튼은 최소 높이 28px(패딩 4px 0)로 둔다.
- **이탈 보호**: 수정이 있으면 `beforeunload`를 건다. 앱 탭 닫기·메뉴 전환·계정 전환은 §5-4의 인라인 확인으로 처리한다(브라우저 확인창 금지 — 기존 테스트 규칙).

## 6. 규격·시안

### 6-1 ① 화면 흐름과 위치
- **메뉴**: 기존 `영업 추진 준비 › 이사회 › 이사회 자료 작성`을 **재사용한다(권장)**. 라벨은 사용자가 정한 이름이라 바꾸지 않는다(⑩장). id `soon:이사회 자료`와 접근 이력 `tasks:board`는 그대로 둔다. 새 메뉴 키를 만들지 않으므로 골든 04·05도 영향이 없다.
- **한 메뉴 안의 세 보기**(같은 앱 탭 안에서 바뀐다, `#bd-root`):
  1. **목록**(첫 화면) — 검색 줄 + 표 + [새 이사회 자료]. 오른쪽 위에 `link-btn` [양식 보기·편집].
  2. **자료**(`← 이사회 자료 목록`) — 머리(기관명 연도 · 상태 · 버전 · 담당) + 탭 [작성] [버전 이력 n] [작업 이력].
  3. **양식**(`← 이사회 자료 목록`) — 지금의 양식 보기·편집·복제·샘플 워드를 그대로 쓴다. **[이 양식으로 작성] 버튼과 권한 안내 2줄은 삭제한다.** 안내 문장은 "표의 숫자는 예시입니다. 틸 배경과 왼쪽 막대가 있는 칸은 엑셀 값이 들어가는 칸입니다."로 줄인다.
- **흐름**: 목록 → [새 이사회 자료] → 인라인 패널(내 담당 입찰 건 radio + 연도 select + 양식 select) → [만들기] → 자료 보기 [작성] 탭(상태 A: 드롭존) → 엑셀 올리기 → 지금의 칸 확인(표 확인·원본 팝업) → [버전 저장](인라인 메모 줄 → [이 내용으로 저장]) → 상태 줄 "버전 1을 저장했습니다." + 배지 준비 중→작성 중 → [버전 이력]·[작업 이력] 탭.
- **기간 검색**: 020a에서는 **연도만** 둔다. 개최일은 020b 확정 뒤에만 값이 생겨, 지금 넣으면 늘 0건을 돌려주는 필터가 된다. 개최일 열과 개최일 범위 필터는 020b에서 함께 넣는다(되돌리기 쉬운 결정이라 팀 결정으로 처리).

### 6-4 ⑤ 출력 규칙(security 중-3)
- `esc()`나 `textContent`로만 출력하고 innerHTML에 날값을 이어 붙이지 않는 값: `institution_name`, `status_name`, `result_name`, `assignees[].name`, 마지막 저장자 이름, `snapshot.note`, `snapshot.saved_by_name`, `tables[].cells` 값 전부, history의 `from_name`·`to_name`·`actor_name`·`reason`·`*_status_name`·`*_result_name`, 양식 이름, 파일 이름, 서버 `detail.message`, PII `kinds[].kind`.
- 속성 안(`aria-label`, `title`, `value`, `data-*`)도 `esc()`를 거친다. `material_id`는 `data-id`에만 두고(숫자여도 esc) 화면 글자·검색·URL 해시에는 넣지 않는다.
- 숫자 칸 값은 `bw.shownNum` 같은 파서를 거쳐 서식을 붙인 결과만 그린다. 원문 문자열을 이어 붙이지 않는다.
- 테스트 제안: 기관명·칸 값·메모에 `<img src=x onerror=…>`를 넣은 응답으로 각 HTML 함수가 `&lt;img`를 내는지 확인한다(프런트 테스트에 추가).

- **열 내용**:
  - 기관명: 버튼, 13px/700
  - 연도: mono "2026"
  - 상태: 배지
  - 담당자: 이름을 쉼표로 이어 쓰고, 내 이름은 `--fg`, 나머지는 `--muted`
  - 마지막 저장: "김영업 11-10 17:24"(이름 13px, 시각 mono 12px). 저장 전이면 muted "저장 전"
  - 버전: mono "v3" 또는 "—"
- **정렬**: 최근 저장(없으면 생성) 시각이 최신인 것부터. 서버 정렬이 다르면 화면에서 다시 정렬한다(300건 이하).
- **검색 동작**: 상태·연도 select는 바꾸면 바로 조회한다. 기관명·담당자 입력은 Enter를 누르거나 입력을 멈추고 400ms 뒤에 조회한다. 조건이 하나라도 있으면 [조건 지우기] `link-btn`을 보인다. 상태 옵션: 전체 / 준비 중(PREP) / 작성 중(DRAFT). 연도 옵션: 전체 / 올해-2 … 올해+1.
- **새 자료 패널**(목록 위에 인라인으로 펼침, 모달 아님):
  - 입찰 건 radio 목록(`.tm-picks`, 최대 높이 280px). 한 항목에 기관명 13px과 시도 12px muted, 오른쪽에 같은 연도 자료가 있으면 "이미 있음 · 작성 중"을 둔다.
  - 연도 select: 올해-1·올해·올해+1, 기본값은 올해.
  - 양식 select: 기본 양식이 기본값, 복제 양식이 있으면 함께 보인다.
  - 버튼: [만들기](`.bd-wb-main` 틸 테두리) / [취소]. 이미 있는 조합이면 [자료 열기]로 바뀐다.
- **자료 머리**:
  - 1줄: `노원구 2026년 이사회 자료` + 상태 배지
  - 2줄(meta): `버전 3 · 김영업 11-10 17:24 저장` / `담당 윤서준, 김영업, 배지아` / `양식 기본 양식`
  - 그 아래 탭
- **작성 탭의 상태 4개**:
  - **A** 값 없음(PREP·current_snap 0): 지금의 드롭존(`bw.dropHtml`)에 §5-4 문구.
  - **B** 저장본만 있음: 표를 저장값으로 채운다. 칸은 출처 없음·직접 고칠 수 있음 상태다. [수익성 분석표 보기]는 비활성으로 두고 describedby "엑셀을 올리면 볼 수 있습니다"를 연결한다. 요약 줄은 §5-4 상태 B 문구.
  - **C** 엑셀을 올린 뒤: 지금의 작성 모드 전체에 "저장하지 않은 수정 k칸"(기준 = 열 때의 버전 값)을 더한다.
  - **R** 읽기 전용(영업부장): 표만 보이고 입력·작성 줄·드롭존은 없다. `.bd-m-ro` 한 줄을 둔다.
- **작성 줄 버튼 순서**(왼→오, 5개를 묶음으로 나눈다): [엑셀 올리기|바꾸기] [수익성 분석표 보기] · [모든 표 복사] [초안 워드 내려받기] · **[버전 저장]**(맨 오른쪽, `.bd-wb-main`). [작성 끝내기]는 삭제하고 머리의 `← 이사회 자료 목록`(이탈 확인 포함)이 그 역할을 한다.
- **[버전 저장] 동작**: 누르면 작성 줄 바로 아래에 `.bd-confirm` 줄이 열린다. 내용은 "바뀐 칸 {k} · 확인 안 한 표 {m}개(저장은 막지 않습니다)" + 메모 입력(선택, maxlength 200, 160자부터 `.bd-m-notecnt` "165/200") + [이 내용으로 저장] / [취소]. 메모 입력에서 Enter를 누르면 저장한다. 저장 중 버튼 문구는 "저장하는 중…"이고 두 번 누를 수 없다. `base_snap_no`는 화면을 열 때 받은 `current_snap`이다.
- **버전 이력 탭**: `.ad-table`, 열은 버전(mono, 현재 버전에 '현재' 배지) | 저장한 사람 | 저장 시각(mono) | 메모(줄바꿈 허용, 최대 32em) | [보기]. [보기]를 누르면 표 위에 "버전 2 보기 · 읽기 전용 [버전 목록으로]"를 두고 그 버전 값을 읽기 전용으로 그린다. 작성 탭의 수정 상태는 그대로 보존한다(탭을 오가도 잃지 않는다).
- **작업 이력 탭**: `.ad-table`, 열은 시각 | 한 일(§5-5) | 한 사람(+자기신고).

## 7. 이관 메모
**개발**
- `[이관: 개발]` 영업부장이 양식 구조를 받는 경로가 필요하다. `/board-forms/{id}`가 403이다. 상세 응답에 문서 구조를 함께 싣거나 부장에게 읽기를 열어야 한다. — 디자인은 상태 R(읽기 전용 표)을 그릴 수 없어 기다린다 — 근거: 실측 403, `BoardFormController:70` `guard.require(req, MENU_KEY)`.
- `[이관: 개발]` 400 BAD_VALUE·422 PII에 문제 칸 위치(`ref`·칸 키, 값 제외)를 달 수 있는가. — [그 칸으로 가기] 버튼이 기다린다 — 근거: `canonNumber`·`checkedValues` 메시지에 위치 없음.
- `[이관: 개발]` 기관+연도 중복 생성 방지(409 `ALREADY_EXISTS` + 기존 material_id). — 화면은 미리 막지만 동시 생성은 막지 못한다 — 근거: `create()`에 중복 검사 없음, UNIQUE 0건.
- `[이관: 개발]` 숫자 정규식이 쉼표 있을 때 15자리까지, 없을 때 13자리까지 받는다(`\d{1,3}(?:,\d{3}){1,4}`). — 문구의 "정수 13자리"와 어긋난다 — 근거: `BoardMaterialService:73`.
- `[이관: 개발]` P0-1 `startWrite`의 `canEdit` 조건, `/excel`·`/draft-docx` 요청에 `bid_case_id` 추가, 저장본으로 화면을 채우는 상태(`buildState` 변형), 시각 KST 변환, 앱 탭 닫기·계정 전환 이탈 확인 훅. — 프런트 구현 몫 — 근거: §4·§6.
- `[이관: 개발]` 읽기 전용 화면의 감사 화면 식별자를 `board_review`로 보내도 되는가(서버 의도는 `/review` 전용일 수 있음). — §6-3 † 확정을 기다린다.

**데이터**
- `[이관: 데이터]` 엑셀 연결 칸의 실제 값 모양 — 괄호 병기 `48.51 (36.85)`, `(1,234)`, `△`, U+2212가 저장 규칙(쉼표·소수 2자리 숫자만)에 걸리는가. — P0-3의 크기가 이 답에 달려 있다 — 근거: `bw.parenOf`·`bw.shownNum` 대 `canonNumber`.

**기획**
- `[이관: 기획]` 수정 사유(반올림 맞춤·원본 오류 등)는 지금 화면 메모리에만 있다. 버전 저장 때 메모로 넘길지, 그냥 버릴지. — 저장 메모 줄의 기본값이 이 답을 기다린다.
- `[이관: 기획]` 자료를 만든 뒤 양식을 바꿀 수 있어야 하는가(지금은 API가 없어 "바꿀 수 없습니다"로 안내). — 새 자료 패널 안내 문구가 이 답을 기다린다.
