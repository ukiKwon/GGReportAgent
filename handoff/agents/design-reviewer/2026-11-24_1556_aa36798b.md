## 4. 우선순위 이슈
**P1-1 뉴스로 닫힌 요청이 'new'(새로 들어온 자료)로 뜸**
- 근거: `PlanCollectService.status()`의 `recent_applied`는 `status_cd=APPLIED`만 보고 `{institution_id, closed_at}`만 실음(close_reason 없음). `plans.js` `appliedMap`·`newChipHtml`이 이것을 'new'로 그림.
- 왜 문제: 예전 사업계획이 있는 기관에 다시 요청 → 새 계획을 못 찾아 뉴스 반입 → **예전 계획 옆에 'new'가 붙음**. 새 자료가 왔다고 거짓으로 알리는 것임.
- 수정 방향: 서버가 `recent_applied[].close_reason`을 내보냄(값은 서버 고정 코드 'NEWS' 또는 null, 개인정보 없음). 화면은 6-3대로 칩을 바꿈. → 이관 개발.

**P1-2 목록·현황판에서 뉴스가 있는 기관이 '자료 없음'(점선 = 아직 모름)으로 보임**

**P1-3 사업계획이 있는 기관은 뉴스로 닫혀도 요청자가 뉴스를 못 봄**

**P2-1 개발부서 처리 화면에서 뉴스로 닫힌 요청이 '반영됨'으로 보임**

**접근성**
- 칩은 글자로 뜻을 전함(색 단독 아님). '뉴스로 대체'는 `aria-hidden` 없이 화면에 그대로 둠('new'처럼 숨기지 않음).
- 기사 목록은 `<ul>`(순서 없는 목록, 보도일 최신순으로 보여 줌). 행마다 제목 링크가 하나뿐이라 Tab 순서는 목록 순서와 같음.
- 링크에 `aria-describedby="pl-news-note"`를 붙여 '인터넷 PC에서 열림'이 링크마다 읽히게 함. 화면 글자는 한 번만 씀.
- 새 창 링크: `target="_blank" rel="noopener noreferrer"`. `safeHttpUrl`이 null이면 링크 없이 제목 글자만 쓰고, 그 뒤에 `wf-badge pp-cancel` '링크 없음'을 둠.
- 대비(토큰 값으로 계산): `pp-neutral` 글자 #1e2124 / #f6f7f9 약 15.6:1, `pp-cancel` #464c53 / 흰색 약 9.3:1, 요약 #1e2124 / 흰색 약 16:1, `.db-why` 12px #464c53 / 흰색 약 9.3:1. 모두 4.5:1 이상.
- 불러오는 중 줄에는 `aria-busy="true"`. 오류 단추는 `<button type="button" id="pl-retry-news">`.

## 6. 규격
### 6-1. 보여 주는 조건 (T5)
- 기준은 사업계획 응답(`GET /institutions/{id}/plans`)의 `docs.length === 0`. 이때만 `GET /institutions/{id}/news`를 받아 그림.
- 뉴스 응답에서 `has_news === true`이면 뉴스 배치를 씀(`plan_state`는 보조 정보이고 화면 판정에 쓰지 않음 — 두 요청 사이에 경합이 생길 수 있음).
- `docs.length > 0`이면 뉴스 절을 그리지 않음. 캐시에 뉴스가 있어도 숨김. 사업계획 반입 뒤 다시 불러오면 자동으로 사라짐.
- 받는 순서(권장, 구현 판단은 프런트): 사업계획 응답이 docs 0으로 오면 그때 뉴스를 받음. 캐시는 `S.cache[id].news = {status, data, code}`.
- 뉴스 응답이 401·403이면 조용히 '뉴스 없음'으로 처리함(같은 map 권한이라 실제로는 드묾).

### 6-2. 사업계획 상세(오른쪽 패널) 배치 — `plans.detailHtml`의 `!docs.length` 가지
```
[h2 기관명] [sub]
┌ section.db-sec.pl-sum  h3 "사업계획"
│  p.pl-st : [관련 뉴스 3건][사업계획 못 찾음][오래됨?][요청됨?]   ← 최대 4개
│  p.db-empty : 사업계획 문서를 찾지 못해 관련 뉴스로 대신합니다. …
│  div.pl-req : [수집 요청] 새 계획이 나왔으면 다시 요청하세요.   ← hasData:true 로 부름
└
┌ section.db-sec.pl-news  h3 "관련 뉴스"
│  p.db-why.pl-news-meta : 확인 2026-11-18 · 보도일 2025-11-18 ~ 2026-11-18(최근 1년) · 3건
│  p.pl-warn (stale일 때만)
│  ul.pl-news-list > li.pl-news-it × N
│  p.db-why#pl-news-note : 요약은 기사 원문이 아니라 …
└
(검색칸 pl-kw 없음 — 사업 표가 없으므로)
```
- 칩 규칙: '관련 뉴스 N건'(`badgeHtml('pp-neutral', '관련 뉴스 ' + mono(n) + '건')`, n = `items.length`) → '사업계획 못 찾음'(`badge('pp-cancel', …)`) → stale이고 열린 요청이 없으면 `badge('cr-st gap','오래됨')` → 열린 요청이 있으면 기존 `OPEN_CHIP`의 짧은 글자(`stChip('cr-st '+open[0], open[1], rc)`). 'new'·'뉴스로 대체' 칩은 상세에는 넣지 않음(본문 문장이 같은 말을 함, 4개 상한).
- 기사 순서: `published_on` 내림차순, 같으면 서버 순서.
- 요약은 자르지 않음: 서버가 3줄·300자를 이미 보장함. 줄 수 제한(line-clamp)도 쓰지 않음.

### 6-3. 마크업 (순수 함수, node 시험 대상)
```js
// nv = { status:'loading'|'error'|'ok', data, code }
plans.newsItemHtml = function (it) {
  const url = logic.safeHttpUrl(it.url);
  const title = esc(str(it.title));
  const field = str(it.field_name || it.field_cd).trim();
  const t = url
    ? '<a href="' + esc(url) + '" target="_blank" rel="noopener noreferrer" aria-describedby="pl-news-note">' + title + '</a>'
    : '<span>' + title + '</span> ' + badge('pp-cancel', '링크 없음');
  const sum = esc(str(it.summary)).replace(/\r\n?|\n/g, '<br>');   // esc 뒤 줄바꿈
  const day = ymd(it.published_on);
  return '<li class="pl-news-it">' +
    '<p class="pl-news-t">' + (field ? badge('pp-neutral', field) : '') + t + '</p>' +
    '<p class="db-why pl-news-src">' + esc(str(it.press)) + (day ? ' · 보도일 ' + mono(day) : '') + '</p>' +
    (sum ? '<p class="pl-news-sum">' + sum + '</p>' : '') + '</li>';
};
plans.newsSecHtml = function (d, months) {
  const items = (Array.isArray(d.items) ? d.items : []).map(function (x, i) { return { x: x, i: i }; })
    .sort(function (a, b) { const p = ymd(b.x.published_on), q = ymd(a.x.published_on); return p < q ? -1 : p > q ? 1 : a.i - b.i; })
    .map(function (o) { return o.x; });
  const mo = Number(months) > 0 ? Math.floor(Number(months)) : 12;
  const meta = '확인 ' + mono(ymd(d.checked_on)) + ' · 보도일 ' + mono(ymd(d.window_from)) + ' ~ ' + mono(ymd(d.window_to)) +
    '(최근 1년) · ' + mono(items.length) + '건';
  return '<section class="db-sec pl-news" aria-labelledby="pl-news-h"><h3 id="pl-news-h">관련 뉴스</h3>' +
    '<p class="db-why pl-news-meta">' + meta + '</p>' +
    (d.stale ? '<p class="pl-warn">확인 ' + mono(ymd(d.checked_on)) + ' 뒤로 ' + mo + '개월 넘게 다시 확인하지 않았습니다. 새 기사가 있을 수 있으니 수집을 다시 요청하세요.</p>' : '') +
    '<ul class="pl-news-list">' + items.map(plans.newsItemHtml).join('') + '</ul>' +
    '<p class="db-why" id="pl-news-note">요약은 기사 원문이 아니라 수집할 때 따로 정리한 글입니다. 원문은 제목 링크로 엽니다(인터넷 PC에서 열림).</p></section>';
};
```
- `months`는 뉴스 응답의 `stale_months`(없으면 12).
- `detailHtml`의 `!docs.length` 가지에서 `o.news` 상태별로 그림:
  - `ok && data.has_news`: 6-2 배치. 이때 `reqLineHtml(..., { hasData: true, ... })`.
  - `loading`: 기존 칩(`stateChipsHtml(null, …)`) + `<p class="db-empty" aria-busy="true">관련 뉴스가 있는지 확인하는 중입니다…</p>` + reqLine.
  - `error`: 기존 칩 + 뉴스 없음 문장 + `<p class="db-why">관련 뉴스를 불러오지 못했습니다(' + esc(code||'연결 실패') + '). <button type="button" id="pl-retry-news">다시 불러오기</button></p>` + reqLine.
  - `ok && !has_news` 또는 `o.news` 없음: 기존 칩 + 뉴스 없음 문장(5절 표, 요청 못 하는 사용자도 같은 문장) + reqLine.

### 6-4. 요청 상태 칩 (`stateChipsHtml`·`sectionInner`·목록 3행) — P1-1 서버 값이 온 뒤
- `appliedMap`: `close_reason === 'NEWS'`인 행은 `CS.applied`에 넣지 않고 `CS.newsClosed`(기관 ID → `{closed_at}`)에 따로 넣음. `ownPut`·`ownGet` 규칙은 그대로.
- `st`가 null이고 `newsClosed`가 있으면 `unk('자료 없음')` 대신 `<span class="wf-badge pp-neutral" data-st="NEWS" title="…">뉴스로 대체</span>`를 그리고, 열린 요청 칩이 있으면 그 뒤에 붙임.
- `st`가 있고 `newsClosed`가 있으면 'new' 자리에 `<span class="wf-badge pp-cancel" data-st="NEWS_OLD" title="…">새 계획 못 찾음</span>`을 그리고, 이때 '오래됨'은 빼지 않음.
- (P1-2 서버 값이 온 뒤) 목록에서 뉴스만 있는 기관은 '자료 없음' 대신 `badgeHtml('pp-neutral','뉴스 ' + mono(n) + '건')`. 목록 필터 '자료 없음'에는 그대로 남음(사업계획 기준). 필터 이름을 '사업계획 있음/없음'으로 바꿀지는 그때 다시 봄.

### 6-5. 개발부서 처리 화면 (`plancollect.js`)

## 7. 전/후 장 필요 (`docs/design_history/index.html`, 적용 커밋과 함께)
- **전**: 사업계획이 없는 기관의 상세는 점선 칩 '자료 없음'과 "아직 수집되지 않았습니다" 한 줄뿐이었음. 뉴스를 반입해도 화면에 보이지 않았음. 요청자 목록에는 파랑 'new'(새로 들어온 자료), 개발부서 표에는 파랑 '반영됨'으로 떠서, 사업계획이 들어온 것처럼 읽혔음.
- **후**: 상세 '사업계획' 절 첫 줄이 [관련 뉴스 3건](회색 칸) [사업계획 못 찾음](흐린 윤곽)으로 바뀜 = 확인된 사실. 아래 '관련 뉴스' 절에 확인일·최근 1년 기간·건수, 기사마다 분야 꼬리표 + 제목 링크 + 언론사·보도일 + 요약(최대 3줄)이 보임. 요청 칩은 무채색 '뉴스로 대체', 개발부서 표도 '뉴스로 대체 + 사업계획 못 찾음 · 관련 뉴스 반입'으로 '반영됨'(파랑)과 색·글자 둘 다 다름. 반입 표에는 파일마다 '사업계획/뉴스' 칩이 붙음.
- **대비**: 회색 칩 글자 15.6:1, 흐린 윤곽 칩 9.3:1, 요약 본문 16:1(토큰 값으로 계산, 렌더 측정 전).
- **왜**: 'new·반영됨'은 사업계획이 왔다는 거짓 신호였음. 뉴스는 사업계획을 대신하는 자료일 뿐이라는 점(본문 없음, 원문은 링크)을 화면에 분명히 밝힘.
