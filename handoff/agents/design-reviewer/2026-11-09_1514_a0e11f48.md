## 6. 규격

### ① 배치(작성 화면)
```
[작성 바] 자료 작성 중 · … | [엑셀 바꾸기][수익성 분석표 보기][모든 표 복사]  (!확인 안 한 표 2개) [초안 워드 내려받기][작성 끝내기]
요약 문구 / 필터 칩(전체·수정됨·확인 필요·확인 안 한 표)
표 확인 4/6   ← 6/6이면 [검수 완료 · 마지막 확인 14:32] 칩
┌ 카드(전체 폭) ─────────────────────────────────────────────────┐
│ (B) 5. 수익성 분석  [합계 차이 1]      [원본 보기][이 표 복사][☐ 이 표 확인 14칸] │
│ (해제 알림 줄 — 해당할 때만)                                       │
│ 표 …                                                            │
└──────────────────────────────────────────────────────────────┘
[상태 줄 — 칸을 골랐을 때만, 한 줄]
```
- `.bd-w-grid`의 2열 배치를 없애고 `.bd-w-tables`만 남깁니다.
  - 폭은 컨테이너 100%입니다.
  - 1600px 이상 화면만 대비해 `max-width:1280px`를 둡니다. 1440에서는 컨테이너가 1142px라 영향이 없습니다.
- **'수익성 분석표 보기'** 버튼은 두 곳에 둡니다.
  - ⓐ 작성 바의 '엑셀 바꾸기' 바로 오른쪽(전체 열기)
  - ⓑ 각 카드 머리의 **'원본 보기'**(그 표 위치로 스크롤해서 열기)
  - 칸을 고른 상태에서 열면 그 칸 위치로 엽니다.
- 카드 머리 오른쪽 순서: `원본 보기` → `이 표 복사` → `이 표 확인`. 확인을 맨 끝에 두는 이유는 마지막 행동이기 때문입니다.

### ② 상태 줄: 줄여서 남기는 것을 권장
없애지 않는 이유가 있습니다. 고치기 전 확인 묻기(`askHtml`), 수정 사유 칩, '원본 값으로' 버튼, 낭독 영역(`#bd-w-live`)이 지금 상태 줄에 있습니다. 이것들을 옮기면 위험이 커집니다.

- 칸을 고르지 않았을 때는 화면에서 숨깁니다. `#bd-w-live`는 화면에 보이지 않게만 숨기고 남겨 둡니다. 안내 문구 `표의 칸을 고르면…`은 뺍니다.
- 칸을 골랐을 때 한 줄 구성: `{표명 › 행 › 열}` │ `48.51 억원 ← K54 4,851.4 백만원`(대조 줄) │ [분석표에서 보기] │ (수정된 칸이면) 사유 칩 + [원본 값으로]
- 빼는 것:
  - 두 번째 줄(시트·표시·원래 값)
  - 계산 줄(`bd-w-calc`)
  - '확인' 버튼
- 계산 줄과 부분 칸 목록은 툴팁(`#bd-tip`)과 팝업 편집 영역에만 둡니다.
- 높이 목표: 수정되지 않은 칸 40px 이하, 수정된 칸 72px 이하. 패딩은 8px 14px, 글자는 13px입니다.

7. 버튼: [적용] (틸 테두리, 채우지 않음) · [원본 값으로] (수정된 칸만) · [취소]
8. 결과 알림(`role="status"`):
   - `총기대수익을 48.51에서 49.00으로 고쳤습니다. ‘5. 수익성 분석’ 표의 확인을 풀었습니다.`
   - 뒤에 재검산 문구를 붙입니다(`recheckLines`).
- 쓰이지 않는 칸을 눌렀을 때: `이 칸은 이사회 자료에 쓰지 않습니다.` 입력은 보이지 않습니다.
- 팝업 안에서는 '고치기 전 확인(ask)'을 생략하는 것을 권장합니다. 편집 영역이 같은 사실을 이미 보여 주기 때문입니다.

**키보드·포커스**
- 열 때 포커스 위치: 고른 칸이 있으면 그 원본 칸, 없으면 원본 표 영역(`tabindex=0`).
- 원본 표 안에서:
  - 방향키: 칸 이동(roving tabindex, 탭 정지는 하나)
  - Home/End: 행의 처음/끝
  - Enter: 편집 영역의 첫 라디오나 입력으로 이동
- 입력 안에서: Enter = 적용, Esc = 입력 취소(팝업은 열린 채). 입력 밖에서 Esc를 누르면 팝업을 닫습니다.
- 포커스 가두기 순서: 머리 버튼 → 원본 표 → 편집 영역 → 다시 머리.
- 배경 비활성: `#bd-w`에 `inert`, 지원하지 않는 환경은 `aria-hidden` + 가두기로 대체합니다.
- 닫을 때:
  - 포커스는 연 버튼으로 돌아갑니다.
  - 팝업에서 마지막으로 고친 이사회 칸을 작성본에서 선택하고, 가운데로 스크롤합니다.
  - 열 때 툴팁(`#bd-tip`)은 숨깁니다.
- 움직임: 열기 200ms 페이드 + scale(.98→1), 줄인 동작 설정(reduced-motion)에서는 없음.

### ⑤ 표별 확인: 상태와 문구
| 상태 | 모양 | 문구 |
|---|---|---|
| 미확인 | 체크박스 해제, 라벨 13px 진한 글자 | `이 표 확인` + `14칸`(11px mono 회색) |
| 확인됨 | 체크됨, 칩 `.bd-w-chip.is-done`(파랑 18% 배경) | `확인함 · 전산팀 마스터 14:32` |
| 수정으로 해제 | 체크 해제 + 카드 머리 아래 주황 알림 줄(12px, warn 아이콘, `role="status"`, 다시 체크하면 사라짐). 카드 왼쪽 테두리 3px 주황(`.is-dirty`와 같은 모양) | `값을 고쳐 확인을 풀었습니다(총기대수익 48.51 → 49.00). 다시 확인해 주세요.` |

- 전체 줄: `표 확인 4/6`(mono). 6/6이면 자동으로 칩 `검수 완료 · 마지막 확인 14:32`를 붙입니다. 하나라도 풀리면 칩이 바로 사라지고 낭독 문구 `검수 완료를 해제했습니다.`를 냅니다.
- 초안 버튼 앞의 경고(막지 않음):
  - 버튼 왼쪽에 주황 글자 + warn 아이콘으로 `확인 안 한 표 2개`를 상시 표시합니다. 버튼의 `aria-describedby`로 연결합니다.
  - 내려받은 뒤 작성 바 메모: `확인하지 않은 표 2개(Ⅲ. 순현재가치(NPV) 수익성, Ⅴ. 세부 수익성 분석표)가 있는 상태로 초안을 만들었습니다.`
- 요약 문구 변경: `값 249칸을 모두 채웠습니다. 표마다 [원본 보기]로 수익성 분석표와 맞춰 보고 ‘이 표 확인’을 눌러 주세요.`
- 필터 변경:
  - 칩 `미확인` → `확인 안 한 표`. 해당하지 않는 카드는 기존 `is-empty`처럼 접습니다.
  - 정의 문구 뒷부분 → `확인 안 한 표: 표 머리의 ‘이 표 확인’을 누르지 않은 표`
- 칸마다 붙던 확인 체크 아이콘(`.bd-w-ck`)과 `is-checked` 클래스는 제거합니다.

## 7. 이관 메모
**기획**
- [이관: 기획] 표 확인 가능 조건: 읽지 못한 칸이나 합계 차이가 남은 표도 '이 표 확인'을 허용할지 결정이 필요합니다. 디자인은 '허용하고 칩으로만 경고'를 가정했습니다. 근거는 지금 '확인했음'도 합계 차이가 있어도 선택할 수 있다는 점입니다(`reviewHtml` 848행).
- [이관: 기획] 검수 완료 기록 저장과 확인자 표기 여부(Q-B2·Q-B3)가 필요합니다. 1차는 화면 메모리만 쓰고 표기는 로그인 이름입니다. 사번이 자기신고 방식이라는 점은 security가 확인해야 합니다.
- [이관: 기획] C-5(150칸)를 체크 한 번으로 확인하는 것이 업무상 충분한지 판단이 필요합니다. 디자인은 라벨에 칸 수를 보여 범위만 알립니다.

**개발**
- [이관: 개발] 지워도 되는 것: `.bd-w-src*` 패널 CSS, `.bd-w-grid` 2열·`is-wide`·`is-one`·`is-stack`·`.bd-stacked`, `--bd-status-h`, `--bd-scroll-top`, `measureSrc`, `stackMode`, `srcScrollTop`, `realignSrc`. 노드 테스트가 `#bd-w-src` 등 id에 묶여 있으니 범위 확인이 필요합니다. `#bd-w-srcbody`와 `.bd-w-srctbl`은 팝업 안에서 재사용하는 것을 권장합니다.
- [이관: 개발] 팝업 수정은 기존 `bw.editCell`을 그대로 거칩니다. 해제 기준을 `ws.done`·`c.checked`에서 표 단위 `t.checked`로 바꿔야 합니다. 한 원본 칸이 두 표에 쓰여도 고친 이사회 칸이 속한 표만 해제합니다.
- [이관: 개발] Esc 처리 순서가 필요합니다: 입력 취소 → 팝업 닫기, 전역 `wireModalDismiss`보다 먼저. 칸 선택 상태와 팝업이 같은 선택 정보(`ui.sel`)를 공유하게 해야 합니다.

**데이터**: 없음.

## 8. 디자인 쪽 열린 질문
- 초안 경고를 '버튼 옆 상시 표시만'(권장, 클릭 늘지 않음)으로 할까요, 아니면 누를 때 한 번 더 묻는 확인 줄(`.bd-confirm` 방식 `그래도 내려받기 / 표 확인하러 가기`)로 할까요? 사용자가 말한 '버튼 앞에 경고'가 어느 쪽인지 확인이 필요합니다.
- 상태 줄을 '선택했을 때만 한 줄'로 남기는 권장안이 괜찮은지 확인이 필요합니다. 완전히 없애려면 사유 칩과 '원본 값으로' 버튼을 칸 옆 팝오버로 옮기는 추가 작업이 생깁니다.
