# 표 정렬 확인 보고 (NEXT 124, 0d 의뢰)

## 1. 대상·방법·못 본 것
- **방법: 실제 화면은 열지 못했고, CSS를 읽어 대조만 했다.** Playwright MCP를 네 번 불렀는데(resize·tabs·navigate·snapshot) 네 번 모두 `Browser is already in use for ...\ms-playwright-mcp\mcp-chrome-b09e9e2`로 막혔다. 다른 세션이나 프로세스가 같은 브라우저 프로필을 잡고 있다는 뜻이다. 그래서 getComputedStyle 실측값과 스크린샷은 **한 장도 없다.** 아래 표의 값은 `frontend/index.html` 스타일 규칙의 우선순위와 순서를 따져 내가 계산한 기대값이고, 숫자로 잰 값이 아니다.
- 브라우저 탭은 열지 않았다. 따라서 닫지도 않았고, 데이터 쓰기 동작도 없었다.
- **못 본 것**: 실제 렌더링 전부(이름 칸이 떠 보이는지, flex 칩 위치, 말줄임이 어디서 잘리는지, `.pb-t` 폭이 깨지는지), 1280px 폭 확인, 랜딩→로그인 흐름. 브라우저 잠금이 풀리면 같은 목록으로 다시 맡겨야 한다.

## 2. 한 줄 총평
가로 정렬(가운데·금액 오른쪽·이름 칸 왼쪽)은 의뢰한 7곳 모두 규칙대로 들어가 있다. 남은 문제는 세로 정렬이다. 한 줄 안에서 위 정렬과 가운데 정렬이 섞이는 곳이 4곳 있고, 의뢰에서 걱정한 '보기 흉한 줄'이 바로 이것이다. 가장 큰 기회는 "위 정렬 본문 칸이 있는 줄은 그 줄의 다른 칸도 위 정렬"이라는 줄 단위 규칙 한 줄을 더하는 것이다.

## 4. 우선순위 이슈
**A. P2 `.pl-tbl`: 한 줄 안에서 top과 middle이 섞인다**
- 근거: index.html 2857행 `.pl-tbl td {vertical-align:middle}`, 2863행 `td.pl-nm {vertical-align:top}`.
- 왜 문제인가: 내용이 3–5줄인 사업이면 사업명은 칸 맨 위에서 시작하는데, 번호와 예산은 칸 높이의 한가운데에 뜬다. 눈으로 사업명과 금액을 짝지을 기준선이 없어진다.
- 수정안 (규칙 보완은 질문 1):
  - 기존 2857행: `.pl-tbl td { padding:8px; border-top:1px solid var(--line); vertical-align:middle; text-align:center; }`
  - 새 2857행: `.pl-tbl td { padding:8px; border-top:1px solid var(--line); vertical-align:top; text-align:center; }   /* 사업명+내용(위) 줄과 첫 줄을 맞춘다 — 줄 단위 위 정렬 */`
  - 그러면 2863행의 `vertical-align:top`은 남겨도 해가 없다.
  - 주의: `frontend/test/table-center.test.js`가 `.pl-tbl td`를 middle로 검사하는지 확인해야 한다. 66행 목록에는 없었다. 이 확인은 개발 쪽 몫이다.

**B. P2 `.tm-t-reason`이 들어간 표 3곳 (team.js:342 담당자 이력, board-material.js:869 버전 이력, :919 작업 이력)**
- 근거: 1378행. 사유·메모 칸만 top이고 같은 줄의 시각·이름·[보기] 단추는 middle이다.
- 수정안: 줄 단위로 맞춘다. 기존 1378행 바로 뒤에 새 줄을 하나 더한다.
  `.ad-table tr:has(> td.tm-t-reason) > td, .ad-table tr:has(> td.tm-t-reason) > th { vertical-align:top; }   /* 여러 줄 사유가 있는 줄은 전부 위 — 줄 단위 정렬 */`
  - `:has`는 Chrome 105 이상에서 동작한다. 폐쇄망 브라우저 버전을 모르면 대신 세 표의 `<table>`에 `tm-hist` 클래스를 붙이고 `.ad-table.tm-hist td { vertical-align:top; }`로 쓴다. JS 세 곳을 고쳐야 하므로 개발 쪽에서 고른다.
  - 같은 줄의 `[보기]` 단추는 위로 붙는다. 칸 패딩(7px)이 같아서 첫 글줄과 단추 윗선은 거의 맞는다. 실화면 확인이 필요하다.

**C. P3 `.ap-tc` 머리값이 top이다**
- 근거: 2530행 `.ap-tc td, .ap-tc th`의 우선순위(0,1,1)가 1745행 `.ad-table th`와 같고, 뒤에 있어서 이긴다. 그래서 `thead th`가 top이 된다. 열 폭 22%/14%에 `word-break:keep-all`이 걸려 있어 머리값이 줄바꿈되면 높이가 어긋날 수 있다.
- 수정안: 기존 2530행은 그대로 두고 아래에 새 줄을 더한다.
  `.ap-tc thead th { vertical-align:middle; }   /* 머리값은 세로 가운데(DESIGN 표 정렬) */`
- 참고: `.ap-tc tbody th[scope=row]`(기관 이름)는 center다. 결재 카드는 보통 1–3곳이라 `.ap-changes`와 같은 이유로 가운데를 유지하는 것이 규칙에 맞다.

**D. P3 키-값 표 (`.ts-doc th`·`.isf-tbl th`): 라벨은 middle, 값은 top**
- 근거: 1680행과 3229/3230행. 지금 DESIGN 규칙을 글자 그대로 따른 결과다. 다만 값이 여러 줄이거나 textarea이면 라벨이 칸 가운데에 떠서, 의뢰에서 말한 '이름 칸이 떠 보이는' 모양이 된다. 규칙을 바꾸는 일이라 질문 1로 넘긴다.

**E. P3 `.hb-tt tr.grp th` (담당 세션 몫, 문제만 적음)**
- 2229행에 `height:32px; padding-top:6px`가 있고, 2188행의 `vertical-align:middle`이 그대로 이어진다. 그래서 묶음 제목 글자가 가운데보다 3px쯤 아래로 내려가 보일 수 있다. 실화면에서 확인해야 한다.

## 5. 문구 / 접근성
- 버전 이력 메모가 비면 `—`(`.dg-hint`)가 왼쪽 위에 혼자 붙는다(board-material.js:874). 비어 있음을 나타내는 표시이므로 다른 빈 칸처럼 가운데가 자연스럽다. P3. 수정안: `.ad-table td.tm-t-reason > .dg-hint:only-child { display:block; text-align:center; }`
- 접근성 쪽 새 결함은 보지 못했다. 정적 검토라 포커스와 대비는 재지 않았다.

## 6. 규격 요약 (DESIGN 102행 보완 제안 문안, 질문 1에 답이 오면 반영)
> 한 줄에 위 정렬 본문 칸(사업명+내용·사유·메모)이 있으면 그 줄의 다른 몸통 칸도 위(`vertical-align:top`)로 맞춘다. 가로 정렬은 그대로다. 머리값(thead th)은 언제나 세로 가운데다. 키-값 표의 라벨 칸(`.ts-doc th`·`.isf-tbl th`)은 값 칸이 여러 줄이면 위로 맞춘다.

- 이 보완이 들어가면 `table-center.test.js` 66행의 middle 검사 목록과 `.isf-tbl th` 항목을 조정해야 한다.
- 전/후 장: 이번 검토는 CSS를 바꾸지 않았으므로 장이 필요 없다. A·B를 적용하면 "전: 번호·예산이 칸 가운데에 뜸 → 후: 사업명 첫 줄과 같은 높이" 문안으로 `docs/design_history/index.html`에 장을 하나 더해야 한다. 스크린샷은 그때 다시 찍는다.
