## 2. 한 줄 총평
지금 띠는 동작을 고르기도 전에 [결재 요청 n건]을 내건다. 그래서 바로 고쳐도 되는 값(구분)까지 결재 창으로 끌려간다. 결재가 필요한 동작과 바로 반영되는 동작을 화면의 서로 다른 자리로 나누는 것이 가장 큰 기회다.
- 바로 반영: 줄의 칩 메뉴, 띠의 보조 단추
- 결재 필요: 띠의 주 단추, 메뉴 아래 묶음

나눠 놓으면 창 안에서 "섞지 마세요" 같은 안내가 필요 없어진다. planner 4번 질문은 이 구조로 답한다.

점수표는 생략했다. 실화면을 못 본 규격 작업이라 근거 있는 점수를 매길 수 없다.

**잘 된 점**
- 결재 중 줄은 칩이 잠금 칩(`hb-pend`)으로 바뀐다. 이 덕분에 바로 저장으로 바꿔도 잠금이 자연스럽게 유지된다.
- 띠의 `role=status`를 먼저 보이게 한 뒤 글을 넣는 순서가 지켜져 있다.
- 오류를 항목별로 표시하는 구조(`chMarkItem`)는 수정 창에 그대로 다시 쓸 수 있다.

## 3. 우선순위 이슈
1. **P1. 띠 단추 `결재 요청 n건`**
   - 근거: tchange.js 46 `barBtnText`
   - 왜: 결재 1건에 n곳이 들어가는데 '건'이라고 쓴다. 무엇을 결재받는지도 말하지 않는다.
   - 수정: 6-1의 단추 이름 규칙, 단위는 '곳'.
2. **P1. 구분을 바꾸면 결재 창이 열린다**
   - 근거: kbboard.js 2013 `if (isApproval() && r.kind !== 'WATCH') openChange({... op:'EDIT', tag })`
   - 수정: 관심 줄처럼 언제나 `changeTag`로 바로 저장한다(6-2). 서버가 받아 주는지는 개발 확인이 필요하다(7절).
3. **P1. 목표 줄에서 메모를 고칠 길이 일괄 창(EDIT)뿐이다**
   - 근거: 줄의 메모는 구분 칸 title에만 있다(kbboard.js 853). 메뉴에 메모 항목이 없다.
   - 왜: planner 1번 결정의 "메모에서 고르면 바로 저장"을 받을 자리가 없다.
   - 수정: 메뉴에 `메모 고치기…`를 넣고 작은 창을 연다(6-3).
4. **P2. `고르기 해제`의 뜻이 불분명하다**
   - 결재 취소로 읽힐 수 있다.
   - 그렇다고 없앨 수는 없다. 고른 줄은 탭·연도를 바꿔도 남는다(tc.newSel 주석). 그런데 머리 체크박스는 "지금 보이는 줄만" 다룬다(kbboard.js 2539 주석). 없애면 화면 밖에서 고른 줄을 풀 방법이 사라진다.
   - 결정: **`선택 지우기` 글자 단추로 낮춰서 남긴다.** 화면 밖에 고른 줄이 있으면 숫자에 함께 밝힌다(6-1).
5. **P2. 결재 창 안내가 바뀌는 규칙과 어긋난다**
   - 근거: tchange.js 49 "이 기관들의 목표·관심은 고칠 수 없습니다"
   - 왜: 이제 구분·메모는 평소에 바로 고칠 수 있다. 결재 중에는 그것까지 잠긴다는 점을 말해야 한다.
6. **P2. `APPROVAL_NOW_MSG`가 [결재 요청]을 가리킨다**
   - 근거: tchange.js 28. 새 단추 이름과 어긋난다.
7. **P2. 메뉴에서 바로 반영 항목과 결재 항목이 같은 모양으로 섞여 있다**
   - 근거: kbboard.js 1020–1029
   - 수정: 결재가 필요한 항목은 `결재 필요` 머리글 아래로 묶는다(6-2).
8. **P3. 1280px에서 띠 폭을 확인해야 한다**
   - 띠 한 줄에 들어가는 것: 숫자 문장, `선택 지우기`, 결재자 안내, 단추 둘
   - 할 일: 1280px에서 줄바꿈이 없는지 확인. 넘치면 `.who`를 먼저 숨기고 그 내용을 단추 title로 보낸다.

## 4. 문구·접근성
**문구** (단추 이름이 알림 동사와 같아야 한다: `수정하기`→`수정했습니다`, `저장`→`저장했습니다`)

| 자리 | 지금 | 바꿀 문구 |
|---|---|---|
| 띠 숫자 | `고른 기관 n곳` | `고른 목표 기관 n곳` / 관심만이면 `고른 관심 기관 n곳` / 섞이면 `고른 기관 n곳(목표 a·관심 b)`. 화면 밖에 고른 줄이 있으면 뒤에 ` · 이 화면 밖 k곳` |
| 해제 | `고르기 해제` | `선택 지우기` |
| 결재 주 단추 | `결재 요청 n건` | 6-1 규칙 |
| 바로 저장 알림(구분) | `{기관}을 '{구분}'로 바꿨습니다.` | `{기관}의 구분을 '{구분}'(으)로 바꿨습니다. 결재 없이 반영되고, 바꾼 사람·시각은 기록에 남습니다.` |
| 바로 저장 알림(메모) | 없음 | `{기관} 메모를 저장했습니다. 결재 없이 반영되고 기록에 남습니다.` / 비웠으면 `{기관} 메모를 지웠습니다. 기록에 남습니다.` |
| 일괄 수정 결과 | 없음 | `목표 기관 n곳의 구분·메모를 수정했습니다. 결재 없이 반영되고 기록에 남습니다.` |
| 결재 창 안내 | `…목표·관심은 고칠 수 없습니다…` | `{결재자} 결재가 끝날 때까지 이 기관들은 구분·메모도 고칠 수 없습니다(요청자 취소·영업부장 반려로 풀림).` |
| APPROVAL_NOW_MSG | `…아래 [결재 요청]으로…` | `목표에서 빼기·옮기기는 결재가 필요합니다. 줄을 고른 뒤 아래 [빼기·옮기기 결재 요청…]으로 올려 주세요. 구분·메모는 결재 없이 바로 바뀝니다.` |

- 조사 `(으)로`는 기존 `josaRo`를 쓴다(kbboard.js 1484).
- 구분 바로 저장 알림 문장은 `kbb.flashTag`를 교체한다. planner 원안("구분을 '…'으로 바꿨습니다")에 기관 이름만 더했다. 알림 띠는 줄과 떨어진 위쪽에 있어서 이름이 없으면 어느 기관인지 모른다.

**바로 저장 오류** (빨간 배너, 기존 `say(msg, true)`)
- 연결 끊김: `서버에 연결되지 않아 구분을 바꾸지 못했습니다. 연결을 확인하고 다시 고르세요.`
- 그사이 결재가 걸림(409 CHANGE_PENDING): `{기관}은(는) 방금 결재 요청에 들어가 잠겼습니다. 결재가 끝나면 다시 바꿀 수 있습니다.` 이어서 `loadGoals()`로 잠금 칩을 보여 준다.
- 다른 사람이 먼저 고침(STALE): 기존 `kbb.outcome`의 stale 문장을 그대로 쓰고 목록을 다시 읽는다.

**접근성**
- 띠의 두 단추 모두 `aria-haspopup="dialog"`.
- `선택 지우기`는 글자 모양이어도 `<button>`으로 둔다. 높이 32px는 기존 `.hb-selbar button` 규칙으로 맞춘다.
- 누른 뒤 포커스는 지금처럼 `#hb-pickall`로 보낸다(kbboard.js 2572).
- 메뉴 머리글 `결재 필요`는 `role="presentation"`이 아닌 `.mh` div로 둔다. 다만 스크린리더가 메뉴 항목과 함께 읽도록 결재 항목 `aria-label`에 `(결재 필요)`를 덧붙인다. 예: `관심 기관으로 옮기기 (결재 필요)`.
- 바로 저장 중에는 칩에 `aria-busy="true"`를 단다(지금처럼).
- 바로 저장 알림은 `#hb-flash`(role=status)로 내보낸다. 성공한 줄은 기존 `.hb-just` 강조를 재사용한다. 색만이 아니라 알림 문장이 함께 전하므로 색 단독 전달이 아니다.
- 현황판 CSS는 opacity를 쓰지 않는다. 비활성은 `root.dlg.setDisabled`를 쓴다.

## 5. 전/후 비교 (design_history에 넣을 장 문안 — "전/후 장 필요")
- **전**
  - 체크박스로 한 곳을 고르면 띠가 나온다: `고른 기관 1곳 [고르기 해제] ……… 영업팀장이 결재합니다. [결재 요청 1건]`
  - 줄의 구분 칩에서 '신규 유치 도전'을 고르면 사유 칸이 필수인 결재 창이 열린다.
  - 메모는 일괄 창에서만 고칠 수 있다.
- **후**
  - 칩에서 고르면 그 자리에서 저장된다. 위쪽 알림: "○○구청의 구분을 '신규 유치 도전'으로 바꿨습니다. 결재 없이 반영되고…"
  - 띠: `고른 목표 기관 1곳 · 선택 지우기 ……… [구분·메모 한꺼번에 수정…] 영업팀장이 결재합니다. [빼기·옮기기 결재 요청…]`
  - 단위가 '건'에서 '곳'으로 바뀐다. 결재 단추는 결재가 필요한 동작의 이름을 단다.
- **왜**: 사용자 11-24 밤 지적 — "말과 동작이 애매하다, 결재가 너무 많다".
- **대비 숫자**: 새 색이 없다. 기존 `.hb-selbar` 틴트와 `.go`를 그대로 쓰므로 대비가 바뀌지 않는다(실측은 못 했다).

## 6. 규격

### 6-1. 바닥 띠 `#hb-selbar` (`tc.selbarHtml` 교체)
- **보이는 조건**: 지금처럼 쓰기 모드이고 1곳 이상 골랐을 때.
- **구성** (왼쪽에서 오른쪽으로, 간격은 기존 gap 8px)
  1. `#hb-seln`: 숫자 문장
  2. `#hb-selclr`: `선택 지우기`
  3. `.sp`
  4. `#hb-seledit`: 보조 단추
  5. `#hb-selwho`: 결재자 안내
  6. `#hb-selgo`: 주 단추
- **`#hb-selclr`** (클래스 `lnk`)
  - 모양: 테두리·바탕 없음, 12px, 색 `--muted`. 마우스를 올리거나 포커스를 받으면 밑줄과 `--fg`. 포커스 링은 기존 잉크+흰 두 겹.
  - 크기: 높이 32px(기존 규칙), 좌우 padding 6px.
- **`#hb-seledit`** `구분·메모 한꺼번에 수정…`
  - 고른 줄이 **전부 목표 줄**일 때만 보인다. 관심 줄이 하나라도 섞이면 `hidden`.
  - 모양: 기존 보통 단추(흰 바탕, 1px `--line-strong`).
  - 결재자 안내(`.who`)보다 **앞**에 둔다. 결재자 안내가 주 단추 바로 옆에 붙어 있어야 그 안내가 어느 단추에 걸리는지 분명하다.
- **`#hb-selgo`** (주 단추, 기존 `.go` 모양 유지)
  - 문구 (n은 쓰지 않는다. 숫자는 왼쪽 문장이 이미 말한다):

    | 모드 | 고른 줄 | 문구 |
    |---|---|---|
    | APPROVAL | 전부 목표 | `빼기·옮기기 결재 요청…` |
    | APPROVAL | 전부 관심 | `목표로 옮기기 결재 요청…` |
    | APPROVAL | 섞임 | `결재 요청 쓰기…` |
    | DIRECT(영업부장) | — | 위 문구의 `결재 요청`을 `바로 반영`으로 바꾼다. 예: `빼기·옮기기 바로 반영…` |

  - DIRECT에서는 `.who`가 빈 글이다(지금과 같다).
- **문장 함수 (tchange.js)**
  - `tc.barBtnText(mode, n)`를 `tc.barBtnText(mode, mix)`로 바꾼다. `mix`는 `'GOAL'|'WATCH'|'MIX'`.
  - `tc.selStatusHtml(n, msg)`에 인자 `(kinds, off)`를 더한다. `kinds`는 `{goal, watch}`, `off`는 화면 밖 개수.
  - sr 문장 예: `목표 기관 5곳 고름, 이 화면 밖 2곳 포함`.

### 6-2. 줄 구분 메뉴 `.hb-menu` (`kbb.menuHtml`)
- **순서** (APPROVAL 모드, 목표 줄)
  1. `.mh` 자동 제안 / `.mh` 달성 판정일 (지금과 같다)
  2. 구분 radio 3개 — **고르면 바로 저장**
  3. `.ms`
  4. `메모 고치기…` (`data-cmd="memo"`) — 바로 저장
  5. `협약 개시일 적기…` (canTerm일 때) — 바로 저장
  6. `.ms`
  7. `.mh` `결재 필요`
  8. `관심 기관으로…`, (closed일 때) `다음 회차 목표로…`, `목표에서 빼기…`
- **DIRECT 모드**: 7번 `.mh`를 빼고 순서는 그대로 둔다.
- **관심 줄**: 지금 구성을 유지하고 `메모 고치기…`만 더한다.
- **메뉴 `aria-label`**: 늘 `목표 기관 동작`.
- **click 처리 (kbboard.js 2013)**
  - 바꾼 뒤: `else changeTag(r, code, btn)`만 남긴다(모드 분기 삭제).
  - 처리 추가: `cmd==='memo'`이면 `openMemo(r, btn)`.
- **결재 중 줄**: 칩이 `hb-pend`라 메뉴가 열리지 않는다. 바꿀 것 없음.

### 6-3. 메모 창 `#mm-dlg` (작은 `.dlg`, 협약 개시일 창 `tt-*`와 같은 뼈대)
- 제목 `#mm-t`: `메모 — {지역} {기관}`
- 단추: `#mm-cancel` `취소`, `#mm-go` `저장` (`.dlg-go`). 저장 중에는 `저장하는 중…` + setDisabled.
- 안내 `.dlg-hint`: `결재 없이 바로 저장됩니다. 고친 사람·시각은 기록에 남습니다. 개인정보를 적지 마세요.`
- 입력 칸
  - `<label for="mm-memo">메모</label><input id="mm-memo" maxlength="100" aria-describedby="mm-cnt mm-e">`
  - 글자 수 `#mm-cnt`: `n/100` (mono 12px)
  - 칸 오류 `#mm-e` (`.dlg-ferr`)
- 오류
  - 창 위 `#mm-err` (role=alert)
  - 422: 칸 아래에 `개인정보로 보이는 내용이 있습니다.`
  - 내용이 같으면 `바뀐 내용이 없어 저장하지 않았습니다.`(기존 nochange 문장)를 띠 알림으로 띄우고 창을 닫는다.
- 성공하면 창을 닫고, 포커스를 칩으로 돌리고, 4절 메모 알림을 띄우고, `loadGoals()`.

### 6-4. 일괄 창 두 갈래 (섞지 않는다. 창 안 안내 문구는 필요 없다)
**A. 수정 창** (`#hb-seledit`가 연다, `#tc-dlg` 재사용 + `data-kind="edit"`)
- 제목: `구분·메모 수정 — n곳`
- 안내: `결재 없이 바로 반영합니다. 바꾼 사람·시각은 기록에 남습니다.`
- **사유 칸 없음.**
- 맨 위 `.tc-all`: `<label for="tc-alltag">고른 목표 줄 모두</label><select id="tc-alltag"><option value="">구분 한꺼번에 정하기</option>…</select>`
- 항목 칸
  - 동작 칸 없이 `<span class="fix">구분·메모 수정</span>`
  - 이후: `구분` select와 `메모` input만 둔다. **목표 연도 select는 빼고**, 연도는 이전 값 그대로 보낸다.
- 주 단추 `#tc-go`: `수정하기`, 저장 중 `저장하는 중…`
- 검증: `tc.validate`의 EDIT 규칙을 쓰되 year 검사는 뺀다. 아무것도 바꾸지 않은 항목은 기존 문장 `고친 내용이 없습니다. 칸을 바꾸거나 이 기관을 목록에서 제외하세요.`
- 결과는 4절 일괄 수정 알림.

**B. 결재 창** (`#hb-selgo`, 메뉴의 결재 항목, 관심 줄 [목표로 옮기기]가 연다)
- 지금 창을 그대로 쓴다. 제목: `목표 기관 변경 결재 요청 — n곳`.
- 동작 select 옵션은 `목표에서 빼기`, `관심으로 옮기기`, `다음 회차 목표로`(closed 줄만) 세 가지다.
- `목표 고치기`(EDIT)는 **목록에서 뺀다.**
  - `다음 회차 목표로`는 내부적으로 op EDIT + year+1이다(kbboard.js 2521).
  - 이후 칸: `<span class="mono">{year+1}</span> 목표 · 구분·메모 그대로`. 구분·메모 칸은 없다.
  - `OP_LONG`에 표시용 이름 `NEXT: '다음 회차 목표로'`를 따로 둔다. 결재함 카드(`tc.cardItemsHtml`)도 EDIT이면서 연도가 +1이면 이 이름을 쓴다.
- `.tc-all` 옵션은 지금처럼 `목표에서 빼기`, `관심으로 옮기기`.
- 안내는 4절 결재 창 안내로 바꾼다. 주 단추 `결재 요청`(DIRECT면 `바로 반영`)은 유지한다.
