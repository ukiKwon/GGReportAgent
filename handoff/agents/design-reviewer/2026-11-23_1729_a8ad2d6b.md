## 2. 한 줄 총평
지금 이 화면은 공고 띠, 월별 막대, 목록이 같은 기관을 세 번 세면서 이름이 저마다 다릅니다('결과 확인', '공고일 기준(결과 공고 미확인)', '공고 후 n일'). 가장 큰 기회는 **'선정 결과 대기'라는 이름 하나로 띠 버튼, 목록 소묶음, 칩을 묶는 것**입니다.

## 3. 규격

### ① 공고 띠 '결과 확인 n곳 보기' → '선정 결과 대기' 소묶음으로 이동 (권장안: 소묶음)
**거르기 칩이 아니라 소묶음을 권장하는 이유**
- 목록에는 이미 [다가오는 입찰]/[경과] 탭, 기간 창, 지역·종류·검색 거르기가 있습니다. 칩을 하나 더 두면 선택지가 5종이 되어 4개를 넘습니다.
- 소묶음은 이동한 뒤에도 '접수 중'과 나란히 보여서 맥락이 남습니다.

**가정**: 선정 결과 대기 = `isCheck`(마감 지남, 또는 공고 후 30일이 넘었는데 마감일 미확인).

**문구**
- 띠 요약: `접수 마감 전 <b>3</b>곳 · 접수 기간 원문 확인 <b>n</b>곳 · 선정 결과 대기 <b>9</b>곳`
- 띠 버튼(`#db-nb-wait`, 자리·모양은 그대로): `선정 결과 대기 <b>9</b>곳 보기`, `aria-controls="db-nwlb"`
- 1곳일 때 옆 문장(`.db-nb-aside`): `선정 결과 대기 <b>n</b>곳 — 결과 공고가 났는지 확인하세요.`

**목록([다가오는 입찰] 탭, 지금의 `#db-g0` + `#db-nlb` 한 덩어리를 둘로 나눔)**
```html
<div class="db-grp" id="db-g0">접수 마감 전 <b>3</b>곳 · 마감 가까운 순</div>   <!-- 원문 확인(30일 이내)도 이 묶음, u>0이면 ' · 접수 기간 원문 확인 <b>u</b>곳' -->
<ul role="listbox" id="db-nlb" tabindex="0" aria-labelledby="db-g0">…open 행…</ul>
<div class="db-grp db-grp-sub" id="db-g0w">선정 결과 대기 <b>9</b>곳 · 결과 공고가 났는지 확인하세요</div>
<ul role="listbox" id="db-nwlb" tabindex="0" aria-labelledby="db-g0w">…isCheck 행(data-check="1" 유지)…</ul>
```
- CSS: `.db-grp-sub { border-top:1px solid var(--line); margin-top:4px; }`
- 이동 강조: `.db-grp.is-target { background:color-mix(in srgb, var(--accent-color) 10%, transparent); transition:background-color 200ms; }`. 1.6초 뒤 클래스를 뗍니다. reduced-motion이면 전이 없이 1.6초 뒤 뗍니다. 색 전이 200ms는 DESIGN '움직임'에서 허용된 범위입니다.

**버튼을 눌렀을 때**
1. 지금 탭이 [경과]면 [다가오는 입찰]로 바꿉니다.
2. `#db-g0w`를 목록 스크롤 맨 위로 올립니다(`scrollIntoView({block:'start'})`).
3. `#db-nwlb`에 포커스를 줍니다. 그러면 화면 읽기 프로그램이 소묶음 제목을 읽습니다.
4. `.is-target`를 붙입니다.

**경우별 처리**
- 거르기 때문에 0곳만 보일 때: 소묶음 자리에 `<p class="db-state">조건에 맞는 선정 결과 대기 기관이 없습니다. <button id="db-clear">조건 지우기</button></p>`
- 선정 결과 대기가 0곳일 때: 소묶음을 그리지 않습니다. 띠 버튼도 없습니다(지금과 같음).
- 목록 행 칩 '공고 후 n일', 행 문구 '결과가 났는지 확인하세요'는 그대로 둡니다.

**같이 바꿀 '결과 확인' 문구(한 이름으로 맞추기)**
- logic.js:346 칩 badge `'결과 확인'` → `'선정 결과 대기'`
- render.js:468 `· 결과 확인 n` → `· 선정 결과 대기 n`
- render.js:496 `결과 확인 공고 n곳` → `선정 결과 대기 n곳`

### ② '월별 입찰 예정' 삭제 → '다가오는 기관별 공고 현황'
**권장안**
- **'공고 중'을 맨 앞 구간으로 넣습니다.** 넣지 않으면 지자체가 '1개월 안 1곳'으로 보이는데, 실제로는 8곳이 공고 중입니다.
- **막대 길이는 같은 척도의 건수로 잽니다.** 종류별 100% 비율로 그리면 대학 2곳과 지자체 243곳이 같은 길이가 되어 일의 양을 속입니다.
- **구간 이름은 겹치지 않게 짓습니다**: `공고 중 | 1개월 안 | 1~3개월 | 3~6개월 ‖ 확인 필요`. '3개월 안'이라고 쓰면 누적으로 읽힙니다.

- '확인 필요'는 8px 띄워 떼고 빗금으로 그립니다. 확실한 일정과 불확실한 것을 모양으로 가릅니다.

  - 구간 하나하나는 누르지 않습니다. 구간이 목록과 1:1로 맞지 않기 때문입니다. 목록 기간 창에는 1개월이 없고, 날짜 미상 99곳은 목록에 없습니다.

- **채도 기준**: 가장 진한 채움을 42%로 잡았습니다. 지금 D1 `.seg.u.f`가 쓰는 값과 같아서 새 예외를 만들지 않습니다.
- **높이**: 6줄이면 약 198px, 5줄이면 약 174px입니다. 지금 282px보다 30~38% 낮습니다. 범례는 머리 줄에 넣어 한 줄을 아꼈습니다.

```css
.db-sub-h small { margin-left:auto; font-size:12px; color:var(--muted); }
```
- noticerec.sectionHtml과 recordBriefHtml에 `{nested:true}` 같은 선택값을 두어, 바깥 `.db-sec`·h3 대신 위 머리를 내게 합니다. 구현 방식은 프런트가 정합니다.
- 팝업(recordBriefHtml)은 h4 아래에 `담당자 기록` 한 줄과 [입찰 공고 현황에서 기록] 단추를 그대로 둡니다.

**② 기관 정보(현재 금고 은행 절을 흡수)**
```html
<div class="db-sec" id="db-bank"><div class="db-sec-h"><h3>기관 정보</h3>
  [기관 정보 수정](팝업·권한 있을 때) [금고 약정 고치기|금고 약정 입력](can_edit일 때)</div>
  <dl class="db-dl">
    금고 은행 줄들(1금고/2금고/단수 — 은행명 + 둘째 줄 '약정 yyyy-mm-dd ~ yyyy-mm-dd', 수집·행안부 줄 포함)
    약정 만료   ← 은행 줄에 약정 기간이 하나도 없을 때만(rec.contractExpiry). 있으면 생략(중복)
    약정 주기
    지난 금고 선정일
    운영 상태(있을 때)
  </dl>
  .db-empty 안내 문장(bankNote) · bk-state(불러오는 중/오류)
  <div class="bk-foot">[출처 n건 보기 details][수정 이력 n건 보기 details] <span class="db-why">권한 없음 문구</span></div>
</div>
```
- **줄 순서의 이유**: '누가(금고 은행), 언제까지(약정)'가 영업이 먼저 묻는 것입니다. 주기와 지난 선정일은 그 근거라서 뒤에 둡니다.
- **지우는 중복 줄**
  - 공고 진행의 `현 약정 만료`를 지웁니다.
  - legacy 경로의 `금고 은행 [미확인]` / `약정 기간 [미확인]` 두 줄은 은행 줄이 없을 때 `금고 은행 [미확인]` 한 줄로 줄입니다. `약정 만료`와 겹치기 때문입니다.
  - id `db-bank`는 이 절로 옮깁니다(기존 스크롤 대상 유지).
- **단추 자리**: 두 편집 단추를 모두 절 머리 오른쪽(`.db-sec-act`, 28px, 12px)에 모읍니다.
  - 지금은 [금고 약정 입력]이 절 아래 오른쪽에 있고, [기관 정보 수정]은 팝업에서만 머리에 있습니다. 같은 절 안에 두 곳으로 흩어집니다.
  - 순서는 `[기관 정보 수정][금고 약정 고치기]`입니다. 현황판 안쪽 칸에서는 [기관 정보 수정]이 없으므로 하나만 보입니다.
- '직접 확인: 행안부…' 바로가기 줄(`.bk-src`)은 dl 바로 아래, 안내 문장 앞에 둡니다.

## 4. 문구·접근성 요약
- **'결과 확인'을 '선정 결과 대기'로 한 이름으로 맞춥니다**(띠 요약, 띠 버튼, 목록 소묶음, 칩, 티커, 지도 툴팁). 이유: '결과 확인'은 할 일인지 상태인지 모호합니다.
- 막대 구간 이름은 겹치지 않게 짓습니다(1~3개월, 3~6개월). '공고 확인 어려움'은 '확인 필요(예정일 지남·날짜 미상)'로 바꿉니다. 무엇을 확인하는지 말하고, 원래 이름보다 짧습니다.
- 띠 버튼에 aria-controls를 달고, 이동한 뒤 포커스를 목록으로 옮깁니다. 지금은 포커스가 목록 전체(`#db-nlb`)로 가서 어디서부터가 대상인지 들리지 않습니다.
- 막대 줄은 단추의 aria-label에 구간별 건수를 문장으로 담습니다. 막대 자체는 aria-hidden입니다.

## 5. 이관 메모
- [이관: 기획] '확인 필요'에 '예정일 경과'를 넣을 때, 경과 탭에서 이미 '처리됨'(공고 종료·입찰 없음)으로 기록한 회차도 셀지 정해야 합니다. 디자인이 기다리는 것: 막대 숫자의 정의. 근거: 경과 34곳 중 상태 보기가 미처리·지연·처리됨으로 나뉩니다(dashboard.js 1147).
- [이관: 기획] 교육청을 공공기관에 합칠지 정해야 합니다. 디자인이 기다리는 것: 줄 5개 또는 6개. 근거: 교육청 16곳 중 막대에 들어가는 곳은 2곳뿐입니다.
- [이관: 기획·데이터] 기관 자료의 약정 만료(rec.contractExpiry)와 직접 입력한 약정 기간이 다를 때 어느 값을 보일지 정해야 합니다. 디자인이 기다리는 것: ②에서 '약정 만료' 줄을 생략하는 조건. 근거: 지금은 두 절에 따로 보여서 충돌이 드러나지 않습니다.
- [이관: 개발] 종류 거르기에서 '공공기관+교육청' 합침을 지원해야 합니다(합칠 경우). 디자인이 기다리는 것: 줄 단추의 거르기 동작. 근거: `dash.filterItems`는 종류 하나만 같음 비교합니다.

## 6. 전/후 장 필요 (docs/design_history/index.html에 구현 뒤 추가)
- **띠 버튼**
  - 전: '결과 확인 9곳 보기'를 누르면 목록이 첫 대상 행 근처로만 스크롤되고, 어디서부터가 대상인지 표시가 없습니다.
  - 후: '선정 결과 대기 9곳 보기'를 누르면 목록 안 '선정 결과 대기 9곳' 소묶음이 맨 위로 오고, 1.6초 동안 강조된 뒤 포커스가 옮겨집니다.
  - 왜: 어떤 기관이 결과를 기다리는지 이름과 묶음으로 보이게 하려고.
- **월별 막대 → 종류별 막대**
  - 전: 13개월 세로 막대와 타일 3개, 높이 282px.
  - 후: 종류별 가로 누적 막대 5~6줄, 높이 174~198px(−30~38%).
  - 왜: 간소화 요청. 어느 종류에 가까운 공고가 몰렸는지 한 줄씩 읽히게 하려고.
