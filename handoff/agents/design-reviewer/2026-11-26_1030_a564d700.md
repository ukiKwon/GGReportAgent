## 2. 한 줄 총평
규칙 자체는 깔끔하게 들어갔다. 표시가 글자로 갈리고, 새 색이 없고, readonly로 포커스를 지킨다. 다만 **끝 칸이 잠겨도 겉모양이 그대로이고**, 확인란이 '안내 글' 클래스를 빌려 써서 컨트롤로 잘 읽히지 않는다.
- **가장 큰 기회**: 잠긴 끝 칸에 겉모양을 주고, 확인란에 전용 클래스(16px, 24px 높이)를 주는 것. CSS 3줄이면 된다.

## 3. 잘 된 점
- '~현재'와 '~미상'을 **글자로만** 가른다(headcard.js:196–197). 색 단독 전달이 없고, 같은 `.yr` 12px mono `--muted`라 위계도 흔들리지 않는다.
- 현직이면 끝 칸을 `disabled`가 아니라 `readOnly`로 잠근다(headcard.js:744–753). 포커스를 잃지 않고, 설명 문단(`hc-cur-h`)을 `aria-describedby`로 잇는다. DESIGN.md 94줄의 "꺼져도 Tab으로 닿아 이유를 읽는다"와 같은 철학이다.
- 정렬 1차 키에서 현직은 '9999-99'다(headcard.js:269–276). 서버 sortKey와 같은 규칙이라고 주석에 적혀 있다. 학력은 current 키가 없어 '~현재'가 나올 수 없다(190줄).

## 4. 우선순위 이슈

**P2-1. 잠긴 끝 칸이 편집 가능한 칸과 똑같이 보인다**
- 근거: headcard.js:747은 `to.readOnly = true`만 한다. index.html의 `.hc-lab input`(2696줄)과 전역 입력(51–53줄)에는 `[readonly]`이나 `:read-only` 규칙이 없다. 그래서 흰 바탕, `--line-strong` 테두리, 자리표시자 "2022 또는 2022-06"이 그대로 남는다.
- 왜 문제인가
  - 마우스 사용자가 칸을 눌러 타자를 쳐도 아무 반응이 없어 고장으로 읽힌다.
  - 안내 문단이 아래에 뜨지만, 칸 자체는 "여기 입력하라"는 자리표시자를 계속 보여 준다.
- 수정 방향: 6절 규격 A. 잠기면 바탕을 `--panel2`로, 자리표시자를 '지금도 이 자리(비워 둠)'로 바꾼다. 토큰만 쓰고 새 색은 없다.

**P2-2. 확인란이 '안내 글' 클래스(`.hc-fhint`)를 빌려 쓴다. 타깃 높이는 약 18px이다**
- 근거: headcard.js:767 `<label class="hc-fhint"><input type="checkbox" …> 지금도 이 자리에 있음</label>`. `.hc-fhint`는 12px, line-height 1.5, `--muted`(index.html:2699)라 줄 높이가 약 18px이다. 체크박스는 브라우저 기본 약 13px이다.
- 왜 문제인가
  - 24px 미만이라 WCAG 2.5.8 최소 타깃 기준에 못 미친다.
  - 바로 아래 설명 문단(`#hc-cur-h`)과 같은 모양이라 컨트롤과 설명이 구분되지 않는다.
  - 저장소에는 이미 16px 체크박스 선례가 있다(`.hb-tt .ck input` 2410줄, `.dc-hits .c-ack input` 1312줄).
- 수정 방향: 6절 규격 B. 전용 `.hc-chk`를 두고 높이 24px 이상, 상자 16px로 한다.

**P3-1. 끝 칸 이름표가 새 규칙(빈 끝 = '~미상')을 말하지 않는다**
- 근거: headcard.js:764 "끝(연도 또는 연-월, 모르면 비워 두세요)".
- 왜 문제인가: 이제 끝을 비우는 경우가 '모름'과 '현직' 두 가지이고, 카드 결과가 다르다. 이름표만 보면 현직인 사람도 그냥 비워 두고 확인란을 지나칠 수 있다. 그러면 카드에 '~미상'이 나온다.
- 수정 방향: 5절 문구 표 (1)·(2)를 적용한다.

**P3-2. 확인란을 켰다 끄면 적어 둔 끝 값이 사라진다**
- 근거: headcard.js:747은 켤 때 `to.value = ''`를 하고, 끌 때 되살리지 않는다.
- 수정 방향: 켤 때 `to.dataset.prev`에 보관하고 끌 때 되돌린다. 구현은 프런트 판단에 맡긴다.

**P3-3. 기간 오류가 칸 아래가 아니라 위쪽 상태 줄에 뜬다**
- 근거: headcard.js:1135–1136은 `setMsg(bad, true)`로 상단에 띄운다. DESIGN.md 105줄은 "빠진 칸마다 빨간 테두리 + 칸 아래 12px 한 줄"을 요구한다. 생년월일은 이미 칸 아래 방식이다(733줄).
- 왜 지금은 우선순위가 낮은가: 이번 변경 전부터 있던 동작이다. 게다가 새 오류 '지금도 이 자리에 있으면 끝을 비워 두세요.'는 UI상 거의 나올 수 없다(켜면 칸이 비워지고 잠긴다).
- 수정 방향: 다음에 기간 칸을 손볼 때 생년월일 방식(`hc-ferr`, `aria-invalid`)으로 맞춘다.

**P3-4. 기간 글자의 줄바꿈 보장**
- 근거: `.hc-items .yr`(2662줄)에 `white-space:nowrap`이 없다. 부모가 `keep-all`이라 실제로 끊길 가능성은 낮지만 렌더로 확인하지 못했다.
- 수정 방향: '2018-07~현재'가 한 덩어리로 남도록 `.hc-items .yr { white-space:nowrap; }`를 더한다. `.hc-nb` 선례와 같다.

## 6. 규격

```css
/* A. 잠긴 끝 칸 — 새 색·새 변수 없음 */
.hc-lab input[readonly] { background:var(--panel2); border-color:var(--line); color:var(--muted); cursor:default; }
/* 포커스 링은 전역 :focus-visible 그대로(6.84:1). --line 테두리는 '꺼짐' 표시이고, 칸의 존재는 이름표가 알린다. */

/* B. 경력 '지금도 이 자리에 있음' 확인란 */
.hc-chk { display:inline-flex; align-items:center; gap:6px; min-height:24px; margin:0; font-size:12px; color:var(--muted); cursor:pointer; align-self:flex-start; }
.hc-chk input { width:16px; height:16px; margin:0; accent-color:var(--accent-color); }

/* C. 기간 한 덩어리 */
.hc-items .yr { white-space:nowrap; }
```

- 마크업: 767줄의 `class="hc-fhint"`를 `class="hc-chk"`로 바꾼다. 순서는 끝 칸 → (2) 안내 `<p class="hc-fhint" id="hc-to-h">` → 확인란 → 켰을 때 안내(`#hc-cur-h`)로 한다.
- 켰을 때(applyCurrent)
  - 칸을 비우고 readonly로 바꾼다.
  - 자리표시자를 '지금도 이 자리(비워 둠)'로 바꾼다.
  - `aria-describedby="hc-cur-h"`로 잇는다.
- 껐을 때
  - 자리표시자를 '2022 또는 2022-06'으로 되돌린다.
  - `aria-describedby="hc-to-h"`로 잇는다. 지금처럼 속성을 제거하지 않는다.
  - P3-2를 적용하면 보관해 둔 값을 되살린다.
- 카드 표시는 바꾸지 않는다. '2018-07~현재'와 '2018-07~미상'은 같은 `.yr` 모양이다. 현직에 굵기나 색을 따로 주지 않는다(DESIGN.md "점수·등급 없음, 테두리 색으로 사람을 가르지 않는다" 2617줄 주석과 일치).

**③ 오늘 규칙과의 충돌 점검**
- 07649ad1 `[aria-disabled]:focus-visible { opacity:1 }`: `.hc-foot [data-hc="docx"]`에만 걸린다. 이번 변경과 겹치지 않는다.
- 3128db3b·95506c06 `.hc-dl` 선택 상자와 단추 묶음: 카드 아래 띠에 있다. 이번 변경은 편집 모달 쪽이라 관계없다.
- readonly 선택은 aria-disabled 계열의 "포커스 유지" 원칙과 같은 방향이다. 충돌 없음.

**④ 새 색·새 변수**: 현재 소스에는 없다. 규격 A·B·C도 기존 토큰(`--panel2 --line --muted --accent-color`)만 쓴다.

**고정 규칙 대조**: 웹 카드는 연도와 기간을 그대로 보여 주고(`.yr`), '미상'은 웹 period()에서만 만들어진다. 화면 쪽에서는 어긋남이 없다. Word가 '미상'을 쓰지 않는지는 서버 쪽이라 이관한다.
