# design-reviewer: 제안 준비 현황 상세 qa 지적 3건 규격 + fa003a7e 문구 대조 (2026-11-25)

## 1. 대상·방법·못 본 것
- **본 방법**
  - 8080 화면을 Playwright로 폭 1280에서 열었다. 로그인 세션은 이영업(팀장) 그대로 두었다.
  - 사립학교교직원연금공단 상세의 1·2·3·8단계를 단계 목록 클릭으로만 이동했다.
  - [다음]·[작성하기]·저장은 누르지 않았다.
  - P2-3 수정안은 페이지에 style 태그를 잠깐 넣어 측정한 뒤 바로 지웠다. 서버로 간 쓰기는 없다.
  - 읽은 코드: `frontend/js/preptask.js`(noticeChecks·noticeGaps·stepBody·foldBlock·T 문구), `prep.js`(noticeInfo 1320~1351, 빈 목록 문구), `prepboard.js`, `kbboard.js`·`dashboard.js`(단추 이름 확인), `frontend/index.html` 1580~1660.
- **못 본 것**
  - 김영업(담당) 화면은 직접 보지 않았다. qa 스크린샷 qa113_08·10으로 갈음했다.
  - [작성하기]를 누른 뒤 양식 창은 보지 않았다. 누르면 저장되기 때문이다.
  - 휴리스틱 점수표는 생략했다. 이번 일은 국소 규격이고, 화면 전체를 평가하지 않았다.

## 2. 한 줄 총평
2단계는 서로 다른 세 판정이 같은 화면에서 각자 말한다. 상자는 '확인 필요(막음)', 붉은 줄은 '알아야 할 사실(막지 않음)', 머리 줄은 '담당자 기록'이다. 가장 큰 기회는 초록 상자가 **자기가 검사한 범위만 말하게** 하는 것이다.

## 3. 잘 된 점
- 붉은 줄에 sr-only '(확인하세요)'를 붙였다. 색만으로 알리지 않는다.
- '막는 항목'(주황 .ts-gaps)과 '막지 않는 사실'(붉은 .ts-chk)이 코드에서 이미 나뉘어 있다(preptask.js 276줄 주석). 그래서 문구·색만 고치면 된다.
- 4단계 안내 profitHint가 단계 번호와 이름을 STEPS에서 가져온다. 이름이 바뀌어도 어긋나지 않는다.

## 4. 우선순위 이슈

### P2-1 2단계 안내 충돌
**근거(코드)**
- 초록 상자는 `gaps.length === 0`이면 무조건 `T.noticeOk`("누락되거나 미확인인 항목이 없습니다…")를 낸다(preptask.js 697~700).
- gaps를 만드는 `pt.noticeGaps`(262~272)가 보는 것은 5가지뿐이다: 예정일 미상, 공고일 확인 필요, 접수 마감일 미확인, 공고 링크 없음, 미처리.
- 붉은 '공고 원본 파일 없음'은 `noticeChecks`의 bad 줄이라 gaps에 들어가지 않는다.
- 기관 정보의 금고 은행·약정 기간·기관장 '미확인'은 아래 `ni.html`(dashboard 팝업 마크업) 안에만 있고, 어느 판정에도 들어가지 않는다.
- 머리 줄 `<dt>공고 상태</dt>`(684줄)는 `notice_status_name`, 곧 **담당자가 적은 공고 상태 기록**(공통코드 NOTICE_STATUS)이다. 그런데 바로 아래 '공고 진행'은 공고 자료에서 **계산한 값**이다.

**근거(실측, 1280)**
- 한 화면에 차례로 나온다: '공고 상태 없음' → '공고 진행 접수 중 · 마감 2026-12-07 (D-12)' → 붉은 '공고 원본 파일 없음…' → 초록 '누락되거나 미확인인 항목이 없습니다' → 기관 정보 '미확인' 3칸.

**왜 문제인가**
- 상자가 "미확인 없음"이라고 단언하는데, 같은 화면에 '미확인'이 세 번 보인다.
- 첫 사용자는 상자와 붉은 줄 중 어느 쪽을 믿을지 모른다.

**수정 방향**: 6절 ① 상태 표대로.

### P2-2 (새로 발견) 빈 목록 안내가 없어진 단추 이름을 가리킨다 — 4번 대조

### P2-3 단계 이름이 옆 칸과 겹침
**근거(실측, 1280)**
- 단추 폭 223px, 열 정의 `22px 14px minmax(0,1fr) auto`.
- '이사회 개최 및 결과'는 scrollWidth 118 > clientWidth 102이고, 이름 오른쪽 끝(431)이 '완료 0/3'(437)을 넘는다.

**측정**
- `.ts-name { white-space:normal }`를 넣으면 '이사회 개최 및 / 결과' 두 줄이 된다. scrollWidth 102 = clientWidth 102로 겹침이 없다.
- 줄 높이는 32→46px로 늘어난다. 확인 캡처: `c:\github\GGReportAgent\.playwright-mcp\dr1125_steps_wrap.png`

## 5. 문구 / 접근성
- **문구**
  - "누락되거나 미확인인 항목이 없습니다"는 검사 범위를 넘는 단언이다. 범위를 이름으로 밝힌다(6절 ①).
  - 머리 줄 '공고 상태 없음'은 "공고가 없다"로 읽힌다. 실제 뜻은 "담당자 기록 없음"이다. 2단계 본문에서 이 줄을 뺀다(6절 ①).
  - 빈 목록 끝말이 '나타납니다'(prep)와 '생깁니다'(prepboard)로 갈린다. '나타납니다'로 맞춘다.
- **접근성**
  - 붉은 줄 글자 `--red` #bd2c0f는 `--panel2` #f6f7f9 위에서 약 5.5:1로 통과한다. 초록 줄 `--green` #1d6f3a는 흰 바탕에서 6.20:1이다(DESIGN.md).
  - 접근성 쪽 새 문제는 없다. 6절 ③의 저장 안내 문장은 단추에 `aria-describedby`로 묶는다.
- **계약 어긋남(발견)**
  - DESIGN.md 66줄은 `--green`을 "시작화면 신규 확정 칩 전용"으로 정한다.
  - 그런데 `.ts-okline`(index.html 1659)이 `--green`을 글자색으로 쓴다(112장 이후). 계약을 고칠지 화면을 고칠지는 8절 질문으로 넘긴다.
