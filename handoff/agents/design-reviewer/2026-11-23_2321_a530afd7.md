# 영업 추진 준비 › 대시보드: '개설 승인 전' 줄의 손 칸 규격 (NEXT 102)

## 1. 대상·방법·못 본 것
- **방법**: 소스만 읽었습니다(Playwright는 지시대로 쓰지 않음). 읽은 곳은 다음과 같습니다.
  - `frontend/js/prepboard.js`: `cellModel`·`cellAria`·`infoParts`·`cellHtml`·`rowHtml`·`legendHtml`·`readOnlyAll`, 문구 표 `T`
  - `frontend/index.html`: `.pb-*` CSS 1460–1506줄, 마크업 3251–3268줄, 토큰 15–16줄
  - `PrepBoardService.java` 59–68·219–229줄과 `PrepService.java`의 상태 코드
  - `DESIGN.md` 89줄(빗금 규칙)
- **못 본 것**: 렌더된 실제 화면이라 대비·넘침 실측이 없습니다. 이전 규격 `2026-11-23_1049_ae4db5c1.md`는 다시 읽지 않았습니다(코드 주석에 적힌 5·6절만 전제).
- **확인한 사실**
  - 서버는 줄마다 `state_cd`를 내려 줍니다(PrepBoardService 219줄). 그래서 화면이 '개설 승인 전'을 따로 알아낼 수 있습니다.
  - `can_check`는 `mine && CHECK_STATES`입니다(229줄). 개설 전(CONFIRMED·OPEN_PENDING)은 활성 담당 배정이 없어서 모두에게 false입니다(64줄 주석 D31).
  - 지금 화면은 개설 전 칸과 '담당 아닌 사람의 읽기 전용' 칸이 **같은 마크업**입니다(`cellHtml`의 마지막 return, `<td aria-readonly><span class="pb-in">`). 겉모양도 같고, 스크린리더가 읽는 이름(aria-label)에도 이유가 없습니다.
  - 아래 정보 줄 `#pb-info`는 `aria-hidden="true"`입니다. 그래서 **스크린리더가 이유를 들을 수 있는 곳은 칸의 aria-label 하나뿐**입니다.

## 2. 한 줄 총평과 가장 큰 기회
'누가 체크하나'에 대한 답이 둘(다른 담당 / 아직 아무도 없음)인데 화면은 한 가지로 보여 줍니다. 가장 큰 기회는 **줄 하나에 '개설 전' 칩을 달고, 손 칸에 이미 쓰는 '준비중' 빗금을 칠하는 것**입니다. 그러면 사용자가 다음에 할 일이 '담당에게 묻기'인지 '승인 기다리기'인지 갈립니다.

## 3. 점수표 / 잘 된 점
- 점수표는 해당 없습니다(한 상태만 정하는 규격이라서).
- **잘 된 점**
  - 칸마다 aria-label에 기관·칸 이름·값·날짜·사람을 말로 담아 두었습니다(`cellAria`). 이번에는 꼬리 한 구절만 붙이면 됩니다.
  - 개설 전 줄은 이미 `.pb-who`에 '담당 미정'이 나옵니다(`T.noAssignee`). 이유의 절반이 화면에 있습니다.
  - 끝난 줄(`is-ended`)은 줄 단위로 따로 표시합니다. 개설 전도 같은 '줄 상태' 방식으로 붙일 수 있습니다.

## 4. 우선순위 이슈
- **P1 — 개설 전 손 칸이 왜 안 눌리는지 알 길이 없음**
  - 근거: `cellModel.button`이 `r.can_check === true`일 때만 버튼을 만들고, 나머지는 모두 `.pb-in`입니다. 정보 줄의 꼬리 문구는 `T.infoNotMine`('체크는 이 기관의 담당 영업만 합니다.')입니다. 개설 전 줄에서는 담당이 없으니 이 문구가 사실과 맞지 않습니다.
  - 왜 문제인가: 팀장·영업이 "담당이 누구냐"를 찾아다니게 됩니다. 실제로 해야 할 일은 개설 승인을 기다리는 것입니다.
  - 수정: 6절 규격 ①–⑥.
- **P2 — 개설 전 줄만 있을 때 표 위 안내가 틀림**
  - 근거: `readOnlyAll`은 '`can_check`인 줄이 하나도 없으면' 참입니다. 그래서 개설 전 줄만 있을 때도 `#pb-ro`('지금 계정이 담당한 기관이 없어 보기만 합니다…')가 뜹니다.
  - 왜 문제인가: 담당 영업 본인도 '담당한 기관이 없다'는 안내를 받습니다.
  - 수정: 6절 ⑦.
- **P3 — 담당 아닌 사람의 읽기 전용 칸도 aria-label에 이유가 없음**
  - 근거: `aria-readonly`만 있습니다.
  - 수정: 같은 꼬리 방식으로 ', 담당 영업이 체크'를 붙입니다. 이번 범위 밖이라 선택 사항입니다. 6절 ④에 함께 적었습니다.

## 5. 문구 / 접근성
- **① 구분 여부: 구분합니다.** 사용자가 할 일이 다르기 때문입니다.
  - 담당 아님 → 보기만 합니다. 지금처럼 평범한 흰 칸으로 둡니다.
  - 개설 전 → 아직 누구도 체크하지 않습니다. 줄에 '개설 전' 칩, 손 칸 3개에 빗금, 범례 한 줄을 둡니다.
  - 빗금은 `DESIGN.md` 89줄의 '준비중/추정' 질감이고, 이미 쓰는 식(index.html 155·1376·2401줄)을 그대로 씁니다. **새 hex는 없습니다.**
  - 빗금은 보조 신호일 뿐입니다. 정보는 칩 글자와 aria-label이 전하므로 색 하나로만 전하지 않습니다.
- **② 문구와 위치 4곳** (네 번째는 조건부, 모두 12px 이상)

  | 위치 | 문구 | 길이 |
  |---|---|---|
  | 줄 칩(이름 칸, `wf-badge pp-neutral pb-chip`) | `개설 전` | 3자 |
  | 칸 aria-label 꼬리 | `, 개설 승인 뒤 담당 영업이 체크` | 17자 |
  | 정보 줄 꼬리(`#pb-info`, 손 칸을 골랐을 때) | `— 개설 승인 뒤 정해지는 담당 영업이 체크합니다.` | 26자 |
  | 범례 한 항목(개설 전 줄이 있을 때만) | `개설 승인 전 — 담당이 정해지면 체크합니다` | 21자 |

  - **title은 쓰지 않습니다.** aria-label이 있는 칸에 title을 붙이면 Chrome이 설명으로 한 번 더 읽어 중복됩니다. 마우스 사용자는 칸을 누르면 정보 줄에서 같은 이유를 봅니다.
  - `.pb-who`는 '담당 미정' 그대로 둡니다. 너비 176px − 20px = 156px 안에 이유까지 넣으면 말줄임(…)이 납니다.
  - 개설 전 줄만 있을 때 `#pb-ro` 문구: `아직 개설 승인된 기관이 없어 체크할 칸이 없습니다. 담당 영업은 개설 승인 때 정해집니다.` (48자)
- **③ 접근성**
  - 스크린리더 예시: '○○구 가결위(재무): 시작 전, 개설 승인 뒤 담당 영업이 체크'.
  - 칸은 `aria-readonly="true"`를 그대로 둡니다. 역할(gridcell)과 roving tabindex도 그대로입니다.
  - 줄 머리(rowheader)에 칩 글자 '개설 전'이 들어가므로, 줄 이동 때 상태가 함께 읽힙니다.
  - 자동 칸(AUTO)과 공고 칸(NOTICE)은 바꾸지 않습니다. 시스템이 채우는 칸이라 개설 전과 상관없습니다.
  - 끝난 줄(`ended`)이 우선입니다. 개설 전에 취소된 건은 '확정 취소' 처리를 그대로 받습니다.

## 6. 규격 — frontend-dev가 그대로 옮길 것
- ① 판정 함수 추가(순수 함수, 테스트 대상)

```js
// 개설 승인 전 — 활성 담당 배정이 개설 승인 때 생기므로 이 줄의 손 칸은 아무도 체크하지 못한다(D31, 팀 결정 A).
pb.PRE_OPEN_STATES = ['CONFIRMED', 'OPEN_PENDING'];
pb.preOpen = function (row) {
  return !!row && !row.ended && pb.PRE_OPEN_STATES.indexOf(str(row.state_cd)) >= 0;
};
```

- ② 문구 `T`에 추가

```js
chipPre: '개설 전',
ariaPre: ', 개설 승인 뒤 담당 영업이 체크',
infoPre: '개설 승인 뒤 정해지는 담당 영업이 체크합니다.',
legendPre: '개설 승인 전 — 담당이 정해지면 체크합니다',
readOnlyPre: '아직 개설 승인된 기관이 없어 체크할 칸이 없습니다. 담당 영업은 개설 승인 때 정해집니다.',
```

- ③ `cellModel`의 반환에 `pre` 추가

```js
pre: kind === 'MANUAL' && pb.preOpen(r),
```

  - `button` 식은 바꾸지 않습니다(`can_check`가 false라 이미 false입니다).
  - `tint`는 그대로 둡니다. 개설 전에 남은 값이 있으면 색도 보이는 게 사실과 맞습니다.
- ④ `cellAria`: 손 칸(MANUAL) 분기의 두 return 끝에 꼬리를 붙입니다.

```js
const tail = pb.preOpen(row) ? T.ariaPre : '';
if (m === 'NONE') return head + name + tail;
...
return head + name + (d ? ', ' + d + (by ? ' ' + by + ' 체크' : '') : '') + tail;
```

  - 선택(P3): 개설 전이 아니고 `row.can_check !== true && !row.ended`이면 꼬리를 `', 담당 영업이 체크'`로 합니다.
- ⑤ `infoParts`: 손 칸의 꼬리를 고릅니다. 개설 전이면 `infoNotMine` 대신 `infoPre`를 씁니다.

```js
const why = r.can_check === true || r.ended ? '' : (pb.preOpen(r) ? T.infoPre : T.infoNotMine);
if (m === 'NONE') return { parts: parts, tail: '— ' + T.infoNoCheck + (why ? ' ' + why : '') };
...
return { parts: parts, tail: why };
```

- ⑥ 마크업
  - `cellHtml`: class 문자열에 `(m.pre ? ' is-pre' : '')`를 더합니다. 읽기 전용 return(마지막 줄)은 그대로 둡니다.
  - `rowHtml`: 칩 식을 바꿉니다.

```js
const chip = row.ended ? '<span class="wf-badge pp-neutral pb-chip">' + esc(str(row.state_name).trim() || T.chipEnded) + '</span>'
  : pb.preOpen(row) ? '<span class="wf-badge pp-neutral pb-chip">' + T.chipPre + '</span>'
  : row.is_mine === true ? '<span class="wf-badge pp-neutral pb-chip">' + T.chipMine + '</span>' : '';
```

  - `legendHtml(hasPre)`: 끝에 `(hasPre ? '<span><i class="sw-pre"></i>' + T.legendPre + '</span>' : '')`를 붙입니다. 부르는 쪽은 `rows.some(pb.preOpen)`을 넘깁니다. 매번 그리기 어려우면 항상 보여도 됩니다(차선).
  - 칩 글자는 상태 이름(확정됨/개설 대기)이 아니라 고정 '개설 전'으로 합니다. 두 상태 모두 '아직 체크 못 함'이라는 같은 뜻이고, 상세한 상태 이름은 이름 칸 정보 줄('상태')에 이미 나옵니다.
- ⑦ `readOnlyAll` 바로잡기와 개설 전 전용 안내

```js
pb.readOnlyAll = function (rows) {   // 개설 승인 뒤 줄이 있는데 내가 체크할 수 있는 줄이 없을 때
  const open = (Array.isArray(rows) ? rows : []).filter(function (x) { return x && !x.ended && !pb.preOpen(x); });
  return open.length > 0 && !open.some(function (x) { return x.can_check === true; });
};
pb.preOnly = function (rows) {        // 살아 있는 줄이 모두 개설 전
  const live = (Array.isArray(rows) ? rows : []).filter(function (x) { return x && !x.ended; });
  return live.length > 0 && live.every(pb.preOpen);
};
```

  - `#pb-ro`의 글자는 `preOnly`면 `T.readOnlyPre`, `readOnlyAll`이면 `T.readOnly`로 넣습니다. 둘 다 아니면 숨깁니다. 마크업 3263줄의 고정 문구는 JS가 덮어씁니다.
  - 확인 필요: 지금은 `readOnlyAll`이 끝난 줄도 셉니다. 끝난 줄만 있을 때 안내가 사라지는 것이 맞는지 frontend-dev가 기존 테스트로 확인합니다.
- ⑧ CSS (index.html의 `.pb-*` 블록, 1497줄 아래에 둡니다)

```css
/* 개설 승인 전 손 칸 — '준비중' 빗금(DESIGN 89줄, 155·1376줄과 같은 식). 값 칸 색(data-mk)이 있으면 그 위에 겹친다. */
.pb-t td.is-pre { background-image:repeating-linear-gradient(45deg, color-mix(in srgb, var(--muted) 14%, transparent) 0 2px, transparent 2px 4px); }
.pb-legend .sw-pre { display:inline-block; width:14px; height:14px; margin-right:4px; vertical-align:-3px; box-sizing:border-box;
  border:1px solid var(--line-strong); border-radius:var(--r);
  background:repeating-linear-gradient(45deg, color-mix(in srgb, var(--muted) 14%, transparent) 0 2px, transparent 2px 4px); }
```

  - `background-color`는 건드리지 않습니다(`background-image`만). 그래서 `data-mk`의 색과 포커스 링(2px `--accent-color`)이 그대로 살아납니다.
  - hover는 없습니다(`.pb-in`은 버튼이 아닙니다). 커서도 기본 그대로 둡니다(`not-allowed` 안 씀). 읽기 칸도 정보 줄을 보려고 누르는 칸이기 때문입니다.
- ⑨ 테스트 대상(frontend-dev 몫)
  - `preOpen`: CONFIRMED·OPEN_PENDING이면 참, `ended`면 거짓.
  - 개설 전 손 칸: aria-label 꼬리가 붙고, AUTO·NOTICE에는 붙지 않습니다.
  - `infoParts` 꼬리가 `infoPre`인지.
  - `readOnlyAll`·`preOnly`의 조합.
  - `cellHtml`에 `is-pre` class가 있는지.
- ⑩ 전/후 장 필요(`docs/design_history/index.html`, 적용 커밋 때 메인이 더할 문안)
  - **전**: 개설 대기 줄의 가결위(재무)·출심위(사업부)·이사회 칸이 다른 사람 담당 칸과 똑같은 흰 칸이고, 눌러도 메뉴가 뜨지 않습니다. 정보 줄은 '체크는 이 기관의 담당 영업만 합니다.'라고 하는데, 담당은 아직 없습니다.
  - **후**: 기관 이름 옆에 '개설 전' 칩이 붙고, 손 칸 3개에 옅은 빗금이 칠해집니다(`--muted` 14%, 지도 '준비중'과 같은 질감). 범례에는 '개설 승인 전 — 담당이 정해지면 체크합니다'가 붙고, 칸을 고르면 '개설 승인 뒤 정해지는 담당 영업이 체크합니다.'가 보입니다. 스크린리더도 같은 이유를 읽습니다.
  - **대비 숫자**: 실측 전이라 적을 수 없습니다. 칩 글자와 정보 줄 글자는 기존 토큰 그대로입니다. 참고로 `--muted` #464c53 / `--panel` #fff는 계산상 약 9:1이고, 빗금 자체는 장식 신호라 대비 기준 대상이 아닙니다.
  - **왜**: 할 일이 '담당에게 묻기'가 아니라 '개설 승인 기다리기'임을 알리기 위해서입니다(팀 결정 A).

## 7. 이관 메모
- [이관: 개발] 개설 전 판정을 화면이 상태 코드 두 개(`CONFIRMED`·`OPEN_PENDING`)로 할지, 서버가 줄마다 `check_block: 'PRE_OPEN'|'NOT_MINE'|null` 같은 이유 필드를 줄지 정해야 합니다.
  - 디자인이 기다리는 것: 없습니다. 지금 규격은 화면 판정으로 동작합니다.
  - 근거: `CHECK_STATES`가 개설 전을 허용 목록에 두고 실제 차단은 담당 검사(403)에 맡겨 두었습니다(PrepBoardService 61–68줄). 그래서 서버와 화면이 판정을 따로 갖게 됩니다.
- [이관: 데이터] 개설 전에 취소했다가 되살린 건(`reviveCase`)의 손 칸에 옛 체크 값이 남을 수 있는지 확인이 필요합니다.
  - 디자인이 기다리는 것: 값이 남는다면 빗금 위에 글리프와 색이 함께 보이는데, 그대로 둘지 정해야 합니다(규격은 보이게 둠).
  - 근거: 이번에는 확인하지 않았습니다.
- [이관: 기획] 영업팀 전원이 개설 전 줄을 보는 게 맞는지(정보 줄 '상세는 담당자와…' 문구와의 관계)는 이번 범위 밖이라 손대지 않았습니다.
