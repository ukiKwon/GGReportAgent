## 4. 우선순위 이슈

**[P2-1] [1년 뒤] 칸과 [1년으로 넓히기]를 누르면 키보드 포커스가 사라짐**
- 근거
  - `dashboard.js` `onClick`의 `case 'db-widen': case 'db-tile-later': setWindow(...)`가 `setWindow` → `renderStrip()`(`#db-tl` innerHTML 교체)·`renderList()`(`#db-scroll` 교체)로 이어집니다.
  - 그래서 방금 누른 버튼이 DOM에서 없어지고 포커스가 `body`로 떨어집니다.
  - 같은 이유로 `db-retry`도 포커스가 사라집니다(`renderStrip`).
- 왜 문제인가: 키보드·화면낭독기 사용자는 Tab 위치를 잃고 화면 맨 위부터 다시 찾아야 합니다. 바뀐 결과(묶음 제목)는 live로 읽히지만, "어디에 있는가"를 잃습니다.
- 수정 방향(패치 후보)
  ```js
  case 'db-widen': case 'db-tile-later': {
    const fromTile = btn.id === 'db-tile-later';
    setWindow(btn.getAttribute('data-win'), true);
    const t = fromTile ? $('db-tile-later') : (host && host.querySelector('#db-per input:checked'));
    if (t) t.focus();
    break;
  }
  case 'db-retry': loadProgress().then(function () { const r = $('db-retry'); (r || $('db-t2') || {}).focus && (r || $('db-rail')).focus(); }); break;
  ```
  - [1년으로 넓히기]는 포커스를 선택된 기간 라디오로 옮깁니다. 사용자가 방금 바뀐 '1년'을 듣고 ←→로 바로 되돌릴 수 있습니다.
  - `db-retry`는 최소한 `#db-rail`에 `tabindex="-1"`을 주고 거기로 보내도 됩니다.

**[P2-2] 1280~1599px에서 작업 줄이 `.db-work` 상자 밖으로 넘칠 가능성(실화면 확인 필요)**
- 근거
  - 기본 규칙은 `.db-work{flex:1 1 0; min-height:440px}`입니다.
  - `@media (max-width:1599px)`에서 `grid-template-rows:auto minmax(440px,1fr)`가 됩니다. 기둥 줄(auto, 와플 9줄 + 제목 ≈ 230px 추정) + 작업 줄 440 이상이라 내용은 약 690px 이상입니다.
  - 그런데 flex-basis 0과 min-height 440 때문에 상자 자체는 440까지 줄어들 수 있습니다.
  - 1366×768은 시간표 약 290 + 간격 20 + 440이라 상자가 최소 높이에 걸리는 폭입니다.
- 예상 증상: 그리드 트랙이 `.db-work` 밖으로 넘칩니다. 스크롤 범위에는 들어가겠지만, 아래 여백이 사라지고 `#db-root` 높이 계산이 실제 내용과 어긋납니다.
- 수정 방향: 미디어쿼리 안에서 기둥 높이까지 포함하도록 바꿉니다.
  ```css
  @media (max-width:1599px){ .db-work{ flex:1 0 auto; min-height:0; } }
  ```
  - 작업 줄의 440 하한은 `minmax(440px,1fr)`가 이미 지킵니다.
  - 확인 방법: 1366×768에서 `#db-root .db-work`의 `scrollHeight`와 `clientHeight`를 비교하고, `.db-list`의 아래 끝이 `.db-work` 아래 끝 안에 있는지 봅니다.

**[P3-1] 범례의 추정 문구가 길어 1366에서 두 줄이 됨(추정)**
- 근거: 범례 문구는 "추정(최근 절차일 + 약정 주기, 또는 약정 만료 6개월 전) — 그중 약정 만료 기준 n곳"이고, `.lg-n`이 `margin-left:auto`라 줄이 접히면 오른쪽 끝에 홀로 남습니다.
- 수정안: "추정(최근 절차일+약정 주기 / 약정 만료 6개월 전) · 약정 만료 기준 n곳".

**[P3-2] 경과 기관의 상세에 D+ 도장이 두 번 나옴**
- 근거: 제목 옆 `.ov-stamp`와 약정 막대 위 `.term-stamp`(`top:-30px`)가 둘 다 보이고, `.term-stamp`는 h3 '약정 주기' 줄 오른쪽에 겹쳐 앉습니다.
- 수정 방향: 막대 쪽 도장을 빼고, 라벨 '오늘 D+n'만 둬도 정보가 같습니다.

**[P3-3] 기관을 고르기 전에는 상세 영역에 이름이 없음**
- 근거: `<section class="db-pane" aria-labelledby="db-name">`인데, 미선택이면 `#db-name`이 없습니다.
- 수정 방향: `aria-label="기관 상세"`를 함께 두거나, blank일 때 aria-labelledby를 뺍니다.

**[P3-4] DESIGN.md에 현황판 부품이 없음(문서 공백)**
- 근거: 월별 막대(빗금 = 추정), 와플(칸 하나 = 기관 하나), 기간 세그먼트(라디오) 규칙이 DESIGN.md에 없습니다.
- 수정 방향: 다음 계약 갱신 때 Components 절에 3줄로 더합니다. 이번 커밋을 막지는 않습니다.

## 5. 문구 / 접근성
- **문구**: 단계 이름이 prep 단계 막대와 같고, '대기'는 승인 대기에만 붙습니다. 색 이름을 쓰지 않고, 빈 상태·다음 구간 안내·권한·오류 문구 모두 원인과 행동이 있습니다. 내부 용어 노출은 없습니다.
- **대비**: 새 색이 없어 기준 보고서 §5-2 값을 그대로 씁니다. 보조 글자 6.4:1, 빨강 5.6:1, 주황 7.3:1, 틸 7.1:1, 도장 약 14:1. 실측은 못 했습니다.
- **색만으로 전달하지 않음**: ▲, 빗금/채움, 와플의 채운 칸/빈 칸, '대기' 글자가 모두 있습니다.
- **키보드**: listbox ↑↓/Home/End/Enter, Esc로 확정 확인 닫기, 라디오 ←→ 모두 있습니다. 결함은 P2-1뿐입니다.
- **움직임**: `.db-row:hover`의 translateX가 남아 있으나, reduced-motion에서 꺼지고 overflow-x hidden이라 넘치지 않습니다.
