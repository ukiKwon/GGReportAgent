**총평**: 절 위치와 폭은 지금 그대로 둬도 됩니다. 넣기 전에 고칠 것은 id 충돌 하나(P0)입니다.

**① 위치·폭·스크롤 (실측)**
- 절은 이미 ①절 '입찰 예정' 안의 h4 소구획에 있습니다. 위치는 본문 위에서 134px 아래입니다. 옮기지 않습니다.
- 팝업 폭은 720px, 본문 높이는 650px입니다. 기록 칸 전체 높이는 입찰 공고 현황 실측 362px라서 800px 화면에서 스크롤 없이 다 보입니다.
- 판정 버튼 4개 묶음(.db-rec-seg)은 458px이고 팝업 내용 폭은 661px라서 한 줄에 들어갑니다. 새 CSS가 필요 없습니다.
- 스크롤은 기존 `.dm-box .db-pane-body`(overflow:auto) 하나만 씁니다.

**② 입력 칸 구성 — 팝업용 조정**
- 그리는 함수를 바꿉니다. `recordBriefHtml` 대신 `nr.sectionHtml(it,{nested:true,...})`를 넣습니다. 넘기는 값은 recViewHtml과 같게 하되 `canEdit: n.canEdit() && !m.readOnly`입니다. 이렇게 하면 '공고 자료' 줄과 "이 회차는 미처리로 셉니다"가 생깁니다. 지금 팝업 요약에는 둘 다 없습니다.
- `#dm-rec-go` 버튼과 `.db-rec-go` 줄은 지도·현황판 팝업에서 뺍니다.
- **P0 — 같은 id가 두 번 생깁니다(실측)**: 입찰 공고 현황 탭을 닫지 않고 지도로 가면 `#db-rec`·`#db-rec-save`·`#db-rec-op`가 숨은 채 DOM에 각각 1개씩 남아 있습니다.
  - 그 상태에서 팝업에 같은 마크업을 넣으면 `label for="db-rec-op"`와 `aria-describedby`가 숨은 쪽을 가리킵니다. 라벨을 눌러도 팝업 칸에 포커스가 가지 않고, 화면낭독기 이름도 틀립니다.
  - 고치는 방향: sectionHtml/formHtml에 id 앞글자 인자(예 `v.idp='dm-'`)를 받아 모든 id·for·aria-*에 붙입니다.
  - 라디오 `name="rec-state"`도 팝업용 이름(`dm-rec-state`)으로 바꿉니다.
  - 이벤트 처리는 `$()`(host 안에서만 찾음) 대신 `m.el.querySelector`를 씁니다.

**③ 저장 뒤**
- 팝업은 열린 채 둡니다. 포커스는 `#dm-rec-save`로 돌립니다(recDone과 같게).
- 성공 문구는 고정 알림 줄 `#dm-flash`에 한 줄로 냅니다. 예: "기록을 저장했습니다. 이영업 · 2026-11-25 01:25"
- 목록을 다시 받아 상태가 'ok'일 때만(moveNoteIf) 같은 줄 끝에 이동 안내를 붙입니다. 이때 기준은 **지도 패널의 지금 보기**이고, 입찰 공고 현황의 st.ovView가 아닙니다.
  - 미처리 보기였으면 "이 기관은 [처리됨] 보기로 옮겼습니다."
  - 경과 목록에서 아예 빠졌으면 "이 기관은 경과 목록에서 빠졌습니다."
  - '전체' 보기면 붙이지 않습니다.
- 닫을 때 원래 누른 기관 이름 버튼이 목록에서 사라졌을 수 있습니다. 그러면 포커스는 그 시·도 묶음의 다음 기관으로, 없으면 묶음 제목(summary)으로 보냅니다(opts.refocus).

**④ 보기 전용 (영업이 아니거나 readOnly)**
- sectionHtml 읽기 모양을 그대로 씁니다: 공고 자료 / 담당자 기록 / 마지막 기록, 그 아래 `.db-empty` "공고 상태는 영업팀이 기록합니다. 다른 팀은 기록을 볼 수 있습니다.", 그리고 이력 펼침.
- 입력 칸·잠금 표시·이동 버튼은 두지 않습니다.
- 목록을 못 받았을 때(error·denied)는 sectionHtml에 이미 있는 문구를 씁니다.

**⑤ 충돌·실패 문구 위치**
- 409 STALE·ROUND_CHANGED(남이 먼저 기록함)와 서버 무응답: 절 안 `#dm-db-rec-alert`(role=alert, tabindex=-1)에 내고 포커스를 옮깁니다. 이력을 다시 받아 최신 기록을 위에 보입니다. 문구가 "위 최신 기록을 확인하고…"라서 절 안에 있어야 말이 맞습니다.
- 400 필드 오류: 각 칸 아래 `.db-rec-err`에 내고 그 칸으로 포커스를 옮깁니다.
- **403과 401은 위쪽 `#dm-err`에 냅니다.** 403 뒤에는 권한을 다시 확인해 입력 칸이 사라지므로 절 안 문구가 함께 지워지기 때문입니다.
- 진행 중 제안 확인(ACTIVE_PREP_CONFIRM_REQUIRED): 절 안 `.db-confirm`에 띄우고 포커스는 [기록하기]로 옮깁니다. 현황판의 '확정 확인 상자'(#dm-act-note)와는 섞지 않습니다.

**⑥ 접근성**
- 탭 순서: 머리 줄(닫기) → 판정 라디오 묶음(방향키로 고름) → 다음 확인일 → 의견 → [기록 저장] → [되돌리기] → 이력 펼침 → 기관 정보 순입니다. dmKey의 포커스 가두기가 그대로 감쌉니다.
- 처음 포커스는 기존대로 `#dm-name`입니다. 라디오로 자동으로 옮기지 않습니다.
- dmKey Escape 우선순위: 저장 중이면 무시 → 기록 확인 상자가 열려 있으면 그것만 닫고 `#dm-rec-save`로 → 확정 상자 → 이탈 상자 → dmBack.
- 저장하지 않은 기록이 있는데 닫기·Esc·바깥 클릭을 하면 leaveBoxHtml 모양을 씁니다. 다만 문구에 인자를 받게 고칩니다: "저장하지 않은 공고 상태 기록이 있습니다." [버리고 닫기]·[계속 입력]. 지금 문구에는 '약정'이 고정돼 있습니다.
- 확인한 크기: 라디오 칸은 32px 높이, [기록 저장]은 35px로 둘 다 괜찮습니다. 지금 `#dm-rec-go`는 29px인데 이번에 버튼째 빠집니다.

**전/후 장 필요** (design_history, 적용 뒤): 전 = 팝업 기록 절이 한 줄 요약과 [입찰 공고 현황에서 기록](탭 이동·팝업 닫힘)뿐. 후 = 같은 자리(본문 위 134px)에서 판정 4개·다음 확인일·의견·[기록 저장]이 바로 보이고, 저장 뒤 팝업 위 알림 줄에 결과와 목록 이동 안내가 뜸. 수치 = 클릭 '이동 → 선택 → 입력 → 저장' 대비 '선택 → 입력 → 저장', 화면 전환 0회.
