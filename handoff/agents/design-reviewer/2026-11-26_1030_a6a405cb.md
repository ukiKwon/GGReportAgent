# design-reviewer 보고 — 입찰 현황판 목표 표: 12개월 띠 삭제와 '동작' 칸 미커밋 변경 대조 (2026-11-26)

## 1. 대상·방법·못 본 것
- **방법: 코드만 읽고 판정했다.** Playwright MCP가 연결 시간 초과(CONNECT_TIMEOUT)로 붙지 않아 8080 화면을 열지 못했다. 그래서 **1280·1440px 실측도 캡처도 없다.** 아래 폭은 모두 계산값이다. 기준은 121장의 1280px 표 폭 989px이고, 고르기 열 +32px, 스크롤 막대 −17px로 셈했다. 단추 폭은 맑은 고딕 12px 글자 폭으로 추정했다.
- 읽은 것: frontend-dev 지시서 `handoff/agents/frontend-dev/2026-11-26_0931_a7ecdb32.md`, `frontend/index.html` `.hb-*` 구역(2115~2494행), `frontend/js/kbboard.js` 928~1067·1895~1914행, `frontend/js/tchange.js` 734~785행, `DESIGN.md` 94~105행, `docs/design_history/index.html`(마지막 장 122).
- 못 본 것: 단추 실제 폭, 두 줄로 쌓인 줄의 실제 높이, 기관 이름이 얼마나 잘리는지, 준비 단계 칸에서 `actHtml` 단추(단계 없는 줄)가 잘리는지, 결재함 카드 실제 모양.

## 2. 한 줄 총평
**조건부 통과다.** 띠·월 머리·범례·관련 CSS는 깨끗이 지워졌다(js·html 모두 `hb-lane`·`td.ln`·`has-acts`·`.hb-tf .lg` 0건). 동작 칸은 관심 표와 같은 방식(`.hb-wacts` + 머리 sr-only '동작')이라 화면 안 규칙이 하나로 맞는다.
**가장 큰 기회:** 고르기 열이 늘 켜지는 편집자 화면에서 기관 열이 이전 150px 고정보다 **좁아졌다**(110~127px). 이름 칸에 전체 이름 `title`을 다는 것이 가장 싼 보완이다.

(이번 일은 국소 변경 대조라 휴리스틱 10개 점수는 매기지 않았다.)

**잘 된 점**
- CSS 우선순위가 맞다. `.hb-tt:not(.wt) col.c-act`는 클래스 셋에 요소 하나라, 클래스 둘짜리인 관심 표 규칙 `.hb-tt col.c-act {150px}`(2357행)와 `@media(min-width:1440px){.hb-tt col.c-act{230px}}`(2467행)를 순서와 상관없이 이긴다. 그래서 목표 표는 140/250px, 관심 표는 150/230px 그대로다.
- 전역 `* { box-sizing:border-box }`(27행) 덕분에 `td.act { padding:4px 6px }`가 줄 높이 40px를 늘리지 않는다. 한 줄 단추는 24+8=32px라 40px 안에 들고, 두 줄은 24+4+24+8=60px다. 포커스 링(2px, 띄움 2px)도 위아래 여백 4px 안에 들어가 `overflow:hidden`에 잘리지 않는다.
- 단추 조건이 그대로다. 보기 전용·결재 중·목표 밖 줄은 단추 없이 sr 문장 '올해 입찰이 끝난 기관'만 둔다. 지난해 목표 줄은 [다음 회차 목표로…]만 둔다. 보이는 글자 '올해 입찰 끝남'을 뺀 것도 맞다(마감까지 칸 '입찰 종료'와 같은 말이 두 번 나오지 않는다).

## 4. 우선순위 이슈

### P1-1 준비 단계 132px는 NEXT 120(단계 칸 두 줄)이 아직 안 들어가 '지연' 줄에서 단계 이름이 사라진다
- 근거: 이 작업 트리에 `.hb-stg.two` 같은 120 패치 흔적이 없다(index.html·kbboard.js grep 0건). `stageCellHtml`(kbboard.js:928~937)은 한 줄 flex에 '이름 + 30px 막대 + n/5 + 지연 칩'을 놓는다.
- 계산: 안쪽 폭은 132−20=112px다. 막대 30 + 숫자 약 22 + 칩 약 38 + 간격 18 = 108px라, 지연 줄의 단계 이름은 약 4px만 남는다(사실상 '…'만 보인다). 지연이 없는 줄도 이름 폭이 58→42px(한글 약 3자)로 준다. 이름에 `title`이 있어 마우스로는 읽을 수 있지만, 이 칸이 주는 핵심 정보가 화면에서 사라진다.
- 수정 방향: **NEXT 120 패치(a794d548)를 같은 커밋에 넣는다.** 그게 안 되면 이번 커밋은 `.hb-tt col.c-stg { width:148px; }`로 두고, 132는 120과 함께 바꾼다(그러면 1280px 기관 열이 16px 더 줄어든다).

### P2-1 고르기 열이 켜진 편집자 화면에서 기관 열이 이전보다 좁다
- 근거: 고르기 열은 `selCol: !!mode`(kbboard.js:1914)라 편집 권한이 있으면 늘 켜진다. 고정 열 합은 166+92+120+124+132+56+140 = **830px**다.
- 1280px 기관 열(계산): 고르기 꺼짐이면 159px(스크롤 막대가 생기면 142px), **켜짐이면 127px(110px)**다. 이전에는 150px 고정이었으므로, 주 사용자(편집자) 화면에서 23~40px 좁아졌다. 110px에서 여백 20, 지역 머리말('서울 ' 약 30px)을 빼면 이름에 약 60px(13px 굵은 글자 약 4자)이 남는다.
- 이름 칸 `<th scope="row">`에는 `title`이 없다(kbboard.js:951). 그래서 잘린 이름을 마우스로도 읽을 수 없다. 화면 낭독기는 단추 이름 전체를 읽으므로 문제없다.
- 수정 방향(폭은 그대로):
  - 목표 표와 관심 표 두 곳(kbboard.js:951과 watchRowHtml의 같은 자리)에서 `'<th scope="row">'`를 `'<th scope="row" title="' + esc(r.regionName + ' ' + r.name) + '">'`로 바꾼다.
  - `title`은 포커스 받는 단추가 아니라 th에 단다(단추 이름과 같은 글이 설명으로 한 번 더 읽히지 않게).
  - 폭을 더 되찾으려면 설명회 열(56px, 모든 줄이 '—')을 어떻게 할지 정해야 한다. 이건 기획이 정할 일이라 이관했다(7절).

### P3-1 낡은 주석과 숫자
- index.html:2115의 머리 주석 '새 :root 변수 없음(표 칸 지역 변수 --rowbg만)'은 --rowbg를 지웠으니 '새 :root 변수 없음, 지역 변수 없음'으로 고친다.
- 880px 이하 `.hb-tt { min-width:990px; }`(2392행)와 시험 주석의 '고정 열 840'은 실제 합 830과 10px 어긋난다. 미지원 폭이라 화면 영향은 없다. 주석을 '980 = 기관 150 + 고정 830'으로 고치거나, 값을 980으로 맞춘다(그러면 시험 `kbboard.test.js` D3도 같이 고친다).

### P3-2 결재함 카드 금고 방식 줄의 바뀐 값 굵은 글씨가 흐린 색이다
- 근거: tchange.js:758 `<span class="tc-memo">금고 방식: A → <b>B</b></span>`. `.tc-memo`는 12px `--muted`(index.html:2482)라 `<b>`도 흐린 색이 된다. 같은 카드의 연도·구분·주 담당이 바뀌면 `goalLine`(tchange.js:734~739)이 보통 글자색 `<b>`로 강조하므로, 같은 '바뀜' 강조가 두 모양이 된다.
- 수정: `.ap-tc .tc-memo b { color:var(--fg); }` 한 줄을 더한다(새 색·새 변수 없음).
- 문구 '정하지 않음 → 1금고'는 '구분 정하지 않음'과 말이 같아 그대로 둔다.

### P3-3 동작 칸 여백이 목표 표와 관심 표에서 다르다
- 목표 표 `td.act`는 4px 6px, 관심 표는 기본값 0 10px이다. 관심 표도 1280px에서 [목표로 옮기기…][관심에서 빼기…](합 약 178px)가 안쪽 130px에 안 들어가 두 줄(52px)로 쌓이는데, 위아래 여백이 0이라 단추가 줄 선에 붙는다.
- 수정(선택): `.hb-tt:not(.wt) td.act`를 `.hb-tt td.act { padding:4px 6px; }`로 넓힌다. 그러면 kbboard-c54.test.js:94의 문자열 단언도 고쳐야 한다. 이번 커밋을 막을 일은 아니다.

## 5. 문구 / 접근성
- 머리 sr-only '동작'은 관심 표와 같다. 빈 칸(입찰 종료가 아닌 줄)은 글자가 없다. 관심 표와 같은 방식이라 문제없다.
- 단추 aria-label은 '{기관명} 관심 기관으로 옮기기' / '{기관명} 다음 회차 목표로 옮기기'로 유지된다. 보이는 이름의 '…'(창이 열림)과 `aria-haspopup="dialog"`도 맞다.
- Tab 순서는 고르기 → 이름 → 구분 → 금고 방식 → (단계 단추) → 동작 단추로, 이전(일정 칸 단추도 맨 끝)과 같다.
- 색만으로 전하는 정보 없음. 새 색·opacity·그림자 없음.
- 기관 이름이 잘려도 `title`로 읽을 길이 없다 → P2-1.
