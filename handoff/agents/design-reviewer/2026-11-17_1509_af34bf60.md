### 6-1. 상태 6종 — 기존 `.wf-badge` 수식자를 다시 쓰고, `.cr-st`로 글자 대비만 보정

**원칙**: 색(hue)은 **이 시스템 안의 누군가가 손을 써야 할 때만** 씁니다. 손쓸 사람이 없으면 중립, 끝났으면 외곽선만 둡니다.

| 상태(코드 제안) | 표기 | 클래스 | 이유 |
|---|---|---|---|
| `REQUESTED` | 요청됨 | `wf-badge cr-st gap` (주황) | 개발부서가 내보내야 함. DESIGN의 "주황 = 대기·관문" |
| `COLLECTING` | 수집 중(반입 대기) | `wf-badge cr-st pp-neutral` | 망 밖이 진행 중이라 안에서 할 일이 없음 |
| `DONE` | 반영됨 | `wf-badge cr-st ok` (파랑) | 끝남(정상) |
| `FAILED` | 실패 | `wf-badge cr-st none` (빨강) | 판단이 필요함 |
| `CANCELLED` | 취소됨 | `wf-badge cr-st pp-cancel` | 사실로 끝남 |
| `EXCLUDED` | 제외됨 | `wf-badge cr-st pp-cancel` | 사실로 끝남. 글자로 취소됨과 구분 |

```css

.wf-badge.cr-st.ok   { color:color-mix(in srgb, var(--blue)   72%, #ffffff); }
.wf-badge.cr-st.none { color:color-mix(in srgb, var(--red)    72%, #ffffff); }
```

- 공용 순수 함수 하나로 두 화면(기관 사업계획·처리 화면)이 같이 씁니다: `plans.reqBadgeHtml(state)`. 형식은 `<span class="wf-badge cr-st gap" data-st="REQUESTED">요청됨</span>`입니다.
- 모르는 코드가 오면 `pp-cancel` 칩에 원문 코드를 그대로 표기합니다(admin.js의 "모르는 값은 원문" 관례).

### 6-2. 기관 사업계획 상세 — 요청 줄 `.pl-req`

- **위치**: `detailHtml`에서 `head()`(h2·배지·sub) **바로 뒤, `impLine` 앞**에 한 곳으로 고정합니다. 자료가 있든 없든 같은 자리입니다.
- **그리지 않는 경우**: `noid`·`offline`·`denied`·`notfound`·`error`·`loading`.

```html
<div class="pl-req" role="group" aria-label="수집 요청">
  <!-- 상태별 안쪽: 아래 표 -->
</div>
```

| 경우 | 안쪽 |
|---|---|
| 열린 요청 없음 · 요청 가능 · 자료 없음 | `<button type="button" id="pl-req-go">수집 요청</button><span class="db-why">개발부서가 수집하고, 자료가 들어오면 쪽지로 알려 드립니다.</span>` |
| 열린 요청 없음 · 요청 가능 · 자료 있음 | `[수집 요청]` + `<span class="db-why">새 계획이 나왔으면 다시 요청하세요.</span>` (반입일은 바로 아래 `impLine`에 이미 있어 반복하지 않음) |
| 요청됨 · 나 포함 | 칩 `요청됨` + `<span class="db-why">나 포함 <span class="v">3</span>명 · 첫 요청 <span class="v">2026-11-17</span></span>` + `<button type="button" id="pl-req-cancel">내 요청 취소</button>` |
| 요청됨 · 나 없음 | 칩 `요청됨` + `<span class="db-why"><span class="v">2</span>명 요청 · 첫 요청 …</span>` + `[수집 요청]` |
| 수집 중 · 나 포함 | 칩 `수집 중(반입 대기)` + `<span class="db-why">나 포함 n명 · 내보냄 <span class="v">YYYY-MM-DD</span></span>` (취소 없음) |
| 수집 중 · 나 없음 | 위와 같은 칩 + `[수집 요청]` (요청자로 덧붙음) |
| 마지막 요청이 실패·제외로 끝남 | 칩 `실패`/`제외됨` + `<span class="db-why">YYYY-MM-DD · 사유: …</span>` + `[수집 요청]` (다시 요청 가능) |
| 디자이너 프로필 | 칩과 사람 수만, **버튼 없음**. 열린 요청이 없으면 줄 자체를 그리지 않음 |

**자료 없음 본문 문구 교체** (`detailHtml` 빈 문서 분기)
- 요청 가능한 사용자: "이 기관의 사업계획은 아직 수집되지 않았습니다." (행동 안내는 위 요청 줄이 맡음)
- 디자이너: "이 기관의 사업계획은 아직 수집되지 않았습니다. 영업부서가 수집을 요청하면 개발부서가 모아 올립니다."

**누른 뒤 `#pl-flash`에 낼 문구**
- 새 요청: "수집을 요청했습니다. 개발부서가 처리하면 쪽지로 알려 드립니다."
- 덧붙음: "이미 요청된 기관이라 요청자로 함께 올렸습니다(나 포함 n명). 결과는 쪽지로 알려 드립니다."
- 취소(나만 빠짐): "내 요청을 취소했습니다. 다른 요청자 n명의 요청은 그대로입니다."
- 취소(마지막 1명): "내 요청을 취소했습니다. 이 기관의 요청은 '취소됨'이 됐습니다."

**목록 줄(`rowHtml`)**: 열린 요청이 있으면 기존 배지 뒤에 칩 하나를 붙입니다. 예: `자료 없음` `요청됨`. 사람 수와 버튼은 붙이지 않습니다. 닫힌 상태는 목록에 표시하지 않습니다. 목록 머리의 상태 라디오(모두/자료 있음/자료 없음)는 그대로 셋으로 둡니다. 넷째 선택지를 늘리지 않습니다.

### 6-3. 현황판·지도 요약 절(`sectionInner`) — **표시는 필요하고, 버튼은 넣지 않습니다**

- **판단**
  - 현황판에서 기관을 볼 때 "누가 이미 요청했나"를 알면 중복 요청과 문의가 줄어듭니다. 그래서 표시는 필요합니다.
  - 쓰기 버튼을 요약 절에 넣지는 않습니다. 이 절에는 "안내 줄을 늘리지 않는다"는 기존 방침(394행 주석)이 있고, 쓰기 지점은 한 곳(기관 사업계획)으로 모읍니다.

| 경우 | `<dd>` | 아래 줄 |
|---|---|---|
| 자료 없음 · 요청 없음 · 요청 가능 | `자료 없음` 점선 칩 | `<p class="pl-open"><button class="link-btn" data-pl-open="{id}">기관 사업계획에서 수집 요청</button></p>` |
| 자료 없음 · 요청 없음 · 디자이너 | `자료 없음` | 없음 (기존 db-empty 문구 삭제) |
| 열린 요청 있음 | `자료 없음`(또는 기존 배지) + 상태 칩 + `<span class="db-why"><span class="v">n</span>명 요청</span>` | 기존 `사업계획 n건 보기` 또는 `기관 사업계획에서 보기` |

- `data-pl-open`은 지금 자료 있는 기관에만 붙어 있습니다. 자료 없는 기관에서도 `plans.openInstitution`이 동작하는지 frontend가 확인해야 합니다.

**칸 규칙**
- **선택 칸**: 요청됨·수집 중 행에만 체크박스를 둡니다. 수집 중을 넣은 이유는 목록을 다시 내려받을 수 있어야 해서입니다. 닫힌 행은 빈 칸입니다.
  - [목록 내려받기]의 n = 선택한 모든 기관
  - [수집 중으로 표시]의 n = 선택한 것 중 **요청됨**만
  - [수집 실행]의 n = 요청됨만
  - 머리 칸 [모두 선택]은 요청됨 행만 고릅니다.
- **경과**: 요청됨이면 "요청 뒤 n일"(첫 요청일 기준), 수집 중이면 "내보낸 뒤 n일"(수집 중 표시일 기준)입니다. 닫힌 행에는 경과 대신 닫힌 날짜를 넣습니다. 예: "반영 2026-11-20".
- **이전 출처**: 호스트만 **글자**로 보이고 링크로 만들지 않습니다. 없으면 `<span class="ad-note">없음</span>`입니다. 여럿이면 첫 값 + "외 n", 전체는 title에 둡니다.
- **행 버튼(상태별)**

| 상태 | 버튼 |
|---|---|
| 요청됨 | [제외] |
| 수집 중 | [실패로 표시] |
| 실패 | 설정 있을 때 [다시 실행], 없으면 없음. 사유나 자동 실패 코드 문구는 상태 칸 `.cr-sub`에 |
| 반영됨·취소됨·제외됨 | 없음 |

- [실패로 표시]의 확인 줄 문구: "서울 도봉구청 수집을 실패로 표시합니다. 요청자 n명에게 쪽지와 사유가 갑니다." / 실행 버튼 [실패로 표시하기].
- **정렬(제안)**: 처리 대기는 첫 요청일이 오래된 순, 끝난 요청은 닫힌 날짜가 최근인 순입니다(기획-3).

**[수집 중으로 표시]** — 되돌리기 어렵지 않고, 바깥으로 나가지도 않으므로 확인 상자를 두지 않습니다.
- 결과: "n곳을 '수집 중'으로 표시했습니다. 자료가 들어오면 자동으로 '반영됨'이 되고 요청자에게 쪽지가 갑니다."

**[목록 내려받기] 뒤 이어 할 일** — 자동으로 상태를 바꾸지 않습니다. 파일이 실제로 망 밖으로 넘어갔는지 시스템은 모릅니다.
- `#ad-flash`: "n곳 목록을 내려받았습니다. 수집 PC로 옮긴 뒤 [선택한 n곳 수집 중으로 표시]를 누르세요." 선택은 그대로 유지합니다.
- **CSV 열(제안)**: `institution_id, 기관명, 이전_출처_도메인, 요청_키, 첫_요청일`. 요청자 이름·사번·사유는 넣지 않습니다.

**[수집 실행]** (설정 있을 때만. 바깥으로 나가는 행동이라 확인 상자 필수)
- 툴바 아래에 `.hc-confirmbox`를 펼칩니다.
  - 문구: "선택한 n곳의 기관 ID·기관 이름·이전 출처 도메인을 망 밖 수집 서버로 보냅니다. 요청자 이름·사번은 보내지 않습니다. 보낸 뒤에는 취소할 수 없습니다."
  - 버튼: [수집 실행] [취소]
- 진행 중에는 버튼을 "실행 중…"으로 바꾸고 disabled로 둡니다.
- 결과: "n곳 중 a곳을 보냈습니다(수집 중). b곳은 실패했습니다 — 연결 안 됨." 실패 사유는 5절 코드 표의 문구에서만 고릅니다. 서버 원문은 보여 주지 않습니다.

**상태 화면**

### 6-6. design_history 전/후 장 문안 (확인 결과: 이번 변경의 전/후 장 필요)
- **전**: 자료 없는 기관을 열면 점선 '자료 없음' 칩과 "폐쇄망 밖에서 수집한 파일을 시스템 관리자가 올리면 이 자리에 보입니다"라는 문장만 보입니다. 할 수 있는 행동이 없고, 원하는 사람은 화면 바닥 CSV를 내려받아 따로 전달해야 했습니다. 현황판 요약에는 사실과 다른 "입찰이 가까운 기관부터 모읍니다"가 보였습니다.
- **후**: 기관 이름 바로 아래에 [수집 요청] 버튼과 한 줄 설명이 있습니다(기본 버튼, 채우지 않음). 누르면 주황 칩 "요청됨"과 "나 포함 n명"이 보입니다. 개발부서는 시스템 관리 > 사업계획 수집 요청에서 기관 단위 목록을 보고, 내려받고, 수집 중으로 표시합니다. 메뉴에는 대기 기관 수 잉크 배지가 붙습니다.
- **대비 숫자(계산값)**: 실패 칩 글자 4.3 → 5.9:1, 반영됨 칩 글자 4.1:1 → 72% 흰색 섞기로 보정.
- **왜**: 빈 자리를 행동으로 바꾸고, 같은 기관 요청을 한 줄로 묶어 중복 수집을 막기 위해서입니다.
