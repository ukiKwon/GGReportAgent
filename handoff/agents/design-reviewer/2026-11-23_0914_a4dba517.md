## 4. 우선순위 이슈
- **P1. 개발부서 팀원에게 [목록 내려받기(CSV)]가 눌리는 단추로 보인다.** 근거: `plancollect.js:133·160`. `can_export`를 보지 않고, 강조 테두리(`pp-next-btn`)까지 붙어 있다. 누르면 403이 나는데, 그때 문구는 `errorText` 403 = '이 화면은 시스템 관리 권한이 있는 개발부서만 씁니다(403)'이다. 팀원은 이미 이 화면을 쓰고 있으니 원인을 틀리게 알려 준다. 수정 규격은 6-3.
- **P2. 화면 머리 안내가 낡게 된다.** 근거: `admin.js:103` "목록을 내려받아 수집하고, 보낸 기관은 '수집 중'으로 표시하세요." 팀원은 내려받지 못하고, 반입 단계 안내가 빠져 있다. 새 문구는 5절.
- **P2. 확인 창의 단추 자리가 DESIGN.md에 정해져 있지 않다(계약 빈칸).** 팝업 4판은 '보는 창 / 기능 있는 보는 창 / 쓰는 창'만 정한다. 입력칸 없이 동작만 확인하는 창은 없다. 선례 `plans.batchDialogHtml`(69장)은 [취소][n곳 요청]을 **오른쪽 아래 `.dlg-foot`**에 둔다. 이번 창도 이 선례를 따른다. DESIGN.md 팝업 항목에 "확인 창(입력 없음) = `.dlg-foot` 오른쪽 아래 [취소][주 동작], role=alertdialog" 한 줄을 더할 것을 권한다. 규칙급 문서이므로 메인이 판단한다.
- **P3. 같은 화면에 확인 방식이 둘이 된다.** [수집 실행]은 `hc-confirmbox` 인라인 상자(`runAskHtml` 165)를 쓰고, 반입은 `.dlg`를 쓰게 된다. 이번 범위 밖이므로 기록만 해 둔다. 수집 실행은 시험용이라 낮게 둔다.
- **P3. 계약과 에이전트 정의가 어긋난다.** 디자이너 역할 정의에는 "틸 단일 악센트"라고 적혀 있는데 DESIGN.md의 포인트색은 파랑(`--accent-color` #0b50d0)이다. 이 규격은 DESIGN.md를 따랐다.

### 5-4. 안내·결과 문구 (`say` 띠 또는 절 안 `.ad-note`)
- 확인 전(띠 안 `.ad-note`): `반입 폴더에 들어온 사업계획 파일을 확인합니다.`
- 확인 중(단추): `확인하는 중…` / 띠 안: `파일이 많으면 20초까지 걸립니다.`
- 확인 끝(say): `파일 {n}개를 확인했습니다 — 반입 가능 {k}개.` (k=0이면 `— 반입할 파일이 없습니다.`)
- 빈 폴더: `반입 폴더에 사업계획 파일이 없습니다. 수집한 파일(기관ID_YYYYMMDD_plan.csv)이 폴더에 들어오면 여기에 보입니다.`
- ignored_count>0: `이름 형식이 맞지 않는 파일 {n}개는 건너뛰었습니다(이름: 기관ID_YYYYMMDD_plan.csv).`
- truncated: `파일이 많아 최근 날짜부터 일부만 확인했습니다. 반입한 뒤 [폴더 확인]을 다시 누르세요.` (숫자 100이 응답에 없으므로 숫자를 쓰지 않는다)
- 409 BUSY: `다른 폴더 확인이나 반입이 진행 중입니다. 잠시 뒤 다시 누르세요.` — '다른 사람'이라고 쓰지 않는다. RPA가 돌고 있을 때도 맞는 문장이다.
- 503 PLAN_INBOX_OFF: 절 전체를 그리지 않는다(안내 없음, [수집 실행] 선례 P2-2와 같다). 확인 중에 이 코드를 받으면 절을 지우고 say: `반입 폴더가 설정되지 않아 폴더 확인을 닫았습니다.`
- 503 PLAN_INBOX_BAD_CONFIG(서버에 있는데 지시에 빠진 코드): 절 안 `.ad-note`를 빨간색 대신 `role=alert`로: `반입 폴더를 열 수 없습니다(503). 서버의 반입 폴더 설정과 폴더 권한을 확인하세요.`
- 400 BAD_FILES: `고른 파일을 확인하세요(400). [폴더 확인]을 다시 누른 뒤 고르세요.`
- 반입 결과(say)
  - 모두 성공: `파일 {a}개를 반입했습니다. 수집 요청 목록을 다시 불러왔습니다.`
  - 섞임: `{n}개 중 {a}개를 반입했습니다. 이미 반입됨 {b}개 · 반입 못 함 {c}개 — 표의 결과를 확인하세요.`
  - 모두 실패(bad): `반입하지 못했습니다 — 표의 결과를 확인하세요.`
  - 500 또는 연결 끊김: `반입 중 멈췄습니다. 앞에서 반입한 파일은 들어갔을 수 있습니다. [폴더 확인]으로 다시 확인하세요.` (서버 주석: 앞 파일은 커밋을 유지한다)
- 상한: `한 번에 {max_import}개까지 반입할 수 있습니다. 선택을 줄이세요.` / 전체 선택 때: `반입 가능 {k}개 중 앞 {max}개를 골랐습니다(한 번에 {max}개까지).` (선례 plans '앞 n곳만')
- 단위: 파일 = **개**, 기관 = **곳**, 사업 = **건** (`plans.js:238` '사업계획 n건'과 같다)
- 화면에 쓰지 않는 말: inbox, IMPORT, batch_id, RPA, '반출'(→ '내려받기').

### 5-5. 접근성
- 절: `<section aria-labelledby="ib-t">`, 제목 `<h3 id="ib-t">` 14/700. 요청 목록 위에는 `<h3>기관별 수집 요청</h3>`을 더해 제목으로 이동할 수 있게 한다.
- [폴더 확인]: 확인하는 동안 `disabled`, 표 영역에 `aria-busy="true"`. 끝나면 커서는 단추에 그대로 두고 결과는 say로 읽힌다.
- 체크: READY 행만 `<input type=checkbox name="ib-sel" aria-label="{기관 이름} {파일 날짜} 파일 선택">`. 같은 기관의 여러 날짜 파일이 구분되도록 날짜를 넣는다. 다른 상태의 행은 `.cr-ck` 칸을 비운다(기존 닫힌 행과 같다). 전체 선택 `aria-label="반입 가능 파일 모두 선택"`. 클릭 영역 24×24 이상(`.cr-ck label` 재사용).
- 스크롤 영역: `.pl-dlg-scroll` 패턴을 따른다(`tabindex=0 role=region aria-label="반입 대기 파일 목록"`, 포커스 링 2px 포인트).
- 확인 창: `role=alertdialog aria-modal aria-labelledby aria-describedby`. 첫 커서는 제목(`.dlg-t[tabindex=-1]`, dlg.open 기본). 취소·Esc·바깥 클릭은 `requestClose`. 닫으면 [n개 반입]으로 돌아간다(dlg.close의 opener 복귀). 반입 중에는 [반입] `disabled` + `반입하는 중…`.
- 반입 뒤 커서: 창을 닫고 파일 표(`#ib-table tabindex=-1`)로 보낸다. 결과는 say로 읽힌다.
- 색에만 의존하지 않는다: 모든 칩에 글자가 있다. NOT_CHECKED는 점선, 오류는 빨강 + '오류/못 함' 글자로 구분된다.
- 대비(토큰 계산, 실측 아님): `.cr-sub`·`.db-why` `--muted` #464c53/흰 ≈ 8.7:1. 칩은 기존 `.cr-st` 72% 섞기와 `.pp-cancel`을 그대로 써서 새 대비가 생기지 않는다. `aria-disabled` 단추의 흐린 글자(약 3.7:1)는 비활성 예외이고, 이유는 옆 글자(8.7:1)로 전한다.

- 보기 전환 라디오(처리 대기/끝난 요청/모두)는 요청 목록에만 걸린다. 그래서 반입 절은 그 띠보다 **위, 따로** 둔다.
- 화면을 열 때 폴더를 자동으로 확인하지 않는다. 확인은 파일 100개를 20초까지 읽고, 잠금을 잡고, 감사 기록이 남는 서버 동작이다.
- 기관 칸: 첫 줄 `name_ko`(없으면 `institution_id`), 둘째 줄 `file_name`(mono 12 muted, `.cr-sub`). 파일 이름이 있어야 폴더에서 해당 파일을 찾아 고칠 수 있다.
- 문서·사업: `{doc_count} · {item_count}` mono. READY·IMPORTED만 값이 있고, 나머지는 `—`.
- 경고: `warning_count`가 0이면 `<span class="ad-note">없음</span>`(이전 출처 칸 선례), 1 이상이면 mono 숫자. 색은 칠하지 않는다.
- (선택, P3) 열린 요청이 있는 기관이면 기관 칸 셋째 줄에 `수집 요청 {요청자 n}명`. `S.items`(open)를 `institution_id`로 대조하고, 보기가 '끝난 요청'이면 생략한다.
- 반입 뒤: 같은 행의 상태 칸을 결과 칩(5-3)으로 바꾸고 체크를 없앤다. 단추는 `[폴더 다시 확인]`. 요청 목록은 `load()`로 다시 불러온다.

### 6-3. P2-1 목록 내려받기(CSV) — 팀원에게는 비활성 + 이유
권장은 **숨기지 않고 `aria-disabled` + 이유 글자**다(선례 `plans.batHtml:435–436` `#pl-bat`). 이유: 팀원도 팀장이 내려받은 뒤 [수집 중으로 표시]를 누르는 흐름 안에 있다(`csvFlash`). 단추를 숨기면 '내려받기는 어디서 하나'를 물을 데가 없어진다.
- `can_export === false`일 때:
  - `<button id="cr-csv" aria-disabled="true" aria-describedby="cr-csv-why">선택한 {n}곳 목록 내려받기(CSV)</button> <span class="db-why" id="cr-csv-why">목록 내려받기는 개발부서 팀장만 할 수 있습니다.</span>`
  - `pp-next-btn`(포인트 테두리)을 **빼서** 눌리는 단추처럼 보이지 않게 한다. 대신 [수집 중으로 표시]에 붙이지도 않는다.
  - 클릭은 무시한다(선택 여부와 상관없음). `disabled` 대신 `aria-disabled`를 쓰므로 Tab으로 가서 이유가 읽힌다.
  - CSS: `#cr-csv[aria-disabled="true"] { opacity:.55; cursor:not-allowed; }` (`#pl-bat` 선례)
- 403 `detail.code=LEAD_ONLY` 문구: **`목록 내려받기는 개발부서 팀장만 할 수 있습니다. 팀장에게 요청하세요.`** 단추 이름이 '내려받기'이므로 '반출'(내부·보안 용어)보다 같은 말이 낫다. 이 문구가 '이 화면은 … 개발부서만 씁니다(403)'보다 먼저 판정되어야 한다(`errorText`에 code 분기). 응답을 받으면 `can_export=false`로 바꿔 단추를 6-3 모양으로 다시 그린다.

### 6-5. design_history 전/후 장 필요 (구현 뒤 메인이 추가)
- **전**: 수집 요청 화면에는 요청 목록만 있었다. 반입은 서버 명령(curl)으로 해서 화면에서는 보이지 않았다. [목록 내려받기(CSV)]는 모든 개발부서원에게 눌리는 단추(포인트 테두리)였고, 누르면 '이 화면은 개발부서만 씁니다(403)'라는 엉뚱한 문구가 나왔다.
- **후**: 목록 위에 '반입 대기 파일' 띠가 있다(접힘 1줄 → [폴더 확인] 뒤 파일 표, 최대 320px). 상태 칩은 반입 가능(주황)·이미 반입됨(회색 실선)·내용 오류 등(빨강)·확인 못 함(점선)이다. 반입 가능만 고를 수 있고, [선택한 n개 반입] → 확인 창 [취소][n개 반입] → 결과 칩 + 띠 문구, 목록은 '반영됨'으로 바뀐다. 팀원에게 CSV는 흐린 단추 + '목록 내려받기는 개발부서 팀장만 할 수 있습니다.'
- **숫자**: 새 색·새 변수 0. 보조 글자 8.7:1(계산). 체크 클릭 영역 24×24 이상. 한 번에 50개.
- **왜**: 담당자가 화면에서 반입하고, 나중에 RPA가 반입해도 같은 화면으로 결과를 감시할 수 있게. 팀원이 권한 없는 동작을 눌러 엉뚱한 오류를 보지 않게.
- 캡처: 이번에는 Playwright를 쓸 수 없었다. 구현 뒤 8080에서 전/후 캡처를 더한다.

- [이관: 개발] INVALID `message`에 파일 셀 값(`(…)`)이 섞이는지 — 디자인은 80자 자르기와 esc만 가정했다 — 근거 `InstitutionCsv.java:114`가 값을 되돌려 줌. 사업계획 CSV 쪽은 확인하지 않았다.
- [이관: 개발] 폴더 반입(`/plan-collect/inbox/import`)도 업로드 반입과 똑같이 열린 요청을 '반영됨'으로 바꾸고 쪽지를 보내는지 — 확인 창 둘째 문장이 이 답을 기다린다 — 근거 NEXT 56 11-17 "새 IMPORT 반입 시 자동 '반영됨'". 경로(origin)별 차이는 확인하지 못했다.
- [이관: 개발] scan 응답에 `max_list`(100)가 없다 — 지금은 truncated 문구에 숫자를 쓰지 않는다. 숫자를 넣고 싶으면 필드가 필요하다. 503 `PLAN_INBOX_BAD_CONFIG` 분기도 화면에 넣어야 한다(지시서에 빠짐).
- [이관: 개발] `errorText` 403 분기는 `detail.code=LEAD_ONLY`를 먼저 판정해야 한다.
- [이관: 기획] RPA가 자동 반입할 때도 이 절을 계속 둘지, 감시용으로 [반입] 단추를 숨길지 — 지금 규격은 문구를 바꾸지 않아도 되는 형태로 짰다 — 근거 사용자 11-20 '최종은 RPA'.
