# 기관 사업계획 '결과 확인 기관' 분리 — 화면 규격

## 1. 대상·방법·못 본 것
- **방법**: 소스를 읽었습니다. 읽은 곳은 `frontend/js/plans.js` 전체, `dashboard.js`(isCheck 379, noticeBandHtml 398–424, renderList 833–865, footHtml 604, moreHintHtml 128, OV_TAB_GUIDE 664), `logic.js` noticeText 291–309, `kbboard.js` 143–149, `index.html`의 `.db-*`·`.pl-*` CSS, 승인된 계획 파일, `docs/design_history` 목차입니다.
- **못 본 것**: Playwright가 연결되지 않아(CONNECT_TIMEOUT) 렌더된 높이·대비·줄바꿈은 재지 못했습니다. 아래 줄 수는 추정치입니다. DESIGN.md는 관련 규칙만 찾아 읽었습니다.

## 2. 한 줄 총평
목록에서 빼고 #pl-foot 맨 위에 한 줄을 두는 방향이 맞습니다. 문구는 입찰 공고 현황의 '결과 확인' 어휘에 맞추고 '미확인'은 쓰지 않습니다.
- **가장 큰 기회**: 지금 `renderFoot`은 서버 현황이 없으면(`!ready()`) 바닥 전체를 비웁니다. 이 안내는 서버 없이 로컬 데이터(M)로 계산되므로 **연결이 안 된 상태에서도 보여야** 합니다.

## 3. 점수표
이번 일은 규격 작업이라 휴리스틱 채점은 하지 않았습니다.

**잘 된 점**
- 판정 정본(`isCheck`)이 하나라서 현황판 띠·지도·이 화면이 같은 기준을 씁니다.
- pin 경로가 이미 있어서, 목록에서 뺀 기관도 바로 열 수 있습니다.

## 4. 우선순위 이슈
- **P1 — 결과 확인 기관이 '입찰 임박' 목록에 섞여 있습니다.**
  - 근거: `plans.listRows`가 `M.notice` 전체를 붙입니다(plans.js 266–273).
  - 왜 문제인가: 기간을 3개월이나 6개월로 골라도 성북·용산·관악(공고 후 81·89·95일)이 남습니다. 기간 선택을 믿을 수 없게 됩니다.
  - 수정 방향: 팀이 결정한 대로 뺍니다.
- **P2 — 안내를 뒀을 때 목록 칸이 좁아질 수 있습니다.**
  - 근거: 왼쪽 칸은 380px이고 바닥 안쪽 폭은 약 340px입니다. 12px 한글은 한 줄에 약 28자라서, 안내 약 3줄과 기존 CSV 안내 2–3줄을 더하면 바닥이 약 140–150px이 됩니다.
  - 왜 문제인가: 목록 높이는 `clamp(440px, 100vh-190px, 820px)`입니다. 1280×720 화면이면 스크롤 칸에 행이 2–3개만 보일 수 있습니다.
  - 수정 방향: 아래 문구를 짧게 확정했습니다. 적용한 뒤 qa가 1280×720에서 스크롤 칸 높이를 재고, 200px 아래이면 CSV 둘째 문장 '폐쇄망 밖에서…'를 버튼의 `title`이 아니라 `aria-describedby`가 가리키는 숨김 글로 옮길지 다시 판단합니다.
- **P2 — 고정(pin)된 행이 목록 밖에서 온 기관이라는 표시가 없습니다.**
  - 근거: `visibleRows`는 pin 행을 맨 위에 그냥 붙입니다(plans.js 460–463).
  - 왜 문제인가: '뺐다'는 안내 바로 위 목록에 같은 종류의 기관이 보이면 모순처럼 읽힙니다.
  - 수정 방향: 6절 규격대로 표시를 붙입니다.
- **P3 — 주석이 실제와 다릅니다.**
  - 근거: `plans.menuVisible`의 주석은 'app.js 의 findNavItem 은 밖으로 나와 있지 않아'라고 하는데, 실제로는 `app.findNavItem`이 내보내져 있습니다(app.js 642).
  - 수정 방향: 새 버튼의 메뉴 판정에는 `app.findNavItem(nav.NOTICE_ID)`를 씁니다(overdue.js 283과 같은 방식).
- **P3 — 남아 있는 '미확인' 글자.** 목록에 남는 '공고 후 30일 이내' 행의 둘째 줄에는 여전히 '마감일 미확인 · 접수 기간은 공고 원문에서 확인하세요'가 나옵니다. 칩이 아니라 글자이고, 문구의 정본(`logic.noticeText`)을 현황판·지도가 함께 쓰므로 이번 범위에서는 고치지 않습니다(이관 메모 참고).

## 5. 문구 / 접근성

### 문구 (확정안)
- **본문**: `공고 결과를 확인할 기관 N곳은 목록에서 뺐습니다. 마감이 지났거나, 마감일 기록 없이 공고 후 30일이 지난 곳입니다.`
- **버튼**: `입찰 공고 현황에서 보기` — kbboard·overdue 팝업과 같은 글자입니다.
- **초안과 비교해 고친 이유**:
  - '마감일을 모름'을 '마감일 기록 없이'로 바꿨습니다. 우리 자료에 없다는 사실만 말하고, '모름·미확인' 같은 칩 어휘를 피합니다.
  - '결과 확인이 필요한'을 '공고 결과를 확인할'로 바꿨습니다. 도착 화면의 [결과 확인 N곳 보기], 지도 배지 '결과 확인'과 어휘가 이어집니다.
  - '입찰 임박에서'를 '목록에서'로 줄였습니다. 바로 위 제목이 '입찰 임박 기관'이라 반복할 필요가 없습니다.
  - 괄호를 문장으로 풀었습니다.
- **30이라는 숫자**: 글자로 박지 말고 `logic.NOTICE_UNKNOWN_OPEN_DAYS`에서 가져옵니다.
- **메뉴가 안 보이는 사람**: 두 문장만 보이고 버튼은 없습니다.
- **열기 실패(탭이 가득 찬 경우 등)**: #pl-flash에 `입찰 공고 현황을 열 수 없습니다. 왼쪽 메뉴의 [입찰 공고 현황]에서 여세요.`를 띄웁니다. kbboard.js 366과 같은 글자입니다.
- **고정된 행 꼬리**: `직접 연 기관`.

### 접근성
- 버튼은 이미 있는 `#pl-foot .db-link` 규칙(padding 4px, min-height 24px)을 그대로 씁니다. 대상 크기 24px 기준을 충족합니다.
- 안내 줄은 aria-live로 두지 않습니다. 조건을 바꿀 때 읽히는 곳은 기존대로 #pl-g 하나입니다(중복 안내 방지).
- '직접 연 기관'은 option 안의 글자라서 화면 낭독기도 읽습니다. 색만으로 전달하지 않고 점선 구분선과 글자를 함께 씁니다.
- 대비: --muted(#98a1af)와 --fg 토큰만 씁니다. DESIGN.md의 '≥4.5:1' 기준을 그대로 따르며 실측은 하지 않았습니다.

## 6. 규격·시안

| 항목 | 결정 |
|---|---|
| 위치 | **#pl-foot 맨 위**. 바닥은 스크롤 칸 밖이라 늘 보입니다. 목록 끝에 두면 긴 목록에서 묻힙니다. 기간 버튼 아래에 두면 '기간을 바꾸면 수가 바뀐다'로 오해합니다. 이 수는 기간과 무관합니다(공고 항목은 기간 창과 상관없음). |
| 순서 | ① 결과 확인 안내 ② 기존 CSV 안내. 두 문단 사이에는 헤어라인을 둡니다. |
| 수 | **지역·기관명 검색은 적용**합니다. 목록 머리 수와 같은 기준이고, `dash.filterItems(M.notice, {q, region})` 가운데 `isNoticeCheck`인 것입니다. **기간·자료 상태(모두/있음/없음)는 적용하지 않습니다.** pin 중인 기관도 셉니다(정규 목록에서 빠진 것은 같기 때문). |
| 0곳 | 문단 전체를 숨깁니다(빈 문자열). 바닥 전체가 비면 기존 `.db-foot:empty`가 숨깁니다. |
| 서버 상태 | 안내는 `ready()`와 상관없이 그립니다. CSV 문단만 기존처럼 `ready()`일 때 그립니다. |
| 버튼 | `.db-link`, `id="pl-to-notice"`. 누르면 `app.openNavItem(nav.NOTICE_ID)`를 부르고, false가 오면 위 실패 문구를 띄웁니다. |
| 고정 행 | 결과 확인 기관뿐 아니라 경과·날짜 미상까지 **고정된 행 전부**에 `data-pin="1"`을 붙입니다. 결과 확인이면 현황판 관례대로 `data-check="1"`도 붙입니다(현황판에도 CSS는 없고 표식 속성만 있음). meta 끝에 ` · 직접 연 기관`을 붙이고, 그 행과 다음 행 사이를 점선으로 가릅니다. 칩은 늘리지 않습니다. |

```js
// plans.js — 순수(노드 시험 대상). n = 지역·검색을 적용한 결과 확인 기관 수, canOpen = 입찰 공고 현황 메뉴가 보이는가.
plans.checkNoteHtml = function (n, canOpen) {
  n = Number(n) || 0;
  if (!n) return '';
  const days = logic.NOTICE_UNKNOWN_OPEN_DAYS;
  return '<p class="pl-fn">공고 결과를 확인할 기관 ' + mono(n) + '곳은 목록에서 뺐습니다. ' +
    '마감이 지났거나, 마감일 기록 없이 공고 후 ' + esc(days) + '일이 지난 곳입니다.' +
    (canOpen ? ' <button type="button" class="db-link" id="pl-to-notice">입찰 공고 현황에서 보기</button>' : '') + '</p>';
};

// renderFoot — 안내는 서버 현황과 무관하게, CSV 문단만 ready() 일 때
function renderFoot() {
  const el = $('pl-foot');
  if (!el || !M) return;
  const d = D(), f = { q: S.q, region: S.region };
  const n = d.filterItems(M.notice || [], f).filter(d.isNoticeCheck).length;
  let h = plans.checkNoteHtml(n, noticeMenuVisible());
  if (ready()) {
    const base = visibleRows().base;
    const csv = plans.footHtml(plans.missingIds(base).length, base.filter(function (r) { return !r.st; }).length, S.dlBusy);
    if (csv) h += '<p class="pl-fn">' + csv + '</p>';
  }
  el.innerHTML = h;
}
// noticeMenuVisible: plans.noticeMenuCheck(시험용) → app.findNavItem(nav.NOTICE_ID). 사이드바가 없으면 true(menuVisible 과 같은 기본값).
// onClick: case 'pl-to-notice': if (!(root.app && root.app.openNavItem && root.app.openNavItem(root.nav.NOTICE_ID))) setFlash('입찰 공고 현황을 열 수 없습니다. 왼쪽 메뉴의 [입찰 공고 현황]에서 여세요.'); break;

// rowHtml — o.pinned 를 받는다(visibleRows 가 pin 으로 붙인 행에 pinned:true)
//   li 에: (o.pinned ? ' data-pin="1"' : '') + (it.notice && D().isNoticeCheck(it) ? ' data-check="1"' : '')
//   meta 끝에: (o.pinned ? ' · 직접 연 기관' : '')
```

### 전/후 장 필요 — ㊶ (계획의 '㉝'은 낡은 번호입니다. 지금 마지막 장은 c40입니다)
- **전**: '입찰 임박 기관' 목록 맨 위에 공고 진행 중 기관이 기간과 상관없이 모두 붙었습니다. 6개월을 골라도 성북(공고 후 81일)·용산(89일)·관악(95일)이 '마감일 미확인 · 결과가 났는지 확인하세요' 줄과 함께 보였습니다. 바닥에는 CSV 안내만 있었고, 서버 연결이 없으면 바닥 전체가 비었습니다.
- **후**: 그 기관들은 목록에서 빠집니다. 바닥 맨 위 12px 회색 글에 '공고 결과를 확인할 기관 **3**곳은 목록에서 뺐습니다. 마감이 지났거나, 마감일 기록 없이 공고 후 30일이 지난 곳입니다. [입찰 공고 현황에서 보기]'가 나옵니다. 숫자는 고정폭 글꼴이고 버튼은 밑줄 글자입니다. 현황판·지도에서 그 기관을 열면 맨 위에 '직접 연 기관' 꼬리와 점선 경계가 붙어 보입니다.
- **숫자**: 3곳은 사용자가 지적한 예시이고, 실제 수는 화면을 찍어서 채웁니다. 기간 버튼과 무관하고 지역·검색 조건에 따릅니다. 0곳이면 줄이 없습니다.
- **왜**: 기간을 골랐는데 기간 밖 기관이 보이면 목록을 믿을 수 없습니다. 재분류는 입찰 공고 현황이 맡으므로 그쪽으로 연결합니다.

## 7. 이관 메모
- **[이관: 개발]** 입찰 공고 현황 화면을 연 뒤 첫 결과 확인 행으로 스크롤·포커스하는 공개 함수가 필요한지 정해 주세요(예: `dash.showCheck()` — `db-nb-wait` 처리와 같은 동작). 디자인은 지금 그대로도 받아들일 수 있습니다(공고 묶음이 목록 맨 위). 근거: dashboard.js 1151에 내부 처리만 있습니다.

- **[이관: 기획]** `logic.noticeText`의 '마감일 미확인 · …' 문구를 '마감일 기록 없음' 계열로 바꿀지 정해 주세요. 현황판·지도·이 화면이 함께 쓰는 문구라 한 화면에서만 바꿀 수 없습니다. 사용자가 '미확인'을 싫어한다는 의견이 근거입니다.
