## 2. 한 줄 총평
생년월일은 **카드에는 내지 않고 편집 팝업 안에만** 둔다. 가장 큰 기회는 팝업 목록에서 값 옆에 '만 n세'를 붙이는 것이다. 그러면 1965를 1995로 잘못 적는 오타를 확정하기 전에 눈으로 잡을 수 있다.

## 3. 결정과 근거

### D-1. 카드 본문: 보이지 않음. '만 n세'는 편집 팝업의 행에만 붙인다
**근거**
1. 카드는 기관을 고르기만 해도 그려진다. 화면을 공유하거나 옆 사람이 보는 순간 노출된다. 팝업은 [기관장 편집]을 누른 사람에게만 열린다.
2. 서버의 빈 머리 판정, 목록 집계, Word가 모두 '카드에 안 보임'을 전제로 짜여 있다(Mapper.xml 154·303, HeadDocBuilder 48, headcard.js 52). 카드에 내면 이 전제를 세 곳에서 다시 열어야 한다.
3. 카드의 날짜 3칸(.hc-facts)은 모두 '임기' 정보다. 나이가 끼면 이 묶음의 뜻이 흐려진다.

**표시 형식**: `1965-03-02 (만 61세)`
- 날짜는 `<span class="v">`(기존 mono)로 그린다.
- '(만 n세)'는 일반 글자로 붙인다.
- 들어가는 곳은 세 군데다. 후보 행, 확정 항목 행, 후보 기관장 요약 줄.

**계산 기준**: 서울 오늘(ctx.today)로 계산한다. 함수는 `hc.ageOn(ymd, todayYmd)`로 둔다.
- 기본은 `만 = 오늘연 - 생년`이다.
- (오늘월, 오늘일)이 (생월, 생일)보다 앞서면 1을 뺀다.
- 형식이 틀리거나 값이 없으면 null을 돌려준다. 이때 '(만 n세)'는 빼고 날짜만 보인다.
- 2월 29일생은 평년 2월 28일에는 아직 생일 전이고, 3월 1일에 한 살 오른다. 위 비교가 자연히 이렇게 동작한다.

**`hc.valueText`**: today 인자를 받게 고친다. BIRTH_DATE 분기를 더한다.

**기획에 넘길 것**: 영업이 카드에서 바로 나이를 봐야 하는 업무가 있다면 기획 결정이 필요하다(8절 질문). 그때도 '만 n세'만 이름·직위 줄에 둔다(생년월일 전체는 넣지 않는다).

### E. 꼬리의 출처 건수·최근 확인: 생년월일을 빼야 한다. 서버 변경이 필요하다
- 카드에 안 보이는 칸이 '출처를 단 항목 N건'에 들어가면, 사용자는 카드에서 N건을 셀 수 없다.
- '최근 확인' 날짜가 생년월일을 확인한 날이 되는 경우도 생긴다.
- 화면에서 빼기로 메우면 안 된다. source_count는 1을 빼면 되지만, last_checked_on은 다시 계산할 수 없다.
- **[서버 변경 필요]** `InstitutionHeadService` A3 루프(564-574)에서 `BIRTH_DATE`이면 `sourceCount++`와 lastChecked 갱신을 건너뛴다.
  - 목록 A1(386-401)은 이미 BIRTH_DATE를 빼고 집계한다(Mapper 154 주석). 고칠 필요가 없다.
- 관찰(범위 밖): 권한대행 '아니오'도 카드에 안 보이는데 건수에는 들어간다. 7절에 이관 메모로 적었다.

## 4. 규격: frontend-dev용

### 4-1. hc.FIELDS: 맨 끝(경력 뒤)에 더한다
```js
{ cd: 'BIRTH_DATE', label: '생년월일', kind: 'birth' },
```
- 서버 SORT_NO 9와 맞춘다. '항목 종류' 선택지에서 맨 아래에 와서, 부가 정보라는 점이 순서로 드러난다.
- confirmedItems는 FIELDS 순서대로 돌므로, 확정 행에서는 임기 만료일 다음, 학력·경력 앞에 온다.
- `hc.fieldLabel('BIRTH_DATE')`가 '생년월일'을 돌려준다. 그래서 후보 행(682), 후보 기관장 요약(707), 확정 행(717), 버튼 aria-label('생년월일 후보 확정' 등)이 한 번에 바뀐다. 이것으로 5번이 해결된다.
- `valueRowHtml(fieldCd, today)`처럼 today를 받게 고친다. 부르는 곳은 784와 992 두 군데다.
  - 992 onMChange는 `envNow().today` 또는 M에 보관한 today를 쓴다.

### 4-2. 생년월일 입력 칸 ('항목 후보 추가' 양식, kind:'birth')
위치는 #hc-valrow 안이다. 항목 종류에서 '생년월일'을 골랐을 때만 나타난다. 기관장 추가 양식(headFormHtml)에는 넣지 않는다(4-5).
```html
<div class="hc-fld wide">
  <label class="hc-lab">생년월일
    <input type="date" name="date" id="hc-birth" required min="1920-01-01" max="{MAX}"
           aria-describedby="hc-birth-h"></label>
  <p class="hc-fhint" id="hc-birth-h">1920-01-01부터 {MAX}(만 18세)까지 고를 수 있습니다. 기관장 편집 화면에서만 보이며 카드·목록·엑셀·워드 파일에는 들어가지 않습니다. 열 때마다 열람 기록이 남습니다.</p>
  <!-- 오류일 때만 -->
  <p class="hc-ferr" id="hc-birth-e" role="alert">{오류 문구}</p>
</div>
```
- **{MAX}** = 서울 오늘에서 18년을 뺀 날이다. 서버 `LocalDate.minusYears(18)`과 같아야 한다. 오늘이 2/29이면 (Y-18)-02-28이다. esc로만 그린다.
- **오류일 때 input 속성**
  - `aria-invalid="true"`를 단다.
  - `aria-describedby="hc-birth-e hc-birth-h"`로 둔다. 오류를 앞에 두고, 기존 값에 **합친다**(덮어쓰지 않는다).
  - 값을 바꾸면(input 이벤트) 오류 문단을 지우고, aria-invalid를 빼고, describedby를 `hc-birth-h`로 되돌린다.
- **오류 문구**: 제출 전에 화면에서 검사하고, 실패하면 이 칸에 포커스를 둔다.

| 경우 | 문구 |
|---|---|
| 비어 있음 | 생년월일을 고르세요. |
| 형식 아님 | 날짜를 YYYY-MM-DD 형식으로 고르세요. |
| 1920-01-01 이전 또는 {MAX} 이후 | 1920-01-01부터 {MAX}까지의 날짜를 고르세요. |
| 서버 400 INVALID_DATE (field_cd=BIRTH_DATE일 때) | 서버 메시지를 **이 칸 아래** 그대로 보인다(상단 #hc-m-status에는 띄우지 않음). |

- 서버 메시지에는 입력값이 없다(HeadText 105). 화면 문구에도 입력값을 싣지 않는다.
- **새 CSS**: 새 hex는 없고, 시안의 .dlg-f/.dlg-ferr와 같은 모양이다.
```css
.hc-fld { display:flex; flex-direction:column; gap:4px; min-width:0; }
.hc-fhint { margin:0; font-size:12px; line-height:1.5; color:var(--muted); word-break:keep-all; }
.hc-ferr { margin:0; font-size:12px; line-height:1.5; color:var(--red); word-break:keep-all; }
.hc-lab input[aria-invalid="true"] { box-shadow:inset 0 0 0 1px var(--red); }  /* 기존 2338에 더함 — 시안 59와 같게 */
```
- 0d의 .dlg로 옮길 때는 `.hc-fld`를 `.dlg-f`로, `.hc-ferr`를 `.dlg-ferr`로 1:1 바꾸면 된다. 구조가 label, input, p 순서라 같다.

### 4-3. 출처 이름 칸 옆 안내 (4번)
`sourceFieldsHtml(today, pre)`로 접두어를 받게 고친다. 이 함수는 한 팝업 안에서 최대 3번 그려지므로(항목·사진·교체 양식) id가 겹치면 안 된다. 접두어는 'it', 'ph', 'hf'로 한다.
```html
<div class="hc-fld">
  <label class="hc-lab">출처 이름(100자 이내)
    <input type="text" name="src_title" maxlength="100" required autocomplete="off"
           placeholder="예: 가람시 누리집 시장 소개" aria-describedby="{pre}-st-h"></label>
  <p class="hc-fhint" id="{pre}-st-h">자료 이름만 적습니다. 생년월일·나이(예: 1965년생)는 적지 마세요.</p>
</div>
```
- 항목 종류와 관계없이 늘 보인다. 서버가 모든 출처 제목을 막기 때문이다.
- 서버가 이 칸을 막으면 메시지를 **이 칸 아래** `.hc-ferr#{pre}-st-e`로 보인다. aria-invalid와 describedby는 4-2와 같은 방식으로 합친다.
  - 그러려면 서버 오류가 '출처 제목' 칸을 가리켜야 한다(7절 개발).
  - 코드가 정해지기 전까지는 기존처럼 상단 상태줄에 메시지를 그대로 둔다.

### 4-4. 확정 대기 후보 행의 라벨 (5번)
4-1로 해결된다. 시험할 때는 '생년월일'이라는 글자, aria-label '생년월일 후보 확정', 값 '1965-03-02 (만 61세)'를 확인한다. 'BIRTH_DATE' 글자가 화면, aria, title 어디에도 없어야 한다.

### 4-5. [A1-①] '기관장 추가' 화면의 이월 안내
- **조건**: `hc.isEmptyHead(d)`가 참이고, `h`가 있고, `h.fields.BIRTH_DATE` 또는 `h.fields.ACTING`이 있을 때만 띄운다. head:null(처음 추가)일 때는 보이지 않는다.
- **위치**: #hc-s4 절에서 기존 `p.hc-hint#hc-s4-hint` 바로 아래, 양식 위에 둔다.
```html
<p class="hc-hint" id="hc-s4-carry">이전 기록의 {항목}은 새 기관장으로 넘어오지 않습니다. 같은 분이면 {행동}</p>
```
- **{항목}과 {행동}**: 실제로 있던 칸만 넣는다. 화면에 없는 칸을 언급하지 않는다.

| 이전 기록에 있던 칸 | {항목} | {행동} |
|---|---|---|
| 둘 다 | 생년월일·권한대행 여부 | 권한대행 여부는 아래에서 다시 고르고, 생년월일은 추가한 뒤 [항목 후보 추가]에서 다시 입력하세요. |
| 생년월일만 | 생년월일 | 추가한 뒤 [항목 후보 추가]에서 다시 입력하세요. |
| 권한대행만 | 권한대행 여부 | 아래에서 다시 고르세요. |

- 초안의 '다시 입력하세요'를 위처럼 나눈 이유가 있다. 추가 양식에 권한대행 칸은 있지만 생년월일 칸은 없어서, 두 칸을 다시 넣는 경로가 서로 다르다.
- 이전 값(날짜·예/아니오)은 이 안내에 **싣지 않는다**. 빈 머리를 보는 사람에게 생년월일을 다시 노출하지 않기 위해서다.
- 이름 칸의 describedby는 `hc-s4-hint hc-s4-carry`로 합친다(headFormHtml의 descId에 공백으로 이어 넘긴다).

### 4-6. [A1-②] 이름 오타는 '덮어쓰기'로 유도
- **위치**: 확정 항목 행에서 **이름 또는 직위의 [무효 처리]를 눌렀을 때 열리는 확인 상자(pendingHtml)** 안에 둔다.
  - 무효로 가려는 바로 그 순간이 결정하는 순간이다.
  - 팝업 머리나 양식 위에 상시로 두면 매번 읽히지 않는 글이 된다.
- **확인 상자 본문**: void-item이고 field_cd가 NAME 또는 POSITION일 때 기존 text를 이것으로 바꾼다.
  > 이 확정값을 무효 처리합니다. 오타를 고치려면 무효 처리하지 말고 아래 [항목 후보 추가]에서 '{이름|직위}'을 골라 고친 값을 넣으세요. 이름·직위를 모두 무효 처리하면 기관장이 비고, 생년월일·권한대행 여부는 새로 추가하는 기관장에게 넘어오지 않습니다.
- 버튼 순서는 그대로 둔다([무효 처리하기][취소]). 사유 칸도 그대로 둔다.
- **선택(P3)**: [취소] 오른쪽에 `<button type="button" data-m="fix-field" data-f="NAME">고친 값 넣기</button>`를 둘 수 있다.
  - 누르면 확인 상자를 닫고, #hc-field를 해당 칸으로 바꾸고, #hc-valrow를 다시 그린 뒤 값 칸에 포커스를 둔다.
  - 단추가 3개가 되므로 넣을지는 frontend-dev 판단에 맡긴다.
- **구현**: `ask-void-item` 버튼에 `data-f="{field_cd}"`를 더해 askPending이 칸을 알게 한다.
- **안내 문구에 대한 주의(서버 동작)**: '항목 후보 추가'에서 다른 이름을 넣으면 '확정값과 다름' 충돌 후보가 된다. 이것은 영업팀장·부장만 확정할 수 있다(BLOCK.LEAD_ONLY). 그래서 문구에 '바로 고쳐진다'는 약속을 넣지 않았다.

### 4-7. 바꾸지 않는 것
- 카드 마크업은 그대로 둔다(D-1).
- 팝업 껍데기(h3·닫기·폭·하단 단추)도 그대로 둔다.
- hc.EMPTY_IGNORE_FIELDS는 이미 BIRTH_DATE를 포함하고 있어 그대로 둔다.

## 5. 문구·접근성 요약
- **용어**: 라벨은 '생년월일'로 통일한다. 코드명(BIRTH_DATE)은 화면과 aria 어디에도 노출하지 않는다.
- **노출 범위 안내**: 사용자 결정(상세만, 목록·엑셀·Word 제외, 열람 기록)을 입력 칸 바로 아래에 한 번만 적는다.
- **오류 문구**: 원인과 행동을 함께 적고(어디부터 어디까지 고르라는 것), 입력값은 반복하지 않는다.
- **접근성**
  - 새 hint와 error는 모두 id를 가지고 input의 describedby에 **합쳐서** 연결한다.
  - 칸 오류는 role="alert"로 알린다.
  - 오류가 나면 포커스를 해당 input에 둔다.
  - 최소 글자 크기는 12px(.hc-fhint, .hc-ferr)이다. 색은 --muted #464c53과 --red #bd2c0f만 쓴다(기존 토큰).
- **대비**: 측정하지 못했다(Playwright 실패). 기존 .hc-hint와 .hc-err가 같은 토큰이라 추가 위험은 없다고 추정한다.

## 6. 시험 관점 (node --test + 화면)
1. `hc.ageOn`
   - 생일 전날, 당일, 다음날
   - 2/29생: 평년 2/28과 3/1, 윤년 2/29
   - 형식 오류이면 null
2. `{MAX}` 계산이 서버와 같은지: 오늘 2024-02-29 → 2006-02-28. 경계값 {MAX}는 통과, {MAX}+1일은 칸 오류.
3. 1919-12-31은 칸 오류, 1920-01-01은 통과.
4. 항목 종류에서 생년월일을 고르면 #hc-valrow에 #hc-birth와 #hc-birth-h가 생긴다. 다른 항목으로 바꾸면 사라진다.
5. 오류 상태
   - aria-invalid="true"이고 describedby가 정확히 "hc-birth-e hc-birth-h"다.
   - 값을 고치면 둘 다 원래대로 돌아간다.
   - 상단 #hc-m-status에는 같은 문구가 중복으로 뜨지 않는다.
6. 서버 400 INVALID_DATE가 BIRTH_DATE일 때는 칸 아래에, 다른 날짜 칸일 때는 기존처럼 상단에 뜬다.
7. 출처 이름 hint
   - 한 팝업 안에서 id(it-st-h, ph-st-h, hf-st-h)가 서로 겹치지 않는다.
   - 각 input의 describedby가 자기 hint를 가리킨다.
8. 후보, 확정, 후보 기관장 요약 행에 '생년월일', '(만 n세)', aria-label '생년월일 후보 확정'이 보이고, 'BIRTH_DATE' 문자열이 0건이다.
9. cardHtml 결과에 birth_date 값과 '생년월일' 글자가 0건이다(카드 미노출 회귀 방지).
10. 이월 안내(A1-①)
    - 빈 머리이고 fields에 BIRTH_DATE와 ACTING이 둘 다, 하나만, 아예 없을 때 문구가 셋 다 맞게 바뀐다.
    - head:null이면 안내가 없다.
    - 안내에 날짜 값이 없다.
11. NAME과 POSITION의 무효 확인 상자에만 덮어쓰기 문구가 뜬다. 다른 칸은 기존 문구 그대로다.
12. 값은 모두 esc를 거친다. `<`가 든 출처 제목으로 확인한다.
13. (서버 E 반영 뒤) 생년월일만 추가하면 꼬리의 N과 '최근 확인'이 그대로다.

## 7. 이관 메모
- **[이관: 개발]** A3의 source_count와 last_checked_on에서 BIRTH_DATE를 빼는 것(InstitutionHeadService 564-574). 디자인은 카드 꼬리 숫자가 보이는 칸과 맞기를 기다린다. 근거는 A1 목록은 이미 빼고 있고 A3만 세는 점이다.
- **[이관: 개발]** '1965년생' 같은 출처 제목을 막을 때의 400 코드나 필드 표지(예: `field:'src_title'`). 디자인은 칸 아래 오류(4-3)를 기다린다. 근거는 현재 grep 0건이고, errText는 메시지만 상단에 보인다는 점이다.
- **[이관: 개발]** HeadDocBuilder(Word)에 출처 건수나 최근 확인을 찍는 곳이 있는지, 거기서도 BIRTH_DATE를 세는지 확인. 근거는 48행에서 빈 판정만 뺀 것을 확인했고, 집계는 읽지 않았다는 점이다.
- **[이관: 개발]** 기관장 추가 API(add-head)가 birth_date를 받을 수 있는지. 받는다면 4-5의 생년월일 2단계를 1단계로 줄일 수 있다. 지금은 받지 않는다고 보고 규격을 짰다.
- **[이관: 기획]** 권한대행 '아니오'는 카드에 안 보이는데 꼬리 건수에는 들어간다. 같은 원칙(보이는 것만 센다)을 적용할지 정해야 한다. 디자인은 꼬리 문구의 정의를 기다린다.
- **[이관: 기획]** 이름 오타 수정이 충돌 후보로 가서 팀장·부장 확정이 필요한 흐름이 의도된 것인지 확인이 필요하다. 본인 오타도 위로 올라간다. 4-6 문구는 현재 흐름을 전제로 썼다.

**전/후 장 필요** (`docs/design_history/index.html`, 반영 커밋 때)
- **전**: 편집 팝업 '항목 종류'에 생년월일이 없다. 후보 행 라벨이 'BIRTH_DATE'로 보인다. 출처 이름 칸에 안내가 없다. 이름 무효 확인 상자는 '카드에서 사라지고 기록만 남습니다' 한 줄뿐이다.
- **후**: '생년월일' 선택지가 생기고, 날짜 칸, 범위·노출 범위 안내(12px --muted), 칸 아래 빨간 오류(12px --red, aria 연결)가 붙는다. 행에 '1965-03-02 (만 61세)'가 보인다. 출처 이름 아래에 '나이 적지 마세요' 안내가 생긴다. 이름 무효 상자에 덮어쓰기 유도 문구가 붙는다. 빈 머리 추가 화면에 이월 안내가 생긴다.
- **대비**: --muted #464c53과 --red #bd2c0f는 기존 토큰이다. 측정값은 반영 뒤 Playwright로 채운다.
- **왜**: 생년월일을 실제로 입력하고 무효 처리할 수 있게 하고, 코드명 노출을 없애고, 오타 때문에 기록을 잃는 일을 줄이기 위해서다.
