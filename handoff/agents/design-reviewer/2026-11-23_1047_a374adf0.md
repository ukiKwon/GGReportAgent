# 기관장 Word 프로필(NEXT 100 S1) 문서 레이아웃과 [워드 내려받기] 화면 규격

## 1. 대상·방법·못 본 것
- **방법**: 소스를 읽었다. `HeadDocBuilder.java`, `DocxKit.java`(여백·칸 여백·글머리 내어쓰기), `headcard.js`의 `hc.refHtml`·`TEXT`·`docxUrl`, `index.html`의 `.hc-ref*` CSS, `design_history` 65장을 봤다. 참고 양식 사진 `data/profile/agency_profile_sample.jpeg`은 레이아웃만 봤고 사람 이름·사번은 옮기지 않았다.
- **못 본 것**:
  - 서버 화면을 허락받지 않아 Playwright로 카드를 열지 않았다.
  - 견본 docx를 Word로 렌더해 재지 못했다. 그래서 아래 높이 값은 맑은 고딕 행간(글자 크기의 약 1.33배)과 DocxKit 상수에서 계산한 **추정에 여유를 더한 값**이다. 실측 보정 절차는 6-3 끝에 적었다.

## 2. 한 줄 총평과 가장 큰 기회
- **총평**: 지금 학력(■ 글머리 목록)과 경력(34:66 표)은 구조가 서로 달라서 내용이 시작하는 열이 어긋난다. 또 경력 기간 칸이 57.8mm로 넓어서 기간과 내용 사이가 비어 보인다.
- **가장 큰 기회**: 학력과 경력을 **같은 폭의 2열 표 하나의 규격(기간 25% | 내용 75%)**으로 통일한다. 그러면 열 맞춤과 공간 절약이 한 번에 해결되고, 남는 높이를 사진에 돌릴 수 있다.

## 3. 잘 된 점
- 제목(18pt, 굵게, 밑줄, 가운데), 쪽 테두리, 사진 왼쪽 + ■ 줄 오른쪽 구성이 참고 양식과 맞는다.
- 경력 기간을 표 칸으로 맞추는 방식은 이미 옳다. 학력에 넓히기만 하면 된다.
- 생년월일 날짜를 빼고 '만 n세'만 쓰는 규칙이 카드와 Word에서 같다.

## 4. 우선순위 이슈
- **P1 열 어긋남** (`eduList`는 ■ 목록, `careerBlocks`는 표 34:66)
  - 왜: 사용자가 11-23에 명시한 요구다.
  - 수정: 6-1을 따른다.
- **P1 1장 넘침 위험**: 지금은 높이 계산 없이 사진을 78mm로 고정해 넣는다.
  - 왜: 사용자는 "절대 1장"이라고 했다.
  - 수정: 6-3 예산식과 6-2 단계로 사진 크기를 고른다. 넘칠 때의 대비책도 6-3에 있다.
- **P2 문서 안 시스템 문구 3종**: 마지막 줄 '확정된 값만 담았습니다. 기준일 …'(사용자가 삭제 지시), '확정된 값이 없습니다.'(빈 학력·경력·정보 줄), '사진을 불러오지 못해 넣지 않았습니다.'(문서 본문).
  - 왜: 외부에 내는 프로필에 내부 상태 문구가 찍힌다. 사용자가 말한 "같은 멘트"에 해당한다고 본다.
  - 수정: 셋 다 문서에서 뺀다. 빈 절의 처리는 6-1을 본다. 사진 실패는 화면 안내로 옮긴다(이관 개발).
- **P2 기간 표기 불일치**: 학력은 'A~B', 경력은 'A ~ B'다.
  - 수정: 둘 다 'A ~ B'로 맞춘다.
- **P2 화면**: 참고자료 번호 칸, 문서 제목 미리보기, 펼침 줄, [취소]가 남아 있다.
  - 수정: 6-4대로 버튼 하나로 바로 내려받게 한다.

## 5. 문구 / 접근성
- **문서**: '확정된 값' 계열 문구를 모두 없앤다. 절 제목 '[ 학 력 ]' '[ 경 력 ]'은 유지한다.
- **화면 안내** (`hc-refnote` 대체): 펼침 줄이 없어지므로 기록 안내는 누르기 **전에** 보이는 꼬리 1줄로 옮긴다.
  - 전: '… · 열람 기록이 남습니다'
  - 후: '… · 열람·내려받기 기록이 남습니다'
  - 감사 고지를 누르기 전에 볼 수 있다.
- **완료 문구** (`TEXT.docxOk`) 후: '워드 파일을 내려받았습니다. 출처 없이 확정된 내용만 담았고, 나이는 만 n세로만 넣었습니다.'
  - 사진 문장은 넣지 않는다. 사진이 실제로 들어갔는지 화면이 모르기 때문이다(이관 개발 2).
- **오류 문구**: 기존 `hc.docxErr` 분기를 유지한다. `refBad`('1~20 사이 숫자를 넣으세요.')와 BAD_VALUE → 칸 오류 분기는 지운다.
- **접근성**:
  - 바쁠 때 버튼은 `disabled` + 문구 '만드는 중…', 줄은 `aria-busy="true"`.
  - 결과 줄은 완료면 `role="status"`, 실패면 `role="alert"`.
  - 포커스는 [워드 내려받기]에 둔다.
  - 버튼의 `aria-controls`·`aria-expanded`는 지운다. 펼침이 없어지기 때문이다.

## 6. 규격

### 6-1. 학력·경력 열 맞춤
- **구조**: 학력도 경력과 **같은 2열 표**로 바꾼다. 두 절 모두 `new DocModel.Table(2, new double[]{25, 75}, rows, 0, true).withoutBorders()`로 같은 폭, 같은 칸 여백(DocxKit 기본 좌우 100twips, 위아래 40twips)을 쓴다.
  - 기간 열: 25% = 42.5mm
  - 내용 열: 75% = 127.5mm
  - 이렇게 하면 학력 내용 첫 글자와 경력 내용 첫 글자의 x좌표가 같아진다.
  - 근거: '■ 2023.12 ~ 2027.12'는 10pt에서 약 29mm, 내어쓰기 3.5mm와 칸 여백 3.5mm를 더하면 약 36mm다. 42.5mm면 여유 6mm다. 지금 34%(57.8mm)는 21mm가 남아 빈 틈이 크다.
- **■ 위치**: 기간 칸 첫 글자(`Bullet.SQUARE`, level 0, 내어쓰기 = 글자 크기). 내용 칸은 `Bullet.NONE`.
- **기간 표기**: 두 절 모두 `periodOf(it, true)`를 쓴다.
  - 'YYYY.MM ~ YYYY.MM'
  - 시작만 있으면 'YYYY.MM ~ 현재'
  - 끝만 있으면 '~ YYYY.MM'
  - 연도만 있으면 '2001 ~ 2003'
  - `spaced=false` 분기는 더 쓰지 않는다.
- **기간 없는 항목**: 칸을 **합치지 않는다**. 기간 칸에는 '■'만, 내용 칸에 값을 넣는다. 지금의 `withSpan(2,1)`은 내용이 기간 열 자리에서 시작해 열 맞춤을 깨므로 없앤다.
- **글자·간격**: 내용 10pt 보통(`DEFAULT_PT`), 문단 뒤 2pt(기본 40twips), 행간 Word 기본(single).
- **절 머리**: 12pt 굵게, 앞 12pt, 뒤 4pt(지금 값 유지).
- **빈 절**: 학력이나 경력이 0건이면 **그 절 머리째 뺀다**. '확정된 값이 없습니다.'는 쓰지 않는다. 열린 질문 1번에 걸려 있다.
- **정보 ■ 줄이 0개일 때**: '확정된 값이 없습니다.'를 넣지 않는다. 그런 머리는 `hasContent`가 이미 409로 막는다.
- **맨 끝 '확정된 값만 담았습니다. 기준일 …' 문단**: 삭제한다. 기준일은 나이 계산에만 쓴다.

### 6-2. 사진 크기
- **비율**: 상자 비율을 유지한다. 높이 = 폭 × 1.0487(81.8/78).
- **최소**: 78 × 81.8mm(지금 크기).
- **최대**: 88 × 92.3mm.
  - 정보 칸 최소 폭은 74mm다. 가장 긴 ■ 줄인 직위+(권한대행)은 약 19자이고, 10pt 한글 3.53mm × 19 + 내어쓰기 3.5 + 칸 여백 3.5 = 74mm다.
  - 사진 칸 = 사진 폭 + 8mm(칸 여백 3.5 + 정보와의 틈 4.5).
  - 따라서 사진 폭은 170 − 74 − 8 = 88mm까지다.
- **단계**: **4단계로 나눈다**(연속 비권장). 높이 추정 오차가 행 1개(약 6mm) 수준이라 연속값은 근거 없는 정밀도이고, 단계여야 시험 기대값을 고정할 수 있다.

| 단계 | 사진 폭×높이 (mm) | 표 폭 비율 사진:정보 (%) |
|---|---|---|
| S0 | 78 × 81.8 | 50.6 : 49.4 (86 : 84mm) |
| S1 | 82 × 86.0 | 52.9 : 47.1 |
| S2 | 85 × 89.1 | 54.7 : 45.3 |
| S3 | 88 × 92.3 | 56.5 : 43.5 (96 : 74mm) |

- 비율 계산: 사진 칸% = (폭 + 8) / 170 × 100. 소수 첫째 자리까지 쓴다.
- 사진은 이제처럼 상자 안에 비율을 지켜 맞춘다(`Math.min`). 상자 크기만 단계값으로 바꾼다.
- 정보 칸은 세로 가운데 정렬을 권한다(참고 양식). DocModel이 세로 정렬을 지원하지 않으면 위 정렬도 괜찮다(P3).
- 사진이 없으면 표 없이 ■ 줄만 쓴다(지금 그대로). 단계 계산은 필요 없다.

### 6-3. 높이 추정 값 (1장 맞춤 근거, Word 렌더 여유 포함)
- **본문 높이**: 257mm. 바닥글 9pt 한 줄은 아래 여백(20mm) 안에 들어가므로 본문을 깎지 않는다.
- **목표 예산**: **247mm**(안전 여유 10mm).

| 요소 | 추정 높이 |
|---|---|
| 제목 (18pt, 앞뒤 18pt) | 22mm (계산 21.2) |
| ■ 정보 줄 1개 (10pt, 뒤 8pt) | 8mm. 직위+임기처럼 \n 두 줄이면 13mm |
| 사진 행 | max(사진 높이, 정보 줄 합) + 1mm |
| 표와 표 사이 1pt 빈 문단 | 1mm씩 |
| 절 머리 (12pt, 앞 12, 뒤 4) | 12mm (계산 11.2) |
| 학력·경력 표 1행 (10pt, 칸 위아래 여백, 문단 뒤 2pt) | 6.5mm (계산 6.1) |
| 내용이 두 줄로 넘어가는 행 | 줄마다 +5mm |

- **내용 열 한 줄 글자 수**: 127.5 − 3.5 = 124mm ÷ 3.53mm 이므로 **34자**(보수적으로 한글 1, 영숫자·공백 0.5로 센다). `ceil(가중 글자 수 / 34)`를 줄 수로 쓴다.
- **사진 단계 고르는 식**:
  - `rows = Σ(학력·경력 행마다 줄 수)`
  - `fixed = 22 + 1 + (절 수 × 12) + (절 수 × 1)`
  - `avail = 247 − fixed − 6.5×rows − 5×(추가 줄 수)`
  - avail 이하인 **가장 큰 단계**를 고른다. 어느 단계도 안 들어가면 S0을 쓴다.
- **참고 (두 절 모두 있을 때)**: 행이 모두 한 줄이면 S3는 약 16행까지, S0은 약 17행까지 들어간다.
- **S0에서도 넘칠 때 (순서대로)**:
  1. 학력·경력 표만 9pt로 낮춘다. 행 6.0mm, 한 줄 38자로 다시 계산한다.
  2. 그래도 넘치면 문서를 만들지 않거나 항목을 자른다. 이 결정은 기획으로 넘긴다(이관 기획 1).
  - 글자를 9pt 아래로 내리거나 사진을 78mm 아래로 줄이는 것은 금지다. 사용자가 최소 크기를 정했다.
- **실측 보정**: backend는 행 수 16·17·18 견본 3개를 Word로 열어 쪽 수를 확인하고, 6.5mm와 34자를 보정한다.

### 6-4. 화면 [워드 내려받기] (`headcard.js`, `index.html` 기관장 카드 블록)
- **동작**: 버튼 하나다. 누르면 바로 요청하고, 펼침 줄은 없다. 꼬리 2줄의 단추 순서 [워드 내려받기][새로 고침][기관장 편집]은 그대로다.
- **상태별 모양**:
  - **평소**: `.hc-ref` 줄이 없다(꼬리 높이 75px 유지).
  - **진행**: 버튼 문구 '만드는 중…'(`disabled`, 폭이 흔들리지 않게 `min-width:7.5em`). 꼬리 아래 전체 폭 `.hc-ref` 줄은 만들지 않는다. 버튼만 바뀐다.
  - **완료·오류**: 지금 위치(꼬리 아래 전체 폭 `.hc-ref`, `--panel2` 바탕, 12px)에 한 줄. 완료는 `.hc-ok`, 오류는 `.hc-err`. 다음 내려받기나 카드를 다시 그릴 때 지운다.
- **`hc.refHtml`이 그리는 것**: `dl.err`와 `dl.ok`만 남긴다. `hc-reflab`·`hc-reftitle`·`hc-refnote`·`hc-refbtns`·[취소]는 지운다.
- **CSS에서 지울 것**: `.hc-ref .hc-reflab`, `.hc-ref input`, `.hc-ref input[aria-invalid]`, `.hc-ref .hc-reftitle b`, `.hc-refbtns`, `.hc-ref button`.
- **CSS에서 남길 것**: `.hc-ref`, `.hc-foot > .hc-ref`, `.hc-ref p`, `.hc-ref .hc-err/.hc-ok`.
- **JS에서 지울 것**: `REF_STORE`·`parseRef`·`refTitle`, 키 처리기(Enter·Esc), `docx-open`·`docx-cancel`, `focusPane('[data-hc-ref]')`.
- **안내 문구**: 펼침 줄이 없으므로 따로 두지 않는다. 기록 고지는 5절의 꼬리 1줄로, 담긴 내용은 완료 문구로 옮긴다.
