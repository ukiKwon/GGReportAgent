- **움직이는 글은 DOM에 처음부터 전체 문장이 있다.** 나타나는 효과는 `clip-path`/opacity로만 낸다. 한 글자씩 span으로 쪼개지 않는다.
- **자동으로 움직이는 동안은 `aria-live="off"`.** 장면 변화를 낭독시키지 않는다(WCAG 2.2.2, login-hero와 같다).
- **색만으로 전달하지 않는다**:
  - 진행 줄의 상태는 색 + 굵기 + `aria-current="step"`으로 나타낸다.
  - D-n은 칩 색 + ▲ + 글자로 나타낸다.
  - 장면 3의 표시는 빨간 점선 + 여백 글자 "다른 기관 이름"으로 나타낸다.

### ② AI 장면 움직임 타임라인
**공통 엔진**
- 장면마다 `[ms, 단계]` 배열을 둔다. JS는 예시 창에 `data-step`만 바꾸고, 모양은 CSS 전이가 맡는다.
- **마크업 기본값은 완성 상태(`data-step="end"`)다.** JS가 `#landing-view`에 `.ld-anim`을 붙이고, 장면이 화면에 들어올 때만 `0`부터 재생한다. 스크립트가 실패하거나 꺼져 있으면 완성 장면이 그대로 보인다.
- 정해 둔 동작 단위:
  - **형광펜(HL)**: 대상 줄 뒤의 `::before`(바탕 `--ld-hl`, 줄 높이 100%, 2px 모서리)가 `scaleX 0→1`, origin left, 400ms `--ld-ease`. 다 그은 뒤 200ms 있다가 opacity 1→0, 300ms. 'AI가 읽는다'는 표시는 이것 하나뿐이다.
  - **써짐(RV)**: 한 줄 글자에 `clip-path:inset(0 100% 0 0)→inset(0)`, linear. 시간은 글자 수 × 30ms, 최소 400, 최대 1400. 두 줄 이상인 글은 줄마다 opacity 0→1, 300ms씩 차례로.
  - **나타남(IN)**: opacity 0→1 + translateY 8px→0, 280ms `--ld-ease`. 크기 변화(scale)는 쓰지 않는다.
  - **되돌림(RESET)**: 예시 몸 전체 opacity 1→0(200ms) → 단계 0으로 → 0→1(200ms). 합계 400.
- **재생 조건**:
  - 예시 창이 50% 이상 보이고, 멈춤 단추가 '재생' 상태이고, 탭이 보이는 상태여야 한다.
  - 동시에 하나만 재생한다. 가장 많이 보이는 장면이 재생하고, 비율이 같으면 위쪽 장면이다.
  - 50% 밑으로 내려가면 즉시 완성 상태로 바꿔 멈춘다. 다시 들어오면 0부터 재생한다.
- **반복**:
  - 완성 뒤 유지 시간: 큰 장면 4000, 작은 장면 3000. 그 뒤 RESET하고 다시 재생한다. 보이는 동안 계속 반복한다.
  - **마우스가 예시 창 위에 있으면** 이번 회차를 끝까지 보여 준 뒤 완성 장면에서 기다리고, 떠나면 유지 시간을 다시 센다.
- **정지**:
  - [움직임 멈춤]을 누르거나 탭이 숨으면 모든 장면을 즉시 완성 상태로 바꾼다(멈춘 자리가 반쯤 쓴 글이 되지 않게).
  - 다시 재생하면 지금 보이는 장면만 0부터 시작한다.
  - 상태는 저장하지 않는다.
- **reduced-motion**: `.ld-anim`을 붙이지 않는다. 모든 장면은 완성 상태로 정지하고, 단추는 "움직임 재생"으로 시작한다(login-hero와 같다). 사용자가 누르면 재생한다.

### ③ 업무 흐름 진행 줄
- `nav.ld-rail`(aria-label "업무 흐름 단계"): `position:sticky; top:112px`(상단 줄 64 + 48).
- `ol` 안에 5항목, 항목 사이 40.
  - 항목은 `a href="#flow-n"`.
  - 28×28 네모(2px 모서리) 안에 번호(모노 14/700, 가운데).
  - 12 뒤 이름 16, 아래 줄 13 muted 칸 수.
  - 칸 수는 하위 칸을 포함해 정본에서 센 값만 쓴다. 세지 못했으면 줄을 뺀다.
- **세로 선**: 네모 가운데(x=14)를 지나 1번 중심부터 5번 중심까지.
  - 밑선 2px `--ld-line`.
  - 그 위 채움선 2px `--ld-gray`. `transform:scaleY(p)`, origin top. p는 묶음 1 중심이 화면 가운데일 때 0, 묶음 5 중심일 때 1. 스크롤과 rAF로 계산하고 전이는 없다(스크롤에 직접 묶음).
- **항목 상태**(지금 묶음 = 화면 세로 가운데 줄에 걸친 묶음, IntersectionObserver `rootMargin:"-45% 0px -45% 0px"`):

| 상태 | 네모 | 번호 | 이름 | 기타 |
|---|---|---|---|---|
| 지난 | `--ld-gray` 채움 | 흰색 | 잉크 400 | |
| **지금** | `--ld-yellow` 채움 + 1px `--ld-gray` 테두리 | 잉크 | 잉크 700 | `aria-current="step"` |
| 남은 | 투명, 1px `--ld-line-strong` | muted | muted | |

  - 상태 바뀜은 바탕색 200ms 전이만 쓴다.
- **칸 사슬 연출**: 묶음이 처음 '지금'이 될 때 한 번만, 그 묶음 칸들의 왼쪽 3px 막대가 `--ld-line`에서 `--ld-gray`로 바뀐다. 70ms 간격, 각 200ms. 다시 와도 반복하지 않는다.
- **reduced-motion**: 칸 막대는 처음부터 진회색이다. 네모 상태 전이 0ms. 채움선은 스크롤에 따라 그대로 움직인다(사용자 조작에 붙은 것이라 자동 움직임이 아니다).
- 항목을 누르면 그 묶음으로 이동한다(reduced면 즉시, 아니면 `scroll-behavior:smooth`). 포커스는 묶음 `h3`(tabindex=-1)로 간다.

## 7. 이관 메모
- **[이관: 기획]**
  - 장면 1의 카드별 '다음 한 걸음' 문구 4개가 필요하다. 시안에서는 이유 줄만 있고 다음 한 걸음은 뺐다(근거: planner 초안 장면 1에 이유만 있음).
  - 장면 3의 앞뒤 문장 4줄이 필요하다. 지금은 회색 막대로 대신한다.
  - 진행 줄의 묶음별 칸 수: 하위 칸을 셀지 정해야 한다(근거: 묶음 머리 3개는 표시용, PrepBoardColumns.java).
  - 디자인은 위 문구가 오면 교체만 하면 된다.
- **[이관: 개발]**
  - 랜딩→로그인 전환 시 `#login-id` 포커스, 로그인 화면에서 '서비스 소개' 링크, 세션이 있으면 랜딩 생략(계획 §동작). 디자인은 전환에 움직임을 두지 않는다(즉시 전환).
  - 기존 로그인 CSS `--lg-edge`가 `100vw`를 쓴다. 랜딩은 `--ld-wrap`(100%)을 쓰고 섞지 않는다(근거: `frontend/index.html` 705행).
- **[이관: 데이터/security]**
  - 장면 2 가상 평가표의 항목 이름이 실제 기준처럼 읽히는지 판정해야 한다. 디자인은 'A시(가상)'을 표 캡션과 공고문 판 위 두 곳에 둔다.
  - 캡처 4장의 가림 처리는 계획 순서 5를 따른다.
- **[이관: 메인]**
  - 시안이 확인되면 DESIGN.md에 '소개 표면(랜딩)' 절을 더해야 한다(3절 표가 원문). 규칙급 문서라 메인 몫이다.
  - 적용 커밋 전에 `docs/design_history/index.html`에 전/후 장이 필요하다. 전: "첫 접속 = 로그인 화면(진회색 띠 + 흰 카드 + 6초 슬라이드)". 후: "첫 접속 = 화면 가득 진회색 첫 장(56px 문구) + 할 일 정렬 예시 → AI 7장면 → 27칸 업무 흐름 → [로그인]". 대비 숫자는 5절 목록. 왜: "사내 시연에서 만든 기능과 앞으로의 AI를 한 번에 보이기 위해(사용자 11-26)".
