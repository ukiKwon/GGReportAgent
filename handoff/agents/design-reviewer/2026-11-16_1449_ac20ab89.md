## 1. 대상·방법·못 본 것
대상: 기관 사업계획 사업표 `.pl-tbl`(c:\github\GGReportAgent\frontend\index.html 1903~1915줄, c:\github\GGReportAgent\frontend\js\plans.js 63~98·160~189줄). 방법: 코드만 읽었다. Playwright 연결이 실패해서 화면은 열지 못했다. 아래 폭은 CSS로 계산한 값이다. 못 본 것: 실제 렌더 폭, 실제 서버 데이터에 있는 '예산 원문' 문구의 최대 길이, item_no의 최대 자릿수.

## 2. 한 줄 총평
원인은 두 가지가 겹친 것이다. ⓐ 예산 칸 `nowrap` 때문에 원문 문구가 긴 행이 하나만 있어도 그 표의 예산 열 전체가 넓어진다(주 원인). ⓑ `width:100%`라서 짧은 사업명 오른쪽에 빈 폭이 크게 남는다. 가장 큰 기회는 `table-layout:fixed`로 열 폭을 고정하고 긴 원문 문구만 칸 안에서 줄바꿈하는 것이다.

## 3. 원인 (계산 근거)
- 상세 본문 `.db-pane-body`는 `max-width:820px; padding:20px 24px`(index.html 1592줄)이라 표 폭은 최대 772px이다.
  - 1280폭: 1280 − 사이드 메뉴 248 − 바깥 여백 약 40 = 992 → 목록 380과 간격 20을 빼면 상세 칸 약 592 → 표 약 544px.
  - 1920폭: 표 772px(상한).
- **주 원인 ⓐ**: 표가 auto layout이라 `width:112px`는 최소값일 뿐이다. 112px는 `td.pl-bud { white-space:nowrap }`(1907줄) 아래에서 확인안됨 칸의 줄바꿈 없는 문구가 열 폭을 결정한다. 그 문구는 최대 40자 + '…' + ' (원문 표기)'로 약 48자이고, 11px 한글이면 약 380~480px이다. `.db-why`가 `display:block`(1915줄)이어도 nowrap을 물려받아 줄이 바뀌지 않는다. 열 폭은 행마다가 아니라 열 전체에 걸린다. 그래서 같은 분야 표 안에서 '1,200' 같은 짧은 금액도 400px대 열의 오른쪽 끝에 붙는다. 1280폭에서는 사업명 열이 오히려 좁아지면서 이름과 금액 사이가 멀어진다. 이것이 사용자가 말한 "형식이 깨졌다"에 해당한다. 원문 표기는 오늘 들어갔다(커밋 960f7d1).
- **보조 원인 ⓑ**: 원문 문구가 짧은 문서라도 사업명 열이 '나머지 전부'를 가져간다. 1920폭에서는 772 − 52 − 112 = 608px인데, 사업명은 대개 120~250px라 금액까지 350~480px가 빈다.
- 참고: 1909줄 `.pl-child td.pl-nm { padding-left:24px }`가 하위사업 들여쓰기다. 문제와는 관계없다.

## 4. 우선순위 이슈
- **P1** 예산 열이 원문 문구 길이에 끌려 넓어진다. 근거: 1907줄 nowrap + auto layout. 문제인 이유: 한 행의 데이터가 표 전체의 열 구조를 무너뜨려 이름과 금액을 같은 행으로 읽기 어렵다. 수정 방향: fixed layout을 쓰고, 예산 열은 160px로 고정하고, 원문 문구(`.db-why`)만 줄바꿈한다.
- **P2** 넓은 모니터에서 이름과 금액이 멀다. 근거: 1903줄 `width:100%`에 상한이 없다. 수정 방향: 표에 `max-width:680px`를 준다. 1280폭(544px)에서는 영향이 없고, 1920폭에서만 사업명 열이 608px에서 468px로 줄어든다. 12px 내용 줄은 한글 약 38자로, 읽기 좋은 길이다.
- **P2** 번호 열 52px는 auto layout에서만 안전하다. 52 − 패딩 16 = 36px이고, mono 13px로는 약 4.6자다. fixed로 바꾸면 '10-12'(5자, 약 39px) 같은 번호가 사업명 칸으로 넘친다. 그래서 64px(내용 48px, 6자)로 넓힌다.
- **P3** 원문 문구가 두 번 보인다. `itemRowHtml`이 `it.note` 전체를 사업명 칸 아래에 `.pl-content`로 보여 주므로(plans.js 170줄), 같은 '예산 원문: …'이 이름 칸과 예산 칸에 다 나온다. 사용자 결정(11-16: 원문 표기를 예산 칸에 보임)은 그대로 둔다. 다만 예산 칸 잘림 한도 `SRC_LIMIT`를 40에서 24 정도로 줄이면 줄 수가 3~4줄에서 2줄로 준다. 이 값은 JS라 프런트 담당에게 넘긴다(선택).

## 5. 문구 / 접근성
- 문구는 바꿀 것이 없다. 낭독용 `sr-only`('원문 표기 …' 전체)는 줄바꿈과 상관이 없다.
- 줄바꿈 뒤에도 `title`(40자 초과 시 전체 문구)은 유지된다.
- 오른쪽 정렬된 여러 줄 문구는 좁은 열(144px 내용 폭)에서 2~4줄이라 읽을 수 있다. 금액 열의 정렬 일관성을 우선해 오른쪽 정렬을 유지한다.

## 6. 규격 + 바로 적용할 CSS (index.html)
관례: 입찰 현황판 상세(`.db-pane-body` 820 상한)와 같은 계열이다. 금액은 오른쪽 정렬·mono·nowrap(`.bd-num`, `.ad-table` 관례), 머리글은 12px `--muted`이고 1px `--line-strong` 아래선을 쓴다. 새 토큰·hex는 없다.

| 열 | 폭 | 정렬 | 줄바꿈 |
|---|---|---|---|
| 번호 | 64px 고정 | 왼쪽 | nowrap |
| 사업명 | 나머지 (1280: 약 332px / 1920: 약 448px) | 왼쪽 | 보통(이름·내용) |
| 예산 | 160px 고정 (내용 144px) | 오른쪽 | 금액·단위는 nowrap, 원문 문구(.db-why)만 줄바꿈 |
| 표 전체 | width:100%; max-width:680px; table-layout:fixed | — | — |

fixed layout에서는 첫 행 `thead` th의 클래스(`pl-no`/`pl-bud`)가 열 폭을 정하므로 colgroup이 필요 없다. 분야 머리 행(`colspan=3`)은 tbody 안에 있어 영향이 없다.

1903줄 교체:
```css
  .pl-tbl { width:100%; max-width:680px; table-layout:fixed; border-collapse:collapse; margin-top:12px; font-size:13px; }
```
1906줄 교체:
```css
  .pl-tbl th.pl-no, .pl-tbl td.pl-no { width:64px; white-space:nowrap; }
```
1907줄 교체:
```css
  .pl-tbl th.pl-bud, .pl-tbl td.pl-bud { width:160px; text-align:right; white-space:nowrap; }
```
1915줄 교체:
```css
  .pl-bud .db-why { display:block; font-size:11px; line-height:1.4; white-space:normal; word-break:keep-all; overflow-wrap:anywhere; }
```
사업명 칸이 긴 영문·URL에 밀려 넘치지 않게 1909줄 아래에 한 줄을 추가한다:
```css
  .pl-tbl td.pl-nm { overflow-wrap:anywhere; }
```
상태별 결과:
- 금액('1,200', '3,400 백만원', '계산값'): 한 줄, 오른쪽 끝, 이름에서 최대 약 450px 거리(1920).
- 원문 표기 '268+32 (원문 표기)': 1~2줄.
- 40자 문구: 3~4줄, 오른쪽 정렬.
- 880px 이하 1단: 표는 100%이고 680 상한이며 열 폭은 같다.

전/후 장이 필요하다: docs/design_history/index.html에 이 변경을 다룬 장이 없다(807~814줄은 원문 표기 도입 장이다). 넣을 문안은 아래와 같다.
- 전: 예산 열이 원문 문구 길이만큼 늘어난다. 긴 문구가 하나 있으면 그 분야 표의 예산 열 전체가 약 400px대가 되고 짧은 금액도 오른쪽 끝으로 밀린다. 1920폭에서 이름과 금액 사이가 최대 약 480px다.
- 후: 열 폭을 번호 64 / 예산 160으로 고정하고 표 폭 상한을 680px로 둔다. 긴 원문 문구는 예산 칸 안에서 2~4줄로 줄바꿈한다.
- 대비: 새 색은 없고 대비 수치도 바뀌지 않는다.
- 왜: 한 행의 문구가 표 전체 모양을 무너뜨리지 않게 하고, 이름과 금액을 같은 행으로 읽게 하려고.

## 7. 이관 메모
- [이관: 개발] 줄바꿈을 적용한 뒤 `SRC_LIMIT`(plans.js 62줄)를 40에서 24로 줄일지는 프런트 판단이다. 디자인은 둘 다 허용한다. 근거: 이름 칸 비고와 내용이 중복되어 예산 칸은 요약이면 충분하다. 바꾸면 frontend/test의 잘림 테스트도 함께 고쳐야 한다.
- [이관: 데이터] item_no 최대 길이(예: 'N-NN-N' 7자 이상)가 있는지 확인이 필요하다. 64px 기준은 6자까지다. 있으면 번호 열을 72px로 늘린다.
