## 2. 한 줄 총평과 가장 큰 기회

서버는 사실 칸·서술 칸·판·확정·바뀜을 다 갖췄다. 화면이 할 일은 **"Word 1쪽을 그대로 펼친 편집기"**다.

**가장 큰 기회**: 작성 창의 본문을 Word 양식의 겉 2열 표('추진 배경'·'기타 사항' 절 이름 열 + 본문 열)와 같은 모양으로 짜는 것이다. 담당자는 종이에서 보던 자리에 바로 쓰고, 확정본 Word와 화면이 한눈에 대응된다. 사용자 원칙 "일을 두 번 하지 않는다"에 맞는 이 제품만의 모양이다.

## 3. 점수표 / 잘 된 점

- **점수는 매기지 않는다.** 화면이 없어 근거가 없다.
- **잘 된 점**
  - `viewer.can_edit / can_confirm / can_unconfirm / can_download / lock_reason`이 있다. 화면은 역할을 다시 판정하지 않고 단추를 보이고 숨기기만 하면 된다.

  - 같은 내용 저장은 `changed:false`로 새 판을 만들지 않는다. 사실 칸을 PUT하면 400 FIELD_READONLY로 막는다. 화면 실수가 정본을 흔들지 못한다.

## 5. 문구 / 접근성

### 5-1. 문구 원칙
- 창 제목: `기관 정보 요약 — {기관명}`
- 칸 이름은 `tpl.keys[].label`을 그대로 쓴다.
- 서버 message는 보이지 않고 코드별 화면 문구를 쓴다(6-8).
- 상태 줄 문장 틀: '{무엇}을 못 했습니다. {원인}. {할 일}.'
- 사용자 단어 '바뀜' 하나로 두 경우를 덮는다. 확정 전 원본이 바뀐 칸과 확정 뒤 원본이 바뀐 칸이다. 차이는 아래 문장과 단추로 낸다.

### 5-2. 접근성 요건
- **창**
  - `role="dialog" aria-modal="true" aria-labelledby="isf-t"`. 열면 제목에 커서가 간다(dlg 기본).
  - 닫으면 [양식 열기] 단추로 돌아간다(`opener.focus()` 뒤 `dlg.open`, kbboard 선례).
- **제목 구조**: 창 제목 h2 → 절(추진 배경·기타 사항) h3 → 소제목('- 기관 현황' 등) h4.
- **입력칸**
  - 모든 입력칸에 보이는 label이 있다. 목록 줄은 글머리 'ㅇ'만 보이므로 `aria-label="추진 배경(현황) 3번째 줄"`을 단다.
  - 줄 단추(24×24, WCAG 2.5.8 최소 충족)는 `aria-label="3번째 줄 위로/아래로/삭제"`.
  - 표 칸은 `aria-label="{대분류} 사업 내용 2번째 줄"`, `"2028년 MMDA 연평잔"`.
- **필수 칸**: 이름 옆 빨간 `*` + `aria-required="true"`. [저장]·[확정]은 막지 않고, 누르면 빠진 칸마다 빨간 테두리 + 아래 12px 한 줄을 보이고 첫 칸으로 커서를 옮긴다(`dlg.invalid`).
- **보기 모드**: 비활성 입력칸을 쓰지 않고 글로 그린다(비활성 입력은 대비 .55, Tab에서 빠짐). 빈 칸은 `—` + `<span class="sr">비어 있음</span>`.
- **색만으로 전하지 않는다**
  - '바뀜'은 글자 칩 + 왼쪽 3px 막대.
  - 협약 종료 뒤 연도는 빗금 + 머리 칸 '협약 종료' 글자.
  - 같은 대분류 묶음은 왼쪽 막대 + 표 아래 설명 문장.
- **대비**(흰 바탕 기준, 계산값)

| 대상 | 대비 |
|---|---|
| `--orange` #8a5c00 글자 | 5.82:1. 12% 틴트 위 약 4.9:1 |
| `--blue` #0a65ab | 약 6.1:1 |
| `--yellow` #6b6000 | 약 6.3:1 |
| `--muted` #464c53 (`--panel2` 위) | 약 8.1:1 |

- **글자 수 표시**: 한도의 80%부터만 보인다(모노 12px). `aria-live="polite"`는 한도의 90%부터만 켠다.
- **결과 줄**: 성공은 `.st-line` + `role="status"`(8초 뒤 접힘). 칸 오류는 칸 아래, 창 전체 오류(서버·연결)만 `.dlg-err`(`role="alert"`).

### 6-3. 머리 줄(52px) 단추: 상태별

| 상태(판정식) | 제목 줄 오른쪽 | 아래 `.dlg-foot` |

- [확정…]은 작성 모드에서 늘 보인다(아래 '먼저 저장' 규칙).
- 단추 높이 32px(`.dlg-acts > button`). [확정…]은 `.dlg-go`(포인트 테두리 + 700)이고 채우지 않는다. 계약의 채운 주버튼 예외 3곳 밖이기 때문이다.

**'먼저 저장' 규칙(한 번만 정의)**
- 저장된 판이 필요한 동작은 세 가지다: [확정], [다시 불러오기]·[주요 사업 다시 채우기]·[시작 연도 채우기], [워드 내려받기(초안)].

- 저장이 칸 오류로 실패하면 거기서 멈추고 칸을 표시한다.

### 6-6. 부품 규격

**사실 칸(FACT, 이 창에서 못 고침)**
- 값: `--panel2` 바탕 상자, 13px `--fg`, `overflow-wrap:anywhere`. 입력칸 테두리를 그리지 않는다. 그래야 '고칠 수 없음'이 모양으로 보인다.
- 아래 12px `--muted` 한 줄: `[원본] {src.title} · 확인 {src.checked_on}`. URL은 http·https일 때만 링크로 만든다(security 하-1).
- 작성 모드에서는 이어서 `[{원 화면 이름}에서 고치기]` 단추(24px)를 둔다.

| fix_screen | 원 화면 이름 |
|---|---|
| inst_edit | 기관 기본 정보 |
| head_card | 기관장 정보 |
| bank_contract | 금고 약정 기록 |

- **원본 없음**(`sources_missing`에 키): 값 자리에 "원본에 값이 없습니다." `--muted`. 아래 줄은 "{원 화면 이름}에서 먼저 넣으세요." 필수가 아니면 "비어 있어도 확정할 수 있습니다."를 덧붙인다.
- **바뀜**(확정 전 `stale_keys` 또는 확정 뒤 `confirmed_changed_keys`에 키)
  - 상자 왼쪽에 3px `--orange` 막대(`box-shadow: inset 3px 0 0`).
  - 값 옆에 칩 `바뀜`(`--orange`).
  - 확정 전 아래 줄: "원본이 바뀌었습니다. [다시 불러오기]" → prefill `{keys:[key]}`, form_refill.
  - 확정 뒤 아래 줄: "확정한 뒤 원본이 바뀌었습니다. 워드에는 확정 당시 값이 나옵니다."
- **[고치기] 동작**
  1. 고친 내용이 있으면 먼저 저장한다(X-Button-Id form_save).
  2. 양식 창을 닫는다(`dlg.close`, 커서를 되돌리지 않음).
  3. 원 화면을 연다.
  4. 원 화면을 여는 함수가 없으면 닫지 않고 상태 줄에 "지도나 입찰 현황판에서 {기관}을 열어 '{원 화면 이름}'에서 고치세요. 고친 뒤 이 양식을 다시 열면 [다시 불러오기]가 나타납니다."를 보인다.

**글 칸 + 출처**(budget·staff·supervisor·address)
- label 12px `--muted`(격자 머리) → 입력 → 아래 작은 칸 `출처` label + 입력(100자).
- 출처 칸 도움말은 처음 한 칸에만 둔다: "어디서 확인했는지 적으세요(예: 2026 예산서 3쪽)."
- 원칙 1(근거 없는 숫자 금지) 때문에 출처 칸을 접지 않는다.

**목록**(overview·mmda_basis·competition)
- 줄마다 `ㅇ` 글머리(20px 열) + 입력 + [↑][↓][삭제](24px, SVG 글리프 + aria-label).
- 아래 [줄 더하기]. 10줄이면 숨기지 않고, 누르면 칸 아래에 "10줄까지 쓸 수 있습니다."를 보인다.
- **여러 줄 붙여넣기**: 붙여넣은 글에 줄바꿈이 있으면 줄마다 나눠 아래로 넣는다.
  - 앞머리 `ㅇ`·`-`·`·`·`○`·`•`와 공백은 지운다. 워드가 글머리를 다시 붙이기 때문이다.
  - 빈 줄은 버린다.
  - 한도를 넘는 줄은 넣지 않고 상태 줄에 "10줄을 넘는 {k}줄은 붙이지 않았습니다."를 보인다.
  - 이것으로 기존 Word 문서에서 옮겨 적는 일이 한 번에 된다.
- **키보드**: Enter = 아래에 빈 줄을 더하고 커서를 옮긴다. 비어 있는 줄에서 Backspace = 그 줄을 지우고 윗줄 끝으로 간다.
- **보기 모드**: `<ul>`에 `ㅇ` 글머리 글만.

**사업 표(biz)**
- 열: 대분류* | 세부 사업 | 내용(줄 목록, 줄마다 입력 + [+줄]) | [삭제].
- 줄 이동은 행 끝 [↑][↓]다.
- **묶음 표시**: 바로 윗줄과 대분류 글이 같으면 대분류 칸에 왼쪽 3px `--line-strong` 막대를 긋고 글자를 `--muted`로 한다. 편집은 그대로 된다. 표 아래 12px: "같은 대분류가 이어진 줄은 워드에서 한 칸으로 합쳐집니다."
- 표 제목 줄
  - `출처: {src.title}(기준일 {src.checked_on})`, src가 없으면 "직접 입력".
  - 작성 모드면 `[주요 사업 다시 채우기]`를 둔다.
- **[주요 사업 다시 채우기]**: `dlg.confirm`을 쓴다.
  - 제목 "주요 사업 다시 채우기"
  - 본문 "주요 사업 표를 지금 반입된 사업계획으로 바꿉니다.\n지금 표의 {n}줄(직접 고친 내용 포함)은 새 판에서 사라집니다. 이전 판은 판 이력에 남습니다."
  - 실행 단추 "다시 채우기", `danger`
  - 확인하면 prefill `{keys:['biz']}`, form_prefill.
- **seed_notices**(표 제목 바로 아래 12px 한 줄씩, 객체 목록)
  - `{reason:'NEWER_IMPORT'}`
    - 확정 전: "이 표를 채운 뒤 새 사업계획이 반입되었습니다. 새 계획으로 바꾸려면 [주요 사업 다시 채우기]를 누르세요."
    - 확정 뒤: 칩 `바뀜` + "확정한 뒤 새 사업계획이 반입되었습니다."
  - `{reason:'ROWS_DROPPED', count}`: "사업계획 {count}줄은 개인정보로 보이는 글자가 있어 가져오지 않았습니다. 필요하면 직접 적으세요."

- **빈 표**: "사업이 없습니다." + 작성 모드면 [사업 줄 더하기]·[주요 사업 다시 채우기]. 반입이 없으면 409 NO_PLAN_IMPORT 문구(6-8).

**운영 방식 표(fund)**
- 열: 구분* | 내용.

  - 누를 때마다 단계 0과 1이 바뀐다.
- lv1 줄은 입력을 20px 들인다. 워드의 '- ' 아래 'ㅇ'과 같다.

**연도 표(years)**
- 제목 옆 칩 `내부 추정`(`--gray`, 틴트 없음). 사실 표시이고 경고가 아니다.
- **조건 줄**: `단위`(20자, 기본 억원) `시작 연도`·`끝 연도`(number, 2000~2100, 모노 72px) `협약 종료 연도`(select: '표시 안 함' + 시작~끝 연도).
- **표**
  - 머리: 구분 | 연도 열(모노). 종료 연도 머리 칸 아래 12px 줄에 "협약 종료".
  - 행: MMDA 연평잔 / 자금수익.
  - 입력은 모노, 오른쪽 맞춤, 72px.
- **종료 뒤 연도 열**
  - 칸 바탕에 빗금(45도, 4px 주기, `--line`)을 칠한다.
  - 입력은 그대로 쓸 수 있다. 막으면 기존 값을 보낼지 버릴지 모호해진다.
  - 표 아래 "협약 종료 뒤 연도는 워드에서 빗금으로 칠해집니다."
- **주석**: `주석` 목록 5줄 × 300. 글머리는 `주1)`부터 자동으로 붙고, 입력에는 쓰지 않는다.
- **연도 바꾸기**: 범위 밖으로 밀려난 연도의 값이 있으면 [저장] 전에 칸 아래 "2027년 값 2개는 범위 밖이라 저장하지 않습니다."를 보인다. 서버는 범위 밖 키를 400으로 막으므로 화면이 빼고 보낸다.
- **years가 null일 때 빈 상태**: "연도 표가 아직 없습니다." + `[약정 만기로 시작 연도 채우기]`(prefill `{keys:['years']}`, form_prefill) `[직접 만들기]`(올해+1부터 1열).
- **화면 사전 검사**
  - 시작 ≤ 끝, 열 수 ≤ 10, 종료 연도는 범위 안.
  - 금액은 쉼표와 공백을 지운 뒤 `^-?\d{1,13}(\.\d{1,3})?$` 또는 빈 값.
  - 틀리면 그 칸에 "숫자로 적으세요(소수 3자리까지, 쉼표 가능)."

**저장 본문 조립**
- fields: 글 칸 9개만 `{val, note}`, 빈 값은 null.
- lists: 3개.
- tables: `biz:{rows}`, `fund:{rows}`, `years|null`.
- 사실 칸과 `biz.src`·`dropped`는 보내지 않는다.
- 통째로 빈 줄(사업 줄의 모든 칸, 운영 방식 내용 줄)은 화면이 빼고 보낸다.
- `isDirty` = 지금 조립한 본문 JSON ≠ 마지막으로 받은 판에서 조립한 JSON.

### 6-8. 동작 → 요청 → 식별자(감사: 누가·어느 화면·어느 버튼)

모든 요청에 `X-Screen-Id: prep_form`과 아래 `X-Button-Id`를 싣는다. **GET도 포함한다**(security 하-6). 사번 머리글은 기존 전역 방식 그대로다.

| 단추·계기 | 요청 | X-Button-Id |
|---|---|---|
| 창 열기 | GET `/bidcases/{id}/prep/forms/INST_SUMMARY` | form_open |
| 첫 작성 자동 채움 | POST `…/prefill {base_ver:0}` | form_open |
| [새로 고침]·[다시 시도]·[최신 판 불러오기] | GET 양식 | form_refresh |
| [저장]·Ctrl+S·[고치기] 앞 저장 | PUT `…/draft` | form_save |
| [다시 불러오기]·[모두 다시 불러오기] | POST `…/prefill {keys:[…FACT 키]}` (+먼저 저장) | form_refill |
| [주요 사업 다시 채우기]·[약정 만기로 시작 연도 채우기] | POST `…/prefill {keys:['biz'] or ['years']}` (+먼저 저장) | form_prefill |
| [확정…] → 확인 창 [확정] | (먼저 저장) POST `…/confirm {base_ver}` | form_confirm |
| [확정 취소…] → 사유 창 [확정 취소] | POST `…/unconfirm {reason}` | form_unconfirm |
| [판 이력] | GET `…/versions` | form_history |
| [워드 내려받기(확정본)] | GET `…/confirmed-docx` | form_docx |
| [워드 내려받기(초안)] | (먼저 저장) GET `…/draft-docx` | form_draft_docx |

- **내려받기**: `fetch` → blob → `a[download]`로 받는다. `window.open`은 머리글이 없어 400이다.
  - 파일 이름은 `Content-Disposition`의 `filename*`을 풀어 쓴다.
  - 성공하면 상태 줄 "워드 파일을 내려받았습니다(v{n}판{, 초안})."
- **[저장] 결과**
  - `changed:true` → "v{cur_ver}판으로 저장했습니다."
  - `changed:false` → "바뀐 내용이 없어 새 판을 만들지 않았습니다."
- **[확정] 결과**: "v{n}판으로 확정했습니다. 워드 확정본을 내려받을 수 있습니다." 그 뒤 보기 모드로 다시 그리고 [워드 내려받기(확정본)]에 커서를 둔다.
- **[확정 취소] 결과**: "v{unconfirmed_ver}판 확정을 취소했습니다. 고친 뒤 다시 확정하세요." 그 뒤 작성 모드로 다시 그린다.
- 응답은 모두 view와 같은 모양이라 그대로 다시 그린다.

### 6-10. 확인 창·확정 취소 창·판 이력 창

- **확정 확인**(`dlg.confirm`)
  - 제목 "기관 정보 요약 확정"
  - 본문 "v{n}판을 확정합니다.\n확정하면 이 내용이 정본이 되고 워드 확정본이 만들어집니다. 고치려면 사유를 적고 확정을 취소해야 합니다."
  - 고친 내용이 있으면 첫 줄을 "고친 내용을 저장한 뒤 확정합니다."로 바꾼다.
  - 실행 단추 "확정". 첫 커서는 [취소].
- **확정 전 화면 사전 검사**: 필수 칸이 비었거나 `stale_keys`가 있으면 확인 창을 띄우지 않는다. 6-9의 FORM_INCOMPLETE·FORM_STALE과 같은 표시를 하고 거기로 커서를 옮긴다.
- **확정 취소 창**(쓰는 창, `.dlg` 560)
  - 제목 "확정 취소 — 기관 정보 요약"
  - 제목 줄 `[취소][확정 취소]`
  - 본문
    - 칸 `취소 사유 *`: `<input type="text" maxlength="200">`, 글자 수 표시.
    - 도움말 12px: "사유는 사전준비 이력에 남습니다. 개인정보(주민등록번호·전화번호)는 적지 마세요."
  - 빈 사유: "취소 사유를 적으세요."
- **판 이력 창**(보는 창, `.dlg` 560, `.dlg-foot`에 [닫기])
  - 표 열: 판(모노) | 한 일 | 저장한 사람 | 시각(모노) | 비고
  - 한 일: PREFILL → "원본 불러옴", DRAFT → "저장"
  - 비고: confirmed true → "확정본"
  - 최신 판이 위다.
  - 판 내용은 열 수 없다(서버에 판별 GET이 없다). 표 위에 "판 내용은 지금 판과 확정본만 볼 수 있습니다."

### 6-12. '우리 회사 기대효과' 칸: 두 안(Q-2026-11-09-01 미답)

위치는 두 안 모두 '기타 사항' 절의 '경쟁은행 동향 및 중점 제안 사항' 아래, 소제목 `- 우리 회사 기대효과`다. 두 안 모두 서버 칸 추가가 필요하다(`InstSummaryTpl` TPL_VER 2 + DocBuilder RENDER_VER 2).

**안 A: 문장만(권장, 질문의 권장과 같음)**
- 부품: 목록(6-6 목록과 같음), key `effect`, 10줄 × 300, 필수 아님.
- 도움말 12px 한 줄: "금액·비율을 적으면 그 숫자가 어디서 나왔는지 같은 줄에 적으세요."
- 이유
  - 연도별 표가 이미 MMDA 평잔·자금수익 숫자를 사람이 적는 자리다. 같은 숫자를 두 곳에 두면 서로 어긋난다.
  - 원칙 1(출처 없는 숫자 금지)을 문장 규칙으로 지킨다.

**안 B: 숫자 연결**
- 부품
  - 위: 사실 칸 줄(`--panel2` 상자, 이 창에서 못 고침). 수익성 분석표(T3) **확정본**에서 가져온 값 n개.
  - 값 이름과 개수는 기획이 정한다. 디자인은 만들지 않는다.
  - 아래 줄: `[원본] 수익성 분석표 확정본 · {파일 이름} · 확정 {날짜}`.
  - 그 아래: 문장 목록(안 A와 같음).
- 상태: T3 확정본이 없으면 "수익성 분석표 확정본이 없어 숫자를 채우지 못했습니다." T3가 다시 확정되면 '바뀜'(6-6 사실 칸 규칙 그대로).
- 비용: T3 칸을 읽는 서버 연결, 낡음 판정에 T3 참조 추가.
- 위험: 연도 표와 숫자가 겹친다.

**안 0(샘플 그대로)**
- 샘플 양식(11-19)에는 이 칸이 없다(planner a1f5ef8f 3절).
- 기대효과는 '중점 제안 사항' 목록 안에 문장으로 쓴다.
- 서버 변경이 없다.
- 질문이 샘플 이전이라 이 선택지를 더해 다시 묻는다(8절).
