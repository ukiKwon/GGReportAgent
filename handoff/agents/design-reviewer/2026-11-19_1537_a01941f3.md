## 6. 규격

### 6-1. 상태 칩 함수 하나: `plans.stateChipsHtml(st, req, closed, isNew)`
입력은 다음 넷입니다.
- `st` = /institution-plans/status 한 건 또는 null
- `req` = 열린 요청(REQUESTED·RUNNING) 또는 null
- `closed` = last_closed. 요청 가능한 사람에게만 옵니다.
- `isNew` = 서버가 주는 7일 표시. 아래 이관 참고. 서버가 주기 전에는 늘 false.

| 상황 | 칩(순서대로) | 클래스 |
|---|---|---|
| 자료 없음, 요청 없음 | 자료 없음 | `pop-unk`(점선 = 미확인) |
| 자료 없음, REQUESTED | 사업계획 요청됨 | `wf-badge cr-st gap` |
| 자료 없음, RUNNING | 사업계획 수집 중 | `wf-badge cr-st pp-neutral` |
| 자료 없음, 최근 FAILED/EXCLUDED | 자료 없음 + 수집 실패 / 수집 제외 | `pop-unk` + `wf-badge cr-st none` / `wf-badge pp-cancel` |
| 자료 있음 | 사업계획 N건 (N은 mono) | `wf-badge pp-neutral` |
| 위 + 7일 안에 새로 들어옴 | + new | `wf-badge cr-st ok`(파랑 = 반영됨과 같은 뜻) |
| 위 + 모든 문서 기간 지남 | + 기간 지남 | `wf-badge pp-cancel` |
| 위 + 오래됨 | + 오래됨 | `wf-badge cr-st gap` (P2-2) |
| 위 + 다시 요청 REQUESTED / RUNNING | + 요청됨 / 수집 중 | `wf-badge cr-st gap` / `wf-badge cr-st pp-neutral` |

규칙은 다음과 같습니다.
- **칩은 최대 4개입니다.** 'new'가 있으면 '오래됨'은 빼고(방금 들어온 자료), 다시 요청이 열려 있어도 '오래됨'을 뺍니다(이미 손쓰는 중).
- **실측 폭**(12px)
  - 칩 하나씩: 사업계획 125건 100px, new 38, 기간 지남 68, 오래됨 52, 요청됨 52, 수집 중 56, 사업계획 요청됨 104, 사업계획 수집 중 108, 수집 실패 68, 새 자료 56.
  - 가장 긴 조합 "사업계획 125건 + new + 기간 지남 + 요청됨"은 100+38+68+52+간격 18 = **276px**. 3행 쓸 수 있는 폭은 실측 328px(스크롤 막대 포함)이라 접히지 않습니다.
- **'자료 있음/없음' 필터와 '자료 없음 n곳' 계산은 그대로 `st` 기준입니다.** '사업계획 요청됨'도 자료 없음으로 셉니다.

### 6-2. 목록 행 (rowHtml)
```html

```
```css
#plans-root .db-row { padding:10px 20px; }                     /* 14→10, P1-2 */
.pl-st { grid-column:1 / -1; display:flex; flex-wrap:wrap; align-items:center; gap:4px 6px; min-height:20px; font-size:12px; }
```
| 서버 현황(ST) | 3행 |
|---|---|
| 불러오는 중 | 빈 `.pl-st`(높이 20px를 미리 잡음, aria-hidden). 도착할 때 행이 커지며 스크롤이 튀지 않게 합니다 |
| 받음(ok) | 칩 |
| 연결 없음·권한 없음 | 3행을 그리지 않습니다(영구히 빈 24px를 남기지 않음) |

- 수집 요청 현황(CS)이 아직 오지 않았거나 재무부서 403이면 `st` 칩만 그립니다.
- '직접 연 기관'은 2행 끝에 그대로 둡니다.

### 6-3. 상세 (detailHtml): 제목 옆 칩은 빼고 '사업계획' 절 하나로
```html
<div class="db-head"><h2 id="pl-name" tabindex="-1">마포구청</h2></div>   <!-- 칩 없음 -->
<p class="db-sub">지자체 · 서울</p>
<section class="db-sec pl-sum" aria-labelledby="pl-sum-h">
  <h3 id="pl-sum-h">사업계획</h3>
  <p class="pl-st">[stateChipsHtml — 목록 3행과 같은 글자]</p>
  <!-- 자료 없음 -->
  <p class="db-empty">이 기관의 사업계획은 아직 수집되지 않았습니다.</p>
  <div class="pl-req" role="group" aria-label="수집 요청">[수집 요청] 개발부서가 수집하고, 자료가 들어오면 쪽지로 알려 드립니다.</div>
  <!-- 자료 있음 -->
  <p class="db-why pl-imp">반입 2026-11-19 · 수집 파일 반입</p>
  <div class="pl-req" ...>[수집 요청] 새 계획이 나왔으면 다시 요청하세요.</div>
</section>
<div class="pl-kwrow">…찾기…</div>
<div id="pl-docs">…문서별 <h4> (지금의 h3와 같은 모양)…</div>
```
- **순서**: 자료가 없을 때는 상태 → 설명 → 할 일, 있을 때는 상태 → 반입일 → 할 일입니다. 버튼은 늘 절의 마지막 줄입니다.
- **간격**
  - `.pl-sum h3 { margin:0 0 8px }`
  - `.pl-st` 위 여백 0
  - `.db-empty`는 지금대로 margin 8px 0 0
  - `.pl-imp { margin:8px 0 0 }`(지금 4px)
  - `.pl-req`는 지금대로 margin 10px 0 0

### 6-5. 전/후 문안 (design_history 장용)
- **제목**: 58(번호는 메인이 다음 번호로) 사업계획 상태 칩을 한 자리로: 목록 3행·상세 '사업계획' 절 첫 줄·현황판 절이 같은 칩, [수집 요청]은 '사업계획' 절 안으로, 새로 들어온 자료 7일 'new' (2026-11-19, 사용자 실사용 11-19, design 11-19)
- **왜**: 사용자가 실제로 써 보니 목록에서는 '자료 없음'이 지역·날짜 줄 끝에 붙어 행마다 위치가 달랐습니다. 요청한 뒤에는 '요청됨' 칩이 하나 더 붙어 상태가 '바뀌는' 것이 아니라 '늘어나는' 것으로 보였습니다. 상세에서는 [수집 요청]이 기관 이름 바로 아래에 있어 무엇을 요청하는 버튼인지 떨어져 보였고, 자료가 있는 기관에는 '사업계획' 제목조차 없었습니다. 수집 요청으로 자료가 들어와도 표시가 없어 요청한 사람이 알아차리기 어려웠습니다.
- **전**
  - 목록 행 2줄: "서울 · 마감 11.23 [자료 없음]". 요청하면 "[자료 없음] [요청됨]"으로 칩이 늘어납니다.
  - 상세: "마포구청 [자료 없음]" 아래 바로 "[수집 요청] 개발부서가 수집하고…", 그 아래 '사업계획' 절. 자료가 있으면 '사업계획' 제목 없이 반입일과 문서가 나옵니다.
  - 현황판 절: "자료 [자료 없음] [요청됨] 2명 요청".
  - '오래됨' 칩 글자 대비 4.51:1.
  - 1280×720 목록에 행 약 3.0개.
- **후**

  - 상세: 기관 이름 옆 칩을 없애고 '사업계획' 절 첫 줄에 같은 칩을 둡니다. 그 아래 설명(또는 반입일), 마지막 줄에 [수집 요청]과 사람 수를 둡니다. 자료가 있어도 같은 절이 있습니다.
  - 현황판·지도 '자료' 칸도 같은 칩입니다.

## 7. 이관 메모
- **[이관: 개발]** 'new' 판정 값이 서버에 없습니다.
  - 디자인이 기다리는 것: /institution-plans/status 한 건에 `collect_new`(bool) 또는 `collect_applied_at`(시각) 필드.
  - 근거: 현황 API(InstitutionPlanService 238–249)는 `imported_at`·`origin_cd`만 줍니다. 요청 → 반입 연결은 PlanCollectMapper의 `APPLIED_IMPORT_ID`에만 있습니다. 그때까지 프런트는 isNew=false로 둡니다.
- **[이관: 기획]** 'new'의 정의를 정해야 합니다.
  - ① 수집 요청으로 반입된 것만인지, 관리자가 직접 올린 반입도 포함하는지
  - ② 7일을 반입 시각부터 168시간으로 셀지, KST 날짜 7일로 셀지
  - ③ 모든 사람에게 같은 7일인지, 요청한 사람에게만인지
  - 디자인은 '수집 요청 반입만, 모두에게, KST 날짜 기준 반입일 포함 7일'을 가정했습니다.
- **[이관: 기획]** 최근 실패·제외(last_closed)를 목록 3행에도 보일지 정해야 합니다. 디자인 권장은 '보임'(요청 가능한 사람만, 서버가 이미 그렇게 거름)입니다.
- **[이관: 개발]** 행 패딩·3행 추가·h3→h4 이후 기존 시험 단언(`frontend/test/plans*.test.js`의 rowHtml·detailHtml 문자열)이 깨질 수 있습니다. frontend-dev가 함께 고칩니다.

## 8. 디자인 쪽 열린 질문
- 'new' 칩의 화면 글자: 사용자 예시대로 영어 **`new`**(권장, 원문 존중, 38px)로 할지, 한국어 **`새 자료`**(56px, 화면 전체가 한국어)로 할지. 어느 쪽이든 낭독은 "새로 들어온 자료"입니다.
