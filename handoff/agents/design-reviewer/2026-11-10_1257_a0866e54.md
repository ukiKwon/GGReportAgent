# 제안팀 구성·배정 화면 규격 (design-reviewer, 2026-11-10)

## 1. 대상·방법·못 본 것
- **방법**: 소스만 읽었다. 읽은 파일은 `PRODUCT.md`, `DESIGN.md`, `.impeccable/config.json`, `frontend/js/nav.js`·`approvals.js`·`app.js`(showSoon), `frontend/index.html`(CSS·#tab-soon), `BidAssignmentController/Service.java`, `ApprovalRequestService.java`(변경 신청 부분), `BidCaseController.java`, `serverdata.js`(applyBidCases), `docs/design_history/index.html`이다. impeccable 런처는 Bash가 없어 돌리지 못했고, 프로젝트 문맥은 위 파일을 직접 읽어 잡았다.
- **못 본 것**: 화면이 아직 없다. 서버(8080)는 열어도 된다는 허락이 없어서 Playwright로 열지 않았다. 대비 숫자는 토큰 hex로 계산한 값이고, 렌더된 화면을 잰 값이 아니다. `Pii.scan`이 무엇을 잡는지, 결재자를 고르는 규칙의 끝부분(leadInvolved일 때 어느 역할이 결재하는지)은 끝까지 읽지 않았다. 그래서 문구에서 이 둘을 단정하지 않았다.
- **위치 확인**: `nav.js`의 `manage`(제안서 관리) › 중분류 `제안팀` › `soon('제안팀', '제안팀 구성·배정')`이다. 지금은 id `soon:제안팀 구성·배정`, 배지 '준비중'이고 영업 계열(영업팀·영업팀장·영업부장·디자이너·마스터)에게 보인다.

## 2. 한 줄 총평과 가장 큰 기회
서버 API가 `viewer` 플래그(can_assign·can_request_change·is_assignee)를 돌려줘서, 화면은 버튼을 보일지 말지만 판단하면 된다. 결재함 패턴을 그대로 다시 쓸 수 있다. 다만 **담당자 후보 목록 API가 없어서 (2)·(4)의 체크 목록을 그릴 수 없다(P0)**. 가장 큰 기회는 다음과 같다. 입찰 건 목록을 **임박도 순(D-day 배지)**으로 세우면, 이 화면이 아무 제품의 "팀 배정"이 아니라 "급한 입찰부터 사람을 붙이는" 이 제품의 화면이 된다(PRODUCT 원칙 3).

## 3. 점수표 / 잘 된 점
- 점수표: 화면이 없어 매기지 않는다. 구현 뒤 검토에서 매긴다.
- 잘 된 점
  1. 버튼 자격을 서버가 정한다(`viewer.*`). approvals.js의 `can_decide`와 같은 원칙이라 화면 쪽 권한 해석이 없다.
  2. 오류에 `code`가 붙는 것(ASSIGNED_ALREADY 등)이 있어 업무 말투 문구를 붙이기 쉽다. 서버 문구에는 사번·이름이 실리지 않는다.
  3. 이력에 `emp_verified`가 있어 "자기신고" 꼬리표를 정직하게 표시할 수 있다.

## 4. 우선순위 이슈 (구현 전 설계 이슈)
- **P0 담당자 후보 목록 API 없음**
  - 근거: 담당자 후보(영업팀·영업팀장 ACTIVE)를 영업팀장이 받을 엔드포인트가 없다. `GET /users`는 SysAdminController의 `guard.require` 뒤에 있고, `GET /approval-deputies/candidates`(ApprovalDeputyService:73)는 전 사용자를 주면서 **본인을 뺀다**. 반면 팀장은 자기 포함 배정이 허용된다(`SELF_REASON "팀장 자기 포함 배정"`).
  - 왜 문제: 최초 배정 체크 목록과 변경 신청의 '추가할 담당자' 목록을 그릴 수 없다.
  - 방향: 이관(개발).
- **P1 진행 중 변경 신청에 이름이 없음**
  - 근거: `pending_change`가 `add_emp_nos`·`remove_emp_nos`·`requested_by`를 사번으로만 준다(Service:518–521).
  - 왜 문제: 해제 대상은 현재 담당자 목록과 맞춰 이름을 찾을 수 있지만, 추가 대상과 신청자는 후보 API 없이는 이름을 알 수 없다. 사번만 보이면 업무 언어가 아니다.
  - 방향: 아래 규격에서는 우선 "추가 n명 · 해제 n명"처럼 인원 수만 보이고, 이름을 찾을 수 있을 때만 이름을 보인다. 이름을 실어 줄지는 이관(개발).
- **P1 결재함 카드 제목에 내부 id 노출**
  - 근거: `r.setTitle("담당자 변경 — " + plan.getBidCaseId())`(ApprovalRequestService:124). 결재함 `requestCardHtml`이 이 제목을 그대로 보인다.
  - 왜 문제: 결재자는 어느 기관 건인지 기관명으로 알아야 한다.
  - 방향: "담당자 변경 — {기관명}". 이관(개발).
- **P1 오류 본문 모양 불일치**
  - 근거: 코드가 붙은 오류는 `detail`이 `{code,message}` 객체다(`coded()`, Service:541). 그런데 approvals.js의 `getJson`/`act`는 `j.detail`을 문자열로 보고 `new Error(j.detail)`를 만든다. 이대로 쓰면 "[object Object]"가 화면에 뜬다.
  - 방향: 이 화면의 오류 해석기는 `detail.code` → 아래 문구 표, 없으면 `detail.message`, 없으면 `detail` 문자열, 없으면 상태별 기본 문구 순으로 읽는다(6절).
- **P2 메뉴는 보이는데 API는 403**
  - 근거: `nav.isSales`는 디자이너·마스터에게 이 항목을 보여준다. 서버 열람은 영업팀·영업팀장·영업부장만이고, 디자이너·관리자는 403이다.
  - 왜 문제: 눌러 볼 수는 있는데 막히는 메뉴가 된다.
  - 방향: 메뉴에서 뺄지는 이관(기획). 빼기 전까지는 6절의 '권한 없음' 상태로 받는다.
- **P2 접근 이력에 남지 않음**
  - 근거: `nav.screenName`은 `soon:*`를 null로 돌린다(nav.js:183). 이사회 자료만 `tasks:board`로 예외다.
  - 방향: 이 화면 열람을 기록할지, 어떤 이름으로 할지는 이관(개발·기획). 디자인 영향은 없다.
- **P3 DESIGN.md와 실제 CSS의 어긋남 (이번 화면에서 발견, 이번 범위 밖)**
  - `.soon-box h2 { font-size:20px }`(index.html:166)이 11–16px 램프 상한(16px)을 넘는다. 이 화면이 #tab-soon을 쓰므로, 이 화면이 열릴 때는 soon-plain이 숨겨져 영향이 없다.
  - `.ad-badge.warn`·`.ad-warn`의 `#e0b44c`(index.html:892·899)는 DESIGN.md에 없는 색이다. DESIGN.md는 결재·게이트 상태에 `--orange`를 쓰라고 한다. 이 화면의 새 배지는 `--orange`를 쓴다(7절).

## 5. 문구 / 접근성

### 5-1. 문구 전체 목록
**화면 머리**
- 제목: `제안팀 구성·배정`
- 머리 옆 힌트(.dg-hint): `— 입찰 건을 고르면 담당자와 배정 이력이 보입니다`

**입찰 건 목록**
- 필터 탭 2개: `전체` · `내 담당`
- 검색칸 placeholder: `기관명 검색`. aria-label도 같은 글.
- 항목 보조 줄: `{지역} · {참여 상태}`. 내가 담당인 건에는 칩 `내 담당`.
- 개수: `{n}건`(mono)
- 비어 있음
  - 전체: `입찰 공고가 등록된 기관이 없습니다. 공고가 등록되면 여기에 나타납니다.`
  - 내 담당: `내가 담당인 입찰 건이 없습니다.`
  - 검색: `'{검색어}'와 맞는 기관이 없습니다.`
- 선택 전 오른쪽 안내: `왼쪽에서 입찰 건을 고르세요. 임박한 건이 위에 있습니다.`

**상세 머리**
- `{기관명}`
- 메타: `{지역} · 입찰 예정일 {YYYY-MM-DD}(예상|확정) · {참여 상태}`, 그리고 D-day 배지 `D-{n}`

**담당자 절**
- 절 제목: `담당자`, 옆에 `{n}명`(mono)
- 진행 중 배지: `변경 결재 중`
- 진행 중 안내: `담당자 변경 신청이 결재 중입니다 — 추가 {a}명 · 해제 {r}명. 결재가 끝나면 이 목록에 반영됩니다.` 이름을 찾을 수 있으면 `해제: 홍길동, 김철수`를 덧붙인다.
- 표 머리: `이름` · `직위` · `배정일`. 본인 행 이름 뒤에 `(나)`.
- 배정 전 (영업팀장이 아닐 때): `아직 담당자가 배정되지 않았습니다. 영업팀장이 배정하면 여기에 표시됩니다.`
- 변경 버튼: `담당자 변경 신청`
- 버튼 비활성 사유(진행 중 신청 있음): `결재 중인 변경 신청이 끝난 뒤 다시 신청할 수 있습니다.`
- 자격 없음 안내(영업팀 비담당자·영업부장): `담당자 변경은 현재 담당자 또는 영업팀장이 신청합니다.`

**최초 배정 (영업팀장 · 배정 전)**
- legend: `담당자 선택 (1~10명)`
- 후보 검색 placeholder: `이름 검색`
- 카운터: `{n} / 10명 선택`
- 10명 도달: `최대 10명까지 고를 수 있습니다. 바꾸려면 먼저 한 명을 빼세요.`
- 본인 체크 시: `본인을 포함하면 이력에 '팀장 자기 포함 배정'으로 남습니다.`
- 후보 없음: `배정할 수 있는 영업팀 사용자가 없습니다. 시스템 관리자에게 사용자 등록을 요청하세요.`
- 버튼: `담당자 배정`. 0명이면 비활성이고, 사유는 `한 명 이상 고르세요.`
- 확인 줄: `선택한 {n}명을 담당자로 배정합니다. 배정 뒤에는 담당자 변경 신청(결재)으로만 바꿀 수 있습니다.` 버튼은 `배정 확정` · `취소`
- 성공: `담당자 {n}명을 배정했습니다.`

**담당자 변경 신청 (모달)**
- 제목: `담당자 변경 신청 — {기관명}`
- 소제목 1: `해제할 담당자`
- 소제목 2: `추가할 담당자`. 검색 placeholder는 `이름 검색`이고, 현재 담당자는 이 목록에서 뺀다.
- 미리보기: `변경 후 {k}명 (현재 {c} · 추가 {a} · 해제 {r})`
  - 0명이 되면: `담당자는 최소 1명이어야 합니다. 해제할 사람을 줄이거나 추가할 사람을 고르세요.`
  - 10명을 넘으면: `담당자는 10명을 넘을 수 없습니다. 추가할 사람을 줄이세요.`
  - 아무것도 안 고르면: `추가하거나 해제할 담당자를 한 명 이상 고르세요.`
- 사유 label: `변경 사유 (필수)`, 카운터 `{n}/200`
- 사유 힌트: `사유에는 개인정보(연락처·주민등록번호 등)를 적지 마세요.` 단, 예시 두 개는 Pii 검출 범위를 확인한 뒤 확정한다(이관).
- 결재자 안내: `결재자는 신청 내용에 따라 시스템이 정합니다. 신청 뒤 [결재함 › 내가 올린 요청]에서 결재 진행을 볼 수 있습니다.`
- 버튼: `취소` · `변경 신청 올리기`
- 닫을 때 사유가 적혀 있으면 확인: `적은 사유가 사라집니다. 닫을까요?`
- 성공(화면 위 알림): `담당자 변경을 신청했습니다. 결재가 끝나면 담당자 목록에 반영됩니다.`, 링크 `결재함에서 보기`. 링크는 `approvals.openTab('mine')`으로 결재함을 연다.

**배정 이력**
- 절 제목: `배정 이력`, 옆에 `최근 순`
- 표 머리: `시각` · `내용` · `처리자` · `사유`
- 내용: `{action_name} — {target_name}`. req_id가 있으면 뒤에 `· 결재 반영`(muted).
- 자기신고 칩: `자기신고`. title과 aria-label은 `로그인 신원을 확인하지 않은 기록입니다`. `emp_verified=true`면 **아무것도 붙이지 않는다**. '검증됨'은 쓰지 않는다.
- 사유 없음: `-`
- 비어 있음: `아직 배정 기록이 없습니다.`

**상태·권한 문구**
- 불러오는 중: `불러오는 중…`
- 목록 오류: `입찰 건 목록을 불러오지 못했습니다.`, 버튼 `다시 시도`
- 상세 오류: `담당자 정보를 불러오지 못했습니다.`, 버튼 `다시 시도`
- 401: `로그인이 필요합니다. 사번으로 로그인해 주세요.`(approvals.js와 같은 글)
- 403(열람): `이 화면은 영업팀·영업팀장·영업부장이 쓰는 화면입니다. 지금 계정({역할 이름})으로는 볼 수 없습니다.`
- 서버 없음(file://): `서버에 연결된 상태에서만 쓸 수 있는 화면입니다.`

### 5-2. 접근성 (대비는 토큰 hex로 계산한 값)
- 대비
  - `--fg` on `--panel` 13.4:1
  - `--muted` on `--panel` 6.4:1, on `--panel2` 5.7:1
  - `--red` 오류 글자 on panel 5.6:1
  - `--orange` 배지 글자 on panel 7.3:1. 18% 틴트 바탕 위에서는 5.2:1
  - `--blue` 5.4:1, 틸 7.0:1
  - 입력 테두리 #626d81은 3:1(DESIGN.md)
- 목록
  - `<ul>` 안의 각 항목은 `<button type="button" class="tm-item">`이다.
  - 선택된 항목에 `aria-current="true"`를 단다.
  - Tab으로 항목 사이를 옮기고 Enter·Space로 선택한다.
  - 필터는 approvals와 같은 `role="tablist"`·`role="tab"`·`aria-selected`다.
- 상세 영역은 `<section aria-labelledby="tm-case-title">`이다. 불러오는 동안 `aria-busy="true"`를 단다. 선택이 바뀌어도 포커스를 옮기지 않는다(목록에 둔다).
- 체크 목록
  - `<fieldset><legend>`로 묶는다. 행 전체를 `<label>`로 감싸고 행 높이를 32px 이상으로 한다(타깃 기준 24px 충족).
  - 카운터는 `aria-live="polite"`다.
  - 10명에 도달해 비활성이 된 체크박스에는 `aria-describedby`로 상한 안내를 연결한다.
- 비활성 버튼에는 `aria-describedby`로 사유 문장을 연결한다. 버튼을 숨기지 않고 이유를 보인다(approvals.inboxNotice와 같은 원칙).
- 모달
  - `role="dialog"`, `aria-modal="true"`, `aria-labelledby`로 제목 h3를 가리킨다.
  - 열리면 첫 체크박스에 포커스를 둔다. 해제 목록이 비면 추가 검색칸에 둔다.
  - Tab은 모달 안에서만 돈다. Esc로 닫되, 사유가 있으면 확인을 거친다. 닫으면 `담당자 변경 신청` 버튼으로 포커스를 돌린다.
- 오류는 `role="alert"`(.ap-err), 성공 알림은 `role="status"`(.ad-flash)다.
- 색 하나로만 뜻을 전하지 않는다. 진행 중 배지·자기신고·D-day·(나)는 모두 글자다. 임박은 색에 더해 `D-n` 글자로 보인다.
- 사유 textarea에 `maxlength="200"`, `aria-required="true"`, `aria-describedby`(힌트+카운터)를 단다. 422이면 `aria-invalid="true"`.
- **esc() 필수 항목**: 기관명, 지역, 참여 상태, 이름(name·target_name·actor_name), 직위, action_name, 사유, 검색어, innerHTML로 넣는 서버 오류 문구. 가능하면 textContent로 넣는다.

### 6-8. design_history 전/후 장 문안 (메인이 다음 장으로 붙이기)
- 제목: `⑪ 제안팀 구성·배정 화면 (YYYY-MM-DD, 커밋 ……)`
- 왜: `[제안서 관리 › 제안팀 › 제안팀 구성·배정]은 '준비중' 안내만 열렸습니다. 입찰 건마다 누가 담당인지 정할 곳이 없어 서버에만 배정 기능이 있었습니다. 이제 입찰 건을 고르면 담당자 배정·변경 신청·이력을 한 화면에서 봅니다.`
- **전**: 사이드바 항목 옆에 '준비중' 빗금 배지가 있었다. 누르면 가운데에 "제안팀 구성·배정 / 아직 제공되지 않는 기능입니다…" 문장만 나왔다. 할 수 있는 일은 0개였다.
- **후**: 배지가 없어졌다. 왼쪽(270px)은 입찰 건 목록으로 임박 순이고 D-day 배지가 붙는다. 오른쪽에 담당자 표, '변경 결재 중' 주황 배지, 배정 이력 표가 있다. 영업팀장은 체크 목록으로 1~10명을 고르고 확인한 뒤 배정한다. 담당자와 팀장은 사유를 적어 변경을 신청하고, 결재자는 시스템이 정한다. 이력에서 신원을 확인하지 않은 기록에는 '자기신고'가 붙는다.
- **대비 숫자**: 본문 13.4:1, 보조 글자 6.4:1(기준 4.5:1). '변경 결재 중' 배지 글자는 18% 바탕 위 5.2:1, 오류 글자 5.6:1. 입력 테두리 3:1(기준 3:1). 후보 행 높이 32px(기준 24px).
- 모의 화면 제안: 기존 `.side`·`.card`·`.tbl` 클래스로 '전'에는 가운데 문장 한 줄, '후'에는 목록 2개 + 담당자 표 2행 + 주황 `.pill`을 그린다.
