## 5. 우선순위 이슈

**P2-1 [협약 개시일 적기…]가 고친 값을 조용히 버린다**
- 근거: kbboard.js 2910–2916 chTermGo는 `d.done = true; root.dlg.close(...)`로 창을 닫는다. 이때 `d.items`의 touched 여부와 결재 쪽 사유 글(d.reason)을 보지 않는다.
- 왜 문제인가: 구분 셋·메모 둘을 고치다가 한 줄의 개시일 단추를 누르면 나머지 입력이 경고 없이 사라진다. 결재 사유도 같다.
- 수정 방향(택1, 권장은 a):
  - a. 고친 값이 있으면(`d.items.some(x => x.touched)` 또는 사유 칸에 글이 있음) 창을 닫지 않는다. 그리고 #tc-err에 다음을 쓴다: **'고친 내용을 먼저 [수정하기](결재 칸이면 [결재 요청])로 보낸 뒤 협약 개시일을 적으세요. 지금 창을 닫으면 고친 내용이 사라집니다.'** 포커스는 그 단추에 남긴다.
  - b. 기존 dm-leave 패턴('저장하지 않은 ○○이 있습니다' [버리고 닫기][계속 입력])을 창 안 펼침으로 띄운다.
  - 고친 것이 없으면 지금처럼 바로 넘어간다.

**P2-2 관심 줄 동작 단추 간격**
- 근거: index.html 2469에는 `.hb-tag[data-act="unwatch"] { margin-left:6px; }`만 있다. kbboard.js 930의 [메모 고치기…]에는 여백 규칙이 없고, 마크업이 공백 없이 이어진다.
- 그래서 생기는 일:
  - [관심에서 빼기…]와 [메모 고치기…]의 테두리가 0px로 붙는다(폭과 무관).
  - [목표로 옮기기]가 없는 줄(movable 아님)에서는 첫 단추가 6px 들여 쓰여 열 정렬이 어긋난다.
  - 1279px 이하에서 줄바꿈되면 위아래 간격이 0이다.
- **CSS가 필요하다.** 1279px 이하 줄바꿈 간격도 이 규칙이 함께 해결한다.
- 수정 방향은 아래와 같다. 순서는 P3-4를 따른다.
  ```html
  <td><div class="hb-wacts">{목표로 옮기기}{메모 고치기…}{관심에서 빼기…}</div></td>
  ```
  ```css
  .hb-wacts { display:flex; flex-wrap:wrap; gap:4px 6px; align-items:center; }
  /* 2469 .hb-tag[data-act="unwatch"] { margin-left:6px; } 는 지운다 */
  ```
  - 단추 높이는 .hb-tag min-height 24px 그대로라 터치 24px 기준을 통과한다. 세로 간격 4px는 표 줄 안 밀도(DESIGN 4px 단위)에 맞춘 값이다.
  - 'sr-only 목표로 옮길 시기 아님' 문장은 묶음 밖 앞에 둔다.

**P3-1 (③) 목표가 아닌 기관의 [입찰 현황판에서 열기]에 누르기 전 단서가 없다**
- 근거: dashboard.js 1044–1046은 c.goal이 거짓이면 단추만 그린다. 설명은 도착한 뒤 flash(kbboard.js 1888)에서야 나온다.
- 수정: c.goal이 거짓일 때 단추 뒤에 다음을 둔다.
  ```html
  <span class="db-why">목표 기관이 아닙니다. 입찰 현황판의 [목표 기관 추가]로 넣은 뒤 제안 사전준비를 합니다.</span>
  ```

**P3-2 (④) 실패 배너에 기관 이름이 없다**
- 근거: dashboard.js 1565 대체 문구는 '제안 확정하지 못했습니다(…)'이고, kbboard.js 2750은 `say(f.msg, true)`를 그대로 쓴다.
- 고른 줄이 화면 밖에 있을 수 있어 기관 이름이 필요하다(규격 B와 같은 이유).
- 수정: kbboard.js에서 `say(e.name + ' 제안 사전준비: ' + f.msg, true)`로 쓴다. f.msg에 이미 기관 이름이 있으면 붙이지 않는다.

**P3-3 (⑨) can_view=false 안내 문장이 모호하다**
- 지금: '이 건은 지금 계정으로는 열 수 없어 목록에서 확인하세요.'
- 바꿀 문구: **'지금 계정으로는 이 건의 상세를 열 수 없습니다. 진행 상황은 [제안 준비 현황] 목록에서 확인하세요.'**

**P3-4 관심 줄 단추 순서와 말줄임**
- 순서: 무거운 동작을 오른쪽 끝에 둔다(규격 A 원칙). 그래서 [목표로 옮기기] → [메모 고치기…] → [관심에서 빼기…] 순으로 한다.
- [목표로 옮기기]도 창을 여는데(aria-haspopup="dialog", kbboard.js 925) '…'가 없다. 옆 두 단추와 맞춰 **'목표로 옮기기…'**로 한다. 시험 단언이 있으면 같이 고친다.

**P3-5 세그먼트 sr 문장이 다른 칸 이유를 읽을 수 있다**
- 근거: tchange.js 459·456. `tc-mode-why2`는 approval 라디오에만 걸려 있다. 그런데 바로 반영 칸이 꺼진 경우 그 이유(av.edit.why)를 담는다.
- 결과: 결재 칸에 포커스가 가면 '관심 기관이 섞여 있어 고칠 수 없습니다'라는 남의 이유를 읽는다.
- 이유는 이미 label 안 `small`에 있어 접근 이름에 들어간다. 그래서 수정은 `tc-mode-why2` span과 aria-describedby를 **지우는 것**이다(시험 단언이 있으면 함께).
