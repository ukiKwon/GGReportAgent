## 3. 사용자 질문 답: 동작구청은 공고가 안 났는데 왜 [목표에 넣기]가 되나
결론: **설계대로입니다.** 목표에 넣는 조건에 '공고'는 아예 들어 있지 않습니다. "협약 종료 2년 안"도 정확한 표현은 아니고, **협약이 끝나는 연도가 목표로 고를 수 있는 연도 안에 있으면** 공고 전에도 목표에 넣을 수 있습니다.

`kbb.popCanAdd`(kbboard.js:205–209)가 보는 조건은 아래가 전부입니다.
- ① 아직 목표·관심 칩이 없다.
- ② 영업부서 편집 권한이 있다.
- ③ '협약 예정(2027년부터)' 줄이 아니다.
- ④ '다음도 국민은행' 줄이 아니다.
- ⑤ 올해 입찰이 이미 끝난 기관이 아니다. 단, 제안이 진행 중이면 이 조건으로 숨기지 않습니다.
- ⑥ `kbb.moveYear(it.endDate, years)`(kbboard.js:512–515): 협약 종료일의 **연도**가 고를 수 있는 연도 목록에 들어 있다.

고를 수 있는 연도는 서버의 `selectable_years`입니다. 서버가 주지 않으면 [올해, 내년, 내후년]을 씁니다(`selYears`, kbboard.js:1291–1294). 2026년 기준으로는 협약 종료가 2026–2028년이면 버튼이 보입니다. 날수로 2년이 아니라 연도 단위라 최대 약 3년 앞까지입니다.

목표는 공고가 나기 전에 재유치 대상을 미리 정해 두는 용도라는 뜻이 코드 주석에 있습니다(kbboard.js:218, 1304). 버튼을 누르면 '목표·재유치 도전'으로 채운 추가 창이 열립니다(kbboard.js:2174).

[목표에 넣기]와 [제안 확정]은 서로 다른 관문입니다. [제안 확정]은 공고가 난 뒤에만 열리고(dashboard.js:368–389), 예외는 올해 목표 기관 하나입니다(dashboard.js:372, 389). 동작구청이 올해(2026) 목표로 들어가면 공고 전에도 [제안 확정]이 열리고, 아래 3번 확인 상자가 붙습니다.

## 4. 항목별 규격

### 4-1. '다음도 국민은행'을 '국민은행 확정'으로 바꾸고 은행 CI 칩으로
**지금:**
- `kbb.staysText`(kbboard.js:200–204)가 '다음도 국민은행'을 돌려줍니다.
- 칩은 `.hb-slot.hb-stay`(index.html:1937)입니다. 12px, 글자색 `--fg`, 테두리 `--line-strong`이고 색이 없습니다.

**문구:**
- 보이는 글자는 `국민은행 확정` 하나입니다.
- 화면 읽기 프로그램용으로 칩 안에 `<span class="sr-only"> (다음 협약)</span>`를 덧붙입니다. 이 줄은 지금 협약 중인 기관 목록 안에 있어서, 지금 협약을 말하는지 다음 협약을 말하는지 들어서 알 수 있어야 하기 때문입니다.
- `kbb.staysText`의 반환값만 바꾸면 됩니다. 빈 후보 주석(kbboard.js:667)과 popCanAdd·renderOurs 주석의 '다음도 국민은행'도 같이 고칩니다.

**마크업:**
```
<span class="hb-slot hb-bank" data-bank="kb">국민은행 확정<span class="sr-only"> (다음 협약)</span></span>
```
- `data-bank` 값은 은행 코드(kb, bnk, …)입니다.
- 다른 은행 칩도 같은 모양으로 씁니다: `<span class="hb-slot hb-bank" data-bank="…">○○은행 확정</span>`
- 지금 `leavesText`(kbboard.js:33–36)는 연도만 갖고 있고 은행 이름이 없습니다. 은행 이름이 없으면 지금의 '다음은 다른 은행'(빨간 윤곽, index.html:1936)을 그대로 둡니다. 이 부분은 7번 이관 메모로 넘깁니다.

**색 규칙(사용자 예외):**
- DESIGN.md '새 색 0개·채도 독점'의 **사용자 예외(11-19)**로, 은행 CI 묶음 하나만 추가합니다.
- 쓸 곳은 **`.hb-bank` 칩 하나**뿐입니다. 행 바탕, 버튼, 지도, 표 머리에는 쓰지 않습니다.
- 상태 칩(색 글자 + 1px 테두리 + 18% 틴트)과 달리 **CI로 채운 칩**입니다. 모양이 달라서 상태 색과 헷갈리지 않습니다. 예를 들어 부산은행 빨강과 임박 `--red`가 섞일 걱정이 없습니다. 칩에 은행 이름이 늘 들어가므로 색만으로 뜻을 전하지도 않습니다.
- 은행 하나에 변수 세 개를 둡니다. `:root`에 추가하고, 동결된 변수 이름은 건드리지 않습니다.
  - `--bk-<코드>`: 칩 바탕(CI 원색)
  - `--bk-<코드>-ink`: 칩 글자
  - `--bk-<코드>-edge`: 칩 테두리 1px

**등급 판정**(CI를 흰 바탕에 놓았을 때의 대비로 정합니다):

| 등급 | CI 대 흰 바탕 | 바탕 | 글자(ink) | 테두리(edge) |
|---|---|---|---|---|
| A 진한 CI | 4.5:1 이상 | CI | `#ffffff`(CI 위 4.5:1 이상) | CI |
| B 중간 | 3–4.5:1 | CI | `#ffffff`와 `--fg`(#1e2124) 중 CI 위 대비가 4.5:1 이상인 쪽 | CI |
| C 밝은 CI(노랑·연두 등) | 3:1 미만 | CI | `--fg`(CI 위 4.5:1 이상 필수) | 그 은행의 보조 CI가 흰 바탕에서 3:1 이상이면 그 색, 아니면 `--line-strong` |

- B에서 둘 다 4.5:1이 안 되면 C로 내립니다.
- 밝은 CI는 **바탕에만** 쓰고, 글자에는 쓰지 않습니다.

**국민은행 예시(가정값):** KB 노랑 #FFBC00과 KB 회색 #60584C로 계산했습니다. data-auditor 확정값으로 다시 계산해야 합니다.
- 노랑은 흰 바탕에서 약 1.7:1이라 **C등급**입니다.
- `--fg` 글자를 노랑 위에 놓으면 약 9.6:1로 통과합니다.
- 테두리는 KB 회색 #60584C로, 흰 바탕에서 약 7.0:1입니다.

**CSS 초안:**
```css
:root { --bk-kb:#FFBC00; --bk-kb-ink:#1e2124; --bk-kb-edge:#60584C; }  /* 은행 CI 예외(사용자 11-19) — 값은 data-auditor 확정 후 교체 */
.hb-slot.hb-bank { font-weight:700; border:1px solid var(--bk-edge); background:var(--bk-bg); color:var(--bk-ink); }
.hb-slot.hb-bank[data-bank="kb"] { --bk-bg:var(--bk-kb); --bk-ink:var(--bk-kb-ink); --bk-edge:var(--bk-kb-edge); }
@media (forced-colors: active) { .hb-slot.hb-bank { border-color:CanvasText; } }
```
- 글자 크기는 12px 그대로입니다(DESIGN 최소 12px).
- 굵기 700은 채운 칩 안에서 글자가 묻히지 않게 하려는 것입니다.

**시험 포인트:**
- `staysText`가 '국민은행 확정'을 돌려준다.
- 'KB 유지'·'부산은행 유지'·'수성 실패' 같은 기존 경계 사례가 그대로 지켜진다(qa 11-17 P3-3).
- `index.html`의 `--bk-*` 값을 읽어 각 은행마다 ink 대 bg ≥ 4.5와 edge 대 흰 바탕 ≥ 3을 자동으로 확인한다. 색 값을 바꿔도 대비가 깨지지 않게 하는 장치입니다.
- DESIGN.md 색 절에 '은행 CI 예외' 한 줄과 은행별 표를 넣는다. 메인이 반영합니다.

### 4-2. '국민은행 확정' 줄에도 [관심에 넣기]
**규칙:**
- [목표에 넣기]는 지금처럼 숨깁니다(popCanAdd의 `!staysText`는 그대로).
- 새로 `kbb.popCanWatch(it, o) = !o.mark && !!o.can && !!kbb.staysText(it.rec, o.verified)`를 둡니다.
  - 관심에는 연도가 없으므로 `moveYear`와 '올해 입찰 종료' 조건은 걸지 않습니다.
  - 이미 '관심'이나 '목표' 칩이 있으면 버튼을 두지 않습니다.

**마크업**(rowHtml의 `add` 자리, 둘 중 하나만 나옵니다):
```
<button type="button" class="hb-tag add" data-act="owatch" data-inst="{rid}" data-key="{key}" aria-label="{기관명} 관심에 넣기">관심에 넣기</button>
```
- 모양은 [목표에 넣기]와 같은 점선 테두리(`.hb-tag.add`)이고, `li.hb-rl` 격자도 그대로 씁니다.

**동작:**
- kbboard.js:2174 옆에 `owatch` 분기를 추가합니다: `closePop(false); openAdd({ id: inst, kind: 'WATCH', opener: $('hb-ours-btn') })`
- 결과는 기존 관심 추가 흐름을 그대로 탑니다: 관심 탭으로 이동하고 `flashWatchAdded` 알림이 뜹니다(kbboard.js:1906–1909).

**문구 일관성:** 팝업 버튼은 '관심에 넣기', 추가 창의 주버튼은 '관심 기관에 넣기'(kbboard.js:1110)입니다. 지금 목표 쪽이 '목표에 넣기'로 양쪽이 같으므로, 관심도 사용자 원문 그대로 둡니다.

**시험 포인트:**
- stays 줄에는 `owatch`만 있고 `oadd`는 없다.
- 이미 '관심' 칩이 있는 stays 줄에는 버튼이 없다.
- 읽기 전용 역할에서는 버튼이 없다.
- 누르면 추가 창이 '관심' 종류로 열리고 기관이 채워져 있다.

### 4-3. 공고 전 [제안 확정] 확인: 기존 확인 상자에 합침
**결정:** 상자를 두 번 띄우지 않습니다. `actHtml`의 `c.confirm` 분기(dashboard.js:972–975) **한 상자 안에서** `c.early`일 때만 모양을 바꿉니다.
- 현황판 상세 팝업(dmRender, dashboard.js:1686)과 대시보드 창(dashboard.js:1165)이 이미 `early`를 넘기고 있어서, 두 곳에 같이 적용됩니다.
- 조건은 `proposeEarly`이고 올해 목표 기관만 해당합니다(`isGoalRec`, dashboard.js:364–366). 사용자 답과 맞습니다.

**`c.early`일 때 상자 구성:**
```
<div class="db-confirm early" role="group" aria-labelledby="db-cf-t">
  <span id="db-cf-t"><b class="db-cf-warn">아직 공고 확인 전입니다. 계속 진행하시겠습니까?</b>
    {기관명}을 제안 대상으로 확정합니다. 확정하면 [영업 추진 준비 › 제안서 사전준비 프로세스]에 이 기관의 준비 건이 생깁니다. 개설 신청 전까지는 확정한 사람·영업팀장이 취소할 수 있습니다.</span>
  <div class="db-act-row"><button class="db-next" id="db-do">계속 진행</button><button id="db-cancel">취소</button></div>
</div>
```
- 버튼 id(`db-do`·`db-cancel`)는 그대로 둡니다. 클릭 처리(dashboard.js:1618–1619, 1768–1769)와 Esc 처리(1551, 1782)를 고치지 않아도 됩니다.
- 저장 중일 때 `계속 진행`은 disabled가 되고 글자는 `저장 중…`이 됩니다. 일반 상자도 같이 맞추면 좋습니다.
- `early`가 아니면 지금 문구와 [확정하기]를 그대로 둡니다.

**CSS:**
```css
.db-confirm .db-cf-warn { display:block; font-weight:700; color:var(--fg); margin-bottom:4px; }
.db-confirm.early { border-style:solid; border-color:var(--orange); background:color-mix(in srgb, var(--orange) 8%, var(--panel)); }
```
- 기존 상태색 `--orange`를 18% 이하 틴트로 쓰므로 새 색은 0개입니다.
- `--orange`(#8a5c00)는 흰 바탕에서 약 5.6:1이라 테두리 기준 3:1을 넘습니다.
- 경고 문장 자체는 `--fg`이고, 색만으로 전하지 않습니다.

**포커스:**
- 상자가 열리면 지금처럼 `#db-do`로 옮깁니다(dashboard.js:1168, 1701).
- 경고 문장이 `aria-labelledby` 첫머리에 있으므로, 화면 읽기 프로그램은 버튼보다 경고를 먼저 읽습니다.
- Esc와 [취소]는 상자를 닫고 포커스를 `#db-cf`로 돌립니다(기존 동작).
- 버튼을 누르기 전부터 보이는 `EARLY_WHY` 한 줄(dashboard.js:396, 978)은 그대로 둡니다.

**시험 포인트:**
- early이고 confirm이면 '아직 공고 확인 전입니다. 계속 진행하시겠습니까?'와 '계속 진행'이 나온다.
- early가 아닌 confirm이면 '확정하기'가 나오고 경고 문장이 없다.
- 관심 기관이나 다른 해 목표 기관에서는 `act`가 'later'라 상자가 열리지 않는다.
- 두 화면(대시보드 창·현황판 팝업) 모두 Esc를 누르면 포커스가 `#db-cf`로 돌아온다.

### 4-4. 목표↔관심 옮긴 뒤 결과 알림 강조
**지금 문제(소스 근거):**
- (a) `#hb-flash`는 제목 줄 바로 아래, 요약 띠 위에 있습니다(kbboard.js:2209). 모양은 `.db-flash`의 13px `--fg` 글자 한 줄이고 테두리도 바탕도 없습니다(index.html:1526–1527). 표에서 작업하던 눈 위치에서는 멀리 떨어져 있습니다.
- (b) 목표→관심으로 옮기면 탭은 '목표'에 그대로 있고(kbboard.js:1981–1983), 옮긴 줄은 그 표에 없습니다. `applyFocusNext`가 그 줄을 찾지 못하면 포커스가 [목표 기관 추가]로 떨어집니다(kbboard.js:1434).
- (c) 같은 '관심'인데 동작이 서로 다릅니다. 관심에 **추가**하면 관심 탭으로 넘어가지만(1907), 관심으로 **옮기면** 넘어가지 않습니다.

**규격:**

1. **알림 위치.**
   - `#hb-flash`와 `#hb-err`를 요약 띠(`#hb-band`) **아래**, 표(`#hb-goals`) 바로 위로 옮깁니다. id와 `role=status`·`role=alert`는 그대로 둡니다.
   - 알림이 화면 밖에 있으면 `scrollIntoView({block:'nearest'})`로 끌어옵니다. 포커스를 옮기는 경우는 3번이 맡습니다.

2. **알림 모양.** `#hb-flash`에만 적용합니다. `.dm-box .db-flash`는 건드리지 않습니다.
   ```css
   #hb-flash:not(:empty) { display:flex; align-items:center; gap:8px; padding:8px 12px; font-size:13px; color:var(--fg);

   @media (prefers-reduced-motion: reduce) { #hb-flash:not(:empty) { animation:none; } }
   ```
   - 문장 앞에 12×12 SVG 체크 글리프(`currentColor`, 획 1.3)를 둡니다.
   - 색은 기존 상태색 `--blue`만 씁니다(흰 바탕에서 약 6.1:1). 새 색은 0개입니다.
   - 왼쪽 굵은 띠(border-left 3px)는 쓰지 않습니다. 1px 테두리와 틴트만 씁니다.
   - 알림은 지금처럼 다음 동작이 있을 때까지 남겨 둡니다. 저절로 사라지지 않습니다.

3. **목표→관심으로 옮긴 경우.**
   - 탭은 바꾸지 않습니다. 목표 표를 차례로 정리하는 흐름을 끊지 않으려는 것입니다.

   - 포커스는 **이 [관심 탭에서 보기] 버튼**으로 옮깁니다. 화면 읽기 프로그램이 결과 문장과 다음 행동을 함께 읽습니다. 지금 떨어지는 [목표 기관 추가]는 쓰지 않습니다.

   - 문장 끝의 `warnFlash`는 지금처럼 붙입니다.

4. **관심→목표로 옮긴 경우와 관심에 추가한 경우.**

5. **줄과 탭의 잠깐 강조(`hb-just`).**
   ```css
   .hb-tt tbody tr.hb-just > *, .hb-tt tbody tr.hb-just > td.ln { animation:hbJust 2.8s ease-out 1 both; }
   [role=tab].hb-just { animation:hbJust 2.8s ease-out 1 both; }

   @media (prefers-reduced-motion: reduce) { .hb-tt tbody tr.hb-just > *, [role=tab].hb-just { animation:none; background:color-mix(in srgb, var(--accent-color) 10%, var(--panel)); } }
   ```
   - 약 1.5초 머문 뒤 1.3초에 걸쳐 사라집니다. 사용자 동작에 대한 응답 모션입니다.
   - 줄을 고정한 칸 `td.ln`은 `--rowbg` 변수를 쓰므로(index.html:1792) 같은 애니메이션을 따로 겁니다.
   - 동작 줄이기 설정에서는 정지 틴트로 보이고, 다음 렌더 때나 4초 뒤 JS가 클래스를 떼면 사라집니다.
   - 선택 행 모양(틴트 13% + 왼쪽 3px 막대, index.html:1596)과 헷갈리지 않도록 막대 없이 틴트만 씁니다.

**접근성:**
- `role=status`는 유지합니다. 버튼 같은 조작 요소는 상태 영역(`#hb-flash`) 바깥 형제 요소로 둡니다. 예를 들어 `<div class="hb-note"><div id="hb-flash" role="status">문장</div><span id="hb-flash-act">버튼</span></div>`처럼 나누어, 상태 영역이 버튼 이름까지 읽지 않게 합니다.
- 그러면 위 2번 CSS는 바깥 `.hb-note`에 겁니다. 비었을 때 숨기는 조건은 `.hb-note:has(#hb-flash:empty)`를 쓰거나 JS로 `hidden`을 붙입니다.

**시험 포인트:**
- 관심으로 옮긴 뒤 `document.activeElement`가 [관심 탭에서 보기]다.
- 그 버튼을 누르면 관심 탭으로 가고 그 줄이 포커스·강조된다.
- 목표로 옮긴 뒤 그 줄 `<tr>`에 `hb-just`가 붙는다.
- DOM 순서가 `#hb-band` → `#hb-flash` → `#hb-goals`이다.
- 동작 줄이기 설정에서 `animation:none`이 적용된다.
