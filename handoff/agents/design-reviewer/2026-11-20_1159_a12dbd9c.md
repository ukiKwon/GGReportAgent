## 2. 한 줄 총평
규격 보정 1–9와 팀 결정 5건(단추 [취소][n곳 요청], 오류 줄 .dlg-note, 보내는 중 Esc·바깥 클릭 허용, 20초 제한, 받는 중 aria-disabled)은 문구까지 거의 그대로 들어갔다. 고칠 것은 P2 3건이다.

가장 큰 기회: 행에 `scroll-margin-top` 한 줄을 더하는 것. 묶음 머리를 넣은 이 개편의 핵심인 '그룹 안에서 키보드로 훑기'가 그래야 성립한다.

## 4. 우선순위 이슈

**P2-1 키보드 이동 시 행이 sticky 머리에 가려짐 (WCAG 2.4.11)**
- 근거: `.pl-gh { position:sticky; top:0; min-height:28px }`(index.html:2481), 선택 행 스크롤은 `o.scrollIntoView({ block:'nearest' })`(plans.js:1021).
- 왜 문제인가: ↑로 올라가면 행이 스크롤 칸 맨 위(top 0)에 붙는다. 머리 약 28–30px가 행 첫 줄(기관 이름 20px)을 덮는다.
- 수정: `#plans-root [role=group] > .db-row { scroll-margin-top:30px; }` (scrollIntoView가 scroll-margin을 따른다).

**P2-2 '직접 연 기관' 점선 경계가 사라짐 (사용자 11-16 요청의 회귀)**
- 근거: 기존 규칙 `#plans-root .db-row[data-pin="1"] + .db-row { border-top:1px dashed … }`(index.html:2465)는 형제 선택자다. 이제 pin 행은 `<ul role=group aria-label="직접 연 기관">` 안에 따로 있고 다음 행은 다른 ul에 있어(plans.js:886, 892) 이 규칙이 맞지 않는다.
- 왜 문제인가: 정렬을 켜면 묶음 머리가 경계 노릇을 한다. 하지만 정렬을 끄면(.pl-flat) 경계가 실선과 같아진다.
- 수정: pin ul에 `class="pl-pinned"`를 주고 `#plans-root .pl-pinned + ul > .db-row:first-child { border-top:1px dashed var(--line-strong); }`. 낡은 2465 규칙은 지운다.

**P2-3 보내는 중 [취소]만 막힘 (DESIGN.md 팝업 계약과 다름)**
- 근거: `paintDlg`에 `cancel.disabled = d.busy`(plans.js:1201)가 있고, 클릭 처리 `if (!d.busy) requestClose`(1193)도 있다. 그런데 팀 결정은 보내는 중 Esc·바깥 클릭을 허용한다. DESIGN.md 100행은 "[닫기]·[취소]·Esc·바깥 클릭은 같은 동작(requestClose)"이다.
- 왜 문제인가: 마우스 사용자는 바깥을 눌러야만 닫을 수 있고, 눈에 보이는 [취소]는 회색이다. 닫아도 결과가 띠로 오도록 이미 만들어 두었으므로(1225) 막을 이유가 없다.
- 수정: 보내는 중에도 [취소]를 살리고 1193의 `!d.busy` 조건을 뺀다. 글자는 '취소' 그대로 둔다. 요청 자체는 취소되지 않으니 아래 P3-5 문구로 보완한다.

**P3-1 확인 창 '구분' 칸 '그 밖'** (plans.js:451 `kindLabel`)
정렬을 끄면 대부분 행에 이 말이 붙는다. 잘린 말처럼 읽힌다. 묶음 머리와 같은 '그 밖의 기관'으로 바꾸거나, muted로 '—'를 쓴다.

**P3-2 숫자 불일치**
정렬을 켜고 표시된 기관을 직접 열면 숫자가 1 어긋날 수 있다.
- 요약줄은 '목표·관심 **13**곳을 위로'다. `marks`를 vr.base에서 센다(874).
- 묶음 머리는 '목표·관심 **12**곳'이다. pin을 뺀 tops로 센다(889).
- 수정: 요약줄도 pin을 포함한 같은 모집단으로 맞춘다. 표시 규칙만 고르면 된다(두 숫자를 같은 기준으로).

**P3-3 #pl-bat-none 포커스 표시 없음**
`#pl-foot #pl-bat-none:focus { outline:none; }`(2489) 때문에 창을 닫은 뒤 포커스가 어디 있는지 보이지 않는다. `:focus-visible { outline:2px solid var(--accent-color); outline-offset:2px; }`로 바꾼다.

**P3-4 안 눌린 정렬 토글의 경계가 약함**
배경 --bg와 흰 패널의 대비가 1.19:1, 테두리 --line과 --bg의 대비가 1.4:1이다. 글자(7.3:1)로는 알아볼 수 있지만, 눌림 상태(파랑 테두리 6.8:1)와 견주면 '단추'로 덜 읽힌다. 권장: 안 눌림 테두리를 `--line-strong`(4.5:1)으로 한다. 새 토큰은 필요 없다.

**P3-5 낡은 CSS·주석**
- 2466 주석 "목록 3행"은 이제 2줄이다.
- `#plans-root .db-row .pl-st { grid-column:1/-1 }`(2469)는 .pl-st가 display:contents가 되어 쓸모가 없다(2485).
- 머리 border-bottom 1px과 첫 행 border-top 1px이 겹쳐 2px 선이 된다. `.pl-gh + .db-row { border-top:0; }`를 권장한다.

## 5. 문구 / 접근성

### 문구 (규격 대조)
- 일치: 머리 '기관 목록', 토글 '목표·관심 먼저'/'목표 먼저', 묶음 머리 3종, 요약줄 5종, 바닥 버튼 3종과 근거 줄, 확인 창 제목·안내·50 초과 경고·'뺀 곳', 결과 문구 6종, 400 문구.
- 다름(P3) — 받는 중 안내 말투가 셋으로 갈린다.
  - 토글 title: '목표·관심 기관을 불러오는 중입니다.'(861)
  - 바닥: '목표·관심 기관 목록을 받는 중'(436, 마침표 없음)
  - 오류 띠: '…목록을 받지 못했습니다.'
  - → 바닥을 '목표·관심 기관 목록을 받는 중입니다.'로 맞추고, 동사는 '받다'로 통일한다.
- 시간 초과 문구 '목록을 새로 고친 뒤 다시 확인하세요.'(503): 화면에 '새로 고침' 단추가 없고, 코드가 이미 `ensureCollect(true)`로 자동 갱신한다. 권장: '응답이 늦어 결과를 확인하지 못했습니다. 요청은 접수됐을 수 있으니 창을 닫고 바닥 숫자가 줄었는지 확인하세요.'
- P2-3을 반영할 경우, 보내는 중 안내 줄(.dlg-note .dlg-hint)에 '창을 닫아도 요청은 계속 보내지고 결과는 화면 위 띠에 나옵니다.'를 넣는다.

### 접근성
- ARIA 구조는 규격대로다. listbox > ul[role=group][aria-labelledby] > li[role=option], 머리 li는 presentation. 정렬을 끄면 ul.pl-flat이 presentation이고 listbox 이름은 #pl-g(aria-live polite)에서 온다.
- 확인 창: alertdialog, aria-modal, labelledby와 describedby, 제목 tabindex=-1, 표 caption sr-only, 스크롤 영역 tabindex=0 role=region과 focus-visible. 보내는 중 aria-busy.
- 토글: aria-pressed. 사용할 수 없을 때 aria-disabled + title. title은 키보드·터치로 읽을 수 없지만, 실패 때는 띠에 같은 이유가 보이니 받는 중일 때만 남는 틈이다(P3, 그대로 둬도 됨).
- 대비(토큰 계산)
