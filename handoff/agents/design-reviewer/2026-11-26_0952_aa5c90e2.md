## 2. 한 줄 총평과 가장 큰 기회
- **총평**: 지금 있는 DocModel API만으로 샘플에 가까운 모양의 약 80%를 낼 수 있습니다. DocxKit을 꼭 고쳐야 하는 것은 세 가지입니다.
  - 칸 세로 가운데 맞춤을 정식 API로 두는 것(지금은 우회로만 됨)
  - 제목 아래 가로줄
  - '·' 줄 내어쓰기
- **가장 큰 기회**: 2쪽 평가표의 열 폭을 '글자 길이 비례' 규칙으로 정하는 것입니다. 샘플 표를 넣으면 13.75 / 13.75 / 50 / 8.75 / 13.75%가 나와 샘플 실측(15 / 14 / 50 / 9 / 12)과 거의 같습니다. 이 하나로 2쪽 넘침 위험(qa P2-1)이 사라집니다. 이 폭에서 22행은 추정 약 17cm로, 쓸 수 있는 높이 25.7cm 안에 들어갑니다.

**잘 된 점**
- 병합 격자 검증(`Table.layout`)이 탄탄합니다.
- 머리 행 반복(tblHeader)과 행 안 자르기(cantSplit)가 이미 있어서, 표가 길어져 다음 쪽으로 넘어가도 깨지지 않습니다.
- `Cell` 생성자가 public이고 정렬·음영·header 값을 받습니다. 그래서 가로 정렬, 굵게, 글자 크기, 문단 간격은 Builder만 고쳐서 바꿀 수 있습니다.

> 휴리스틱 점수표는 화면이 아니라 인쇄물 규격이라 생략했습니다.

## 3. 사실 확인: 지금 API로 되는 것과 안 되는 것

| 하고 싶은 것 | 지금 기능으로 되나 | 근거 |
|---|---|---|
| 칸 가로 가운데 | **된다**: `new DocModel.Cell(blocks, cs, rs, false, Shade.NONE, Align.CENTER)` | DocxKit `emitPara`의 `a = para.align != LEFT ? para.align : cellAlign` |
| 칸 세로 가운데 | **우회로만 된다**: `header=true` + `Shade.NONE`. docout 안에서 `Cell.isHeader()`는 vAlign에만 쓰이고, 머리 행 반복은 행 번호(headerRows)로 정해짐 | DocxKit `tcPr.addNewVAlign().setVal(cell.isHeader() ? CENTER : TOP)`(grep 결과 docout에서 유일한 사용처) |
| 칸 굵게 | 된다: `Run.bold` | DocModel `Run.bold` |
| 문단별 글자 크기 | 된다: `new Para(runs, bullet, level, size, align)`(6–40pt, 정수) | DocModel `Para` 생성자 |
| 문단 앞뒤 간격 | 된다: `Para.withSpacing(before, after)` | DocModel `withSpacing` |
| 줄 간격(배수·고정) | **안 된다**. w:line을 쓰지 않아 Word 기본(한 줄)이 됨 | DocxKit `emitPara`는 before/after만 씀 |
| 위첨자 | 된다: `Run.sup` | DocModel `Run.sup` |
| 같은 문단 안 글자 크기 섞기 | **안 된다**. 크기는 문단 단위 | `emitRun(p, text, para.getSize(), …)` |
| 제목·문단 아래 가로줄 | **안 된다** | Heading은 keepNext와 spacing만 냄 |
| '·' 줄 내어쓰기, 임의 들여쓰기 | **안 된다**. 들여쓰기는 글머리가 있을 때만, 글머리는 ㅇ·-·■ 세 가지 | `emitPara`의 `if (bullet != NONE)` 안에서만 ind |
| 표 왼쪽 들여쓰기(tblInd) | 안 된다 | `emitTable` |
| 머리 음영 색 바꾸기 | 안 된다. F2F2F2 고정 | `shd.setFill("F2F2F2")` |
| 칸 안쪽 여백 | 고정: 위아래 40tw(2pt), 좌우 100tw | `CELL_MAR_TB/LR` |

**세로 가운데 우회 판단**: 우회는 지금 동작합니다. 다만 e4가 나중에 `header`에 다른 뜻(예: 자동 굵게, 자동 음영)을 붙이면 **v4 확정본 모양이 말없이 바뀝니다**. 그래서 둘 중 하나를 고릅니다.
- e4 요청 R1(정식 vAlign API)을 먼저 받는다.
- 우회를 쓰되, 시험으로 vAlign=center와 음영 없음, 굵기 상태를 고정한다.

### P2-A. 2쪽 평가표 열 폭: 글자 길이 비례 규칙 [현]
- **근거(샘플 2쪽)**: 사진의 열 경계 x = 297 / 448 / 588 / 1082 / 1168 / 1283. 비율은 평가 부문 15.3, 평가 항목 14.2, 세부 평가 항목 50.1, 배점 8.7, 평가 방법 11.7(%).
- **지금 상태**: 균등 폭입니다(`new DocModel.Table(cn, null, …)`). 칸 하나가 약 3.0cm라 '최근 3년간 평균 고정이하여신비율(NPL)' 같은 칸이 3줄로 접히고, 2쪽이 넘칠 위험이 큽니다.
- **규칙(열 수와 상관없이 같은 식)**:
  1. 글자 단위로 길이를 셉니다. 한글, 한자, 전각 문자(U+1100–11FF, U+3000–303F, U+3130–318F, U+AC00–D7A3, U+4E00–9FFF, U+FF00–FFEF)는 2, 나머지(숫자·영문·공백·문장부호)는 1입니다.
  2. 열 k마다 두 값을 구합니다.
     - `H_k` = 머리 행 칸 중 그 열에서 시작하고 cs=1인 칸의 가장 긴 줄(`\n`으로 나눈 줄)
     - `B_k` = 본문 칸 중 c=k이고 cs=1인 칸의 가장 긴 줄. 가로로 병합된 칸(합계 등)은 넣지 않습니다.
  3. 가중치는 `w_k = clamp(max(H_k + 2, B_k), 7, 40)`입니다. 머리 +2는 굵은 글자 여유, 최솟값 7은 숫자 열, 최댓값 40은 긴 서술 열이 다른 열을 누르지 않게 하는 값입니다.
  4. 비율은 `pct_k = w_k / Σw × 100`입니다.
- **샘플로 검산**: 부문 max(11, 11)=11 / 항목 max(11, 11)=11 / 세부 max(14, 72)→40 / 배점 max(6, 3)→7 / 방법 max(11, 6)=11. 합 80이고, 결과는 **[13.75, 13.75, 50.0, 8.75, 13.75]**로 샘플과 1~2%p 안에서 같습니다.
- 숫자 열을 따로 판별할 필요가 없습니다. 짧아서 자연히 7에 붙습니다.
- 열이 1~2개인 표도 같은 식으로 계산하고, 결과가 그대로 쓰입니다.

### P2-B. 2쪽 평가표 칸 정렬·굵게·음영 [현] + 세로 정렬 [우]/[D]
- **근거(샘플 2쪽)**:
  - 부문·항목·배점·방법·합계는 가로·세로 모두 가운데입니다.
  - 세부 항목은 왼쪽 정렬, 세로 가운데입니다.
  - 부문 칸('재무안전성 (10점)')은 굵고, 항목 칸은 보통 굵기입니다.
  - 머리 행은 회색 음영에 굵게입니다.
  - '합계'와 '100'은 보통 굵기입니다.
- **일반 규칙(열 수가 다른 표에도 적용)**:
  - 가로 정렬: `w_k ≥ 30`인 열(긴 서술 열)은 **왼쪽**, 나머지는 **가운데**입니다. 샘플에서는 세부 항목만 왼쪽입니다.
  - 세로 정렬: 본문 칸은 모두 **가운데**입니다. 지금은 `header=true, Shade.NONE` 우회로 하고, R1이 오면 교체합니다.
  - 굵게: 0열에 rs>1인 칸이 하나라도 있으면(= 0열이 묶음 열이면) 그 열 본문 칸을 **굵게** 합니다. 단, 합계 줄(TOTAL_LABELS 칸이 있는 행)은 모든 칸이 보통 굵기입니다.
  - 머리 행: 지금 그대로 `Cell.header`(굵게, F2F2F2, 가운데)입니다. 샘플은 조금 더 진한 회색으로 보이지만 인쇄 가독성에 차이가 거의 없으므로 **바꾸지 않습니다**(DocxKit 변경도 요청하지 않음).
  - 덧붙이는 합계 문단('합계 n점'): 지금처럼 오른쪽 굵게, 변경 없습니다.

### P2-C. 2쪽 글자 크기·간격: 줄 수 추정으로 단계 선택 [현]
- 한 쪽에서 쓸 수 있는 높이는 (PAGE_H − 2×MARGIN) = 14570tw = 728pt입니다. 쪽 나눔 문단, 제목(14pt), ■ 소제목을 빼면 표에 약 **660pt**가 남습니다(안전 여유 10pt 포함).
- **추정 줄 수 L**: 행마다 그 행에서 시작하는 rs=1 칸들의 `ceil(줄 길이 / 칸 용량)` 중 최댓값을 더합니다. 칸 용량(글자 단위)은 `(열 폭 tw − 200) / (글자 pt × 10)`입니다. 병합 칸(rs>1)은 계산에서 뺍니다.
- **단계 선택**: 아래 순서로 보고, 처음으로 들어맞는 단계를 씁니다.

| 단계 | 칸 글자 | 칸 문단 앞/뒤 | 추정 표 높이 |
|---|---|---|---|
| A(기본) | 10pt | 3pt / 3pt | L×13.3 + 행 수×10 |
| B | 10pt | 0 / 0 | L×13.3 + 행 수×4 |
| C(하한) | 9pt | 0 / 0 | L×12 + 행 수×4(L을 9pt로 다시 셈) |

- C로도 넘치면 C를 그대로 쓰고 다음 쪽으로 넘어가게 둡니다. 머리 행은 이미 반복됩니다. **9pt 아래로는 내리지 않습니다**(인쇄 판독 하한).
- **샘플 추정**: L=23(ESG 칸만 2줄), 22행입니다. A 단계로 23×13.3 + 220 ≈ 526pt(약 18.6cm)이고, 660 안에 들어갑니다. 샘플 사진의 행 높이(약 1cm)와 비슷한 여유입니다.
- 줄 간격은 Word 기본(한 줄)입니다. 고정 줄 간격은 R4(선택)로 요청합니다.
- 머리 행 글자 크기는 본문 단계와 같게 맞춥니다.

### P3-C. 1쪽이 한 쪽을 넘을 때의 원칙
- **원칙**: 내용은 자르지 않습니다. 사용자가 입력한 사실을 지우거나 줄이는 것은 PRODUCT.md 원칙 1(실측이 전부)에 어긋납니다. 모양만 줄입니다.
- **줄이는 순서(앞 단계로 안 되면 다음 단계)**:
  0. (항상 적용) P3-A 열 폭. 겉 표 8/92만으로 내용 줄이 덜 접힙니다.
  1. 안쪽 표(현황·사업·예산·연도)의 칸 문단 뒤 간격을 2pt → 0으로 합니다(`withSpacing(0, 0)`).
  2. 안쪽 표 글자를 10 → 9pt로 합니다.
  3. 본문 글머리 줄(ㅇ·-·'·')을 10 → 9pt로 합니다. 제목 14와 ■ 11은 그대로 둡니다. 위계를 지키기 위해서입니다.
  4. 하한: 9pt까지입니다. 그래도 넘치면 그대로 넘깁니다. 2쪽은 쪽 나눔으로 시작하므로 평가표는 다음 쪽 맨 위에서 시작합니다.
- 단계를 자동으로 고를지(줄 수 추정), 사용자가 고를지는 이관합니다(개발·기획).

### P3-D. RENDER_VER 의견
- **조건부로 3을 유지하고 v3 정의를 고치기를 권합니다.**
  - v3 모양은 아직 사용자가 한 번도 본 적이 없습니다(11-26 실화면 저장 0건, Word 실물 확인 0회).
  - 확정본이 0건인 판을 위해 옛 분기를 영구히 남기면 이득 없이 복잡도만 늘어납니다.
- **조건**: backend가 **모든 DB**(로컬, 다른 PC, 시험 서버)에서 render_ver=3인 저장 판이 0건임을 확인하고, 이 변경 커밋 전에 v3 확정이 생기지 않게 해야 합니다.
- 하나라도 확인하지 못하면 **4로 올립니다**. Builder 17행 주석의 원칙(렌더러를 고치면 옛 판 분기를 남기고 RENDER_VER를 올린다)을 따릅니다.
- 어느 쪽이든 InstSummaryDocBuilderTest의 v3 기대값은 이번 규격으로 다시 고정합니다.
