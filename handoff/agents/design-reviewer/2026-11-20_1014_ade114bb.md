## 2. 한 줄 총평
서버 계약은 화면을 붙이기에 충분하다. 다만 화면이 메워야 하거나 서버가 보완해야 할 빈칸이 셋 있다. ① 공개범위에 추가할 **사람을 고를 출처가 없다**(사번만 받음) ② 운용 수칙 **확인 체크가 서버로 가지 않는다** ③ 오류 문구 일부에 내부 용어가 그대로 나온다.
**가장 큰 기회**: 미리보기에서 `[이름]`·`[가림]` 자리를 눈에 띄는 칩으로 보여 준다(textContent로 분할). 올리는 사람이 가림이 빠진 곳을 저장 **전에** 눈으로 찾을 수 있다. 외부인 이름 누락(security R11)을 막는 유일한 단계가 여기다.

## 3. 점수표 / 잘 된 점
- 점수표: **해당 없음.** 아직 그려진 화면이 없어 휴리스틱 점수를 매길 근거가 없다.
- 잘 된 점
  - 서버가 권한을 `viewer.can_*` 플래그 8개로 내려 준다. 화면은 역할 이름으로 판정하지 않고 이 플래그만 따르면 된다.
  - 오류가 `{code, message, slot, line, kinds}`로 정형화돼 있고 값 에코가 없다. 화면이 코드별 문구를 붙이기 좋다.
  - 미리보기 응답(`putSummary`)과 상세 응답의 모양이 같다. 렌더러 하나로 미리보기와 상세를 함께 그릴 수 있다.

## 4. 우선순위 이슈

**P1-1 공개범위 '사람 추가'에 고를 사람 목록이 없다**
- 근거: `BoardMinutesService.scopeAdd`는 `emp_no`만 받는다. 영업부장이 부를 수 있는 사람 목록 API는 `/assignment-candidates`뿐이다. 이 API는 활성 영업팀·영업팀장만 돌려준다(`BidAssignmentController.java:94`).
- 왜 문제인가: 영업부서 밖 사람(예: 임원)을 더하려면 사번을 외워 쳐야 한다. 잘못 친 사번은 `SCOPE_TARGET_INVALID`로 막히긴 한다.
- 수정 방향(1차): `/assignment-candidates` 중 `role==='영업팀'`만 고르기 목록으로 보여 준다. 영업팀장·영업부장은 이미 기본 열람자라 목록에서 뺀다. 그 아래 "목록에 없는 사람: 사번 직접 입력" 칸을 둔다. 전용 후보 API는 이관한다(7절).

**P1-2 운용 수칙 확인 체크가 감사에 남지 않는다**
- 근거: security 1319는 "수칙을 확인함 체크를 받고 그 사실을 감사 기록에 남깁니다"라고 했다. 그런데 `MinutesOptions`에 해당 필드가 없다(`BoardMinutesIn.java:15`).
- 수정 방향: 화면은 체크해야만 [저장]을 켠다. options에 `rules_ack: true`를 **지금부터** 실어 보낸다. 모르는 키는 서버가 무시하므로 무해하다. 서버 기록은 이관한다.

**P2-1 `UI_ID_REQUIRED` 서버 문구에 헤더 이름이 그대로 나온다**
- 근거: 서버 문구가 "화면·버튼 식별자(X-Screen-Id, X-Button-Id)…"다(`BoardMinutesController.java:344`).
- 수정 방향: 화면은 이 코드에서 서버 message를 쓰지 않고 6-5 표의 문구를 쓴다.

**P2-2 `LIMIT_SPEAKER`의 고정 문구가 없다**
- 근거: `MinutesException.messageFor`에 이 코드가 없어 "요청을 처리할 수 없습니다."로 떨어진다. 코드를 내는 곳은 `TranscriptParser.java:198`이다.
- 수정 방향: 화면 문구표에 따로 둔다(6-5). 서버 문구는 이관한다.

**P2-3 등록자·공개 대상에게 "언제까지 볼 수 있는지"를 정확히 말할 수 없다**
- 근거: `uploader-days`는 설정값(기본 14)인데 응답에 없다. 공개 대상의 `grant_until`은 상세 `viewer`에 없다.
- 수정 방향(1차): 기한을 날짜로 쓰지 않는 문구를 쓴다(6-5 '보기 자격 안내'). 서버 필드는 이관한다.

**P2-4 영업부장이 연 020 화면 id와 회의록 화면 id가 맞지 않는다**
- 근거: 020에서 영업부장은 `board_review`를 보낸다(`board-material.js:33`). `MinutesUiIds.SCREENS`에는 `board_review`가 없다.
- 수정 방향: 탭 확인(LIST_MATERIAL) 호출은 역할과 무관하게 `board_write`를 보낸다. backend 설계 3-2가 "board_write = 020 상세 안의 탭"이라고 정해 두었다. 이 어긋남은 이관에 적는다.

**P3-1 020을 열 때마다 탭 확인 호출이 감사 행을 만든다**
- 근거: `LIST_MATERIAL`은 보이는 회의록 행마다 한 줄을 남긴다(`recordRows`).
- 화면 쪽 처리: 같은 자료를 여는 동안에는 한 번만 부른다. 탭을 오갈 때는 다시 부르지 않는다.

## 5. 문구 / 접근성

### 문구 원칙
- 팀 이름은 부서 이름으로 쓴다(영업부서). 직책은 그대로 쓴다(영업팀장·영업부장).
- "참석자 N"은 서버가 준 그대로 쓴다. 사람과 짝짓는 문구·칸은 두지 않는다(R14).
- 코드명·헤더명·영문 칸 이름(transcript 등)은 화면에 내지 않는다. 칸 이름은 원문 / 시간대별 요약 / 맞춤 요약으로 쓴다.

### 6-1. 파일·변경 범위(e4 회피)
- **새 파일** `frontend/js/board-minutes.js`(전역 `root.boardMinutes`)와 `frontend/test/board-minutes.test.js`를 만든다. **모든 DOM은 createElement + textContent로 만든다. innerHTML·insertAdjacentHTML은 금지한다(security S13·R8).** 테스트에 정적 검사로 "board-minutes.js 안에 `innerHTML` 문자열이 없다"를 넣는다.
- **board-material.js**: 손대는 곳은 아래 다섯 군데다.
  - ① `TABS`에 `['minutes','회의록']`을 더하고 `PANEL.minutes='bd-m-hist'`로 둔다. **패널은 기존 `#bd-m-hist`를 재사용하므로 index.html 마크업은 바꾸지 않는다.**
  - ② `tabsHtml(active, verCount, isHead, mn)`에 선택 인자 `mn={show, count}`를 더한다. `mn.show`일 때만 회의록 탭을 그리고, 라벨은 `'회의록' + (count>0 ? ' '+count : '')`로 한다. 인자 없이 부르는 기존 테스트 결과는 바뀌지 않는다.
  - ③ `tabKey(cur, key, ids)`에 선택 인자 `ids`를 더한다. 없으면 지금처럼 3개다(기존 시험 `hist→ArrowRight→write` 유지).

### 6-2. 탭 위치와 진입
- 탭 순서는 `작성(내용) · 버전 이력 · 작업 이력 · 회의록 n`이다. 회의록은 권한 체계가 따로라 맨 뒤에 둔다.
- 탭 확인 호출: `GET /board-materials/{mid}/minutes`, 헤더 `board_write`/`minutes_tab`.
| 응답 | 탭 |
|---|---|
| 404(기능 꺼짐 — 본문 문자열) | **숨김.** 오류도 띄우지 않는다(존재 은닉 설계 그대로). |
| 200, `items.length>0 \|\| can_upload===true` | 보임. 라벨 수 = `items.length` |
| 200, 둘 다 아님 | 숨김. 볼 것도 올릴 것도 없는 사람이다. |
| 401 | 앱 공통 세션 처리 |
| 5xx·네트워크 | 역할이 영업팀장·영업부장이거나 020 `viewer.is_assignee===true`면 탭을 보이고 패널 안에 오류 + [다시 불러오기]를 둔다. 그 밖이면 숨긴다. |
- 탭을 연 뒤의 404(상세·원문)는 "이 회의록을 볼 수 없습니다. 삭제됐거나 볼 수 있는 기간이 끝났습니다." + [회의록 목록]으로 처리한다. 업로드 중의 404는 6-5를 따른다.

  - 구간: `segments[{seg_no,start_sec,end_sec,keywords[],items[],first_seq,utter_cnt}]`, `out_of_segment_cnt`
  - 권한: `viewer{via,can_edit,can_check_todo,can_view_history,can_scope,can_scope_edit,can_delete}`
  - `masked`는 상세에서 그리지 않는다(미리보기 전용). `confidential`은 늘 true라 표지를 항상 그린다.
- **원문이 쓰는 필드**: `items[{seq_no,speaker,time,seg_no,noise,text,edited}]`. `seg_no`로 묶고, null이면 '구간 밖' 묶음에 넣는다. 빈 발언은 서버가 '(내용 없음)'으로 준다. 화면은 다른 문구를 만들지 않고 그대로 쓴다.
- **시각 표기**: `start_sec`→`mm:ss`, 3600초 이상이면 `h:mm:ss`(서버 `time()`과 같다). 구간은 `00:00–03:20`(en dash)이고 `--mono`로 쓴다. 길이는 `duration_sec`→"32분", 60초 미만이면 "1분 미만", 1시간 이상이면 "1시간 5분"이다.
- **가림 토큰**: 모든 글은 `mn.textNodes()`로 `[이름]`·`[가림]`·`[가림: 개인정보 의심 줄]`을 `span.mn-mask`로 갈라 넣는다. 상세와 미리보기가 같다.
- **고치기(can_edit)**: 항목·발언 옆 [고치기]를 누르면 그 자리에 textarea(발언 maxlength 20000, 항목 1000), [저장]·[취소]가 열린다. 성공하면 글과 `rev_no`를 갱신하고 "고침" 배지(`.bd-badge`)를 붙인다. `changed:false`면 "바뀐 내용이 없습니다."를 쓴다.
- **할 일(can_check_todo)**: 체크하면 바로 `POST …/items/{no}/done {done}`을 보낸다. 보내는 동안 disabled, 실패하면 체크를 되돌리고 오류 상자를 띄운다. 권한이 없으면 disabled 체크박스 + `title` 대신 보이는 글 "(영업팀장 이상만 체크)"를 둔다.
- **삭제(can_delete)**: 인라인 `.bd-confirm` 줄로 확인한다. 열리면 포커스는 [취소]에 둔다.
- **변경 이력(can_view_history, 1차 선택)**: [변경 이력] 토글로 `logs[]`를 보여 준다. 각 줄은 사건 이름 · `actor_name` · 시각이다. `revs[]`의 `old_text`/`new_text`는 "고치기 전"/"고친 뒤" 두 줄로, 모두 textContent로 쓴다.

### 6-4. 업로드 흐름(3단계 — 실제 순서라 번호를 쓴다)
```
회의록 올리기 (h3 #mn-up-h)                                   [취소]
┃대외비·참고용 …
① 파일 고르기
  회의일*  [date min=2000-01-01 max=오늘]     제목*  [text maxlength=100]
  원문*            (●파일 ○붙여넣기)  [파일 고르기 .txt]  선택: 회의녹음.txt 41KB → 파일명은 화면에만, 보내지 않음
  시간대별 요약     (●파일 ○붙여넣기)  …                    "없어도 됩니다"
  맞춤 요약         (●파일 ○붙여넣기)  …
  추가로 가릴 단어  [textarea, 한 줄에 하나]  3/100
  안내: 직원 명단에 없는 사람(기관·다른 은행)의 이름은 여기에 적어야 가려집니다.
                                                    [미리보기] (주버튼 테두리)
② 미리보기 확인 (h4 #mn-pv-h, 응답 뒤 포커스)
  발언 59건  참석자 7명  32분  구간 10개  요약 항목 24개
  가린 곳: 이름 12곳 · 성+직함 2곳 · 개인정보 3곳 · 지정한 단어 1곳
  [경고 목록]
  직원 이름과 같아 가린 말 ─ 지원 3곳 [☐ 가리지 않기] …
  ┌ 미리보기 상자(상세 렌더러 재사용, max-height 420) ┐
③ 저장
  ┃운용 수칙 4줄
  ☐ 위 수칙을 확인했습니다
  [저장] (주버튼)   mn-save-why: "미리보기를 확인하고 수칙에 체크하면 저장할 수 있습니다."
```
- **보내는 방식**: multipart로 `transcript`·`timeline?`·`summary?`·`options`를 보낸다. `options`는 `new Blob([JSON], {type:'application/json'})`이다.
  - 붙여넣기는 `new Blob([text], {type:'text/plain'})`을 파일명 `transcript.txt`(칸 이름.txt)로 append한다. 서버가 `.txt` 확장자를 보기 때문이다.
  - options 내용: `{meeting_date, title, terms[], release[], preview_digest, rules_ack}`
- **미리보기**: `board_minutes_upload`/`minutes_preview`. 응답을 localStorage·sessionStorage에 두지 않고, 컨트롤러 변수에만 둔다. `stop()` 때 비운다.
- **저장**: `board_minutes_upload`/`minutes_upload`. 미리보기 때 보낸 **같은 File/Blob**과 `preview_digest`를 다시 보낸다(서버는 상태를 들지 않는다).
- **무효화**: 미리보기 뒤에 파일·붙여넣기·가릴 단어·가리지 않기를 바꾸면 ② 위에 "내용이 바뀌었습니다. [다시 미리보기]"를 띄우고 [저장]을 끈다. 가림 단어만 바꿔도 digest는 같지만, 보이는 결과와 저장 결과를 같게 하려고 끈다.
- **사전 검사(보내기 전)**: 원문 필수, `.txt`만, 비어 있지 않음, 칸당 2MB 이하(붙여넣기는 `Blob.size`), 제목 1~100자, 회의일 범위, 가릴 단어 한 줄 2~30자·100개 이하. 이것을 통과해야 [미리보기]가 나간다. 서버 한도는 설정으로 더 낮을 수 있어 서버 413 문구도 그대로 받는다.
- **진행 표시**: 보내는 동안 fieldset `aria-busy=true`, 버튼 글 "미리보기 만드는 중…" / "저장하는 중…", 두 번 누름은 막는다. 막대가 필요하면 `.bd-w-prog`를 재사용한다(감소 모션 처리돼 있음).
- **경고 코드 → 문구**(`warnings[{code,count}]`, n = count)
  - PREAMBLE_SKIPPED: "파일 앞부분 n줄은 발언 형식이 아니어서 건너뛰었습니다."
  - TIME_NOT_SORTED: "시각이 앞으로 되돌아간 곳이 n군데 있습니다. 원문 순서 그대로 둡니다."
  - SEG_OVERLAP: "시간대별 요약에 서로 겹치는 구간이 n개 있습니다."
  - SEG_BEYOND_END: "녹음 길이를 넘는 구간이 n개 있습니다. 다른 회의의 요약이 아닌지 확인하세요."
  - LABEL_RENAMED: "이름으로 적힌 발언자 n곳을 '참석자 번호'로 바꿨습니다."
- **가린 곳 문장**: 0이 아닌 것만 잇는다. 이름(`name`), 성+직함(`title`), 개인정보(`pii`), 지정한 단어(`term`), 개인정보 의심 줄(`line`, "줄"), 가리지 않기로 한 말(`released`).
  - 전부 0이면: "가린 곳이 없습니다. 외부 참석자 이름이 없는지 미리보기를 한 번 훑어보세요."
- **저장 성공(201)**: 상세(새 `minutes_id`)로 들어가 `#mn-title`에 포커스하고, 탭 수를 +1 한다. `#bd-m-msg`에는 "회의록을 저장했습니다. 클로바 노트 기록과 메일, PC에 남은 원본 파일을 지워 주세요."를 쓴다(security 1319 표 3행).

### 6-6. 공개범위 편집(scope)

  - [추가]

### 6-9. design_history 전/후 장 문안
- **전**: 이사회 자료 상세의 탭은 3개(작성·버전 이력·작업 이력)다. 이사회에서 오간 말은 시스템 밖(클로바 노트·메일·담당자 PC)에만 있고, 누가 봤는지 남지 않는다.
- **후**: 볼 수 있는 사람에게만 4번째 탭 '회의록 n'이 생긴다. 안에는 다음이 있다.
  - 목록, 그리고 상세: 주요 주제 | 다음 할 일(체크) 2열, 시간대별 구간 목록, 구간에서 원문으로 바로 가기
  - 올리기 3단계: 파일 → 미리보기(가린 자리가 점선 칩으로 보임) → 수칙 체크 → 저장
  - 맨 위 '대외비·참고용' 표지는 접을 수 없다.
- **대비 숫자**: 표지 글 8.1:1, 표지 굵은 글 15.1:1, 가림 칩 점선 4.2:1, 이동 표시 막대 6.4:1
- **왜**: 부장 의견(11-17) "회의에서 오가는 좋은 내용이 전수되면 좋겠다". 원문의 이름·개인정보는 서버가 가리고, 화면은 가린 자리를 보여 줘 누락을 사람이 마지막으로 잡게 한다.
