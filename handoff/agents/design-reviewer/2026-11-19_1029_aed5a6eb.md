### A. 목표 밖 준비 줄에 입찰 종료 적용 (P2, 고침)

- 규격:
  - 줄 모델: 목표 밖 줄(out=true)의 `closed`는 `kbb.closedBasis(id, noticerec.snap(), today, sumById[id])`다. 근거 종류는 서버 근거 두 가지만 쓴다. `screenNote`(행안부·기관 자료)는 지금처럼 쓰지 않는다.

  - 12개월 일정 칸:

  - 정렬과 거르기: 목표 밖 묶음 안에서 맨 아래로 가고(rankOf 4), 상태 '입찰 종료' 거르기에 걸린다. 기존 규칙 그대로다.

### B. P3-1 표 제목(sr)의 '목표 기관 2곳' (고침)
- 근거: `kbboard.js:930-931`에서 `total`은 `rows.length + out.length`(1471줄)인데, 이름표는 `'{year} 목표 기관 ' + total + '곳 중 '`이다.
- 판단:
  - 보이는 건수 '2 / 2곳'은 **그대로 둔다**. c55 규칙 "단계 버튼의 수 = 누르면 남는 줄 수 = 건수"가 표 전체 줄을 세야 성립한다. qa 5번이 '2곳 중 1곳 보임'으로 확인했다.
  - 보이는 건수에는 명사가 없어 거짓말이 아니다. 탭의 '목표 1'은 탭 이름의 수이고, 표 안 묶음 머리줄이 나머지 1곳을 설명한다.
  - 틀린 것은 '목표 기관'이라고 이름 붙인 표 제목뿐이다.
- 규격(goalTableHtml에 `nGoal = rows.length`, `nOut = out.length`를 거르기 전 값으로 넘긴다):
  - 목표 밖이 없을 때: `2026 목표 기관 3곳 중 2곳 보임, 마감까지 오름차순`
  - 목표 밖이 있을 때: `2026 목표 기관 1곳과 그 밖의 제안서 준비 중인 기관 1곳, 2곳 중 2곳 보임, 마감까지 오름차순`
  - 정렬이 없는 분기(928): `2026 목표 기관 1곳, 마감 가까운 순`. 목표 밖이 있으면 위와 같이 `과 그 밖의 … n곳`을 붙인다.
  - 관심 탭: `관심 기관 n곳 중 m곳 보임, …`. 지금 문장에 '보임'만 더한다.

### C. 제안 진행 5단계 수에 목표 밖 포함 (포함 유지, 밝힘)
- 근거: 1476줄 `kbb.stageCounts(rows.concat(out))`. 띠 aria-label은 `{year} 목표 요약`(1487)이다. 다만 단계 줄은 별도 그룹 `aria-label="제안 진행 단계"`(755)다.
- 판단:
  - 빼면 두 가지가 깨진다. 하나는 버튼의 수와 남는 줄 수의 일치(c55 규칙)다. 다른 하나는 사용자 2순위인 "우리가 얼마나 준비하고 있는지"다. 가평의 제안 확정 진행이 띠에서 사라진다.
  - 그러나 '목표 요약' 띠 안에서 목표가 아닌 기관을 말없이 세는 것은 사용자 결정('목표가 아님')과 어긋난다.
  - 그래서 포함하되 문장으로 밝힌다. 되돌리기 쉬우므로 팀이 정한다.
- 규격:
  - nOut > 0일 때만, 단계 버튼들 뒤(지금 `.why` 자리)에 `<span class="why">그 밖의 제안서 준비 중인 기관 1곳 포함</span>`을 둔다. 12px, var(--muted), 기존 `.why` 스타일이다.
  - 자료 오류로 `.why`가 이미 떠 있으면 오류 문장만 둔다. 이때는 nOut=0이다.
  - 그룹 aria-label: `제안 진행 단계, 그 밖의 제안서 준비 중인 기관 1곳 포함`
  - 버튼 aria-label: 그 단계에 목표 밖 줄이 있을 때만 `제안 확정 1곳(그 밖의 준비 기관 1곳) — 표를 이 단계로 거르기`. 눌린 상태의 '거르기 끄기' 문장도 같은 방식으로 한다.
  - 띠 aria-label `2026 목표 요약`은 그대로 둔다. 4칸(목표 기관 수 등)은 이미 `bandModel(rows)`로 목표만 센다.

### D. P3-2 팝업 열림 시 inert 범위 (고침)
- 근거:
  - `kbboard.js:2055`는 `#hb-root`에만 inert를 건다.
  - 팝업 overlay는 `host`(현황판이 붙은 화면 요소, #shell 안)에 붙는다(2053). 그래서 app.js `setBehindInert`처럼 `body > header`·`#shell` 통째로 inert를 걸면 **팝업까지 잠긴다**. 그 방식은 쓰지 않는다.
- 규격(동작):
  - 열 때: overlay에서 `document.body`까지 조상을 올라가면서, 경로에 있지 않은 **형제 요소마다** inert를 건다. 이미 inert인 요소는 건너뛴다. 걸어 준 요소만 목록에 기억한다.
  - 닫을 때(closePop): 기억한 목록만 풀고 목록을 비운다. 로그인 화면이 건 inert를 풀지 않기 위해서다.
  - 화면을 떠날 때와 계정이 바뀔 때도 closePop을 거친다(기존 테스트 c54:301의 의도 유지). 이 테스트는 `$('hb-root')` 문장을 정규식으로 찾고 있어 같이 고쳐야 한다.
  - 결과: 왼쪽 메뉴, 상단 머리, 열린 화면 탭 줄, #hb-root가 모두 inert가 된다. qa로 navInert와 headerInert가 true인지 재측정한다.
- 상세 창(#dm-box)이 줄 클릭으로 이어 뜨는 경로는 closePop이 먼저 불리므로 영향이 없다.

### E. P3-3 일정 칸 글자 위의 월 격자선 (고침)
- 근거: `index.html:1798`에서 `.hb-lane`의 바탕은 반복 그라디언트 세로선이다. `.off`/`.unk`(1808)에는 바탕이 없다. 줄 바탕은 `tr > *`에 칠해진다(1768 hover, 1769 late).
- 규격: 새 색 없이 칸의 바탕색을 변수로 물려받는다. 선택자의 강도를 기존 hover와 late 규칙과 같은 관계로 맞춰, 겹칠 때 이기는 쪽이 똑같다.
  ```css
  .hb-tt tbody td.ln { --rowbg:var(--panel); }
  .hb-tt tbody tr:hover > td.ln { --rowbg:color-mix(in srgb, var(--accent-color) 6%, var(--panel)); }
  .hb-tt tr.late > td.ln { --rowbg:color-mix(in srgb, var(--red) 8%, var(--panel)); }
  .hb-lane .off, .hb-lane .unk { background:var(--rowbg, var(--panel)); padding:0 4px; box-sizing:border-box; }
  .hb-lane .off { right:2px; max-width:calc(100% - 4px); }
  .hb-lane .unk, .hb-lane .unk.before { left:calc(100%/12 + 2px); max-width:calc(100% - 100%/12 - 4px); }
  ```
  - 글자의 시작 위치는 padding 4px와 위치 −4px로 상쇄돼 지금과 같다.
  - 세로선은 글자 상자(top 12px, 높이 16px) 위아래로만 보인다. 라벨이 격자를 덮는 모양이 된다.
  - A에서 새로 생기는 '올해 입찰 끝남'도 `.unk`라서 같은 처리를 받는다.
