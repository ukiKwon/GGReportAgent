## 4. 우선순위 이슈(현재 화면)

- **P1. 잠김 칸 95개가 키보드 정지점**
  - 근거: `board.js` `editCellHtml`(700–706행 부근)에 `tabindex="0" aria-readonly="true"`가 있습니다. 측정해 보니 `[tabindex=0]` 95개, 편집 가능한 입력·버튼은 79개였습니다.
  - 왜 문제인가: 고칠 수 없는 칸이 고칠 수 있는 요소보다 많은 Tab 정지점을 차지합니다. `td`에 붙은 `aria-readonly`는 grid 역할이 없으면 의미가 없습니다.
  - 수정 방향: 잠김을 없앨 때 `tabindex`와 `aria-readonly`도 같이 뺍니다. 값 칸은 일반 `td` 글자로 둡니다.
- **P1. 머리 칸 입력의 접근성 이름이 모두 표 제목뿐**
  - 근거: `th .bd-cell-in`의 aria-label을 측정했습니다. 표 A의 머리 입력 3개가 모두 '재산상 이익제공 및 기부금(안)'이었고, 표 B의 머리 입력 8개는 모두 '5. 수익성 분석'이었습니다.
  - 왜 문제인가: 행·열 기능이 생기면 머리 칸이 핵심 입력이 됩니다. 그런데 스크린리더 사용자는 지금 어느 열 이름을 고치는지 알 수 없습니다.
  - 수정 방향: 6-5절의 이름 규칙을 따릅니다.
- **P2. 편집 안내 줄(`.bd-legend`) 글자 아랫부분이 잘려 보임**
  - 근거: `bd-edit-rowcol-04-legend.png`. 편집 막대의 아래 끝이 y=208, 안내 줄이 y=208–224(높이 16, `line-height:normal`), 양식 이름 줄이 y=224에서 시작해 간격이 0입니다.
  - DOM 겹침은 `elementsFromPoint`로 측정했을 때 없었으므로 원인은 확인하지 못했습니다.
  - 수정 방향: 안내 줄을 새 안내 상자(6-1절)로 바꾸면서 위아래 여백 8px와 `line-height:1.5`를 줍니다.
- **P2. 800px 폭에서 값과 '잠김'이 두 줄로 쌓이고 머리 입력이 잘림**
  - 근거: `bd-edit-rowcol-03-800px.png`에서 '총기대' '명목가'처럼 잘립니다. 표 B는 scrollWidth 634 대 clientWidth 520입니다.
  - 수정 방향: 잠김을 제거하면 줄바꿈은 해소됩니다. 머리 입력은 `min-width:5em`이 아니라 글자 수에 맞춰 늘게 합니다(6-7절).
- **P3. 매핑 칸의 틸 배경 10%가 One Teal Rule('틸은 선택·상호작용 전용')과 긴장 관계**
  - 근거: `index.html` `.bd-mapped`(173행 부근).
  - 보기·작성 모드에서 이미 쓰고 있는 기존 결정이라 이번 범위에서는 바꾸지 않습니다. 다만 행·열을 '선택'할 때 틸 배경을 또 쓰면 둘이 구별되지 않습니다. 그래서 선택은 배경이 아닌 테두리로 표시합니다(6-3절).

## 5. 문구 / 접근성

**문구**
- '잠김'(배지, title '엑셀 값이 들어가는 칸 · 잠김', `.bd-legend`의 '개발자만 연결을 바꿀 수 있습니다')은 전부 삭제합니다. '개발자' 같은 내부 역할도 노출하지 않습니다.
- 동사를 정합니다. 표는 '빼기'(카탈로그에서 다시 '추가'할 수 있음)를 유지합니다. 행·열은 엑셀 한국어판 동사인 **'삽입/삭제'**를 씁니다. 은행 사용자에게 가장 익숙한 말이고, 다시 가져올 수 없다는 점도 '빼기'와 구별됩니다.
- 위치 표현은 **'위에 행 삽입 / 아래에 행 삽입 / 왼쪽에 열 삽입 / 오른쪽에 열 삽입'**입니다. 엑셀·워드 표 메뉴의 어순과 같습니다.

**접근성**
- 버튼 크기:
  - 현재 위로·아래로·빼기 버튼: 46–58×28px.
  - 새 손잡이 버튼: 24×24px(WCAG 2.5.8 최소 24px 충족).
- 포커스: 전역 `:focus-visible`(틸 2px, 오프셋 2px)을 그대로 씁니다.
- 색 단독 전달 금지: 삭제 대기 중인 행은 빨강 테두리에 더해 확인 줄 문구로도 알립니다. 매핑 칸은 틸 배경에 더해 title 툴팁과 삭제 확인 문구로도 알립니다.

### 6-2. 행·열 조작 UI: 세 안 비교 후 권장

| 안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| A. 손잡이 버튼(행마다 하나, 열마다 하나) → 펼침 메뉴 | 대상이 분명함(삭제 확인에 그 행 이름을 넣을 수 있음). 키보드로 도달 가능. 위치가 늘 보임 | 버튼 수가 늘어남(표 C-2 기준 9+7=16개) | **권장** |
| B. 호버하면 경계에 + 버튼 | 화면이 깨끗함 | 키보드·터치로 도달할 수 없고 발견하기 어려움. 삭제는 결국 따로 필요 | 기각 |
| C. 표 머리 툴바(현재 칸 기준 6버튼) | 버튼이 6개로 고정 | 값 칸은 포커스할 수 없어서(6-1절) '현재 행/열'이 보이지 않는 상태가 됨. 선택지 6개는 4개를 넘음. 칸에서 툴바로 돌아가려면 Shift+Tab을 여러 번 눌러야 함 | 기각 |

- **권장 A의 배치(사용자의 '각 행 끝'에서 수정 제안)**:
  - 행 손잡이는 행의 **왼쪽** 여백 열에 둡니다.
  - 열 손잡이는 머리 행 **위** 여백 줄에 둡니다.
  - 이유: 800px에서 표가 가로 스크롤되면(측정 634>520) 행 끝은 화면 밖으로 밀립니다. 왼쪽 손잡이는 `position:sticky; left:0`으로 늘 보이게 할 수 있고, 행 이름(머리 칸) 바로 옆이라 '이 이름의 행'이라는 연결도 강해집니다.
  - 사용자가 꼭 오른쪽 끝을 원하면 sticky `right:0`으로 같은 규격이 성립합니다(8절 질문).
- 손잡이 수는 **펼친 격자 기준**입니다(`gridOf`). 표 B는 '구분' colspan 2 때문에 열 손잡이가 2+7=9개입니다. 쪼개진 '구분'의 두 하위 열을 각각 다룰 수 있어야 하므로 이것이 의도한 동작입니다.
- **메뉴 항목**(각 3개, 4개 이하):
  - 행 메뉴: `위에 행 삽입` · `아래에 행 삽입` · `행 삭제`
  - 열 메뉴: `왼쪽에 열 삽입` · `오른쪽에 열 삽입` · `열 삭제`
- **패턴**: 펼침(disclosure)을 씁니다. 손잡이에 `aria-expanded`와 `aria-controls`를 달고, 패널은 `role="group"` + `aria-label`, 그 안에 일반 `<button>` 3개를 둡니다.
  - `role=menu`는 쓰지 않습니다. 화살표 키 계약이 필요하고 저장소 선례도 없습니다. `#bd-add` 패널과 같은 패턴입니다.
  - 한 번에 메뉴 하나만 엽니다. 다른 손잡이를 누르면 앞 메뉴는 닫힙니다.
- **메뉴 위치**: `.bd-table-wrap`은 `overflow-x:auto`(index.html 166행 부근)라서 안에 두면 잘립니다.
  - **카드(`.bd-card-edit`, `position:relative`) 직속**에 absolute로 둡니다. 손잡이 아래 4px, 왼쪽은 손잡이에 맞추되 카드 안쪽으로 맞춥니다.
  - 표를 가로 스크롤하거나 창 크기가 바뀌면 메뉴를 닫습니다.

### 6-3. 손잡이·대상 표시 모양
- **손잡이 버튼** `.bd-handle`:
  - 24×24px, padding 0, `background:transparent`, `border:1px solid transparent`, radius 8px.
  - 아이콘: 인라인 SVG(12×12 viewBox, 세로 점 3개를 r=1.2 원으로 그림, `fill:currentColor`), `color:var(--muted)`.
  - 문자 '⋯'는 쓰지 않습니다(DESIGN: 크롬에 문자 글리프 아이콘 금지).
  - 호버: `background:var(--panel2); border-color:var(--line-strong); color:var(--fg)`. 들어올림(lift)은 없습니다. 표 안이라 흔들림을 막기 위해서입니다.
  - 펼침 상태(`[aria-expanded=true]`): `border-color:var(--accent-color); background:color-mix(in srgb,var(--accent-color) 13%,transparent)`.
- **여백 칸**:
  - 행용: `td.bd-gut`, 폭 32px, padding 4px, `border:0`, 배경 없음.
  - 열용: `tr.bd-colbar > td`, 높이 32px, 가운데 정렬, `border:0`.
  - 표 테두리 격자 밖처럼 보이게 합니다.
- **대상 표시**(메뉴가 열려 있거나 손잡이에 포커스·호버가 있을 때): 그 행·열의 칸에 `box-shadow: inset 0 0 0 1px color-mix(in srgb,var(--accent-color) 55%,transparent)`.
  - 배경 틴트는 쓰지 않습니다. 매핑 칸의 틸 배경 10%와 구별하기 위해서입니다.
- **삭제 확인 대기 중**: 대상 칸에 `box-shadow: inset 0 0 0 1px var(--red)`와 `background-image:linear-gradient(color-mix(in srgb,var(--red) 8%,transparent),color-mix(in srgb,var(--red) 8%,transparent))`.
  - 매핑 칸의 틸 배경 위에 겹쳐 보이게 하려고 background-image로 깝니다. 8%는 18% Tint Rule의 '행' 범위 안입니다.
- **새로 넣은 행·열**: 칸 표시는 따로 하지 않습니다. 카드 배지에 `'행·열 바뀜'`을 추가합니다(기존 '변경됨'·'순서 바뀜'과 같은 `.bd-badge`).
  - 변경 건수(`changeCount`)에는 표마다 1건으로 셉니다.

### 6-4. 삽입·삭제 동작과 문구
- **삽입**:
  - 즉시 반영하고, 확인 줄을 띄우지 않습니다.
  - 새 행·열의 **머리 칸**은 빈 입력에 placeholder `행 이름` / `열 이름`을 둡니다. **포커스는 즉시 그 입력으로** 옮깁니다.
  - 상태 알림(`aria-live="polite"`, 아래 6-6절): `'예비비' 아래에 행을 삽입했습니다. 행 이름을 입력해 주세요.`
- **빈 값 표시: 공란을 권장합니다(0이 아님)**.
  - 0은 '값이 0'이라는 주장이 되어 샘플 워드에 실제 숫자처럼 찍힙니다. 근거 없는 데이터 금지(PRODUCT 원칙 1)와도 충돌합니다.
  - 새 값 칸은 입력이 아닌 빈 `td`로 둡니다. 핵심은 머리 문구이고, 예시값 입력은 범위 밖입니다.
  - 스크린리더 누락을 막기 위해 칸 안에 `<span class="sr-only">빈 칸</span>`을 둡니다.
- **새 열이 '행 머리 영역'에 들어간 경우**: 첫 값 열보다 왼쪽에 넣었을 때입니다. 표 B '구분' 쪼개기가 이 경우입니다.
  - 그 열의 본문 칸도 `행 이름` 입력(`th`)으로 만듭니다.
  - 값 영역에 넣었으면 본문 칸은 빈 `td`입니다.
- **삭제: 매핑 칸이 없는 행·열**
  - 확인 없이 즉시 지웁니다.
  - 알림: `'예비비' 행을 삭제했습니다.` 뒤에 `[되돌리기]` 링크 버튼(`.link-btn`)을 붙입니다.
- **삭제: 매핑 칸이 있는 행·열**
  - 카드 안 인라인 확인 줄(`board.confirmHtml` 재사용, act `rowdel`/`coldel`)을 씁니다.
  - 문구(줄바꿈 유지):
    > '예비비' 행을 삭제할까요?
    > 이 행에는 작성할 때 엑셀에서 값이 채워지는 칸이 3개 있습니다. 삭제하면 작성할 때 이 값들이 문서에 들어가지 않습니다.
    > 저장하기 전에는 실제 양식이 바뀌지 않습니다.
  - 열 문구는 '행'을 '열'로 바꿉니다. 이름이 비면 `3번째 행` / `2번째 열`이라고 씁니다.
  - 버튼: `[행 삭제]` `[그대로 두기]`. **첫 포커스는 `[그대로 두기]`**입니다. 엑셀 연결을 잃는 일이라 '편집 끝내기' 확인과 같은 안전 쪽 기본값을 줍니다.
  - 닫으면 포커스는 그 행·열의 손잡이로 돌아갑니다.
- **삭제 후 포커스**: 같은 자리로 올라온 행(열)의 손잡이로 갑니다. 마지막 행이었다면 바로 위 행의 손잡이로 갑니다.

### 6-5. 보호 규칙·병합 규칙·이름 규칙
- **머리 행 보호**(첫 행에 `header:true`가 있을 때):
  - `행 삭제`와 `위에 행 삽입`을 끕니다.
  - `아래에 행 삽입`은 허용합니다(첫 본문 행이 됩니다).
- **최소 크기**:
  - 본문 행이 1개면 `행 삭제`를 끕니다.
  - 열이 1개면 `열 삭제`를 끕니다.
  - 행 머리 영역의 열이 1개뿐이면 그 열의 `열 삭제`를 끕니다. 행 이름이 사라지기 때문입니다.
- **꺼진 항목 표시**: `disabled`를 쓰지 않고 `aria-disabled="true"`를 써서 포커스를 받게 합니다. 이유 문구를 버튼 안 두 번째 줄(11px, muted)에 둡니다.
  - 문구: `머리 행은 삭제할 수 없습니다.` / `행이 하나뿐이면 삭제할 수 없습니다.` / `열이 하나뿐이면 삭제할 수 없습니다.` / `행 이름 열이 하나뿐이면 삭제할 수 없습니다.`
- **병합 칸**(엑셀·워드 동작에 맞춤):
  - 삽입 위치가 병합 칸의 **안쪽**이면, 그 병합 칸의 rowspan(열이면 colspan)을 1 늘립니다. 예: 표 B에서 '구분'(colspan 2)의 두 하위 열 사이에 열을 삽입하면 '구분'이 colspan 3이 됩니다.
  - 삽입 위치가 병합 칸의 **경계**(위·아래 끝, 좌·우 끝)면 늘리지 않습니다.
  - 병합 칸이 걸친 행·열을 삭제하면 그 병합 칸의 span을 1 줄입니다. 병합 칸이 **시작하는** 행·열을 삭제하면 칸 내용은 다음 행·열로 옮겨 span을 1 줄입니다. 머리 문구를 잃지 않게 하려는 것입니다.
  - 병합 만들기·풀기는 이번 범위가 아닙니다. 메뉴에도 넣지 않습니다.
- **이름 규칙(aria-label)**:
  - 행 손잡이: `'예비비' 행 편집`. 이름이 비면 `3번째 행 편집`.
  - 열 손잡이: `'총기대수익' 열 편집`. 병합 머리 아래 하위 열이면 `'구분' 1/2번째 열 편집`.
  - 패널: `role="group" aria-label="'예비비' 행 편집"`.
  - 머리 입력: 열 머리는 `<표 제목> · 2번째 열 이름`, 행 머리는 `<표 제목> · 3번째 행 이름`. 이름 자체는 입력 값으로 읽힙니다.
- **키보드**:
  - 손잡이에서 Enter/Space로 펼치면 첫 '켜진' 항목으로 포커스가 갑니다.
  - Esc는 닫고 손잡이로 돌아갑니다.
  - 마지막 항목에서 Tab을 누르면 닫고 다음 요소로 갑니다.
  - 전역 단축키(Ctrl+Z 등)는 걸지 않습니다. 입력 칸의 기본 실행 취소와 충돌하기 때문입니다.

### 6-6. 되돌리기·상태·오류 문구
- **되돌리기를 제공합니다.**
  - 편집 막대(`#bd-editbar`) 오른쪽에 `[되돌리기]` 버튼을 둡니다. 행·열 조작이 쌓였을 때만 켜집니다.
  - aria-label은 `되돌리기: '예비비' 행 삭제`처럼 마지막 동작을 담습니다.
  - 여러 단계를 허용합니다. 불변 상태라 스택이면 충분합니다.
  - 저장하면 스택을 비웁니다.
  - 행·열 조작만 대상으로 합니다. 글자 입력은 브라우저 기본 실행 취소에 맡깁니다.
- **알림 위치**: 편집 막대 안 `<span id="bd-rowcol-msg" aria-live="polite">`(12px, muted). 5초 뒤 비웁니다. `[되돌리기]` 링크가 있으면 비우지 않습니다.
- **문구**:
  - 되돌리기 완료: `'예비비' 행 삭제를 되돌렸습니다.`
  - 저장 전 검증(기존 `validateEditAt`에 위치 추가, [고치러 가기] 연결):
    - `2번째 표에 이름이 빈 행이 있습니다.` (target `rowhead:1:<r>`)
    - `2번째 표에 이름이 빈 열이 있습니다.` (target `colhead:1:<c>`)
  - 최대 크기: `표 하나에 행은 최대 N개까지 넣을 수 있습니다.` (N은 개발이 정함, 이관 참조) 이때 삽입 항목을 `aria-disabled` 처리하고 이 문구를 이유로 씁니다.

### 6-7. 좁은 폭(880px 이하)
- 행 손잡이 여백 칸은 `position:sticky; left:0; background:var(--panel); z-index:1`로 둡니다.
- 머리 입력은 `min-width: 6em`을 기본으로 하고, 열 머리 입력은 `field-sizing:content`(지원 브라우저) 또는 `size` 속성을 글자 수+2로 줍니다.
- 560px 이하에서는 메뉴 패널을 카드 폭 100%(좌우 12px 여백)로 펼칩니다. 버튼을 세로로 쌓고 각 버튼 높이를 32px로 합니다.

## 7. 이관 메모

**[이관: 개발]**
- **표 구조 저장 스키마**: `board.putBody`는 '구조·매핑은 보내지 않고 재정의 값만 보낸다'고 되어 있습니다(board.js 488행 부근 주석). 행·열 삽입·삭제를 저장하려면 rows/columns 구조를 보내고 서버(`BoardFormService`·`BoardDocSpec`)가 받아야 합니다. 디자인은 '저장하면 새 버전에 구조가 반영된다'를 전제로 문구를 썼습니다.
- **엑셀 매핑이 칸을 무엇으로 가리키는지**(키 또는 행·열 위치): 위치 기반이면 행 하나만 삽입해도 아래 매핑이 전부 어긋납니다. 이 경우 6-4절의 '삽입은 확인 없이 즉시'가 성립하지 않고, 삽입에도 경고가 필요합니다. 근거로 `excel-map.json`과 `BoardExcelMap`을 아직 확인하지 않았습니다.
- **행·열 최대 개수와 서버 검증 한도**: 6-6절의 N이 필요합니다.
- **새 머리 칸의 key 발급 방식**: 현재 칸 입력은 서버가 준 key가 있어야 편집됩니다(`editSetCell`의 `has(t.cells,key)`).
- **병합 칸 span 조정 로직**: 6-5절 규칙을 순수 함수로 구현하고 테스트해야 합니다.

**[이관: 기획]**
- 새 행·열의 값 칸이 작성 모드에서 공란으로 워드에 찍혀도 업무상 괜찮은지 정해야 합니다. 디자인은 공란을 권장합니다. 근거는 0을 넣으면 예시가 아닌 실제 숫자로 읽힌다는 점입니다.
- 매핑 칸이 있는 행을 지운 양식으로 작성할 때, 그 엑셀 값이 '쓰이지 않음'을 작성 모드에서도 알려야 하는지 정해야 합니다.

**[이관: 데이터]** 없음.

## 8. 디자인 쪽 열린 질문
- 행 손잡이 위치: 디자인은 '각 행 **왼쪽**'(좁은 폭에서도 늘 보이고 행 이름 옆)을 권장합니다. 사용자가 말한 '각 행 끝(오른쪽)'을 그대로 원하는지 확인이 필요합니다. 어느 쪽이든 규격은 같고 sticky 방향만 바뀝니다.
- 행·열 동사: 엑셀식 '삽입/삭제'로 정했습니다. 표의 '빼기'와 다른 말을 쓰는 데 사용자가 불편함이 없는지 확인이 필요합니다. 불편하면 '행 넣기/행 빼기'로 통일하는 대안이 있습니다.
