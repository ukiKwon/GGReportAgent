## 2. 한 줄 총평
지금 표는 줄을 고르는 일과 값을 고치는 일이 따로 논다. **줄의 '고침' 표시 → 자동 체크 → 띠의 [수정하기]**를 한 흐름으로 묶으면 체크박스에 처음으로 분명한 뜻이 생긴다. 그 뜻은 "저장할 줄"이다. 가장 큰 기회가 이것이다. 일정 칸은 빼도 잃는 정보가 거의 없다. 날짜 글자만 '마감까지' 칸으로 옮기면 된다.

**잘 된 점**
- 고른 줄은 탭·연도·거르기를 바꿔도 남는다(`tc.reconcile`). 고친 값도 이 수명에 그대로 얹을 수 있다.
- 입찰 종료 줄의 옮기기 동작은 이미 구분 메뉴에도 있다(menuHtml `towatch`·`tonext`). 그래서 일정 칸을 빼도 동작이 거의 사라지지 않는다. 한 군데 예외는 P1-2에 적었다.
- [제안 확정] 판정은 dash.proposeGate 한 곳에 모여 있다. 지도 팝업과 표가 같은 규칙을 쓴다.

## 4. 우선순위 이슈 (이번 변경에서 지켜야 할 것)
- **P1-1 [제안 확정]이 두 번 그려질 위험**
  - 근거: 지금도 '준비 단계' 칸이 `actHtml`로 [제안 확정]을 그린다(kbboard.js stageCellHtml → actHtml `act==='confirm'`).
  - 왜 문제인가: 끝 칸에 단추를 더하면 한 줄에 같은 단추가 둘 생긴다.
  - 수정 방향: 동작은 **끝 칸 하나**로만 옮긴다. '준비 단계' 칸은 상태만 보인다(6-3).
- **P1-2 '받는 쪽 화면(관심 기관 탭)'이 없는 서버면 [다음 회차 목표로…]가 사라진다**
  - 근거: menuHtml의 `canMove: r.kind !== 'WATCH' && !noWatchNow()` 때문에 noWatch일 때 `tonext`도 숨는다. 반면 지금 일정 칸의 closedActsHtml은 noWatch에서도 `tonext`를 그린다.
  - 왜 문제인가: 일정 칸을 빼면 이 경우 다음 회차로 옮길 길이 없다.
  - 수정 방향: 메뉴에서 `tonext`는 `r.closed && 쓰기 자격`만 보고 noWatch와 떼어 낸다. `towatch`만 noWatch를 본다.
- **P1-3 다음 해 목표 줄에서 서버가 거절할 단추가 보일 수 있음**
  - 근거: proposeGate는 공고가 접수 중이면 목표 여부와 무관하게 'confirm'을 낸다. 서버는 결재가 끝난 **올해** 목표만 받는다(b7f42c22: NOT_GOAL_TARGET, GOAL_CHANGE_PENDING).
  - 수정 방향: 표의 단추는 `r.targetYear === 올해 && !r.pend && !r.out && act==='confirm'`일 때만 그린다.
- **P2-1 '확인 중…' 문구가 DESIGN 위반**
  - 근거: actHtml `wait`. DESIGN 104줄은 "'확인 중'처럼 무엇을 확인하는지 말하지 않는 말은 쓰지 않는다"고 정한다.
  - 수정 방향: '진행 자료 받는 중'으로 바꾼다.
- **P2-2 저장 중 비활성 표시에 opacity를 쓰면 안 됨**
  - 근거: DESIGN의 단추 비활성은 .55인데, 현황판 CSS에는 opacity를 쓰지 않는다는 지시가 있다.
  - 수정 방향: 저장 중인 [수정하기]는 `aria-disabled="true"`, 글자 `var(--muted)`, 테두리 `var(--line)`, 문구 '수정하는 중…'으로 표시한다.
- **P2-3 문서·이력 정리**
  - 메모 창 단추 이름이 계약과 어긋난다(5절). DESIGN.md 팝업 절에 예외 한 줄이 필요하다.
  - design_history에 전/후 장(109)이 필요하다(6-9).

## 6. 규격

### 6-1. 고친 값(저장 대기) 상태 모델
- 줄마다 `gs.edits[id] = { targetNo, revNo, tag, memo, autoPicked }`를 둔다. 원래 값은 `gs.sel.by[id]` 스냅샷(tagCd·memo)이다.
- **구분 메뉴에서 다른 구분을 고르면**
  - ① 서버를 부르지 않는다.
  - ② `gs.edits`에 기록한다.
  - ③ 줄이 아직 안 골라졌으면 `tc.pick`으로 고르고 `autoPicked=true`로 둔다. pick이 20곳 한도로 실패하면 값을 바꾸지 않고 한도 문장을 띄운다.
  - ④ 표를 다시 그리지 않는다. 그 줄 칸·체크·띠만 고친다(syncPickDom·paintSel처럼).
- **원래 값으로 다시 고르면** 고친 값을 지운다. autoPicked였으면 체크도 푼다. 사용자가 먼저 손으로 고른 줄이면 체크를 그대로 둔다.
- **메뉴 머리 줄**: 고친 줄이면 `.mh` 한 줄 `원래 값: 재유치 도전`을 더한다. 구분 묶음 끝에 메뉴 항목 `원래 값으로 되돌리기`(data-cmd="revert")를 둔다.
- **메모**: 같은 방식으로 한다(일관성 권장). openMemo의 [적용]은 `gs.edits[id].memo`만 채우고 자동 체크한다.
- **목록을 다시 받을 때(loadGoals)**
  - 잠기거나 사라진 줄은 reconcile이 고른 줄에서 뺀다. 그 줄의 고친 값도 같이 버린다.
  - 상태 줄 문장: `{기관}은 결재 요청에 들어가 고친 값을 버렸습니다.`
  - 남은 줄의 고친 값은 다시 그린 표에 다시 입힌다.

### 6-2. 체크·지우기·떠나기
| 상황 | 처리 |
|---|---|
| 체크만 하고 고치지 않은 줄 | 저장에 보내지 않는다. 띠 문장으로 알린다 |
| 고친 줄의 체크를 풂 | 고친 값을 버린다(확인 창 없음, status 문장) |
| [고친 값 버리기]/[선택 지우기] | 모든 체크를 풀고 고친 값을 전부 버린다(확인 창 없음 — 한 줄씩 다시 고칠 수 있고 서버에 간 것이 없다) |
| 목표↔관심 탭·연도·거르기 | 고친 값을 유지한다(고른 줄과 같은 수명). 화면 밖 줄은 `이 화면 밖 n곳`으로 센다 |
| 현황판을 떠남(다른 메뉴·화면 탭), 새로고침, 창 닫기 | 고친 값이 1곳 이상이면 떠날 때 확인 창(5절 문구). 새로고침·창 닫기는 `beforeunload` |
| 계정 바뀜·로그아웃 | 묻지 않고 버린다(지금 sel 처리와 같다) |

### 6-3. [수정하기] — 권장안: 창 없이 바로 일괄 저장
- **이유**
  - 결재가 없다.
  - 다시 고칠 수 있다.
  - 기록이 남는다.
  - 전/후가 이미 줄에 보인다('고침' + 원래 값).
  - 확인 창은 DESIGN상 되돌리기 어려운 동작에만 쓴다.
- **보이는 조건**: 고친 줄 ≥1, 고른 줄이 전부 목표, 지난해 목표 없음, canBulkEdit. 지금 `#hb-seledit` 조건에 '고친 줄 ≥1'을 더한다.
- **보내는 것**: 고친 줄만, 지금 `toItem` EDIT 모양 그대로 보낸다. `target_year`=snap.year, 구분·메모는 고친 값(없으면 원래 값), `base_rev_no`=snap.revNo, 단추 `tc.BTN.values`.
- **저장 중**
  - 단추는 `aria-disabled` + '수정하는 중…'(opacity 없음).
  - `gs.busy`로 메뉴와 체크를 막는다.
  - 고친 칩에 `aria-busy="true"`.
- **성공**: 고친 값을 비우고, 고른 줄을 비우고, `gs.justIds`로 그 줄들을 강조하고, 위 알림에 결과 문장을 띄운다.
- **실패**
  - 고친 값을 그대로 둔다.
  - 띠 `.lim` 자리에 오류 문장을 띄우고 role=alert로 한 번 읽힌다.
  - 항목 번호가 있으면 그 줄 구분 칩으로 포커스를 옮기고, 그 줄 칸 title·sr에 오류 문장을 붙인다.
  - STALE이면 목록을 다시 받는다. 그 줄은 rev만 갱신하고 고친 값은 남긴다. 사용자가 다시 누른다.
- **기존 일괄 수정 창**(`openChange({kind:'edit'})`)은 띠에서 더 열지 않는다. 지울지는 기획에 넘긴다(이관).

### 6-9. 시험 포인트
1. 구분을 고르면 네트워크 요청 0건, 위 알림이 없다. 칩에 `.ed`와 '고침'이 붙고 체크박스가 켜지며 띠에 `고친 기관 1곳`이 뜬다.

3. 고친 줄의 체크를 풀면 칩이 원래 값으로 돌아오고 status 문장이 나온다.
4. 고친 줄 2 + 체크만 한 줄 1에서 [수정하기]를 누르면 items가 2개이고 각 항목에 `base_rev_no`가 들어간다. 감사 버튼은 `save_target_values`.
5. 저장 성공 뒤: 고친 값과 체크가 비고, justIds 강조가 나오고, 결과 문장이 뜨고, 포커스가 이동한다.
6. 409 STALE이나 연결 실패면 고친 값이 그대로 남고, 오류 문장이 띠에 뜨며 그 줄로 포커스가 간다.
7. 21번째 줄을 고치면 값이 그대로이고 한도 문장이 뜬다.
8. 탭·연도를 바꿔도 고친 값이 남고 `이 화면 밖 n곳`이 보인다. 다른 화면으로 가면 확인 창이 뜨고, [계속 고치기]에 첫 커서가 있다.

11. noWatch 서버에서 입찰 종료 줄 메뉴에 `다음 회차 목표로…`가 있는지.
