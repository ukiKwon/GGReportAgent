## 4. 우선순위 이슈
**A. P2 `.rs-tt` 열 폭 배분 (협약 성과 관리)**
- 근거: index.html 3032–3033행. 1280px에서 은행 열(auto)이 336px를 차지해 "—"만 있다. 반면 구분·약정 시작·제안 진행·기관 4개 열은 말줄임으로 잘린다.
- 왜 문제인가: 결과 대기 단계에서 사용자가 실제로 읽는 값이 구분("신규유치 도전" / "재유치 도전")과 진행 상태다. 둘 다 "…"로 잘려 칸을 누르거나 title을 띄워야 읽힌다.
- 수정안:
  - 기존 3032행: `.rs-tt col.c-nm { width:210px; } .rs-tt col.c-tag { width:72px; } .rs-tt col.c-res { width:180px; } .rs-tt col.c-bank { width:auto; }`
  - 새 3032행: `.rs-tt col.c-nm { width:240px; } .rs-tt col.c-tag { width:96px; } .rs-tt col.c-res { width:180px; } .rs-tt col.c-bank { width:auto; }`
  - 기존 3033행: `.rs-tt col.c-from { width:84px; } .rs-tt col.c-evd { width:150px; } .rs-tt col.c-prep { width:100px; }`
  - 새 3033행: `.rs-tt col.c-from { width:96px; } .rs-tt col.c-evd { width:150px; } .rs-tt col.c-prep { width:120px; }`
  - 기존 3030행의 `min-width:880px`는 `min-width:1080px`로 바꾼다. 고정 열 합이 882px이라 은행 열이 0이 되지 않게 하려는 것이다. 1280px에서 은행 열은 약 250px로 은행 두 개를 쓰기에 충분하다.

**B. P3 `.pb-t` 68px 머리값이 낱말 가운데서 꺾인다**
- 근거: 1543행 `padding:4px` + `overflow-wrap:anywhere`. 쓸 수 있는 폭은 59px(68 − 테두리 1 − 패딩 8)이고, 12px 글자 5자는 60px가 필요하다. 1px이 모자란다.
- 수정안: 1543행 `.pb-t thead th { ... padding:4px; ...` → `padding:4px 2px;`. 쓸 수 있는 폭이 63px가 된다. 세로 패딩은 그대로다.

**C. P3 `.pl-tbl td.pl-bud` 원문 표기 문장이 오른쪽 정렬로 여러 줄**
- 근거: t124-plan-budget.png. 숫자 예산이 아니라 원문 문장(`.db-why`)이 160px 칸에서 오른쪽 정렬로 3–4줄 꺾인다. 그래서 각 줄의 시작점이 들쭉날쭉하다.
- 규칙상 "금액 오른쪽"이 맞지만, 실제로는 "여러 줄 본문 칸"이다. 수정안(규칙 해석은 질문 1):
  - 3022행대 `.pl-tbl` 블록 아래에 새 줄: `.pl-tbl td.pl-bud .db-why { display:block; white-space:normal; text-align:left; }   /* 원문 문장은 여러 줄 본문 — 숫자만 오른쪽 */`

**D. P3 위 정렬 줄에서 글자 크기가 다른 칸이 1–2px 어긋난다**
- 근거: 담당자 이력은 칸 위 간격이 모두 8px로 같지만, mono 11px 시각이 13px 본문보다 글자 기준선이 높아 떠 보인다. `.pl-tbl`은 번호 글자 위 간격 11px, 사업명 9px다.
- 수정안: 줄 단위 위 정렬을 `top` 대신 `baseline`으로 바꾼다. 표 칸의 baseline은 각 칸 첫 줄의 기준선을 맞추면서 위에서부터 쌓는다.
  - `.ad-table tr:has(> td.tm-t-reason) > td, ... { vertical-align:top; }` → `vertical-align:baseline;`
  - 2857행 `.pl-tbl td { ... vertical-align:top; ...}` → `vertical-align:baseline;`
  - `table-center.test.js`가 top을 검사하면 같이 고쳐야 한다(개발).

**E. P3 담당자 이력의 빈 사유가 "-"이고 왼쪽에 혼자 붙는다**
- 근거: team.js 347행이 `esc(r.reason)`를 그대로 출력한다. 버전 이력은 `—`를 `.dg-hint`로 가운데에 둔다. 빈 표시가 화면마다 다르다(t124-team-hist.png).
- 수정 방향: 빈 사유를 `<span class="dg-hint">—</span>`로 출력하면 이미 들어간 `:only-child` 가운데 규칙이 적용된다(서버가 "-"를 넣는지는 개발이 확인).
