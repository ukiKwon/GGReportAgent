## 2. 한 줄 총평과 가장 큰 기회
- **총평**: 크기 4단계는 지방에서는 바로 읽힙니다. 하지만 수도권·세종처럼 몰린 곳에서는 전국 축척에서 원 61개 중 45개가 서로 겹쳐 A만으로는 "한눈에"가 깨집니다.
- **가장 큰 기회(권장)**: C(면=지자체, 원=건물, 범례 하나)를 기본 구조로 둡니다. 여기에 전국 축척에서만 B식 시도 칸을 더하되, 30일 이내 원은 묶지 않고 그대로 둡니다. 시안 B 탭의 "30일 이내는 전국에서도 원으로"를 켜면 이 모습이 됩니다.

## 3. 점수표 / 잘 된 점
- **점수표**: 매기지 않았습니다. 기존 화면 진단이 아니라 시안 비교라서 근거 있는 휴리스틱 점수를 낼 수 없습니다.
- **잘 된 점 1**: 크기 축이 색 축(현행 5단계)을 대신하지 않고 그 안쪽을 더 나눕니다. 180일 이내는 원래 모두 빨강이라, 크기가 그 빨강 안을 세 칸으로 나누는 셈입니다. 색 단독 전달 문제가 생기지 않습니다.
- **잘 된 점 2**: "30일 이내 = D-n 글자"라는 규칙 하나가 면·원·목록·티커에 공통으로 적용됩니다.

### A·B·C 비교 (같은 가짜 300곳, 1280px)
| | A 크기 원 | B 시도 칸 → 펼침 | C 면+원 혼합 |
|---|---|---|---|
| 전국 겹침 | 180일 이내 원 45/61개가 겹침, D-n 글자 15개 중 4개 겹침 | 시도 칸 17개, 겹침 0(칸 97×48px) | A와 같음(45/61) |
| 확대 후 | 수도권 ×4: 원 겹침 10, 누르기 어려운 원 31(146표식 중) / 세종·대전 ×4.8: 겹침 4/15, 어려움 10/15 | 펼치면 A와 같음 | A와 같음 |
| 가독성 | 지방의 큰 원·D-n은 즉시 보임. 서울은 덩어리 | 숫자를 읽어야 함. 전국에서 개별 위치는 안 보임 | 면 정보가 살아 있음. 면 50%가 탁해짐 |
| 누르는 대상 | 큰 원(26px)만 24px 기준 충족. 전국에서는 61/61이 다른 표식과 24px 미만 거리 | 칸 97×48 충족, 버튼이라 Tab 이동 가능 | A와 같음 |
| 색 단독 전달 | 없음(크기·글자·속 빈 점·흰 테로 구분) | 없음(▲ 도형 + "D-30 이내 n" 글자) | 없음. 단, 빨간 면 위 빨간 원은 크기와 어두운 테두리로만 갈림 |
| 지자체 면 | 22%로 흐려져 사실상 꺼짐 | 22% | 50%, "원 끄기"면 100% |

**C가 왜 낫고 왜 못한가**:
- **낫다**: 지자체 면 정보를 끄지 않습니다. 범례 하나(열=남은 기간, 행=면/원/글자)로 두 종류 기관이 같은 문법을 씁니다. 레이어를 따로 켜고 끌 수 있습니다.
- **못하다**: 원 겹침은 A와 똑같이 풀리지 않습니다. 50% 면 위에서는 파스텔 빨강 원 테두리 대비가 **2.2:1**로 떨어집니다(어두운 후광 덕에 원 경계 대비 4.4:1은 유지). 노랑 면은 올리브색(#7d7c64)으로 탁해집니다.
- **그래서**: C는 B의 전국 칸과 함께 써야 완성됩니다.

## 4. 우선순위 이슈 (구현 시)
- **P1. 밀집지 겹침**
  - 근거: A·C 전국에서 45/61 겹침, 61/61이 누르기 어려움. 수도권 ×4에서도 31개.
  - 왜: 성공 기준인 "전국 지도에서 한눈에"(PRODUCT.md)가 서울·세종에서 깨집니다.
  - 방향: 전국 축척(×2.4 미만)은 B식 칸 + 30일 이내 원 유지. 그리고 지도 클릭이 아니라 오른쪽 "화면 안 임박순" 목록(버튼)을 정식 접근 경로로 둡니다.
- **P1. DESIGN.md 계약과 충돌: 유형별 모양**
  - 근거: DESIGN.md Shapes의 "▲ 공공기관 ■ 공기업 ● 대학병원 ⬟ 대학교" 규칙. `logic.markerShape`(logic.js:260)와 상단 `.fsw` 필터 글리프가 이 규칙과 1:1로 맞물려 있습니다.
  - 왜: 사용자 결정(원으로 통일)대로 하면 유형 모양 규칙이 없어지고, 필터 글리프와 지도 모양이 서로 어긋납니다.
  - 방향: 원으로 통일하고 유형은 필터·툴팁·목록이 맡게 할지, 크기는 유지한 채 모양으로 유형을 남길지 결정이 필요합니다. 모양마다 면적 인지가 달라 크기 비교에는 원이 유리합니다. 결정 뒤 DESIGN.md를 고쳐야 합니다(8번 질문).
- **P2. 크기 경계와 색 경계 불일치**
  - 근거: `computeUrgency`는 182일 이내를 빨강으로 봅니다(logic.js:92). 크기의 작은 원은 180일까지입니다.
  - 왜: D-181·182는 빨간 점으로 나옵니다. 크기 단계와 색 단계가 이틀 어긋납니다.
  - 방향: 작은 원 경계를 182일로 맞추기를 권장합니다(기획 확인 필요).
- **P2. '추측' 날짜 표시가 새 원에 없음**
  - 근거: 현행은 `confidence==='추측'`이면 빗금을 덧씌웁니다(render.js `drawMarkers`).
  - 방향: 모든 크기에 테두리 점선(`stroke-dasharray:2 1.5`)을 씁니다. 빗금은 10px 이하에서 안 보입니다.
- **P2. 미상(속 빈 점) 링 대비 부족**
  - 근거: #7c8699 링은 A 면(22%) 위에서 2.8:1, C 면(50%) 위에서 1.2:1입니다.
  - 방향: 링을 `--muted`(#98a1af)로 바꾸고 바깥에 1px #0f1420 후광을 둡니다. 어두운 속(#0f1218)이 면 대비 4.4:1로 형태를 받쳐 줍니다.
- **P3. 계약과 코드 어긋남(기존 문제)**
  - 근거: DESIGN.md는 클러스터 배지를 "#202835로 재도색 완료"라고 적었는데, render.js:421은 아직 `#1a2029`입니다.
  - 방향: 이번 구현에서 클러스터(8개 이상 24px 칸 → 숫자만 표시)를 없애거나 바꾸면 함께 해소됩니다. 이 클러스터 배지도 숫자만 보여 임박도를 숨기는 문제가 B와 같습니다.

## 6. 규격 (구현용)
### 원 표식
| 단계 | 반지름(px) | 지름 |
|---|---|---|
| D-30 이내 | 13 | 26 |
| D-31~90 | 8 | 16 |
| D-91~180(권장 182) | 5 | 10 |

- 크기는 **화면 px로 고정**합니다. 확대해도 커지지 않으므로 이것이 최대 크기 상한입니다.
- 180일 이내 원:
  - 채움: 해당 단계 파스텔 색, `fill-opacity:.34`
  - 테두리: 같은 색 1.6px
  - 아래 후광: #0f1420 3.2px
- 점: 단계 색 채움 + #0f1420 1px 테두리.
- 미상: #0f1218 속 + 링(→ #98a1af 권장).
- 경과: #0f1218 속 + `--fg` 1.5px 링, 반지름 3.6. Overdue Stamp Rule처럼 색상을 쓰지 않습니다.
- 그리는 순서: 큰 원 → 중간 → 작은 → 점. 같은 단계 안에서는 임박한 것이 위.
- 누르는 영역: 원 단계는 반지름 ≥12, 점은 6.

### D-n 글자
- 11px `--mono` 700, #f5c1c3(= #f0a6a9 70% + 흰색, Two-Tier 밝힘 규칙), 후광 #0f1218 3px.

### 면 투명도

- C는 원을 켜면 0.5, 원을 끄면 1, 면을 끄면 0.07.

### B 시도 칸
- 유리 스타일: rgba(24,30,41,.86) + blur 8px + 흰색 8% 테두리, 반경 10px, 11px 글자.
- 30일 이내가 있으면 테두리를 `--red` 55% 섞음으로 바꿉니다.
- 칸은 지도 좌우 바깥 기둥에 위도 순으로 놓습니다. 경도 127.6 기준으로 좌우를 나누고 칸 간격은 8px입니다.
- 지시선: 1px #98a1af 55%. 30일 이내가 있으면 #e07856 80%.
- 펼침 경계는 ×2.4입니다. 칸을 누르면 그 시도 범위로 확대하며, 확대 배율은 최소 ×2.7입니다.

function inView(i) { var s = scr(i.b); return s[0] > -30 && s[0] < W + 30 && s[1] > -30 && s[1] < H + 30; }
function rectHit(p, q) { return p.x < q.x + q.w && q.x < p.x + p.w && p.y < q.y + q.h && q.y < p.y + p.h; }
function rectCircle(q, c) { var nx = clamp(c.x, q.x, q.x + q.w), ny = clamp(c.y, q.y, q.y + q.h), dx = c.x - nx, dy = c.y - ny; return dx * dx + dy * dy < c.r * c.r; }

function drawMarkers(list) {
  var items = list.map(function (i) { return { i: i, s: scr(i.b), r: R[i.tier] }; });
  items.sort(function (a, b) { return (ORDER[a.i.tier] - ORDER[b.i.tier]) || ((b.i.d === null ? 9e9 : b.i.d) - (a.i.d === null ? 9e9 : a.i.d)); });
  var selItem = null;
  items.forEach(function (o) {
    var i = o.i, g = el('g', { transform: 'translate(' + o.s[0].toFixed(1) + ',' + o.s[1].toFixed(1) + ')' }, mkL);
    if (BIG[i.tier]) { el('circle', { r: o.r, 'class': 'halo' }, g); el('circle', { r: o.r, 'class': 'disc', fill: P[i.band], stroke: P[i.band] }, g); }
    else if (i.tier === 'dot') el('circle', { r: R.dot, 'class': 'dot', fill: P[i.band] }, g);
    else el('circle', { r: R[i.tier], 'class': i.tier }, g);
    el('circle', { r: BIG[i.tier] ? Math.max(o.r, 12) : 6, 'class': 'hit', 'data-id': i.id }, g);
    if (i.id === V.sel) selItem = o;
  });
  /* D-n 글자: 임박한 순서로 오른쪽, 왼쪽, 위, 아래 중 빈 자리 */
  var t1 = items.filter(function (o) { return o.i.tier === 't1'; });
  var circles = t1.map(function (o) { return { x: o.s[0], y: o.s[1], r: o.r, o: o }; });
  var placed = [], hidden = 0;
  t1.slice().sort(function (a, b) { return a.i.d - b.i.d; }).forEach(function (o) {
    var txt = dd(o.i.d), w = txt.length * 6.2 + 4, h = 13, x = o.s[0], y = o.s[1], r = o.r;
    var cands = [[x + r + 4, y - h / 2, 'start'], [x - r - 4 - w, y - h / 2, 'end'], [x - w / 2, y - r - 4 - h, 'middle'], [x - w / 2, y + r + 3, 'middle']];
    var pick = null;
    for (var n = 0; n < cands.length && !pick; n++) {
      var q = { x: cands[n][0], y: cands[n][1], w: w, h: h };
      var bad = placed.some(function (p) { return rectHit(p, q); }) || circles.some(function (c) { return c.o !== o && rectCircle(q, c); });
      if (!bad) pick = cands[n];
    }
    if (!pick) { pick = cands[0]; hidden++; }
    placed.push({ x: pick[0], y: pick[1], w: w, h: h });
    var tx = pick[2] === 'start' ? pick[0] + 2 : pick[2] === 'end' ? pick[0] + w - 2 : pick[0] + w / 2;
    var t = el('text', { x: tx.toFixed(1), y: (pick[1] + h - 3).toFixed(1), 'text-anchor': pick[2], 'class': 'dlab' }, lbL); t.textContent = txt;
  });
  /* 측정: 겹친 원, 누르기 어려운 원 */
  var big = items.filter(function (o) { return BIG[o.i.tier]; }), ov = 0, hard = 0;
  big.forEach(function (a) {
    var isOv = false, isHard = false;
    items.forEach(function (b) {
      if (a === b) return;
      var dx = a.s[0] - b.s[0], dy = a.s[1] - b.s[1], dist = Math.sqrt(dx * dx + dy * dy);
      if (BIG[b.i.tier] && dist < Math.max(a.r, b.r)) isOv = true;
      if (dist < 24) isHard = true;
    });
    if (isOv) ov++; if (isHard) hard++;
  });
  if (selItem) { [1, 2, 3].forEach(function (n) { el('circle', { cx: selItem.s[0], cy: selItem.s[1], r: Math.max(selItem.r + 2, 6), 'class': 'ring r' + n }, selL); }); }
  return { n: items.length, big: big.length, ov: ov, hard: hard, lab: hidden };
}

var anim = 0;
function animateTo(k, tx, ty) {
  cancelAnimationFrame(anim);
  if (RM.matches) { V.k = k; V.tx = tx; V.ty = ty; render(); return; }
  var k0 = V.k, x0 = V.tx, y0 = V.ty, t0 = performance.now(), D = 380;
  function step(t) { var p = Math.min(1, (t - t0) / D), e = 1 - Math.pow(1 - p, 3); V.k = k0 + (k - k0) * e; V.tx = x0 + (tx - x0) * e; V.ty = y0 + (ty - y0) * e; render(); if (p < 1) anim = requestAnimationFrame(step); }
  anim = requestAnimationFrame(step);
}
function zoomBox(minLon, minLat, maxLon, maxLat, minK) {
  var tl = base(minLon, maxLat), br = base(maxLon, minLat), padPx = 50;
  var k = clamp(Math.min(W / (br[0] - tl[0] + padPx * 2), H / (br[1] - tl[1] + padPx * 2)), minK || 1, KMAX);
  var cx = (tl[0] + br[0]) / 2, cy = (tl[1] + br[1]) / 2;
  animateTo(k, W / 2 - cx * k, H / 2 - cy * k);
}

  zoomBox(lo[0] - .03, lo[1] - .03, hi[0] + .03, hi[1] + .03, BREAK + 0.3);
}

## 7. 이관 메모
- [이관: 기획] **기관 분류 규칙**: 기관 종류 코드(공공기관/공기업/대학교/대학병원/법원/기타)와 "구역형(면) vs 건물형(원)" 분류가 필요합니다.
  - 디자인이 기다리는 것: C의 두 층에 각각 무엇이 들어가는지.
  - 근거: `logic.FILTERABLE_TYPES`에 법원이 없습니다. 법원은 관할구역이 시군구 면과 다를 수 있습니다.
- [이관: 기획] **한 면에 여러 구역형 기관이 겹칠 때**(예: 지자체 + 법원) 면 색을 무엇으로 정할지.
  - 디자인이 기다리는 것: 면 색 규칙. 현행은 지자체 중 가장 임박한 것입니다(render.js `regionUrgencyColor`).
- [이관: 기획] **D-180과 182 경계**를 맞출지, 그리고 **예정일 경과 건**의 크기를 정할지(공고가 진행 중일 수 있어 크게 보여야 할지).
  - 근거: logic.js:92는 지난 것을 포함해 182일 이내를 빨강으로 봅니다. 티커는 D<0 건을 뺍니다.
- [이관: 기획] **좌표 확보 방법**(폐쇄망: 반입 때 주소를 좌표로 미리 변환), 좌표 정확도 등급, 시도 묶음 기준(좌표로 계산 vs 주소의 시도 코드).
- [이관: 개발] **기관 레코드 필드**: `lat`·`lng`(WGS84, 건물 기준점), `type_code`, `sido_code`, `sigungu_code`, 입찰일, confidence(확정/추측), sources(1개 이상). 수백 건은 한 번에 받아 화면에서 그리는 방식이면 충분해 보입니다(시안 300건 렌더에 문제 없음). bbox 조회가 필요한지는 백엔드가 판단합니다.
- [이관: 개발] **프런트 구현 범위**: `render.drawMarkers`(render.js:399~453) 교체, 8개 이상 클러스터를 없앨지, `logic.markerShape` 관련 테스트 영향, `#1a2029` 잔재(render.js:421). 계약 수정은 메인 몫입니다.
- [이관: 데이터] 들여온 좌표와 기관 종류 값의 출처 대조(data-auditor). 시안 값은 모두 가짜입니다.
