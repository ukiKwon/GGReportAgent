### J2. 새 문구는 '(지금 보는 화면이 이 안에 있음)'. 화면 읽기용 덧말은 쉼표 대신 '앞 공백 + 괄호'로 쓴다
**쉼표 앞에 공백이 생기는 원인**:
- `.sr-only`는 `position:absolute`다(index.html:1890). Chrome은 이런 요소를 이름에 이어 붙일 때 앞에 구분 공백을 넣는다.
- 그래서 덧말이 ', …'로 시작하면 이름이 '시작화면 , 고정 탭'이 된다. 마크업에는 공백이 없다(app.js:804).
- CSS로는 이 공백을 없앨 수 없다. 문장 쪽을 고친다.
- **규칙**: 덧말은 ' (…)'처럼 앞 공백으로 시작한다. 한국어 표기에서 괄호 앞 공백은 자연스럽다. Chrome이 넣는 공백과 우리가 넣은 공백은 하나로 접힌다.

**문구를 정한 이유**:
- '지금 보는 화면 포함'은 무엇을 포함하는지 주어가 없어 뜻이 흐렸다.
- 앞 보고서가 낸 후보 '열린 화면 있음'은 탭에 열린 화면 여러 개와 헷갈린다.
- '지금 보는 화면이 이 안에 있음'은 접힌 분류(aria-expanded=false가 '축소됨'으로 읽힘) 바로 뒤에 들어도 뜻이 선다.

**바꿀 것** (`frontend/js/app.js`만 고친다. nav.js·prep·preptask는 건드리지 않는다):
1. **804행**: `<span class="sr-only">, 고정 탭</span>`을 `<span class="sr-only"> (고정 탭)</span>`로 바꾼다. 화면에 보이는 title '시작화면 (닫을 수 없음)'과 같은 괄호 형식이 된다.
2. **853행**: `nav-cat-here` 줄을 지운다. 덧말을 852행의 `nav-cat-sr` 하나로 합친다. 괄호 두 개가 연달아 읽히지 않게 하려는 것이다.
3. **899–914행**: `here` 처리를 아래처럼 `sr` 안으로 합친다.
```js
const num = b.querySelector('.nav-cat-count'), sr = b.querySelector('.nav-cat-sr');
const showN = n > 0 && !open, showHere = b.classList.contains('has-active') && !open;
// (num 처리는 그대로)
```
