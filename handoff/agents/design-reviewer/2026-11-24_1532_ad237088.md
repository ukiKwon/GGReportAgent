## 1. 대상·방법·못 본 것

## 2. 한 줄 총평
선택지가 둘뿐이고 기본값이 늘 보여야 한다. 그래서 단추 바로 앞에 붙는 **기본 선택 상자(`<select>`)**가 가장 작고 안전하다.
- 가장 큰 기회: 완료·진행 문구에 받은 종류를 넣는 것이다(예: '워드 파일(날짜 포함)을 내려받았습니다.'). 그러면 받는 도중 선택을 바꿔도 무엇을 받았는지 헷갈리지 않는다.

## 3. 잘 된 점(지금 그대로 지킬 것)
- 받는 중에 `disabled`가 아니라 aria-disabled를 쓰고, 포커스 링이 있을 때는 흐리지 않는다(링 대비 6.84:1). min-width 7.5em이라 문구가 바뀌어도 폭이 흔들리지 않는다.
- 완료·오류는 .hc-ref 한 줄로만 알리고, 진행은 sr-only status로 낭독만 한다. 새 선택 상자도 이 구조에 그대로 얹힌다.

### ② 문구
- **선택 상자 항목:** `요약본`(기본, 맨 위) / `날짜 포함`
  - 사용자 용어 '날짜정보 포함'에서 '정보'를 뺐다. 뜻은 같고 폭이 줄어든다(팀 결정, 되돌리기 쉬움).
- **선택 상자 이름**(화면에 안 보이는 라벨): `워드에 넣을 내용`
  - 낭독은 "워드에 넣을 내용, 요약본, 콤보 상자"가 된다.
- **단추:** `워드 내려받기` 그대로. 받는 중에는 `만드는 중…` 그대로.
- **진행 낭독**(sr-only): `워드 파일(요약본)을 만드는 중입니다.` / `워드 파일(날짜 포함)을 만드는 중입니다.`
- **완료:** `워드 파일(요약본)을 내려받았습니다.` / `워드 파일(날짜 포함)을 내려받았습니다.`
  - 뒤에 붙는 사진 실패 문구와 '1장에 맞추려고 … 뺐습니다' 문구는 그대로 이어 붙인다.
- **오류 문구**(docxEmpty·docxServer·docxSaveFailed·docxUi)는 바꾸지 않는다. 종류와 무관한 원인이기 때문이다.
- 카드 꼬리의 '열람·내려받기 기록이 남습니다'도 그대로 둔다.

### ③ 기본값과 기억
- 페이지를 새로 불러올 때마다 `요약본`이다. 이 결정은 사용자가 정한 기본값과 맞다.
- **같은 화면을 쓰는 동안**(F5 전까지)에는 마지막 선택을 모듈 변수 하나로 기억한다. 기관을 옮기거나 카드를 다시 그리거나 지도 팝업을 열어도 유지된다.
  - 이유: 여러 기관을 이어서 '날짜 포함'으로 받는 경우 매번 다시 고르게 하지 않기 위해서다.
- **localStorage나 사번별 저장은 하지 않는다.**
  - 이유 1: 다음 날 기본값이 '날짜 포함'으로 바뀌어 있으면 사용자가 정한 기본값과 어긋난다.
  - 이유 2: 이 화면을 처음 보는 사람이 그 설정이 어디서 왔는지 알 수 없다.
  - 사용자가 사번별 기억을 원하면 열린 질문 1로 넘긴다.

### ④ 키보드·스크린리더 (07649ad1·3128db3b 규칙과 맞춤)
- **Tab 순서:** [후보 보기] → 선택 상자 → [워드 내려받기] → [새로 고침] → [기관장 편집]. 고른 다음 받는 순서다.
- **받는 중에도 선택 상자는 막지 않는다**(`disabled` 금지).
  - `disabled`로 막으면 그 칸에 있던 포커스가 body로 빠지는 같은 문제가 다시 생긴다.
  - 대신 docxGo가 시작할 때 고른 값을 고정해 서버에 보낸다. 완료 문구에 그 값을 적는다.
  - 받는 도중 선택을 바꿔도 이번 파일에는 영향이 없다. 다음에 받을 때만 적용된다.
- **포커스 복귀는 지금 규칙 그대로**다(키보드로 눌렀을 때만 단추로 되돌림, 받는 사이 다른 곳으로 옮겼으면 끌어오지 않음).
  - 선택 상자를 바꾸는 것도 다른 곳으로 옮긴 것으로 본다. paneHasFocus가 단추 기준이므로 손댈 것이 없다.
- **카드를 다시 그릴 때 선택 상자 상태를 지킨다.** 다시 그릴 때 `selected`를 기억값으로 내보낸다. 선택 상자에 포커스가 있었다면 다시 그린 뒤 그 칸으로 되돌린다.
  - 이것은 paintDl이 .hc-foot을 통째로 다시 그리는 경우에만 필요하다. frontend-dev가 확인할 것.
- **409(기관장이 비었음) 뒤 포커스 후보 목록:** 단추가 사라지면 선택 상자도 함께 사라진다. 목록(1231)은 지금 그대로 두면 된다.
- 색만으로 전달하는 것은 없다. 항목 이름이 곧 상태다.

### ⑤ 지도 상세 팝업(#dm-box, 720px)에서의 폭

  - 새로 고침: 약 72px

  - 두 묶음 합계: 약 542px. #dm-box 안쪽 폭 약 640px 안에 한 줄로 들어간다.
- 지금 `.hc-foot .sp`에는 flex-wrap이 없다. 안전을 위해 `flex-wrap:wrap; justify-content:flex-end`를 더한다. 줄이 바뀌어도 선택 상자와 단추는 묶음(.hc-dl)으로 붙어서 함께 내려간다.

## 5. 규격

마크업. `.sp` 안에서 기존 docx 단추 자리를 아래로 바꾼다.
```html
<span class="sp">
  <span class="hc-dl">
    <label class="sr-only" for="hc-dlopt">워드에 넣을 내용</label>
    <select id="hc-dlopt" data-hc="docx-opt">
      <option value="sum" selected>요약본</option>
      <option value="date">날짜 포함</option>
    </select>
    <button type="button" data-hc="docx">워드 내려받기</button>
    <!-- 받는 중: aria-disabled="true", 문구 '만드는 중…' (지금과 같음) -->
  </span>
  <button type="button" data-hc="refresh">새로 고침</button>
  <button type="button" data-hc="edit">기관장 편집</button>
</span>
```

CSS. 기존 토큰만 쓰고 새 색·변수는 0개다.
```css
.hc-foot .sp { flex-wrap:wrap; justify-content:flex-end; }          /* 기존 줄에 두 속성 추가 */
.hc-dl { display:inline-flex; align-items:stretch; }               /* 선택 상자와 단추를 한 덩어리로, 높이를 단추에 맞춤 */
.hc-dl select { font-size:12px; padding:0 6px 0 8px; width:auto; border-radius:var(--r) 0 0 var(--r); }
.hc-dl [data-hc="docx"] { margin-left:-1px; border-radius:0 var(--r) var(--r) 0; }
.hc-dl select:focus-visible, .hc-dl button:focus-visible { position:relative; z-index:1; }   /* 이웃 테두리에 링이 가리지 않게 */
```
- 붙인 모양(왼쪽 선택 상자, 오른쪽 단추)이면 '이 선택은 이 단추에 딸린다'가 간격 없이도 읽힌다. 새로 고침·편집과는 6px 떨어진다.
- 기존 `[data-hc="docx"]`의 min-width 7.5em, aria-disabled 흐림, focus-visible 규칙은 그대로 둔다.

## 7. frontend-dev 구현 메모
1. **선택값 기억:** headcard.js에 모듈 변수 `let dlOpt = 'sum';`을 둔다. cardHtml에서 `selected`를 dlOpt로 내보낸다. `change` 이벤트(data-hc="docx-opt")에서 dlOpt를 갱신한다. onPaneClick 위임이 click만 받는다면 change 연결이 따로 필요하다.
2. **docxGo:** 시작할 때 `const opt = dlOpt;`로 값을 고정한다. `fetchDocx(instId, screen, opt)`로 넘긴다. docxOkText와 진행 문구가 종류 이름을 받게 한다. 종류 이름 표는 `{sum:'요약본', date:'날짜 포함'}`이다.
3. **paintDl로 다시 그릴 때:** 선택 상자에 포커스가 있었다면 다시 그린 뒤 `#hc-dlopt`로 되돌린다(받는 중 선택을 바꾸는 경우).
4. **CSS:** 5절 그대로. 바꾸는 곳은 `.hc-foot .sp` 한 줄이고, 나머지는 새 규칙이다.
5. **시험 갱신:** 카드 꼬리 마크업을 문자열로 비교하는 head-card 시험, docxOkText·docxBusy 문구 시험. 새 시험은 다음 셋이다.
   - selected가 기억값을 따르는지
   - 받는 중 선택을 바꿔도 보낸 값이 그대로인지
   - 완료 문구에 종류 이름이 들어가는지

## 8. 이관 메모
- [이관: 개발] **서버에 종류를 넘기는 방식**(예: `GET …/head/docx?dates=1`, 없으면 요약본)과 응답 확인 머리를 정해야 한다. 디자인은 그 이름을 받아 fetchDocx에 연결하기를 기다린다. 지금 근거: headcard.js 475–477의 docxUrl·fetchDocx에 인자가 없다.
- [이관: 개발] **'1장 맞춤'으로 빼는 줄 수가 종류마다 달라질 수 있다.** 날짜 포함은 줄이 길어 더 많이 뺄 수 있다. 완료 문구의 뺀 줄 수가 종류별로 맞게 오는지 확인이 필요하다. 지금 근거: docxOkText의 X-Head-Trimmed-*.
- [이관: 기획] **날짜 포함일 때 괄호 안 형식을 정해야 한다.** 사용자 예시는 졸업처럼 날짜 하나뿐이다. 확인할 경우는 셋이다.
  - 경력처럼 기간이면 `(2018.07~2022.06)` / `(2018.07~현재)`로 할지
  - 연도만 입력된 경우 `(2018)`로 할지
