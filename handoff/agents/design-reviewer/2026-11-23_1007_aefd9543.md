# '날짜 의미 확인 중' 표식 바꾸기 — 화면 규격 (design-reviewer)

## 1. 대상·방법·못 본 것
- **방법**: 소스만 읽었다. 읽은 파일은 `frontend/js/dashboard.js`, `overdue.js`, `render.js`, `logic.js`, `index.html`의 CSS, `DESIGN.md` 색·글자 절이다.
- **못 본 것**: Playwright로 화면을 열지 않았다. 서버를 써도 된다는 허락이 지시에 없었다. 그래서 줄바꿈과 실제 행 폭, 렌더된 밑줄 모양은 확인하지 못했다. 적용한 뒤 qa-verifier가 화면을 열어 확인해야 한다.
- **지시와 다른 사실 2가지**:
  - **지도 위에는 이 표식이 없다.** `render.js:50`은 아이콘(점선 원 + i)을 정의만 한다. 실제로 쓰는 곳은 `overdue.js:50`의 경과 패널과 로그인 경과 팝업 행 하나뿐이다. 지도 툴팁의 '결과 확인'(`render.js:466`, `logic.js:325`)은 이 표식이 아니다. 공고 마감이 지났다는 뜻으로, 같은 `check` 이름을 쓰는 다른 개념이다. 이번에 바꾸지 않는다.
  - **경과 행에는 날짜 자체가 없다.** `dashboard.js:606`의 경과 행은 D+n과 안내 문장만 보이고 날짜는 보이지 않는다. 밑줄을 그을 날짜가 없으므로 날짜를 새로 넣어야 한다(⑤ 참조).

## 2. 결론과 가장 큰 기회
- **결론**: '의미 확인 중'은 무엇을 확인하는지, 누가 확인하는지, 내가 무엇을 하면 되는지를 하나도 말하지 않는다. 그래서 시스템이 무언가를 처리 중이거나 오류가 난 것처럼 읽힌다.
- **가장 큰 기회**: 날짜마다 이름표를 붙이고, 확실하지 않은 날짜에만 세 가지를 함께 단다.
  - 그 날짜 글자에 빨간 점선 밑줄
  - 바로 아래에 빨간 12px 문장 한 줄
  - 문장은 "무엇과 무엇을 구분하지 못했는지 + 할 일"로 쓴다
- '확인 중'이라는 말은 화면에서 모두 없앤다.

## 3. 잘 된 점
- 경과·공고 정렬에서 불확실한 기관을 맨 뒤로 보내는 판단(`logic.js:434`)은 옳다. 그대로 둔다.
- 아이콘이 느낌표(!)가 아니라 점선 원 + i라서 경고가 아닌 안내를 뜻한다. 이 방향은 맞다. 문구만 그 뜻을 따라가지 못했다.

## 4. 우선순위 이슈
- **P1 — 무슨 날짜인지 알 수 없다.**
  - 근거: `dashboard.js:444` chkHtml, `:648`, `:906`, `overdue.js:50`.
  - 왜 문제인가: 사용자가 실제로 "오류처럼 보이고 뜻을 모르겠다"고 했다(11-23).
  - 수정 방향: ①·③의 문구 체계로 바꾼다.
- **P1 — 설명이 마우스 올림(title)에만 있다.**
  - 근거: `overdue.js:37` TITLE_CHECK는 `title` 속성에만 들어 있다.
  - 왜 문제인가: 키보드 사용자, 터치 사용자, 화면낭독기 사용자 대부분이 이 설명을 받지 못한다.
  - 수정 방향: 보이는 글자(보조 문구)로 옮기고 title은 지운다.
- **P2 — 색이 다른 표식과 섞여 있다.**
  - 근거: `.db-chk`는 `--orange`(`index.html:1777`)로, '개원 확인 필요', '수집 기록과 다름', '겹치는 약정'과 같은 모양이다. 경과 패널(`.ov-conf.is-check`, `index.html:1645`)은 회색 점선 테두리 칩이다. 같은 뜻이 곳마다 다른 모양으로 보인다.
  - 수정 방향: `.db-chk`를 고쳐 쓰지 않는다(다른 세 표식이 함께 바뀐다). 새 클래스 2개(`.dt-q`, `.dt-q-note`)를 만든다.
- **P2 — 빨강의 뜻이 겹친다.**
  - 근거: `DESIGN.md` 66·73행에서 `--red`는 임박을 뜻한다(빨간 윤곽 칩 + ▲ + D-n).
  - 왜 문제인가: 사용자가 빨강을 지정했으므로 따른다. 다만 임박과 모양으로 갈라야 한다. 불확실한 날짜에는 칩(상자)을 쓰지 않고, 점선 밑줄 + 문장 + i 아이콘만 쓴다.
  - 수정 방향: `DESIGN.md`에 아래 규칙을 더해야 한다(호출자가 직접 수정). 문안: "`--red`의 둘째 용도 — 종류가 불확실한 날짜: 날짜 글자에 2px 점선 밑줄 + 바로 아래 12px 빨간 문장 + 점선 원 i 글리프. 상자·틴트 없음. 임박(윤곽 칩 + ▲ + D-n)과 모양으로 구분한다."

## 5. 문구·접근성

### ① 날짜 이름표 체계
날짜 앞이나 뒤에 붙는 이름(12px, `--muted`)이다.

| 날짜 근거 | 이름표 | 불확실할 때 |
|---|---|---|
| 확정 공고 (basis notice, 확정) | 공고일 | 공고일(확인 필요) |
| 접수 기간 | 접수 MM.DD~MM.DD | 그대로 |
| 약정 만료 (basis expiry) | 약정 만료일 / 입찰 예정일(약정 만료 6개월 전 추정) | 약정 만료일(확인 필요) |
| 지난 선정일 + 주기 | 입찰 예정일(추정) | 그대로 |
| **지금 7곳** (공고일인지 만료일인지 모름) | **공고일 또는 약정 만료일** | 항상 불확실 표시 |

- 지금 데이터는 어느 칸이 불확실한지 구분하지 못한다(`isDateUnderReview`, 기관 키 목록 하나). 그래서 7곳은 모두 마지막 줄 "공고일 또는 약정 만료일"로 표시한다.
- 사용자가 예로 든 '약정 만료일에 밑줄'과 '공고일에 밑줄'을 각각 쓰려면, 날짜 칸마다 불확실 여부를 담는 데이터가 필요하다. 7번 이관 메모로 넘긴다.

### ③ 보조 문구 예시
문장 구조는 "무엇을 구분하지 못했는지 + 할 일"이다.

- **행(짧게, 한 줄 목표)**:
  - 지금 7곳: `공고일인지 약정 만료일인지 원문 확인 전입니다. 출처를 확인하세요.`
  - 약정 만료일이 불확실할 때: `약정 만료일이 아니라 공고일일 수 있습니다. 출처를 확인하세요.`
  - 공고일이 불확실할 때: `공고일이 아니라 약정 만료일일 수 있습니다. 출처를 확인하세요.`
- **카드(기관 상세, 두 줄까지)**: `이 날짜가 공고일인지 약정 만료일인지 원문으로 아직 확인하지 못했습니다. D+일수와 예정일은 이 날짜로 셌습니다. 아래 [출처 n건 보기]에서 원문을 확인하세요.`
  - 'D+일수는 이 날짜로 셌다'는 `logic.js:347`(effectiveBid 날짜로 일수 계산)을 근거로 썼다.

### 접근성 (⑥)
- **색만으로 알리지 않는다.** 신호는 네 겹이다. (a) 점선 밑줄이라는 모양 (b) 보이는 문장 (c) i 아이콘 (d) 이름표 "또는 / (확인 필요)". 흑백으로 인쇄해도 전달된다.
- **대비(계산값)**:
  - `--red` #bd2c0f 글자: 흰 바탕 6.0:1, `--panel2` #f6f7f9 약 5.6:1, `--bg` #e9ecf0 5.1:1, 선택 행(포인트 13% 틴트) 약 4.9:1. 모두 4.5:1 이상이다.
  - 밑줄은 글자가 아닌 요소라 3:1 기준이며 넉넉히 넘는다.
- 문장은 목록 항목(`li role="option"`)과 `dd` 안에 보이는 글자로 두어 접근성 이름에 자연히 포함되게 한다. `title`, `aria-describedby`에만 두는 방식은 쓰지 않는다.
- 아이콘은 `aria-hidden="true"`를 유지한다. 뜻은 문장이 전한다.
- 글자 크기는 12px 이상이다(DESIGN.md 최소 기준).

## 6. 규격 (② 모양)

```css
/* 종류가 불확실한 날짜 글자(.v / .d / .ov-date 위에 덧붙임) */
.dt-q { text-decoration-line: underline; text-decoration-style: dashed;
  text-decoration-color: var(--red); text-decoration-thickness: 2px;
  text-underline-offset: 3px; text-decoration-skip-ink: none; }
/* 바로 아래 보조 문구 */
.dt-q-note { display: block; margin-top: 2px; font-size: 12px; line-height: 16px;
  font-weight: 400; color: var(--red); }
.dt-q-note .gph { width: 12px; height: 12px; vertical-align: -2px; margin-right: 4px; } /* render.ICONS.check, currentColor */
/* 범례 견본: 16px 길이 점선 */
.lg-q { display: inline-block; width: 16px; height: 0; border-top: 2px dashed var(--red);
  vertical-align: middle; margin-right: 6px; }
```

- **밑줄**: 2px 점선, 색 `--red`, 글자에서 3px 띄운다. 점선을 고른 이유는 '추정 / 확정 아님'을 나타내는 기존 어휘(빗금, 점선)와 맞추기 위해서다. 물결선은 맞춤법 오류처럼 보여 쓰지 않는다. 실선은 링크처럼 보여 쓰지 않는다.
- **표(행) 안** (`.db-row .meta`, 경과 패널·팝업 행):
  - 보조 문구는 행 안의 둘째 줄이다. 행의 이름 칸 왼쪽 끝에 맞추고, 행 높이는 늘어나는 것을 허용한다.
  - 짧은 문구를 쓰고, 넘치면 줄을 바꾼다(말줄임 금지).
  - 행 상자, 바탕 틴트, 빨간 테두리는 넣지 않는다.
- **카드 안** (기관 상세 `dd`):
  - 같은 `dd` 안에서 날짜 줄 아래에 한 블록으로 둔다. 긴 문구를 쓰고 두 줄까지 허용한다.
  - 기존 `.db-why`(근거 문장)는 불확실할 때 빼고 보조 문구로 대신한다. 같은 이야기를 두 번 하지 않기 위해서다.

## 8. 이관 메모
- `[이관: 개발]` 날짜 칸마다 '불확실' 여부와 후보 뜻(공고일일 수도 / 만료일일 수도)을 담을 자리가 필요하다.
  - 디자인이 기다리는 것: ①표의 '공고일(확인 필요)', '약정 만료일(확인 필요)' 두 갈래를 쓰려면 이 자리가 있어야 한다.
  - 지금 보이는 근거: `logic.js:203` OVERDUE_CHECK_KEYS는 기관 단위 목록 하나뿐이라 지금은 '또는' 한 갈래만 쓸 수 있다.
- `[이관: 개발]` 경과·공고 항목의 `check` 이름이 두 뜻으로 쓰인다.
  - 공고 쪽(`logic.js:257`)은 결과 확인, 경과 쪽(`logic.js:354`)은 날짜 종류 불확실이다. `dashboard.js:80`에서 `resultCheck`로 이름을 갈라 놓았지만 헷갈리기 쉽다.
  - 디자인이 기다리는 것: 바꾼 문구가 엉뚱한 행에 붙지 않는지 시험으로 확인.
- `[이관: 데이터]` 7곳(관악·광명·삼척·양양·정읍·영천·청송)의 원문 대조는 data-auditor가 진행 중이다(권장안 ⓐ). 표시 규칙은 데이터 정정과 상관없이 유지한다.
- `[이관: 기획]` 보조 문구의 '할 일'을 '출처를 확인하세요'로 둘지 정해야 한다.
  - 디자인 기본 보기 역할의 사용자에게도 같은 문구를 보일지, 정정 요청 경로(누구에게 알리는지)를 덧붙일지에 따라 문장이 달라진다.

## 9. 디자인 쪽 열린 질문
- 기관 상세 카드의 보조 문구를 두 줄(D+일수를 이 날짜로 셌다는 설명 포함)로 둘지, 행과 같은 한 줄로 줄일지. 답에 따라 카드 문구만 바뀐다.
