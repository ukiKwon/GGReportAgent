대상은 NEXT 106 미커밋분이다: `frontend/js/doccheck.js`, `frontend/js/designer.js`(245–965줄), `frontend/index.html`(CSS 1205–1254, #tab-designer 3008–3025, #dc-submit-modal 3270–3282).

못 본 것: Playwright 브라우저를 다른 세션이 쓰고 있어("Browser is already in use") 8080을 열지 못했다. 그래서 1280px 한 줄, 실제 렌더된 배지 대비, 펼침 화살표 회전은 실측하지 못했다. 아래 숫자는 모두 계산값이다.

## 2. 총평
문구 표(사유 18종·오류·위치·안내), 배지 순서, 접근성 속성, 제출 확인창 A/B, 헤더(6-6), CSS 토큰이 규격과 거의 글자 그대로 맞는다. 새 hex나 새 변수는 없다(`#eef1f5`는 규격에 있던 값). 팀 결정 6건(확인함 n건, withObj, “ ” 화면 부착, .dc-tg svg 선, 제출 중 Esc·바깥 클릭 차단, 포커스 대체)도 모두 반영돼 있다.

## 4. 규격과 다른 곳 / 이슈
**P2-1 긴 사유 문구가 파일 줄을 깰 수 있음(실측 필요, 커밋은 막지 않음)**
- 근거: `.dg-file`은 줄바꿈 없는 flex이고, 파일명 `.dg-dl`은 `min-width:0`이다(index.html 1193). 줄의 `.dc-why`에는 폭 제한이 없다(designer.js 406). 예를 들어 FORMAT_UNSUPPORTED 문구(약 45자, 12px로 약 480px)는 이 줄에 그대로 들어간다.
- 1280 화면에서 #dg-pane은 사이드바와 #dg-list(270)를 빼면 약 700–750px로 추정한다. 이 폭에 크기·시각(약 170) + 배지(약 90) + 사유(480) + [점검 결과](약 95) + [삭제]가 들어가야 한다. 그러면 파일명이 거의 0까지 줄고, 사유는 2–3줄로 접힐 가능성이 크다.
- 이는 내 규격 6-2의 결함이다(사유를 줄 안에 둔 것).
- 수정 방향:
  - 최소안: `.dg-file .dg-dl { min-width:8em; }`, `.dg-file .dc-why { flex:0 1 20em; min-width:0; line-height:1.4; }`
  - 더 나은 안: 줄에는 배지와 [다시 점검]만 남기고, 사유는 펼침 칸 안내 줄로 옮긴다(P3-1과 함께).

**P3-1 결과가 없는 펼침 칸이 빈칸으로 보임**
- 근거: `panelEl`이 `if (!hits.length) return p;`(designer.js 320)로 끝난다. 그래서 DONE이면서 찾은 것이 0건이거나 NOT_CHECKED이면 칸에 머리 줄([다시 점검])만 남는다.
- 수정 방향: 이 경우 `.dc-why` 한 줄을 넣는다.
  - DONE: "찾은 이름 없음"
  - NOT_CHECKED·ERROR: `reasonInfo(d.reason).text`
  - P2-1을 더 나은 안으로 가면 사유는 여기가 정본 자리가 된다.

**P3-2 펼침 칸의 [다시 점검]이 다시 해도 소용없는 사유에도 보임**
- 근거: designer.js 295는 언제나 [다시 점검]을 그린다. FORMAT_UNSUPPORTED·ENCRYPTED 같은 사유에서 누르면 같은 결과만 돌아온다.
- 규격 6-3이 "잠긴 작업에서도 누를 수 있음"이라고만 해서 생긴 빈틈이다. state가 NOT_CHECKED이고 `retry:false`이면 숨기기를 권한다. 커밋 뒤에 해도 된다.

**P3-3 [점검 결과] 글자 뒤 공백 중복**
- `fidBtn('점검 결과 ', …)`(415)의 끝 공백과 `gap:4px`가 겹쳐, 글자와 화살표 사이가 약 8px로 벌어진다. `'점검 결과'`로 공백을 빼면 된다.

**P3-4 [돌아가서 확인]의 포커스 대체 목표가 없음**
- 근거: restoreFocus의 `first` 분기(691–699)는 체크칸이 없으면 아무 데도 포커스를 두지 않는다(상세를 불러오다 오류가 난 경우 등). 그러면 포커스가 body로 빠진다.
- 수정 방향: 체크칸을 못 찾으면 `tryFid('toggle')`로 [점검 결과] 토글에 포커스를 둔다.

**P3-5 변형 A에서 [취소]가 채운 주 단추**
- 규격 6-5 마크업이 `.dlg-go`를 #dc-sm-back에 고정해 둔 탓이다. 변형 B(돌아가서 확인)에는 맞다. 하지만 일반 결재 요청(A)에서 [취소]가 채운 주 단추가 되는 것은 다른 .dlg 창들과 다르다.
- 이번에는 규격대로 두고 기록만 남긴다. 바꾸면 A일 때 go에 .dlg-go를 주고 back에서 빼면 된다.

**P3-6 조사 '을/를'**
- withObj는 마지막 글자가 라틴 문자이면 '를'을 쓴다. pptx·pdf·ppt·png·jpg는 맞다. zip만 읽으면 '집'이라 '을'이어야 하지만 '를'이 붙는다. 무시해도 된다.
