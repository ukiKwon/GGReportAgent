## 4. 우선순위 이슈

**P1-1 발언을 고치면 가린 자리를 지워 실명을 되살릴 수 있다(미리보기·상세 공통)**
- 근거: `openEditor`는 textarea 값을 그대로 보낸다(board-minutes.js 730–735행). `[이름]` 칩을 지우고 외부인 이름을 적어도 화면은 막지 않는다. 서버 `MASK_REQUIRED`는 직원 명단·개인정보 패턴만 잡는다(이전 규격 6-5). 기관·다른 은행 사람의 이름은 '추가로 가릴 단어'에 없으면 통과한다.
- 왜 문제인가: 고치기 기능이 가림을 푸는 통로가 된다. 이번 기능으로 미리보기에서도 고칠 수 있게 되면 노출 면이 커진다.
- 수정 방향: 편집기는 원래 글에 있던 가림 토큰 수를 종류별로 세고, 고친 글에 그보다 적으면 반영과 저장을 막는다(6-3 `mn.lostMasks`). 서버도 같은 규칙으로 막아야 한다(이관: 개발·보안).

**P2-1 미리보기 안의 [원문 보기] 10개가 동작하지 않는다(실측)**
- 근거: 미리보기 상자의 첫 구간 [원문 보기]를 눌러도 포커스는 `#mn-pv-h`에 그대로 있고 `.is-target`은 0개였다. 원인은 `goSeg`가 `ctx.cur`가 null이면 그냥 돌아오는 것이다(685–686행). 미리보기는 `cur:null`로 그린다(1155행).
- 왜 문제인가: 이름표를 정하려면 그 참석자의 발언을 찾아 읽어야 하는데 이동 수단이 고장 나 있다. 원문은 상자 안 2121px 아래에 있다.
- 수정 방향: 미리보기 모드에서는 `pvJump(seq)`가 상자 안에서 스크롤하고 강조하고 포커스한다(6-3). 이 함수를 이름표 표의 [발언 보기]와 함께 쓴다.

**P2-2 [고치기] 버튼 높이 20.7px(실측) — 규격 28px에 못 미친다**
- 근거: 상세의 `#mn-ed-utter-*`·`#mn-ed-item-*`는 `.link-btn`(padding 2px 4px, 12px)이라 높이가 20.66px다. 이전 규격 5절은 "고치기 ≥28px"였다.
- 수정 방향: 6-7 CSS로 `min-height:28px`를 준다.

**P3-1 발화자 칸 72px — 이름표가 들어가지 않는다**
- 근거: 실측 `grid-template-columns: 72px 52px …`. 12px 한글은 6자쯤에서 넘친다.
- 수정 방향: 96px로 넓히고 이름표는 최대 8자로 한다. 이름표 아래에 원래 번호를 두 번째 줄로 둔다(6-2).

**P3-2 고친 뒤 [취소]하면 고친 내용이 확인 없이 사라진다**
- 근거: `cancelUpload`는 바로 `S.up = null`을 한다(977행).
- 수정 방향: 고친 것이 1건 이상이면 인라인 확인 줄을 띄운다(6-5).

## 5. 문구 / 접근성

### 문구 원칙(이번 추가분)
- 기능 이름은 **'발화자 이름표'**, 동사는 **'바꾸기'**로 쓴다. 발언은 기존대로 '고치기'다. '수정'·'편집'은 섞어 쓰지 않는다.
- 미리보기의 반영 버튼은 **[반영]**이다. 서버에 쓰지 않으므로 [저장]이라고 하지 않는다. 상세 편집기의 [저장]은 그대로 둔다.
- 원래 표기 '참석자 N'은 지우지 않고 늘 같이 보인다. 이름표는 올린 사람이 판단한 것이고, 자동 화자 구분이 틀렸을 수 있기 때문이다.

## 6. 규격

### 6-1. 결정: 이름표는 **번호별 표 하나**로 바꾼다(줄마다 바꾸지 않는다)
- 근거(실측): 발언은 59줄이고 번호는 7개다(참석자 1: 15, 2: 9, 3: 17, 4: 3, 5: 11, 6: 3, 7: 1). 같은 번호는 같은 목소리이므로 번호 단위가 의미 단위다. 줄마다 바꾸면 같은 사람에게 이름표가 갈라질 수 있다.
- 클로바가 한 사람을 두 번호로 나눈 경우: 두 번호에 같은 이름표를 허용하고 안내 한 줄을 띄운다.
- 한 번호에 두 사람이 섞인 경우: **1차 범위 밖**이다(이관: 기획).
- 고친 표시는 상태 열의 배지 '바꿈'으로 한다. 되돌리기는 줄마다 둔다.

```
  │ … 원문                                                      │
  │ 구청장     07:24  발언 글 …                   고침 [되돌리기][고치기] │

```
- **이름표 입력의 반영 시점**: 이름표는 `change`(칸을 떠날 때·Enter) 때 검사한다. 통과하면 `u.fix.labels[no]`에 넣고, 미리보기 상자의 해당 번호 줄만 다시 그린다. 포커스는 입력칸에 그대로 둔다. `input` 이벤트마다 다시 그리지 않는다.
- **추천 목록**: `datalist#mn-lbl-list`에 사용자 예시 4개만 둔다(구청장, 영업부장, 기관 측, 은행 측). 더 늘리는 것은 기획에 넘긴다.
- **이름표 검사(화면)**: 6-3 `mn.labelCheck`. 이름 대조 대상은 이 미리보기의 '직원 이름과 같아 가린 말' 후보(`u.cands` 키)와 '추가로 가릴 단어' 목록이다. 이것으로는 외부인 실명을 다 막지 못한다. 최종 판정은 서버가 한다(이관).
- **발화자 칸**: `span.mn-spk` 안에 `b`(이름표, 없으면 '참석자 N')와 `small`(이름표가 있을 때만 '참석자 N')을 둔다.
- **발언 [고치기]**: 미리보기에서는 모든 줄에 보인다. 잡음 줄도 펼치면 보인다. 열면 기존 `openEditor` 모양에 버튼만 [반영] [취소]로 바뀌고, 서버를 부르지 않는다. 반영한 글이 원래 글과 같으면 고친 것을 지운다(되돌리기와 같다).
- **가림 칩**: 고친 글도 `mn.textNodes`로 그려 `[이름]`·`[가림]` 칩이 유지된다. 이름표에는 칩을 쓰지 않는다(이름표에 `[` `]`는 금지).
- **다시 미리보기와의 관계(기본 가정)**: 고친 내용은 `mn.signature`에 넣지 않는다. 고쳐도 stale이 되지 않고 [다시 미리보기]도 필요 없다. 서버가 저장할 때 고친 글을 다시 가린다고 가정한다.
- **파일 등을 바꿔 다시 미리보기를 한 경우**: 응답이 오면 `mn.mergeFix`를 돌린다.
  - 이름표는 새 응답에 그 번호가 있으면 유지하고, 없으면 버린다.
  - 발언은 같은 `seq_no`의 원래 글(`orig`)이 새 응답과 글자 하나까지 같을 때만 유지하고, 다르면 버린다.
  - 버린 수는 status와 `#mn-fix`에 쓴다.

### 6-3. 상태·순수 함수(시험 가능하게)
- 상태: `u.fix = { labels: { '3': '구청장' }, utt: { '12': { orig: '…', text: '…' } } }`. 메모리에만 두고 `stop()`과 취소 때 비운다. localStorage·sessionStorage에 두지 않는다.
```js
mn.LABEL_MAX = 8;
mn.LABEL_SUGGEST = ['구청장', '영업부장', '기관 측', '은행 측'];
// names: u.cands 키 + 추가로 가릴 단어. 빈칸 = 원래 표기.
mn.labelCheck = function (s, names) {
  const t = String(s == null ? '' : s).replace(/\s+/g, ' ').trim();
  if (!t) return { ok: true, value: '' };
  if (t.length > mn.LABEL_MAX) return { ok: false, code: 'LEN' };
  if (!/^[가-힣A-Za-z0-9 ·]+$/.test(t)) return { ok: false, code: 'CHAR' };
  if (/^참석자\s*\d+$/.test(t)) return { ok: false, code: 'SPK' };
  if ((names || []).some(function (n) { return n && t.indexOf(n) >= 0; })) return { ok: false, code: 'NAME' };
  return { ok: true, value: t };
};
const MASK_G = /\[이름\]|\[가림(?:: 개인정보 의심 줄)?\]/g;
mn.maskCount = function (s) { const c = {}; (String(s || '').match(MASK_G) || []).forEach(function (k) { c[k] = (c[k] || 0) + 1; }); return c; };
mn.lostMasks = function (orig, next) { const a = mn.maskCount(orig), b = mn.maskCount(next);
  return Object.keys(a).reduce(function (n, k) { return n + Math.max(0, a[k] - (b[k] || 0)); }, 0); };
```
- `mn.fixCount(fix)` → `{spk, utt}`: 이름표는 빈칸이 아닌 것, 발언은 `text !== orig`인 것을 센다.
- `mn.mergeFix(fix, pv)` → `{fix, droppedUtt, droppedSpk}`
- `mn.spkView(u, labels)` → `{main, sub}`
- `mn.buildForm`: `digest`가 있을 때(저장)만 `o.edits = { speakers:[{no,label}], utterances:[{seq_no,text}] }`를 싣는다. 비었으면 키를 넣지 않는다. 미리보기 요청에는 싣지 않는다.
- 서버가 화자 번호를 숫자로 줘야 한다: 미리보기·원문 응답 `items[]`에 `speaker_no`(정수)가 필요하다. 지금은 `speaker` 문자열 "참석자 3"뿐이다. 받기 전까지는 `/^참석자 (\d{1,3})$/`로 뽑는 임시 처리를 쓴다(이관).

### 6-4. 저장 후 상세에서 이름표 바꾸기(can_edit)
- 자리: [고치기 켜기]가 켜져 있고 `viewer.can_edit`일 때, '원문' h4 옆에 [발화자 이름표 바꾸기](`id=mn-lbl-open`, `aria-expanded`, `aria-controls=mn-spk-fs`)를 둔다. 누르면 원문을 아직 안 받았을 때 받고(`loadTranscript`, 기존 감사 그대로), 원문 목록 바로 위에 6-2와 같은 표를 연다.
- 상세에서는 칸마다 바로 반영하지 않는다. 표 아래 [이름표 저장] [취소]로 한 번에 보낸다. 가칭 `PUT /board-minutes/{id}/speakers {labels:[{no,label}], rev_no}`, 버튼 id `minutes_speaker`(서버 허용 목록에 추가해야 한다).
- 성공하면 `rev_no`를 갱신하고 원문을 다시 그린다. status에 문구를 쓰고 포커스를 `#mn-lbl-open`으로 옮긴다. REV_CHANGED는 기존 편집기 처리(새로 불러오기)와 같다.
- 발언 고치기는 기존 [고치기](PUT utterances)를 그대로 쓴다. 다만 P1-1 가림 토큰 검사와 편집기 안내 문구를 상세 편집기에도 같이 넣는다.

### 6-9. design_history 전/후 장 문안(장 번호는 71 다음 — 다른 세션과 겹치는지 확인)
- **제목**: 회의록 올리기 — 미리보기에서 발화자 이름표·발언 고치기
- **전**: ② 미리보기는 확인만 할 수 있었다. 발언 59줄의 화자가 모두 '참석자 1~7'로만 보였고(72px 칸, 회색 12px), 고치려면 클로바 노트로 돌아가 다시 내보내야 했다. 미리보기 상자의 [원문 보기]는 눌러도 움직이지 않았다. [고치기] 버튼은 높이 20.7px였다.
- **후**: ②가 '미리보기 확인·고치기'가 된다.
  - 번호별 이름표 표(7줄)에 '구청장'·'은행 측' 같은 직책·역할을 적으면 그 번호의 발언이 한꺼번에 바뀐다. 원래 '참석자 N'은 이름표 아래 작은 글로 남는다.
  - 발언마다 [고치기] → [반영]이 있다. 고친 줄은 '고침' 배지와 왼쪽 회색 막대로 표시되고 [되돌리기]가 있다.
  - 위에 '고친 내용: 발화자 3명 · 발언 2건' 요약이 있다.
  - 저장한 뒤에도 상세에서 [발화자 이름표 바꾸기]로 고칠 수 있다.
  - [원문 보기]·[발언 보기]가 미리보기 상자 안에서 동작한다. 버튼 높이는 28px다.
- **대비 숫자**: 이름표 글 16:1, 원래 번호 8.7:1, 고친 줄 막대 4.5:1, 포커스 링 6.8:1, 대상 크기 20.7px → 28px
- **왜**: 사용자 요청(11-20) "미리보기 다음에 클로바가 아닌 웹에서 발화자와 내용을 고치고 싶다". 실명은 넣지 못하게 한다(사용자 결정 1). 가린 자리를 지워 이름을 되살리지 못하게 막는다.

## 7. 이관 메모
**개발(backend-dev 설계와 맞출 것)**
- [이관: 개발] 저장 요청 `options.edits{speakers[{no,label}], utterances[{seq_no,text}]}`를 받을지, 이름을 확정해 달라. 디자인이 기다리는 것: 6-3 `buildForm` 키 이름. 근거: 지금 `MinutesOptions`에 해당 필드가 없다.
