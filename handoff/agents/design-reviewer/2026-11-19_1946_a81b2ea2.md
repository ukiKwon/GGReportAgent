## 5. 우선순위 이슈

**P1-1 정적 창 5개는 대화상자로 인식되지 않음.**
- 근거: `#more-modal`·`#notify-modal`·`#doc-modal`·`#theme-modal`·`#add-modal`에 role·aria-modal·labelledby가 없고, 포커스 이동·가둠·복귀도 없습니다(render.js `openMoreModal`, notify.js `open`, knowledge.js `openDocument`, app.js `wireTheme`·`openAdd`).
- 왜 문제인가: 키보드 사용자가 머리 띠의 `#btn-notify`로 쪽지함을 열면 포커스는 덮개 뒤 단추에 그대로 남고, Tab은 가려진 화면을 돕니다.
- 수정 방향: 6절 틀로 옮깁니다.

**P1-2 전역 Esc가 정적 창을 한꺼번에 닫고 포커스를 돌려주지 않음.**
- 근거: app.js `wireModalDismiss`는 연 시점의 `.modal-overlay` 목록 전체를 `display:none` 합니다.
- 왜 문제인가: 첫 사용자가 `#add-modal`에 10칸을 채우다 Esc나 배경 클릭 한 번이면 확인 없이 사라집니다. 쪽지함에 쓰던 내용도 같습니다.
- 수정 방향: 맨 위 창 하나만 `requestClose`로 닫습니다. 정적 창을 다 옮긴 뒤 `wireModalDismiss`는 지웁니다.

**P1-3 겹침이 DOM 순서에 맡겨져 있음 — 모든 덮개가 z 30.**
- 근거:
  - `#edit-modal`은 index.html에 정적으로 있어 `#dm-ov`(body 끝에 붙음)보다 **앞**에 있습니다. 같은 z면 뒤에 붙은 dm이 위에 그려집니다.
  - 지금은 `dm-edit`가 `closeDetail`을 먼저 하므로 문제가 없습니다.
  - 그런데 fa가 `instedit.open`에 `noBank`·`onClose`를 더했습니다(6a29986, "기관 상세 팝업 안 편집"). 상세를 열어 둔 채 편집 창을 띄우면 **편집 창이 상세 뒤에 깔립니다.**
  - `#ov-pop`(정적)도 늦게 뜨면 `#hb-ours`·`#dm-ov` 밑에 깔립니다.
  - kbboard `isModalEl`의 주석이 이 경우를 이미 의식하고 있습니다.
- 수정 방향(당장): fa가 편집 창을 상세 위에 띄우는 경우에 한해 `#edit-modal`에 `z-index:31`을 주거나, 열 때 body 끝으로 옮깁니다.
- 수정 방향(근본): 6-5의 층 규칙입니다.

  - `[버리고 닫기][계속 편집]`: ie
  - `[계속 작성][버리고 닫기]`: pp
  - `[계속 작성][닫기]`: tm

**P2-4 닫기 모양 5가지.** × 32px 아이콘(dm), 머리의 `[닫기]` 글자(hb-ours·bd-src·more), 발의 `[닫기]`(ie·hc·ov-pop·doc·notify), `[취소]`만(hb-dlg·pp·tm·bd-m-rw·add), 브라우저 기본.

**P2-5 inert는 16개 중 2개(hb-ours·bd-src)만.** 나머지는 aria-modal과 Tab 처리에만 기대고 있어, 화면 낭독기의 가상 커서가 팝업 밖으로 나갈 수 있습니다.

**P2-6 `#theme-modal [기본값으로 초기화]`가 그 자리에서 저장까지 함.**
- 근거: `store.resetTheme()`을 곧바로 부릅니다.
- 왜 문제인가: 그 뒤 `[취소]`를 눌러도 되돌아가지 않습니다.
- 수정 방향: 초기화는 칸 값만 기본값으로 채우고, 저장은 `[저장]`이 하게 합니다.

**P3**
- 너비 9가지(360/420/520/560/720/840/1320), 위 여백 4가지(5vh/6vh/8vh/32px).
- 제목이 h2와 h3, 14px와 16px로 섞여 있습니다.
- `.dm-x svg stroke-width:1.6` — DESIGN은 아이콘 획을 1.2~1.4로 정합니다(계약과 어긋남).
- `.modal-box.bd-src-box`의 열기 애니메이션 `bdsrcin`(scale .98) — DESIGN의 움직임 목록에 없습니다(계약과 어긋남).
- `.modal-overlay` 주석 "라운드 + 블러 스크림 + 틴티드 섀도"는 낡았습니다(실제 `--shadow:none`, 블러 없음).
- `#hb-ours`는 mousedown 한 번에 닫힙니다(dm은 mousedown과 click 모두 확인).
- **클래스 이름 충돌**: 지시의 예시 `.pop-*`는 이미 `.pop-unk`·`.pop-raw`·`.pop-rl`과 **`.pop-confirm`(prep.js 제안 확정 인라인)**이 쓰고 있습니다. 그래서 틀 이름은 `.dlg-*`를 제안합니다. `.dlg`로 시작하는 CSS 클래스는 지금 없습니다(kbboard의 `dlg`는 JS 변수).

## 6. 문구 / 접근성

**문구**
- 닫기·버리기 낱말 통일: × 아이콘은 `aria-label="닫기"`. 버리는 동작은 **'버리고 닫기'** 하나. 남는 동작은 **'계속 작성'** 하나('계속 편집'은 ie에서 바꿈).
- 미저장 확인 문장: "저장하지 않은 {무엇}이 있습니다. 닫으면 사라집니다." {무엇}은 묶음·칸 이름입니다(예: 입찰 예정일, 운영 상태 / 변경 사유 / 메모). 이름을 모르면 "적은 내용".
- notify.js `open`, workflow.js의 "상단에서 이름·소속을 먼저 입력하세요"는 위치가 낡았습니다. 프로필 편집은 [내 정보] 탭으로 옮겨졌습니다(index.html `#mi-demo` 주석). "[내 정보]에서 이름·소속을 먼저 입력하세요."로 고칩니다.
- 기관 추가 오류: `alert('필수 누락: …')`, `'기관 추가 실패 (500)'` → 창 안 `.dlg-err`에 "이름·유형·지역을 적어야 추가됩니다."처럼 원인과 할 일을 적습니다. 상태 코드는 뺍니다.

**접근성(수치)**
- × 단추 32×32. 머리 단추 높이 32. `#hb-ours [닫기]`는 위아래 3px 여백·12px 글자라 계산상 약 24px로, 맞춥니다.
- 대비(계산값)
  - 위험 단추 `--red` #bd2c0f 글자: `--panel2` 위 5.55:1, 흰 바탕 5.95:1
  - 주 단추 테두리 `--accent-color`: 흰 바탕 6.83:1
  - 안내 줄 `--muted` #464c53: `--panel2` 위 약 8:1
- 열 때 포커스 이동이 없는 창 5개, 닫을 때 복귀가 없는 창 5개(#12~16).
- 색만으로 전달하지 않음: 위험 단추는 빨강과 함께 동사("지우기", "버리고 닫기", "확정 풀고 …")로 구분합니다.

## 7. 규격 — 공통 틀 `.dlg`

### 7-1 창의 종류 3가지

| 종류 | 무엇 | 머리 오른쪽 | 발 줄 | 예 |
|---|---|---|---|---|
| 보는 창 `data-kind="view"` | 읽고, 동작은 다른 데서 함 | [동작…][×] | 없음 | 기관 상세, 협약 중인 기관, 분석표, 전체 입찰건, 원문, 쪽지함(목록) |
| 쓰는 창 `write` | 창 전체에 저장 하나 | [×]만 | **[주][취소]** 오른쪽 정렬, 왼쪽에 이유 | 목표·관심 5종, 사전준비, 담당자 변경, 재작성 요구, 지도 색상, 기관 추가 |
| 쓰는 창 — 묶음 저장 `write-sections` | 본문 묶음마다 [저장] | [×]만 | **없음**(× = requestClose) | 기관 정보 변경, 기관장 |
| 알림 창 `alert` (role=alertdialog) | 사용자가 고를 일을 알림 | [×](= 가장 안전한 선택과 같은 동작) | 선택지 최대 3개, 주 선택 먼저 | 입찰 없음 알림, 경과 요약 |

### 7-2 크기
- `.dlg--s` min(440px, 100vw−32)
- `.dlg--m` 560
- `.dlg--l` 720
- `.dlg--full` min(1320px, 100vw−64) × (100vh−64) 고정
- 모두 위 32px, `max-height:calc(100vh − 64px)`, 높이는 내용을 따름(full 제외).
- 880px 이하: 폭 100vw−24, 위 12px. full은 화면 전체에 테두리 없음.
- 배정

| 크기 | 창 |
|---|---|
| s | 재작성 요구, 입찰 없음, 지도 색상 |
| m | 경과 요약(목록이 있어 520→560), 기관 정보 변경, 담당자 변경, 사전준비, 목표·관심, 쪽지함, 기관 추가 |
| l | 기관 상세, 협약 중인 기관, 기관장, 전체 입찰건, 원문(840→720) |
| full | 분석표 |

### 7-3 머리 줄 `.dlg-bar`
- 52px, `--panel2`, 아래 1px `--line-strong`, 여백 0 12px 0 24px, 간격 12px.
- 제목 `.dlg-t`: **h2 16/700**, −0.01em, 한 줄 말줄임, 전체 이름은 `title` 속성. `tabindex=-1`, 링 없음.
- 보조 `.dlg-meta`: 12px muted(건수·도장·기준일).
- 단추 `.dlg-acts > button`: 높이 32, 여백 0 14px, 12px. **×는 언제나 맨 오른쪽**.
- 좁은 화면에서 넘치면 줄바꿈(min-height 52).
- 머리에는 저장하는 단추를 두지 않습니다. 쓰는 창의 저장은 발 줄에 둡니다.

### 7-4 안내 줄 `.dlg-note`(스크롤 안 됨, 비면 숨김)
- 순서: `.dlg-hint`(안내 한 문장, 12px muted, 여백 8px 24px, 아래 1px `--line`) → `.dlg-flash`(role=status) → `.dlg-err`(role=alert, `--red`) → `.dlg-cf`(확인 상자).
- 안내는 한 문장이며 말줄임하지 않습니다(줄바꿈 허용).
- 도구 줄 `.dlg-tools`(검색칸 등)는 안내 줄 아래에 두고 스크롤하지 않습니다.

### 7-5 본문·발
- `.dlg-body`: flex 1, min-height 0, overflow auto, overscroll-behavior contain, 여백 16px 24px. 안쪽 절 제목은 h3 14/700.
- `.dlg-foot`(쓰는 창·알림 창만): 여백 12px 24px, 위 1px `--line`, 오른쪽 정렬, 간격 8. `.dlg-why`는 왼쪽(margin-right:auto).

### 7-6 닫기 규칙
- ×, Esc, 배경 클릭은 **같은 함수 `requestClose()` 하나**로 갑니다.
- 보는 창은 곧바로 닫습니다.
- 쓰는 창은 변경이 없으면 닫고, 있으면 확인 상자를 엽니다.
- 쓰는 창에서도 배경 클릭을 **막지 않습니다**. 확인 상자가 입력을 지켜 주고, 탈출구가 없던 것이 사용자 보고("편집 팝업이 안 닫힘", app.js 주석)의 원인이었기 때문입니다.
- 배경 클릭은 mousedown과 click이 모두 덮개일 때만 인정합니다.
- 저장 중(`aria-busy=true`)에는 세 경로 모두 무시하고, 주 단추에 "저장 중…"을 띄워 막습니다.
- Esc 순서: 콤보 목록 → 입력 취소(분석표) → 확인 상자 접기 → 창 닫기. **맨 위 창만** Esc를 받습니다.

### 7-7 미저장 확인 문법
- **위**(`.dlg-note` 안 `.dlg-cf`)에 펼칩니다.
- 문장: "저장하지 않은 {무엇}이 있습니다. 닫으면 사라집니다."
- 단추: `[버리고 닫기](.dlg-danger)` `[계속 작성]`. 포커스는 [계속 작성]에 둡니다.
- 펼쳐진 동안 발 줄과 머리의 주 단추는 막습니다(dm 방식). Esc는 상자만 접고, 포커스는 확인을 연 요소로 돌아갑니다.
- '변경' 판정: 연 때 값과 달라진 입력이 하나라도 있음. 고르기 하나뿐인 창(옮기기 연도)은 확인하지 않습니다.

### 7-8 확인 상자 `.dlg-cf` — 모든 팝업 공통, 위에서 펼침
- 점선 1px `--line-strong`, 여백 12px 14px, 13/1.5.
- `--warn`: 실선 `--orange` + 8% 틴트(dm 공고 전 확정).
- `--danger`: 실선 `--red` + 6% 틴트(삭제·확정 풀기).
- 단추 줄 `[실행][되돌리기]`, 왼쪽 정렬.
- 포커스
  - 되돌리기 어려운 것(지우기·버리기·확정 풀기·중단): 되돌리기 단추
  - 되돌릴 수 있는 것(제안 확정 — 개설 신청 전 취소 가능): 실행 단추
  - 둘 다 **펼칠 때 한 번만** 옮깁니다.

### 7-9 단추 모양
- 주 `.dlg-go`: `--accent-color` 1px 테두리 + 700, 채우지 않음(DESIGN '채운 주버튼 예외 3곳' 유지).
- 위험 `.dlg-danger`: 현행 `.pp-danger` 값(글자·테두리 `--red`, 바탕 `--panel2`, hover 18% 틴트).
- 위험 단추 대상: 지우기, 버리고 닫기, 확정 풀고 재작성 요구, 중단, 목표·관심에서 빼기. 제안 확정은 주 단추입니다.

### 7-10 겹침 층과 inert
- 지시의 예시처럼 종류별로 층을 나누는 방식(30 보는 창 / 31 쓰는 창 / 40 확인)은 **보는 창 위에 보는 창**이 뜰 때 깨집니다(`#hb-ours` → `#dm-box`).
- 그래서 **연 순서 깊이**로 층을 정합니다.
  - z = 30 + 깊이(0부터, 최대 38)
  - 39 = 비동기로 뜨는 시스템 알림(`#ov-pop`)
  - 메뉴 60, 로그인 100은 그대로
- 덮개는 모두 열 때 **body 끝에 붙입니다**(`#hb-ours`의 host 안, 정적 `#edit-modal`·`#ov-pop` 포함).
- 덮개 색은 한 가지 `rgba(19,20,22,.5)`(DESIGN). 겹치면 아래 창도 어두워지는 것이 '지금은 위 창'이라는 신호입니다.
- 새 창을 열 때: 아래 창을 포함해 body 아래 형제 모두에 inert를 겁니다. `kbb.inertBehind`를 일반화하되, 이미 inert인 것은 건너뛰고 자기가 건 것만 기록합니다.
- 닫을 때: 그 목록만 풀고 바로 아래 창을 다시 살립니다.
- Tab 가둠은 inert가 맡고, JS 순환은 처음↔끝 둘레만 처리합니다.

### 7-11 포커스
- **열 때**: 보는 창·알림 창은 제목 `.dlg-t`, 쓰는 창은 첫 입력칸, 도구가 있는 보는 창(전체 입찰건)은 검색칸. 지정 진입(`opts.focus`)이 있으면 그것을 따릅니다.
- **다시 그릴 때**: 같은 id로 돌려주고, 없으면 제목.
- **닫을 때**: opener(살아 있으면) → `opts.refocus()` → 바로 아래 창의 제목 → 화면 제목. body로 떨어지지 않게 합니다.
- Tab 순서: 제목 → 머리 단추(주 → 편집 → ×) → 안내 줄 → 도구 → 본문 → 발.
