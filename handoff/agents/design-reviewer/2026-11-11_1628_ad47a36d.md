# 로그인 첫 화면 시안 보고서 (design-reviewer, 2026-11-11)

## 1. 대상·방법·못 본 것
- **대상**: `frontend/index.html`의 `#login-view`. 마크업은 1415–1429줄, CSS는 585–605줄. 동작은 `frontend/js/app.js` 795–921줄, 계정 목록은 `frontend/js/login.js`, 배경은 `frontend/img/login-bg.svg`(사진 슬롯 `img/login-bg.jpg`는 비어 있음).
- **방법**: 소스를 읽었습니다. 시안은 Playwright로 자체 격리 탭(`about:blank`에 document.write)에 띄웠고, 1440×900과 1366×768에서 스크린샷을 찍고 요소 크기를 쟀습니다. 스크린샷은 `.playwright-mcp/login-mock-A3.png`, `login-mock-B.png`, `login-mock-B-1366.png`입니다. 대비는 WCAG 공식으로 계산했습니다.
- **못 본 것**:
  - 지금 화면을 실제로 열어 보지 못했습니다. `file://`은 Playwright가 막고, `localhost:8080`은 허락받지 않아 열지 않았습니다. 지금 화면 진단은 소스만 보고 한 것입니다.
  - 시안의 구 경계는 실제 `geo/seoul.js` 대신 **가짜 격자 경계**로만 렌더를 확인했습니다. 실제 경계에서 구 이름 라벨이 겹치는지(동대문·중랑·광진이 붙어 있음)는 확인하지 못했습니다.
- **⚠ 도구 사고 2건**:
  - 시작할 때 `browser_resize`가 다른 컨텍스트(`dr-77b`)의 localhost:8080 탭 크기를 1440×900으로 바꿨습니다.
  - 마지막에 `browser_close`를 불렀더니 "No open tabs"로 응답했습니다. 다른 세션의 `dr-77b` 탭(시안·8080)과 **사용자 웹메일 탭까지 닫혔을 수 있습니다.** 웹메일에서 작성 중이던 내용이 있었는지 사용자에게 알려야 합니다. 쓰기 동작(저장·제출)은 하지 않았습니다.

## 2. 한 줄 총평
지금 로그인 화면은 제품과 무관한 '사람 아바타 네트워크' 그림을 깔고 있어서 아무 제품에나 붙는 화면입니다. **가장 큰 기회는 히어로 자체를 '올해 우리 데이터(공고 번호·약정 체결일)' 콜라주로 만드는 것**입니다. 그러면 첫 화면부터 "실측이 전부"(PRODUCT 원칙 1)를 보여 주게 됩니다.

## 4. 시안 2개 — 설계 요지

**공통 콘셉트**: "올해 결과로, 다음 입찰을."
- 히어로 콜라주에 2026년 국민은행이 금고로 지정된 서울 6개 구를 놓습니다.
  - 신규 유치(우리은행에서 이동): 영등포·강동·중랑
  - 재선정: 동대문·광진·노원
- 콜라주 조각은 세 종류입니다.
  - **고시 공고 조각**: 공고 번호와 날짜. 이중선 머리, 바탕체.
  - **보도 조각**: 바탕체 헤드라인 + 회색 단 줄.
  - **구 실루엣 타일**: 경계는 `geo/seoul.js` 실측(통계청 2018).
  - 여기에 서울 25구 지도 한 장을 더합니다. 신규는 꽉 채움, 재선정은 굵은 윤곽으로 표시해 톤에만 기대지 않게 했습니다.
- **모든 문장은 `institutions.js` sources에 있는 것만 썼습니다.** 각 조각에 출처 종류(공고 번호, "보도 2026.11.04")를 달고, 하단에 출처 한 줄을 둡니다.
- 제목은 콜라주(올해 결과)와 짝을 이루게 "다음 금고 입찰을 / 먼저 봅니다"로 했습니다. 지도 우선이라는 성공 기준에 맞춘 것입니다.
- 글꼴은 모두 시스템 글꼴이라 폐쇄망에서도 동작합니다.
  - UI: 맑은 고딕
  - 큰 제목: 맑은 고딕 Semilight 300. 렌더에서 적용을 확인했습니다.
  - 기사·공고: **바탕**. 신문 지면 느낌을 내고 UI와 구분하려는 용도입니다.
  - 숫자: Consolas
- 참고 스타일(갤러리·흰 카드·알약 버튼)은 구조만 빌렸고, 로고·이름·글꼴 이름은 쓰지 않았습니다. 강조색은 인디고 대신 기존 틸 하나로 정했습니다.

**DESIGN.md에서 벗어나는 점**(로그인 표면 예외로 문서화가 필요합니다):
- ① 제목 56px(48px, 높이 ≤820일 때). 앱 크롬의 11–16px 램프 밖입니다.
- ② 알약형 50px 버튼. 반경 25px은 새 모양입니다.
- ③ 카드 반경은 브리프의 16px 대신 **토큰 14px(--r-lg)**을 지켰습니다.
- ④ 그림자는 브리프의 `rgba(0,0,0,.1)` 대신 **`rgba(8,12,24,…)`**를 지켰습니다(Tinted Shadow Rule).
- ⑤ 시안 A의 흰 면 자체가 새 표면입니다.

`:root` 변수 이름은 그대로 두고, A 전용 값만 `--a-*`로 더했습니다.

**구현 시 주의(프런트 담당)**:
- app.js는 `#login-view`에 `hidden`만 토글합니다(802·818·866줄). 시안의 상단 막대와 무대 **전체**를 `#login-view`(fixed, inset 0, z 100, `overflow:auto`) 안에 넣어야 합니다.
- id 7개를 유지합니다: `login-view`, `login-id`, `login-pw`, `login-role`, `login-msg`, `login-go`, `login-guest`. 테스트는 이 id들을 참조하지 않는 것을 grep으로 확인했습니다.
- `<select>` 옵션은 app.js가 채우므로 시안의 option은 보기용입니다.
- 시안의 `<form>`·submit 처리는 상태를 보여 주려는 데모입니다. 실제로는 app.js의 Enter·click 처리를 그대로 둡니다.

## 5. 문구 / 접근성 (시안에 반영한 값)
- 문구:
  - 사번 칸: "사번 또는 임시 계정", placeholder "사번 7자리"
  - 선택 칸: "임시 계정 (팀·직위)"
  - 보조 버튼: "로그인 없이 둘러보기"
  - 안내 2줄: "시험 운영 중에는 비밀번호를 확인하지 않습니다." / "로그인과 화면 사용은 접근 이력에 남습니다."
- `#login-msg`: `role="status" aria-live="polite"`. 사번 칸은 `aria-describedby` + 실패 시 `aria-invalid`(테두리가 오류색으로 바뀜).
- `autocomplete`: 지금은 `off` → 시안은 `username` / `current-password`. 공용 PC 정책에 따라 결정할 일이라 열린 질문으로 둡니다.
- 콜라주는 `<figure role="img" aria-label="2026년 국민은행이 금고로 지정된 서울 6개 구. 신규 유치: …, 재선정: …">`로 요약 한 문장을 읽어 주고, 내부 SVG는 `aria-hidden`입니다.
- 포커스:
  - A: 2px `color-mix(accent 55%, #000)`(=#30655f), 흰 바탕 대비 **6.7:1**. 원래 틸 #57b8ad는 흰 바탕에서 **2.4:1로 실패**합니다.
  - B: 2px 틸, 패널 대비 **7.1:1**.
- 클릭 대상(측정): 로그인 279×50, 둘러보기 197×50, 입력칸 488×48.
- 움직임: 콜라주 조각이 한 번만 70ms 간격으로 자리잡고, `prefers-reduced-motion`에서는 꺼집니다. 카드는 움직이지 않습니다.
- 반응형:
  - ≤1399px: 콜라주 0.9배
  - 높이 ≤820px: 제목 48px로 압축. 1366×768에서 확인했고, 카드 하단이 약 50px 스크롤됩니다.
  - ≤960px: 콜라주를 숨기고 카드만 표시
  - 1440에서 가로 넘침이 없음을 확인했습니다(scrollWidth 1440).

## 7. 앱 본화면(어두운 테마)과의 전환 — 판단과 권장
- **A → 앱**: 화면 전체가 #fff에서 #0f1218로 넘어갑니다. 휘도비 18.8:1의 전면 반전이 로그인할 때마다 한 번씩 일어납니다(사무실 PC에서 눈부심과 깜빡임). A는 DESIGN.md에 없는 두 번째 시각 세계(흰 갤러리)를 만들기 때문에, 문서화하고 유지할 대상이 늘어납니다.
- **B → 앱**: 같은 charcoal 바닥, 같은 결(grain), 같은 틸, 같은 유리 카드라 전환이 이어집니다.
- **권장: B를 실제 화면으로 쓰고, A는 '시연용 비교안'으로 보관**합니다. A를 쓰겠다면 최소한 다음이 필요합니다.
  - 로그인 직후 240ms 동안 #0f1218로 페이드
  - 주버튼을 charcoal로 유지(시안에 이미 반영)
  - DESIGN.md에 '로그인 표면은 밝음' 예외 장 추가

## 8. 실제 사진·뉴스 화면을 쓰려면 필요한 것
지금 시안은 사진 없이 우리 데이터와 실측 경계만 씁니다.
- **기관 사진**: 해당 구청 누리집 사진 중 **공공누리 제1유형(출처표시)**만 안전합니다.
  - 제2유형(상업적 이용 금지): 은행 영업 도구가 '상업적 이용'에 해당하는지 법무 확인이 필요합니다.
  - 제3·4유형(변경 금지): 콜라주용 자르기·회전이 '변경'에 해당할 수 있어 쓰지 않습니다.
  - 사진마다 출처 표기를 화면에 넣어야 합니다.
- **뉴스 화면 캡처**: 기사 지면, 사진, 레이아웃은 언론사 저작물입니다. 해당 언론사나 한국언론진흥재단(뉴스저작권)의 **이용 허락**이 필요합니다. 시안처럼 사실(제목 요지·날짜)을 우리 글로 다시 쓰는 것은 별개입니다.
- **사내 홍보 자료**: 협약식 사진 등 KB 홍보 부서 자료는 사내 사용 승인이 필요합니다. 인물이 나오면 **초상권 동의**를 확인해야 합니다.
- **폐쇄망**: 핫링크는 불가하므로 `frontend/img/`에 동봉해야 합니다. 사진 한 장당 약 200KB 이하로 하고, 기존 `img/login-bg.jpg` 슬롯이나 콜라주 조각의 `<img>`로 넣습니다.
