## 1. 대상·방법·못 본 것

## 2. 한 줄 총평 / 가장 큰 기회
지금은 서버만 막고 있어서, 관리자가 본인 행의 [수정]·[잠금]·[퇴직]을 누르고 입력까지 끝낸 뒤에야 빨간 오류를 봅니다. 가장 큰 기회는 **못 하는 일을 처음부터 버튼 대신 한 줄 안내로 보여 주는 것**입니다. 이렇게 하면 헛된 시도와 쓸모없는 Tab 정지점이 둘 다 사라집니다.

## 3. 잘 된 점
- 서버 오류 문구가 이미 업무 언어입니다("본인 정보는 다른 관리자가 바꿉니다."). 화면 안내도 같은 말을 그대로 쓰면 용어가 하나로 맞춰집니다.
- 접근 이력 표에 이미 `신원` 칸(검증됨=`ad-badge ok` / 자기신고=`ad-badge muted`, admin.js 693–694)이 있습니다. 권한 변경 이력도 같은 모양을 쓰면 새 표기가 필요 없습니다.
- 권한 표의 결재 칸 비활성이 이미 native `disabled` + `title`입니다(613–619). 본인 읽기 전용도 같은 계열로 이으면 됩니다.

(휴리스틱 점수표는 생략했습니다. 실화면을 보지 못해서 근거 있는 점수를 매길 수 없습니다.)

## 4. 우선순위 이슈

**P1-1. 본인 행의 조작 버튼이 그대로 보이고, 저장해야 실패가 드러납니다**
- 근거: `paintUsers` 497–503은 모든 행에 [수정]·[잠금]/[잠금 해제]·[퇴직]을 그립니다. 오류는 `saveUser`/`userOp`의 catch → `say(fail(e), true)`로만 나옵니다.
- 왜 문제인가: 이름·역할 입력을 다 하고 나서야 거절됩니다(오류 예방 실패). 본인 행 하나에 쓸모없는 Tab 정지점이 3개 생깁니다.
- 수정 방향: 6절 ①-A대로 본인 행의 버튼을 빼고 안내 한 줄을 넣습니다. 서버 400은 마지막 안전망으로 둡니다.

**P1-2. 결재자 목록에서 본인(관리자)을 빼면, 이미 본인으로 지정된 사용자의 결재자가 저장 한 번에 '자동'으로 조용히 바뀝니다**
- 근거: `approverOptions` 418은 후보에 없는 값은 option을 만들지 않습니다. 그러면 select가 첫 값 `""`(자동)로 떨어집니다. 이어서 `approverChange`(137–141)는 `""` + MANUAL을 `{mode:'AUTO'}` 변경으로 계산합니다. 이름만 고치고 [저장]해도 결재자가 풀립니다.
- 이 버그는 결재자가 퇴직·잠금이 된 경우(MANUAL_INVALID)에 이미 있습니다. 본인을 후보에서 빼면 한 경로가 더 늘어납니다.
- 수정 방향: 현재 지정값이 후보 밖이면 그 값을 **선택된 option으로 남겨 둡니다**. 문구는 6절 ②에 있습니다.

**P2-1. 시스템 관리의 모든 쓰기 요청에 화면·버튼 머리글이 없습니다**
- 근거: `api()` 266–279는 `Content-Type`만 붙입니다. 서버 `AdminUiIds.of`는 값이 없으면 `UNKNOWN`·`uiValid=false`로 남깁니다.
- 결과: 지금 쌓이는 PERM_CHANGE_LOG의 화면·버튼은 전부 '알 수 없음'입니다.
- 수정 방향: 6절 ④ 표대로 머리글을 붙입니다.

**P2-2. 메뉴 관리 화면은 로그인한 사람의 역할을 모릅니다**
- 근거: `paintMenus`/`loadMenus` 353–387은 `/menus`만 부릅니다. `store.loadSession()`(store.js 91–95)에는 `emp`만 있고 역할이 없습니다.
- 결과: 자기 역할 줄을 표시할 수 없습니다.
- 어디서 역할을 받을지는 개발 쪽 결정입니다(7절 이관).

**P3-1. 권한 변경 이력 표에 '누가 확실한가'와 '어디서 눌렀나'가 없습니다**
- 근거: 626–631의 칸은 시각·변경자·항목·이전·이후 5개뿐입니다. 서버 PermChange는 `emp_verified`·`screen_id`·`button_id`·`ui_valid`를 이미 줍니다. 칸 이름은 `actor_emp_no`가 snake_case로 오는 것을 보고 같은 직렬화로 추정했습니다.
- 수정 방향: 6절 ③대로 넣습니다.

**접근성**
- **본인 행(사용자 관리)**: 버튼을 `disabled`로 남기지 말고 **빼고 글로 바꿉니다**. 셀 글자가 그대로 읽히므로 ARIA가 더 필요 없습니다. Tab 정지점은 3개에서 0개가 됩니다. 근거: DESIGN.md "Server-only tabs are hidden, not disabled"와 같은 원칙입니다.
- **권한 관리 / 메뉴 격자 체크박스**: native `disabled`를 씁니다. `aria-disabled`는 쓰지 않습니다.
  - 이유: 칸이 많아서(메뉴 수×4, 또는 메뉴 수) 하나하나 Tab에 걸리면 안 됩니다. 이유는 표 위 한 줄로 이미 보입니다.
  - 체크박스는 "흐리게 표시됨/사용 불가"로 읽힙니다.
  - 안내 문단에 `id`를 주고, 표(`table`)와 비활성 체크박스 각각에 `aria-describedby`로 연결합니다(읽기 모드에서도 이유가 따라오게).
- **`aria-disabled`를 쓰는 곳은 없습니다.** 초점은 받되 이유를 말해야 하는 단일 컨트롤이 이번 범위에 없습니다.
- **권한 관리에서 본인 선택 시**: [저장]·[되돌리기]는 `disabled`가 아니라 **숨깁니다**. 저장할 것이 생길 수 없습니다.
- **결재자 select**: 본인을 `<option disabled>`로 두지 말고 목록에서 뺍니다. disabled option은 화면낭독기가 안내를 일관되게 읽지 않습니다. 안내는 select 아래 `.ad-note`로 두고 `aria-describedby`로 연결합니다.
- **대비(토큰으로 계산)**: 안내 `--muted` #98a1af
  - `--panel` #181e29 위 **6.4:1**
  - `--bg` #0f1218 위 **약 7.2:1**
  - 모두 4.5:1 이상입니다(design_history ②의 6.41과 일치).
  - native disabled 체크박스는 WCAG 비활성 예외라 대비 기준 대상이 아니고, 실측은 못 했습니다.
- **글자 크기**: 안내 12px(`.ad-note`), 배지 11px(`.ad-badge`). 11px 미만은 없습니다.

## 6. 규격·시안

**공통 원칙**
- 새 hex와 새 CSS 변수는 없습니다. `--muted` 글자, 기존 `.ad-badge`(기본: `--line-strong` 테두리 + muted 글자), `.ad-note`(12px muted)만 씁니다.
- 투명도 흐림은 쓰지 않습니다(DESIGN.md Neutral 규칙). 행 배경 틴트와 틸 강조도 쓰지 않습니다. '본인'은 선택 상태가 아니므로 One Teal Rule에 걸립니다.
- "본인"의 기준은 `store.loadSession().emp`입니다(서버 SelfChange와 같은 기준).

**① 상태별 모양**

A. 사용자 관리 목록의 본인 행
```html
<tr class="st-active is-self">
  <td class="mono">8203417</td>
  <td>홍길동 <span class="ad-badge">본인</span></td>
  … (역할·직위·등급·결재자·상태·최근 로그인 그대로)
  <td class="ad-ops"><span class="ad-note">다른 관리자가 바꿉니다</span></td>
</tr>
```
- 배지는 이름 뒤 1칸 띄우고 기본 `.ad-badge`(11px, r9)를 씁니다.
- 조작 칸은 오른쪽 정렬(`.ad-ops`) 그대로이고, 글자는 12px muted입니다.
- 본인이 퇴직 상태여서 [복직]만 보이는 행도 같은 처리를 합니다. 복직도 본인 상태 변경이라 서버 400 대상입니다.
- 편집 창: 본인 행에는 [수정]이 없으므로 본인용 편집 창은 열리지 않습니다. 별도 비활성 폼은 만들지 않습니다.

B. 권한 관리에서 본인을 골랐을 때
- 툴바 select option 끝에 ` — 본인`을 붙입니다.
- 표 바로 위에 `<p class="ad-note" id="pm-self-note">본인 권한은 다른 관리자가 바꿉니다 — 여기서는 볼 수만 있습니다.</p>`를 둡니다. 툴바와 표 사이 간격 8px입니다.
- `<table class="ad-table ad-perms" aria-describedby="pm-self-note">`로 연결합니다. 모든 체크박스에 `disabled aria-describedby="pm-self-note"`를 붙입니다. 결재 칸의 기존 `title`("이 메뉴에는 결재 기능이 없습니다")은 유지합니다.
- `#ad-actions`([저장]·[되돌리기])는 그리지 않습니다.
- 변경 이력 표는 그대로 보여 줍니다. 본인 권한이 누구에 의해 바뀌었는지 보는 것은 허용입니다.

C. 메뉴 관리 격자의 자기 역할 줄
- 격자 위에 `<p class="ad-note" id="mg-self-note">본인 역할(전산팀) 줄은 다른 역할의 관리자가 바꿉니다.</p>`를 둡니다. 기존 `*` 각주는 표 아래 그대로입니다.
- 줄 머리는 `<th>전산팀 <span class="ad-badge">본인 역할</span></th>`입니다.
- 그 줄 체크박스에 `disabled aria-describedby="mg-self-note"`를 붙이고, `aria-label`은 기존("전산팀 대시보드") 그대로 둡니다.
- 역할을 모르면(로드 실패 등) 줄을 잠그지 않습니다. 서버 400이 안전망입니다. 안내 문단도 그리지 않습니다.

**② 결재자 선택 목록**
- 후보 조건은 기존 `approverCandidates`에 "**로그인한 사람(`session.emp`)이 아님**"을 하나 더한 것입니다. 본인은 option에서 뺍니다(disabled 아님).
- **예외**: 수정 대상의 현재 값(`approver_value`)이 후보 밖이면 맨 위 '자동' 다음에 그 사람을 `selected` option으로 남깁니다. 표기는 5절 표의 두 줄입니다. 그대로 저장하면 `approverChange`가 `null`을 돌려 결재자가 바뀌지 않습니다. 이 예외가 P1-2를 막습니다.
- select 아래 `#uf-chain` 바로 앞에 `<div class="ad-note ad-form-wide" id="uf-appr-note">본인은 결재자 목록에 없습니다 — 본인을 결재자로 정하는 일은 다른 관리자가 합니다.</div>`를 두고, `<select id="uf-appr" aria-describedby="uf-appr-note uf-chain">`로 연결합니다.
- 안내는 로그인한 사람이 실제로 결재 후보 조건(ACTIVE·등급 있음)을 만족해서 빠졌을 때만 보입니다. 원래 후보가 아닌 관리자에게는 소음입니다.

**③ 권한 변경 이력 표**
- 넣는 것이 맞습니다. 감사 기록 요구(누가·어느 화면·어느 버튼)와 접근 이력 화면과의 일관성 때문입니다.
- 칸은 5개에서 6개로 늘리고 `신원`은 변경자 칸 안에 넣습니다. `nowrap` 표라서 7칸이면 가로 넘침 위험이 있습니다.

| 시각 | 변경자 | 화면·버튼 | 항목 | 이전 | 이후 |
|---|---|---|---|---|---|
| 11-16 14:02 | `8203417` `[자기신고]` | 사용자 관리 [잠금] | … | … | … |

- 변경자 칸: 사번 mono + 공백 + `emp_verified ? '<span class="ad-badge ok">검증됨</span>' : '<span class="ad-badge muted">자기신고</span>'`. 접근 이력 693–694와 같은 마크업입니다.
- 화면·버튼 칸: `화면 라벨 + ' [' + 버튼 라벨 + ']'`. 라벨은 ④ 표의 "보이는 이름"입니다.
  - `screen_id`나 `button_id`가 `UNKNOWN`이면 그쪽만 `알 수 없음`으로 표기합니다(muted 글자, `<span class="ad-note">`).

- `ui_valid`는 따로 칸을 만들지 않습니다. UNKNOWN 표기로 이미 드러납니다.
- 접근 이력 힌트(62줄)와 같은 취지의 문장을 권한 관리 힌트(60줄) 뒤에 붙이지는 않습니다. 배지 자체가 설명입니다.
