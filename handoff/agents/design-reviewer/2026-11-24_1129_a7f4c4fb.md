## 4. 정할 것 1~4: 권장안·문구·위치

### 결정 1. `viewer.view_until`·`view_until_at` → 날짜 문구로 바꿉니다(권장)
- **위치**: 지금 자리 그대로입니다. 상세 머리 메타 줄과 표지 다음, `p.mn-meta`(board-minutes.js:713-714). 크기·색은 그대로 12px `--muted`입니다.
- **날짜 모양**:
  - 공개범위 표의 기한 칸과 같은 `yyyy-MM-dd`로 씁니다. 영업부장이 표에서 보는 글자와 공개받은 사람이 보는 글자가 같아야 서로 맞춰 보기 쉽습니다.
  - 날짜 부분만 `<span class="mono">`로 감쌉니다. DESIGN.md 133 "모든 날짜는 --mono".
  - 지시서 예시의 '11월 30일' 꼴은 표와 모양이 갈려서 쓰지 않습니다.
- **문구**:

| 경우 | 문구 |
|---|---|
| 등록자(`via=UPLOADER`, `view_until_at` 있음) | `올린 사람이라 2026-12-08 15:20까지 볼 수 있습니다. 그 뒤에는 영업팀장·영업부장에게 공개를 요청하세요.` (시각은 `mn.kst` 계열로 KST로 바꿔 `yyyy-MM-dd HH:mm`) |
| 등록자, 끝이 오늘 | `올린 사람이라 오늘 15:20까지 볼 수 있습니다. 그 뒤에는 영업팀장·영업부장에게 공개를 요청하세요.` |
| 공개받은 사람(`via=GRANTEE`, `view_until` 있음) | `공개범위에 추가되어 2026-12-24까지 볼 수 있습니다(그날 포함).` |
| 공개받은 사람, 기한이 오늘 | `공개범위에 추가되어 오늘까지 볼 수 있습니다.` |
| 값이 null(부장급·기본 열람자) | 지금처럼 줄을 내지 않습니다. 기한이 없는 사람에게 '기한 없음'을 따로 쓰지 않습니다. |
| UPLOADER·GRANTEE인데 값이 null(서버 파싱 실패) | 날짜 없는 문구로 돌아갑니다. 등록자 문구에서는 '(기본 14일)'을 빼서 `올린 사람이라 올린 뒤 정해진 기간 동안 볼 수 있습니다. …`로 씁니다. 근거 없는 숫자를 내지 않습니다. |

- **남은 날 수(D-n)는 넣지 않습니다.** 날짜만으로 충분하고, D-day 칩은 입찰 화면의 위계라 여기로 옮기면 무게가 맞지 않습니다.

### 결정 2. `speakers[].first_seq` → 원문을 받기 전에도 [발언 보기]를 띄웁니다(권장)
**왜**: 지금은 이름표 표를 열면 `toggleLbl`이 원문을 자동으로 받습니다(1246). 원문 받기는 서버에서 `VIEW_TRANSCRIPT` 감사로 남습니다(Controller 117). 그래서 원문을 펴지 않은 사람에게도 '원문 열람' 기록이 생깁니다. `first_seq`가 있으면 원문은 눌렀을 때만 받으면 됩니다.

**규격**(이름표 표 '첫 발언' 칸, 1056-1060):

| 상태 | 칸 내용 |
|---|---|
| 원문 받기 전, `first_seq` 있음 | 링크 버튼 `발언 보기`만 둡니다. aria-label `참석자 N 첫 발언 보기`(지금과 같음). 시각은 없습니다. |
| 원문 받는 중에 누름 | 버튼을 그대로 두고, 받기가 끝나면 그 발언으로 옮깁니다. 지금 `jumpUtter`는 `loading`일 때 아무것도 하지 않아(951) 누른 것이 사라집니다. 기다렸다가 옮기는 것이 필요한 동작입니다. |
| 원문을 받은 뒤 | 지금처럼 `<time>` + `발언 보기`. 시각이 칸 앞에 붙어 생기는 밀림은 허용합니다(열 머리 '첫 발언'이 자리를 잡아 둠). |
| 원문을 못 받음 | 지금 원문 오류 문구를 씁니다. 버튼은 남겨 다시 누르면 다시 받습니다. |
| `first_seq` 없음(옛 서버, 발언 0) | 칸을 비웁니다(지금과 같음). |

- **옮긴 뒤 알림**: 시각이 없을 때 `참석자 N의 첫 발언으로 옮겼습니다.`, 받은 뒤에는 지금 문구(`…첫 발언(00:03:12)으로 옮겼습니다.`)를 씁니다.
- **자동 받기 제거**: `toggleLbl`의 자동 원문 받기(1246-1253)는 `first_seq`가 있으면 하지 않습니다. 원문이 필요한 때는 사용자가 [발언 보기]나 [원문 펼치기]를 누를 때뿐입니다.
- **미리보기**(1219): 이미 원문을 가지고 있어 `firstOf` 그대로 둡니다.
- **불일치 주의**: 화면 `firstOf`는 잡음이 아닌 첫 발언을 고릅니다(322-325). 서버 `first_seq`는 잡음까지 포함한 SEQ 순 첫 발언입니다(설계 패치 F). 받기 전과 받은 뒤에 옮겨 가는 곳이 다를 수 있습니다. 개발로 넘깁니다(7절). 그 전까지 화면은 "원문이 있으면 `firstOf`, 없으면 `first_seq`"로 둡니다.

### 결정 3. 화면 id → `screenFor(is_assignee)`로 맞춥니다(권장, 화면 모양 변화 없음)
- **바꿀 것**: `mn.UI.TAB`·`mn.UI.VIEW`(board-minutes.js:8, 지금 둘 다 `board_write` 고정)를 탭 상태의 `isAssignee`로 정합니다(`S.isAssignee`, 528). 담당자는 `board_write`, 그 밖은 `board_review`입니다. 판정은 `board-material.js:33`의 `screenFor`와 같은 함수를 쓰거나 같은 식으로 씁니다.
- **그대로 둘 것**: `UPLOAD`(`board_minutes_upload`)·`LIST`는 그대로 둡니다. 올리기는 담당자만 하는 별도 단계입니다.
- **이유**: 영업부장이 연 이사회 자료 상세의 감사가 020 쪽은 `board_review`, 회의록 탭은 `board_write`로 갈려 있습니다. 한 사람이 한 화면에서 한 일이 감사에서 두 화면처럼 보입니다.
- **기록·확인**: 보이는 글자·모양이 바뀌지 않으므로 design_history 장은 필요 없습니다. `labelScreen()`(13)도 같이 따라가는지 확인합니다. 바꾼 뒤 qa P3-D('board_write 통일')를 다시 확인해야 합니다(서버 설계 6절).

### 결정 4. 공개범위 '사람 추가' 목록과 '공개 대상이 아닙니다' 문구 점검
- **잘 맞는 것**:
  - 서버 명단을 쓰고, 화면 쪽 영업팀 필터는 빠졌습니다(1378).
  - 잘림 안내와 불러오기 실패 안내가 고르기 상자 바로 위에 있습니다.
  - '공개 중 ~기한' / '기한 지남 기한' 표시가 공개범위 표의 '기한 지남' 배지와 같은 말을 씁니다.
- **P2-1 용어 충돌 '공개 대상'**: 같은 묶음 안에서 '공개 대상'이 두 뜻으로 쓰입니다.
  - '지금 공개한 사람'의 뜻: `SCOPE_FULL` "공개 대상이 30명입니다", `SCOPE_CAP` "공개 대상은 30명까지입니다"(101·214)
  - '공개할 수 있는 자격'의 뜻: `SCOPE_TARGET_NOT_ELIGIBLE` "공개 대상이 아닙니다"(212)
  - 30명이 찬 상태에서 자격 없는 사번을 넣으면 두 문구가 함께 보여 모순처럼 읽힙니다. 고칠 문구:
    - 212 → `이 사람에게는 회의록을 공개할 수 없습니다. 영업부서와 임원급에게만 공개할 수 있습니다.`
    - 101 → `공개한 사람이 30명입니다. 새 사람은 추가되지 않고, 이미 있는 사람의 기한만 바꿀 수 있습니다.`
    - 214 → `공개할 수 있는 사람은 30명까지입니다. 필요 없는 사람을 먼저 빼세요.`
- **P2-2 동명이인 구별**: 후보 줄이 '이름 직책'뿐입니다(119). 명단이 영업부서와 임원급으로 넓어져 '김○○ 차장'이 둘이면 구별이 안 됩니다.
  - 권장 형식: `홍길동 차장 (12345678)`. 공개 중이면 `홍길동 차장 (12345678) — 공개 중, 2026-12-24까지`, 지났으면 `… — 기한 지남, 2026-11-20`.
  - 사번은 공개범위 표(1431)와 직접 입력 칸이 쓰는 같은 식별자라서 고릅니다.
  - 부서 이름을 넣으려면 `role`이 무엇을 담는지 확인이 먼저입니다(7절 이관).
  - `~2026-12-24`의 물결표는 낭독기가 '물결'로 읽을 수 있어 '까지'로 씁니다.
- **P3-1 안내와 상자 연결**: 잘림·실패 안내 `p`에 id를 주고 `#mn-sc-sel`과 `#mn-sc-emp`에 `aria-describedby`로 잇습니다. 지금은 키보드 사용자가 상자로 바로 들어가면 안내를 듣지 못합니다.
- **P3-2 이력의 수칙 판 번호**: `RULES_ACK`의 `target_kind='RULES'`가 `TARGET`(133)에 없어 판 번호가 버려지고 '운용 수칙 확인'만 나옵니다. 수칙 문구가 바뀌면(`UPLOAD_RULES_VER` 올림) 누가 어느 판을 확인했는지 화면에서 구별할 수 없습니다. `TARGET.RULES = '수칙'`을 넣되 표시는 `운용 수칙 확인 (수칙 1판)`으로 씁니다. 숫자는 서버 값 그대로입니다.
- `SCOPE_TARGET_INVALID`의 '사번을 확인하세요(퇴사·정지된 사람은 …)'는 이제 자격 오류와 갈려 뜻이 맞습니다. 그대로 둡니다.
