# 표 정렬 3차 실측 보고 (NEXT 124, 0d)

## 1. 대상·방법·못 본 것
- **방법**: Playwright로 localhost:8080을 직접 열었다. 영업팀장 **이영업**으로 업무 화면을, 전산팀 **권전산**으로 관리 화면을 봤다. 화면마다 getComputedStyle로 textAlign·verticalAlign을 쟀다. 잘림은 scrollWidth만 보지 않고 **글자 폭(Range)과 칸 안쪽 폭을 소수점까지 비교**해 판정했다. 04dd55d7 규칙(`.rs-tt col.c-nm 240`, `.pb-t thead th padding:4px 2px`, `.pl-bud .db-why … text-align:left`)이 불러온 CSS에 들어 있음을 확인했기 때문에 강력 새로고침은 하지 않았다.
- **중요한 측정 조건 발견**: 이 Playwright 브라우저는 **배율 90%(devicePixelRatio 0.9)** 로 떠 있다. 창을 1280으로 맞추면 실제 레이아웃 폭(innerWidth)은 **1422px**가 된다. Ctrl+0으로는 풀리지 않아서 창을 1152×810으로 줄여 **innerWidth 1280 / innerHeight 900**을 맞춘 뒤 쟀다. **2차 보고서(a6a5d7df)의 열 폭 측정과 수정안은 1422px 기준이었다.** 그래서 아래 이슈 A의 넘침이 생겼다. 요소 단위 스크린샷도 이 배율 때문에 위치가 어긋나서, 스크린샷은 모두 뷰포트로 찍었다.
- **쓰기 동작은 없다.** 화면 전환, 기관 선택, 단계 탭 이동, 탭(버전 이력·작업 이력) 전환, 수집 요청 창 열기와 Esc 닫기, 요약 양식 창 열기와 `#isf-cancel` 닫기만 했다. 닫은 뒤 과제 상태가 '완료' 그대로인지 확인했다. 관리 화면 진입 전에 뜬 '공고 예정일이 지난 미처리 건' 팝업은 [닫기]로만 닫았다. 측정용으로 표 2개에 임시 id를 붙였는데, 페이지 안의 일이라 새로고침하면 사라진다. 마지막에 browser_close로 닫았다.
- **못 본 것**:
  - 반입 확인 창(`.pl-dlg-tbl`, plancollect). 수집 요청 화면에 반입 절이 없다(반입 폴더가 꺼진 것으로 보임).
  - 요약 양식 `.isf-years`·`.isf-tbl`. 양식 창은 열었지만 연도 표와 평가 기준표가 비어 있다("연도 표가 아직 없습니다", "아직 평가 기준표가 없습니다"). [직접 만들기]·[빈 표로 시작]은 데이터 변경일 수 있어 누르지 않았다.
  - 입찰 결과의 '목표 구분 기준' 표시가 붙은 결과 칸, 은행 두 개가 든 은행 칸. 이영업의 데이터 2건은 모두 결과 대기라 없었다.

## 4. 우선순위 이슈
**A. P2(회귀) `.rs-tt`가 1280px에서 패널 밖으로 넘치고, 구분 칸이 아직 잘린다**
- 근거: index.html 3052행 `min-width:1080px`. 1280 화면에서 `.rs-tp` 안쪽 폭은 990px다. 3088행 `@media (max-width:1169px) { .rs-tp { overflow-x:auto; } }`는 1280에서 적용되지 않으니 overflow:visible로 넘친다. 3054행 `c-tag 96px`에서 쓸 수 있는 폭은 76px인데 '신규유치 도전'은 76.2px이다.
- 왜 문제인가: 기준 해상도에서 제안 진행 열이 화면 밖으로 잘려 나가고 페이지 전체에 가로 스크롤이 생긴다. 2차 수정안이 배율 90%(1422px)에서 잰 값이었기 때문이다(디자인 쪽 측정 실수).
- 수정안 (고정 열 합 874 → 990에서 은행 열 116px, 쓸 수 있는 폭 96. '1금고 국민은행'(약 82px)이 은행 하나당 한 줄에 들어간다):
  - 기존 3052행: `.rs-tt { width:100%; min-width:1080px; table-layout:fixed; …}   /* 고정 열 합 882 + 은행 열 최소 ~200(design 11-26 실측) */`
  - 새 3052행: `.rs-tt { width:100%; min-width:960px; table-layout:fixed; …}   /* 1280 화면 안쪽 990 — 고정 열 합 874 + 은행 열 최소 86(design 11-26 3차 실측, 배율 100%) */`
  - 기존 3054행: `.rs-tt col.c-nm { width:240px; } .rs-tt col.c-tag { width:96px; } .rs-tt col.c-res { width:180px; } .rs-tt col.c-bank { width:auto; }`
  - 새 3054행: `.rs-tt col.c-nm { width:224px; } .rs-tt col.c-tag { width:104px; } .rs-tt col.c-res { width:180px; } .rs-tt col.c-bank { width:auto; }`
  - 3055행(`c-from 96 · c-evd 150 · c-prep 120`)은 그대로 둔다.
  - 시험: `frontend/test/table-center.test.js:150`의 `'.rs-tt col.c-tag { width:96px; }'` 검사를 `104px`로 고쳐야 한다.
  - 확인: 적용한 뒤 1280(배율 100%)에서 `.rs-tp` scrollWidth ≤ clientWidth인지, '신규유치 도전'이 잘리지 않는지 다시 잰다.

**B. (해소) `.pb-t` 머리값 낱말 꺾임** — 04dd55d7로 해결됐다. 위 표를 보라.

**C. P3 '예산 미기재'가 원문 문장 규칙을 따라 왼쪽에 붙는다**
- 근거: index.html 2894행 `.pl-bud .db-why { … text-align:left; … }`. '예산 미기재'도 `<span class="db-why">`로 출력된다.
- 왜: DESIGN 102행에서 빈 값 표시는 가운데(`.dg-hint` 관례)다. 한 열에 숫자(오른쪽), 원문(왼쪽), 빈 표시(왼쪽)가 섞이면 빈 칸이 문장처럼 읽힌다.
- 수정 방향: 출력하는 쪽(plans.js 예산 칸)이 빈 표시에 구분 클래스를 붙이도록 개발이 정한다. 예: `<span class="db-why pl-bud-none">`. CSS는 2894행 아래에 새 줄 `.pl-bud .db-why.pl-bud-none { text-align:center; }`를 둔다.

## 5. 문구 / 접근성
- 메뉴 관리 각주 "file://로 열면 켜져 있어도 보이지 않습니다"는 사용자에게 내부 용어를 드러낸다(P3, 정렬과는 별개).
- 기관 사업계획과 시작화면에서 scrollIntoView를 하면 문서 전체가 45~314px 위로 밀려 상단 막대가 사라지고 아래에 회색 띠가 생긴다(scrollHeight 6482, body overflow:hidden). 2차 이관 건이 다시 나타난 것이다(t124c-portal.png 첫 촬영본에 보였고, 다시 찍으며 덮어썼다).
- 콘솔 오류는 favicon.ico 404 하나뿐이다.

## 6. 규격 요약 / 전·후 장
- 4절 A의 CSS 3줄과 시험 1줄이 전부다. 정렬 규칙은 바꾸지 않는다.
- **전/후 장 필요**(A를 적용하면, 04dd55d7 장이 이미 있다면 그 장에 '3차' 정정으로):
  - 전: 1280에서 표 1080px가 패널(990) 밖으로 90px 넘친다. 제안 진행 열이 오른쪽 끝에서 잘린다. 구분 칸에 "신규유치 도…"가 보인다(t124c-results-1280.png).
  - 후: 표 990px 안에 들어간다(은행 열 116). 구분 '신규유치 도전'이 다 보인다.
  - 숫자: 넘침 90px → 0, 구분 여유 −0.2px → +7.8px.
  - 왜: 2차 측정이 배율 90% 브라우저에서 이뤄져 실제 1280보다 432px 넓게 잰 것을 바로잡는다.
