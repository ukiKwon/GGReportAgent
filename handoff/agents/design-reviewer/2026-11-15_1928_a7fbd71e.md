## 2. 한 줄 총평
지금 편집 모달은 서버가 정한 "날짜·확정·출처는 한 묶음" 규칙을 화면에 드러내지 못한다. 그래서 저장하면 이유 없이 `alert('서버 저장 실패 (400)')`가 뜬다.
**가장 큰 기회:** 모달을 **입찰 예정일 / 운영 상태 / 기본 정보** 세 묶음으로 나누고 묶음마다 저장 버튼을 둔다. 버튼 이름은 서버 X-Button-Id(save_schedule·save_open_status·save_basic)와 1:1로 맞춘다. 서버 규칙을 화면이 미리 보여 주면 400이 날 일이 거의 없어진다.

**잘 된 점**
- 잠긴 칸에 이유를 붙이는 방식(app.js 364–369)과 비운 칸·안 건드린 칸을 구분하는 방식(clearable)이 이미 있다. 새 묶음도 같은 원칙으로 확장하면 된다.

- 서버 오류 문구는 고정 문구라 내부 정보가 없다(EditRules 17행). 대부분 그대로 보여 줘도 된다.

**보내는 규칙 (화면 동작 규칙, 고정)**
1. `contract_end`는 **날짜칸 값(앞뒤 공백 제거)이 기준값과 다를 때만** 보낸다. 빈칸이면 null. 안 건드렸으면 키 자체를 넣지 않는다.
2. 이 묶음을 저장할 때 `contract_end_confirmed`는 **늘** 보낸다(true/false).
3. `contract_end_src_url` / `_src_no`는 [공고로 확정]이고 그 입력칸이 **비어 있지 않을 때만** 그 키를 보낸다.
4. 날짜·근거가 그대로이고 새 출처칸이 둘 다 비었으면 "바뀐 것 없음"으로 보고 저장 버튼을 disabled로 둔다.

**화면 사전 검사 (서버와 같은 글자)**
- 날짜 형식이 틀리면 "날짜는 YYYY-MM-DD 형식이어야 합니다."
- 필수인데 출처가 비면 "확정하려면 출처(공고 링크 또는 번호)가 필요합니다."
- 링크가 http(s)가 아니면(safeHttpUrl) "출처 링크는 http 또는 https 주소(500자 이내)여야 합니다."

**보내는 규칙**
- `op_status`와 `open_date`는 각각 바뀐 경우에만 보낸다.
- `op_src_url` / `op_src_no`는 비어 있지 않을 때만 보낸다. 이렇게 하면 서버 L1 오류("모두 비울 수 없습니다")가 화면 흐름에서 생기지 않는다.

**사전 검사 문구 (서버와 같은 글자)**
- "개원 예정에는 개원 예정일(연, 연-월 또는 연-월-일)이 필요합니다."
- "운영 상태를 바꾸려면 출처(링크 또는 번호)가 필요합니다."
- "개원 예정일은 YYYY, YYYY-MM 또는 YYYY-MM-DD 형식이어야 합니다."

### 6-C. 기본 정보 묶음 (save_basic)

- 칸: 기관명(잠김, 기존 문구 유지), 기관구분, 지역코드, 구시군코드, 입찰주기(년), 지난 입찰일, 약정 만료일, 경도, 위도, 출처(wide). 2열이다.
- **입찰예상일과 확정여부 칸은 이 묶음에서 뺀다.**
- 저장 동작은 지금 로직(서버 필드는 PUT, 로컬 칸은 setEdit)을 유지하되, 서버로 보내는 것은 바뀐 칸만이다.
- 하단 힌트는 P3-a 문구로 바꾼다.

### 6-D. 확정 배지 옆 출처 (현황판 상세·지도 상세·팝오버)

**어디에**
- `dashboard.paneHtml` 입찰 예정일 `<dd>`의 `why` 뒤에 줄바꿈 한 번, `<span class="db-why">출처</span> …`.
- render.popoverHtml의 pop-grid 입찰 예정일 `<dd>`에는 같은 내용을 `<br>` 뒤 12px로.

**언제**
- 표시 날짜가 **기관 행의 확정 값**일 때만이다(공고에서 온 날짜가 아니고, contract_end_confirmed=true).
- 공고에서 온 날짜는 기존 '공고 진행' 절이나 출처 목록이 맡는다(중복 금지).

**모양**
- `출처 <a href="{esc(safeHttpUrl)}" target="_blank" rel="noopener noreferrer" title="{esc(전체 주소)}">{esc(호스트)}</a> <span class="db-why">(인터넷 PC에서 열림)</span>`
- 번호가 있으면 ` · 공고 번호 <mono>{esc}</mono>`를 덧붙인다.
- 호스트 = `new URL(u).hostname`에서 앞의 `www.`를 뗀 값.
- safeHttpUrl을 통과하지 못한 값은 링크 없이 글자로만 보인다.

**출처 없는 옛 확정 행 (9곳)**
- `<span class="pop-unk">출처 미기록</span>`(점선 칩, 기존 클래스). 근거 없는 확정을 숨기지 않는다(PRODUCT 원칙 1).

**운영 상태 줄 (같은 상세의 기관 정보 dl)**
- 개원 예정 기관에만 `<dt>운영 상태</dt><dd>개원 예정 · 개원 예정일 <mono>…</mono> {출처 같은 모양}</dd>`를 단다. 운영 중인 기관에는 줄을 두지 않는다(정보 없는 줄 금지).

### 6-E. '개원 확인 필요' 표시

- **지도:** 바꾸지 않는다. 개원 예정 법원은 지금처럼 그리지 않는다(isOpeningCourt).
- **현황판 목록 (bid_board):**
  - '공고 예정일 경과' 토글(dashboard.js 764) 바로 아래, **n>0일 때만** 같은 `.db-more` 모양의 토글을 둔다: `개원 확인 필요 <b>n</b>곳` / 펼치기·접기. 기본은 접힘, `aria-expanded`/`aria-controls`.
  - 펼치면 `ul role=listbox aria-label="개원 확인 필요 기관"`.
  - 행: `.nm` 기관명 + `<span class="db-chk">개원 확인 필요</span>` + `.meta` "{지역} · 개원 예정일 <mono>{open_date}</mono> 지남".
  - D-day 태그는 두지 않는다(입찰 대상이 아님).
- **현황판 상세 (행 선택 시):**
  - 머리의 D-day 자리에 `.db-chk` "개원 확인 필요".
  - 기관 정보 dl에 6-D의 운영 상태 줄.
  - 행동 줄: `<span class="db-why">개원했는지 확인하고 출처와 함께 운영 상태를 바꾸세요.</span> [기관 정보 변경]`. 이 버튼은 openEdit을 열고 포커스를 운영 상태 묶음 첫 라디오로 보낸다(X-Screen-Id bid_board, X-Button-Id open_edit).
  - [제안 확정]은 두지 않는다(§7 기획 확인).
- **색:** `.db-chk`(`--orange` 12px 글자)는 '확인 필요' 계열에 이미 쓰는 표시를 재사용한다. 새 색이나 채움은 없다(Saturation Monopoly·18% 규칙 준수).

### 6-F. 1280폭 측정 (시안 주입)
- 상자 560×672px, 위 40px.
- 입력칸 236×30.7px, 라디오 라벨 높이 28px.
- 가로 넘침 없음.
- 최악의 경우 내용 높이 1072/530px라 스크롤된다. 그래서 6-B의 운영 상태 접힘은 필수다. 보통(지자체, 공고 없음) 높이는 약 480px로 예상하며 측정은 하지 않았다.

- **전:** 360px 1열에 13칸. '입찰예상일' 칸과 확정 여부(이 PC에만 저장)가 따로 논다. 저장하면 `서버 저장 실패 (400)` 팝업만 뜨고 이유가 없다. 공고가 있는 기관은 공고 날짜가 칸에 들어가 있어 손대지 않아도 실패할 수 있다.
- **후:** 560px 2열, 세 묶음(입찰 예정일 / 운영 상태 / 기본 정보)마다 저장 버튼. '추정 / 공고로 확정'을 고르고, 확정이면 공고 링크나 번호를 적어야 저장된다. 왜 안 되는지가 칸 바로 아래 글자로 나온다(대비 약 7.7:1). 확정 날짜 옆에는 출처 호스트(예: g2b.go.kr)가 보이고, 개원 예정일이 지난 법원은 현황판 '개원 확인 필요 n곳'에 모인다.
- **왜:** 서버가 "날짜를 확정하려면 근거를 남긴다" 규칙을 세웠는데 화면이 그 규칙을 몰라 저장이 막혔기 때문이다.

## 7. 이관 메모

**개발 (프런트)**
- [이관: 개발] 모달 초기값에 쓸 **기관 행 원래 값**(contract_end, contract_end_confirmed, *_src_*)을 공고로 덮인 rec와 따로 보관해야 한다. 디자인이 기다리는 것: §6-A 초기값 규칙. 근거: serverdata.js 109–110이 rec.contractEnd를 덮는다.
- [이관: 개발] 새 칸 매핑이 필요하다. mapServerRow FIELD_MAP(serverdata.js 7–11)에 새 칸이 없고, 화면은 opStatus를 '개원 예정' 글자로 판정한다(logic.js 209). 서버 PLANNED → '개원 예정' 변환과, open_check_needed 기관을 6-E 목록에 따로 모으는 처리가 있어야 한다.
- [이관: 개발] 확정 여부를 LOCAL_ONLY_FIELDS(store.js 38)에서 빼야 한다. 그대로 두면 로컬 overlay가 서버 값을 덮을 수 있다(store.js 55–58은 공고 행만 막는다).

**개발 (백엔드)**
- [이관: 개발] §5의 서버 문구 3개를 바꿔야 한다(`(contract_end_confirmed)`·`true 또는 false`·`JSON`). 화면 흐름에서는 거의 나지 않지만 그대로 보이는 정책이라 내부 용어가 남는다.

**기획**
- [이관: 기획] 운영 상태 묶음을 법원 밖 기관(교육청·공공기관)에도 둘지 정해야 한다. 디자인은 접어서 모두에게 두는 것을 기본안으로 했다. 걸리는 점: 개원 예정을 지도·목록에서 빼는 규칙(logic.js 209)은 법원만 보므로, 지자체를 개원 예정으로 바꾸면 지도에 그대로 남아 어긋난다.
- [이관: 기획] '개원 확인 필요' 기관에 [제안 확정]을 막을지 정해야 한다. 디자인은 두지 않는 쪽으로 규격을 썼다.
- [이관: 기획] 묶음별 저장(버튼 3개)과 한 번 저장 중 무엇으로 갈지. 디자인은 서버 버튼 ID 3개와 묶음별 오류 위치 때문에 묶음별 저장을 택했다. 감사 기록 단위가 버튼 ID 하나라는 점도 확인이 필요하다.
- [이관: 기획] P3-2 "추정에 출처를 남길 수 있게 할지". 지금 규격은 추정이면 출처칸을 숨긴다.

**데이터**
- [이관: 데이터] 출처 없는 확정 9곳의 출처를 채워야 한다. 그 전까지 화면에는 "출처 미기록"이 보인다.
