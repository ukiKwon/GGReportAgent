## 4. 우선순위 이슈

**P2-1 목록으로 돌아오면 포커스가 body로 사라진다**
- 근거: 실측. 열기 → [← 이사회 자료 목록]을 누른 직후 포커스는 `bd-l-open`에 있었지만, 1초 뒤에는 `BODY`였다. `board-material.js` `toList()`가 포커스를 먼저 옮기고 `loadList()`를 부른다. 응답이 오면 `drawRes()`가 `#bd-l-res`의 innerHTML을 통째로 바꿔 포커스 받은 버튼이 사라진다. 양식 화면에서 돌아오는 `leaveForm`도 같은 구조다.
- 왜: 규격 §5-6 "열었던 그 버튼으로 포커스를 돌려준다"가 실제로는 지켜지지 않는다. 키보드·스크린리더 사용자는 페이지 맨 위부터 다시 탐색해야 한다.
- 수정: 돌려줄 버튼의 id를 `pendingFocus`에 담아 두고, `drawRes()` 끝에서 `byAttr(..., 'data-id', pendingFocus)`로 다시 포커스한 뒤 비운다. 또는 `loadList().then(() => focusNode(...))`로 순서를 바꾼다.

**P2-2 목록 안 세 덩어리 사이 간격이 0이다**
- 근거: `#bd-list`는 `display:block`이다. 실측 y값: 머리 107–127, 검색 줄 127–157, 표 157. 새 자료 패널과 검색 줄 사이도 붙어 있다(`bd14-5`). `#bd-root`의 gap 10px은 `#bd-list` 안쪽에는 적용되지 않는다.
- 왜: 규격 §6-5는 "머리 → 검색 줄 → 표" 순서에 10px 간격을 정했다. 지금은 제목 아래에 검색 입력칸이 바로 붙어 위계가 흐려진다.
- 수정: `#bd-list:not([hidden]) { display:flex; flex-direction:column; gap:10px; }`. `#bd-l-top`이 비어 있지 않으므로 그대로 두면 된다.

**P2-3 양식 편집 안내가 없어진 버튼을 가리킨다**
- 근거: `board.js` `editGuideHtml`의 "표 안의 숫자는 예시입니다. 실제 값은 [이 양식으로 작성]에서 엑셀을 올리면 채워집니다."
- 왜: 규격 §6-6에서 그 버튼을 삭제했다. 양식 편집 권한자에게 존재하지 않는 경로를 안내한다.
- 수정 문구: "표 안의 숫자는 예시입니다. 실제 값은 이사회 자료 목록에서 자료를 열고 엑셀을 올리면 채워집니다."

**P2-4 [작성] 탭 패널에 탭 역할이 없다**
- 근거: `#bd-tab-write`의 `aria-controls="bd-body"`. 그런데 `#bd-body`에는 `role`도 `aria-labelledby`도 없다. `#bd-m-hist`에는 `role="tabpanel"`이 있고 aria-labelledby도 바꿔 준다.
- 왜: 스크린리더가 작성 탭의 내용을 탭 패널로 알리지 않는다. 같은 탭 묶음 안에서 동작이 다르다.
- 수정: 자료 보기에서 `#bd-body`에 `role="tabpanel"`과 `aria-labelledby="bd-tab-write"`를 붙인다. 양식 보기로 갈 때(`showView('form')`)는 두 속성을 뗀다.

**P3-1 "아직 저장한 버전이 없습니다"가 화면에 두 번 나온다**
- 담당자 화면: 머리 meta와 작성 줄 상태(`bd14-6`). 부장 화면: 머리 meta와 본문(`bd14-2`).
- 수정: 저장본이 없을 때 머리 meta는 **"저장 전"**으로 쓴다(목록의 '마지막 저장' 열과 같은 말). 문장 형태는 작성 줄·본문에만 둔다.

**P3-2 [버전 저장]이 꺼진 이유를 설명하지 못한다**
- 근거: `aria-describedby="bd-m-state"`. 상태 A에서 읽히는 말은 "아직 저장한 버전이 없습니다"뿐이다. 실제로 꺼진 이유는 '바뀐 칸 0'이다. 규격 §5-6이 이렇게 정한 것이라 규격 쪽 빈틈이다.
- 수정: 숨김 글자 `<span class="bd-sr" id="bd-m-savewhy">엑셀을 올리거나 칸 값을 고치면 저장할 수 있습니다.</span>`를 두고, 꺼져 있을 때 describedby를 `"bd-m-state bd-m-savewhy"`로 한다.

**P3-3 같은 동작을 하는 버튼이 둘씩 있다**
- ⓐ 검색 결과 0건일 때 [조건 지우기]가 검색 줄(link-btn)과 빈 상태(버튼)에 둘 다 있다(`bd14-4`). 수정: 결과 0건일 때는 검색 줄 쪽 `#bd-l-clear`를 숨긴다.
- ⓑ 상태 A에서 [엑셀 올리기](작성 줄)와 [엑셀 파일 고르기](드롭존)가 함께 있다(`bd14-6`). 수정: 드롭존이 보이는 동안 작성 줄의 [엑셀 올리기]를 숨긴다. 드롭존이 주 행동이다.

**P3-4 담당 건이 없는 사람에게 검색 줄과 "0건"이 보인다**
- 근거: `bd14-8`. 검색할 대상이 없다.
- 수정: 부장이 아니고, 담당 건이 0이고, 검색 조건이 없고, 결과가 0건이면 `#bd-l-bar`를 숨긴다.

**P3-5 이름 표기가 엇갈린다**
- 목록·머리는 "노원구", 새 자료 패널은 "노원구청"이다(NEXT 67과 같은 뿌리).
- 새 자료 패널의 양식 선택은 "기본 양식", 머리 meta는 "이사회 자료 수익성 분석(기본 양식)"이다.
- 수정: 양식 이름은 한쪽으로 맞춘다. 서버 양식 이름을 쓰는 쪽을 권장한다. 기관명은 이관 항목으로 넘긴다.

**P3-6 양식 화면 제목이 목록 제목과 같다**
- 근거: `index.html`의 `#bd-head` "이사회 자료 — 양식을 고르면 문서가 표로 표시됩니다".
- 수정: 제목을 "**이사회 자료 양식**"으로 바꾸고 보조 글은 "양식을 고르면 문서가 표로 표시됩니다"로 둔다. [← 이사회 자료 목록]도 자료 보기처럼 제목 위 한 줄(`bd-m-back`)에 둔다. 지금은 양식 선택과 같은 줄에 있다.

**P3-7 쓰이지 않는 옛 403 문구가 남아 있다**
- 근거: `board-write.js`의 `status === 403`(자료 모드가 아닌 분기) "이 양식으로 자료를 작성하려면 업무 수정 권한이 필요합니다."와 `canPerm` → [권한 신청하러 가기].
- 자료 모드가 아닌 작성 경로는 이제 화면에서 들어갈 수 없다. 규격 §6-6 '삭제' 목록에 들어 있으니 지운다. 정리 담당(cleaner)이나 프런트 담당에게 넘긴다.
