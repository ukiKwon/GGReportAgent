## 3. 점수표 / 잘 된 점
- **점수표**: 생략합니다. 실화면을 보지 못해 휴리스틱 점수를 매길 근거가 없습니다. 다음 실화면 검토 때 매깁니다.
- **잘 된 점**
  - **꺼진 버튼마다 이유가 붙습니다.** `disabledNext`가 `aria-describedby`로 연결합니다. 담당자가 아닌 사람에게는 카드마다 반복하지 않고 목록 위에 한 번만 보입니다(규격 §6-A).
  - **포커스 복귀가 꼼꼼합니다.** 확인 줄을 열면 안전한 쪽 버튼으로, 체크 뒤에는 같은 과제로, 모달을 닫으면 연 버튼으로 돌아갑니다. 연 버튼이 사라졌으면 제목으로 갑니다.
  - **'미확인' 칩이 PRODUCT 원칙 1을 지킵니다.** 현 유치 은행·임직원 수·기관장은 근거가 생기기 전까지 빈칸이나 추정값 대신 '미확인'으로 보입니다. 내부 칸(지역코드·경도·위도)은 팝오버에서 빠졌습니다.

## 5. 우선순위 이슈

**[P2] 팝오버가 화면 아래로 잘릴 수 있음**
- **근거**
  - `#popover`에 `max-height`·`overflow`가 없습니다(index.html 1185~1188행).
  - `showPopover`는 top을 `innerHeight - 300`까지만 끌어올립니다(render.js 639행).
  - 소스로 추정한 높이는 접힌 상태 약 230px입니다. '원본 정보'를 펼치면 6줄과 출처 URL이 더해져 300px를 넘고, [제안 확정] 확인 문구(280px 폭에서 4~5줄)도 더해집니다.
- **왜 문제인가**: 아래쪽 카드나 마커에서 연 팝오버는 [확정하기]·[취소]가 화면 밖으로 밀릴 수 있습니다.
- **수정 방향**: CSS 패치(§6-5). 실측이 필요합니다.

**[P3] 확인 줄 두 종류의 버튼 순서가 반대**
- **근거**
  - 과제·끝 노드의 `.pp-confirm`은 [취소][실행] 순서이고, 첫 포커스가 취소입니다(prep.js 436~441행).
  - 팝오버의 `.pop-confirm`은 [확정하기][취소] 순서입니다(266~273행).
  - 모달은 [닫기][실행] 순서입니다.
- **수정 방향**: 팝오버도 [취소][확정하기]로 바꿉니다. 첫 포커스는 규격대로 [확정하기]에 둡니다. 실행 버튼은 오른쪽이라는 한 규칙으로 맞추는 것입니다.

**[P3] `.pp-confirm`의 group에 이름이 없음**
- **근거**: prep.js 438행·745행의 `role="group"`에 aria-label이 없습니다.
- **왜 문제인가**: 화면낭독기 사용자는 "그룹"이라고만 듣습니다.
- **수정 방향**: §6-3.

**[P3] 회수 중 버튼 상태가 없음**
- **근거**: `onWithdraw`에는 `S.busy`로 두 번 누름을 막는 장치만 있습니다. 버튼 글자와 aria-disabled는 바뀌지 않습니다.
- **비교**: 이사회 자료는 회수 중에 "회수하는 중…"을 보입니다.
- **수정 방향**: §6-2.

**[P3] 계약과의 어긋남: 위험 버튼 규칙**
- **근거**: `.pp-danger`(1057~1058행)를 쓰는데 DESIGN.md에 규칙이 없습니다.
- **수정 방향**: §6-4의 한 줄을 DESIGN.md에 더합니다. 메인이 직접 고치는 문서입니다.

## 6. 문구 / 접근성 — 패치 후보

1. **회수 성공 문구(prep.js 95행)**
   ```js
   okWithdraw: '개설 신청을 회수했습니다. 담당자를 다시 지명해 [개설 신청]을 올릴 수 있습니다.',
   ```
2. **회수 버튼 처리 중 표시(prep.js 574행 부근)**
   - `S.busy`이면 버튼 글자를 '회수하는 중…'으로 바꾸고 `aria-disabled="true"`를 겁니다.
   - endHtml에 busy를 넘기거나, 클릭 직후 DOM에서 버튼 글자만 바꿉니다.
3. **확인 줄 이름과 버튼 순서**
   - `confirmHtml`에 label 인자를 더해 `role="group" aria-label="{label}"`로 씁니다.
     - 완료 취소: "완료 취소 확인"
     - 기획승인: "기획승인 요청 확인"
     - 작성 시작: "제안서 작성 시작 확인"
     - 닫기 확인: "닫기 확인"
   - `popConfirmHtml`의 버튼 순서를 `<button data-pp-pop="cancel">취소</button><button class="pp-next-btn" data-pp-pop="go">확정하기</button>`로 바꿉니다. 포커스 코드(prep.js 1512행)는 그대로 둡니다.
4. **DESIGN.md 'Modals & Popover' 또는 버튼 절에 넣을 한 줄(계약 보강)**
   > 되돌릴 수 없는 위험 동작의 **최종 실행 버튼 하나만** `--red` 글자 + 1px `--red` 테두리 + `--panel2` 배경으로 그리고, hover 때 `--red` 18% 틴트를 씁니다(대비 5.6:1). 위험 동작을 여는 머리 버튼(예: [중단…])은 일반 버튼입니다. 채운 빨강은 쓰지 않습니다.
5. **팝오버 높이 CSS(index.html #popover)**
   ```css
   #popover { /* 기존 값 유지 */ max-height:calc(100vh - 16px); overflow:auto; overscroll-behavior:contain; }
   ```
   - `showPopover`의 top 고정값을 실제 높이로 바꿀 수도 있습니다. `pop.offsetHeight`를 읽어 `Math.min(y+12, innerHeight - pop.offsetHeight - 8)`로 계산합니다. 이것은 구현 선택이라 프론트가 정합니다.
6. **대비(토큰 계산값)**: 모두 기준을 넘습니다. 회색 #5a6273은 글자에 쓰지 않았습니다(grep으로 `.pp-`·`.pop-` 규칙 확인).
