# 에이전트 작업 기록 — 소통 규칙

에이전트별 작업 기록을 `handoff/agents/<에이전트 이름>/`에 둔다. 에이전트 정의는 `.claude/agents/`,
쓰기 범위를 막는 훅은 `.claude/hooks/agent-guard.ps1`. (여러 **세션**이 동시에 돌 때의 기록은
`handoff/sessions/`와 `CLAUDE.md` "여러 세션 동시 작업"을 따른다 — 이 폴더는 **에이전트** 단위다.)

## 소통 방식 — 메인 세션이 허브, 파일이 우편함

에이전트끼리 직접 대화하지 않는다. 서브에이전트는 사용자에게 질문할 수도 없다.

1. **지시**: 메인 세션이 에이전트를 부르며 대상·맥락·확정된 결정을 지시문에 담는다. (에이전트는 대화 내용을 모른다.)
2. **결과**: 에이전트가 자기 폴더에 작업 파일을 쓰고, 같은 내용을 메인에 돌려준다.
3. **이관**: 에이전트가 자기 역할 밖의 문제를 만나면 해결하지 않고 작업 파일의 "이관 메모"에 적는다.
4. **결정**: 메인이 이관 메모를 읽고 **사용자에게 묻는다.** 결정이 나오면 `handoff/NEXT.md`에 항목으로 기록한다 (NEXT.md는 메인만 고친다).
5. **다음 에이전트**: 메인이 NEXT.md 항목 번호 + 앞 에이전트의 작업 파일 경로를 지시서로 넘긴다.

사용자 승인은 항상 메인 단계에서 받는다 (`CLAUDE.md` "작업 착수 전 승인").

## 작업 파일

- 위치·이름: `handoff/agents/<에이전트>/YYYY-MM-DD_<주제>.md` — 작업 1건당 파일 1개.
- 권장 구성: `## 지시` (메인이 준 요청·확정 결정) → `## 결과` → `## 이관 메모` → `## 열린 질문`.
- 이관 메모 한 줄: `[이관: 기획|개발|데이터] 무엇을 결정/확인해야 하나 — 기다리는 것 — 근거`.
- 이 폴더는 SessionStart 훅이 읽지 않는다. **새 작업 파일을 만들면 `handoff/NEXT.md`의 관련 항목에 한 줄 포인터**를 남긴다.

## 에이전트와 쓰기 범위

범위는 `agent-guard.ps1`의 표가 정본이다 (아래는 사람이 보기 위한 사본 — 어긋나면 스크립트가 맞다).

| 에이전트 | 상태 | 쓸 수 있는 곳 | 주 역할 |
|---|---|---|---|
| `design-reviewer` | 있음 | `DESIGN.md`, `docs/design/mockups/`, `handoff/agents/design-reviewer/` | 디자인 진단·규격·시안·문구·접근성. 소스는 읽기만 |
| `frontend-dev` | 예정 | `frontend/`(단 `frontend/data/` 제외), 자기 폴더 | JS·마크업·CSS 구현, 프런트 테스트 |
| `qa-verifier` | 예정 | 자기 폴더만 | 구현 뒤 테스트·화면 확인 |
| `data-auditor` | 예정 | 자기 폴더만 | 기관 레코드 날짜를 원문 출처와 대조 |
| `backend-dev` | 예정 | `kgi-ggreport-web/`, `db/`, 자기 폴더 | 서버·DB·서버 테스트 |

새 에이전트를 추가할 때: ① `.claude/agents/<이름>.md` ② `agent-guard.ps1`의 `$rules`에 항목 추가 ③ 이 표 갱신
④ `handoff/agents/<이름>/` 폴더 생성.

## 주의

- `agent-guard.ps1`은 **ASCII만** 쓴다 (Windows PowerShell 5.1이 BOM 없는 UTF-8을 ANSI로 읽는다 — NEXT.md 23번).
- 프로젝트 훅은 이 폴더의 **신뢰 허용**을 수락해야 작동한다. 훅이 안 걸리면 쓰기 제한이 없는 것과 같으니, 에이전트를 새로 만들거나 고친 뒤에는 차단 시험을 한다.
- 서버(`localhost:8080`)·로컬 DB는 한 번에 한 세션/에이전트만 쓴다.
