### 1. 대상·방법·못 본 것
- 대상: `frontend/data/institutions_nonmuni.js`의 법원 레코드 103건(운영 97, 개원 예정 6). 본원 33곳(+개원 예정 2곳)은 호스트를 모두 조회했다. 지원 64곳(+개원 예정 5곳)은 별도 호스트가 없다는 것까지만 확인했다.
- 방법: 각 호스트의 `https://<호스트>/dcboard/new/DcNewsListAction.work?gubun=41`을 WebFetch로 열어 글 링크의 `cbub_code`를 읽었다. 호스트 이름은 `https://www.scourt.go.kr/portal/info/location/LocationListAction.work?mode=list`에서 가져왔다.
- 한계: 한글이 EUC-KR 깨짐으로 보인다. 그래서 호스트와 법원 이름의 대응은 호스트 약칭(sldongbu 등)에서 추정한 것이다. 이 추정은 다른 근거(기존 보고서, 검색 결과 제목)와도 맞는다.
- 못 본 것:
  - 지원 64곳의 목록 화면. 지원 전용 호스트가 없어서 열 곳이 없다.
  - 첨부 다운로드 호스트(④). WebFetch가 첨부 링크(JS 호출)를 돌려주지 않았다.
  - http 접속 시 https로 넘어가는지. 도구가 리다이렉트 여부를 알려주지 않았다.
  - 개원 예정 전주가정·세종 호스트.

### 2. 요약
- 본원 호스트 33개 전부 https로 열렸고, 인증서 오류는 없었다. 호스트마다 글 링크의 `cbub_code`는 하나뿐이다(위 표). 목록 URL 형식은 모두 같다.
- 표본 5건에서 '공탁금 보관은행' 글이 그 게시판에 실제로 있었다(아래 5절).
- 지원: 호스트가 없다. 근거는 `bucheon.scourt.go.kr`·`dgseobu.scourt.go.kr`의 DNS 없음과, 법원 위치 목록에 지원 호스트가 없다는 점이다. 단 `bucheon`·`dgseobu`는 내가 지어낸 이름이라 DNS 없음만으로 지원 호스트가 없다고 단정할 수는 없다. 지원 글이 본원 게시판에 올라오는지는 정황으로만 봤다.

### 4. 규칙 요약
1. 호스트는 `<이름>.scourt.go.kr` 한 단계이고, 이름은 법원마다 제각각이다(sldongbu, slbukbu, swfamily, usfamily 등). 이름 규칙으로 만들 수 없으니 허용 목록 33개를 정확 일치로 적어야 한다. 기관 이름이 같은 이름과 대응하는지는 도메인만으로 알 수 없다.
2. cbub_code 6자리는 호스트마다 하나로 고정이다. 호스트에 다른 code를 붙여도 무시된다. `daegu` 호스트에 `cbub_code=000520`을 붙여도 글 링크는 000310으로 나왔고, `incheon` 호스트에 `000241`을 붙여도 000240으로 나왔다. 따라서 수집기에는 호스트 → code 매핑표를 두면 된다.
3. 지원은 별도 호스트가 없는 것으로 보인다. 지원 건물 코드는 본원+1 꼴이다(인천 000240 → 부천 건물 000241, 대구 000310 → 건물 000311). 하지만 새소식 목록의 code는 본원 것만 확인했다. **기존 메모의 "대구서부 000520"은 오기로 보인다.** 000520은 전주지방법원 호스트의 code다. 대구서부 글 17576이 000520 링크로 검색에 잡힌 것은 그 글이 전주 호스트에서도 열리기 때문이다. 아래 5절 참고.
4. `seqnum`은 전 법원 공통 번호다. 같은 seqnum 17576이 daegu·jeonju 호스트에서 모두 열렸다(제목은 둘 다 대구서부 관련으로 읽힘). 전국 게시판은 `https://www.scourt.go.kr/portal/dcboard/DcNewsListAction.work?gubun=41`(글 번호 42897까지)이고 글 보기는 `https://www.scourt.go.kr/portal/dcboard/DcNewsViewAction.work?...`로 열린다(제목 읽기 확인은 5절 표). 지원 글은 본원 호스트의 글 제목에 "[대구지방법원 서부지원]" 같은 머리말이 붙는다. 수집기는 호스트별이 아니라 전국 게시판 하나에서 제목 필터로 모을 수도 있다. 단 전국 게시판의 법원별 필터(검색 폼 동작)는 확인하지 못했다.
5. 글 인코딩은 EUC-KR이라 수집기가 디코딩해야 한다. 글 링크는 상대경로(`/dcboard/new/DcNewsViewAction.work?seqnum=…&gubun=41&cbub_code=…`)다. security 조건인 "호스트 정확 일치, `cbub_code`는 6자리 숫자"와 모순되는 곳은 없었다. 전부 6자리 숫자였다.
