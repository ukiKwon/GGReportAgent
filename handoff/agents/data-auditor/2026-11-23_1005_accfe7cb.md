## 4. 레코드 상태 의심
7곳 모두 입찰이 이미 끝났을 가능성이 큼(약정 12월 31일 만료, 공고 7~8월이라 9~11월에 결과가 났을 시점). 공개 자료로는 확인 안 되어 원문 재조회 필요.
- 관악구: 2026-11-04 기사에서 미정 6곳 중 하나. 11-23 현재 결과는 모름. 접수 2026-09-03~09-04, 게재기간 08-13~09-02.
- 삼척: 재공고 접수 08-14~18. 결과 공개 자료 못 찾음.
- 정읍·영천·청송: 공고기간 ~08-25, ~08-30. 청송은 계획 공고(07-24)만 있음.
- 광명·양양: 8월 공고 이후 상태 정보 없음.
- 재확인 대상: 각 시청 eminwon의 "금고 지정 결과", "협력사업비", "금리 공고" 제목. 장애 화면이 나오는 곳은 재시도하거나 구 홈페이지 고시/공고 게시판 확인. 관악 eminwon은 오늘 장애.

## 5. 스키마 시사점
- contractEnd 칸에는 7곳 모두 공고일이 들어 있음. 같은 칸이 어떤 곳은 약정 만료일, 어떤 곳은 공고일 의미.
- 원문에 만료일이 적힌 곳(삼척·정읍·영천·청송)에서도 칸에는 공고일이 들어갔고, 만료일은 sources 메모로만 있고 필드로는 없음.
- confirmed: true가 7곳에 모두 붙어 있음. "공고일 확인됨"인지 "약정 만료일 확인됨"인지 칸 의미가 섞임.
- contractEnd 이름의 칸 옆에 receiveFrom/receiveTo, noticeNo 같은 공고 단계 칸이 같은 레코드에 있음.
- 서버 시드(광명)에도 같은 공고일이 있어 번들·서버 양쪽 정리 필요. 6기관 시드는 미확인. 해법 설계는 하지 않음.

## 7. 열린 질문
- 7곳 중 입찰이 끝난 곳을 찾으려면 eminwon 결과 공고를 다시 조회해야 함. 장애 사이트는 재시도하고, 막히면 사용자가 브라우저로 확인해 줄 수 있는지.
- contractEnd에 약정 만료일(2026-12-31)을 넣을지, 공고일을 그대로 두고 임시 표식을 유지할지 사용자 결정 필요. 이 결정이 나야 바로잡을 곳 수(0곳 대 최대 7곳)가 정해짐.
