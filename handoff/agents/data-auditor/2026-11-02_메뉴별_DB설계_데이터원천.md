## 1. 대상·방법·못 본 것

## 2. 요약
- 데이터 원천 7종. 기관 일정 데이터는 이름이 3벌(프런트/CSV/DB), 같은 칸에 날짜 종류 혼재, 출처·사실·조사이력이 `sources` 문자열 배열 하나에 섞임.
- DB에 없는 원천 필드 17개(표 5). 좌표·구시군코드·확정여부·출처·수정일은 서버 모드에서도 브라우저 localStorage가 유일한 저장처.
- 품질 위험 12건(표 7). 최대 위험: 기관 식별을 이름 문자열로 함 — 서버 '도봉구', 번들·CSV '도봉구청', 완전일치 비교라 CSV 반입 시 중복 기관 생성.

## 4. 필드 사전 — 같은 개념, 다른 이름
| 개념 | 프런트 | CSV | DB | manifest | 비고 |
|---|---|---|---|---|---|
| 기관 식별자 | (없음)/`institutionId` | (없음) | INSTITUTION_ID | (없음) | 시드 'dobong', 반입분 'new-…' |
| 기관명 | `name` | 기관명 | NAME_KO | institution.name_ko | '도봉구청'(S1·S2) vs '도봉구'(S4) |
| 기관구분 | `type` | 기관구분 | TYPE | institution.type | 현재 전부 '지자체' |
| 광역코드 | `region` | 지역코드 | REGION_CODE | region_code | 행정표준 2자리 |
| 시군구코드 | `subRegion` | 구시군코드 | 없음 | sub_region_code | kostat 2018 체계(R7) |
| 주기 | `term` | 입찰주기 | TERM | schedule.term | 실제 '약정주기', 2·3·4 |
| 직전 절차일 | `lastBid` | 지난입찰일 | LAST_BID | schedule.last_bid | 날짜 종류가 레코드마다 다름(R2) |
| "입찰예상일" | `contractEnd` | 입찰예상일 | CONTRACT_END | schedule.contract_end | 진행 중 건엔 공고일(R1) |
| 확정 여부 | `confirmed` | 확정여부 | INSTITUTIONS 없음 / BID_CASES.SCHEDULE_CONFIDENCE | schedule.confidence | 어휘 3벌(R5) |
| 좌표 | `lng`,`lat` | 경도,위도 | 없음 | - | |

| 수정일 | `updatedAt` | 수정일 | 없음 | collected_at | |
| 공고 게시일 | (sources 문장) | 없음 | 없음 | schedule.posted_at | 반입 때 버려짐 |
| 제안 접수 마감 | (sources 문장) | 없음 | BID_CASES.EXPECTED/CONFIRMED_DATE에 섞임 | schedule.deadline_at | InboxService.scheduleDateFrom |
| 공고 식별 | (sources 문장) | 없음 | BID_CASES.SOURCE_SLUG·NOTICE_ID·TITLE·NOTICE_URL | source.* | |

## 7. 품질 위험
| # | 위험 | 영향 |
|---|---|---|
| R1 | CONTRACT_END/'입찰예상일'에 공고일(진행 중 건), 반입은 접수마감까지 같은 칸 | 한 칸에 4가지 의미 |
| R2 | lastBid 날짜 종류 7가지 | lastBid+term 추정 정확도 들쭉날쭉 |

| R11 | 날짜·시각 형식 혼재(UTC vs +09:00, 전부 문자열) | 정렬·시간대 오류 |
| R12 | 사람·역할 참조 문자열, 시드 ROLE·직위·등급 어긋남(백수아) | 무결성·역할 판정 |
