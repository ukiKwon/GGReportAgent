## 1. 대상·방법·못 본 것
- 대상은 행정표준코드(기관코드·법정동코드), 법원 코드, 알리오·클린아이 코드, 저장소 현황이다.
- 방법은 공식 페이지 WebFetch와 WebSearch다. 저장소는 파일:줄로 확인했다.
- 확인 못 한 것은 다음과 같다.
  - **법원 개별 기관코드 값**: code.go.kr 조회 화면이 동적이라 서울중앙지방법원 등의 7자리 값을 보지 못했다.
  - **지자체 기관코드 7자리의 실제 값 예시**: 같은 이유로 보지 못했다.
  - **알리오 apbaId와 클린아이 기관코드의 공식 형식**: 공식 문서에서 찾지 못했다.
  - **인천 개편의 새 법정동코드 숫자**: 공지 첨부파일을 열지 못했다.
  - 코드 폐지 후 재사용 여부: 공식 설명을 찾지 못했다.
- 나무위키와 GitHub 자료는 공식 출처가 아니므로 "간접"으로 표시했다.

## 4. 번호 체계 후보 비교 (결정 아님)

| 기준 | A. 종류 접두 + 행정기관코드(7자리) | B. 종류 접두 + 법정동 시군구코드(5자리) + 순번 | C. 자체 슬러그/순번(현재 방식 연장) |
|---|---|---|---|
| 외부·내부가 독립적으로 같은 번호를 만드는가 | 가능. 같은 code.go.kr 표를 양쪽이 쓰면 된다. 다만 내부(폐쇄망)가 그 표를 반입해야 한다. 표는 공개 자료라 업무망 기관 목록을 내보내는 일은 아니다 | 가능(계산 규칙이 같으면). 순번 때문에 기관 목록 순서가 같아야 하고 그러려면 규칙이 필요하다 | 불가능(무작위 `new-…`) 또는 사람이 정한 철자에 의존(슬러그) |
| 개편 시 안정성 | 코드 변경 이력 필드(`preorg_cd`, `use_cd`)가 있어 연결 근거가 있다. 통합·분리 때 새 코드를 주는지는 미확인 | 인천처럼 구가 폐지·신설되면 시군구 코드가 바뀐다. 서해·검단은 같은 폴리곤을 공유하면 충돌한다. 순번이 보완책이 된다 | 개편과 무관하게 불변이다. 대신 규칙이 없어 외부·내부가 어긋난다 |
| 지자체 구분력 | 일반구·자치구 포함 개별 기관 단위로 코드가 있을 것으로 보이나 값은 확인 못 함 | 일반구(수원 4개)는 시군구 코드가 따로 있으나 기관(시)은 하나다. 일반구 복제 32줄을 합칠 규칙이 따로 필요하다 | 규칙으로 정하기 나름 |
| 법원 포함 | 기관코드 체계에 사법부가 있고 법원 소관 부서도 있다. 개별 법원 코드는 미확인이라 확인이 선행돼야 한다 | 불가. 법원은 행정구역이 아니어서 소재지 코드로 대체해야 하고 동일 시군구 안에 여럿이 있을 수 있다 | 가능 |
| 공공기관·지방공기업 포함 | 행정표준 기관코드에 공공기관 유형이 있다(필터 확인). 알리오·클린아이 기관이 모두 들어 있는지는 미확인 | 불가(행정구역이 아님) | 가능. 알리오·클린아이 코드를 별도 칸에 둘 수 있다 |
| 기존 코드와의 연결 | `subRegion`(통계청 코드)과 매핑 표가 따로 필요하다 | 5자리 `subRegion`과 자릿수는 같으나 값 체계가 다르다(법정동 vs 통계청 2018) | 현재 값 유지 |

## 5. 스키마 시사점(사실만)
- `subRegion`은 이름은 같지만 `region`과 같은 코드 체계가 아니다. 시도 자리가 다르고(경기 41/31, 부산 26/21) 법정동코드가 아니다.
- `subRegion`은 기관 번호가 아니라 지도 폴리곤 키라서 서해·검단이 같은 값을 갖는다. 기관 식별자로 쓸 수 없다.
- 서버 ID는 두 종류가 섞여 있다. 시드 25건은 슬러그이고, 나머지는 `new-`+무작위다.

## 6. 이관 메모
- [이관: 기획] "기관 하나 = 번호 하나"의 정의(일반구 32줄, 서해·검단, 법원 본원과 지원)와, 개편 때 옛 번호를 유지할지 새로 부여할지를 정해야 번호 체계를 고를 수 있다.
- [이관: 백엔드] `INSTITUTIONS.INSTITUTION_ID`가 VARCHAR(64)라 후보 A·B의 길이는 충분하다. 번호 칸을 새로 둘지, 기존 ID를 바꿀지는 설계 사안이다.
- [이관: 프런트] `subRegion`은 지도용 키로 유지하고, 번호표와는 별도 칸으로 보는 게 사실관계상 맞다.
