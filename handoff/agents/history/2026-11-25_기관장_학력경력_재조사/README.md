# 기관장 학력·경력 재조사 — 이어 하기 (e4, 2026-11-25)

사용자 지시(11-25): "학력·경력이 각각 3줄 미만인 건은 조사가 잘못된 것으로 보고 웹 조사를 다시 하라."

## 상태
- 11-25 기준 로컬 DB(옛 PC)에서 기관장 387명 중 **364명**이 학력 또는 경력 3줄 미만이었다(둘 다 3줄 미만 271명).
  - 지자체 222, 법원 75, 공공기관 38, 교육청 15, 지방공기업·병원·대학 14.
- 1차 data-auditor 8명(r0~r7)을 띄웠지만, 세션이 끝나며 결과 없이 멈췄다. **입력된 것은 없다.**

## 이 폴더
- `BRIEF2.md`: 조사 규칙.
  - 시작 연도 필수(연도만 가능).
  - 학력은 졸업 연도만 알면 from=to.
  - 끝을 모르는 과거 경력은 넣지 않는다.
  - 정당 관련 말은 쓰지 않는다.
  - 나무위키 단독 값은 넣지 않는다.
- `r0.txt`~`r14.txt`: 법원을 뺀 289명, 20명씩. `c0.txt`~`c3.txt`: 법원장 75명.
  - 각 줄: 기관ID | head_id | 기관 | 이름 | 직위 | 학력 n | 경력 n | 이미 있는 값.
  - **head_id는 옛 PC DB 값이다.** 다른 PC에서는 다를 수 있다. 입력 스크립트는 head_id가 다르면 'headchanged'로 건너뛴다. 다른 PC에서는 명단을 그 PC 8080 기준으로 다시 만드는 편이 안전하다(아래 3단계).
- `fill_apply.js`: 결과 JSON을 8080 API로 넣는다.
  - 사용: `node fill_apply.js <rows.json>`로 시험한 뒤 `--go`.
  - 중복·정당·끝 모름은 건너뛴다.
  - 입력자는 5047192다.
  - 안의 BASE·TODAY 값을 확인한다.
- `pickjson.js`: 에이전트 보고서(md)의 마지막 ```json 블록을 파일로 꺼낸다.

## 다음 한 걸음(다른 PC)
1. 8080·MySQL을 띄운다. 그 PC DB에 기관장 데이터가 있는지 확인한다. 없으면 `kgi-ggreport-web/tools/head-transfer/` 묶음으로 먼저 옮긴다.
2. 학력·경력 '연도만 허용' 서버(b821d0f7 이후)로 떠 있는지 확인한다.
3. 대상을 다시 센다. `/institution-heads`로 각 기관을 받아 `/institutions/{id}/head`의 education·career 길이를 센다. 3줄 미만을 20명씩 나눈다.
4. data-auditor(sonnet)를 묶음마다 하나씩 띄운다(한 번에 8개 안팎). 규칙은 BRIEF2를 쓴다.
5. 결과는 `pickjson.js` → `fill_apply.js`로 넣는다. 그다음 다시 세어 3줄 미만이 얼마나 줄었는지 보고한다.

예상 비용은 에이전트 1명당 약 5만 토큰, 전체 약 100만 토큰이다. 이전 실적으로는 기사 약력에 연도가 없는 경우가 많다. 특히 법원장은 연도가 없어 채우기 어렵다.
