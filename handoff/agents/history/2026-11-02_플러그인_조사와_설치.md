# 플러그인 조사와 설치 (2026-11-02)

> 조사: claude-code-guide 에이전트(공식 문서·공식 마켓플레이스 직접 확인). 설치: 메인(사용자 승인). 출처 URL은 끝에.

## 계기
PC 초기화로 플러그인 설치 목록이 비어(`~/.claude/plugins/installed_plugins.json` = `{}`) 에이전트 정의의 playwright 도구가 동작하지 않았다. 사용자가 "에이전트가 어떤 플러그인 도움을 받는지" 확인을 요청.

## 서브에이전트가 플러그인 기능을 쓰는 방식 (조사 결론)
| 방식 | 결론 |
|---|---|
| 플러그인 MCP 도구 | 에이전트 `tools`에 `mcp__plugin_<plugin>_<server>__*` 형식으로 넣으면 사용 가능(설치·활성 필요). playwright는 `mcp__plugin_playwright_playwright__*` |
| 플러그인 스킬 | `Skill` 도구가 허용되면 호출 가능, 또는 frontmatter `skills:`로 미리 주입. **우리 역할 에이전트는 `tools`를 명시해 Skill이 빠져 있어 못 씀** |
| 플러그인 slash command | 사용자 입력용 — 서브에이전트 직접 실행 불가(추정), main이 실행 |
| 플러그인 hooks | 세션 전체에 자동 적용(역할·읽기 전용 여부와 무관) |
| 플러그인 agents/ | main이 `<plugin>:<name>`으로 직접 호출 가능(자연어 위임·`@agent-…` 멘션) |

## 읽기 전용 원칙과 맞는 대안
- **A. main이 플러그인 실행 → 결과를 지시문으로 전달**(가장 안전)
- **B. 에이전트에게 SKILL.md만 Read로 읽게 함**(지침만, 스킬 안의 Bash·Write는 에이전트 도구 목록 때문에 실행 안 됨)
- E. MCP 도구는 역할별로 필요한 도구만(예: 브라우저 열람·스냅샷·스크린샷)
- 주의: 스킬 도구를 열면 스킬이 쓰기·명령을 포함할 수 있음 → 읽기 전용 역할은 `disallowedTools`에 `Skill` 검토. 훅은 세션 전체에 돈다(security-guidance: Stop 시 diff를 API로 리뷰, impeccable: 편집 후 UI 검사·시작 시 카탈로그 조회·텔레메트리).

## 역할별 추천 (실재 확인분만, 5개를 억지로 채우지 않음)
| 역할 | 추천 | 쓰는 방식 |
|---|---|---|
| planner | feature-dev | 플러그인 에이전트(main 호출) |
| pm | 없음 | — |
| security | security-guidance, claude-security | 훅 / main 명령 |
| qa-verifier | playwright, pr-review-toolkit, typescript-lsp | MCP / 플러그인 에이전트 / LSP |
| design-reviewer | playwright, frontend-design, impeccable(제3자), playground | MCP / main 실행 후 결과 전달 |
| frontend-dev | playwright, typescript-lsp, frontend-design, code-simplifier | MCP / LSP / 플러그인 에이전트 |
| backend-dev | jdtls-lsp(Java 17+ 필요, jdtls 바이너리), pr-review-toolkit, code-simplifier | LSP / 플러그인 에이전트 |
| cleaner | claude-md-management(파일을 쓰므로 main 실행) | main |
| data-auditor | 없음(내장 WebFetch·WebSearch로 충분) | — |
제외: context7(원격 MCP, 폐쇄망 불가), code-review(GitHub·gh 필요), commit-commands(쓰기).

## 설치 결과 (2026-11-02, 사용자 승인 "바로 설치 + 조건부")
- 방법: VSCode 확장 동봉 CLI `…\anthropic.claude-code-2.1.314-win32-x64\resources\native-binary\claude.exe plugin install <이름>@<마켓플레이스> --scope user`(사용자 범위 — 프로젝트 settings.json 불변).
- 설치: playwright, pr-review-toolkit(1.0.1), frontend-design(1.1.1), code-simplifier(1.0.0), feature-dev(1.0.1), security-guidance(2.0.17) — `claude-plugins-official` / impeccable(4.8.0) — 제3자 마켓플레이스 `pbakaus/impeccable` 추가 후. 모두 enabled.
- impeccable 조건: 사용자 환경변수 `DO_NOT_TRACK=1` 설정(텔레메트리 끔).
- security-guidance: 작업 종료(Stop)마다 diff 리뷰로 비용 증가 — 사용자 승인. 끄려면 `ENABLE_STOP_REVIEW=0`.
- 나중에: typescript-lsp, jdtls-lsp(언어 서버 별도 설치), claude-security.
- 적용: 세션에서 `/reload-plugins` 또는 새 세션. playwright MCP는 `npx @playwright/mcp@latest`(첫 실행 시 패키지·브라우저 내려받기 가능, Node 필요).

## 미확인
`skills:`에 플러그인 스킬 이름 형식(추정 `<plugin>:<skill>`), 서브에이전트의 슬래시 명령 실행, 플러그인 훅의 서브에이전트 도구 호출 적용 여부, playwright 첫 실행 브라우저 다운로드, jdtls의 Java 8 프로젝트 분석 설정.
