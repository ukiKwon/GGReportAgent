`npx impeccable detect portfolio/index.html` 실측 **33건**. 차이는 훅이
`maxFindings: 5`로 끊어 보고하기 때문이고, CLI에서만 보이던 것이 **radius 1건 ·
kicker 2건**이었다. 사용자가 ⓐ안 + kicker·radius까지 함께 처리하도록 확정했다.

**고친 것**

  색이라 구분에 기여하지 않으면서 탭처럼만 읽혔다. 강조는 단계 번호(`b`)가 진다.
- kicker 2건 — `OVERVIEW`·`TECH` 라벨 삭제. **`PART 1~4`는 남겼다** — 순서 정보를
  담고 있고 검출에도 걸리지 않는다(라벨 6개 중 2개만 검출된 이유가 이것으로 보인다).
- radius 1건 — 태그 `999px` → `14px`(DESIGN.md `rounded.lg`). 태그 높이가 22px라
  브라우저가 어차피 절반으로 클램프해 **화면상 같은 알약**이다.

**예외로 둔 것** — 색 21건·폰트 6건. `DESIGN.md`는 다크 대시보드의 디자인 시스템이고
`portfolio/index.html`은 8/5에 따로 만든 **라이트 테마 별개 문서**라, 서로 다른
산출물에 같은 팔레트를 댄 결과지 드리프트가 아니다. 사용자 확정으로
**파일 한정 value 예외**만 등록했다:

```

hook-admin.mjs ignore-value design-system-font-size "*" --file "portfolio/index.html"
```

`ignore-file`/`ignore-rule`은 **쓰지 않았다**(훅 정책: 사용자 승인 없이 금지, 그리고
파일 전체를 영구히 침묵시키므로 실제 UI 문서에는 과하다). 결과 **검출 0건**.
`em-dash-overuse` 1건은 advisory(실패 아님)라 한국어 본문을 건드리지 않았다.
