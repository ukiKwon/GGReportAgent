# 2026-09-07 작업 요약

## Session 18:32 — uploader 내부망 WebLogic 기동 검증 (외부망 지원)

### 목표

외부망에서 만든 `uploader/`(Spring Boot 2.7.18 WAR)를 **내부망 로컬 환경의
Eclipse Photon(4.8.0) + WebLogic 12.2.1.4** 에서 기동시키는 것. 사용자가 내부망에서
작업하고, 이 세션은 외부망에서 진단·산출물 생성·안내를 담당했다.

**결과: 기동 검증 성공.** 화면이 `ORA-00942`(테이블 없음)로 끝나는 지점까지 도달했고,
그것은 SQL이 실제로 Oracle에 도달했다는 뜻이라 그 앞의 모든 배선(Servlet API ·
JNDI DataSource · MyBatis Oracle 방언 판정 · Spring MVC)이 살아 있음이 증명됐다.
남은 것은 DBA의 테이블 생성뿐이다.

### 겪은 문제와 원인 (시간순 — 다음에 같은 길을 안 돌게 하려고 전부 남긴다)

| # | 증상 | 진짜 원인 | 조치 |
|---|---|---|---|
| 1 | `javax.servlet.ServletException cannot be resolved` (Eclipse) | 서블릿 API jar를 **일부러** `WEB-INF/lib`에 안 넣었다(WebLogic 것과 두 벌이 되면 배포가 깨진다) | **Targeted Runtimes → WebLogic 12.2.1** 체크 |
| 2 | (외부망 IntelliJ) `try-with-resources is not supported in -source 1.5` | IntelliJ가 pom을 안 읽음 | Maven 프로젝트로 연결 + Reload |
| 3 | 내부망에 `.m2`가 아예 없음 | 폐쇄망 | **Maven 경로 포기 → WTP 사본 반입으로 전환** |
| 4 | `Publish was cancelled. Referenced file contains errors ... javaee_5.xsd` | 폐쇄망이라 Eclipse가 `weblogic.xml`/`web.xml`의 **스키마 URL을 못 받아옴** → WTP가 발행을 막음 | 프로젝트 **Properties → Validation** 에서 `XML Validator`·`XML Schema Validator` 해제 |
| 5 | `ORA-12514 TNS:listener does not currently know of service` | DataSource URL의 **서비스명 자리에 호스트명**이 들어가 있었다 | 서비스명 `DSKGIT01`로 교정 |
| 6 | `Driver oracle.jdbc.OracleDriver claims to not accept jdbcUrl, jdbc:derby:memory` | ⚠️ **사용자가 `config-envs/local`을 도메인 config로 복사했다.** 그 파일의 `spring.autoconfigure.exclude=...JndiDataSourceAutoConfiguration` 이 **JNDI를 꺼 버렸고**, 거기서 `spring.datasource.url` 을 지우자 Spring Boot가 **WebLogic 번들 Derby로 폴백** | `config-envs/prod` 기반 내용으로 **파일 통째 교체** |
| 7 | `Failed to look up JNDI DataSource 'java:comp/env/jdbc/uploaderDS'` · `didn't find subcontext 'jdbc'` | 🔴 **DataSource가 서버에 배포되지 않아 JNDI 트리에 `jdbc` 폴더 자체가 없었다.** `config.xml`에 정의와 `<target>`은 있었는데도 바인딩이 안 돼 있었다 | DataSource **삭제 후 재생성**, 마법사 마지막 화면에서 **Targets에 AdminServer 체크** → Activate Changes → 재기동 |
| 8 | `http://localhost:7001/uploader` 빈 화면 | 대시보드가 `@GetMapping("/")` 라 **끝 슬래시 필요** | `/uploader/` 로 접속 |

**⚠️ 7번에서 가장 오래 돌았다.** `web.xml`·`weblogic.xml`·`application.properties`를
차례로 의심하며 `<resource-description>` 매핑까지 추가했는데, **셋 다 처음부터 정상이었다.**
`java:comp/env` 조회가 실패하면 **앱 서술자보다 JNDI 트리를 먼저 봐야 한다** —
트리에 `jdbc` 폴더가 없으면 그건 앱 문제가 아니다. (→ NEXT 항목 25-⑧에 문서화 과제로 등록)

### 판단·결정

- **자동 재분류(`ReclassificationJob`)는 껐다.** `reclassification.cron=` 을 비워
  `ReclassificationTrigger`가 예약을 걸지 않게 했다. 그러면 `DEPLOY.md` 3번
  (CommonJ Work Manager `uploaderTM` 등록)과 A→B→C 시행착오를 통째로 건너뛴다.
  기동 검증이 목적이라 변수를 줄이는 쪽을 택했다. **차후 과제**(NEXT 25-②).
  함께 `web.xml`의 `timer/uploaderTM` `resource-ref`도 **임시 주석 처리**했다
  (당시 ENC 구성 실패 원인 후보였다 — 결과적으로 무관했으므로 되돌려도 된다).
- **`upload.base-dir=C:/uploader-local`** (Windows 내부망 로컬).
  ⚠️ `.properties`에서 역슬래시는 이스케이프라 `C:\uploader-local`로 적으면
  `\u`가 유니코드 이스케이프로 읽혀 **기동이 실패**한다. 슬래시를 쓴다.
- **DDL의 `NUMBER(19)` → `NUMBER(18)`** (사용자 사내 DB 규격). ID는 Java `Long`이라
  이론상 19자리까지 되지만 시퀀스가 1부터 증가하므로 자릿수는 실사용에서 무의미하다.
- **`UPLOADED_FILE` 컬럼 순서 재배치** — 탐색 기준값을 앞으로, 가장 긴
  `STORED_PATH`(1000자)를 맨 뒤로:
  `ID, CATEGORY, FILE_YEAR, STATUS, INSTITUTION_NAME, ORIGINAL_NAME, UPLOADED_AT, CLASSIFIED_AT, STORED_PATH`.
  앱은 컬럼을 **이름으로만** 다루므로(resultMap 이름 매핑 + INSERT 컬럼 목록 명시)
  순서 변경은 무해함을 코드로 확인했다. `INSTITUTION`은 그대로 둔다.
- **`uploader/`에 한해 `main`이 `weblogic-java-migration`의 상위집합**임을 확인했다.
  `git diff main HEAD -- uploader/` = **2200줄 삭제 / 60줄 추가**이고, 그 60줄은 전부
  *"Oracle DDL이 아직 없다"·"스케줄러를 WebLogic에서 쓰면 안 된다"* 같은 **미완성 고지**와
  **주석 처리된 Oracle SQL**이다. `main`은 그 경고가 가리키던 일을 실제로 해서
  (`43dc186` Oracle DDL + Mapper 방언 분기, `9162317` DEPLOY.md, `1ee71c4` WTP 스크립트)
  경고가 필요 없어진 상태다. → **반입물은 `main` 기준으로 만들었다.**
