   SQLite 가 `UNIQUE(BID_CASE_ID, TEAM)` 인덱스로 찾아 그렇게 준 것이고(실측: 삽입
   순서인 영업·전산·예산이 **아니다**) Oracle 은 보장하지 않는다. `ORDER BY TEAM` 명시.
   `rowid` 계열의 9번째 자리다.

### 주요 결정

- **골든 URL 은 이미 퍼센트 인코딩돼 있다.** `GoldenRunner` 가 문자열을 넘기면 MockMvc 가
  URI 템플릿으로 보고 다시 인코딩해 `%EC`→`%25EC` 가 된다. 증상이 "파일 없음 404" 라
  원인을 컨트롤러에서 찾게 된다. `URI.create()` 로 고정.
- **테스트 컨텍스트는 하나여야 한다**(`@AppTest`). 정본 DDL 이 멱등하지 않고 H2 가
  `DB_CLOSE_DELAY=-1` 이라, 컨텍스트가 둘 뜨면 `001` 이 두 번 돌아 죽는다.
- **`ACTIVE_INSTITUTION_ID` 단일 컬럼 UNIQUE** 로 "한 기관에 실행 하나"를 지킨다.
  복합 UNIQUE 는 안 된다 — Oracle 이 일부만 NULL 인 복합 키를 색인해 **끝난 실행끼리
  충돌**한다. 두 DB 의 NULL 취급이 갈리는 자리를 피한 설계다(MySQL 실측 확인).
- **`commonj.work.*` 를 컴파일 의존성으로 넣지 않는다.** 오프라인 빌드가 합격 기준인데
  `.m2` 에 없다 → JNDI 객체를 리플렉션으로 부르고 `Work` 는 동적 프록시로 만든다.
- **아직 못 옮긴 노드는 소리 내어 실패한다.** 빈 구현으로 통과시키면 실행이 끝까지 돌아
  화면에는 **정상 완료로 보이고**, 아무도 배점표가 비었다는 걸 모른 채 제출일을 맞는다.
- **uploader JSON API 재정의** — 2개 → 8개(CloudDisk 파일 API + HMAC 헤더 4 + `CHUNK`
  봉투). 화면 14개는 그대로. 분석은 `docs/uploader_json_api_재정의_gap분석.md`.
