### 4. 단계 1 — `kgi-ggreport-web` 신설 (`fb5f89c`, `15bbcc6`, `0c028ec`)

**좌표(사용자 확정)**: groupId `com.kbstar` / artifactId `kgi-ggreport-web` /
패키지 `com.kbstar.kgi.ggreport.web`.
사용자가 준 `com.kbstar.kgi-ggreport-web`은 **Java 패키지명에 하이픈을 쓸 수 없어**
artifactId·폴더명만 하이픈 표기를 유지하고 패키지는 점으로 옮겼다.

**Task 1.1 + 1.2 (`fb5f89c`)** — 실기동으로 "끝난 모습"을 확인했다:
`GET /` → 200(`static/index.html`), `js`·`geo`·`vendor` → 200,
디자인 실험본 `/index_2.0_impec.html` → **404**(제외가 실제로 걸림).

계획과 **다르게 한 것 3건**:
1. **화면을 복사하지 않는다.** `pom.xml` `<resources>`가 빌드할 때 `../frontend`를
   가져온다. 복사본을 두면 원본과 갈라지는데, 이관 검증이 "같은 입력 → 같은 출력"이라
   화면이 두 벌이 되면 무엇과 비교하는지가 흐려진다.
2. **`web.xml`에 필터를 선언하지 않는다.** Boot가 프로그램적으로 등록하며
   `asyncSupported` 기본값이 이미 `true`라 요구는 충족되고, 다시 선언하면 **필터가
   두 번 돈다.** `resource-ref` 2건(`jdbc/ggreportDS`·`wm/ggreportWM`)만 둔다.
   `metadata-complete="false"` 명시(`true`면 `SpringBootServletInitializer`가 안 돈다).
3. **Thymeleaf 미포함.** 화면이 순수 정적이라 템플릿 엔진이 필요 없다(uploader와 갈림).

`dependencies.txt`는 손 목록이 아니라 `mvn dependency:list` 산출물 —
**반입 54건 / 제외 1건**(`mysql-connector-j`). 합격 기준은 **`mvn -o` 통과**.

**Task 1.3 (`15bbcc6`)** — DDL 2벌, **11테이블**(registry 7 + 검색 4).
`ORCH_RUN`/`ORCH_STEP`은 **단계 4로 미뤘다**(사용자 확정 — 신규 설계라 성격이 다르다).
Oracle Text `CONTEXT` 인덱스는 문의 3 회신 후 `002_`로(테이블 구조는 1안/2안 동일).
- ⚠️ **설계 §5-(A)가 실행 불가능했다** → `574b1c7`로 설계 원문도 개정.
  "`NOT NULL` 유지 + INSERT 시 명시값"은 성립하지 않는다 — Oracle이 `''`를 NULL로
  바꾸므로 **최초 INSERT가 반드시 실패한다.** NULL 허용 + Mapper `null→""` 정규화로 변경.
- ⚠️ **외래키가 실제로 강제된다.** `server/db.py`는 `PRAGMA foreign_keys`를 켜지 않아
  현재 SQLite에서는 선언만 돼 있다. **단계 2 골든 비교에서 지켜볼 것.**
- 예약어 회피 3건: `files.size`→`FILE_SIZE`(**SIZE는 Oracle 예약어**),
  `meta.key`/`value`→`META_KEY`/`META_VALUE`, `chunks.text`→`CHUNK_TEXT`.
- ⚠️ **`messages.model`을 놓칠 뻔했다** — `SCHEMA`가 아니라 `MESSAGE_MIGRATIONS`에만
  있다. **실제 스키마는 SCHEMA + MIGRATIONS다.**
- 검증: MySQL 미러 **2회 연속 적용 성공**(테이블 11·인덱스 9, 멱등).
  **Oracle 정본은 문법만 확인**(H2 `MODE=Oracle`) — 실검증은 내부망에서 처음.

**IntelliJ 실행 경로 (`b80f831`)** — 사용자의 실제 작업 계획이
"IntelliJ(외부망)에서 통합 화면을 로컬 확인, DB는 MySQL"이라 그 경로를 문서화하고
걸릴 문제를 미리 막았다. `config-envs/out-local`에
`spring.web.resources.static-locations=file:../frontend/,classpath:/static/` 추가 —
IntelliJ 자체 빌드는 모듈 밖 경로(`../frontend`)를 복사하지 못할 수 있어 **화면이 통째로
404가 될 수 있다.** 덤으로 `frontend/` 수정이 **재빌드 없이 반영**된다.
⚠️ **Working directory를 `kgi-ggreport-web`으로 둬야 한다**(세션 중 실제로 걸렸다).

**Task 1.4 (`0c028ec`)** — 골든 비교 하네스 4클래스 + 자체 테스트 29건, 모듈 **31건 통과**.
- ⚠️ **실제 결함을 잡았다: 골든 34건 중 10건이 `X-User-Id` 헤더를 들고 있다**
  (결재 시나리오 15~24번, dave/boss). 처음 만든 로더가 `request.headers`를 무시했다.
  그대로 뒀다면 **단계 2 후반이 전부 틀린 행위자로 돌아** `assignee`/`approver`가
  어긋났을 것이다. 헤더 지원 + 회귀 테스트로 고정.
- **`Accept` 강제도 테스트가 잡았다** — 강요하면 JSON 아닌 응답이 실제 동작과 무관하게
  406을 받는다. `capture.py`는 지정하지 않는다.
- 정한 것: **배열 순서는 비교, 객체 키 순서는 비교하지 않는다**(pydantic ↔ POJO 필드
  순서 차이로 실패시키면 진짜 차이가 소음에 묻힌다).
- **하네스 자신을 스텁 컨트롤러로 검증**했다 — 없으면 "테스트 통과"와 "러너가 아무것도
  안 봄"이 구분되지 않는다.
