### git 처리 — 브랜치 착오와 정정 (중요)

세션 시작 시점에 리포가 **`main`이 아니라 `feature/dashboard-enhancements`에 체크아웃돼
있었다**(다른 세션의 dashboard 2차 확장 작업 브랜치, 커밋 4개 `8aba368`~`0450831`).
이를 모르고 커밋해서 강남 산출물이 그 기능 브랜치 위에 얹혔다(`3c756d0`).

- 사용자 선택으로 **main으로 이동**: `main` 체크아웃 → `3c756d0` cherry-pick(`a6d2896`) →
  `git branch -f feature/dashboard-enhancements 0450831`로 그 브랜치에서 내 커밋만 제거해
  **원래 상태로 복원**. dashboard 커밋 4개는 그대로 보존됨.
- **push는 보류**(사용자 선택). 이유: `main`이 `origin/main`보다 **5커밋 앞서** 있는데
  그중 4개가 다른 세션의 dashboard 작업이라, push하면 이번 세션 범위를 벗어난 커밋이
  같이 원격에 올라간다. "마무리는 이번 세션 작업분만" 지시와 충돌하므로 보류.
- 세션 종료 시 HEAD는 **`main`**(강남 파일이 디스크에 존재하는 상태). 다른 세션이
  dashboard 작업을 재개하려면 `feature/dashboard-enhancements`를 다시 체크아웃해야 한다.

→ **교훈**: 배치 작업 커밋 전 `git branch --show-current`로 브랜치를 먼저 확인할 것.
이 리포는 여러 세션이 같은 워킹트리를 공유하므로 HEAD가 바뀌어 있을 수 있다.
