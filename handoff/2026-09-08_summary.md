### 전체 머지를 포기한 이유 (시도해서 알아낸 것)

`git merge --no-commit --no-ff main` 을 돌려 본 결과 **충돌 23건**이고,
전부 **`add/add`** 였다 — 두 브랜치가 같은 파일을 **각자 독립적으로 추가**해서
공통 조상이 없다는 뜻이다(PR #2·#3이 `main`에 따로 들어오며 생긴 구조).

**서브트리별로 최신인 쪽이 정반대**라 기계적 해소가 불가능했다:

| 대상 | 충돌 | 최신 | 근거 |
|---|---|---|---|
| `kgi-ggreport-web/` | 16건 | **이 브랜치** | `main`은 `bb4547c`(PR #2) **한 번**만 건드린 초기 스냅샷. 이 브랜치는 merge-base 이후 **30커밋**. 파일 242 vs 216, `InstitutionController` 230 vs 126줄 |

| `docs/tools/md2pdf.py` · `docs/이관문의서_WebLogic_확인사항.md` | 2건 | 개별 확인 | `main`에 실제 개선 `b88be6d` 있음 |

🔴 **`kgi-ggreport-web/`을 `main` 쪽으로 받으면 단계 5-B 작업 30커밋이 통째로 되돌아간다.**
사용자에게 위 근거를 제시하고 **"uploader만 가져오기"** 로 확정했다.
→ 머지는 `git merge --abort` 로 취소했고, 작업 트리는 원상복구됐다.

## Session 09:11 — 후속 ⑥⑦⑧⑨ (문서·gitignore)

전날 기동 검증에서 **실제로 사람을 붙잡았던 함정 3개**를 문서에 박았다. 어제 세션이
기억으로만 갖고 있던 것들이라, 다음 사람(또는 다음 세션)이 같은 반나절을 쓰지 않게 하는 게 목적이다.

### ⑨ `.gitignore`

`dist/`(export_wtp가 만드는 40MB급 반입 패키지)와 `.worktrees/`를 추가했다.
둘 다 `main`에는 이미 있고 이 브랜치에만 없어서 `git status`에 계속 떠 있었다.

### ⑥ 폐쇄망 XML 검증 → `DEPLOY.md` **7-B** 신설 + `tools/README-WTP.md` §2 3번 단계

`Publish was cancelled. Referenced file contains errors (…javaee_5.xsd)` 의 정체와 조치
(**Properties → Validation → `XML Validator`·`XML Schema Validator` 해제**).
WebLogic은 자기 파서로 읽으므로 **Eclipse만의 문제**라는 점, 이걸 꺼도
**well-formed 오류는 그대로 잡힌다**는 점을 함께 적었다(안전망이 사라지는 게 아니다).
README-WTP는 **처음 여는 절차의 3번**으로 승격시켰다 — 사후 문제해결이 아니라
안 하면 반드시 걸리는 단계라서다.

### ⑦ `config-envs` 혼동 → `DEPLOY.md` **4번**에 🔴 경고 + `README-WTP.md` §1

핵심은 `local`·`dev`·`stg`의
`spring.autoconfigure.exclude=…JndiDataSourceAutoConfiguration` 한 줄이
**`jndi-name`을 무력화한다**는 것. **증상이 원인을 전혀 안 가리킨다**는 점을 명시했다
(JNDI가 꺼진 채 `url`까지 없으면 WebLogic 번들 Derby로 폴백해
`… claims to not accept jdbcUrl, jdbc:derby:memory…`).
같은 자리에 **`config/`의 실제 위치가 `<DOMAIN_HOME>\config\`**(= `config.xml` 옆)라는 것과,
**Windows 역슬래시 함정**(`C:\uploader-local` → `\u`가 유니코드 이스케이프로 읽혀
`Malformed \uxxxx encoding`)도 적었다. 부록에 이미 비슷한 말이 있었지만 **문서 맨 끝
"연습할 때"** 여서 실제로 실수하는 자리(4번)에 닿지 않았다 — 그래서 4번으로 옮겨 왔다.

### ⑧ 진단 순서 → `DEPLOY.md` **7-A** 신설

*"`java:comp/env` 조회가 실패하면 앱 서술자부터 뒤지지 마라."*
**1) JNDI 트리 → 2) DataSource(Testing 행·Targets·Activate·`config.xml`의 `<target>`)
→ 3) 그제서야 `web.xml`/`weblogic.xml` 매핑** 순서로 적었다.
트리에 `jdbc` 폴더가 없으면 **앱은 무죄**라는 판정을 표로 박아 뒀다.
`§7` 표에도 두 행(JNDI 예외 → 7-A로, derby 오류 → 4번으로)을 연결했다.
