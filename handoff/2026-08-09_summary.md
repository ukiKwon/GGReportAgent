**증상**: 서버 모드에서 대시보드의 '기관 추가' 버튼을 누르면
`dashboard/js/app.js`가 "서버 모드에서는 기관 추가가 아직 지원되지 않습니다 —
CSV 반입을 사용하세요"라는 alert만 띄우고 끝났다. 기관을 한 건 늘리려면
CSV를 만들어 반입하는 길밖에 없었다.

**원인**: 기관 생성 API가 아예 없었다. `backend/routers/institutions.py`에는
GET(목록·상세)·PUT(부분 갱신)·`POST /import`(CSV)만 있었다.

#### 서버

- `POST /institutions` 신설(201). 본문은 기존 `InstitutionImportRow` 재사용
  (`name_ko` 필수 + region_code·type·term·last_bid·contract_end 선택).
- `backend/repository.py`에 `create_institution()` 신설. 기존 `upsert_institution`과
  INSERT 부분을 `_insert_institution()`으로 공유해서 **id 발급 규칙이 한 곳**이다
  (`new-` + `secrets.token_hex(4)`).
  - NEXT.md가 "먼저 정해야 한다"고 적어둔 institution_id 생성 규칙은 **이미 존재했다**
    — CSV 반입이 쓰던 그 규칙을 그대로 재사용했다. 새로 정할 것이 없었다.
  - 이름을 id로 쓰지 않는 이유: 한글·공백·개명 문제를 전부 떠안게 된다.
- **이름 중복은 409**(사용자 확정). `POST /import`가 같은 이름을 조용히 upsert하는 것과
  **일부러 다르다** — 같은 표를 다시 올리는 것은 정상 동작이지만, 사람이 화면에서 같은
  이름을 다시 누르는 것은 거의 언제나 오타나 중복 등록이다. 409일 때 기존 행의 값을
  덮지 않는 것도 테스트로 고정했다.
- 이름 없음 → 422(pydantic), 공백뿐인 이름 → **400**. 공백만 허용하면 이름으로 찾을 수
  없는 행이 생기고, `find_id_by_name` 기반의 중복 판정·반입 매칭이 전부 무의미해진다.
