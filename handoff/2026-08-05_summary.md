### 1. INSTALL.md를 실제 인스턴스(m7i-flex.large) 기준으로 교정 (main `df9e0a9`)

사용자가 EC2를 **t3.small → m7i-flex.large**로 올렸다. 그 과정에서 두 번 교정했다.

- **t3.small은 불가**임을 먼저 알렸다 — RAM 2GB에 `llama3.1:8b`(실행 시 5~6GB)는 OOM으로
  죽는다. "느려도 감수" 범위가 아니다. 다만 시연 8개 화면 중 **6개는 LLM이 필요 없고**,
  대화 탭은 계획 F 후속(G1)에서 실패 사유를 화면에 띄우게 해둬서 깨지지 않는다는 점도 함께.
- **m7i-flex.large(2 vCPU/8GB)로는 RAM 벽은 넘지만 CPU가 병목** — 8b는 답변 1건에 수 분
  예상. 그래서 기본 모델을 **`llama3.2:3b`(~2GB)** 로 내렸다(사용자 확정).
- 문서에 **"RAM=올라가는가 / vCPU=쓸 만한가"** 두 벽을 분리해 서술하고, 8b·1b·qwen 대안과
  c7i 원안(4배 요금)을 선택지로 남겼다. 스토리지 40→20GB, 비용 문단($0.4/h·월 $250 →
  $0.10/h·월 $70)도 실제 유형에 맞췄다.
- **문서를 코드와 대조해 사실오류 3건도 함께 고쳤다**: ①pytest 기준선 478 → **526**(실측)
  ②지식 탭 503 조치에 "앱 재시작" 누락 — 데모 인덱스는 `build_demo_index()`가 기동 때
  운영 인덱스를 **복사**해 만들므로 4단계 ②만으론 안 바뀐다 ③deps 확인 import 목록에
  `langchain_openai` 누락(없으면 화면은 뜨는데 대화만 죽는다).
- 검토에서 확인하고 **문제없던 것**: 4단계 ①②③ 순서, `--no-serve`·`--port`·`--reset`·
  `reindex --no-embed` 옵션 실재, `_env()` 폴백 설명, `127.0.0.1` 바인딩 설명, nginx 스톡
  `default_server` 교체 이유, SQLite FTS5 trigram 3.34+ 요건.

### Oracle 전환에서 실제로 깨지는 지점 (스키마를 읽어 찾은 것)

- **빈 문자열 = NULL.** `tasks.draft_content TEXT NOT NULL DEFAULT ''`가 Oracle에서 그대로는
  제약 위반이고, 의미도 달라진다(Python이 `""`로 판단하던 자리에서 Java는 `null`을 받는다).
  → DB 기본값 없이 앱이 항상 명시값 INSERT + Mapper에서 `null → ""` 정규화로 JSON 계약 유지.
- **CLOB 필요.** `draft_content`·`messages.content`·`chat_messages.content`·색인 청크 본문은
  4000바이트를 넘길 수 있다. 대가로 등호비교·`ORDER BY`/`DISTINCT` 제약이 붙는다.
- **날짜는 `VARCHAR2`로 1:1 이관**(현재 전부 ISO 문자열, 타입 승격하면 화면 표시가 바뀐다).
- `backend/db.py`의 기동시 `ALTER TABLE` 마이그레이션 딕셔너리는 폐기 — 최종 DDL 정본 +
  번호 붙은 스크립트로 대체(폐쇄망 DBA 절차와도 맞는다).
