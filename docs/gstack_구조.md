3. **프리앰블** — 모든 스킬이 시작 시 브랜치·저장소 모드·세션 종류·설정을 셸로 읽어 동작을 바꾼다.

## 3. 파이프라인 (6단계 · 32개)

번호는 장식이 아니라 실제 실행 순서다 — 발상에서 배포 후 문서까지 한 방향으로 흐른다.

### 01. 발상 · 기획

| 스킬 | 설명 |
| --- | --- |
| `/office-hours` | YC 오피스아워. 창업 모드(압박 질문 6개) / 빌더 모드(디자인 씽킹). 설계 문서 저장 |
| `/spec` | 5단계로 정밀 스펙 작성 → 이슈 등록 → 새 워크트리에 에이전트 투입. 나중에 `/ship`이 머지 시 그 이슈를 닫음 |

- **`weblogic-java-migration` 브랜치(실제 코드)** — `/plan-eng-review` → `/review` → `/cso`

  웹·iOS·배포 계열은 이 저장소와 무관하다.
- **⚠️ 중복 주의** — `/context-save`·`/context-restore`는 이 저장소의 `handoff/NEXT.md`
  체계와 정확히 같은 일을 한다. 둘을 같이 돌리면 이월 기억이 두 군데로 갈라지므로
  **하나만 쓰는 것이 낫다.** (이 저장소는 `handoff/` 체계를 이미 `CLAUDE.md`에 규정해 두었다.)
