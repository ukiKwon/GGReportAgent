## ② 스키마

```python
class ScoringCriterion(BaseModel):
    category: str
    item: str
    score: int
    description: str | None = None
    level: int | None = None   # 1=계(총계 행) · 2=대분류 · 3=세부항목 · None=단층(계층 없음)
```

- **선택적(None 허용)이어야 하는 이유 셋**: ⓵ 기존 `rfp_scoring.json`·아카이브
  사본이 그대로 유효해야 한다(v1 파일을 고쳐 쓰지 않는다 — coverage_map v2 선례).
  ⓶ `.claude/skills/rfp-locate`의 **사람 경로**가 같은 규격을 쓴다 — 사람이 레벨
  판정을 생략해도 규격 위반이 아니어야 한다. ⓷ 단층 배점표(계층 없는 공고문)가
  실제로 존재한다.
- `rfp_scoring.json` **파일에는 전체 계층을 그대로 저장**한다(레벨 포함) —
  원문 정보를 버리지 않는다.

## ③ `scoring_consistency()` — 레벨별 합산

레벨 그룹(None은 '단층' 그룹)별로 합산해 **어느 한 그룹이라도 총점과 일치하면
통과**. 모두 어긋나면 그룹별 합계를 열거해 경고한다.

- 기존 평면 파일 = 그룹이 '단층' 하나 → 현행과 동일하게 동작(회귀 없음).
- 9b 산출(계 100 / 대분류 합 100 / 세부 합 100) → 세 그룹 모두 일치 → 통과(오탐 해소).
- 한 레벨이 우연히 총점과 맞는 조작을 놓칠 수 있다 — 이 규칙은 휴리스틱 방어이고
  5·8단계 사람 승인이 최종 방어라는 기존 전제(항목 5 실측 결론) 그대로다.

## ④ 하류 소비처 — 대표 레벨 필터 `main_criteria()`

`content_writer`(항목당 제안 섹션)·`verification`(항목당 커버리지 매칭)·`pptx`가
계층 목록을 그대로 받으면 **'계' 행에도 섹션이 생기고 같은 내용이 레벨 수만큼
중복**된다. 새 헬퍼 `main_criteria(criteria)`가 대표 레벨만 남긴다:

- 규칙: level 1(총계 행) 제외 → level 2가 있으면 level 2만 → 없으면 level 3만 →
  레벨이 아예 없으면 전부(현행).
- **적용 지점은 상태 주입 두 곳뿐**: `rfp_extract_node`의 반환 `scoring_table`,
  `rfp_analysis`의 파일→상태 적재. 하류 노드·화면·API는 무수정.
  (파일·coverage-map API·배점표 매핑 화면은 전체 계층을 그대로 다룬다 — 표시가
  계층을 보여주는 것은 정보이지 오류가 아니다.)

## ⑤ 프롬프트

`SCORING_PROMPT`에 계층 안내를 추가한다 — 배점표가 계/대분류/세부 계층일 수
있고, 각 행에 level(1/2/3)을 판정해 담되 **계층이 없으면 level을 비우라**고
지시한다. "원문에 없는 항목·배점을 만들지 마라"는 기존 지시는 유지.
