# 사업계획 수집 요청

메뉴 위치: 시스템 관리 › 사업계획 수집 요청(개발부서 처리 화면). 영업부서가 요청을 내는 쪽은 '기관 사업계획' 화면 규칙을 본다. 공통 규칙은 `00_공통.md`. 초판 2026-11-27(planner C 묶음).

## 목적·누가 쓰나
- **영업부서의 [수집 요청]이 전산 담당에게 목록·알림으로 온다. 이 처리 화면에서 중복을 빼고 수집을 돌린다** (출처: Q-2026-11-17-47)
- **개발부서 처리 화면에서 기관 단위로 묶어 보고, 목록을 CSV로 내려받고(사번 없음), 수집 중 표시와 제외·실패 사유를 다룬다** (출처: NEXT 56, 사용자 11-17 결정)

## 보는 범위·권한
- **[수집 실행]은 전산팀 전원이 누를 수 있다** (출처: Q-2026-11-17-54)
- **전산팀은 다른 곳에서는 보기 전용이지만, 사업계획 수집 요청 처리는 할 수 있다** (출처: Q-2026-11-19-51)
- **목록을 밖으로 가져갈 때는 전산팀장이 직접 내려받는다** — 목록에는 기관명·기관ID·홈페이지 주소뿐이다 (출처: Q-2026-11-20-61 → Q-2026-11-20-66)
- **결과 반입은 최종적으로 RPA가 사람 없이 한다. 그 전까지는 개발부서 전산팀 담당자가 [반입]을 누른다** (출처: Q-2026-11-20-62)
- **자동 반입 기록의 '누가'는 로그인할 수 없는 잠긴 '시스템' 계정으로 남긴다** (출처: Q-2026-11-20-67)

## 화면 구성·표시 규칙
- **반입 파일의 '수집자' 칸에는 사번이 아니라 수집 프로그램 이름(예: plan-collector/1.0)을 넣는다. '누가'는 업로드한 관리자 사번으로 기록한다** (출처: Q-2026-11-16-09)

## 동작·흐름 규칙
- **[실행]이 인터넷 쪽 수집 프로그램을 직접 부르는 것은 사업계획 수집만의 예외이고, 인터넷 PC 시험용이다. 내부망에서는 꺼 둔다. 공고 찾기는 지금처럼 '미리 돌려두고 들여오기'다** (출처: Q-2026-11-17-48)
- **밖으로 보내는 값은 기관 ID와 이름이다** — 사업계획이 빠진 기관 목록이라 관심 기관이 드러날 걱정은 없다 (출처: Q-2026-11-17-47·Q-2026-11-17-52)
- **최근에 자료를 받은 기관이라도 요청은 실행한다. 이전 출처의 메인 도메인을 함께 기록한다** (출처: Q-2026-11-17-47)
- **요청은 새 자료가 들어오면 자동으로 끝난다** (출처: Q-2026-11-17-55)
- **반입되면 자동으로 '반영됨'이 되고, 요청자에게 쪽지가 간다** (출처: NEXT 56, 사용자 11-17 결정)
- **반출 주기는 주 1회 정기(목요일)이고, 필요하면 수시로 한다** (출처: Q-2026-11-20-60)
- **uploader와 이 시스템은 같은 내부망에서 같은 폴더 경로를 쓴다. 경로 이름은 아직 정하지 않았다** (출처: Q-2026-11-20-64)
- **사업계획을 한 번 못 찾으면 바로 그 기관 관련 뉴스 정리로 넘어간다** — 기관 특성상 사업계획이 없을 수 있다 (출처: Q-2026-11-20-63, 결정 모음 U1 사용자 11-24)
- **뉴스는 기관당 최근 1년·최대 10건, 분야는 금고·재정·예산·주요사업·기관장 동정이다** (출처: 결정 모음 U2 사용자 11-24)
- **뉴스는 제목·언론사·보도일·링크·직접 쓴 요약(300자·3줄)만 저장한다. 기사 본문은 저장하지 않는다** (출처: 결정 모음 U3 사용자 11-24)
- **뉴스로 채운 기관도 '사업계획 없는 기관' 목록에 남긴다. 정기 수집에서 다시 찾는 것은 뉴스 반입 3개월 뒤다(급하면 수시 요청)** (출처: 결정 모음 U6 사용자 11-24; 장부 Q-2026-11-24-72)
- **uploader에서 CSV를 올리는 PC를 제한하지 않는다(올리는 PC가 아직 정해지지 않음). 올린 기록(영수증)은 1년 보관한다** (출처: 결정 모음 U4·U5 사용자 11-24; 장부 Q-2026-11-24-54)
