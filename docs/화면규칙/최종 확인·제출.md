# 최종 확인·제출

메뉴 위치: 제안서 작성·관리 › 검토·제출 › 최종 확인·제출(준비 중). 제출 흐름은 지금 제안서 진행 현황 9단계에 걸려 있다. 공통 규칙은 `00_공통.md`. 초판 2026-11-27(planner C 묶음).

## 목적·누가 쓰나
- **팀별 제안서 작성이 모두 끝나면 결재를 거쳐 '제출 완료'까지 마친다. 그 뒤 입찰 결과는 협약·관계 관리에서 등록한다** (출처: 사용자 시나리오 11-10)
- **제출은 사내 절차 안의 행위이며, 제안서 진행 현황에 반영된다** (출처: NEXT 59 사용자 답 11-09 3차)
- **현업 평가는 '보류'이며, 지금대로 두고 늘리지 않는다** (출처: 사용자 1차 답 11-10)

## 보는 범위·권한
- **제출은 해당 제안서 담당자 가운데 영업팀 소속이 누른다. 1차 결재는 영업팀 담당 직원, 2차 결재(최종 확정)는 영업팀장이 한다** (출처: NEXT 59 사용자 답 11-09 3차)
- **'전 팀 작성 완료 확인'을 1차로 본다(확인하면 바로 디자이너에게 보낼 수 있음). 팀장의 제출 확정이 2차다** (출처: done.md 63 사용자 11-09 QA①)
- **완료 확인에 넣는 팀은 영업·전산이다(예산팀은 넣지 않는다)** (출처: done.md 63 사용자 11-09 QC①)
- **기획승인과 최종 결재는 그대로 두고, 이관 결재는 이것으로 대체한다** (출처: done.md 63 사용자 11-09 QB①)

## 동작·흐름 규칙
- **이사회 가결 전에는 업무상 제출할 수 없다. 예외로 풀어 주는 길도 없다** (출처: NEXT 59 사용자 답 11-09 2차 ④·3차)
- **모든 제안서는 반드시 이사회 안건을 거친다. 이사회 건이 없는 경우는 과거 자료를 확보하지 못한 경우뿐이다** (출처: NEXT 59 사용자 답 11-09 3차)
- **사전준비 뒤에 결재가 필요하다면 제안서 제출 단계쯤에서 받는다. 그 결재의 모양은 제출 단계를 설계할 때 인터뷰해서 정한다** (출처: NEXT 118, 사용자 11-25)
