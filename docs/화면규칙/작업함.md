# 작업함

메뉴 위치: 제안서 작성·관리 › 진행·작성 › 작업함. 공통 규칙은 `00_공통.md`. 초판 2026-11-27(planner C 묶음).

## 목적·누가 쓰나
- **제안서 작업물 파일(PPT·PDF 등)을 올리고, 점검을 받고, 제출(결재 요청)하는 곳이다. 시스템 안에서 본문을 쓰지는 않는다** (출처: Q-2026-11-20-37 질문 전제, NEXT 106)
- **제안서 담당자는 제안서 작성 때 팀을 꾸리며 정한 담당자다. 한 사람이 여러 건을 동시에 맡을 수 있다** (출처: done.md 63, 사용자 11-09)
- **재무팀장에게는 이 묶음(제안서 작성·관리)을 열지 않는다** — 결재 말고는 여기서 하는 일이 없다. 결재는 머리 띠 결재함에서 한다 (출처: Q-2026-11-23-27)

## 보는 범위·권한
- **디자이너가 쓰는 범위는 ⑥ 최종 단계(제안서 디자인)뿐이다. 사전준비 양식은 보기만 한다** (출처: Q-2026-11-19-45·48·49 답, 사용자 11-19)
- **담당으로 지정되지 않은 디자이너는 기본값 '보기'다** (출처: 사용자 11-16·11-19, 메모리 project_designer-default-view)
- **디자이너가 작업한 확정본의 확인과 최종 확정은 영업이 한다** (출처: 사용자 11-19, 메모리 project_designer-default-view)

## 화면 구성·표시 규칙
- **파일을 고르면 [업로드] 단추를 강조하고, 다른 기관 이름이 잡혔으면 [문맥 보기]를 강조한다. 이 화면의 동작 이름은 '업로드'로 통일한다** (출처: 사용자 실사용 의견 11-23, NEXT 106)
- **제출해서 잠긴 작업에는 '제출한 작업이라 바꿀 수 없습니다'만 보인다. [다시 수정] 단추는 따로 정한다** (출처: 사용자 11-23, NEXT 106)

## 동작·흐름 규칙
- **제안서 점검(다른 기관 이름 찾기)은 작업함에 올리는 모든 작업물을 대상으로 한다** (출처: NEXT 106 사용자 11-20; 장부 Q-2026-11-20-37)
- **다른 기관 이름은 정식 이름만 찾는다(약칭은 찾지 않는다)** (출처: NEXT 106 사용자 11-20)
- **다른 기관 이름이 나와도 확인 창을 거치면 제출할 수 있다. 일부러 쓴 이름(비교 사례 등)은 '의도한 언급'으로 지울 수 있다** (출처: NEXT 106 사용자 11-20; 장부 Q-2026-11-20-38)
- **디자인은 결재가 아니라 '디자인 작업 완료' → 알림 → 피드백 → 다시 수정 순서로 돈다. 영업팀 검토를 거쳐 영업부장에게 간다** (출처: 사용자 11-19, 메모리 project_designer-default-view)
