## 2026-08-25 개정에서 우리가 알게 된 것 (발송본에 없는 내부 판단)

- **eGovFrame 제약은 애초에 잘못 받은 확정이었다.** 2026-08-05 브레인스토밍에서
  "eGovFrame 4.x 준수 필수"로 적어 문서 제목·Spring Boot 배제·문의서 6번까지
  끌고 갔으나, 이관 목적지가 당행 내부 플랫폼이라 **적용 대상이 아니다.**
  제안 대상이 구청·지자체라는 점에서 혼선이 있었던 것으로 보인다.
  → **되살아나는 조건**: 이 시스템을 지자체·공공기관에 **납품**하기로 하는 경우.
- **폐기의 이득**: `web.xml`을 우리가 소유하게 되어 종전 6번 문항이 통째로
  불필요해졌고(직접 `async-supported=true`를 명시하면 끝), Spring Boot 2.7.x
  구조를 그대로 쓸 수 있다. 그 결과 **`uploader/`(사용자가 외부에서 만들어 온
  Spring Boot 2.7.18 + JDK 8 + WebLogic WAR + MyBatis + PDFBox/POI)가 이관
  단계 1(골격)의 실물 출발점이 된다** — 계획서 Task 1.1 참조.
- **6번 답이 "재검증 필요"로 오면 일정이 늘어난다.** uploader의 `/api/files/*`는
  현재 **인증이 한 줄도 없고**(spring-security 의존성 자체가 없다), 망 안 Python
  시스템도 마찬가지다. 게이트웨이가 인증을 완결해 준다는 답이면 그대로 가고,
  아니면 인증 계층이 신규 과제로 추가된다. **답을 받기 전에는 어느 쪽도 구현하지
  않는다.**
  - *2026-08-30 — 이 문단은 그대로 유효하다.* 6번의 **나가는 쪽**(LLM 호출용 토큰)은
    사라졌지만 **들어오는 쪽(ⓒ 재검증)** 은 남았고, 그것이 곧 이 문단이다.
    6-1(서비스 등록)과 함께 확인한다.
