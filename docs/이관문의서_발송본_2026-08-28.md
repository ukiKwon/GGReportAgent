# 문의서 발송본 (2026-08-28)

첨부 원본: `docs/이관문의서_WebLogic_확인사항.md` (10개 항목, 답변 칸 포함)

발송 형태는 **두 가지**를 준비했다. 상황에 맞는 쪽을 골라 그대로 복사해 쓰면 된다.

- **A. 통합 1통** — 수신처가 한 곳(정보화 총괄 등)이거나, 어느 부서 소관인지
  모를 때. 첨부 1건으로 끝난다.
- **B. 부서별 3통** — 담당 부서를 이미 알 때. **회신이 빨라진다** — 각 부서가
  자기 항목만 보면 되고, 2·3번(설계를 가르는 항목)이 서로 다른 부서라
  통합본으로 보내면 한쪽 회신이 다른 쪽을 기다리다 늦어진다.

⚠️ 아래 본문의 `[ ]` 표시 부분(수신자·부서명·회신 희망일·연락처)은 **보내기 전에
채워야 한다.** 회신 희망일은 비워두지 말 것 — 기한 없는 문의는 뒤로 밀린다.

## A. 통합 1통

**제목**: [협조요청] 입찰 워크플로우 시스템 행내 이관 — 인프라·DB·사내 API 확인 10건

**본문**:

```
[수신 부서/담당자]님, 안녕하십니까.

「입찰 워크플로우 지원 시스템」을 행내 표준 환경(WebLogic + Oracle + Java 8)으로
이관하는 작업을 진행하고 있습니다.

설계는 마쳤고 이관 개발도 상당 부분 끝냈습니다만(WAR 골격·DB 스키마·데이터 계층·
결재 흐름·문서 산출 완료), 남은 기능이 아래 확인 사항에 막혀 더 진행되지 않는
상태입니다. 첨부한 확인 요청서의 10개 항목에 회신을 부탁드립니다.

특히 아래 두 항목은 답에 따라 설계가 통째로 바뀌는 부분이라, 나머지보다 먼저
회신해 주시면 그동안 나머지 작업을 이어갈 수 있습니다.

  · 2번 — 사내 API의 임베딩(embedding) 엔드포인트 제공 여부
           (없으면 의미 검색을 포기하고 전문검색 단독으로 가야 하며,
            현 시스템보다 검색 품질이 낮아집니다. 사전 합의가 필요합니다)
  · 3번 — Oracle Text 사용 가능 여부
           (가능/불가에 따라 한글 전문검색 구현이 두 갈래로 갈립니다)

각 항목의 "답변" 칸을 채워 회신해 주시면 됩니다. 확실치 않은 항목은 "미상"으로
두시고 담당 부서만 알려주셔도 진행에 도움이 됩니다.

회신은 [YYYY-MM-DD]까지 부탁드리겠습니다. 문항 취지에 대한 문의는 언제든
연락 주십시오.

감사합니다.

[성명 / 부서 / 연락처]
```

## B. 부서별 3통

각 통의 첨부는 **원본 전체를 그대로 보내되**, 본문에서 볼 항목을 지정한다
(다른 부서 항목까지 보이면 소관 판단이 오히려 빨라진다).

### B-1. AI/정보화 부서 — 1·2번

**제목**: [협조요청] 사내 공용 LLM API 호출 규격 및 임베딩 엔드포인트 확인 (2건)

```
[부서/담당자]님, 안녕하십니까.

「입찰 워크플로우 지원 시스템」의 행내 이관 작업 중, 사내 공용 LLM API 연동
구현이 규격 확인에 막혀 있어 문의드립니다. 첨부 확인 요청서의 1번·2번 항목입니다.

  · 1번 — 호출 규격이 OpenAI 호환인지 (엔드포인트 형식, 인증 방식,
           JSON 스키마 구조화 출력 지원 여부, 사용 가능 모델·컨텍스트 길이)
  · 2번 — 임베딩(embedding) 엔드포인트 제공 여부 (모델명·차원 수·호출 규격)

2번은 답에 따라 설계가 바뀝니다. 임베딩 API가 없으면 현재의 "전문검색 + 의미검색"
하이브리드에서 의미검색을 빼야 하고, 검색 품질이 현 시스템보다 낮아집니다.
이 경우 품질 저하를 감수할지 사전에 합의가 필요해 미리 여쭙습니다.

회신은 [YYYY-MM-DD]까지 부탁드리겠습니다.

[성명 / 부서 / 연락처]
```

### B-2. DBA — 3·4번

**제목**: [협조요청] Oracle Text 사용 가능 여부 및 DB 버전 확인 (2건)

```
[부서/담당자]님, 안녕하십니까.

「입찰 워크플로우 지원 시스템」의 행내 이관 작업 중, 한글 전문검색 구현 방식을
정하지 못해 문의드립니다. 첨부 확인 요청서의 3번·4번 항목입니다.

  · 3번 — Oracle Text 사용 가능 여부
           ⓐ 설치·라이선스 사용 가능 여부
           ⓑ 한글 형태소 렉서(KOREAN_MORPH_LEXER) 사용 가능 여부
           ⓒ 인덱스 생성 권한을 애플리케이션 계정에 부여 가능한지
  · 4번 — Oracle 버전 (11g / 19c / 23ai)

3번은 가능 여부에 따라 구현이 두 갈래로 갈리는 항목이라(Oracle Text CONTEXT 인덱스
vs. 애플리케이션 자체 색인), 이 회신 없이는 해당 기능을 착수할 수 없습니다.
4번은 DDL 확정 전에 못 박아 두면 재작업이 없습니다.

회신은 [YYYY-MM-DD]까지 부탁드리겠습니다.

[성명 / 부서 / 연락처]
```

### B-3. 인프라/미들웨어 — 5·5-1·6·6-1·6-2·7번

**제목**: [협조요청] WebLogic 환경, 공통 API 게이트웨이 연동 규격·등록 절차 확인 (6건)

```
[부서/담당자]님, 안녕하십니까.

「입찰 워크플로우 지원 시스템」을 행내 표준 환경(WebLogic + Oracle + Java 8)으로
이관하고 있습니다. 배포 환경과 공통 API 게이트웨이(경유지) 연동에 대해 확인이
필요해 문의드립니다. 첨부 확인 요청서의 5번·5-1·6번·6-1·6-2·7번 항목입니다.

  · 5번   — WebLogic 버전 (12.2.1.x / 14.1.1 / 기타)
  · 5-1번 — 애플리케이션의 WorkManager(CommonJ) 사용 가능 여부
            (JNDI 조회 이름, 전용 WorkManager 별도 정의 필요 여부, 시험 환경)
  · 6번   — 경유지의 OAuth 인증 규격 (서비스 간 호출 방식, 토큰 수명·갱신 절차,
            게이트웨이가 인증을 완결하는지 뒤쪽 서비스도 재검증해야 하는지)
  · 6-1번 — 신규 서비스의 API 통합관리시스템 등록 절차
            (신청 창구·양식, 필요 정보, 소요 기간, 환경별 등록 여부)
  · 6-2번 — 게이트웨이 공개 API가 지켜야 할 표준 규격 문서
  · 7번   — 경유지의 응답 버퍼링·유휴 타임아웃 설정값과 변경 요청 창구

5-1번은 오래 걸리는 작업을 요청 스레드 밖에서 돌리기 위해 여쭙습니다. WAS에서
애플리케이션이 스레드를 직접 만들 수 없어 WorkManager로 구현했는데, 저희 개발
환경에는 WebLogic이 없어 이 경로만은 행내 환경에서만 검증이 가능합니다.
6-1번은 등록이 끝나야 연동 시험을 시작할 수 있어 일정 산정에 직접 영향을 줍니다.
6-2번은 현재 저희 API가 시험용 형태라 규격에 맞춘 변경 개발이 필요한데, 규격을
먼저 받아야 재작업 없이 한 번에 맞출 수 있습니다.
7번은 실시간 진행 표시(SSE) 때문에 여쭙는 항목입니다 — 앞단에서 응답을 버퍼링하면
표시가 멈추고, 유휴 타임아웃이 짧으면 작업 도중 연결이 끊깁니다(저희 검증 환경에서
타임아웃 60초에서 응답이 잘리는 것을 확인했고, 300초로 늘리고 버퍼링을 끄는 것으로
해결했습니다).

회신은 [YYYY-MM-DD]까지 부탁드리겠습니다.

[성명 / 부서 / 연락처]
```

## 회신을 받은 뒤에 할 일 (다음 세션용)

회신이 오면 **문의서의 "답변" 칸을 채워 커밋**하고, 아래 매핑대로 계획의 잠정
지점을 확정한다. 판단이 아니라 기계적 반영이다.

| 회신 | 확정되는 것 |
|---|---|
| 2번 (임베딩) | 단계 3 검색 — 하이브리드 유지 vs 전문검색 단독 |
| 3번 (Oracle Text) | 단계 3 검색 — Oracle Text CONTEXT vs Java 인메모리 색인 |
| 1번 (LLM 규격) | Task 4.4 LLM 어댑터 — 어댑터 두께, 노드 본문 4개 착수 |
| 6번 (경유지 OAuth) | Task 4.4 — 토큰 획득·갱신 구현 범위 |
| 7번 (버퍼링·타임아웃) | Task 4.3 SSE — 경유지 설정 변경 요청서 작성 |
| 4번 (Oracle 버전) | DDL 001~006 확정 (현재 Oracle 미검증, MySQL 미러만 실적용) |
| 5번 (WebLogic 버전) | `weblogic.xml` 설정, SSE 관련 프록시 타임아웃 값 |
| 5-1번 (WorkManager) | Task 4.2 배경 실행 — JNDI 이름 확정, 폴백 경로 탈출 검증 |
| 6-1·6-2 (등록·규격) | 연동 시험 일정, API 표준 규격 맞춤 변경 개발 범위 |
