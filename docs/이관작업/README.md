### 3. DB 스크립트 적용 (DBA)
- [ ] 02의 B절 순서대로 적용한다. 대부분 **한 번만** 돌리는 파일이다.
- [ ] 015(외래키 떼기)는 이미 외래키가 걸린 채 적용된 표가 있을 때만 돌린다.
- [ ] 적용 뒤 정합성 점검 쿼리 `db/oracle/ops/integrity_check.sql`을 돌린다(결과 0행이 정상).
- 근거: `kgi-ggreport-web/src/main/resources/db/README.md`, `kgi-ggreport-web/README.md` §8
- ⚠️ 외부망 MySQL·H2 통과는 Oracle 정합성의 근거가 아니다. **실검증은 내부망 Oracle에서 처음 이뤄진다.**

### 4. 서버 배포 (WebLogic)
- [ ] 콘솔에서 리소스 2개를 먼저 만든다: DataSource `jdbc/ggreportDS`(DB 비밀번호는 여기에만), Work Manager `wm/ggreportWM`.
- [ ] **DB가 먼저, 서버가 나중이다.** 026, 030·031·032 적용을 확인한 뒤 WAR를 올린다(반대면 기관 목록 오류). 026을 아직 적용하지 않았다면 설정 `ggreport.inst-head.enabled=false`로 배포한다.
- [ ] **옛 흐름 스위치를 닫은 채 배포한다**(`ggreport.legacy-flow.open=false`) — 열려 있으면 공고 생성(`POST /bidcases`)에 권한 검사가 없다(security 11-15, NEXT 64② 2단계 전까지). 2단계를 끝냈으면 이 줄은 지운다.
- 근거: `kgi-ggreport-web/README.md` §6·§6-1(`web.xml`의 `metadata-complete=false`, 필터 재선언 금지)

### 5. 설정 (config-envs 내부망)
- [ ] `config-envs/{local|dev|stg|prod}/application.properties` 중 하나를 `config/application.properties`로 복사한다. Spring 프로파일 인자가 아니다.
- [ ] 자리표시자를 채운다: dev·stg DB 주소, 첨부 원본 폴더 `ggreport.prep-attach-dir`(절대경로·백업 대상), 기관장 사진 폴더(웹 루트 밖 절대경로). stg·prod는 사진 경로가 자리표시자로 남아 있으면 기동하지 않는다.
- [ ] 키 이름만 out-local과 비교해 빠진 키가 없는지 본다(값은 보지 않는다).
- 근거: `kgi-ggreport-web/README.md` §3, NEXT 71(보안 PUSH-GATE 11-11)

### 6. 반입 (의존성·데이터)
- [ ] 라이브러리: `dependencies.txt`가 명세다. **합격 기준은 `mvn -o`(오프라인) 통과**다. `mysql-connector-j`는 반입하지 않는다.

- 근거: `kgi-ggreport-web/README.md` §9
