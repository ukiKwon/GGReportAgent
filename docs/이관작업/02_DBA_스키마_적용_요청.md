「입찰 워크플로우 지원 시스템」을 회사 내부망 Oracle로 옮기기 위해 표 구조 스크립트(001~032)를 준비했습니다. 회사 기준에 맞춰 **외래키는 두지 않았습니다**. 표 사이 연결은 프로그램이 저장 전에 확인하고, 정기 점검 쿼리로 감시합니다. 업무 코드는 공통 코드표 하나에 모았습니다.

**적용 전에 A절 확인을 먼저 부탁드립니다.** 특히 A1(버전)의 답에 따라 스크립트를 고쳐 다시 드려야 할 수 있습니다.

## A. 먼저 확인 부탁드릴 것

| # | 확인 사항 | 왜 필요한지 | 답에 따라 달라지는 것 |
|---|---|---|---|
| A1 | **Oracle 버전 재확인.** 8월에 11g로 들었습니다. | 스크립트 11개(002·005·008·012·014·019·020·024·025·026·030)가 12c부터 되는 자동 번호 칼럼(IDENTITY)을 씁니다. | 11g면 시퀀스 방식으로 바꾼 대체본을 드리고, **그때까지 적용을 보류**해 주십시오. 12c 이상이면 그대로 적용합니다. |
| A2 | **값 검사(CHECK)·중복 금지(UNIQUE) 제약** 허용 여부 | 001~014 일부에서 씁니다(019 이후는 쓰지 않음). | 불가면 프로그램 검사와 잠금용 표로 바꾼 대체본을 드립니다. |
| A3 | **이미 적용된 표**가 있는지(001~014 중), 외래키가 걸린 채인지 | 예전 판에는 외래키 18개가 있었습니다. | 있으면 015(외래키 떼기)를 실행하고, 없으면 015는 건너뜁니다. |
| A4 | **사내 표준 명명·칼럼 규칙** 적용 여부 | 9월 업로더 표는 사내 표준(표 코드명 TSKGIAF01·02, 한글 칼럼명, 작업자·작업 시각 감사 칸 2개, 스키마 접두어)으로 만들었습니다. 이 시스템 표는 영문 이름입니다. | 표준을 적용해야 하면 전체 이름을 바꿔야 해서 작업이 큽니다. 아니면 그대로 갑니다. |
| A5 | **번호·날짜 형식**: 시각을 날짜형이 아니라 국제 표준 문자열(최대 40자)로 저장, 여러 칼럼을 묶은 기본키(예: 코드 그룹+코드) 사용 | 두 DB(외부망 시험용·내부망)에서 프로그램 한 벌로 쓰기 위해서입니다. | 날짜형이 필수면 해당 칼럼과 조회문을 바꿉니다. |
| A6 | **행 잠금**(SELECT … FOR UPDATE) 허용 여부와 인덱스 이름 규칙 | 같은 기관에 진행 건이 둘 생기지 않도록 기관 행을 잠근 뒤 확인합니다(024). | 불가면 다른 직렬화 방법으로 바꿉니다. |
| A7 | **이름 없는 PL/SQL 블록** 실행 가능 여부 | 015가 이 형식입니다. | 불가면 `ALTER TABLE … DROP CONSTRAINT` 18문으로 대체합니다. |
| A8 | 문자셋(AL32UTF8 전제)과 테이블스페이스 지정 규칙 | 한글 칸 길이를 글자 단위로 잡았습니다(VARCHAR2(n CHAR)). | 문자셋이 다르면 칸 길이를 다시 봅니다. |
| A9 | (참고) 문서 검색 기능용 Oracle Text 사용 가능 여부 | 서버 이관 담당께 따로 여쭸습니다. DB 쪽 소관이면 함께 답해 주십시오. | 검색 구현 방식이 갈립니다. |

## C. 앱 계정 권한

| 표 | 권한 | 근거 |
|---|---|---|
| ACCESS_LOG, PERM_CHANGE_LOG(접근·권한 변경 기록) | **SELECT·INSERT만** | 감사 기록(008) |
| INST_HEAD_LOG, INST_HEAD_ACT(기관장 정보 이력·열람 기록) | **SELECT·INSERT만** | 026 |
| INST_EDIT_LOG(기관 수정 이력) | **SELECT·INSERT만** | 030 |

| NOTICE_ROUND(입찰 회차) | SELECT·INSERT + 칸 단위 UPDATE(ANCHOR_LAST_BID, CLOSED_AT, CLOSE_REASON_CD, CLOSED_BY, CLOSED_LAST_BID), **DELETE 없음** | 037 |
