2026-W32 08-03 ~ 08-09

협업 화면이 모두 붙어 설계 시나리오 19개 항목을 전부 충족했습니다. 결재 라인·역할 체계, 시연 환경, 배포 문서, 설명회 자료도 정비했습니다.

한 일

  • 협업 화면을 구현했습니다.
    • 9단계 현황판과 단계별 참여자
    • 대화, 쪽지함, 지식 검색
    • 계정 전환(시연용)
    • 참여 결정 3단 결재
    • 데이터 앞뒤가 안 맞을 때 띄우는 정합성 경고
  • 시연 환경을 운영 자료와 분리해, 명령 한 줄로 띄울 수 있게 했습니다.
  • AWS EC2 시연 배포 계획서와 '이 문서 하나로 설치하는' 매뉴얼을 썼습니다. 실제 구축은 하지 않았습니다.
  • 디자이너 전용 화면을 만들었습니다. 역할별 메뉴 권한과 팀장·부장 결재 라인도 구현했습니다.
  • AI 사용 투명성을 높였습니다.
    • 대화가 실패하면 이유를 화면에 보여 줍니다.
    • 근거 원문을 열어 볼 수 있습니다.
    • 배점 합계가 총점과 다르면 경고합니다.
    • 어떤 모델을 썼는지 표시하고, 예비 모델로 넘어간 경우도 기록합니다.
  • WebLogic/Java 이관이 가능한지 검토하고 설계서를 썼습니다.
  • 설명회용으로 사업제안 보고서 2.0과 화면 포트폴리오(캡처 15장)를 만들었습니다.
  • 밀린 결함을 정리했습니다.
    • 이전 회차 제안서를 한 번도 못 찾던 문제
    • 개인정보 건수가 부풀려 보이던 문제
    • 기관 추가가 서버에 저장되지 않던 문제
    이로써 9단계 시스템 항목을 종결했습니다(08-09).

결정·요건 변경

  • 08-03 카드를 '각 단계에 실제로 참여한 사람·팀'만 보이게 다시 설계했습니다. 사용자 말로는 "내가 잘못 계획했어"였습니다.
  • 08-03 시험용 자료와 운영 자료를 분리했습니다. 사용자가 "구동이 복잡하면 나중에 하기 어렵다"고 제안했습니다.
  • 08-03 데이터 앞뒤가 안 맞는 경우는 점검 에이전트 대신 시스템이 처음부터 막고, 규칙으로 점검하기로 했습니다. 계기는 사용자 지적입니다: "9단계까지 다 돌았는데 참여결정이 '대기'인 건 말이 안 된다".
  • 08-03 추측 날짜를 지도 면에 빗금으로 표시하지 않기로 했습니다. 사용자 결정입니다.
  • 08-04 EC2는 시연 전용으로 정했습니다. 사용자는 처음에 앱 로그인을 새로 만들자고 했다가, 계정 전환 시연과 부딪혀 철회했습니다. 그래서 다음처럼 갑니다.
    • 앱 로그인은 만들지 않고, 웹서버 기본 인증과 접속 IP 제한으로 막습니다.
    • 외부 AI API는 쓰지 않고, 서버 안에서 모델을 돌립니다.
  • 08-05 EC2 사양을 m7i-flex.large로, 기본 모델을 소형(3b)으로 낮췄습니다. 메모리 한계 때문입니다.
  • 08-05 모델 자동선택은 '켤 때만' 동작합니다. 운영 모델이 조용히 바뀌지 않게 하기 위해서입니다.
  • 08-05 이관 제약을 확정했습니다: 실제 이관, Oracle, JDK 1.8, Java만 허용, 사내 AI API 사용, 크롬·엣지. 전자정부프레임워크 준수 조건도 이때 받았는데, 08-25에 폐기됩니다.
  • 08-05 역할 구조를 다시 정했습니다. 사용자 지시는 "소속은 영업·전산·예산 3그룹, 디자이너 결재는 영업팀장, 영업팀장이 영업부장에게 올리는 것으로 종료, 본부장 개념은 없앤다"였습니다.
  • 08-05 보고서 2.0은 원본을 두고 새 파일로 만들었고, 스크린샷은 넣지 않았습니다. 포트폴리오의 영어식 용어는 한글로 고치고 옆에 영어를 병기했습니다('워크플로'·'아카이브'는 그대로 둠).
  • 08-06 작업 전에 '무슨 의도인지' 먼저 설명하고 진행 의사를 다시 묻기로 했습니다. 사용자 요청입니다.
