uploader를 내부망 WebLogic에서 실제로 띄워 보는 데 성공했고, 사내 DB 표준(테이블 코드명, 한글 컬럼, 감사용 칸)에 맞춰 스키마를 확정했습니다.

한 일

  • 내부망 개발도구와 WebLogic에서 uploader를 띄우는 데 성공했습니다. '테이블 없음' 오류까지 도달했다는 것은 DB 연결이 정상이라는 뜻입니다. 그 과정에서 막힌 문제 8건의 원인과 조치를 기록했습니다.
  • 내부망 반입 패키지(43.7MB)와 DBA 테이블 생성 요청서를 만들었습니다.
  • 이관 작업 갈래에는 본선의 uploader만 가져왔습니다. 전체를 합치려 하니 충돌이 23건이었고, 폴더마다 최신인 쪽이 서로 반대라 포기했습니다.
  • 현장에서 실제로 시간을 잡아먹은 함정 3건을 배포 문서에 넣었습니다.
  • 사내 DB 표준을 반영했습니다. 테이블 이름은 TSKGIAF01·02, 컬럼은 한글이고, 감사용 2칸(누가·언제 작업했는지)이 자동으로 기록됩니다. 그 결과 내부망에 옮길 소스가 27개로 늘었습니다.

결정·요건 변경

  • 09-07 uploader 기동 검증 관련으로 셋을 정했습니다.
    • 변수를 줄이려고 자동 재분류 배치를 껐습니다.
    • 번호 칸 자릿수를 19에서 18로 줄였습니다(사내 규격).
    • 반입물은 본선 기준으로 만들었습니다.
  • 09-08 전체 합치기 대신 'uploader만 가져오기'로 정했습니다. 사용자 확정이고, 전체를 합치면 Java 쓰기 기능 작업 30건이 되돌아가기 때문입니다.
  • 09-08 사용자 지시는 "내부는 한글명 컬럼을 써야 한다"였고, 테이블 이름 TSKGIAF01·02도 함께 지정받았습니다. 하루 사이에 컬럼 이름이 세 번 바뀌어 최종안으로 확정됐습니다.
  • 09-08 스키마 접두어(INST1.)는 내부망 안내 문서에만 붙이고, 저장소 소스에는 넣지 않았습니다. 넣으면 외부망 점검 62건이 깨지기 때문입니다(사용자 지시).
  • 09-08 감사용 시각은 DB가 아니라 앱에서 정해 넘기기로 바꿨습니다. 사용자가 "분류일시가 없으면?"이라고 짚었기 때문입니다.
