2026-W44 10-26 ~ 11-01

화면을 로그인·사이드바 구조로 바꾸고, 시스템 관리·결재라인·이사회 자료 양식을 처음 만든 주. 일하는 방식(여러 세션·역할 에이전트) 규칙도 이때 생겼다

한 일

  • 업로더를 WebSphere 서버에서도 돌릴 수 있게 하는 작업을 시작했다. 배포 파일을 만들 수 있는 것까지 확인했고, 본류에는 아직 합치지 않았다
  • 화면 개편 1·2단계: 로그인 화면(사번·팀·직위 선택), 왼쪽 사이드바 메뉴, 헤더 오른쪽의 쪽지함·프로필, 임박 TOP5 전광판 효과
  • 엑셀 수치를 워드에 자동으로 채우는 기능을 시험 삼아 만들어 봤다. AI 없이 정해 둔 규칙만으로 가능하다고 판단했다. 실제 양식이 없어 정식 구현은 보류하고 메뉴에 '구현 예정'으로만 표시했다
  • 시스템 관리 화면: 사용자·권한·메뉴·접근 이력을 관리하고 사번으로 로그인한다. 이어서 결재라인(상위 결재자 자동 지정, 직급 규칙, 대결, 권한 신청 결재)과 결재 알림 쪽지, '내 정보' 화면을 만들었다
  • 보안 점검 보고서를 냈다(핵심: 서버가 로그인한 사람을 확인하지 않고 사번을 본인 신고로 받음). 같은 주에 바로 고칠 수 있는 5건을 적용했다(메뉴 권한 변경은 관리자만 등)
  • 사이드바 메뉴를 재편하고 '제안서 진행 현황' 목록 화면을 만들었다. 기관 정보 고치기는 영업 계열만 하도록 제한했고, 쪽지는 본인 것만 볼 수 있게 했다
  • 이사회 자료 1차: 기본 양식을 화면에 보여 주고 워드로 내려받게 했다. 양식을 바꾸는 기능(표 추가·삭제·문구 수정)은 서버 쪽까지 만들었다
  • 작업 환경: 할 일 목록에서 끝난 항목을 따로 떼어 냈고, 지난 작업 이력을 그림처럼 이어 보는 Obsidian 이력 묶음을 만들었다. 새 PC에 개발 환경을 세웠고, 에이전트 진행판에 데이터 담당 선수를 추가했다

결정·요건 변경

  • 10-27 업로더 서버 교체 대상을 WebSphere Traditional 9.x로 정함. 본류 병합은 검증이 끝날 때까지 미룸 — 실제 서버 환경을 아직 확인하지 못해서
  • 10-27 로그인은 사번·비밀번호와 역할 선택, 메뉴는 왼쪽 사이드바로 전면 교체 — 소속을 고르기 전에는 결재 메뉴가 보이지 않는 문제가 출발점
  • 10-28 엑셀→워드 자동 채우기는 실제 양식이 들어올 때까지 구현을 보류하고 메뉴만 '구현 예정'으로 표시 — 실제 양식(수익성 분석표→이사회 자료)을 구할 수 없어서
  • 10-28 결재선은 사용자마다 상위 결재자를 두고(기본은 자동, 변경은 관리자), 대결자는 결재자 본인이 지정. 상위 직급자가 하위 직급자에게 결재를 올리는 것만 금지. 이사회 자료 확정은 작성자→팀장→부장
  • 10-29 임박 TOP5 기준을 '입찰 공고 예정일까지 남은 일수'로 바꾸고, 예정일이 지나면 경과일로 표시. 협약 중인 기관과 영업 대상 기관을 나눠 봄. 공고 예정일은 '지난 공고일 + 협약 기간'으로 추정 — 화면 날짜가 실제로는 공고일이 섞여 의미가 맞지 않았기 때문
  • 10-29 여러 세션이 동시에 일할 때는 작업 폴더를 세션마다 나누고 기록도 따로 둠 — 두 세션이 같은 문서를 동시에 고친 일이 있어서
  • 10-30 TOP5 데이터 담당자는 영업팀 전원. 영업부장도 전 기관 진행 현황을 볼 수 있어야 함. 보안은 회사 SSO를 쓰고, 개인정보가 든 파일은 업로드를 막고, 감사 로그는 ISMS 규칙대로 보존
  • 10-30 결재자는 올린 사람보다 직급이 반드시 높아야 함(같은 직급은 대결자만). 이사회 자료 범위는 수익성 분석표를 참고하는 부분이고, 원본 엑셀은 저장하지 않으며, 쪽 구분은 없앰
  • 10-30 일의 크기와 상관없이 모든 작업은 역할 에이전트를 먼저 부름 — 사용자 요청
