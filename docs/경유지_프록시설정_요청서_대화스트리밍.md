# 경유지(공통 API 게이트웨이) 프록시 설정 조정 요청 — 대화 화면 스트리밍

- **요청 대상**: 공통 API 게이트웨이 운영 부서 (인프라/미들웨어)
- **대상 시스템**: 입찰 워크플로우 지원 시스템 (`kgi-ggreport-web`, WebLogic WAR)
- **대상 경로**: `POST /institutions/{기관ID}/chat` **이 한 경로만** 해당합니다.
- **작성일**: 2026-08-28 (구현계획 Task 4.3 산출물)

> ⚠️ **이 문서는 문의서 7번의 회신을 받은 뒤에 보냅니다.** 현재 설정값과 조정 창구를
> 모르는 상태에서 보내면 "무엇을 어떻게 바꿔 달라"가 성립하지 않습니다. 회신이 오면
> 아래 §3의 `[현재값]` 자리를 채워 발송하십시오.
> 관련: `docs/이관문의서_WebLogic_확인사항.md` 7번.

## 1. 무엇을 요청하는가 (요약)

이 한 경로에 대해 두 가지를 요청합니다.

| 항목 | 요청 값 | 이유 |
|---|---|---|
| 응답 버퍼링 | **끄기** (`off`) | 켜져 있으면 답변이 다 만들어질 때까지 화면에 아무것도 안 나온다 |
| 유휴(read) 타임아웃 | **300초 이상** | 짧으면 답변 도중 연결이 끊긴다 |

나머지 경로는 일반 JSON 응답이라 **조정이 필요 없습니다.**

## 2. 왜 필요한가

대화 화면은 LLM 답변을 **다 만들어진 뒤 한 번에** 주지 않고, 만들어지는 대로
**HTTP 응답 본문을 조금씩 나눠 보냅니다**(chunked). 사용자는 답변이 타이핑되듯
나타나는 것을 봅니다.

- **SSE(Server-Sent Events)가 아닙니다.** `POST` + `text/plain; charset=utf-8` 이며
  `data:` 프레이밍이 없는 평문 청크입니다. 브라우저도 `EventSource` 가 아니라
  `fetch` + `ReadableStream` 으로 읽습니다.
  → **SSE 전용 예외 설정이 있더라도 이 경로에는 적용되지 않을 수 있으니**, 경로 기준으로
  조정해 주시기를 요청드립니다.
- 앞단이 **응답을 버퍼링하면** 서버가 아무리 조금씩 보내도 게이트웨이가 모았다가 한 번에
  내보냅니다. 기능은 동작하지만 **실시간 표시가 통째로 사라집니다**(사용자에게는 수십 초
  동안 멈춘 화면으로 보입니다).
- **유휴 타임아웃이 짧으면** 답변 생성이 그보다 오래 걸릴 때 연결이 끊겨,
  **중간까지만 나온 답변**이 남습니다.

## 3. 확인·조정 요청 항목

| # | 항목 | 현재값 | 요청값 |
|---|---|---|---|
| 1 | 응답 버퍼링 (nginx `proxy_buffering` 상당) | `[현재값]` | **off** |
| 2 | 유휴/읽기 타임아웃 (`proxy_read_timeout` 상당) | `[현재값]` | **300s 이상** |
| 3 | 경로 단위 예외 설정 가능 여부 | `[가능/불가]` | 이 경로만 적용 |
| 4 | 조정 신청 창구·절차·소요 기간 | `[창구]` | — |

**참고로 서버 쪽에서는 이미 다음을 하고 있습니다** — 그런데도 앞단이 버퍼링하면 같은
증상이 나므로 이 요청을 드립니다.

- 응답 조각마다 즉시 `flush`
- `Content-Length` 를 달지 않음 (chunked 전송)
- `Cache-Control: no-cache`, `X-Accel-Buffering: no` 헤더 부착
  (표준 헤더가 아니라 게이트웨이가 무시할 수 있습니다)

## 4. 근거 — 실측값

**300초·버퍼링 off 는 임의로 고른 값이 아닙니다.** 같은 시스템을 AWS EC2 + nginx
구성으로 시연 준비하며 실제로 측정한 값입니다.

| 설정 | 결과 |
|---|---|
| 기본값 (버퍼링 on, 타임아웃 60초) | 실시간 표시가 사라지고, 60초에 **504** 로 잘림 |
| `proxy_buffering off` + `proxy_read_timeout 300s` | 정상 |

## 5. 조정이 안 될 경우

설정 변경이 불가하다면 아래 중 하나를 협의해야 합니다. **셋 다 사용자 경험이 나빠지므로
설정 조정을 우선 요청드립니다.**

1. **스트리밍 포기** — 답변이 다 만들어진 뒤 한 번에 표시. 타임아웃은 여전히 문제입니다
   (긴 답변은 응답 자체가 타임아웃에 걸립니다).
2. **폴링으로 전환** — 답변을 서버에 쌓아 두고 화면이 주기적으로 조회.
   ⚠️ **화면 코드를 고쳐야 합니다** — "화면 무변경"이 이관의 전제였으므로 별도 합의가
   필요합니다.
3. **답변 길이 제한** — 타임아웃 안에 끝나도록 짧게. 품질 저하를 감수해야 합니다.
