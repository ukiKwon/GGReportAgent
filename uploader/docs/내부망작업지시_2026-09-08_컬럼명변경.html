DB 컬럼명 변경 — 내부망에서 해야 할 일

외부망에서 DB 컬럼명을 전부 다시 지었습니다. 내부망에서는 텍스트 파일 4개만 교체하면 됩니다. 자바 소스·화면·설정·jar는 하나도 바뀌지 않아 zip 재반입이 필요 없습니다.

작성일 2026-09-08 대상 내부망 WebLogic 12.2.1.4 / Eclipse Photon 선행 상태 웹 기동 정상 · 테이블 미생성 검증 외부망 mvn -o clean test 62건 통과

1왜 바꿨나

종전 컬럼명은 “무엇의” 이름·경로·상태·분류인지가 드러나지 않았습니다. ORIGINAL_NAME이 기관명인지 파일명인지, STATUS가 무슨 상태인지 컬럼만 봐서는 알 수 없었습니다.

새 이름은 본체(kgi-ggreport-web)의 명명 규칙 — 서술형 영문 풀네임 + 테이블명 접두 ID(INSTITUTION_ID·PARTICIPATION_STATUS· LAST_SYNCED_AT) — 을 따랐습니다. 나중에 두 스키마를 합칠 때 규칙이 갈리지 않게 하려는 것입니다.

지금이 바꿀 수 있는 유일한 시점입니다

아직 테이블이 만들어지지 않았습니다. 데이터가 들어간 뒤에 바꾸려면 ALTER TABLE … RENAME COLUMN 과 서비스 중단이 필요합니다. 지금은 마이그레이션 비용이 0입니다.

zip을 다시 반입할 필요가 없습니다

WEB-INF/lib의 jar 57개, WEB-INF/classes의 클래스, 자바 소스는 하나도 바뀌지 않았습니다. 위 4개는 전부 텍스트 파일이라 합쳐서 수십 KB입니다.

4번은 내부망에서 쓰지 않지만(외부망 테스트·로컬용) 같이 옮기시길 권합니다 — 두 파일이 갈리면 나중에 어느 쪽이 맞는지 알 수 없게 됩니다.

4순서 — 이걸 틀리면 깨집니다

  1. 매퍼 2개 + 스키마 2개를 교체한다
    Eclipse에서 파일을 덮어쓴 뒤 Project → Clean. src/의 .xml·.sql은 컴파일 대상이 아니라 WEB-INF/classes로 복사됩니다.
  2. 서버에 Publish 하고 재기동한다
    이 시점에는 테이블이 아직 없으므로 화면에서 ORA-00942가 나는 것이 정상입니다 (지금과 같은 상태).
  3. DBA에게 새 schema-oracle.sql을 전달해 테이블을 만든다
    테이블 2개 + 시퀀스 2개 + 인덱스 2개.
  4. 재기동 후 확인한다 (아래 6절)
매퍼와 DDL은 반드시 같은 이름이어야 합니다

왜 자바가 안 바뀌나

MyBatis의 resultMap이 자바 필드명(property)과 DB 컬럼명(column)을 명시적으로 이어 줍니다. 컬럼명만 바꾸고 매핑 줄을 고치면 자바 쪽은 바뀐 사실을 모릅니다. 자바 필드는 그대로입니다 — originalName · storedPath · year · category · status.

6교체 후 확인

시점확인할 것정상
매퍼 교체 후 Publish 서버 로그 기동 성공. ORA-00904가 없어야 합니다
테이블 생성 전 http://localhost:7001/uploader/ ORA-00942 — 지금과 동일. 정상입니다
테이블 생성 후 /uploader/institutions 에서 기관 1건 등록 등록 성공 = 컬럼명·시퀀스가 모두 맞다는 증명
그다음 /uploader/upload 로 파일 1건 업로드 C:\uploader-local\unclassified\ 에 파일 생성 + 목록에 표시
기관 등록이 실패하면
  • ORA-00904 → 매퍼와 테이블의 컬럼명이 다릅니다. 4절 표를 보십시오.
  • ORA-02289: sequence does not exist → 시퀀스 2개가 안 만들어졌습니다. 테이블만 만들면 조회는 되고 등록만 실패합니다.
  • ORA-02290: check constraint violated → CLASSIFICATION_STATUS에 허용되지 않은 값이 들어갔습니다(허용: UNCLASSIFIED·CLASSIFIED· REJECTED·DELETED).

7새 DDL 전문 (DBA 전달용)

-- ── 업로드된 파일 ───────────────────────────────────
CREATE TABLE UPLOADED_FILE (
    UPLOADED_FILE_ID      NUMBER(18)          NOT NULL,
    INSTITUTION_NAME      VARCHAR2(200 CHAR),
    INSTITUTION_CATEGORY  VARCHAR2(100 CHAR),
    DOCUMENT_YEAR         VARCHAR2(4 CHAR),
    CLASSIFICATION_STATUS VARCHAR2(20 CHAR)   DEFAULT 'UNCLASSIFIED' NOT NULL,
    ORIGINAL_FILE_NAME    VARCHAR2(255 CHAR)  NOT NULL,
    UPLOADED_AT           TIMESTAMP           NOT NULL,
    CLASSIFIED_AT         TIMESTAMP,
    STORED_FILE_PATH      VARCHAR2(700 CHAR)  NOT NULL,
    CONSTRAINT PK_UPLOADED_FILE PRIMARY KEY (UPLOADED_FILE_ID),
    CONSTRAINT CK_UPLOADED_FILE_STATUS CHECK
        (CLASSIFICATION_STATUS IN ('UNCLASSIFIED', 'CLASSIFIED', 'REJECTED', 'DELETED'))
);

-- ── 기관 (기관명 → 카테고리 매핑표) ─────────────────
CREATE TABLE INSTITUTION (
    INSTITUTION_ID       NUMBER(18)         NOT NULL,
    INSTITUTION_NAME     VARCHAR2(200 CHAR) NOT NULL,
    INSTITUTION_CATEGORY VARCHAR2(100 CHAR) NOT NULL,
    MODIFIED_AT          TIMESTAMP          NOT NULL,
    CONSTRAINT PK_INSTITUTION PRIMARY KEY (INSTITUTION_ID),
    CONSTRAINT UK_INSTITUTION_NAME UNIQUE (INSTITUTION_NAME)
);

-- ── 시퀀스 (이름 변경 불가 — 매퍼가 그대로 부른다) ──
CREATE SEQUENCE UPLOADED_FILE_SEQ START WITH 1 INCREMENT BY 1 NOCACHE;
CREATE SEQUENCE INSTITUTION_SEQ   START WITH 1 INCREMENT BY 1 NOCACHE;

-- ── 인덱스 (식별자는 29자 — 11g 상한 30에 여유 1자뿐) ──
CREATE INDEX IDX_UPLOADED_FILE_UPLOADED_AT ON UPLOADED_FILE (UPLOADED_AT);
CREATE INDEX IDX_UPLOADED_FILE_INST_STATUS ON UPLOADED_FILE (INSTITUTION_NAME, CLASSIFICATION_STATUS);

8아직 안 한 것 — 기동 이후 과제

① 카테고리 코드값 5종 정리

카테고리를 지방자치단체 · 공공기관 · 대학교 · 병원 · 법원 5종으로 확정했지만, 코드에는 아직 옛 4종이 박혀 있습니다. 그것도 세 곳에 흩어져서요:

위치현재 값
KGI12000$FileStatusList.java:18지자체 · 대학교 · 대학병원 · 공공기관
KGI12400$ClassifiedFileList.java:18같은 4개 (복제)
templates/institution.html:43-46같은 4개를 <option>에 직접 박음
그래서 카테고리에는 CHECK 제약을 일부러 걸지 않았습니다

DB에 5종 CHECK를 먼저 걸면, 화면이 여전히 지자체를 보내는 순간 기관 등록이 ORA-02290으로 실패합니다. 코드를 5종으로 맞춘 뒤에 제약을 거십시오.

② 기관 입력을 드롭다운으로

지금 기관명은 자유 입력 텍스트입니다(upload.html:30). 오타 한 글자면 매칭에 실패해 파일이 조용히 UNCLASSIFIED로 남고, 조회도 LIKE '%…%'라 인덱스를 쓰지 못합니다. INSTITUTION 표를 드롭다운 소스로 쓰면 셋 다 해결됩니다 — “A 기관 자료 들어왔나?”가 주 용도라면 이것이 가장 큰 개선입니다.

③ 자동 재분류 켜기

reclassification.cron이 비어 있어 5분마다 도는 재분류가 꺼져 있습니다. 켜려면 web.xml의 timer/uploaderTM 선언을 되살리고 WebLogic 콘솔에서 Work Manager uploaderTM을 만들어야 합니다 (DEPLOY.md 3번의 A → B → C).
