식별자에 따옴표를 쓰지 않았습니다

Oracle·MySQL·H2 모두 한글 식별자를 따옴표 없이 받습니다 (MySQL은 U+0080~U+FFFF를 무인용 식별자로 명시 허용). 큰따옴표로 감싸면 대소문자가 고정돼 도구마다 성가셔지므로 쓰지 않았습니다. 외부망 테스트 62건이 H2에서 한글 식별자로 실제 SQL을 돌려 통과했습니다.

Oracle 11g 식별자 상한은 30바이트입니다

한글은 AL32UTF8에서 글자당 3바이트라 한글 10자가 한계입니다. 컬럼명은 가장 긴 업로드파일ID가 17바이트라 여유가 있지만, 인덱스·제약 이름은 테이블 코드를 접두로 써야 들어갑니다 — 전면 한글이었다면 IDX_업로드파일_업로드일시가 35바이트로 넘칩니다. 현재 가장 긴 이름은 IX_TSKGIAF01_업로드일시(29바이트)입니다. 이름을 늘리지 마십시오.

헷갈리기 쉬운 자리입니다. 매퍼 XML 2개는 이번 변경의 핵심이고(위 1·2번), 안 바뀐 것은 .java 소스입니다. 문장 단위 전·후는 부속 문서 내부망작업지시_2026-09-08_매퍼변경상세.pdf 에 있습니다.

4순서 — 이걸 틀리면 깨집니다

  1. 매퍼 2개 + 스키마 2개를 교체한다
    Eclipse에서 파일을 덮어쓴 뒤 Project → Clean. src/의 .xml·.sql은 컴파일 대상이 아니라 WEB-INF/classes로 복사됩니다.
  2. 서버에 Publish 하고 재기동한다
    이 시점에는 테이블이 아직 없으므로 화면에서 ORA-00942가 나는 것이 정상입니다.
  3. DBA에게 새 schema-oracle.sql을 전달해 테이블을 만든다
    테이블 2개 + 시퀀스 2개 + 인덱스 2개.
  4. 재기동 후 확인한다 (아래 6절)
매퍼와 DDL은 반드시 같은 이름이어야 합니다

왜 자바가 안 바뀌나

MyBatis의 resultMap이 자바 필드명(property)과 DB 컬럼명(column)을 명시적으로 이어 줍니다. 컬럼명만 바꾸고 매핑 줄을 고치면 자바 쪽은 바뀐 사실을 모릅니다. 자바 필드는 그대로입니다 — originalName · storedPath · year · category · status.

6교체 후 확인

시점확인할 것정상
매퍼 교체 후 Publish서버 로그 기동 성공. ORA-00904가 없어야 합니다
테이블 생성 전http://localhost:7001/uploader/ ORA-00942 — 지금과 동일. 정상입니다
테이블 생성 후/uploader/institutions 에서 기관 1건 등록 등록 성공 = 컬럼명·시퀀스가 모두 맞다는 증명
그다음/uploader/upload 로 파일 1건 업로드 C:\uploader-local\unclassified\ 에 파일 생성 + 목록에 표시
기관 등록이 실패하면
  • ORA-00942: table or view does not exist → 테이블 이름이 다릅니다 (TSKGIAF01·TSKGIAF02인지 확인).
  • ORA-00904 → 매퍼와 테이블의 컬럼명이 다릅니다. 2절 표를 보십시오.
  • ORA-02289: sequence does not exist → 시퀀스 2개가 안 만들어졌습니다. 테이블만 만들면 조회는 되고 등록만 실패합니다.
  • ORA-02290: check constraint violated → 분류상태에 허용되지 않은 값이 들어갔습니다.

8아직 안 한 것 — 기동 이후 과제

① 기관분류 코드값 5종 정리

지방자치단체 · 공공기관 · 대학교 · 병원 · 법원 5종으로 확정했지만, 코드에는 아직 옛 4종이 박혀 있습니다. 그것도 세 곳에 흩어져서요:

위치현재 값
KGI12000$FileStatusList.java:18지자체 · 대학교 · 대학병원 · 공공기관
KGI12400$ClassifiedFileList.java:18같은 4개 (복제)
templates/institution.html:43-46같은 4개를 <option>에 직접 박음
그래서 기관분류에는 CHECK 제약을 일부러 걸지 않았습니다

DB에 5종 CHECK를 먼저 걸면, 화면이 여전히 지자체를 보내는 순간 기관 등록이 ORA-02290으로 실패합니다. 코드를 5종으로 맞춘 뒤에 제약을 거십시오. (분류상태는 값이 코드에 고정돼 있어 지금 걸었습니다.)

② 기관 입력을 드롭다운으로

지금 기관명은 자유 입력 텍스트입니다(upload.html:30). 오타 한 글자면 매칭에 실패해 파일이 조용히 UNCLASSIFIED로 남고, 조회도 LIKE '%…%'라 IX_TSKGIAF01_기관명분류를 쓰지 못합니다. TSKGIAF02를 드롭다운 소스로 쓰면 셋 다 해결됩니다 — “A 기관 자료 들어왔나?”가 주 용도라면 이것이 가장 큰 개선입니다.

③ 자동 재분류 켜기

reclassification.cron이 비어 있어 5분마다 도는 재분류가 꺼져 있습니다. 켜려면 web.xml의 timer/uploaderTM 선언을 되살리고 WebLogic 콘솔에서 Work Manager uploaderTM을 만들어야 합니다 (DEPLOY.md 3번의 A → B → C).
