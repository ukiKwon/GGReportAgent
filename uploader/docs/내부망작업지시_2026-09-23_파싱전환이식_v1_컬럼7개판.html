1. 무엇이 바뀌는가

분류 방식이 통째로 바뀐다. 파일명 규칙으로 기관을 알아내 classified/ 로 파일을 옮기던 것을, 문서 내용을 파싱해 산출물을 만드는 방식으로 교체한다. 원본은 옮기지 않고 userdata/ 에 보관한다.

구분변경 전 (지금 내부망)변경 후
업로드pdf·hwp·md, 파일명 년도_기관명_설명 제안서 ppt·pptx / RFP pdf·hwp·hwpx, 창구 2개
기관 판별파일명에서 잘라 TSKGIAF02 조회문서 본문에서 찾아 매칭, 없으면 미분류
결과물원본을 classified/ 로 이동 제안서 → {연도}_{기관분류}_{기관명}_{파싱일}_bid_proposal.json
RFP → {공고일}_{기관분류}_{기관명}_{파싱일}.md
상태분류상태 1개 축분류상태 + 파싱상태 2개 축
재처리5분 주기 배치배치 폐지 → 화면의 수동 재파싱
연동/api/files/*위 유지 + /api/proposals, /api/rfps, agent 테스트 패널

적용 순서

  1. DDL 먼저 (3장). 소스를 먼저 올리면 조회에서 ORA-00904 가 난다.
  2. 반입물 배치 (2장) — jar, parse 패키지, agent-test.js
  3. 설정 → 도메인·코드값 → 매퍼 → 서비스 → 컨트롤러 → 화면 (4~9장)
  4. 폐기 파일 삭제 (10장) · 테스트 정리 (9장)
  5. 빌드 → 기동 → 검증 (11장)
내부망 고유 자산은 그대로 둔다. 감사 2열(시스템사용일시·시스템사용자번호), SystemUser ThreadLocal, databaseId 오라클/MySQL 분기, 화면번호 규약 (KGI#####$이름), 스케줄러 추상화, 삭제·반려 화면, 검색 API 는 손대지 않는다. 아래 diff 에도 그 부분은 나오지 않는다.
