5-5. 코드 클래스와 TypeHandler 신규

code/ClassificationStatus.java 와 똑같은 모양으로 만듭니다.

public final class DocumentType {
    public static final String BID_PROPOSAL = "BID_PROPOSAL";   // 01 입찰제안서 (ppt·pptx)
    public static final String RFP          = "RFP";            // 02 입찰공고문 (pdf·hwp·hwpx)
    // put("01", BID_PROPOSAL); put("02", RFP);
    // nameToCode() / codeToName() 제공
}

public final class ParseStatus {
    public static final String PENDING = "PENDING";   // 01
    public static final String SUCCESS = "SUCCESS";   // 02
    public static final String FAILED  = "FAILED";    // 03
}

public class DocumentTypeTypeHandler extends CodeTypeHandler {
    @Override protected Map<String, String> nameToCode() { return DocumentType.nameToCode(); }
    @Override protected Map<String, String> codeToName() { return DocumentType.codeToName(); }
}
// ParseStatusTypeHandler 도 동일
TypeHandler 를 빈으로 등록하지 않습니다. 내부망은 mybatis.type-handlers-package 를 쓰지 않고 Mapper XML 에서 자리마다 FQCN 으로 명시합니다. 네 핸들러의 자바 타입이 모두 String 이라 자동 등록하면 어느 것이 잡힐지 알 수 없기 때문입니다. 새 핸들러 2개도 같은 규칙을 따르십시오.
이식원은 DocType 을 자바 enum 으로 씁니다(DocType.BID_PROPOSAL, accepts(filename), getLabel()). 내부망은 코드값 변환 규약이 있으므로 문자열 상수 + TypeHandler 로 바꾸는 것이 일관됩니다. 확장자 검증(accepts)과 화면 표시명(getLabel)은 DocumentType 의 static 메서드로 옮기십시오.
