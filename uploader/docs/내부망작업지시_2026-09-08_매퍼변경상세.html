매퍼 변경 상세 — 무엇이 어떻게 바뀌었나

테이블·컬럼명 변경으로 매퍼 XML 2개가 함께 바뀌었습니다. 이 문서는 그 전·후를 문장 단위로 보여 줍니다. 파일을 통째로 교체하실 거라면 4절만 보셔도 되고, 손으로 고치거나 대조 검수를 하실 때 2·3절을 쓰십시오.

1왜 매퍼를 고쳐야 하나

MyBatis의 resultMap은 자바 필드명과 DB 컬럼명을 잇는 번역표입니다. 자바가 컬럼명을 직접 알지 못하고 이 표를 거치기 때문에, 이름이 바뀌면 번역표와 SQL 문장만 고치면 자바는 손댈 필요가 없습니다. 

번역표<result property="storedPath" column="저장경로"/>
                    ↑ 자바 필드 (안 바뀜)  ↑ DB 컬럼 (바뀜)
매퍼를 안 고치면 어떻게 되나

테이블은 TSKGIAF01인데 매퍼가 UPLOADED_FILE을 부르면 기동은 성공하고 조회할 때마다 ORA-00942가 납니다. 기동 로그에는 아무 문제가 없어서 원인을 찾기 어렵습니다 — 매퍼를 반드시 테이블보다 먼저 교체하십시오.

이번엔 모든 문장이 바뀝니다

지난 변경(컬럼명만)과 달리 테이블명까지 바뀌어, FROM· INSERT INTO·UPDATE·DELETE FROM 이 들어간 모든 문장이 대상입니다. 손으로 고칠 때 빠뜨리기 쉽습니다.

방법 ⓑ — 손으로 고칠 때의 치환 순서

INSTITUTION → TSKGIAF02 를 먼저 돌리면 INSTITUTION_NAME·INSTITUTION_SEQ 까지 깨집니다. ID 는 databaseId·keyProperty 같은 속성 이름에도 들어 있어 무차별 치환하면 XML이 통째로 깨집니다. 반드시 아래 순서대로, 긴 이름부터 바꾸십시오.

증상별 원인
  • ORA-00942: table or view does not exist → 테이블 이름이 다릅니다. 매퍼가 아직 UPLOADED_FILE을 부르고 있거나, DDL을 아직 안 돌렸습니다.
  • ORA-00904: invalid identifier → 컬럼명이 다릅니다. 어느 컬럼인지 메시지에 나오니 2절 표와 대조하십시오.
  • ORA-02289: sequence does not exist → 시퀀스 이름(3-2·4-2)을 확인하십시오. 이번에 시퀀스도 바뀌었습니다.
  • 오류는 없는데 업로드한 파일이 계속 UNCLASSIFIED → findByName(4-4)을 의심하십시오. 그다음은 기관명 오타입니다.
  • Invalid bound statement → 컬럼명이 아니라 방언 분기 문제입니다. mybatis.* 3줄이 설정 파일에 있는지 보십시오.
