매퍼 변경 상세 — 무엇이 어떻게 바뀌었나

컬럼명 변경으로 매퍼 XML 2개가 함께 바뀌었습니다. 이 문서는 그 전·후를 문장 단위로 보여 줍니다. 파일을 통째로 교체하실 거라면 4절만 보셔도 되고, 내부망에서 손으로 고치거나 대조 검수를 하실 때 2·3절을 쓰십시오.

작성일 2026-09-08 근거 커밋 1e13025 본 문서 컬럼명 변경 지시서의 부속 검증 mvn -o clean test 62건 통과

1왜 매퍼를 고쳐야 하나

MyBatis의 resultMap은 자바 필드명과 DB 컬럼명을 잇는 번역표입니다. 자바가 컬럼명을 직접 알지 못하고 이 표를 거치기 때문에, 컬럼명이 바뀌면 번역표와 SQL 문장만 고치면 자바는 손댈 필요가 없습니다. 

번역표<result property="storedPath" column="STORED_FILE_PATH"/>
                    ↑ 자바 필드 (안 바뀜)   ↑ DB 컬럼 (바뀜)
매퍼를 안 고치면 어떻게 되나

테이블은 새 이름인데 매퍼가 옛 이름을 부르면 기동은 성공하고 조회할 때마다 ORA-00904: invalid identifier 가 납니다. 기동 로그에는 아무 문제가 없어서 원인을 찾기 어렵습니다 — 매퍼를 반드시 테이블보다 먼저 교체하십시오.

방법 ⓐ — 파일 통째 교체 권장

외부망 리포의 아래 두 파일을 내부망 WTP 폴더의 같은 자리에 덮어쓰십시오. 그다음 Project → Clean → Publish.

외부망 리포내부망 WTP 폴더
uploader/src/main/resources/mapper/UploadedFileMapper.xml src/mapper/UploadedFileMapper.xml
uploader/src/main/resources/mapper/InstitutionMapper.xml src/mapper/InstitutionMapper.xml

⚠️ WTP 배치는 src/가 평면이라 경로가 다릅니다 (src/main/resources/가 아니라 src/). Eclipse가 .xml을 WebContent/WEB-INF/classes/mapper/로 복사합니다.

방법 ⓑ — 손으로 고칠 때의 치환 규칙

일괄 찾기·바꾸기를 그냥 돌리면 망가집니다

CATEGORY → INSTITUTION_CATEGORY 를 두 번 돌리면 INSTITUTION_INSTITUTION_CATEGORY 가 됩니다. ID 는 더 위험합니다 — databaseId·keyProperty 같은 속성 이름에도 들어 있어 무차별 치환하면 XML이 깨집니다.

순서찾을 것바꿀 것주의
1ORIGINAL_NAMEORIGINAL_FILE_NAME안전
2STORED_PATHSTORED_FILE_PATH안전
3FILE_YEARDOCUMENT_YEAR안전
4CATEGORYINSTITUTION_CATEGORY한 번만. 이미 바뀐 것에 다시 걸림

그래서 ⓐ(파일 교체)를 권합니다. 두 파일 합쳐 수십 KB입니다.

증상별 원인
  • ORA-00904: invalid identifier → 매퍼와 테이블의 컬럼명이 다릅니다. 어느 컬럼인지 메시지에 나오니 2·3절 표와 대조하십시오.
  • ORA-02289: sequence does not exist → 시퀀스 2개가 안 만들어졌습니다. 매퍼 문제가 아닙니다.
  • 오류는 없는데 업로드한 파일이 계속 UNCLASSIFIED → findByName(3-4)을 의심하십시오. 그다음은 기관명 오타입니다.
  • Invalid bound statement → 컬럼명이 아니라 방언 분기 문제입니다. mybatis.* 3줄이 설정 파일에 있는지 보십시오.
