# golden/ — WebLogic/Java 이관 검증용 골든 파일 (이관 설계 §8의 "단계 0")

현재 Python 시스템의 **결정적** API 응답과 산출물을 떠 둔 것이다. Java 재작성이
끝나면 같은 시나리오를 돌려 이 파일들과 비교한다 — "같은 입력 → 같은 출력".
프런트(`dashboard/`)가 재작성 없이 그대로 가므로, 이 비교가 통과하면 화면도
통과한다는 것이 이관 설계(`docs/superpowers/specs/2026-08-05-weblogic-java-migration-design.md`)의
전제다. **현 Python 시스템이 살아 있는 동안에만 뜰 수 있는 산출물**이라 이관
착수 전에 먼저 만들었다(NEXT.md 항목 9의 추천 순서 ③).

## 구성

- `capture.py` — 캡처 스크립트. `py -3.14 -m golden.capture`로 재실행하면 전부
  다시 떠서 덮어쓴다(운영 `data/`는 건드리지 않는다 — 임시 디렉터리에 새로 시드).
  재실행 후 `git diff`가 곧 "무엇이 달라졌나"다. **같은 커밋에서 두 번 떠서
  diff 0인 것을 확인했다**(결정성 검증 — 이 검증을 깨는 변경은 정규화 규칙부터
  의심할 것).
- `api/*.json` — 34개 스냅샷. 파일명 순서 = 실행 순서다(뒤 번호는 앞의 상태
  변경을 전제한다). 각 파일은 `{request, status, body}`.
- `artifacts/` — API 밖 산출물 2종:
  - `suwon_rfp_text.txt`(+meta) — 수원시 공고문 PDF의 pdfplumber 텍스트 추출.
    **Java(PDFBox)와 비교할 핵심 지점** — 줄바꿈·공백 차이가 그대로 드러난다.
  - `pptx_slides.json` — 고정 입력으로 만든 PPTX의 슬라이드별 텍스트.
    바이너리 비교가 아닌 이유: pptx(zip) 내부 타임스탬프가 비결정적이다.
- `manifest.json` — 캡처 목록·시드 기관·FTS 인덱스 통계.

## 시나리오 (Java 쪽도 같은 순서로 돌려야 한다)

1. 새 DB에 `corpus/institutions/` 25개 기관 시드.
2. 읽기 API 일괄(기관 목록/상세/404, 계정, 메뉴 2종, 문서 열람, 정합성,
   coverage-map, 아카이브 목록). coverage-map은 수원시 정답지 배점표 +
   coverage_map **v2** 픽스처를 노원구에 심어 병합 응답을 캡처.
3. 결재 시나리오 — `backend/tests/test_api_bidcases.py`의 E2E와 같은 시퀀스:
   입찰 건 생성 → 참여 결정 3단(tier 1·2·3, 영업팀, alice/bob/carol) →
   참여확정으로 자동 생성된 작업 3건을 각각 임시저장(assignee 선점, dave) →
   제출 → 승인(boss) → 최종 확정(finalize, approved). 이후 조회
   API(담당자 뷰·팀 작업함·쪽지함·정합성·타임라인·워크플로 상태) 캡처.
4. 검색(FTS 모드) 3건 — '금고'(2글자)·'소상공인 지원'·'청년 창업'.

## 정규화 규칙 (Java 비교 하네스도 같은 규칙을 적용할 것)

| 대상 | 치환 | 이유 |
|---|---|---|
| ISO 타임스탬프(초 이상 정밀도) | `<TS>` | 실행 시각 종속 |
| `bc-`/`task-`/`ntf-`/`msg-`/`chat-`/`new-` + hex 8자리 | 접두사`-<ID>` | `secrets.token_hex(4)` 랜덤 |
| 임시 작업 디렉터리 절대경로 | `<WORK>` | 실행마다 다름 |
| 리포 루트 절대경로 | `<REPO>` | PC마다 다름 |

날짜만 있는 값(YYYY-MM-DD)과 정수 id는 치환하지 않는다 — 시드·시나리오 순서가
고정이라 결정적이다.

## 캡처하지 않는 것 (비결정적 — 이관 검증은 다른 수단으로)

- **LLM 경로 전부**: 대화(chat)·업로드 즉시검사·워크플로 실행(run)·작업
  메시지(messages). Java 쪽도 같은 외부 LLM API를 부르므로 골든 비교가 성립하지
  않는다 — 구조(스키마)만 계약 테스트로 검증할 것.
- **검색 벡터 모드**: 임베딩 부동소수가 모델·환경 종속. FTS 모드만 캡처했다.
- **PPTX 바이너리**: 위 참조 — 슬라이드 텍스트로 대체.

## 알아둘 실제 동작 (버그가 아니라 계약)

- `search?q=금고`(2글자)는 **0건**이다 — trigram 색인은 3글자 미만 질의로
  트라이그램을 만들 수 없다. Java(Oracle Text 형태소 색인)가 여기서 결과를
  내면 그것은 "의도된 개선"이다 — 이관 설계 §6-A대로 차이를 문서화하고 수용
  여부를 받을 것(랭킹 차이도 같은 절차).
- 참여확정 직후 시스템이 분석 자동 시작을 시도하고, 공고문(rfp_path)이 없어
  실패하면 **영업팀 쪽지로 남긴다** — `24_notifications_sales`의 1건이 그것이다.
