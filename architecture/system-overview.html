Architecture Snapshot · 2026-07-28

구청 제안 자동화 파이프라인, 지금까지 지어진 부분과 설계도만 있는 부분

giganlist/ 연구 데이터에서 출발해 정적 보고서(report/), 레지스트리 API와 입찰건 워크플로우(backend/), 제안서 자동화 에이전트(agent/)로 뻗어나가는 현재 구조와, 이를 흡수할 예정인 9단계 입찰워크플로우 목표 아키텍처를 한 화면에 정리했다. 지난 스냅샷(07-27) 이후 영업·IT·예산 3팀 협업 워크플로우 전체가 실제 코드로 들어왔다.

01 / CHANGELOG

지난 스냅샷(07-27) 대비 무엇이 바뀌었나

07-27 스냅샷은 "레지스트리 API 하나만 기동되는 상태"였다. 그 뒤 한 세션에서 기관 인텔리전스 에이전트 설계가 확정되고 7개 Task가 전부 구현·리뷰·병합되면서 미구현 영역의 상당 부분이 실제 코드로 넘어왔다.

  • 미구현 → 완료 입찰건(BidCase) 엔티티와 3단계 참여 결재 — 실무자 → 팀장 → 부장 순서를 서버가 강제하고, 어느 단계든 미참여·보류를 고르면 그 자리에서 종료된다.
  • 미구현 → 완료 영업·IT·예산 3팀 Task 병렬 생성 — 3차 결재가 "참여"로 끝나는 순간 tasks 3건이 자동 생성된다(팀당 1건, 상태 대기).
  • 미구현 → 완료 에이전트와의 SSE 스트리밍 대화 — 팀별로 다른 코퍼스를 읽어 답하고, 응답 전문이 그대로 그 Task의 초안(draft_content)이 된다.
  • 미구현 → 완료 Task별 2단계 결재 + 최종 결재(finalize) — 3개 Task가 모두 2차완료여야 확정 가능하고, 확정 시 institutions.stage가 7(취합)로 올라간다. 누가 확정·반려했는지도 기록된다.
  • 20 → 66 백엔드 테스트 — backend/tests 10개 모듈 66건 전부 통과 (이 문서 작성 시점에 직접 재실행해 확인).
  • 변화 없음 agent/ 파이프라인·dashboard/ — 여전히 부분 구현. 다만 agent/llm.py가 백엔드 채팅에 실제로 쓰이면서 둘 사이에 처음으로 실선 연결이 생겼다.

03 / API SURFACE

엔드포인트 현황

지금 backend.main:app에 실제로 붙어 있는 전부다. 13개 모두 동작하며, 상태 전이를 어기는 호출은 400/403/409로 막힌다.

엔드포인트하는 일거부 조건
GET/institutions기관 목록—
GET/institutions/{id}기관 상세404
POST/institutions/importCSV 반입(6개 한글 헤더)400 형식오류
GET/institutions/{id}/artifacts산출물 경로 3종404
POST/bidcasesNEW입찰건 생성—
GET/bidcasesNEW내 담당 입찰건(team·assignee)—
GET/bidcases/{id}NEW입찰건 + 3팀 진척도404
POST/bidcases/{id}/participation-decisionsNEW참여 결재 1·2·3차400 순서/중복
POST/bidcases/{id}/finalizeNEW기획안 확정·반려409 미완료 · 422 헤더누락
GET/tasks/{id}NEWTask + 대화 이력404
POST/tasks/{id}/messagesNEW에이전트와 대화(SSE 스트리밍)403 타인 · 409 결재후
POST/tasks/{id}/submitNEW1차 제출403 담당자아님 · 409 상태
POST/tasks/{id}/approveNEW2차 승인·반려403 결재자아님 · 409 미제출

backend/routers/{institutions,bidcases,tasks}.py · 호출자 신원은 X-User-Id 헤더

인증은 아직 없다 — 담당자·결재자 판정은 X-User-Id 헤더를 그대로 믿는다. 이 리포지토리에는 로그인/RBAC가 존재하지 않으며, 스펙이 이를 의도적 트레이드오프로 명시하고 있다. 실제 배포 전에 반드시 별도 설계가 필요한 지점.

08 / RUN

지금 실행 가능한 것

서버 하나를 띄우면 레지스트리 조회부터 최종 확정까지 전 구간을 curl로 통과시킬 수 있다.

py -3 -m pip install -r requirements.txt py -3 -m backend.seed # giganlist/ → registry.db 시딩 set OPENAI_API_KEY=... # /tasks/{id}/messages 스트리밍에 필요 py -3 -m uvicorn backend.main:app --reload curl http://127.0.0.1:8000/institutions curl -X POST http://127.0.0.1:8000/bidcases --data-binary @bidcase.json py -3 -m pytest backend/tests -q # 66 passed

agent/ 파이프라인은 CLI가 없어 Python에서 run_pipeline() 직접 호출로만 시험 가능 (06절 참고)

git-bash에서 한글 본문 curl은 깨진다 — -d '{"...한글..."}'로 보내면 서버가 본문 파싱 오류를 낸다(앱 버그 아님). --data-binary @file.json으로 보낼 것.
