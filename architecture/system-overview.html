Architecture Snapshot · 2026-07-29 (rev.3, E2E 관점)

입찰 감지에서 제안서 제출까지 — 실제로 이어진 구간과 사람이 손으로 건너는 구간

이 문서는 컴포넌트 목록이 아니라 업무 흐름 9단계를 축으로 정리했다. "지도에서 입찰 임박을 발견한다 → 공고문을 구한다 → 참여를 결재한다 → 3팀이 초안을 쓴다 → 취합·검토해 제출한다"는 한 줄기 위에, 각 구간을 실제로 수행하는 코드/파일이 무엇이고 어디가 아직 사람이 파일을 옮겨야 이어지는지를 표시했다. 핵심 결론: 참여 결재부터 ⑦ 취합(제안서 PPTX 산출)까지가 서버 자동 구간이고, 그 앞 ①~③과 뒤 ⑧~⑨는 여전히 사람이 손으로 잇는다.

구현 완료 · 테스트 통과 부분 구현 (코드는 있으나 미연결) 사람이 수동으로 수행 설계만 (미구현)
01 / CHANGELOG

07-28 초판(커밋 0b1bd4e) 대비 무엇이 달라졌나

rev.2에서 E2E로 다시 훑으며 드러난 결함 두 가지를 rev.3에서 곧바로 해소했다. ⑦단계가 트리거만 쏘고 끝나던 구간이 이제 실제 산출물까지 이어진다.

  • 미구현 → 완료 ⑦ 취합이 실제로 문서를 만든다 — backend/assembler.py 신규. finalize 승인 시 3팀 draft_content를 영업 → IT → 예산 순 슬라이드로 묶어 PPTX를 저장하고, 경로를 institutions.pptx_path에 기록한다 (GET /institutions/{id}/artifacts로 바로 조회 가능). 슬라이드 생성은 agent/nodes/pptx_builder.py:build_pptx() 재사용.
  • 해소 python-pptx 의존성 누락 — requirements.txt에 추가. 수집조차 안 되던 agent/tests 2개 모듈이 살아나 16 → 24건 통과.
  • 66 → 72 백엔드 테스트 — test_assembler.py 4건 + finalize 승인/반려 시 산출물 생성 여부 2건 추가. 전부 TDD(실패 확인 → 구현)로 작성.
  • 재분류 dashboard/는 "기존 자산"이 아니라 ①단계 도구다 — 금고은행 입찰 임박도 D3 히트맵(전국/서울/경기). 초판은 이걸 흐름 밖 레거시로 그렸지만, 실제로는 E2E의 출발점이다. node --test 36건 통과 확인.
  • 개선 지도 가독성·드릴인 연출 — 커밋 c5b03d6(구 단위 subRegion 매칭·파스텔 팔레트·선택 강조), be194ee (라벨 헤일로·범례 우하단 고정·줌 타이틀). 지도 자체는 지시 없이 건드리지 않는 영역.
  • 새로 드러남 RFP/에 실제 공고문 1건이 있다 — "수원시 금고 지정 계획 공고문.pdf". 그런데 수원시는 giganlist/(서울 25구)에 없다 → ③단계 산출물이 ④단계로 넘어가도 근거 코퍼스가 없어 멈춘다. 신규 기관 spec 자동생성 노드 부재가 추상적 결함이 아니라 지금 실제로 막고 있는 지점.
  • 여전히 열림 ⑧ 검토 · ⑨ 제출은 그대로 사람 몫 — 산출물이 생겼으니 다음 후보는 verification_node를 취합 결과에 물리는 일이다.
  • 관점 변경 문서 구성 자체 — 컴포넌트 나열형(초판)에서 9단계 흐름 축으로 재편. 02·03·06절이 신규, 나머지는 초판 내용을 흐름 위에 다시 배치했다.

02 / END-TO-END

E2E 전체 흐름 — 9단계 위에 실제 자산 얹기

06 / SEAMS

E2E 단절 지점 — 사람이 손으로 건너는 다섯 곳

"무엇이 없는가"(11절)와 달리, 여기 적은 것은 양쪽 조각은 이미 있는데 사이가 비어 있는 곳이다. 대체로 비용이 작고 효과가 커서 다음 작업 후보 1순위다.

  1. 지도 → 레지스트리 (①→◆) 대시보드는 CSV 내보내기가 있고 백엔드는 POST /institutions/import가 있는데 둘을 잇는 사람이 필요하다. 스키마도 다르다(한글명+region vs institution_id).
  2. 공고문 → RFI 분석 (③→④) RFP/*.pdf를 rfp_analysis_node에 넣는 호출자가 없다. agent/에는 CLI 진입점 자체가 없어 Python REPL에서 직접 부르는 수밖에 없다.
  3. 신규 기관 → 근거 코퍼스 (④ 진입 조건) giganlist/에 없는 기관(예: 수원시)은 agent_adapter가 읽을 파일이 없어 ⑥단계가 의미 있게 동작하지 않는다. spec_research_node/ plan_writer_node가 담당할 자리인데 미구현이며, 현재는 사람이 institution-corpus-format 스킬로 손으로 만든다.
  4. 검토 (⑧) verification_node는 파이프라인 내부 커버리지 검사용으로만 존재하고, 워크플로우에서 호출되지 않는다. 스펙이 요구한 오탈자·RFI 역대조도 미구현.
  5. 화면 (전 구간) ④~⑨를 조작할 UI가 없다. 지금은 curl로만 워크플로우를 돌릴 수 있고, 유일한 화면인 dashboard/는 ①단계 전용이며 백엔드를 호출하지 않는다 (fetch 호출 0건).
직전에 닫은 단절 — rev.2에 여섯 번째 항목으로 적혀 있던 "확정(⑦) → 문서 산출"은 rev.3에서 backend/assembler.py로 메웠다(목록에서 제거). 트리거와 입력이 이미 DB에 있었기 때문에 신규 코드는 45줄이었다. 남은 것 중 같은 성격(양쪽 조각이 이미 있는 곳)은 위 S4 검토 — 이제 검토 대상 파일이 실제로 생기므로 verification_node를 물릴 자리가 생겼다.
