# 에이전트 대시보드 (agent-dashboard)

에이전트=선수, 메인=코치. 2D canvas 웹, 외부 라이브러리 없음.

- **보기**: `node agent-dashboard/serve.js`(또는 `python agent-dashboard/serve.py`) → http://localhost:8090 (서버 없이 `index.html`만 열면 데모 모드 — 버튼으로 조작)
- **상태 넣기**: `curl -X POST http://localhost:8090/api/state -H "Content-Type: application/json" -d '{"agents":{"qa":{"active":true,"task":"회귀 검증"}},"coach":{"task":"NEXT 31"}}'` — 2초 안에 반영
- **자동 연동**: `.claude/settings.json`의 훅(PreToolUse Agent·SubagentStart/Stop·UserPromptSubmit·Stop)이 `hook.js`로 `state.json`을 갱신한다. 사용자가 조작하지 않아도 에이전트가 호출되면 선수가 뛰고, 끝나면 쉰다. 같은 역할이 병렬·여러 세션에서 동시에 돌면 인스턴스마다 선수가 추가로 나타나고(`QA#2` 등, 역할당 최대 2명까지 표시) 현황판에는 `QA ×2`로 합쳐진다. 정지 이벤트가 유실돼도 15분 뒤 자동 정리. `state.json` 쓰기는 `statefile.js`(잠금+원자적 쓰기)가 맡는다. 훅 변경은 창을 다시 불러온 뒤 적용.
- **세션 시작 자동 실행**: SessionStart 훅이 `start.js`를 돌려, 서버(8090)가 안 떠 있으면 백그라운드로 띄우고 브라우저를 한 번 연다. 이미 떠 있으면(다른 세션) 그대로 쓴다 — 단 그 서버가 서버 코드(`serve.js`·`statefile.js`)보다 먼저 켜진 옛 프로세스면(`/api/server`의 기동 시각으로 판단, 이 주소가 없는 옛 서버는 포트의 프로세스 번호로) 내리고 새로 띄운다(브라우저는 다시 열지 않음, 11-23 site.js 404로 테마 전환이 안 된 사례). 브라우저를 열지 않으려면 `AGENT_DASH_NO_OPEN=1`, 포트는 `AGENT_DASH_PORT`. 서버는 세션이 끝나도 계속 떠 있다(끄려면 8090 프로세스 종료).
- **청소부**: `cleaner` 에이전트가 일하는 동안 청소부 캐릭터가 출근해 생수 채우기(병 잔량이 보임, 선수가 마시면 줄어듦) → 벤치 닦기 → 트랙 걸레질을 반복하고, 일이 끝나면 퇴근한다. 누워 쉰 지 3초(배속 따름)가 지난 선수가 있으면 수도에서 물을 받아 부어 깨운다. 1분에 한 번만 돈다(배속 따름) — 한 번 돌 때 누워 있는 사람은 차례로 모두 깨우고, 다음 번은 마지막으로 실제로 깨운 붓기가 끝나고 60초 뒤다(아무도 못 깨운 회차는 쿨다운 없음)(휠체어·구급차 장면이 사라지지 않게). cleaner가 일하지 않을 때도 연출로만 오른쪽에서 나오는데, 이때 현황판·칩은 '대기'로 표시된다. 물을 맞은 선수는 바퀴 수는 그대로이고 피로가 풀려 벤치로 돌아가고, 다시 일을 받으면 정상으로 달린다(판정 = 바퀴 − 물 맞은 시점 바퀴). 구급차가 출동 중이면 기다린다. OS의 '움직임 줄이기' 설정이 켜져 있으면 이동 없이 깨운다.
- **마무리 수동 실행(`closing.js`)**: `node agent-dashboard/closing.js [--dry] [--merge] [--now]` — 18:00 스케줄러는 인자 없이 실행한다. `--now`는 사용자가 직접 지시한 수동 실행에서 '최근 10분 안 사용자 프롬프트' 대기를 건너뛰는 옵션이다(다른 에이전트가 작업 중이면 여전히 대기·건너뜀. 푸시·병합 제한은 그대로).
- **누적 바퀴(전광판)·에이전트별 진행 — 하루 유지(2026-11-16 사용자)**: 누적 바퀴와 에이전트별 바퀴·피로(`stats.agents` = {선수 id: {lapF, freshAt}}, 추가 인스턴스는 `qa_2` 식)는 `state.json`의 `stats`에 저장돼 새로고침·새 Claude 세션에서도 이어지고, **날짜(이 PC 기준)가 바뀌면** 0부터다(전에는 새 세션(startup·clear)마다 0 — 2026-10-30 규칙을 바꿈). 화면은 3초마다 진행이 바뀌었을 때만 보내고, 서버는 형식이 틀린 항목을 버리며 같은 id의 진행이 줄어드는 값은 받지 않는다(여러 탭·지연 쓰기 대비). 탭이 없거나 숨겨지면 세지 않는다(2026-10-30). 10,000 미만은 전체 숫자, 이후 `12.3천`·`1백만`·`1십억`. serve.py는 `agents`를 받지 않는다(누적만).
- **serve.py의 한계**: Node 서버(`serve.js`)가 표준이다. `serve.py`는 python만 있는 PC용 보조로, ① `/api/version`이 없어 코드가 바뀌어도 열린 탭이 자동 새로고침되지 않고 ② `state.json` 쓰기에 파일 잠금이 없어 훅과 동시에 쓰면 갱신이 유실될 수 있으며 ③ 이 저장소 PC에는 python이 없어 실행 시험을 하지 못했다(코드 읽기로만 검토).
- **사용자에게 물은 질문 장부**(2026-11-15) — **화면 패널은 같은 날 사용자 요청으로 뺐다**(답 자동 기록 오작동, 1b486a1). 답 자동 기록은 폐기했다 — 훅 등록을 끈 데 이어 코드(answer 모드·AskUserQuestion 응답·직전 턴 사용자 글을 답으로 쓰던 경로)도 삭제(사용자 결정 11-15, NEXT 84 ②). 질문 자동 수집(Stop 훅)·장부·`/api/questions`만 남았고, 장부는 PM 금요일 주간 보고의 '이번 주 질문' 표 원천이다(CLAUDE.md 4절). 아래 패널 설명은 기록용이다. 정본은 저장소 루트 `handoff/questions.json`(git 추적)이고, 서버는 `GET /api/questions`로 그 파일 하나만 읽어 `{"questions":[...]}`로 돌려준다(읽기 전용 — POST 등은 405. 서버 전체 규칙(NEXT 31): `/api/state`는 POST만(그 외 405 `Allow: POST`), 나머지 경로는 GET·HEAD만(그 외 405 `Allow: GET, HEAD`), PROPFIND 등 안 쓰는 메서드는 501, Host 403이 가장 먼저. 256KB 초과·파일 없음·깨진 JSON은 200 + 빈 목록 + `error`, 화면은 직전 목록 유지). 화면은 30초마다 자동 확인(사용자 11-15, 패널 머리 '↻ 새로고침'은 즉시 다시 읽고 '확인 HH:MM:SS'를 갱신)이라 파일을 고치면 새로고침 없이 반영된다. 1100px 이상은 오른쪽 고정 열, 미만은 상단 '질문 n' 버튼 서랍. 탭 [미응답 n](open·hold, 최근에 물은 순) | [응답 n](answered 최근 답한 순 + 맨 아래 '해소된 질문' 접기 = done). 항목: `id, summary, askedAt, next[], options, recommend, status(open 미답|hold 보류|answered 답함·반영 대기|done 해소), answer, answeredAt, appliedRef, source?, answerSource?`. **기록**(`.claude/hooks/capture-questions.js`): Stop 훅이 `🙋 **물어볼게:**` 블록·AskUserQuestion 질문을 open으로만 추가(`source:"auto"`, 질문·선택지는 비밀값·이메일·전화·계좌·IP·토큰을 가리고 300자 상한). 답(answered)·해소(done + appliedRef)·보류(hold)는 메인이 손으로 기록한다 — 훅은 answer·status를 바꾸지 않는다. `answerSource`는 예전 자동 기록 항목에만 남은 이력 칸이다. 훅 변경은 창을 다시 불러온 세션부터 적용.
- **테마(2026-11-16)**: 헤더 `테마` 칸에서 **트랙 / 공사판**을 고른다(브라우저에 기억, 주소 `?theme=site`도 됨, 바꾸면 새로고침). 기능·판정·훅 연동은 같고 그림·문구만 다르다(`site.js`). 공사판 대응: 코치→현장소장(흰 안전모), 전광판→공정 현황판, 바퀴→**공정**, 트랙→**3층 단면도**(계단: 1↔2층 오른쪽, 2↔3층 왼쪽. 걸음은 트랙 달리기 속도의 0.85배), 현황판은 위쪽 두 줄, 치어리더→깃발 신호수 2명 "안전 제일!", 청소부→정리반, 휠체어→수레, 구급차→휴식 이송. **역할별 업무 동선**(사용자 11-16): 1층 출입구에서 출발해 자기 정류장을 차례로 들러 일하고 돌아오면 1공정(뛰지 않고 걷는다). 보안: 출입 통제→1층 외벽·2층 실내·3층 창호 손전등 점검 / QA: 건물 안팎 하자 확인(돋보기, 빨간 ! → 확인되면 초록 ✔) / 데이터: 1층 자재 하역장에서 상자를 들고 2·3층에 납품(층별 적치가 늘어남) / 기획: 공정표 갱신·진척 확인·자재 일정 확인 / 디자이너: 도면 수정·현장 실측 대조(레이저) / 프론트: 벽 도장·타일 시공 / PM: 3층 상황실에 앉아 CCTV(층별 작업자가 점으로 보임)·2층 도면 협의 / 백엔드: 크레인·꼭대기 골조, 지쳐 내려오면 층별 기둥 수직 확인. 공간 이름표(자재 하역장·상황실 · CCTV 등)가 붙고, 현황판에 지금 하는 일이 나온다. 공정 3개마다 1층. **엘리베이터** 2대(1~2층 오른쪽, 2~3층 왼쪽): 계단 앞에서 차가 내 층에 비어 있으면 타고, 다른 층에 있거나 누가 타고 있으면 계단. 차는 마지막으로 내린 층에 멈춰 있다(층 표시등 초록). **백엔드 = 타워크레인**: 백엔드가 일하면 크레인이 야적장 H빔을 들어 건물 꼭대기에 올리고, 건설용 리프트를 타고 올라가 1번은 운전석, 2번째부터는 건물 꼭대기에서 용접한다(피로 10 이상이면 리프트로 내려와 단면도에서 일함). **건물** 층수 = 누적 공정 ÷ 3 + 1(새 세션에서 1층부터). 16층을 넘으면 오른쪽 위 **고도 창**이 꼭대기를 따라가며 구름(20층, 비행기)·성층권(60층, 열기구)·우주(120층, 인공위성·UFO)를 보여 주고, 처음 닿을 때 알림이 뜬다(구간 경계는 `site.js` ZONES — 하루 실제 누적을 보고 조정). **행성(사용자 11-16 ③안)**: 120층(우주)에 닿으면 건물에 불꽃이 붙어 로켓처럼 날아가고(약 6.5초, 고도 창에 `지구 → 민들레 행성`), 다음 행성(지구 다음부터 꽃 이름 4글자 이하 + 행성: 민들레→장미→수국→라벤더→벚꽃→해바라기… 20종, 한 바퀴 돌면 `민들레 행성 2`. 땅·하늘 색은 꽃 색을 따름) 1층부터 다시 쌓는다. 행성·층은 누적에서 계산(`fmt.js planetOf`: 전체 층 T=누적÷3+1, 행성=(T−1)÷120, 층=(T−1)%120+1)이라 새로고침해도 같은 자리이고, 발사 장면은 화면을 연 뒤 행성이 바뀔 때만 나온다(움직임 줄이기면 알림만). 시험 도구 `누적 +100공정(시험)`·`🚀 우주선 발사(시험)`(다음 행성 1층으로 바로 발사)은 화면 층수만 올리고 `state.json`은 바꾸지 않는다.
